2025 年 3 月，Manus 以「通用 AI 智能体」的姿态刷屏，邀请码一码难求，二手市场一度被炒出高价；随后几个月，它逐渐从舆论中心淡出。最近它带着 2.0 版本回归，还发布了一个新物种——全天候智能体 Cue。这次更新值得聊的点，不在于「又发了新品」，而在于它把 agent 的交互范式，从「你喊一声它干一次」推向了「它常驻后台、随时候命」。这篇文章把来龙去脉、技术原理和行业坐标一次讲清。

## 一、先补课：Manus 到底是什么

- **出身与路线**：据公开资料，Manus 由创业团队 Butterfly Effect（蝴蝶效应）于 2025 年 3 月推出。名字取自 MIT 校训「Mens et Manus」（mind and hand，知行合一）中的「手」。它没有自研基座模型，走的是多模型编排路线，底层调用 Claude、Qwen 等模型，外加工具调用与浏览器操作。
- **与 Chatbot 的本质区别**：ChatGPT 类产品交付的是「一段回答」，Manus 交付的是「一个结果物（deliverable）」。比如丢给它一包简历，它自己开云端虚拟机、写脚本、跑筛选，最后交付一张排序表格，甚至一个可以直接访问的网页。
- **架构上是典型的多智能体协作**：规划者（planner）拆解任务 → 执行者（executor）在沙箱里操作浏览器和代码 → 验证者（verifier）检查产出。整个过程异步进行，你关掉网页，它还在云端继续跑。
- **技术底气**：它在 GAIA 基准（一个考察真实世界助理任务能力的公开测试集）上曾取得领先成绩，这也是当初刷屏时被反复引用的论据。此后据公开报道，团队将总部迁至新加坡并获得美元基金投资，这次回归算是一次阶段性答卷。

## 二、2.0 升级了什么：从「演示级」到「生产级」

第一代 agent 产品的通病可以总结成三个字：**慢、贵、飘**。

- 慢：一个长程任务跑半小时起步，用户全程干等；
- 贵：大量 token 消耗在中间试错上，一次复杂任务的成本可能是普通对话的成百上千倍；
- 飘：执行到第七、八步开始跑偏，错误像滚雪球一样累积（error accumulation），最后交付物没法用。

2.0 的迭代方向，基本是对着这三点打的：

1. **更快**：并行执行子任务、更激进的模型调度策略，压缩端到端耗时；
2. **更稳**：强化浏览器操控与上下文记忆，支持中途介入纠偏，而不是眼睁睁看它一路狂奔到黑；
3. **交付质量**：产出物更接近「能直接用」，减少人工返工。

展开讲一个原理点：**长程任务为什么难？** LLM 的上下文窗口有限，agent 每一步都要「背着全部历史」做决策，步骤越多，噪声越多、偏移越大。业界的通行解法有三件套：任务分解（把大任务拆成可验证的小步）、检查点（checkpoint，每步落盘、可回滚）、验证器（每步产出先自检再进下一步）。2.0 这类版本号背后，本质上就是在给这套机制打补丁。

## 三、Cue：交互范式从「拉」变「推」

如果说 1.0/2.0 是把「你吩咐的事」做得更快更好，Cue 改变的是一个更根本的变量：**谁来发起任务**。

- 过去的模式是**拉（pull）**：你想起来了，才去问 agent；
- Cue 的模式是**推（push）**：它 7×24 常驻，监听事件、盯指标、到阈值就主动提醒，甚至直接执行。

打个比方：1.0 是外卖，你下单它做饭；Cue 是管家，你还没开口，它已经把变质的菜挑出来了。典型场景（据发布会演示与公开报道归纳）：

1. 盯着竞品官网和招聘页，有变动自动汇总成一页日报；
2. 守着邮箱和日历，按你的风格起草回复、预留时间段；
3. 监控数据看板，指标异常时主动拉数、写出初步归因。

技术上，「全天候」绝不是把网页挂着就行，它意味着一整套新基建：常驻运行环境、事件驱动架构（event-driven）、跨会话的持久记忆、触发器设计，以及最现实的问题——闲置时间的算力成本怎么算。这也解释了为什么这类产品倾向于「数字员工月薪制」的订阅逻辑，而不是按次付费。

## 四、行业坐标：Manus 站在哪，在和谁竞争

- **国外**：OpenAI 的 ChatGPT Agent / Operator、Anthropic 的 computer use、Google 的 Project Mariner，都在做「让模型操作电脑」这件事；
- **国内**：字节 Coze、智谱 AutoGLM 等也在 agent 方向持续加码；
- **Manus 的差异化**：异步云端执行（不占用你本地电脑）、结果物导向（交付表格/网页/报告而非对话）、多模型中立（哪家强用哪家）。

但所有玩家共享三道坎：

1. **可靠性**：agent 在复杂任务上的成功率仍明显低于人类，跑十次成七次和成九次，是产品与玩具的分界线；
2. **成本**：复杂任务的 token 消耗量大，定价能不能覆盖、用户愿不愿意付，仍是未知数；
3. **安全**：全天候运行意味着常驻权限——让 agent 存着你的账号、半夜自动发邮件，这个信任门槛不低。

## 五、三条冷思考

1. **把 agent 当「实习生」而不是「员工」**。先交给它高容错、易验证、低风险的任务：信息汇总、格式转换、初稿生成。当「核对它产出的成本」低于「自己动手的成本」时，才值得委托。
2. **评估 agent 产品看三个硬指标**：过程可回放（能不能看清它每一步干了什么）、失败可恢复（出错后能否原地续跑，而不是从头再来）、权限可粒度化（读与写、看与发，能否分开授权）。做不到这三点，演示再漂亮也要打个问号。
3. **开「全天候」之前先算账**：触发频率 × 单次成本 × 人工确认成本，三个数乘出来不划算就别开。涉及支付、对外发送、删除操作的场景，默认保留人工确认（human-in-the-loop）——省下的那几分钟，不值得拿去赌。

一句话收尾：agent 竞赛的上半场比的是「能不能干活」，下半场比的是「能不能一直干活、干得让人放心」。Cue 们迈出的这一步方向清晰，但答卷还没写完。
