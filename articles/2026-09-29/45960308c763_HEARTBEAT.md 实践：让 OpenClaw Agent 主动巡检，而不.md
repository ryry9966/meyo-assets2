## 背景

多数人用 Agent 还是“人找 AI”：想起一件事，开个会话问一句。OpenClaw 的心跳机制把方向反过来——agent 按固定间隔（默认约 30 分钟）自动醒来，读取工作区根目录的 `HEARTBEAT.md`，按清单逐项自检：有事就做并汇报，没事就返回 `HEARTBEAT_OK`，消息被静默吞掉。这个几十行的 Markdown 文件，就是 agent “主动性”的全部配置面。

## 问题

在用它之前，我的 agent 大部分时间在空转：下载目录没人清、仓库挂着未提交改动、早上没人推日程摘要，全靠我自己记得去问。曲线救国方案是写一堆 cron 定时往会话灌 prompt，但那是“到点必发”，不管有没有事，一天几十条“无事发生”，很快被自己静音。缺的是一个“到点检查、有事才说”的机制。

## 做法

1. **建文件**：在 agent 工作区（默认 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`。
2. **按四段式写规则**：触发条件、动作、汇报方式、静默条件。核心是条件可判定——“盯一下邮箱”没用，要写“未读邮件含账单/验证码关键词时”。
3. **调节奏**：间隔和安静时段在 agent 的 heartbeat 配置里改，键名随版本变动，以当前版本文档为准。
4. **跑一周再修剪**：从心跳日志看哪些规则天天空跑、哪些从不触发，删掉或合并。

我实际在用的精简版：

```markdown
# Heartbeat checklist

- 每天早上 8 点后第一次心跳：汇总今日日程 + 天气，发到日常频道；其余时间静默。
- 检查 ~/Downloads：有超过 3 天未整理的文件就归类并汇报，否则 OK。
- 检查各仓库：未提交改动超过 24 小时，提醒一次。
- 任何检查项出错：连续失败 3 次以上才汇报。
```

## 踩坑点

- **心跳不是免费的**。每次醒来都是一次完整模型调用（含上下文加载），间隔压到几分钟，token 和噪音一起涨，30 分钟是巡检类任务的合理起点。
- **规则模糊等于乱动**。“看看有没有重要的事”会让 agent 每次强行产出内容。每条规则必须能回答“什么情况下什么都不做”。
- **忘了静默条件**。最早的规则没写“否则 OK”，agent 每半小时汇报一次检查结果——`HEARTBEAT_OK` 只在它判断无事时生效，你得先定义什么叫“无事”。
- **别把重活写进心跳**。心跳适合做轻量触发器：条件满足就起任务、调 MCP 工具，长任务异步跑，别让一次心跳卡十分钟。
- **外部依赖会坏**。依赖的 API 挂掉时，心跳会周期性报错刷屏，“连续失败 N 次才说”几乎是必备条款。

## 可复用建议

- 把 `HEARTBEAT.md` 当代码管理：进 git、写 commit message，每次改动可回溯。
- 规则从 2–3 条起步，稳定跑一周再扩，总量控制在个位数。
- 四段式模板（条件/动作/汇报/静默）固化下来，谁加规则格式都一致。
- 多 agent 场景按职责分文件，别让两个 agent 巡检同一件事。
- 主动性和打扰是同一根旋钮：宁可漏报，不要误报。漏了的事你还会想起，刷屏的 agent 会被永久静音。

## 总结

`HEARTBEAT.md` 的本质，是把“你希望 agent 定期关心什么”从对话里沉淀成一个可版本管理的文件。难点不在技术，而在于把每条规则想成可判定的条件，加一个明确的静默出口。从一个早上摘要、一个下载目录清理开始，一周后你会发现，开新会话问“帮我看看……”的次数明显变少了。
