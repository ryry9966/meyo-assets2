## 背景

我们在社区用 OpenClaw 跑了一条内容流水线：Agent 定期汇总本周高质量讨论、生成周报帖，通过 MCP 工具调用论坛 API 发出去。技术上一次跑通很容易，难的是跑了一个月后，有老用户在回复里说"这帖一看就是脚本发的"。这句话比任何报错都值得警惕。

## 问题

复盘下来，"像机器人"不体现在内容质量，而是三个可被统计出来的模式：

1. **时间太规律。** cron 定在每天 09:00，两个月的时间戳标准差不超过 1 分钟，反垃圾系统和真人都能一眼看穿。
2. **内容太同构。** 固定模板、固定段落长度、固定 tag，相邻帖子改改日期就能复用。
3. **只有输出没有输入。** 帖子从不回复评论，发帖:回帖比是 10:0，这在真实社区里几乎不存在。

## 做法

我们把节奏控制拆成独立模块，和内容生成分离：

**时间分布。** 废弃固定 cron，改成"窗口 + 抖动"：每天在 09:30–11:00 窗口内随机取一个时间点，抖动至少 ±20 分钟；周末密度减半；设静默时段（本地时间 0:00–7:00 绝不发）。时间戳生成后先过检查：与上一帖间隔小于最小冷却期就顺延。

**内容差异。** 维护 3–4 套模板轮换，长度用分段开关随机组合；发帖前用 simhash 和最近 30 篇历史比对，相似度超阈值打回重写。前四周走半自动：草稿进人工审核队列，通过后才进全量自动化。

**互动闭环。** Agent 每天固定一个时间窗读回复，生成的回复同样过抖动排队——绝不秒回。红线是回帖数 ≥ 发帖数的一半，达不到就暂停新的自动发帖。

**兜底。** 限速放在 MCP 工具层而非调度层，防止 Agent 自己决定连发；失败重试用指数退避并封顶次数；后台每周画一次发帖间隔分布图，间隔的变异系数低于阈值就告警——说明节奏又变"死"了。

## 踩坑点

- **抖动幅度太小。** 早期只加 ±1 分钟随机，分布图上仍是一条直线，等于没加。
- **随机没有记忆。** 有次两帖间隔只差 11 分钟，单点看是随机，放在一起比固定间隔更扎眼。冷却期检查必须全局生效。
- **时区错了。** 服务器是 UTC，用户在东八区，自动帖一度全落在凌晨四点。"随机但不人类"和"规律"一样可疑。
- **重试风暴。** API 报 429 后立刻重试，三连发直接触发平台风控。退避和熔断要从第一天就有。
- **队列积压。** 停机一天后补发，五分钟连出四帖。积压超过阈值宁可丢弃，不要追发。

## 可复用建议

- 节奏和内容一定分模块，节奏参数全部配置化，别写死在调度里。
- 先 shadow 模式（只写日志不真发）→ 半自动（人工放行）→ 全自动，每周看一次间隔分布再放下一级。
- 发帖:回帖比、间隔变异系数、相似度命中率，这三个指标值得长期记录。
- 模型或 prompt 升级后，先抽几篇旧帖新帖对比语气——突变比规律更引人注意。

## 总结

"不像机器人"归根结底是三件事：时间分布要有人类活动的形状，内容要有方差，互动要有来有回。自动化应该模仿人类行为的统计特征，而不是只完成"发出去"这个动作。当你的时间戳经得起画分布图、内容经得起相似度比对、评论区有人愿意认真回复时，节奏这件事才算真正解决。
