## 背景

社区每天都有资讯要发：新帖汇总、周报、活动预告。最初靠人工整理，两个问题：一是耗时，二是总比热点慢半拍。于是我用 OpenClaw 搭了一个发帖机器人，跑了两个月，发了 200+ 帖，中途 3 次故障都被自动恢复。这篇记录架构与踩过的坑。

## 核心问题

“能发一条帖”是 demo 级难度，真正难的是三件事：**内容可信**（不能瞎编链接）、**流程幂等**（重试不重复发）、**权限可控**（出问题能止血）。

## 架构与步骤

整体分五层，agent 只做“加工”，不做“采集”和“发布”：

1. **采集层**：脚本抓 RSS / 论坛 API，产出结构化 JSON（标题、链接、时间戳），落本地 SQLite。
2. **加工层**：OpenClaw agent 读取未处理条目，按模板生成摘要。输入只给 JSON，不给自由上网权限。
3. **审核层**：规则校验（链接域名白名单、敏感词、长度）+ 一个 `DRY_RUN` 开关，默认先输出到预览频道。
4. **发布层**：发帖动作封装成独立 MCP 工具，一个工具只做一件事：`create_post`、`edit_post`，不复用通用 HTTP 工具。
5. **观测层**：每次运行写日志表（run_id、状态、失败原因），失败进重试队列，连续失败 3 次告警。

## 踩坑实录

**1. cron 时区导致重复发帖。** 容器时区是 UTC，我按本地时间配了两套调度，凌晨各触发一次。解决：调度配置显式声明时区，发布前查库判断“今天是否已有同类型帖”。

**2. 重试造成重复内容。** 网络超时后重试，社区实际已发成功，出现两帖。解决：以“内容 hash + 日期”为唯一键发布前查重，工具返回“已存在”按成功处理。

**3. 模型编造链接。** 早期让 agent 自由发挥，产出过 404 链接。解决：摘要中禁止模型生成 URL，只透传采集层的原始链接，域名校验不过直接打回。

**4. 长列表 token 溢出。** 一天 40+ 条目一次性塞给模型，尾部被截断。解决：map-reduce——先分批各生成一句话，再汇总成正文。

**5. 工具权限过大。** 起初图省事用了全量 API token，后改为“只读采集 + 只写发帖”两个最小权限凭证，即使 prompt 被注入也做不了别的事。

## 可复用建议

- 状态外置到数据库，agent 保持无状态，随时可重建；
- MCP 工具粒度要小、语义要清晰，便于单独测试和限权；
- 上线前先跑 `DRY_RUN` 一周，人审通过再放开；
- 正文模板化，模型只填槽，不自由写作；
- 失败要有队列和告警，不能只靠翻日志。

## 总结

这个项目代码量不大，但工程上“少发、稳发、可撤回”远比“多发”重要。核心经验一句话：**把模型放在最窄的位置，把确定性逻辑放回代码里**。目录结构和配置模板整理在评论区，欢迎交流。
