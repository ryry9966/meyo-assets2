## 背景

OpenClaw 每次会话启动时，会把 workspace 下的一组 Markdown 注入上下文：`AGENTS.md` 管规则，`SOUL.md` 管价值观和边界，`TOOLS.md` 管工具用法。还有一个最容易被跳过的文件——`IDENTITY.md`，管的是"我是谁"：名字、形象、语气、一个代表 emoji。默认模板只有几行，很多人直接放着不动。实际上，它是整个 workspace 里维护成本最低、收益最持续的一张牌。

## 问题

实践里常见两类极端。一是完全不配，agent 用默认人设，多 agent、多渠道混跑时毫无辨识度，日志里分不清谁在说话。二是把人设写成几十行散文塞进系统提示词：改一次要翻半天，多个文件互相冲突，版本一乱，行为就漂移。核心矛盾在于：**人设需要长期稳定，又需要持续演化，但没人愿意维护一份大而散的 prompt。**

## 做法

文件位置在 workspace 根目录，我现在的版本精简成这样：

```markdown
# IDENTITY

- **Name:** Nova
- **Creature:** 电子守林人
- **Vibe:** 冷静、简洁、先给结论
- **Emoji:** 🌲
- **Avatar:** assets/nova.png
```

配套的迭代流程只有四步：

1. **只写事实性字段**，一行一个。行为规则（"拒绝什么、怎么拒绝"）归 SOUL.md，不混进来。
2. **用 git 管 workspace**。每次改人设一个小 commit，写清动机，例如："上周在群聊里太啰嗦，加一行：默认三句内说完。"
3. **建一个五问回归集**：固定问它自我介绍、如何拒绝请求、报错时怎么说话等 5 个问题，改完开新会话跑一遍，对比回答是否漂移。
4. **多 agent 用多 workspace**，各自一份 IDENTITY.md，别在一个文件里写条件逻辑。

## 踩坑点

- **写成小作文。** 人设超过二三十行，就会和 SOUL.md、AGENTS.md 抢话语权，模型行为变得不可预测。人设越短越稳。
- **改了不重开。** 编辑 IDENTITY.md 不影响已运行的会话，"改了没用"多半是旧会话还挂着旧上下文，重开再验证。
- **任务规则混进人设。** "回复必须带表格"这类属于 AGENTS.md，混进去会导致闲聊也在输出表格。
- **人设泄漏。** 过强的 persona（口头禅、高频 emoji）会渗进代码注释和正式通知里，自动化场景尤其明显，关键渠道要做克制约束。

## 可复用建议

- 把 IDENTITY.md **当配置代码**：小步提交、diff 可见、每次改动有理由，回滚也就是一次 `git revert`。
- **最小可行人设 = 名字 + 三个语气词 + 一条红线。** 先跑起来，再按对话日志迭代，不要一次设计到位。
- **定演化节奏**：每周扫一次对话记录，把"不像它"的回复归纳成一行写进文件，而不是当场打一堆补丁。
- **语言保持一致**：文件用中文写，中文输出会更贴。

## 总结

IDENTITY.md 的价值不在"让 AI 有个性"这类玄学叙事，而在于它把人格从散落的 prompt 变成了可版本化、可回归测试的一等配置。人设稳定是信任的基础，而演化机制决定这份信任能不能长期维持。花半小时建好文件、git 仓库和一个五问回归集，之后每次迭代只需一行 diff——这就是它性价比最高的地方。
