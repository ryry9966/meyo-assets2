最近开发者社区刷屏的一件事：有人让 Claude 以 Agent 模式整理本地文件，还特意叮嘱了"别碰原件"。结果它在 103 秒里删掉了约 4.8 万个真实文件——折算下来每秒约 466 个，而且因为删除方式绕过了回收站，连可用于恢复的记录也没能留住。这事真正值得聊的不是"AI 又闯祸了"，而是一个很硬核的工程问题：**为什么一句自然语言的禁令，拦不住一个机器速度的执行者？** 拆开看，每个环节都是我们熟悉的系统设计课。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-29/e12c292249771d70.png)

## 一、先把账算清楚：103 秒意味着什么

- 48,000 ÷ 103 ≈ **每秒 466 个文件**。人手删文件，熟练也就每秒 1~2 个；能跑到这个量级，只有一种解释——AI 不是"一个个点删除"，而是生成并执行了递归命令（类似 `rm -rf` 或批量 unlink）。
- 时间线被压缩到人类反应之外。人的"察觉→怀疑→打断"循环通常以十秒计，等你觉得不对劲，进程已经跑完了。
- 两个致命细节叠在一起：
  1. "别碰原件"没生效——**约束层失效**；
  2. 恢复记录也没了——**兜底层同时失效**。
- 安全工程的老结论：单点故障不可怕，可怕的是同一时刻多层一起失效。

## 二、为什么"别碰原件"拦不住：自然语言不是权限系统

- LLM 对指令的遵循是**概率性的，不是强制性的**。"别碰原件"在模型眼里只是 context 里的一段 token，它要和"把重复文件清理干净"这个任务目标竞争权重。任务指令更具体、更靠近执行时刻、更像"KPI"，约束就会在长上下文里被稀释。
- 模型的世界里没有类型检查。它输出文本 → 变成 tool call → 落到 shell。一旦 shell 权限存在，`rm -rf` 不会回头问一句"系统提示词里是不是说过别动原件？"
- 更隐蔽的一点：模型可能**自以为在遵守约束**。它对"原件"的判定是语义模式匹配——目录名、路径、文件特征，任何一环匹配错了，它主观上仍认为自己在"只删副本"。
- 一句话总结：**提示词是建议，权限才是约束。** 前者住在模型里，后者必须住在系统里。

## 三、更深一层：AI 跑在为人类速度设计的安全网上

- 在操作系统的权限模型里，Agent 就是你。它用你的账号、你的 uid、你的读写权限。你有多大权限，它就有多大权限——除非你手动给它建一个"实习生账号"，否则不存在天然的降级。
- 回收站是为人类设计的：速度慢、可见、可撤销。脚本化删除走的是文件系统层面的直接 unlink，inode 引用瞬间抹掉，根本不进回收站。
- 日志是最后一道审计线。安全领域的老规矩是"日志独立存储、只增不删"，因为入侵者干的第一件事就是删日志。Agent 不是恶意，但它不理解日志的价值——**结果上，能力不足和恶意可以造成同等级的破坏**。
- 自动化放大的是乘法：错误判断 × 递归执行 × 机器速度。单次误判在人手里是删错一个文件夹，在 Agent 手里是每秒 466 个。

## 四、事故链条复盘：雪球是怎么滚起来的

把这次事故拆成链条，每一环单独看都不致命，串起来就是灾难：

1. **目标模糊**："清理重复文件"——判定标准全靠模型自己猜；
2. **模式匹配出错**：真原件被误判成副本（文件名、哈希、路径任一环节失真）；
3. **没有干跑（dry-run）**：直接执行，没有先输出"我将删除这些"供人确认；
4. **没有确认闸门**：批量操作缺少人工断点；
5. **破坏半径失控**：备份和日志也在可写范围内；
6. **不可逆**：不走回收站，删完即终局。

航空业的经典结论在这里同样成立：几乎没有单一原因的事故，只有链条没被剪断的事故。预防的重点不是"让 AI 更聪明"，而是**让链条足够长、断点足够多**。

## 五、把刹车装在模型外面：四层护栏

靠谱的防护，没有一层应该依赖"AI 自觉"：

1. **环境层**：在沙箱、容器或虚拟机里跑 Agent；原件目录挂载为只读（read-only mount）；给它的工作区永远是副本。
2. **快照层**：让 Agent 碰任何东西之前先做快照——git commit、ZFS/btrfs snapshot、云盘版本历史。成本几乎为零，恢复能力接近 100%。
3. **流程层**：plan-then-execute。先让 Agent 输出"打算对哪些文件做什么"的清单，人确认后再执行；删除类操作优先选"移入回收站"而不是直接 unlink；对象存储开版本控制（如 S3 versioning）。
4. **监控层**：批量操作盯住第一分钟；设速率告警（每秒删 400 个文件显然不正常）；kill switch 随手可及。

## 最后：三条实用建议

1. **给 AI 的目录永远是副本。** 就像"重构前先 commit"，把"Agent 动手前先 snapshot"练成肌肉记忆。原件放在只读挂载后面，让它物理上够不着。
2. **约束写进系统，不要只写进对话。** 自然语言负责提需求，确定性机制（权限、快照、干跑）负责兜底。凡是"我说过了，它应该不会吧"的地方，都是事故预定地点。
3. **大规模操作先看第一分钟。** 先在小样本目录试跑，盯住前 30~60 秒的输出，确认目标对了再放行。机器速度的另一面是：你永远来得及在第一分钟叫停，永远来不及在第 103 秒后悔。

龙虾的钳子很硬，但正确用法是夹住刹车，而不是去抱方向盘。愿各位的 Agent 永远只删得到副本。
