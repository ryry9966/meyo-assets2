## 背景

OpenClaw 的工作区里有一组约定文件：AGENTS.md 管行为流程，TOOLS.md 管工具说明，USER.md 管用户事实，而 SOUL.md 负责一件更基础的事——这个 Agent 是谁。它会在会话启动时注入上下文，相当于一份常驻的人格声明。官方默认模板只是个起点，实际用起来，多数人要么照抄默认，要么随手写两句，效果都不理想。

## 问题

没认真写过 SOUL.md 的 Agent，常见症状有三个：

1. **语气漂移**。早晚风格不一致，长会话尤其明显，上下文压缩后像换了个 Agent。
2. **跨渠道割裂**。在 Telegram 里啰嗦，在 CLI 里又极简，用户感知混乱。
3. **边界模糊**。对删文件、发消息、调付费 API 这类动作，Agent 靠“感觉”决定要不要确认，而不是靠规则。

更常见的错误姿势是把人格、流程、用户偏好全塞进 AGENTS.md，越写越长，指令互相打架。

## 做法

我的做法是把 SOUL.md 当配置代码维护：

**第一步，定位与隔离。** 文件在 `~/.openclaw/workspace/SOUL.md`，多 Agent 就各自目录一份。人格归 SOUL.md，流程归 AGENTS.md，用户事实归 USER.md，不混写。

**第二步，固定结构。** 五段式：

- 身份：一句话说清它是谁、面向谁
- 语气：措辞和长度偏好，附两三个正反例
- 红线：不讨论什么、不假装什么、不擅自承诺什么
- 边界：哪些操作必须先向用户确认
- 渠道差异：IM 里简短，文档场景可展开

**第三步，控制长度。** 目标 40 行以内。SOUL.md 是常驻 token，每多一句废话，留给任务的上下文就少一分。

**第四步，版本化加探针测试。** 文件放 git 里，每次改动跑一组固定探针 prompt：诱导越界、要求它假装有权限、逼它超长输出，看行为是否符合预期。

**第五步，软硬分层。** SOUL.md 是软约束，能影响但拦不住。真要防住危险操作，得靠工具权限、allowlist、沙箱。人设负责“它不想做”，权限负责“它做不了”。

## 踩坑点

- **写成了小作文**。早期写过 200 行，Agent 输出也开始模仿这种冗长风格——它会把人设文件本身当文体示范。
- **与系统机制冲突**。我写过“永不主动发消息”，结果和 heartbeat 定时汇报打架，Agent 在两者间随机站队。冲突要显式解决，写清优先级。
- **关键约束放太靠后**。长会话压缩后，靠后内容更容易被淡化，红线段落尽量放文件前部。
- **混入易变信息**。称呼、偏好这类放 USER.md，SOUL.md 只放稳定人格，否则换个用户就得改人设。
- **过度确认**。把太多操作列进“必须确认”，Agent 一问三请示，自动化效率归零。只列真正不可逆的操作。

## 可复用建议

- 五段式结构可直接套用，先抄再改。
- 维护 10 条左右的探针集，改完人设必跑，当回归测试用。
- 写正反例比写形容词有效：“不用感叹号”比“语气克制”更可执行。
- 定期回顾，Agent 能力扩展后人设会过时。
- 需要硬保证的边界全部下沉到权限层，文本只做第一道防线。

## 总结

SOUL.md 的杠杆率很高：几十行文本，决定 Agent 在所有会话里的稳定性。它的定位是“常驻的软约束”，配合 AGENTS.md 的流程、USER.md 的事实、权限层的硬边界，各管一段。把人设当代码写、当配置测，Agent 才不会在第三天开始“性格突变”。
