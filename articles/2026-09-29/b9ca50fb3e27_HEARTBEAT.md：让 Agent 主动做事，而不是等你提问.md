## 背景

大多数人用 Agent 仍是"拉"式：打开会话、提问、得到回答、关掉。Agent 的能力被锁在你的问题里。OpenClaw 有一个简单但常被低估的机制，**HEARTBEAT.md**：守护进程按固定间隔（默认 30 分钟）唤醒一次 Agent，把工作区根目录下的这个文件作为"常驻指令"喂给它。每次心跳，Agent 读一遍文件、判断有没有该做的事，有就执行，没有就回一个约定的轻量标记（`HEARTBEAT_OK`），不打扰你。

## 问题

大量有价值的任务天然是时间/条件驱动的：早上汇总一次未读通知、盯一个 issue 有没有新回复、磁盘快满时提醒。这些事你不会每次都记得问；用外部 cron + 脚本能做，但上下文得重写一遍。HEARTBEAT.md 的定位，就是把这个中间地带交还给 Agent 本身。

## 做法

1. 在工作区根目录建 `HEARTBEAT.md`，先只写**一个**任务，参考格式：

```markdown
# 每日摘要（08:00 后首次心跳触发）
- 检查 inbox.md 中的未读事项
- 有新增：汇总为 3 行以内，发到 #daily 频道
- 去重：对照 notes/state.md，已提醒过的事项跳过
- 无新增：不说话，直接 HEARTBEAT_OK
```

2. 确认心跳间隔配置（默认 30 分钟，可调大；设 0 关闭）。初次建议先设 60 分钟观察。
3. 把心跳输出路由到一个专门的低噪音频道，别让它进主聊天。
4. 跑一两天后复盘：哪些任务天天空转、哪些在刷屏，据此删改文件。

## 踩坑点

- **成本**：每次心跳都是一次带完整工作区上下文的模型调用，30 分钟一次就是每天 48 次。文件保持精简；版本支持的话，给心跳单独配小模型。
- **重复提醒**：Agent 不记得上次说过什么。必须在文件里明确要求它把"已提醒"状态落盘，下次心跳先比对再决定。
- **任务写得太模糊**："帮我盯着仓库"会导致行为不可预测。每个任务都要凑齐四要素：条件、动作、输出格式、沉默规则。
- **心跳不是精确调度**：机器休眠、守护进程重启都会跳拍，别用它做分钟级告警；对时间敏感的任务用真正的 cron 去触发 Agent。
- **别把它当数据库**：它是指令文件，状态和数据放到别的文件里。

## 可复用建议

- **沉默优先**：默认"没事别说话"，只在该说的时候说。这是心跳机制不变成骚扰的关键。
- **轻重分层**：HEARTBEAT.md 只放轻量巡检（读几个文件、调一两个 MCP 工具）；重活写成 cron 触发的独立任务。
- **每周剪枝**：心跳任务和 cron 表达式一样会腐烂，定期删掉不再关心的条目。
- **一个模板走天下**：条件 / 动作 / 去重 / 沉默 / 输出去向，五要素齐了再写进文件。

## 总结

HEARTBEAT.md 把 Agent 从"应答机"变成了"值班员"，本质是一份被周期性执行的常驻提示词。它没有魔法，工程活一样不少：预算、去重、降噪、剪枝。但只要按纪律维护，它就能覆盖那些"你想起时已经晚了"的任务，这恰恰是纯对话式 Agent 最大的盲区。
