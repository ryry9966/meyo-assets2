## 背景

大多数 agent 的默认形态是被动问答：你发一条消息，它回一条。OpenClaw 的常驻进程、cron/heartbeat 和 MCP 工具生态，让"主动做事"在技术上完全可行——但真正的问题不是能不能主动，而是怎么主动才不会退化成定时骚扰。

## 问题：三个绕不开的矛盾

1. **触发时机**：定时轮询浪费 token，纯事件驱动又会漏掉"该看但没人通知"的事；
2. **行动边界**：查个日志可以直接干，删数据、给别人发消息呢？
3. **噪音控制**：主动消息超过每天三五条，用户就会开始忽略，主动能力等于失效。

## 做法：四层结构

### 1. 信号层：把"值得看一眼的事"收敛成三类

- **定时类**：cron 心跳，比如每天早高峰前拉一次日历、CI 队列状态；
- **事件类**：webhook / MCP 事件订阅，PR 被评论、磁盘越过阈值；
- **差异类**：定时跑，但只在"有变化"时输出，diff 为空就静默。这一类最容易被忽略，也最省心。

### 2. 判断层：先诊断，再决定要不要打扰

每个主动任务配一个独立的诊断 prompt，强制输出三档结构化结果：

- `SILENT`：记到本地，不发消息；
- `DIGEST`：进每日汇总；
- `INTERRUPT`：立刻推送。

关键是让模型只输出 JSON，由外层脚本解析后做路由，不给它自由发挥发消息的余地。

### 3. 行动层：分级权限

- 只读（查状态、抓日志）：直接执行；
- 低风险写（建 issue、写草稿）：允许执行，但打标记；
- 高风险写（部署、删除、对外发送）：生成建议，等你确认。

### 4. 汇总层：一个 digest 通道

SILENT 和 DIGEST 的结果累积到一个文件或轻量数据库，每天固定时间生成一份摘要推送。INTERRUPT 走独立通道，保持它的稀缺性。

## 踩坑点

1. **心跳烧 token**：heartbeat 每次都带全量上下文，一天几百次调用账单很难看。解法：心跳用精简系统提示 + 独立会话，不挂主记忆。
2. **幂等性**：webhook 重试会导致重复执行。给每个事件生成 event id，执行前查重。
3. **上下文过期**：主动判断基于"当时的快照"，执行写操作前必须重新拉一次最新状态，否则会出现"基于两小时前的磁盘水位做清理"这种事故。
4. **阈值误报**：磁盘 80% 告警后每轮心跳都报。做状态记忆：告警进入 acknowledged 状态，指标恢复后才重置。
5. **权限蔓延**：判断层不要挂全量 MCP 工具，按任务最小授权，只给它诊断需要的几个只读工具。

## 可复用建议

- 每个主动任务一个独立会话 + 固定输出 schema，方便单独调试和熔断；
- 先把所有任务设成 DIGEST 跑一周，从积累里观察哪些真的值得 INTERRUPT，再逐步放开；
- 加预算熔断：单任务每日调用上限，超了自动降级成静默，宁可不主动也不能失控；
- 每周翻一次 SILENT 记录——里面藏着最真实的"它本该主动做什么"的反馈，比拍脑袋加任务靠谱。

## 总结

Proactive 的本质不是"更勤快"，而是"更懂什么时候闭嘴"。信号分层、判断结构化、行动分级、输出收敛，这四层搭稳之后，助手才会从定时轰炸机变成一个真正省心的同事。
