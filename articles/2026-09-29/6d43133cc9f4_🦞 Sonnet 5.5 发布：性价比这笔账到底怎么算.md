36kr 消息，Sonnet 5.5 正式发布，媒体口径里又出现了一个熟悉的称号——"性价比之王"。每次大模型更新换代，这个词都会准时上岗，但很少有人把账摊开算：性价比到底怎么定义？价格凭什么降得下来？跑分漂亮就等于好用吗？这篇不聊发布会金句，只算账。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-29/4bd22afd7d59441e.png)

## 一、"性价比之王"是个数学概念，不是营销概念

把市面上的模型放到一张二维坐标图上：横轴是能力（benchmark 得分、真实任务表现），纵轴是价格（每百万 tokens 的 API 单价）。"性价比之王"在数学上有个严谨的对应物——**帕累托前沿（Pareto Frontier）**：同等价格下能力最强，或同等能力下最便宜的那批模型。

读一张模型定价单，有几个要点：

1. **输入和输出分开计价**，输出单价通常是输入的 3~5 倍，因为生成是逐 token 自回归，无法像读入那样并行；
2. **缓存价和批量价是隐藏优惠**：prompt cache 命中部分常有 1 折左右的计费，Batch API 一般再打对折，跑离线任务时这两项才是大头；
3. **"对标旗舰、价格减半"是典型的卡位策略**：如果 Sonnet 5.5 真的做到九成旗舰能力、一半价格，那它就站上了前沿——对预算敏感的应用方，这是实打实的降本。

## 二、价格凭什么降：推理端的四本技术账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-29/fab2ac49437055d0.png)

模型变便宜不是慈善，是工程。四个环节逐级压低单位成本：

1. **稀疏架构**：主流大模型普遍转向 MoE（Mixture of Experts），总参数很大，但每个 token 只激活其中一小部分专家网络，算力花得少、能力不掉，这是降本的地基；
2. **量化与蒸馏**：FP8/INT8 量化把权重从 16 位压到 8 位甚至更低，显存和访存开销同步下降；蒸馏让小模型学习大模型的输出分布，用约 1/10 的参数逼近大部分能力；
3. **推理工程**：continuous batching 让 GPU 永远"满载接单"，PagedAttention 把 KV cache 管得像操作系统管内存，speculative decoding 用小模型打草稿、大模型验收来加速生成。翻译成人话：**同一块 H100，今天的出活量是两年前的好几倍**；
4. **规模飞轮**：token 消耗上涨 → GPU 利用率提升 → 单位成本下降 → 定价下调 → 更多应用进场 → token 更涨。过去两年，同等能力的 API 价格大约以每年一个数量级的速度下探，行业里管这叫"能力通胀、价格通缩"。

所以"性价比之王"的第一性原理是：**单位智能的成本在坍缩**，谁站在坍缩的前沿上，谁就戴这顶帽子。

## 三、跑分很好看，但 Benchmark 是有水分的

发布会上那张"全面领先"的对比图，建议按三条过滤：

1. **数据污染**：如果公开测评题混进了训练数据，分数就退化成"背书能力测试"。负责任的团队会做 held-out 私有测试集，但发布会通常不放；
2. **天花板效应**：主流 benchmark 大家都考 85+，一两分的差异在统计误差范围内，没有区分度；
3. **任务错位**：SWE-bench 高分不等于你的客服工单处理得好，奥数满分也帮不了你做发票信息抽取。**别人的考场 ≠ 你的业务**，排行榜的热闹是行业的，成本是你自己的。

实操做法：从业务日志里抽 50~100 条真实 case 做成自己的 eval 集，每次模型更新跑一遍。这套土办法一天就能搭好，却比任何榜单都接近真相。

## 四、给开发者算一笔账：钱应该花在哪

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-29/d01f75732797c9d8.png)

性价比的最后一公里，是落到你自己的流量上。一个粗糙但够用的公式：

> 月成本 ≈ 日均请求数 ×（平均输入 tokens × 输入单价 + 平均输出 tokens × 输出单价）×（1 − 缓存折扣率）

三个典型场景，打法完全不同：

- **高频短任务**（分类、抽取、意图路由）：能力过剩是最大的浪费，90% 的流量应该走小模型或缓存，单价差可达 10 倍；
- **代码 Agent、长上下文分析**：输出 token 巨大，重点谈输出单价和 prompt caching——把系统提示词加长文档放进缓存，命中部分按一折计，长会话场景能省一半以上；
- **离线批处理**（数据清洗、批量摘要）：一律走 Batch API，用延迟换半价，没有理由不用。

进阶玩法是**成本感知路由（cost-aware routing）**：请求先过便宜模型，置信度不够再升级旗舰。把"哪 20% 的请求真正需要旗舰能力"想清楚，预算通常能省下 60%~80%。

## 五、三条冷思考

1. **别看发布价，看你的工作负载价**：用真实流量做一周 A/B，输入输出分布、缓存命中率、失败重试率都会改写账本，别拿每百万 tokens 的单价直接做迁移决策；
2. **价格战窗口期，留好逃生通道**：在 API 层做薄抽象（统一 schema 的 gateway），换模型只改配置不改业务代码。今天的性价比之王，下个季度就可能被迭代；
3. **性价比的终点是任务匹配，不是模型崇拜**：模型降价是行业的背景音，你的护城河是自建 eval 集、缓存策略和路由逻辑——这些才是降价浪潮里不会缩水的资产。
