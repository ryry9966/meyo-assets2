## 背景

我们在社区维护了一条由 OpenClaw 驱动的内容管道：Agent 定期汇总项目进展、精选问答和插件动态，通过 MCP 调用论坛 API 发帖。跑了一个月后问题暴露——帖子本身内容没毛病，但评论里开始有人问“这是不是脚本发的”，还有人直接屏蔽了这个账号。

## 问题

复盘发布日志后发现，不像人的不是内容，而是节奏：

- cron 固定每天 10:00 整发布，误差不超过两秒；
- 队列积压时一次连发三帖，把别人的动态顶下去；
- 模板完全一致，连结尾都是同一句话；
- 只发不回，评论区零互动；
- 一条动态被拆成五个碎片帖。

单看每一帖都正常，合起来就是典型的广播机器行为。

## 做法

核心思路是把“生成内容”和“发布决策”拆开，节奏只管后者。

1. **生成与发布解耦。** Agent 随时产出草稿进待发布队列，发布器是独立进程，只决定“什么时候发、发不发”。
2. **窗口 + 抖动。** 不用固定 cron，改成在目标窗口（如工作日 9:30–11:00）内取随机时间。窗口来自社区活跃时段统计，不是拍脑袋。
3. **配额与合并。** 每日上限 1 帖、每周 4 帖。积压超过阈值不连发，合并成一条 digest——宁可少发，不发碎片。
4. **结构变化而非措辞轮换。** 早期试过三个开场白模板轮换，两周就被认出来了。后来改为让 Agent 根据当期内容重写开头，同时保留统一署名，明示这是自动化账号。
5. **人工在环。** 前四周草稿全部过人审；跑顺之后，只有通过质量检查（长度、内容去重、至少一个实质细节）的帖子才自动发出。
6. **回评闭环。** 自动化账号必须回复评论；低置信度的问题就 @ 值班的人。单向广播是最大的机器人信号。
7. **自适应降频。** 追踪回复率和负反馈，上一帖表现差就自动拉长间隔，而不是加量。

## 踩坑点

- 抖动范围开太大，随机到了凌晨三点发帖，比固定时间更假。抖动必须加在活跃窗口**内**。
- 时区坑：服务器 UTC、社区 CST，第一版“活跃时段”整体偏了八小时。
- 失败重试导致重复发帖，要用内容 hash 做幂等去重。
- digest 合并后写太长，没人读完。正文控制在三段以内，细节放链接。
- 最重要的一条：**不要伪装人类。** 装错别字、装“刚看到”这类小动作，被识破的代价比大方承认自动化大得多。

## 可复用建议

- 节奏参数全部配置化：窗口、抖动、配额、安静时段，调参不改代码。
- 发布器记录决策日志（为什么现在发 / 为什么跳过），排查节奏问题靠日志，不靠猜。
- 明示自动化身份，用礼貌和响应换信任，而不是靠模仿骗信任。
- 指标看回复率和屏蔽数，别看发了多少条。

## 总结

“不像机器人”的重点从来不是把随机性涂在表面，而是不做机器人式行为：连发、刷屏、单向广播、无视反馈。队列 + 窗口抖动 + 配额 + 回评闭环，加上诚实的署名，这套组合跑了一个季度后，账号回复率回到了人工运营时的水平。自动化账号能不能在社区里活下去，取决于它像不像一个守规矩的成员，而不是它伪装得多像人。
