## 背景

用 OpenClaw 跑自动化，主会话免不了派活：批量检索、整理仓库、跑数据清洗。这类任务的共同点是过程长——一个子任务几十轮 tool call 很正常。如果这些过程全部留在主会话上下文里，很快会看到三个症状：compact 触发越来越频繁、早期定下的约束被摘要吃掉、模型开始"忘事"。token 账单也同步难看。

## 问题：三种污染路径

实践中污染不止一种：

1. **过程污染**：子 Agent 每一步的工具输出都回流到主会话历史；
2. **返回污染**：任务结束时，子 Agent 把整段执行记录当"结果"塞回来；
3. **状态污染**：子 Agent 与主会话共用同一份 session 文件甚至记忆文件，并发追加会导致历史顺序错乱，严重时 session 文件直接写坏。

前两种是上下文层面的，第三种是存储层面的，都得处理。

## 做法：四步隔离

1. **独立 session**。派发子 Agent 时显式开新 session，它的全部 tool 调用和中间输出只落在自己的 session 文件里，主会话历史不追加任何过程记录。
2. **文件当总线**。约定一个工作目录，子 Agent 把产物（报告、diff、清洗后的数据）写成文件，主会话只拿路径。原则是传引用、不传内容。
3. **收口返回**。返回策略用 summary 模式并设长度上限，比如 500 字符摘要 + 产物路径清单，并要求子 Agent 自己先做一轮提炼，而不是原样吐出。
4. **上围栏**。限制 max turns、token 预算、工具白名单和超时。子 Agent 应该被当成"允许失败的函数"，失败也要在预算内失败。

任务书建议固定模板，至少包含四项：

```text
目标：一句话说清要产出什么
输入：绝对路径，不要让它猜
输出：写到哪个目录 + 返回摘要的格式
禁项：不改记忆文件、不读无关目录
```

## 踩坑点

- **后门污染**：session 隔离做了，返回策略没收紧，子 Agent 把工具原始输出整段当结果回传，隔离形同虚设。
- **上下文偷懒**：任务书里写"参考主会话上文"——它根本看不到。必要上下文要么写进任务书，要么落成文件给它路径。
- **并发共写**：多个子 Agent 往主 session 追加，历史会乱序甚至损坏。并发任务必须各开各的 session。
- **记忆回写**：子 Agent 默认继承记忆/人设文件且可写，我们曾被打断过一次——主会话长期记忆被子任务改坏。给子 Agent 的记忆 scope 设只读或独立目录。
- **没有超时**：子 Agent 对着一个必失败的工具重试到天荒地老，预算上限是最后的安全网。

## 可复用建议

- 把子 Agent 当函数设计：输入是任务书，输出是结构化摘要 + 文件产物，副作用只发生在工作目录内。
- 主会话维护一行式"结果台账"：任务名 / 状态 / 产物路径，需要细节再开文件，不回灌内容。
- 落盘记录每次子 session 的 session id，出问题可回放审计。
- 定期验证隔离：故意让子 Agent 中途失败，检查主会话上下文长度是否异常增长、历史里是否混入过程记录。

## 总结

session 隔离的本质不是省 token，而是给子 Agent 定接口：过程留在外面，只有契约化的结果进来。四步里最容易被忽略的是"收口返回"和"记忆 scope"，这两处守住了，主会话才能长时间保持稳定。有更好的返回策略设计，欢迎在群里贴配置一起对齐。
