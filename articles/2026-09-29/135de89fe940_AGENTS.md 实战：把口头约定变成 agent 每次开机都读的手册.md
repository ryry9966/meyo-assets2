## 背景

OpenClaw 里 workspace 是 agent 的“家目录”：笔记、脚本、临时产物都在这里。但 agent 每次新开一个会话，上下文几乎是空白的——它不知道你的目录约定，不知道哪些东西不能碰，不知道你希望它怎么汇报。AGENTS.md 就是补这个缺口的机制：workspace 根目录下的一个普通 Markdown 文件，每次会话启动时被注入到 agent 的上下文里，相当于随包附带的使用手册。

注意它的定位：不是 gateway 配置（不改变进程行为），也不同于记忆文件（MEMORY.md 存的是事实沉淀），AGENTS.md 装的是“规则 + 约定”。

## 问题

没有 AGENTS.md，或者写得稀烂的 workspace，常见症状有这几类：

- agent 每次都把临时脚本散落在根目录，或者反复问你“放哪里”；
- 涉及敏感路径时没有边界，全靠你事后收拾；
- 同一件事反复交代：回复格式、命名习惯、部署流程；
- 换模型、重建容器之后，之前口头交代的约定全部蒸发。

本质问题只有一个：约定只存在于聊天历史里，而聊天历史不会稳定地进入新会话。

## 做法

推荐按这个骨架写，我自己的文件目前 60 行左右：

1. **身份与边界**：这个 agent 在这台机器上负责什么，附一张“不做”清单，例如不动 `~/.ssh`、不自动 `git push`、危险命令先确认。
2. **工作空间地图**：3~8 行讲清目录约定。比如 `scripts/` 放可复用脚本、`notes/YYYY-MM-DD.md` 是每日笔记、`tmp/` 可随意写入。
3. **工具使用规则**：什么时候用 exec、什么时候走 browser、长任务必须后台跑等。
4. **沟通约定**：默认语言、汇报格式、哪些操作需要先问你。
5. **自我修订规则**：连“改 AGENTS.md 前先列出改动点”这种元规则也可以写进去。

验证方式很简单：新开一个会话，问它“你现在的工作空间有哪些约定？”，看复述准不准。不准就改文件，直到它答得上来。

## 踩坑点

- **写太长**。AGENTS.md 每个会话都占上下文，我见过 400 行的手册，一半是历史遗留。原则：只写“每次会话都需要成立的事”，一次性任务请写到笔记里去。
- **放秘密**。有人图省事把 token、内网地址直接写进去。这个文件会进上下文，还可能随 workspace 备份同步——敏感信息一律走环境变量。
- **多层规则打架**。OpenClaw 有分层：全局说明、workspace 的 AGENTS.md、SOUL.md、记忆文件。同一条规则写两处且内容不一致，agent 行为就会飘。定一个唯一事实来源，其他地方只做引用。
- **写愿望不写规则**。“尽量做得稳一点”这种句子没有可执行性，改成“push 前必须先跑 lint”才有效。

## 可复用建议

- 把 AGENTS.md 纳入 git 管理，每次改动有 diff 可回溯，也方便多机同步；
- 每次发现 agent 犯了“它本该知道”的错，第一反应是往文件里加一条规则，而不是口头纠正——口头纠正撑不过下一次会话；
- 每月做一次清理：过期的删掉、重复的合并，长度控制在标准一屏以内；
- 多机部署时公共部分共用一份，机器差异下沉到各自的 workspace 级文件。

## 总结

AGENTS.md 的价值不在于“写了什么”，而在于把口头约定变成稳定的、每次会话都生效的上下文。门槛极低：一个 Markdown 文件，十几行就能起步。真正难的是维护纪律——把每次踩坑都沉淀成一条规则。做久了你会发现，调教 agent 的过程，其实就是把这个文件越写越准的过程。
