## 背景

多数人用 Agent 的姿势是一问一答：你想起来，才去问。但高价值的场景往往相反——磁盘快满了、日报该汇总了、某个工单三天没人回——这些事不该依赖"你想起来"，而该有一个定时自查的机制。

OpenClaw 内置了 heartbeat（心跳）：Agent 按固定间隔被唤醒，读取工作区根目录的 `HEARTBEAT.md`，据此决定干不干活、要不要打扰你。这个文件就是 Agent 的主动行为清单。

## 问题：被动模式的三类浪费

- 巡检类任务靠人记，一忙就漏；
- 每次都要重新交代背景，重复消耗上下文；
- Agent 明明能做的事，因为没人提问而永远不发生。

## 做法

1. 在 workspace 根目录新建 `HEARTBEAT.md`，每条任务一个 checkbox，写清楚三件事：判断条件、执行动作、通知策略：

```markdown
- [ ] 检查 ~/logs 目录体积
  - 超过 2GB：清理 7 天前的旧文件，发消息到 #ops
  - 未超过：静默，不发任何消息
```

2. 设置心跳间隔，默认约 30 分钟，可在配置里调整。轻量巡检 30–60 分钟足够；别为了"实时"调到 1 分钟——每次心跳都是一次真实的模型调用，纯烧 token。

3. 在 `AGENTS.md` 里约束行为：心跳结果默认静默，只有命中告警条件才发消息。这条不写，群里很快全是"一切正常"。

4. 临时停用：清空 `HEARTBEAT.md` 即可，心跳检测到空文件会直接跳过，比删文件好恢复。

## 踩坑点

- **条件模糊**。"看看有没有异常"没有判定标准，Agent 每次都会自由发挥。阈值、路径、时间窗口必须写死成可判定的规则。
- **频率混着写**。有的任务每小时查一次就够，有的每天一次即可，而整个文件共用一个间隔。把节流逻辑写进任务里（如"仅当距上次报告超过 24 小时"），或者干脆把低频任务移出心跳。
- **文件变垃圾场**。临时任务做完忘删，每次心跳都在为它付费。建议每周清一次，只留当前真正需要的条目。
- **重活放心跳里**。心跳适合几十秒内能结束的轻量判断；要跑十分钟的批处理，交给系统 cron 触发脚本或独立会话，别占用心跳通道。

## 可复用建议

- 固定模板：`条件 → 动作 → 通知策略`，三段缺一不可；
- 心跳产出落盘到日志文件，事后能对上"它什么时候检查过什么、为什么报了"；
- 从 1–2 条低风险任务起步（磁盘、日报、日程提醒），稳定跑一两周再加；
- 涉及写操作的任务，务必写明边界：只动哪个目录、只删什么前缀、绝不碰什么。

## 总结

HEARTBEAT.md 的本质，是把"你记得去问"变成"它定时自查"。机制本身很朴素，价值几乎完全取决于任务写得清不清楚：条件可判定、动作有边界、通知有策略。把这三件事写明白，Agent 才真正从应答工具，变成一个会自己巡检的同事。
