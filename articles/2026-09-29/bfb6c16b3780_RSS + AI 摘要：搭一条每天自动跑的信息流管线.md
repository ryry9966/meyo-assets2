## 背景

信息源越来越散，RSS 看似过时，其实是目前唯一开放、可控、格式稳定的订阅协议。配上 LLM 做筛选和摘要，可以把"每天刷半小时信息流"压缩成"读一份两分钟的日报"。这篇帖子记录我在 OpenClaw 上搭的一条信息流管线，跑了差不多一个月，够稳定，把过程和坑分享出来。

## 问题

- 订阅源 20+ 个，日均 150 条左右，人工筛不动；
- 很多源在 RSS 里只给标题和两行摘要，质量参差；
- 我要的不是"更多内容"，而是"更少但更相关的内容 + 可回溯的原文"。

## 做法

管线分五步，每步独立，中间状态全部落库：

1. **抓取**：定时任务每 6 小时跑一次，用标准 RSS/Atom 解析器拉全部源入库，只存 guid、链接、原始内容、时间戳。
2. **去重与粗筛**：guid + 链接哈希去重，再用关键词黑名单过滤一轮，能砍掉约 40% 无关条目——这一步不花 token。
3. **打分与摘要**：剩余条目喂给模型，要求输出固定 JSON：`{score, summary, tags}`。score 低于阈值的只记标题、不生成摘要，控制成本。
4. **日报分发**：按 score 排序取 Top N，拼成 Markdown 日报，通过 webhook 推到 IM。
5. **归档**：原文和摘要都留在本地库，之后随时可以让 Agent 检索"上周关于某个话题的讨论"。

在 OpenClaw 里，第 2–4 步可以挂成同一个插件的三个 handler，也可以拆成独立技能让 Agent 按需调用，两种我都试过，后者更适合想临时单独跑某一步的场景。

## 踩坑点

- **全文 vs 摘要**：不少源 RSS 里只有 200 字摘要，直接拿去总结会失真。我的做法是摘要过短就回抓正文，抓不到就明确标注"仅基于摘要"。
- **去重要放在调模型之前**：最早图省事全量过模型，一天的 token 大半烧在重复条目上。先去重再打分，成本直接降一个量级。
- **日期解析**：各家 pubDate 格式五花八门，时区也乱。用一个宽容的解析库统一处理，解析失败就丢弃并记日志，别让一条脏数据挂掉整批。
- **摘要幻觉**：在 prompt 里写死"只允许使用给定内容，不确定就写'原文未提及'"，实测能压住大部分编造。
- **任务幂等**：定时任务偶尔重叠触发，靠"已处理 guid 记状态"保证重复执行不会重复推送。

## 可复用建议

- 每步输出落库，任何一步挂了都能从断点重跑；状态不要只放内存。
- 摘要是可再生的，原文必须保留。换了模型或 prompt 后可以全量重跑摘要，不用重新抓取。
- 过滤阈值先调低，跑两周看误杀率再收紧，别一上来就激进过滤。
- 把"打分标准"写成独立的 prompt 片段，和个人兴趣清单分开维护，改兴趣不用动管线代码。

## 总结

这套东西没有一行"高级"代码，价值全在结构：抓取、过滤、摘要、分发、归档各自独立，用一张状态表串起来。RSS 提供稳定输入，LLM 负责压缩和判断，剩下的是工程上的脏活——脏活做得越扎实，管线越能长期跑。欢迎在社区里交流各自的信息源配置和打分策略。
