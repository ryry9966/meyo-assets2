## 背景

社区每周的「本周精选」帖一直靠人工整理：翻论坛、挑帖子、写摘要、排版、发帖，全程约两小时，还容易漏好内容。我的目标不是全自动无人值守，而是做一条**半自动流水线**：机器人负责采集、起草、发布，人只做审核。技术栈：OpenClaw 作为 agent 运行时，工具层走 MCP，cron 定时触发。

## 整体架构

拆成四层，每层可独立替换：

1. **采集层**：拉论坛 API + RSS，归一化为统一结构（标题、链接、作者、热度、时间）。
2. **起草层**：OpenClaw agent 读取候选列表，按写在系统提示里的「编辑规范」选出 5 条逐一生成摘要，输出结构化草稿。
3. **审核层**：草稿写入 SQLite 待审表，我收到通知后回复「通过 / 改写第 N 条 / 全部重来」。
4. **发布层**：审核通过后调用社区发帖 API，带幂等键，失败重试。

关键决策：**agent 只能通过工具拿事实，不能自己编链接和数据。**摘要里的 URL 必须来自采集层的原始记录，发布前再做一次链接存在性校验。

## 实施步骤

1. 写采集脚本落库，先跑一周 shadow mode——只记录不发帖，人工核对召回率。
2. 编辑规范写成系统提示，配四个 MCP 工具：`list_candidates`、`get_item`、`submit_draft`、`publish`。
3. 状态表 `items(id, url_hash, status, draft, published_at)`，`url_hash` 建唯一索引。
4. 幂等键取 `digest-YYYY-Www`，同一周重复触发不会发两遍。
5. cron 每周一 09:00 触发，发布层加令牌桶限速。

## 踩坑实录

**坑 1：模型编造链接。**第一版让 agent 自由发挥，它给两篇帖子配了不存在的「原文链接」。解法：摘要模板强制引用 `item_id`，发布前脚本校验 URL 是否在库里。

**坑 2：cron 重叠导致重复发帖。**上游 API 卡了三分钟，下一次 cron 又触发，同一帖发了两遍。解法：文件锁 + 幂等键双保险。

**坑 3：上下文被原始网页撑爆。**起初把整篇正文塞给 agent，token 消耗巨大，摘要质量反而下降。解法：采集层先做正文抽取和截断，agent 只读前 800 字。

**坑 4：Markdown 转义炸版。**标题里的下划线、代码片段的反引号把社区渲染器搞乱了。解法：起草层输出后加一道 escape 步骤，专门处理嵌套代码块。

**坑 5：审核疲劳。**每天推 10 条草稿，第三天我就不想看了。解法：改为每周一批量，只对置信度低的条目要求确认。

## 可复用建议

- 先 shadow mode 再上线，别直接对社区开火。
- 幂等键 + 内容 hash 去重，是所有发帖机器人的底线。
- 编辑规范放系统提示，事实数据走工具返回，两者严格分离。
- 保留「原始素材 → 草稿 → 已发布」完整链路，出问题能回溯到具体 item。
- 密钥只放环境变量，日志脱敏——agent 日志很容易被你忘了它在记什么。

## 总结

上线两个月，每周省约两小时，正式发布零事故（踩坑期除外）。最大的体会：发帖机器人的难点不在「让模型写东西」，而在幂等、审核、事实校验这些无聊但致命的工程细节。把无聊的部分做扎实，有趣的部分才敢放手交给模型。
