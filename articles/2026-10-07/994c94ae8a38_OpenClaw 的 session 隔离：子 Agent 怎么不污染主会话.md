## 背景

在 OpenClaw 里做多步任务编排时，最常见的模式是：主 Agent 负责拆解任务，把子任务派发给若干子 Agent（subagent）执行——批量检索、逐文件代码审查、数据清洗都是典型场景。子 Agent 每次执行都会产生自己的模型调用和工具调用记录，如果这些内容直接涌回主会话，跑不了几轮主会话就废了。这篇帖记录一下我们团队在编排层做 session 隔离的实际做法。

## 问题：污染有三种形态

1. **上下文污染**：子 Agent 的中间推理、工具返回的大段 JSON 和日志进入主会话上下文，token 成本飙升，主 Agent 的注意力被稀释，后续拆解质量明显下降。
2. **状态污染**：子 Agent 直接写共享 memory 或会话变量，先执行的把后执行的覆盖掉，主 Agent 拿到的是互相踩踏后的脏状态。
3. **副作用污染**：子 Agent 触发的写文件、发通知等副作用没有边界，事件冒泡回主会话，排查时根本分不清哪条记录是谁产生的。

## 做法

我们的原则是：**子会话独立运转，只回传结构化结果**。具体分五步：

1. **显式派发子会话**。给每个子 Agent 分配独立 session_id（如 `main:{task_id}:child`），transcript 和工具调用历史只落在子会话自己的文件里，主会话流里只留一条派发记录。
2. **约定返回契约**。子 Agent 结束时只输出固定 schema 的 JSON：结论、产物路径、错误码。可以在派发参数里限制返回策略，同时在子 Agent 的 system prompt 里约束"最终回复只输出 schema，不携带原始工具输出"。
3. **工具按需收窄**。子 Agent 只挂载本任务必需的工具，尤其是写类工具，能不给就不给，从源头切断对主会话资源的写入。
4. **隔离文件副作用**。所有落盘操作写到 `workspace/{task_id}/` 下，主 Agent 只读最终产物，不读过程文件。
5. **绑定超时与取消**。子会话设置独立超时，主会话用非阻塞方式等待，单个子 Agent 卡死不会拖垮整次编排。

## 踩坑点

- **摘要过度压缩**：早期只让子 Agent 回一行结论，主 Agent 复核时缺证据，只能重跑。改进是摘要里必须带产物文件路径，需要细节时按路径回读。
- **隐式共享 memory**：几个子 Agent 默认往同一命名空间写笔记，互相覆盖。要给每个子会话独立命名空间，主会话只合并最终结果。
- **调试期图省事复用父 session_id**：回放日志方便，但 transcript 混在一起，上线前务必改回独立 id。
- **并行子 Agent 争抢外部服务**：触发限流后，失败重试的报错被当成正常"结果"写回主会话，建议在返回契约里强制区分 success/error。

## 可复用建议

- 把返回契约做成模板并做 schema 校验，校验不过直接重试子任务，不进主会话。
- 利用子会话独立的 transcript 做单点回放：排查某个子任务时只看它自己的会话文件，不用翻主会话长日志。
- 给子会话设 token 预算上限，预算耗尽即终止并返回部分结果，成本可控。

## 总结

session 隔离的本质是两句话：**边界清晰，回传显式**。子 Agent 在自己的会话里可以自由调用工具、试错、产生大量中间产物，但主会话只接收一份经过契约约束的结构化结果。把这条边界立住，多 Agent 编排才不会随着任务规模增长而失控。
