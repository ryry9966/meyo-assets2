## 背景

OpenClaw 的 workspace 里有几个引导文件，`IDENTITY.md` 是其中最不起眼的一个：默认模板只有几行——名字、emoji、一句话 vibe、头像路径。它在每次会话启动时被注入系统上下文，作用相当于回答"你是谁"。很多人装完就再没打开过它。

但我们跑了几个月多实例之后发现，这个文件其实是整个 agent 体系里唯一"越改越好用"的配置——前提是你把它当配置管理，而不是当人设写作。

## 问题

实际使用中撞到三类：

1. **默认身份和用途脱节**。默认名字/语气是通用助手向，拿去跑日志分析、自动化脚本时很违和，协作者也不知道该信哪个设定。
2. **身份漂移**。有人图省事直接让 agent "自己更新你的身份文件"，几次会话后风格越走越偏，改无可改。
3. **无历史**。身份文件被覆盖式编辑，两周前那个"好用的版本"找不回来了。

## 做法

我们把它拆成三层：

**稳定层**：`IDENTITY.md` 本体控制在 10 行以内，只放不变量——名字、代词、一句 vibe、头像路径。不要塞行为规则，那些属于 SOUL.md / AGENTS.md。

**变更层**：单独建 `identity-changelog.md`，按日期追加，旧值、新值、原因各一行。这样旧会话记忆里的称呼、口吻仍能对上历史版本。

**流程层**：身份修改走 git。workspace 本来就该进版本库，把每次变更做成独立 commit，message 写清"为什么改"。更进一步，可以加一个定时任务让 agent 每月基于近期交互记录起草一份身份 diff，人工 review 后合并。"可进化"的关键就在这里：进化有提案、有审批、有回滚，而不是即兴发挥。

## 踩坑点

- **身份写太长**。50 行人设意味着每次会话都吃掉这段上下文，还会和 system prompt 里的实际指令打架。删到 10 行内后行为反而更稳。
- **与 SOUL.md 职责重叠**。一边写"简洁直接"，一边写"热情周到"，模型会随机站队。分工要清楚：身份=是谁，灵魂=怎么做事。
- **免审批自改**。试过让 agent 直接改自己的身份文件，一周后语气完全变形。任何变更必须过人工 diff。
- **头像写死绝对路径**，换机器全挂。用 workspace 相对路径。
- **改名但旧记忆没同步**，检索历史对话时出现两个称呼。改名时在 changelog 里显式记录旧名映射。

## 可复用建议

- 把身份当版本化配置：小、稳定、变更留痕。
- 进化频率固定（比如每月一次回顾），不要在交互中即兴改。
- 多实例场景：共享价值观放 SOUL.md，差异化的名字/风格各写各的 IDENTITY.md。
- 身份 diff 让 agent 起草、人来拍板——这是我们目前验证过的最稳的"自我进化"边界。

## 总结

IDENTITY.md 的价值不在那几行字本身，而在于它提供了一个低成本抓手，把"AI 是谁"从一次性设定变成可 review、可回滚的工程问题。写短一点，改慢一点，留好历史——身份会随着使用真正长出来，而不是漂走。
