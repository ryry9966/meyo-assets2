# 背景

RSS 是个老东西，但它至今是我找到的最"无平台绑架"的信息入口：源自己选、格式统一、退出成本为零。问题在于订阅源一多，未读条目的堆积速度远超阅读速度。我的解法不是"读得更快"，而是让 Agent 先读一遍：RSS 负责采集，LLM 负责压缩，人只看最终摘要。

# 问题

直接把 RSS 条目丢给模型，会踩两类坑：

1. 多数 feed 的 `description` 只有摘要或前几行，模型基于残缺文本总结，产出"正确的废话"；
2. 所有条目都过一遍 LLM，token 成本和噪音都不可控——大部分条目本来就不值得总结。

所以这条管线的核心不是"摘要"，而是**过滤 + 摘要**。

# 做法

管线跑在 OpenClaw 上，cron 定时触发，分四步，每步独立成模块：

**1. 采集。** 每 4 小时跑一次抓取任务，用自托管 Miniflux 聚合订阅源，通过 API 拉未读条目；没有 RSS 的站点用 RSSHub 补齐。

**2. 过滤与去重。** 三层漏斗：关键词黑名单先砍一刀；URL 规范化（去掉 utm 参数）后对正文做 hash，SQLite 查重；剩下的按来源权重和关键词加分排序。

**3. 摘要。** 只取 Top 10 调 LLM。正文过短的条目，先抓原网页用 readability 抽正文再喂给模型。输出强制 JSON schema：

```json
{title, one_line, key_points(≤3), tags[], deep_read_score(0-10)}
```

提示词里附一句关键约束："只依据给定正文，正文没有的信息不要编。"

**4. 投递。** 拼成日报推到 IM 频道，同时原始条目和摘要都落库，供后续检索与去重。

# 踩坑点

- **抓取频率别太高。** 有源站直接封了我服务器 IP，后来老实尊重 ETag / Last-Modified，间隔放到 4 小时。
- **一文多源是常态。** 同一篇文章会同时出现在博客、周刊、聚合站三个 feed 里，不做正文 hash 去重，日报会重复三遍。
- **摘要幻觉。** 早期模型会把标题里的猜想当事实写进要点，加上"不要编"约束并要求要点逐条对应原文后才稳定。
- **成本失控。** 第一版对所有未读条目做摘要，每天烧的 token 是现在的十倍，信息增量几乎为零。先过滤再摘要，省的是真金白银。

# 可复用建议

- **各阶段解耦。** 采集、过滤、摘要、投递做成独立函数，换模型或换推送渠道不用动其他部分。
- **原始条目永远落库。** 摘要是可再生的衍生数据，换模型后随时可以重跑。
- **订阅源做减法。** 从 5–10 个高质量源起步，跑稳再加。源的质量决定管线上限，模型只是下游。
- **留人工校验通道。** 日报附原文链接，每周抽查几个摘要，发现幻觉及时收紧提示词。

# 总结

管线跑了一个多月，日报条目点开率约 30%，比之前刷阅读器效率高不少。最大的体会是：LLM 摘要只是最后一环，真正决定信息质量的，是采集和过滤这两个"笨环节"。自动化管线的价值不在于替你读完所有东西，而在于把噪音压到你能快速扫完的量级。
