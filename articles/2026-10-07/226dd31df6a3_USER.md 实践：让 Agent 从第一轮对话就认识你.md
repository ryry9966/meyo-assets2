## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，大多数人会遇到同一个瓶颈：MCP、插件、定时任务都跑顺了，但 Agent 对"你"的了解仍然接近零。每次新会话，它要么从记忆文件里翻出几句碎片，要么重新确认一遍你的时区、技术栈和沟通偏好。

很多人的第一反应是往 MEMORY.md 里堆交互日志。但记忆是流水账，不是画像。USER.md 的定位不同：它是一份你主动维护的、描述"我是谁"的静态档案，每次会话注入上下文，优先级高于历史记忆。

## 问题

没有 USER.md 时的典型症状：

- 反复确认基础事实：时区、项目名、部署环境；
- 语气错位：你要简短结论，它给长篇教程；
- 记忆污染：三个月前的临时状态被当成你的长期偏好。

## 做法

在 workspace 根目录建 USER.md，建议固定五段：

```markdown
# 基本盘
- 时区 / 常用语言 / 回复语言偏好

# 沟通风格
- 先结论后细节；不确定就直说，不要客套

# 环境与工具链
- OS、常用路径、主力语言、部署方式

# 当前项目（不超过 5 条）
- 一行一个：名称、目标、当前阶段

# 红线
- 不要替我答应外部请求；不要动生产配置
```

三个原则：

1. **短**。控制在 80 行以内，每条是一行事实，不写散文——它每个会话都要占用上下文。
2. **稳**。只放变化频率以月计的信息。今天改的 bug、临时的想法，归 MEMORY.md。
3. **可版本化**。放进 git，每次 Agent 表现不对、你手动纠正后，顺手 diff 一行进去。

一个偷懒但有效的启动方式：让 Agent 反向采访你十个问题，基于回答生成初稿，你再删减。比从空白页开始快得多。

## 踩坑点

- **写成简历或日记**。Agent 需要可执行的约束。"我喜欢喝咖啡"没意义，"默认中文回复、代码注释用英文"才有用。
- **塞敏感信息**。密钥、住址、手机号不要明文进 USER.md——它随每次会话进上下文，还可能被工具调用带出去。
- **与 AGENTS.md / 记忆打架**。旧记忆和新档案冲突时，Agent 可能随机选边。定期清理矛盾的记忆条目。
- **过期不更**。项目列表半年没动，Agent 会自信地基于过时事实行动，比不知道更糟。设个季度提醒，五分钟过一遍。
- **过度人格化**。性格描述写太多，Agent 会开始表演"懂你"，把猜测当事实输出。

## 可复用建议

- 维护一个"纠错区"：Agent 每猜错一次，加一行"不要 X，要 Y"，每月复盘合并进正式段落；
- 项目段落标注日期，过期条目一眼可见；
- 多设备 / 多 Agent 场景，USER.md 放同一 git 仓库同步，避免画像分叉。

## 总结

USER.md 不是什么高级技巧，本质是把"每次口头解释自己"固化成一份版本化的配置文件。成本是 30 分钟初稿加偶尔维护，收益是 Agent 从第一轮对话就站在正确的上下文里。记忆系统回答"发生过什么"，USER.md 回答"我是谁"——两者补齐，Agent 才算真正接入你的工作流，而不是一个每次都要重新自我介绍的实习生。
