## 背景

在 OpenClaw 的日常用法里，让 Agent 产出内容已经不难：技术笔记、周报、Issue 说明、社区帖子，基本都是 Markdown 出稿。真正麻烦的是发出去这一步——同一篇稿子要进公众号、知乎、掘金、GitHub Wiki，格式要求各不相同，手动适配一遍比写稿还累。

我的思路是把格式适配从人肉搬运变成管线：Agent 只负责产出一份规范的源 Markdown，转换交给脚本和一个 MCP 工具。

## 问题

各平台本质上是不同的 Markdown 方言：

- 公众号编辑器不认 Markdown，只收带内联样式的 HTML，且会剥离大部分标签；
- 知乎支持的子集很窄，表格、脚注、任务列表基本残废；
- 掘金兼容 GFM，但代码高亮和数学公式的写法有差异；
- GitHub 支持 GFM 加 alerts，脚注没问题。

如果用正则做转换，第一个 `<br>` 或嵌套列表就会翻车。正确做法是在 AST 层面操作。

## 做法

管线基于 remark（unified 生态），分四步：

1. **规范化**：源文件带 frontmatter（title、tags、目标平台），先用 remark-lint 检查标题层级、图片链接、代码块语言标注，不合格直接打回给 Agent 重写。
2. **统一 AST**：`remark-parse` 把 Markdown 解析成 mdast，所有转换写成 remark 插件，而不是字符串替换。
3. **按平台分发转换**：
   - 公众号：mdast → HTML，样式全部内联到元素上，图片先传图床换永久链接；
   - 知乎：降级处理——表格转列表，脚注改成文末"注："段落，删任务列表语法；
   - 掘金 / 静态站：基本直出，只需统一数学公式分隔符。
4. **输出与预览**：每平台产出独立文件到 `dist/<platform>/`，本地渲染后用无头浏览器截图做视觉抽查。

第 3 步包成了一个 MCP 工具 `convert_md(source, target)`，挂在 Agent 工作流里，写完稿直接调用，不用离开会话。

## 踩坑点

- 公众号粘贴时会剥掉 `<style>` 标签，样式必须逐元素内联，`pre` 里的换行要单独处理；
- 图床防盗链：知乎引用外站图片会挂，发布前统一转存；
- 数学公式：`$...$` 在部分平台渲染成原文，转换前先确认目标平台认哪种分隔符；
- 硬换行：行尾两个空格在公众号会被吃掉，用 `<br/>` 更稳；
- 转义：Agent 偶尔输出未转义的 `<` 和 `&`，lint 阶段就要拦住，否则渲染直接挂。

## 可复用建议

- 源文件只表达语义，平台差异全部下沉到转换插件，别在源头写兼容写法；
- 准备一份覆盖全语法的"黄金样例"文档（表格、代码、公式、脚注、嵌套列表），每次改插件跑一遍 diff 测试；
- 转换必须幂等：同一输入跑两次输出字节一致，方便 CI 校验；
- remark 插件版本锁死，生态库小版本升级偶尔会改 AST 结构。

## 总结

这套管线没有黑魔法，就是"单源 Markdown + AST 转换 + 平台 profile"。Agent 管写作质量，管线管格式正确性，两者解耦后，新增一个发布平台只是新增一个 profile，成本可控。对常做社区分发的团队来说，值得一次搭到位。
