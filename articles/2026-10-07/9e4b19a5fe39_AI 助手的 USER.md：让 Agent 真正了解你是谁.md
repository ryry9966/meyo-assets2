# 背景

OpenClaw 的 workspace 里有一组约定文件：`AGENTS.md` 约束行为，`SOUL.md` 定义性格，`MEMORY.md` 存滚动记忆。很多人把前两个调得很细，`USER.md` 却常常是空的。后果是 Agent 知道自己"该是什么语气"，却不知道"对面坐的是谁"。

# 问题

每次新会话，上下文都是重建的。如果 USER.md 缺位，Agent 会用默认假设补齐你的信息：默认时区、默认技术栈、默认你想要详尽的解释。一次性问答里这无所谓，但 OpenClaw 是长期驻留、会主动执行任务的形态，错误假设会被放大：按错时区排日程、在你明确弃用的框架上继续给建议、把你一次性的提问当成持久偏好。你反复纠正，它下次照犯。

# 做法与步骤

1. **建文件**：在 workspace 根目录（默认 `~/.openclaw/workspace/`）新建 `USER.md`。注意：文件存在不等于会被读，先确认 `AGENTS.md` 里有"会话开始时读取 workspace 文件"的指令，没有就补上。
2. **分层写**：
   - 稳定事实：时区、语言、怎么称呼你、日程类硬约束（如"周末不开会"）；
   - 技术上下文：主力语言和版本、常驻仓库路径、代码风格约定（缩进、测试框架、是否允许自动装依赖）；
   - 协作偏好：回复详略、要不要解释理由、哪些操作必须先确认。
3. **一条一个事实**，动词或名词开头，别写散文。`用 pnpm，不用 npm` 远比"我喜欢高效的包管理"有用。
4. **控制体积**。这个文件每个会话都进上下文，几十行足够，超了就该砍。
5. **靠纠错迭代**。Agent 猜错一次，就回去补一行明确规则——这是 USER.md 最可靠的增量来源。

# 踩坑点

- **写太长**。上下文膨胀，关键指令被稀释，token 成本也跟着涨。
- **写易变状态**。"当前在做 X 项目"两周后就过期，过期信息比没有更糟。这类内容放 `MEMORY.md` 或每日笔记，USER.md 只放半年内不会变的东西。
- **放敏感信息**。USER.md 是明文，且会进每一次 prompt。密钥、密码、证件号绝对不要出现。
- **写评价不写指令**。"希望聪明一点"不包含任何可执行信息。
- **多实例漏同步**。跑了多个 agent 或子 agent 时，确认每个的 workspace 指向同一份 USER.md，否则不同 agent 对你的认知会分叉。

# 可复用建议

- 把 USER.md 当 dotfiles 维护，进 git：既留修改历史，也方便多机同步。
- 稳定/易变分离是核心原则：USER.md 管身份，MEMORY.md 管状态。
- 起步模板四段即可：身份 / 技术上下文 / 协作偏好 / 禁区，每段三五条。
- 每月或每季度花五分钟通读一遍，删掉过时项往往比新增更有价值。

# 总结

USER.md 的本质，是把"Agent 应该了解你"从玄学变成一份配置文件。它不智能，但它确定：写进去的每一条都会被稳定带进每个会话。花二十分钟写第一版，之后靠日常纠错慢慢长出来，比一次性憋一份完美档案现实得多。
