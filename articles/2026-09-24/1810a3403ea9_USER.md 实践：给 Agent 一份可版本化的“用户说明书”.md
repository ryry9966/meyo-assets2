## 背景

OpenClaw 的 workspace 里，除了 MEMORY.md，还有一个常被忽略的文件：USER.md。两者分工其实很清楚——MEMORY.md 记"发生过什么"，USER.md 定义"你是谁"。Agent 每次会话本质上是无状态的，它能走多远，很大程度上取决于工作区里给了它什么基线上下文。

## 问题

没有 USER.md 时，通常有三个症状：

1. **重复交代**。时区、技术栈、回复语言、代码风格，每个新会话都要重说一遍，或者靠 MEMORY.md 里零散的日记条目碰运气。
2. **错误假设**。Agent 默认按训练数据里最常见的画像猜：macOS、英文、个人项目。如果你是 Arch + 中文回复 + 公司内网环境，它第一次猜错的成本由你承担。
3. **多用户串味**。家庭服务器或共享实例上，没有清晰的用户画像，Agent 很容易把 A 的偏好套到 B 的请求上。

MEMORY.md 是流水账，会膨胀、会过时、检索还有噪声。稳定事实和动态事件混在一起，是最常见的结构性问题。

## 做法

我的 USER.md 目前控制在 40 行以内，分五段：

```markdown
# 用户画像
- 身份：后端工程师，主力 Go/Python，中文交流
# 环境
- 本机 Arch Linux，时区 Asia/Shanghai，服务在内网
# 偏好
- 回复先结论后细节；代码注释用中文；不用表情符号
# 当前项目
- openclaw 插件开发，仓库在 ~/dev/xxx
# 边界
- 不主动重构既有代码；删库、支付类操作必须二次确认
```

几点经验：

- 放在 workspace 根目录，与 AGENTS.md、SOUL.md 平级，每次会话都能被读到。
- 写"事实"而不是"期望"。期望靠提示词临时给，事实才值得落盘。
- 用 git 管理 workspace，Agent 的每次修改建议都走 diff，你能审计。
- 让 Agent 参与维护：会话结束时说一句"根据本次对话，提议 USER.md 的增量修改"，它给出改动，你决定合不合。

## 踩坑点

- **写太长**。早期我写了 200 行，结果 Agent 在小事上反复引用过期偏好，重要指令反而被稀释。画像文件的信噪比比信息量重要。
- **敏感信息**。不要放密钥、密码、证件号。workspace 可能被备份、同步，也可能整段进入模型上下文。
- **静态过期**。换了工作、换了技术栈没更新，Agent 会一直用旧画像推理。建议每月自查一次，或让 Agent 主动问"画像需要更新吗"。
- **职责不清**。规则很简单：稳定超过一个月的事实进 USER.md，其余留在 MEMORY.md，定期让 Agent 归档。
- **过度约束**。"永远简洁"这类绝对化表述，会在你需要深度分析时反向限制它。改成"默认简洁，可要求展开"。

## 可复用建议

- 五段模板足够：身份 / 环境 / 偏好 / 当前项目 / 边界。
- 把"边界"段当成给 Agent 的最小权限声明来写，这是全文件性价比最高的一段。
- 团队场景可按用户拆分 USER.md，配合会话路由按需加载。
- 升级 OpenClaw 后做一次自检：让 Agent 复述它理解的你的画像，与你的预期对照，偏差点就是该改的地方。

## 总结

USER.md 解决的不是"记忆"问题，而是"基线上下文"问题：把那些不该依赖模型猜测、也不该每次重复的稳定事实，固化成一份你能审计、能版本化的文件。二十分钟写完初版，之后每次偏差都变成一次五行的 diff——这大概是让 Agent 长期可用、成本最低的一笔投资。
