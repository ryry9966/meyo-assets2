最近一条消息在技术圈刷了屏：36kr 报道，DeepSeek 发布新论文，公开了自家的 Agent 训练方法，作者列表里出现了创始人梁文锋的名字。对一家常年“只发论文、不开发布会”的公司来说，这个动作本身就是信息量——Chat 模型的故事讲完了，下一章的主角是“会干活的模型”。这篇论文到底揭示了什么？Agent 训练和普通 LLM 训练差在哪？这篇把技术脉络拆开聊聊。

## 一、从“答题”到“干活”：Agent 是 LLM 的下一站

大模型这两年走的是一条清晰的三级跳：

1. **Chat 阶段**：模型学会对话，本质是“陪聊”，比拼语言流畅度；
2. **Reasoning 阶段**：R1、o 系列把推理拉上台面，模型开始“先想后答”，比拼思考深度；
3. **Agent 阶段**：模型学会调用工具、拆解任务、多步执行——从“说得好”变成“干得成”。

一个完整的 Agent = 模型 + 工具（代码执行器、浏览器、API）+ 环境 + 多轮交互。评测也跟着换赛道：以前看 MMLU、GPQA 这种“考试题”，现在看 SWE-bench（修真实 GitHub issue）、WebArena（操作网页完成任务）这种“工作任务”。

行业背景摆在那：OpenAI 的 Deep Research、Anthropic 的 Claude Code，加上国内一批 Agent 产品，都在抢同一块地——“把任务交出去，把结果收回来”。谁能把 Agent 训练工业化，谁就摸到下一代入口。

## 二、论文的核心思路：让模型去真实环境里“挨打”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/728c9d8759b4292d.png)

综合公开报道和论文披露的信息，核心思路可以拆成四个关键词：

- **RL 而不是 SFT**。SFT（监督微调）是“抄作业”——给模型看人类示范的标准轨迹，学得快，但上限低，遇到没见过的坑就歇菜。RL（强化学习）是“自己试错”——模型自己行动，环境给反馈，奖励设计对了，能力就自己长出来。
- **路径有迹可循**。R1 已经用 GRPO 加规则奖励证明过一件事：纯 RL 能把推理能力“练”出来，不需要人工标注思维链。Agent 训练是同一套哲学往长程任务上的延伸。
- **真实环境优先**。合成沙箱里的“假问题”容易让模型学会投机取巧（reward hacking），而真实环境的任务自带分布多样性。换句话说，环境本身就是最大的数据集，不用人工造题。
- **可验证奖励 + 经验驱动**。代码能不能跑通、测试过没过、任务验收标准是否达成——这类奖励不依赖人打分，才能大规模 scale。同时，成功轨迹是教材，失败轨迹同样是资产，模型从真实交互经验里持续进化。

打个比方：带新员工，最好的方式不是让他背 SOP，而是让他直接接真实工单，挨骂、复盘、再上。

## 三、训练 Agent，比训练 Chat 模型难在哪？

听起来很美，但 Agent 训练的工程难度是台阶式上升的：

1. **奖励稀疏且延迟**。一个任务跑几百步才知道成败。第 3 步那次错误的搜索，和第 200 步失败的调用，锅算谁的？credit assignment 是 RL 的老难题，在长程任务里被成倍放大。
2. **环境成本高**。训练 Chat 模型，“环境”只是文本；训练 Agent，环境是可交互系统——沙盒、浏览器、代码执行器，每一个都要并发、隔离、低延迟。环境一卡，rollout 就卡。
3. **轨迹数据贵**。一条长任务轨迹动辄几十次工具调用、上百万 token，采样本身就是算力大头。
4. **Infra 是隐形门槛**。生成与训练交替进行的异步系统、超长上下文、大规模 RL 基础设施——DeepSeek 敢啃这块，和它 V3 时代攒下的工程底子直接相关：671B 参数的 MoE 架构只激活 37B，训练成本被压到业内闻名的水平，靠的就是工程效率。
5. **评测更难**。考试题会泄漏（contamination），真实任务又难标准化。这也是为什么大家越来越看重“真实环境里的通过率”。

## 四、梁文锋署名，传递的是什么信号

把这件事放在技术商业视角看，有三层含义：

- **优先级信号**：创始人的名字通常出现在公司最押注的方向上。Agent 不是某个团队的探索项目，而是公司级路线。
- **生态信号**：参考 R1 之后开源推理模型扎堆出现的节奏，头部玩家公开方法论，会直接影响开源社区的技术选型和人才流向。
- **一句冷话**：论文公开不等于能力公开。replication 的坑从来写在论文没说的地方——数据细节、infra 配方、那些“显而易见所以没写”的取舍。

## 五、冷思考：给三拨人的三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/7f648ca35d162193.png)

1. **开发者**：把 Agent 项目从“提示词工程”升级为“环境工程”。设计好工具集、日志和验收标准，比反复调 prompt 收益高一个量级；把任务拆成可验证的小单元，奖励才可计算。
2. **企业落地**：先把 trajectory 数据攒起来。用户真实使用产生的成功/失败轨迹是最稀缺的资产——模型可以换，带上下文的真实环境回放搬不走。
3. **读论文的人**：抓三个变量——奖励怎么定义、环境怎么搭、失败样本怎么用。凡是只展示成功 Demo、不谈失败率的宣传，都多留一个心眼。

Agent 的竞争，本质上是“谁能让 AI 在真实世界里犯错、复盘、再犯错”的竞争。DeepSeek 把方法摊开了，剩下的部分——环境、数据、耐心——各家得自己练。
