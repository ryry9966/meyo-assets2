## 背景

OpenClaw 的 Agent 每次会话启动时，都会从工作空间读取一组 Markdown 文件来重建上下文：身份、记忆、工具说明，以及本文的主角 AGENTS.md。它本质上是一份写给 AI 的操作手册——不负责解释“你是谁”，而是规定“在这个工作空间里怎么干活”。社区里不少人把 AGENTS.md 当成 README 的附属品，写两行就完事，跑一段时间发现 Agent 行为飘忽才回头补课。这篇帖记录我重写自家 AGENTS.md 的过程和结论。

## 问题

没有一份像样的 AGENTS.md 时，典型症状有三类：

1. **重复犯错**：明明上周纠正过“不要直接动部署目录”，新会话又来一遍。
2. **风格漂移**：提交信息、回复格式、目录约定每次都不一样，全凭运气。
3. **越界操作**：Agent 热心过头，未经确认就发消息、改配置、清理“看起来没用”的文件。

根因很朴素：模型没有跨会话记忆，任何约束如果没有落到每次都会加载的文件里，就等于不存在。

## 做法

我的 AGENTS.md 固定为五段，总量控制在 120 行以内：

1. **工作空间事实**：这个目录是什么、关键路径在哪、哪些服务在跑。只写 Agent 无法自己发现的硬信息。
2. **常规操作**：构建、测试、部署的具体命令。直接给可复制执行的完整命令，不要写“参考某某文档”。
3. **约定**：命名、提交信息格式、回复格式。写成可判定的规则，例如“提交信息用祈使句，不超过 50 字”，而不是“保持整洁”。
4. **禁止事项**：这是最有价值的一段。列红线：不删除不认识的文件、对外发消息前先确认、不改动 .env 之类。
5. **升级路径**：遇到拿不准的事，停下来问人，附上上下文，而不是自行猜测。

写完做一次验证：开全新会话，问它“这个工作空间怎么测试？哪些事你需要先问我？”答不上来的段落，就是没写清楚的段落。

## 踩坑点

- **写成 README**：背景介绍、架构故事塞进去没有用，Agent 需要的是操作规程。
- **贪长**：超过两三百行后指令互相稀释，靠后的规则经常被忽略。删到每一行都有明确触发场景为止。
- **形容词式约束**：“小心一点”“注意安全”没有执行力，必须翻译成具体动作。
- **和其他文件打架**：OpenClaw 工作空间还有 SOUL.md、TOOLS.md 等文件，身份和工具说明放它们那儿；AGENTS.md 只管行为规程，重复且矛盾的规则会让输出随机化。
- **塞密钥**：有人把 API key 直接写进去“方便 Agent 用”，等于把钥匙贴在门上。密钥走环境变量，文件里只写“凭据在环境变量 X 中”。

## 可复用建议

- 把 AGENTS.md 纳入 git 版本管理：Agent 每犯一个新错误就补一条规则，把它当事故复盘记录用。
- 规则统一用“条件 + 动作”句式：遇到什么情况，做什么或不做什么。
- 多项目的用户给每个工作空间一份独立的 AGENTS.md，公共约定抽出来，别复制粘贴出三份各自腐烂的副本。
- 每月清理一次：不再触发的规则果断删掉，文件越短越可靠。

## 总结

AGENTS.md 不是配置项，而是你和 Agent 之间的接口契约。写它的成本很低，收益是所有后续会话的确定性。原则一句话：Agent 该知道的硬事实、该遵守的硬规矩、该问人的硬边界，全部落在文件里，剩下的才交给模型。
