DeepSeek 九月底挂出一篇二十多页的综述《Towards Experience Manufacturer: A Survey on Large Language Model Agents》，主题直指大规模 Agent 训练，梁文锋出现在作者名单里。一家以“论文少而硬”著称的实验室，为一篇综述投入这种篇幅，本身就是信号：这不是文献整理，更像一份路线图。论文把 LLM 概括为"token 制造商"，把下一代 Agent 定义为"经验制造商"——一字之差，背后是数据形态、训练范式和产业机会的整体切换。这篇就把它拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/776fbd1bcfb881a5.png)

## 一、一篇综述为什么值得刷屏

- **作者配置不寻常**：一作邵智宏是 DeepSeekMath 的一作、GRPO 算法的主要提出者，也位列 R1 论文。梁文锋此前在 V3、R1 技术报告里也署名，但那些是“交结果”，这次是“指方向”。
- **实验室综述的潜规则**：头部 lab 不会为综述而综述。二十多页、上百篇引用的长文，通常是在给内部团队和整个生态画靶子——“我们认为瓶颈和金矿在这里”。
- **全文一句话论点**：预训练把互联网文本压进权重，是“制造 token”；Agent 应该在环境里反复交互，把原始轨迹提炼成可复用的经验，是“制造经验”。前者的燃料在见底，后者刚刚点火。

## 二、数据墙：为什么必须换燃料

1. Epoch AI 在 2024 年测算：按当前消耗速度，公开的高质量人类文本将在 2026—2032 年间被用尽。预训练边际收益递减，头部实验室集体转向 RL 与后训练。
2. 但 R1 那套 RL 主要解决“思考”——数学、代码这类有标准答案、可自动验证的任务。Agent 要解决的是“行动”：多步、长程、带工具、在真实环境里试错。
3. 更麻烦的是，Agent 没有现成的“互联网”。预训练面对的是整个网页语料，而 Agent 的行动轨迹数据近乎为零——每一次浏览器操作、每一次代码提交都得现场 rollout，又慢又贵。
4. 所以论文的潜台词是：谁能源源不断、低成本地生产和提纯“经验数据”，谁就握住了下一轮 scaling 的阀门。

## 三、现在的 Agent 到底卡在哪

- 主流配方一直是：基座模型 + 精心打磨的 System Prompt + 手工工作流（RAG、工具编排、反思模板）。业界戏称"workflow 套娃"，好用，但天花板明显。
- 三个结构性问题：
  1. **不泛化**：为 A 网站写死的操作流程，换 B 网站就碎；在 Python 仓库调好的 pipeline，换个 Go 项目从头再来。
  2. **误差累积**：一个 50 步的任务，就算单步成功率高达 97%，全程成功率也只剩 0.97⁵⁰ ≈ 22%。长程任务奖励稀疏，RL 里的 credit assignment 相当痛苦。
  3. **评测与现实脱节**：SWE-bench Verified 上顶级模型已过 70%，但题目高度结构化；换到 OSWorld 这种真实电脑操作基准，人类能拿 72%，2024 年初最强模型只有 12%，一年半后顶级系统也就在 40%—60% 区间徘徊。
- 论文的判断很直接：瓶颈不在提示词写得好不好，而在于“经验”没有被系统性地生产、精炼和复用。

## 四、药方：探索、收割、精炼、复用

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/41b77ea2769a106c.png)

论文给经验画了一条完整的生命周期，载体分两类：

1. **隐式经验（烧进权重）**：用 RL 把环境反馈变成能力。R1 已经验证过这条路——在可验证奖励上做强化学习，模型自己长出长链思考。Agent 版本就是把“标准答案”换成“环境回报”。
2. **显式经验（外挂挂载）**：记忆库、技能库、工作流库。代表作是 2023 年 NVIDIA 的 Voyager——在 Minecraft 里把学会的操作固化成代码技能，遇新任务先查技能库，查不到再探索，学完存回去。

几个关键细节：

- **精炼是核心工序**：一条原始轨迹动辄几十万 token，每次点击、报错、重试都在里面，直接存等于堆垃圾山。必须蒸馏成紧凑的记忆、可调用的技能、可迁移的工作流。类比一下：老员工和新员工的差距，从来不是看过多少代码，而是复盘笔记的质量。
- **环境工程被抬到核心位置**：沙箱、模拟器、benchmark、工具 API，就是经验制造的“车间”。先例是 AlphaZero 的自对弈——引擎自己生产训练数据；“经验制造商”就是把这套逻辑搬到 Agent 身上。
- 两条回路互补：RL 改权重，慢但学得深；记忆/技能外挂，快但偏浅。

## 五、产业视角：机会在哪，坑在哪

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/32970ad6f4986b33.png)

- 三层格局正在成形：
  1. **模型层**：RL 后训练，拼算法效率和算力，DeepSeek 的主场。
  2. **环境层**：高质量沙箱、可自动验证的任务、评测框架——这是新的“数据护城河”，类似当年的标注产业，但技术密度高得多。谁先把环境造出来，谁的飞轮先转。
  3. **应用层**：垂直场景 Agent 的胜负手，正在从 prompt 技巧变成“有没有闭环数据”。
- 对开发者，两件事值得马上做：
  - 从第一天就记录 trajectory：工具调用、报错、修复路径，全量落盘。这是未来 RL 的原料，现在不攒，以后没得炼。
  - 优先挑“能自动打分”的场景：有单元测试、能对账、能回归验证的任务，才是 RL 咽得下去的菜。
- 顺便记一笔成本账：一次长程 Agent 任务动辄几十万 token（含重试），失败率一高，账就没法看——“全自动”叙事绕不开这道算术。

## 六、收尾前三条冷思考

1. **先问奖励，再谈智能**：动手做 Agent 前，先确认场景里有没有一个廉价、稳定的自动评分器。没有就先造评测，否则所有优化都是盲飞。
2. **提示词红利在缩水**：论文的潜台词是，手写工作流是脚手架，不是大楼。真正的壁垒是“数据管线 + 环境反馈”组成的飞轮，越早转起来越好。
3. **对“Agent 元年”之类的说法保持钝感**：方向已经清楚（制造经验），但环境工程、成本、安全三个约束一个都没解。没有近路，只有探索、复盘、复用——虾在海底靠钳子试错攒经验，Agent 大概也一样。
