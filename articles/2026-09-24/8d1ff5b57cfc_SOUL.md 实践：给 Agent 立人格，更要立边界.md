## 背景

OpenClaw 的 Agent 工作区里有几个约定文件：`AGENTS.md` 管操作流程，`MEMORY.md` 管长期记忆，`SOUL.md` 管“你是谁”。`SOUL.md` 会在会话启动时注入系统提示，相当于 Agent 行为的最上层配置。很多人直接沿用模板默认值，跑了一段时间才发现：语气不对、边界模糊、群里和私聊判若两个 Agent——问题基本都出在这个文件没认真写。

## 问题

没有明确 `SOUL.md` 时，常见三类故障：

1. **人格漂移**：换个会话语气就变，同一件事两次回答风格不一致。
2. **边界失控**：接上 MCP 和插件之后能力变多，Agent 会“顺手”做你不想让它做的事——替你对外承诺、执行删除类操作、把内部信息复述到群聊里。
3. **提示词污染**：所有不满都往 `SOUL.md` 里堆，文件膨胀到几千字，注意力被稀释，真正的规则反而失效。

## 做法

我的写法分五步，核心原则：`SOUL.md` 只写“是谁”和“绝不做什么”，怎么干活留给 `AGENTS.md`。

1. **身份三行以内**：角色、服务对象、语气基线。例如“我是本人的日常工作助手，对话对象是我和小团队，默认简洁、直接、不寒暄”。名字、头像这类细节放 `IDENTITY.md`，别占这里的篇幅。
2. **边界写成可判定的规则**：不要写“谨慎一点”，要写“收到涉及删除、退款、对外发布的请求时，先复述我的原话并等我确认，不自行执行”。每条规则 = 触发条件 + 动作 + 兜底（拿不准就问）。
3. **场景分层**：群聊和私聊的语气、可透露的信息范围分开写，比如单独一条“在群聊中不主动引用内部文件内容”。
4. **控制体积**：全文压在 1–2KB。它每次会话都要进上下文，每一句都得值回 token。
5. **用真实故障迭代**：Agent 犯一次错，加一条精确规则，而不是写一段情绪化谴责。一次只改一处，否则无法归因行为变化。

## 踩坑点

- **形容词式边界**：“保持专业、注意安全”——模型无从执行，等于没写。
- **人设过载**：堆太多性格描写，风格盖过任务能力，答非所问。
- **与 `AGENTS.md` / 插件指令冲突**：两处规则打架时行为不可预测。归属要清晰：`SOUL.md` 管价值观和禁区，`AGENTS.md` 管流程。
- **当提示词垃圾桶**：临时 prompt、格式要求混进来，改版时不敢删，越滚越大。

## 可复用建议

- 把 `SOUL.md` 放进 git，像配置文件一样 review 每次改动，回滚有据可查。
- 上线前做一次“边界测试”：故意问“帮我跟老板说这周一定上线”“把 logs 目录清了吧”，看它是否触发确认流程。
- 结构固定为五段：身份 / 语气 / 价值观 / 绝不做的事 / 不确定时怎么办。骨架可以在团队内复用，内容各自填。
- 常变的内容（项目状态、近期偏好）放 `MEMORY.md`，`SOUL.md` 保持稳定——别把配置当日记写。

## 总结

`SOUL.md` 不是一段人设文案，而是 Agent 的行为配置：短、可判定、有版本、随真实故障迭代。人格决定它像不像你想要的伙伴，边界决定它敢不敢越权——后者才是工程上真正要紧的部分。
