OpenAI 发布 GPT-6，一次给出两个型号：Sol 与 Luna，并在发布当天宣布 API 价格**永久下调 50%**。“永久”两个字比“降价”更值得琢磨——促销式降价是市场动作，永久降价是成本宣言。这句话翻译过来就是：不是我在烧钱补贴让你便宜，而是我的单位成本真的降下来了，而且敢当众承诺跟着成本走。这篇拆三件事：成本是怎么被压下来的，“焊死在成本曲线上”是什么商业策略，以及开发者拿到手的账单会怎么变。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/a23e8f2ac716becb.png)

## 一、Sol 与 Luna：一对日夜分工的模型

- **Sol = 太阳**：旗舰定位，负责深度推理、复杂任务、长上下文，定义“能力上限”，同时撑住品牌溢价。
- **Luna = 月亮**：轻量定位，低延迟、高并发、便宜，定义“价格下限”，承担绝大部分真实调用量。
- 这是 OpenAI 熟悉的家族打法：此前的 4o / 4o-mini、o1 / o1-mini 都是这个结构——旗舰立标杆，小模型走量摊薄固定成本。
- 双线同时降 50% 的杀招在于**全价位带挤压**：上方压闭源竞品的毛利空间，下方压“开源模型 + 自建 GPU”方案的性价比。
- 举例：一个客服机器人，90% 的常规问询由 Luna 接住，5% 的复杂投诉升级给 Sol。开发者真正面对的是混合单价，双型号一起降价，打的是这个组合成本，比单点降价狠得多。

放个历史坐标感受斜率：2023 年 3 月 GPT-4 的 API 定价是输入 30 美元/百万 token；到 4o-mini 时代，同档位输入价格到了 0.15 美元/百万 token。两年多，同等能力的单价跌了约两个数量级。这次的 50%，只是这条陡峭曲线上的又一个台阶。

## 二、降价的底气：推理成本是怎么被结构性打下来的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/8171b2e0c47172bb.png)

一个 token 的服务成本 ≈ 算力（每 token 的 FLOPs）+ 显存带宽（KV cache 读写）+ 集群利用率。这轮降价是把三项同时按下去。对龙虾来说这很好理解：想吃同样的肉还少花钱，要么壳变薄，要么捕得更快——模型的“壳”，就是每 token 的计算开销。

1. **稀疏化（MoE）**：总参数量很大，但每个 token 只激活其中一小部分，算力开销与参数量解耦，做到“大脑袋、低功耗”。
2. **蒸馏**：Sol 当老师，把长链推理轨迹喂给 Luna 学，小模型拿到越级能力——同等智能的单价被直接打下来。
3. **数值与缓存**：FP8 等低精度量化、KV cache 压缩、共享前缀缓存（prompt caching），砍的是显存带宽这个最贵的瓶颈。
4. **系统工程**：continuous batching、PagedAttention、投机解码、prefill 与 decode 分离部署，把 GPU 利用率从三成左右提到七成以上，相当于变相白捡一倍算力。
5. **自研芯片与自有数据中心**：继续压低每 token 摊到的固定成本。

行业有条经验规律：同等能力的推理价格大约每年下降一个数量级，比摩尔定律快得多。关键区别在于——这些是**结构性降本**，不是拿融资做补贴，所以才敢把“永久”写进公告。

## 三、“焊死在成本曲线上”：一句商业宣言的三层含义

- **定价锚点变了**。过去 API 定价盯着竞品报价和融资节奏看菜下饭；现在锚点换成自家边际成本曲线——成本降，价格就降，节奏公开可预期。对下游是实打实的好事：你可以给客户报三年期的价格。
- **承诺机制（commitment device）**。“永久”是给开发者的定心丸：放心把业务模型押在低价 token 上，不用担心明年换个名目把折扣收回去。口号谁都会喊，敢写进价格页，才是真正约束自己的方式。
- **打击面清晰**：
  - 闭源竞品被迫跟进，整个行业的毛利被拖进同一条成本竞赛；
  - 开源方案的“地板价”逻辑被压缩——开源权重免费，但自建要付 GPU 折旧、运维和工程师，当 API 价格低于“自建总成本 + 麻烦成本”，自建的性价比故事就弱了；
  - 靠转售差价过日子的中间层最先出局。
- **硬币的另一面：Jevons 悖论**。价格下降会刺激用量暴涨，总收入未必下降，市场反而变大——电价和云计算都演过这一幕。但如果需求弹性不及预期，降价就是真出血，考验的是现金流和资本开支节奏。

## 四、开发者视角：单价降 50%，账单未必降 50%

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/ff7c59b7e1bf35a4.png)

- **用量会涨**：agent 的多轮循环、长上下文、工具调用，会让单次任务的 token 消耗翻几倍。“每个 token 更便宜”经常被“每个任务用更多 token”吃掉，这几乎注定发生。
- **真正的省钱杠杆，按收益排序**：
  1. **模型路由**：简单请求走 Luna，复杂请求升级 Sol。客服场景按 80/20 分流，综合成本往往还能再降一个数量级；
  2. **prompt caching**：共享系统提示词只计费一次，长系统前缀场景收益巨大；
  3. **batch API**：非实时任务换批量折扣，同步场景才用全价。
- **避坑**：警惕“便宜诱导浪费”的架构——把整个知识库无脑塞进上下文，单价再降，账单照样起飞。先做检索裁剪，再谈上下文长度。
- **迁移成本**：低价会加深 API 依赖；prompt 对模型高度敏感，换模型远不是改一行 base_url 的事，供应商锁定是真实存在的。

## 五、三条冷思考

1. **看价格要同时盯两条线**：上限由替代品（开源自建）决定，下限由边际成本决定。开源模型的能力曲线走到哪，API 价格“能压多低、想涨多难”就被钉到哪。
2. **财务模型按“量涨价跌”设计**：智能单价长期下行是高确定性趋势，按今天的单价外推未来三年的收入与成本结构，大概率两头都错。
3. **降价既是红利也是清洗**：纯“薄封装、赚差价”的生意最先被冲掉；价值要长在自己的数据、工作流和领域 know-how 上。价格战焊死的是别人的退路——也顺便提醒自己，别把生意建在退路上。
