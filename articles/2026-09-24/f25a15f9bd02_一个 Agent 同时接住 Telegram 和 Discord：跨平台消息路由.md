## 背景

我的日常聊天在 Telegram，项目社区在 Discord。最初图省事跑了两个 Agent 实例，各自接一个平台。跑了一个月问题就来了：系统提示词改了一边忘另一边，工具插件版本漂移，最难受的是两边记忆完全隔离——我在 Telegram 交代过的上下文，去 Discord 问它一无所知。于是决定收敛成一个 Agent 实例，两个平台只是不同的入口。

## 问题

拆开看其实是三件事：

1. **会话隔离与记忆共享的边界**：不同平台、不同群聊的对话上下文必须独立，但长期记忆（用户偏好、项目背景）应该共享；
2. **平台格式差异**：Discord 单条消息 2000 字符上限，Telegram 是 4096，且 Markdown 方言不同，Telegram 用错 parse_mode 会整条发送失败；
3. **身份映射**：两端的用户 ID 体系完全不同，不做映射的话，同一个人在 Agent 眼里是两个陌生人。

## 做法

**第一步，双通道注册。** 在网关配置里同时声明两个 channel（字段名以你版本的文档为准，以下是示意）：

```json
{
  "channels": {
    "telegram": { "botToken": "****", "dmPolicy": "pairing" },
    "discord":  { "token": "****", "guildAllowlist": ["..."] }
  }
}
```

**第二步，会话键设计。** 会话按 `{channel}:{chatId}` 隔离，私聊、群聊、频道各自独立上下文。共享的部分不进会话，而是落到工作区文件和长期记忆里，Agent 通过工具按需读取。

**第三步，身份映射。** 建一个简单的映射文件，把两个平台的用户 ID 指到同一个人标识。这一步做完，跨平台对话的连续性才真正成立。

**第四步，输出适配。** 在注入给 Agent 的上下文里带上当前平台标记，让它知道自己在哪说话；超过长度上限的消息按平台规则分段或折叠，代码块优先保完整。

**第五步，灰度上线。** 先在 Discord 只开 @提及触发、Telegram 只开私聊白名单，跑一周观察日志，再放开权限。

## 踩坑点

- **Telegram 文件下载**：Bot API 拉取文件有 20MB 上限，大图大文件要么压缩引导，要么走 MCP 工具换通道拿；Discord 附件链接有有效期，别把原始 URL 存进记忆，存下载后的本地路径。
- **Markdown 发送失败**：Telegram 开 MarkdownV2 后，未转义的字符会让整条消息被拒。工程上做降级：格式化发送失败就回退纯文本重发，别让用户看到"静默丢消息"。
- **分段发送撞限速**：长回复拆成多条在 Discord 很容易触发 per-channel 限速。能用换行拼接就别拆条。
- **自回环**：如果额外搭了平台间桥接，注意 Agent 会对自己转发的消息再回复一次。必须在路由层明确"不响应任何 bot 身份的消息"。
- **会话键写错**：出现过群聊消息落进了私聊会话、表现为"失忆"的情况。排障第一步永远是看日志里的 session key，而不是重启。
- **群聊触发语义差异**：Telegram 群里 @机器人 和 Discord 的提及行为不一致，触发规则按平台分开配置，不要假设一份规则通吃。

## 可复用建议

- **会话隔离、记忆共享**，这条边界想清楚，80% 的设计争议就没了；
- 身份映射独立成文件维护，日志里统一打上 `{channel}:{userId}` 标签，跨平台排障效率翻倍；
- 新平台接入时先只读、后应答、再放开群聊，每一步留观察期；
- 路由策略全部写进配置，不要散落在提示词里靠模型"自觉"。

## 总结

跨平台路由的核心不是把两个 bot 拼起来，而是把"入口"和"大脑"分开：入口负责协议适配和格式转换，大脑只维护一份会话与记忆。做完这套收敛，配置漂移清零，记忆终于跟人走了——这才是单实例多通道的真正收益。
