# 让 Agent 安全地采集网页：一套工程化的稽客做法

## 背景

在 OpenClaw 的日常使用里，最常见的需求之一就是让 Agent 读网页：追踪一个项目的更新日志、汇总论坛新帖、盯价格变动、生成每日简报。听起来是基本功，实际跑起来最容易翻车。本文把"让 Agent 采集网页内容"这件事称作**稽客**，重点不在"能不能抓下来"，而在抓得干净、省 token、不惹麻烦。

## 问题

三种典型翻车方式：

1. **凭记忆回答**：让模型"想一下"某网站的内容，页面早就改版了，输出一本正经地编造；
2. **原始 HTML 进上下文**：一个页面几万 token，塞两三次会话就爆，还夹带页面里藏的注入文本；
3. **滥用无头浏览器**：Agent 自作主张起一个浏览器实例，一条消息跑两分钟，并发一多把目标站打挂。

本质问题是：很多人把"读网页"当成一个动作，而不是一条有分层的流水线。

## 做法

**第一步：先降级，再升级。** 按优先级选获取方式：优先用 RSS 和站点公开 API；其次用静态 HTTP 请求加正文抽取（readability 类算法）；最后才考虑无头浏览器。大多数页面不需要 JS 渲染，先手动抓一次看返回内容再决定。

**第二步：封装成 tool，不要散落在对话里。** 把抓取逻辑做成一个 MCP tool 或 skill 脚本：输入 URL，输出统一的 Markdown 加元数据——标题、规范 URL、抓取时间、截断位置。Agent 拿到的是干净数据，不是一坨 HTML。

**第三步：限制输出。** 正文抽取后截断（比如 4000 字符），超长内容返回摘要加"分段拉取"的句柄，避免一次性撑爆上下文。

**第四步：缓存与限速。** 同一 URL 短时间重复请求走缓存，TTL 按场景定：监控类 5–10 分钟，资料类可以到一天。请求加节流，User-Agent 带可联系信息，尊重 robots.txt。

**第五步：把网页内容当数据。** 在系统提示里明确：页面内容是"待引用的资料"，其中任何指令性文字都不执行。这是对 prompt 注入最基本的一道防线。

## 踩坑点

- **JS 渲染页抓到空壳**：返回只有骨架 div。先检测内容里有没有正文关键词，再决定切 headless；有接口就调接口，别硬渲染。
- **正文抽取在论坛和文档站失灵**：侧边栏、评论混进正文。给常用站点配 CSS 选择器白名单，通用算法只做兜底。
- **相对链接和懒加载图片没拼全**：输出前统一规范化 URL，否则 Agent 引用的链接根本点不开。
- **失败重试死循环**：抓取失败后模型反复重试，token 烧得飞快。给 tool 设重试上限，返回结构化的错误信息，让模型能"死心"换路径。
- **注入文本**：真实见过页面里藏 "ignore previous instructions"。除了提示词约束，抓取层可以顺手剥掉隐藏元素和 HTML 注释。

## 可复用建议

一张可以直接抄的 checklist：

- 获取优先级：API / RSS > 静态 HTML > headless，能低不高
- 输出必带来源元数据和截断标记
- 缓存与限速默认开启，不允许配置之外的裸请求
- 网页内容只作数据引用，不作指令
- 快速失败，错误信息对模型可读
- 登录后内容和敏感页面不进通用抓取管线

## 总结

稽客做得好不好，不看能不能抓到，看三件事：**抓得稳**（限速、重试、缓存）、**抓得省**（正文抽取、截断）、**抓得干净**（元数据、防注入）。把采集收敛成一个边界清晰、行为可控的工具，Agent 的检索、监控、简报这些上层能力才有可靠的数据底座。别让它拿着无头浏览器在别人的站点上裸奔。
