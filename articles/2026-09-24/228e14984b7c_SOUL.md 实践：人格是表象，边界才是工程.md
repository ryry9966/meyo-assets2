## 背景

OpenClaw 的工作区里有几个约定俗成的 Markdown 文件：`AGENTS.md` 管操作规程，`USER.md` 存用户画像，`SOUL.md` 定义"这个 agent 是谁"。它会在会话启动时注入系统提示词，相当于 agent 的长期人格层。不少人把它当可选装饰，写一句"你是一个友好的助手"就完事。但跑过一段时间自动化后会发现：这份文件真正值钱的不是人格描述，而是边界条款。

## 问题

没有明确边界的 agent，在长会话和自动化场景里会漂移：

- **语气漂移**：工作时段正经干活，深夜陪聊越走越远；
- **越权执行**：MCP 工具链一多，agent 会"好心"替你做没确认的操作——直接发消息、删文件、改配置；
- **风格不一致**：换个会话像换了个模型；
- **拒绝方式糟糕**：该拦的时候瞎编，不该拦的时候堆免责声明。

这些问题靠"调教话术"治标不治本，得落进文件里。

## 做法

一份可落地的 SOUL.md，控制在 30–40 行以内，五个段落：

1. **身份与语气**（5 行以内）：一句话定位 + 语气基线。例："语气直接，先给结论再给理由，不用表情符号。"
2. **NEVER 清单**：写成可判定的行为，不是态度。差的写法："注意安全"；好的写法："NEVER 在未经我明确回复'确认'的情况下向任何群聊发送消息。"
3. **升级规则**：什么情况必须停下来问人。涉及付费、删除、对外发送、修改生产配置，一律暂停等待确认。
4. **拒绝方式**：直接说做不到 + 一句原因 + 给替代方案，不堆免责声明。
5. **语言与格式偏好**：默认中文、代码注释语言、Markdown 结构习惯。

写完放工作区根目录，开新会话验证：让 agent 复述它被告知的行为准则，确认注入生效。

## 踩坑点

- **写成小作文**：SOUL.md 每轮都占上下文，几百行的人设模型记不住重点，30 行内反而执行力强；
- **和 AGENTS.md 打架**：SOUL.md 说"谨慎"，AGENTS.md 说"失败自动重试"，冲突时行为不可预测。人格管"是什么"，规程管"怎么做"，别交叉；
- **边界太抽象**："要有分寸"无法执行，模型只能瞎猜；
- **不做版本管理**：SOUL.md 就是配置，进 git，改动写清楚 commit message，出问题能回滚；
- **一次写完不迭代**：跑两周，把实际发生的越界行为反写成 NEVER 条款——这是最有效的条款来源。

## 可复用建议

- 模板五段：身份 / 语气 / NEVER 清单 / 升级规则 / 语言偏好；
- 每条边界都要能回答"怎么判定违反了"；
- 定期做对抗性测试：诱导它发消息、删东西、装熟人，看是否拦截；
- 多 agent 场景下，每个 agent 一份独立 SOUL.md，不要共享；
- 职责分文件：SOUL.md 管人格与红线，AGENTS.md 管流程，USER.md 管事实。

## 总结

SOUL.md 的价值不在于让 agent "更有个性"，而在于把你的风险偏好显式化。人格是表象，边界才是工程。先写 NEVER 清单，再谈语气；30 行以内，进版本控制，按实际事故迭代。这样一份文件，比任何话术都可靠。
