## 背景

RSS 依旧是最可控的信息获取方式：格式稳定、可自托管、不受推荐算法干预。但订阅源一多，每天上百条条目人工全读不现实。我的目标是：机器负责抓取、过滤、摘要，人只看每天两份定时推送的精选摘要。整条管线跑在 OpenClaw 上，模型调用走自己配的 key，数据不出本地。

## 问题

市面上的"AI 日报"类工具有三个不满：内容过第三方服务器，隐私和定制都受限；摘要粒度不可控，常把没有阅读价值的水文也认真摘要一遍；去重和状态管理基本缺失，同一条新闻反复推。所以自己搭，核心诉求是：可控过滤、按条摘要、状态可追溯。

## 做法

管线分四段，各自独立，任何一段失败不拖垮其他段：

1. **抓取**：用 Miniflux/FreshRSS 做聚合层，OpenClaw 定时任务每小时拉一次增量，原始条目先落 SQLite，guid 做主键。
2. **过滤**：规则先行——标题正则、来源权重、URL 规范化去重、近 48 小时已推过的直接丢弃。这一步纯代码实现，不花 token。
3. **摘要**：候选条目交给 agent skill 处理。feed 只给 description 的，先抓原文做正文提取再喂模型；单条摘要限定 2-3 句加一行"为什么值得看"。模型不负责生成链接，链接一律取原始 guid。
4. **推送**：攒批推送，每天早晚各一次 digest，固定模板：来源 / 标题 / 摘要 / 链接。模板写在 skill 里，改格式不动管线。

配置示意（字段名以你手头版本为准）：

```yaml
schedule: "0 8,20 * * *"
steps:
  - fetch_feeds -> sqlite
  - filter: dedupe + keywords + source_weight
  - summarize: per_item, max_sentences=3, link_from=guid
  - push: batch_digest
```

## 踩坑点

- **全文缺失**：一大半 feed 只给摘要，直接喂模型等于"摘要的摘要"。必须补一步正文抓取 + readability 提取；抓取失败的降级用 description，并在条目上打降级标记。
- **跨源重复**：同一篇内容被多个源收录，URL 参数不同导致 guid 不重复。做 URL 规范化（去 utm、统一 https）加标题相似度合并，能消掉大部分重复。
- **token 成本失控**：最初全量摘要，一天几十万 token。改成两段式后降了一个数量级——规则砍掉约 80%，LLM 只看候选。
- **模型幻觉链接**：让模型"附上原文链接"必然出错。链接永远取自原始条目，prompt 里明确禁止生成 URL。
- **推送疲劳**：每小时推一次，第二天频道就被静音了。改成每日两批 digest 后，打开率明显回升。

## 可复用建议

- **先小后大**：5-10 个源跑两周，统计命中率（推送后真的点开的比例）再加源，否则只是扩大噪声。
- **原始条目永久落库**：SQLite 成本几乎为零，后续做周报、回溯检索都靠它。
- **prompt 当代码管**：摘要模板进版本库，每次调优有 diff 可查，出问题能回滚。
- **阶段解耦**：抓取、过滤、摘要、推送各自可独立重跑，任何一段挂了不丢数据。
- **压缩与判断分开**：摘要要求里把"压缩事实"和"给出阅读判断"写清楚，只压缩不判断的摘要没有信息增量。

## 总结

这条管线没有用到任何新技术——RSS、SQLite、cron、LLM 调用，全是成熟件。真正决定可用性的是过滤规则和状态管理，模型只是最后一环。OpenClaw 在这里的角色，是把这些胶水逻辑收敛进一个可维护的 skill：定时跑、失败可查、改动可控。信息流自动化这件事，工程占八成，模型占两成。
