## 背景

OpenClaw 的 workspace 里有一组"软配置"文件：`SOUL.md` 管价值观，`AGENTS.md` 管行为规则，`MEMORY.md` 管长期记忆，而 `IDENTITY.md` 管的是最底层的一层——**它是谁**。内容通常很短：名字、形象设定、代表 emoji、整体 vibe，默认在 `~/.openclaw/workspace/IDENTITY.md`。

很多人初始化完就再没打开过这份文件。但它会被注入到系统提示的高优先级区域，直接影响每次对话的开场方式、自称和对你的称呼。

## 问题

实践中最常见的三类症状：

1. **人格漂移**：重启或换会话后，agent 的自称、语气、口头禅变了，像换了个人。
2. **实例串味**：主号和测试号共用 workspace，调试时改的身份设定污染了主号。
3. **身份滞后**：换了底层模型、加了新技能后，身份描述还停在最初版本，和实际行为对不上。

根因是同一个：身份被当成一次性装饰，而不是需要持续维护的配置资产。

## 做法

我目前的工作流，供参考：

**1. 回到最小字段集。** 保持 Name / Creature / Emoji / Vibe 四个核心字段，各一行。IDENTITY.md 应该像接口定义，而不是小作文。

**2. 划清职责边界。** 价值观和说话底线放 SOUL.md；自称规则、禁用口癖（比如"作为一个 AI"这类开头）放 IDENTITY.md；技能与流程放 AGENTS.md。三处不重复，模型才不会在两套指令间摇摆。

**3. 用 git 管身份。** 整个 workspace 进仓库，任何身份修改走 commit 并写清动机。出问题可以 diff、可以回滚，身份变更从此有据可查。

**4. 建立进化节奏。** 每月或每次大升级后，让 agent 自审一轮：把稳定出现的新习惯、新分工整理成候选条目，人工确认后合并进 IDENTITY.md。过程性讨论留在 MEMORY.md，身份文件只放结论。

**5. 多实例隔离。** 每个 agent 实例独立 workspace，IDENTITY.md 各自维护，测试号用目录后缀区分，避免交叉污染。

## 踩坑点

- **写太长**：身份文件超过半屏，核心设定被稀释，模型记不住重点，还白烧 token。
- **让 agent 免审自改**：没有人工把关的自我修改，几轮之后会漂出奇怪的自我描述。务必逐条确认再合并。
- **改了不生效**：部分客户端对 emoji/头像有缓存，先重启会话再排查配置路径是否正确。
- **SOUL 和 IDENTITY 互相抄**：两份文件内容重叠时，行为表现会不稳定，优先删重复项。

## 可复用建议

- 把 IDENTITY.md 当**版本化接口**：字段少而准，变更走 PR 思路，合并前有 review。
- **换模型后跑身份回归**：固定问三个问题——你是谁、怎么称呼我、你的风格是什么——对比前后输出，偏差超出预期就回头改文件。
- 团队场景下，把它放进 agent 初始化模板，新实例一键继承统一的身份规范，减少"每个人的 bot 性格都不一样"的维护成本。

## 总结

IDENTITY.md 的价值不在"给 bot 起个名字"这种趣味性，而在于它把 AI 的人格从散落在 prompt 里的散文，变成了一份**有版本、可 diff、可回归测试**的工程资产。身份稳定，行为才可预期；可预期，才谈得上长期协作。花半小时把这份文件治理起来，收益会体现在之后的每一次会话里。
