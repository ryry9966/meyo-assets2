又到大模型"上新季"。这一波的主角是 GPT-6 的两个型号：主打深度推理的旗舰 Sol，和主打性价比的轻量款 Luna——API 价格直接砍半，跑分还在涨。评论区一片"等等党大获全胜"，但常年盯着 API 账单的人会更关心三个问题：价格凭什么砍一半？性能卷的到底是什么？这波对做应用的人意味着什么？这篇把账摊开来算。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/342a8529c4d088ee.png)

## 一、Sol 与 Luna：先看懂"双线布局"的套路

- 命名本身就在传递产品定位：Sol（太阳）负责"想得深"，扛最难的推理任务；Luna（月亮）负责"跑得快、花得少"，接住高并发的日常请求。
- 这不是新玩法，而是行业已经收敛的标准组合拳：OpenAI 自家的旗舰与轻量系列、Claude 的 Opus/Sonnet/Haiku、Gemini 的 Pro/Flash，全是"一个旗舰 + 一条轻量线"的结构。
- 背后的账很简单：推理成本和延迟基本由参数规模、激活 token 数决定。让 80% 的简单请求走小模型，把贵的算力留给 20% 的硬任务，平台方才能既压价格又保毛利。
- 对开发者的直接含义：产品里大概率不该"全押一个模型"，做模型路由（routing）正在从加分项变成基本操作。

## 二、价格砍半，靠的不是情怀，是四个技术杠杆

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/2624a4138d197005.png)

降价一半听着像让利，实际上更像"成本确实降下来了"。大模型推理的单位成本，主要靠四个杠杆往下压：

1. **MoE（Mixture of Experts）架构**：总参数做大，每次只激活一小部分"专家"，算力账单按激活量走，模型容量和推理成本解耦。这是近几年旗舰模型普遍转向的路线。
2. **KV Cache 与前缀缓存（prompt caching）**：重复的系统提示词、固定的长文档不用每次重算，缓存命中部分的价格可以低一个数量级。对 agent 类高频调用，这是最大的省钱项。
3. **蒸馏与量化**：Luna 这类轻量款，大概率是用 Sol 当老师蒸馏出来的，再叠上 FP8/INT8 量化，把能力塞进更小、更便宜的躯体里。
4. **推理栈与硬件**：continuous batching、speculative decoding、更快的互联、专用推理芯片——这些不改变模型本身，但让每张卡的吞吐稳步上升。

历史数据可以佐证这个趋势：GPT-4 发布时输出 token 约 60 美元/百万，GPT-4 Turbo 降到 30 美元，GPT-4o 到 15 美元上下。"旗舰能力约一年后价格腰斩"这条曲线，行业已经跑了两轮，这次等于把曲线又往前推了一格。大模型的价格曲线和摩尔定律像失散多年的兄弟，唯一区别是它降得比硬件还快。

## 三、性能继续卷：卷的其实不是跑分

- 榜单通胀已是共识：MMLU、GPQA、AIME、SWE-bench 分数节节走高，但"会做题"和"会把活干完"是两回事。真正拉开差距的是这几个维度：
  1. **长程 agentic 能力**：多步工具调用不崩、不陷入幻觉循环，能把一个任务从头执行到尾。
  2. **长上下文的有效利用率**：号称 1M context，中间段落能不能被稳定检索和引用，比数字本身重要。
  3. **指令遵循与输出稳定性**：对做产品的人，JSON 格式不抖、字段不漏，比跑分高 2 分值钱得多。
  4. **多模态的实用化**：看图、读表格、听语音，直接输出结构化结果，而不是"能看"就行。
- 还要警惕一个反直觉的账：agent 一次任务可能几十上百次调用。token 单价砍半，但如果降价让你"敢上 agent 了"，总消耗可能是原来的十倍——这就是 Jevons 悖论：效率提升，总量暴涨，团队总账单未必下降。预算要按"单位任务成本"算，别按"每 token 单价"算。

## 四、对应用开发者：三个机会，三个坑

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-24/0a9c514b73e02ffe.png)

机会：

- 以前算不过账的场景成立了：高频摘要、客服回复、内容审核、批量文档处理，成本砍半往往意味着从"不可行"变成"可规模化"。
- agent 产品门槛下降：每一步调用都便宜了，多步规划、多轮反思才敢真正上生产环境。
- 端侧与私有化路线更清晰：Luna 级别的能力下放到小模型，边缘部署、私有数据的合规方案都多了一条路。

坑：

- 新模型上线初期的稳定性折价：限流、延迟波动、行为漂移都可能发生，关键链路务必留 fallback。
- 隐性迁移成本：prompt cache、工具调用协议、结构化输出的约定，换一家供应商往往要重写一遍。
- 榜单过拟合：别人的 benchmark 不等于你的场景，没有自建评测集（eval）的团队，等于闭着眼睛切模型。

## 五、冷思考：价格战不是慈善，价值在往上走

- 平台方敢降价，前提是成本降幅大于售价降幅，同时用低价换市占率和开发者生态——典型的"毛利换规模"打法。
- 基础模型的商品化（commoditization）趋势越来越明显，利润池正加速向应用层、专有数据、分发渠道移动。
- 换句话说：单纯"套壳"的护城河会更薄，但懂场景、懂数据、懂成本架构的团队，反而迎来最好的窗口期。

## 写在最后：三条可执行的动作

1. **自建评测集**：挑 30~50 条真实业务样本，每次换模型全量跑一遍。信自己的数据，别信榜单。
2. **架构里内置路由和 fallback**：难任务给旗舰，简单任务给轻量款，多供应商兜底——光"简单请求走小模型"这一条，省下 50% 以上成本是常态。
3. **按"每任务成本"做预算**：一次完整任务的调用次数 × 单价，才算得出真实成本，也才不会被"降价一半"的叙事带偏。

价格腰斩、性能继续卷，卷到最后，受益的确实是开发者。只是别忘了：省下来的 token 钱，大概率会变成你下一个 agent 的调用量。账，永远算不完——龙虾与你共勉。
