## 背景

社区里的周报汇总、版本速递、问答精选，很多同学已经交给 OpenClaw agent 定时跑：MCP 拉数据 → agent 渲染 → 插件发帖。链路通了之后，新问题立刻浮现：帖子本身挑不出毛病，但"发帖行为"一眼假——每天 9:00:00 整准时出现，标题句式三个月不变，发完对回复零响应。一位版主的原话是："内容没问题，但我就是知道是脚本发的。"

## 问题：机器人味来自三个层面

1. **时间特征**：固定整点、固定间隔、秒级准时、节假日照发、深夜也发。
2. **内容特征**：模板唯一、emoji 固定、链接顺序不变、标题可被正则命中。
3. **行为特征**：只发不回、无 follow-up，偶发重试导致的连发重复。

拟人化的目标不是"骗过谁"，而是让自动化输出匹配社区的真实带宽：正常活跃用户不会每天整点发帖，也不会对讨论毫无反应。

## 做法：五步节律改造

**1. 调度层：时间窗 + 抖动。** 把 `0 9 * * *` 换成窗口内随机取点，且精确到秒：

```yaml
schedule:
  window: "09:00-11:30"
  jitter: uniform_seconds
  skip_if:
    - same_board_post_within: 6h
    - holiday: true
  on_low_engagement: backoff(3x)
```

**2. 预检层：发送前查上下文。** 先读目标板块：6 小时内有同源帖则顺延；当天有紧急公告则主动让路。宁可晚半天，不做"不合时宜的准时"。

**3. 内容层：模板池轮换。** 开头/结尾各备 3–5 套模板按周轮换，链接顺序打乱，标题句式至少两种。模板池进 git，改动有据可查。

**4. 行为层：回访闭环。** 发出后挂延迟任务：24 小时后回收回复，高赞纠错由 agent 二次补充或转人工。只发不回，是最强的机器人信号。

**5. 熔断层：低互动降频。** 连续几期回复率低于阈值，自动退避到 2–3 倍间隔并进入人工 review 队列——逻辑与 API 的 exponential backoff 一致：被冷落就是反馈。

## 踩坑点

- 抖动只加在分钟级，秒位仍是 `:00`，日志里一眼穿帮；
- 随机数种子固定，agent 每次重启后的"随机"序列完全相同；
- 服务器 UTC、社区 CST，抖动全落在凌晨三点——先统一时区再谈拟人；
- 重试未做幂等：用"内容 hash + 日期"做去重键，否则抖动反而放大重复发送；
- 抖动后的计划时间未持久化，进程重启任务重复入队；
- 过度随机：把发送时间铺到深夜。拟人的对象是"一个有作息的活跃用户"，不是均匀分布的噪声。

## 可复用建议

- 把发帖建成六段 pipeline：调度 → 预检 → 渲染 → 去重 → 发送 → 回访，每段独立可关；
- 永远留一条人工 review 旁路，宁可少发，不要错发；
- 衡量"像不像人"的指标是回复率、被举报数、加精次数，而不是发送成功率；
- 模板与调度参数都进版本库，行为变化可回溯。

## 总结

节奏控制的本质不是伪装，而是克制：自动化负责产能，节律负责信任。当你的 agent 学会了"晚一点发、偶尔不发、发了会回"，它才真正融入社区，而不是寄生在社区的时间轴上。
