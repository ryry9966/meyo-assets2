## 背景

OpenClaw 每次会话启动时，都会把工作空间里的 `AGENTS.md` 注入上下文。它不是项目 README，也不是人设文件，而是**给 AI 看的岗位说明书**：环境是什么、默认流程怎么走、哪些操作要先问人。本质上就是一份 onboarding 文档，只不过读者是一个每次醒来都失忆的执行体。

## 问题

实际使用中有两种典型偏差。一种是放任不管，默认模板几行字，agent 靠猜干活，行为每次会话都不一样。另一种是用力过猛：把 AGENTS.md 写成几千字散文，塞满身份背景、闲聊规则、过期的部署命令。结果上下文被垃圾占满，真正重要的指令被稀释，执行反而变差。

## 做法

1. **先分层**：AGENTS.md 管“怎么干活”，SOUL.md / USER.md 管“我是谁”，MEMORY.md 管动态记忆和待办。别把身份和当日任务塞进来。
2. **只写可执行内容**：常用命令（启动、测试、部署）、消息渠道处理规则、危险操作边界。
3. **写成指令而非描述**：“回复保持简短”不如“单次回复不超过 300 字，长任务除外”。前者是愿望，后者才是规则。
4. **用真实会话校验**：跑一周，把 agent 做错的地方逐条反写成规则。AGENTS.md 是迭代出来的，不是一次写完的。
5. **纳入版本控制**：workspace 放进 git，改规则像改代码一样有 commit，坏了能回滚。

## 踩坑点

- **写太长**：每次会话都计 token，几千字规则会让重点被淹没。经验是核心部分控制在一屏内。
- **规则冲突**：前面写“先确认再执行”，后面又写“日常任务自动处理”，模型会随机挑一个解释。写完自己通读一遍消歧。
- **塞进临时内容**：今天的待办属于 MEMORY.md，AGENTS.md 只放长期不变的东西。
- **忘了同步**：换了部署方式但没更新文件，agent 会一直用旧命令，而且理直气壮。

## 可复用建议

每条规则问自己一句：“模型读到这条，行为会变吗？”不会就删。多用小节和短句，命令用代码块包起来，模型对格式化命令的执行率明显更高。删文件、发消息、花钱的 API 调用这类危险操作，单独列一节“必须先确认”清单。多人或多设备场景下，把 AGENTS.md 当共享配置 review，谁改规则谁提 PR。

## 总结

AGENTS.md 的价值不在写了多少，而在每一条都被真正执行。把它当成需要持续维护的生产配置，而不是一次性人设文档。**写短、写具体、用会话结果反推规则**——这三个习惯最划算。
