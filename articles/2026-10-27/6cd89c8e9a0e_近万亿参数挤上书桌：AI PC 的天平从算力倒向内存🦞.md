过去两年，"AI PC"基本是个营销词：CPU 里塞一颗 40 TOPS 的 NPU，跑跑背景虚化和本地小助手。2025 年风向突变：苹果机器学习团队在 512GB 统一内存的 Mac Studio 上，把 671B 参数的 DeepSeek R1 用 4-bit 量化跑出约 17 tokens/s；英伟达 128GB 内存的桌面机 DGX Spark 正式发货，定价 3999 美元；社区甚至用 2-bit 级量化，把总参数约 1T 的 Kimi K2 塞进了桌面。近万亿参数从数据中心走进书房，不是玄学，而是内存架构、MoE 与量化三条技术线交汇的结果。这篇拆开讲：牌桌是怎么被掀的，普通人和团队该怎么接招。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/74a075aa294c5662.png)

## 三年三级跳：桌面模型是怎么一路爬上来的

- 2023：llama.cpp 带火 4-bit 量化，7B 模型第一次在笔记本 CPU 上“能跑”，个位数 tokens/s，纯极客玩具。
- 2024：消费级显卡 24~32GB 显存封顶，70B 模型要精打细算才塞得下；同期"AI PC"的官方定义锁定 NPU ≥ 40 TOPS，主打 3B~13B 小模型。
- 2025：两件事同时发生——MoE 架构普及（R1 671B、Qwen3-235B、Kimi K2 约 1T，但每个 token 激活参数只有几十 B），加上统一内存桌面机（Mac Studio 512GB、DGX Spark 128GB）成熟，几百 B 参数第一次“可日用”地跑在桌面上。

判断标准也变了：以前的“能跑”是演示，现在的门槛是“能用”——生成速度接近人类阅读速度（10~20 tokens/s），首字延迟可接受。

## 被忽视的那堵墙：决定速度的不是算力，是内存带宽

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/80e4d5ea9dffb1d1.png)

先给一个反直觉结论：大模型本地推理，绝大部分时间卡在内存，而不是算力。

- 原理一句话：生成阶段每输出一个 token，都要把一份“激活权重”从内存读进计算单元。生成速度 ≈ 内存带宽 ÷ 每 token 需读取的权重体积。
- 举例：70B 密集模型 4-bit 量化约 40GB。273GB/s 带宽的 DGX Spark 理论上限约 7 tokens/s；换成双通道 DDR5 台式机（约 100GB/s），直接掉到 2~3 tokens/s，基本不可用。
- 带宽阶梯感受一下：DDR5 台式机约 100 GB/s；DGX Spark 273 GB/s；Mac Studio M3 Ultra 819 GB/s；RTX 5090 约 1.8 TB/s 但显存只有 32GB；数据中心 H200 约 4.8 TB/s 配 141GB HBM。带宽和容量像鱼与熊掌，桌面端长期两头缺。
- MoE 的精妙之处：R1 总参数 671B，但每个 token 只激活约 37B，生成速度按 37B 算；代价是 671B 全部权重必须常驻内存。一句话：MoE 省带宽，不省容量。
- 别忘了 KV cache：32K 长上下文的 KV cache 动辄吃掉几十 GB，这是“内存要买大”的另一半理由。而处理长 prompt 的 prefill 阶段是算力密集型，决定“等第一个字要多久”——这正是 DGX Spark 强调 1 PFLOP FP4 算力的原因。

## 两种掀桌姿势：苹果的“顺手”与英伟达的“锚点”

苹果的路线更像无心插柳：

- 它没发布过任何“AI 工作站”，Mac Studio 只是产品线顶配；但统一内存让 CPU 和 GPU 共享一个大内存池，512GB + 819GB/s 的组合本是给视频剪辑设计的，意外成了最大的桌面推理平台。
- 路线早有伏笔：2023 年苹果论文《LLM in a flash》就在研究如何把大模型塞进受限内存；如今 MLX 框架加上 llama.cpp、Ollama 生态，基本开箱即跑。
- 硬件是顺手赚的，软件生态是开源社区自发长出来的。

英伟达则是主动把桌子搬进书房：

- DGX Spark 用 GB10 芯片、128GB 统一内存、273GB/s 带宽、约 240W 功耗，定位不是“更快地打游戏”，而是本地原型机。
- 打法在软件栈：本地用 CUDA 做开发验证，跑通后同一套代码平滑迁移到云端 GPU 和数据中心。Spark 本质是 CUDA 生态的开发者入口，硬件利润反而是小事。
- 两台 Spark 经 ConnectX-7 互联凑出 256GB 内存，可跑 405B 级模型——桌面之间开始出现“组网扩容”这种数据中心玩法。

一句话总结：苹果是被自家产品线“顺便”掀了桌，英伟达是主动把你的书桌变成机柜的第一层。

## 桌面跑大模型，到底图什么

- 数据不出门：医疗、法律、金融等强合规场景，本地推理常常是唯一解，prompt 不再流经第三方。
- 成本结构反转：API 按量付费适合低频调用；一天几千次的研发迭代和评测，本地一次投入后的边际成本趋近电费。
- 离线与延迟：断网可用，无排队、无限流。
- 但别神化：4-bit 量化相对原模型有精度损失，长文档和复杂推理任务差距更明显；“能跑”与“好用”之间，还隔着 prefill 速度、上下文长度和软件工程质量三道坎。

## 冷思考与三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/71f15a9cd59c2ed5.png)

1. 买硬件只看两个数：内存容量与带宽。经验公式：目标模型 4-bit 体积 × 1.2 ≤ 可用内存（给 KV cache 和系统留余量）；带宽直接决定生成速度。TOPS 分数对跑大模型基本没有参考意义——它是给小模型生态划的线。
2. 选型从 MoE 量化模型入门：128GB 机器跑 GPT-OSS-120B、Qwen3 系列很从容；256~512GB 再碰 R1、K2 级别；密集大模型别硬刚，性价比极差。先用 Ollama / MLX-LM 验证工作流，再谈硬件升级。
3. 本地与云端混合是常态：本地承担数据敏感的沙箱、研发迭代、离线兜底；高峰负载、长上下文、重评测交给 API 或云端 GPU。把桌面大模型当成“私有基础设施”的一部分，而不是云服务的替代品。

结尾一句：AI PC 的定义权，正在从“NPU 跑分”转移到“内存架构”。下次翻参数页，直接跳过 TOPS，去看内存那两行——你就知道这桌是谁掀的。
