## Agent 是吞金兽：一次任务烧掉几十万 token

先看量级对比：

- 一次普通对话，输入加输出约 1K~5K token，成本几乎可以忽略；
- 一个完整的 Agent 任务——理解需求、查资料、调工具、写代码、跑测试、失败、重试、再失败——轻松烧掉 50 万~200 万 token，差了两个数量级以上。

为什么这么费？三台"放大器"同时在工作：

1. **上下文反复重放**。Agent 每走一步，通常要把之前的完整历史重新读一遍。步数越多、历史越长，token 消耗接近平方级增长——这是 Agent 和聊天最本质的结构差异。
2. **多 Agent 传话**。规划者、执行者、审校者互相转述上下文，每转一次就是一次全量往返，成本成倍放大。
3. **试错照常计费**。Agent 的工作方式本质是"尝试—失败—修正"，失败消耗的 token 一分不少。跑过 SWE-bench 类任务的人都知道，重试才是账单的大头。

举例：让 Agent 修一个真实的 GitHub issue，社区实测普遍在数十万 token 量级。按 10 美元/M 计价，一次几美元，批量跑一千次就是几千美元——这类任务直接被挡在商业账本之外。单价降一个数量级，账突然就算得过来了。这才是"骨折价"的真实含义：不是让老用户省点钱，而是让原本不成立的产品成立。

## 骨折价的底气：成本三级火箭

单价为什么能砍这么狠？技术侧和竞争侧同时在发力。

先感受一下历史曲线：

- 2020 年，GPT-3 级别的能力在 API 上约 60 美元/M token；
- 2023 年 GPT-4 发布，输入价 30 美元/M，同档的 GPT-3.5 只要 0.5 美元/M；
- 2024 年，能力更强的 mini 级小模型跌破 0.2 美元/M，开源模型普遍进入 1 美元以下区间。

有投资机构给这个现象起了名字叫"LLMflation"：同等智能的单价，大约每年下降一个数量级。

技术侧的三级火箭：

1. **MoE 架构**：总参数做大，每个 token 只激活一小部分专家。DeepSeek V3 总参数 671B，单 token 只激活 37B——聪明和便宜第一次不再互斥。
2. **缓存与批处理**：Prompt Caching 命中的重复前缀，各家折扣从五折到一折不等；Batch API 离峰处理再砍半。Agent 场景前缀重复率极高，正好把折扣吃满。
3. **蒸馏与量化**：旗舰模型当老师，把能力蒸馏进小参数模型；FP8 量化加更好的算子内核，把 GPU 利用率再榨出一截。

竞争侧更直白：开源阵营（DeepSeek、Qwen、Llama 系列）持续逼近闭源水平，闭源厂商只能用价格守阵地。2024 年国内那轮 API 价格战，已经把这套逻辑预演过一遍。

## "打工模型"和旗舰模型，差在哪

一个类比：旗舰模型是按小时收费的资深顾问，负责最难的 20%；打工模型是量大管饱、稳定出活的基层团队，干完剩下的 80%。没有哪家公司能只靠顾问运转。

所以打工模型的 KPI 换了一套：

1. **单价**，尤其是输出侧价格——Agent 的输出远比对话多；
2. **吞吐与延迟**：tokens/s 和首 token 时间，决定一个任务跑 2 分钟还是 20 分钟；
3. **function calling 正确率**：格式错一次就重试一轮，成功率 95% 和 99.9% 的实际成本能差出好几倍；
4. **长上下文检索**：在几十万 token 里"大海捞针"的准确率；
5. **结实程度**：不幻觉、不跑偏、结构化输出永远格式正确。

评测风向也在跟着换：从知识问答类榜单，转向 SWE-bench、tau-bench 这类"活能不能干完"的考试。一句话总结：打工模型不参加奥赛，参加的是入职体检。

## 骨折价之后，账会怎么变

- **Jevons 悖论**：19 世纪经济学家 Jevons 发现，蒸汽机效率提升后，煤的总消耗不降反升。token 变便宜 → 以前"算不过账"的任务被解锁 → 总消耗和总开支大概率不降反升。厂商打折，赌的正是用量弹性。
- **价值上移**：模型层毛利变薄，价值向编排、记忆、评测、垂直工作流迁移。参考云计算：算力打成白菜价，赚钱的是跑在算力上的 SaaS。
- **创业视角**：很多 Agent 产品不是死于没人用，而是死于毛利为负。单价降一个数量级，等于给一批"差一口气"的产品线发了复活卡。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/7f2dfbd1c0c52501.png)

1. **用 token 记账，别用感觉记账**。上线前先跑 100 次真实任务，统计平均消耗、重试率、失败率，算出单次任务的真实成本；再按子任务难度做模型路由——80% 的常规步骤交给打工模型，20% 的硬骨头留给旗舰。分层路由是省钱空间最大的杠杆。
2. **挂牌价不等于到手价**。缓存折扣、批处理折扣、限流额度、function calling 成功率，几项叠起来，实际成本能差 3~5 倍。用自己真实负载做评测，榜单分数只是入场券。
3. **留好迁移层**。打折不一定永远打折。架构上抽象一层统一的模型接口，随时可换供应商——谈判桌上最大的筹码，就是"我可以随时走"。

价格战没有观众，全是参与者。对开发者来说，真正的问题从来不是"模型多便宜"，而是"你的任务值多少 token"。账算清楚了，骨折价是你的杠杆；算不清，它只是别人的财报。
