2025 年初最出圈的 AI 新闻是 DeepSeek-R1，但基础设施圈同期还上演了一场不太出圈的「极速接力」：模型权重刚开源没几天，vLLM、SGLang 等推理框架的优化 PR 就连夜合入主干，跑分很快超过官方参考实现。模型是别人发布的，速度却是社区先跑出来的——这件事拆开看，比热搜本身更有营养。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/f2f76c6b1b5cbc04.png)

## 一、「连夜反超」到底反超了什么

先纠正一个常见误解：反超的对象不是官方 API，而是官方开源的参考推理代码。

- DeepSeek 放出 V3/R1 权重时，附带一份极简的 inference demo，定位是「帮你跑通、复现结果」，没有任何生产级优化。
- 开源后几小时内，SGLang、vLLM 团队开始适配新架构；圈内流传最广的段子是 SGLang 团队凌晨三点接到 DeepSeek 的电话一起排障，第二天优化就合进了主干。
- 几天后，社区实现在相同硬件上的吞吐与延迟全面超过官方 demo，部分场景达到数倍。
- 真正的大招在随后的 DeepSeek 开源周：FlashMLA（注意力内核）、DeepEP（MoE 通信库）、DeepGEMM（矩阵内核）等自家基础设施代码也全部开源，等于把独门兵器也交了出来。

为什么大家这么拼？推理速度直接挂钩 API 成本——同一张卡每秒多吐一倍 token，单位成本就砍一半，这是各家价格战打得起的底层底气。一句话总结这次接力：官方负责把模型做出来并公开细节，社区负责把它跑快，分工明确，各赢一次。

## 二、为什么能「连夜」：架构公开才是优化的前提

推理提速不是玄学，前提是 kernel 工程师知道往哪儿使劲。DeepSeek 把细节全写进了论文和代码：

- **MLA（Multi-head Latent Attention）**：把传统 Attention 里越攒越大的 KV Cache 压缩成低维 latent 向量，缓存体积降到传统 MHA 的十几分之一，长上下文的显存成本直接跳水。代价是计算模式特殊，通用内核跑不快，必须写专用 kernel——于是有了 FlashMLA。
- **MoE 稀疏激活**：671B 总参数，每个 token 只激活约 37B。算得省，但专家之间的 all-to-all 通信成了新瓶颈，于是有了专攻通信的 DeepEP。
- **FP8 低精度**：训练和推理都吃 FP8，显存和带宽压力减半，但需要配套的量化与累加精度处理，DeepGEMM 补上这一块。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/bb64e2a5a9be2dba.png)

对比一下就明白了：闭源模型只暴露一个 API，你连 KV Cache 怎么存的都不知道，基础设施层无从下手。开源放出的不只是权重，而是「可被优化的权利」。社区能连夜出活，是因为图纸全在，照着盖就行，剩下的拼手速和工程功底。

## 三、vLLM 和 SGLang，各自在卷什么

两家是当前最主流的开源推理框架，路线有明显差异：

**vLLM**
- 出身 UC Berkeley 的 PagedAttention 论文（2023），核心思路是把显存管理做成操作系统式的分页机制，碎片极小。
- v1 引擎重写后主打 zero-overhead scheduler，调度开销压到微秒级；对 MLA、FP8 的支持也已合入。

**SGLang**
- 招牌是 RadixAttention 前缀缓存：Agent 和多轮对话场景里大量重复的系统提示词，命中缓存直接跳过重复计算。
- 在 DeepSeek 上的组合拳：DP Attention（注意力部分数据并行）、PD 分离（prefill 和 decode 拆到不同节点各干各的）、two-batch overlap（两批请求的计算与通信互相掩护着流水推进）。

共同的卷点可以归纳成一句话：把 GPU 的每一瓦算力和每一字节带宽都用到极限——内核融合、通信与计算重叠、调度开销压缩、投机解码（借助 MTP 一次预测多个 token）。两家在公开跑分上互有胜负，PR 速度以小时计，这大概是开源世界最健康的一种内卷。

## 四、看跑分之前，先搞懂这几个指标

「速度提升 X 倍」这类表述最容易误导人。推理性能至少要看四个维度：

1. **TTFT**（Time To First Token）：首 token 延迟，决定「响应快不快」的体感。
2. **TPOT / ITL**：每个输出 token 的间隔，决定「打字机」流不流畅。
3. **Throughput**：系统总吞吐，直接决定单 token 成本。
4. **Goodput**：满足延迟 SLA 约束下的有效吞吐，才是生产环境真正的决策指标。

关键在于这些指标互相牵制：batch 越大吞吐越高，但延迟也水涨船高；输入输出长度、量化精度、并发数、缓存命中率，任何一个变量都能让同一框架的跑分差出几倍。脱离条件比数字，等于不看病历直接开药。

## 五、三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/57033c6d6870740a.png)

1. **看跑分先看脚注**：硬件型号、并发数、序列长度、量化方案、是否算 goodput，一样都不能少。自建服务前，用自己真实的流量分布压测——榜单只提供候选名单，不提供结论。
2. **选框架按场景走**：要跑多种模型、生态兼容优先 → vLLM 覆盖面最广；主力就是 DeepSeek、Agent 场景前缀重复度高 → SGLang 的缓存与专项优化收益明显；愿意锁死硬件追求极致 → 还有 TensorRT-LLM 等闭源选项备选。
3. **把 infra 当成第二模型**：FlashMLA、DeepEP 这类基础设施的演进，对成本的影响常常不小于换一版模型。与其只盯着模型版本号，不如留一半注意力给推理栈——省下来的真金白银，都藏在调度器和 kernel 里。

开源的妙处就在这个飞轮：模型厂公布架构，社区把工程做到极限，部署成本下降，应用铺开，需求与数据再反哺下一代模型。速度不是某一家卷出来的，是一整条开源链路一起转出来的。
