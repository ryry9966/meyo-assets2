2025 年开年，两条新闻撞在了一起：苹果发布搭载 M3 Ultra 的新款 Mac Studio，顶配 512GB 统一内存，官方演示在桌面本地运行 671B 参数的 DeepSeek R1；英伟达在 CES 甩出 Project DIGITS（后定名 DGX Spark），发布时定价 3000 美元起的小盒子，宣称能跑 2000 亿参数模型。“近万亿参数”过去是数据中心的专属词汇，如今跑进了桌面。这不只是两场常规发布会——它把"AI PC"这个词的定义，重新写了一遍。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/46725e14c379bad5.png)

## 先说结论：桌面的瓶颈不是算力，是内存

跑大模型推理，资源的优先级非常明确：**内存容量 > 内存带宽 > 算力**。很多人第一反应是“显卡不够强”，但真正的死结一直卡在内存上。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-27/315c937c3438f969.png)

- **先算容量账**：模型权重必须整个装进内存才谈得上推理。7B 模型 FP16 精度约 14GB，4-bit 量化后约 4GB；而 DeepSeek R1 有 671B 参数，4-bit 量化后仍需约 400GB，再算上推理时的 KV cache，500GB 级内存才比较从容。
- **再算带宽账**：自回归生成阶段，每输出一个 token，都要把激活的权重从内存完整过一遍，带宽 × 时间决定速度。这就是为什么同一个模型在不同机器上，生成速度能差出好几倍。
- **对比一下**：桌面旗舰显卡 RTX 4090 显存上限 24GB，数据中心 H100 也只有 80GB。大模型上不了桌面，卡点从来不在 FLOPS，而在“装不装得下、读得快不快”。

## 苹果的牌：统一内存 + MLX

苹果没发布任何叫"AI PC"的新品类，它只是让一台普通工作站的参数表里，多了一行“能本地跑 R1"。

- **架构红利**：Apple Silicon 从 M1 起就是统一内存架构（Unified Memory），CPU 和 GPU 共享同一块内存池，没有显存与内存的边界，也没有来回拷贝的开销。当年被调侃“内存焊死不可升级”的设计，如今成了跑大模型的最大优势。
- **关键数字**：M3 Ultra 顶配 512GB 统一内存，带宽 819GB/s，正好塞下 4-bit 的 R1；得益于 R1 的 MoE 架构（每个 token 只激活约 37B 参数），社区实测生成速度在每秒 16-18 个 token，属于“日常可用且不烦躁”的区间。
- **软件跟进**：苹果开源的 MLX 框架 API 风格接近 PyTorch，专为统一内存优化；Hugging Face 上的 mlx-community 已积累数千个现成量化模型，一行命令就能加载。
- **一句话总结**：掀桌子的人往往不坐在牌桌上——苹果顺手把当年最大的工程赌注，变成了大模型时代的护城河。

## 英伟达的牌：把数据中心压缩成一台台式机

- **硬件规格**：DGX Spark 的核心是 GB10 Grace Blackwell 超级芯片，20 核 ARM CPU + Blackwell GPU，128GB LPDDR5x 统一内存，FP4 精度下提供 1 petaFLOP 算力，普通插座就能带动。
- **官方口径**：单机可运行最高 200B 参数的模型；两台通过 ConnectX 网口互联，能跑 405B 级别的模型。
- **真实意图不在卖硬件，而在守 CUDA**：开发者在这个盒子上本地调试、微调，写完的代码可以近乎无缝迁到云端 DGX/HGX 集群。硬件是小号的，生态是大号的。
- **一个值得注意的取舍**：LPDDR5x 带宽约 273GB/s，远低于 RTX 4090 的 1TB/s。英伟达用容量换了带宽，思路与数据中心里的 Grace 芯片一脉相承。

## 旧的 AI PC 叙事，为什么被掀了

过去两年的标准叙事是：x86 或 ARM 芯片 + 一块 40+ TOPS 的 NPU，代表是各类 Copilot+ PC。但把数字摆在一起，故事就变了。

- **NPU 的实际负载**是背景虚化、实时字幕、小图生成，离大语言模型很远；16-32GB 的常规内存，意味着量化后的 7B-14B 就是天花板。
- **带宽差距是量级式的**：典型 AI PC 的 LPDDR5x 带宽约 130GB/s，M3 Ultra 是 819GB/s，RTX 4090 约 1TB/s。同样一句“本地跑大模型”，背后是完全不同的体验。
- **计分板换了**：竞争维度从“NPU 算力 TOPS”变成“内存容量 × 带宽 × 软件生态”。以后看设备，这三项比 NPU 跑分有用得多。

## 对谁有用：三个真实受益场景

1. **隐私敏感行业**：法律、医疗、金融的内部文档分析，数据不出本地是硬需求。过去只能妥协上云或干脆放弃，现在本地推理第一次成了体面选项。
2. **高频调用的开发者和小团队**：按 token 计费的 API 在高频场景下一年可能烧掉数千美元，一次性硬件投入在两三年周期内可能更划算；低频用户继续用 API 反而省钱。
3. **小模型先行验证**：DeepSeek R1 蒸馏出的 Qwen/Llama 7B-70B 蒸馏版，让 32GB 内存的普通设备也能获得不错的推理能力。先在本地把 prompt 和 pipeline 跑通，再决定要不要上云，节奏完全自己掌握。

## 冷思考：三件事想清楚再掏钱

1. **先算内存账，再看发布会**：目标模型参数量 × 量化系数（4-bit 约每 10 亿参数 0.5-0.6GB）+ 20-30% 的 KV cache 余量，得出的数字就是内存下限。预算照这个倒推，而不是照 keynote 倒推。
2. **“能跑”和“跑得爽”是两回事**：同样装得下 70B 模型，1TB/s 和 273GB/s 带宽的机器，生成速度可能差 3-4 倍。写代码要快，跑批处理要稳，先想清楚自己属于哪一种。
3. **生态选边要跟工作流走**：苹果押 MLX 和统一内存，英伟达押 CUDA 和 GB10，两条路线工具链不通用。跟着你现有的技术栈选设备，而不是跟着参数表选。
