## 背景

多数人对 Agent 的用法是"一问一答"：你提需求，它执行，然后回到待机。OpenClaw 提供了一个经常被忽略的机制——heartbeat（心跳）。开启后，Agent 会按固定间隔被唤醒一次，读取工作区的 HEARTBEAT.md，自行判断有没有值得做的事。用得好，它就是一个低配版值守进程；用不好，就是一个定时骚扰你的喇叭。

## 问题

我最初的诉求很简单：让 Agent 每天盯几件事——服务器磁盘、日志报错、日历冲突——有问题主动来汇报，没事就闭嘴。直接上手会踩两类坑：一是 Agent 每次心跳都回复"暂无事项"，消息通道被刷屏；二是心跳频率一高，token 消耗肉眼可见地涨。核心矛盾在于：主动性和噪音、成本之间需要显式的工程约束，模型自己不会替你把握这个度。

## 做法

1. 在工作区根目录（默认 `~/openclaw/workspace/`）创建 `HEARTBEAT.md`。它的定位不是文档，而是给 Agent 的"值班手册"。
2. 每条任务写成三段式：**检查什么、什么条件触发上报、上报成什么样**。例如："检查 /var/log/app/error.log，若出现新的 ERROR 且上一轮未报告过，则汇总最近 5 条发给我；否则只回复 HEARTBEAT_ACKED。"
3. 关键是 `HEARTBEAT_ACKED`：Agent 无事时输出这个约定字符串，OpenClaw 会将其抑制，不转发到聊天频道。没有这一条，你的频道会被"无事发生"刷满。
4. 心跳间隔通过环境变量/配置控制（`HEARTBEAT_INTERVAL`）。我从默认 30 分钟起步，跑稳后再调。固定时刻的事（每天早上的摘要）不要放心跳，交给 cron 任务；心跳只管"条件触发"类。
5. 观察会话日志一两周，删掉从未触发过的任务，合并相似的检查项。

## 踩坑点

- **无静默规则就开始用**：必刷屏。先写好 ACK 约定，再上任务。
- **间隔贪短**：5 分钟一次叠加长工作区上下文，一天烧掉的 token 够几百次普通问答。心跳场景用便宜模型足够。
- **心跳里放长任务**：一次心跳跑 20 分钟，后续触发会排队堆积。心跳只做"检查 + 短动作"，重活让 Agent 记成待办或交给你确认。
- **重复告警**：Agent 没有跨心跳记忆时，同一个错误每轮都报。在任务里明确"上一轮已报告的不再报"，或让它把状态写进一个 state 文件做幂等。
- **机器睡眠**：gateway 跑在笔记本上，合盖心跳就停。值守类任务放常开的主机或服务器。

## 可复用建议

把 HEARTBEAT.md 当配置代码维护：进 git、写注释、改动留记录。任务模板固定为"条件 + 动作 + 静默规则"三段式；先上 1~2 个任务观察一周日志再扩。和 cron 的分工记住一句话：**定时的事用 cron，看情况的事用心跳**。

## 总结

HEARTBEAT.md 的价值不在"AI 主动"这个噱头，而在于它逼你把"什么值得打扰我"写成明确的规则。规则写得越清晰，Agent 越像个可靠的值守进程；写得含糊，它就只是定时器加语言模型的随机组合。建议从一个最小任务开始：让它在磁盘超过 80% 时喊你，跑一周，再决定要不要给它更多活。
