## 背景

社区每天产出不少内容：GitHub issue、群聊讨论、外部文章。人工整理精选摘要费时费力，于是我用 OpenClaw 搭了一个「每日精选」发帖机器人，跑了三个多月，累计自动发帖 90+ 篇。这里把架构取舍和踩过的坑如实记下来。

## 问题与约束

需求很简单：每天上午自动发一篇摘要帖。但工程上真正的约束是：

- 内容必须可溯源，所有链接真实存在
- 失败不发、不重发，宁缺毋滥
- 全程可观测，出问题 5 分钟内收到告警

## 架构：四个阶段拆开，不要一个 prompt 干到底

核心决策是把流水线拆成四段，每段独立可测试：

1. **采集**：纯脚本，不用 LLM。抓 RSS、GitHub API、群聊导出，落成本地 JSON。确定性的事交给确定性工具。
2. **生成**：OpenClaw agent 只做一件事——把结构化素材改写成帖子。prompt 里明确「只能使用传入的 URL，禁止新增任何链接」。
3. **校验**：第二遍独立检查。链接逐个 HEAD 验证、字数上限、敏感词、语气。任何一项不过，整体判定失败。
4. **发布**：MCP tool 封装社区 API，token 走环境变量。发布成功后追加 JSONL 台账。

调度用系统 crontab 调 CLI 触发，而不是 agent 内置定时——agent 进程重启后内置任务会丢，这是第一版踩的坑。crontab 里还加了随机抖动，避免整点触发被论坛风控盯上。

## 踩坑实录

**坑 1：模型编链接。** 第一版让 agent 自己「回忆」文章地址，结果帖子里出现似是而非的 404。解法：素材里只放真实 URL，prompt 明令禁止新增，校验层再做 HEAD 复核，双保险。

**坑 2：重试导致重复发帖。** 发布超时后重试，同一天发了两篇。解法：以日期为幂等键，标题带日期，API 侧去重；本地状态文件在确认成功后才更新，重试前先查。

**坑 3：撞上反垃圾风控。** 固定时间、固定格式连发两周后触发频控。解法：和管理员沟通加白名单，同时拉大间隔、轮换不同帖子模板。

**坑 4：时区。** crontab 默认 UTC，帖子迟发八小时。解法：cron 表达式显式指定时区，机器时区统一。

**坑 5：密钥进仓库。** token 写在配置文件里差点被提交。解法：一律环境变量，配置只放非敏感项，pre-commit 加密钥扫描。

## 可复用建议

- 采集与生成彻底分离，LLM 不碰网络请求，只吃确定性素材
- 校验 fail closed：存疑就不发，宁可当天空窗
- 上线顺序：手动触发 → dry-run 看产出 → 再开定时
- JSONL 台账比日志好用，统计、复盘、回滚都靠它
- 每个阶段一条命令能独立跑通，出问题时可以二分定位

## 总结

这个机器人代码量不大，难点全在工程细节：幂等、校验、频控、时区。经验一句话——把 LLM 当「不确定的员工」用：给它清晰的输入、卡死它的输出、再配一个不信任它的质检环节。流水线拆得越细，半夜被叫起来修的次数就越少。
