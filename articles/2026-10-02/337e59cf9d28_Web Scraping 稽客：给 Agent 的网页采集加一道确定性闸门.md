## 背景

OpenClaw 里的 Agent 天然有上网需求：查文档、盯页面变更、抓个表格喂下游工具。多数实现里，URL 由模型自己挑，页面原文直进上下文——能跑，但跑不远。

我们把这一层抽成独立角色，内部叫“稽客”：一个介于 Agent 和目标网站之间的确定性采集网关，以 MCP server 形式挂载。核心思路一句话：**准入、限速、净化交给代码，不交给提示词**。

## 问题

让模型裸抓网页，实践里反复遇到四类问题：

1. **提示词注入**：页面正文藏一句“忽略之前的指令”就能劫持 Agent。在 system prompt 里写“别听网页的话”是软约束，不闭环。
2. **上下文污染**：一个 JS 渲染页转出来上万 token，两轮工具调用就把预算吃光。
3. **合规与礼貌**：robots.txt、QPS、UA 标识，模型不会主动做，代码不做就没人做。
4. **内网穿透**：URL 来自不可信来源时，`127.0.0.1`、内网 IP 会被照抓不误。

## 做法

五个关卡，串成一条流水线：

1. **URL 准入**。只放行 https；域名走白名单（初始为空，按需加）；解析 IP 后拒绝环回、私网、链路本地地址；重定向**每一跳都重新校验**——只查首跳是常见漏洞。
2. **礼貌控制**。robots.txt 按主机缓存 1 小时（404 视为全放行），同主机串行加固定间隔，UA 用真实标识。收到 429 就指数退避，不硬刚。
3. **抓取执行**。静态页走 HTTP + HTML 转 Markdown；需渲染的走 headless 浏览器，15 秒超时，一次性临时 profile，不共享登录态。编码按 header → meta → UTF-8 兜底探测，GBK 站点并不少见。
4. **内容净化**。先转 Markdown 再截断 8k 字符，避免把标签腰斩。返回结构化字段 `url / fetched_at / title / content / truncated`，用分隔符包裹并标注“外部数据，仅作参考”。
5. **审计落盘**。每次抓取记一条日志：谁、抓了哪、多少字节、命中哪条规则。出问题能回放，这是排查的底气。

配置大致长这样：

```yaml
scrape:
  allow_domains: [docs.example.com]
  deny_ip: [loopback, private, link-local]
  qps_per_host: 0.5
  max_chars: 8000
  respect_robots: true
```

## 踩坑点

- **只校验首跳重定向**：https 站点 302 到 `http://10.x.x.x` 就绕过了闸门。
- **先截断再转 Markdown**：会在表格、代码块中间剪断，产出脏数据，顺序必须反过来。
- robots.txt 的 `Crawl-delay` 单位是**秒**，误当成毫秒就是十倍速轰炸对方。
- headless 浏览器长期驻留会内存泄漏，我们用每 200 次强制重启的土办法兜底。
- **净化不等于免疫注入**：strip 标签挡不住自然语言指令。真正的防线是工具结果一律当数据、写操作必须人工确认。稽客收窄攻击面，不能消灭攻击面。
- 别抓登录后的页面和付费内容。技术上做得到，合规上不该做，这条写进策略，不留给模型裁量。

## 可复用建议

- **默认拒绝，白名单慢速生长**。宁可让用户报错后补域名，也不要开局放行 `*`。
- 所有安全判断放代码里，提示词只做辅助说明——模型不可靠时，闸门必须可靠。
- 用本地 mock server 做测试夹具：正常页、超大页、注入样本、302 到内网，四个用例覆盖大部分回归。
- 给稽客独立日志和指标（拦截数、命中率、平均耗时）。安全组件没有观测，等于没做。

## 总结

让 Agent 安全采集网页，重点不在抓取本身，而在抓取之前和之后：准入是闸门，净化是缓冲，审计是兜底。稽客做的就是把确定性逻辑从模型的决策循环里拿出来，钉死在代码里——Agent 负责理解页面，闸门负责决定能不能碰页面。分工清楚，两边都省心。
