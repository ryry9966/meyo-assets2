## 背景

社区里跑 Agent 的人越来越多：挂上几个 MCP 服务、配好插件和自动化流程，日常巡检、数据处理都交给它。遇到问题来社区求助，顺手把日志、截图、配置贴上来，是最自然的动作。但 Agent 和传统工具有个关键区别：它的上下文里不只是当前这次报错，还有你整个工作区的状态——system prompt、挂载的工具列表、内部路径、业务数据片段。贴出去的东西，往往比你以为的多。

## 三条主要泄露通道

1. **人工粘贴**：日志尾部带着环境变量，堆栈里有内网 IP，截图边缘露出 token。
2. **Agent 自动输出**：让 Agent 定时"总结今日工作"发到社区频道，而它的上下文里有内部文档和数据库内容。
3. **权限过宽的 MCP**：filesystem 挂到根目录、只读账号能看到全库 schema——Agent 哪怕只是"列一下文件"，也在泄露组织结构。

## 做法

**Step 1：划三级红线。** 公开（可以直接贴）、内部（只描述行为，不贴配置）、机密（凭证、客户数据、内网拓扑，最好永不进入上下文）。

**Step 2：拆出 demo 工作区。** 单独一份 agent profile：工具白名单只留演示必需的两三个 MCP，凭证用测试账号，工作目录放干净的示例数据。社区排障永远在 demo 里复现，不在生产实例上翻日志。

**Step 3：输出加闸门。** Agent 自动发到社区的内容，先落到本地队列，人工过目再放行。哪怕只延迟十分钟，也能拦住大部分事故。

**Step 4：贴日志前过脱敏脚本。** 用正则匹配 token 形态的字符串、内网网段、家目录路径，替换成占位符。脚本比肉眼可靠。

## 踩坑点

- 让 Agent 自己"匿名化"再输出不可靠。它会改写措辞，但具体数值、路径、schema 往往原样保留，还会漏掉你不知道敏感的字段。
- 手动删 token 容易漏掉 base64 形态和 URL query 参数。
- 终端截图的信息量远超你选中的区域，回滚缓冲区里什么都在。
- "只是内部社区"是个错觉——频道会被归档、被搜索、被转发。
- demo 配置从生产 profile 复制后忘了摘工具，等于白拆。

## 可复用建议

- **一条原则**：凡是 Agent 读得到的东西，都按"可能被公开"来设权限。权限收紧了，泄露面自然小。
- **一句守则**：描述行为，不贴配置。"我用了个只读的文件系统 MCP"可以说，完整挂载参数不必给。
- **一个习惯**：维护一个 20 行左右的脱敏脚本放进 bin，贴任何日志前跑一遍，形成肌肉记忆。

## 总结

Agent 泄露不是玄学，是上下文管理问题：上下文里有什么，就有什么可能被输出。工作区拆开、权限收窄、输出加人工闸门、脱敏脚本常态化——四件事做下来，红线基本就守住了。社区求助的效率和安全性并不冲突，干净的复现环境反而更容易换来有效回答。
