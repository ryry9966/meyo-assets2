## 背景

OpenClaw 的 agent 平时是个被动角色：你在会话里发消息，它响应；没人说话，它就闲置。但用一段时间后会发现，很多真正有价值的活儿不是“问答型”的，而是“时间驱动”的：每天早上汇总一次日历和邮件、巡检磁盘和进程、盯一个 RSS 源有没有更新。这些事靠人记着去问 agent，本质上还是你在当调度器。

OpenClaw 内置了一个很轻的机制来解决这个问题：HEARTBEAT.md。

## 问题

自己搭定时任务当然可以：cron + 脚本 + 调 agent 接口。但这条路有几个代价——逻辑散落在脚本里、与 agent 的工具和记忆体系脱节、改一次需求就要改一次代码。HEARTBEAT.md 的思路是把“什么时候做什么”直接写进工作区的一个 Markdown 文件，由 gateway 的心跳调度器周期性唤醒 agent，agent 自己读文件、判断要不要干活、干完要不要出声。

## 做法

1. 在工作区根目录（默认 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`；
2. 把任务写成 checklist，每条尽量是“触发条件 + 动作 + 沉默规则”的结构，例如：
   - 每次心跳检查磁盘占用，超过 85% 才通知我，否则保持沉默；
   - 每天 9 点后的第一次心跳，汇总当日日历和未读邮件，推送到指定频道；
3. 按任务时效性调整心跳间隔（默认 30 分钟）；
4. 想临时停用，删除文件或写上 `NO_HEARTBEAT`，不必动配置。

## 踩坑点

- **每次心跳都是一次真实的模型调用。** 间隔调太密纯粹在烧 token。非时效任务 30 分钟足够，秒级精度需求请老老实实回到 cron。
- **任务描述模糊，agent 就会自行发挥。** “看看有什么新闻”这种写法，轻则输出噪音，重则反复推送打扰你。每条都要写清“什么条件下才出声”。
- **心跳依赖宿主机活着。** 笔记本合盖睡眠会漏拍，错过的心跳不会补跑；对时效敏感的任务要有兜底。
- **依赖的 MCP 工具或凭证失效时，心跳会静默失败。** 建议在文件里加一条“任务连续失败要汇报一次”的自检项。
- **HEARTBEAT.md 是任务清单，不是笔记本。** 别把长期状态和记忆塞进去，那是 memory 文件的职责，混写会让任务越滚越乱。

## 可复用建议

- 把每条任务当 SRE runbook 的最小单元写：触发、条件、动作、沉默规则，四要素缺一不可；
- 从 1–3 个只读、低风险任务起步（晨报、磁盘巡检、日历预览），跑稳一周再放开写操作；
- 用 git 管理这个文件，每次改动即审计记录；
- 建一个“看门狗”条目：心跳机制本身挂了，要能被你感知到，而不是无声消失；
- 推送目标单独指定到低打扰频道，别和主会话混在一起。

## 总结

HEARTBEAT.md 的价值不在于“自动化”本身——cron 几十年前就会了——而在于它把调度和判断都留在了 agent 的语境里：任务是人写的 runbook，执行时的条件判断、工具调用、结果汇总由 agent 自己完成。沉默规则写得好，它是个安静的值班同事；写得不好，它就是个每小时打扰你一次的群发机器人。区别，只在文件里的那几行字。
