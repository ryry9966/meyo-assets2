## 背景

OpenClaw 的主会话是和用户长期对话的那条线程：系统提示、记忆、历史消息、工具输出都在同一个上下文窗口里滚动。窗口是稀缺资源，塞进去的每一行都在挤占别的东西。

实际用下来，最烧上下文的不是聊天，是干活：全仓搜索、批量抓网页、跑一轮测试、整理日志。OpenClaw 的 sub-agent 机制（如 `sessions_spawn`，不同版本参数略有差异）就是让主 agent 派生子 agent 去干这些脏活。隔离做对了，主会话只收结论；做错了，草稿纸上的涂鸦全糊到会议纪要上。

## 问题：不隔离会发生什么

子 agent 若与主会话共用 session，它的每次工具调用、每段中间输出、每次自我纠错都会写进主 transcript，三个后果：

1. **上下文膨胀**：几轮探索就触发 compaction，真正重要的用户偏好和早期决策被挤掉；
2. **成本失控**：中间态随每轮请求反复重发；
3. **语义污染**：子 agent「我猜……先试试……不对，换一种」的思考残渣，会带偏主 agent 后续判断。

## 做法

我们目前的固定套路，四步：

1. **派生即隔离**：用 `sessions_spawn` 派生子 agent，它拿到独立的 session key 和独立上下文窗口。主会话只收最终返回，中间过程默认不可见，需要审计时再单独拉 transcript。
2. **派生时做减法**：任务描述 + 最小必要上下文（如相关文件路径），别把主会话历史整段贴进去——那是把污染前置。同时在任务里约定返回格式：结论、关键数据、产物路径。
3. **独立 workspace 与工具集**：每个 agent 配独立工作目录；重工具（浏览器、shell）只在子 agent 侧开放；有外部副作用的操作（git push、发消息）白名单化，默认不放。
4. **任务结束即归档**：子会话 transcript 落盘留档，session 及时关闭。需要留给主 agent 的结果，让子 agent 写进共享 workspace 的文件，主 agent 按需读——文件是显式边界，比往对话里塞长文本可控得多。

## 踩坑点

- **session 隔离 ≠ 状态隔离**：上下文分开了，文件系统还是共享的。两个子 agent 并发改同一个文件会互相覆盖，分子目录或串行化敏感路径。
- **子 agent 继承主 agent 人设**：我们遇到过子 agent 自作主张直接回用户消息。给它单独写 system prompt，就一句话：只产出结果，不承担对话。
- **忘记收割子会话**：session 列表越积越多，哪天 `sessions_list` 一拉，又把主上下文撑爆。归档动作要和派生写在同一个流程里。
- **返回值太「丰富」**：三千字报告和直接污染差别不大。返回要契约化：摘要几行，细节进文件给路径。

## 可复用建议

- 心智模型一句话：**主会话是会议纪要，子会话是草稿纸**。只有誊写后的结论，才有资格上纪要。
- 给子 agent 设预算：最大步数、最大 token，防止探索型任务跑飞。
- 排障先看 session key：确认工具调用记在谁名下。我们碰到的一半「污染」其实是路由配错——子 agent 跑在了主会话的 key 上。

## 总结

session 隔离的本质不是技术开关，而是上下文预算的分配策略：让干活的地方随便脏，让对话的地方保持干净。派生做减法、返回做契约、结束做归档，三件事固定下来，sub-agent 才是放大器，而不是泄漏源。
