## 背景

OpenClaw 的工作区约定里有几个核心文件：`AGENTS.md` 管 agent 行为，`SOUL.md` 管人格，`USER.md` 管你是谁。很多人把前两个配得很细，USER.md 却是空的——或者只有一行名字。

结果就是：agent 每次都要重新问一遍你的时区、技术栈、项目背景，或者自作主张地用默认假设回复。USER.md 的本质，是把"每次会话都重复的自我介绍"固化下来：一次写好，处处生效。

## 问题

实践中 USER.md 的失败模式大致三类：

1. **空白或太薄**：agent 只能靠猜。时区猜错，定时任务全乱；系统猜错，给 macOS 用户输出 apt 命令。
2. **写成日记**：把每日进展、临时状态全塞进去。USER.md 会被注入到几乎每个会话，流水账既浪费 token 又稀释重点。时效性内容应该进 MEMORY.md，不是这里。
3. **从不更新**：三个月前的项目描述还躺在里面，agent 会基于过时信息做判断——过时信息比没有更糟。

## 做法

我的 USER.md 现在稳定在 30 行左右，分五段：

```markdown
# User Profile
## 基本盘
- 称呼、时区、常用语言、活跃时段
## 环境
- 主力设备/OS、常用 shell、主力语言和框架、部署方式
## 偏好
- 回复风格（中文、简洁、先给结论）、注释语言、不喜欢的表达
## 进行中
- 当前 2-3 个项目，各一句话状态
## 边界
- 明确不要做的事（如：不主动重构旧代码、不在群里代我发言）
```

写法上有三条原则：

- **只写长期稳定的事实**。换工作、换主力语言之前，这些信息会重复出现几十上百次，值得固化。
- **让 agent 自己维护**。直接说"把我刚才提到的偏好记进 USER.md"，让它 diff 后更新，比手写省力，措辞也更贴近它的理解方式。
- **进 git**。USER.md 的变更历史就是你偏好的演进史，写坏了随时回滚。

## 踩坑点

- **不要放敏感信息**：密钥、密码、内网地址一概不进。这个文件会被注入所有会话，还可能被插件读取。
- **别和 AGENTS.md 抢职责**："回复要简洁"这类行为规则放 AGENTS.md，USER.md 只放"关于你"的事实。混着写，两处都会漂移。
- **"进行中"段落最容易腐化**：我的办法是让 agent 在较长会话结束时问一句"有需要更新到 USER.md 的长期信息吗"。有效，但偶尔嫌它烦，看个人取舍。
- **多实例场景**：跑多个 agent 或多个工作区时，确认它们共享同一份 USER.md，否则会出现"这个 bot 记得、那个 bot 不记得"的分裂体验。

## 可复用建议

- 篇幅红线：超过 60 行就该砍。每个字段问自己一句——"这条信息一年会被用到几次？"
- 三个月 review 一次，重点清"进行中"段落。
- 模板直接从上面抄即可：先填 5 行跑一周，再按 agent 实际反复问到的痛点补全，比一次性写满更准。

## 总结

USER.md 不是配置，是你和 agent 之间的"入职交接文档"。写它的一次性成本大约 20 分钟，换来的是每次会话省掉的开场白、更少的错误假设，以及一个不会在你换时区后把定时任务排错的助手。空着不写，等于每次都让新同事盲猜你的工作方式。
