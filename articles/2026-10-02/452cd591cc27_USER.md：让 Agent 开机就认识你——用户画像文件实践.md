## 背景

用 Agent 做日常自动化的人大概都有类似体验：换了新会话，它又来问你的时区，又用错称呼，又在你明确说过"先给结论"的时候写三段铺垫。原因很简单——模型没有跨会话记忆，而 system prompt 通常是产品侧写死的，不可能装下"你是谁"。

OpenClaw 的 workspace 里有一组约定文件：`AGENTS.md` 管行为规则，`MEMORY.md` 管动态记忆，`USER.md` 管用户画像——一份随会话自动注入上下文的"我是谁"说明书。这可能是性价比最高的一类配置：写一次，受益所有会话。

## 问题

没有 USER.md 时，个性化全靠对话里临时喂，代价包括：

- 同一信息反复回答：时区、语言偏好、技术栈，每次开聊都来一遍；
- 风格漂移：今天简洁明天啰嗦，像换了个人；
- 项目背景缺失：agent 只能给出通用建议，落不到你的实际环境；
- 有人干脆把这些塞进全局 system prompt，结果提示词膨胀，关键指令反而被稀释。

## 做法

在 workspace 根目录（如 `~/.openclaw/workspace/USER.md`）建文件，核心原则：**只写事实与偏好，不写任务，不写过程**。骨架示例：

```markdown
# 关于我
- 称呼：老张；时区：Asia/Shanghai；语言：中文优先

## 环境
- 主力机：macOS，终端重度用户；常用路径 ~/work

## 技术栈
- 主写 Python / Go；部署只用 systemd + docker compose

## 沟通偏好
- 先结论后展开；不确定就直说；不要客套话

## 进行中
- OpenClaw 插件 xx（至 3 月底）——过期即删
```

配套两条更新机制：

1. 给 agent 加一条规则：发现"同一问题被问第二次"时，提醒你写入 USER.md；
2. 涉及修改 USER.md 时，先列 diff，你确认后再落盘。

最后把整个 workspace 用 git 管起来：多机同步、历史可回滚。

## 踩坑点

- **写成简历**。几十行足够。它每个会话都要进上下文，长文会稀释关键信息，也在持续烧 token。
- **混入临时状态**。"这周要交付 X"属于 MEMORY.md。USER.md 里放了任务，两周后就是污染源。
- **放敏感信息**。密码、API key、证件号绝对不进这份文件——它会被明文注入每一次请求。
- **条目无日期**。项目会结束、时区会变，"进行中"一类信息务必带时间，定期清理。
- **放手让 agent 自我改写**。模型会脑补你的偏好，未经确认的写入会让画像慢慢漂移，最后你都不知道它"以为"你是谁。

## 可复用建议

- 分工固定：USER.md = 静态画像，MEMORY.md = 动态事实，AGENTS.md = 行为规则。别互相塞。
- 写法上用"机器可判断"的短句："中文回复"比"我比较喜欢中文一点"有效得多。
- 把"提醒写入 USER.md"作为 agent 的一条常驻规则，画像会随使用自然生长。
- 每月 review 一次：删比加更重要。

## 总结

USER.md 的本质，是把"让 agent 认识你"从无数次重复对话，压缩成一份可版本管理的配置文件。它没有任何黑魔法：十分钟的初始投入，加上一点点维护纪律，就能让每次会话从"重新认识"变成"接着聊"。对重度用 Agent 跑自动化的人来说，这是所有调优手段里回报最确定的一项。
