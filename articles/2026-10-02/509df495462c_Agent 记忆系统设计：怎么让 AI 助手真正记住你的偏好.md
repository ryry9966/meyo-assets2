## 背景

在 OpenClaw 里跑长线 Agent 时，最常见的抱怨不是"不够聪明"，而是"每次都从头来"。项目约定、代码风格、部署习惯……这些偏好散落在历史会话里，上下文一刷新就归零。上下文窗口再大也解决不了这个问题——它是工作台，不是档案柜。

## 问题：三种常见错误做法

1. **全塞进 system prompt**：开始有效，两周后 prompt 里几百条"记忆"，token 贵、干扰大，模型开始张冠李戴。
2. **聊天记录原样存档再检索**：存的是过程不是结论，检索回来的大多是噪音。
3. **指望模型"自己记住"**：跨会话没有任何持久化，纯属玄学。

核心矛盾在于：记忆既要写得全（覆盖面），又要取得准（信噪比），还要改得动（可维护）。三者只能靠分层设计同时满足。

## 做法

我目前的方案分四步，用 MCP 工具 + SQLite 就能落地：

1. **分层**。三层足够：会话内工作记忆（本来就有）、长期偏好（稳定项，如"commit message 用中文祈使句"）、情节记录（一次性任务结论，低价值自动过期）。
2. **写入走显式通道**。不要每轮对话都做抽取。用 hook 在任务完成后触发一次抽取，schema 固定：`content / scope / confidence / source / updated_at`。用户明确说"记住……"时直接写入，confidence 拉满。
3. **存储别过度设计**。SQLite 一张表 + FTS5 全文索引起步完全够用，几百条记忆用不上向量库。等记忆过千条、且主要靠语义模糊匹配时再上 embedding。
4. **读取按需注入**。会话启动注入 top 5 全局偏好；执行任务时按 scope 检索相关项，只拼当前需要的几条。关键细节：注入的记忆要带来源和时间，方便模型判断新旧。

再加两个运维动作：一个 cron 任务每周做去重和冲突合并；暴露 `add / update / delete / list` 四个 MCP 工具，让用户随时能看、能改。

## 踩坑点

- **记忆污染最常见**。一次性的"这次用 pnpm"被写成永久偏好，之后每个项目都强制 pnpm。对策：抽取时强制判断 scope，一次性指令默认不入库。
- **隐式偏好别硬抽**。模型容易把巧合当规律——你两次用了某个库，不等于你偏好它。只抽高频且明确的模式，confidence 起始值压低。
- **冲突不处理等于没记**。新旧偏好冲突时要覆盖旧条目并保留历史，否则检索时两条都回来，模型随机选一个。
- **注入太多反而变笨**。超过 10 条左右，模型开始被无关偏好带偏。宁可少注入、多按需检索。

## 可复用建议

- 从"显式记忆 + 极少量自动抽取"起步，先让用户满意，再谈智能。
- 把记忆做成可审计的工具而非黑盒：用户能看到 Agent 记了什么，信任度完全不同。
- 准备一个 10 条左右的偏好问答测试集（比如"我的 commit 风格是什么"），每次改抽取规则跑一遍，防止回归。
- 保留遗忘机制：confidence 衰减 + 手动清理。记忆系统和缓存一样，需要淘汰策略。

## 总结

记忆系统的本质不是"存得多"，而是**写入有门槛、读取有范围、冲突有仲裁、用户有控制权**。SQLite + MCP 工具一晚上就能搭出第一版；但比任何"高级记忆框架"更值得先做的，是把 schema 和更新策略想清楚。
