## 背景

AGENTS.md 是放在 OpenClaw workspace 根目录的一个 Markdown 文件。每次会话启动时，它会被注入到 agent 的系统上下文里——相当于你给这个 AI 助理写的"员工手册"：工作区里有什么、东西放哪、哪些事不能碰。和 agent 自己维护的 MEMORY.md 不同，AGENTS.md 完全由你编写、可进 git，是整个工作区里最稳定的一层约定。

## 问题

没有这份手册时，踩过的坑都很相似：

- agent 把临时文件散落在 workspace 根目录，几次会话后一片狼藉；
- 记忆写入格式每次不一样，翻 MEMORY.md 像考古；
- 它不确定哪些操作需要确认，偶尔自作主张删文件、发消息；
- 每次会话都要在对话里重新交代一遍规矩，口头约定无法沉淀。

本质上是"新员工没有 onboarding 文档"的问题，靠在聊天里纠正无法根治。

## 做法

建议从最小骨架起步，用真实失败驱动迭代：

1. **目录约定**：写清 memory/、daily note、产出文件各放哪，给出完整路径示例；
2. **开场行为**：明确"每次启动先读 MEMORY.md，结束前把重要事项写回"；
3. **安全边界**：删除、对外发消息等操作列为需确认项，用祈使句写，别写"尽量小心"这种无法执行的形容词；
4. **风格约束**：回复语言、长度、格式，一条一条列；
5. **版本管理**：AGENTS.md 进 git。迭代循环是：agent 犯错 → 复盘 → 把纠偏写成一条规则 → commit。

每条规则建议套一个模板：**触发条件 + 具体动作 + 示例路径**。例如："凡记笔记，写入 /memory/当天日期.md，一行一事。"

## 踩坑点

- **写太长**。AGENTS.md 每次会话都占 context，几千行会稀释注意力。控制在一两屏内，细则拆成引用文件按需读。
- **规则冲突**。"始终先问我"和"心跳时自动处理"放在一起，agent 只能随机选一个。写完通读，冲突的合并或标明优先级。
- **动态信息混进来**。今天的任务、临时状态应放 MEMORY.md 或 daily note，AGENTS.md 只放稳定约定。
- **改完不生效就怀疑 bug**。多数情况是当前会话没有重新加载，开新会话验证。
- **路径大小写不一致**。文档写 `Memory/`，实际目录是 `memory/`，agent 会犹豫甚至自建目录。

## 可复用建议

- 用"给新同事写 onboarding"的心态写：假设它聪明但零上下文；
- 和 MEMORY.md 明确分工：AGENTS.md 是你写的宪法，MEMORY.md 是它写的工作记忆，互不越界；
- 每周复盘一次：把新踩的坑收敛成一两条规则，同时删掉从未生效的规则，保持文件瘦身；
- 多工作区（个人助理 / 项目仓库）各写一份，公共段落抽成模板复用。

## 总结

AGENTS.md 的价值，在于把"调教 agent"从一次次口头纠正，变成一份可版本控制、可持续演进的工程资产。写好它花不了多少时间，但它决定了你的 agent 是一个反复犯错的实习生，还是一个边界清晰的同事。
