## 背景

AGENTS.md 是一个很轻的约定：在工作区根目录放一个 Markdown 文件，Agent 每次启动会话时自动读取，作为长期生效的行为说明。OpenClaw 沿用了这个约定——你的工作区（默认 `~/.openclaw/workspace`）里的 `AGENTS.md`，就是 Agent 的"入职手册"。

它不是新协议，也不需要插件，就是一个纯文本文件。价值恰恰在于够笨：任何工具、任何模型都能读，而且这是多个编码类 Agent 共同采纳的跨工具约定，写一次多处受益。

## 问题

没有它时，常见的三种重复劳动：

1. 每次新会话都要重新交代："笔记放 notes/""回复用中文""改代码前先跑测试"。
2. 规则散落在历史对话里，这次记住了，下次会话又忘。
3. 把所有要求塞进每条消息，上下文被临时指令撑爆，真正的任务反而没空间。

本质是把"持久规则"和"临时任务"混在了一个通道里。AGENTS.md 就是把前者搬出去。

## 做法

1. 在工作区根目录创建 `AGENTS.md`。
2. 写短规则，不写散文。推荐五块内容：
   - **身份与语气**：回复语言、风格、称呼；
   - **文件约定**：笔记、代码、临时文件各放哪，命名规则；
   - **工具规则**：什么场景用哪个工具/插件，哪些操作要先确认；
   - **边界**：不碰哪些目录，破坏性操作必须先询问；
   - **会话习惯**：开工先看哪些文件（比如待办清单）。
3. 控制篇幅。它会随每轮对话进入上下文，一两百行是上限，写完通读一遍，删掉模型本来就会做的事。
4. 分层：搭配支持嵌套约定的工具时，子目录可以再放一份只管本目录的规则，离得近的优先。
5. 迭代：同一个问题纠正 Agent 两次，就该沉淀进 AGENTS.md 了。

起步模板，可直接粘贴删改：

```markdown
# 工作区规则
- 默认用中文回复，简短直接。
- 笔记写入 notes/，文件名用日期前缀。
- 删除、覆盖文件、对外发消息前，先向我确认。
- 不读取 .env 和密钥相关文件。
- 会话开始时先看 todo.md。
```

## 踩坑点

- **写成长文**。规则超过一屏，注意力就被稀释，改成短句和列表。
- **规则互相冲突**。文件里说 A，聊天里又说 B，行为会变得随机。一个事实只在一处维护。
- **把密钥写进去**。这是明文文件，可能被同步、备份、随仓库分享，敏感信息走环境变量。
- **把它当记忆用**。AGENTS.md 是"规则"不是"经历"，写"怎么干活"，别写流水账；记忆走专门的 memory 机制。
- **文件名写错**。用大写 `AGENTS.md`，部分文件系统区分大小写。

## 可复用建议

- 工作区用 git 管理，AGENTS.md 每次修改都有 diff，改坏了能回滚。
- 每月做一次"规则瘦身"：删过时条目，合并重复条目。规则和代码一样会腐化。
- 团队共用时，通用约定放仓库根目录，个人偏好放用户级文件，避免互相覆盖。

## 总结

AGENTS.md 的杠杆率很高：几十行的文件，换来跨会话的一致行为。把它当成给新同事写的入职须知来维护——短、准、常更新。如果你现在每次开会话都在重复自我介绍，今天就该写第一版了。
