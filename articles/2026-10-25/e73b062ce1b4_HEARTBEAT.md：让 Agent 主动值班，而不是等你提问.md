# 背景

大多数人用 OpenClaw 的方式还是"人问、Agent 答"。但 OpenClaw 有个常被忽略的机制：心跳（heartbeat）。Gateway 会按固定间隔唤醒 Agent，让它读一遍工作区根目录的 `HEARTBEAT.md`，然后自己判断——有事就干，没事就输出 `HEARTBEAT_OK`，这次心跳静默结束，不会打扰你。也就是说，OpenClaw 原生就支持"Agent 巡检"，只是这个文件默认不存在，很多人从没写过第一行。

# 问题

定时任务（cron）适合"某个时刻必须执行"的事，但更多真实需求是**状态变了才要做**：仓库里新 issue 超过 12 小时没人回、磁盘用量过阈值、有内容才发的日报。这类判断写进 cron 很别扭，写在对话里，会话一关 Agent 就忘了。

`HEARTBEAT.md` 正好补这个位置：它是一份常驻的状态巡检清单，Agent 每次醒来都会看一眼。

# 做法与步骤

1. **在 Agent 工作区根目录建 `HEARTBEAT.md`**，用短句 + 复选框写条目。关键是把每条写成"条件 → 动作"结构，并默认静默：
   - 检查仓库最近 24h 的未回复 issue，超过 12h 才在群里提醒，否则保持沉默
   - 检查磁盘用量，超过 85% 再通知
   - 每天 21 点后第一次心跳，汇总当日已完成事项，没有内容就不发
2. **调间隔做测试**：在配置里把心跳间隔临时改成 2 分钟（默认约 30 分钟），观察日志。
3. **验证两条路径**：无事时日志里应出现 `HEARTBEAT_OK` 且用户侧无消息；有事时按条目执行并投递到指定渠道。
4. **调回常规间隔**（20–30 分钟），进入长期运行。

# 踩坑点

- **每次心跳都是真实调用**。即使最终 `HEARTBEAT_OK`，系统提示词和 `HEARTBEAT.md` 照样进上下文，token 实打实烧掉。文件控制在十几行以内，别把它当第二块记忆用。
- **通知风暴**：条目里不写"否则保持沉默"，Agent 会每次心跳都汇报"一切正常"。每条都要有明确的触发阈值。
- **长任务阻塞**：某个条目触发的任务跑几分钟，下次心跳可能被跳过或排队。心跳里只放轻量巡检，重活让它触发后交给子任务或 cron。
- **心跳不是 cron 替代品**：确定时间的任务（每天 9 点抓取）用 cron，心跳只做"轮询状态、条件触发"。
- **时区**：日报类条目要写清时间基准，否则"21 点后第一次心跳"可能落在错误的时区。

# 可复用建议

- **条目模板**：`检查 X；如果 <阈值条件> 则 <动作 + 通知渠道>；否则保持沉默`。三段缺一不可。
- 三类适合放进 `HEARTBEAT.md` 的事：**状态巡检**（监控阈值）、**例行维护**（清理临时文件、检查订阅过期）、**条件日报**（有内容才发）。
- **让 Agent 自己维护清单**：可以允许它完成一项后勾掉或改写条目，但要定期人工 review，防止清单越改越跑偏。
- 单独开一个通知渠道接收心跳消息，和日常对话分开，减少对主会话的干扰。

# 总结

`HEARTBEAT.md` 把 Agent 从"应答器"变成"值班员"。写好它的标准很简单：**90% 的心跳应该是 HEARTBEAT_OK，剩下 10% 替你发现真问题**。如果比例反过来，先修清单，再谈自动化。
