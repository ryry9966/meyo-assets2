## 背景

在 OpenClaw 的工作流里，Agent 的产出物大多是 Markdown：周报、教程、changelog、技术方案。写完只是一半，另一半是发出去——同一篇内容往往要同时进博客、掘金、知乎和公众号。这时你会发现，"Markdown 一次编写、到处渲染"是个美丽的误会。

## 问题

三个层面：

1. **平台方言**。GitHub 支持 GFM 和脚注；掘金基本兼容 GFM；知乎会吞掉大部分 HTML；公众号连代码高亮都要靠内联样式硬凑。
2. **AI 产出不可控**。模型会自作主张输出脚注定义、HTML 标签、LaTeX 公式、四层嵌套列表——每一项都是某个平台的渲染炸弹。
3. **手动适配不可持续**。每次发布对着编辑器改半小时格式，两周后就会放弃维护。

## 做法

我把整条链路收敛成一条管线，核心思想：**以 AST 为事实源，平台差异全部沉到适配器层**。

1. **约束生成端**。给 Agent 的 system prompt 明确：只输出 GFM，禁用 HTML、脚注、公式，列表不超两层。在源头消灭问题成本最低。
2. **统一解析**。用 remark-parse 把 Markdown 解析成 mdast，后续所有处理基于这棵树，不再碰原始字符串。
3. **lint 校验**。写一组自定义 mdast 规则：节点类型白名单（heading/text/code/image/list/table），发现 `footnoteDefinition`、`html`、`math` 节点直接 fail。lint 在构建前跑，不合规则让 Agent 自动重写一轮，仍不过就阻断。
4. **平台适配器**。每个平台一个 renderer：公众号走 mdast → HTML + CSS 内联，代码高亮输出成带 style 的 span；掘金和博客直接输出 GFM 原文；知乎做降级，宽表格转图片。新增平台只加 renderer，上游不动。
5. **资源与发布**。图片统一走上传步骤，把本地路径替换成平台无关的图床 URL，返回映射表保证幂等。最后封装一个 MCP tool 写剪贴板（`text/html` 格式），一键粘贴进目标编辑器，人工确认后发布。

## 踩坑

- 公众号粘贴 HTML 时，code 块内的换行和空格会被编辑器吞掉。解法：换行转 `<br>`、空格转 `&nbsp;`，且必须以 `text/html` 类型写剪贴板，纯文本粘贴会丢样式。
- 模型偶尔无视禁令输出脚注。lint 不是可选项，且失败路径要闭环到自动重写，否则等于没做。
- 嵌套列表在知乎必错位，超两层直接在适配器里拍平。
- 图床要平台无关。公众号图床的链接在知乎侧会被防盗链拦掉，反过来也一样。
- 移动端表格宽度必炸，超过四列的表格统一转图片。

## 可复用建议

- **内容与呈现分离**：mdast 是唯一事实源，任何平台差异都写成转换规则，不散落在脚本里。
- **lint 规则当契约维护**：生成端 prompt 和校验规则放同一仓库，改一处必改另一处。
- **自动化止步于"一键生成 + 一键复制 + 人工确认"**：全自动发布省下的时间，抵不上一次误发的事故成本。

## 总结

这条管线没有炫技的部分，价值在于把格式适配从"每次发布的手工活"变成"构建系统的测试项"。AI 生成解决写的问题，AST + lint 做契约，适配器解决发的问题——多平台发布就从碰运气变成了可回归验证的工程流程。
