# 背景

LLM 本身无状态，每次会话都是重新开始。但 OpenClaw 里的 agent 往往是常驻的：定时任务、插件钩子、MCP 工具调用，跑几周后用户最直观的抱怨是——"它怎么又问我一遍时区""说过多少次 commit message 用中文"。偏好记忆不是锦上添花，而是常驻 agent 的基础设施。

# 问题

社区常见两条路：把历史对话全量塞进上下文，或者一上来就架向量库。前者几轮就撑爆预算，关键信息被稀释；后者检索回来一堆语义相近但已过期的记录。实践下来，难点不在"存"，而在四个策略：**写什么、何时更新、取多少、怎么忘**。存储反而是最简单的部分。

# 做法：最小可行方案

1. **分层**。记忆分三类：偏好（稳定、结构化，如输出格式、工具选择）、事件（会话摘要）、流程（学到的操作习惯）。先只做偏好，收益最大。
2. **写入**。会话结束时跑一次轻量抽取，只保留可执行的陈述。"commit message 用中文、不加 emoji"是合格记忆，"用户喜欢简洁"不是。每条记录带字段：`key / value / scope / confidence / source(explicit|implicit) / updated_at / hit_count`。
3. **存储**。一个 JSON 文件或 SQLite 就够，一条偏好一行。向量索引只做召回，结构化字段负责去重和冲突判断，记录超过几百条再考虑 embedding。
4. **检索**。会话开始按 scope + 任务相关性取 top-N 注入，预算控制在 500~800 token。插件可声明自己关心的 scope，避免"写代码偏好"被注入到日程提醒场景。
5. **更新与遗忘**。同 key 覆盖并留版本；显式更正直接覆盖，隐式信号（用户又一次打断纠正）只降置信度不删记录；连续被纠正 N 次或置信度低于阈值就清理。务必提供"忘掉 X"这类工具。
6. **接入**。把记忆封装成 MCP 工具（memory_search / memory_write / memory_forget），让 agent 在对话中主动写，与会话末尾的批量抽取互补。

# 踩坑点

- **写入过泛**：抽象评价无法指导行为，抽取 prompt 里要强制"可验证、可执行"。
- **一次更正当永久**：用户疲惫时说"别解释这么细"，不该立刻固化为规则，用 confidence 缓冲。
- **冲突追加而非覆盖**：新旧版本同时命中，模型随机听一个，表现为行为时好时坏。
- **记忆膨胀**：半年 2000 条，检索噪声淹没真正重要的偏好。设上限，定期合并同义条目。
- **跨会话泄漏**：共享部署里 scope 隔离是安全问题，不是功能细节。
- **记忆不可见**：用户不知道助手记了什么，一次错误行为就会摧毁信任。给一个可查看、可删除的入口。

# 可复用建议

- 起步版本 300 行以内：JSON 文件 + 一段抽取 prompt + 会话开始注入，先跑通闭环再谈架构。
- 建一个"偏好留存测试集"：重放旧会话，断言偏好是否被应用，当回归测试跑。这比任何指标都诚实。
- 把"忘记"当一等公民设计——写入、更新、遗忘是同一个生命周期的三段，不是三个功能。

# 总结

让助手"记住你"，等于同时做对四件事：写入策略、更新策略、检索预算、遗忘机制。向量库只是其中一环。先小闭环跑通，再按真实失败数据加复杂度，比一开始就搭复杂架构省得多。
