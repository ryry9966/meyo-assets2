## 背景

OpenClaw 的 agent 每次会话启动时，都会把工作区根目录（默认 `~/.openclaw/workspace`）下的 `AGENTS.md` 注入上下文。它是纯文本、归用户所有、可以进 git——本质上是一份"写给 AI 看的 README"。首次启动时 OpenClaw 会生成一份模板，但实际观察下来，很多人要么原样放着不动，要么把它当成万能垃圾桶什么都往里塞。两种用法都在浪费这层最有杠杆的配置。

## 问题

我自己反复遇到三类情况：

1. agent 每次重建目录、乱放文件，命名风格随会话漂移；
2. 同一个错误反复犯——聊天里纠正过一次，下个会话全忘；
3. 规则写了一大堆，上下文被吃掉几千 token，行为却没变化。

根因是缺少一个稳定、可版本化、每次会话自动生效的行为约定层。逐条在对话里说，成本高且不持久；改代码或系统提示词，门槛又太高。AGENTS.md 正好是中间这层。

## 做法

我的工作区分工是：`SOUL.md` 管人格语气，`USER.md` 管用户事实，`TOOLS.md` 放具体工具备注，而 `AGENTS.md` 只写"怎么干活"。里面维护五个小节：

1. **目录布局**：memory、sessions、scripts 各放什么，新文件的默认落点；
2. **日常流程**：心跳检查哪些东西、每日简报的步骤和输出位置；
3. **渠道礼仪**：Telegram 和 WhatsApp 的回复风格分开写，不共用一套；
4. **工具偏好**：能用 MCP filesystem 就别开 shell，读文件优先走专用工具；
5. **硬性禁令**：不动 `~/.ssh`、不执行 `rm -rf`、不自动 `git push`。

每条规则按"触发条件 → 动作 / 禁止"来写，要可检验，别写形容词。

出错后的修正流程也固定下来：agent 犯错 → 不在聊天里骂 → 直接改 AGENTS.md → 下个会话验证。让修正持久化，而不是消耗在对话里。

## 踩坑点

- **把人格写进 AGENTS.md**：和 SOUL.md 双份维护，两周后必然漂移。手册只写操作。
- **写太长**：这个文件每次会话都进上下文，300 行规则等于每轮对话背着 300 行跑。我控制在百行内，长参考资料放独立文件，这里只留指针。
- **规则互相冲突**：遇到冲突 agent 会随机选一边。每次改完通读一遍查矛盾。
- **把它当安全边界**：AGENTS.md 是建议性的，模型在压力下可能不遵守。真正的安全约束要落在沙箱、权限和网关配置里，更别把 API key 写进去。
- **放手让 agent 自己追加"经验教训"却不 review diff**：一个月后全是正确的废话。

## 可复用建议

- 把 AGENTS.md 当 SRE 的 runbook 管：进 git、小步提交、定期 review；
- 每条规则写完自问：下个新会话的行为会因此不同吗？不会就删；
- 每隔几周裁剪一次，删掉从未触发过的条目；
- 明确优先级：沙箱权限 > AGENTS.md > 聊天里的临时指示。

## 总结

AGENTS.md 是 OpenClaw 里性价比最高的一层配置：不改代码、不写插件，就能把反复踩的坑固化成每次会话自动生效的约定。它的价值不在于写了多少条，而在于每一条都真的改变了 agent 的行为。当这本手册短到全是有效规则时，agent 才算真正"住进"了你的工作区。
