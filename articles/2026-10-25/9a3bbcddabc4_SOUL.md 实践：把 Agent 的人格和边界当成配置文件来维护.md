## 背景

在 OpenClaw 的 workspace 里，除了 AGENTS.md（怎么干活）、TOOLS.md（工具说明）、USER.md（用户是谁），还有一个常被忽略的文件：SOUL.md。它只负责一件事——定义这个 Agent "是谁"。每次会话建立时，这份文件会进入 system prompt，成为模型行为的最底层约束。很多人拿默认模板跑了几个月都没动过，直到某天发现助手在正式邮件里用颜文字、或自动执行了没人交代的事，才回头补这一课。

## 问题

没认真写过的 SOUL.md，常见症状有三类：

- **人格漂移**：上午冷静克制，下午热情过头；
- **边界缺失**：跑自动化时"顺手"做了预期外的事；
- **语气失控**：所有输出一个调子，不管是在写周报还是在陪你排障。

根因大多是文件里写的是"你要乐于助人、积极友好"这类形容词，而不是可执行的行为规则。

## 做法

我的 SOUL.md 最终收敛成五段：

1. **身份**：两三句话，说明它是什么角色、服务谁。别写成小作文。
2. **语气**：给正反例。比如"技术解释先给结论，控制在三句内；不要用'当然可以！'开头"。
3. **边界**：写具体触发条件，而非原则。例如"给第三方发消息前必须先给我看草稿""22:00 后只记录不执行"。
4. **升级规则**：删文件、花钱、对外发送，一律先停下确认。
5. **禁止清单**：三到五条硬规则，越短越有效。

写完后跑一周，每次行为不对，就在对应段落补一条具体规则，而不是整段重写。SOUL.md 应该像代码一样增量修改，而不是每次推翻重来。

## 踩坑点

- **写太长**。它每轮都占上下文，3000 字的"人格设定"会稀释真正重要的规则，两百行以内是合理上限。
- **形容词无效**。"保持专业"没有行为指向，"回复不超过五句、不用感叹号"才有。
- **和 AGENTS.md 打架**。AGENTS.md 说"自动重试"，SOUL.md 说"不确定就问"，模型会随机选一个。冲突时以 SOUL.md 为准，所以别在里面写流程性的内容。
- **改完不重启会话**。旧会话的系统提示已经定型，改了不生效是最常见的"我怎么改了没用"。
- **把人格写进子 Agent**。主 Agent 负责对话，子 Agent 只看自己的提示词，边界要写在正确的层。

## 可复用建议

- 段落模板固定为：身份 / 语气 / 边界 / 升级 / 禁止，换 Agent 只换内容。
- 一条规则对应一个行为，条件写清楚：何时、对谁、做什么。
- 每次自动化事故后复盘一句"SOUL.md 里缺哪条规则"，把结论沉淀进去。
- 定期审一次，删掉从未触发的规则——和清理死代码一个道理。

## 总结

SOUL.md 不是给模型"注入灵魂"的玄学，而是一份高优先级的配置文件。它解决的是：当 Agent 长期运行、跨场景使用时，行为要有一个稳定的下限。写法上记住三条——**短、具体、可执行**。把它当基础设施代码维护：进版本管理、小步修改、定期 review，比任何"高级提示词技巧"都管用。
