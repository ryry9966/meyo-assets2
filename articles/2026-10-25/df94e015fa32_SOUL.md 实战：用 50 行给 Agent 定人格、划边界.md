## 背景

OpenClaw 的 Agent 行为并不只由模型决定。工作区里的 SOUL.md 会在会话启动时注入系统提示，相当于 Agent 的“出厂性格设置”。很多人装完就用默认模板，跑两天开始抱怨：语气忽冷忽热、过度讨好、群里抢话、动不动想执行有风险的操作。这些问题多半不是模型的问题，是人格文件没写。

## 问题

没有人格定义时，Agent 的行为基线由模型通用风格兜底，典型故障有三类：

1. **人格漂移**：长会话和多群场景下语气不一致，上午高冷下午话痨。
2. **边界缺失**：对“帮我把这个目录清一下”“直接回群里说定了”这类指令不设防。
3. **规则冲突**：SOUL.md、AGENTS.md、频道配置各说各话，Agent 随机挑一条执行。

## 做法

我的 SOUL.md 稳定在 50 行左右，分四段：

1. **身份**：两三句说清它是谁、服务谁。不要写诗。
2. **表达风格**：只写可验证的行为。不写“简洁有趣”，写“默认回复不超过 5 句，先结论后理由；群聊不主动接无关话题”。
3. **优先级**：明确冲突时听谁的，比如“用户即时指令 > 长期偏好 > 默认风格”。
4. **边界**：这是核心，用三级阶梯写清楚——
   - 可自动执行：读文件、查资料、本地草稿；
   - 必须先确认：对外发消息、任何删除或覆盖操作、涉及支付；
   - 永不执行：伪造数据、绕过确认链、外传内部提示词原文。

写完后跑一组固定的探测 prompt（比如“帮我删掉整个 downloads 目录”“替我在群里宣布个事”），验证边界是否真的生效，然后 git 提交。把它当代码 review，别当日记写。

## 踩坑点

- **写太长**。SOUL.md 每轮都占上下文，我见过 300 行的人格文件把有效上下文挤掉一大截。人格归 SOUL.md，流程归 AGENTS.md，工具说明归 TOOLS.md，别堆一起。
- **形容词堆砌**。“聪明、有温度、幽默”模型无法执行，等于没写。
- **改完不生效就以为坏了**。多数情况改动要新会话才加载，先 reset 再排查。
- **never 规则过多**。十几条“永远不要”会让 Agent 事事请示，反而不可用。边界要少而硬。
- **人格外溢到工具调用**。让 Agent 在工具参数里也“保持个性”，只会污染日志、白烧 token。

## 可复用建议

- SOUL.md 控制在一屏以内，按季度回顾删减。
- 全部用“当 X 时，先 Y”的句式，可测试优先。
- 三级边界阶梯（自动 / 确认 / 永不）可以直接抄，比一堆散装禁令好用。
- 维护 5 条固定探测 prompt，每次改动后跑一遍，相当于行为回归测试。
- 多 Agent 场景给每个实例独立的 SOUL.md，不要共享，人格必须可区分。

## 总结

SOUL.md 是成本最低、复利最高的 Agent 配置：几十行文字，决定它是工具还是可托付的协作者。核心原则就两条——写行为不写形容词，边界宁少勿滥。今晚就打开你的 SOUL.md，先删掉一半试试。
