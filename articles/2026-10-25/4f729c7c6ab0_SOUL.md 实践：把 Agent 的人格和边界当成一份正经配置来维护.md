## 背景

OpenClaw 的 Agent 每次会话启动时，会把工作区里的一组 Markdown 文件注入上下文：AGENTS.md 管操作流程，USER.md 记用户偏好，而 SOUL.md 负责回答"这个助手是谁"——语气、价值观、行事原则和拒绝边界。很多人搭完 Gateway、接好 MCP 工具和插件之后就把这个文件忽略了，结果是 Agent 能干活，但行为不可预期。

## 问题

没有 SOUL.md 的 Agent 有几个典型症状：

- **语气漂移**：今天高冷明天话痨，长会话跑完面目全非；
- **过度顺从**：你说"帮我看看服务器"，它直接开始扫端口，哪怕你只是随口一问；
- **职责越界**：本该提醒你确认的操作，它默默执行了；
- **重复调教**：每个会话都要在首条消息里重新立规矩，prompt 越堆越长。

这些不是模型能力问题，而是约束没有沉淀成文件。人格写在聊天记录里，等于没有人格。

## 做法

我目前的 SOUL.md 维护流程，四步：

1. **先写"不做清单"**。人格描述很容易写空，禁止行为反而具体。比如：不主动删除文件、不代替用户做消费决策、用户没明确要求时不执行写操作。
2. **三段式结构**。第一段身份与语气，两三行就够；第二段决策原则（模糊请求先确认、涉及风险先说后果）；第三段拒绝话术，给一个固定句式，让拒绝行为可复现。
3. **控制长度**。它是每次会话都进上下文的文件，我压在 40 行以内。超了就砍形容词，只留行为规则。
4. **进 git**。改人格等于改配置，走 commit 和 diff，出问题能回滚。

一段可参考的骨架：

```markdown
# 身份
你是私人助理，语气平实，先给结论再给细节。

# 原则
- 模糊请求先确认再执行
- 删除、支付、对外发送类操作，必须复述并获得确认

# 边界
- 不执行未被要求的写操作
- 不确定时直说"我不确定"，不编造
```

分工上记住一条：SOUL.md 管"是谁、什么不做"，AGENTS.md 管"怎么干、走什么流程"。两边写重了，模型行为会抖。

## 踩坑点

- **把 SOUL.md 当权限系统**。它只是软约束，真正的边界要靠工具白名单、exec 审批和沙箱。"不许删文件"写进了 SOUL.md 但没配执行审批的，都吃过亏。
- **写形容词不写行为**。"要可靠""要聪明"没有可执行性，模型只能靠猜。
- **往里塞操作步骤**。把部署流程写进 SOUL.md，和 AGENTS.md 打架，模型时而走时而不走。
- **换模型不复测**。同一份 SOUL.md 在不同模型上服从度差异明显，升级后先用老用例跑一遍再上线。
- **一次写完不再迭代**。人格是运行出来的，不是写出来的。前两周我每周都会对着不满意的对话回填一条规则。

## 可复用建议

- 准备一组探测用例：越权请求、情绪化输入、模糊指令。改完 SOUL.md 就跑一遍，当成回归测试。
- 拒绝话术给模板，别靠模型即兴发挥。
- 长度预算当硬指标：SOUL.md + AGENTS.md + USER.md 合计建议控制在 2k token 内，超了先删后加。

## 总结

SOUL.md 的价值不在"让 Agent 更像人"，而在把不可预期的行为收敛成可维护的配置。写短、写具体、写行为不写形容词，配上版本管理和回归用例，它就是 Agent 最便宜也最有效的一层约束。如果你现在还没建这个文件，先从那份"不做清单"开始。
