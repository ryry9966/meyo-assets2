## 背景

社区每周都有值得沉淀的内容：Release Notes、精华讨论、新插件实测。靠人肉整理坚持了两个月，中断三次，于是我决定做一个定时发帖机器人：自动汇总社区动态生成草稿，人工确认后发到论坛。技术栈围绕 OpenClaw 展开：cron 触发 + Agent 生成 + MCP 工具采集 + 轻量脚本发布。

## 问题定义

需求看着简单，实际有三个硬约束：

1. 内容必须有据可查，不能让模型自由发挥；
2. 发布动作要可控，宁可延迟，不可发错；
3. 全链路无人值守，失败必须能被看见。

## 架构：生成与发布分离

```text
cron（每周一 09:00）
  → 采集层：MCP 工具抓 RSS / 仓库 Release / 精华帖列表
  → 生成层：独立 Agent，输出结构化 JSON（标题、摘要、链接列表）
  → 发布层：Python 脚本调论坛 API，先落盘草稿，approve 后发布
```

关键决策：Agent 只负责"写"，不负责"发"。发布走一个无 LLM 的薄脚本，重试、幂等、审计都发生在确定性代码里，出错不烧 token，也方便单独测试。

## 实施步骤

1. **采集**：给 Agent 挂三个 MCP 工具（RSS 读取、GitHub Release、论坛搜索），输入输出都限制条数，防止上下文膨胀。
2. **任务定义**：新建专用 agent，system prompt 明确"只允许引用工具返回的条目，输出固定 JSON schema，字段缺失则返回 error"，封装成 skill 复用。
3. **发布脚本**：读 JSON → 拼论坛正文 → 调 API，带 `--dry-run` 参数，只打印不提交。
4. **调度**：OpenClaw cron 设定时任务，显式指定时区，日志写本地文件并按周轮转。

## 踩坑实录

- **重复发帖**：API 超时后脚本重试，帖子发了两遍。修复：本地维护 `posted.json`，以"内容 hash + 目标板块"为幂等键，发布前先查。
- **上下文污染**：一开始图省事用主 agent 跑，几周后它开始"记得"旧素材，摘要里混入过期信息。换独立 agent + 每次全新会话后解决。
- **时区坑**：cron 默认 UTC，首帖发在凌晨三点。显式声明时区，并在日志里记录实际触发时间。
- **幻觉**：模型偶尔给不在列表里的链接"补全"。prompt 强约束之外，代码层再校验一次：链接必须出现在采集结果中，否则整篇打回。
- **格式逃逸**：论坛 API 对 Markdown 的处理和本地预览不一致，代码块里的下划线被吃掉。发布脚本统一做一次转义，再用 dry-run 比对渲染结果。

## 可复用建议

1. 生成与发布解耦，中间用结构化 JSON，任何一层都能独立替换和测试。
2. 状态外置到文件，幂等键设计在先，重试随便加。
3. dry-run 是发帖类自动化的标配，没有它不要上线。
4. Agent 权限最小化：只给必需的工具和只读 token。
5. 人审开关保留到最后一步，先全 dry-run 跑一个月，再逐步放开。

## 总结

上线六周，发帖 6 篇，零事故，单篇人工修改量从 20 分钟降到 5 分钟。最大的体会是：LLM 产出的内容质量是概率性的，所有工程设计都应假设它会出错——用确定性代码包住不确定性，自动化才敢真正交给定时任务。欢迎大家在自己的频道里套这套结构，采集源和发布目标换了，骨架不用动。
