## 背景

写 Agent 的人大多熟悉 CLAUDE.md / AGENTS.md 这类项目级上下文文件：告诉模型仓库怎么跑、有哪些约定。但项目文件描述的是"事"，不是"人"。换个会话，Agent 依然不知道你用 macOS 还是 Linux、偏好 pnpm 还是 npm、回复要详还是略。

在 OpenClaw 这类常驻型框架里，问题更明显——它是长期陪你干活的助手，不是一次性问答工具。偏好每次靠人工重申，长期协作就名存实亡。

## 问题

三个典型痛点：

1. **重复交代**。同一句"测试用 vitest，别用 jest"，一个月说了四遍。
2. **假设错误**。Agent 默认按 Linux 写命令，而你的主力机是 macOS；或自作主张加 emoji 和客套话。
3. **行为漂移**。多会话之间不一致，因为它每次都在猜。

## 做法：把"你是谁"写成一个文件

思路很朴素：项目有 AGENTS.md，用户也该有一份 USER.md——固定路径、随会话加载。

1. 建 `~/.openclaw/USER.md`，控制在 60 行以内。
2. 内容分五段：
   - **身份与角色**：一句话，如"后端工程师，主写 Go 和 TypeScript"。
   - **环境事实**：OS、shell、包管理器、时区。只写可验证的事实。
   - **偏好**：代码风格、回复语言与详略、是否要解释理由。
   - **边界**：明确禁止项，如"不要主动 sudo""不要动 .env"。
   - **维护记录**：末尾留一行更新日期。
3. 在启动配置里把它挂进 system prompt 或首条 bootstrap 消息；走 MCP 的话可以封装成 resource，按需读取。
4. 提交进私有仓库，跨机器同步。

关键取舍：USER.md 管"人"的稳定偏好，AGENTS.md 管"项目"的具体约定。冲突时项目优先——这条规则本身也写进 USER.md，让 Agent 知道。

## 踩坑点

- **写太长**。超百行后关键偏好会被淹没，模型注意力不是均分的，重要规则放前面。
- **塞敏感信息**。API key、手机号、内网地址一律不写，它是明文且会被同步。
- **写成许愿池**。"帮我把代码写好"这种无法判定的句子不如不写，每条都要具体到可判断对错。
- **忘了更新**。换了机器、换了技术栈，文件里还是半年前的事实，Agent 拿旧假设出错。更新日期就是给自己看的警告。
- **和项目文件打架**。全局说回复用中文，项目要求英文提交信息，Agent 会犹豫。优先级必须显式声明。

## 可复用建议

- 让 Agent 参与维护：定期让它读最近会话和 git 历史，提议 USER.md 修订，你只做审核，比手写省力得多。
- 按"事实 > 偏好 > 边界"的优先级组织内容，排查行为异常时按这个顺序查。
- 团队场景可把"环境事实"抽成共享模板，个人偏好各自保留，降低新人配置成本。
- 30 行写清楚，好过 200 行写全。定期删。

## 总结

USER.md 不是什么新范式，本质是把 prompt 里最稳定的部分持久化成文件，用工程手段管理而非依赖模型记忆。它的价值不在第一次配置，而在第 20 次会话——Agent 不再猜你是谁。半小时写第一版，每季度花十分钟审一次，这笔账很划算。
