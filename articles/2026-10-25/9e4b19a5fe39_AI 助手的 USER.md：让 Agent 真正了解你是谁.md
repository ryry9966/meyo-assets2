## 背景

OpenClaw 的 workspace 里有几类约定文件：AGENTS.md 管"怎么干活"，SOUL.md/IDENTITY.md 管 agent 自己的人设，MEMORY.md 管事件流水。但有一块长期缺位：agent 对"我"的了解。每次新会话，你可能都要重新交代一遍技术栈、时区、沟通偏好。USER.md 就是补这个缺口的——一份随 workspace 注入上下文的用户档案。

## 问题

没有 USER.md 时的三种典型损耗：

1. **重复成本**：换会话、换设备就要自我介绍一遍；
2. **假设漂移**：agent 按通用习惯回答，比如给你生成 Debian 的命令而你在 macOS，或用你不喜欢的风格写代码；
3. **记忆不可控**：重要偏好散落在历史消息里，无法审计、无法迁移、无法批量修改。

## 做法

**第一步：建立文件。** 放在 workspace 根目录 `~/.openclaw/workspace/USER.md`，全文控制在 300–500 token。一个够用的骨架：

```markdown
# USER

## 环境
- 主力机：macOS (arm64)，服务器 Ubuntu 22.04
- 时区：Asia/Shanghai

## 技术背景
- 后端方向，主力 Go/Python，正在学 Rust
- 偏好：直接给结论和代码，不要铺垫

## 硬性约束
- 提交信息用中文，代码注释用英文
- 改数据库、删文件类操作先确认再执行

## 禁止
- 回复不用 emoji
```

**第二步：让 agent 维护它。** 在 AGENTS.md 里加一条规则：当你说"记住 XX"，或 agent 发现对话事实与 USER.md 冲突时，先复述要写入的内容，确认后追加或修改对应小节，而不是直接落盘。

**第三步：纳入版本管理。** workspace 建议 git 化。USER.md 的每次变更可 diff、可回滚，换机器也能同步。

**第四步：定期修剪。** 每月过一遍，删掉过期项（换了栈、换了机器），合并重复项。

## 踩坑点

- **写太长**：USER.md 每轮都进上下文，超过 1000 token 就是纯烧钱，还会稀释注意力。原则：只写"会影响它怎么回答你的事实"，不写生平简历。
- **放敏感信息**：密码、API key、真实住址不要放。接云端模型时这份文件会随上下文出网；敏感约束用规则表述（"密钥只从环境变量读"），绝不写值。
- **和 MEMORY.md 混职责**：USER.md 放长期稳定的"你是谁"，MEMORY.md 放事件与项目进展。混在一起，两周后就没法看了。
- **信息过期不自知**：agent 会忠实执行过时约束。我换设备后忘了更新一条，被错误执行了两周才想起来。
- **多 agent 场景没分层**：全局 USER.md 放个人偏好，项目级 AGENTS.md 放项目约定，冲突时后者优先——优先级要明写。

## 可复用建议

- 用**指令式**而非描述式写法：「代码注释用英文」优于「我是中国人」，前者是可直接执行的规则；
- 每条一个事实，一行一条，方便 agent 精准增删；
- 把"记住 XX"做成固定指令或 MCP 工具调用，落到文件而不是对话记忆；
- 团队场景里 USER.md 是个人资产，别提交到公共仓库，放私有 dotfiles 管理；
- 修剪时的心智模型：逐条问"这条还成立吗"，不成立就删，不恋战。

## 总结

USER.md 本质上是把上下文工程里最容易被忽略的一层——用户画像——变成显式、可审计、可版本化的文件。它没有玄学，就是几条整洁的事实加上一套维护流程。花二十分钟写第一版，之后每次"它怎么又不知道这个"的烦躁，都会变成一行 diff 的修补。Agent 了解你，不该靠运气，该靠文件。
