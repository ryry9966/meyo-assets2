## 背景

我日常用 OpenClaw 管几个小项目和一台服务器，信息散落在 git 提交、shell 历史、服务报错日志和 IM 消息里。每天手写日报半小时，还经常漏掉真正重要的异常。于是搭了一条「采集 → 归一 → 摘要 → 成稿 → 投递」的流水线，由定时任务驱动，Agent 每天早上固定产出一份日报。

## 问题

核心矛盾有两个：

1. 原始日志又多又噪，直接丢给模型，context 撑不住，关键信息还会被稀释；
2. 日报要的是「固定结构 + 稳定投递」，而模型输出天然会漂移。

所以原则是：**能用脚本算的绝不让模型算，模型只做最后一公里的归纳。**

## 做法

流水线分五段，各自独立，失败可单独重跑：

1. **采集**：三个 cron 任务每天 07:30 各自运行：`git log --since=...` 导出当日提交；服务日志 grep ERROR/WARN 带上下文；OpenClaw 会话记录里筛出当天确认过的关键决策。也可以用 MCP 工具从任务系统拉当日事项。输出统一为 JSONL，字段固定：`source / ts / level / text`。
2. **归一与降噪**：正则白名单过滤心跳类噪音，去重，每个 source 截断上限（80 条），时间统一转 UTC。token、内网 IP 等敏感字段在这一层脱敏。
3. **分源摘要（map）**：JSONL 按 source 分块，逐块让 Agent 产出三句话以内的要点，避免单次 context 过长。
4. **汇总成稿（reduce）**：固定 Markdown 模板，四个固定小节：今日完成 / 异常与风险 / 关键数据 / 明日待办。统计类数字（提交数、报错数）由脚本预算好填入，模型不负责数数。
5. **投递与校验**：通过消息渠道推送，同时落盘 `reports/YYYY-MM-DD.md`。投递前跑校验：小节齐全、数字与源数据一致；不一致重试一次，再失败则降级为「原始摘要版」并告警。

## 踩坑点

- **时区**：cron 默认 UTC，日志时间戳却混着本地时间，第一天日报直接「跨天」。现在采集层统一 UTC，渲染时再转本地。
- **格式漂移**：只靠 prompt 约束结构，三天后小节就开始变形。改成模板填充 + 校验后才稳定。
- **静默失败**：流水线挂了不报错，连续两天没收到才发现。补了心跳机制：成功写标记文件，连续两次失败发告警。
- **数字幻觉**：让模型「统计今日提交数」，十次能错两次。数字全部脚本预计算。
- **脱敏别指望模型**：凭证在采集层直接抹掉，不要让敏感内容进入 context。

## 可复用建议

- **采集与生成解耦**：collector 只产标准 JSONL，生成器只消费标准格式。以后接新数据源（如 CI 结果），只需写一个新 collector。
- **Prompt 模板进 git**：改动可回溯，报告质量变化能对应到模板版本。
- **日报落盘存档**：既是回溯材料，也是后续调 prompt 的评测集。
- 先保证「每天准时、结构固定、数字可信」，再考虑加图表。

## 总结

这条流水线的价值不在「AI 会写报告」，而在工程侧的固定结构、预计算和校验兜底；模型只承担它擅长的归纳。整套东西一个晚上能搭完，第二天起每天早上九点，日报会准时出现在会话里。
