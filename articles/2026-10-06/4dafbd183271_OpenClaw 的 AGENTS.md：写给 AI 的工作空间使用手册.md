## 背景

OpenClaw 的 agent 并不是每次会话都从零开始理解你。它在工作空间（workspace）里有一组常驻文件：`MEMORY.md` 管长期记忆，`memory/` 目录按时间归档过程记录，`HEARTBEAT.md` 管周期任务。而 `AGENTS.md` 是其中最特殊的一个——每次会话启动时自动注入上下文，相当于写给 AI 的操作手册。README 是给人看的，AGENTS.md 是给 agent 看的。

## 问题

没有手册时，agent 的行为完全取决于模型默认习惯和零散聊天记录，问题很典型：

- 每次会话重新确认时区、语言偏好这些环境事实；
- 记忆写入随意，`MEMORY.md` 很快膨胀成流水账；
- 装了 MCP 工具后，agent 不确定该用内置工具还是外部工具，路由靠猜；
- 高风险操作（删文件、对外发消息）缺少统一约束，每次都得口头叮嘱。

在单条消息里反复提示不可扩展，上下文一重置就归零。这些规则需要一个稳定、自动生效的落点。

## 做法与步骤

1. **定位文件**。AGENTS.md 放在工作空间根目录（默认 `~/.openclaw/workspace/AGENTS.md`），会话自动加载，不需要手动引用。
2. **用五段式搭骨架**：身份与边界、环境事实、工具路由、记忆管理、安全红线。每段只写规则，不写散文。
3. **写成可判定条目**。"保持高效"没用；"回复默认中文，日期用本地时区"才有用。一条一行，附正反例更好。
4. **明确工具路由**。例如"文件检索优先内置工具，网页抓取走 MCP 的 fetch；工具失败一次后降级重试一次再报告"。每接入一个新 MCP server，就补一条对应规则。
5. **约束记忆写入**。写清什么进 `MEMORY.md`（长期偏好、稳定事实），什么进 `memory/` 归档（过程记录），避免 agent 把一切塞进长期记忆。
6. **纳入版本管理**。放进私有 git 仓库，每次修改有 diff 可回溯。

## 踩坑点

- **写太长**。它每次会话都占上下文，几百行的手册会挤压有效空间、稀释关键规则。控制在百行以内，细节下沉到子代理 prompt。
- **混入敏感信息**。API key、家庭地址写进去等于每次会话都注入一遍，这类内容应放环境变量或凭据管理。
- **放任 agent 自我改写**。不加约束的话手册会慢慢漂移，建议规定"修改 AGENTS.md 需人工确认"。
- **只写愿景不写规则**。写得像入职文化手册，agent 却无从执行。
- **一次写完不再维护**。手册的价值在迭代，每次踩坑补一条，比追求一次写完美更现实。

## 可复用建议

- 用 incident 思维维护它：agent 每犯一个错，先判断是模型能力问题还是规则缺失，后者补进对应小节。
- 主手册保持精简，场景化规则（某条自动化流程的细节）交给子代理的独立 prompt，形成分层。
- 每周 review 一次 git diff，主动删掉过时规则——失效规则比没有规则更糟。
- 多设备/多实例场景下，通过私有仓库同步，保证所有 gateway 行为一致。

## 总结

AGENTS.md 成本极低、杠杆极高：几十行规则就能显著压低 agent 行为的方差。把它当成给 AI 的 README 持续维护，是 OpenClaw 实践里投入产出比最高的事情之一。手册的质量，基本决定了 agent 的稳定下限。
