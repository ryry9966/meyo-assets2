## 背景

这一年来，社区在上下文工程上花了不少力气：AGENTS.md 约定项目规则，MCP 把工具和数据标准化接入，插件补齐能力。但有个更基础的问题长期没被系统解决——**Agent 不知道你是谁**。每个新会话都是冷启动，模型对你的了解约等于零。

## 问题

冷启动的真实代价不是开场多打几句，而是一类持续性摩擦：

- 环境每次重新交代：macOS 还是 Linux、用什么包管理器、时区在哪；
- 输出风格漂移，昨天约好的简洁风格，今天又变回长篇大论；
- 行为约束失效，"不要自动 commit"这类禁令得反复声明；
- 依赖平台内置记忆又不可控：黑盒、无法 review、无法 diff、无法迁移。

## 做法

思路很朴素：把用户侧上下文抽成一个文件，命名为 `USER.md`，放在固定路径（比如 `~/.openclaw/USER.md`），会话启动时注入 system prompt。

1. **建文件**，按五个区块组织：环境（OS/shell/时区/语言）、输出偏好、行为边界（明确写 never do）、常用工具链与路径、当前关注点；
2. **控制体积**在 1–2KB，短句加列表，不写散文；
3. **注入**：在启动配置的 system prompt 模板里加一行 include；也可以用 MCP resource 暴露，供多个客户端复用；
4. **分层**：全局 USER.md 只放跨项目事实，项目约定进 AGENTS.md，冲突时项目侧优先；
5. **纳入 dotfiles 仓库**做版本管理。

骨架示例：

```markdown
# 环境
- 系统: macOS 15 / arm64, shell: zsh
- 时区: Asia/Shanghai, 回复语言: 中文

# 偏好
- 先给结论，解释放最后
- 代码改动优先最小 diff

# 边界
- never 自动 git push
- never 删除未备份的数据

# 工具链
- Node 22 + pnpm; Python 走 uv
```

## 踩坑点

- **写太长**。条目超过一定数量后遵循度明显下降，关键禁令被稀释，宁少勿多；
- **信息腐化**。换机器、换技术栈后旧条目还留着，Agent 会拿过期事实自信输出。建议每季度 review，或直接让 Agent 对比现状提出 diff 提案；
- **隐私泄露**。USER.md 会随每次请求发往模型 API，别放 token、内网域名、真实客户名，敏感值一律占位符；
- **职责混淆**。用户侧写"我是谁"，项目侧写"这个项目怎么做"，混写两边都难维护；
- **用第一人称散文写**。结构化条目的遵循度远高于大段自述。

## 可复用建议

- 检验标准很朴素：**看重复指令的消失量**。之前每个会话都要交代的事，现在不说也生效，就写对了；
- 维护公开/私有两份：私有版全量自用，公开版脱敏后可给团队或开源仓库复用；
- 把沉淀变成即时动作：每次发现自己在重复交代某件事，当场写进 USER.md，比事后回忆准确得多。

## 总结

USER.md 没有任何黑科技，本质是把"用户是谁"从聊天记录里抽出来，变成可版本化、可 review、可迁移的一等配置。二十分钟能写完第一版，之后持续沉淀。当 Agent 不再问你已经回答过十遍的问题时，收益自然显现。
