## 背景

OpenClaw 的 workspace 里有一组约定文件：`SOUL.md` 管价值观，`MEMORY.md` 管记忆，`USER.md` 管对用户的了解，而 `IDENTITY.md` 管的是"我是谁"。它会在每次会话启动时被注入系统提示，构成这个 agent 在所有对话里的身份基线。

很多人装完只写两行"你是一个助手"，之后再没动过。这份文件的价值不在第一次写了什么，而在它提供了一条可控的身份演化通道。

## 问题

不用或滥用 IDENTITY.md 时，典型症状是：

- 每次重开会话语气不一致，今天简洁明天话痨；
- 想调整说话方式只能改全局配置，一次改动全家受影响；
- 身份定义散落在各种 prompt 片段里，无法 diff、无法回滚；
- 长期目标、命名、边界这些"稳态信息"和记忆里的"动态信息"混在一起。

本质上是：身份没有被当成一个有生命周期的工程对象来管理。

## 做法

1. **定位文件**：工作区根目录的 `IDENTITY.md`。多实例部署时每个 agent 一份，不要共享。
2. **只写稳态字段**：名字、一句话 bio、性格基调、emoji、口吻规则（比如"默认简洁，代码注释用中文"）。整体控制在 20 行以内。
3. **写行为，不写口号**。"要有温度"模型执行不了；"回复默认不超过五句话，除非用户追问细节"才可执行。
4. **用 git 管**：workspace 本身就是仓库，每次改动都 commit，身份漂移了能回滚，也能看 diff。
5. **让进化可控**：在 cron 任务里加一条"每月回顾 IDENTITY.md，发现行为不匹配时提出修订建议，改动需人工确认"。默认不要给 agent 免确认的写权限。

## 踩坑点

- **塞记忆进去**。写到 80 行，token 翻倍还稀释重点。动态信息归 MEMORY.md。
- **放任 agent 自我改写**。模型会往"讨好用户"的方向漂，两周后发现它变成了另一个东西。人工 review 是底线。
- **多 agent 复用同一份**。工作 agent 和私人助手串味，语气互相污染。
- **改完不生效**。IDENTITY.md 在会话启动时注入，改完需要重开会话或重新加载才会生效。
- **写空话**。"聪明、可靠、友好"这类形容词约等于没写。

## 可复用建议

- **身份分层**：IDENTITY.md（我是谁）→ SOUL.md（我相信什么）→ MEMORY.md（我记得什么），各管各的，别越界。
- **版本化 + 定期回顾组合拳**：git 提供回滚能力，月度回顾提供进化通道，两者缺一不可。
- **排查入口**：每次觉得 agent "不对劲"，先 diff 身份文件，再查配置和插件。

## 总结

IDENTITY.md 是个很小的文件，但它把 agent 的身份变成了可审查、可回滚、可定期演化的对象。四件事做完就够：20 行以内、写可执行的行为、进 git、改动留痕。做到这些，agent 才算有了一个随时间生长、但不会跑丢的身份。
