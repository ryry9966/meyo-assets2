## 背景

Agent 每次会话都是冷启动。OpenClaw 的 workspace 约定里，AGENTS.md 管行为规范，SOUL.md 管人格基调，MEMORY.md 记过程流水——但"用户是谁"这件事，一直没有固定位置。结果是每次新会话都要重新交代一遍：时区、技术栈、说话风格、正在做的项目。说得烦，不说就靠模型猜。

USER.md 就是补上这块的：一份关于用户本人的稳定事实文件，随 workspace 一起被注入上下文，每次会话都生效。

## 不写它的典型症状

- 每次重复自我介绍，或者懒得说，agent 按默认习惯输出
- 它不知道你在 Docker 里部署、主力是 Python、时区 UTC+8，给出的方案总差点意思
- 回复风格忽长忽短，和你的阅读习惯对不上
- MEMORY.md 里"用户偏好"和"事件记录"混在一起，越翻越乱

## 做法

1. 在 workspace 根目录建 USER.md，控制在 30–60 行。
2. 分区写，只放稳定事实：

```markdown
# 关于我
- 称呼 / 时区 / 常用工作时段

## 环境
- 主力语言、框架、部署方式、常用机器

## 沟通偏好
- 回答详略、是否要推理过程、中英术语习惯

## 硬约束
- 不要自动 git push
- 不要动某个目录

## 当前焦点
- 一两句话级别的长期项目
```

3. 易变信息（本周任务、临时决定）一律进 MEMORY.md，不进 USER.md。
4. 用 git 管起来。需要更新时直接说"把 XX 写进 USER.md"，然后人工 review 那次 diff——这个习惯能挡住大半事故。

## 踩坑点

- **写太长**：几十条偏好塞进去，注意力被稀释，硬约束反而被淹没。宁少勿多。
- **放敏感信息**：token、密码、内网地址不要写。这份文件会进每一次会话的上下文。
- **易变信息混入**：任务清单不是身份事实，一周就过期，之后全是误导。
- **约束互相冲突**：既要求"回复简短"又要求"每步详细解释"，模型只能随机选一边。
- **多用户部署没隔离**：一个 gateway 服务多人时，每人的事实要分开，否则上下文串味。

## 可复用建议

- 把 USER.md 当配置文件对待：版本化、小步改、diff 有理由。
- 每月扫一遍，删过期项，比加新项更重要。
- 新装一个 agent，先花十分钟写 USER.md 再干活，成本很低，换来之后所有会话不用重新对齐。
- 多个 agent 共用 workspace 时，抽公共事实为单一来源，避免多份拷贝各自漂移。

## 总结

USER.md 不是什么新协议，就是把上下文工程里最稳定的那一层显式化。它解决的不是模型能力问题，而是重复沟通成本。一张小卡片，agent 少猜，你少说，输出的一致性立刻能感知到。
