## 背景

大部分人用 Agent 的姿势是问答式：你提问，它回答，窗口一关就结束。但 OpenClaw 的 Agent 是常驻进程——一直在线、有工具、有 MCP、能碰你的文件和消息。只做被动应答，等于雇了个全职员工却只让他看前台。

OpenClaw 内置了心跳机制：网关按固定间隔（默认 30 分钟，可在配置里调整）把工作区里的 `HEARTBEAT.md` 注入 Agent 上下文，让它像值班员一样过一遍值班表，自己判断这轮有没有值得做的事。

## 问题

纯被动模式覆盖不了时间驱动的任务：每天早上汇总邮件和 commit、盯磁盘和监控告警、跟进之前说好"回头处理"的事项、检查定时脚本的产物。系统 cron 能管时间点，但没有判断力，发出来的永远是死板的固定内容；心跳机制则把"定时触发 + 是否值得打扰用户"这两个判断都交给模型本身。

## 做法与步骤

1. 在工作区根目录（默认 `~/clawd/workspace`）新建 `HEARTBEAT.md`，写成清单式：

```markdown
# Heartbeat
- 有未读的紧急邮件时，一行摘要 + 链接，主动通知我
- 检查 repo 的 CI 状态；失败则报告原因和日志路径
- 无事发生时，只回复 HEARTBEAT_OK
```

2. 调整间隔：默认 30 分钟够日常用，调试期可临时调短到一两分钟快速验证行为。
3. 理解短路机制：Agent 判断无事可做时回一个 `HEARTBEAT_OK`，网关据此不向你推送任何消息；只有真有发现才进主会话。
4. 心跳轮次里可以正常调用工具和 MCP：读日历、查 API、跑脚本，和普通对话没有区别。

## 踩坑点

- 清单别写长。文件每轮都会注入，50 条 × 每天 48 轮是实打实的 token 开销，控制在 3–5 条。
- 指令必须可判定。"关注一下仓库"只会得到沉默或刷屏，"CI 失败就报告"才能稳定执行。
- 别漏掉 `HEARTBEAT_OK` 兜底，否则你会每 30 分钟收到一句"本轮无事"。
- 心跳跑在主会话上下文里，长期对话会让每轮心跳越来越贵，定期清理会话。
- 心跳本身会静默挂掉：网关崩了、机器休眠了都算。加一个外部看门狗，超过 N 分钟没有心跳日志就报警。

## 可复用建议

- 把 `HEARTBEAT.md` 当代码管理：进 git，每次改动走 review，留变更记录。
- 每条用固定模板：触发条件 + 判定标准 + 动作 + 汇报格式。
- 有条件的话心跳轮用便宜的小模型，真有发现再切大模型处理。
- 让 Agent 把每轮心跳的决策追加到日志文件，方便审计和调间隔。
- 只把"值得叫醒老板的事"放进心跳，其余交给普通 cron 和脚本。

## 总结

HEARTBEAT.md 的本质是给 Agent 一张值班表：定时器是心跳，清单是值班日志，`HEARTBEAT_OK` 是"本轮无事"。守住短、可判定、可观测这三条，Agent 就能从一个你提问才动的聊天框，变成会自己巡逻的同事。
