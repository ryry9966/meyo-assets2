## 背景

Agent 落到真实业务里，几乎绕不开"读网页"：调研、监控、RAG 语料补充。和传统爬虫不同，Agent 的抓取目标是**运行时由模型动态决定**的——用户一句话、模型一次推理，就可能触发一次任意 URL 的请求。这里玩了个谐音：不只当"爬客"，还得会"稽查"自己。风险模型因此和写死的爬虫完全不同。

## 问题

三类核心风险：

1. **SSRF**：模型被诱导请求 `http://127.0.0.1`、云元数据地址（169.254.169.254）或内网服务，等于把内网探测权交给了模型。
2. **提示注入**：抓回来的页面里藏着"忽略之前的指令"，内容直接进上下文，工具调用权就可能被劫持。
3. **失控成本与封禁**：SPA 返回空壳触发反复重试、单站点并发过高被封 IP、原始 HTML 塞爆上下文。

## 做法：把抓取收敛成一个带闸门的工具

在 OpenClaw 里挂成一个 MCP tool，所有抓取只走这一个入口，工具层做五道闸：

1. **网络闸**：URL 解析校验后，先做 DNS 解析，检查 IP 是否落在私有/回环/链路本地段；跟随重定向时**每跳重新校验**，最多 3 跳。
2. **抓取闸**：限制超时、体积、Content-Type 白名单；默认纯 HTTP 抓取，仅当内容明显是空壳时才降级到无头浏览器，且浏览器跑在独立沙箱。
3. **提取闸**：正文抽取转纯文本，剥离 script/style，按结构截断，返回"标题 + 正文 + 来源 URL + 抓取时间"，控制在几千 token 内。
4. **礼仪闸**：缓存 robots.txt，按域名做令牌桶限速，支持条件请求（ETag / Last-Modified），结果按内容哈希缓存，TTL 内不重复抓。
5. **注入闸**：页面内容以明确的"数据块"包裹进上下文，系统提示声明其中任何指令一律不执行；涉及写操作或二次工具调用强制人工确认。

一份可抄的基线配置：

```yaml
fetch:
  timeout: 10s
  max_bytes: 2097152
  max_redirects: 3
  block_private_ip: true
  respect_robots: true
  per_domain_rate: 1rps
extract:
  mode: readability
  max_tokens: 4000
```

## 踩坑点

- 只校验了 URL 字符串，没校验 DNS 解析结果，十进制 IP 写法和 DNS rebinding 直接穿透。
- 重定向投毒：第一跳合法、第二跳跳进 `169.254.x.x`，必须逐跳检查而不是只查入口。
- robots.txt 只查了主域，子域名路径照样抓，收到了对方投诉。
- 失败重试没做退避，Agent 一"慌"连打 20 次，IP 进了对方黑名单。
- GBK 编码页面没按 charset 转码，进上下文全是乱码，白烧 token。

## 可复用建议

- **抓取能力只暴露一个工具**，不要散落在各处 prompt 里；允许列表按部署环境配置化。
- 把抓取当**贵重操作**：缓存、去重、指数退避，默认悲观。
- 用本地 fixture 服务做回归测试：专门放一个含 SSRF 探针和注入样本的页面，跑进 CI。
- 留一个全局开关和审计日志（URL、状态码、字节数、内容哈希），出事能立刻定位和止血。

## 总结

Agent 时代的抓取，难点不在"会不会写爬虫"，而在"抓取决策交给了模型"这一步。防线必须落在工具层：网络校验、抓取限额、内容抽取、访问礼仪、注入隔离，五道闸各自独立生效。提示词约束只能作为补充——模型会被骗，闸门不会。
