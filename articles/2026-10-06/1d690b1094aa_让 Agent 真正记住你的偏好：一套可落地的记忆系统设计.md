## 背景

Agent 每次会话都是无状态的。用 OpenClaw 搭的助手，昨天说过"代码注释用中文、默认用 pnpm、别加 emoji"，今天还得再说一遍。上下文窗口再大，跨会话也带不走。社区常见两类做法：把历史全塞进 system prompt，或者上向量库做全量 RAG。前者贵且稀释注意力，后者召回的多是噪音——偏好是"结构性事实"，不是"可检索的片段"。

## 问题定义

记忆系统的难点不在"存"，而在四件事：

- **写什么**：会话里大量内容是一次性的，只有少数是稳定偏好
- **怎么更新**：偏好会变，旧记忆不能永远压过新指令
- **怎么读**：哪些每次必带，哪些按需召回
- **怎么过期**：不清理的记忆库，半年后信噪比必然崩

## 做法：最小可行设计

1. **分层**。三类记忆分开存：用户画像（稳定偏好，几十条以内）、情景记忆（近期项目事实，带 TTL）、项目知识（按 workspace 隔离）。
2. **定义 schema**。起步一个 `memory.json` 就够：`key`、`value`、`scope`、`confidence`、`source`（用户明说 / 行为推断）、`updated_at`。key 要规范化，比如 `code.comment_lang`，避免"注释语言""comment style"这种近义重复。
3. **写入走提取，不走直录**。会话结束后跑一个提取步骤，用小模型按 schema 抽候选记忆，confidence 低的不落盘。用户显式说"记住我偏好 xxx"的，confidence 直接拉满。
4. **读取分两路**。画像层每次会话开始固定注入，硬预算 500 token 以内；情景层用工具按需查询，不默认加载。MCP 里把画像暴露成 resource，读写暴露成 tool，Agent 自己也能调。
5. **生命周期**。同 key 写入即合并更新；冲突时"用户明说 > 行为推断，新 > 旧"；每周跑一个 compaction job，合并相似条目、淘汰过期项。

## 踩坑记录

- **把临时指令推断成永久偏好**：用户某天说"简短点"，被写成永久偏好，之后所有回答都变干瘪。解法：临时指令只在当前会话生效，除非重复出现 N 次才升级。
- **旧记忆压新指令**：用户换了语言或工具链，Agent 还按旧偏好走。解法：`updated_at` 参与排序，检测到冲突时明确问一句"你之前偏好 X，现在要改成 Y 吗"。
- **无限增长**：三个月涨到两千条，注入的信噪比雪崩。解法：画像层硬上限（比如 40 条），超出走摘要压缩。
- **隐私与遗忘**：记忆文件会被同步备份，里面可能有敏感偏好。必须有 `forget` 命令，且是物理删除，不是标记失效。
- **没有评测**：记忆 bug 出现得很晚，改完不知道有没有修好。解法：固定一组跨会话测试用例，每次改动跑一遍。

## 可复用建议

- 从文件 + schema 起步，别一上来上向量库——偏好召回基本用不上语义检索。
- 写入策略比读取策略重要，源头脏了后面全白搭。
- 给每条记忆带 `source` 和 `session_id`，排查"它为什么这么做"时救命。
- 提供查看和遗忘的入口，用户可控是信任底线。

## 总结

Agent 记忆本质是个数据工程问题：schema、写入策略、读取预算、生命周期，四件事做扎实，比换更强的模型有效得多。先用最土的 JSON 方案跑起来，等痛点真实出现了再演进。
