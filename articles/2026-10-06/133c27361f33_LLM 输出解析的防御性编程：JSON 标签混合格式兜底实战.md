## 背景

在 OpenClaw 的插件和 Agent 自动化里，让模型按约定格式返回结构化结果是家常便饭：子任务结果回传、工具调用的中间约定、多步编排里脚本与模型的握手。常见做法是让模型把 JSON 包在 `<JSON>...</JSON>` 标签里，脚本再用正则抠出来。这条路能用，但模型输出是概率性的——换个模型、调个温度，甚至只是重跑一次，包法就可能不一样。

## 问题

跑了一段时间后，我的解析日志里攒出了这些真实形态：

1. 标准形态 `<JSON>{...}</JSON>`
2. 标签里再套一层 markdown 围栏
3. 标签丢失，只剩裸 JSON 或裸围栏
4. 标签大小写、空格漂移：`< json >`、`</JSON >`
5. JSON 后面跟着一段“补充说明”
6. JSON 本身不合法：尾逗号、单引号、`True/None`、未转义换行
7. 多轮输出拼接后，贪婪正则把两段 `<JSON>` 吞成一段

任何一种单独看都不难，混在一起就是线上故障配方。我的第一版解析器上线三天，就因为第 7 条把两轮工具调用粘成了一段脏数据。

## 做法

思路是把解析做成一条从严格到宽松的流水线：每一步失败就降级，永不指望一步到位。

```python
import json, re

def extract_json(text: str):
    text = text.strip().lstrip("\ufeff")
    try:                                   # 1) 快速路径：整体就是 JSON
        return json.loads(text)
    except Exception:
        pass
    cands  = re.findall(r"<\s*json\s*>([\s\S]*?)<\s*/\s*json\s*>", text, re.I)
    cands += re.findall(r"```(?:json)?\s*([\s\S]*?)```", text)   # 2) 标签对 + 3) 围栏
    cands += balanced_scan(text)           # 4) 括号配平扫描出的 {…} / […] 候选
    for c in reversed(cands):              # 5) 从后往前：模型常先铺垫后给答案
        try:
            return json.loads(c.strip())
        except Exception:
            continue
    return None
```

几条补充：

- 正则一律非贪婪、忽略大小写，且保证开闭标签成对完整，避免抓到只开了头的半截。
- `balanced_scan` 从每个 `{` 或 `[` 出发，逐字符记录深度和“是否在字符串内”（注意转义符），配平时截取候选。它兜住标签和围栏全部失效的情况。
- 全部失败前加一道克制的修复层：只修尾逗号、`True/False/None` 这类低风险问题，修一轮再重试。激进的单引号转双引号会破坏含撇号的字符串值。
- 解析失败先把原始输出落盘再返回 `None`，失败样本是你后续改进的语料。

## 踩坑点

- `[\s\S]` 别忘写：JSON 跨行是常态，`.` 默认不匹配换行，这是最经典的翻车点。
- Python 的 `json.loads` 默认接受 `NaN` 和 `Infinity`，这不是合法 JSON，下游序列化会再炸一次；严格场景用 `parse_constant` 拦掉。
- 标签可能出现在字符串值里——模型把你 prompt 里的示例原样复读了一遍，所以要抓“完整对”，必要时取最后一个完整对。
- BOM、零宽字符、中文语境的全角引号，都会让 `json.loads` 静默失败，入口处先清洗不可见字符。
- 输出被 `max_tokens` 截断时标签有头无尾，任何提取器都救不回完整 JSON，此时该触发的是带纠正提示的重试，而不是继续修。
- `temperature=0` 也不保证格式稳定，模型一升级照样漂移，别指望 prompt 一劳永逸。

## 可复用建议

- 解析逻辑收口到一个模块，全项目唯一入口，别让正则散落在各插件里。
- 失败不要抛异常打断 Agent 循环，返回结构化错误对象，让上层决定重试还是降级到默认值。
- parse 成功不等于数据可用。过一层 schema 校验，校验失败和解析失败走同一条重试通道。
- 给解析器加命中路径埋点（strict / tag / fence / brace / repair）。如果 fallback 命中率持续偏高，该回去改 prompt 或收紧输出约束，而不是继续堆正则。
- prompt 侧同步加压：few-shot 给出精确格式，明确“只输出一个 JSON 对象，不要附加解释”。这能压低变异率，但替代不了防御性解析。
- 每种新失败形态沉淀成 fixtures，加进回归测试。

## 总结

LLM 输出本质上是不可信输入，解析边界要按处理用户输入的标准来建。目标不是写出完美 prompt，而是让流水线在格式漂移时依然可观测、可降级、可回归。标签、围栏、配平三层兜底，加一层克制的修复，基本覆盖了我这一年见过的所有形态。
