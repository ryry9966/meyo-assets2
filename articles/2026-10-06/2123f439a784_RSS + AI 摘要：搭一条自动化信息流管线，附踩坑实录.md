## 背景

信息源散落在各家站点和社交平台，算法推荐又不可控。RSS 虽然老，但结构化、可自持、没有中间商。不过 RSS 只解决"聚合"，不解决"筛选"——30 多个订阅源每天几百条，全读不现实，全弃又怕漏。这篇记录我用 OpenClaw + MCP 搭的一条管线：**定时抓取 → 粗筛 → AI 摘要 → 推送 digest**，目标是每天早上收到一条能当导航用的早报。

## 问题定义

- 订阅源多，人工通读不现实，但也不能全交给模型，成本和幻觉都在那里
- 大部分条目价值低，需要分级过滤
- 摘要必须有出处、可回溯，不能让模型自由发挥
- 管线要幂等可重跑，静默失败最伤

## 做法

整体架构：**Miniflux（聚合层）→ OpenClaw 定时任务 → MCP 工具集（抓正文 / 去重缓存 / 推送）→ Telegram / 飞书**。

**1. 收敛订阅源。** 用 Miniflux 集中管理，站点不提供 feed 的用 RSSHub 补路由。关键配置：能抓全文就抓全文，抓不到就挂 readability 抓正文，这一步决定后面摘要质量的上限。

**2. 调度。** OpenClaw cron 每天两次拉未读：早间出 digest，晚间补漏。错峰执行，避免撞上源站限流。

**3. 两级处理，控制成本。** 第一级只看 title + summary，用规则加小模型做相关性打分，丢弃 80% 以上；第二级才对留下的 10~20 条做全文摘要。Prompt 要求：三句话以内、保留关键数字和结论、只基于给定正文、信息不足时明确标注"原文信息不足"而不是编。

**4. 去重与状态回写。** content hash + 标题相似度双保险去重；处理完回写已读状态，保证重跑不重推。

**5. 推送。** digest 按主题分节（技术 / 行业 / 工具），每条必带原文链接，超长拆条。

## 踩坑点

- **只有摘要没有全文的源很多。** 直接摘要会丢上下文，必须先抓正文；抓不到就降级为"标题 + 描述"模式，宁可信息少，不要硬编。
- **同一事件多源报道刷屏。** 做了标题相似度合并，按源权重留一条。
- **feed 会悄悄 404 或改结构。** 加了健康检查：连续 N 次抓取失败标灰，在 digest 末尾提示，别让它无声死掉。
- **摘要幻觉。** 要求只基于给定正文，并引用一句原文片段佐证；抽查发现编造就回滚该条并记入 badcase。
- **token 成本。** 全量上大模型一天不便宜，改成"规则粗筛 + 摘要才上大模型"后，成本降了一个数量级。
- **调度细节。** 凌晨跑批撞限流，改成错峰加指数退避重试才稳。

## 可复用建议

- 先跑"只推送不摘要"的最小闭环，验证源质量，再接模型
- 摘要输出固定为结构化 JSON，渲染与生成解耦，下游随便换
- 每条摘要必带原文链接，摘要是导航不是替代品
- content hash 落库，一切步骤设计成幂等
- 把"源健康度"当一等功能维护，坏源比没源更误导

## 总结

这套管线代码量不大，核心是工程纪律：去重、降级、回写、成本分级。AI 在这里只做两件事——粗筛和压缩，判断权仍然在你手里。自动化能省时间，但"订阅什么"的品味，是省不掉也外包不出去的部分。欢迎在社区贴出你们的 digest prompt 和源列表，互通有无。
