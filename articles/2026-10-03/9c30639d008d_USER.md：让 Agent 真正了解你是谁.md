# USER.md：让 Agent 真正了解你是谁

## 背景

用 OpenClaw 这类常驻 Agent 时，我们在项目上下文上花了不少心思——AGENTS.md 写仓库规范，MEMORY.md 记会话结论。但「你是谁」这件事，多数人还停留在每次对话开头自我介绍：时区、技术栈、代码习惯、沟通偏好，重复粘贴，漏一条就翻车。

OpenClaw 工作区（默认 `~/.openclaw/workspace`）里本来就有 USER.md，定位很明确：AGENTS.md 描述项目，MEMORY.md 记录过程，USER.md 描述人。它随会话加载进入上下文，是成本最低的个性化配置，但很多人从没认真写过。

## 问题

没有 USER.md 时，常见三类问题：

1. **重复解释**。每次新会话都要说「用 pnpm、回复用中文、commit message 别加 emoji」。
2. **假设错误**。Agent 默认按 UTC 排日程、默认英文注释、默认输出长篇解释，你每次都要纠正。
3. **行为漂移**。同样的问题这次答得简洁，下次又啰嗦起来——因为偏好从未落盘。

## 做法

1. 打开工作区根目录的 USER.md，控制在 60 行以内。它每次都进上下文，长文只会稀释指令的注意力。
2. 只写**会改变 Agent 行为的事实**：
   - 身份与称呼：怎么叫你、回复语言；
   - 环境事实：OS、shell、包管理器、版本策略；
   - 时间与节奏：时区、活跃时段；
   - 沟通偏好：先结论还是先推理、非显然步骤要不要解释；
   - 禁区：「不自动 commit」「不替我回复消息」。
3. 每行写成可执行指令，而不是自我评价。「习惯 pnpm」有用，「学习能力较强」没用。
4. 建立「重复纠正即入档」的习惯：同一件事纠正 Agent 两次，就写一行进去。
5. 每月修剪一次，尤其是「当前在做的事」这类会腐烂的内容，加日期标注。

一个可直接抄的骨架：

```markdown
# 关于用户
- 称呼：X；回复一律中文
- 环境：macOS + zsh，包管理器 pnpm / brew
- 时区：Asia/Shanghai，工作日 9:00–19:00
- 偏好：先结论后细节；非显然步骤要解释
- 禁区：不自动 commit；演示不使用真实客户数据
```

## 踩坑点

- **写成简历**。形容词无法被执行，Agent 只响应具体指令。
- **塞敏感信息**。USER.md 随每次模型调用发送，也出现在 MCP 工具可见的上下文里。密钥、电话、住址不要写，PII 越少越好。
- **与 AGENTS.md 冲突**。项目规则应覆盖个人偏好，两边不要重复写同一条，否则改的时候必漏一边。
- **内容腐烂**。「当前在做 X」三个月后就是误导，日期标注加定期修剪是必须的。
- **自我标榜反噬**。写「资深工程师」可能让 Agent 略过你想看的解释。写行为——「即使我有经验，关键步骤也要解释」——而不是人设。

## 可复用建议

- 判断标准：删掉某行后 Agent 行为不变，这行就该删。
- 工作区放进 git，USER.md 每次修改可 diff、可回滚。
- 多机同步用 dotfiles 仓库软链；团队场景下 AGENTS.md 共享，USER.md 各自私有，不要混在一个仓库。
- 层级别混：稳定事实进 USER.md，会话中发现进 MEMORY.md，项目约定进 AGENTS.md。

## 总结

USER.md 本质是「个人偏好即配置」。一次写好十几行，换来所有会话里的默认正确。它不值得写得漂亮，只值得写得准：事实、可执行、常修剪。
