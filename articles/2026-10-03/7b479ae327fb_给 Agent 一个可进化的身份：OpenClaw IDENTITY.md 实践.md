## 背景

OpenClaw 的 workspace 里有一组约定文件：`AGENTS.md` 管行为规范，`SOUL.md` 管价值观，`MEMORY.md` 管记忆，而 `IDENTITY.md` 是其中最轻的一个——它只回答一个问题：“你是谁”。会话启动时，这些文件会被拼进系统上下文，Agent 的自我介绍、语气、用词习惯，基本就是这一页 Markdown 决定的。

很多人装完 OpenClaw 就再没打开过这个文件，其实浪费了它最大的价值：**身份可以被当成配置来迭代**，而不是一次性设定。

## 问题

不带身份管理的 Agent 通常有三种状态：

1. **完全没写**。表现随模型波动，同一个任务今天简洁明天啰嗦。自动化场景尤其难受——cron 推送的消息风格每两天变一次。
2. **写死在别处**。人设硬编码进启动参数或外部 system prompt，改一次要动配置、重启进程，改完还无法追溯是谁、为什么改。
3. **当筐用**。往 IDENTITY.md 里塞小作文，希望它同时承担人设、规则、记忆三种职责，结果上下文被稀释，真正关键的指令反而被淹没。

## 做法

我的做法是把 IDENTITY.md 当成一个小型配置仓库来维护：

1. **最小字段集**：名字、形象/emoji、一句话定位、2~3 条硬性语气规则（比如“回复不超过三段”“不使用感叹号”），全文控制在 30 行以内。
2. **git 管理**：workspace 本身就是目录，`git init` 之后每次改身份都是一个可回滚的 diff，能看清身份是怎么一步步演化的。
3. **区分职责**：稳定特质进 IDENTITY.md，行为反馈进 MEMORY.md，底线原则进 SOUL.md。三者有重叠时，IDENTITY.md 只做“外在呈现”这一层。
4. **定期复盘**：每两周让 Agent 自评最近输出哪里不符合预期，把确认的问题转成新规则，一次只加一条。

## 踩坑点

- **当记忆用**。“用户偏好深色模式”这类内容写进 IDENTITY.md，会话一多就互相污染，该去 MEMORY.md。
- **和 AGENTS.md 冲突**。一边写“回复要详细”，一边写“不超过三段”，模型会随机站队。改身份前先全局搜一遍相关关键词。
- **中途大换人设**。长会话里身份突变，Agent 会出现明显割裂感，严重时连之前的任务约定都忘掉。要换，新开会话再换。
- **以为改了就生效**。文件通常是会话启动时加载的，改完不重载，测的还是旧行为。

## 可复用建议

- **冒烟测试**：改完身份，用“你是谁、你说话什么风格”两个问题验证，比翻日志快得多。
- **自动化 Agent 也配身份**：cron 报告、值班 bot 这类无人值守任务，给它一个克制的身份（比如“简洁的值班助理”），输出风格立刻稳定。
- **多 Agent 各自隔离**：多个 Agent 就多个 workspace，各自的 IDENTITY.md 互不干扰，别用一个文件管所有人。

## 总结

IDENTITY.md 的价值不在于“设定了什么人设”，而在于它把身份变成了一个可以小步提交、随时回滚、持续演进的配置。身份不是开头写完就结束的设定，而是和代码一样需要 review 的活文件。30 行以内，一次改一条，两周一个迭代周期——这就是“可进化”的全部含义。
