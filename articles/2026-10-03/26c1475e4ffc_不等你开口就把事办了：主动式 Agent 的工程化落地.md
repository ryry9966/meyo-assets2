## 背景

大多数 agent 的默认形态是“应答机”：你发消息，它干活，然后沉寂。但个人助理的真正价值在于主动性——比如每天早上把日程和昨天落下的 PR 汇成一段简报，发现依赖有安全更新时提前打招呼。OpenClaw 提供了实现这类能力的基础件：heartbeat（周期性自检）、cron（定时任务）加上 skills/MCP 工具层。但把这些直接拼起来，很容易做出一个“烦人精”或“烧钱机器”。

## 问题

朴素的 proactive 有三个典型翻车模式：

1. 心跳太频繁，每次都是完整一轮 agent 调用，token 成本失控；
2. 没有去重和冷却，同一个未处理问题每小时提醒一次，用户一周后直接关掉功能；
3. 主动执行了不可逆操作（删文件、发消息），一次事故就摧毁信任。

## 做法

我的落地围绕“信号 → 决策 → 动作”三层，分四步：

1. **触发层分离**。固定时间的用 cron（早报、周报）；条件触发的用 heartbeat，把检查清单写进 HEARTBEAT.md。触发层只负责“叫醒”，不做判断。

2. **清单保持短小**。HEARTBEAT.md 控制在 15–20 行，每条是一个可快速判定的检查项（如“检查 inbox 是否有未归类文件”）。判断成本高的检查，下沉为 skill 里的一次工具调用，不要让模型自己翻文件系统。

3. **三档动作策略**。每次主动检查的结论必须落到三档之一：
   - **直接做**：幂等、可回滚的低风险操作（整理目录、预取缓存）；
   - **草稿+确认**：不可逆或对外可见的动作（发消息、提 PR），生成草稿推给你，等你确认；
   - **沉默**：无事发生。这一档应占 90% 以上的心跳。

4. **状态去重**。用一个本地 JSON 记录“最近已通知事项 + 时间戳”，同一事项在冷却窗口内（如 6 小时）不重复提醒，处理完成后清除条目。

## 踩坑点

- **心跳即成本**：哪怕结论是“没事”，每轮也有开销。我把间隔从 15 分钟调到 1 小时，固定时间任务改走 cron 后，心跳开销降了一半以上。
- **清单越长越漏检**：早期塞了 40 多行，agent 开始跳项。按优先级拆成两份配置后才稳定。
- **重复提醒**：持续报错的容器会反复触发。加了一条“未解决事项只报一次，之后仅在状态变化时再报”才解决。
- **时区**：cron 按容器时区跑，早报晚到 8 小时，必须显式写死时区。
- **主动写操作必须过确认门**：我吃过 agent 自作主张改配置的亏，之后所有写类 skill 默认 dry-run 输出 diff。

## 可复用建议

- 新的主动功能一律先跑 **notify-only** 模式观察两周，再放开自动执行；
- 每个主动动作保证**幂等**：同样输入跑两次，第二次应是 no-op；
- 设**每日调用与成本上限**，超限自动降级为纯通知；
- 每次心跳写一条结构化日志（触发源、结论档位、token 数），这是后续调优的唯一依据。

## 总结

主动性不是让 agent 更聪明，而是给它套上纪律：便宜的触发、短小的清单、三档决策、状态去重、写操作过确认门。做到这几条，“不等你开口就把事办了”才能从演示效果，变成日常可依赖的行为。建议从一个心跳检查项开始跑通全链路，再逐步加清单——主动能力是养出来的，不是一次配置出来的。
