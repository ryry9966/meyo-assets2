## 背景

LLM 会话天然无状态。每次新开会话，Agent 对你的了解归零：偏好 TypeScript、commit message 用中文、测试框架用 Vitest、目录结构有自己的一套约定——这些你可能在过去几十个会话里重复了无数遍。上下文窗口再大也解决不了这个问题，因为“记住”本质是**跨会话的持久化 + 检索问题**，不是容量问题。

## 问题：三种常见但跑不通的做法

1. **全量塞 system prompt**：token 成本线性上涨，记忆一多，模型注意力被稀释，真正相关的偏好反而被忽略。
2. **让模型自由发挥“记笔记”**：存下来的是自然语言流水账，无法结构化更新、无法去重、无法删除。
3. **上来就堆架构**：向量库 + 图谱 + 反思机制三件套。偏好类记忆其实就几十条，杀鸡用牛刀，调试成本远超收益。

## 做法：最小闭环

我的方案分四步，核心原则是**把记忆当数据，不当 prompt**。

**1. 分层存储。** 第一层是偏好库：结构化小事实，比如 `{key: "commit_language", value: "zh-CN", confidence: 0.9, updated_at}`；第二层是情景库：历史会话摘要，用于“上次我们聊到……”这类召回，这层才值得上向量检索。偏好库用 SQLite 就够。

**2. 写入靠提取，不靠堆日志。** 会话结束或用户说出“以后都……”这类显式信号时，跑一个独立的提取步骤（单独 prompt 或小模型）把候选事实抽出来，带来源和时间戳。不要把原始对话直接落库。

**3. 读取靠排序，不靠全量。** 会话开始时注入 top-K（我设 5～8 条），排序权重 = 相关性 × 最近命中 × 置信度。宁可少注入，也不要让记忆区变成第二个垃圾场。

**4. 用 MCP 工具收敛写入面。** 把 `memory_write` / `memory_search` / `memory_delete` 做成 MCP server 暴露给 Agent。好处是写入路径可控、可审计，任何支持 MCP 的客户端都能直接复用这套记忆。

## 踩坑记录

- **记忆污染**：模型会把临时任务细节也当偏好存，“这个项目用 Vue”被存成“用户永远用 Vue"。解法：提取时强制分类 + 置信度阈值，偏好类记忆要求用户显式确认过才给高置信。
- **过期与冲突**：偏好会变。设计成 last-write-wins，检测到语义冲突时保留新旧两版并降级旧版，而不是直接覆盖——有些“冲突”其实是不同场景（工作/个人）。
- **注入格式**：自由文本句子没法 upsert。字段化 key-value 虽然丑，但更新、去重、删除都便宜。
- **可观测性**：一定要记“这次注入了哪些记忆、输出是否遵守”。没有这份日志，你调不了排序权重，也不知道记忆到底有没有用。

## 可复用建议

- **记忆即缓存**：有 TTL、有失效、有命中率，按管理缓存的纪律来管理它。
- **先跑通闭环再加机制**：SQLite → 提取 → 注入 → 反馈日志，闭环转起来之后，向量库和反思机制才有意义。
- **给用户一个看记忆的入口**：一条 `memory list` / `memory rm` 命令，信任问题迎刃而解，顺手解决隐私焦虑。

## 总结

让 Agent 记住你，本质是数据工程而不是 prompt 技巧：分层存储、显式提取、排序注入、可观测、可删除。先用最小的 SQLite + MCP 工具跑通闭环，再谈更花哨的架构。记忆系统的价值不在存了多少，而在每次注入的那几条恰好是对的。
