## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，会发现一个尴尬的现实：它再聪明，默认也是被动的——你不发消息，它就不动。所谓"个人助理"，实际上是你得先想起来问它。而真正有价值的事情，比如每天早上的摘要、盯某个仓库的 issue、磁盘快满时提醒你，本质上都不需要"你先问"。

OpenClaw 提供了一个朴素但有效的机制：**heartbeat（心跳）**。一个定时器按固定间隔唤醒 agent，让它去读工作区根目录下的 `HEARTBEAT.md`，按里面的指示决定"这轮要不要干活、要不要打扰你"。

## 问题

- 纯问答模式下，**你就是调度器**：所有周期性任务都靠你记得开口。
- 但直接"cron + LLM"会走向另一个极端：每 30 分钟一条"一切正常"，三天后你就把它静音了。

所以 heartbeat 的工程目标其实是"安静"，而不是"勤快"——大多数心跳应该什么都不发生。

## 做法

**1. 建文件**。放在 workspace 根目录（默认 `~/.openclaw/workspace/HEARTBEAT.md`），写法上要当"值班手册"而不是作文，条目短、可判定：

```markdown
# HEARTBEAT.md

## 规则
- 没有值得汇报的事，返回 HEARTBEAT_OK，不要发消息
- 只在状态变化/异常时汇报，同一事件不重复报

## 每次心跳
- 读取 STATE.md 里的监控项，逐项判断
- 周一 09:00-10:00：汇总上周 GitHub 通知，不超过 5 条
- 磁盘占用 > 85%：提醒我，并给出可清理目录
```

**2. 配置间隔与时段**（`~/.openclaw/openclaw.json`，字段名以你版本的文档为准）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": {
        "intervalSeconds": 1800,
        "activeHours": "08:00:00-23:00:00"
      }
    }
  }
}
```

`activeHours` 用来避免半夜被吵。

**3. 理解 HEARTBEAT_OK**：agent 回这个标记时，本轮不向你投递消息，但这次心跳照样消耗 token。这是控制噪音的关键开关，务必在文件里显式写明沉默规则。

**4. 状态持久化**：心跳轮次之间 agent 记不住"上次报过什么"。让它把已处理事件（时间戳 + 一句摘要）写进 `STATE.md`，每次先读再判，做去重。

## 踩坑点

- **成本**：每次心跳都是一轮完整 agent turn。我最初用主模型跑 10 分钟间隔，一天下来 token 烧得心疼。改成心跳单独配便宜模型、间隔拉到 30 分钟，成本降了一个量级。
- **噪音**：不写沉默规则，模型会礼貌性地汇报"今日无事"。加了"无事必须 HEARTBEAT_OK"才安静下来。
- **心跳做重活**：一轮心跳里跑 10 分钟的爬取任务会阻塞后续节拍。重活让 agent 生成脚本交给独立定时任务，心跳只做"检查 + 触发"。
- **文件膨胀**：`HEARTBEAT.md` 每个节拍都会注入上下文，越长越贵。细节挪到其他文件，这里只留规则和路径引用。
- **注入风险**：让心跳去读邮件、网页，等于把不可信文本定时送进有工具权限的上下文。监控项尽量收敛到只读工具。

## 可复用建议

- 把 `HEARTBEAT.md` 固定成三段：**规则**（何时沉默）、**监控项**（引用 STATE.md）、**周期任务**（按星期/时段）。新任务只往监控项加一行。
- 先跑 1~2 个任务观察一周，重点看两个数字：**误报率**和**日均 token**。它们比"功能多酷"重要。
- 心跳 + MCP 组合：监控项直接调用 MCP 工具（仓库、日历、服务器指标），比让 agent 自由发挥稳定得多。
- 排障时去看 `~/.openclaw` 下对应 agent 的会话日志，确认心跳轮次实际读了什么、为什么没触发。

## 总结

HEARTBEAT.md 的价值不在于让 Agent 更聪明，而在于给它一份"值班守则"：什么时候出声、什么时候沉默、检查什么、状态存哪。写好它的核心是压制误报和控制成本——把心跳当成一个低频、便宜、只做判定的哨兵，重活外包出去。做到这一步，Agent 才算第一次有了"主动"，而你的通知栏不会变成灾难。
