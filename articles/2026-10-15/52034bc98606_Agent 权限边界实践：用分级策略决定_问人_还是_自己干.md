## 背景

OpenClaw 这类框架把 agent 接上工具的门槛降得很低：挂一个 MCP server、装个插件，agent 就能读文件、跑命令、调外部 API。但能力越强，出错的代价越不均匀——读错一个文件无所谓，往客户群里发错一条消息就收不回来。

实际项目里常见两种极端：全放开（效率高，出事靠运气），或者每步都弹确认（安全，但人很快变成点"允许"的机器）。两种都不可持续。

## 问题

根源是两个维度没有被显式建模：

1. **可逆性**：这个操作能不能撤销？
2. **影响半径**：搞砸了波及多大？沙箱内、仓库内、团队协作空间，还是外部世界？

还有一个隐性误区：让模型现场判断"这个操作危不危险"不可靠。模型对不可逆性的自我评估不稳定，**风险分级必须是静态配置，不能交给模型临场决定**。

## 做法

**第一步：给每个工具打标。** 列一张工具清单，每个 MCP tool 过一遍，标两个属性：可逆性（可逆 / 难逆 / 不可逆）、半径（沙箱内 / 仓库内 / 外部）。

**第二步：分四级。**

- **L0 自动执行**：只读、沙箱内。读文件、查 schema、本地搜索。
- **L1 自动执行 + 审计**：可逆的仓库内写操作。改工作区文件（有 git 兜底）、建分支、开 PR。
- **L2 计划级确认**：批量或有成本的操作。装依赖、调用计费 API、批量改文件。按"计划"确认一次，而不是按步骤确认二十次。
- **L3 每次必问**：外部副作用。发消息、发邮件、部署生产、删数据、花钱。

**第三步：在工具调用前加一层策略网关。** 在插件层按分级决定放行、拦截或转人工。L2/L3 的确认必须带上下文：执行什么、作用对象、预期效果、怎么回滚。

**第四步：会话内授权要有 TTL。** 默认选项是"本次会话允许"，而不是"永远允许"，过期重新问。

**第五步：全量审计日志。** 无论问没问人，每次工具调用的参数和结果摘要都落日志。

## 踩坑点

- **确认疲劳**：一天弹 30 次确认，人就会无脑点允许，比不问还糟。L2 按计划确认就是为了压缩询问次数。
- **不可逆动作藏在链路后面**：agent 前面几步都"安全"，读文件、写临时文件，最后一步一个覆盖写把东西毁了。分级要按最终副作用算，不能只看单步。
- **确认文案太模糊**："是否继续？"没人知道继续什么。确认必须展示 diff、参数和目标对象。
- **一次授权永久生效**：第一次问了，之后"不再询问"被当成默认，权限悄悄漂移。
- **把模型当风险评审**：prompt 里写"请判断这个操作是否危险"只是安慰剂。

## 可复用建议

- **默认拒绝**：凡出网、出沙箱、花钱的动作，没配置就是 L3。
- **用可逆性换询问次数**：让 agent 优先产出可审查的产物（分支、PR、dry-run 输出）而不是直接改目标。产物模式下，少问也是安全的。
- **每周翻一次审计日志**，重点检查 L1 调用里有没有该升级成 L2/L3 的。
- **策略文件随仓库走**，和代码一起 review，别散在个人配置里。

## 总结

权限边界不是"问得多安全"还是"问得少高效"的选择题，而是把可逆性和影响半径做成显式配置，让"问人"只发生在少数真正关键的岔路口——并且每一次问，都值得人认真看。策略管住工具，日志管住策略，人只管决策。
