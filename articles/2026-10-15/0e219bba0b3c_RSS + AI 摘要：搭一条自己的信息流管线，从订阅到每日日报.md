## 背景

信息源分散是常态：技术博客、GitHub Release、邮件列表、几个论坛。我原来的做法很土：书签 + 每天手动刷。问题是效率低——真正值得读的不到一成，剩下全是噪音。

RSS 解决了"聚合"，但不解决"筛选"。这次的目标很明确：让 AI 做第一轮分流和摘要，我只看它认为值得的，且**始终保留原文入口**。

## 问题

把订阅直接丢给 LLM，有三个现实问题：

1. **token 成本**：源一多，全量摘要又贵又慢；
2. **摘要质量**：很多 RSS 只有 summary 或截断文本，模型在残缺内容上总结，容易写出"通顺但没依据"的话；
3. **重复信息**：同一件事多个源都报，逐条摘要等于重复付费。

## 做法

管线分四步，挂在 OpenClaw 的定时任务里，每天早上跑一次：

**1. 拉取与去重。** 脚本抓取 Miniflux 的未读条目（直接解析 RSS、或用 RSSHub 补源也行），按 URL 和标题 hash 去重入库。标题相似度用分词 Jaccard 就够，别一上来就上 embedding。

**2. 先过滤，再摘要。** 关键一步：不要对所有条目调 LLM。先用规则（关键词、来源权重）粗筛，剩下的让模型打 0–10 相关性分，只对 7 分以上的生成摘要。这一步砍掉了绝大部分 token 开销。

**3. 结构化摘要。** Prompt 强制 JSON 输出：一句话总结、2–3 个要点、原文链接、置信度。要点必须能在原文找到出处，禁止模型补充观点；置信度低于阈值时只给标题不给摘要——宁可少说，不要编。

**4. 汇总成日报。** 按主题分组生成一篇 Markdown，Agent 通过 MCP 工具写入我的笔记库，手机端同步可看。

## 踩坑点

- **别信 RSS 的 description 就是全文。** 大量站点只给截断文本，高分条目要再抓一次正文（注意 UA，有的站会 403）。
- **"摘要的摘要"会失真。** 试过让模型直接总结前一天的摘要列表，信息衰减很明显。现在每条单独出摘要，日报层只做分组，不做二次压缩。
- **截断输入要显式标注。** 正文抓不全时，在 prompt 里告诉模型"以下内容不完整"，让它相应降低置信度，编造率明显下降。
- **定时任务要幂等。** 失败重跑是常态，去重放第一层，重跑不会重复推送。
- **警惕源质量漂移。** 有个论坛源后来水帖越来越多，相关性分整体虚高。每周人工抽查一次摘要与原文的一致性，不行的源直接退订。

## 可复用建议

- 最小闭环只要 3–5 个高质量源，先跑通再加量；
- 过滤放在摘要之前，成本能差一个数量级；
- 结构化输出是管线的接口，下游换投递渠道不用动上游；
- AI 负责分流和提炼，判断和点击留给人类，保留原文链接这条底线别破；
- 管线脚本化、可重跑、日志留痕，别把逻辑藏在某次对话里。

## 总结

这套东西没有单点技术难度，价值在于把"聚合、过滤、摘要、投递"拆成可独立替换的环节。跑了两周，我每天早上花十分钟看日报，比原来刷一小时信息源效率高，而且每条结论都能点回原文验证。如果你已经用过 OpenClaw 的定时任务和 MCP 工具，一个下午能搭起来。欢迎在评论区交流你们的过滤策略。
