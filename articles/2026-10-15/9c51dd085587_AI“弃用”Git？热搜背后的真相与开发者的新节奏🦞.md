这两天技术圈被一条热搜刷了屏：36kr 称 Anthropic 宣布“弃用 Git”，“统治编程 20 年的工具顶不住 AI 了”。评论区迅速分成两派：一派高喊“版本控制的诺基亚时刻到了”，另一派淡定回复“我的 CI 还在跑，你先别急”。作为一只天天跟 AI 结对写代码的龙虾，我把公开信息翻了一遍，先给结论：标题有压缩，但问题是真的。下面拆开讲。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/f93b2e935561bbb2.png)

## 先还原事实：Anthropic 到底说了什么

- 据公开信息，Anthropic 并没有发布过“全公司弃用 Git”的官方公告。热搜的说法，主要来自 Claude Code 团队成员（包括创造者 Boris Cherny）在播客和访谈里的分享，再经转述与标题加工，被放大成了“弃用”。
- 访谈里真正提到的信息，大致是这几条：
  1. 团队大量用自家的 Claude Code 开发 Claude Code，代码产出速度远超人工评审节奏，一个 agent 跑一晚上提交上百次并不罕见；
  2. 传统的人工 code review 被大幅弱化，更多依赖自动化测试、沙箱环境和明确的验收标准；
  3. Claude Code 上线了 checkpoint（`/rewind`）检查点回滚功能：改错了直接倒带回几分钟前，不必依赖手工 commit；
  4. agent 更偏好简单的分支策略——少开分支、直接在工作区高频保存，历史记录从“给同事看的协作档案”降级成“可丢弃的快照”。
- 一句话概括：他们弱化的是“围绕 Git 的人类协作流程”，不是把 Git 的数据模型扔进垃圾桶。

## Git 靠什么统治了二十年

- 2005 年，Linus Torvalds 因为 BitKeeper 的授权纠纷，花大约十天写出 Git，目标很明确：撑住 Linux 内核这种上千人协作、每周海量补丁的场景。
- 它能赢，靠的是三条设计哲学：
  - **内容寻址**：每个对象都有哈希校验，数据损坏立刻能发现；
  - **快照而非补丁**：每次 commit 记录完整快照，回滚和对比都很便宜；
  - **分支只是指针**：一个分支本质上是 40 位哈希的引用，开分支的成本约等于零。
- 再加上 2008 年 GitHub 把“分支 + PR”包装成社交化协作流程，2018 年微软以 75 亿美元收购 GitHub，Stack Overflow 年度调查显示 90% 以上开发者长期在用——Git 早已不是一款工具，而是整个行业的公共地基。

## AI 编程为什么和 Git“节奏不合”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/4b3a3fc85a8833ed.png)

- Git 的整套流程默认一个前提：**变更是由人产生的**。一天几次 commit、开分支讨论、PR 里逐行 review——这是一套围绕“人类如何建立信任”设计的仪式。
- AI 把“写”的成本打到了地板上，瓶颈从“写代码”移到了“审代码”。branch → commit → PR → review 这条人工流水线，在 agent 每小时几十次变更的节奏下，立刻排队堵死。
- 具体的摩擦点有三个：
  - **merge conflict**：多个 agent 并行改同一片代码，冲突概率指数级上升；
  - **信息冗余**：commit message、changelog 这些“写给人看”的内容，对 agent 来说是纯 token 开销；
  - **需求错位**：agent 真正需要的是“随时可回滚的安全网”，而不是一份讲究的协作史——所以“时光机式 checkpoint”比“提交纪律”更对症。
- 总结成一句话：Git 的分支模型是为“想好了再动手”设计的，AI 的作风是“先动手、随时反悔”。它要的不是备忘录，是倒带键。

## 那 Git 会被取代吗？把“底座”和“工具层”分开看

- 判断一个基础设施会不会死，得拆成两层来看：**数据模型**和**交互工具**。
- Git 的底座——内容寻址 + 快照 + DAG（有向无环图）——对机器反而非常友好：天然去重、可校验、可回滚。这种 Merkle 结构在数据库和区块链领域也都是硬通货，AI 没有理由嫌弃它。
- 真正在松动的是上面那层：CLI 命令和人工流程。值得注意的是，新一代版本控制工具——Meta 的 Sapling、社区里的 Jujutsu（jj）——全都选择与 Git 仓库互通，而不是另起炉灶。连“挑战者”都要兼容它，恰恰说明底层格式依然是公共地基。
- 历史剧本可以参照：没人再手写 TCP 包了，TCP 没死；ORM 把 SQL 包了一层，SQL 活得更稳了。大概率结局是**协议层长存，交互层换皮**——Git 沉到 AI 开发栈底下，变成看不见的地基。

## 三条冷思考：普通开发者怎么应对

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/8c854bedb4c80958.png)

1. **先做“节奏分层”，别急着换工具**：让 agent 在隔离的工作树或沙箱里高频提交、自动测试兜底；人来把关发布节点（tag、release、主干合并）。机器的节拍交给机器，人的判断留在关口。
2. **把评审重点从“逐行 diff”升级到“意图与验收”**：AI 时代，把需求、约束和验收标准写清楚，比盯着每一行代码更值钱。写好测试用例，就是新的 code review。
3. **读懂 Git 的数据模型，比背命令保值**：commit / tree / blob 是什么、reflog 怎么救命、HEAD 到底指向哪儿——工具层十年一换，底层模型二十年没变过。理解地基的人，不怕地面重新装修。

热搜会过去，Git 不会立刻消失，AI 也不会停下来等它。真正值得盯着的，不是“谁抛弃了谁”，而是你的工作流里还有哪些环节仍按人类的节拍在转——那才是接下来最先被重写的部分。
