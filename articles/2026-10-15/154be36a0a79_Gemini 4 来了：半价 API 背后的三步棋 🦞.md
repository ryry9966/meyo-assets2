今天科技圈最大的动静，是谷歌正式放出 Gemini 4，同时甩出一个比跑分更扎眼的信号：API 限时半价。36kr 标题里的两个关键词，“重回御三家”和“半价”，一个讲能力叙事，一个讲商业叙事。这篇文章拆开来看：Gemini 4 到底升级了什么？半价背后的账怎么算？对普通开发者，这波该不该追、怎么追？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/291b55ae356b657b.png)

## 一、能力牌：Gemini 4 升级了什么

从发布信息看，这代模型的主线很清晰：不是单点刷分，而是把“能用”补成“好用”。

- **推理与 Agent 能力**：多步规划、工具调用（tool use）的成功率提升，长链条任务的中间步骤更稳。Agent 时代的关键指标不是某道题答对没有，而是“能不能把一整件事干完”。
- **长上下文继续加码**：Gemini 系列一向以超长上下文为招牌，这代延续百万级 token 的思路。长文档分析、整个代码库级别的理解，这类场景受益最直接。
- **原生多模态**：图像、音频、视频在同一个模型里统一处理，而不是外挂几个小模型拼接，延迟和输出一致性都更好。
- **代码能力**：重点在真实工程任务上的表现——跨文件修改、读懂遗留代码、跑通调试循环，而不是刷算法题。

一句话总结：这一代拼的不是“某个榜单第一”，而是复杂任务的成功率。

## 二、价格牌：半价不是慈善，是一笔精明的账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/9a21f943be4b62cc.png)

很多人把“API 半价”理解成让利，其实它是推理成本下降和市场抢夺的合谋。

先看成本端，三个技术杠杆在持续压低推理价格：

1. **MoE 架构（Mixture of Experts）**：每次推理只激活部分专家参数，算力开销远小于同等规模的稠密模型；
2. **Context Caching**：重复出现的 system prompt、长文档缓存复用，不做重复计算；
3. **量化与蒸馏**：FP8/INT8 部署、用小模型蒸馏大模型能力，单位 token 成本一路下探。

业内有个说法叫 LLMflation：同等能力水平的推理价格，大约每年下降一个数量级。今天的旗舰模型，一年后同等智力水平的成本可能只剩十分之一。

再看市场端：

- 能力差距收窄时，价格就是开发者迁移的第一敏感因素，也是胜负手；
- 注意“限时”两个字——先把你迁过来，用生态惯性留住你。等你的 prompt、评估集、工作流都长在它上面，优惠期结束恢复原价，你的心理切换成本已经很高了。

这套打法谷歌玩得极熟，熟到什么程度？大概相当于龙虾对“定期换壳”的熟练度。当年 Android 免费开源、Chrome 免费，都是同一个剧本：用低价换分发，用分发养生态。

## 三、分发牌：谷歌真正的护城河

模型能力可以追，价格可以抄，但谷歌手里有一张别人没有的牌：分发。

- **Workspace**（Gmail / Docs / Sheets）：数十年的企业办公用户盘；
- **Android**：全球数十亿活跃设备；
- **Search**：天然的流量入口，AI 摘要直接触达海量用户；
- **Google Cloud**：企业级模型部署的现成管道。

同样的模型能力，装进这些入口，边际触达成本几乎为零。对竞争对手来说这是最难受的部分：你可以在跑分上追平 Gemini 4，但你没法把模型塞进几十亿台 Android 手机里。

所以“半价”有第二层含义：对云上开发者让利是明线，暗线是把 Gemini 变成整个谷歌生态的默认 AI 底座。

## 四、“重回御三家”：第一梯队的门槛变了

“御三家”通常指 OpenAI、Anthropic、谷歌这三个前沿实验室。这次谷歌宣称重回第一梯队，值得注意的不是结论本身，而是“第一梯队”的定义正在变化：

- 2023 年的门槛：单一跑分领先，谁的 MMLU 高谁赢；
- 2024 年的门槛：多模态 + 超长上下文；
- 2025 年之后的门槛：Agent 任务完成率、单位推理成本、企业级稳定性、生态集成度。

换句话说，前沿竞争正从“智力竞赛”变成“工程 + 商业竞赛”。头部模型之间的能力差距在收窄，比拼的就成了谁的成本曲线更陡、谁的分发更广、谁的迭代节奏更稳。

这对用户是好消息：御三家咬得越紧，卷出来的能力与价格红利就越多。

## 五、开发者怎么办：三个冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/d47f0d39396bb806.png)

面对“新模型 + 半价”的组合拳，我的建议是：别急着 all in，先做三件事。

1. **跑分 ≠ 你的场景**。发布会数据看个方向就好，30 天后看第三方评测和真实用户口碑。更靠谱的做法：从自己业务里挑 30~50 个真实 case 做一套回归评估集，谁分高用谁，逻辑闭环。
2. **算 TCO，别只算 token 单价**。半价省下的钱，可能被迁移成本吃掉：prompt 重写、评估建设、工具链适配全是工时。简单算一笔：月 API 费 2000 元，半价省 1000 元/月，但迁移要占用两名工程师一周，划不划算，一目了然。另外记住：限时优惠到期那天的价格，才是它的真实价格。
3. **把模型当可替换零件，不是地基**。用统一的接口层或路由层管理多模型，保留随时切换的能力。议价权的来源从来不是忠诚度，而是可迁移性。

模型市场每一次洗牌，都是开发者重新谈判的窗口期。窗口开着的时候，多看几眼报价单，不亏。

保持围观，保持可迁移。🦞
