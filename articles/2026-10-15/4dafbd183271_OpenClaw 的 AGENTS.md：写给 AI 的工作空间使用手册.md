## 背景：README 给人看，AGENTS.md 给 AI 看

OpenClaw 的 agent 每次会话启动时，都会把工作空间（默认 `~/.openclaw/workspace/`）下的 AGENTS.md 注入 system prompt。它不是普通文档，而是持续生效的运行时指令——概念上类似编码 agent 圈的 repo 级 AGENTS.md 约定，只是 OpenClaw 把它用在了个人助手的常驻工作空间里。`openclaw onboard` 会生成一份模板，但模板只是骨架，真正决定 agent 表现的是你怎么填。

## 问题：不写、乱写、写错位置

实践中常见三类症状：

- **不写**：时区、机器路径、回复偏好每次口头交代，换个会话全忘，agent 重回“第一天实习生”状态。
- **乱写**：几千字长文堆进一个文件，指令互相稀释，关键规则（比如“删文件前必须确认”）被淹没。
- **错位**：把人格写进 AGENTS.md、把操作规程写进 SOUL.md。OpenClaw 对这几个文件有分工，混着写两边都不干净。

## 做法：按 runbook 的写法来

我的 AGENTS.md 控制在 80 行以内，分四块：

1. **环境事实**：这台机器的系统、常驻路径、时区。只写事实，不写愿望。
2. **操作规程**：每条规则 = 触发条件 + 动作 + 兜底。例如“涉及删除或覆盖文件 → 先列出影响范围等我确认 → 我超时未回则放弃操作”。
3. **工具约定**：优先走哪个 MCP 工具、什么时候降级到 shell；低频操作引用 TOOLS.md，不内联。
4. **边界**：明确不做什么（发消息、支付、动系统配置）。这是安全兜底，放文件靠前位置。

写完跑 `openclaw doctor` 确认工作空间被正确识别，然后重开会话做回归：问三个你最常问的问题，看它是否照做。不生效的规则要么删掉，要么改写到无法误解。最后把 workspace 纳入 git，每次调整有 diff、可回滚。

## 踩坑点

- **规则冲突**：“回复要简洁”和“每次给出完整步骤”同时存在，agent 会静默二选一且不告诉你。改完通读一遍，删掉矛盾项。
- **塞机密**：AGENTS.md 每次会话都会进入上下文，token、内网地址写进去等于反复广播，还可能随日志外泄。密钥一律走环境变量和网关配置。
- **绝对路径**：多机同步 workspace 时写死的路径必挂。用相对路径，或让 agent 先列目录确认再操作。
- **写完不养**：工具链变了文件不变，旧指令变成噪声。我的习惯是每次纠正 agent 后自问一句：这条要不要沉淀进去？能沉淀就当场改文件，减少重复纠正。

## 可复用建议

- 每条规则按“触发条件 + 动作 + 失败兜底”三段式写，天然可测试。
- 分层：规程进 AGENTS.md，人格进 SOUL.md，用户事实进 USER.md，工具细节进 TOOLS.md，互相不抄。
- 高频规则放文件前部；超过 100 行就该拆，拆不动的部分改成独立技能或引用文档。

## 总结

AGENTS.md 的价值不看写了多少字，只看一件事：agent 是否真的照做。小、准、可执行、定期回归——把它当成你写给 AI 的 runbook 来维护，比任何长文都有效。欢迎在社区帖里贴出你的 AGENTS.md 结构，互相抄点好习惯。
