一家不上市、不打广告、发布会开得极其克制的公司，单季营收 168 亿美元，环比再涨 45%——这是 36kr 报道的 Anthropic 最新战绩。数字只是结果，真正值得拆的是三个问题：钱从哪来？为什么涨这么快？高增速背后藏着什么代价？下面用拆引擎的方式，把这台"营收机器"打开看看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-15/6ad34568e704af88.png)

## 一、先校准口径：168 亿是什么量级

Anthropic 是私营公司，不发财报，这组数字来自媒体援引的内部数据，未经审计。所以第一步不是惊叹，是校准：

- 168 亿单季对应约 **670 亿美元的年化跑速（run-rate）**；按环比 45% 反推，上一季度约为 116 亿美元。
- 一个对比锚点：上市二十多年的 Salesforce，2025 财年全年营收约 379 亿美元——Anthropic 一个季度，干出了它将近半年的收入。
- 三个"水分来源"要留意：run-rate ≠ GAAP 确认收入，签了合同也要分期分摊计入；客户预付的 credits 是否算当期收入；数据授权这类一次性大单，会人为抬高某个季度的基数。

一句话：没审计的数字，先当 Debug 日志看，别当 Release Notes 看。

## 二、钱从哪儿来：API 与企业客户是主引擎

据多家媒体报道，其收入结构中 API 与企业端占大头，个人订阅（Claude Pro/Max）只占较小份额。主引擎有三个：

1. **Coding 场景**：Claude Code 及各类编程 agent 是报道中占比最高的收入类目。程序员是付费意愿最强、ROI 最容易算清的群体——工程师年薪数十万美元，工具每月几百美元还能明显提效，采购决策几乎不用开会。
2. **云渠道**：AWS Bedrock、Google Cloud Vertex、Azure 都把 Claude 摆上货架，相当于三家顶级销售团队帮它卖 API。
3. **企业大单**：金融、法律、咨询等对可靠性与合规敏感的行业，正把 Claude 接进生产流程，合同金额与粘性都远高于散户订阅。

## 三、为什么涨这么快：Agent 把 token 用成了水电费

传统 SaaS 按席位收费，收入上限约等于客户员工数。Agent 时代规则变了——按 token 计费，收入上限等于客户的**自动化程度**。

- 一次 agent 任务是"规划 → 调用工具 → 观察结果 → 修正 → 重来"的循环。人在循环外，token 在循环里烧，一个复杂编程任务跑掉几百万 token 很常见。
- 于是出现软件史上少见的正反馈：客户自动化程度越高，付的钱越多。客户越"省人"，厂商越赚钱。
- 类比 2006 年的 AWS：把服务器变成水电表，按用量计费。现在轮到"智能"被装上了电表。

这套模型的天花板取决于一件事：客户愿意把多关键的流程交给 agent。目前的答案是——比绝大多数人预期都快。

## 四、营收 ≠ 利润：增长的代价清单

收入涨 45%，成本端同样在涨：

- **训练成本**：一次前沿模型训练动辄数亿到数十亿美元，且算力需要提前锁定。
- **推理成本**：agent 大量长上下文、多轮调用，推理是持续燃烧的固定支出；行业普遍估计头部模型公司的推理毛利率低于传统 SaaS。
- **算力承诺**：为了拿卡，Anthropic 与云厂商签下大规模算力承诺（据报道含数百亿美元级的 Azure 合同）。而 AWS、Google、Microsoft 既是它的销售渠道又是它的股东——"我投资你、你买我算力、我再帮你卖"的循环结构，看营收时值得打个问号。
- **融资节奏**：2025 年 9 月其估值已达 1830 亿美元，后续据称还有更大规模融资计划。高增速支撑高估值，高估值反哺算力采购——一个不能停的飞轮。

基数越大，45% 的绝对增量越恐怖：增速本身就是对毛利与现金流的极限压测。

## 五、三个行业信号

1. **价值在向模型层回流**。2023 年流行的判断是"模型终将商品化，钱都在应用层"。但 coding 与 agent 的收入证明：当能力差距存在、生态粘性形成（IDE 集成、MCP、agent 框架），模型层自己就能收大钱。
2. **企业采购在收敛**。大公司不会同时养七八家模型供应商，预算正向头部两三家集中；同时开源模型（DeepSeek、Qwen、Llama 系）在中低端压价，逼闭源玩家死守高端溢价。
3. **领先不等于护城河**。Benchmark 差距几个月内就会被追平；今天的营收领先靠生态与交付，明天就得靠持续产品化。模型公司的竞争窗口，比以往任何软件时代都短。

## 六、三条冷思考

1. **看营收先问口径**。run-rate 还是确认收入？含不含 credits 与数据授权？不同口径能差出三成。除了增速，更要看净收入留存率（NRR）：老客户是不是在主动加钱。
2. **用模型的公司：做 multi-model 架构**。别把业务命脉押在单一 API 上；用好 prompt caching、分级路由（简单任务走便宜模型）能砍掉一大截账单；把"换模型成本"设计进架构层，谈判时腰杆才硬。
3. **从业者：盯 unit economics**。agent 与 coding 是当前确定性最高的需求侧，但评估机会时看单位经济模型而非单纯增长率——上一轮 SaaS 已经教过我们：增长帮你融资，毛利才能让你活着。

168 亿美元不是故事的高潮，而是行业从"比参数"进入"比账本"的转折点。夹紧钳子、算清账，再谈理想。
