## 背景

多数 Agent 的默认形态是"应答机"：你不说话，它永远安静。OpenClaw 里有个不起眼但很关键的机制，heartbeat（心跳）：Agent 每隔一段时间被唤醒一次，去读工作区里的 `HEARTBEAT.md`，按里面的指令决定要不要做事、要不要说话。配合 MCP 工具和插件，这个文件就成了 Agent 的"主动巡检清单"。

## 问题

把心跳间隔调短并不等于"主动性"，实际会遇到三个问题：

1. Agent 每次醒来都发消息，很快变成骚扰；
2. 指令写得太模糊，Agent 自由发挥，做了不该做的事；
3. 每次心跳都是一次真实的模型调用，任务堆多了，token 成本线性上涨。

核心矛盾是：怎么让"定时唤醒"产生确定性的、值得打扰你一次的产出。

## 做法

1. 在 Agent 工作区根目录创建 `HEARTBEAT.md`。
2. 配置心跳间隔，`openclaw.json` 里大致是（字段名以你版本的文档为准）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": {
        "every": "30m"
      }
    }
  }
}
```

3. 文件写成"检查项 + 触发条件 + 动作"的结构，例如：

```markdown
# Heartbeat

每次醒来依次检查，没有需要汇报的就回答 NO_REPLY。

- 收件箱有超过 2 小时未处理的邮件：汇总发给我
- workspace/notes 今天有新增：生成三行以内摘要
- 每天早上 8 点后的第一次心跳：整理今日待办
```

4. 关键是最后一行约定：无事发生时让 Agent 输出 `NO_REPLY`，框架会吞掉这次回复、不投递消息。这是"主动但不聒噪"的开关。

5. 重活不要写在心跳里。心跳适合"检查"而不是"执行"：发现有事，再调 MCP 工具或脚本去干，或先通知你确认。

## 踩坑点

- **指令不可判定**。"帮我盯着邮件"会触发脑补，改成可判定条件（数量阈值、时间窗口）。
- **`NO_REPLY` 靠模型自觉，不是硬约束**。任务列表一长它就"忍不住"汇报，保持文件一屏以内。
- **投递位置**。心跳默认发到上次活跃的会话/频道，多设备用户会在奇怪的地方收到消息，确认 target 配置。
- **沉默也花钱**。每次心跳都消耗 token，即使最后没产出。5 分钟 × 24 小时不是好主意，从 30m 起步，观察一周再调。
- **外部依赖没验证**。依赖 MCP 工具的检查项，先手动跑通；心跳里的报错你通常不会及时看到。
- **文件职责混乱**。心跳每次醒来都会重读这个文件，改动即时生效，但别往里堆长篇 SOP，那是 SOUL.md 和技能文件该干的事。

## 可复用建议

- 把 HEARTBEAT.md 当**巡检清单**，不是**任务队列**：条目只回答"要不要打扰用户"，动作只有"汇报"或"沉默"。
- 分钟级的高频检查交给 cron/外部调度直接跑脚本；心跳留给低频、需要理解和判断的事。
- 建一个专用投递频道，把主动汇报与日常对话隔离，避免污染主会话。
- 每月审一次：删掉两周没触发过汇报的条目——要么没用，要么阈值不对。

## 总结

HEARTBEAT.md 的价值不在"AI 会自己动了"的新鲜感，而在于它是个极简的工程接口：一个 Markdown 文件 + 一个间隔配置 + 一个 `NO_REPLY` 约定，就把 Agent 从应答机改成了带巡检能力的助手。写好它的诀窍是克制：检查项可判定、汇报有阈值、无事必沉默。
