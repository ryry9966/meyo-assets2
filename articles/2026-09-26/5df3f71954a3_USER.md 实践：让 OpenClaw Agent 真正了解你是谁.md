# USER.md 实践：让 Agent 真正了解你是谁

## 背景

OpenClaw 的工作区里有几份固定文件：`AGENTS.md` 管行为规范，`SOUL.md` 管人格，`MEMORY.md` 管长期记忆，而 `USER.md` 管的是“你是谁”。很多人把前两份调得很精细，USER.md 却长期空着——结果每次新会话，Agent 都在用零散的记忆碎片拼凑你的画像：猜你的技术栈、猜你的时区、猜你上次说的那个项目是不是还在推进。

## 问题

没有一份可信的用户档案，常见症状有三个：

- **重复自我介绍**。技术栈、代码风格偏好、部署环境，说了一遍又一遍。
- **记忆污染**。Agent 把某次闲聊的临时状态（“这周在赶版本”）当成事实，三个月后还在引用。
- **多来源冲突**。MEMORY.md 里零散记着“用户偏好 TypeScript”，AGENTS.md 里又有别的相关规则，互相打架，行为不稳定。

一句话：Agent 不缺记忆，缺一个**关于用户事实的唯一事实来源**。

## 做法

1. **初始化**。在工作区（`~/.openclaw/workspace/`）创建 USER.md，第一版直接手写，不要指望 Agent 自己总结——它只会写出泛泛的档案。
2. **分区写**。建议五个区块：
   - 身份与环境：时区、语言、角色；
   - 技术上下文：主力语言/框架、常用工具、部署习惯；
   - 硬约束：明确不许做的事，如“不要自动提交代码”；
   - 沟通偏好：简洁还是展开、要不要解释原理；
   - 当前状态：**带日期**的短期事实，如“2025-06 至 09：主攻某项目”。
3. **定规则**。在 AGENTS.md 里加一条：关于用户本人的事实以 USER.md 为准；MEMORY.md 只记事件与偏好变化，不重复事实。
4. **让 Agent 参与维护**。约定一个动作：当你说“记住这个”，它判断该写入 USER.md 还是 MEMORY.md，并回报改动内容。
5. **定期修剪**。每月看一次，删掉过期的“当前状态”，整体控制在 60 行以内。

## 踩坑点

- **写成简历**。超过一屏的 USER.md 每次会话都在吃上下文，低频信息还会稀释高频信息。原则：只写“会改变 Agent 行为”的事实。
- **状态没有失效日期**。“我在休假”如果不带日期，一个月后 Agent 还在小心翼翼地不给你排任务。
- **放敏感信息**。API key、密码、证件号绝不能出现。工作区可能被同步、被备份，也可能被你随手贴出去。
- **职责越界**。行为规则归 AGENTS.md，人格语气归 SOUL.md，USER.md 只放事实。写成“回复我应该热情一点”就已经写错地方了。
- **群聊场景**。USER.md 描述的是 owner。群成员问“我是谁”时，Agent 可能拿你的档案硬套，需要在规则里圈定适用范围。

## 可复用建议

- 好的一条：`主力机：M 系列 Mac，Docker 部署，习惯 pnpm 而非 npm`。
- 差的一条：`我喜欢技术`——不改变任何行为，删。
- 用“带日期的状态 + 无日期的常量”分层，状态过期后整段删除即可。
- 如果你的插件或脚本需要读用户画像，把它做成固定的结构化字段，比让脚本解析自然语言稳得多。

## 总结

USER.md 的价值不在“记录了多少”，而在“Agent 是否据此做出了不同的决策”。写它的过程也是一次自我梳理：哪些事实值得机器长期持有。从近几周的实践看，一次认真的一小时初始化，加上每月五分钟修剪，就能让 Agent 从“每次都像新来的实习生”变成“了解你的老同事”。
