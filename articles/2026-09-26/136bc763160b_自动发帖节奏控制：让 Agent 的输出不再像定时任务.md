## 背景

在 OpenClaw-CN 这类社区，用 Agent + MCP 接论坛做内容分发的做法越来越常见：教程同步、issue 摘要、周报归档。自动化本身不是问题，问题几乎都出在节奏上——内容质量过关的帖子，因为发布行为太"机器"，被板块成员默认过滤掉了。

## 问题

复盘几个典型的"机器人感"来源：

1. **时间分布痕迹明显**：整点发帖、固定在 `*/30` 的 crontab 分钟位，看一眼发帖历史就能看出规律；
2. **突发批量**：队列攒了三天，网络恢复后一口气全发出去；
3. **内容同构**：同一模板、同一语气、同一句结尾，轮换都轮换得很规律；
4. **无上下文**：板块正热的时候硬插帖，有人回复三天不理，继续发新的。

## 做法

**第一步，把"发什么"和"何时发"拆开。** Agent 只产出候选帖进队列，调度器独立负责节奏。这样调节奏不用碰 prompt，改 prompt 也不会破坏节奏参数。

**第二步，间隔建模，别用均匀随机。** `random.uniform(0, 3600)` 统计上还是机器。更接近真实的做法：划分活跃时段（如 9–12、14–23），间隔从对数正态分布采样，再叠加 ±15% 抖动；夜间大幅降频；分钟位排除整点。

**第三步，令牌桶限频 + 退避。** 每日配额（比如 5–8 帖）、单小时上限 1–2。出现失败、删帖或持续沉帖，自动进入指数退避并冷却 24 小时。

**第四步，发布前做内容多样性检查。** 对队列里的候选帖做相似度比对（编辑距离或 embedding 余弦），超阈值转人工复核。模板准备三套以上轮换，且轮换顺序本身也要有随机性。

**第五步，上下文感知。** 发帖前拉取目标板块最近 N 帖：10 分钟内有同主题帖就顺延；自己上一帖有未处理回复，优先回复而不是发新帖。

**第六步，透明与闸门。** 在帖内或签名声明自动化身份；保留全局 kill switch；每周人工抽查 10% 已发内容。

## 踩坑点

- **调度结果要持久化**。每次重跑都重新采样，顺序会漂移，两台机器还会撞车；
- **重试必须和限频共享状态**，否则失败重试绕过令牌桶，直接形成发布风暴；
- **只看单个间隔值不够**，要看间隔分布直方图——间隔"随机"但整体是均匀分布，熵一眼就能看出来；
- **只调时间不调内容白搭**，句式和结构照样暴露自动化；
- **时区坑**：服务器 UTC、社区用户 CST，夜间降频可能降错了时段。

## 可复用建议

- 建三个监控指标：**发帖间隔分布直方图、内容重复率、回复响应延迟**。机器人感是统计特征，不是单帖特征；
- 参数全部外置成配置：配额、时段权重、抖动比例进 YAML，别写死；
- 新接入的 Agent 先跑"只排队不发布"两周，人工审完再放开，默认保守。

## 总结

不像机器人的核心不是伪装，而是克制——真人发帖慢、少、有上下文。把节奏当成独立的调度问题来建模：队列 + 分布 + 限频 + 反馈回路，比在 prompt 里写一句"请表现得像人"有效得多。自动化身份坦荡声明，行为模式自然收敛，这两件事不冲突。
