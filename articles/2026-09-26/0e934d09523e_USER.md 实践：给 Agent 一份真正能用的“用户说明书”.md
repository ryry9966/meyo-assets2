## 背景

做 Agent 日常化这段时间，最常见的摩擦不是模型不够聪明，而是它每次开会话都“不认识我”。换台机器、隔一周再来，它又会问：项目用什么框架？代码风格偏好？部署习惯？答一次两次还行，答二十次就开始烦了。

很多人的解法是把自我介绍塞进 system prompt。能用，但问题很快出现：prompt 越写越长、越改越乱，个人信息和任务指令混在一起，改一处怕动全身。

## 问题

本质上这是一个记忆分层问题。Agent 的上下文有三层：模型通用能力、本次会话的任务输入、以及介于两者之间的“你是谁”。第三层长期缺位，导致：

- 每次会话重复交代背景，token 和耐心双重浪费；
- Agent 按通用假设输出——比如默认你写 Python，实际你主写 Go；
- 输出风格不稳定，今天简洁明天啰嗦。

system prompt 不适合承载这一层：它是给“任务”的，不是给“人”的，而且难版本化、难跨工具复用。

## 做法

我的方案是工作区根目录放一个 `USER.md`，配合启动引导在每次会话开始时注入。

**1. 建文件，只写“可执行的事实”。** 模板分五段：

```markdown
# USER.md

## 环境
- 主力机: macOS, 终端 iTerm2, shell zsh
- 技术栈: Go / TypeScript, 部署用 Docker Compose

## 偏好
- 回答默认中文，代码注释英文
- 先给最小可运行方案，再谈扩展

## 红线
- 不要未经确认直接 git push
- 不要重写我能小幅修改的文件

## 当前项目
- xxx（一句话描述 + 关键路径）

## 修正记录
- 2025-06-01: 部署已从 k8s 迁回 compose
```

**2. 接入引导流程。** 在启动指令里加一句：会话开始先读 `USER.md`，与任务冲突时以任务为准。OpenClaw 这类支持工作区文件的框架，把文件放进 workspace 让它随上下文可读即可。

**3. 让 Agent 参与维护。** 允许它在我纠正后往“修正记录”追加一行，格式固定：日期 + 一句话。这比我自己记得改文档靠谱得多。

**4. 控制体积。** 上限 2KB 左右，超出就合并旧条目、删过时内容。

## 踩坑点

- **写成人物小传。** “我喜欢简洁美学”这类描述 Agent 用不上，要写“回答不超过 300 字，先结论后过程”。
- **敏感信息入库。** API key、内网地址别写，`USER.md` 会随上下文进每次请求。
- **条目互相打架。** 迭代半年后新旧偏好并存，Agent 只能随机选一个。定期清理冲突，“修正记录”保留最新即可。
- **和项目级上下文混放。** 全局偏好放 `USER.md`，项目结构、构建命令放项目内的 `CONTEXT.md`，别把个人口味带到别的项目。
- **以为它读了。** 偶尔问一句“你目前对我环境的理解是什么”，验证注入是否生效，尤其是换工具或改配置之后。

## 可复用建议

- 把 `USER.md` 放进 dotfiles 仓库，多机同步，天然带修改历史。
- 团队场景镜像一份 `TEAM.md`，写协作规范而非个人偏好。
- “修正记录”是最有价值的一段，它本质上是人工标注的偏好数据集。
- 每月花五分钟删一次：删过时条目、合并重复项。文档和代码一样，不维护就腐烂。

## 总结

`USER.md` 不是记忆系统的替代品，它只是把“你是谁”从对话流里抽出来，变成一份可版本化、可审计、可同步的静态文件。成本是初始半小时加每月五分钟，收益是每次会话省掉开场白，输出一致性也明显提升。Agent 能力在涨，但“了解你”这件事，目前还是得自己动手写清楚。
