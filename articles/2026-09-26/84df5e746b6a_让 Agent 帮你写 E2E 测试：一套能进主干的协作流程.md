## 背景

E2E 测试是投入产出比最纠结的一层：写起来慢、选择器脆、维护贵。多数团队的现状是核心链路盖几条，其余靠人肉回归。Agent 改变了成本结构——它能读代码、跑命令、操作浏览器，而写 E2E 恰好是"读上下文 + 重复劳动"的典型场景。但直接丢一句"给这个页面写测试"，得到的多半是能编译却跑不通的脚本。这篇分享一个我们跑了几个迭代的流程，目标是让 Agent 的产出能进主干。

## 问题

两个核心矛盾：

1. **Agent 会幻觉选择器。** 不真实打开页面时，它倾向凭 class 名猜定位器，测试第一次运行就红。
2. **Agent 会为通过而放水。** 测试失败时若不加约束，它会删断言、塞 `waitForTimeout(5000)`，把测试改"绿"而不是改"对"。

## 做法

技术栈是 Playwright，通过 MCP 把 Playwright server 挂到 OpenClaw 的 agent 上，流程五步：

1. **人定范围，Agent 写计划。** 让它先读路由和页面组件，产出测试计划：哪些用户流、每条流验证什么不变量。人审计划不审代码，这一步成本最低、收益最大。
2. **强制走真实浏览器。** 要求 Agent 先用浏览器工具把流程"走一遍"再写代码，选择器必须来自实际 DOM 快照。Playwright MCP 返回的是 accessibility tree，比截图可靠得多。
3. **按项目规范落盘。** 仓库里放一份测试规范（page object 结构、fixture 用法、命名约定），写进 agent 的项目说明。生成的代码对齐现有结构，review 成本大幅下降。
4. **跑-修循环。** Agent 自己执行测试、读失败输出自行修复。关键约束：失败时只允许修定位器和等待策略，不允许动断言语义。
5. **人工 gate 只看断言。** review 时我只读 `expect` 行：断言是否表达业务不变量，有没有同义反复（比如断言跳转后的 URL 等于刚点的链接）。

## 踩坑点

- **登录态别让 Agent 现写。** 用 `storageState` 复用会话，否则每条测试都拖一段脆弱的登录脚本。
- **禁用 `waitForTimeout`。** 写进规范，改成 `toBeVisible()` 这类自动等待断言，否则 Agent 会大量撒等待，测试又慢又飘。
- **选择器契约要 lint 兜底。** 组件强制 `data-testid`，ESLint 禁止测试文件用裸 class 选择器——Agent 猜不了不存在的东西。
- **一次只给一条用户流。** 让它一次生成整站测试，review 质量断崖式下跌。
- **警惕"全绿"。** Agent 改完全过不代表没问题，先看 diff 有没有动断言。

## 可复用建议

- 把测试规范当成 prompt 的一部分维护，随代码一起 review；
- MCP 浏览器工具是这个场景的刚需，纯靠读代码生成 E2E 基本不可用；
- 给 Agent 的权限做减法：能跑测试、能改 `*.spec.ts`，不碰生产代码；
- CI 失败日志回喂 Agent 自动修复是自然延伸，但保留人工合并。

## 总结

Agent 写 E2E 的价值不在替代人，而在把覆盖率从"顾得上几条"拉到"核心流全覆盖"。工程上就三件事：真实浏览器兜住选择器、规范文档约束代码风格、断言语义留给人审。跑通之后，新增一条用户流的测试成本降到半小时以内，E2E 回归才算真正常态化。
