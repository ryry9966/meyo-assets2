## 背景

高频使用 Agent 的人基本都卡在同一个循环里：新开会话，先花两分钟自我介绍——"我 macOS + zsh，包管理用 pnpm，中文回复，别自动 push"。项目侧我们有 AGENTS.md / CLAUDE.md 这类约定文件，但「用户侧」一直没有对等物。Agent 自带的记忆功能又偏黑盒：不知道它记了什么，记错了也没法审查和修正。

USER.md 补的就是这个缺口：一份由你本人维护、每次会话自动注入的静态用户画像。

## 做法

**1. 固定路径 + 自动加载。** 放在 `~/.openclaw/USER.md`，在 agent 配置里把内容注入 system prompt，或作为 MCP resource 暴露。关键是"每次会话自动带上"，别依赖手动引用。

**2. 内容控制在 300–500 字**，只写会影响回答方式的事实：

```markdown
# USER
## 环境
- macOS 15 / zsh / pnpm；服务器 Ubuntu 22.04
- 主力 Python 3.12 + Go
## 偏好
- 中文回复；先结论后原因
- 注释少而精，不写废话日志
## 红线
- 不自动 git push，不用 --force
- 改配置文件前先出 diff
```

**3. 明确分层规则。** 个人事实进 USER.md，项目事实进 AGENTS.md，冲突时项目级优先——把这条也写进文件，让 Agent 自行裁决。

**4. 维护节奏。** 每季度人工过一遍；也可以做一个 `/update-user` 自定义命令，让 Agent 主动提问、经你确认后以 diff 方式更新。

## 踩坑点

- **写太长。** USER.md 每轮都占上下文，塞满个人经历只会稀释真正的任务指令，还烧 token。300–500 字是实用上限。
- **写成自我评价。**"我是资深架构师"这类标签会让 Agent 省略你其实需要的解释。写行为偏好，不写身份。
- **信息过期。** 换了技术栈没更新，Agent 会自信地按旧栈出方案，比没有文件更糟。
- **敏感信息入库。** 密钥、内网域名写进去，很容易随截图外泄。这份文件里永远不放假名以外的真实凭据。
- **写入权放开。** 允许 Agent 基于对话自由改 USER.md，等于给 prompt injection 开了持久化后门。读可以自动，写必须人工确认。

## 可复用建议

- 把 USER.md 纳入 dotfiles 仓库做版本管理，多机同步；
- 模板固定五段：环境 / 偏好 / 红线 / 当前重点 / 沟通方式；
- 团队内共享的是脱敏模板，不是任何人的个人文件；
- 定期让 Agent 复述它从 USER.md 读到的关键点，验证注入链路确实生效。

## 总结

USER.md 没有任何新技术：一份 500 字以内的静态文本，加一条注入规则。但它把"每次重新解释自己"的隐性成本变成了一次性维护，且可审查、可版本化、可迁移。对每天高频用 Agent 的人来说，性价比极高——值得今天花十分钟写第一版。
