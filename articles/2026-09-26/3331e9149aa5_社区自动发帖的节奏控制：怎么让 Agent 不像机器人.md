## 背景

用 OpenClaw 挂定时任务往社区发帖，是很多人跑通 Agent 自动化的第一件事：每日精华、版本速递、周报汇总。跑通不难——一个 cron 触发的 skill，或者一条 MCP 定时工具调用，测试当天效果惊艳。难的是跑两周之后，版面开始出现一种整齐得可疑的节奏：每天 9:00:00 准点一条，间隔均匀，句式一致。人一眼能看出来，反垃圾规则也能。

## 问题：三层指纹

机器味不是单一来源，拆开看是三层：

1. **时间指纹**：固定 cron，秒级准时，周一到周日无差别。
2. **频率指纹**：事件触发就直发，一天多条连发；失败重试不设退避，故障恢复后逐条补发积压，形成爆发。
3. **内容指纹**：同一模板、同一链接结构、相近长度、同样的结尾句。

## 做法：把节奏做成一个独立模块

不要把发送逻辑散在各处，收拢成一个发送器，配一个节奏文件：

```json
{
  "window": ["08:30", "10:00"],
  "jitter_minutes": 45,
  "daily_cap": 5,
  "min_gap_minutes": 40,
  "backoff_minutes": [5, 15, 60],
  "digest_first": true
}
```

对应五个机制：

1. **时间窗 + 抖动**：不定义"9:00 发"，定义"08:30–10:00 之间发"，实际出队时间 = 窗口起点 + 随机偏移。周末单独一套窗口。
2. **频率预算**：状态文件记录当天已发条数和上一条时间，超日上限或距上一条不足 40 分钟就进队列延后。
3. **队列优先于直发**：所有事件先入队，由发送器按节奏消费；多条同类事件合并成一条 digest，而不是逐条刷屏。
4. **内容变体**：每类帖子准备 3–4 套开头和结构模板，按 hash + 随机选择，链接顺序和段落长度允许差异。
5. **失败退避**：按 5/15/60 分钟退避重试，恢复后积压内容先合并再发，不做逐条补发。

## 踩坑点

- **均匀随机也是指纹**。每次 `random(0,60)` 统计上仍是均匀分布，窗口 + 工作日/周末加权更自然。
- **忘了时区和夏令时**。服务器是 UTC，社区在东八区，结果每天下午五点发"早报"。
- **抖动加错了位置**。加在生成侧没用，出队时间才是对外可见的节奏。
- **重试风暴**。三个任务各自重试，一分钟发了三条重复帖。发送器必须全局单例，退避状态共享。
- **时间修好了，内容指纹还在**。同样的"今日更新如下："连发三十天照样露馅。

## 可复用建议

节奏参数全部配置化，换一个社区只改一份 JSON。再留两个开关：`digest_first`（默认合并同类事件）和 review flag（敏感类目先落草稿，等人过一眼再放行）。这两项把自动化事故的成本降了一个量级——尤其是后者，出过一次事故你就懂了。

## 总结

不像机器人的本质，不是把随机性堆上去，而是让对外可见的行为——什么时候发、发多频、长什么样——服从一个有人参与边界的分布。时间窗、频率预算、队列合并三件事做完，八成机器味就没了；剩下两成靠模板轮换和偶尔的人工介入兜底。自动化要的不是"完全无人"，而是"无人时也体面"。
