## 背景

用 Agent 干活超过两周，你大概率会陷入一个循环：每次新会话都要自我介绍一遍。“主力语言是 TypeScript”“部署在自建 K8s 上”“回复用中文”“别动我的 lint 配置”。项目级的 CLAUDE.md / AGENTS.md 解决了“这个仓库怎么干活”，但“我是谁、我怎么工作”这一层，通常散落在聊天记录或黑盒式的自动记忆里，既不可控也不可审计。

## 问题

- **重复输入**：用户级偏好没有稳定落点，每个会话都是冷启动。
- **记忆不可控**：自动记忆会积累，但你很难检查它记了什么、记错了什么，更难一键纠正。
- **多入口漂移**：CLI、网关、不同模型接的同一套 MCP 工具，各自“对你的理解”互不一致。

## 做法

在 OpenClaw 的 workspace 里，除了项目说明，再维护一份用户级文件，比如 `USER.md`（文件名不重要，职责单一才重要）。四条要点：

1. **分层**：`USER.md` 只写“我是谁、我的环境和偏好”，与仓库级说明互不重叠。优先级自己定死，并写进两个文件里。
2. **写事实，不写口号**：“保持简洁”没用；“默认回复中文，代码注释用英文，commit 遵循 Conventional Commits”才有可执行性。
3. **控制体积**：这份文件每个会话都进上下文，建议压在 1–2KB。一个条目一行，别写成自传。
4. **分区**：环境与时区（OS、时区、工作时段）／技术栈与规范／当前项目（一句话 + 状态）／回复偏好／红线（明确禁止的操作）。

再配一条维护流程：当 Agent 发现“用户重复纠正了同一件事”时，**提出**更新建议，diff 展示，你确认后写入。每周花五分钟通读一遍，删掉过时条目。

## 踩坑点

- **写太长**：10KB 的 USER.md 每个会话都在烧 token，且后半段常被模型忽略。删减是常态工作。
- **信息过期**：项目换了、时区变了、文件没跟上，Agent 会自信地按旧信息干活。给易变条目加日期戳。
- **塞敏感信息**：密钥、内网地址不要放。这份文件会被注入每一次上下文，任何被调用的工具、MCP server 都可能看到它。
- **让 Agent 自由改写**：无确认的自动更新会让文件漂移。原则是“Agent 提案，人拍板”。
- **和项目文件打架**：两边都写“如何写代码”，模型行为会不稳定。用户级写人，项目级写事。

## 可复用建议

- 把 USER.md 放进私有 git 仓库，改动走 diff review，配置即代码。
- 用固定模板起步，先填五条，跑两周再补。
- 与自动记忆配合而非替代：稳定事实进 USER.md，过程性记忆留给记忆系统。
- 多 Agent 场景下，把它当作唯一的用户上下文源，其他入口只读引用。

## 总结

USER.md 本质上是一份你完全可控、可审计、可版本化的“用户级系统提示”。它不神秘，也不智能——但正因为它足够笨，才足够可靠。花半小时写好第一版，你会省下之后每天的自我介绍。
