## 背景

Agent 用久了都会遇到同一个尴尬：每次新会话，它都不认识你。你得重新交代一遍自己用 macOS 还是 Linux、shell 是 zsh、回答用中文、代码示例不要太啰嗦、某些目录不要碰。这些信息和任务本身无关，却直接决定了每次交互的质量。

系统提示词解决的是"Agent 是谁"，而"用户是谁"这件事一直没有正式的落点，散落在历史对话里，会话一关就丢。USER.md 就是补这个缺口的：一份纯 Markdown 文件，在会话启动时注入上下文——静态、可版本化、可 review。对 OpenClaw 这类常驻 Agent 来说，它对 MCP 工具调用和定时自动化任务同样生效；尤其是无人值守跑任务时，Agent 唯一能依赖的"对你的了解"，就是这份文件。

## 做法

三步就够：

**1. 固定位置，划分职责。** 放在 `~/.openclaw/USER.md`（或你所用 Agent 约定的全局记忆路径），确保每次会话自动加载。项目级约定另放仓库根目录的 AGENT.md。两者职责分开：一个写人，一个写仓库。

**2. 控制结构和长度。** 建议不超过 60 行，分四段：

- **环境**：OS、shell、编辑器、时区、语言偏好；
- **技术栈**：主用语言、框架、版本约束、明确避开的依赖；
- **协作方式**：直接给结论还是先给方案、代码示例的详细程度、是否需要解释取舍；
- **红线**：不允许自动执行的命令、不碰的路径、不要生成的内容。

**3. 建立更新习惯。** 核心是把"纠错"变成"入库"：Agent 猜错一次，口头纠正即可；同样的错出现第二次，就该写进 USER.md。每月 review 一遍，删掉从未起过作用的条目。

## 踩坑点

- **写太长。** 200 行的 USER.md 约等于没有。上下文注意力是稀缺资源，每一条都在稀释其他条目的权重。
- **把易变信息写死。** "当前在做 X 项目"这类内容两周就腐烂。要么标注日期，要么挪到单独的临时文件里定期清理，别和稳定偏好混在一起。
- **当成机密容器。** 它会进入每一次 prompt，可能被同步、被截屏、在分享 dotfiles 时被一起带出去。密钥、内网地址、客户信息绝对不写。
- **和项目文件打架。** 项目 AGENT.md 要求用 pytest，USER.md 里却写着偏爱 unittest。要定好优先级：仓库相关的以项目文件为准，USER.md 只保留跨项目稳定的个人偏好。
- **一次写完就不管。** 它不是安装时的一次性配置，是 living doc。三个月不更新的 USER.md，大概率一半内容已经失真。

## 可复用建议

- **每行原子化，用祈使句。** "回答用中文"远比"我觉得还是中文好一点"有效。
- **两遍法则：** 同一条指令重复说了第二遍，说明它该进 USER.md 了。
- **做减法优先于做加法。** 季度性删减比持续堆叠更重要，起不到作用的条目只会消耗注意力。
- **用 git 管理。** 改动留痕，也能在多台机器之间干净地同步。

## 总结

USER.md 是一个成本极低的工程动作：一份静态文件，换来 Agent 对你的稳定认知，并且这份认知是可 review、可回滚、可迁移的。它的价值不在于写了多少，而在于被维护得多好——小、准、常更新，比面面俱到重要得多。如果你每天和 Agent 打交道超过一小时，这份文件的投入产出比大概率超过你最近调的任何一段提示词。
