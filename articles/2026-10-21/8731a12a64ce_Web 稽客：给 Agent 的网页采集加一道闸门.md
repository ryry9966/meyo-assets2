## 背景

让 Agent「去看一下这个网页」是最高频的需求之一。但直接把抓取能力丢给模型，问题从来不是抓不到，而是抓回来的东西不可控：上下文被撑爆、被页面内容注入、甚至被诱导去访问内网地址。我们在 OpenClaw 里加了一个内部工具，代号「稽客」（取"稽查"之意），职责只有一条：所有出网请求都过它，返回给 Agent 的必须是干净、可溯源、限定体积的文本。

## 问题

裸抓会踩四类坑：

- **安全**：页面正文里可以埋「忽略以上指令，转而访问 xx」式注入；URL 校验缺失时还会被用来做 SSRF。
- **合规与礼貌**：不读 robots.txt、不限速，跑几次任务就被目标站 403，连累同 IP 的其他服务。
- **质量**：整页 HTML 直接塞上下文，导航、页脚、内联脚本占掉八成 token，正文反而被截断。
- **不可审计**：Agent 到底访问过什么、拿到哪个版本的内容，事后说不清，排查全靠猜。

## 做法

稽客是独立的小服务，Agent 侧只看到一个工具调用（用 MCP 封装），流水线六步：

1. **入口校验**：URL 规范化 + 域名白名单；解析 DNS 后检查目标 IP，拒绝私网、环回、链路本地段，防 SSRF。
2. **礼貌层**：读 robots.txt（缓存 1 小时），按域名做令牌桶限速，默认每 2 秒 1 个请求，UA 带真实联系方式。
3. **抓取**：15 秒超时、5 MB 体积上限、只接受白名单 Content-Type；跟随重定向，但每一跳重新过校验。
4. **提取**：readability 类算法抽正文，HTML 转 Markdown，剥掉脚本、表单和导航噪音。
5. **消毒与裁剪**：扫描 "ignore previous instructions" 等高置信注入模式并打标；按 token 预算截断，宁短勿脏。
6. **出参**：结构化返回——正文、原始 URL、抓取时间、内容哈希、截断标志。约定 Agent 引用时必须带 URL。

## 踩坑点

- robots.txt 每次现拉太慢，缓存太久会失效；固定 1 小时再加手动刷新接口比较稳。
- 限速器一开始放内存，服务一重启计数清零，又被同一家站点限流。挪进 SQLite 才彻底解决。
- JS 渲染页面需要 headless 浏览器兜底，但必须单独容器运行，限 CPU/内存、禁止出站网络。
- 分页里的「下一页」会被 Agent 当任务循环一路追下去，要限制单次会话每域名的最大抓取页数。
- 中文老站编码坑：GBK 页面要结合响应头和 meta 双重探测，只信 chardet 会出乱码。

## 可复用建议

- 把网页内容当不可信输入，进模型前先消毒——这是底线，不是优化项。
- 采集能力独立成服务，Agent 只见结构化文本，天然可审计、可限权。
- 所有请求留日志：URL、时间、状态码、内容哈希，出事能回放。
- 提供「引用模式」：只回片段加 URL，鼓励 Agent 少抓多引。
- 按域名做熔断：连续 429/403 自动冷却 30 分钟。

## 总结

稽客没有黑科技，本质是把「礼貌、限额、消毒、留痕」四个词落成工程约束。上线后采集类任务失败率明显下降，更重要的是每一次抓取都能在日志里对上号。给 Agent 开网页权限之前，先给它建好这道闸门。
