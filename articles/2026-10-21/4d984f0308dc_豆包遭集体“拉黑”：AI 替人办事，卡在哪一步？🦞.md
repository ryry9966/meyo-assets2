最近一条热搜很能说明 AI 应用的现实处境：据 36kr 等媒体报道，豆包的 AI 助手在替用户完成酒店预订、票务比价这类“代理办事”时，被多家 OTA、票务和电商平台的反爬风控识别并拦截，被网友称为集体“拉黑”。一边是用户想省事的真实刚需，一边是平台严防死守的边界线。这背后不只是一次产品摩擦，而是一整套技术攻防加三本商业账。这篇把它拆开讲清楚：AI 怎么替人办事、平台怎么认出它、为什么拦，以及普通人现在该怎么办。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/1e3ac1d66392b09a.png)

## 先还原现场：AI 代理是怎么“办事”的

豆包这类 agent 替用户办事，工作流大致是：拆解任务 → 打开目标网页或调用工具 → 用用户授权的账号登录 → 比价、筛选、填表 → 提交订单。技术上通常走两条路：

- **API 路线**：调用平台开放的接口，稳定合规，但大多数平台根本没开放下单类 API；
- **浏览器自动化路线**：用 headless browser 或 computer use，让 AI 像人一样“看页面、点按钮”。

问题就出在第二条路上。对平台风控来说，这种“全自助”的 AI 和手速惊人的抢票脚本，在流量层面几乎长一个样：请求节奏稳定、无鼠标轨迹、设备指纹异常——一个“太完美的人类”，本身就是破绽。

类似摩擦并不新鲜：OpenAI 的 Operator、Perplexity 的 Comet 浏览器代理都曾被大型平台限制；2025 年 11 月，亚马逊明确封禁 Comet 的自动化访问，双方还隔空交锋了一轮。

## 平台为什么拦：算的是三本账

1. **流量账**。平台的商业模式建立在注意力上：广告位、推荐位、会员入口、促销弹窗，构成一条完整的曝光链路。Agent 直接取走结果，用户不看不点不逛，整条链路的转化归零。
2. **数据账**。实时价格、库存、评价是平台的核心资产。第三方高频抓取，轻则推高带宽成本，重则价格体系被套利、库存被脚本“扫货”。
3. **责任与公平账**。AI 订错日期、重复支付，责任算谁的？票务场景更敏感——黄牛外挂抢票的前车之鉴，让平台对所有“机器手速”高度过敏。

打个比方：你派了位全能管家去商场代购，商场保安拦在门口——管家免进，主人请亲自来。拦的不是人，是“不走我收银台的交易”。

## 风控怎么认出 AI：一套三层过滤器

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/e208c3b10d9cea44.png)

1. **身份层**：robots.txt（1994 年诞生的机器人排除协议，本质是君子协定）加 User-Agent 名单。AI 厂商如果自报家门，平台可以直接拒绝其抓取。
2. **特征层**：设备指纹与行为指纹——鼠标轨迹、滚动节奏、打字间隔、Canvas/WebGL 渲染差异、TLS/JA3 指纹；headless 浏览器的 navigator.webdriver 标志、CDP 调试痕迹，都是显性破绽。
3. **行为层**：频率与路径。真人会犹豫、回看、点错；agent 的访问路径近乎最优解，点击间隔方差极小，“从不手滑”反而可疑。

验证码的进化史就是攻防史：从扭曲字符，到 reCAPTCHA v3 直接给行为打分，再到无感风控。AI 破解旧锁的速度永远快于平台换锁的速度，于是平台干脆从“认码”转向“认人”。

## 深层矛盾：Agent Web 撞上围墙花园

互联网其实谈成过一次同样的交易——搜索引擎。Googlebot 被允许抓取，交换条件是带回流量：你帮我被找到，我帮你获客。这是一份隐形的双边契约，robots.txt 就是它的合同文本。

Agent 打破了这份契约：它不带走链接、带回访客，而是直接带走结果。交易在对话里完成，平台全程隐身。

历史上的剧本大概率重演：

- 2015 年底，多家航司集体下架去哪儿网旗舰店，撕扯近两年，最终以资本合并收场；
- 2023 年，X（Twitter）把免费 API 收成高价订阅，第三方客户端一夜团灭；
- 每一轮拉锯的走向都相似：先围墙，后收费站。

解法的雏形也已经在路上：Anthropic 的 MCP、Google 主导的 AP2（Agent Payments Protocol）、OpenAI 与 Stripe 推的 Agentic Commerce Protocol，都在尝试给“AI 代下单”修一条带闸门的官方管道——授权、支付、责任链全部留痕。欧盟《数字市场法》也把互操作性写进了大型平台的义务清单。所以问题的本质不是“能不能拦住”，而是“开放到什么程度、向谁收费”。

## AI 还能替我办事吗：三条现实路径

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/1ff1c514dae0cff6.png)

1. **走官方通道**：优先用平台自己接入的 AI 助手、开放 API 和授权插件。慢一点、功能少一点，但合规、稳定，出了问题有客服兜底。
2. **半自动模式**：让 AI 干侦察活——比价、筛选项、起草填表内容；把“扣扳机”的动作（提交订单、支付、授权隐私）留给自己。效率损失不到一成，风险却降一个数量级。
3. **审查授权链**：给任何 agent 开权限前问三个问题——它能看什么？能花多少？出错谁担？没有清晰授权边界的“全能助理”，等于把家门钥匙插在门外的锁上。

## 三条冷思考

- **封锁是防御，不是终局**。商业史上这类博弈通常收敛为“白名单 + 付费接口 + 按单分成”，真正值得盯的是：谁来定价、平台和 agent 厂商怎么分账。
- **对普通人**：判断一个 AI 办事工具靠不靠谱，先看它有没有官方授权，再看它要多少支付与账号权限。能力越强，权限审查要越严。
- **对行业**：Agent 时代真正稀缺的不是模型能力，而是“机器可读的商业规则”。谁先把授权与结算的标准定下来，谁就握住了下一个入口。
