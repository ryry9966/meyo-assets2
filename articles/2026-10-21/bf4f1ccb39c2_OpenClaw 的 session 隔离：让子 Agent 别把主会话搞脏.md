## 背景

我们在 OpenClaw 里跑长周期任务时，主会话是长期上下文的载体：项目约定、历史决策、用户偏好都在里面。子 agent 通常被派出去做检索、批量处理、跑工具这类"脏活"。早期我们的做法很随意——直接在主会话里 spawn，子 agent 的中间输出原样回流。跑了几天之后主会话上下文膨胀得厉害，模型开始忘事，明明刚确认过的约定又会问一遍。

## 问题

复盘下来，污染主要有三类：

- **上下文污染**：子 agent 的工具结果、失败重试、思考过程直接写进主会话历史，挤占了真正重要的信息。
- **状态污染**：子 agent 和主会话共享同一份 memory/workspace，子 agent 改了文件，主会话读到的状态和预期对不上。
- **行为污染**：子 agent 的错误和工具调用记录进入主会话，触发不必要的重试，甚至让主会话误判任务失败。

## 做法

现在我们的 spawn 流程固定成五步：

1. **显式声明独立 session**。spawn 时指定独立 session，让子 agent 拥有自己的历史栈，不复用主会话上下文。
2. **约定回传协议**。子 agent 结束时只返回结构化摘要：结论、产物路径、失败原因，不回传完整 transcript。上下文是"上行只给摘要，下行给足任务"。
3. **workspace 分层**。子 agent 在独立子目录里干活，持久化的结果由主会话确认后再合并进共享 memory。
4. **收窄工具面**。只给子 agent 开它需要的工具，避免它顺手改掉主会话依赖的配置。
5. **管理生命周期**。任务结束显式关闭子 session，检查有没有残留的定时任务或订阅。

## 踩坑点

- **任务描述太省**。只给子 agent 一句话，它就自己脑补上下文，产出一堆主会话根本不需要的东西。spawn 参数里要把约束和输出格式写清楚。
- **并发写共享文件**。两个子 agent 同时改一份 memory，互相覆盖。改成各写各的子目录、主会话统一合并后才解决。
- **摘要丢了失败信息**。有一次子 agent 部分失败，回传摘要里没体现，主会话当成成功继续往下走，错了一整条链路。现在摘要里强制包含 status 字段。
- **继承配置没清理**。子 agent 继承了主会话的定时任务，任务结束后还在跑，隔天发现会话里多了几条来历不明的消息。
- **调试时关隔离忘了开回来**。排查问题图省事直接共享 session，提交前忘了恢复，第二天上下文又乱了。

## 可复用建议

- 把回传摘要做成固定模板：**status / 结论 / 产物路径 / 需要主会话决策的点**。四项缺一不可。
- 隔离粒度按"是否写共享状态"判断：只读型子 agent 可以宽松些，会写 memory 或配置的必须隔离。
- 定期 review 代码里所有 spawn 调用点，确认都声明了独立 session 和工具白名单——这条我们写进了 CR checklist。

## 总结

Session 隔离不是把子 agent 关进信息孤岛，而是控制信息流动的方向：下行给足任务上下文，上行只回传摘要。主会话保持"指挥席"的角色，子 agent 是"外派工位"——干完活交报告，而不是把整个工位搬回指挥部。这套流程落地后，我们的主会话上下文体积稳定了一个量级，模型"失忆"的问题基本消失。
