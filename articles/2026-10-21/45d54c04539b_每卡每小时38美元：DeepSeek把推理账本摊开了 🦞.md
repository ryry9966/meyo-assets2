最近 AI 基础设施圈刷屏的消息：DeepSeek 宣布全面开源其推理框架，并一口气给出三个相当“硬”的数字——兼容英伟达与华为昇腾芯片、单集群日吞吐 155 万亿 Token、每张卡每小时收入 38 美元。这三个数字其实各自回答一个问题：系统跑在哪？能扛多少量？划不划算？这篇文章把这份被摊开的“推理账本”逐项拆开，看看数字背后的工程与商业逻辑。

## 一、先搞清楚：推理框架到底是干什么的

训练和推理常被混为一谈，其实是两套完全不同的活：

- **训练**像盖楼：一次性的大工程，动辄数月，拼集群稳定性和算子效率；
- **推理**像开餐厅：模型做好后每天开门营业，迎接海量请求，拼的是“翻台率”——同样一张卡，一小时内能服务多少用户。

推理框架就是这家餐厅的后厨管理系统，核心职责包括：

1. **请求调度**：把成百上千个并发请求拼成批次（continuous batching），不让 GPU 空转；
2. **KV Cache 管理**：已算过的上下文缓存起来，避免重复计算；
3. **算子优化**：注意力、矩阵乘等核心运算用手工调优的 kernel 压榨到硬件极限；
4. **并行切分**：模型大到单卡装不下时，切分到几十上百张卡协同工作。

DeepSeek 从 2025 年初的“开源周”起，已陆续放出 FlashMLA、DeepEP、DeepGEMM、3FS 等组件，这一次相当于补上最后一块拼图——直接对外服务的完整推理栈。此前各家开源的多是模型权重，而“怎么把模型跑得又快又便宜”这层工程细节，往往才是真正的护城河。

## 二、155 万亿 Token：高吞吐是“攒”出来的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/c7f27b2a5387ec19.png)

先做量级换算：155 万亿 Token/天，约等于每秒处理 18 亿个 Token。按中文粗略折算（1 个 Token 约对应 1.5 个汉字），相当于一天“读完”数亿部《红楼梦》。注意这是整套系统的吞吐口径，而非单一模型的极限，它靠四件事叠加：

1. **MLA + 定制 kernel**：多头潜在注意力（MLA）大幅压缩 KV Cache，配套的 FlashMLA 把显存带宽吃到接近极限——推理的瓶颈往往不在算力，而在“搬数据”的速度；
2. **MoE + 专家并行**：DeepSeek-V3 总参数 671B，每个 Token 只激活约 37B（约 1/18），DeepEP 提供高效的全对全通信，让上万张卡之间的“专家调度”不成为堵点；
3. **Prefill / Decode 分离**：读提示词（算力密集）和生成回答（访存密集）拆到不同节点，像切菜台与出菜口分开，互不挡道；
4. **前缀缓存**：公共上下文（如长系统提示词）只算一次，此前披露的统计周期里缓存命中率约 56%。

工程上这始终是个三角权衡：吞吐、延迟、成本。吞吐可以靠大批量硬堆，但用户等不起；真正值钱的是“在延迟红线内把批量拉到最大”的调度功力——同样的卡，不同团队跑出的成本能差数倍。

## 三、38 美元/卡/小时：账本比模型本身更值钱

这个数字要配合口径看：它是特定统计周期内、按 API 定价折算的**理论收入**，不是净利润。可以对照此前披露过的那笔账：

- 成本端：按 H800 租金每小时 2 美元计；
- 收入端：同期 API 折算日收入达数十万美元量级，**成本利润率约 545%**；
- “每卡每小时 38 美元”是把高峰收入进一步折算到单卡的口径。

三点提醒：

1. **收入 ≠ 利润**：电费、带宽、运维、硬件折旧、夜间低谷的算力闲置，都会摊薄真实利润率；
2. **这是工程效率的证明**：低价不是烧钱补贴，而是靠 MoE、MLA 架构和系统优化把单位 Token 成本打下来——账本的价值在于“证明低价可持续”；
3. **定价权信号**：当头部玩家公开成本结构，API 市场的定价逻辑就从“拍脑袋”转向“对标效率”，压力给到所有闭源服务商。

别人晒跑分，DeepSeek 晒账本，这波属于理工科式的凡尔赛。

## 四、兼容英伟达 + 昇腾：解开硬件绑定的那颗螺丝

同一套框架跑两家芯片，技术上靠清晰的抽象分层：

- **上层**：模型定义、调度策略、并行逻辑——硬件无关；
- **下层**：算子实现——分别面向 CUDA 和昇腾 CANN 各写一套，核心 kernel 按硬件特性重写。

这件事的意义在三个层面：

1. **对开发者**：应用代码不必为芯片重写，换硬件只动框架底层，有点像当年 JVM 的“一次编写、到处运行”；
2. **对芯片厂商**：能否顺畅跑好 DeepSeek 系模型，正在变成大模型时代的“实战通行证”，软件生态第一次成为芯片竞争的主战场；
3. **对供给安全**：在先进 GPU 获取存在外部不确定性的客观背景下，推理侧多硬件支持是工程上的对冲——多一条可用供给链，系统韧性就多一分。

## 五、冷思考：三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/0bfca89676d346b6.png)

1. **数字有口径，别直接抄进 BP**：“155 万亿”是特定集群的日吞吐，“38 美元”是理论折算收入。评估自己的项目，请用真实业务负载压测，算自己的账。
2. **开源 ≠ 零成本部署**：把这套框架跑到接近官方性能，需要懂并行策略和算子调优的工程团队。合理路径是：先用托管 API 验证产品，等规模、成本敏感度或数据合规要求到位，再基于开源栈自建。
3. **权重会过时，工程知识不会**：MoE 服务、大规模专家并行、稀疏注意力的设计文档，是少有的“一线实战公开课”。哪怕不部署，把 FlashMLA、DeepEP 的设计思路读一遍，对理解大模型系统的真实瓶颈也极有价值。
