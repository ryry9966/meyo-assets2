最近 36kr 报道，美团上线了一个叫 DeepSkill 的平台，定位很直白：收录和分发 AI 技能，目前入库超过 37 万个技能工具。媒体给它起了个传神的称呼——“大众点评版的 Skill 平台”。这个类比不算蹭热度：当 AI Agent 的“技能”像短视频一样疯狂供给时，发现、筛选、信任，每一环都缺基础设施。这篇文章拆三件事：技能到底是什么，为什么需要一个“点评平台”，以及美团在这盘棋里想要什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/a5875d7cca9281d3.png)

## 一、先搞清楚：这里说的“技能”是什么

- 在 Agent 语境里，Skill 不是大模型本身的能力，而是教模型“具体怎么干成某件事”的打包材料。以 Anthropic 2025 年 10 月推出的 Agent Skills 为例，一个 Skill 本质是个文件夹：一份 SKILL.md 写清楚什么时候用、分几步做，再配上参考文档和可选脚本，模型按需读取。
- 生态里类似的能力包还有好几种形态：MCP Server（工具调用协议）、插件、提示词模板、工作流编排文件。37 万这个数字，基本是把各家生态的技能、工具、模板合并统计的总量级。
- 打个比方：大模型是“会做饭的人”，Skill 是菜谱加锅具加半成品。人都会做饭，但有菜谱和没菜谱，出餐速度和稳定性差得远——顺便说一句，菜谱不能替你洗碗，所以 Skill 好不好用，最终还得看执行。

## 二、为什么需要一个“点评平台”：供给爆炸之后，发现成本上升

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/204ef2526f7a8c8d.png)

- 这个剧本互联网演过三轮：网站多到找不到 → 搜索引擎做索引；App 多到刷不完 → 应用商店做榜单和编辑推荐；餐馆多到没法选 → 大众点评做 UGC 评分。每一次供给爆炸，都会催生一个“分发 + 筛选”的基础设施，而卡住这个位置的平台，通常吃掉最肥的一段红利。
- 现在轮到 Skill。MCP 协议 2024 年 11 月开源后，社区里的 Server 数量一年内涨到上万量级；各家 Skill 仓库从 2025 年下半年开始指数式增长，37 万的收录量就是增速的直接体现。
- 供给爆炸带来三个典型问题。第一，同质化严重：“PDF 处理”“Excel 操作”这类高频需求动辄几百个变体，像外卖平台上一百家店用不同招牌卖同一碗黄焖鸡。第二，质量方差极大：有的是精调过的工程产物，有的只是把 prompt 换个文件名重新上传。第三，安全风险真实存在：Skill 里的指令会被模型读取并执行，恶意 Skill 等于把 prompt injection 的入口直接递到 Agent 手上。
- 这三点正好对应点评平台的三件套：索引解决“找得到”，评价解决“选得对”，核验解决“敢不敢用”。

## 三、“点评模式”的灵魂三件套：索引、评价、信任

- **索引层**：把 Skill 的功能描述、适用模型、权限需求做成结构化元数据。对人类用户是搜索和分类，对 Agent 是一份“可被检索的能力目录”——后者可能才是未来的主要流量来源，因为 Agent 不会刷页面，只会查目录。
- **评价层**：大众点评的核心资产从来不是餐馆列表，而是真实消费后沉淀的几亿条评价。对应到 Skill 上，最有价值的信号不是五星好评，而是执行数据：调用次数、成功率、失败归因、复用留存。
- **信任层**：应用商店用审核兜底安全，Skill 平台大概率靠三层组合——静态扫描（有没有可疑指令和外部请求）、沙箱试跑（真实环境跑一遍看行为）、权限披露（这个 Skill 能碰哪些数据）。
- 说句实话：前两件是体力活，第三件才是技术活。Skill 本质是“给模型读的自然语言程序”，语义层面的恶意意图检测远比传统代码审计难，这也可能是这类平台真正的技术壁垒。

## 四、美团的算盘：当 Agent 开始“点外卖”，入口在哪

- 表面看是个工具站，往深看是入口之争。设想用户对 Agent 说“订个适合四人聚会的川菜馆”，Agent 需要调用的是商家数据、库存接口、下单核销能力——这些恰好是美团的腹地。
- 逻辑其实很顺：人找服务的时代，平台分发流量（搜索、推荐）；Agent 找服务的时代，平台分发能力（Skill、工具、API）。分发对象变了，分发生意本身没变。谁掌握 Agent 的能力分发入口，谁就坐在下一轮本地服务竞争的牌桌上。
- 大众点评当年吃到的红利是评价数据护城河：几亿条真实消费评价无法短期复制。DeepSkill 若能沉淀“哪个技能在什么场景跑得通”的执行数据，复制的思路是同一个。
- 当然，不确定性也不小：Agent 调用服务的事实标准还没收敛，各家都在抢协议层和入口层，现在下结论为时过早。

## 五、冷思考：点评模式搬到技能生态，会不会水土不服

- **评分的参考价值可能打折**。“这家店好不好吃”是主观但稳定的判断，Skill 的效果却高度依赖模型版本和具体场景——同一个 Skill 在 A 模型上是神器，换个模型可能直接报错。评价体系如果不绑定“模型 + 场景”维度，评分会失真。
- **刷量会更隐蔽**。App 时代刷榜靠假下载，Skill 时代可以刷调用量、伪造执行日志，甚至用一堆马甲技能互相关联。反作弊要看真实任务的端到端完成率，而这恰恰只有掌握执行环境的玩家才做得到。
- **收录数量不是核心指标**。37 万听起来壮观，但如果大量条目是模板变体或已失效的旧版本，目录价值会快速衰减。点评平台的生死线是评价的新鲜度，Skill 平台的生死线是技能的存活率。

## 写在最后：三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-21/f81e60c35376b58b.png)

1. **如果你是开发者**：把 Skill 当产品做，别当代码片段做。写清楚适用场景和边界、给可复现的示例、权限申请最小化——往后，可验证的执行记录比 README 写得漂亮值钱得多。
2. **如果你是使用者或企业**：选技能别只看下载量和评分，优先看三样——执行成功率、权限范围、最近更新时间。涉及资金和数据的高风险操作，先在沙箱里小样本试跑。
3. **如果你是行业观察者**：判断这类平台的成色，盯一个指标就够——真实执行数据的回流量。收录可以靠爬，评分可以靠刷，只有持续回流的真实执行数据，才是“点评模式”成立的前提。
