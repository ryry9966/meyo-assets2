## 背景

OpenClaw 的 agent 围绕一套 workspace 文件工作：每次会话启动时，框架会把工作区里的几个 Markdown 注入上下文——SOUL.md 管行为基调，AGENTS.md 管操作约定，MEMORY.md 管长期记忆。IDENTITY.md 是其中最不起眼的一个，只回答一个问题：我是谁。字段很少：name、creature（形象）、vibe（气质）、emoji、头像。

关键设计在于：这个文件默认不是我们替 agent 写的，而是 bootstrap 阶段让 agent 自己起草第一版，之后人和 agent 共同维护。

## 问题

实践中常见两类症状：

1. **人格漂移**。跨会话没有稳定的自我描述，语气、自称每次随机，用户感知到的是一群相似但不同的助手。
2. **身份硬编码**。人设塞在 system prompt 或配置常量里，改一次要动代码重启，没有 diff、没有历史，agent 自己也无法参与修订。

多实例并存时更明显：两个实例出现在同一场会话里，用户分不清谁是谁。

## 做法

我们目前分四步：

**1. 自写初稿 + 人工边界。** 初始化时只给红线：语气约束、自称规则、行为边界声明，其余让 agent 自己填。它自己写的版本，遵守率明显高于我们代写的。

**2. 固定字段 + 自由段落。** 头部字段保证可解析，正文留一段自我描述：

```markdown
- name: 螺丝
- creature: 工作台上的机械爪
- vibe: 直接、少废话、先给结论
- emoji: 🔧
```

**3. 慢节奏修订。** 每两周一次身份复盘：让 agent 重读自己的 IDENTITY.md，结合近期会话提出修订 diff，人审后合入 git。身份是慢变量，不该跟着单次对话波动。

**4. 保持薄。** 只放“是谁”，怎么做事进 AGENTS.md，用户偏好进 USER.md。整体控制在 40 行以内。

## 踩坑点

- **写太长**。早期塞了二十条性格规则，每次会话注入一堆软指令，和任务指令打架，行为反而更不稳定；瘦身到一屏内才恢复。
- **混入任务指令**。“回复要带表格”属于 AGENTS.md，混进身份文件后，改个输出格式也得动身份，版本历史全是噪音。
- **放开自改**。允许 agent 随时改写身份，一周内出现讨好型漂移，自称越来越卑微。必须走 diff + 人工合入，且只开放 vibe 和自由段落，name 轻易别动。
- **多实例不同步**。两台设备各改各的，git 冲突后实例拿到旧版。现在固定单一远端，改动即推。

## 可复用建议

- 把身份当**有版本控制的资产**：git 管理，修订打 tag，随时可回滚。
- **模板化启动**：新实例复制模板加三条差异化约束，几分钟可用，不必每次从零引导。
- 写十行脚本做**一致性检查**：字段齐全、行数上限、禁用词扫描，挂到定时任务即可。
- 在意人设稳定的话，固化一组探针问题（如“介绍一下你自己”），每次修订后重跑并对比输出风格，算是最朴素的人设回归测试。

## 总结

IDENTITY.md 的价值不在“让 AI 有个性”这种玄学，而在于把人格从散落在 prompt 里的隐式状态，变成显式、可 review、可回滚、可演化的文件。设定一次是配置，持续演化才是机制。跑长周期的 OpenClaw 实例，建议认真维护这个文件——它很便宜，复利却不低。
