# 背景

大多数人用 Agent 的方式是"问答式"：想起来才问一句。但真正省心的自动化，是 Agent 自己按节奏巡检——定时看一眼有没有该做的事。OpenClaw 为此给了一个很轻的机制：工作区根目录的 `HEARTBEAT.md`。网关按固定间隔（默认约 30 分钟，可配置）唤醒一次 Agent，Agent 读这个文件，按里面的清单决定"做事"还是"什么都不做"。

# 问题

纯被动模式有三个痛点：

1. 周期性事务靠人记：日报、证书到期检查、磁盘水位，想起来才查；
2. 上下文断了：隔两天回来，你得重新交代一遍背景；
3. 要么不管，要么过火——早期不少人把一堆任务塞进心跳，结果每小时烧一遍 token、消息提示响个不停，最后干脆关掉。

HEARTBEAT.md 要解决的就是"主动但不吵"这个平衡。

# 做法

三步跑起来：

1. 打开工作区的 `HEARTBEAT.md`，没有就建一个。空文件时心跳开销最低，接近跳过，所以放心留空，想到了再加。
2. 用"条件 + 动作"的短清单写法，一行一条：

```markdown
- 若距上次日报超过 24h：汇总昨日会话记录，生成日报发到 #daily
- 若磁盘占用 > 85%：清理临时目录并通知我
- 每天首次心跳且是工作日上午：检查日历，播报今日安排
- 其他情况：不回复、不通知
```

3. 精确到时刻的任务别靠心跳猜时间。心跳间隔是"约"多久一次，不是准点；准点任务交给 cron 类工具或插件触发，HEARTBEAT.md 只负责巡检时顺带判断的事。

# 踩坑点

- **非空心跳 = 完整轮次**。每次都会读文件、推理、可能调工具。清单塞十几个常驻任务，等于每小时跑一遍全家桶，成本很可观，控制在 5 条以内。
- **"其他情况：不回复"一定要写**。不写的话，部分模型会每次心跳都礼貌性地汇报一句"今日无事"，通知轰炸就是这么来的。
- **长任务会阻塞节拍**。某次心跳触发十分钟的任务，后续节拍就推迟了。重活丢给后台任务或异步队列，心跳只做发现和分派。
- **文件里只写指令，不写数据**。有人把待办、密码提示都堆进去，Agent 每次都读一遍，既费 token 又扩大泄露面。
- **间隔漂移是常态**。重启、报错、模型慢都会让节拍不准，别把"第 N 次心跳"当业务逻辑依赖。

# 可复用建议

- 把 HEARTBEAT.md 当**巡检清单**而不是任务队列：它回答"现在有没有值得做的事"，而不是"按顺序执行这些"。
- 给每个动作加明确出口：做完往一个 `heartbeat-log.md` 追加一行，月底能审计它到底干了什么，避免黑盒自动化。
- 通知分级：无事静默，小事攒进日报，大事立刻发。确认你的通知渠道对心跳轮次默认不响铃。
- 每月删一次清单。巡检项和垃圾桶一样，只进不出迟早爆炸。

# 总结

HEARTBEAT.md 的价值不在功能多强，而在它把"主动性"变成了一个可版本控制、可审计的纯文本文件。从一个真正让你烦的周期性小事开始，跑稳了再加第二条。克制的清单 + 明确的静默条件，就是"主动但不吵"的全部秘密。
