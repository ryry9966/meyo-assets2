## 背景

OpenClaw 的 workspace 是 agent 的大本营：SOUL.md 定义人格，USER.md 存用户画像，memory 目录放长期记忆。但真正决定 agent 每次新会话第一件事做什么的，是 AGENTS.md。它不是给人看的 README，而是会话启动时注入上下文的操作规程。写得好的 AGENTS.md 能让 agent 少问、少猜、少跑偏。

## 问题

常见症状：每次开新会话 agent 都要重新摸索文件结构；明明写了 memory 协议却从不执行；heartbeat / cron 里的自动化任务每次输出口径不一样。根因大多不是模型能力，而是工作空间缺一份稳定、简短、可执行的说明书。上下文有限，没有纪律的手册等于没有手册。

## 做法与步骤

1. **先列硬约束**，放在最前面：目录地图（SOUL.md、USER.md、TOOLS.md、memory/ 各是什么）、回复语言与格式约定、禁止事项（如不主动外发、不覆盖 memory 归档）。
2. **写清读写路径**：哪个文件只读、哪个可追加、memory 按什么粒度分文件（比如按月）、agent 动手前应先读什么。
3. **把重复任务流程化**：例如"用户让记一件事 → 追加写入 memory/YYYY-MM.md → 回复一句确认"。步骤化比描述性语言可靠得多。
4. **写清工具路由**：接了 MCP 或插件后，把"哪类请求优先用哪个工具"放进手册；参数细节留给 TOOLS.md，两者别混。
5. **控制篇幅**：建议 150 行以内。AGENTS.md 每个会话都占上下文，写成长篇等于每轮交税。
6. **用空会话验证**：开一个全新会话，只观察默认行为是否符合预期；不符就回头改手册，而不是在对话里反复纠正。

## 踩坑点

- **当日记写**。情感化、叙事内容应进 SOUL.md 或 memory，手册只留规程。
- **层级混乱**。OpenClaw 支持全局 `~/.openclaw/AGENTS.md` 与 workspace 内文件叠加：通用约定放全局，工作区特定规则放局部，别全塞进全局。
- **改了不验证**。手册改动后不跑空会话测试，等于部署不回滚。
- **职责重叠**。工具怎么用进 TOOLS.md，何时用、用完做什么才进 AGENTS.md。
- **规则不可判对错**。"尽量""适当"这类词 agent 没法执行，等于没写。

## 可复用建议

- 结构分层：硬约束 → 目录地图 → 常用流程 → 工具路由 → 变更记录（附日期）。
- 每条规则可执行、可验收，能写"必须先读 X 再写 Y"就不写"注意 X"。
- 每月 review 一次：把对话里反复纠正 agent 的点固化进手册，这就是你的 agent 运维日志。
- 自动化任务（cron、heartbeat）单独一节，写清输出落点和失败时的行为。

## 总结

AGENTS.md 的价值不在写了多少，而在 agent 能否在新会话里稳定复现你期望的行为。把它当作持续维护的操作规程而非一次性配置，工作空间的可靠性会明显提升。不必追求一次写完美——先列目录地图加三条硬约束，跑一周空会话再迭代，比什么都没写强得多。
