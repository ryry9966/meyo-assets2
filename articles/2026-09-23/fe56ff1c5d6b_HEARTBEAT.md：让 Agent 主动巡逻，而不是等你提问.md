## 背景

多数人用 Agent 仍是"一问一答"：你提问，它回答，然后闲置。OpenClaw 的定位是常驻在聊天渠道里的个人助理网关，但如果它只在你 ping 的时候才工作，"助理"就名不副实——真正需要它的时刻，往往是你忘了问的时候。

HEARTBEAT.md 就是为此设计的机制：在 Agent 工作区根目录放这个文件，网关会每隔一段时间唤醒一次 Agent，让它读文件、判断"现在有没有该做的事"。有就执行，没有就静默返回。

## 问题

"让 AI 主动做事"听上去简单，实际有两个对立的坑：

- **完全被动**：监控某个目录、按状态提醒、整理笔记，全靠你记得开口；
- **天真轮询**：每分钟唤醒一次，token 烧得快，聊天里塞满无意义的主动消息，最后只能关掉。

心跳机制的价值，是把"什么时候该动"收敛成一份声明式、可维护的清单。

## 做法

1. 在工作区（默认 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`，写成检查清单，每条包含三要素：**触发条件、动作、汇报策略**。
2. 在配置里调整心跳间隔（`HEARTBEAT_INTERVAL_SECS`，默认约 30 分钟），低频起步。
3. 明确"无事可做"的输出约定：让 Agent 没有动作时只回复 `HEARTBEAT: ok`，网关会拦截这类回复，不会推给你。默认心跳提示词已带此约定，自定义时可别弄丢。
4. 分工清晰：每天 9 点发日报这类**硬性定时**交给 cron；**基于状态**的模糊检查才放心跳。

示例，可直接改用：

```markdown
# 常驻检查
- 若 ~/notes/inbox.md 出现未处理的新行：整理进 todo.md，不发消息
- 若 todo.md 未完成超过 20 条且连续两次心跳无变化：简短提醒我一次
- 工作日 09:00-10:00：检查当日日程，仅在有冲突时通知我
- 无事可做：只回复 HEARTBEAT: ok
```

## 踩坑点

- **成本**：每次心跳都是一次真实的模型调用，即使没动作。清单控制在 5 条以内，间隔宁可拉长。
- **自激循环**：Agent 上一轮写了个文件，下一轮又对它做出反应。清单里要写"不要对你自己刚写入的文件再次响应"，或用独立的 state 文件记录上次处理位置。
- **聊天轰炸**：不写清汇报策略，任何小事都会推到手机上。原则是"默认安静，异常才出声"。
- **时间感知**：别指望它自己知道现在几点。涉时条目让它先查系统时间，并写明时区。
- **上下文污染**：心跳默认跑在主会话里，长篇大论会挤占你日常对话的上下文，务必要求它简短。

## 可复用建议

- 把 HEARTBEAT.md 当运维 runbook 对待：进 git、写变更说明、定期清理失效条目；
- 每条规则坚持"条件 / 动作 / 汇报策略"三段式，拒绝含糊指令；
- 需要跨心跳记忆的状态，落盘到文件，不要依赖会话记忆；
- 新场景先加一条、跑几天、观察成本和误报率，再决定是否扩展。

## 总结

HEARTBEAT.md 本质上是给 Agent 加了一个低频巡逻循环，配合 `HEARTBEAT: ok` 的静默约定，把"主动"从口号变成可控的工程行为。它的价值不在清单多长，而在克制：少数几条高信号规则，加上"异常才打扰"的纪律，Agent 才会真正像一个值班助理，而不是一个定时说话的机器人。
