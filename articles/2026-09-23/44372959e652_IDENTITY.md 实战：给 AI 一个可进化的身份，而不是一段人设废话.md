## 背景

OpenClaw 的 workspace 里有一组 Markdown 文件各司其职：`AGENTS.md` 管行为规则，`SOUL.md` 管价值观与语气底色，`IDENTITY.md` 管"它是谁"——名字、形象、Vibe、emoji。每次会话启动，这些文件会被注入 system context。也就是说，IDENTITY.md 不是摆设，它是每个 session 都要付费加载的配置。

## 问题

默认状态下 agent 是一个"通用助手"：回复风格随模型心情波动，今天简洁明天话痨；多渠道（CLI / Telegram / 微信）下人格不一致；你想纠正语气，只能在聊天里反复说。把人设写死在长 system prompt 里也不行——改一次要动主配置，还和工具指令搅在一起，排查行为问题时分不清哪句 prompt 在起作用。

## 做法

1. **定位 workspace**（默认 `~/.openclaw/workspace`），编辑 `IDENTITY.md`，最小字段四行就够：

```markdown
- Name: 小螺
- Creature: 寄居蟹机器人
- Vibe: 克制、直接、偶尔冷幽默
- Emoji: 🐚
```

2. **控制篇幅。** 这个文件每个 session 都进上下文，建议 15 行以内，三个字段够用就不加第四个。
3. **分层放置。** 表层人格（名字/形象/语气）放 IDENTITY.md；行为规则（回复格式、工具习惯）放 AGENTS.md；价值观底线放 SOUL.md。身份文件里别写"回复先列步骤"这类指令，那是 AGENTS.md 的事。
4. **纳入 git。** workspace 本身就是目录，init 一个仓库，身份改动像代码一样提交，回滚有据可查。
5. **进化机制。** 当你在聊天里第三次纠正同一个语气问题时，把它提炼成一行写进 IDENTITY.md，然后 commit。身份是蒸馏出来的，不是一次想清楚的。

## 踩坑点

- **写成小作文。** 500 字的身份描述会稀释真正的行为指令，且每轮对话都在烧 token。
- **Vibe 词太强。** 写了"话痨""夸张"，agent 可能在技术排障时也插科打诨。形容词要像调参数一样克制。
- **与 AGENTS.md 冲突。** 一边要求"简洁到两行"，一边身份说"热情健谈"，模型行为会摇摆。改身份时顺手 grep 一遍规则文件。
- **多机编辑不同步。** 家里和公司各改一版，最后生效的是后写入的。git 同步是唯一解。

## 可复用建议

把身份当 config-as-code：短、版本化、小步修改，一次只动一个字段，观察一两天再继续。用户事实放 USER.md，事件记忆放 MEMORY.md，不要混进身份文件。每次 OpenClaw 升级后重读一遍这几个文件的注入逻辑——加载方式变了，你的优化就可能白做。

## 总结

IDENTITY.md 是个很小的文件，但它把"AI 是谁"从临时对话里拔出来，变成可评审、可回滚、可蒸馏的资产。工程上看，它解决的不是炫技问题，而是一致性问题：跨 session、跨渠道、跨时间的风格稳定性。写好这十几行，比在聊天里反复调教省事得多。
