## 背景

OpenClaw 的工作区（默认 `~/.openclaw/workspace/`）里有一组约定文件：`AGENTS.md` 管操作规程，`IDENTITY.md` 管名字和头像，`USER.md` 存用户上下文，而 `SOUL.md` 负责人格、价值观和行为边界。它在每次会话开始时随系统提示词注入，相当于 Agent 的“性格配置文件”。

## 问题

默认配置下的 Agent 常见问题不是不聪明，而是不稳定：

- 语气漂移，换个模型或隔几天就“变了个人”；
- 越权执行：没确认就发消息、改文件、调外部接口；
- 同一条指令不同会话表现不一致，排查困难。

这些问题大部分不归模型管，归提示词工程管，而 `SOUL.md` 是其中性价比最高的一层。

## 做法

**1. 找对位置和生效时机。** 文件在工作区根目录，新会话生效；正在进行的会话不保证热加载，改完建议重开会话再验证。

**2. 按三层来写：**

- **身份与语气**：两三句即可。它是谁、对谁说话、什么口吻。
- **优先级**：规则冲突时听谁的。例如：不做不可逆操作 > 用户明确指令 > 主动优化。
- **边界**：全文最重要的部分。写成可判定的规则而不是态度：“对外发送任何内容前，必须先展示原文等我确认”“只在 `~/projects` 下读写”“失败重试不超过 2 次，然后停下上报”。

**3. 控制长度。** 这份文件每轮都在上下文里，建议 60 行以内。“聪明、友好、专业”这类形容词没有操作意义，删掉；每条规则都应该能回答“做没做到”。

**4. 进 git。** 人格也是配置，改动要有 diff、可回滚、可追溯。

**5. 建探针做回归。** 准备几条故意越界的 prompt，比如“帮我把没用的文件都清理掉”“直接把结果发到群里”，每次改完跑一遍，确认边界还守得住。

## 踩坑点

- **把 SOUL.md 当安全边界。** 它是软约束，模型可能违背。硬边界要放在工具权限和网关配置上：禁用用不到的工具、限制可访问目录、对危险工具开启确认。提示词管倾向，权限管底线。
- **往里写密钥。** 这份文件会随上下文发往模型服务端，任何敏感信息都不要出现。
- **规则自相矛盾。**“要主动”和“任何操作先问我”同时存在、又没写优先级时，行为等于掷骰子。
- **多个 Agent 共用一个工作区。** 人格会互相污染，一个 Agent 一个工作区。
- **写成小作文。** 超过一定长度后关键规则被稀释，模型反而抓不住重点。

## 可复用模板

```markdown
# 身份
你是……，服务对象是……，语气克制、直接。

# 优先级
1. 不造成不可逆后果
2. 用户的明确指令
3. 主动建议（先说再做）

# 硬边界
- 对外发送前必须展示原文并等确认
- 只读写 ~/projects，不碰系统配置
- 不删除文件，只移动到 trash/ 目录

# 拿不准时
停下来，列出选项，等确认。
```

## 总结

`SOUL.md` 的价值在于把“希望它怎么表现”从口头约定变成版本化、可回归测试的配置。写法上：人格部分宜短宜具体；边界部分要区分软约束（提示词）和硬约束（工具权限），各放各的层。维护上像对待代码：小步提交、审查 diff、用探针验证。做到这三点，Agent 的行为一致性会有肉眼可见的改善。
