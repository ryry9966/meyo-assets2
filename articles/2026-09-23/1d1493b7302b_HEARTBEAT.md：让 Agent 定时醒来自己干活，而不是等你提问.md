# HEARTBEAT.md：让 Agent 定时醒来自己干活

## 背景

大部分人用 OpenClaw 的方式还是"一问一答"：你发消息，它回消息，会话结束它就沉寂了。但真正有价值的自动化场景往往是周期性的——每天看一眼 CI 是否挂了、每周确认备份是否完成、收到标记紧急的邮件时提醒我。这些事你不想每次都靠自己去想起来问。

OpenClaw 在 workspace 里内置了一个朴素但有效的机制：`~/.openclaw/workspace/HEARTBEAT.md`。Agent 会按固定间隔"心跳醒来"，读这个文件，有活就干，没活就继续睡。

## 问题

被动式 Agent 的核心缺陷是：**发起权在你手里，记忆也靠你**。你忘了问，事情就没人管。cron 能解决"定时"，但逻辑写死在脚本里，遇到需要判断的场景（"测试全绿就不用管，红了才通知我"）就笨重了。HEARTBEAT.md 的定位介于两者之间：定时触发，执行者是带上下文、能做判断的 Agent。

## 做法

**1. 建文件**。在 workspace 下写任务清单，`#` 开头的行是注释：

```markdown
# 心跳任务（注释行不触发）

- 检查 GitHub Actions 最近一次运行状态，全部通过则不打扰我
- 检查 /data/backup 下是否有今天时间戳的备份文件，缺失则警告
- 每周五整理本周未处理的待办摘要发给我
```

**2. 配间隔**。默认 30 分钟，可通过配置里的 `agents.defaults.heartbeat.interval` 或环境变量 `HEARTBEAT_INTERVAL` 调整。低频巡检拉到 60–120 分钟即可。

**3. 写清"何时沉默"**。这是任务描述里最重要的一句，比如"无异常不要回复我"，能省掉绝大多数无效打扰。

**4. 验证**。先把间隔临时调到 1 分钟，盯日志确认 Agent 行为符合预期，再恢复常规间隔。

## 踩坑点

- **空文件不触发是特性**：文件为空或只有注释时，心跳直接跳过、不产生调用。停用任务用注释掉是对的，但别误以为"文件存在内容就会跑"——写进去的必须是可执行指令。
- **间隔太短烧 token**：每次心跳都是一次真实的模型调用。5 分钟一次跑全天，成本自己算。没那么多事就别开高频。
- **任务写得模糊**："帮我看看项目"会让 Agent 自由发挥，结果不可预期。任务要可判定：查什么、什么算异常、异常时做什么。
- **心跳是串行的**：上一轮没跑完，下一轮不会并发执行。别把 20 分钟的重分析塞进 10 分钟间隔里。
- **忘了写静默规则**：Agent 默认倾向汇报。没有"无事不扰"的约束，你每天会收到一堆"一切正常"。

## 可复用建议

- **固定三段式**：每条任务按"检查 X → 若满足 Y → 动作 Z，否则静默"来写，执行稳定性明显更高。
- **心跳管模糊周期，cron 管准点**：需要每天 9:00 整触发的，用 OpenClaw 的 cron 任务更合适；心跳留给"隔段时间看一眼"的松散巡检。
- **让结果落盘**：让 Agent 把每次检查结果 append 到一个日志文件，回溯时不用猜"它到底跑没跑"。
- **任务保持幂等**：心跳可能因重启等原因重复触发，任务本身不应产生副作用累积。

## 总结

HEARTBEAT.md 本质上是把一个 markdown 文件变成了 Agent 的值班手册。它不炫技，但解决了一个真实问题：让 Agent 从被动应答变成有节奏的值守。建议从一两条低频、可判定、带静默规则的任务起步，观察一两天 token 消耗和打扰频率，再逐步加量。Agent 主动性的边界，就是你写进这个文件的内容。
