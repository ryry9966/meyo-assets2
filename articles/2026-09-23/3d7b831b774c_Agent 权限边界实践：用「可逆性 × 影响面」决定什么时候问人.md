## 背景

Agent 接上 MCP 和插件之后，能力从"聊天"扩展到"能写文件、能跑 shell、能发外部请求"。权限问题随之而来：确认太多，人会疲劳，确认沦为仪式；确认太少，一条错误命令可能删库、误发消息、烧掉 API 额度。这篇帖分享我们在实践中收敛出来的一套判断框架，不谈理念，只谈怎么落地。

## 问题

大多数团队划权限靠感觉："危险的操作问一下人"。但"危险"不可执行——模型不会因为你写了"危险"两个字就识别出 `git push --force` 和 `git commit` 的区别。真正可执行的判据只有两个维度：**可逆性**和**影响面**。

## 做法：二维四分级

| 层级 | 特征 | 例子 | 策略 |
|---|---|---|---|
| L0 | 只读 | 读文件、搜索、GET 请求 | 自动执行 |
| L1 | 可逆写 | 工作区写文件、feature 分支 commit | 自动执行 + 全量日志 |
| L2 | 不可逆/外溢 | push、publish、发消息、支付、删数据 | 必须过人 |
| L3 | 一律禁止 | 改自己的权限配置、接触凭证明文 | 不留判断空间 |

## 落地步骤

1. **配置层划界，不靠提示词劝**。在 MCP/插件配置里做工具级 allowlist/denylist。提示词是建议，配置才是边界。
2. **给 L2 工具包一层 human-gate**。模型必须调用 `ask_human`，参数强制带上：将执行的具体命令、目标对象、出错后果。
3. **计划审批替代步骤审批**。让 agent 先出执行计划，人批一次；批完后 L0/L1 自动跑，命中 L2 再停。逐条确认只会训练出无脑点"确认"的用户。
4. **给自动执行加硬约束**。调用次数、花费配额、沙箱、超时。边界不能只依赖模型判断，要让错误的爆炸半径有物理上限。
5. **审计 + 复盘**。所有自动执行落日志（工具名 + 参数），定期复盘，根据事故记录把工具在层级间移动。

## 踩坑点

1. **确认疲劳**。每步都问等于没人看确认内容。把确认压缩到检查点上。
2. **问得太空**。"我可以继续吗？"是无意义的问题。有效提问必须含命令、对象、后果三要素，最好带 diff 或预览。
3. **权限漂移**。"本次允许"悄悄变成"永久允许"，或任务 A 批的权限被复用到任务 B。权限要绑定任务/session，过期失效。
4. **隐性不可逆**。表面可逆的写操作触发了下游 webhook，实际不可逆。上线前梳理每个工具的副作用链。
5. **边界本身没测过**。新配置先在 dry-run 环境跑一遍，观察模型实际会触发哪些确认、有没有漏网的 L2。

## 可复用建议

- 判据写短：四行分级表放进 agent 配置即可，千字规章模型和人都不看。
- 宁可批计划，不要批步骤。
- 没有预览的确认等于掷硬币。
- 用配额兜底，别赌模型判断力。

## 总结

权限边界 = 可逆性 × 影响面 × 频率。原则是**少问、问准、错了也炸不大**。人工确认是人类唯一真正拥有的控制点，把它花在不可逆和外溢的操作上；其余交给日志、沙箱和配额兜底。边界不是一次画完的，是跟着事故记录迭代出来的。
