最近 AI 应用圈有个耐人寻味的钟摆效应：上半年大家比着赛把 Agent 的"自主权"拉满，让它自己规划、自己点鼠标、自己修错；下半年，越来越多一线开发者开始往回拧螺丝。36kr 那篇 Jev 发明者的专访，标题几乎一句话讲完了这股回流——"把工作流程掌握在程序里，只在需要理解和判断的地方嵌入 AI"。这不是保守，这是被线上故障教育出来的工程直觉。顺带一提，Jev 这个名字容易让人联想到经济学里的杰文斯悖论：蒸汽机效率越高，煤反而烧得越多。放到 AI 语境里就是——单次调用越便宜，人越容易把模型塞进根本不需要它的地方。而 Jev 的主张，恰恰是踩一脚刹车。这篇就拆一拆它背后的原理、机制和适用边界。

## 先算一笔账：全自动 Agent 为什么容易翻车

大模型的本质是一个概率采样器：同样的输入，输出不保证一致。这在单步任务里叫"创造力"，在长链路任务里就是"不确定性税"。

做个示意性的算术：假设每一步可靠率 95%，一条 20 步的串行链路，整体成功率就是 0.95 的 20 次方 ≈ 36%。一半以上的运行会死在半路。

- **误差链式放大**：上一步理解偏一点，下一步就在错误地基上继续盖楼。让 Agent 自主订机票加报销，它可能点错页面、编造航班号，或者在同一个循环里兜圈。
- **调试体验极差**：传统程序报错有堆栈可查，Agent 出错你得"在提示词里找 bug"——改一句话，全盘行为跟着变，回归测试无从做起。
- **成本与延迟不可控**：每一步都过一遍大模型，token 费用和响应时间随流程长度线性膨胀，而其中大量步骤（格式校验、字段比对、路由跳转）本来就不需要智能。

一句话总结：确定性任务交给概率模型，等于用火箭送外卖——能送到，但没必要，还容易炸。

## Jev 的答案：流程归代码，判断归模型

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-23/69f473373c0b9fd3.png)

这套思路的架构其实很朴素：

1. **程序做骨架**。用状态机或有向无环图（DAG）把流程写死：步骤顺序、分支条件、失败重试、超时兜底，全部是普通代码。
2. **模型只做一类特殊节点**。它的输入输出用结构化约束（JSON Schema、function calling）框死——模型不是自由发挥的聊天对象，而是一个"输入文本、输出带类型的判断结果"的模糊函数。

拿发票处理流水线举例：

- OCR 提取文字 → 确定性工具
- 字段是否齐全、格式是否合法 → 纯 if/else 代码
- 这张发票属于哪个费用类别 → 模型判断（语义分类）
- 金额超标、日期过期 → 代码规则
- 判断冲突时转人工 → 代码路由

整条流水线里，模型只出现在"分类"这一个工位上。类比一下：程序是流水线的传送带和轨道，AI 是流水线上唯一需要"看一眼、拿主意"的熟练工。更狠一点的说法是——大模型像个聪明但不稳定的实习生，别让他重新设计报销制度，只让他判断"这张票据看起来对不对"。

## 三个直接好处：可测试、省成本、能追责

- **可测试**：代码节点写单元测试，模型节点建"金标数据集"跑评测（evals）。改了提示词之后跑一遍基准，才知道有没有退化——这才是 AI 应用的回归测试。
- **省成本**：确定性步骤可以缓存结果，甚至完全不调模型。实践中常见的比例是：八到九成步骤是普通代码，模型只占两三个节点，token 账单和延迟大幅下降。而且小模型与大模型的调用成本差出一个数量级，判断点收窄之后，才有"哪步用便宜模型、哪步用贵模型"的路由空间。
- **能追责**：每次输出都能定位——代码 bug 查 commit 和日志，模型误判回放当时的输入与输出。全自主 Agent 最怕的就是"它为什么这么干"说不清楚；流程握在程序里，链路白纸黑字。

这个方向并非孤例。Anthropic 那篇流传很广的 Building Effective Agents 给过类似建议：能用 workflow 就别上 agent，永远从最简单的方案开始；LangGraph、Temporal 这类编排框架，也都在朝"显式状态机 + 受控的模型调用"靠拢。工程社区正在用脚投票。

## 边界：什么时候不该这么干

把流程写进程序不是免费午餐，它有三个前提：

1. **流程得先存在**。开放探索类任务（深度调研、发现式搜索）前期根本画不出状态机，硬套这套思路等于把未知硬编码成已知。
2. **建模成本要算得过账**。规则多到写不完的长尾流程，维护代码的成本可能超过收益。
3. **流程得相对稳定**。业务天天变、状态机天天改的场景，灵活的 Agent 反而更划算。

反过来说，凡是"步骤明确、分支清楚、只有少数环节需要理解语义"的任务——内容审核、工单分类、数据抽取、批量处理——"代码为骨、AI 为脑"几乎是当前性价比最高的架构。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-23/611950b335a620d7.png)

1. **能把流程讲清楚，本身就是稀缺能力**。AI 时代真正值钱的不是背 prompt 模板，而是把业务拆解成"确定性步骤 + 判断点"的工程能力——这正是 Jev 发明者反复强调的工作方式。
2. **判断点的边界会漂移**。定期复盘模型节点的准确率：某类判断已经高度稳定，就把它沉淀回代码规则；反过来，某段规则代码频繁打补丁，就考虑升级成模型判断。流程是活的，架构要留出迁徙通道。
3. **警惕双向偷懒**。"每一步都塞 AI"是凑热闹，"完全不用 AI"是赌气。动手之前先给每个环节分类：这是确定性任务，还是判断任务？答案不同，工具就不同。

技术的进步常常不体现为"更强的自动化"，而是"更清楚地知道哪里该自动化"。这条朴素的经验，可能比任何一代新模型都耐用。
