## 背景

OpenClaw 的主会话是你和 agent 长期对话的那个 session：历史逐轮累积，每轮都带着全部上下文进模型。日常问答没问题，但一旦主 agent 干重活——连续读几十个文件、抓网页、跑长输出的工具——上下文迅速膨胀，直观后果是：每轮 token 成本上涨、响应变慢、早期关键信息被稀释，模型开始“变笨”。

## 问题

我们踩过的坑很典型：让主 agent 调研一次技术选型，它连读十几个文档、抓了几轮网页，任务完成了，但主会话从此背上了几万 token 的中间产物，后续闲聊也在为这些垃圾付钱。根因是**执行过程和决策上下文共用同一个 session**。

## 做法

OpenClaw 的子 agent 机制正好解这个问题：spawn 出来的子 agent 拿到独立 session，干完活只把最终回复作为工具结果回传主会话。落地步骤：

1. **定下沉阈值**。预计批量读取、长输出、纯探索的任务一律 spawn；一两步能完成的小事直接做——spawn 本身有系统提示和工具定义的开销，小任务是负收益。
2. **任务写三段式**。目标（要什么结论）、约束（别动主工作区文件）、输出格式（“只返回结论和关键路径，控制在 20 行内”）。第三段最重要，回传内容会进主上下文。
3. **按需回捞**。真需要过程数据时用 `sessions_history` 定向拉取，别默认全量回流。
4. **工作区隔离**。给子 agent 配独立 workspace 或子目录，多任务并行时避免写冲突；涉及敏感目录的活开沙箱兜底。
5. **模型分级**。主会话用强模型做决策，子 agent 跑粗活可配性价比模型，成本立降。
6. **定期清理**。用 `openclaw sessions` 巡检，归档或删掉已跑完的子 session。

## 踩坑点

- **回传没限长**：子 agent 把“摘要”写成三千字报告，主会话照样被撑大。长度约束必须写进任务里，不能靠默契。
- **套娃 spawn**：子 agent 又拉子 agent，深度失控。要么禁掉子 agent 的 spawn 权限，要么显式限深。
- **状态错觉**：子 agent 每次都是全新 session，不会记得上次干了什么。需要跨次保留的状态落盘到文件，下次在任务里指路。
- **误用 `sessions_send`**：那是往已有 session 里塞消息，会直接污染对方上下文。跨会话协调要克制，能落盘就别发消息。

## 可复用建议

把「主会话 = 决策层，子会话 = 执行层，文件系统 = 交接板」当成团队约定写进 CLAUDE.md 类的规范文件；spawn 任务模板固化成 snippet 复用，三段式别每次现编；固定一个周期跑 sessions 巡检，防僵尸 session 堆积。

## 总结

Session 隔离的本质是划定上下文边界：**脏活下沉、结论上浮、状态落盘**。做到这三条，主会话能长期保持轻、准、便宜——这是子 agent 机制带来的最实际收益，比任何 prompt 技巧都稳。
