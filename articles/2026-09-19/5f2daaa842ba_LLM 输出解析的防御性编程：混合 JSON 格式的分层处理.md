## 背景

在 OpenClaw 的 agent、MCP 工具链和自动化插件里，让模型输出结构化 JSON 是绕不开的一环：工作流节点之间靠它传数据，插件靠它决定下一步动作。提示词里写"只输出 JSON，不要任何解释"，模型也答应了，但任务跑上几百次你会发现，返回格式并不稳定。

## 问题

从真实失败日志里归类，大致几种：

- **裸 JSON**：理想情况，`JSON.parse` 直接过；
- **围栏包裹**：整段被 ```json ... ``` 包住，前后还带一句"以下是结果"；
- **散文夹带**：JSON 前后有说明文字，甚至 value 里嵌了示例代码，出现嵌套围栏；
- **语法瑕疵**：尾逗号、中文引号、单引号键、`//` 注释；
- **截断**：max_tokens 打满，右括号缺失。

任何一层直接 `JSON.parse`，除第一类外全部失败。更麻烦的是同一任务跨多次调用格式会漂移——温度、上下文长度、模型版本都会影响。

## 做法：五层漏斗

我们把解析收敛成一个工具函数，按代价从低到高分五层：

1. **快速路径**：先直接 `parse`，多数调用到这层就结束；
2. **剥壳**：正则剥掉 markdown 围栏与首尾散文，注意语言标记可能是 `json`、`JSON` 或干脆没有；
3. **定位**：放弃用正则匹配 JSON 主体，改用括号配对扫描——从第一个 `{` 或 `[` 起做深度计数，且必须跳过字符串内部（处理 `\"` 转义）：

```javascript
function extractJsonBlock(text) {
  for (let i = 0; i < text.length; i++) {
    const open = text[i];
    if (open !== '{' && open !== '[') continue;
    const close = open === '{' ? '}' : ']';
    let depth = 0, inStr = false, esc = false;
    for (let j = i; j < text.length; j++) {
      const c = text[j];
      if (inStr) {
        if (esc) esc = false;
        else if (c === '\\') esc = true;
        else if (c === '"') inStr = false;
      } else if (c === '"') inStr = true;
      else if (c === open) depth++;
      else if (c === close && --depth === 0) return text.slice(i, j + 1);
    }
  }
  throw new Error('no balanced block');
}
```

4. **修复**：仍失败时处理尾逗号、智能引号，或交给 jsonrepair 这类库兜底；
5. **校验与重试**：`parse` 成功不等于数据可用。用 zod/ajv 做 schema 校验，失败就把原始输出连同报错喂回模型，要求"只修格式、不改语义"，通常一轮就能修好。

## 踩坑点

- 贪婪正则 `/\{.*\}/s` 会吞掉多个对象之间的内容，非贪婪又可能截断，别用正则定位主体；
- 括号计数器若忽略字符串内的引号，遇到 value 里有 `{` `}` 就崩——这是被复制最多的错误实现；
- 截断输出不要盲目修复：补右括号会得到结构合法但语义残缺的数据。应识别为独立失败类别，调大 token 上限或拆分输出；
- jsonrepair 可能"顺手"改数据：日期被规整、数字精度漂移，修复层之后必须强制过 schema；
- 流式场景可能一次吐多个 JSON 对象，先想清楚取第一个还是全解析。

## 可复用建议

- 插件/技能的解析入口只留一个，杜绝散落各处的 `JSON.parse`；
- 日志里记录"第几层救回的"，积累一段时间就能量化自己的提示词漂移程度；
- 线上失败样本脱敏后存成 fixture 做回归测试，比任何凭空写的用例都真实；
- 优先用运行时提供的结构化输出/工具调用 schema（JSON mode 等），防御解析是兜底，不是替代。

## 总结

防御性解析不是不信任模型，而是承认"格式不确定"本就是系统输入的一部分。五层漏斗 + schema 校验 + 带错误信息的重试，实现成本很低，却能把长跑工作流里最烦人的偶发失败压到接近零。
