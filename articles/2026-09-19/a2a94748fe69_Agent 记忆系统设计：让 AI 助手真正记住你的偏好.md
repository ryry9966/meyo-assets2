## 背景

LLM 本身无状态，每次会话都从零开始。上下文窗口再大，也解决不了跨会话问题：总不能每次都告诉 Agent「提交信息别用 emoji、部署目标是家里那台 NUC、包管理用 pnpm」。而且上下文越长成本越高，历史记录里真正稳定的偏好只占很小比例。记忆系统的目标不是「记住一切」，而是低成本、可靠地把少量高价值事实带进下一次会话。

## 问题：三种常见的错误做法

1. **全塞 system prompt**：token 成本线性上涨，旧偏好还会和新指令互相冲突。
2. **上来就微调**：改一个偏好要重训模型，完全不合算。
3. **裸向量库**：所有对话都 embed 进去，检索噪声大，矛盾信息随时间堆积。

本质问题是：记忆系统 = 写入策略 + 读取策略 + 维护机制，三者缺一不可。

## 做法：分层记忆 + 工具化读写

**先把记忆拆成三层：**

- **用户画像（稳定事实）**：语言、工具链、部署环境、沟通风格。用结构化存储（SQLite 或 JSON），字段建议：`fact / category / confidence / source / created_at / status`
- **会话摘要（情景记忆）**：会话结束时用小模型生成 200 字以内摘要，向量化后按需检索
- **工作记忆**：当前会话上下文，不用额外处理

**写路径：不要自动写一切。** 触发条件限定为三种：用户显式说「记住 X」、同一偏好出现 ≥2 次、会话结束时的高置信度抽取。写入前先查重，命中则更新而不是追加。

**读路径：** 会话启动时注入 top-K 画像条目（预算控制在几百 token）；同时通过 MCP 暴露 `memory_search` / `memory_update` / `memory_forget` 三个工具，让 Agent 按需检索和修正。排序用「最近使用 + 频率 + 置信度」加权，别只看向量相似度。

**维护：** 新事实覆盖旧事实时保留历史（审计需要）；给事实加 TTL 或按 `last_used` 衰减；提供 `memory_list` 让用户随时查看、删除。

## 踩坑点

- **只增不改**：三个月后记忆里同时存在「用 npm」和「迁移到 pnpm」，Agent 行为随机化。必须做冲突更新。
- **过度抽取**：把用户随口一说当偏好存下来，慢慢污染画像。宁可漏存，多次确认再写。
- **记忆投毒**：检索出的记忆会拼进 prompt，本质是不可信输入。共享记忆库场景下，一条恶意「偏好」就可能让 Agent 执行错误命令。要标记来源、保持沙箱意识。
- **预算失控**：注入记忆从 500 token 悄悄涨到 5000。给注入量加硬上限和监控。
- **静默写入**：Agent 偷偷记住东西会让用户不安。每次写入都应在对话中可见、可否决。

## 可复用建议

- 最小可行版本：一个 markdown/JSON 画像文件 + 一个读写工具 + 会话结束摘要，一天能跑通。
- 先做结构化画像，再上向量检索。很多人顺序反了。
- 改动记忆策略后，用历史会话回放做回归测试，别靠感觉。

## 总结

让 Agent 记住偏好，难点不在存储，而在写入的克制、读取的精准、维护的可持续。从一个小画像文件开始，把每条记忆变成可审计、可删除的数据，比堆一个「超级记忆库」实用得多。
