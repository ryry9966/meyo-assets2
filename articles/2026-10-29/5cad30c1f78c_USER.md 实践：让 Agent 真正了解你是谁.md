# 背景

项目里我们习惯写 AGENTS.md 告诉 Agent「这个仓库怎么玩」，但很少有人写一份文件告诉它「我是谁」。结果就是每次新会话都重复自我介绍：我用 macOS 不用 Windows、包管理器是 pnpm、部署走内网、回答用中文、别自作主张升级依赖。

# 问题

缺少用户画像时，Agent 只能按「平均水平」假设行事：

- **环境猜错**：给出 `brew` 命令，而你在用 apt；
- **流程猜错**：直接 push main，而你的团队要求走 PR；
- **风格不合**：输出长篇铺垫，而你要的是先给结论。

这不是能力问题，是上下文缺失。会话级 memory 能缓解一部分，但跨工具、跨机器、跨模型时依然冷启动。

# 做法

1. **建文件**：固定位置放一份 `~/.openclaw/USER.md`，全局一份；项目差异放各仓库的 AGENTS.md。
2. **控制结构**，五个小节：身份角色 / 运行环境（OS、shell、语言版本）/ 固定工作流（部署、命名、提交习惯）/ 沟通偏好（语言、详略）/ 红线（不许做什么）。
3. **注入方式三选一**：启动 hook 把 USER.md 拼进 system prompt；或封装成 MCP resource 按需读取；或插件在会话初始化时加载。OpenClaw 里 hook + 模板变量最省事。
4. **纳入版本管理**：放进 dotfiles 仓库，多机同步，改动可追溯。
5. **让 Agent 帮你写初稿**：「请采访我 10 个问题，然后生成 USER.md」——比对空文件发呆快得多。

骨架示例（15 行内足够）：

```markdown
# USER.md
## 环境
- macOS 15 / zsh / node 22 / pnpm
## 工作流
- 提交遵循 Conventional Commits；不直接动 main
## 沟通
- 中文回复；先结论后细节；代码注释保持英文
## 红线
- 不主动升级依赖；不删除未确认的文件
```

# 踩坑点

- **写太长**。我第一版 80 行，塞满历史偏好，每次会话白吃几千 token，还稀释了任务本身的权重。压到 30 行内。
- **信息过期**。换机器、升版本后忘了更新，Agent 一直引用不存在的路径。建议每月扫一遍，或让 Agent 在命令失败时提示你核对环境段。
- **塞敏感信息**。API key、真实全名、内部域名都别放——这份文件会被拼进 prompt 发给云端模型。
- **和 AGENTS.md 打架**。两边对提交规范描述不一致时，Agent 行为随机。定好优先级：项目级覆盖全局级，两边注明。
- **偏好写得太虚**。「代码写好一点」没有信息量，要写「函数不超过 40 行、优先标准库」。

# 可复用建议

- 把 USER.md 当**个人配置即代码**：小、结构化、可 review、可回滚。
- 全局放身份与环境，项目放工程约定，职责分清。
- Agent 每猜错你一次，就补一行对应约束——把摩擦变成增量维护。
- 团队场景做一份脱敏模板，新人 fork 后只改环境段即可上手。

# 总结

USER.md 的本质是把「重复解释自己」从每次会话中抽出来，固化成一份可维护的文本资产。成本半小时，收益是新会话的冷启动摩擦直接归零。对同时跑多套 Agent 工作流的人来说，这大概是投入产出比最高的一份 Markdown。
