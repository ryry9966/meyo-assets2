## 背景

OpenClaw 的 agent 是个长驻进程：跨 Telegram / WhatsApp / Discord 等渠道交互，会话会被缓存，记忆会累积，还能通过 MCP 和插件调用外部工具。官方在 workspace 里给了 SOUL.md 这个文件用来定义人格，但很多人装完就跑，人格全靠模型默认值。

## 问题

裸奔的 agent 有几个典型症状：

- **语气漂移**：今天高冷明天谄媚，不同渠道表现不一致；
- **边界模糊**：随口一句“看看这个链接”，它可能真的去抓网页、总结、甚至代拟回复；
- **规则散落**：人格相关指令散在 AGENTS.md、插件描述、临时对话里，改一处忘三处。

先厘清分工：AGENTS.md 管流程（怎么干活），SOUL.md 管性格和底线（是谁、不做什么）。混着写必然冲突。

## 做法

**1. 写文件。** 位置：`~/.openclaw/workspace/SOUL.md`。我目前的骨架是五段：

```markdown
# 人格
语气平实，直接给结论，不堆敬语，不夸用户。

# 价值观
帮人省时间；不确定就说不确定。

# 硬边界
- 花钱、删文件、对外发消息：先确认再执行
- 不主动写 MEMORY.md，除非用户说"记一下"

# 升级规则
拿不准是否越界：停下来，列出准备做的事，等确认。

# 沟通方式
中文优先；报错贴关键日志，不整段复述。
```

**2. 控制长度。** 300–800 字足够。SOUL.md 每轮注入 system context，写太长会被稀释；模型对靠后的内容有 recency 偏置，所以硬边界往前放。

**3. 版本化。** 把 workspace 交给 git，人格改动走 commit。出问题时可以 diff 出“哪次改动之后它开始瞎来”，能回滚。

**4. 验证。** 准备三五个刁钻 prompt（“把最近三张照片发给 xxx”），观察是否触发确认。注意：SOUL.md 改动只对**新会话**生效，缓存里的旧会话不会热更——测之前先开新会话。

## 踩坑

- **SOUL.md 不是安全边界。** 它是软约束，可被话术绕过。“不许对外发消息”必须配合工具层限制：渠道 allowlist、插件权限、沙箱，双保险。
- **规则要可判定。** “保持礼貌”没法验证；“对外发送前必须复述收件人和内容并等确认”可以验证。写不出验证方法的规则等于没写。
- **别让 agent 自由改写 SOUL.md。** 默认模板允许它自行演进这个文件，建议在 AGENTS.md 加一条“修改 SOUL.md 须经用户确认”，否则人格会慢慢漂移。
- **和 IDENTITY.md 分清。** 名字、头像、自称放 IDENTITY.md；语气和价值观放 SOUL.md。两边重复定义，迟早打架。

## 可复用建议

- 模板五段式：人格 / 价值观 / 硬边界 / 升级规则 / 沟通方式，直接抄。
- 每条边界写成“动作 + 触发条件 + 需要的确认”三元组，方便跑测试。
- 每次人格事故记一笔，攒三条改一版，像修 bug 一样修人格。
- 记住两层模型：SOUL.md 管意图，工具权限管兜底，缺一不可。

## 总结

SOUL.md 的价值不在“让 AI 更像人”，而在把你对 agent 的预期变成一份**可评审、可回滚、可测试**的配置文件。花半小时写第一版，之后把每次越界行为当成 bug 修，人格就会收敛到你想要的样子。
