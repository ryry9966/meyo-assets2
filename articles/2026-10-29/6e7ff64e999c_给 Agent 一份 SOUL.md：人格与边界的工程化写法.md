## 背景

OpenClaw 的 agent 不是"问一次答一次"的聊天机器人：它常驻网关、接了 MCP 工具、可能主动在群里发言。系统提示词是官方给的通用模板，对所有人生效。真正属于你、完全可控的人格层，就是 workspace 根目录（默认 `~/.openclaw/workspace`）下的 `SOUL.md`——会话启动时注入上下文，优先级在默认提示词之上。

## 问题

没写 SOUL.md 时，我的 agent 有三类典型毛病：

1. **语气漂移**：不同会话里一会儿简洁一会儿话痨，改语气只能靠对话里反复纠正；
2. **边界缺失**：对"删掉这个目录""直接退款"这类请求不假思索就调工具；
3. **场合感错乱**：在多人群里接所有话、抢答，像没关掉的自动回复。

这些都是提示词层的问题，靠对话里骂它没有用，得落到文件里。

## 做法

**第一步，明确分工。** `SOUL.md` 管"我是谁、我什么不做"；`AGENTS.md` 管"怎么干活"。两份文件重复的规则是最常见的翻车源，宁可互相引用也不要抄两遍。

**第二步，四段式骨架。** 我的模板大约 35 行：

- **身份与语气**：两三句加一个具体例子，例如"回复默认不超过五行，先给结论"；
- **优先级**：规则冲突时先保什么（安全 > 正确性 > 速度）；
- **硬边界**：写可判定的行为，不写形容词。"转账、删除、群发类操作必须先复述关键参数并等待明确确认"，远比"要谨慎"有效；
- **风格细则**：语言、称呼、表情符号的使用。

**第三步，生效与验证。** 改完 `/reload`（或开新会话），用固定的三到五个测试提问跑一遍——我会专门准备一条诱导性请求，测硬边界是否真的触发。

**第四步，版本管理。** workspace 整个 git 化，SOUL.md 每次改动单独提交，翻车时能 diff 回退。

## 踩坑点

- **写太长太"哲学"**："你是一颗真诚的灵魂"这类段落只会稀释指令权重，40 行以内是合理上限；
- **与 AGENTS.md 或工具描述冲突**：工具说"直接执行"、SOUL 说"先确认"，行为就随机了，出问题先查这两处；
- **禁令清单无限膨胀**：每翻车一次加一条"不许……"，三个月后没人读得完。同类问题翻车两次以上，就该升级成一条判断原则；
- **旧记忆打架**：`MEMORY.md` 里的历史偏好可能和新 SOUL 矛盾，改人格时顺手 review 一遍记忆文件；
- **多 agent 误假设**：每个 agent 有独立 workspace，主 agent 的 SOUL 不会"传染"给子 agent；
- **忘了 reload**：改完不重载，得出"没用"的结论——先排除自己。

## 可复用建议

1. 把 SOUL.md 当配置文件而非作文：小步改、可回滚、有提交记录；
2. 每条硬边界配一个测试用例，当作回归测试，每次改动都跑；
3. 每两周通读一次，删掉再没触发过的规则；
4. 边界尽量写成"先复述 + 等确认"的协议，而不是一串"禁止"。

## 总结

SOUL.md 不是给 AI 注入灵魂的玄学，它就是一份需要维护的配置：短、具体、可测试、有版本。人格负责一致性，边界负责兜底，两者都靠小步迭代磨出来。花一个下午写好这 40 行，之后每一个会话都在替你省时间。
