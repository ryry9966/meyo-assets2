# 背景

订阅了 60 多个 RSS 源，未读条目轻松破千。算法时间线是为平台优化的，RSS 是为自己优化的，但 RSS 天然缺一层“帮我读”。这个活正好是 Agent 能干的：定时拉取、筛选、摘要、汇总、推送。本文记录我用 OpenClaw 搭的一条个人信息流管线，跑了三周，每天稳定出一份日报。

# 问题

目标很朴素：

- 每天早上收到 10 条以内的摘要日报，按重要度排序；
- 每条摘要可溯源，点链接回原文；
- 全程可审计，中间产物能离线回放。

# 做法

整体分五段，每段落一个中间文件，方便排查：

1. **抓取**：cron 任务每 2 小时触发脚本，拉 OPML 里的全部源，解析出标题、链接、时间、正文，追加写入 `items.jsonl`。只有摘要的源，用 readability 再抓一遍全文。
2. **去重**：同一新闻会被多个源转载。先按链接去重，再对标题做分词 + Jaccard 相似度，超阈值合并，保留最早那条。
3. **粗筛**：关键词规则 + 发布时间过滤，把当天条目砍到 50 条以内。这步用规则不用模型，省钱且可控。
4. **摘要与打分**：粗筛结果分批（每批 10 条）交给 Agent，提示词要求输出严格 JSON：一句话摘要、分类、0–10 重要度、理由。模型只允许基于给定正文，读不到就标 `unknown`，不许编。
5. **汇总推送**：取 Top 10 渲染成 Markdown 日报，经 MCP 通道推到 Telegram，同时落一份到 workspace 的 `daily/` 目录留档。

第 4 步是唯一调模型的地方，用便宜模型跑批，日报层级再精读。Agent 侧只负责任务编排，抓取和去重是独立脚本，不把逻辑塞进提示词。

# 踩坑点

- **摘要 only 的源不少**。不补 readability 抓全文，摘要质量会明显塌，模型只能对着标题和导语发挥。
- **pubDate 时区五花八门**。不统一转 UTC 再过滤，“当天”就会多收或少收一批。
- **去重阈值别拍脑袋**。Jaccard 0.6 起步，观察一周日志再调，过低会把同主题的不同报道也合并掉。
- **提示词必须显式禁止模型用外部知识补摘要**，否则它会拿训练语料里的旧闻“脑补”，看似通顺但和原文对不上。
- **cron 静默失败最伤**。加了兜底：连续两次跑完条目数为 0，就推一条告警给自己。
- **对源保持礼貌**：抓取间隔 2 小时起，带正常 User-Agent，别把小站抓挂了。

# 可复用建议

- 管线拆成纯函数阶段，每阶段输入输出都是 JSONL，任何一天出问题都能回放定位，不用猜。
- 源列表、关键词、阈值全部进配置文件，不写死在脚本和提示词里。
- 模型分层：筛选用便宜的，只在日报环节花预算。
- 换推送渠道（TG / 邮件 / 本地文件）时只改最后一段，前四段不动。

# 总结

这条管线没有引入新框架，就是 cron + 脚本 + 一次模型调用 + MCP 推送。它解决的不是“读得更多”，而是“读得更少但更准”。下一步打算把重要度标准做成可反馈的：对日报里某条点踩，就反写进粗筛关键词。信息流自动化的难点从来不在抓取，而在筛选标准的持续校准。
