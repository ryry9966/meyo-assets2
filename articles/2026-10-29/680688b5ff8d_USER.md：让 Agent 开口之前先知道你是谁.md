## 背景

常驻型 Agent（OpenClaw 这类网关 + 多渠道入口）和一次性网页会话最大的区别，是它会在你的工作流里持续做事：早上读日程、白天改 PR、晚上替你回消息。但对模型来说，每个新会话它依然是无状态的——记忆库解决了"发生过什么"，AGENTS.md 解决了"怎么干活"，还剩一个空白：**你是谁**。

## 问题

我的真实体感：没有 USER.md 时，Agent 用一套通用语气跟我说话；排日程不知道我在 UTC+8；给方案时默认我熟 Rust 而不是 Go；最尴尬的是替我对外发消息时，署名和自称全不对。

记忆检索是概率性的——库里明明写过"主力语言是 Go"，但不保证每次被召回。而一个每次会话**必读**的静态 profile，是确定性的兜底。

## 做法

**1. 建文件。** 在工作区根目录放 `USER.md`，与 `AGENTS.md`、`MEMORY.md` 并列，并确认系统提示里有"会话开始先读 USER.md"的指令。

**2. 按"稳定信息优先"写，控制在 30–60 行：**

```markdown
# USER
## 基本信息
- 称呼：老张（对外署名 Zhang Wei）
- 时区：UTC+8，工作时间 9:00–19:00
- 中文交流，代码注释和 commit message 用英文

## 技术背景
- 主力：Go / Python，十年后端
- 别贴入门链接，直接给结论和代码

## 当前项目
- gateway：自部署网关，路径 ~/code/gateway
- 相册服务：side project，只周末碰

## 协作偏好
- 方案先给 2 个选项再动手；改文件先出 diff
- 我说"先这样"= 挂起任务，不是完成

## 红线
- 不碰 prod 分支；不主动给客户群发消息
- 涉及钱、删库类操作必须二次确认
```

**3. 让 Agent 帮你写初稿。** 直接说："对我做一次访谈，问 10 个问题，整理成 USER.md。"比自己憋快得多，它问的角度往往比你想到的全。

**4. git 管起来，多机同步**；每月或项目大变动时，让 Agent 发起一次 review："哪些条目过时了？"

## 踩坑点

- **写成自传。** 几百行的 USER.md 每次会话都吃 token，还会稀释关键信息。原则：只写"影响 Agent 决策的事实"，不写"我的经历"。
- **时态混乱。** "最近在做 X"两周就过期。USER.md 只放稳定特质，动态的事进 MEMORY.md 或项目级配置。
- **敏感信息别进。** 这个文件会被同步、可能进备份和日志。密码、密钥、证件号一律不写，用引用："密钥在 vault 的对应条目"。
- **和 AGENTS.md 打架。** 两边都写规则，行为会飘。分工：USER.md 回答"我是谁"，AGENTS.md 回答"怎么干活"，冲突时以后者为准，优先级写进系统提示。
- **当成法律条文。** 模型仍会漏读误判，USER.md 是先验不是保险箱，关键操作的确认一步都不能省。

## 可复用建议

- 把模板存成 gist，新 Agent 起步时复制改 10 分钟；
- 在 AGENTS.md 加一条："发现 USER.md 与我的实际行为矛盾时，主动指出并建议更新"，让 profile 长出自己的维护机制；
- 多身份用户可按渠道拆分 `USER.work.md` / `USER.personal.md`，在对应渠道配置里指明加载哪个。

## 总结

USER.md 的价值不在花哨，而在于把"每次会话重新认识你"变成一个确定性输入。30 行稳定的事实，胜过三个月模糊的记忆召回。今天花 15 分钟建一份，下次 Agent 叫错你的名字时，你会感谢自己。
