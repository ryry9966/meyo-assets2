# 背景

跑 OpenClaw 一段时间后，agent 的行为大致靠三层文件塑形：`AGENTS.md` 管行为规则，`TOOLS.md` 管工具说明，`MEMORY.md` 管会话记忆。但多数人漏了一层：**你是谁**。

结果就是每个新会话都要重新交代一遍“我用 Arch、主力是 Go、回复请用中文、别替我做删库级操作”。这些信息高度稳定，却一直靠聊天记录隐式恢复，靠不住。

# 三个实际问题

1. **重复自我介绍**：跨渠道更糟，Telegram 里说过的话，CLI 会话里 agent 完全不知道。
2. **偏好漂移**：agent 每次根据零散记忆猜你的口味，时对时错，而且错的时候你未必发现。
3. **职责混淆**：把用户画像塞进 `MEMORY.md`，事件流水和稳定画像搅在一起，两边检索质量都下降。

# 做法

**1. 在 workspace 根目录建 `USER.md`**，并确认它确实被加载——可以直接问 agent“你当前上下文里有我的时区吗”来验证。

**2. 分区写，每区职责单一**。一份可抄的骨架：

```markdown
# User
## 基本信息
- 时区：Asia/Shanghai
- 语言：中文交流，代码与注释用英文
## 技术画像
- 主力：Go / Python；编辑器 Neovim；OS Arch
- 风格：先给最小可用实现，再谈优化
## 协作偏好
- 默认简洁回复，除非我要求展开
- 引用资料时给出处
## 红线
- 未经确认不执行 rm -rf、force push
## 当前项目（每月清理）
- 正在做：xxx
```

**3. 控制长度**。这份文件每轮都进上下文，建议 200 行以内。写它像写配置，不像写日记。

**4. 进 git**，改动可 diff、可回滚。

**5. 让 agent 参与维护，但别放权**。每周末让它对比近期会话提议一版 diff，你人工审。整理权可以给它，写入权必须在你手里。

# 踩坑点

- **越写越长**。上下文被稀释后，agent 开始“脑补”你的偏好，比不写还糟。删比加重要。
- **敏感信息入库**。密钥、家庭地址别写——这文件既进 git，也进每轮上下文。
- **过期信息污染**。“最近在折腾 Rust”三个月后还挂着，agent 会持续按旧画像回答。过期条目要么删，要么挪进 `MEMORY.md`。
- **和 `MEMORY.md` 抢职责**。稳定事实进 `USER.md`，事件与临时状态进 `MEMORY.md`，冲突时以 `USER.md` 为准。
- **共享实例串画像**。多人共用的 workspace 里 `USER.md` 是全局的，别写真名和私人偏好。

# 可复用建议

- 三个分区起步就够：基本信息、协作偏好、红线。技术画像等真实使用留痕后补，别预先虚构。
- 设一个 review 节奏：月度看一次 diff，季度清一次“当前项目”区。
- 定期自检：问 agent“根据 USER.md，我上一次教你的是什么习惯”。答不上来，说明文件没进上下文，或者已经太长被稀释了。
- 归位判断法：三个月后还有用 → `USER.md`；只与某次会话有关 → `MEMORY.md`；对所有项目生效的行为约束 → `AGENTS.md`。

# 总结

`USER.md` 不是什么新协议，就是把“你希望 agent 默认知道的事”从聊天记录里拆出来，变成一份显式、版本化、可审计的文件。工程收益在于把隐式上下文变成显式配置：出错时可 diff，可回滚，可追责。写好它的原则和写好任何配置一样——短、分区、定期清理、变更走人工审核。
