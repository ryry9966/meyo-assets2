热搜把三个数字钉在了一起：微软单季收入 6100 亿（人民币口径），其中约 667 亿被媒体算到 OpenAI 头上，Azure 增速冲到 48%。很多人的第一反应是"微软赢麻了"，但如果只看到这层，这季财报就算白看了。这三个数字其实是一个故事——一场由算力驱动的商业循环。今天把窗户纸捅破，看看钱到底怎么流。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-29/c45d05b0ed38c04e.png)

## 三个数字不是一类东西，先拆干净

- **6100 亿是总收入**：覆盖 Windows、M365/Office、游戏、LinkedIn、广告和云。传统业务仍贡献大头，别把整季营收都记在 AI 账上。
- **667 亿是媒体测算，不是官方科目**：微软财报里从来没有单独一行叫"OpenAI 收入"。这笔钱主要是 OpenAI 消耗 Azure 算力产生的云账单，外加历史协议下的分润安排（据媒体报道）。
- **48% 是 Azure 的同比增速**：微软披露 Azure 年收入已超 750 亿美元，在这个基数上涨 48%，一年增量就是 300 多亿美元——相当于凭空多出一个中型云厂商。
- 三者关系一句话：OpenAI 的需求是"因"，Azure 增速是"果"，6100 亿是"被放大的总分"。理清这条链，后面全通。

## Azure 凭什么涨 48%：先看云是怎么收钱的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-29/e2054a5c984f2e07.png)

云的本质是"把算力当水电卖，按用量计费"，而 AI 客户把这套模式推到了极限：

1. **训练负载**：一次性、脉冲式。OpenAI 每训一代新模型，就要在 Azure 包下上万张 GPU 的集群连跑数月，像给整个小区同时开满空调。
2. **推理负载**：持续性、随用户线性增长。你每问 ChatGPT 一句话，后台都在烧 token，这笔钱最终流进微软的云收入。
3. **Commitment 承诺采购**：大客户签多年期预付承诺。公开信息显示，OpenAI 承诺未来采购 2500 亿美元的 Azure 服务。注意：这种承诺不会立刻变成收入，而是先计入 bookings 和 RPO（剩余履约义务），再随实际消耗逐季确认。所以读微软财报，RPO 的规模和转化节奏比单季收入更能说明问题——目前它的商业 RPO 已是数千亿美元量级。

## 微软和 OpenAI：房东 + 股东 + 水电公司的三合一

时间线不长，但每一步都在加杠杆：

- **2019 年**：微软投 10 亿美元，OpenAI 换来 Azure 的优先算力支持。
- **2023 年初**：投资追加到累计约 130 亿美元。
- **2025 年 10 月**：结构重组。微软持有 OpenAI 集团约 27% 股份，改用权益法（equity method）记账；OpenAI 同步扩大 Azure 采购承诺；微软获得模型 IP 的长期授权（据报道延至 2032 年）。

重组后的微软，一家公司占了三个位置：

- **房东**：数据中心和机柜租给 OpenAI；
- **水电公司**：GPU 算力按小时、按 token 计费；
- **股东**：OpenAI 估值涨，股权资产跟着涨。

于是形成闭环：微软投钱 → 买 GPU、建数据中心 → OpenAI 租算力跑训练和推理 → 微软确认云收入和股权收益 → 利润再投下一批数据中心。

打个工程师式的比方：你入股了室友的外卖创业项目，他还必须用你家厨房做饭，你按度收电费。账面两头赚——但你家电表也在疯狂空转，这句先记住，后面有用。

## 光鲜数字的另一面：Capex、折旧和电表

四个容易被热搜过滤掉的细节：

1. **资本开支爆炸**：微软单季 Capex 在 350 亿美元量级（含融资租赁），年化超 1000 亿美元。这些钱没有直接变成利润，而是压在资产负债表上，变成数据中心、GPU 和电力设施。
2. **折旧的时间差**：服务器按约 6 年折旧，但 GPU 大约两年一代。如果新芯片能效翻倍，老集群的账面价值和使用价值同时缩水——这是悬在所有云厂商头上的共同问号。
3. **亏损也在同一条管道里流**：改用权益法后，OpenAI 的亏损按持股比例传导进微软利润表，此前一个季度就有约 30 亿美元的拖累（据当时财报披露口径）。"靠 OpenAI 狂揽 667 亿"的另一面，是同一个伙伴也在亏钱。
4. **物理瓶颈**：AI 数据中心是重资产工程，单个园区动辄数百兆瓦，电力接入、变压器、液冷的交付周期以年计。钱能买到 GPU，但买不到电网排期。

## 这场军备竞赛重排了云市场

- **旧逻辑是存量迁移**：企业把自建机房搬上云，三家分蛋糕，增速 20% 就算健康。
- **AI 把逻辑改成增量扩容**：训练和推理是从前不存在的负载，蛋糕本身在变大。
- **结果是增速重排**：近几个季度 Azure 增速（40%+）明显高于 AWS（约 20%）和 Google Cloud（约 30%+，各家口径略有差异）。云市场的排名叙事，第一次被 AI 需求直接改写。
- **但别过度解读**：增速差 ≠ 份额逆转，AWS 的绝对体量仍然领先；微软是在用短期利润率换 AI 生态位，这笔账要十年后才算得清。

## 三条冷思考：怎么读财报，怎么定位自己

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-29/84b2a7c62813d4fb.png)

1. **看增速，先问基数和口径**。48% 是在 750 亿美元基数上跑出来的，含金量和"从 1 亿涨到 1.48 亿"完全不同。同时区分"官方披露"与"媒体测算"——667 亿属于后者。个人可以盯三个硬指标：RPO 规模及转化节奏、Capex / 经营现金流的比值、云收入里 AI 相关的占比。
2. **别把巨头的循环当成自己的商业模式**。微软能玩"我投你、你租我"的闭环，靠的是足够厚的资产负债表和足够长的租约。创业者和开发者必须算清 unit economics：GPU 时薪、每百万 token 成本、真实毛利率。闭环好看不代表现金流好看，后者才是生死线。
3. **技术选型给自己留活口**。算力价格正处在剧烈波动期，签任何单一云的长约之前，先算迁移成本。多云抽象、可移植的推理层、严格的成本监控——AI 时代的 vendor lock-in 不是架构洁癖，是财务风控。

6100 亿不是终点，只是这场算力长跑的补给站。真正值得记住的不是某个季度的数字，而是那个结构：当计算变成基础设施，谁能同时占住"卖水、修水厂、给水厂入股"三个位置，谁就握住了行业里最大的杠杆。数据会过季，结构不会。
