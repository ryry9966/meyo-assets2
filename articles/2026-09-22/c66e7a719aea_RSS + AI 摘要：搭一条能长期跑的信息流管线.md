## 背景

信息获取这件事，RSS 依然是覆盖面和信噪比最好的方案，但订阅一多人就刷不过来了。OpenClaw 生态里大家已经在用 Agent 做各种自动化，把"读信息"交给管线是很自然的延伸。这篇记录我搭的一条 **RSS → 清洗 → AI 摘要 → 推送** 管线，跑了两个多月，分享结构和踩坑。

## 问题

- 订阅 40+ 个源，每天原始条目 300+，人肉根本看不完
- 相当一部分源只输出截断摘要，直接丢给模型总结质量很差
- 不同源重复报道同一件事，摘要大量撞车
- 长期跑必须考虑成本和幂等，不能每条都调大模型

## 做法

整体分四层，每层独立可替换：

1. **采集层**：Miniflux 自托管统一管理订阅和轮询，利用 ETag / Last-Modified 做条件请求，个别站点用 RSSHub 补源。
2. **清洗层**：对 summary-only 的源做正文抓取 + 可读性抽取；同时做 URL 归一化和 simhash 去重。这一步全是规则代码，零成本。
3. **摘要层**：接 OpenClaw 的 Agent 节点（或独立 MCP tool），两阶段设计——先用便宜模型 + 关键词/embedding 打分筛掉约 70% 无关条目，剩下的按主题分批生成日报式摘要，强制输出结构化 JSON：标题、一句话结论、要点、原文链接、置信度。
4. **分发层**：汇总成 Markdown 日报推到 IM 和静态页；原始正文与摘要都落库，摘要只是派生视图，随时可换 prompt 重算。

## 踩坑点

- **摘要幻觉**：早期让模型自由发挥，出现"合理但原文没有"的结论。改成先抽取关键句再压缩，并强制附原文链接后基本可控。
- **正文抽取翻车**：JS 渲染站点抽出来是空的。兜底策略：抽取失败就退回 feed 自带摘要，并打上降级标记。
- **Token 成本**：全量喂模型一天烧不少，加筛选层后成本降了一个数量级。
- **提示词注入**：feed 内容是不可信输入，不要把正文拼进指令区，明确"以下仅作为数据处理"，输出侧再做长度和 schema 校验。
- **重复触发**：cron 重叠导致日报发两次，后来加状态锁 + 按时间窗口的幂等键解决。

## 可复用建议

- **先规则后模型**：URL 归一化、关键词、simhash 能解决的，不要动用模型。
- 摘要输出走 **结构化 JSON + schema 校验**，失败重试，别依赖自由文本。
- 原文落库、摘要作为可重建视图，prompt 随时迭代不心疼。
- MCP 工具按 fetch / extract / summarize 拆开，单独测试、单独缓存，别塞成一个巨型 tool。

## 总结

这条管线的核心不是"AI 替你读新闻"，而是把脏活（去重、抽取、筛选）全部放在模型之前，让模型只做它擅长的那一小段压缩。两个多月跑下来，日报稳定在 10 条以内，5 分钟扫完，漏报率可接受。建议起步先接 5–10 个源跑通全链路，验证摘要质量后再扩规模。
