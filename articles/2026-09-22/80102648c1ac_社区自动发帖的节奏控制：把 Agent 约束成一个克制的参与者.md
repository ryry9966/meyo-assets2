## 背景

在 OpenClaw-CN 里，不少人用 Agent + MCP 做自动内容：把群聊精华整理成周报、同步新 release、定时推教程。我也维护一个“每周精华”自动帖，前两周差点被管理员请去喝茶——内容没问题，是节奏太机械：每天 9:00:00 准时出现，格式永远一样，连续一周占板块第一屏。后来按“把 Agent 当成真实社区成员来约束”的思路改了一版，帖子 mute 率从约 8% 降到 1% 以下，投诉归零。

## 问题

自动发帖翻车通常不是内容问题，而是行为特征太机器：

1. **固定时间点**：整点整分触发，时间戳一眼假；
2. **匀速连发**：补历史任务一口气发 5 条，间隔精确 60 秒；
3. **格式僵化**：同一模板发 30 天，标题连标点都不变；
4. **零互动**：发了就跑，评论三天不回，像贴小广告的；
5. **重复占坑**：源数据没变化也照发。

社区反感的本质是“低信息密度 + 高出现频率”。所以解法不是伪装，而是把频率压到与信息密度匹配。

## 做法

我把节奏控制做成独立调度层（不塞在 Agent 主循环里），分四步：

**1. 队列化。** 生成完的内容先入队，调度层独立决定“什么时候发”，模型抖动不会直接变成刷屏。

**2. 目标时间 + 随机抖动。** 早间档设 8:30–9:40 区间随机取值，每次重摇随机数。避免整点，也避免固定偏移（比如永远 +17 分钟）。

**3. 全局节流 + 冷却。** 单账号最小间隔 20 小时起步，每周 2–3 帖；同板块有真人发帖后 30 分钟内主动顺延让路；补发场景加指数退避，两条间隔至少 25 分钟。

**4. 去重 + 人工闸门。** 发前做摘要相似度比对，阈值 0.85 以上直接合并进上一帖；前 20 帖强制“草稿 → 人工确认”，稳定后闸门也没关——每天十几秒成本，换来出问题能当场拦住。

## 踩坑点

- **抖动写死了随机 seed**：调试为了复现，上线忘改，等于每天同一时刻发。seed 只留在测试环境。
- **冷却只算发帖没算回复**：Agent 回评论走同一账号，六连发回复和刷帖一样显眼。现在所有写操作共享一个令牌桶。
- **让路逻辑死循环**：板块一直有人发帖就一直顺延，攒了三天没发出去。改成最多顺延 2 次，超了就接受不完美时机直接发。
- **去重阈值拍脑袋**：先设 0.75，正常周报也被合并。必须结合自己语料调。
- **时区**：调度层用 UTC，社区活跃在东八区晚间，第一次跑成凌晨 3 点发帖，比不抖动还假。

## 可复用建议

- 把时间窗、日配额、冷却、顺延上限全放调度层配置，支持热改，别硬编码。
- 定一条硬规则：**平均每帖至少带来一条真实回复或收藏，否则降频**。频率跟着价值走，不跟着任务走。
- 监控三个信号：被屏蔽次数、被管理员或用户提醒、发帖 24 小时零互动比例。任一超标，自动暂停转人工。
- 帖尾固定一句“本帖由 Agent 整理，有问题请 @我”。坦诚标注不降低接受度，反而减少举报。

## 总结

“不像机器人”的关键不是把行为伪装得更像人，而是把自动化约束成低频、高密度、可问责的参与者。队列 + 抖动 + 节流 + 闸门，加起来不到两百行代码，却决定你的 Agent 是社区助手还是噪音。先慢下来，再谈自动化。
