## 背景

OpenClaw Agent 的行为不只由模型决定。workspace 里的几个 Markdown 文件在每次会话启动时都会注入上下文：AGENTS.md 管“怎么干活”，TOOLS.md 管工具用法，USER.md 记用户偏好，而 SOUL.md 管的是“我是谁、什么能做、什么不能碰”。它是成本最低、见效最快的文件，也是最容易写废的一个。

## 问题

没有 SOUL.md 的 Agent 常见三种症状：

1. **语气漂移**：同一个 Agent 今天话痨明天高冷，替你转发消息时的措辞完全不像你本人。
2. **边界缺失**：你说“帮忙处理下消息”，它可能直接替你回了不该回的人；让它清理目录，它顺手删了不确定的东西。
3. **规则打架**：临时在对话里补的约束，过几个会话就忘，或者和 AGENTS.md 里的旧规则冲突。

## 做法

我的 SOUL.md 稳定在 30 行左右，分五段：

- **身份**：一段话说明角色定位和服务对象。写给模型看，不是 slogan。
- **语气**：不写“简洁克制”这类形容词，写可判定的样例，比如“默认回复不超过 5 句；技术结论放第一句；不用表情”。
- **优先级**：指令冲突时的裁决顺序，如“安全 > 当前指令 > 历史偏好 > 性格设定”。
- **边界**：一条规则 = 一个触发条件 + 一个动作。例如“不可逆操作（删除、发给第三方、支付）必须先复述内容并等待确认”“未明确要求时不主动联系任何人”。
- **升级**：什么情况下停下来问人，而不是自作主张。

三个原则：SOUL.md 只写“我是谁”，操作细节留给 AGENTS.md，同一规则绝不写两遍——两遍必然漂移成两个版本；每条规则都要能在具体场景里判定违反与否；文件进 git，行为变化时 diff 一下就知道改了什么。

## 踩坑点

- **写成小作文**：SOUL.md 每个会话都注入，500 行意味着每次都烧 token，且注意力被稀释，中间的规则基本失效。超过 50 行就该删。
- **人设压过任务**：见过有人写“毒舌评论员”，结果 Agent 执行运维操作时还在插科打诨，关键确认信息被淹没。人设服务于功能，别让性格抢戏。
- **边界写成情绪**：“要有分寸感”模型无法执行，换成触发器和动作才稳定生效。
- **让 Agent 自己改 SOUL.md**：它会把限制越改越松，这个文件的写权限要留在人手里。
- **改完不重开会话**：SOUL.md 在会话启动时加载，长会话里改文件不生效，验证记得开新会话。

## 可复用建议

- 把 SOUL.md 当 runbook 维护：Agent 出格，修完对话后落一行进文件，月底统一修剪一遍。
- 多人共用一个 Agent 时，边界多写“确认门”（哪些操作必须停下问人），语气少写——语气可以个性化，门禁必须统一。
- 用三个探针任务做回归测试：一个正常任务、一个诱导越权、一个规则冲突，每次改完 SOUL.md 就跑一遍。

## 总结

SOUL.md 不是性格包装，而是一份最小化的行为契约：身份一段、语气几条、边界若干，每条可判定、可验证。它解决的不是模型能力问题，而是行为一致性与权限边界——这恰恰是 Agent 从玩具走向常驻助手时最先撞上的墙。写好它，比换更强的模型便宜得多。
