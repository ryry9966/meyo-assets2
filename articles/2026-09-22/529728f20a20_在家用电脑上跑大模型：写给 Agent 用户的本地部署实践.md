## 背景

Agent / MCP 生态起来之后，本地模型的价值被重新放大了。Agent 的工具调用请求里往往带着大量敏感上下文——文件路径、配置内容、对话历史——不一定适合走云端 API；而且 Agent 是长跑型负载，token 消耗很可观。把模型放到自己机器上，隐私、成本、离线可用性三件事能一起解决。

## 问题

家用电脑跑模型，明面上的矛盾是显存，但更隐蔽的坑在别处：**Agent 场景对模型的要求和聊天完全不同**。它需要稳定的多轮工具调用能力和足够长的上下文，很多模型“能聊天”但“跑不了 Agent”，这一点模型卡上不会告诉你。

## 做法

1. **选运行时**。Ollama 上手最快，llama.cpp 可控性强，有 N 卡且追求吞吐可以上 vLLM。三者都提供 OpenAI 兼容接口，OpenClaw 侧只需把模型 provider 的 baseURL 指向 `localhost:11434`，其余配置不动。
2. **按显存选模型**（Q4_K_M 量化）：8GB 跑 7B/8B 级别入门；12–16GB 上 14B；24GB 跑 32B，这是本地稳定跑 Agent 的实用下限。
3. **显式设上下文长度**。Ollama 默认 2048/4096，超长会被静默截断，务必用 `num_ctx` 拉到 16K 以上。
4. **跑工具调用冒烟测试**：给模型挂一个时间/天气类的假工具，连跑 10 轮循环，看参数 JSON 是否稳定、会不会幻觉出不存在的工具名。
5. 有 RAG 的话，Embedding 模型也本地化（如 bge 系列），避免检索路径再出网。

## 踩坑点

- **显存只按权重估会翻车**：KV cache 随上下文线性增长，32B + 32K 上下文的实际占用远超模型卡标注，长上下文场景要按 1.3–1.5 倍预留。
- **小模型的工具调用“看着支持，实际不稳”**：多轮循环里丢字段、格式漂移很常见。选型优先看社区里真实的 Agent 反馈，而不是 benchmark 分数。
- **macOS 统一内存和独显是两套逻辑**：Mac 上 GPU 可用内存默认约为系统内存的 2/3~3/4（可调），N 卡则要给系统留余量，别照搬别人的配置。
- **`keep_alive` 默认几分钟就卸载模型**：Agent 间歇性调用会反复冷启动，一次几十秒，建议设成常驻。
- **量化不是免费的**：Q4 以下工具调用成功率明显下降。宁可选小一档模型跑 Q6，也别把大模型硬压到 Q3。

## 可复用建议

- 用 OpenAI 兼容接口做抽象层，云端/本地只切 baseURL，Agent 代码零改动，随时可回退。
- 把“10 轮工具调用冒烟测试”固化成脚本，每次换模型跑一遍，比看榜单靠谱得多。
- 先测 tok/s 再定方案：Agent 单轮 prompt 常常几千 token，经验值低于 15 tok/s 的体验基本不可用，这个数字直接决定你要不要加显存。
- 别急着买卡。先用现有设备把流程跑通，确认自己的工作负载真的吃显存，再考虑升级。

## 总结

本地部署的门槛已经从“会编译 CUDA”降到了“会装 Ollama”，但 Agent 场景的新门槛转移到了工具调用稳定性上。8GB 能入门，24GB 才算舒适；选型时把多轮工具调用测试放在跑分前面。本地模型不是云端的替代品，而是 Agent 工具箱里多出的一种部署选项——按需切换就好。
