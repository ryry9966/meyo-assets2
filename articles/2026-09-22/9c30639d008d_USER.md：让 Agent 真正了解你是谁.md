# USER.md：让 Agent 真正了解你是谁

## 背景

OpenClaw 这类长期运行的 Agent，会话天然是碎片化的：重启、换设备、清上下文之后，模型对你重新归零。项目侧我们有 AGENTS.md、SOUL.md 这些"说明书"，但很少有人认真填 workspace 里自带的 USER.md——多数人留空，或者只写一行名字。结果就是：Agent 记得住代码库的规矩，记不住你是谁。

## 问题

没有用户画像，每天都要重复交代：

- "我用 Arch，别给 apt 命令"
- "回复用中文，代码注释可以英文"
- "时区 UTC+8，深夜别安排 cron"

更麻烦的是 Agent 会自行假设：默认英文、默认 macOS、默认你愿意 sudo。假设错了，脚本和方案就要返工。这类错误和模型能力无关，纯粹是上下文缺失。

## 做法

1. 打开 `~/.openclaw/workspace/USER.md`，控制在一屏以内（60 行左右）。
2. 分五段写，全部用短句事实，不写散文：
   - **环境**：系统、Shell、时区、常用路径
   - **技术栈**：主用语言、明确不碰的东西
   - **沟通偏好**：语言、详略程度、要不要讲原理
   - **红线**：永不自动做的事（自动 push、无确认删文件）
   - **当前焦点**：最近两周在推进什么
3. 在 AGENTS.md 里写明优先级，例如："个人偏好以 USER.md 为准，仓库规范以本文件为准"。
4. 纳入 git。改习惯就手动改文件，或者直接让 Agent"把这条写进 USER.md"，然后 review 它的 diff。

## 踩坑点

- **写成自传**。段落式描述模型抓不住重点，压成短句后遵守率明显提升。
- **太长**。两三百行会稀释注意力，反而更不被遵守。超了就做减法。
- **和项目文件打架**。我的约定：代码行为归 AGENTS.md，个人偏好归 USER.md，并在两处写清覆盖关系。
- **信息过期**。上月的项目名、已下线的服务器还躺在里面，Agent 会一本正经地引用。让它每月列出"疑似过期条目"是个低成本解法。
- **放敏感信息**。密钥、真实住址不要写——USER.md 可能被插件读取、被同步、被贴进别的工具。

## 可复用建议

- 把 USER.md 当 dotfiles 养：短、事实、版本化、定期修剪。
- 三层记忆各司其职：USER.md 管"我是谁"，AGENTS.md 管"这个仓库怎么干活"，MEMORY.md 管"发生过什么"。别互相塞。
- 让 Agent 更新画像时输出 diff，而不是全文重写，防止它顺手"润色"掉你的原话。

## 总结

USER.md 是性价比最高的定制手段之一：十分钟写完，不依赖插件、MCP 或额外记忆机制，只是把"你应该了解我"从每次对话挪进一个文件。Agent 记不住你，但文件记得住——而且文件是你可以审计的。
