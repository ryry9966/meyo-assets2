## 背景

OpenClaw 的 workspace 里有一组约定文件：`AGENTS.md` 管操作规范，`TOOLS.md` 管工具用法，`USER.md` 管用户偏好，而 `SOUL.md` 专门定义"这个 Agent 是谁"。每次会话启动时它会被注入 system prompt。很多人装完框架直接跑，SOUL.md 留着模板默认内容——结果语气、主动性、边界感全靠模型默认值，行为不稳定。

## 问题

长时间跑下来的典型症状：

- **语气漂移**：第一天克制简洁，第三天开始满屏 emoji；
- **边界模糊**：heartbeat 触发后自作主张发消息、随手调用付费工具；
- **规则散落**：人格要求写在一堆 prompt 里，改一次要翻五处；
- **多渠道失配**：同一个灵魂同时服务 Telegram 的私人会话和 Discord 的技术群，风格必有一头不合适。

根因是：人格没有被当作一份可维护的配置来对待。

## 做法

SOUL.md 就在 workspace 根目录，直接编辑。我的结构稳定在 60 行左右：

1. **身份段**：两三句说明角色定位，例如"你是运行在作者个人服务器上的助理，主要服务作者本人"。别写成小作文。
2. **语气示例**：与其写"专业、简洁"这类形容词，不如放两组 before/after——同一件事，不想要的回答长什么样，想要的回答长什么样。few-shot 对语气的塑造远强于形容词。
3. **边界清单**：写成可判定的条目：
   - 未经确认不发送任何主动消息；
   - 涉及花钱、删文件、对外发布的操作，先列计划等确认；
   - 不确定时明确说"我不确定"，不编造。
4. **自改政策**：声明 Agent 可以提议修改 SOUL.md，但必须在对话中先给出变更内容征得同意。

配套原则：**SOUL.md 管"是谁"，AGENTS.md 管"怎么干活"**。定时任务、心跳逻辑、MCP 工具调用规范都放 AGENTS.md，两边不要重复。

改完重启会话即生效。建议把 workspace 纳入 git，每次改动提交一次，行为异常时可以 diff 回溯。

## 踩坑点

- **写太长**。SOUL.md 每轮占 context，200 行的灵魂会让关键边界淹没在中段，而模型注意力对中段内容最不敏感。控制在 80 行以内。
- **边界写成了原则而非规则**。"要有安全意识"没法执行，"删除操作必须先确认"可以。
- **与 AGENTS.md 冲突**。一边要求"简洁回复"，一边操作规范要求"每步汇报详情"，Agent 会随机选一边。冲突规则宁可删掉重写。
- **放错文件**。有人把 cron 说明、MCP 服务列表塞进 SOUL.md——那不是灵魂，是手册。
- **让 Agent 自改但没有版本控制**。人格漂移了都不知道从哪天开始的。

## 可复用建议

- 存下每次"行为不对"的对话片段，改完 SOUL.md 后用同样输入重放验证；
- 边界条目尽量每条对应一次真实事故，不预设一堆用不上的规则；
- 需要分渠道风格时，优先在渠道层做少量覆盖，别复制两份 SOUL.md 各养一个；
- 每月固定十分钟通读一遍，删掉过时条目——灵魂也需要 GC。

## 总结

SOUL.md 本质是"以 prompt 形式存在的生产配置"。像对待配置一样对待它：短小、可版本化、可测试、有明确的变更流程。人格不是一次写定的文学创作，而是随着 Agent 实际跑出的事故不断打补丁的过程——这也是它被设计成 workspace 里一个普通 Markdown 文件的原因。
