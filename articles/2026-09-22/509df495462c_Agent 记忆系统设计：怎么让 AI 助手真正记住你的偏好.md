## 背景

用过一段时间 OpenClaw 的 Agent 之后，最常见的抱怨不是“不够聪明”，而是“不记事”。每次会话都要重新交代一遍：用 pnpm 不用 npm、commit message 用中文、别主动加 emoji、部署走 staging 先跑一遍。这些不是推理能力问题，是记忆系统的问题。

目前社区里常见的做法有两类：一类是把所有历史塞进 context，靠长窗口硬扛；另一类是每次让 Agent 自己“总结一下之前的偏好”存进一个 markdown 文件。前者贵且检索噪音大，后者写多了就变成一锅粥。这篇帖子分享我基于 MCP 插件搭的一套分层记忆方案，思路简单，重点是工程细节。

## 问题拆解

把“记住偏好”拆开，其实是三个不同的问题：

1. **提取**：从对话流里判断“这句话是不是一个持久偏好”。用户说“这次用 pnpm”和“以后都用 pnpm”完全是两回事。
2. **存储**：偏好之间会冲突和演化，需要更新而不是无限追加。
3. **检索**：新会话开始时，把相关的偏好按相关性注入 context，而不是全量灌入。

## 做法与步骤

我把记忆分成三层，各自用一个 MCP tool 暴露给 Agent：

- **会话层**：当前任务的状态、中间结论。直接放 scratch 文件，会话结束即弃。
- **情景层**：项目级的决策记录，比如“这个仓库用 pnpm”。带 scope 标签，检索时按项目路径过滤。
- **画像层**：跨项目的用户偏好，比如“回复用中文”“不要 emoji”。量很小，每次会话全量注入，不需要语义检索。

写入策略是关键。我不让 Agent 自由发挥，而是在 system prompt 里规定：只有当用户表达**明确的、面向未来的约束**时才调用 `memory.write`，且写入前先 `memory.search` 查重。查到旧条目就更新（覆盖 + 保留时间戳），不新增。每条记忆都带 `confidence` 字段，低置信度的写入需要用户确认——实现上就是 Agent 回复里附一句“我记下了：……，有误请纠正”。

检索时用 embedding 做粗排 + 关键词过滤做精排，阈值设得偏保守（余弦相似度 0.7 以上才注入），宁可漏几条，也不要塞一堆似是而非的内容污染 context。

## 踩坑点

- **过度记忆**：早期我把“用户今天提到下雨了”也存了，一周后画像层全是垃圾。后来加了白名单类别（语言、工具链、代码风格、沟通偏好），其他一律不存。
- **记忆腐蚀**：Agent 每轮都复读并重写同一条偏好，embedding 会慢慢漂移。解决办法是写入去重必须命中，禁止“顺手更新”。
- **scope 泄漏**：项目 A 的“用 pnpm”被检索进了项目 B 的会话。scope 过滤必须在检索层做，不能指望模型自己分辨。
- **删除很痛**：用户说“忘掉之前那条”，语义检索经常找不到。我给每条记忆生成一个短 ID，注入 context 时带上，删除时直接按 ID 操作。

## 可复用建议

- 先做画像层，收益最大、成本最低，一个 JSON 文件就够。
- 写入规则宁可苛刻，检索宁可保守。记忆系统的口碑毁于“记错”，而不是“记少”。
- 一定要给用户一个可见的入口查看和清理记忆，这既是信任问题，也是调试利器。
- 记忆条目设计成结构化的（key / value / scope / confidence / updated_at），别存纯文本段落。

## 总结

记忆系统不是让 Agent“更聪明”，而是让它在正确的时间拿到正确的上下文。分层存储 + 严格的写入门槛 + 保守的检索策略，这套组合在我自己的日常使用里已经能稳定“记住”偏好了。方案里没有黑科技，全是约束设计。欢迎大家在自己的 Agent 上试一下，也期待社区里出现更成熟的遗忘和冲突解决策略。
