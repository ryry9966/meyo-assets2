## 背景

OpenClaw 的 agent 跑在 workspace 里，会话重启后对话记忆基本归零，真正跨会话存活的是几个 Markdown 文件：AGENTS.md、SOUL.md、MEMORY.md，以及今天的主角 TOOLS.md。它的定位很明确：agent 写给自己的环境笔记——这台机器上工具怎么装、命令怎么敲、路径在哪。每次会话启动时，它会被注入上下文。

所以先纠正一个常见误解：**TOOLS.md 不是给运行时解析的配置文件，而是给模型看的 runbook。** 理解这一点才能用对它。

## 问题

放任不管，通常演变成三种局面：

1. **每次重新猜。** agent 换个会话就忘了本机用 `uv` 不用 pip、ffmpeg 在 /opt/homebrew/bin 而非 /usr/bin，然后试错、报错、烧 token。
2. **多机互相污染。** macOS 笔记本、Ubuntu VPS、实验室机器各有各的包管理器和路径，一份笔记混着写，agent 在 A 机照 B 机的笔记干活。
3. **知识散落。** 有的在 .zshrc 注释里，有的在某次对话里，谁也不敢删，谁也找不到。

## 做法

**1. 划边界。** 只写"这台机器上把活干成需要知道的事实"：命令绝对路径、版本管理器行为、本地服务端口、已验证的调用方式。不写密钥，不写通用知识（那是 AGENTS.md 和 skills 的事），不写愿望。

**2. 给模板，按域分节，每条带验证时间：**

```markdown
# Tools Notes — macbook-work

## 运行时
- node 走 nvm，非登录 shell 不会自动加载，先 `source ~/.nvm/nvm.sh`
- Python 一律 `uv run`，本机没有全局 pip

## 路径
- ffmpeg: /opt/homebrew/bin/ffmpeg
- 本地 Postgres 在 5433 端口，凭据在密码管理器，不入本文件

## 已验证
- `bash ~/scripts/transcode.sh <dir>`（2025-06-12 验证通过）
```

**3. 建立"验证后写入"纪律。** 让 agent 踩坑后自己更新，但要求明确：先跑通一遍确认可行，再把最终写法追加进 TOOLS.md 并标注日期。没验证过的猜测不许入册。

**4. 多机方案：hosts/ 目录加软链。** 把笔记按机器拆成 hosts/macbook.md、hosts/vps.md，全部进 git；本机的 TOOLS.md 做成指向对应文件的软链并 gitignore。换机器只改一次软链，笔记永不串台。

**5. 定期修剪。** 每两周让 agent 自己过一遍："逐条检查失效或冗余的条目，删除并汇报。"过期条目比空白更危险——agent 会盲信笔记。

## 踩坑点

- **写入了 token 和密码。** 这个文件是明文、会进模型上下文、会被同步。任何凭据只写"去哪里拿"，不写值。
- **越写越长。** 每一行都是常驻 context 的成本，几百行的 TOOLS.md 只会让 agent 在旧信息里打转。我的预算是 80 行以内。
- **把它当配置改。** 改了 TOOLS.md 就期待运行时行为变化，不会的。行为开关在 agent 配置和 skills 里，这里只是笔记。
- **条目无日期。** 没有验证时间的条目无法判断可信度，修剪时也没法下手。

## 可复用建议

- 把 TOOLS.md 当 runbook 运营：有边界、有模板、有写入仪式、有修剪周期，四件事缺一不可。
- 长度预算化：超限就强制合并同类项，宁可删，不可堆。
- 迁移到新机器的第一件事：跑通基础命令链，验证一条写一条，别靠回忆批量粘贴。

## 总结

TOOLS.md 的价值在于把"环境经验"从易失的会话记忆外置成一个可版本化、可审计的文件。克制地写、验证后写、按机器隔离、定期修剪——做到这四点，agent 换会话、换机器，都不用再重新猜你的环境。
