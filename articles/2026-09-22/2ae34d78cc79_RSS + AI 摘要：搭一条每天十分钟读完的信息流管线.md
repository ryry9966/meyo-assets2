## 背景

信息源多了以后，纯靠人肉刷 RSS 已经不现实。我目前订阅了 60 多个源（技术博客、GitHub Release、几个期刊的 TOC），每天全读大概要两小时。目标很简单：让 agent 定时抓取当天的条目，去重、按相关性摘要，最后推给我一份五分钟能读完的日报。

## 问题

直接"把 RSS 喂给 LLM 总结"有几个明显的坑：

- 条目数不可控，一个活跃源一天 50 条很正常，token 成本和上下文长度都吃不消
- 重复内容多，同一件事经常有三四个源同时报道
- 摘要模型容易幻觉出不存在的链接或结论
- 状态管理：哪些条目处理过了，重启后不能重复推

## 做法

管线分四段，抓取和摘要严格分离：

1. **抓取层**：Miniflux 自托管，统一管订阅和已读状态；全文抓不到的源用 RSSHub 补，个别站写脚本取正文兜底。agent 不直接碰原始 feed，只走 Miniflux API。
2. **调度**：OpenClaw 的定时任务，每天早上 7 点触发一次。用系统 cron 加 webhook 触发 agent 也一样。
3. **摘要层**：agent 通过 MCP 工具拉过去 24 小时的未读条目，先做规则粗筛（关键词、来源权重），通过粗筛的才进 LLM。摘要要求结构化输出：标题、一句话摘要、原文链接、相关度评分。链接只允许从输入逐字符复制，禁止生成。
4. **分发与状态**：结果拼成一条 Markdown 推到 IM 频道；已处理条目的 id hash 落在本地 sqlite，每次跑之前先 diff。

关键设计：**粗筛放规则里，不放进 prompt**。规则先行能把进模型的条目砍掉 60–70%，成本直接降一个量级。

## 踩坑点

- **去重要在摘要前做**。早期只按 URL 去重，结果同一条新闻三个源各推了一段几乎一样的摘要。后来加了标题相似度去重。
- **幻觉链接**。没加约束时模型会自己"补"原文链接。现在输出后用正则校验：不在输入 url 集合里的链接，整条丢弃。
- **feed 时区混乱**。有的 pubDate 是 UTC，有的干脆乱填。切 24 小时窗口时用本地时间对齐，宁多勿漏。
- **cron 重叠**。上一次没跑完下一次又触发，加了文件锁解决。
- **输出格式漂移**。同一 prompt 跑一周后格式会松散，改成 JSON schema 校验，不合格重试一次。

## 可复用建议

- 抓取、筛选、摘要、分发四段解耦，每段单独可跑、可重放，别把所有逻辑塞进一个 prompt。
- 状态用最简单的 sqlite 或 json 文件，别上数据库服务。
- 给每个源记一个"命中率"——摘要后我实际点开的比例。连续两周低命中的源降权或退订，信息源本身也要做垃圾回收。
- 成本控制靠规则粗筛和小模型分层，别一上来就全量进大模型。

## 总结

这条管线跑了一个多月，每日推送稳定在 15 条以内，阅读时间从两小时降到十分钟左右。没有黑科技，核心就四句话：抓取归抓取，判断归模型，状态落本地，链接只复制不生成。下一步想把命中率反馈接回去做自动调权，但目前手动降订阅已经够用，先不过度设计。
