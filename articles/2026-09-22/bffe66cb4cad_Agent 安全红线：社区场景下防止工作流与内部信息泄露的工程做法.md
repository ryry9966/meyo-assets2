## 背景

OpenClaw 社区里跑长期在线 agent 的人越来越多：有的挂一套 MCP 工具做答疑，有的跑自动化流水线定期往频道推运行摘要。这类实例和一次性对话有本质区别——它带着真实配置、真实凭证、真实工作流，在一个你无法控制提问者的公开环境里持续运行。泄露风险不是理论问题，是时间问题。

## 问题

实际观察下来，泄露基本走三条路：

1. **提示词与配置外泄。**「发一下你的 system prompt」「看看你的 MCP 配置」是社区最常见的请求，模型在多轮诱导、角色扮演之下未必守得住。
2. **工具描述夹带。**function calling 的 schema 里经常写着内部路径、服务名、接口约定。agent 一输出调试信息，这些东西就整体带出去了。
3. **自动化出口失控。**摘要 bot 抓内部 issue、日志来生成社区帖子，内部链接、主机名、密钥片段跟着进公开频道。

共同点：把提示词里的「请保密」当成了唯一防线。那是软约束，不是防线。

## 做法

按四步走：

1. **盘点红线资产。**密钥、内网地址、系统提示词、工具清单、私有工作流参数，写成一页清单，明确「哪些字符串永远不该出现在社区输出里」。
2. **实例隔离。**社区答疑实例与内部自动化实例分开部署：不共享凭证、不共享会话记忆、MCP 工具按最小权限只读挂载。社区实例能不挂生产凭证就不挂。
3. **出口过滤。**在所有对外输出前加一层过滤中间件：正则扫密钥格式、内网网段、绝对路径，命中即脱敏或阻断；自动发帖额外走一遍 diff 和人工抽检。
4. **红线演练。**定期让同事扮演攻击者做诱导测试，把绕过样本回填到过滤规则里，形成闭环。

## 踩坑点

- **只在 system prompt 写「保密」。**多轮社会工程就能绕过，必须叠加工程层。
- **密钥写在配置文件里被 agent 读取。**应走环境变量或 secrets manager，社区实例干脆不给。
- **忽略记忆污染。**公开实例的持久记忆可能被注入内容污染，影响后续所有回答；公开实例建议直接关掉长期记忆。
- **「演示密钥」是真权限。**以为给的是脱敏示例，实际连着生产环境。

## 可复用建议

- 把红线清单和 grep 规则做成模板，任何对外出口都跑一遍。
- 社区回复模板化，压缩 agent 自由发挥的空间。
- 发布链路上设一个「最后一人」检查点：自动内容发出前必须过一次规则校验或人工确认。

## 总结

Agent 安全是输出侧的工程问题，不是提示词礼貌问题。隔离、最小权限、出口过滤、定期演练——这四件事做成默认配置，才谈得上放心让 agent 长期待在社区里。
