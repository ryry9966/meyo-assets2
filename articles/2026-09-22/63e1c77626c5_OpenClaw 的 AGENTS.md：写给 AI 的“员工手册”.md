## 背景：Agent 也有“第一天上班”的问题

OpenClaw 装好后，workspace（默认 `~/.openclaw/workspace`）里会生成一组模板文件：SOUL.md 管人格，USER.md 存用户档案，MEMORY.md 和 `memory/*.md` 是长期记忆，HEARTBEAT.md 描述心跳任务。文件都在，但每个新会话里的模型并不知道这套布局的“使用规则”——哪份文件该读、笔记往哪写、哪些事不许做。

AGENTS.md 就是解决这个问题的：它在会话启动时被注入上下文，相当于贴在工位上的《新员工手册》。它不负责性格（那是 SOUL.md 的事），也不负责记忆（那是 MEMORY.md 的事），只负责流程和约定。

## 问题：约定只存在于聊天记录里

之前我的 agent 有几个反复出现的问题：

- 我在聊天里说过“日记写到 memory 目录”，但换个会话它又开始往 MEMORY.md 里追加大段流水账；
- 心跳任务全靠临时口头交代，重启后忘了一半；
- 换设备同步 workspace 后行为不一致，因为它“记得”的东西有一半躺在旧机器的聊天记录里。

本质原因：约定没有被落盘到每次会话必读的位置。聊天记录不是配置。

## 做法：把 AGENTS.md 当 onboarding 文档写

步骤不复杂，重点在内容取舍：

1. 打开 workspace 下的 AGENTS.md，先通读默认模板，能留的留；
2. 按“工作空间地图 → 常规流程 → 工具约定 → 安全边界”四段组织。节选示例：

```markdown
# Workspace 手册
## 地图
- SOUL.md：人格，别往里写流程
- USER.md：用户档案，只更新事实
- memory/YYYY-MM-DD.md：每日笔记；MEMORY.md 只放索引和长期结论
## 流程
- 我说"记一下"：写入当日 memory 文件，一句一行
- 心跳：按 HEARTBEAT.md 检查，无事不打扰
## 边界
- 不主动给联系人发消息；不删除 memory 目录
```

3. 控制篇幅：这份文件每个会话都会进上下文，几十行足够。目标不是“全”，而是“新会话第一秒必须知道的事”；
4. 验证：新开会话，问它“我怎么让你记笔记”，看它能否复述你写的流程。答不上来说明写法有问题——多半是指令埋在长段落里。

## 踩坑点

- **写太长**。超过一两百行后关键指令被稀释，模型开始“选择性遵守”。一次性信息一律砍掉。
- **职责越界**。人格写进 AGENTS.md、流程写进 SOUL.md，两份文件打架时行为随机。分层要干净。
- **写了做不到的要求**。“永远记住我们所有对话”这类指令没有落盘机制支撑就是空话。要求 agent 做事，先确认对应的文件和流程存在。
- **改完不验证**。已运行的会话不会自动重读，至少新开一个会话确认生效。

## 可复用的建议

- 判断标准：这句话是不是“任何新会话第一天都需要”？不是，就移到 MEMORY.md 或待办里；
- 指令写成动作，不写成态度：“每日笔记一句一行”优于“要认真记录”；
- 把 workspace 纳入 git，AGENTS.md 每次修改都有 diff，出问题可回滚；
- 关键内容靠前：安全边界和文件职责放最上面，长尾偏好放后面。

## 总结

AGENTS.md 的价值不在于“配置了什么”，而在于把散落在聊天里的默契，固化成一份机器每次必读的说明书。写得克制、可执行、定期维护，agent 的行为就会从“看心情”变成“按手册”。它大概是你所有 AI 配置里性价比最高的一个文件。
