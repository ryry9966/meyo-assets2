# 从零搭建 AI 社区发帖机器人：四层架构与五个踩坑实录

## 背景

社区每周的「技术精选」一直靠人肉整理：翻 RSS、挑文章、写摘要、排版、发帖，一轮下来两三个小时。人一忙就断更，断更两次之后我决定把它自动化——用 OpenClaw 搭一个发帖机器人，目标是「人只做最后一道审核，其余全自动」。

先收敛范围：只做摘要类帖子，不做互动回复；每周发布一次；**必须有草稿审核环节，不允许模型直接发布**。

## 整体设计

拆成四层，层与层之间用本地 SQLite 落库，不直连：

1. **采集层**：通过 MCP tool 拉 RSS 源和 GitHub Trending，字段清洗后入库；
2. **生成层**：OpenClaw agent 读库里未处理条目，按 prompt 模板生成 Markdown 草稿；
3. **校验层**：规则脚本过一遍——链接可达性（HEAD 请求）、长度、敏感词、与历史帖子的标题相似度；
4. **发布层**：调用社区发帖 API，带分类和标签，写入发帖记录。

调度用 cron，周三早上跑采集 + 生成，我中午审核，通过后触发发布。别急着全自动，先让闭环跑通。

## 踩坑实录

**1. 模型编造链接。** 第一版草稿里三分之一的外链是模型「脑补」的：域名对、路径错。解法：prompt 里明确「只能使用输入材料中出现的 URL」，校验层再加 HEAD 请求，404 直接打回重生成。

**2. 重试导致重复发帖。** 发布接口超时后脚本重试，同一篇帖发了两次。解法：发帖前按标题 hash 查重，发布请求做幂等，本地记录 post_id。

**3. cron 时区坑。** 服务器是 UTC，定好的「周三早八」实际下午才发。所有调度显式指定 `TZ=Asia/Shanghai`，别信系统默认值。

**4. 素材超 token。** 十几篇文章全文塞给模型直接爆上下文。改成 map-reduce：每篇先单独摘要，再合并成周报，质量和成本都可控。

**5. Markdown 渲染差异。** 社区编辑器对 GFM 支持不全，表格和任务列表全乱。最终模板只敢用标题、列表、引用、代码块这几种最稳的语法。

## 可复用建议

- **生成和发布必须分离**，中间落库，永远先出草稿——这不仅是安全设计，也让任何一步失败后可重跑；
- 外部输入进 prompt 前先清洗、截断，模型只做它擅长的归纳，不做事实溯源；
- 每一步幂等：采集可重跑、生成可覆盖、发布有查重；
- 告警接到 IM，别等周末才发现 bot 挂了三天；
- 先灰度：前两周只发测试版块，确认渲染和风控没问题再切正式区。

## 总结

这套东西技术上没有难点，难点全在边界条件：幻觉链接、重复发布、时区、渲染差异。自动化把「每周两小时的体力活」换成了「每天五分钟的看护活」，这笔账是划算的。但审核环节我暂时不打算去掉——内容质量是社区的底线，bot 负责省时间，人负责签字。

代码整理后打算开源，采集器和校验脚本通用性还行，可以拆出来给别的场景复用。有同行做法欢迎跟帖交流。
