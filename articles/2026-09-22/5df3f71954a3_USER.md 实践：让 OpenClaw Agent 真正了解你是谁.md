## 背景

OpenClaw 的 Agent 每次会话启动时会读取 workspace 下的上下文文件（`AGENTS.md`、`SOUL.md`、`USER.md` 等）。其中 `USER.md` 的定位很纯粹：描述"用户是谁"。但不少部署里这个文件是空的，或者只有一行名字——Agent 对你的全部认知，只剩每次对话里的临时输入。

## 问题

实际使用中最常见的三类摩擦：

1. **重复自我介绍**。换设备、重开会话后，"我的主栈是 Go""服务部署在内网"这类信息要反复说。
2. **语气与粒度错配**。Agent 不知道你是资深工程师还是新手，回复要么啰嗦要么过于省略。
3. **跨会话信息断裂**。上周说的偏好这周就丢，因为 `MEMORY.md` 塞满了任务流水，稳定的用户画像反而没地方放。

## 做法

1. 在 workspace 根目录建 `USER.md`（默认路径 `~/.openclaw/workspace/USER.md`）。
2. **用事实条目，不写散文**。参考骨架：
   - 身份与角色：职业、当前主职方向
   - 技术栈：语言、框架、部署环境
   - 偏好：回复语言、详略程度、要方案还是直接给结论
   - 硬约束：明确不希望 Agent 做的事
   - 进行中的项目：一行一条，带日期
3. **控制篇幅：50 行以内**。这是每次会话都要进 system prompt 的内容，不是简历。
4. **让 Agent 参与维护**：在 `AGENTS.md` 里加一条规则——"对话中出现关于用户的稳定事实（偏好、环境变更、新项目）时，征得确认后追加到 `USER.md`，格式为 `- 2025-06-11: ...`"。
5. **用 git 管理 workspace**。Agent 每次改写后 `git diff` 一眼，防止幻觉条目混入。

## 踩坑点

- **写太多**。300 行的 `USER.md` 会稀释真正重要的约束，模型注意力不是无限的。
- **信息过期**。"我在用 Vue2"三年没更新，Agent 会一直按旧栈给方案。条目带日期，定期修剪。
- **职责混淆**：`USER.md` 放"关于你的稳定事实"，`MEMORY.md` 放"发生过什么"，`SOUL.md` 管"Agent 的性格"。混着写迟早互相打架。
- **敏感信息**。密钥、证件号、住址别写进去——workspace 可能被同步、被插件读取。
- **多用户共用一份**。家庭/团队部署应按人拆文件，并在 `AGENTS.md` 写清路由规则。

## 可复用建议

- 模板三段式：**稳定事实 / 硬约束 / 滚动项目区**（项目区只保留最近 5 条）。
- 每月一次"画像修剪"：删过期条目、合并重复项。
- 坚持"事实 + 日期 + 来源"格式，能追溯是哪次对话写入的。
- 如果接了 MCP，可以把 `USER.md` 的读写封装成一个轻量 memory server，比让模型直接改文件更可控、可审计。

## 总结

`USER.md` 的价值不在文件本身，而在于把"了解用户"从一次性对话行为，变成持续维护的结构化资产。50 行以内、条目带日期、定期修剪、git 可回溯——做到这四点，Agent 回复的贴合度会有肉眼可见的提升。建议今天就动手：先写下三条你最不想再重复说的偏好。
