## 背景

Agent 要真正落地干活，绕不开“读网页”这件事：查文档、追变更日志、盯竞品页面、抓内部知识库。在 OpenClaw 生态里，无论是 MCP 的 fetch / headless browser 类 server，还是浏览器插件形态的工具，都让 Agent 具备了直接采集网页的能力。但“能抓”和“抓得好、抓得安全”之间，差着一整套工程约定。这篇帖把我们团队踩过的坑和沉淀下来的管道整理出来，供直接复用。

## 问题

实际跑起来，常见四类翻车：

1. **上下文爆炸**：一个长页面整页 HTML 灌进对话，几轮就把 token 吃光，任务还没开始就断了粮。
2. **内容污染**：网页正文里藏着“忽略之前的指令”之类的注入文本，Agent 照单全收，行为失控。
3. **采集脆弱**：JS 渲染页面用裸 fetch 只拿到空壳；站点一改版，选择器全线失效。
4. **合规风险**：无视 robots.txt、高频率轰炸，轻则被封 IP，重则触碰站点条款。

## 做法

我们把采集拆成一条五步管道，在工具层统一封装，Agent 只调用、不自己造轮子：

1. **白名单先行**。可访问域名收敛到配置文件，按项目维护；默认拒绝，而不是默认放行。
2. **两段式抓取**。先 fetch 原始页面，再过 readability 类提取器转 Markdown，只留正文、标题、元信息；script、iframe、注释一律剥掉。
3. **当成不可信输入**。网页内容只进“资料区”，绝不拼进 system prompt；让 Agent 引用摘要或结构化字段，并强制标注来源 URL 和抓取时间。
4. **限速与缓存**。同一 URL 结果按站点 TTL 缓存，请求间隔 1–2 秒，统一 UA 并标明用途。重复任务第二次跑，实测约八成命中缓存。
5. **失败可观测**。对抓取结果做最小校验（正文长度、编码、链接补全），异常写日志并降级为“明确告知用户失败”，而不是让 Agent 拿着半截内容硬编。

## 踩坑点

- 裸 fetch 遇到 SPA 拿到的是壳；该上 headless 浏览器的场景别省，但只在白名单站点启用，成本和风险都高。
- 截断要“按结构截”，不是傻切前 5000 字——优先保标题、表格、代码块，截断处显式标注省略。
- 相对链接忘了补全 base URL，Agent 给出的引用全点不开，用户观感直接崩。
- 有些站点对无 Cookie 请求返回登录墙或软 404，要做内容判空，别把导航栏当成正文喂给模型。
- 缓存键别只按 URL，要带上查询参数和 UA 差异，否则调试时一直读到旧值，排查半天发现是缓存。

## 可复用建议

把采集约束沉淀成 checklist，挂在工具封装里，每次新增采集目标过一遍：

- 域名是否在白名单？robots.txt 是否允许？
- 是否有现成 API / RSS 可以替代爬取？（有就别爬）
- 提取后的正文是否经过结构化截断与来源标注？
- 失败路径是否定义了降级行为？
- 该目标的频率上限与缓存 TTL 是否显式配置？

## 总结

Web scraping 对 Agent 而言不是“能不能”的问题，而是“以什么约定去做”。白名单、清洗、不可信输入隔离、限速缓存、可观测降级——五件事单看都不复杂，但缺任何一件，采集就会从能力变成事故源。建议在工具层统一封装这些约定，而不是让每个 Agent 各抓各的；约定收敛在代码里，比写在提示词里可靠得多。
