2025 年 7 月，OpenAI 在没有提前造势的情况下上线了 ChatGPT Agent 模式：它不再只是回答问题，而是接管一个虚拟浏览器，自己点链接、填表单、跑脚本、整理文件，最后把成品交给你。热搜说它“突袭 Chrome”，翻译成技术语言就是：当 AI 能替用户走完“搜索 → 比价 → 下单 → 产出文档”的全流程，浏览器和搜索引擎作为“人机入口”的地位就开始松动了。这篇拆解它的原理、商业含义，以及宣传页上不会写的坑。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/d06ff30e26a8376d.png)

## 从“会聊天”到“会干活”：这次升级到底动了什么

- **合体拳**：Agent 模式本质上是把今年早些时候的两样东西捏在一起，能操控电脑的 Operator（2025 年 1 月）和能查资料写报告的 Deep Research（2025 年 2 月）。此前它们是两个独立产品，现在合成了一个连续工作的“数字员工”。
- **能力清单**：浏览网页、点击滚动、填表下单、写代码并运行终端命令，还能通过 connector 挂上 Gmail、GitHub 等账户数据，最终输出 slides、DOCX、表格等成品文件。
- **典型任务**：官方演示里，给它一句“计划一份四人份的日式早餐”，它会自己查食谱、列采购清单、把食材加进购物车，顺手生成预算与步骤文档；竞品分析、做 PPT 这类多步任务也直接包办。
- **节奏与定价**：Pro（200 美元/月）用户首发，随后向 Plus 和 Team 开放。单个任务跑十几分钟很常见，长任务半小时起步，还有额外加算力的 Max 模式，agent 模式的算力消耗比普通对话高好几个量级，这是定价分层的直接原因。

一句话总结：过去是你提问它回答，现在是你给目标，它自己拆任务、选工具、试错、重试。

## 「双手」的原理：眼睛、大脑和手的闭环

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/ade0be80ae83763a.png)

- **虚拟浏览器**：Agent 的“工作台”是跑在 OpenAI 沙箱里的 Chromium 浏览器，与你本地电脑隔离，所有操作在云端虚拟机里完成。
- **感知是双通道**：模型一边“看”屏幕截图（视觉理解），一边解析页面的 DOM 和文本（结构化数据）。纯视觉容易翻车的场景，比如找餐厅、查位置，它会直接调用地图类结构化接口，比“用眼睛找图标”稳得多。
- **行动是原子操作**：模型输出的不是“帮我把菜买了”，而是一次次具体的点击坐标、键盘输入、滚动动作，逐条执行。
- **循环才是灵魂**：目标拆解 → 执行动作 → 截图观察 → 与目标比对 → 修正策略，类似 ReAct 式的感知-行动环。中途弹出验证码？它会先尝试，不行再回头请你接管。
- **训练方式**：底层 CUA（Computer-Using Agent）模型先在模拟环境里用强化学习练“看图点击”，再泛化到真实网页——所以面对没见过的网站，它也能直接动手。

换句话说：以前是你开着浏览器，现在是浏览器里坐着个不打瞌睡的实习生。

## 为什么说它“突袭 Chrome”：入口权力的转移

- **Chrome 份额六成以上**，Google 的基本盘是“搜索结果页 + 广告位”。而 agent 不看广告：它自己挑结果、自己比价、直接在页面里完成交易。
- **搜索漏斗被压缩**：原来的链路是“查询 → 结果页 → 广告曝光 → 点击 → 转化”，每一步都有变现点；现在变成“目标 → agent 直接交付”，中间的曝光环节整段消失。
- **各家都在抢同一个位置**：Anthropic 的 computer use（2024 年 10 月）、Google 的 Project Mariner、Perplexity 的 Comet 浏览器，方向一致——谁替用户“点那一下鼠标”，谁就握住流量的起点。
- **网站的反制已经开始**：Cloudflare 等基础设施厂商在 2025 年 7 月前后推出了面向 agent 流量的验证与管控方案，网站可以放行、验证，也可以直接拦截。
- **商业本质**：入口之争从“用户看哪里”变成了“用户的 agent 有权访问哪里”。这是过去十年从 PC 到手机再到浏览器之后的又一次入口迁移。

## 现实很骨感：慢、贵、不可靠与安全债

- **慢**：一个任务十几分钟起步，人手直接做可能更快。它赢的是“不需要你盯着”，不是“比你快”。
- **贵**：高算力消耗正是 Pro 先行、Max 模式收费的原因，短期内普通用户高频使用并不现实。
- **不可靠**：网页改版、弹窗、验证码都可能让任务中途翻车；复杂多步任务的成功率仍明显低于人，失败后如何优雅收场是产品要补的课。
- **安全是最重的债**：prompt injection（提示注入）绕不开，网页里藏一句恶意指令，agent 可能“照做”。OpenAI 在系统卡里也承认这是全新且长期的攻防难题。
- **已有的缓解机制**：发邮件、下单等关键操作会暂停并请求人工确认；金融类站点默认只读；登录、输密码这类步骤强制由用户接管。

工程师视角说句实话：这是“demo 很惊艳、prod 要拉满兜底”的典型场景。

## 三条冷思考与实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/69418fbfafe91fdb.png)

1. **把它当实习生，别当自动驾驶**：下达目标时写清约束，预算上限、信息来源、哪些事不许做；支付、发送、删除这类关键操作永远保留人工确认。
2. **结果必须验收**：自动生成的数据、链接、结论都可能一本正经地出错，重要交付物自己过一遍，尤其是数字和引用来源。
3. **从业者换个角度想**：你的网站和产品对 agent 是否友好？结构化数据清晰、流程可被程序化完成的服务，可能先吃到“agent 分发”的红利；而靠信息差和广告曝光生存的环节，会被最先压缩。

入口一直在换主人：从 PC 到手机，从搜索框到推荐流，现在轮到 agent。ChatGPT 长出双手这件事，短看是产品更新，长看是一场流量与交易起点之争的开场，值得每个做互联网的人盯着它的下一版更新。
