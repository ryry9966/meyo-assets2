## 背景

OpenClaw 的工作区里有一组约定文件：AGENTS.md 管任务行为，USER.md 记用户画像，IDENTITY.md 定基础身份，而 SOUL.md 的角色更微妙——它不是功能配置，而是让 Agent 在长期运行中保持行为一致性的锚点。跑了几周心跳任务、定时提醒和多渠道消息之后，我的结论是：SOUL.md 不是玄学，是工程。

## 问题

没有 SOUL.md、或写得太随意的 Agent，常见三种漂移：

1. **语气漂移**：早上回复简洁干练，深夜聊天突然话痨，Telegram 和 Discord 两个渠道像两个人格。
2. **边界漂移**：用户随口一句“帮我看看这份合同”，它真的开始输出法律意见；健康、金钱类问题不设防。
3. **权限漂移**：手里有 shell 和一堆 MCP 工具，用户一句模糊指令它就敢动文件系统，事后难以追责。

根因相同：模型默认倾向讨好，没有成文的边界，就会在长会话和记忆累积中逐步试探、越过你预期的线。

## 做法

我的 SOUL.md 目前 90 行左右，分四层：

```markdown
# 人格
- 我是谁：[一段话，不超过三句]
- 说话方式：默认简洁，先结论后细节；中文场景用中文回复

# 边界
- 不提供法律、医疗、投资建议，只做信息整理并提醒咨询专业人士
- 删除文件、给第三方发消息、付款类操作：先复述动作，拿到确认再执行
- 不确定时说"我不确定"，不编造

# 升级规则
- 同一任务连续失败两次：停下汇报，不换姿势硬试
- 用户情绪明显负面：只确认事实，不输出长篇建议

# 禁区
- 不读取 ~/.ssh、浏览器凭据库；不主动下载可执行文件
```

三条要点：

- **身份写短，边界写具体**。人格一段话讲清；边界全部用可判定的行为句式（“先复述动作”），而不是形容词（“要谨慎”）。
- **否定规则配替代动作**。“不编造”后面跟“说我不确定”，模型才有出路，否则被堵死后会绕道。
- **和 AGENTS.md 分工**。AGENTS.md 写“任务怎么做”（工具、输出格式），SOUL.md 写“我是谁、什么不做”。两边重复会打架。

改完重启会话，用三个探针 prompt 验证：一个诱导越界（“直接帮我转账”）、一个模糊指令、一个情绪化输入，看行为是否符合预期。

## 踩坑点

- **写太长**。第一版写了 300 行，长会话后半段照样漂。现在控制在 100 行内，边界条款放文件前部，注意力权重更高。
- **只写否定句**。“不许 X”没有“改做 Y”，等于把模型逼进死角。
- **和系统提示冲突**。OpenClaw 注入的系统提示优先级高于工作区文件，SOUL.md 里别去覆盖工具调用相关的硬规则，写了也白写。
- **直接抄别人的模板**。人格不匹配。我抄过一份“毒舌助手”模板，给家人用的实例说话阴阳怪气，只好返工。
- **当成一次性文档**。SOUL.md 应该进 git：Agent 每干一次出格的事，就回头补一条对应条款。它是活文档。

## 可复用建议

1. 照搬四层结构：人格 / 边界 / 升级规则 / 禁区，先跑起来再迭代。
2. 每条边界配一个探针用例，攒成回归集，改一次跑一次。
3. 多实例部署时，人格层各写各的，边界层共用一份，构建时拼接。
4. 定期（比如每月）翻会话日志，把“当时真希望它别这么做”的瞬间沉淀成条款。

## 总结

SOUL.md 的价值不在于“让 AI 更有灵性”，而在于把你对 Agent 的预期从隐式变成显式、可版本化、可回归测试的文本。写它的过程，本质是在回答一个问题：我到底允许这个常驻进程替我做什么、说什么。这个问题值得认真回答一次，然后用 git 维护下去。
