2021 年出生、2023 年被官方下线 API 的 Codex，在 2025 年上演了一出标准的"王者归来"。据 36kr 等媒体报道，接手 Codex 不到一年的负责人 Tibo，把这个曾经的边缘项目做成了 OpenAI 增长最猛的产品线，甚至被形容为"吞掉了 ChatGPT"——它消耗的算力、贡献的收入增速，开始在内部压过那位消费级顶流。翻盘从来不是玄学，这篇文章把它的技术逻辑、商业逻辑和团队打法逐一拆开。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/56b04b03f33325e7.png)

## 一、Codex 的"两世为人"：从补全模型到编码智能体

- **第一世（2021–2023）：一个模型。** Codex 是 GPT-3 的代码特化版本，真正的高光时刻是给初代 GitHub Copilot 当底层引擎。但它的产品形态是"自动补全"——你写上半句，它猜下半句。2023 年 3 月，OpenAI 以使用率不足为由下线了 Codex API，第一世草草收场。
- **第二世（2025 至今）：一个智能体。** 名字没换，物种换了。4 月，开源的 Codex CLI 先把"终端里的编码智能体"铺开（终端老炮儿的胜利）；5 月，云端 Codex 上线：你派给它一个任务，它在隔离沙箱里读仓库、改代码、跑测试、提交 PR，还能并行开好几个任务同时干活。底层 codex-1 从 o3 定制而来，用真实软件工程任务做强化学习，在 SWE-bench Verified（题目全是真实 GitHub issue 的"工程期末考"）上把修复率做到 70% 以上，后续的 GPT-5-Codex 继续抬升。
- 一句话总结：**第一世是打字员，第二世是外包工程师。** 交付物从"下一个词的猜测"变成"一个可合并的 diff"，后面所有故事的分水岭都在这里。

## 二、"吞掉"是什么口径：算力、收入、战略重心

- **算力口径**：一次聊天问答输出几千 token；一个 agent 任务动辄数十万甚至上百万 token——读代码、试错、重跑测试，全是消耗。agent 干一小时活的推理开销，可能顶得上普通用户几年的聊天量。当用户规模上来后，Codex 吃掉内部推理资源的大头并不奇怪。
- **收入口径**：开发者是付费意愿最高的人群之一，而且 Codex 走 usage-based 计费——模型越强、任务越多、账单越大，收入曲线和算力消耗曲线是同一条。固定月费的消费级订阅，没有这种"能力越强收入越高"的弹性。
- **战略口径**：ChatGPT 拥有数亿周活的超大入口，但它是"回答问题"的形态；Codex 验证了"交付工作"的智能体平台走得通，随后 ChatGPT 自己也开始长出 agent 能力。与其说被吞掉，不如说被改造。
- 务实提醒：不同报道里的"吞掉"各有统计口径——算力、收入、使用时长，三者结论可能完全不同。读的时候先问一句：这数据量的到底是哪个？

## 三、为什么"智能体 × 编程"先跑通：机制拆解

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/44fca5e3cc058557.png)

- **可验证性**：代码任务成没成，跑一遍测试就知道，奖励信号清晰，强化学习才有抓手。对比"帮我把文案改得更有感染力"——没有 unittest，模型只能靠人类偏好硬拟合。
- **环境封闭**：代码世界的输入输出全是数字，沙箱随便造：跑挂了重来，成本是电费，不是事故。现实世界 agent（操作电脑、订机票）推进慢，很大程度就卡在环境不可靠、试错代价高。
- **数据飞轮**：全球开源仓库是史上最大的工程师行为数据集，RL 拿真实 issue 和 PR 当训练场；用户越多 → 轨迹越多 → 模型越强 → 任务成功率越高 → 用户更多，一个能自转的飞轮。
- **Token 经济学**：agent 的价值主张是"为完成的事付费"，而完成一件事天然要烧海量 token。举个具体例子：给 Codex 一个 issue"重构登录模块并修复超时 bug"，它的循环是——clone 仓库 → 定位相关文件 → 提出改动 → 跑测试 → 失败 → 读日志再改 → 通过 → 生成 diff 等你审查。几十轮循环下来，每一次都是模型调用，token 消耗自然上天。这等于把"模型能力"直接换算成"算力账单"，Codex 是第一个把这条等式跑通的产品化样本。

## 四、翻盘方法论：团队做对了哪几件事

- **小队快跑，指标干净**：据公开报道，Codex 起步时是个小团队，北极星指标非常朴素——任务成功率、PR 合并率。指标越干净，迭代越快。
- **公开试错，不憋大招**：research preview 直接丢给开发者，定价从"塞进订阅"快速切到按量计费，边跑边改。翻盘项目最怕内部打磨两年再"惊艳亮相"。
- **吃自己的狗粮**：OpenAI 自家工程师就是 Codex 的重度用户，反馈回路短到以小时计，痛点当天变需求。
- **敢于自我吞噬**：当 agent 用法开始分流 ChatGPT 的使用场景时，团队选择顺势加码而不是护旧。iPod 不革自己的命，就会被 iPhone 革命——这个道理在 AI 产品里同样成立。

## 五、给开发者和产品人的三条建议 + 一点冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/99170486576cd58c.png)

1. **开发者：把角色从"写代码"迁向"定义任务 + 审查 diff"。** 学会把需求翻译成清晰的验收标准——测试用例、边界条件、性能约束；把 agent 的产出当作一个勤快但需要 code review 的初级同事，信任但要验证。
2. **产品人：盯住"可验证任务 + 按量计费"这对组合拳。** 这是 Codex 翻盘的核心配方，大概率会被复制到数据分析、设计、运维等垂直场景。先问自己：我的领域里有没有"unittest 等价物"来定义"做完了"？
3. **冷思考：别把增长曲线线性外推。** agent 生意的毛利被算力成本死死压着，任务成功率每提升一个百分点，商业模型才更稳一分。"吞掉 ChatGPT"是媒体的修辞；工程上的真相是——这条赛道刚开局，谁先把成功率与成本两条曲线掰过来，谁才有下一章。
