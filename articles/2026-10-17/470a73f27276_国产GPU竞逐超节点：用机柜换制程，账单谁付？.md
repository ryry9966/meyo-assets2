过去两年，国产GPU发布会比拼的是单卡算力与显存容量；2025年起，比较对象变成了一整排机柜。华为CloudMatrix 384把384颗昇腾910C拧成一个逻辑计算域，英伟达GB200 NVL72把72颗Blackwell装进一个机架，国内寒武纪、海光、摩尔线程、壁仞、燧原等厂商也纷纷跟进“超节点”叙事。技术上是漂亮仗，但商业上有个朴素的问题：这套又贵、又吃电、又考验运维的系统，最终账单寄给谁？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/8aecfc8121a4c1c0.png)

## 一、超节点是什么：把一排机柜当成一块GPU用

先给定义：超节点（SuperPod）指用高带宽、低延迟的专用互联，把几十到几百颗GPU连同交换、供电、冷却封装成一个“逻辑计算域”，对外呈现为一台算力巨大的单机。

- **scale-up vs scale-out**：传统集群是 scale-out，节点间走 IB/以太网 RDMA，带宽有限、延迟高；超节点做的是 scale-up，把“单机8卡”的互联域直接扩大到64卡、128卡乃至384卡，域内通信带宽接近显存带宽。
- **量级感受**：英伟达 NVLink 5 单卡双向带宽 1.8TB/s，NVL72 整个域的总互联带宽约 130TB/s；华为 CM384 用灵衢（UnifiedBus）互联 384 颗芯片。据 SemiAnalysis 测算，CM384 总 BF16 算力约为 NVL72 的 1.7 倍、HBM 总容量约 3.6 倍，代价是整机功耗约 3.9 倍（约 559kW 对约 145kW），一个 Pod 还要用掉数千个 400G 光模块。
- **为什么需要这么大的域**：训练侧的张量/流水线并行，推理侧 MoE 的大 EP（专家并行）与 PD 分离（prefill/decode 拆开部署），都对域内通信极度敏感。域越大，通信墙出现得越晚，MFU（算力利用率）越好看。

一句话总结：单芯片撞上物理墙后，把问题抛给系统与电气工程——用互联、光模块、液冷和电力，换回一块“更大的虚拟显卡”。

## 二、国产GPU为什么集体押注：制程受限下的系统级补偿

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/4b0d234cda09a999.png)

逻辑其实很直白，四条线：

1. **单卡有差距，就摊到系统里补**。先进制程受限意味着单卡峰值算力、HBM 容量与带宽落后一线产品一代以上。单点突破难，就用“数量+互联”做积分补偿，在通信跟得上的前提下，384 颗效率打折的芯片，聚合算力可以超过 72 颗顶级芯片。
2. **推理需求接得住**。推理模型（long CoT）把单次请求的 token 产出量放大了一个量级，MoE 大 EP 推理天然需要大互联域。超节点不只是参数好看，它对应真实增长的负载形态。
3. **商业模式升级**。从卖芯片到卖机柜、卖集群、卖方案。单卡拼不动时，整机柜交付反而是国产厂商能拉开差异的地方——供电、液冷、互联、调度软件，全是系统工程活儿，也是毛利结构更健康的部分。
4. **标准卡位**。华为把灵衢互联开放出来，国内信通院等也在推动开放的超节点互联标准；海外对应动作是 UALink 联盟与超以太网。谁的标准被更多厂商采用，谁就握住下一层生态入口。

代价同样清楚：故障域从 8 卡变成 384 卡，一颗芯片、一根光模块、一条液冷支路出问题，影响面完全不同。工程师会瘦，电费单会胖。

## 三、账单有多重：TCO 里没有一项是省油的灯

- **硬件**：光模块是隐形吞金兽。互联域越大，光模块数量近乎非线性增长，这部分成本常被“每卡单价”掩盖。
- **电力与机房**：500kW 级单 Pod 意味着供电密度、液冷改造、甚至新机房选址都要重做。放到“东数西算”枢纽能拿低电价，但网络与运维半径变大。
- **利用率是命门**：多项第三方调研显示，相当比例新建智算中心利用率不足三成，算力租金近两年持续下探。超节点单位成本更高，利用率上不去，折旧每天都在烧。
- **软件迁移**：CUDA 生态迁移成本高，国产软件栈的算子覆盖、框架适配、调优人力都是隐性支出，精明的客户一定算进 TCO。

所以真实比价公式从来不是“卡多少钱”，而是**每百万 token 成本 + 供给稳定性**。

## 四、谁来买单：四类买家的真实算盘

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-17/4132f4d2d7f3e2a8.png)

1. **头部云厂商**：自用推理+对外 MaaS。要的是每 token 成本可控、供应确定性高，算得过账就买，但一定压价、要定制。
2. **运营商与国资智算中心**：国产化示范属性强，对价格敏感度相对低，对合规、安全与国产化比例要求高，这是当前国产超节点最先落地的场景。
3. **大模型公司**：以租代买为主，只认单位 token 成本和互联域规格，议价能力最强，事实上充当价格锚。
4. **行业客户（金融、制造等）**：数据不出域、买服务不买机器，最终通过 MaaS 或行业云间接买单。

冷判断：短期订单靠“国产化+示范项目”撑起；中长期能否复购，取决于真实业务负载率。名字叫超节点没用，客户的报表只认 token 成本。

## 五、冷思考：三条实用建议

1. **给买方**：把“每百万 token 成本、承诺利用率、故障恢复 SLA”写进合同与验收，别为互联域参数付超出业务的溢价；先用小域 POC 跑真实负载，再谈扩容。
2. **给厂商**：故障域变大后，运维与 SLA 本身就是产品的一部分；软件栈“好迁移、好调试”决定复购率，发布会参数只决定首轮竞标。
3. **给从业者**：盯三个硬指标，单位功耗算力（perf/W）、互联标准开放性（开放生态 vs 私有绑定）、真实负载率。少看峰值数字，多看客户第二年还买不买。

超节点这步棋，技术上没毛病，商业上刚开考。卷机柜的时代，能收上账的，是把电费、利用率和运维都算明白的人。
