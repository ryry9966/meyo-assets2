## 背景

OpenClaw 的每次会话默认是冷启动：Agent 不知道你是谁、用什么技术栈、偏好怎样的回复。它的解法是 workspace 里的一组约定文件——`AGENTS.md` 管行为规范，`SOUL.md` 管人格底色，而 `USER.md` 专门承载"用户是谁"。这个文件会在会话启动时注入上下文，相当于每次对话前，Agent 先读一遍你的档案。

## 问题

没有 USER.md 时，常见三类损耗：

1. **重复提问**。换个会话就要重新解释一遍"我用 Arch + fish，别给我 bash 语法"。
2. **风格错位**。你要简短结论，它给你八百字教程；你用中文提问，它回一堆英文术语。
3. **上下文漂移**。多项目并行时，它分不清哪个是主业哪个是副业，建议经常打偏。

这些不是模型能力问题，是输入缺失问题。

## 做法

文件位置在运行 gateway 的机器上：`~/.openclaw/workspace/USER.md`。建议按这个骨架写：

```markdown
# 关于我
- 时区 / 作息：
- 设备与系统：

# 技术环境
- 常用语言、编辑器、shell、部署方式

# 沟通偏好
- 简洁优先，直接给结论；中文回复，术语保留英文

# 常驻上下文
- 正在维护的项目，各一句话说明（不要展开）

# 红线
- 不要动的东西、不要自动执行的操作
```

三条原则：**写事实不写感想**；**控制在 100 行以内**——它是每次会话的固定 token 开销；**用 git 管理**，改动有据可查。

## 踩坑点

- **别放密钥**。USER.md 会进入每次会话上下文并发给模型服务商，token、内网地址、客户名一律不写。
- **别写长文**。内容太长后，中间部分容易被注意力稀释，等于没写。先做减法，再谈加法。
- **别和 AGENTS.md 抢职责**。"回复用中文"放这里没问题，"改代码前必须跑测试"属于行为规范，放 AGENTS.md。
- **别存会话性内容**。今天的 todo 归 MEMORY.md，USER.md 只放"半年内大概率不变"的稳定事实。
- **忘了更新**。过期信息比没有信息更糟，建议头部加一行"最后更新日期"，按季度 review。

## 可复用建议

- **让 Agent 参与维护**：跑一段时间后，让它对比自己的记忆和 USER.md，输出 diff 提案，你人工审。比从零写快得多，还能暴露你自己都没意识到的习惯。
- **多人共享 gateway 时注意作用域**：USER.md 是全局的，涉及个人的敏感偏好应下沉到独立 workspace。
- **和 MEMORY.md 分层**：USER.md 存稳定画像，MEMORY.md 存动态笔记，边界清晰才不会互相污染。
- **每条信息自问一句**："这条变了，Agent 的行为会更好还是更差？"没区别就删。

## 总结

USER.md 是成本最低、收益最直接的 Agent 调优手段：不写代码、不装插件，一个 Markdown 文件就把"每次重新自我介绍"的开销消掉。核心纪律是短、准、新。建议先花二十分钟写个一页版，跑一周，再根据实际觉得别扭的地方迭代——档案是养出来的，不是设计出来的。
