## 背景

用 OpenClaw 这段时间，我改动最频繁的文件不是配置，而是 workspace（默认 `~/.openclaw/workspace`，以你的配置为准）里的 `AGENTS.md`。OpenClaw 的 agent 行为很大程度由 workspace 里的几个 markdown 文件决定：`SOUL.md` 管人设，`MEMORY.md` 管长期记忆，而 `AGENTS.md` 管最核心的一层——每次对话都会被注入 system prompt，告诉 agent 在这个工作区里该怎么干活。初始化时 bootstrap 会生成一份模板，但那只是占位，让它真正有用的是你补写的内容。

## 问题

不做定制，agent 就是"通用"的：不知道你的目录布局、不知道默认用中文回复、不知道哪些路径不能碰、出错时该自己排查还是先来问。典型症状：

- 在工作区乱建文件，命名风格每轮不一样；
- `scripts/` 里明明有现成脚本，还是手敲一遍命令；
- 同一个错犯好几轮——会话一结束就忘，没人把教训固化成规则；
- 执行破坏性操作前不确认。

这不是模型能力问题，是入职没发文档。

## 做法

我的 `AGENTS.md` 固定五段，总量控制在 100 行内：

1. **工作区地图**：一段话讲清分工——`MEMORY.md` 存长期事实，`memory/` 按日期记流水，`scripts/` 只放我授权过的脚本。agent 才知道东西在哪、该往哪写。
2. **环境事实**：操作系统、关键路径、运行时版本、用哪个包管理器。这类信息查一次很贵，写下来很便宜。
3. **沟通约定**：默认中文；先结论后过程；长任务分段汇报。
4. **安全边界**：禁触目录列表；`rm`、`git push --force`、对外发消息必须先确认；涉及钱的操作一律停下问人。
5. **错误处理**：工具调用失败重试一次，仍失败就带完整报错来找我，禁止静默降级。

改完开个新会话跑一轮，确认注入生效，然后进入"犯错即回写"循环：agent 每犯一个新错，就转成一条规则补进文件，而不是在聊天里再说一遍。

## 踩坑点

- **写太长**。它每轮都占 prompt 预算，几百行只会稀释关键指令；重要规则放开头和结尾，中段最容易被忽略。
- **写太虚**。"要细心""要谨慎"没有可验证动作，基本无效。改成"删除文件前必须复述目标路径并等待确认"。
- **和 SOUL.md 打架**。两处写了矛盾的语气要求，表现就会飘。一个文件只管一件事。
- **当记忆用**。流水账、临时状态塞进来是错的，那是 `MEMORY.md` 的事；这里只放稳定规则。
- **放密钥**。文件内容会进 prompt，等于发给了模型服务商，token、密码一律走环境变量。
- **忽略分层**。agent 进某个 git 仓库干活时，仓库自带的 `AGENTS.md` 也会生效（就近优先）。workspace 这份管全局默认，两处别写互相矛盾的规则。

## 可复用建议

- 心法一句：按"给新同事的 onboarding 文档"来写，而不是按配置文件来调。
- 规则统一用"当 X 时，做 Y"的句式，可执行、可验收。
- workspace 直接 `git init`，每次修改有 diff 可回溯，行为退化能定位到具体改动。
- 单独维护一个"已知错误"小节，这是复利最高的部分：坑只踩一次。

## 总结

`AGENTS.md` 是 OpenClaw 里成本最低、杠杆最高的配置面：不写代码，只写清"我希望你如何在这个工作区工作"。它不会一次写好，价值来自把每次踩坑回写成规则。文档越养越准，agent 才越用越省心。
