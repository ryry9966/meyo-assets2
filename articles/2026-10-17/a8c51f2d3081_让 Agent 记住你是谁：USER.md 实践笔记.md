## 背景

OpenClaw 的 agent 每次会话都会把 workspace 下的几个固定文件注入系统提示：AGENTS.md 管行为规范，SOUL.md 管人格，TOOLS.md 管工具说明。其中最容易被忽略的是 USER.md——专门描述"用户是谁"。

很多人的 agent 打磨了很久，但每次开新会话它仍是陌生人：不知道你的主力语言、不知道服务器部署在哪、不知道你想先看结论还是先看过程。结果就是它反复问重复的问题，给出的建议永远偏通用。

## 问题：稳定信息和动态记忆混在一起

我们习惯用 memory 记东西，但它适合动态事实："这周在迁移数据库""上次说部署脚本有 bug"。而"我是后端工程师，主要写 Go，时区 UTC+8，用中文回复"这类信息几乎不变。把它们也塞进 memory，检索时制造噪音；每次靠对话重新解释，浪费 token 还容易遗漏。

USER.md 就是给"稳定档案"的固定位置：每次会话无条件加载，不依赖检索。

## 做法

1. 在 workspace 根目录建 USER.md（通常是 `~/.openclaw/workspace/USER.md`），新会话即生效。
2. 按四段写，控制在 40 行以内：

```markdown
# 用户档案
## 基本信息
- 称呼：老周
- 时区：UTC+8，工作日 10:00–19:00 在线
- 语言：中文回复，术语可保留英文

## 技术背景
- 主力：Go / Linux 运维，前端能改但不熟
- 环境：Debian 12 自建服务器两台，Docker 部署

## 偏好
- 先给结论再给过程，不需要客套
- 给命令时直接给可复制的完整命令

## 红线
- 不要动 nginx 配置，改动需先说明
- 永远不要在回复里复述任何密钥
```

3. 验证：开新会话问它"你怎么称呼我？我的主力语言是什么"，答对说明加载成功。
4. 在 AGENTS.md 里加一条授权：允许 agent 发现稳定事实时**提议**更新 USER.md，由你审核后写入，而不是自动追加。

## 踩坑点

- **写太长**。它每次会话都占上下文，超过一两百行会稀释真正重要的指令。经验值是 30–50 行封顶。
- **放易变内容**。项目进度、本周任务写进去两周就腐烂，这些归 memory。
- **放行为指令**。"回答要简洁"属于 AGENTS.md。每个文件单一职责，后期才好维护。
- **放敏感信息**。密码、API key、住址一律不写——这份文件会完整进入每次会话上下文，别给它泄密的机会。
- **只增不删**。让 agent 自动维护时容易越写越长，要求它"替换过时条目而非追加"，每月人工过一遍。

## 可复用建议

- 结构固定为四段：基本信息 / 技术背景 / 偏好 / 红线，换其他 agent 生态也通用。
- 用 git 管 workspace，agent 改了 USER.md 能看到 diff。
- 多人共用一个 bot 要小心：USER.md 按 workspace 加载，最好每人独立 workspace，否则档案互相污染。
- 把三个文件当三层配置理解：USER.md 是"你是谁"，SOUL.md 是"它是谁"，AGENTS.md 是"它该怎么做"。

## 总结

USER.md 是性价比最高的 agent 配置之一：十五分钟写完，立刻消除每次会话的自我介绍成本。原则一句话——稳定身份进 USER.md，动态事实进 memory，行为规则进 AGENTS.md，三者别混。写完只是开始，把它当配置代码定期迭代，agent 对你的了解才会持续对齐。
