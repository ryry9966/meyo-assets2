# OpenClaw 的 session 隔离：子 Agent 怎么不污染主会话

## 背景

OpenClaw 的主会话是长期存活的：system prompt、历史消息、工具调用记录全部堆在同一个上下文窗口里。日常问答没问题，但一旦让主 agent 亲自去跑"过程很脏"的任务——爬十几个页面、跑测试、分析长日志——工具输出会把窗口撑满，早期真正重要的上下文（用户偏好、项目约定）被挤掉或被压缩得面目全非。子 agent 机制就是为这个场景准备的：过程在独立 session 里发生，主会话只拿回结论。

## 问题：污染长什么样

实际踩下来，"污染"主要有三种表现：

1. **上下文膨胀**：一次浏览器抓取塞进几万 token，之后主会话开始"失忆"，答非所问。
2. **状态泄漏**：子任务探索中的临时结论（"这个接口好像挂了"）被主会话当成长期事实记住，后续决策被带偏。
3. **并发写冲突**：多个子 agent 同时往全局 memory 或同一个文件写，后写的覆盖先写的，而且静默失败，不报错。

## 做法

我们的团队约定是四条，核心思路一句话：**过程留子会话，结论回主会话**。

1. **派生而非就地做**。凡是预期产生大量工具输出的任务（网页抓取、日志分析、批量重构），主会话不直接调工具，而是用 `sessions_spawn` 派子 agent，task 里写清：输入是什么、期望返回什么格式、"只返回结论，不要过程日志"。
2. **给子 agent 划独立工作目录**。spawn 时显式指定 cwd，文件副作用全部收敛到隔离目录，主会话工作区保持干净。
3. **显式指定模型和超时**。子 agent 默认继承主配置，跑批时成本容易失控；长任务不设 timeout 会一直挂着占 gateway 资源。
4. **主会话只消费摘要**。子 agent 返回后，主会话用自己的话把结论复述一遍再入库，不复述中间过程，避免二次膨胀。

补充一点：如果只是想要"一次干净的上下文"而不需要并行，直接 `/new` 重开会话更简单，不必为了隔离而隔离。

## 踩坑点

- **task 描述太模糊**：子 agent 返回一大段探索日志，主会话一塞又爆了。返回格式必须写进 task。
- **嵌套 spawn**：子 agent 里再 spawn，层级一深，超时和 token 成本翻倍，排障也痛苦。我们限制最多一层。
- **子 agent 直接写全局 memory**：并发覆盖是静默失败的，等发现记忆丢了已经晚了。改成主会话统一写入，或每个子 agent 写独立文件再合并。
- **孤儿 session**：子 agent 超时被放弃后，session 文件还躺在磁盘上。定期用 `sessions.list` 巡检清理。

## 可复用建议

把派生子 agent 当成一次**函数调用**来设计：输入明确、输出有契约、副作用收敛到指定目录。再把这条规则写进 agent 的系统提示（SOUL / AGENTS.md）：什么任务该 spawn、什么任务就地做，让 agent 自己形成稳定的分流习惯。其中"大输出工具默认走子 agent"是性价比最高的一条，建议先从最痛的场景——浏览器抓取或日志分析——开始试点。

## 总结

session 隔离不是什么高级特性，本质是上下文管理：把脏活的过程性输出关在子会话里，主会话只沉淀结论和决策。四条约定（spawn 派生、独立 cwd、显式模型与超时、只回摘要）实施成本很低，但对长会话稳定性的改善非常明显。如果你也在跑长期 agent，欢迎在评论区交流你们的分流规则。
