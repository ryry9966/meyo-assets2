最近又一条热搜：梁文锋署名，DeepSeek 又发新论文。评论区分成两拨，一拨在讨论"创始人为什么亲自署名"，另一拨在问"这次到底做了什么"。其实这两件事是一体两面：DeepSeek 把真金白银押在哪条技术路线上，以及他们公开交出的技术答案。这篇文章把两层都拆开看——署名背后的组织信号，和论文核心的稀疏注意力（Sparse Attention）。它可能是这两年长上下文成本曲线陡然下坠的最大功臣。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-25/8e8029d7d52f79d0.png)

## 一、创始人署名，为什么能上热搜？

- **学术圈的惯例**：技术论文的作者列表通常是研究员，公司创始人出现在名单里，业内一直少见。所以每一次出现，都会被当成新闻解读。
- **DeepSeek 不是第一次**：2025 年 1 月的 R1 论文（后来还登上了 Nature 封面）、2 月的 NSA（Native Sparse Attention）论文、9 月的 V3.2-Exp 技术报告，作者列表里都有他。
- **合理的解读是组织信号**：说明这条技术路线被当成战略级投入，创始人深度参与方向判断，而不是挂名站台。
- **也别过度神化**：大型模型工作是几十人团队作战，署名位置不等于每行代码出自谁手。真正的看点不是"他写没写代码"，而是**公司把最强的人往哪里押**。

## 二、论文要解决的老大难：注意力太贵

- Transformer 的 self-attention 有个数学上的"平方诅咒"：n 个 token 要两两计算相关度，复杂度 O(n²)。上下文翻倍，计算量近似翻四倍——GPU 的电费大半烧在这个平方上。
- 推理时还有 KV cache：每个历史 token 都要在显存里留一份"笔记"，上下文越长，显存占用越高，解码速度被内存带宽卡死。
- 打个比方：让 AI 读一份十万字合同，dense attention 意味着它每写一个字都要"逐字复读"全部历史；而人类是跳读、抓重点、必要时回翻。
- 稀疏注意力的出发点就一句话：**绝大多数 token 之间其实没关系，为什么要全算？**

## 三、怎么"省"：从 NSA 到 DSA 的三板斧

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-25/6215fb1fc5b42b29.png)

1. **Top-k 精选**：V3.2-Exp 中的 DeepSeek Sparse Attention（DSA），每生成一个 token，只在全部历史里挑约 2048 个最相关的参与计算，其余直接跳过——从"全文复读"变成"精准跳读"。
2. **Lightning indexer（闪电索引器）**：先训练一个轻量索引器给 query 和历史 token 打相关分，粗筛出 top-k 子集，再做昂贵的精确注意力。相当于"先查目录，再翻那一页"。
3. **Natively trainable（原生可训练）**：稀疏不是上线后打的补丁，而是训练第一天就按稀疏方式学。索引器通过蒸馏对齐稠密注意力的相关度分布，让模型天生适应"跳读"这种阅读姿势。
4. **硬件对齐（hardware-aligned）**：按 tensor core 友好的分块组织计算，算法与 kernel 联合设计。从 V3 的 FP8、DualPipe，到 V2 的 MLA 压缩 KV cache，这是 DeepSeek 论文一以贯之的母题。

- **成绩单（官方口径）**：相比 V3.1-Turbo，长上下文场景下注意力开销大幅下降，预填充 FLOPs 约省一半，API 价格同步下调 50% 以上；更早的 NSA 论文给出过 64K 上下文解码最高约 11.6 倍加速的数据。
- **代价也写得明白**：V3.2-Exp 带"-Exp"后缀，是实验版；索引打分若失手，可能漏掉关键 token，超长文本的"大海捞针"类任务仍需工程验证。省下的是算力，不自动等于精度保险。

## 四、为什么坚持全文公开：论文背后的商业账

- 开源加细到 kernel 级的技术报告，是 DeepSeek 的标准动作。这不是做慈善，而是一套清晰的商业策略：
- **把模型层商品化**：当开源模型把基线拉平，竞争焦点就转向推理效率和单位成本——恰好是这家公司最强的环节。
- **人才引力场**：真实的研究问题 + 发表自由 + 顶配算力，对研究者是硬吸引力，论文本身就是最好的招聘广告。
- **生态占位**：MIT 协议、允许自由蒸馏，让全行业踩着它的成本曲线往下走，反而巩固了它"效率标杆"的位置。
- 从 R1 用纯强化学习（GRPO）逼出推理能力，到 DeepSeek-OCR 探索"把上下文压成像素"的光学压缩，这个团队的论文风格一以贯之：把一个问题打穿，再把方法写得让人能复现。

## 五、和我们有什么关系：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-25/453bfb8c972d9555.png)

1. **长上下文正在变成水电煤**。价格快速下探，做应用的不必再为省 token 牺牲体验；但 RAG 与"全文直接塞"的取舍要重新算账——稀疏注意力降的是"读"的成本，并不保证"理解"更准，该做的校验一步都不能少。
2. **值得抄的作业是方法论，不是结论**。算法与硬件协同设计（tile、kernel、带宽约束）是这批论文共同的底层母题。做 infra 的同学，CUDA 与系统层的功夫，可能比多读十篇模型论文更保值。
3. **对"署名"祛魅**。作者列表反映的是组织把资源压在哪条技术路线上，这往往比任何发布会都诚实。看懂这个信号，比讨论创始人是否亲自敲键盘有价值得多。

一项技术从论文热搜变成你账单上便宜下来的那 50%，中间隔着一整套算法、内核与商业设计。下次再看到"又发新论文"，值得点开的不是八卦，而是那几页公式背后，成本曲线正在往哪个方向拐。
