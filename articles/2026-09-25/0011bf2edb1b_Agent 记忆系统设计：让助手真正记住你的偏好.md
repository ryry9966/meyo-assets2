## 背景

LLM 是无状态的。每次新会话，Agent 对你的了解归零：回复语言、代码风格、部署习惯、上次的排障结论，全都不在。OpenClaw 用户大多在跑长期自动化任务，工作流越依赖 Agent，重复交代偏好的成本就越高。

多数人的第一反应是把所有信息塞进 system prompt——上下文一长注意力稀释、成本上涨，百来个会话后 prompt 膨胀到没法维护。记忆系统要解决的不是“存得下”，而是**记得对、取得准、改得动**。

## 问题拆解

工程上就四个子问题：

1. **记什么**：事实、偏好、事件混存会互相污染；
2. **何时写**：全量记录等于没记录；
3. **怎么取**：检索错了，记忆反而放大错误；
4. **怎么改**：偏好会变，旧记忆要能被覆盖和遗忘。

## 做法：分层文件 + 严格写入 + 范围检索

核心是一个 MCP 记忆服务（等价的插件钩子也行），分五步：

1. **定义 schema。** 每条记忆含：scope（user/project/session）、category（preference/fact/event）、content、source（用户明示/行为推断）、confidence、时间戳。schema 定下来，后面的去重和冲突处理才有抓手。
2. **保守写入。** 只在三种情况触发：用户明确说“以后都……”；同一偏好重复出现 ≥3 次；用户纠正了 Agent 行为。由模型按判据做捕获，宁缺毋滥——记错的记忆比没记忆更糟。
3. **分层注入。** 会话启动时，user 级稳定偏好进 system prompt，上限 2k token；project 级按工作目录匹配；session 级只在被询问时检索。不做全量注入。
4. **检索策略。** 先 tag/关键词精确匹配，命中不够再上 embedding。顺序不能反：向量检索擅长模糊召回，但偏好这种事，模糊匹配经常张冠李戴。
5. **冲突与遗忘。** 同 scope 同 category 的新条目覆盖旧条目，旧版本留档；90 天未被检索命中的进“待清理”列表，每月人工扫一遍；覆盖写入要求用户确认，防止 Agent 把记忆改漂移。

## 踩坑点

- **写权限没约束。** 早期允许 Agent 随便写，几周后偏好条目被反复改写、语义漂移。现在写入走白名单，覆盖需确认。
- **scope 泄漏。** 项目 A 的“别用 TypeScript”被带进项目 B 的会话，排查了很久。scope 必须在注入前严格过滤，别指望模型自觉。
- **记忆与当前指令打架。** prompt 里要显式声明：当前指令优先于历史记忆，记忆只是默认值。
- **敏感信息入库。** API key、内网地址曾被写进记忆文件。写入前加一层正则过滤，记忆文件本地存储、不进仓库。
- **上来就上向量库。** 几百条以内，Markdown + git + grep 完全够用，可 diff、可审计，规模大了再演进。

## 可复用建议

- 存“提炼后的规则”，不存对话原文。一条记忆 = 一句可执行的偏好。
- 记忆文件保持纯文本、用户可直接编辑。可见性是信任的基础，记错了用户能当场改。
- 建一个小评测集：十条“Agent 应该记得 X”的用例，每次改检索策略跑一遍，别靠感觉。
- 写入判据越严越好。记忆系统的质量，取决于你拒绝了多少条不该记的内容。

## 总结

记忆系统 = 存储 + 写入策略 + 检索 + 治理，四块缺一不可。实践下来最重要的一条是克制：默认不记，值得记的才记；默认不注入，需要时才取。先用最土的方案（文件 + 关键词）把闭环跑通，再考虑 embedding 和更复杂的索引。记忆的价值不在记得多，而在每一次回忆都是对的。
