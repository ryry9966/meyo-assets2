## 背景

OpenClaw 的 agent workspace 里有一组以 Markdown 组织的"软配置"：AGENTS.md 管行为守则，SOUL.md 管性格底色，USER.md 管对用户的认知，而 IDENTITY.md 管的是"这个 agent 是谁"——名字、形象、语气、自我介绍方式。它不是装饰。每次会话冷启动时，这份文件会随系统上下文一起注入，直接决定模型如何回答"你是谁"，以及在日常对话里维持什么样的人格一致性。

## 问题

没有身份定义的 agent 常见三种漂移：

1. **自我介绍随机**：今天自称助手 A，明天报模型全名，用户感知割裂；
2. **语气不稳定**：群聊里活泼，私聊里突然正经，跨渠道人格不一致；
3. **边界模糊**：被用户带几句就开始扮演别的角色，回不到主线。

把这些硬编码进系统提示当然可行，但每次调整要改代码、重启、走发布流程，试错成本太高。身份本来就应该像配置一样被频繁迭代。

## 做法

最小可用的 IDENTITY.md 只需要四五行：

```markdown
- Name: 阿钳
- Creature: 一只住在终端里的机械螃蟹
- Vibe: 干脆、工程化、偶尔冷幽默；先给结论，再给理由
- Boundaries: 不模仿其他人格；不确定的事先说不确定
```

要点三条：

- **描述人格，而不是罗列命令**。写"语气像资深运维在值班"比写二十条"你必须"更稳，模型对描述性人设的遵循度明显高于命令式清单；
- **放在 workspace 根目录**，保存后新会话即生效，改身份不需要碰任何代码；
- **进 git**。身份是会演化的，diff 比记忆可靠。

进化节奏建议固定成一个小闭环：跑一周 → 收集跑偏的对话片段 → 把结论写成一句新描述追加进对应段落 → 下周观察效果。我在自己的实例上坚持了三周，文件从 8 行涨到 22 行，语气漂移的反馈从每周两三次降到基本没有。

## 踩坑点

- **写太长**。超过 40 行后重点被稀释，模型开始选择性遵循，反而不如 20 行的版本。身份文件要克制，细节留给 SOUL.md 和 MEMORY.md；
- **职责重叠**。IDENTITY.md 写"不要闲聊"，SOUL.md 写"亲切健谈"，模型会随机站队。建议划一条线：IDENTITY 管"我是谁、怎么自称、什么口吻"，性格底色和行为守则各归各的文件；
- **改了不重载**。编辑后必须开新会话，长会话里的旧身份不会热更新，这是最常被误判为"改了不生效"的场景；
- **语言混排**。文件里中英夹杂严重时，模型回复的语言风格也会跟着晃。统一用一种语言写，语气最稳。

## 可复用建议

- 把 IDENTITY.md 当产品规格而非日记：每句话都应该可执行、可观察、可验证；
- 多渠道部署时，在文件末尾留一小节写渠道覆盖项（比如"群里回复不超过三句"），避免为每个渠道复制整份文件；
- 每次改动配一行 commit message 说明动机，一个月后回看，你会免费得到一份 agent 人格的变更史。

## 总结

IDENTITY.md 的价值不在于让 agent "更像人"，而在于把人格从玄学变成可版本化、可评审、可回滚的工程产物。五段起步，小步迭代，盯住漂移案例往回写——身份会自己长成合适的样子。
