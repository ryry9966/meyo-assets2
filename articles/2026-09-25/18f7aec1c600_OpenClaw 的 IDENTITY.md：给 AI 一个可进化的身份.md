## 背景

OpenClaw 的工作区里有一组大写命名的 Markdown 文件承担"启动配置"的角色：AGENTS.md 管行为规则，SOUL.md 管性格与价值取向，IDENTITY.md 管"它是谁"——名字、形象、语气、emoji、头像。很多部署把 IDENTITY.md 留成默认模板，或当成可有可无的人设文案。实际上它每次会话都会被注入系统上下文，影响所有通道、所有工具调用的表达方式。

## 问题：身份不是"没调"，就是"漂移"

常见三类故障：

1. **口吻不一致**：同一天打招呼像客服、报错像律师；
2. **身份漂移**：改了 SOUL.md 或某条 prompt 之后，之前调好的语气莫名变了，且无法回退；
3. **身份与场景错位**：拿别人的模板（比如某个编程助手的冷幽默人设）套在自己的家庭助理上，怎么调都别扭。

根因通常是同一个：身份散落在零散 prompt 里、没有版本化、没有反馈机制。

## 做法：把身份当配置管理

**1. 先写最小版本。** IDENTITY.md 只回答"是谁"：name、vibe、emoji、avatar、interaction style，控制在 20–30 行。任务类指令（"必须在几分钟内回复"）不写在这里，归 AGENTS.md；价值观归 SOUL.md。一个判断标准：这句话换一个 agent 是否还成立？成立，就是放错地方了。

**2. 用你对话的语言写。** 中文对话配英文身份描述，语气映射会有损。身份文件是给模型读的，更是给你的实际使用场景读的。

**3. 版本化。** 把 workspace 纳入 git，IDENTITY.md 每次修改单独提交，commit message 写清触发原因（"太啰嗦，砍掉铺垫"）。回滚一个版本就回到之前的语气，比在文件里维护 changelog 干净得多。

**4. 建立小反馈回路。** 某次交互让你觉得"不像它"，先归因：是身份问题（语气/称呼/幽默感），还是 prompt/记忆问题？身份问题就改 IDENTITY.md，**一次只改一处**，观察两三天再动下一处。维护固定的三五条探针问题（打招呼、交接任务、报错场景），每次改完跑一遍做回归。

**5.（可选）让 agent 参与提案。** 允许它在 MEMORY 里记录"用户似乎偏好简洁回复"这类观察，定期由你审核后落进 IDENTITY.md。注意：进化的决策权留在人手里。

## 踩坑点

- 把 IDENTITY.md 写成 system prompt 超集，塞满指令：角色扮演味变重，还持续吃上下文预算；
- 让 agent 无监督地自我改写身份：很容易滑向讨好型人格，且不可逆——除非你有 git；
- emoji/头像在多通道（聊天、邮件、语音）表现不一致：提前定 fallback；
- 身份文件里放敏感信息：它每次会话都会被注入；
- 一次改太多：改坏了不知道是哪句导致的。

## 可复用建议

- 一个 commit 一处改动，观察窗口 2–3 天；
- 探针问题集固定下来，和身份文件放同一个仓库；
- 跑多个 agent 时，SOUL 可以共享，IDENTITY 按工作区独立；
- 把"不像它"当作一个正式的 bug 类别记录在 issue 里，而不是随手重写一版。

## 总结

IDENTITY.md 的价值不在于写出多精妙的人设，而在于把身份变成一份**可版本化、可回滚、可增量演进**的最小配置。小步提交、固定回归、人来拍板——身份会随使用越长越对，而不是越长越偏。这大概就是"可进化"的工程含义。
