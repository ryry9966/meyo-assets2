## 背景

玩 OpenClaw 时，多数人的精力都花在工具侧：接了哪些 MCP、装了什么插件、心跳任务怎么排。但决定"它回复起来像不像同一个助手"的，其实是 workspace 里那几份小文件，其中最容易被草率对待的就是 IDENTITY.md。它默认位于 `~/.openclaw/workspace/IDENTITY.md`（以你的实际配置为准），每次会话启动时被读入上下文，定义 Agent 的名字、角色定位、语气风格、emoji 等基础信息。

## 问题

没有这份文件、或者随手写写时，常见的三类问题：

1. **风格漂移**：今天像客服，明天像百科，跨会话没有一致性；
2. **身份写在系统提示词里**：升级或迁移后丢失，每次调整都要动启动配置；
3. **多 Agent 串台**：几个实例共用工具，但没有人格边界，输出和记忆互相渗透。

## 做法

我目前的维护方式是把它当"配置即代码"：

**第一步：最小结构。** 只写五类字段——名字、身份定位（一句话）、语气规则（3~5 条）、emoji/头像、禁止事项。全文控制在 30 行以内。

**第二步：划清文件边界。** IDENTITY.md 只回答"我是谁"；价值观和行为边界放 SOUL.md；用户画像放 USER.md；事实性记忆放 MEMORY.md。身份和记忆混写，是后续一切混乱的源头。

**第三步：纳入 git。** workspace 初始化成仓库，改身份前先 commit，改完看 diff，确认没有顺手夹带别的改动。

**第四步：进化机制。** 在月度回顾任务里让 Agent 提交"身份修订提案"，写成 patch 文件丢回给我 review，由我决定合不合入。它参与进化，但没有自我修改权。

## 踩坑点

- **写成小作文**：早期我给它写了 200 行人设，每次会话白烧上下文，细节互相冲突，行为反而不稳。压缩到 20 行后明显更稳。
- **语言不一致**：身份文件用英文写、日常对话用中文，语气会打架。我最后用中文写规则，字段名保留英文。
- **放开自我编辑**：放手让它直接改过一次，两周后语气越来越"讨好"，diff 一看全是软化措辞。收回权限，改为提案制。
- **emoji 当装饰**：这个字段会出现在消息前缀和命名里，多 Agent 场景下，随手设的和刻意设的辨识度差很多。

## 可复用建议

- **模板化**：团队内维护一份 IDENTITY 模板仓库，新 Agent 复制后只改五个字段即可启动；
- **一个 Agent 一个 workspace**：多实例场景靠独立目录里的 IDENTITY.md 做隔离，比在提示词里写"你是几号"可靠得多；
- **一致性自测**：改完身份后跑一句话测试——"用三个词形容你自己"，看输出与文件是否对得上，对不上说明有冲突指令；
- **修订走 review**：身份变更当成一次 code review，小步提交，拒绝"一次性重写"。

## 总结

IDENTITY.md 只有几十行，却是 Agent 行为一致性的锚点。工程上值得做的就三件事：写短、隔离边界、git 管理。身份可以进化，但每一步进化都应该被人审过——这大概是"给 AI 一个身份"最务实的姿势。
