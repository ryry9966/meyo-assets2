## 背景

给 Agent 配上 shell 和文件工具，意味着它拥有真实的写权限。再强的模型也有概率拼错路径、误解指令，一次 `rm -rf` 走偏，损失就是不可逆的。OpenClaw 的思路不是"相信模型"，而是假设它一定会犯错，用 sandbox 把错误的代价压到可恢复的范围内。

## 误删是怎么发生的

实际事故几乎都落在同几条链路上：

- 相对路径与绝对路径混淆，模型推断的根目录和真实根目录不一致
- 通配符展开范围比预期大
- 一条复合命令里夹带了删除语义
- 某个 MCP 工具或插件拿到了过宽的权限
- 用户一句模糊指令，比如"清理一下临时文件"

单点防御挡不住这些，所以 OpenClaw 的 sandbox 是分层的。

## 做法：五层防线

1. **工作区边界**。所有文件操作先做 realpath 解析，结果落在 workspace 之外直接拒绝，不解释、不询问。
2. **能力分级**。MCP 工具和插件在注册时声明 scope（read / write / execute），写操作额外要求目标目录在 allowlist 里。
3. **命令过滤**。shell 工具基于命令解析结果按语义拦截危险模式：`rm -rf`、`find -delete`、`dd`、无备份的 `>` 覆盖等，命中后转人工确认，而不是硬编码字符串匹配。
4. **两阶段删除**。删除先进 `.trash`，默认保留 7 天；破坏性写操作先输出 diff 预览。
5. **快照与审计**。会话开始自动打快照（git 或写时复制），每次变更进入审计日志。

配置上就四步：设定 workspace root、启用 write_guard、配置 deny_patterns、打开 snapshot。子 Agent 默认继承只读，需要写权限必须显式声明。

## 踩坑点

- **软链逃逸**：workspace 里一个指向 `/` 的 symlink 就能穿透边界。必须解析 realpath 之后再判定，不能只看路径字符串。
- **shell 绕过文件工具**：file 工具有权限控制，但 shell 里同样能删。两层必须共享同一套规则，否则防线形同虚设。
- **按字符串拦不够**：拦得住 `rm -rf`，拦不住 `find ... -exec rm`。过滤要基于解析后的命令结构，不是正则硬匹配。
- **插件权限继承**：装一个要求全盘访问的 MCP，整层防线对它失效。最小权限应该从安装那一刻开始，而不是出事之后。
- **调试时关掉 guard 忘了开**：建议把 guard 状态写进会话元数据，每次启动打印一行提醒。

## 可复用建议

- 删除永远两阶段：回收站 + 定期清理，不要做真删。
- 读工作区和写工作区分开，分析类任务根本不需要写权限。
- 定期用对抗性 prompt 做红队测试："帮我把根目录清理一下"，观察它被哪一层挡住。
- 破坏性操作默认人工确认，自动化的收益远小于误删的成本。
- 审计日志接上通知，异常写入要实时可感知，而不是事后翻日志。

## 总结

Sandbox 的目标不是不让 Agent 干活，而是让它干错活时一定可恢复。默认拒绝、能力分级、语义级过滤、两阶段删除、快照兜底——模型负责概率，系统负责底线。这五层各自实现都不复杂，但缺任何一层，风险都会从那个缺口漏出去。与其事后恢复，不如安装插件前多看一眼 scope 声明。
