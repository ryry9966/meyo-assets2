## 背景

OpenClaw 的 agent 不是靠一坨 system prompt 跑起来的，而是靠 workspace 里的一组 Markdown 文件：SOUL.md 管性格与价值观，USER.md 记用户画像，而 IDENTITY.md 回答最基础的问题——"我是谁"。名字、形象、语气风格、emoji 都写在这里，每次会话启动时被注入上下文。

听起来像玩具配置，但用下来发现它是最容易被低估的一个文件。

## 问题

早期我把 IDENTITY.md 留在默认状态，结果遇到三个典型问题：

1. **人格漂移**。Telegram 上和 Discord 上语气不一致，长会话后期风格散掉。
2. **提示词重复**。为了让它"少废话、直接给方案"，我在各处配置里反复补救，改一处漏一处。
3. **无法回溯**。行为变好变坏，说不清是哪次改动导致的，因为身份定义从未被当作配置管理。

## 做法

我现在的流程是这样的：

**第一步：把身份写成可执行约束。** 不要写"你是一个友好的助手"，而是写具体行为，比如"回复默认三段以内；技术问题先给结论再给推导；不确定时直说，不编造"。可验证的句子才有进化价值。

**第二步：划清文件边界。** IDENTITY.md 只管"我是谁、什么风格"；价值观和底线放 SOUL.md；用户偏好放 USER.md。职责重叠是漂移的源头。

**第三步：git 管理 + 小步提交。** workspace 本身就是仓库，每次修改单独一个 commit，message 写清动机，例如 `ident: 收紧回复长度`。

**第四步：改完跑固定回归。** 我留了五个固定问题（一个技术排障、一个闲聊、一个越界请求），改完逐个问一遍，diff 行为差异。符合预期才合入，否则 revert。

这个"观察 → 假设 → 改文件 → 验证"的循环，就是"可进化"的实际含义：身份不再是一次性设定，而是持续迭代的配置。

## 踩坑点

- **一次改动太大**。有回我重写了整个文件，行为全面变化，完全定位不了哪句起作用。现在一次只改一到两行。
- **指望 emoji 和 avatar 影响行为**。它们几乎只影响自我介绍时的呈现，别把行为期望寄托在这上面。
- **多实例共享一份身份文件**。我跑过工作和生活两个 agent，共用 IDENTITY.md 后语气互相污染，后来拆成独立 workspace 才解决。
- **职责外溢**。"不要主动推送消息"这类调度行为写进 IDENTITY.md 没用，那属于 heartbeat / 调度层的配置。

## 可复用建议

- 把 IDENTITY.md 当代码评审对象：改动必须带动机和验证记录。
- 建一份 5–8 条的"行为回归清单"，每次改动跑一遍。
- 每月翻一次会话日志，把反复纠正的地方固化进身份文件——这才是进化真正的输入。
- 团队共用 agent 时，身份文件的修改走 PR 评审，避免某人顺手改了所有人的助手。

## 总结

IDENTITY.md 的价值不在"给 AI 起个名字"，而在于把 agent 人格从散落的提示词收敛成一个可版本化、可测试、可回滚的配置单元。当你开始用工程方式对待它——小步提交、行为回归、定期吸收日志反馈——agent 的表现会从"时好时坏"变成"可预期地变好"。
