# 背景

OpenClaw 的工作区（workspace）里有一组结构化记忆文件：`AGENTS.md` 约束行为，`MEMORY.md` 记录过程状态，而 `USER.md` 专门存放"关于你这个人的持久事实"。多数人第一周都在调提示词、换模型、折腾工具链，却跳过了这个最便宜的杠杆——花十分钟写清楚自己是谁，之后每一次会话的默认质量都会上一个台阶。

# 问题

没有 USER.md 的 Agent 每次都是冷启动，典型表现：

- 技术栈、时区、称呼偏好，每次会话都要重新交代；
- 语气不合拍：你要结论先行，它给百科式长文；
- 同一件事在不同会话里被问了三遍；
- 你以为它"记住了"，实际信息只活在上次会话的 MEMORY 增量里，还容易和长期事实冲突。

核心矛盾在于：会话记忆是易失且有噪的，而"你是谁"恰恰是低频变化、高复用的事实。这类信息应该有独立的、由人主导维护的载体。

# 做法

**1. 定位文件。** 默认在 `~/.openclaw/workspace/USER.md`（以你的 workspace 配置为准），不存在就新建。

**2. 只写稳定事实。** 我的分区结构：

```markdown
## 基本信息
时区 / 语言 / 常用称呼
## 技术背景
主力语言、操作系统、部署环境
## 沟通偏好
回答风格、默认不要的解释项
## 当前上下文
正在推进的 2-3 个项目，每个一句话
## 雷区
不希望 Agent 做的事
```

**3. 控制篇幅。** 50 行以内。这个文件每次会话都会进入上下文，每一行都是持续成本。

**4. 区分事实与状态。** "我是后端工程师、日常用 Linux"是事实，进 USER.md；"本周在排查网关超时"是状态，进 MEMORY.md。混写的后果是文件迅速腐烂。

**5. 允许 Agent 增量维护，但人审校。** 可以在 AGENTS.md 里加一条规则：确认到新的持久事实时追加到 USER.md。但每周花一分钟 diff 一遍，删掉过时项。

**6. 验证。** 开一个全新会话，问一句"基于 USER.md，你了解我什么"，看它复述是否准确、有没有幻觉。

# 踩坑点

- **写成简历**：三大段人生经历，关键偏好反而被淹没。事实密度比篇幅重要。
- **把指令写进来**："回答要简短"是行为规则，归 AGENTS.md。USER.md 是描述性档案，混进去之后 Agent 会分不清该执行还是该"知道"。
- **塞敏感信息**：常用称呼可以，密钥、密码、证件号绝对不要——这份文件会随上下文被反复发送。
- **放任 Agent 自动写**：它可能把一次性推断固化成事实（比如猜错时区），错误会长期污染所有后续会话。
- **与 MEMORY.md 重复**：同一事实两处维护必然漂移，定期去重。

# 可复用建议

- 把 USER.md 当静态配置纳入 git，改动走 commit，出问题可回滚。
- 角色变化时（换工作、开新项目、换主力设备）立即更新，别等它烂掉才想起来。
- 这个模式不绑定 OpenClaw：任何支持用户档案文件的 Agent 框架都能移植同一套分区。
- 篇幅预算上，50 行 USER.md + 严格的 MEMORY 策略，好过一个 2000 字的 persona 提示词。

# 总结

USER.md 是投入产出比最高的一类配置：十分钟写作成本，换取所有后续会话的默认对齐。它的本质是把"你的画像"从易失的对话流里抽出来，变成版本化的静态资产。写它的时候记住三个词：**事实、简短、可审校**。
