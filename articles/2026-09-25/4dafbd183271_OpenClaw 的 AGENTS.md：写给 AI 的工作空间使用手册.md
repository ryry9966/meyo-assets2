## 背景

OpenClaw 的工作空间里有一组分工明确的 Markdown 文件：`SOUL.md` 管人格，`IDENTITY.md` 管身份，`MEMORY.md` 管长期记忆，而 `AGENTS.md` 是每次会话启动时都会注入上下文的"操作手册"。它不负责性格，也不负责记忆，只负责一件事：告诉 Agent 在这台机器、这个工作空间里，按什么规矩干活。

`AGENTS.md` 本身是一个跨工具的开放约定，不少编码类 Agent 都认这个文件名。所以你在 OpenClaw 里沉淀的规则，换工具时大部分可以带走。

## 问题

大多数人刚开始用都会遇到类似情况：

- Agent 每次重建文件的方式都不一样，目录越写越乱；
- 聊天里纠正过的行为，过几个会话又复发；
- 换个入口（Telegram、终端、Cron 任务）表现不一致。

原因很直白：聊天里的纠正只活在当前上下文里，会话一滚，规则就没了。想要"纠正一次、永久生效"，需要一个每次会话都必然被读取、且由你自己维护的地方——这正是 `AGENTS.md` 的位置。

## 做法

我的工作流是"事件驱动式补规则"，三步：

1. **从最小模板开始。** 新工作空间先用官方模板跑几天，别一上来写几百行。初始内容大概只有：工作空间路径、时区、回复语言、"改动文件需确认"这类底线。
2. **Agent 犯一次错，补一条规则。** 每次手动纠正 Agent 之后，问自己：这条能不能固化成一句指令？能就写进去，格式尽量是"祈使句 + 一句原因"，例如：临时脚本一律放 `scripts/tmp/`，避免污染根目录。
3. **定期做减法。** 每隔一两周通读一遍，删掉过时规则和模型本来就会做的事。我的经验是控制在 100 行以内——这个文件每个会话都要进上下文，长度直接烧 token。

## 踩坑点

- **把 AGENTS.md 当状态存。**"当前项目是 X""昨天改到 Y 文件"这类会过期的信息属于 `MEMORY.md`。写进 AGENTS.md 迟早变成和记忆互相矛盾的噪音。
- **职责串门。** 语气和人格归 `SOUL.md`，工具细节归 `TOOLS.md`。把"说话要温柔"写进 AGENTS.md，后面维护时两头改，必然漂移。
- **写愿望不写规则。**"要有条理""认真一点"没有可执行边界，等于没写。规则要具体到路径、格式、触发条件。
- **改完不验证。** AGENTS.md 在会话启动时读取，进行中的会话不会热加载，改完记得开新会话确认生效。
- **别放密钥。** 这个文件可能被复制、被分享、被其他工具读取。

## 可复用建议

- 把整个工作空间放进 git：AGENTS.md 每次修改都有 diff 可查，出问题能回滚。
- 区分"全局手册"和"项目手册"：跨项目通用的放工作空间根目录，项目特有的放到项目自己的 AGENTS.md。
- 给规则分节编号，聊天里可以直接说"按 AGENTS.md 第 3 节"让 Agent 自查。
- 每条规则记一下来源（哪次事故），半年后你就知道哪些还能不能删。

## 总结

AGENTS.md 的本质不是"更聪明的提示词"，而是把你和 Agent 协作中的教训固化成配置。它应该像代码里的 linter 规则：由真实事故驱动、条条可执行、定期修剪。写好这个文件，Agent 会从"每次都要重新教"变成"大多数时候不用教"——这才是自动化该有的样子。
