## 背景

在 OpenClaw 的工作区里，大多数人熟悉 `MEMORY.md` 和 `memory/` 目录，却常常忽略旁边那份 `AGENTS.md`。它的地位和 README 类似，但读者不同：README 写给人看，AGENTS.md 写给 agent 看。每次会话启动，它会被注入 system prompt，是 agent “上班第一眼”读到的操作规程。换句话说，它是你唯一一份不需要每次对话重复交代、却持续生效的约定载体。

## 问题

没有这份文件或写得潦草时，症状很典型：

- 每次会话都要口头重复工作区约定，说一遍管一次；
- agent 把临时信息一股脑写进 `MEMORY.md`，主记忆越滚越胖，检索质量跟着下降；
- 心跳任务做了不该做的事，比如把例行巡检变成群发消息；
- 对目录结构的理解每次都不一样，产出物写得到处都是。

根因只有一个：约定只存在你脑子里，靠对话临时传递，成本高且不稳定。AGENTS.md 就是把这些口头约定固化下来。

## 做法

我的路径分四步，可以直接复用：

1. **先观察再动笔。** 让 agent 以默认状态跑一周，把每次你手动纠正它的地方记下来。这份“纠正清单”就是第一稿素材，比凭空规划靠谱得多。
2. **分区写，别写成散文。** 建议按四块组织：记忆规范（长期事实进 `MEMORY.md`，临时笔记进 `memory/` 的日期文件）；工具边界（哪些 MCP、插件可用，哪些操作要先确认）；目录约定（产出物放哪、怎么命名）；节奏约定（心跳做什么、明确不做什么）。
3. **写成可执行的祈使句。** “尽量简洁”没有判定标准，不如写“回复超过 300 字时，先给三行摘要”。每条指令都要让 agent 能自检是否做到。
4. **分层放置。** 全局约定放主工作区的 AGENTS.md；让它进某个项目干活时，项目根目录再放一份项目级的，两者职责不重叠。每次改完重启会话做对照验证，确认行为真的变了。

## 踩坑点

- **写太长。** 它每轮都占上下文，超过一两百行会稀释注意力，关键指令反而失效。原则：一行一个约束，能删就删。
- **和其他文件职责重叠。** 我的分工是：`SOUL.md` 管人格和底线，`TOOLS.md` 管工具说明，AGENTS.md 管工作区操作规程。同一件事写三处，改的时候必漏一处。
- **把愿望当指令。** 含糊的形容词（“认真点”“注意安全”）无法被执行，要写具体条件和对应动作。
- **只写不验。** 改完不重启、不做对照测试，你以为生效了，实际上下文里还是旧版本。

## 可复用建议

- 每次手动纠正 agent 后多问一句：这条能不能固化成 AGENTS.md 的一行？能就当场加进去。
- 每月裁剪一次：模型已经稳定遵守的条目删除或下沉，保持文件最小化。
- 把 AGENTS.md 纳入版本控制，每次修改单独提交。行为突变时，diff 一眼就能定位是哪条改动引入的。

## 总结

AGENTS.md 的价值不在写得全，而在写得准、可执行、持续维护。它是你和 agent 之间那份唯一自动生效的“合同”。花一个晚上把纠正清单整理成二十行有效指令，之后每一次会话都省掉重复交代——这是我目前在使用 OpenClaw 过程中投产出比最高的一个维护动作。
