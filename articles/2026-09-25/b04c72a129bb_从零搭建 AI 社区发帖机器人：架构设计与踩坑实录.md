## 背景

社区每周都有值得回顾的内容：成员的实践帖、插件更新、新接入的 MCP 工具。此前这些“每周精选”全靠人工整理，一次约两小时：翻帖、摘要点、排版、发布。流程不难，但重复且容易因为忙而断更。于是决定做一个发帖机器人，目标很明确：**自动完成素材收集和草稿生成，人只负责最后审核。**

## 问题界定

先说清楚不做什么。不做全自动发布——让 LLM 直接对论坛发内容，出一次事实错误就是社区事故。所以任务边界定成四段：

素材收集 → 草稿生成 → 人工审核 → 定时发布

## 架构与做法

整体是“调度 + Agent + 存储 + 发布”四层：

1. **调度层**：cron 定时触发，显式指定时区，每周三早上八点跑。
2. **Agent 层**：LLM 通过 MCP 协议挂三个工具——`fetch_sources`（拉取 RSS 和论坛新帖）、`check_duplicate`（查已发记录）、`submit_draft`（把草稿写入待审队列）。注意发布接口不在 Agent 手里，审核通过后由独立脚本调用。
3. **存储层**：SQLite 存素材池、已发帖 ID、每次 LLM 调用的输入输出。
4. **发布层**：审核脚本读待审队列，人工确认后调论坛 API。

Prompt 用固定模板：标题、三段式摘要、来源列表，口吻参照社区历史帖写 few-shot。先跑了一周 dry-run，草稿只写日志不发帖，确认质量稳定后才开放审核发布。

## 踩坑实录

- **去重失效**。最初用关键词匹配，第二周就撞车：两条帖子讲同一个插件更新，措辞不同没拦住。改成对标题和首段做 embedding 相似度比对，阈值 0.85 以上直接丢弃，才稳下来。
- **模型编造链接**。草稿里出现过一条不存在的帖子链接，格式完全正确。解法是让模型只能引用工具返回的 `source_id`，发布前统一校验 URL 可达性，不过就打回。
- **Markdown 渲染兼容**。论坛渲染器对表格和嵌套列表支持很差，草稿发出去排版稀碎。最后在 prompt 里硬约束：只允许标题、段落、代码块三种元素。
- **触发反垃圾机制**。补发积压时连续发了五帖，被论坛限流。加了最小发布间隔（2 小时）和每日上限（2 帖）。
- **时区漂移**。cron 默认 UTC，实际发布比预期晚八小时。低级错误，但值得进 checklist。
- **全自动翻车一次**。图省事跳过审核直接发过一次，里面有处版本号写错。从此把“人工必须过目”写成硬约束，脚本层面不提供跳过参数。

## 可复用建议

1. 发布动作永远留人工卡点，这是底线，不是可选项。
2. 所有 LLM 调用留痕：输入、输出、时间、token 数，出问题能回溯。
3. 工具做薄，prompt 入库做版本管理，改动走提交而不是手改。
4. dry-run 默认开启，稳定跑满一周再放行。
5. 失败要有兜底动作：素材不足就发“本周无精选”，不要静默失败让人以为它还在跑。

## 总结

机器人上线两个月，发帖没断更，人工投入从每周两小时压到十分钟审核。真正的价值不在“全自动”，而在把重复劳动压缩掉，把人的精力留给判断。想动手的同学，建议从 dry-run 模式和 MCP 工具封装开始，先把素材管道跑通，再考虑接发布接口。
