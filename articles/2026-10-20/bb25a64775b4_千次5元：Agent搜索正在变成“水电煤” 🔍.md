做 Agent 的朋友，账单一般分三份：模型 token 一份，编排框架一份，还有一份最容易被忽略——搜索 API。Agent 接到任务的第一件事往往是“上网查资料”，单次不贵，架不住次数多。最近 36kr 报道，DeepSeek 面向 Agent 开放自研搜索能力：千次 5 元，搜不到不收钱，价格大约只有海外主流方案 Tavily 的零头。这件事的意义不止于降价——它可能把“Agent 联网”从精打细算的奢侈品，变成随手拧开的水电煤。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/93a36f0e011c67c2.png)

## 一、Agent 为什么离不开“搜索”这双手

- LLM 的知识有截止日期，幻觉（hallucination）也是老毛病。要回答“今天的汇率”“上周刚放出的论文”，必须外挂实时信息源。
- 主流 Agent 的工作循环是：理解任务 → 拆解计划 → 调用工具 → 观察结果 → 再决策。所有工具里，搜索是调用频率最高的那个，地位类似程序员手边的 `git status`。
- 一次 Deep Research 类任务，跑 10~30 次搜索是常态：先搜一轮、读结果、发现新线索、再搜。任务越复杂，搜索次数越膨胀。
- 于是搜索费成了 Agent 成本里的“长尾大头”：单价低 × 频次高 × 并发用户多，账单就压不住了。

## 二、搜索 API 卖的不是搜索框，是“干净的上下文”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/d682749e62e30472.png)

传统搜索引擎服务的是人眼：结果页里有蓝色链接、广告位和 SEO 味十足的标题。给 Agent 用的搜索 API，服务的是模型，卖的是三件事：

1. **检索**：接到 query，从索引里召回相关网页；
2. **抽取**：剥掉导航栏、广告、cookie 弹窗，只留正文；
3. **结构化**：输出机器可读的片段、摘要和相关性分数，直接塞进 context window。

这条赛道早有玩家：Tavily、Exa、Serper、Brave Search API、Jina Reader、Firecrawl 等。一个重要背景是，微软的 Bing Search API 已宣布退役，市场留出真空期，各家都在抢位。DeepSeek 的路线是自建抓取与索引，再把抽取、排序与自家模型的“口味”对齐——相当于镜头和机身出自同一厂家，调校上天然占便宜。

## 三、千次5元，价格是怎么压下来的

- **成本工程学**：DeepSeek 的基础设施效率业内有名，训练和推理的成本控制一直很激进。爬虫、索引、推理全在自己手里，垂直整合之后边际成本极低。
- **战略定价**：搜索 API 大概率不是利润中心，而是生态入口——搜索便宜，开发者来搭 Agent，Agent 的推理调用再走自家模型。这是“刀架便宜卖、刀片持续赚”的翻版，只不过刀片换成了 token。
- **规模摊薄**：这套基础设施在自家产品（App 内联网搜索）里早就跑着，对外开放只是把固定成本摊到更多请求上。

按 5 元/千次折算，单次 0.5 分钱；海外同类方案普遍在单次一美分上下，差了一个数量级。对动辄几十次搜索的 Agent 任务来说，这一项成本基本可以忽略。

## 四、“搜不到不收钱”：把风险翻了过来

这个细节比价格更值得琢磨。行业惯例是按调用计费，搜好搜坏钱照收；DeepSeek 改成了按结果计费。

- **激励对齐**：供应商自己扛“查不到”的风险，倒逼索引覆盖率、抓取时效和抽取质量。相当于把 SLA 从合同条款写进了计费逻辑。
- **试错成本归零**：以前接搜索 API 要小流量灰度、盯着错误率跑，现在可以直接全量上，跑不坏钱包。
- **历史参照**：广告业从按展示付费演进到按点击、按转化付费，本质都是风险从买方移向卖方。敢这么报价，通常说明对自己召回率有底气。

当然要盯住细则：什么算“搜不到”？召回了十条但九条不相关算不算？这些边界定义决定承诺的实际含金量。

## 五、机会与隐忧：搜索 API 正在“大宗商品化”

机会面：

- Deep Research、多跳检索类应用的预算约束被拿掉，从“省着搜”变成“放开搜”；
- 竞争向上转移：从“能不能搜到”变成“排得准不准、抽得干不干净、垂直领域扎得深不深”。

隐忧面：

- **单一依赖**：把检索命脉交给一家供应商，等于把 Agent 的眼睛挂在别人墙上；
- **价格曲线**：平台经济的老剧本——低价铺量、站稳调价。今天的 5 元，并不承诺永远是 5 元；
- **内容生态反噬**：抓取规模上去后，robots 协议、版权、反爬升级的摩擦随之而来，这是所有搜索基础设施的长期考题。

## 写在最后：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/369ca81d2043b430.png)

1. **先跑 benchmark，再看价格**。拿业务里最刁钻的 100 条真实 query，横向对比候选方案的召回率、时效性、正文干净度和延迟。便宜十倍但查不到关键信息，等于贵到无穷。
2. **抽象一层，别裸接**。把搜索 provider 包成可替换的 adapter，自定义 query/response 接口。换供应商应该是一次配置变更，而不是一次重构。
3. **按“次数膨胀”重算成本**。搜索变便宜，总成本未必下降——杰文斯悖论大概率再次应验：效率提升，消耗反增。预算请按“次数涨了三倍之后的账单”来排，而不是今天的单价乘今天的用量。
