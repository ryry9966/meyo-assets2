最近 36kr 的报道又把 DeepSeek 顶上热搜：别人家的团队把研究员按在榜单前日夜刷分，这家公司的研究员却被曝在工位打游戏，模型能力反而控制不住地涨。听起来像玄学，其实背后是一套自洽的工程系统加组织设计——榜单分数只是这套系统的副产品。这篇把它拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/6d62db72faaa275c.png)

## 先泼冷水：榜单是体温计，不是暖风机

经济学里有个 Goodhart 定律：**一旦一个指标变成了目标，它就不再是好指标。**大模型圈的“刷榜”正是它的标准案例，常见姿势有三种：

1. **测试集污染**：公开 benchmark 的题目混进训练数据，模型相当于“背过原题”；
2. **过拟合评测格式**：针对 MMLU、GPQA 这类选择题做格式特训，卷面分上去了，真实能力没动；
3. **挑好看的数**：报 best-of-N、报特定温度下的峰值，把方差藏起来。

公开基准的污染问题学界早有共识，旧榜失效就造新榜，leaderboard 无限套娃。DeepSeek 的选择是：把精力放在“能力生产系统”上，评测只当读数的仪表，不当生产目标。

## 能力狂涨的发动机：可验证奖励 + 纯强化学习

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/bb684314521d4f48.png)

R1-Zero 的路线简单粗暴：跳过大规模 SFT 热身，直接在 base model 上跑强化学习。奖励规则简单到离谱：

1. **答案对不对**：数学题比对答案，代码题跑测试用例，全部机器可验证；
2. **格式对不对**：思考过程放进规定的标签里即可。

关键差别在于：传统 RLHF 依赖一个 reward model 给回答打分，模型会学会“讨好评委”，也就是 reward hacking；而规则化奖励像物理规则，对就是对，错就是错，几乎无法被绕过。

配套算法 GRPO（Group Relative Policy Optimization）的思路也省事：对同一道题采样一组回答，用组内平均分当基线，省掉独立的 value model，显存和算力直接省下一块。

于是出现了论文里那个著名的 **"aha moment"**：模型在 RL 中自发学会在算不下去时“等一下，我先检查一遍”。自我验证、反思这些没人教过的行为，是从奖励信号里自己长出来的。

这也顺手解释了“打游戏”：一个 RL run 一跑就是几天，训练期间研究员没什么可干预的，盯着曲线看两眼就去打游戏、睡觉，回来复盘 checkpoint。学习发生在 GPU 里，不在会议室里。

## 省出来的算力去哪了：把“单位算力”做厚

学霸看起来在玩，往往是因为做题速度是别人的好几倍。V3 论文里堆满硬活：

- **MLA（Multi-head Latent Attention）**：大幅压缩 KV Cache，推理显存开销骤降；
- **细粒度 MoE + 无辅助损失的负载均衡**：671B 总参数，每次仅激活约 37B；
- **FP8 混合精度 + DualPipe 流水线并行**：把集群算力利用率打满；
- **MTP 多 token 预测**：同样的数据榨出更密的训练信号。

官方给出的账本：预训练 14.8T tokens，约 278.8 万 H800 GPU 小时，正式训练阶段成本约 557.6 万美元。这笔钱的意义不在“便宜”本身，而在于：**单次实验更便宜 → 同样预算能跑更多实验 → 迭代速度变成复利**。能力“控不住地涨”，涨速是被工程效率买出来的。

## 组织层面：自由度不是鸡汤，是资源配置

据公开访谈报道，这个团队以年轻研究员为主，不设 KPI，自下而上选题，"Aha moment"被当作组织级的庆祝时刻。翻译成工程语言，至少有三层含义：

- **探索需要冗余**：每个动作都被 KPI 锁死的系统会退化成贪心搜索，只能摘到低垂的果实；
- **留白是给长期回报留的探索预算**：没人规定明天必须涨 2 个点，才有空间去做“三年后才见效”的底层研究；
- **开源 + 全量技术报告**：架构、超参、训练成本全写进论文，等于逼自己不靠神秘叙事得分，接受同行检验。

## 冷思考：三条可以带走的

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/d6cd1e45b5073f89.png)

1. **把指标当仪表盘，别当方向盘**。业务同理：考核留存就刷留存，考核时长就堆时长。用 held-out 私有测试集、人工抽检、真实用户行为回流做交叉验证，别让单一公开指标驱动迭代。
2. **找到你业务里的“可验证奖励”**。DeepSeek 赌的是数学和代码天然能判对错；你的场景里大概率也有同类信号——退款率、一次解决率、测试通过率。把优化目标锚定在机器能客观判分的环节，比堆人工标注更抗作弊。
3. **给系统留冗余时间**。看起来低效的“自由时间”，是复杂系统做探索的燃料。你考核什么，组织就会长成什么样——这条定律对模型训练和团队管理同样生效。

降维打击的真相往往不性感：不追着分数跑，把底层系统修对，分数自己会追上来。
