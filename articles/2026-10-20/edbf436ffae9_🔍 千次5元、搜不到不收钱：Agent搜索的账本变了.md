最近 Agent 开发圈的一条消息值得认真拆一拆：DeepSeek 把自家聊天产品里跑了很久的联网搜索能力，拆成一个独立的 Web Search API 对外开放，定价千次 5 元，还附带一句很抓人的承诺——"搜不到结果不收钱"。对照主流竞品 Tavily 约 8 美元/千次的公开定价（折合人民币 50 多元），这差不多是一个数量级的价差。但这条新闻的价值不止于"便宜"两个字：它把 Agent 技术栈里最不起眼、又最绕不开的一层——搜索，第一次推到了聚光灯下。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/8cfd9cea0f7f56fc.png)

## 先搞清楚：Agent 为什么离不开搜索 API

- 一个典型 Agent = 模型 + 工具循环（function calling）。模型负责想，工具负责做；而在所有工具里，web search 出场率最高——写调研报告、比价、追新闻、查文档，规划器的第一反应几乎都是"先搜一下"。
- 注意，这里的搜索 API 不是给搜索引擎包层壳。为 LLM 设计的搜索服务（Tavily、Exa 这类）返回的通常不是一排蓝色链接，而是抓取、清洗、去广告后的正文片段，能直接塞进上下文窗口。一句话：链接给人看，正文给模型吃。
- 背景助攻：2025 年 8 月微软停掉了 Bing Search API，大量依赖它的应用被迫迁移；同时 Agent 应用爆发，搜索调用量水涨船高。搜索从此成了技术栈里的标准件，也成了账单上最常出现的一行。

## 自研搜索难在哪：一条重资产的流水线

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/4295cc73916b7e8d.png)

"自研搜索"不是接个第三方接口，而是自己把整条流水线建起来：

1. **全网抓取**：爬虫调度、去重、反垃圾、应对各种反爬策略，纯基建苦活；
2. **建索引**：倒排索引管关键词命中，向量索引管语义召回，两者混合检索；
3. **排序**：相关性、新鲜度、权威性多路打分，还要给长尾查询兜底；
4. **内容抽取**：把 HTML 剥成干净正文——这一步直接决定喂给模型的 token 质量。

全球真正维护全网页面级索引的公司一只手数得过来，因为这是重资产、长周期的投入。DeepSeek 的特殊之处在于：它不是从零开始——自家聊天产品的联网搜索早已把抓取、清洗、索引这套流程跑通，开放 API 更像把现成基础设施的边际产能拿出来卖，边际成本极低。更关键的是协同效应：模型可以在训练阶段就学会"何时搜、怎么问、怎么用结果"，搜索和模型互相放大，这是纯搜索 API 公司手里没有的牌。

## 千次 5 元的成本账：搜索不再是账单大头

先换算：千次 5 元 = 0.005 元/次；Tavily 约 8 美元/千次，价差约一个数量级。

以前搜索为什么"贵得有道理"？算一笔典型任务的账：一个深度调研任务，Agent 拆解问题后发起 20 次搜索，每次读取 5~10 个页面、每页约 1000 token，光搜索结果读进来就是十几万 token。模型 API 大降价之后，成本结构反转了——20 次搜索按旧价格约合 1 元人民币，很可能反超整个任务的模型 token 开销。**搜索从配角变成了新的成本墙。**

千次 5 元之后，同样 20 次搜索只花一毛钱。价格信号直接改写工程决策：并行搜索、多路查询扩展、多轮迭代，这些"烧搜索换召回率"的玩法突然都变得随便用。以前每次调搜索像点外卖要掂量半天，现在像拧开水龙头。

"搜不到不收钱"也有两层含义：工程上，长尾和探索性查询经常空手而归，按结果计费等于把空转风险从买家转给卖家；商业上，这是对自家索引覆盖率的信任状。但条款要看细——是"零结果不收钱"，还是"相关性差也不收钱"？如果搜回一堆垃圾照样收钱，下游浪费的 token 才是大头。

## 低价背后的商业逻辑：把相邻层打成水电

- 这不是孤立降价，而是"把相邻层商品化"的连续动作：先把模型 API 卷到地板价，再把搜索层价格打穿。当基础设施白菜价化，竞争上移到编排、评测、领域数据这些更高的层面——而上层跑得越欢，底层水电卖得越多。
- 对 DeepSeek 自己：搜索调用量和 token 消耗正相关。搜索越便宜，Agent 跑得越勤，模型 API 的 token 就卖得越多。搜索 API 本身赚不赚钱可能不重要，它是自家模型流量的漏斗。
- 对 Tavily、Exa 这类公司：跟价格打没有胜算，出路只剩差异化——垂直领域数据（金融、电商、学术）、语义检索、企业级合规与 SLA、私有数据接入。通用搜索这门生意，正在被模型厂商顺手做掉。
- 对开发者：搜索从精打细算的稀缺资源，变成敞开用的水电。该担心的问题变了：不再是"搜不搜得起"，而是"怎么搜得准"。

## 三条实用建议与冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/9307819bb2c71d97.png)

1. **选型别只看单价**：用自己业务的真实查询建一个小型评测集，横向测四件事——覆盖度（中英文都要）、时效性（索引延迟多久）、正文抽取质量、限流与稳定性。搜索本身再便宜，搜回一堆垃圾、下游多烧的 token 和错误结论都会加倍还回来。
2. **把搜索做成可替换的适配层**：统一接口 + 适配器模式，供应商可配置、可冗余。这个市场的价格和格局还在剧烈变动，别把 Agent 架构焊死在任何一家的 API 上。
3. **优化"每个任务的成本"，而不是"每次搜索的成本"**：缓存高频查询、复用抽取结果、砍掉无效重试循环。账单大头永远在 token 和失败的循环里，不在搜索单价上——而且单价越便宜，人越容易不知不觉多搜一百次，这个原则反而更重要。

搜索被卖成白菜价之后，真正值钱的东西反而清楚了：不是数据通道，而是知道该往哪里看、看到之后怎么判断的那颗"脑子"。
