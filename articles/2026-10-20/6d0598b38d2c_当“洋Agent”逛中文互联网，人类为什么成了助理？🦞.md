最近 36氪一篇题为《让“洋Agent”逛中国互联网，我成了它们的助理》的文章火了：作者让国外 AI Agent 替自己逛中文互联网——查信息、比价、订服务，结果自己全程沦为“贴身助理”：帮它接验证码、扫码登录、点“同意协议”。原本该是“人指挥 AI”，实际成了“AI 在前台操作、人类在后台打工”。这个身份反转比任何发布会都诚实：它同时暴露了 AI Agent 的真实能力边界，和中文互联网的基础设施现状。下面把这件事拆开看看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/5be8a289c0de3ba8.png)

## 一、先搞清楚：这里的“洋Agent”到底是什么

- **定义**：Agent = 大模型 + 工具调用 + 自主循环。它不是聊天框，而是接到一个目标（比如“帮我订一张周五的票”）后，自己拆任务、自己操作、自己核对结果。
- **主流形态**是 Browser Use / Computer Use：模型像人一样面对一个浏览器或操作系统，观察屏幕 → 决定下一步 → 执行点击/输入/滚动 → 检查反馈，循环直到任务完成。
- **两条技术路线**：
  - 看像素（视觉路线）：视觉模型直接理解截图，输出坐标去点。通用性强，对任何界面都适用，但慢、贵、容易点偏。
  - 读结构（DOM 路线）：解析网页的 HTML 树，按元素操作。快而准，但页面一混淆、一动态渲染就抓瞎。
- **代表产品**：OpenAI 的 Operator、Anthropic 的 computer use、开源框架 Browser Use 等。在英文互联网的开放网页上，它们填表单、查航班、做信息汇总的完成率已经相当能看——这正是后文“水土不服”的参照系。

## 二、一进中文互联网就“水土不服”：卡住它的不是智力，是门禁

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/7c4de09ef4603256.png)

实验里 Agent 的翻车点高度一致，逐个拆开：

1. **登录墙与扫码**：国内主流平台几乎都强制登录，而登录方式集中在手机验证码和二维码扫码。Agent 没有手机卡，验证码只能转交人类——“人类助理”的第一项工作就这么诞生了。
2. **风控与验证码**：滑块拼图、点选文字、行为轨迹检测，本来就是冲着“非人类操作”设计的。讽刺的是，Agent 的鼠标轨迹太直太稳，反而一眼假——人类的手抖才是通过测试的关键。
3. **超级 App 的套娃结构**：外卖、支付、共享单车这些高频服务，很多只活在 App 内的小程序里，没有独立网页。Agent 面对的不是一片开放大陆，而是一间间要门禁卡的房子，而且门禁卡在另一栋楼里。
4. **页面工程复杂**：动态渲染、混淆后的代码、canvas 绘制内容，让“读结构”路线直接失明；“看像素”路线又面对信息密度极高的复杂界面，识别负担翻倍。
5. **反爬与设备指纹**：IP 风控、频率检测，Agent 操作得稍微连贯高效，就会被判定为机器人踢下线。

注意一个关键点：这些关卡没有一条是“模型不够聪明”，**全是准入问题**。这是整场实验最有信息量的发现。

## 三、身份反转：从“人指挥机器”到“人给机器打杂”

- 实验中人类的工作清单变成了：接验证码、扫码、点“同意隐私协议”、做支付确认。每一条都是**“身份与授权”性质的活儿**，而不是“智力”性质的活儿。
- 技术上这叫 human-in-the-loop（人机协同回路），原本是设计出来当“保险丝”的——在关键操作前让人类把关。但在这场实验里，它变成了补丁：凡是 Agent 过不去的门禁，都由人类临时顶上。
- 于是分工变得很清晰：**人类负责“我是谁、我授权了什么”，Agent 负责“怎么查、怎么比、怎么执行”**。瓶颈不在模型能力，在权限体系——这是个很工程师式的结论：架构的问题，不能靠给模型加算力解决。
- 往前推一步，这种协作以后可能产品化成“授权清单”：你给 Agent 划一个范围——能用哪个账号、能动多少额度、哪些操作必须叫醒你。“人类助理”可能升级为“人类审批员”。

## 四、这场实验照出的三道门槛

1. **接入门槛**：网页是给人看的界面，不是给机器用的接口。Agent 最喜欢 API 和结构化数据。国外正在推进的 MCP（Model Context Protocol）、llms.txt 这类尝试，本质是给机器修“专用通道”——有了通道，就不用翻墙撬锁。
2. **信任门槛**：涉及钱和身份的操作（支付、实名、签约），平台不敢放给一个身份不明的自动化程序。Agent 需要可验证的身份和明确的担责主体，业界的 agent identity / agent auth 讨论还在很早期。
3. **生态门槛**：开放网页越多，Agent 越如鱼得水；封闭生态越多，Agent 越依赖人类代理。超级 App 模式客观上抬高了 Agent 的通行成本——这不是谁的错，是架构选择的代价。

补一句公道话：平台反自动化并不全是刁难，同一套风控同时拦着垃圾注册、黄牛脚本和数据爬虫。门槛与安全是一体两面，讨论 Agent 准入时不能只骂门禁。

## 五、三条冷思考与实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/57b853d05835317f.png)

1. **普通用户**：把 Agent 当“新来的实习生”用，而不是当全知全能的管家。先派只读任务（比价、汇总、查信息），涉及支付和账号的操作永远保留人工确认；绝不共享主账号密码，用子账号和最小权限。
2. **开发者和产品**：与其严防死守，不如留一个“机器友好入口”——干净的 API、结构化数据、清晰的操作流。未来谁的界面对人和 Agent 同时友好，谁就多一条分发渠道；Agent 时代的第一批入口红利，会发给先修通道的人。
3. **观察者的判断框架**：下次看到“Agent 自动完成一切”的演示，先问三个问题——它有没有预授权的账号？有没有人在镜头外过验证码？目标网站有没有反爬？三个答案凑齐，演示成色立刻现形。

这场实验最值得记下的，不是 AI 有多笨或多强，而是那个反转瞬间：当机器学会了操作电脑，人类的稀缺能力变成了“我是那部手机的主人”。权限，正在成为人机协作里比智力更硬的通货。
