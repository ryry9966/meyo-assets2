## 背景

社区每天要发一条「今日精选」汇总帖：挑内容、写摘要、排版、发布，全流程手动大概花掉 40 分钟。坚持两个月后决定把它自动化。技术栈选了现成的：OpenClaw 做 Agent 编排，MCP 接数据源和发布接口，一个定时触发器。目标不是一步到位的全自动，而是「机器起草 + 人审核」逐步过渡。

## 问题

最初版本非常天真：cron 触发 → 抓取原始内容 → 塞进一个长 prompt → 调发布 API。跑了三天就暴露了所有典型问题：内容风格漂移、同一条帖子发两次、模型编造了不存在的帖子链接、有一次因为抓取量太大直接超上下文。核心矛盾在于：**Agent 负责生成没问题，但生成之外的一切（去重、鉴权、幂等、风格一致性）都需要工程护栏。**

## 架构与做法

最终架构分四层：

1. **采集层**：MCP tool 封装 RSS 和论坛 API，输出归一化的 JSON（标题、链接、摘要、时间戳），不含任何自由文本。
2. **编排层**：OpenClaw Agent 接收结构化数据，按模板填槽生成草稿。prompt 里明确禁止生成 URL，链接只能引用采集层给的原始字段。
3. **审核层**：草稿先发到内部审核频道，走 dry-run 模式。前两周全部人工过目。
4. **发布层**：发布插件只暴露一个接口，带幂等键（日期 + 内容 hash），发布前查重。

落地顺序很重要：先定输出 schema，再写 prompt，最后才接发布。我们是两周 dry-run → 一周抽审（每天随机复核 3 条）→ 放开自动发布。

## 踩坑实录

**1. 上下文塞太满。** 一开始把 50 条原始内容直接丢给模型，token 暴涨且质量明显下降，摘要开始互相串。改成两段式：先让模型对每条产出一句话摘要，再从中选 top 5 深度展开。

**2. 风格约束被稀释。** 第三周起机器人开始用夸张标题，排查发现 prompt 越改越长，关键约束埋在中段被模型忽略。解决方式不是继续加长 prompt，而是把风格要求收敛成一份 checklist，让模型输出前逐项自查，不合格就重写。

**3. 重复发帖。** 发布失败后的重试逻辑没有幂等保护，同一条汇总发了两遍。修复：幂等键落在发布层而非业务层，任何重试天然去重。

**4. 幻觉链接。** 模型"补全"了一条看起来合理但根本不存在的帖子链接。这是最危险的一类错误。根治办法是收窄能力：prompt 明确禁写 URL，链接字段从采集层数据直通到发布模板，模型碰不到。

**5. 触发器漏发。** 部署在会休眠的环境里，crontab 不触发也不报错，漏发了两天才发现。迁移到常驻环境，并加了发送前心跳检查：采集层拿不到数据就不走发布，宁可空跑也不发垃圾。

## 可复用建议

- **先 schema 后 prompt**：输出契约不定义清楚，prompt 写得再好也不稳定。
- **dry-run 是必选项**，不是加分项。没跑过两周人审的自动发布都是赌博。
- **工具权限最小化**：发布插件只开一个接口，模型能做错的事越少越好。
- **checklist 自查 > 长 prompt**：约束写十条不如让模型逐条核对一遍。
- **留 trace**：每次生成的原始输入、草稿、发布结果都落库，出问题能回溯到具体哪一环。

## 总结

做完这个机器人最大的体会是：难点不在让模型写出一条好帖子——那反而是最容易的部分。真正的工程量在护栏上：幂等、去重、权限收窄、可回溯。Agent 是油门，护栏才是让你敢踩油门的东西。「人审 → 抽审 → 全自动」这条渐进路径，建议任何想复刻的同学都别跳步。
