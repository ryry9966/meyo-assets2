最近 36kr 一篇《让"洋 Agent"逛中国互联网，我成了它们的助理》在圈里刷屏：博主给 OpenAI 的 Operator、Claude 的 computer use 这类"会自己操作电脑"的 AI 布置任务——查攻略、比价、订服务——结果 Agent 走三步卡两步：卡在手机号注册、卡在滑块验证码、卡在只有 App 里才有的功能。最后是人类坐在旁边，帮它输验证码、找入口、点登录。AI 替人上网的想象，暂时变成了人替 AI 打杂的现实。这个反差背后，是 Agent 技术的真实水位，加上中文互联网特殊的生态结构。今天拆开讲讲。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/fe7399d0aa3d029b.png)

## 先弄明白：Agent 到底是怎么"上网"的

主流 Agent 上网有三条路：

1. **API 调用**：最稳、最快，但前提是平台开放接口，覆盖面取决于商业合作。
2. **浏览器自动化**：类似 Playwright 的思路，解析网页 DOM，按元素定位点击。轻量高效，但遇到动态渲染、加密接口就容易翻车。
3. **视觉操作（computer use）**：截图 → 视觉模型理解画面 → 生成鼠标键盘动作 → 再截图确认效果。这是 Operator、Claude computer use 的路线，通用性最强，也最像人。

无论哪条路，核心循环都一样：**观察 → 规划 → 行动 → 校验**。模型的全部信息来源，就是它"看到"的那一块屏幕。它没有手机号、没有账号、没有肌肉记忆，也不知道某个按钮长按三秒会弹出菜单。理解了这一点，就能理解后面所有的翻车现场。

## 为什么洋 Agent 在中文互联网频频"迷路"

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/3dbfb639caff7c69.png)

1. **登录墙 + 实名制**：中文互联网的核心服务和账号深度绑定，注册基本需要中国大陆手机号。Agent 没有手机号，第一步就被拦在门外。
2. **验证码与风控体系**：滑块、点选文字、行为指纹检测——这套体系本来是为防自动化脚本设计的，而 Agent 恰好就是自动化脚本，属于"精准误伤"。
3. **内容藏在 App 里**：很多服务的完整体验只在 App 内：外卖、社区精华、小程序。网页版要么功能残缺，要么直接引导下载 App。小程序更是个封闭生态，浏览器 Agent 根本进不去。
4. **语言与黑话**：搜索结果里的缩写、谐音、拼音代替，足够让模型的检索路径跑偏；界面文案一变，它上一步学会的操作就失效。
5. **反爬与协议差异**：接口加密、字体反爬、高频请求拦截，默认都在对"非浏览器流量"关门。

单点看都不致命，连起来就是：Agent 每隔一两步就可能中断，人只能不断补位。

## "人肉助理"不是段子，是 human-in-the-loop

工程上有个正经名词：**human-in-the-loop**（人在环路中）。Agent 卡住或遇到敏感操作时，把控制权交还人类，这是设计好的机制，不是事故。

- OpenAI 的 Operator 有 takeover mode：填密码、支付这类敏感操作，强制交还用户确认；
- Anthropic 发布 computer use 时明确建议：人类应在旁边监督；
- 各家 Agent 产品普遍要求支付环节由人来按最后的按钮。

所以"人当助理"这件事，一半是能力问题（Agent 还不够强），一半是设计使然（安全和合规需要人兜底）。

真正值得玩味的是一道数学题：假设 Agent 单步操作成功率 90%，连续 20 步的任务链，整体成功率只剩约 12%。人本来是"监工"，成功率不够高时，就被迫升级成"代打"。体验好坏，直接取决于"成功率 × 任务链长度"这个乘积——这也是各家拼命优化长任务能力的原因。

## 更深一层：Web 的"Agent 友好度"竞赛

回头看，搜索引擎时代，网站拼命做 SEO、写 robots.txt，是为了让爬虫"读得懂"。Agent 时代的要求升级了：不光要"读得懂"，还要"操作得顺"——结构化数据、完整的网页版功能、可预测的交互。

两个趋势值得关注：

- **协议层**：MCP（Model Context Protocol）这类标准正在把"给 Agent 用的接口"标准化，相当于给 AI 修无障碍通道。网站主动提供 agent-friendly 的结构化入口，可能成为新的流量来源。
- **生态层**：中文互联网的"App 内闭环"是长期商业选择——数据资产、用户留存、支付闭环，都沉淀在 App 里。这不是技术做不到开放，而是开放的成本和收益算不平。Agent 要进来，要么走官方 API，要么继续卡在门口。

做个类比：搜索引擎时代，"被收录"等于存在；Agent 时代，"可被操作"才等于存在。谁的 Web 对 Agent 更友好，谁就可能拿到下一代入口。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/459d4e4a270de2bb.png)

1. **想自己试的人**：把 Agent 当"实习生"，而不是"员工"。挑开放度高的站点起步，准备好手机号和支付环节的人工接管；涉及钱和隐私的操作，永远自己来。别为了省事把账号密码交给自动化工具。
2. **做产品的人**：先别急着封杀 Agent。想清楚哪些操作可以开放给自动化——清晰的结构化信息、可用的网页版功能，会吸引新的"机器流量"；一味全站风控，等于主动放弃下一代爬虫……哦不，助理。
3. **长期观察者**：验证码、实名、风控，本来是为"防坏人"设计的，如今也拦住了"好 Agent"。身份与授权体系可能需要重做一层——比如给经过认证的 Agent 发"数字工牌"，让它能光明正大地替你办事。人机分工的边界，最终由成功率、责任划分和这套基础设施共同决定。

AI 替人上网这件事，方向大概率没错，只是进度条还卡在验证码那一页。我们能做的，是当好这个助理：别抢方向盘，但也别松开安全带。
