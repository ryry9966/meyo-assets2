这一轮国产模型发布里，最值得开发者点开看的，不是 benchmark 又涨了几分，而是两个更朴素的数字：输出 200+ TPS，价格砍到对标产品的一半。MiniMax 把 M3.1 Flash 定位成正面硬刚 DeepSeek 的型号，很多人的第一反应是“价格战又来了”，但这件事真正的含金量，得从“速度到底值多少钱”说起。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/b06b1d0cb4f5b6eb.png)

## 一、200 TPS 是什么概念：从“等泡面”到“倒杯水”

- TPS（tokens per second）指模型每秒生成的 token 数，一个 token 大致对应 1~2 个汉字。200 TPS ≈ 每秒吐出两三百个汉字，而人的阅读速度大约每秒 5~7 个字——模型写得比你看快几十倍，屏幕上的字不再是“蹦”出来的，接近整段浮现。
- 纵向对比更有感觉：早期 GPT-3.5 时代流式输出的常见体感是 20~40 TPS，之后多数模型官方标称徘徊在 50~80 TPS。200+ 意味着翻倍再翻倍。
- 为什么 agent 时代速度突然变得这么重要：
  1. 推理模型先“想”后“答”，thinking token 动辄上千，输出总长度比以前翻了几倍；
  2. agent 完成一次任务要串 5~20 次模型调用，每次调用都在叠加输出时延；
  3. 端到端耗时里输出阶段占大头——同样生成 3000 token，50 TPS 要等 60 秒，200 TPS 只要 15 秒。写代码的人都懂，等 60 秒和等 15 秒，是两种完全不同的工作流。

## 二、速度怎么“卷”出来的：一笔推理侧的工程账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/3043f39abb136098.png)

TPS 从来不是单点技术的胜利，而是一整层栈叠加的结果：

1. **架构层**：主流模型普遍采用 MoE（混合专家）稀疏激活，每个 token 只走一小部分参数，计算量先砍一个量级；Flash 这类命名通常还意味着更精干的激活参数，用一点点能力上限换大把速度。
2. **框架层**：continuous batching、paged attention、KV cache 精细化管理、算子融合，把 GPU 的有效算力利用率（MFU）一点点往上顶——这是最脏最累的活，也是真正拉开差距的地方。
3. **解码层**：speculative decoding 投机解码，小模型先起草、大模型一次验证多个 token，接受率够高时吞吐能翻 2~3 倍。
4. **部署层**：FP8/INT8 量化加大 batch，单卡每秒能塞进更多 token。
5. **供给层**：集群规模、网络拓扑和闲时调度，决定高峰期你实际拿到的速度。

还有一个关键认知：**速度和价格是一枚硬币的两面**。单位算力每秒产出的 token 翻倍，单 token 成本就近似腰斩。所以"200 TPS"和“价格砍到 1/2”不是两件事，是同一件事的两种报法——发布会把两个数放在一起讲，本身就是竞争力的自证。

## 三、价格砍半，钱到底从哪省出来

- API 定价的底层逻辑很粗暴：单 token 成本 ≈ 单位算力成本 ÷ 每 GPU 每秒产出 token 数。吞吐上去了，降价空间自然被腾出来——这是技术驱动的降价，和单纯烧钱补贴是两回事。
- 在此之上再叠三层：训练成本摊销（一次训练、靠海量推理摊薄）、规模效应（自有集群利用率越高越便宜）、以及抢市场的策略性定价——用短期毛利换开发者生态。
- 放到时间线里看，这不是第一轮价格战：2024 年 5 月国产大模型集体降价，有厂商把某档长文本模型直接砍了 97%；2024 年底到 2025 年，DeepSeek 把百万 token 的单价打到个位数人民币，行业基准价从此被锚死。每一轮降价的底气，都来自推理成本曲线的整体下移。
- 提醒一句：“价格砍到 1/2”要看分母是谁——是对标 DeepSeek 同档，还是自家上一代？缓存命中价、阶梯定价、thinking token 是否单独计费，都会让真实成本和广告数字差出一个身位。发布会讲的是分子，参数表脚注里才是分母。

## 四、正面硬刚 DeepSeek，打的到底是什么仗

- DeepSeek 的角色很清晰：开源、低价、benchmark 硬，它把“性价比基准线”钉在了行业正中间，后来者绕不开。
- 但对位方式已经变了：
  1. 旗舰模型之间的“智商”差距在收窄，单看跑分很难拉开身位；
  2. 真正消耗 token 的是 agent 工作负载——写代码、调工具、跑长链路任务，一个重度用户一天几十万 token 起步；
  3. 对这类负载，选型公式变成了“够聪明 × 足够快 × 足够便宜”，速度和单价从加分项升级成显性变量。
- 所以这一仗打的不是“谁更聪明”，而是“谁的推理经济学更好”：单位算力产出、高峰稳定性、缓存能力、API 体验。名字里带 Flash，本身是行业通行的产品分层信号——Google 用 Gemini Flash 率先确立了“旗舰管上限、Flash 管成本”的打法，现在轮到国产阵营贴身肉搏。对开发者来说，神仙打架永远是好事。

## 五、给开发者的选型框架：别只读发布会

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/74cbe70f5b248ce1.png)

拿自己最重的真实任务做压测，比看任何 PPT 都管用：

1. **测端到端**：记录 TTFT（首 token 时延）和稳态吞吐，在你的真实并发下看 P95，而不是只信厂商峰值——广告里的 TPS 是最好情况，不是平均情况。
2. **算真实账**：按任务长度估算 token 消耗（把 thinking token 算进去），对比“单任务成本”而不是“单 token 单价”。
3. **查稳定性和限额**：限流阈值、高峰降速、SLA、缓存命中率，这些决定生产环境里的真实体验。
4. **能力做匹配**：你的场景是代码、工具调用还是长文本，看对应维度的评测，警惕“一个 benchmark 定生死”。
5. **留好退路**：模型层做薄、做抽象，双供应商兜底——价格战的红利，只属于随时能换模型的人。

## 冷思考：三条

1. **速度与价格是结果，不是原因。** 想判断一家模型公司能不能持续便宜下去，去看它单位算力的 token 产出和推理团队的功力，比看发布会数字靠谱得多。
2. **现在是把模型层做薄的最好窗口。** 价格战红利期，抽象、路由、评测先行，谁性价比高就切谁；等格局固化再动手，切换成本就完全是另一个量级了。
3. **警惕“快而浅”。** agent 场景里返工一次的成本，可能吃掉十次提速的收益；先给任务定好质量底线，再让速度入场。模型可以 Flash，你的验收标准不能 Flash。
