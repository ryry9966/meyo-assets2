最近 36kr 那篇《让"洋Agent"逛中国互联网，我成了它们的助理》在技术圈刷屏：作者让 Operator、Claude 这类 browser agent 替自己跑任务，结果十分钟不到，自己就在旁边专职拖滑块、收验证码、扫码登录。画面很魔幻——本来指望 AI 打工，结果自己先给 AI 上了岗。这篇不聊段子，直接拆技术逻辑：Agent 到底怎么逛网页？为什么一到中文互联网就频繁卡壳？"人肉助理"这件事又意味着什么？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/fa8b478fa5e822c8.png)

## 先看懂：Agent 是怎么"逛"网页的

主流 browser agent（Operator、Claude computer use、开源的 Browser Use 等）跑的都是同一套循环，可以理解为一个"长着眼睛的实习生"：

1. **观察**：读取页面状态。结构派直接解析 DOM / accessibility tree，视觉派干脆截图丢给多模态模型"看图说话"。前者轻量但怕动态渲染和 canvas，后者通用但 token 烧得快，还容易看漏小按钮。
2. **决策**：LLM 根据目标 + 当前页面状态，推理下一步动作。
3. **行动**：执行 click / type / scroll，等待页面响应。
4. **校验**：检查结果是否符合预期，不对就回退重试，直到目标达成或彻底放弃。

水平如何？OpenAI 的 CUA 模型在 WebArena 基准上成功率约 58%，换到更接近真实桌面的 OSWorld 就掉到 38% 左右，而人类基线约 72%。翻译一下：目前最强的 agent，约等于一个手速很快、但社会经验严重不足的实习生——正常流程能走通，遇到意外就卡住。

## 中文互联网给 Agent 上的三道坎

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/051eda19c2cb9466.png)

把这位实习生空投到中文互联网，它会连续撞上三堵墙：

1. **登录墙 + 实名体系**。手机号注册、短信验证码、滑块/点选验证码、扫码登录，层层设卡。注意，验证码的设计初衷就是"区分人和机器"，而 agent 恰好就是机器——这是定义级别的冲突。
2. **内容住在 App 里**。公众号、小红书、抖音的核心内容大多只在 App 内完整可见，Web 版要么阉割要么强制唤起 App。Agent 不能装 App、不能扫码，等于站在商场门口，只能隔着玻璃看橱窗。
3. **风控与设备指纹**。真人浏览是随机的：走走停停、回滚、乱点。Agent 的行为是规律性的：匀速滚动、等距点击。在风控系统眼里，它比十年前的爬虫还好认。

底层原因是历史岔路口：英文 Web 从桌面互联网和 SEO 时代进化而来，留下大量语义化 HTML、公开 API 和 RSS，机器读起来天生顺滑；中文互联网则直接跳进了移动时代——CNNIC 数据显示网民规模约 11 亿，手机上网占比超过 99%，所有交互都默认"一只手握着手机的人类"。二维码是给人扫的，滑块是给人拖的，App 是给人装的。Agent 三样都不占。

## 为什么最后是我来救场：Human-in-the-Loop 的回旋镖

36kr 作者的体验，本质上踩中了一个成熟的设计模式：**HITL（Human-in-the-Loop）**。

- Operator 这类产品在敏感操作前（输入密码、确认支付）会主动暂停，把控制权交还人类。这是刻意设计，为了安全。
- 但真实世界的"敏感操作"远比设计者预想的多：验证码、扫码、勾选协议、选收货地址……于是人从"监督者"一路降级成"异常处理器"——agent 每卡一次壳，系统就往你脸上弹一个待办。
- 自动化的经典规律在这里重演：自动化并不消灭人的工作，而是把人的工作**集中到例外场景**。流水线如此，RPA 如此，Agent 也如此。只是这一轮，例外率高到有点好笑。

同时有个新角色正在浮现：agent 监工/调教师。职责包括拆解任务、盯运行轨迹、失败后复盘、往 agent 的 memory 里喂经验。那位作者无意中体验的，可能就是两年后的一个正式岗位。

## 别急着甩锅中文互联网：整个 Web 都在对机器关门

- 登录墙、paywall、Cloudflare 人机挑战是全球现象。Imperva 的报告显示，全球网页流量里 bot 占比已接近一半——平台不可能不设防。英文世界只是墙矮一点、门多一点。
- 更值得留意的是反向运动：MCP（Model Context Protocol）、llms.txt、GEO（Generative Engine Optimization）这些新东西，本质是网站主动给 agent 开一条"员工通道"。
- 可以类比 2000 年代的 SEO：谁先服务好爬虫，谁先吃到搜索红利。下一轮很可能是谁先服务好 agent，谁先吃到 agentic traffic。对内容平台和电商来说，agent 流量是敌是友，未来两年会见分晓。

## 收尾：三条建议与一点冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-20/ed22d8356238ae1f.png)

1. **分层授权**。只读类任务（信息聚合、比价、调研）放心交给 agent；涉及登录态、支付、实名的一律自己来。别把主账号密码贴给任何 agent，重要支付走虚拟卡或沙箱环境，出事也有防火墙。
2. **挑场景下菜**。结构化、重复、容错率高的任务收益最大（信息汇总、表单预填、多站比价）；遇到扫码登录、强风控平台，提前把"人工介入点"设计进流程，别等 agent 卡住再手忙脚乱。
3. **冷思考**。当人开始给机器当"外设"，价值从来不在点了哪个按钮，而在两件事：定义目标，处理例外。往上走是任务设计与结果验收，往下走就是无限验证码。目前的主动权还在人这边——毕竟，验证码还得你来拖。
