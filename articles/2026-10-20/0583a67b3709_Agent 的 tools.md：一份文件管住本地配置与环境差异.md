## 背景

OpenClaw 这类常驻 Agent 有个尴尬的现实：它对运行环境一无所知。模型每次会话都像新员工报到，不知道这台机器是 macOS 还是 Debian，不知道包管理器是 brew 还是 apt，更不知道你上周刚把工作目录挪了位置。

单机玩玩无所谓，一旦你有两台以上机器——家里的 Mac mini、一台 VPS、通勤用的笔记本——问题就被放大。同一个提示词，在不同机器上得到不同结果，而且模型错得理直气壮。

## 问题

没有环境说明时，Agent 的典型翻车姿势：

- **路径猜错**：在 VPS 上写出 `/Users/xxx/...`
- **包管理器用错**：Debian 上执行 `brew install`
- **能力假设错**：机器上根本没有 ffmpeg / Docker / GPU，它照样生成依赖它们的命令
- **服务操作错**：重启命令、日志路径、端口，全靠“合理猜测”

这些错误每次都要在对话里重新解释一遍，上下文一长还会忘。环境知识是典型的“重复、低熵、但致命”的信息——正适合沉淀成文件，而不是每次口头补课。

## 做法：把 tools.md 当环境接口

OpenClaw 的 workspace 约定里，`TOOLS.md` 会随上下文加载给 Agent，这正是放环境差异的地方。我的写法：

```markdown
# TOOLS.md

## 机器
- mac-mini: macOS 15 / brew / 工作目录 ~/work / 常驻开机
- vps-01: Debian 12 / apt / 无 Docker / 出网走 127.0.0.1:7890

## 约定
- Python 一律用 uv，不要直接 pip install
- 服务重启：systemctl restart openclaw；日志在 /var/log/openclaw/
- mac-mini 没装 ffmpeg，需要转码时先停下来问我

## 禁止
- 不要改 /etc/nginx/，涉及配置变更必须先确认
```

步骤上就四步：

1. 在 workspace 根目录建 `TOOLS.md`，按“机器 / 约定 / 禁止”三段起头；
2. 只写模型猜不出或容易猜错的信息，每台机器控制在 10 行以内；
3. 进 git，和 dotfiles 一起管，机器私有内容用分段标注；
4. 每次踩坑后把修正写回去，形成闭环。

注意分工：`AGENTS.md` 管行为规范，`TOOLS.md` 管环境事实，会话状态交给 memory。三者混写是大忌。

## 踩坑点

- **写太长**。这份文件每次会话都进上下文，50 行以内是舒适区；详细文档放链接，别塞正文。
- **写成百科而不是指令**。用祈使句写“怎么做、不要做什么”，模型要的是行为约束，不是背景介绍。
- **过期比缺失更糟**。环境改了文件没更新，Agent 会拿着旧路径自信执行。我的做法是要求 Agent 遇到“文件与实际不符”时主动报告，我顺手改掉。
- **敏感信息别写**。token、密码会进上下文和日志，环境文件里只写“凭据在密钥管理器里，条目名叫 xxx”。

## 可复用建议

- **新机器初始化时让 Agent 自己起草**：让它探测系统信息生成初稿，人来审核。起草快，审核省心。
- **当接口，不当文档**：字段稳定、内容精简、变更走 git，谁改谁知道。
- **多机共享一份文件时**，用明确的主机名分段，避免 Agent 在 A 机读出 B 机的约定。

## 总结

`TOOLS.md` 解决的不是高深问题，而是把“环境差异”从每次对话的口头解释，变成一份版本化的、Agent 每次都能读到的小文件。它足够笨，但足够可靠。从三段模板起步，踩一次坑补一条，两周后你会发现：在“哪台机器上该怎么做”这件事上，Agent 基本不再需要你操心。
