一场持续 48 小时不间断的自动化攻击，一位用 AI 追查入侵痕迹的防守者，和一次出现在最关键时刻的“拒答”，据 36kr 报道，一位开发者遭遇了长达两天的连续攻击，他借助开源终端 AI 编码代理 OpenCode 分析日志、溯源入侵，结果防守侧的 AI 在半路突然停止配合。攻击方 48 小时不休息，防守方的“AI 队友”却先下线了。这件事真正值得聊的不是猎奇，而是它暴露了 AI 时代网络防御的一个结构性矛盾：安全对齐在拦住攻击者之前，先拦住了防守者。

## 先复盘：这 48 小时大致发生了什么

先补一个背景常识：互联网上的扫描和爆破从未停止。一台暴露了 SSH 端口的服务器，一天收到成百上千次登录尝试是常态，业内称之为“背景噪音”。所谓“连攻 48 小时”，大概率不是某个黑客苦守两天，而是自动化攻击工具——如今越来越多是 agent 化的脚本，在高频持续地跑流程。

这类持续攻击的典型剧本：

1. **侦察**：端口扫描、目录爆破、指纹识别；
2. **入口尝试**：弱口令爆破、撞库、针对已知 CVE 的 exploit 投放；
3. **驻留**：尝试写入 webshell、注册计划任务、提权；
4. **循环**：失败就换姿势，7×24 不停。

防守侧用 OpenCode 这类 agent 干活也顺理成章：让它解析 auth.log 和 Web 日志、提取 IOC（失陷指标）、比对威胁情报、生成检测规则。问题出在分析深入之后——当需要解释一段可疑载荷的行为、复现利用路径、或为验证检测规则构造测试样本时，底层模型直接输出：无法协助该请求。

注意一个关键差异：**攻击脚本是无状态的，被拦一次就换个姿势继续；防守 agent 是有状态的，中途一次拒答就可能让整条分析链路卡死。**

## 拒答不是玄学：安全对齐是怎么“误伤”的

模型拒答不是随机抽风，而是安全训练的产物。主流模型普遍经过 RLHF 和安全微调，把“协助网络攻击”划为高危类别，再用大量拒绝样本训练出条件反射。研究甚至发现，拒答行为在模型内部近似一个可开关的“方向”，2024 年有论文证明，干预残差流中的单一方向就能显著增减拒答倾向（Arditi et al., *Refusal in LLMs Is Mediated by a Single Direction*）。

那为什么防守也会被拒？三个原因：

1. **双用性**：“分析这段 shellcode 在做什么”和“帮我写一段 shellcode”，在词法层面几乎无法区分。策略上允许的防御性安全（恶意样本分析、CTF、取证）和禁止的攻击协助，对分类器来说是同一串 token。
2. **上下文丢失**：agent 长对话会被截断或摘要。开场声明的“我是防守方、有授权”，到了第 40 轮可能已不在窗口里，分类器只看到“生成绕过检测的载荷”这类高危片段。
3. **agent 自我触发**：agent 自己的执行计划里写着“下一步生成 PoC 验证漏洞”，这句计划本身就会在后续轮次触发安全策略。

一句话：**拒答系统看到的是危险句式，看不到你的授权文件。**

## 不对称：攻击者从来不需要“被允许”

真正的麻烦在于不对称。攻击者不排队：他们用对齐很弱的开源权重模型，或者用越狱模板绕过商业模型。Anthropic 2025 年公开的威胁报告就演示过，攻击团伙通过提示注入驱动编码 agent，以极少的人工干预自动跑完侦察、利用、横向移动的链路。而防守方每一次拒答都是纯损耗——业内已经开始把这类损耗称作“防守者税”。

这其实是老问题的 AI 版本：安全知识天生双用，Metasploit、exploit 数据库既能用于测试也能用于攻击，行业靠“授权渗透测试”“负责任披露”这套社会契约来管理。模型时代把契约烧进了权重，可权重里的规则不认识你的授权邮件。

## 防守方的工程化对策

拒答短期不会消失，但可以在架构层面兜住：

1. **多模型冗余**：关键链路别绑单一模型。A 模型拒答，自动降级到 B 或本地部署的开源模型。把“拒答”当成一种可重试的错误类型，而不是流程终点。
2. **任务重述与降级拆解**：把“帮我写利用代码”换成“分析该载荷行为并给出检测逻辑”；payload 生成留给沙箱里的确定性工具，让模型做它擅长的高层研判。
3. **上下文保鲜**：把防守授权与任务背景写进 system prompt，长会话中定期重申；高危片段拆成独立子任务隔离处理。
4. **脏活下沉到本地**：涉及真实恶意样本的脱壳、反汇编、行为分析，放进气隙沙箱用本地模型跑，商业 API 只负责汇总研判。
5. **保留人工扳机**：隔离主机、封禁 IP、取证快照等高危动作永远留人工确认——既是安全要求，也是合规要求。

厂商侧也在改善：Anthropic 与 OpenAI 的使用政策都为防御性安全开了明确豁免，过度拒答（over-refusal）也已成为专门评测维度，例如 XSTest 这类基准。但政策豁免要真正落地到分类器，还需要时间。

## 冷思考：三条带走的东西

1. **把拒答当架构信号，而非模型缺陷**。这次事件的价值不是“AI 不行”，而是提醒：任何把安全运营全权交给单个 agent 的设计，都会在一次拒绝上全线停摆。冗余与降级路径要从第一天就设计进去。
2. **建立自己的过度拒答回归集**。把团队历史上真实的防守任务——日志研判、样本分析、规则编写——整理成内部评测集，选型时实测各家的拒答率，这比看厂商 demo 可靠得多。
3. **分层分工**：自动化留给确定性工具，判断留给模型，授权留给人。攻击侧 48 小时不眠的是脚本，不是天才；防守侧同样应该脚本扛噪音、模型做研判、人握扳机。

AI 深度参与攻防才刚起步，而“防守工具在关键时刻掉链子”这类问题，暴露得越早越好。这次的 48 小时，算是替整个行业交了一次学费。
