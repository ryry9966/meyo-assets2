## 背景

我们用 OpenClaw 挂了一个 MCP 发帖插件，把每日精华摘要、版本说明自动同步到社区频道。功能两周就跑通了，但真正的功夫在后面：第一版按 cron 整点发布，第三天就有群友回了一句“机器人又来了”。自动化本身没人反对，大家反感的是那种一眼假的节奏。

## 问题

拆开看，“像机器人”主要体现在三个维度：

- **时间指纹**：固定整点、固定星期几、凌晨也在发；
- **频率指纹**：多个事件触发就连环发五条，间隔精确到秒；
- **内容指纹**：每篇开头一样、结构一样、长度方差为零。

这些不是功能 bug，而是节奏设计的缺失。反垃圾系统和人眼的判据，其实是同一套。

## 做法

**1. 活跃窗口 + 抖动。** 先统计频道历史消息量，按小时画热力图，把发布窗口收敛到活跃时段（我们是 9:00–23:00，砍掉凌晨）。发布时刻 = 基准点 + 随机偏移，偏移量取 0–35 分钟均匀分布，绝不用整点。

**2. 频率上限 + 合并窗口。** 用一个简单的令牌桶：每日上限 3 条，任意两条间隔 ≥2 小时。合并窗口内的多个事件（比如一小时内的三条更新）合成一条摘要发出，而不是各发一条。

**3. 内容去指纹。** 准备 3–4 套开头模板随机轮换，段落结构允许变化，长度自然出现差异。但保留统一的身份标识（固定 tag），坦率承认这是 agent 发的。

**4. 失败退避 + 幂等。** API 失败走指数退避（30 秒起步，封顶 10 分钟）；发帖前用内容哈希 + 持久化的 post id 去重，保证重启后不重发。

## 踩坑

- **时区。** 服务器是 UTC，直接 cron 导致凌晨四点发帖。改成都转本地时区后再判断窗口。
- **抖动太小也是指纹。** 早期设了 ±3 分钟，两周后依然规律得可疑，后来拉到半小时级别才像样。
- **重试风暴是最差签名。** 有一次网络抖动，1 分钟内重发了 5 条重复帖，比不发还伤。去重逻辑必须先于重试逻辑上线。
- **别伪装成人。** 故意加错别字、假装口头语，这类方案内部评审时就否了：目标不是隐瞒自动化，而是做一个节奏得体的成员。身份透明和节奏收敛，两者并不冲突。

## 可复用建议

- 把节奏做成一等配置：`active_hours`、`jitter_range`、`min_gap`、`daily_cap`、`merge_window`，别写死在 cron 表达式里。
- 状态必须持久化；把“计划发布时间 vs 实际发布时间”落日志，每周看一次分布图，比拍脑袋靠谱。
- 新账号冷启动要预热：前两周把 `daily_cap` 降到 1，观察反垃圾系统和群友反应再加量。
- 留一条人工兜底通道：agent 拿不准的内容进待审队列，而不是直接发出去。

## 总结

节奏控制不是为了伪装，而是把 agent 当成一个有分寸的社区成员来设计：在对的时间、以合适的频率、用不重复的形式发言，同时诚实地亮明身份。做好这四件事，“机器人又来了”会慢慢变成“摘要更新了”。剩下的，交给时间分布图说话。
