## 背景

我用 OpenClaw 搭了一套社区自动发帖流水线：定时拉取仓库动态和 issue 摘要，让 agent 整理成帖子，再通过 MCP 插件推送到社区频道。内容质量没出过大问题，但跑了两周后收到一条扎心评论：“这号是脚本吧？每天 21:00 准时出现。”

内容过关，节奏出卖了它。

## 问题

复盘下来，“机器味”主要来自三类确定性模式：

1. **时间太准**：cron 固定 21:00 触发，连续一个月误差不到一秒；
2. **密度太稳**：每天恰好一篇，节假日照发，产量曲线是一条水平线；
3. **格式太一致**：开头句、分隔符、结尾签名完全一样，肉眼一眼识破模板。

人类发帖天然带抖动：早晚不一、密度随事件波动、偶尔断更。自动化要做的不是模仿“人类的随机”，而是先消灭“机器的确定性”。

## 做法

我的方案分三层，分别管住时间、频率、内容。

**第一层：时间抖动（jitter）**

放弃固定 cron 触发，改成“窗口内随机取点”：

```python
import random, datetime

def next_slot(base_hour, jitter_min=35):
    base = datetime.datetime.now().replace(
        hour=base_hour, minute=0, second=0, microsecond=0)
    offset = random.uniform(-jitter_min * 60, jitter_min * 60)
    return base + datetime.timedelta(seconds=offset)
```

调度器每次取 `next_slot()` 结果注册一次性任务，跑完再算下一个。注意用真随机源，别图省事固定 seed。

**第二层：频率配额**

- 单日上限 1–2 篇，周内设总量软顶；
- 两篇之间强制冷却（≥6 小时）；
- 先拉一周社区活跃数据，把发帖窗口对齐到读者活跃峰值，周末和节假日主动降频。

**第三层：内容去模板化**

- 开头、结尾各备 4–5 个变体，轮换 + 随机；
- 保留固定栏目结构（读者需要预期），只抖动“外壳”；
- emoji 和格式符号保持克制，但不完全一致。

**兜底：可观测 + 人工抽检**

每次发帖记日志（时间、内容哈希、结果），每周抽 20% 帖子人工回看。前两周建议全量走“队列 + 人工确认”，节奏稳定后再放开。

## 踩坑点

- **伪随机退化成规律**：早期我为了复现问题加了 `random.seed(42)`，忘删，抖动变成固定偏移，依旧每天 21:23 准时出现；
- **时区错位**：调度机是 UTC，读者在东八区，“晚间窗口”实际落在凌晨。发帖时间要对齐读者时区，不是部署时区；
- **失败重试风暴**：一次 API 超时后插件指数重试，5 分钟连发三篇重复内容，比不发还难看。重试必须带冷却，且发出前查重；
- **只抖了时间没抖内容**：时间像人了，但每天同一句开头，还是被认出来。

## 可复用建议

1. 先观测再调参：发帖窗口贴着真实活跃分布，再叠加 ±30 分钟抖动，别拍脑袋定“晚上八点”；
2. 所有阈值配置化：抖动幅度、配额、冷却时间进配置文件，方便灰度调整；
3. 沙箱先行：节奏变更先在测试频道跑三天，肉眼确认自然再上生产；
4. 主动披露：账号简介注明自动化身份。透明不损害信任，被识破才会。

## 总结

“不像机器人”的本质是消除确定性：时间有抖动、密度有弹性、外壳有变体、失败有节制。这套流水线改造后跑了一个多月，再没人怀疑它是脚本——不是藏得更好了，而是节奏终于对齐了真实场景。自动化负责内容质量，人负责判断“什么时候值得说”，这个分工是我目前试过最稳的形态。
