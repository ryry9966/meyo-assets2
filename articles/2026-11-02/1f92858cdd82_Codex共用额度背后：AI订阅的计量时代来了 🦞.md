最近开发者圈刷屏的一条消息：OpenAI 把 ChatGPT 的对话额度与 Codex 的任务额度并进了同一个池子，超出订阅内用量可以花钱买 credits 补充。过去那种“到点免费重置、相当于平台再送一桶”的体验，正在退出历史舞台。先把结论放在前面：这不是 OpenAI 一家的算盘，而是整个 AI 行业从“圈地拉新”切换到“按量变现”的同一个动作。下面按老规矩，把发生了什么、为什么发生、普通人怎么应对，一次讲清。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-02/e5c5041b4dc85a9c.png)

## 先把事情说清楚：合并的到底是什么

- **变化之前**：ChatGPT 订阅和 Codex 各有一套限额。2025 年 5 月 Codex 上线时，Plus/Pro 用户拿到的是“独立额度”，本地任务按 5 小时滚动窗口重置，云端任务另有每周上限。重置意味着不用额外花钱，等窗口刷新就又是一桶新的。
- **变化之后**：对话消息和 agent 任务从同一个用量池里扣减，用超了不再只是“等”，而是可以购买 flexible credits 续杯。
- **关键差别**：重置是“免费的补充”，credits 是“花钱的补充”。更准确地说，重置窗口还在，但“重置 = 白得第二份额度”的逻辑结束了。
- **一句话总结**：订阅从“包月自助餐”变成“基础配额 + 超量计量”，向云计算行业用了几十年的 base + overage 模型靠拢。

## 为什么偏偏是 Codex：一次 agent 任务的算力账单

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-02/a1f2e97afb1e2f2b.png)

对比两种用法的成本结构，答案就很直白：

1. **一条普通对话**：输入几百 token，输出几百到几千 token，一次推理结束，成本基本可预测。
2. **一个 Codex 任务**：读仓库、建计划、改文件、跑测试、看报错、再改——每一轮循环都是一次完整的模型调用，上下文像滚雪球一样膨胀。中等复杂度的任务，几十万 token 是家常便饭；并行跑三个任务，直接乘以三。
3. **隐藏成本**：reasoning 模型的“思考 token”你看不见，但照样烧 GPU；长上下文的 attention 计算量也随长度上涨。

如果说聊天像去餐厅点菜，agent 就像雇了支施工队进场——进场前你以为按位收费，进场后才发现按工时算。包月制的隐含假设是“用户用量方差有限”；聊天时代这个假设勉强成立，agent 时代重度用户和轻度用户的消耗能差出一两个数量级，低价包月盖不住重尾，定价引擎就必须换挡。

## 不是孤例：整个行业在同步换计费模型

把时间线摆在一起看，会发现这是一场各自独立、却高度同步的迁移：

- 2025 年 8 月前后，Anthropic 给 Claude 加了每周用量上限，官方说明里直接提到“少数重度用户带来成本压力”。
- GitHub Copilot 把“无限请求”改成了 premium requests 配额，高级模型按次扣减。
- Cursor 在 2025 年年中收紧了“无限慢速请求”，社区里吵了好几轮。
- OpenAI 这次是同一部剧本的最新一集：2023 年 ChatGPT Plus 以 20 美元开启圈地阶段，两年多后重度 agent 用法把边际成本顶上来，切向计量阶段。

根本原因在经济学结构：Netflix 多一个订阅用户，边际成本约等于零；而大模型每多处理一个 token 都要过一遍 GPU。AI 订阅的商业模式天然更接近水电煤，而不是视频网站，水电煤的定价方式，最终都会长成“基础费 + 抄表”。

## 谁疼，谁无感

- **轻度用户**：每天几条对话，共用池基本无感，订阅内额度大概率仍然够用。
- **重度 agent 用户**：主要受力人群。以前 Codex 的窗口重置相当于“隐形第二份额度”，并池后消耗速度肉眼可见地变快，超出就要买 credits 或排队等窗口。
- **团队与企业**：影响最小，甚至偏正面——本就该按用量核算成本，统一计量反而方便做成本归因和预算管理。
- **免费用户**：同一逻辑也在起作用。“免费重置”本质是平台的获客补贴，圈地阶段结束，补贴退坡是必然。

## 应对思路：把额度当预算管

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-02/bf950bc8c1e3ebc8.png)

- **任务分级**：改正则、写单测这类机械活，交给便宜模型或本地小模型；架构设计、疑难 bug 才上旗舰 agent，好钢用在刀刃上。
- **把规格写清楚**：agent 烧 token 的大头是“自主探索”。直接给复现步骤、报错日志、失败的用例，比让它满仓库乱翻能省下好几轮循环。
- **机械工作外移**：格式化、grep、lint、批量重命名，交给本地工具链完成，agent 只保留需要判断力的部分。
- **看仪表盘**：像管云账单一样管 AI 额度，设个月度预算线，别等月底账单出来才复盘。
- **留一条备胎路线**：DeepSeek、Qwen 这类开源权重模型，本地或 API 跑高频低难度任务，商业旗舰留给高价值场景，混合工作流会越来越常态。

## 冷思考：三条

1. **订阅价不再是天花板价。** 月费会越来越像“基础费”，真实成本 = 订阅 + 超量。评估工具时，把它当云服务算 TCO，而不是当视频会员只看月费。
2. **效率差就是真金白银。** 同一个任务，会写规格的人和随手丢一句话的人，token 消耗能差一个量级。prompt 与上下文管理从“技巧”变成了“成本科目”。
3. **比单价更重要的是单位任务成本。** 贵的模型如果少走三轮弯路，总账可能更便宜。计量时代要学会按“完成了多少事”计价，而不是按“聊了多少条”计价。
