## 背景

这一年大家都在折腾项目级的 `AGENTS.md` / `MEMORY.md`，让 Agent 记住仓库的构建方式和目录约定。但很少有人维护一份**用户级**的档案。结果就是：每个新会话都要重新自我介绍一遍——"我用 pnpm 不用 npm""时区 UTC+8""回复别堆 emoji"。说第三遍的时候就会想：这不该是人干的活。

## 问题

Agent 的默认行为是"面向所有人的平均值"：给你 npm 命令、英文注释、四平八稳的解释。这不是 bug，是缺输入。项目记忆解决"这个仓库怎么干活"，用户记忆解决"我这个人怎么被服务"——两者不该混在一个文件里，也不该都不存在。

## 做法

1. **位置分离**。在 Agent 的全局工作区（OpenClaw 默认布局下就是 `~/.openclaw/workspace` 这类目录）新建 `USER.md`，不要写进某个项目里。
2. **只写四类内容**：稳定身份（称呼、语言、时区）、技术栈偏好（包管理器、Shell、框架及版本）、协作风格（结论先行、示例要可跑、注释语言）、边界（未经确认不 push、不动哪些目录）。
3. **控制体积**。这个文件每个会话都进上下文，建议压在 1KB 上下，一行能说清的不写三行。
4. 模板参考：

```markdown
# USER
- 称呼: 老周; 中文回复; 时区 UTC+8
- 环境: macOS + fish shell; pnpm; Node 22
- 风格: 先给结论; 示例可跑; 注释用中文
- 禁止: 未经确认不执行 rm / git push --force
```

5. **更新策略**：同一件事纠正 Agent 超过两次，就沉淀进 `USER.md`。别指望脑子记。

## 踩坑点

- **写太多**。见过 3KB 的版本，塞满周报级进度描述。上下文是预算，泛泛的自我描述会稀释真正的指令。
- **写易变内容**。"本周在做支付重构"两周后就是误导。进度类进 `MEMORY.md` 或项目文件，`USER.md` 只放半年内大概率不变的东西。
- **和项目文件打架**。明确优先级——项目级覆盖用户级——并在文件头用注释写明，免得 Agent 自己猜。
- **放敏感信息**。这份文件会随每次请求上行，密钥、住址、手机号一律不进。
- **写口号不写动作**。"喜欢整洁的代码"模型无法执行；"Python 项目一律用 ruff 格式化"才可以。

## 可复用建议

- 把 `USER.md` 放进 dotfiles 仓库用 git 管理，换机器即迁移，还能看历史。
- 加一个会话收尾钩子：让 Agent 输出"本次发现的偏好冲突"提案 diff，人工审后合并。自动化采集，人工把关。
- 每月 diff 一次，删过时条目。这类文件的生命力靠修剪，不靠追加。
- 玩 MCP/插件的同学可以更进一步：把偏好字段（比如默认包管理器）抽成结构化配置，让工具侧和 Agent 读同一份来源，避免两套标准。

## 总结

`USER.md` 的价值不在"档案"本身，而在把重复的口头纠正变成一次性的工程决策。成本极低——一个 Markdown 文件，十几行字——但能把 Agent 从"通用客服"拉近到"了解你的同事"。建议路径：先写五行，跑两周，再迭代。
