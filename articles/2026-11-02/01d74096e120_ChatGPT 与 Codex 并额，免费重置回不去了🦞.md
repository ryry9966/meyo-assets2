2025 年 8 月 GPT-5 发布时，OpenAI 在更新说明里塞了一句不起眼的话：未来几周，ChatGPT 与 Codex 将引入跨产品共用的速率限制。当时大多数人没当回事，直到额度真的并到一起，不少人才反应过来——过去“这边用完切那边”的日子结束了。36kr 把这件事概括为：免费重置时代结束。它表面是一次产品规则调整，底下是一条清晰的商业逻辑线：AI 的“补贴期”正在收尾。这篇就拆三件事：并额到底并了什么、为什么编码 Agent 是额度黑洞、以及全行业为什么正一起走向“统一账单”。

## 并额到底并了什么：从“两个池子”到一个池子

先回顾旧规则。并额之前，ChatGPT 和 Codex 是两套独立体系：

- **ChatGPT 对话**：按消息次数计，典型的 5 小时滚动窗口加每周上限，用完就等免费重置；
- **Codex**：独立的一池额度。2025 年 5 月上线时相当慷慨——官方口径 Plus 用户有 30~40 小时云端任务用量，Pro 从 80 小时起步，后续还多次放宽。

两套池子带来一个隐性福利：ChatGPT 对话额度耗尽，可以切到 Codex 里继续让模型干活；Codex 触顶了，再回 ChatGPT 聊天。一份订阅，实际吃到两份额度，且各自独立重置。

并额之后逻辑反了过来：GPT-5 系列模型无论在 ChatGPT 里回消息，还是在 Codex 里跑任务，扣的都是**同一个池子**。你上午让 Codex 连跑三个重构任务，下午想用 ChatGPT 写方案，大概率已经在等窗口重置。与此同时，OpenAI 还在推进给触顶用户开放按量购买额外用量的通道——从“白送的滚动窗口”走向“明码标价的用量包”，路径已经画得很清楚了。

## 为什么编码 Agent 是“额度黑洞”

要理解并额的杀伤力，得先看 Codex 这类 Agent 的工作方式。它不是“你问一句、它答一句”，而是：

1. 在云端起一个隔离的沙箱环境，加载你的代码仓库；
2. 读文件、理解结构、动手改代码；
3. 跑测试、读报错、再改、再跑——循环，直到任务完成或判断收敛。

问题出在第 3 步。一次普通聊天，输入加输出通常在几百到几千 token 的量级；而一次 Agent 任务动辄几十上百轮工具调用，每一轮都要把不断膨胀的上下文重新送进模型，推理模型还要额外消耗大量“思考 token”。一个跑 50 轮的任务，光上下文就可能被重复处理几十遍（工程上有 prompt caching 缓解，但缓存命中同样要花钱）。粗略估算，一个中等复杂度的重构任务，消耗的算力相当于**上百次普通聊天**，折算成 API 计价往往抵得上好几美元。

这就是经济学的麻烦：订阅制定价的前提是“大多数人用不满”，用轻度用户补贴重度用户。而 Agent 恰恰把使用量极端集中到少数重度用户身上——同样一个 20 美元的 Plus，一个每天跑几十个任务的开发者，真实推理成本可能是普通用户的几十倍。池子并起来，本质是先把这个漏洞堵上。

## 不止 OpenAI：全行业都在从“吃到饱”转向“统一账单”

把镜头拉远，这不是某一家公司的抠门，而是一次行业性收敛：

- **GitHub Copilot**：2025 年引入 premium requests 机制，高级模型按次数扣减额度；
- **Cursor**：Max 模式从包月畅用改为按实际用量计费；
- **Anthropic**：Claude Code 上线后被重度使用打到限流，随后干脆加上了每周限额。

共同背景有三个：GPU 供给依然紧张；Agent 工作负载把单用户的边际推理成本成倍放大；订阅价格短期内不可能涨到覆盖真实成本。于是“统一额度 + 超额按量购买”成了几乎所有 AI 产品殊途同归的方案。

这套剧本历史上反复上演：宽带不限量套餐最后变成“达量降速”，手机流量从畅用变成阶梯计价。规律是一样的——**补贴期拉新，成本期回收，定价回归单位经济**。AI 只是把周期压缩得更快了。

## 对不同用户分别意味着什么

- **轻度用户：几乎无感，甚至变好。** 你本来就只和 ChatGPT 聊天，并额影响有限；滥用型重度任务被抑制后，高峰期的响应稳定性反而可能提升。
- **重度用户：从“想用就用”切换到“预算管理”。** 额度从模糊的背景变成了每天要盘的资产——什么时候跑大任务、用哪个档位的模型、哪些任务值得花 token，都成了显性决策。
- **团队与企业：可控性提升，但需要治理。** 统一额度让用量可预测、可分配，不用再担心“某个同事把池子跑光”；但反过来，也该建立基本的用量规范，比如给 Agent 任务设明确的验收边界。

## 收尾：三条实用建议与一点冷思考

1. **给 Agent 任务“定边界”。** 下发任务时写清验收标准（比如“测试全绿即完成”），复杂任务先让模型出执行计划、确认后再跑，能显著减少无效迭代轮次——每一轮省下的都是真金白银的 token。
2. **分清两类负载。** 短平快的问答、头脑风暴，交给 ChatGPT 对话；有明确输入输出的工程任务，才值得交给 Codex。别用吞额度的大炮打蚊子。
3. **一点冷思考：** 额度收紧不是终点，而是行业从“烧钱换增长”转向“单位经济核算”的信号。把工作流绑在单一产品的免费额度上，风险只会越来越高。API 按量付费、多供应商备份、关键场景的开源模型本地化，都是值得提前铺的对冲选项。
