过去两年，我们习惯了「你问我答」式的 AI：输入问题，等一段文字，关掉页面。但从 2024 年底开始，产品形态悄悄变了——Claude Code、OpenAI 的 Operator 与 Deep Research、Manus……这些被归入 "Super Agent"（超级智能体）名下的产品，做的是另一件事：你给目标，它自己拆任务、调工具、跑完整条流程。36kr 那篇文章的标题点得很准：会主动干活，更懂何时闭嘴。主动性和分寸感，是它的一体两面。这篇就拆开聊聊：它靠什么主动干活？"闭嘴"又为什么比听上去难得多？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-02/ab4b8f94d8762d72.png)

## 从答题机器到执行者：四年演化线

Super Agent 不是一夜冒出来的，往前捋一下脉络：

- **2023 年初**：AutoGPT 一夜爆红，「给个目标全自动跑」听着很美，实际经常死循环、无限烧 token。当时不少 demo 的结局是：任务没完成，API 账单先完成了。彼时模型的规划能力和工具调用都不成熟，属于想法跑在能力前面。
- **2023–2024**：function calling 标准化，模型学会稳定调用搜索、代码执行和外部 API；长上下文与 RAG 补上了「记忆」。Agent 从 demo 变成勉强可用的流水线。
- **2024 年底–2025 年**：Anthropic 在《Building Effective Agents》里明确区分了 workflow（人编排步骤）与 agent（模型自己编排）；MCP 协议让模型接工具像插 USB 一样规范。随后 Operator、Deep Research、Manus、Claude Code 等产品，把「长任务自主执行」做成了正式形态。

落到定义上，Super Agent 大致有四个特征：**目标导向**（输入的是 outcome，不是步骤清单）、**多步规划**（自己列 todo、边跑边改）、**工具调用**（浏览器、终端、文件系统）、**主动性**（不必每一步都被人推着走）。

## 「主动干活」的引擎：一个不断转圈的闭环

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-02/7e0f51e80fd16479.png)

拆开看，Super Agent 的核心是一个循环，业界常用 ReAct（Reason + Act）来概括：

1. **观察**：读取任务描述、环境状态、上一步工具返回的结果；
2. **规划**：把大目标拆成子任务，写成显式或隐式的清单，随进度动态调整；
3. **行动**：调用工具——搜网页、跑代码、点按钮、改文件；
4. **反思**：检查结果对不对，错了就回头换路线，而不是硬着头皮往前冲。

支撑这个循环的是三块底座：

- **记忆**：长上下文装下几百页资料，向量库和本地文件负责随时取用；
- **工具层**：MCP 这类协议把「接一个新工具」的成本从定制开发降到填配置；
- **计算预算**：Deep Research 类产品允许模型「想上几分钟甚至更久」，用推理时算力换任务质量——这是 2025 年与 2023 年最本质的差别之一。

效果在基准测试里能看到：SWE-bench 让 agent 修真实的 GitHub issue，2023 年顶级模型的解决率还不到 2%，2025 年主流模型已能稳定处理六成以上。长任务的可行性，是被这个闭环一圈一圈转出来的。

## 「何时闭嘴」为什么难：本质是校准问题

「更懂何时闭嘴」听着像产品话术，其实是个严肃的工程命题。可以借自动驾驶的 SAE 分级来理解——agent 同样有一条「自主性滑杆」：

- **副驾档**：每一步都请示，模型是纯粹执行者；
- **检查点档**：关键里程碑汇报一次，中间过程自己消化；
- **托管档**：全程自动，只在出错或需要授权时求助。

而「闭嘴」其实包含三种能力：

1. **该问的时候问**：不可逆操作（删数据、转账、对外发消息）前必须停下等确认；
2. **不该问的时候别问**：可逆的中间步骤自己处理，别每五分钟弹一个通知，把用户变成流水线瓶颈；
3. **该停的时候停**：目标达成、方向跑偏、预算耗尽，主动终止而不是无限空转。

难点在于 LLM 的校准（calibration）问题：模型常常「不知道自己不知道」。自信过头就自作主张，保守过头就事事请示——两种失败的体验一样糟。工程上的解法很朴素：给操作按风险分级（可逆 / 不可逆），设置确认门（confirmation gate）、里程碑检查点，以及步数与花费上限。本质上，一次询问的成本是「打断用户」，不问出错的成本是「返工甚至事故」。Super Agent 的分寸感，就是在这两种成本之间做实时权衡。

## 泼点冷水：错误在长任务里会复利

- **错误累积**：假设单步准确率 95%，一个 20 步任务的端到端成功率只有 0.95 的 20 次方，约等于 36%。Agent 越自主，单步可靠性越重要——反思与回滚不是锦上添花，是生存必需。
- **成本**：多轮工具调用意味着 token 消耗可能是普通对话的几十倍，跑一次深度研究任务花掉几美元很正常。
- **安全**：给了 agent 浏览器和文件权限，就要面对 prompt injection——网页里埋一句恶意指令，agent 可能照单执行。沙箱与权限隔离是底线。
- **评测难**：长任务难复现、难打分，很多惊艳演示换个场景就不灵了。

## 三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-02/6a80c972604cf3a3.png)

1. **先划权限，再谈自主**：把不可逆操作隔离在确认门之后，用沙箱和预览代替盲跑。自主性是发放出来的，不是模型自带的。
2. **写目标，也写红线**：任务描述里除了「要什么」，还要明确「不许动什么、何时必须停下问」。模糊指令换来的只会是模糊执行。
3. **保留人工抽查**：agent 产出 + 人工把关（human-in-the-loop）仍是当下性价比最高的组合。让机器接手 80% 的机械步骤，把 20% 的判断留给自己，比追求 100% 全自动现实得多。

Super Agent 的进化方向，从来不是「更吵地干活」，而是「更安静地把活干完」——主动性决定它能在多复杂的任务里走远，分寸感决定别人敢让它走多远。
