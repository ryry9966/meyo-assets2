# 背景

跑 OpenClaw 一段时间后会发现：默认状态下的助手是"通用但平庸"的。语气飘忽、边界模糊——今天过于热情，明天在群里抢话；你让它帮忙盯服务器，它可能顺手就把重启命令跑了。会话级的 system prompt 解决不了这类问题：不持久、不可版本化、多人协作时更是一团浆糊。

OpenClaw 的做法是把人格放进工作区的一个文件：**SOUL.md**。它在会话启动时注入上下文，相当于给 Agent 一份长期生效的"性格说明书 + 行为红线"。

# 问题

没有 SOUL.md 时，常见的三种失控：

1. **语气不一致**：跨会话、跨渠道（私聊/群聊）风格漂移；
2. **动作越界**：装了 MCP 和一堆插件后，Agent 有了执行能力，却没人告诉它哪些事必须先问；
3. **人格靠口口相传**：团队共用一个 bot，每个改过 prompt 的人都在留下自己的痕迹。

# 做法

我的 SOUL.md 骨架分四块：

```markdown
# 我是谁
一两句身份定义：名字、定位、与用户的关系。

# 语气
3-5 条具体规则 + 一组正反例对话。
不写"要友善"，写"回复不超过 5 行；群聊里被 @ 才说话"。

# 边界（红线）
- 删除/重启/付款类操作：先复述命令，等确认
- 代发消息、读取通讯录：每次明示授权
- 不确定时：问，而不是猜

# 优先级
安全 > 用户当前指令 > 人格风格。冲突时按此顺序裁决。
```

几个工程细节：

- **控制在 100 行以内**。它是常驻上下文，写长了模型"读过就忘"；
- **和 AGENTS.md 分工**：SOUL.md 管"我是谁、什么不能做"，AGENTS.md 管"怎么干活"（流程、工具用法），别混着写；
- **进 git**。每次 Agent 惹祸，把教训写成一条规则提交进去，当 postmortem 产物维护。

# 踩坑点

- **形容词不约束行为**。"聪明、可靠、有分寸"模型无法执行，必须翻译成可判定的条件和示例。
- **规则互相打架**。我同时写过"保持主动"和"任何操作先确认"，结果它在自动任务里疯狂来问我。后来补了例外清单才消停。
- **人格漏进工作场景**。为私聊调的插科打诨，在群里会很尴尬，用渠道条件区分语气。
- **别把 SOUL.md 当安全边界**。它只是软约束，模型可能违反。危险命令白名单、额度上限这类硬限制要落在工具权限和网关配置上，文件只负责让 Agent"知道自己该守规矩"。

# 可复用建议

- 一条规则一行，祈使句，带触发条件；
- 放 2-3 段正反例对话，比十行描述管用；
- 每次接入新的 MCP server 或插件，重过一遍边界清单：新能力 = 新红线；
- 每季度回顾一次，删掉从未触发的规则。

# 总结

SOUL.md 的价值不在"让 AI 更像人"，而在把人格和边界从聊天记录里捞出来，变成一份可评审、可回滚、可协作的文本资产。写它的过程也是给自己梳理需求的过程——你必须先想清楚"我到底要一个什么样的助手"，才写得出来。建议从一个 20 行的最小版本起步，跑两周，再按踩到的坑逐条加规则。
