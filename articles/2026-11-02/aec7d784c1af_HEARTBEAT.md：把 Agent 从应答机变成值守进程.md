## 背景

大多数 Agent 是应答式的：你问，它答，然后沉寂。OpenClaw 在网关层内置了心跳机制：按固定间隔（默认 30 分钟，可用 `HEARTBEAT_INTERVAL_MS` 调整）触发一次 Agent turn，并让它读取工作区的 `HEARTBEAT.md`。文件里只有 `NO_REPLY` 时 Agent 保持沉默；一旦写进检查项，它就变成一个定时巡逻的值守进程。

## 问题

我最初把 HEARTBEAT.md 当"想到什么写什么"的便签，一周踩了三个坑：

- **噪音大**：每半小时汇报一次"一切正常"，三天后我开始条件性忽略推送，真告警反而被淹掉。
- **烧 token**：每次心跳都是完整的 Agent 调用，系统提示和上下文全量进入。提示词里多十行废话，就是每天几十次的纯浪费。
- **行为不可控**：写过一条"看看邮件有没有重要的"，Agent 自作主张翻了邮箱还做了总结。心跳场景没人盯着，自由度就是风险。

## 做法

后来我把 HEARTBEAT.md 当作一份值守合同来写，核心原则：**默认沉默、阈值触发、重活下沉到脚本**。

**第一步：检查逻辑收敛成脚本**。放在工作区 `scripts/` 下，有输出代表告警，空输出代表正常：

```bash
#!/bin/bash
# check_disk.sh：磁盘 ≥85% 才输出
usage=$(df / | awk 'NR==2{gsub("%","");print $5}')
[ "$usage" -ge 85 ] && echo "磁盘 ${usage}%，建议清理 Docker 卷"
```

**第二步：HEARTBEAT.md 只写合同**：

```markdown
# 心跳检查
规则：脚本有输出才提醒；全部正常回复 NO_REPLY。
只读操作，不执行修复、不对外发送任何消息。

1. bash scripts/check_disk.sh
2. bash scripts/check_cert.sh   # 证书剩余 <14 天
3. bash scripts/check_feed.sh   # RSS 有新增条目

上报格式：一行摘要 + 一行建议命令，等我确认后再执行。
```

**第三步：状态去重**。心跳是电平触发，条件持续满足就每轮都报。在脚本里加状态文件：首次触发写标记，之后只有状态翻转（恢复，或超过 6 小时仍未处理）才再次输出。告警从"每半小时吵一次"变成"状态变化才说话"。

**第四步：验证**。手动跑三个脚本确认输出符合预期，把间隔临时调到 5 分钟观察两三轮日志里的心跳 turn，确认静默和推送都正常，再调回默认值。

## 踩坑点

- **别和定时任务混用**："每天早八发日报"这类固定时间的事交给 cron 类调度，心跳适合"需要 Agent 判断"的巡检，混写会让文件迅速膨胀。
- **状态文件别放工作区**：放 `/tmp`，重启丢了代价只是多告警一次；放工作区会被扫进 Agent 上下文，白耗 token。
- **上报格式必须约束**：不限定"一行摘要"，Agent 会输出三段式小作文，移动端推送没法看。
- **"只读"要落到权限层**：光在提示词里写"不做修复"不够，心跳 turn 不应拥有发消息、删文件这类工具权限，兜底靠配置不靠自觉。

## 可复用建议

- 把 HEARTBEAT.md 当 oncall runbook 维护：每月清一次，删掉一个月没触发过的检查项。
- 每一行都有成本：行数 × 每日心跳次数 = token 底噪，能进脚本的别进提示词。
- 阈值保守、定位明确：关键路径交给 Prometheus 这类专业监控，心跳补的是低频、需要理解上下文的那部分。

## 总结

HEARTBEAT.md 的价值不在"Agent 会主动干活"这个噱头，而在它逼你把"什么值得打扰我"写成明确契约。默认沉默、阈值触发、重活下沉、状态去重，守住这四条，它是一个安静的值守进程；守不住，就是一个每小时说废话的昂贵定时器。
