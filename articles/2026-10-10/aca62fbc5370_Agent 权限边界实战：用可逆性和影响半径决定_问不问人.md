## 背景

OpenClaw 这类 agent 生态成熟后，工具调用已经不是瓶颈：MCP 接上文件系统、shell、浏览器、消息通道，插件把能力越挂越多。真正卡住落地的是另一件事——agent 到底哪一步该停下来问人。

## 问题

实践中反复出现两种失败模式：

- **过度请示**：每写一个文件都问"可以继续吗"。人类很快退化成无脑回 "y" 的橡皮图章，自动化价值归零，而这种批准习惯比不批准更危险。
- **过度自主**：agent "觉得有把握"就直接 push 到远端、给真实用户发消息、删数据、调付费 API。复盘会发现，出事从来不是模型能力不够，而是它做了一个本就不该由它做的决定。

关键认知：**问不问人，不该由模型的"自信心"决定，而该由动作本身的属性决定。**

## 做法：按"可逆性 × 影响半径"分级

把 agent 能触达的每个动作过一遍四个维度：是否可逆、是否离开工作区、是否花钱、对象是不是真人或生产环境，然后落成四档：

| 层级 | 典型动作 | 策略 |
|---|---|---|
| T0 | 读文件、检索、沙箱内草稿 | 直接干，不问 |
| T1 | 工作区内可逆写（编辑文件、建分支） | 直接干，落日志、事后可见 |
| T2 | 难回滚或离开工作区（push、装依赖、付费调用） | 先出 plan/diff，批准一次、整批执行 |
| T3 | 不可逆或外部副作用（删数据、发消息给人、动 prod、改权限） | 逐项确认，附 diff 和目标地址，超时默认拒绝 |

落地步骤：

1. **盘点工具清单**：列出当前挂载的所有 MCP tool 和插件，逐个标层级，没标的不许挂。
2. **在工具层强制执行**：T3 工具包一层确认 hook，或在 MCP 网关拦截。prompt 里写"执行前问我"只是建议不是边界——长上下文和压缩之后它会忘。
3. **用产物代替提问**：T2/T3 的确认必须带具体东西：diff、命令列表、目标 URL、预估费用。拒绝回答"我可以继续吗"这种空问题。
4. **批量确认只给 T2**：一组 T2 动作批一次没问题；T3 永远不许搭车。
5. **记审计日志**：每条自动执行、每次人工批准都落日志，月底看数据调阈值，而不是凭感觉放宽。

## 踩坑点

- **批准疲劳**：发现自己连续几天无脑回 "y"，说明阈值错了，先收紧再谈放宽。
- **把 prompt 当边界**：确认逻辑写在系统提示里，跑两周就失效，边界必须做在工具层。
- **字符串黑名单兜底**：正则拦 `rm -rf` 拦不住 `rm -fr` 和变量拼接。优先控制"这个工具根本挂不挂"，而不是匹配命令文本。
- **一次批准变永久授权**：会话里批过一次，agent 把它当成对该类动作的长期许可。批准应绑定到具体 plan，带过期时间。
- **静默即同意**：子 agent 自问自答、或把超时当默认通过。T3 超时必须默认拒绝。
- **环境漂移**：agent 分不清 dev 和 prod。用独立凭证和环境标记让工具层自己知道在哪个环境，别指望模型从 URL 里猜。

## 可复用建议

- 默认拒绝五类动作：花钱、触达真人、动 prod、碰密钥、不可逆删除。
- 与其纠结阈值，不如把动作做"可逆"：先建分支、带 dry-run、删除进回收站——可逆了就自动降到低层级。
- 收紧是配置问题，放宽要靠日志证据（例如"沙箱内 30 天 200 次删除零事故"）。
- 最小挂载：任务用不到的工具不挂。边界问题在挂载那一刻就已经解决了一半。

## 总结

权限边界不是"agent 聪明到什么程度可以放手"，而是每个动作的可逆性与影响半径。用分级把决策从"模型感觉"变成静态配置，把执行强制在工具层，用具体产物换人类批准，最后让审计日志驱动阈值演进。做到这四点，才敢真正放手让 agent 干它该干的活。
