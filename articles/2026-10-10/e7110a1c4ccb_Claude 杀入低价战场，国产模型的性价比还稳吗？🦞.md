最近 36kr 的热搜把不少人看愣了：Anthropic 的 Claude Haiku 5.5 延续这条产品线一贯的激进定价，把“小而快”的档位继续往下压。过去两年，“便宜大碗”几乎是国产模型的专属标签；如今海外大厂主动下场掀桌子，问题就变成了：国产模型的性价比叙事还站得住吗？这篇拆三件事：小模型战场为什么重要、API 价格是怎么定出来的、开发者怎么接住这波红利。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-10/6f0a7c4443b49ccd.png)

## 小模型，才是消耗战的主战场

- 看真实业务的流量分布就知道：生产环境里大部分请求是“低难度高频任务”——分类、信息抽取、改写、RAG 检索后的摘要、简单的工具调用。这类活儿不需要旗舰模型的智商，但胜在量大，token 费用随调用量线性堆叠。
- 所以小模型档位是各家 API 收入的基本盘，更是获客入口：开发者先用便宜模型把 pipeline 跑通，碰到硬骨头再切旗舰模型。入口一旦被占住，向上销售顺理成章。
- Haiku 这条线的打法很清晰：上一代 Haiku 4.5 已经做到 $1/百万输入 token、$5/百万输出 token，官方口径是编码与 agent 能力接近自家更高档的模型。小模型的能力天花板被蒸馏、合成数据、更优训练配方一路抬高，价格反而下探——真正让同行紧张的点是：不是“便宜的能用”，而是“便宜的很能打”。
- 回看历史，2024 年 5 月字节把豆包系模型打到“厘时代”（每千 token 不到一厘钱），掀起了国内第一轮价格战；两年后，战火烧到了海外厂商的价目表上。竞争姿态变了，故事也得重新讲。

## API 价格怎么定：一笔推理账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-10/7efc1099df990149.png)

模型 API 的成本结构并不神秘，大致由四块叠出来：

1. **算力底租**：GPU 采购或租赁的折旧，按小时烧钱；
2. **吞吐效率**：同样的卡，batch 调度、KV cache 管理、FP8 量化、投机解码做得好，单位 token 成本能差好几倍；
3. **架构红利**：MoE 稀疏激活、MLA 式的 KV 压缩、Prefill/Decode 分离部署，都是把成本曲线往下掰的手段——DeepSeek 敢连番降价，很大程度是架构层面省出来的；
4. **规模分摊**：请求量越大，卡越容易填满，空转率越低，边际成本越低。

看懂这四块，就能看懂价格战的两种姿势：海外厂商在成本之上留出可观毛利，降价属于让利换份额；而不少国产厂商过去是贴着成本甚至亏本定价，用价格直接换生态位。动作看起来一样，财务结构完全不同。

## 国产模型的性价比，还剩几张牌

把“性价比”拆开看，单价只是最薄的一层：

- **单价**：纯比 token 单价，国产模型多数档位仍然更低。换算一下，Haiku 系列输出 $5/M 约合每百万 token 三十多元人民币，而国产第一梯队旗舰的输出价大多在个位数到十几元之间。但价格是最容易被追平的东西——在 API 的世界里，唯一比模型降价更快的，是下一封调价邮件。
- **单位智能成本**：真正该比的是“每块钱买到多少能力”。小模型的编码与 agent 能力上来后，“便宜但凑合”与“贵但好用”之间的过渡地带被填平，国产模型原来的性价比舒适区被双向挤压。
- **非价格护城河**：数据合规与私有化部署、中文垂类语料的打磨、超长上下文定制、专属集群与 SLA、发票对账这类“企业服务的脏活”，以及与国产芯片的适配。这些短期卷不动，是比价格更稳的壁垒。
- **开源筹码**：DeepSeek、Qwen、GLM、Kimi 都开源了主力模型。开源权重意味着企业可以把 token 成本换成“电费 + 卡”的自建成本，这本身就是议价牌：你敢涨价，我就自己部署。

## 别只看单价：算一笔“单位智能成本”的账

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-10/e141e6387d6a26e8.png)

举个直观的例子：一个月跑 10 亿 token 的客服问答业务，假设全部按输出计价，用输出 ¥8/M 的方案是 ¥8000，换成输出 $5/M 的方案要三万多——单看这组数字国产优势巨大。但如果便宜模型答错率高 5%，多出来的人工复核和重跑成本，可能远超差价。所以选模型时，把账算细一层：

1. **输出膨胀**：同一个答案，有的模型 200 token 说完，有的啰嗦 400。输出单价贵一倍但话少一半，实际成本反而更低。
2. **缓存与折扣**：prompt cache 命中部分的价格常是原价的几分之一，batch 模式再打折——长 system prompt 的应用，这两项能省下 30% 以上。
3. **失败成本**：agent 场景里一次工具调用失败就是重跑一轮。能力差一截的“便宜”模型，重试成本可能把差价吃光。
4. **兜底链路**：省钱省出来的 bug，最后靠人工或旗舰模型收拾。省下的 API 费和多烧的工时，要放在同一张表里算。

## 收尾：三条冷思考

1. **架构先行**：把模型调用抽象成 router 层，小模型兜底、按需升级旗舰，provider 可热插拔。价格战的红利，属于那些随时能换模型的团队。
2. **用自家数据说话**：维护一个一两百条真实任务的评测集，每月重跑一次“价格-质量”曲线。榜单是别人的业务，评测集才是你的资产。
3. **拿住开源这张牌**：API 价格会波动，开源权重不会。关键链路保留自建推理能力，就是永远有效的议价筹码。

价格战里最难被甩开的，从来不是报价最低的那个，而是“单位智能成本 + 生态粘性”两条曲线都好看的那个。想明白这一点，热搜就不只是热搜。
