## 背景

OpenClaw-CN 社区每周都要产出技术周报、活动预告和新人指引，人工写帖重复度高。我们尝试用 OpenClaw 搭一个"发帖助手"：模型负责起草，流程负责把关。目标不是全自动发帖，而是把单篇帖子的人力成本从一小时压到十分钟以内。

## 问题

动手前明确了三个核心问题：

1. Agent 如何安全地对接社区发帖接口；
2. 如何拦截幻觉内容和重复内容；
3. 出错时如何快速回溯定位。

## 总体架构

五层结构：

- **触发层**：cron 定时任务，产出"写周报"事件；
- **智能层**：OpenClaw Agent，只负责生成草稿；
- **工具层**：自建 MCP Server 封装社区 API，只暴露三个工具：`query_topics`、`submit_draft`、`publish_post`；
- **安全层**：规则引擎，做标签白名单、长度、去重、链接校验；
- **存储层**：SQLite 记录每次工具调用与发布结果。

## 实施步骤

1. 先写 MCP Server，不动 Agent。用社区 API token 封装三个工具，`publish_post` 额外要求一个由人工审批产生的 `review_token`。
2. Prompt 约束输出为固定 JSON：标题、正文、标签、来源引用，标签只能从白名单里选。
3. 草稿生成后先过规则引擎：标签校验、正文长度、与近 30 天帖子的相似度比对（阈值 0.85）。
4. 通过后进入审批队列，人工确认后携带 `review_token` 调 `publish_post`，附带幂等键防止重复发布。
5. 所有工具调用写日志，含输入摘要与输出哈希。

## 踩坑点

- **第一版让 Agent 直接调发布接口**，结果一天内发出去两篇内容雷同的帖子。教训：发布动作必须与人工审批解耦，靠提示词约束 Agent 不可靠。
- **模型会"发明"不存在的标签和链接**。所有校验放在模型外的代码里，模型输出只当数据。
- **cron 默认 UTC**，社区在东八区，周报差点凌晨四点发出去。所有定时任务现在显式指定时区。
- **Agent 反复调用 `query_topics` 刷上下文**，排查后发现是工具描述写得太模糊。把每个工具的用途、参数、返回结构写清楚，并设置最大调用步数。
- **集中触发撞上 429 限流**，改成队列加指数退避。

## 可复用建议

- 原则一句话：**模型生成，代码裁决**。凡是对外发布的行为，裁决权在规则引擎和审批流手里。
- 发布接口一律幂等化，用幂等键兜底重试。
- MCP 工具粒度小而正交，宁可多两三个工具，也不要一个万能工具。
- 外部抓取的内容一律当作数据注入，不当指令执行，防提示注入。
- 新项目先跑"草稿模式"，观察两周再逐级放开权限。

## 总结

目前机器人稳定运行八周，周报起草时间降到十分钟以内，发布事故零次。回头看，价值不在于模型多聪明，而在于那些"不信任模型"的护栏设计。示例代码已放在社区仓库的 `mcp-examples` 目录，欢迎复用和拍砖。
