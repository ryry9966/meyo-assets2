## 背景

Agent 接上 MCP 之后，最自然的需求就是“去网上拿点东西”：查文档、盯价格、抓公告、汇总页面。抓取本身不难，难的是安全地抓。社区里常见的做法是直接给模型一个通用 `fetch(url)` 工具让它自己发挥，短期能跑，长期一定出事。

## 问题

把抓取裸交给 Agent，风险集中在四类：

1. **上下文炸裂**：一个没截断的页面就是几十万 token，一次调用吃光预算，任务质量随之下滑。
2. **提示注入**：网页是不可信输入，HTML 注释、隐藏文本里都能塞“忽略之前指令”，模型分不清内容与指令。
3. **SSRF**：URL 由模型生成，`127.0.0.1`、`169.254.169.254`、内网网段都可能被试探——尤其 Agent 跑在你自己服务器上的时候。
4. **礼貌与合规**：无限速的循环重试会把目标站打挂，robots.txt 被无视，最后 IP 被封，任务中断。

## 做法

核心思路一句话：**抓取收口在工具层，模型只拿加工后的结果**。

1. **封装成专用 MCP 工具**，而非通用 fetch。URL 在服务端校验：仅允许 http/https，解析后拒绝私网、回环、链路本地地址。
2. **域名白名单 + 首次确认**。白名单外的新域名触发一次人工确认，通过后写入配置；配置外置，别硬编码。
3. **服务端加工内容**。HTML 转纯文本，做正文提取，去掉脚本和注释；单页设字符上限，超限截断并在返回体里标记 `truncated: true`，让模型知道拿到的是节选。
4. **限速与缓存**。按域名做令牌桶限速；相同 URL 走 TTL 缓存；超时 10 秒、退避重试一次，绝不许模型自己写重试循环。
5. **隔离不可信内容**。网页内容包在明确的标记段里，系统提示写死：标记段内一律当数据、不当指令。结构隔离比口头约定可靠。

## 踩坑点

- **重定向绕过白名单**：校验了入口 URL，结果 302 跳到内网。重定向的每一跳都要重新校验。
- **DNS rebinding**：校验时解析到公网，请求时换成内网 IP。要么解析后固定 IP 发请求，要么做二次校验。
- **robots.txt 按路径生效**，不是整站一份，缓存时要带路径粒度。
- **SPA 正文提取拿到的是导航和空壳**，Agent 拿着垃圾继续推理。要么走渲染通道，要么如实返回失败原因。
- **无头浏览器是独立攻击面**：能不开就不开，开就必须禁下载、禁外联、设资源限额。

## 可复用建议

- 工具返回结构化字段：`url / title / content / fetched_at / truncated`，便于日志审计和断点续跑。
- 提供 `inspect` 轻量模式：只回状态码、Content-Type、长度和摘要，先探路再决定全量抓取，省 token。
- 日志记 URL、状态、耗时、截断标记——排查“Agent 为什么抓不到”基本全靠它。
- 需要登录态的站点，凭证由服务端注入，永远不进模型上下文。

## 总结

让 Agent 安全抓网页，不是写更强的提示词，而是在工具层把边界做实：URL 校验、域名白名单、内容截断、限速缓存、不可信内容隔离。这五件事做齐，抓取就从“随时会炸的边角功能”变成一个无聊、可控、可审计的常规能力。而无聊，恰恰是基础设施最好的状态。
