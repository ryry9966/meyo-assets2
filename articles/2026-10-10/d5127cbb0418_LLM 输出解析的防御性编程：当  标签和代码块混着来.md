## 背景

在 OpenClaw 插件和 MCP 工具链里，让模型返回结构化数据是常态：工具调用参数、子 Agent 汇报、审批卡片，最后都压在一次 `json.loads` 上。理想情况用 JSON mode 或 `response_format` 兜住，但跨模型、跨网关、跨版本时约束并不总生效，于是很多实现退回“提示词 + 包裹标签”：要求模型输出 `<json>...</json>` 或 ```json 围栏。

问题在于模型不永远守约。同一份提示词，今天输出标签包裹，明天输出裸 JSON，后天标签外多一段“好的，以下是结果：”。解析层必须按最坏情况设计。

## 做法：五层降级链

核心思路是**提取 → 解析 → 校验**三段分离，提取层做逐层降级：

```python
def extract_json(text: str):
    # 1. 快路径：整段直接解析
    try:
        return json.loads(text), "direct"
    except JSONDecodeError:
        pass
    # 2. 标签提取：容忍大小写、属性、空白
    m = re.search(r"<\s*json[^>]*>(.*?)</\s*json\s*>",
                  text, re.I | re.S)
    if m:
        return try_parse(m.group(1).strip()), "tag"
    # 3. 围栏提取：```json ... ``` 或裸 ```
    # 4. 括号配平扫描：引号感知地找首个 { 或 [，数深度取平衡子串
    # 5. 修复：去尾逗号、中文引号转半角，最后再试一次
    return None, "fail"
```

每层命中即返回，同时带上策略名。上层拿到 `(data, strategy)` 后再做 schema 校验（pydantic/zod），解析成功不等于字段合法。

## 踩坑点

- **贪婪匹配**：`(.*)` 会把两个代码块之间的说明文字一起吞掉，必须非贪婪 + `re.S`。
- **标签出现在字符串值里**：JSON 内容含 `"</json>"` 时正则会提前截断。标签提取失败时用括号扫描交叉验证一次。
- **few-shot 复读**：提示词示例里写了 `<json>{...}</json>`，模型可能原样输出两份。取能通过校验的那个，而不是第一个。
- **修复要克制**：尾逗号、中文引号可以修；“自动补全括号”不要做——半截输出语义多半已残缺，触发重试比硬修可靠。
- **别信任 JSON mode**：部分网关会静默忽略 `response_format`，降级链永远留着。

## 可复用建议

- 把提取逻辑做成 SDK 层公共函数，所有插件共用，别各写各的正则。
- 策略名进日志并做指标：fallback 命中率突然升高，通常是提示词被改或模型版本换了，比用户报错更早暴露。
- 流式场景下括号不配平先缓冲，别解析半成品。
- 提示词侧配合：明确“标签外不要输出任何内容”，示例 JSON 换种包裹方式避免被复读。

## 总结

防御性解析的本质不是让解析器更聪明，而是承认“格式不确定”是常量：用一条固定顺序的降级链消化它，用策略标签和命中率让不确定性可观测。解析层稳了，上层 Agent 的重试逻辑才有意义。
