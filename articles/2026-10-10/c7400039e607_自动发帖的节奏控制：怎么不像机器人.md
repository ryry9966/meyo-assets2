## 背景

在 OpenClaw 生态里，用 Agent + MCP 接社区发布通道是很常见的自动化场景：把构建日志生成周报、将 issue 摘要同步到板块、定时放出教程草稿。管道跑通很容易，难的是跑起来之后——单条内容没问题，但账号整体的行为模式一眼就是机器。

## 问题：机器味从哪来

机器味通常不在内容本身，而在时间序列和交互结构上：

- **固定 cron**：每 2 小时整点发一条，时间戳分布过于规整；
- **突发连发**：Agent 一批任务跑完，5 条帖子 3 分钟内排队挤出；
- **结构雷同**：每条都是同样的开头、长度和结尾 CTA；
- **不看语境**：社区刚发大公告，它还按计划推无关内容；评论区有人提问，它从不回复。

结果轻则被折叠限流，重则被当成 spam 清理，连累整个插件的可信度。

## 做法：四层节奏控制

我们在 OpenClaw-CN 的发帖插件里做了四层处理：

**1. 时间层：抖动 + 预算。** 发布窗口限制在目标读者时区的活跃时段，在窗口内按历史活跃热区采样，再叠加 ±20~40 分钟抖动。同时设每日预算（1~3 条），并允许某些天发布量为 0——“今天没东西值得发”本身就是人类行为。

**2. 节流层：队列 + 最小间隔 + 合并。** 出站帖子先进队列，强制最小间隔（≥90 分钟），每小时/每日上限硬截断。同一主题的多条更新自动合并成一条 digest，而不是连发：

```python
def should_post(now):
    if in_quiet_hours(now):        return defer()
    if sent_today() >= DAILY_BUDGET: return merge_into_digest()
    if now - last_post < MIN_GAP + jitter(): return defer()
    if channel_has_major_event():  return defer()
    return send()
```

**3. 内容层：模板方差 + 人工闸门。** 准备 3~5 套开头结尾模板轮换，长度自然浮动，外链帖子比例设上限。低置信度或敏感主题强制进人工审核队列，Agent 只产出草稿。

**4. 反馈层：先读再写。** 发布前用 MCP 只读接口拉频道最近 N 条消息：刚有大公告或正在讨论相关话题就推迟或改写角度；上一条帖子的回复没处理时，优先回复而非发新帖。我们内部大致守 1:3——每 1 条主动广播，至少对应 3 条互动。

## 踩坑点

- **均匀随机抖动没用**：`random.uniform(0, 30min)` 叠在整点 cron 上，分布统计上还是一眼假，要用真实活跃时段的分布采样。
- **队列报复性倾泻**：只加最小间隔没加每日上限，攒一夜的帖子早上按最小间隔连发，比不加还难看。
- **时区错位**：服务器 UTC、读者在 UTC+8，“活跃时段”全错。时区必须是每个频道的显式配置。
- **重试导致双发**：网络超时重试没做幂等，同一条内容出现两次。发布调用必须带幂等键，先落账本再返回成功。
- **别去“演人类”**：故意打错字、模拟在线时间这类方向我们碰了一下就停了。目标是守规矩、有节制，不是伪装身份——伪装被识破的信任损失远大于限流。

## 可复用建议

- 所有节奏参数（预算、间隔、静默时段、外链比例）进配置文件，按频道独立设置，不硬编码；
- 维护发布账本（时间、触发源、内容哈希、状态），排查“为什么这个点发了这条”全靠它；
- 上线先跑 shadow 模式：所有“要发”的帖子只写日志不出站，人工看一周节奏曲线再放开；
- 监控互动指标而非只看发帖成功率：回复率持续走低，就是节奏或内容出问题的最早信号。

## 总结

自动发帖的“机器味”，本质是对社区注意力的不尊重：不挑时间、不看来量、不做回应。四层控制——时间预算、队列节流、内容方差、先读后写——没有一层是黑科技，都是把“替读者着想”翻译成约束条件。目标不是把机器人化妆成人，而是让自动化像一个守规矩、有节制的成员那样工作。做到这一点，坦荡标明“本帖由 Agent 生成”也不会招人烦。
