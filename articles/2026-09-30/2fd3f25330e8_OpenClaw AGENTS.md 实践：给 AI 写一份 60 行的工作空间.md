## 背景

OpenClaw 的 agent 每次新会话启动时，都会先读工作空间里的一组 markdown 文件。其中 `SOUL.md` 管人格和语气，`USER.md` 管用户画像，`MEMORY.md` 管长期记忆，而 `AGENTS.md` 管的是最实际的一层：AI 在这台机器上怎么干活。可以把它理解成岗位作业指导书——不谈性格，只谈操作规范。

## 问题

不写或乱写 AGENTS.md，常见症状有三个：

1. **行为漂移。**今天把临时脚本放 `~/tmp`，明天放桌面，后天直接写进仓库根目录，每次都要口头纠正。
2. **边界模糊。**哪些命令可以直接跑、哪些要先确认、哪些碰都不能碰，全靠模型当场发挥。
3. **规则散落。**纠正记录散在聊天历史里，新会话一开，一切归零。

本质上是把"团队规范"寄托在模型记忆上，而不是沉淀在文件里。

## 做法

我的 AGENTS.md 稳定在 60 行左右，分四段：

**一、工作空间地图。**每个目录一句话职责，比如 `notes/` 只放当天笔记，`scripts/` 只放可执行脚本，命名统一 kebab-case。

**二、事实卡。**时区、常用路径、默认语言——每条会话都用得到又懒得重复说的信息。

**三、工具规则。**shell 命令分级：只读命令直接执行；写文件的先说明意图；涉及网络请求、删除、`sudo` 的必须先确认。

**四、红线。**NEVER 级条款：不删 `MEMORY.md`，不在配置文件里明文写密钥，不主动 git push。

写法上有两条经验：用祈使短句，别写长段落；关键动词用 MUST/NEVER 这类强标记，遵从度明显高于"建议""尽量"。

## 踩坑点

- **写太长等于没写。**第一版我写了 200 多行，表面上全收，实际注意力被稀释，红线照样踩。裁到 60 行后执行率反而上去了。
- **职责别越界。**"回复要简洁"属于 SOUL.md，写进 AGENTS.md 会和人格设定打架，规则冲突时模型行为很随机。
- **否定规则要给替代动作。**只写"NEVER rm -rf"，AI 遇到清理需求会卡住或换更糟的姿势；改成"NEVER 直接删除，先 mv 到 `trash/`"就顺了。
- **别写敏感信息。**AGENTS.md 全文进上下文，密钥、内网地址写进去等于每次会话暴露一次。
- **改完要新开会话验证。**已有会话仍持有旧版本内容，别误判成"没生效"。

## 可复用建议

1. **口头纠正沉淀成条款。**同一个错误纠正到第二次，就该写进 AGENTS.md 了。
2. **定期反向裁剪。**每月删掉 AI 已稳定做到的条目，手册越短越有力。
3. **分两层，别互相复制。**工作区层写"这台机器"的规则；项目仓库自己的 AGENTS.md 写"这个项目"的规则，子代理进入仓库时自然叠加。
4. **让 AI 参与维护。**我加了一条：发现规则冲突或缺失时主动提议修订，然后我像 review 代码一样 review 它的 diff。
5. **用例子代替描述。**一条"标准的任务完成样例"，比十行抽象描述都管用。

## 总结

AGENTS.md 是工作空间里杠杆最高的文件之一：一小时的投入，换掉之后每次会话的重复沟通。它不是一次性配置，而是需要版本化、定期裁剪的活文档。如果你还没写，建议今晚就从"红线"那一段开始——那是最便宜的安全带。
