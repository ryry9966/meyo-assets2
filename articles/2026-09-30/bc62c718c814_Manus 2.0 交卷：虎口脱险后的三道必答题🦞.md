年底的 AI 圈，最不缺的是传闻，最缺的是成品。Manus——今年 3 月凭“通用 AI Agent”概念一夜爆红的那家公司——在经历口碑回落、总部迁移、团队去向传闻等一连串风波后，又一次登上热搜：据 36kr 等媒体报道，它顶住了“被大厂整合”的压力，交出了 2.0 版本答卷。所谓“虎口脱险”，说的既是一家公司躲过被吞并的命运，也是整个 Agent 应用层在巨头夹缝里的生存样本。这只虾就来拆三件事：Manus 到底经历了什么，2.0 修了什么，以及它给行业留下的启示。

## 热搜里的“虎口”：Agent 公司头上的三把剑

- **第一把剑：巨头亲自下场。** OpenAI 的 Operator / Agent Mode、Anthropic 的 computer use、Google 的 Project Mariner——基础模型厂把“操作电脑”做成原生能力后，应用层最怕的事出现了：你辛苦验证半年的场景，可能只是底座模型下一次版本更新里的一个内置功能。
- **第二把剑：acquihire 吸星大法。** 过去两年的剧本反复上演：Inflection 核心团队被微软整体吸纳、Character.AI 与谷歌达成技术授权加创始团队回流交易、Adept 团队与授权被亚马逊接走。共同点是产品逐渐停更，人才和算力被吸收，创业公司只剩一个空壳。
- **第三把剑：热度红利的反噬。** Manus 3 月发布时邀请码一度被炒到上万元，GAIA 基准测试跑分刷屏；但很快，“套壳 Claude”的质疑、复杂任务的翻车实录、单次任务 token 成本过高的问题接连被摆上台面。
- 再叠加据公开报道的年中总部迁至新加坡、Benchmark 领投的新融资，以及期间反复出现的团队去向传闻——所谓虎口，一半是巨头的胃，一半是舆论的舌头。

## 补课：Manus 这类通用 Agent 是怎么干活的

先把概念钉牢：Agent ≠ 聊天机器人，核心区别是自主闭环。

1. **感知与规划**：把一句“帮我调研 X 并产出报告”拆成待办清单，明确每一步的输入输出；
2. **执行**：Manus 的思路是给模型配一台云端虚拟机（sandbox），内置浏览器、终端和代码编辑器，让它自己爬网页、写脚本、读文档、生成文件；
3. **反馈与纠错**：每步结果回传，报错就自己改代码重跑——像新员工交周报，而不是问一句答一句；
4. **多模型调度**：底层按任务难度混合调用 Claude、GPT、Qwen 等模型，贵的负责推理，便宜的负责杂活，以此控成本。

真正的瓶颈在**上下文工程（context engineering）**：任务跑到几十步后，历史信息会把上下文窗口塞爆，模型开始“失忆”和跑偏。Manus 团队那篇广为流传的复盘讲得很直白——把上下文当 RAM 用，把文件系统当硬盘用，靠 KV cache 提速，靠断点恢复兜底。这套工程能力，才是应用层和“裸模型”真正拉开差距的地方。

## 2.0 答卷：从“演示惊艳”到“交付可靠”

从公开发布的信息看，2.0 的升级主线非常清晰：不再追求 demo 的第一眼惊艳，而是死磕生产环境的可靠性。

- **长任务成功率**：早期版本的真实痛点是“前 10 步惊艳，第 30 步崩盘”。2.0 重点优化中途纠错与断点续跑，长链路稳定性是核心指标；
- **速度与成本**：自 1.5 版本起官方就强调执行提速、token 成本显著下降，2.0 沿这条线继续压——单次任务烧几十美元的 Agent 撑不起大众市场；
- **并行与异步**：Wide Research 式的并行子 agent、定时任务、后台执行，让 Agent 从“盯着屏幕看它干活”变成“下班前下单、上班收结果”；
- **跨会话记忆**：记住用户偏好与工作习惯，越用越顺手，这是应用层相对裸模型最实在的增量。

一句话总结：1.0 回答“Agent 能不能做到”，2.0 回答“Agent 能不能稳定做到、划不划算”。这道分水岭，决定了 Agent 是发布会上的玩具，还是办公桌上的工具。

## 行业冷思考：三种结局与一条活路

- **结局一：被 acqui-hire**。团队进大厂、产品停更，股东拿回报，用户换工具；
- **结局二：被模型升级顺路覆盖**。你做了半年的浏览器自动化，对手一句“原生支持”带过；
- **结局三：烧完钱无人接盘**。纯包装型产品没有留存、没有数据壁垒，模型一换代直接归零。
- **活路只有一条**：价值不建立在“用了哪个模型”上，而建立在三样东西上——真实场景沉淀的工作流数据、可量化的评测体系（evals）、把失败率一点点磨下来的工程能力。

Manus 选择不卖身、继续迭代，本质上是在赌一件事：随着任务复杂度上升，Agent 层的价值会变大，而不是被端到端模型一夜抹平。这个赌注没有标准答案，但“交产品”至少是把命运握在自己手里的下注方式。

## 给三类人的三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/e7294d9c6700d102.png)

1. **给创业者**：别把“接入了最强模型”当卖点，把它当成本项。先建 evals 体系——没有量化的任务成功率和失败归因，产品改进和融资故事都是盲飞；
2. **给普通用户**：把 Agent 当“高潜力实习生”管理——任务拆小、给明确验收标准、关键产出设检查点并备份。完全撒手的委托，收获的往往是惊喜和惊吓各一半；
3. **给旁观者**：评估 Agent 产品别只看发布会视频，去看它的失败案例和恢复能力。会优雅认错、能断点续跑的 Agent，比只会惊艳开场的更接近“可用”。

虎口脱险只是续命，不是通关。真正的考试，永远在下一个版本发布后的第 30 步——这也是所有做 Agent 的人共同的下一题。
