# 背景

OpenClaw 的 workspace 里，除了大家熟悉的 AGENTS.md 和 MEMORY.md，还有一个容易被忽视的文件：USER.md。每次会话启动时它会作为上下文注入，Agent 读到的第一批信息里，就有“你是谁”。

我的场景很典型：每天通过多个入口（CLI、Web、定时任务）调用同一个 Agent。不写 USER.md，每次都要重复交代技术栈、代码习惯、输出偏好；写好之后，冷启动成本基本归零。

# 问题

实践中 USER.md 常被写成两种失败形态：

1. **空白或一句话**。等于没写，Agent 还是靠猜。
2. **许愿池**。堆几百行“我希望你……”，关键偏好被稀释，该记住的还是没记住。

还有隐性风险：workspace 可能被 MCP 工具、插件、shell 命令读取。USER.md 里写什么，等于主动披露什么。

# 做法

**第一步：划清边界。** 三个文件各司其职：AGENTS.md 管行为规范（怎么干活），MEMORY.md 管动态记忆（最近发生了什么），USER.md 只放**关于你的稳定事实**。凡会过时的内容，一律不进 USER.md。

**第二步：按结构写。** 我目前的模板：

```markdown
# 用户档案
## 环境
- 时区 UTC+8，macOS + Linux 服务器
- 技术栈：Python / TypeScript，编辑器 VS Code
## 偏好
- 回答先给结论，细节放最后
- 代码示例给可运行的最小片段
## 边界
- 不要主动重构我没问的代码
- 不确定时先问，不要猜我的意图
## 当前阶段
- 正在做某项目的 MCP 接入，目标月底前完成
```

**第三步：控制体量。** 实测 40 行以内效果最好。USER.md 看密度不看长度——每一条都应该能在具体对话中被“用上”。

**第四步：建立更新机制。** 让 Agent 在对话中发现稳定的新信息（比如你换了主力语言）时**提议**增补，由你确认后写入；“当前阶段”每月手动 review 一次。workspace 用 git 管理，每次改动都有 diff 可查。

# 踩坑点

- **时效内容混进来**：“这周在赶版本”写进去，两周后就是误导。动态的事归 MEMORY.md。
- **写成指令**：“永远用中文回复”是行为规范，该去 AGENTS.md。职责混了，排查时很难定位是哪条在生效。
- **敏感信息过度披露**：真实姓名、公司名、服务器 IP 都没必要。Agent 需要的是“偏好和约束”，不是身份证明。
- **人设写太满**：详细到性格、情绪的描述会让 Agent 过度迎合，输出反而变软。

# 可复用建议

1. 把 USER.md 当配置文件维护：版本化、小步提交、定期 review，而不是一次性文案。
2. 增删条目时自问：这条信息下次对话能被实际引用吗？不能就删。
3. 多入口场景（CLI + 定时任务）下，先在低风险任务上验证效果，再逐步放开。

# 总结

USER.md 是典型的低成本高杠杆 context 工程：几十行稳定事实，换来每次会话零冷启动。核心原则三条——只放稳定事实、控制信息密度、与 AGENTS.md / MEMORY.md 严格分层。它不是让 Agent“显得懂你”，而是把本来靠猜的部分，变成一份可 review、可 diff 的显式配置。
