## 背景

主会话跑得越久，上下文越臃肿。把独立任务委派给子 Agent 是常规解法：主 Agent 拆任务、发指令，子 Agent 在自己的 session 里干活，完成后只交回结果。OpenClaw 支持在会话内派生子 Agent（自带独立 session），听起来很干净——但实际用起来，“隔离”并不是开一个开关就完事。

## 问题：污染有三种形态

实践中踩过的污染主要有三类：

1. **上下文污染**：子 Agent 的完整过程记录（工具调用、重试、冗长输出）被合并回主会话历史，token 暴涨，主 Agent 还会被无关中间步骤带偏节奏。
2. **状态污染**：子 Agent 往共享文件里写东西——memory、TODO、笔记，最典型的症状是打开主 memory 文件，发现里面混着子 Agent 的草稿。
3. **工具状态污染**：有状态的 MCP server（比如浏览器会话、已登录的连接）被子 Agent 改了状态，主流程接着用就出幺蛾子。

如果只做了一层 session 分离，后两类照样发生。

## 做法：四个动作

**1. 独立 session 启动，不继承历史。** 派生时确认子 Agent 拿到的是全新上下文，注入的只有任务简报和必要的文件路径。有些派生模式默认“复制当前历史给子 Agent 当背景”，这是污染的头号来源，务必检查。

**2. 约定返回格式。** 子 Agent 只返回结构化摘要：结论、产物路径、异常。原始过程记录留在它自己的 session 里，主 Agent 不接收全文。

**3. 工作目录做命名空间。** 给每个子 Agent 分配独立 scratch 目录，如 `workspace/sub/<task_id>/`；共享文件对子 Agent 一律只读。示意配置：

```yaml
subagent:
  session: isolated        # 不继承主会话历史
  context: brief_only      # 只注入任务简报
  workspace: workspace/sub/${task_id}
  return: summary_json
  tools: [fs:rw@own_workspace, web:ro]
```

**4. 收窄工具与凭证。** 子 Agent 只拿完成任务所需的最小工具集；有状态的 MCP server 尽量按 session 实例化，或者直接禁止子 Agent 触碰改状态的工具。

## 踩坑点

- **memory 路径没覆盖**：框架默认 memory 写入路径是全局的，子 Agent 一调用就往主 memory 追加，记得显式覆写。
- **并发写冲突**：两个子 Agent 写同一个文件，用 per-task 目录 + 唯一 ID 规避。
- **无退出条件**：子 Agent 陷进循环烧 token，设置最大步数或 token 预算。
- **环境变量整包继承**：密钥跟着 env 全量下发到子 Agent，按需传递。

## 可复用建议

派生子 Agent 前过一遍三问：**它需要什么上下文？它往哪写？它用哪些工具？** 三个答案都收窄了，隔离基本就到位了。再配合两条习惯：共享资源默认只读；主会话定期 diff 一下 memory 和共享目录，发现污染趁早回滚，别等它发酵。

## 总结

session 隔离不是一个开关，而是三个平面的事：**上下文隔离**（只给简报）、**状态隔离**（独立目录、共享只读）、**工具隔离**（最小权限、无状态优先）。在派生时花五分钟配好，比事后清理一次污染便宜得多。子 Agent 的价值在于“干完就走”——让它把过程留在自己屋里，只把结果递出门。
