今年的 OpenAI DevDay，台上出现频率最高的词不是 GPT，而是 Agent。从 AgentKit 工具链到对话内应用（Apps in ChatGPT），从实时语音模型到 Sora 2 开放 API，OpenAI 把叙事从"更大的模型"切换到了"能干活的智能体"。ChatGPT 周活跃用户已接近 8 亿，但 OpenAI 想讲的下一章不是"更多人聊天"，而是"更多 agent 替人干活"。这篇文章把大会重点拆开：发了什么、Agent 的原理是什么、为什么偏偏是现在，以及落地前要避开的坑。

## 这次 DevDay 到底发了什么

先上干货清单：

- **AgentKit 全家桶（本次核心）**：Agent Builder——可视化拖拽编排 agent 工作流，官方演示里像画流程图一样"画"出一个 agent；ChatKit——可嵌入自家产品的聊天界面组件；Evals——专门评测 agent 的工具，支持对工具调用、多轮对话逐步打分；Connector Registry——企业统一管理内外部数据连接器的注册中心。
- **Apps in ChatGPT / Apps SDK**：第三方应用直接嵌进 ChatGPT 对话里运行，底层协议是 MCP。首批合作方包括 Booking.com、Canva、Coursera、Figma、Expedia、Spotify、Zillow 等。预览期免费，商业化后续开放。
- **模型与基础能力**：GPT-5 Pro 上线，gpt-realtime 与 gpt-realtime-mini 实时语音模型开放 API，Sora 2 开放 API，Codex 宣布 GA（正式商用）。
- **一个容易被忽略的信号**：OpenAI 提到未来会试验"按用量/按效果"的计费方式。平台方开始为 agent 的"完成结果"定价，而不只是按 token 收租——商业模式跟着技术叙事一起换挡。

一句话总结：模型是发动机，这次发布的全是底盘、方向盘和仪表盘。

## Agent 和聊天机器人，差的不只是"多聊几句"

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/c6682a8ecfe65049.png)

把 Agent 理解成"更聪明的客服"，就偏了。两者的差别在结构上：

- **聊天机器人**：一问一答，输出即终点。没有工具，没有状态，任务边界就是你这句话。
- **Agent**：目标驱动 + 工具调用 + 多步循环。核心是一个 loop：接收目标 → 拆解计划（planning）→ 调用工具（function calling、浏览器、代码执行）→ 观察返回结果 → 修正策略 → 循环，直到达成目标或触发熔断。
- 拆开看有四个部件：**大脑**（LLM 负责推理和决策）、**手**（tools + MCP，连接数据库、API、浏览器等外部系统）、**记忆**（上下文窗口加向量库，让长任务有连续性）、**缰绳**（guardrails 和人工审批，约束它别乱来）。

举个例子：让 agent"把这季度财报里的同比数据核对并画成图"。它会自己读文件、写脚本、跑数字，发现两处口径对不上，回头重查原始表格，最后交付图表和核对说明——中间不需要人盯着每一步。聊天机器人做不到，因为它没有"手"，也没有"回头"。

MCP 是这轮生态的关键零件：它把"模型怎么调用工具"标准化成了开放协议，地位类似 AI 时代的 USB-C。有了统一插口，工具生态才从 M×N 的定制适配，变成 M+N 的即插即用。

## 为什么是现在：三块拼图凑齐了

Agent 概念不新鲜——2023 年 AutoGPT 就火过一轮，然后迅速哑火。这次不一样，因为三块拼图同时到位：

1. **大脑够用了**。o 系列和 GPT-5 这类推理模型，在多步规划和工具调用的可靠性上有台阶式提升。上一波 agent 死就死在模型"想三步就迷路"。
2. **协议统一了**。MCP 在 2024 年开源后快速成为行业默认，这次 Apps SDK 直接建在它上面。标准化的意义，是让全行业替你修路。
3. **账算得过来了**。主流模型 API 价格两年降了约一个数量级，长上下文普及，多步循环的 token 消耗才变得经济上可行。

再加上这两年业界踩坑攒出的 evals、可观测性、权限管理经验，基建齐了，闸门才敢开。

## AgentKit 的野心：开发工具 + 分发入口，两头卡位

看懂 AgentKit，要看它的商业位置，不只是"又一套 SDK"：

- **Agent Builder** 把 LangGraph 这类编排框架产品化，门槛从"会写代码"降到"会画流程图"。这是在抢 agent 时代的 IDE。
- **Evals 是隐藏重点**。agent 最痛的不是写不出来，而是"改了一版，不知道变好还是变坏"。Evals 支持端到端评分 + 逐步 trace 评分，甚至可用第三方模型当裁判——把评测做成标配，等于替行业补上质量体系。
- **Apps in ChatGPT** 则是对话内的应用分发入口，相当于在 8 亿周活的对话流里开了一个"应用柜台"。

一头做开发工具，一头做分发入口，两头一起收——典型的平台打法。对开发者来说，机会和依赖同时到货。

## 冷启动现实：落地前先看清四个坑

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/f9d1053d4a477c90.png)

1. **可靠性会连乘**。单步准确率 95% 的任务，串联 20 步后整体成功率只剩约 36%。所以关键节点要设 checkpoint 和人工审批，"全自动"是营销词，不是工程词。
2. **没有评测就别上线**。先建 eval 数据集和基线，再迭代功能。没有 eval 的 agent，等于没有测试的代码——你只是在赌运气。
3. **安全是一等公民**。prompt injection、工具越权、数据外泄，是 agent 特有的攻击面。工具权限最小化、敏感操作二次确认、日志全量留痕，三件套不能省。
4. **成本按任务算，不按调用算**。一个任务可能烧掉几十次模型调用，先算清单任务成本和失败重试成本，再谈 ROI。不少团队死在"演示惊艳、账单吓人"上。

## 收尾：三条冷思考

1. **别急着推翻现有产品**。agent 适合"多步、可验证、高频重复"的流程——代码审查、数据处理、工单分派都是好靶子。先垂直深挖，再谈通用。
2. **工具设计比 prompt 调优更值钱**。命名清晰、参数 schema 规整、报错信息可读的工具，对成功率的提升远大于玄学调 prompt。Agent 的上限，取决于你给它造的钳子好不好用。
3. **红利与依赖并存**。Apps in ChatGPT 是新的分发入口，但规则和抽成权在平台手里。自己的数据、用户关系和场景理解，才是搬不走的护城河——别把整栋房子盖在别人家的地基上。

Agent 时代的入场姿势就一句话：让模型长出手，缰绳握在自己手里。
