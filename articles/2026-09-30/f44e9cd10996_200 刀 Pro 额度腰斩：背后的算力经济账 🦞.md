2024 年 12 月，OpenAI 推出 200 美元/月的 ChatGPT Pro，当时的卖点是让重度用户"近乎无限量"地使用最强推理模型。一年多过去，据 36kr 等媒体报道，这个套餐在改版重启之际额度被大幅下调——社区俗称"腰斩"，全球开发者论坛骂声一片。骂完之后，问题依然值得认真拆：无限量为什么撑不住？钱烧在哪？开发者真正在气什么？RY哥这篇就掰开揉碎，讲讲这条算力经济账。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/d5c1f533da5e02b4.png)

## 先对齐事实：这张 200 刀的票经历了什么

- **2024.12**：ChatGPT Pro 上线，主打 o1 pro mode，官方口径接近 "unlimited access"，附带 Sora 等额外权益；
- **2025 上半年**：Pro 用户开始零星报告"触顶"；o1-pro 开放 API 后定价 150 美元/百万输入 token、600 美元/百万输出 token，是同期普通模型的 10~30 倍；
- **GPT-5 Pro 时期**：订阅档引入更复杂的额度规则，按"任务复杂度"动态扣减；
- **最近**：改版重启，Pro 档额度据称明显缩水，重度用户一天几次 Pro 级推理就可能到顶。

一句话总结：从"无限量"到"限量供应"，不是某次运营失误，而是两年来定价故事被算力现实反复修正的结果。

## 烧钱点一：推理模型的"思考"是按 token 计费的黑箱

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/0ac2dc5f3df4a5b0.png)

- **普通模型**：你问一句、它答几百字，成本大头在可见输出；
- **推理模型**：回答前先生成成千上万条不可见的"思考 token"（chain-of-thought）。这些 token 照样占 GPU、照样计费，只是用户看不见；
- **Pro 档更狠**：对同一道题做多次并行求解再择优（best-of-N + grader），一次提问 ≈ N 次推理，成本直接乘以 N；
- **参考数据**：Arc Prize 团队评测 o1 pro mode 时，测得单题成本最高约 20 美元；同期的普通问答一次只要几美分——三个数量级的差距；
- **算笔账**：一个重度用户一天跑 10 次 Pro 级推理，就算单次摊薄成本 2 刀，一个月就是 600 刀。订阅费 200 刀——卖一单亏一单，用得越多亏得越狠。

这就是"无限量"在数学上不成立的根源：订阅制的隐含假设是边际成本趋零，而顶级推理模型的边际成本是实打实的美元。

## 烧钱点二：算力池子就那么大，先喂给谁是个排序题

- 大模型推理的硬约束是 GPU 与电力：H100/B200 的产能、数据中心的建设周期，都以"年"为单位，不是加钱就能立刻变出来的；
- OpenAI 背着巨额算力合约和数据中心扩建计划，每一张卡都要在 API 收入、企业大单、订阅用户三方之间做分配；
- 排序逻辑很朴素：API 和企业客户按用量计费，毛利可算、可预测；订阅是固定月费，重度用户占比越高、亏损越大——经济学上这叫**逆选择（adverse selection）**：最能薅的，恰恰是最活跃的那批人；
- 于是"降订阅额度、保 API 供给"不是技术翻车，而是把有限算力优先换成能按 token 收钱的需求。

一句话：薅羊毛的羊毛，最终都出在 GPU 身上。

## 开发者在骂什么：不是 200 刀，是不可预期

- 对普通用户，额度调整是体验问题；对开发者，额度是生产资料。不少团队把 Pro 档当"性价比 API"跑 agent、批量代码审查、数据分析——额度一腰斩，工作流直接断电；
- 更难受的是黑箱：不公布具体次数、按"复杂度"浮动计费，等于让团队在没有仪表盘的情况下编预算。比如一个 nightly agent 每晚扫 200 个 PR，规则一变，第二天早上全队等米下锅；
- 横向对比：Anthropic 的 Claude Max（200 刀档）主打高额度编码场景，Google AI Ultra 定价 250 刀——头部厂商都在转向"高价 + 显性额度"划档，200 刀早就不是"无限"的同义词；
- 根本矛盾：订阅制天然适合边际成本趋零的产品（视频、音乐都是这个逻辑），前沿推理模型恰恰相反。拿卖会员的思路卖超算，迟早要在"营销承诺"和"电表读数"之间二选一。

## 三条实用建议：把额度焦虑翻译成架构问题

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/961642fa61252749.png)

1. **重度负载走 API + 用量预算**：把 reasoning effort、上下文长度、调用频率做成可配置项，按任务难度分级调度——简单问题低档跑，难问题才动用大算力，让每一分钱花在刀刃上，而不是风扇上；
2. **订阅当试驾，别当生产管线**：Pro 档适合探索、原型和有人工审核的高质量场景；任何无人值守、批量执行的流程，都应该落在 API 或自托管上，避免额度一变就停机；
3. **保持多模型冗余**：核心管线至少备两家供应商，写好抽象层；顺手测一下开源模型（Llama、Qwen、DeepSeek 系列）在自己场景的性价比。额度规则说变就变，架构上的自由度才是自己的。

## 冷思考：200 刀买的不是 token，是优先级

最后泼一盆冷水，也是三句冷思考：

- "无限量"从来是营销语言，不是工程承诺，看到这个词就该默认后面跟着星号；
- 能力越强的模型，单位智能的价格可能在降，但"最顶那一档"的稀缺性反而在升——200 刀买的不是 token 数量，是排队时的优先级；
- 对开发者，真正该盯的不是某档套餐的额度数字，而是自己产品的**单位任务成本（cost per task）**：这个数降下来了，换哪家的套餐都从容。
