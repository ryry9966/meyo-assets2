## 背景

我们用 OpenClaw 跑了一个社区周报机器人：定时抓取群里的精选讨论，agent 汇总后发到论坛。第一版很粗糙——cron 整点触发、固定模板渲染、失败自动重试。跑了两周，管理员私下提醒：你们的帖子时间太准、格式太像，像在刷屏。

## 问题拆开看

所谓“机器味”是三个维度叠加的结果：

- **时间节奏**：整点触发、等间隔、全年无休；
- **内容结构**：同一模板、同一口吻、标题模式固定；
- **行为特征**：只发不读、零互动、失败后高频重试。

节奏控制的本质不是“绕过检测”，而是降低对社区的噪音。这两者做法一致，但动机决定你会不会走偏——伪装身份那条路我不建议走。

## 做法

1. **先定配额再写逻辑。** 硬编码上限：每天 ≤1 帖、同版块每周 ≤3 帖。配额写在代码里，不写进 prompt，LLM 不负责决定“发不发”。
2. **时间抖动 + 业务时间窗。** cron 触发后加 0–90 分钟随机延迟，避开整点；只在工作日晚间和周末上午的窗口内随机。注意容器时区，我们踩过 UTC 导致凌晨发帖的坑。
3. **内容去模板化。** 不做“标题模板 + 正文填空”，把要点交给 LLM 每次重写，system prompt 里明确给反例：“不要复用上周的开场句式”。标题生成 3 个候选，与近期历史比对，筛掉最雷同的两个。
4. **队列 + 指数退避。** 发帖统一过队列串行消费，失败最多重试 2 次，超出进 pending 等人工。绝不做立即重试。
5. **人工闸门。** 前 20 帖全量审核，稳定后按置信度抽审。工具很简单：OpenClaw 消息通道推给我，回“发 / 不发 / 改”三个词。
6. **可披露的自动化。** 帖末固定一行注明由 agent 生成。实践下来反而降低了敌意——社区反感的是噪音和隐瞒，不是自动化本身。

## 踩坑点

- 抖动的随机数用了固定 seed，两周后发现间隔呈完全相同的周期，等于没抖。
- 只抖了时间没抖内容，“【精选】xxx”的标题格式一眼假，改掉后观感立刻不同。
- API 超时触发重试风暴，一分钟连发 4 帖——这是最像机器人的时刻。退避必须落在队列层，不能指望回调层。
- 想让 agent“顺便”回复别人显得活跃，结果答非所问，比不发更糟。互动能力在质量达标前宁可不开。

## 可复用建议

- 把配额、时间窗、抖动幅度、退避上限抽成一个配置文件，和 prompt 分离，复盘只改参数。
- 每次发帖记一条结构化日志：计划时间、实际时间、模板版本、审核结果。回看两周日志，机器味基本都能看出来。
- 发帖前让 agent 自评：“这条与上一条结构是否雷同？信息密度是否够？”自评不过就进 pending。

## 总结

自动发帖的目标不是“更像人”，而是“更克制”。时间抖动解决规律性，内容重写解决模板感，配额和人工闸门解决噪音。做到最后你会发现，真正让帖子不像机器人的，是发得少、发得准，以及坦然承认自己是自动化。
