## 背景

OpenClaw 里每一个对话都会落成一个独立的 session 文件（JSONL，按 agent + channel 的 session key 组织在 `~/.openclaw/agents/` 下）。你日常聊天的那个主会话会长期累积上下文；而当主 Agent 通过 `sessions_spawn` 拉起子 Agent 去跑任务——查资料、批量改文件、跑定时脚本——隔离没做对的话，子过程的中间输出、工具日志、长篇推理就会反过来挤占主会话的上下文窗口。

## 问题

污染的典型症状：

- 主会话响应变慢、token 成本悄悄上涨；
- 模型开始"记得"一些你从没聊过的细节，实际是子任务日志的残留；
- 甚至把子任务的中间结论当成"用户说过的话"来引用。

`/compact` 只能缓解，压不干净。根治思路是：过程数据留在子会话和文件里，主会话只保留决策上下文。

## 做法

1. **先确认默认行为**。`sessions_spawn` 会给子 Agent 开一个全新 session，子 Agent 默认看不到主会话历史——除非你在任务描述里显式塞进去。跑完后只有最终结果回传主会话。
2. **把任务写成函数调用风格**。输入 = 明确的任务描述 + 文件路径；输出 = 让子 Agent 把详细产物写到 workspace 文件，只回传一段简短摘要。例如："读取 `notes/raw.md`，整理后写入 `notes/clean.md`，回复不超过 5 行的变更摘要。"
3. **长任务走后台**。spawn 支持后台运行和超时控制，主会话不阻塞，结果通过通知或稍后查询回来。
4. **高频噪音任务单独建 agent**。定时抓取、批量处理这类自动化，配独立 workspace 和 session，和主会话物理隔离。
5. **主会话定期 `/new` 或 `/compact`**，当作例行维护。

## 踩坑点

- **在任务描述里整段粘贴主会话上下文**：等于手动把污染带回来。只传摘要和文件路径。
- **指望子 Agent 记得上一个子 Agent 的工作**：它们互相无状态。需要共享状态就落盘到文件，在任务描述里指路。
- **让子 Agent 直接回传长结果**：主会话照样被撑大。务必约束返回格式："摘要 + 产物文件路径"。
- **并发子 Agent 写同一个文件**：会互相覆盖。给每个子任务独立的 tmp 目录，最后再合并。
- **主会话 reset 之后**：确认后台任务的回调结果会落到哪个会话，别丢了输出。

## 可复用建议

- 把子 Agent 当**无状态函数**用：输入清晰、输出精简、产物落盘。
- 主会话只放决策上下文，过程数据一律进文件。
- 每类高频噪音任务一个专属 agent，宁多勿混。
- 定期看一眼 `~/.openclaw/agents/*/sessions` 下各文件大小——某个 session 异常膨胀，就是污染的信号。

## 总结

OpenClaw 的 session 隔离机制本身是够用的：子 Agent 天生独立会话，回传可控。真正容易出问题的是我们怎么"喂数据"——把上下文整段搬运、让长结果直传、多任务共用一套文件。管住这三点，主会话可以长期保持干净，压缩和 reset 的频率也会明显下降。隔离不是配置出来的，是写任务描述时约束出来的。
