## 背景

用 OpenClaw 挂一个定时任务往社区发内容，是很多人落地 Agent 的第一件事：接一个 MCP 发帖工具，配 cron，每天定点推一篇。跑起来不难，难的是跑两周之后——帖子被折叠、账号被限流，或者明明是原创内容，却被老用户一眼认出"这是机器人发的"。

## 问题

机器味通常不是内容质量问题，而是**时间分布和行为结构**问题。定点发的 bot 有三个典型特征：

1. 时间戳过于规律：每天 09:00、12:00、20:00 准时出现，方差为零；
2. 只有输出没有输入：从不浏览、回复、点赞，只发帖；
3. 内容形态同质：篇幅、结构、开场白高度一致。

社区管理员和反垃圾规则识别的就是这些统计特征，而不是"内容是不是 AI 写的"。

## 做法

**1. 把 cron 换成"时间窗 + 抖动"。** 不要定点，给一个窗口，在窗口内按近似人类的活跃分布采样。比均匀随机更好的是双峰分布：上午一个峰、晚上一个峰，凌晨基本不发。

```yaml
schedule:
  windows: ["09:30-11:30", "19:30-22:00"]
  jitter: gaussian          # 峰值附近密度高
  quiet_hours: ["01:00-08:00"]
  daily_quota: 2
  min_gap_minutes: 180
```

**2. 事件驱动优先于定时驱动。** 真正的人是"有事才说"。给 Agent 配一个监听：关键词命中、关注的板块有新讨论、仓库来了新 issue——命中才进发帖队列，定时器只做兜底。这比任何随机化都更像人。

**3. 混入低成本的互动行为。** 每天固定比例的"只读"动作：浏览、回一两句、给相关帖点个赞。发帖与互动建议控制在 1:3 左右。一个只发不回的账号，内容再好，画像也是异常的。

**4. 重要内容走审核队列。** Agent 产出的帖子先进草稿箱，人工扫一眼再发。自动化负责节奏，人负责值不值得说。这半步成本很低，但能挡住大部分"AI 味浓但没人拦"的尴尬。

## 踩坑点

- **均匀随机不等于像人**：`uniform(9, 22)` 会发出凌晨 3 点的帖子，必须叠加静默时段。
- **抖动种子写死**：`random.seed(42)` 固定后，两周的发布时间序列是重复的。种子用时间或系统熵源。
- **停机后爆发**：服务挂一天，重启后积压队列一次性发出去，比不抖动更显眼。队列要有过期丢弃策略，过了时效的内容直接不发。
- **时区错位**：目标社区在海外，你按北京时间排的"黄金时段"正好是对方深夜。
- **重试产生重复**：发帖接口超时重试没做幂等，同一条内容连发三遍，是反垃圾系统的头号信号。

## 可复用建议

- 三个参数一起调：**窗口、配额、最小间隔**，缺一不可。只加抖动不限量，等于没控。
- 发布日志记录"计划时间 vs 实际时间"，方差长期趋于零说明调度器退化了，加个告警。
- 内容层面做轻量多样性：长度、是否带代码块、有无列表，用简单规则轮换，不要每次套同一个模板。
- 先在低权重板块灰度一两周，观察折叠率和回复率，再上主板块。

## 总结

让自动发帖不像机器人，核心不是把随机数玩出花，而是把**发布节奏建模成人类行为分布**：有活跃峰谷、有输入也有输出、有事才说、量入为出。OpenClaw 的调度能力加 MCP 工具链足够把这套节奏做成配置项，剩下的克制——少发、发好——才是真正决定账号寿命的变量。
