## 背景

大多数人对 Agent 的使用模式是"问答式"：想起来一件事，打开对话，提需求，等结果。但真正有价值的自动化往往反过来——Agent 定时醒来，自己过一遍该做的事，有事就报，没事就闭嘴。

OpenClaw 提供了一个很轻的机制：心跳。Agent 每隔一段时间（默认 30 分钟）被唤醒一次，读取工作区根目录的 `HEARTBEAT.md`，按清单逐项判断要不要干活。这个文件本质上就是一份"值班手册"。

## 问题

我最初想让 Agent 做的事很零散：盯某个仓库有没有新 issue、磁盘快满提醒我、每天早上汇总一次 RSS。两条老路都走不通：手动问靠人肉记；写 cron 脚本则只會发固定文本，做不了"读取内容、判断后再决定"的事。

心跳机制补的就是这个断层：调度由 OpenClaw 负责，判断逻辑写在 Markdown 里，执行时可以直接调用 Agent 已有的工具（MCP、shell、消息通道）。和 cron 的本质区别在于——决策在模型这一侧。

## 做法

三步：

1. **建文件**。在工作区根目录新建 `HEARTBEAT.md`，写成 checklist。每条尽量遵循"触发条件 + 动作 + 输出位置"三段式：

```markdown
- 每天早上 8 点：抓取 inbox 未读邮件，汇总成 3 条以内摘要发到 #daily
- 若 error.log 今天有新增：取最后 20 行发给我，附一句可能的归因
- 每次心跳：磁盘占用 > 85% 才提醒，否则跳过
```

2. **调节奏**。用 `HEARTBEAT_INTERVAL_MINUTES` 控制唤醒间隔。高频检查（磁盘、日志）15–30 分钟足够；日报类任务在条目里写明"每天只执行一次"，让 Agent 自己过滤。

3. **管好输出**。配置心跳的投递 target，把消息路由到一个独立的静音会话，别污染主对话。没任务时 Agent 回 `HEARTBEAT_OK`，系统静默处理，不转发给你。

## 踩坑点

- **清单写得太虚**。早期我写过"看看今天有什么值得关注的"，结果每次心跳都返回一堆废话。教训：条件必须可判定，动作必须可执行。
- **清单越长，token 越烧**。每次心跳都会唤醒模型跑一轮上下文，10 条任务和 3 条任务成本差数倍。不急的项标低优先级，并写明"条件不满足就跳过"。
- **合盖就停**。心跳依赖本机进程，笔记本睡眠期间的心跳会错过。值班类的活要么放在常开设备上，要么接受"错过就错过"。
- **静默失败**。心跳是无人值守运行的，某个 MCP server 的 token 过期，任务会默默失败。重要检查项要让 Agent 在失败时也发通知，宁可吵一点。

## 可复用建议

- 把 `HEARTBEAT.md` 当代码管：进 git，改动走 review，跑稳一周再加新条目。
- 分层设计：心跳级（分钟级、便宜检查）和日报级（聚合多个安静检查、固定时间发一条）分开，避免消息轰炸。
- 没有明确出口的任务不进清单——每条都要写清结果发到哪。

## 总结

HEARTBEAT.md 的价值不在技术复杂度，而在把"主动性"收敛成一份可版本管理、可 review 的文本。Agent 从"你问它答"变成"定时巡检、有事报告"，中间只需要一个 Markdown 文件和一次对节奏的克制设计。建议从最小清单起步（一条日报 + 一条条件告警），跑稳了再加。
