10 月 6 日，OpenAI 在旧金山办了今年的 DevDay，上千名开发者到场。整场 keynote 里最抢眼的，不是某个新模型又刷了什么榜，而是 Agent（智能体）相关的一整套工具链集中落地：AgentKit、Apps SDK、Codex 正式版、Sora 2 API 一齐端上来。36kr 那句"欢迎来到 Agent 时代"并不算夸张——OpenAI 这次做的事，本质是在给 Agent 铺路：把"让 AI 自己干活"从少数团队的攻坚项目，变成普通开发者可以动手组装的工程。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/6742cf9dc918a76f.png)

## 一、这次发布了什么：主角是工具链，不是新模型

先过一遍主要清单：

- **AgentKit**：一套"组装 Agent"的全家桶
  - Agent Builder：可视化拖拽画布，像画流程图一样编排智能体
  - ChatKit：开箱即用的嵌入式对话界面组件
  - Evals：把评估直接嵌进工作流，能对整条链路逐步打分
  - Connector Registry：统一管理企业内的工具与数据连接
- **Apps in ChatGPT / Apps SDK**：第三方应用可以"住进"ChatGPT 对话里，底层基于 MCP 协议
- **Codex GA**：编程智能体正式商用，配套 SDK，可接入 CI 流程和本地开发环境
- **Sora 2 API 与实时语音接口更新**：视频生成、低延迟语音进入开放接口阶段
- **GPT-5 Pro**：给更长的推理时间，主打高难度任务

一个值得注意的信号：前几年 DevDay 的关键词是"新模型多聪明"，这次的关键词是"你能在平台上做什么"。模型能力进入平台期后，竞争的重心开始往工具链和生态转移——路径有点像云计算时代从卖服务器走到卖开发平台。

## 二、Agent 到底是什么：不是更会聊天，而是会循环干活

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/7694fb3bdb0a3054.png)

拆开看，一个 Agent 系统通常包含四个部件：

1. **大脑**：LLM 负责理解与决策；
2. **手**：工具调用（function calling），模型输出结构化请求，由运行时去执行 API、跑代码、操作浏览器；
3. **记忆**：短期上下文 + 长期存储；
4. **循环**：感知 → 决策 → 行动 → 观察结果 → 再决策，直到目标完成。

它和聊天机器人的差别就在这个"循环"上：聊天机器人答完就结束，Agent 会把执行结果喂回模型继续推理，自己走完整个任务链。举个例子，用户问客服 Agent"我的订单到哪了"，它要先判断需要查单，再调物流 API，拿到结果组织回复，发现物流异常还会追加一次"创建工单"的工具调用——整个过程是它自己排的。

为什么 Agent 到 2025 年才真正爆发？三个前提缺一不可：

- **模型侧**：推理能力、长上下文、指令跟随过了及格线；
- **协议侧**：MCP（Model Context Protocol）由 Anthropic 在 2024 年底提出，OpenAI 今年宣布接入，逐渐成了事实标准，"接工具"从每家定制的私有接口变成类似 USB-C 的通用标准；
- **成本侧**：主流 API 价格两年间降了约一个数量级，多轮循环才"烧得起"。

## 三、Apps in ChatGPT：分发逻辑被改写了

- ChatGPT 周活跃用户已达 8 亿（DevDay 官方口径）。对开发者来说，这意味着应用不用再"等人下载"，而是"在需求发生的对话现场被唤起"。
- 举例：用户在对话里说"帮我规划东京五日行程"，一个旅游应用会被自动唤起，直接在聊天窗口里返回可交互的地图和日程界面，而不是甩给用户一条跳转链接。
- 类比：这有点像 App Store 之于移动互联网。MCP 正在成为 Agent 生态的接口协议，而先做好标准接口的一方，往往能定义生态的格局。
- 商业层面，官方口径是内测期不抽成，长期模式未定。换句话说，红利期大概率存在时间窗口，值得开发者留意。

## 四、冷思考：Agent 落地绕不开的三个现实

1. **可靠性会复合衰减**。单步准确率 95% 的任务，串 10 步成功率只剩约 60%（0.95¹⁰ ≈ 0.599）。这就是 OpenAI 把 Evals 做成一级产品的原因——评估不是上线后的补丁，而是链路设计的一部分。
2. **成本和延迟是乘法关系**。多轮循环意味着 token 成本成倍增长，一个"看起来省事"的 Agent 任务，算上重试和评估开销，可能比熟练的人工更贵。上线之前先算账。
3. **安全面被放大了**。Agent 有权限读写外部内容，prompt injection（提示注入）可以从网页、邮件、文档里夹带恶意指令。权限最小化、高危操作加人工确认，是工程底线，不是可选项。

## 五、给不同角色的三条建议

- **开发者：先做窄场景**。别一上来就造"通用助理"，挑一条可验证的链路（比如工单分类、周报汇总），把评估指标建扎实，再谈扩展。
- **架构决策：投资协议，而不是押注模型版本**。工具接口用 MCP 这类标准协议封装好，未来换模型的迁移成本会低一个档次——接口设计好的系统，换发动机比换底盘容易得多。
- **普通用户：把 Agent 当实习生管理**。给明确目标、限定权限、验收产出；同时分清"演示效果"和"生产可用"，发布会视频和你的真实工作流之间，隔着无数个边界情况。

Agent 时代的入场券，不是"会用某个模型"，而是像上一代工程师理解 HTTP 和数据库那样，理解循环、工具和评估这三件事。工具已经递到手上了，剩下的看谁先把活干扎实。
