一条热搜把不少人看愣了：据 36kr 等媒体报道，OpenAI 的 24 小时在线智能体（代号 dots）正式上岗，同时挂出了 500 美元/月的顶配套餐。评论区两极分化——有人喊“AI 打工人来了”，有人冷笑“这钱够雇个真人了”。价格从 20 美元一跳到 500 美元，中间差的不是胆子，是产品形态和成本结构。这篇把三件事讲清楚：常驻 Agent 到底怎么干活、500 美元贵在哪、以及你怎么判断要不要掏这个钱。



## 一、从“你问我答”到“7×24 在岗”：换掉的是整个工作模式

传统 ChatGPT 是请求-响应（request-response）模式：你不发消息，它一个 token 都不产出，边际成本几乎为零。而“24 小时在线”是另一套架构：常驻任务（persistent task）+ 事件驱动。它有自己的日程——定时盯信息源、监听邮箱变化、触发条件一满足就自动跑流程。

工程上要补齐四件套：

1. **任务编排（orchestration）**：把大目标拆成步骤，排队、调度、失败重试；
2. **长期记忆**：用向量库存你的偏好和历史，跨会话续上 context；
3. **工具调用（tool use）**：浏览器、代码沙盒、外部 API，干完活还要自查结果；
4. **异步执行**：任务在云端后台跑，跑完通知你，人只做验收。

一个类比：Plus 订阅像点外卖，下单才开火；常驻 Agent 像包月私厨，一直守在你家厨房随时颠勺。后者的成本结构天然高一个量级——这就是 500 美元出现的技术前提。



## 二、500 美元贵在哪：把一笔推理账摊开算

关键在于 Agent 的一次“任务”背后是几十次模型调用。目标 → 拆解 → 搜索 → 读写 → 反思 → 修正，每一环都在烧 token；而且多轮任务的上下文会被反复带入计费，长上下文的推理开销是随长度明显上升的。

粗算一笔账：让 Agent 每天盯 10 个信息源、汇总成一份带来源的日报，一天消耗几十万 token 很正常；如果用上 o1/o3 这类“先想再答”的推理模型，单日推理成本几美元起步，一个月就是上百美元，还没算浏览器、沙盒这些工具执行的算力。

底层资源也在涨价：H100/B200 级 GPU 长期供不应求，数据中心的电力和折旧是硬成本。OpenAI 曾被曝 2024 年收入约 37 亿美元、亏损约 50 亿美元——“卖得越多亏得越多”的模式，撑不起“无限量常驻”这种产品。

所以 500 美元档不是“加大号 Plus”，而是把“按次聊天”换成了“包月算力池 + 结果交付”。订阅定价从来不按成本加成，而是圈定“为结果付费意愿最强”的那批人。

## 三、为什么一定要有“最贵档”：分层定价的生意经

- **价格分层（tiering）是软件业的老手艺**：让支付意愿高的人多付钱，同时不把大众用户挡在门外。ChatGPT 的阶梯很清晰：Free → Plus $20 → Pro $200 → 更高的企业/Agent 档，每一档本质都是“算力配额 + 服务优先级”的阶梯。
- **锚定效应（anchoring）**：有 500 美元杵在那，200 美元瞬间显得“性价比很高”。这是定价心理学的标准操作，仓储会员店的会员体系早就验证过了。
- **真实目标客群不是个人玩家**，而是咨询、投研、研发这类专业服务者：对他们来说，比较对象不是“另一款订阅”，而是“半个实习生的工资”。按这个锚点，500 美元甚至显得便宜。
- **竞争也在推着走**：Anthropic、Google 都在同价位段布局企业档。API 按量计费和订阅包月的边界正在模糊，未来大概率是“订阅保底 + 用量上限 + 超量另计”的混合模型。

## 四、24 小时在线的另一面：空转、越权与安全面

- **成本失控风险**：Agent 出现死循环或重试风暴时，烧的是平台的钱——相当于你雇的实习生半夜疯狂给自己加班，只是电费算老板的。所以高价档一定伴随限流和“合理使用”条款，“24 小时在线”不等于 24 小时满负荷干活。
- **攻击面变大**：常驻权限意味着它能长期读你的邮箱、操作你的浏览器。Prompt injection 在 Agent 场景被严重放大——一封夹带恶意指令的邮件，可能让它在后台替攻击者办事。
- **跑得久 ≠ 跑得对**：Agent 的错误会累积，越自主越需要验收机制。没有人工确认（human-in-the-loop）的全托管，目前只适合容错率高的任务。
- **隐私与审计**：后台持续处理你的数据，日志能不能导出、数据会不会用于训练，签约前值得逐条看清楚。

## 五、要不要上车：三条冷思考

1. **先算替代成本**：把任务拆开问三个问题——高频吗？可自动化吗？出错的代价大吗？用“省下的时间 × 你的时薪”对比月费，三项全中才值得掏钱，缺一项就先降级试试。
2. **用 API 先试水**：同样的能力多数能靠 API 自己拼出来。按量付费跑一周，拿到真实用量和成本曲线，再决定订不订阅——别为“在线”这个状态本身付费。
3. **权限做减法**：坚持最小权限原则（least privilege），敏感邮箱、支付操作一律不一键授权，关键动作保留人工确认。Agent 越能干，你越要守住那个确认按钮。

价格会波动，产品名会换来换去，但判断框架不会变：看它替代了多少真实工时，而不是看它“在线”了多久。龙虾钳子再锋利，也只夹值钱的那个贝壳。
