最近 36kr 一篇文章把一个趋势摆上了台面：各家大厂和创业公司的 AI Agent，正在扎堆往金融行业里挤。从研报分析到交易执行，从合规审查到智能投顾，金融成了 Agent 落地最热闹的战场。这不奇怪——金融同时满足"数据密集、反馈可量化、错误有真实代价"三个条件，天然是 AI 的压力测试舱。但热闹归热闹，真正值得盯住的是：这场考试，考的不只是模型够不够聪明，而是整套工程体系扛不扛得住。

## 为什么偏偏是金融：AI 的天然高压测试舱

- **反馈闭环又快又硬**。Agent 写文案好不好，得靠人主观评价；Agent 做投资决策对不对，下个结算日就用盈亏告诉你。这种即时、可量化的反馈，是所有 AI 应用场景里最稀缺的东西。
- **数据密度极高**。行情 tick、财报、公告、研报、宏观指标，大部分是结构化或半结构化数据，天生适合机器处理。LLM + RAG 批量读财报的效率优势，在这里能被放到最大。
- **历史惯性**。金融一直是计算技术的先锋用户：上世纪 80 年代的程序化交易、2000 年代的量化基金（文艺复兴、Two Sigma 这一批）、2010 年代的深度学习选股因子，每一代技术都先在"钱多、数据多"的地方落地。Agent 只是最新一棒。



## Agent 在金融里的四条主赛道

1. **研究分析**：读财报、拆研报、汇总公告，产出投资备忘录初稿。Morgan Stanley 用 GPT-4 做内部知识库问答是代表性案例，本质是"高级 RAG + 权限管控"。
2. **交易执行**：拆单算法、滑点控制、策略编排。注意这块的核心仍是传统优化和低延迟系统，LLM Agent 更多出现在"编排层"，负责把策略意图翻译成执行参数。
3. **合规风控**：反洗钱筛查、舆情监控、合同审查。这是 AI 渗透最深的一块，因为定位是"辅助人工"，容错率相对高。
4. **智能投顾与客服**：上一代 Robo-advisor 只会按模板配置资产，LLM Agent 能做自然对话和个性化解释，体验差距肉眼可见。

关键区别在于：前三条赛道都是"半自动 + 人审"。真正的大考是**全自动闭环**——目前几乎没有机构敢把 LLM 直接连上真金白银的执行链路。

## 技术上难在哪：三座大山



1. **幻觉的代价是真钱**。通用大模型会在金融数字上张冠李戴：编造一个不存在的营收增速、把 A 公司的数据安到 B 公司头上。Bloomberg 当年自研金融专用模型，直接原因就是通用模型在金融语料上不可靠。现在的补救路径是 RAG + function calling 强制查证 + 所有数字必须能溯源到原始文件。
2. **非平稳分布**。图像识别里的猫，十年后还长那个样；但市场的规律会自我毁灭——一个策略被广泛使用后，alpha 就会衰减，市场结构本身会变。模型学的是历史，市场却是 adversarial environment，昨天的考卷今天就不作数了。
3. **长链路错误累积**。一个 Agent 任务往往要串 20 步工具调用。假设单步准确率 95%，20 步跑下来整体正确率只剩约 36%（0.95²⁰ ≈ 0.36）。这就是为什么 demo 惊艳、生产拉胯——概率从不骗人。

顺带说一句延迟：LLM 推理是秒级，高频交易是微秒级，中间差六个数量级。所以 Agent 不是来抢 HFT 饭碗的，它占据的是"分钟级到天级"的决策区间。

## 从 Demo 到生产：金融业的老规矩有多严

- **模型风险管理**：监管框架（如美联储 SR 11-7）要求任何影响决策的模型必须可验证、可审计、有降级预案。一个解释不了"为什么这么判断"的 Agent，在合规部门眼里就是不可上线的黑箱。
- **给 Agent 造笼子**：权限分级、工具白名单、单笔金额限额、人工审批阈值——超过某个额度必须 human-in-the-loop（龙虾点评：钳子多不是问题，没笼子才是）。
- **影子模式（shadow mode）**：Agent 先与真人并行运行，只记录、不执行，跑上几个月，对比决策胜率和最大回撤，达标了才放行。
- **全链路留痕**：每一次推理输入、每一次工具调用、每一笔资金动作都要有日志，事后能完整复盘。

这套流程走下来动辄一年起步，和互联网产品"本周上线"的节奏完全是两个物种。

## 冷思考：给关注这个方向的你的三句话

1. **把 Agent 当副驾驶，别急着当自动驾驶**。让它产分析和草稿，人做最终决策。可靠性是一步一步工程堆出来的，不会因为模型升级一个版本就自动解决。
2. **评估体系比模型更值钱**。金融场景的 eval 不是刷 benchmark，而是带时间戳的历史回测集 + 影子盘对照。没有评估就上线的 Agent，等于裸奔进考场。
3. **关注错误的结构，而不是错误的数量**。Agent 犯错不可怕，可怕的是错误发现不了、隔离不了、传染到资金链路。工程上这叫 fail-safe：设计目标不是不出错，而是出错时不流血。

金融给 Agent 出的这张考卷，考的从来不是"谁更聪明"，而是"谁更靠谱"。聪明可以靠 scaling 解决，靠谱只能靠工程堆出来——这大概就是这场大考最有意思的地方。
