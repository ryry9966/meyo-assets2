## 背景

大多数人对 Agent 的使用是被动的：想起来，才去问一句。OpenClaw 提供了一个很轻的机制来改变这件事——心跳（heartbeat）。Agent 每隔一段时间自动醒来一次，读取工作区里的 HEARTBEAT.md：有任务就执行，没任务就沉默。一个小 Markdown 文件，让 Agent 从"应答机"变成"值班员"。

## 问题

被动模式丢掉了一类需求：不是"我现在想知道"，而是"有事你叫我"。比如：

- 每天早上汇总昨天的 GitHub 通知和 RSS
- 盯着某个目录、磁盘、进程，异常才汇报
- 到点提醒某件事

这些事靠人记得去问，等于没有自动化；写传统 cron 脚本又太重，逻辑一变就要改代码。HEARTBEAT.md 恰好卡在中间：用自然语言描述"定期检查什么、什么条件才出声"。

## 做法

1. 在工作区（默认 `~/.openclaw/workspace/`）新建 `HEARTBEAT.md`。
2. 每个任务写清四件事：**触发条件、动作、输出到哪、静默规则**。
3. 调间隔：默认约 30 分钟，调试期可在配置里先压到 5 分钟。
4. 文件顶部加一条总规则："无事可做时回复 NO_REPLY，不要发空消息"——这是控制噪音的关键。
5. 一次性任务带日期，过期即删；周期任务只留持续有效的。

示例片段：

```markdown
# 总则：无事可做时回复 NO_REPLY，保持沉默
- 每天早上第一次心跳：汇总 GitHub 未读通知，超过 5 条才发到 #daily，否则跳过。
- 检查 ~/data 目录大小，超过 10GB 时提醒我，并列出最大的 5 个文件；平时沉默。
- 2025-08-01 前提醒我续费服务器（一次性，做完删除此行）。
```

注意：精确到点的任务（整点日报之类）不要靠心跳猜时间，交给 cron 工具或系统 cron 触发更可靠。心跳适合"间隔巡逻"，不适合"准点闹钟"。

## 踩坑点

- **Token 成本**：每次心跳都是一次模型调用。文件塞几十条任务，等于每 30 分钟把全部内容烧一遍。控制在 10 条以内，重活挪去 cron。
- **噪音**：不写静默规则，Agent 可能把"今天无事发生"也发出来。NO_REPLY 总则必须放在最显眼的位置。
- **描述模糊**：写"帮我关注一下服务器"会得到随意发挥。阈值、范围、输出格式都要写死。
- **权限**：心跳等于给了 Agent 自主执行权。工具权限按最小化配置，别在心跳任务里安排有副作用的写操作，除非明确需要。
- **长任务阻塞**：某次心跳跑了一个重型抓取，后续心跳会排队或被跳过。大任务拆出去。

## 可复用建议

- 把 HEARTBEAT.md 当"值班手册"维护，每周清理过期货，保持文件短小。
- 分层组合：心跳负责"扫描 + 判断是否值得打扰你"，MCP 工具负责取数，cron 负责准点触发。单押一个都不稳。
- 所有通知类任务默认静默、异常才出声——这是主动型 Agent 不讨人厌的核心。

## 总结

HEARTBEAT.md 没有黑科技，本质就是"定时醒来 + 读文件 + 按规则行事"。它的价值在于把主动性变成一份可以进版本管理的纯文本配置。建议从一个低风险任务起步（比如每日摘要），跑一周，观察 token 消耗和噪音水平，再逐步加码。当 Agent 第一次在你没问的情况下，把真正有用的消息递到你面前——你就回不去了。
