最近 36kr 一篇报道把「DeepSeek 加速向华为靠拢」顶上了热搜。评论区迅速两极分化：一边喊「国产芯片支棱起来了」，一边说「CUDA 护城河无可撼动」。两边都有道理，但都太粗糙。这篇文章把它拆开看清楚：靠拢到什么程度、为什么是推理先行、真正的难点在哪、对普通开发者和企业选型又意味着什么。

## 先对齐事实：所谓「靠拢」，目前走到哪一步

先把公开信息捋一遍，避免脑补：

- **推理侧已落地**：DeepSeek 官方开源的 V3/R1 推理引擎，据公开仓库记录已合并对昇腾 910B 的适配支持，由华为工程师参与贡献；国内多家云厂商（华为云、硅基流动等）已经能在昇腾集群上对外提供 DeepSeek 系列模型的推理服务。
- **内核层在共建**：2025 年 2 月 DeepSeek 连续开源 FlashMLA、DeepEP、DeepGEMM 等核心算子库，昇腾团队在几天内宣布完成移植。相当于头部模型公司把「考卷和参考答案」一起公开了，适配的反馈回路被压到极短。
- **训练侧在试点**：据 Financial Times 报道，DeepSeek 在下一代模型的训练中尝试引入昇腾做验证，但主力训练仍在 NVIDIA 集群上。「正在试」，不等于「已完成」。
- **背景板**：2025 年 H20 出口政策几经反复，先进 GPU 供应的不确定性，是所有国内 AI 公司都在做的压力测试。

一句话概括：**推理已落地，训练在试点，生态在共建**。「靠拢」是真实的，「全面切换」是误读。

## 为什么推理先行：训练和推理根本不是同一种活

很多人以为「换芯片」是一个动作，其实训练和推理的迁移难度差着量级：

1. **训练是数周不间断的极限运动**。数千卡集群跑 MoE 训练，跨机通信（all-to-all）、混合精度、容错恢复、算子精度对齐，任何一环出问题损失都以「天」计。这一层深度绑定软件栈的成熟度。
2. **推理是长期规模化运营**。权重固定、算子集合有限，瓶颈集中在显存带宽、KV cache 和批调度上——这些恰恰是软件优化最能撬动的部分。而且推理是商业大头：一个模型生命周期内 serving 花掉的算力，通常远超训练本身。
3. **DeepSeek 恰好是「抠算力」的祖师爷**。V3 论文里的操作——MoE 架构（671B 总参数、每 token 只激活 37B）、MLA 压缩 KV cache、FP8 训练、甚至手写 PTX 汇编优化 H800 的跨机通信——本质都是「硬件给什么，就把什么榨干」。对硬件理解越深的团队，换平台的适应成本反而越低。
4. **单卡不够，系统来凑**。华为 CloudMatrix 384 用全光互联把 384 颗 910C 组成超节点，据第三方测算，聚合算力能超过英伟达同代旗舰机柜方案，代价是更高的功耗和运维成本。推理侧对单卡峰值没那么偏执，「堆系统」路线有生存空间。

## 真正的战场在软件生态：CUDA 的护城河不是编译器

芯片参数表最容易看，也最不重要，真差距在软件栈：

- CUDA 生态攒了将近 20 年：cuDNN、NCCL、Triton，完善的 profiler/debugger，加上几十万受过训练的工程师。昇腾的 CANN 在算子覆盖率、工具链成熟度、社区体量上仍有明显差距。
- 迁移的真实痛点很琐碎：某个融合算子没有对应实现、精度对不上、性能瓶颈定位不了。换硬件最痛的不是装驱动，是算子对不上号——家具都搬来了，插座全是反着装的。
- 这正是 DeepSeek 这类头部用户的价值：他们有动机也有能力把栈打穿。每补一个缺失算子、每贡献一个优化 kernel，整个生态都受益。「开源内核 → 快速适配 → 反哺社区」的飞轮，这次是真的转起来了。
- 顺带说一句，DeepSeek 开源这些 kernel 未必是为了「扶持谁」，工程师的朴素逻辑就是「我有更好的实现，就放出来」。但客观效果是，给所有非 NVIDIA 硬件铺了一条路。

## 一个头部用户的带动效应，比参数表重要

为什么这件事值得整个行业关注：

1. **心理阈值被打破了**。此前不少公司对「国产算力能不能跑前沿模型」持观望态度；现在公认最会压榨算力的团队之一在昇腾上跑推理，后来者的决策成本大幅降低。
2. **人才和工具链跟着流量走**。更多工程师在 CANN 上解决真实问题，社区积累的 issue、文档、最佳实践才会变厚。生态不是发布会上讲出来的，是 bug 和 PR 堆出来的。
3. **市场结构在变**。「训练用 A、推理用 B、不同业务用 C」的多后端形态会越来越常见。NVIDIA 在训练侧的短期优势难以撼动，但推理市场会被系统性分走一块。
4. **也要诚实记录另一面**：系统级补偿不是免费的——更大集群、更高功耗、更多运维人力。工程上「能跑通」和商业上「划算」之间，还隔着单位 token 成本这道坎。

## 三条实用建议与冷思考

1. **给开发者**：架构上保留「硬件可替换性」。推理侧优先选 vLLM、SGLang 这类多后端框架，少把业务绑死在单一私有特性上，量化和导出链路尽量标准化。未来换后端的成本，取决于你今天多写了多少抽象层。
2. **给做选型的团队**：评估国产算力别只看峰值 TFLOPS——那是体检报告，不是日常表现。更该看算子覆盖率、profiler 好不好用、大集群连续训练的稳定性记录，以及折算到单位 token 的真实成本。
3. **冷思考**：既别喊「一夜替代」，也别信「生态差距永不可破」。生态是时间的函数，头部用户的每一次适配都在给曲线加斜率；但单卡差距和功耗代价同样真实。理性的姿势是把它当成两三年的工程演进来做，而不是一场宣言。
