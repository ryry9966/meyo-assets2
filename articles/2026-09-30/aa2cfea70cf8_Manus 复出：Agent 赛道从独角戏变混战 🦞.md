2025 年 3 月，Manus 用一支“让 AI 自己干活”的演示视频刷屏全网，邀请码一度被黄牛炒到数万元，成为当年最出圈的 AI 产品事件之一。几个月过去，Manus 放宽注册、迭代新版本，重新回到大众视野。但这一次它抬头一看：OpenAI、Anthropic、Google、微软全都在主线产品里塞进了 Agent 能力，开源框架也把搭 Agent 的门槛打到了地板价。通用 Agent 这条赛道，已经从一个人的独角戏变成了全行业的团战。这篇拆三件事：Manus 靠什么出的圈，Agent 的技术内核难在哪，以及战场拥挤之后，竞争的胜负手变成了什么。



## 一、出圈逻辑：一场教科书级的演示胜利

Manus 的爆火路径非常清晰，值得所有产品人复盘一遍：

1. **定位踩中了时代情绪**。2025 年初，大家已经看腻了聊天机器人，“AI 不只说，还能替你做”恰好是下一个集体期待。
2. **演示即产品**。筛选简历、生成报告、规划行程——视频里 Agent 自己拆任务、开浏览器、写代码、交付成品，"Watching it work"本身就是最强的传播素材。
3. **稀缺性助攻**。邀请码机制制造了饥饿营销，二级市场价格被炒到数万元，反而进一步放大了话题热度。
4. **站在巨人的肩膀上**。底层调用 Claude、Qwen 等成熟模型，Manus 自己做的是任务编排（orchestration）、工具调用和环境隔离这一层“工程胶水”。

当时社区最大的争议也在这里：这到底是颠覆式创新，还是一次高质量的工程整合？平心而论，整合本身有价值——把模型能力包装成“给目标、交结果”的体验，就是产品化。问题只在于：这层胶水，别人贴起来难不难？后来的故事证明，答案是“不难”。

## 二、Agent 的技术内核：为什么演示惊艳、日常难用



看懂战场，先看懂 Agent 在技术上的真实难度。一个通用 Agent 的最小闭环是：

> LLM 做规划 → 调用工具执行 → 观察结果 → 修正计划 → 循环往复，直到交付

听起来简单，每一步单拎出来都成熟，难点全在“循环”里：

- **误差累积**。假设单步成功率为 95%，一个含 30 个串行步骤的任务，整体成功率只剩 0.95^30 ≈ 21%。这就是“演示里一路丝滑、自己用时半路翻车”的数学根源。
- **上下文管理**。长任务会把 context 窗口撑爆，记忆怎么压缩、状态怎么外置到文件或数据库，都是脏活累活。
- **环境非确定性**。浏览器弹窗、API 限流、网页改版……真实世界不会按脚本出牌，Agent 的容错与恢复能力才是硬指标。
- **评测难**。GAIA、SWE-bench、OSWorld 这些基准在努力量化“任务完成率”，但离真实生产力场景仍有距离。

所以业内有个共识：做一段 Agent 演示，一两周就能像模像样；做一个能天天用的 Agent，是以年为单位的持久战。

## 三、战场为何拥挤：三线包夹

Manus 沉寂调整的几个月里，赛道一点没闲着，对手来自三个方向：

1. **大厂平台化包夹**。OpenAI 把 Operator、Deep Research 陆续并入产品线；Anthropic 的 Computer Use 和 Claude Code 把“操作电脑”“独立完成项目”做成原生能力；Google 有 Project Mariner 和 Jules；微软把 Copilot 改造成企业级 Agent 入口。通用能力被大厂“顺手”内置，是外挂编排层最大的生存威胁。
2. **模型能力上移**。推理模型把规划、反思内化进模型本身，多步任务不再那么依赖外部脚手架；MCP（Model Context Protocol）这类协议又在把工具接入标准化——编排层的护城河两头被挖。
3. **开源与低代码平民化**。LangGraph、Dify、Coze、OpenHands 这类框架把“搭一个 Agent”的门槛降到周末项目级别，会写提示词的产品经理也能一天拼出 demo。

三线夹击的结果很残酷：Manus 首发时占据的“通用编排层”生态位，上下同时受压。剩下的差异化空间主要在：垂直场景深耕（科研、代码、销售、设计）、多 Agent 协作架构、成本控制（大小模型路由调度），以及用户工作流与数据的长期沉淀。

## 四、胜负手改写：从“演示惊艳”到“单位任务成本与可靠性”

Agent 的竞争正在变得像十年前的云计算：Demo 谁都能做，最后拼的是 SLA、价格和迁移成本。新的比拼维度可以列成一张硬指标清单：

- **真实任务完成率**：不是精心布置的演示环境，而是用户每天的真实杂活；
- **失败恢复能力**：出错后是自愈重试，还是直接躺平甩锅给用户；
- **单任务成本**：token 消耗与调用次数，决定商业模型能否跑通；
- **延迟与可中断性**：跑半小时的任务，能不能随时插手、纠正、回滚；
- **数据与工作流沉淀**：用得越久越懂你，这才是 Agent 版本的网络效应。

对 Manus 来说，手里的牌是先发品牌认知、海外市场经验和迭代速度；风险是模型厂每一次版本升级，都可能把它的某个核心场景“顺手”做掉。这几乎是所有应用层公司共同的时代考题。

## 五、三条冷思考：给用户和从业者



1. **把 Agent 当实习生，别当自动售货机**。给明确目标和验收标准，小任务起步，重要产出必须人工过一遍——这既是效率问题，也是安全边界。
2. **评估 Agent 产品只看三个硬指标**：真实任务完成率、失败时的恢复方式、单任务成本。演示视频是 Agent 界的美颜相机，看看就好，别当体检报告。
3. **从业者想清楚自己站在哪一层**。通用编排层的窗口期极短，壁垒要么在垂直数据和行业工作流，要么在基础设施（记忆系统、评测体系、沙箱环境）。站错了层，跑得越快越危险。

Agent 大战才刚进入小组赛，Manus 的复出不是终局，而是把一个问题摆上了台面：当能力不再稀缺，什么才稀缺？答案大概率不在模型参数里，而在你替用户省下的那些真实的麻烦里。
