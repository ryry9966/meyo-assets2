## 背景

OpenClaw 这类常驻型 Agent 有个特点：它 7×24 跑在你自己的机器上，接入你的聊天渠道，随时被唤醒。但每次会话启动时，它对你的了解几乎为零——`SOUL.md` 定义了它是谁，却没定义你是谁。结果就是反复自我介绍："我用 pnpm 不用 npm""回复请精简""别动 main 分支"。

## 问题

这些上下文散落在历史消息里，有三个代价：

1. **重复消耗**：每次新会话都要重新交代一遍；
2. **不一致**：Agent 从零散聊天里"猜"出来的偏好时对时错；
3. **易失**：换设备或清理会话后，这些信息直接蒸发。

## 做法

解法很朴素：在工作区根目录建一个 `USER.md`，作为每次会话的稳定输入。我的结构是五段：

```markdown
# USER.md
## 身份
后端开发，主要写 Go，时区 UTC+8
## 环境
macOS / 包管理用 pnpm / 项目都在 ~/dev 下
## 当前在做什么
- 某项目：正在重构消息队列（截至 2025-06）
## 偏好
回复中文、先结论后细节、代码注释用英文
## 红线
- 不要直接 push 到 main
- 不要安装未经确认的全局依赖
```

三步落地：

1. 建 `USER.md`，控制在 40 行 / 2KB 以内——它会随会话注入上下文，长了稀释注意力；
2. 在 `AGENTS.md` 里加一条：会话开始先读 USER.md；遇到与文件冲突的新信息，先确认再改；
3. 跑一周，把 Agent 猜错的地方逐条修掉。这一步比初稿重要。

## 踩坑点

- **写成流水账**。USER.md 不是聊天记录，"上周说过什么"应该进 `MEMORY.md`。过时信息比没有信息更糟——我踩过：文件里还留着旧项目名，Agent 一口咬定我在做那个。
- **塞敏感信息**。API key、密码、私人关系一律不写。它是明文文件，还可能被后续工具链读到。
- **放任 Agent 自动追加**。不加约束的自我更新会让文件三周膨胀到 200 行。要规定格式（只改指定段落）、规定时机（仅在明确纠正后），并定期人工审一遍。
- **多机不同步**。如果你在两台设备跑 OpenClaw，把它纳入同步（dotfiles 仓库或 Syncthing 都行），否则两边的"你"会逐渐分叉。

## 可复用建议

- **职责分离**：`AGENTS.md` 管"怎么干活"，`SOUL.md` 管"什么性格"，`USER.md` 管"为谁干活"，`MEMORY.md` 管"发生过什么"。混在一起早晚打架。
- **条目带日期**，过期的移到底部"归档区"而不是直接删，保留演进痕迹方便回溯。
- **模式可推广**：给每个常驻项目配一份 `PROJECT.md`，结构照抄"身份 / 环境 / 现状 / 约束"四段即可。

## 总结

USER.md 本质上是给 Agent 的一份"入职文档"：十分钟写完初稿，之后每周花两分钟维护，换来的是它不再问重复的问题、不再猜错你的偏好。对常驻型 Agent 来说，这是投入产出比最高的一类配置，值得作为标配。
