2025 年 8 月下旬，DeepSeek 在官方 GitHub 仓库提交并公开了一批针对昇腾（Ascend）硬件的推理 kernels（算子），包含基于 TileLang 编写的算子，以及此前开源过的 FP8 矩阵乘库 DeepGEMM 的昇腾适配版。一条看似普通的工程动态，很快冲上热搜。大家真正在讨论的其实不是“又开源了一批代码”，而是这条提交记录背后透出的信息：头部模型团队的生产推理，已经实实在在跑在了一条新的硬件路线上。这篇文章把它拆开讲清楚：开的是什么、为什么重要、对不同角色意味着什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/0021212957955cc3.png)

## 一、先搞清楚：这次开源的到底是什么

先排除最常见的误解，这次开源的既不是模型权重，也不是整套训练框架，而是“算子层”的代码。

- 大模型可以看作一张巨大的计算图，拆到最底层全是重复性极高的运算单元：矩阵乘（GEMM）、注意力计算、MoE 的专家路由等。这些单元就是“算子（kernel）”。
- 算子是性能的关键。同一个模型，算子写得好不好，推理吞吐量可以差出数倍。
- 关键在于：算子和硬件深度绑定，换一种芯片就得重写一遍——就像同一份菜谱换了个灶台，锅具和火候都得重新调。
- 这次公开的内容大致包括：针对 DeepSeek-V3.1 模型结构（MLA 注意力、MoE 专家网络）编写的昇腾版算子，以及 DeepGEMM 的昇腾适配。后者在 2025 年 2 月的“开源周”上曾发布过 CUDA 版本。

一句话概括：菜谱（模型）没变，这次公开的是“在昇腾这个灶台上把这道菜炒好”的刀法和火候。

## 二、为什么重要：瓶颈正在从参数转向软件栈

很多对芯片的讨论停留在纸面算力（TFLOPS），但工程实践中真正的差距往往在软件层。

- NVIDIA 真正的护城河不是某一代芯片，而是 CUDA 生态：将近二十年的算子库、编译器、调试工具链，以及几百万工程师的使用习惯。
- 软件栈的层次大致是：模型 → 框架（如 PyTorch）→ 算子库 → 驱动 → 硬件。中间任何一层覆盖不全，上层就得自己填坑。
- 一块参数很漂亮的芯片，如果算子覆盖率低、成熟度不够，跑大模型就是“有引擎没变速箱”。
- 头部团队把自家生产环境验证过的算子直接公开，等于把最难那部分的“作业答案”共享给全行业，对昇腾的软件栈 CANN 是实打实的补强。

所以不少工程师看到消息的第一反应是：这比多发几篇论文的产业价值都高。

## 三、被顺手证实的事实：昇腾在跑生产推理

这里需要一点严谨的推断，而不是喊口号。

- 工程界的常识：只有生产环境持续使用的代码，才会被反复打磨到值得维护、值得开源的程度。没人会给玩具项目做性能优化。
- 因此可以合理推断：DeepSeek 内部至少有一部分推理流量运行在昇腾上。但官方没有披露具体比例，“全面替代”之类的说法属于过度演绎。
- 商业角度看，这等于给自己配了“第二引擎”：推理成本是 AI 公司最大的开销项之一，多一条被验证过的硬件路线，意味着更强的成本控制能力和供应链韧性。
- 对行业而言，这是第一次有头部实验室公开证明“多供应商硬件路线”在生产环境可行，信号意义大于事件本身。

## 四、TileLang 与社区飞轮：这次开源的方法论亮点

容易被忽略的细节：这批算子不是纯手写汇编式的苦活，而是基于 TileLang 这类 DSL（领域专用语言）完成的。

- TileLang 是一种 Python 嵌入式的“瓦片级”编程语言：开发者用接近数学表达的方式描述计算逻辑，框架自动处理分块（tiling）、内存搬运、流水调度这些脏活。
- 它大幅降低了写高性能算子的门槛，让模型研究员也能参与底层优化。
- 飞轮逻辑：DSL 降低写算子的成本 → 模型团队贡献生产级算子 → 更多硬件厂商跟进适配 → 更多用户反馈问题 → 生态迭代加速。这套打法在 NVIDIA 生态里已被 Triton 验证过一轮，现在相当于在第二条硬件路线上复刻。
- DeepSeek 也在公告中明确欢迎社区反馈问题。开源从来不是单向输出，而是把测试和优化外包给了整个互联网。

## 五、对不同角色的三重影响

- 部署侧工程师：如果业务考虑在昇腾上做推理，现在有生产级参考实现可以对照，能省掉大量从零摸索的时间。
- 算子开发工程师：一套针对真实模型结构（MLA、MoE）的高质量代码，学习价值远超教程示例，尤其是内存布局和调度策略的处理方式。
- 做技术选型的企业：评估维度里多了一项硬指标，目标模型在国产硬件上的官方适配程度，这会逐渐进入采购和技术评审清单。

也泼一盆冷水：这批算子是针对 V3.1 的结构和特定硬件版本调优的，不是拿来即用的万能积木。搬运之前，先确认模型结构、硬件型号、软件栈版本是否对得上。

## 最后：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/2d69c7cc4b4bb633.png)

1. **别把“开源算子”等同于“生态追平”。** 一次开源是里程碑，不是终点。生态差距要看算子覆盖率、工具链成熟度和长期维护投入，这些得以年为单位衡量。
2. **异构算力选型，先跑 POC 再谈战略。** 重点测吞吐（tokens/s）、长时间压测的稳定性、算子覆盖和迁移成本，而不是只对比峰值参数，峰值漂亮、均值拉胯的案例并不少见。
3. **关注三个月后的第三方实测，而不是发布当天的热搜。** 开源最大的价值是让独立验证成为可能，真正有信息量的数据，永远出现在社区复现之后。

热搜会过去，代码会留下来。对一个行业来说，往往是后者更重要。
