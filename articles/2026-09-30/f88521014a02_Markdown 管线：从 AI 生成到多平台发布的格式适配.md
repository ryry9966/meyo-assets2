## 背景

在 OpenClaw 的典型工作流里，Agent 产出的第一产物往往是 Markdown：MCP 工具返回报告、插件生成周报、skill 输出文章草稿。但"生成"只是起点，真正麻烦的是发布——公众号、知乎、掘金、静态博客，每家的渲染器都是一个方言子集，直接粘贴几乎必翻车。

## 问题

- **语法集不同**：任务列表、脚注、公式，有的平台支持，有的原样吐出 ` - [ ]`。
- **样式机制不同**：公众号剥掉 `<style>` 和 class，只认内联样式；博客端却习惯 CSS 主题。
- **资源限制**：外链图片遇到防盗链直接裂图；无 JS 环境下代码高亮全靠构建期生成。
- **LLM 输出不稳定**：同一个 prompt，模型今天写 GFM 表格、明天塞一段裸 HTML，正则后处理越堆越脆。

## 做法：把适配当成构建管线，而不是复制粘贴

核心思路：以 AST 为枢纽，Markdown 进、目标格式出，平台差异全部收敛到配置。

1. **规范源**。Agent 只产出受限方言（GFM 基础子集 + 图片 + 代码块），禁止行内 HTML 和脚注。lint 不合规就返回结构化错误，让 Agent 自我修正。
2. **解析为 AST**。用 unified/remark 或 markdown-it 拿到语法树，后续变换全是纯函数。
3. **按平台 profile 变换**，每个目标一份配置：
   - `wechat`：标题降级映射、代码块构建期高亮成 inline span、外链转文末引用、图片重传白名单图床并替换 URL；
   - `blog`：基本直出，补 frontmatter；
   - `zhihu`：表格降维成列表，防窄屏炸版。
4. **资产处理**：图片按内容哈希去重后重传，产物里不出现外部图床 URL。
5. **接入 Agent**：整条管线包成一个 MCP 工具 `render(content, target)`，Agent 写完草稿先自调用拿各平台预览，再决定是否发布。

## 踩坑点

- 公众号对 `<style>` 是**静默剥离**，不报错。第一次发布以为是样式丢失，实际是构建期没做内联。必须在 build 时把样式烤进每个标签。
- 防盗链在编辑器预览里看不出来，只有真机打开才裂图。预览环节要模拟无 Referer 的请求。
- 嵌套列表缩进 2 空格和 4 空格在不同渲染器下结构不同，lint 里直接统一成 4 空格。
- **不要用正则修 Markdown**。见过一个管线用正则剥 HTML，遇到代码块里的 `<div>` 示例直接把正文截断。一切变换走 AST。
- 模型偶尔在正文里夹 frontmatter，粘贴出去就是三行乱码，lint 要把 frontmatter 当独立通道处理。

## 可复用建议

- 建一份"金样本"：把允许使用的每种语法写成一个 MD 片段，对每个平台 snapshot 渲染结果，方言一变测试立刻红。
- 平台差异只写配置不写代码，新平台接入 = 新增一份 profile。
- 变换函数保持纯函数，方便单测与回放。
- 失败要机器可读：lint/render 返回错误码和位置，Agent 能据此重写，而不是人工盯日志。

## 总结

多平台发布适配的本质是"一个规范源 + 一组平台 profile + 一条 AST 管线"。建成构建步骤后，Agent 只负责产出内容，格式债由管线偿还。最大的收益不是省时间，而是发布结果可预测——每个平台长什么样，在点发布之前就已经确定了。
