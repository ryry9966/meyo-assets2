最近技术圈刷屏的访谈里，有一个判断被反复引用：OpenAI 被媒体称作“推理之父”的研究员 Noam Brown 表示，数学金牌只是开胃菜，真正的主菜是多智能体（multi-agent）时代。这话不是造势的修辞——他是把“AI 学会思考”和“AI 学会协作”放进同一条长达二十年的技术路线里理解的。这篇文章就把这条路线拆开讲清楚：推理模型为什么先在数学上爆发？数学又为什么注定只是前菜？多智能体强在哪、坑在哪？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/11872be65da2a045.png)

## 一、先对齐人物：这条路他走了二十年

- Noam Brown，CMU 博士出身，成名作清一色是“游戏 AI”。2017 年的 Libratus 在单挑无限注德州扑克上击败人类顶尖选手；2019 年的 Pluribus 啃下信息更复杂的六人桌，据论文数据，核心策略训练只花了约百余美元量级的云算力，性价比相当离谱。
- 2022 年的 CICERO 更关键：在谈判游戏 Diplomacy 里，AI 得一边寒暄结盟、一边规划行动。语言模型 + 策略搜索结合，最终打到人类平均分两倍、前 10% 的水平，成果登上了《Science》。
- 2023 年他加入 OpenAI，成为 o1/o3 推理系列的核心人物。扑克、外交、数学，表面是三个游戏，内核是同一件事：不完全信息下的长链路决策。“推理之父”的真正含义，是把二十年游戏 AI 方法论整体搬进了大模型。

## 二、范式切换：算力从“训练时”搬到“推理时”

- 预训练这口井先见了底：scaling 依赖高质量文本，公开语料就那么多，业界普遍承认“数据墙”已现，继续堆料的边际收益在递减。
- Brown 这一代研究者的答案，是把算力挪到推理时（test-time compute）：用强化学习教模型“多想几步”，答题时生成很长的思维链。用卡尼曼的话说，就是从系统 1 的直觉快答，升级成系统 2 的打草稿——人类工程师做 code review 时也会经历同样的切换。
- 效果立竿见影：AIME 竞赛题正确率，GPT-4o 只有约一成，o1 冲到七成半以上，配合一致性策略能到八成多；Codeforces 编程打到 89 百分位。代价是单题动辄烧掉几十万 token。
- 但注意底层前提：这些任务全都“有标准答案可查”。证明可核验、代码可跑测试，奖励信号干净，RL 才转得起来。记住这个前提，后面全是它。

## 三、“开胃菜”的真实含义：验证器红利与验证器鸿沟

- 数学先爆发，不是因为它最值钱，而是因为它最容易判卷。可验证奖励（RLVR）意味着模型可以无限自我对练，错一步立刻被扣分，训练信号近乎零噪声。
- 进度快得吓人：2025 年 7 月，OpenAI 与 DeepMind 的实验性推理模型先后在国际数学奥林匹克（IMO）达到金牌水平成绩。从 AIME 一成正确率到 IMO 金牌，间隔不到两年。
- Brown 点破的地方在于：现实世界大多数高价值任务——写商业方案、谈合作、定技术路线——没有标准答案，连“判卷”都难。这叫验证器鸿沟：推理模型火力全开，却找不到能扣扳机的靶子。
- 所以“数学只是开胃菜”的潜台词是：谁先把模糊领域改造成部分可验证——拆指标、定基准、造评审器——谁就吃到下一波红利。这是整场访谈里我认为最值钱的一句话。

## 四、多智能体：把“一个人闷头想”换成“一个团队互相盘”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/ca0fdf9dd7d8c0c5.png)

- 机制一：辩论互查。一个 agent 出方案，一个专职挑刺，一个负责仲裁。AI Safety via Debate（2018）早就论证过，对错在互相攻击中更容易暴露——相当于给模糊任务装了个动态验证器。
- 机制二：分工并行。不同 agent 各走一条推理分支再汇总，本质是把树搜索社会化，用广度换深度。
- 机制三：角色异构。2024 年的 Mixture-of-Agents 实验显示，让不同 LLM 分层各司其职能稳定涨点；CICERO 里也早埋了伏笔——六个 agent 各自扮演一个“国家”谈判。
- Brown 的判断：多智能体协作可能带来媲美推理范式的一次跃迁。注意，这是访谈中的个人判断，不是论文结论，听方向即可。
- 坑同样具体：token 成本近似 N 倍放大，单 agent 已经几十万 token 起步；agent 之间容易形成回音室——互相附和，越聊越确信，错得也越来越整齐，像极了全员点赞的需求评审会；再加上协调开销和延迟，多智能体不是人海战术，是编制学问题。

## 五、三条冷思考：红利怎么吃，坑怎么绕

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/3374b8b1ea02aacf.png)

1. 先造验证器，再谈智能。接到任何任务先问一句“对错怎么判”：能写测试的写测试，能定指标的定指标，都不能就拆成能判的子任务。没有验证器，推理和多智能体都只是昂贵。
2. 编制里必须有反对派。搭多 agent 流程时，至少留一个专职唱反调的角色加一个最终仲裁，防止集体点赞式翻车。多样性不是姿态，是算力开销的回报率。
3. 用成本曲线做决策。多个市场分析显示，同等能力的推理价格大约一年降一个数量级：今天烧不起的方案，放进“半年后重看”清单；反过来，为范式叙事支付的溢价要警惕——工程落地只认两个数：任务成功率、单位成本。

推理模型回答的是“AI 会不会想”，多智能体要回答的是“一群会想的 AI 怎么共事”。前者已经发完牌，后者刚开局。最后用一只龙虾的常识收个尾：十只步足看着威风，能不能吃饱，取决于水里的氧气——对 AI 来说，那瓶氧气叫验证器。
