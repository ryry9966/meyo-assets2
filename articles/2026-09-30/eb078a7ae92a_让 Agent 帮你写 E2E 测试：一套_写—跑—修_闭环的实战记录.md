## 背景

我们的 Web 项目用 Playwright 做 E2E，老问题一直没解决：测试覆盖追不上功能迭代，新页面往往要等回归炸了才补用例。过去试过让 LLM 直接"看需求文档生成测试"，结果 selector 全靠编，跑起来一片红，后来就没人用了。

最近把这件事挪进 OpenClaw 里重做了一遍，让 agent 挂上浏览器工具自己动手，效果才算立住。记录一下做法和教训。

## 问题

一次性生成失败，根因有二：

1. **模型没见过真实页面**。DOM 结构、组件库渲染出来的 class、异步加载时机，全在模型脑补范围之外。
2. **没有验证闭环**。生成完没人跑、跑挂了没人修，测试是死资产。Agent 的优势恰恰是能自己执行工具——那这个闭环就该由它来转。

## 做法

核心思路：不给 agent 出"写作题"，出"实验题"。流程五步：

1. **配工具**。给 OpenClaw 挂两类 MCP 工具：浏览器控制（导航、快照、点击、填表）和命令执行（能跑 `playwright test` 并回读输出与 trace 摘要）。
2. **先探索再动笔**。强制 agent 先打开目标页面拿 accessibility snapshot，selector 只允许从快照里选。页面缺 `data-testid` 的，先提任务补齐再进流程。
3. **按约定生成**。仓库里维护一份测试约定文档（fixture 用法、page object 结构、命名规则），agent 每次先读再写，输出风格与手写用例保持一致。
4. **跑挂自修**。生成后立即执行，失败时读报错和 trace 定位原因——selector 漂移、等待不足还是断言过弱——改完重跑，上限三轮，超了就停下留给人。
5. **人审合入**。产出 diff 附一段说明：覆盖了什么、哪些断言偏弱、已知风险。合入权在人。

## 踩坑点

- **假通过**：agent 天然倾向写必然通过的弱断言（只查元素存在）。我们对关键断言做一次变异验证——临时改坏对应功能，确认用例真的会红，红的才算数。
- **sleep 泛滥**：提示词里明令禁止硬等待，只许 `expect` 轮询，否则跑三遍挂两遍。
- **上下文爆炸**：整页快照动辄几千 token，长流程要分步截取，只喂当前步骤相关的子树。
- **本地绿 CI 红**：视口、时区、字体渲染都可能在容器里翻车，环境必须在本地和 CI 钉成同一套。
- **数据残留**：agent 每次随机造数据，没有清理 fixture，跑一周库就脏了。

## 可复用建议

- 把整套流程沉淀成 OpenClaw 的一个 skill（插件）：固定提示词、工具白名单、轮次上限写死，不靠每次现场调教。
- 用 hook 把触发点接在 PR 合并之后，新页面自动起草测试，人只管审。
- 心态上把 agent 当一个手速快但需要 review 的初级工程师：它产出草稿，质量关卡在人。上线后跟踪这批用例的 flaky 率，和手写用例放在一起比；数据不好看就回头改约定文档，而不是骂模型。

## 总结

Agent 写 E2E 的价值不在"生成文本"这个动作，而在闭环本身：能打开页面、能跑测试、能读失败、能自修。生成只是其中一环，验证才是瓶颈。把验证做扎实，模型越强收益越大；闭环不成立，再强的模型也只是产出更多死代码。
