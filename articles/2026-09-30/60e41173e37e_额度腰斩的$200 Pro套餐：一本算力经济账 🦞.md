花 $200 买顶配，结果额度先被砍了一半。据 36kr 报道，OpenAI 重启 ChatGPT Pro 套餐，但 pro 级模型的调用配额明显收紧，开发者社区的画风从"真香"秒切"退订"，骂声几乎刷屏。骂归骂，这背后其实是一本非常值得拆的算力经济账：为什么"不限量"的承诺在大模型时代注定撑不住？开发者的愤怒，又到底在气什么？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/4298f6e821310d72.png)

## 一、先看事件：Pro 套餐这一年经历了什么

- 2024 年 12 月，ChatGPT Pro 首次上线：$200/月，主打 o1 pro 模式，宣传口径接近"不限量使用"。
- 2025 年上半年，Deep Research、Codex、Sora 等高耗能功能陆续叠加进来，Pro 逐渐成为重度用户和开发者的事实标配。
- GPT-5 发布前后，Pro 套餐一度下架又重新上架——这就是所谓"重启"。重启之后，高端推理模型的配额明显收紧。
- 本轮变化的核心：pro 级模型调用、深度研究、长代理任务的额度大约砍半。开发者实测，同样一天的工作量，额度提前见底。

一句话概括：价格没动，天花板降了。老程序员都懂，所谓 unlimited，区别只在于上限写没写进文档。

## 二、算力账本：为什么"不限量"撑不住

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/ea9f133649251bb3.png)

1. **思考模型有 token 乘数效应。** o 系列、GPT-5 Pro 这类模型，会先在内部生成大量"思考 token"再给答案。用户看不见这些 token，但算力是真金白银烧掉的。一次 pro 级请求的算力消耗，可能是普通对话的 10 倍以上。
2. **单次成本可以到"美元级"。** 行业公开信息基本一致：pro 级模型单次请求的推理成本在数十美分到数美元之间。Sam Altman 在 Pro 上线时就公开承认过，重度用户"用得越多我们亏得越多"。举个粗糙的例子：假设一次深度研究综合成本 $2，重度用户一个月跑 150 次，算力成本就是 $300——月费还没捂热，账已经倒挂。
3. **逆向选择悖论。** 固定月费天然吸引用量最大的人，而他们恰好是成本最高的那批。订阅制在传统 SaaS 里成立，因为复制一份软件的边际成本趋近于零；大模型不成立，每多调一次 API，成本就实打实多一截。
4. **算力是刚性瓶颈。** GPU 集群规模短期是固定的，峰值时段一个重度用户的占用，等于挤掉好几个普通用户的体验。配额本质上是一种配给制——不是不想给你用，是物理上排不开。

更深一层：模型能力提升的重要方向之一就是把算力花在推理时（test-time compute）。这意味着"更强"和"更贵"在结构上锁死了，这是行业级趋势，不是某家突然变抠。

## 三、行业剧本：所有人都在从"包月"往"按量"退

OpenAI 不是第一个，大概率也不会是最后一个：

- **Anthropic**：Claude Max 推出周额度限制，官方给出的理由同样是编码代理的极端用量挤爆了资源。
- **Cursor**：从"不限量包月"转向按用量计费，2025 年年中引发过几乎一模一样的用户骂战。
- **GitHub Copilot**：引入 premium request 配额，重度场景单独计价。

共同逻辑只有一条：**AI 服务的成本随用量线性增长，而不是随席位数增长。** 传统订阅定价的根基是"边际成本≈0"，大模型把这条根基抽掉了。当各家从烧钱换增长转向追求毛利——上市公司尤其如此——"无限量"必然演化为"基础额度 + 加量包 + 峰值限速"的组合拳。

## 四、开发者在气什么：不只是钱的事

- **工作流被打断。** 编码代理的典型用法是连续跑几十轮"读代码—改代码—跑测试"，额度腰斩等于任务队列中途断供，整个 agentic loop 作废。对把 Pro 当生产工具的人，这不是体验问题，是产能问题。
- **规则信任受损。** 订阅制的核心价值是"可预期的固定支出"。配额静默收紧比明码标价更伤——上个月能跑 100 个任务，这个月只能跑 50 个，预算模型全作废，个人和团队都没法提前规划。
- **被锁定的焦虑。** 重度用户心里清楚，同样用量走 API 按量计费往往更贵，但迁移有成本，只能留在原地挨刀。这是典型的平台议价权不对称：你可以退订，但你退订的速度，赶不上人家改规则的速度。

## 五、三条冷思考：怎么在"额度时代"活下来

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/a43d005f57ece6cd.png)

1. **把订阅折算成"单位任务成本"再做决策。** 拿上个月的实际调用量除以月费，得到每任务单价，再和 API 报价对比。中低频用户订阅划算；高频代理任务，走 API + 小模型路由 + 结果缓存，通常更便宜也更可控。
2. **架构上保持可迁移。** 别把工作流绑死在任何一家的额度政策上。加一层 provider 抽象——统一的模型路由、prompt 管理、工具接口——让切换成本趋近于零。你的谈判筹码从来不是忠诚度，是随时能走。
3. **把额度当云资源来管。** 监控用量、设告警、错峰跑长任务、把机械性子任务降级到便宜模型。这套思路就是 AI 时代的 FinOps——不是抠门，而是让成本曲线服从工程决策，而不是反过来。

订阅制与推理经济学之间的张力，还会持续很多年。额度腰斩不会因为骂声就涨回去，但把账本看清楚的人，至少每次调价时，都不会措手不及。
