36kr 那篇实测的标题里藏着两个关键词：一个是「个人助理」，一个是「送钱」。前者说的是产品形态，DeepSeek 把 Harness 做成了桌面客户端，AI 不再住在你随手关掉的浏览器标签页里，而是拿到了你电脑的"门禁卡"；后者说的是推广打法，补贴。热搜看热闹容易，这篇想把三件事讲清楚：Harness 到底是什么？桌面版改变了什么交互范式？"送钱"背后，厂商在算什么账？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/f0adb779a6eed465.png)

## 一、Harness：包在模型外面的那层"骨架"

- **词源先捋一下**。Harness 原意是马具，赛马场上套在马身上、让人能驾驭它的那套装备。挪到 AI 圈，指包住大模型的执行环境：terminal、文件读写、浏览器控制、代码沙箱、长期记忆、权限管理。
- **为什么需要它**。模型本身只有"大脑"，输出永远只是 token。要让它真正干活，得接上"眼睛"（读屏幕、读文件）和"钳子"（执行命令、点按钮）。这套手脚系统，就是 harness。
- **这条路线已被反复验证**。过去一年，Claude Code 把 harness 架在终端里，各家 coding agent 架在 IDE 里。DeepSeek 的差异点是把官方 harness 直接做成桌面客户端——厂商下场定义执行环境，而不是只丢出一个 API 让开发者自己拼。
- **对普通用户的意义很直接**：不用配 MCP、不用写一行脚本，装个客户端就有完整的 agent 运行时。使用门槛从"会用终端的工程师"降到了"会装软件的任何人"。

## 二、从聊天框到助理：交互范式变了三处

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/95e9876cf85b7a28.png)

1. **输入变了：从"问问题"到"派任务"**。聊天框时代你想让它分析合同，得自己复制文本贴过去；桌面助理直接读本地文件，任务粒度变成"把这 12 张发票整理成报销表"。
2. **执行变了：跑 agentic loop**。plan → act → observe → reflect 的循环，先拆解任务，再调用工具，观察结果，发现报错自己回头修。实测里它能连续执行十几步不找人打断，这和"一问一答"已经是两个物种。
3. **输出变了：交付物替代答案**。聊天框给你一段话，你自己粘贴；助理直接给你改好的表格、跑通的脚本、归档完的文件夹。评价标准从"说得对不对"变成"事办没办成"。

举一个直观例子：整理乱成一团的下载文件夹。手动要花 40 分钟；助理模式下，你说一句"按文件类型和日期归档，重名文件保留最新版"，然后去倒杯水，回来活儿已经干完了。

## 三、"送钱"背后，厂商在算三笔账

据 36kr 的实测描述，产品里有新人奖励、任务激励、免费额度这类真金白银的投入。表面大方，实际是精算过的获客策略。拆开看有三层：

1. **数据账，最值钱的一笔**。训练一个能干活的 agent，最稀缺的不是算力，而是真实使用轨迹（trajectory）：哪步工具调用成功了、用户在哪一步纠正了它、任务最终怎么闭环。这些数据互联网上搜不到，只能从真实用户那里"跑"出来，是 agent 强化学习的直接原料。补贴买的不只是日活，是数据采集权。
2. **习惯账，入口之争**。一旦桌面助理成为你开机后的第一个动作，它就占据了"AI OS"的位置。默认入口的迁移成本极高，想想你上一次换浏览器是哪一年。补贴期的真正目标，是把"有事找助理"焊进你的肌肉记忆。
3. **生态账，飞轮的起点**。被激励的重度用户和开发者会产出工作流模板、插件和教程，反过来降低后来者的上手成本，形成正循环。

对比一下 2014 年前后的打车大战：当年补贴买的是支付习惯和出行入口，这次买的是行为数据加助理心智。逻辑一脉相承，只是标的物从交易流水换成了 trajectory。

## 四、泼点冷水：桌面 agent 的三个现实瓶颈

1. **可靠性的数学题**。假设单步操作成功率 90%，一个 10 步任务的整体成功率只剩约 35%（0.9 的 10 次方 ≈ 0.35）。误差沿链路累积，这就是为什么"演示很惊艳"和"每天稳定替你干活"之间，还隔着好几个版本。
2. **权限与安全的钢丝**。桌面 agent 要干活就得给权限：读文件、控浏览器、甚至碰支付。权限给多了怕误操作，给少了干不了活。最小权限原则加关键操作人工确认，是现阶段必须手动打开的设置，别指望默认配置就是安全的。
3. **成本结构待验证**。一次 agent 任务的 token 消耗可能是普通对话的几十倍，多轮规划、工具结果回灌、自我检查都在烧 token。补贴期能覆盖，补贴停了呢？这个问题的答案，决定了它最终是免费基础设施，还是订阅制服务。

## 五、给普通用户的三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-30/6a1454f7fd41819d.png)

1. **先派"只读任务"试水**。整理、总结、搜索、写报告这类不涉及删除和支付的任务，先跑一两周建立信任，再逐步放开写权限。别上来就让它碰网银和系统目录。
2. **把它当实习生，不是外包**。关键操作保留人工确认，文件改动前看一眼 diff，命令执行前扫一遍内容，像 review 代码一样 review 它的动作。信任是逐步授权出来的，不是一键全给的。
3. **补贴期内沉淀工作流，别只薅羊毛**。钱会停，但你调教出的指令模板、归档规则、周报流程是你的。产品可以换，流程资产带得走。

一句话收尾："送钱"是钩子，真正留住你的是它每天帮你省下的那 40 分钟。对厂商，这是一场入口之战；对用户，这是第一次值得认真考虑"给电脑配个助理"的时间点——带着审慎的乐观去用，收益最大。
