## 背景

E2E 测试是回报和成本都很极端的一类资产：跑通了能兜住核心链路，写起来却最费人。选择器易碎、流程一改就得跟着改、断言写浅了等于没写。我们在 OpenClaw 的 agent 工作流里接入了浏览器类 MCP 工具，让 agent 参与 E2E 用例的生成和维护，跑了两个迭代，记录一下可行的做法。

## 问题

直接把需求文档丢给 agent 说“帮我写 Playwright 测试”，产出基本不可用：

- 选择器全靠猜，页面上根本没有 `data-testid`；
- 用 `waitForTimeout(3000)` 糊等待，CI 上必炸；
- 断言只到“页面能打开”，核心业务状态没校验；
- 更隐蔽的是 agent 会顺手 mock 掉接口，测试绿了但什么都没测到。

根因不是模型不行，而是上下文不对：它没见过真实页面，也不懂团队的测试规范。

## 做法

1. **先给眼睛，再给笔。** 通过 Playwright MCP 让 agent 实际打开测试环境页面，取 accessibility snapshot（可访问性树）而不是截图。文本树自带 role、name 和层级，agent 生成选择器的命中率明显高于看图猜。
2. **让 agent 先走一遍流程。** 明确指示：只观察、不触发落库操作，逐步记录真实选择器和等待点，输出一份“流程纪要”，人过目后再进入生成环节。
3. **用项目规范约束生成。** 仓库里放一份 `e2e-conventions.md`：强制 page object、禁止 sleep、断言必须落在业务状态（如订单状态字段）、测试数据一律走 fixtures。作为 system prompt 注入。
4. **闭环跑批。** 生成后直接在隔离环境执行，失败日志（error snippet + 现场描述）回喂 agent 修复，限制 3 轮，防止无限改选择器。
5. **人工只审断言。** 选择器、等待、page object 交给 agent 维护；断言是否覆盖真实业务风险，由人拍板。

## 踩坑点

- **快照太大撑爆上下文。** 整页 snapshot 几千行，只喂目标区域，或让 agent 先定位再截取。
- **agent 对“测试通过”有执念。** 不加约束它会删断言让用例变绿，指令里必须写明“禁止通过弱化断言修复失败”。
- **测试环境数据漂移。** 昨天能跑今天挂，查下来是共享环境的脏数据。测试数据必须 agent 自己建、自己清理。
- **验证码 / OTP 流程。** 别让 agent 硬绕，直接给测试后门 token 或 stub 掉认证中间件，并把这条写进规范。

## 可复用建议

- 把“流程纪要 → 规范注入 → 生成 → 执行回喂”固化成一个 OpenClaw 工作流或插件，一次搭好长期用。
- 规范文档比 prompt 措辞重要：团队约定沉淀成文件，agent 每次都读。
- 统计“agent 首轮通过率”，低于 60% 时先修上下文质量，而不是怪模型。
- 支付、删除等敏感流程保持人工编写，agent 生成的拿来做对照草稿。

## 总结

这套协作的本质是把 E2E 的成本重心从“手写”移到“审阅”。agent 负责它擅长的重复劳动——找选择器、处理等待、套模板；人负责它不擅长的判断——断言对不对、风险覆盖够不够。上下文给足、闭环收紧，AI 写的 E2E 才是真测试，而不是绿的安慰剂。
