## 背景

我用 OpenClaw 加 MCP 插件搭了一套社区内容流水线：抓取资料、整理成帖、定时发布。跑了两周被管理员提醒：发帖时间太规律、内容模板味重、从不参与评论区，一眼就是脚本。问题不在"能不能发"，而在"发得像不像一个正常的社区成员"。

## 问题

机器行为的典型特征其实很集中：

1. **时间均匀**：每天 9:00、14:00 准时发，间隔方差接近 0
2. **内容同构**：同一套句式模板，只改几个词
3. **突发补发**：重试逻辑导致失败后连环补发，短时间刷屏
4. **只发不回**：从不读评论，行为单向

这些先暴露的往往不是态度问题，而是工程问题——被限流、被折叠、被移出。

## 做法

**Step 1：调度层加抖动。** 不用裸 cron，用"窗口 + 随机偏移"：

```python
base = random.choice(WINDOWS)        # 早/午/晚各一个窗口
t = base + random.gauss(0, 40 * 60)  # 高斯抖动，标准差 40 分钟
t = max(now, t)
```

均匀分布肉眼仍能看出"整点附近聚集"，换成高斯后观感明显改善。

**Step 2：全局配额 + 令牌桶。** 按天设硬上限（比如 2 条），按周设软上限，卡在发送函数入口而不是调度入口。失败走指数退避，退避后的时间点重新参与抖动，不立即重发。

**Step 3：内容层去同质化。** 发布前与最近 N 条历史帖算 embedding 余弦相似度（简单场景用 shingle 也行），超过阈值 0.85 就打回草稿队列重写。准备 2-3 套结构骨架轮换，但注意：轮换模板不等于拟人，过度轮换反而像洗稿。

**Step 4：静默时段与日历感知。** 凌晨 1–7 点不发，节假日和社区活动周降频或暂停。把这些做成 MCP tool 的配置参数，而不是改代码。

**Step 5：人在环上。** 所有帖子先进审核队列，人工 30 秒扫一眼再放行。这不是偷懒，是成本最低的"像人"手段——人改过的东西才真的像人。

## 踩坑点

- 重试逻辑放在调度层外面，失败后一天连发 5 条；配额必须卡在发送入口
- 相似度阈值设太低（0.7），正常更新帖也被拦，陷入重写死循环；阈值要和最大重写次数一起配
- 时区坑：服务器 UTC、社区 UTC+8，静默时段全错位，发帖全落在半夜
- 自动回复比自动发帖更容易显得机械，宁缺毋滥，至少要让流程包含"读评论、汇总给人工"这一环

## 可复用建议

- **参数全部外置**：窗口、方差、日配额、静默时段、相似度阈值，都进配置
- **留观测数据**：每次记录计划时间 vs 实际时间，跑两周画出间隔分布图，方差是否接近 0 一眼可见
- **最低配方案**：日上限 + 抖动 + 人工过目，三件套就能解决 80% 的问题
- **规则优先**：如果社区要求机器人标明身份，照做。伪装身份带来的封禁风险远大于收益

## 总结

"不像机器人"本质不是话术问题，是节奏问题：时间分布有方差、频率有上限、内容有差异、行为有反馈、关键节点有人。把"拟人化"拆成这五个可测的工程指标，比在 prompt 里反复要求模型"写得像人"靠谱得多。
