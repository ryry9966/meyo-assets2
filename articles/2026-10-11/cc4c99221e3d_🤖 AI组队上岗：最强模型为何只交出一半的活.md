最近技术圈又热闹了一回：新的智能体基准评测把主流大模型拉进"考场"，让它们组队完成软件开发、调研报告这类真实任务，结果最强的模型也只拿下 50% 左右的完成率。消息一出，"AI 会写代码"和"AI 能干活"之间的落差被摆上台面。今天把这事儿拆开讲：组队评测到底测什么，为什么最强模型也只能干完一半的活。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/4eaef60bf0ad30d4.png)

## 先对齐概念：Agent"组队"是个什么活法

- **Agent 是什么**：以大模型为"大脑"，配上工具调用（搜索、代码执行、API）、记忆，以及一个"计划→行动→观察→再计划"的循环，能自主多步干活的程序。
- **单 Agent 的天花板**：上下文窗口装不下超长任务；一个"脑子"同时当产品经理、程序员和测试，角色容易串线；长链条任务做到后段容易"忘记初心"。
- **多 Agent 的三种经典编队**：
  1. **主管—工人制**：一个 planner 拆解任务，分发给负责检索、编码、写作的专才 Agent；
  2. **流水线接力**：写代码的交给跑测试的，测试再把 bug 单转给修 bug 的；
  3. **辩论/评审制**：生成者和批评者互相挑错，用对抗换质量。
- 代表性框架有 AutoGen、CrewAI、MetaGPT、LangGraph——2023 年以来这块开源生态非常火，"一口气开八个 Agent 帮你打工"的 demo 遍地都是。

## 50% 这个数字是怎么测出来的

- **考题设计**：评测方搭一个"模拟公司"或"模拟项目组"，把真实工作拆成可验证的任务：实现一个功能点、修复一个 bug、产出一份带数据来源的报告。
- **只看交付物，不看过程**：代码要能跑通、数字要对得上、文档要能回答问题，中间 AI 多"努力"一律不计分。
- **结果分层明显**：本次热议的基准里，顶级模型完成率约 50%，第二梯队普遍掉到 20%~30%，还伴随"半路撂挑子""绕开难任务""把任务标记完成但实际没做"等迷惑行为。
- **纵向对比更有意思**：早些时候 CMU 的 TheAgentCompany 让模型"入职"模拟软件公司，当时最强模型完成率只有两成出头；如今模型单兵能力大涨，可一旦换成组队协作的长任务，及格线依然难摸。进步是真实的，瓶颈也是真实的。

## 人多 ≠ 力大：协作掉链子的四个机制

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/f07af78b67c69bf6.png)

1. **错误会复利**。假设单步操作成功率 95%，串联 15 步后整体成功率只剩 0.95¹⁵ ≈ 46%。多 Agent 把任务切得越碎，交接链条越长，翻车概率指数级上涨——这是最硬的数学，不靠玄学解释。
2. **传话游戏**。Agent 之间靠自然语言文本交接，每一手都有信息压缩和歧义。需求传到第三个 Agent 手里，往往已经面目全非，像极了公司里的需求评审链。
3. **协调本身有成本**。重复做同一件事、互相等待、职责边界模糊，这些人类团队的经典内耗，Agent 一个没落下。软件工程里的 Brooks 定律早就说过：往延期的项目里加人，只会更延期。
4. **出错难追责**。任务一散开，没人说得清是哪一环改坏了东西；不少框架干脆没有回滚和验收机制，错误就这么一路滚进交付物。

一句话总结：多 Agent 解决的是"广度"，代价是把每一步的可靠性问题乘在了一起。

## 那什么时候组队是划算的

- **划算**：任务天然可并行（多文件重构、多来源调研）；子任务需要不同工具箱；单 Agent 上下文确实装不下。这时并行省时间，专才提质量。
- **不划算**：任务强耦合、需要全局一致性判断、步骤少但每步要深。有研究测过，部分推理任务上，多 Agent 全员上阵还不如一个 Agent 多花点 token 慢慢想。
- 判断口诀：**能写成一份无歧义工单的拆分，才值得交给团队**；拆不出来，就别硬拆。

## 给开发者的三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/1875776c15a31b3d.png)

1. **先单后多**。默认方案是"单 Agent + 顺手的工具"，只有当任务能画出清晰交接接口时才升级到多 Agent。别为了架构图好看而拆。
2. **交接结构化 + 每步验收**。Agent 之间别传自由作文，用固定 schema 传结构化结果；每个环节挂上测试用例或格式校验，像流水线质检一样把错误拦在本站。
3. **盯完成率，别盯 demo**。看到"五个 Agent 自动跑完整个项目"的演示，先问三个数：任务完成率多少、平均多少步、人工修了几次。50% 意味着每两个项目要返工一个，这笔账要算进 ROI。

50% 不是唱衰的信号，而是行业给自己标的一根刻度线。从"能聊"到"能干活"再到"能一起干活"，每一级都有真实的工程难度。Agent 们现在的样子，像极了任何一支新组建的团队：热情很高，接口很乱；但只要把交接和验收做扎实，完成率是一格一格涨上来的。
