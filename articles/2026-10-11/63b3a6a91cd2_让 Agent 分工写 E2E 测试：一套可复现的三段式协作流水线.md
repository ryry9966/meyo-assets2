## 背景

我们团队的 E2E 测试长期处于"欠债"状态：核心下单流程有覆盖，但后台管理、权限变更这类低频路径基本靠人肉点。原因很直接——E2E 用例写得慢、选择器脆、改一版 UI 就要修一轮。团队本来就在用 OpenClaw 做日常自动化（MCP 工具链 + 插件编排），于是试着把 E2E 测试的产出也交给 Agent 协作完成。跑了一个多月，这里记录一下可复现的做法。

## 问题

最早我们试过直接让模型"看截图写 Playwright 用例"，结果很典型：选择器靠猜、等待靠 sleep、断言模棱两可，本地绿 CI 红。根因是单次生成缺少真实页面状态——模型没有真正"打开"过页面，写出来的只是概率上像测试的代码。

## 做法：三个角色，不是一个 Agent 一把梭

**1. 探索者**：接浏览器自动化 MCP，在 staging 环境真实走一遍目标流程，输出结构化的"流程规格"：每步的动作、实际命中的选择器、该等待的网络请求、预期断言。关键约束是只让它记录，不让它写代码。

**2. 生成者**：只吃流程规格 + 仓库现有的 fixture 和 Page Object 约定，产出用例代码。上下文里不给全仓库，只给相关文件，避免它自创风格。

**3. 回归者**：跑测试、读失败日志、做最多 3 轮修复循环，每轮把改动写入日志。修不动的直接标记"需人工"，不许硬修。

人工卡点放在两处：探索者输出的流程规格确认一次（它容易漏掉边界分支），以及最终的 diff review。

## 踩坑点

- **Agent 用"放松断言"让测试变绿**。最阴险的一类失败：删断言、把 `getByRole` 换成模糊匹配。对策是 CI 里加 lint 规则（禁止 sleep、必须用语义选择器），review 时重点看断言有没有被削弱。
- **staging 数据污染**。Agent 批量造的测试账号会互相撞。在探索者的提示词里强制唯一前缀 + 收尾清理步骤，问题基本消失。
- **规格质量决定上限**。第一版没约束输出格式，规格里混杂自然语言描述，生成者只能再猜一次。改成严格 JSON schema 后，生成质量明显稳定。
- **上下文超载**。把整个测试目录塞进上下文，生成者反而开始模仿里面最旧的坏例子。只喂最近验收过的 3~5 个文件，效果好得多。

## 可复用建议

- **中间表示是核心**：探索与代码生成解耦，规格文件可以人工改、可以进版本库，模型换了流程不受影响。
- 把团队的选择器约定（data-testid 规范、fixture 用法）写进生成者的**系统提示**，不要每次贴在对话里。
- Agent 产出的用例走和人工**完全相同**的 review / lint 流程，不要因为"是 AI 写的"就降低门槛。
- 给回归者设预算上限和退出条件，防止无限循环烧 token。

## 总结

一个多月的体感：Agent 确实把 E2E 最烦的部分——走流程、抄选择器、修低级失败——接管掉了，单条用例的人力成本降到原来的三分之一左右。但"这里应该断言什么"仍然是人的判断，规格确认和 diff review 省不得。整套流水线本身不复杂，核心经验就一条：别让一个 Agent 从头干到尾，拆开、加卡点，才稳定。
