## 背景

OpenClaw 的工作区里有一组约定俗成的 Markdown 文件：AGENTS.md 管操作流程，MEMORY.md 管长期记忆，而 SOUL.md 负责回答一个更根本的问题——**这个 Agent 是谁，它不做什么**。SOUL.md 会在每次会话启动时注入上下文，相当于所有对话共用的系统级人格层。很多人搭完环境直接跳过这个文件，或者贴一段抄来的模板，结果就是 Agent 行为飘忽：时而过度的热情，时而越界执行。

## 问题

不写 SOUL.md 的代价不会立刻显现，通常在自动化场景里集中爆发：

- 群聊里它抢答、刷存在感，私聊和群聊没有行为区分；
- 心跳任务里它自作主张，执行了本该先确认的操作；
- 你说"帮忙处理一下"，它把含糊指令猜成了危险的默认值；
- 换模型或升级版本后语气突变，之前的调教经验全部失效。

这些本质是同一件事：人格和边界没有显式声明，全靠模型默认值兜底。

## 做法

我的 SOUL.md 大约 40 行，分五段：

1. **身份**：名字、外观类基础设定如果拆了 IDENTITY.md 就放那边，SOUL.md 专注语言行为——明确写"默认使用简体中文回复"。
2. **语气基线**：描述可观察的行为而非形容词。不写"要谦虚"，写"不确定时先说不确定，再给两个候选答案"。
3. **硬边界**：每条一行，动词开头。核心三条——不可逆操作（删除、发送、支付、改配置）必须先列出影响并等待确认；不主动读取或引用记忆文件里的私人内容；没被问到不主动扩展任务范围。
4. **拒绝话术**：给一两句固定句式，避免它临场发挥出奇怪的道歉文学。
5. **场景差异**：群聊中只在被 @ 或明确接话时发言；cron 和心跳任务只做最小动作，不闲聊。

写完新开会话让新版本生效，用一组固定的"边界探针"提示词测一遍：让它删个文件、让它替你回复消息、在群里 @ 它无关话题，观察是否触发确认。

## 踩坑点

- **写成小作文**。超过百行会稀释指令权重，还烧 token。人格层要短，流程细节放 AGENTS.md。
- **和 AGENTS.md 打架**。SOUL.md 管人格和边界，AGENTS.md 管操作步骤，同一件事两边写规则，行为就不可预测。
- **只有正向描述**。"保持谨慎"没有可执行语义，模型各自解读；"先确认再执行"才有判断标准。
- **改了没生效**。SOUL.md 是会话启动时读取的，在旧会话里测试会得出错误结论。
- **人格在自动化里超重**。心跳和 cron 不需要完整人格，把它当闲聊对象是对 token 的浪费。

## 可复用建议

- 用 git 管理整个 workspace，每次调 SOUL.md 单独提交，行为回归时有 diff 可查；
- 维护 10 条左右的边界探针提示词作为测试集，每次改动后跑一遍；
- 按场景分层：SOUL.md 放通用人格，具体任务的约束写在对应工具/插件的说明文件里；
- 边界条目用"条件 + 动作"格式，例如"涉及花钱：先报价，等确认"，模型好对齐，你也好审计。

## 总结

SOUL.md 的价值不在写得动人，而在于把"我希望它是什么样"翻译成模型每次都能读到的、可判断的规则。短、具体、可测试，是三个够用的标准。人格调好之后你会发现，很多此前归咎于"模型不行"的问题，其实是环境里没写清楚。
