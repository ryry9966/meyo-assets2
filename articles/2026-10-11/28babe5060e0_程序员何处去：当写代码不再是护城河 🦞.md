36kr 那篇《程序员何处去》能冲上热搜，说明焦虑已经不是个别现象。一边是 Copilot、Cursor、Claude Code 把"写代码"的成本打到地板，一边是行业招聘从扩张转向收缩，两件事撞进了同一个时间窗口。情绪先放一边，这篇用工程师的方式拆三件事：什么在变、什么没变、人往哪挪——给结论，也给依据。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/c06dca39631ae3c0.png)

## 一、焦虑从哪来：三股力量同时进站

- **AI 编程工具的曲线变陡了。** GitHub 对 Copilot 的对照实验显示，受控任务完成速度提升约 55%；2024 年之后，Cursor、Claude Code 这类工具已经能独立完成多文件的中小型改动。以前 AI 抢的是"补全"，现在抢的是"初级交付"，抢的姿势越来越像正式工。
- **行业周期切换。** 互联网从增量市场进入存量市场，大厂招聘从"扩编"变成"替换"，坑位不再凭空多出来。
- **供给基数变大。** 过去十年计算机相关专业持续扩招，入行者数量的增长跑在了行业扩张前面。

三件事叠加，焦虑不是错觉。但注意它的性质：这是**结构性信号**，不是"行业要没了"的信号。结构变化的典型特征是——有些技能迅速贬值，有些位置反而更贵。

## 二、历史参照：程序员的岗位是被工具"喂大"的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/6aded70b971b9347.png)

看历史会更冷静：

1. 1950 年代程序员直接写汇编，FORTRAN 编译器 1957 年问世时，很多人担心"不用手写汇编，程序员就要失业了"。结果恰恰相反：软件复杂度的上限被抬高，需要更多人去写更大的系统。
2. 之后每一层抽象——高级语言、IDE、开源生态、云计算——都在重复同一个剧本：**做软件变便宜 → 软件被做得更多更复杂 → 更高层的岗位变多**。
3. 经济学里这叫杰文斯悖论（Jevons Paradox）：1865 年 Jevons 发现蒸汽机效率提升后，煤耗不降反升。效率提升降低使用成本，成本降低放大总需求。

写代码的成本正在被 AI 打下来，剧本大概率还是同一个：**被淘汰的从来不是"程序员"这个职业，而是某个具体的技能层。** 这一次被压缩的，是"把明确需求翻译成代码"这一层。

## 三、真正在变的：技能阶梯在重新洗牌

把程序员的工作拆成五层，AI 的侵蚀程度完全不同：

1. **把需求翻译成代码**——正被快速接管。样板代码、CRUD、配置、常规单测，AI 已经做得又快又便宜。
2. **把模糊问题定义成需求**——很难被替代。业务方自己都说不清要什么的时候，AI 没有抓手。
3. **系统设计与权衡**——几乎没有唯一解。上不上缓存？强一致还是最终一致？本质是在成本、延迟、可维护性之间做取舍，需要一个为决策负责的人。
4. **验证与兜底**——AI 能生成代码，但责任无法生成。线上事故、安全漏洞、合规风险，`git blame` 追到最后指向的还是人。
5. **跨界翻译**——同时懂技术和行业的人，负责把两边的语言对上。

举个例子：Cursor 可以让初级前端半天画完一个落地页，但"这个页面转化率为什么低、信息架构该怎么改"依然要靠人判断。岗位画像因此改变：美国劳工统计局（BLS）对软件开发岗位未来十年的增速预测约为 17%，仍显著高于全职业平均水平——但增量集中在能做第 2~5 层的人身上，第 1 层的坑位在肉眼可见地减少。

## 四、往哪里去：四条被验证过的跑道

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/15304313569f6c4a.png)

- **AI 基础设施层。** 推理优化、GPU 调度、RAG 与 Agent 工程化。每次平台迁移都会长出新工种——移动互联网催生了 Android/iOS 工程师，AI 平台化正在复制这个过程。
- **软件渗透"慢行业"。** 制造、医疗、农业、能源的数字化程度远低于互联网，缺的不是会写代码的人，而是懂行业又能把系统落地的人。
- **硬件 + 软件交叉。** 新能源车、机器人、IoT。这类场景对代码可靠性的容错率极低，纯 AI 生成的代码不敢直接上线，人的验证价值反而更稳。
- **技术出海。** 把国内验证过的产品与工程能力带向海外市场，工程师是最容易随产品一起迁移的资产之一。

判断一条跑道值不值得去，用三个过滤器过一遍：

1. 需求是真实增长，还是概念先行？
2. 你的存量经验能复用多少，转型成本算不算得过来？
3. 它的瓶颈在"写代码"，还是在别处？**瓶颈在别处的地方，程序员更值钱。**

## 五、冷思考：比逃离焦虑更管用的三件事

1. **把 AI 当杠杆，而不是对手。** 每天用它完成真实任务，练出"审查 AI 产出"的手感。未来的绩效会越来越看"单位时间交付的有效变更"，而不是代码行数——会用杠杆的人，产出密度是别人的好几倍。
2. **把学习预算投给慢变量。** 框架是快变量，两年一换；OS、网络、分布式、数据结构是慢变量，老化周期以十年计。AI 越擅长上层抽象，底层理解就越稀缺——因为排查问题时，你得知道地板在哪。
3. **构建"技术 + X"的复利。** 挑一个行业扎进去三年，让自己成为"那个最懂业务的技术人"。这个位置的护城河不是代码，而是上下文积累和信任，这两样东西 AI 都复制不了。

潮水换向的时候，最先看清流向的人，从来不需要游得最快。先看清，再换挡，别把力气耗在原地焦虑上。
