## 背景

把 Agent 接进社区场景现在是常规操作：自动答疑、issue 分诊、周报摘要。但跑着跑着你会发现，Agent 手里握着的三样东西——系统提示词、MCP/插件工具清单、工作区记忆文件——恰好也是你最不想公开的部分。社区是公开场合，Agent 是自动化出口，两者叠起来就是一条容易被忽视的泄露面。

## 三条泄露路径

实际出事的基本就这三种：

1. **人为粘贴**：调试时把完整 config、system prompt、MCP server 列表、终端截图直接贴进社区求助。
2. **Agent 主动输出**：给了社区发帖权限的 Agent，回答时引用了内部文档、私有端点、客户数据。
3. **上下文导出**：为复现问题导出 session 或记忆文件上传，里面带着历史对话、内部路径和工具调用记录。

## 做法：五步划红线

**1. 先划资产。** 把“内部信息”列成清单：提示词、工具名与端点、项目代号、目录结构、SOP、记忆文件。划不清楚，等于没有红线。

**2. 权限最小化。** 社区发帖用独立低权限身份，只给“写社区频道”一个能力；社区问答 Agent 和内部运维 Agent 不共享同一个 MCP 实例，否则后者会继承前者的访问面。

**3. 出口加闸门。** 在发送前加一层 hook 做输出扫描：匹配密钥格式、内网域名、绝对路径、项目代号，命中即拦截转人工。这层闸门必须放在工具/网关层，不能只写在提示词里。

**4. 备一份脱敏调试模板。** 做占位符版 config 专门用于社区求助，或起一个"debug profile"，端点全是假地址。求助贴模板，不贴原件。

**5. 记忆分区。** 社区会话不挂载私有记忆目录；调试导出的 session 先过一遍脱敏再上传。

## 踩坑点

- **只拦 API key 正则。** 密钥好拦，项目代号、内网 hostname、`/srv/xxx` 这类路径才是高频泄露源，正则覆盖不到就得靠代号词典。
- **把“不要泄露”写进提示词当防线。** 提示词是约束不是执行，模型可以被绕；执行必须落在网关层。
- **脱敏了截图正文，忘了窗口标题和终端回滚。** 回滚缓冲区里那行 token 经常一起入镜。
- **事后才清理记忆文件。** 帖子删得掉，已经进上下文的内容收不回来，记忆污染要按“已泄露”处理。

## 可复用清单

- 所有对外输出必过闸门，拦截记录留痕可审计
- 社区身份与内部身份物理隔离
- 常备一份脱敏求助模板，随用随贴
- 私有记忆不进公开会话，导出必脱敏
- 每月做一次审计：Agent 能读什么 × 能写到哪里，两个集合的差就是风险面

## 总结

红线不是一句提示词，而是一组工程边界：资产清单、权限隔离、出口闸门、记忆分区。核心心态只有一条——把 Agent 的每一条对外输出都当成不可信出口来设计。这样即使哪天被套话、被误触发，你也有得拦、有得查、有得撤。
