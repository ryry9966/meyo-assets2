## 背景

OpenClaw 的 workspace 里已经有一套文件约定：AGENTS.md 管行为规则，SOUL.md 管人格语气，MEMORY.md 管每日记忆。但跑了一段时间你会发现，这三份文件回答的都是"Agent 应该怎样"，没有一份回答"它在服务谁"。

结果是每个新会话都在重新认识你：时区猜错、称呼不对、你上个月确认过的部署环境它一无所知，长期偏好全靠在聊天记录里碰运气。

## 问题

把个人信息往 AGENTS.md 里塞是常见的第一反应，但很快会出问题：

1. 规则文件越来越臃肿，真正重要的行为指令被稀释；
2. 身份信息和规则混在一起，改的时候容易误伤；
3. 这些信息大多是"关于我的事实"，生命周期和规则完全不同。

USER.md 就是把这一层拆出来：一份稳定的、关于"你是谁"的事实档案，每次会话随 workspace 上下文自动加载。

## 做法与步骤

**第一步：建文件。** 在 workspace 根目录新建 USER.md，不用改任何配置，它会被当作上下文的一部分读入。

**第二步：按三层写。** 我的结构：

```markdown
# 用户档案
## 身份
- 称呼：老陈
- 时区：Asia/Shanghai
- 语言：默认中文回复，技术名词保留英文
## 环境
- 主力环境：家里一台 Linux 小主机，OpenClaw 跑在 Docker 里
- 常用工具：Obsidian、Git、自建 Nextcloud
## 偏好
- 先给结论，再给推理过程
- 不确定时直接说不确定，不要编
```

**第三步：控制生命周期。** 稳定事实进 USER.md，易变事项（本周安排、某个项目进展）留给 MEMORY.md。判断标准很简单：三个月后这句话还成立吗？

**第四步：让 Agent 参与维护。** 对话中确认了新的长期事实，直接说一句"把这个更新进 USER.md"，比手动维护省力得多。我固定每月 review 一次，删掉过时条目。

**第五步：验证。** 新开会话，问几个只有档案里才有的事实（时区、称呼、部署方式），确认加载真的生效，而不是靠猜。

## 踩坑点

- **敏感信息别放。** USER.md 会进模型上下文，也会随 workspace 备份和同步。密钥、详细住址这类内容写进去就是给自己埋雷。
- **写成简历。** 档案不是越全越好，每个条目都占 token。我第一版写了 60 多行，精简到 25 行后效果反而更好，因为重点不再被稀释。
- **愿望式表述。** "希望沟通高效"没有信息量，"先结论后过程"才是可执行指令。每条都问自己：Agent 能据此做出不同行为吗？
- **职责重叠。** USER.md 和 SOUL.md 里都写"语气直接"，两处修改不同步就会出现矛盾行为。原则：一个事实只放一个地方。

## 可复用建议

- 25 行以内起步，优先写时区、称呼、语言偏好这三个最容易出错的字段；
- 每条尽量是一行、可判断真伪的事实，方便后续删改和 review；
- 多实例（工作/生活分开部署）各写一份 USER.md 即可，重叠部分复制就行，别搞花哨的引用机制；
- 团队场景同理，可以衍生一份记录团队约定的 PROJECT.md，思路完全一致。

## 总结

USER.md 做的事情很朴素：把"关于用户的事实"从聊天记录和规则文件里拆出来，变成一份显式、可版本管理、可持续维护的档案。它本身没有任何智能，但它把 Agent 的默认猜测换成了你的明确输入——在自动化系统里，这往往就是"偶尔靠谱"和"稳定可用"之间的差距。
