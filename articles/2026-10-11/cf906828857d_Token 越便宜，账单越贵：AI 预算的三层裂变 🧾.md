过去两年，大模型推理价格经历了教科书级的跳水：GPT-4 发布时输入价格 $30/百万 tokens，如今同级模型已跌到 $2 上下，开源侧更低。按常识，企业的 AI 账单该越省越多，现实恰好相反——36kr 报道的热议话题指出，美国企业的 AI 预算正在"裂成三层"，其中一层正大规模流向中国的开源模型。单价更便宜、总账更贵，这不是玄学，是经济学定律叠加工程结构的必然结果，值得拆开看清楚。

## 单价跳水、总账暴涨：Jevons 悖论重演

- 1865 年，经济学家 William Stanley Jevons 在《煤炭问题》里记录了一个反直觉现象：蒸汽机效率提升、烧煤成本下降后，英国煤炭总消耗不降反升——成本下降刺激了更多使用场景，需求弹性远超预期。这就是 **Jevons 悖论**。
- LLM 推理正在精确复刻这条曲线：GPT-4 级别的智能从 $30/M tokens 跌到 $2 上下只用了约一年半；DeepSeek-V3 的 API 输入定价 $0.27/M（cache miss 口径），R1 约 $0.55/M，比同期闭源推理模型低一到两个数量级。
- 小学数学开始生效：单价 × 用量 = 总账。单价跌 10 倍，用量涨 30 倍，账单还是涨 3 倍。
- 2025 年 1 月 DeepSeek-R1 发布当天，英伟达单日市值蒸发约 5890 亿美元，市场恐惧的正是这个逻辑：智能变便宜，需求会不会爆炸？后来的答案是：会，而且整体右移。

## 账单里的隐藏项：Agent 时代，token 是被"乘"出来的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/8a44f0c53e199c5b.png)

单价只是成本公式的一个变量，真正的推手在应用形态上。

- Chatbot 时代是"加法"：一次提问 = 一次推理，消耗可预估。
- Agent 时代变成"乘法"：一个 agent 任务 = 规划 + 多轮工具调用 + 每轮重读上下文 + 失败重试。上下文随轮次累积，第 N 轮的输入包含前 N-1 轮的全部内容，总消耗近似 O(N²)。
- 举个工程上常见的例子：编程 agent 修一个 bug，读代码库花 5 万 tokens，规划 2 万，工具调用 10 轮、每轮重读上下文，单任务烧掉 30 万+ tokens 很正常——相当于上百次普通问答。
- tokens 之外还有"影子成本"：eval 评估流水线、可观测性、向量库、人工抽检、路由网关本身。有行业分析估计，推理费用只占 AI 应用总成本的 30%~50%，其余是工程与运营。
- 结论：token 降价只优化了一个变量，而 agent 化把其余变量指数级拉高。这是"越便宜、越贵"的第二重解释。

## 预算裂成三层：从"一个大模型包打天下"到"模型组合拳"

美国企业的采购结构，正在从"选一家旗舰"变成"搭一个梯队"：

1. **前沿层**：o1/R1 类 reasoning 模型、Claude、Gemini，负责高难度规划、代码、复杂推理。流量占比可能只有 5%~15%，却吃掉大头预算——贵，但用在刀刃上。
2. **主力层**：GPT-4o-mini、Claude Haiku、Gemini Flash 这类轻量旗舰，承接日常摘要、分类、信息抽取，性价比优先。
3. **海量层**：格式转换、内容审核初筛、数据清洗、内部搜索改写——单次任务简单、调用频次极高。这一层正大规模转向开源模型，其中相当比例是中国系：DeepSeek、Qwen（阿里通义）、GLM（智谱）。

落地形态有两种：直接调低价 API，或者自托管——用 vLLM/SGLang 起服务，GPU 成本摊薄后，每百万 tokens 的边际成本可以压到很低。工程上的标准打法是 model routing：网关按任务类型和难度分流，简单任务走第三层，置信度不足自动升级到第一层，省的正是长尾里的最大头。

## 为什么接住海量层的是中国的开源模型

- **许可证友好**：DeepSeek-R1 用 MIT、V3 许可允许商用，Qwen 主流版本 Apache 2.0——可商用、可蒸馏、可自托管，企业最关心的三个"能不能"全给了。
- **架构效率**：DeepSeek-V3 采用 MoE 架构，总参数 671B、每 token 仅激活约 37B，推理成本天然低于同规模 dense 模型；训练阶段 GPU 租金口径约 558 万美元，虽不含前期研发，但足以说明工程优化的功力。
- **性能踩线**：在通用知识、代码、数学等基准上，DeepSeek-V3/R1 与 Qwen 系列已接近同期闭源旗舰，而价格低一到两个数量级。对海量层任务，这点差异用户通常无感。
- **生态在位**：Azure AI Foundry、AWS Bedrock 以及 Together、Fireworks、Groq 等均提供托管，调一个 OpenAI 兼容接口就能用，现有架构几乎不用改。
- **数据主权**：开源权重 + 自托管意味着数据不出企业内网，对合规敏感行业是硬需求，这也是"美国云厂商 + 中国开源权重"组合能成立的原因。

## 便宜不等于免费：这一层的代价清单

- **运维成本转移**：自托管意味着自己管 GPU、量化、并发和显存。省下的 API 费用，一部分变成了运维工程师的工资——你不是省了 token 钱，你是把账单换成了工资单。
- **质量长尾**：基准分接近不等于生产环境表现一致。幻觉率、指令遵循、多语言细节都要按自己的业务做 eval；错误代价高的场景（金融、医疗），慎用海量层模型直出。
- **版本漂移**：开源模型迭代快，权重一换行为可能漂移，回归测试要纳入流程。
- **治理流程**：涉密或受监管数据能否使用特定来源的模型权重与 API，需走各企业自己的数据治理评审——这是流程事实，各家标准不同。
- **迁移惯性**：开源看似自由，但深度定制之后，切换成本同样逐年累积，"自由"不等于"零成本迁移"。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/89d879f0c8fb32a2.png)

1. **别只算单价，要算"任务经济"**。为核心场景建立 per-task 成本基线：token 数 × 单价 + 重试率 + 人工复核成本，按月复盘。降价红利只属于有度量体系的人。
2. **用架构吃掉红利，而不是靠等降价**。prompt cache（命中读取通常只要原价的一到五成）、batch API、量化/蒸馏、模型路由——四件套下来，同样的预算能多干 3~10 倍的活。省钱的正确姿势是让便宜的 token 干更多活，而不是少干活。
3. **接受 Jevons 悖论是常态**。预算按"用量增长曲线"规划，而不是按"单价下降曲线"幻想。当智能的边际成本趋近于零，稀缺的不再是 tokens，而是判断力——知道哪些任务值得烧贵的 token，哪些用便宜的就够了。
