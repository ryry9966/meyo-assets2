## 背景

OpenClaw 的主会话是长期存活的：你和助手的对话、工具调用记录、系统注入，全都堆在同一份 transcript 里。跑批量任务时如果让主会话亲自下场，比如逐个扫描 50 个文件、爬一组页面、跑一轮数据核对，中间产生的工具输出会把上下文撑爆。轻则 token 开销上涨、响应变慢，重则模型"失忆"，把早前对话里的关键约束丢掉。

子 Agent 机制就是为这个设计的：把脏活外包到一个独立 session，干完只把结论带回来。但实践中要提醒一句：**开了子 Agent 不等于隔离生效**，配置不当照样互相污染。这篇记录我们踩过坑之后沉淀下来的做法。

## 问题：污染的三种形态

1. **上下文污染**：子任务的全量工具输出直接涌入主会话 transcript；
2. **状态污染**：子 Agent 往主工作区写临时文件、改共享配置，后续任务读到脏数据；
3. **会话复用污染**：跑完的子 session 被拿来接新任务，上一单的残留上下文悄悄影响行为。

## 做法：三层隔离

核心是**会话隔离 + 上下文契约 + 产物落盘**，缺一不可。

**第一步，写自包含的任务简报。** 用 `sessions_spawn` 起子 Agent 时，只给一份独立简报：目标、约束、交付格式、禁止事项。不要把主会话历史整段塞过去，这是隔离失效的头号原因。

**第二步，约定交付协议。** 要求子 Agent 返回限长的结构化结果（JSON 或短 markdown），大体积明细写到独立子目录（如 `workspace/tasks/<task-id>/`），主会话只收"摘要 + 文件路径"。

**第三步，管好生命周期。** 任务完成即关闭子 session，不复用；并行任务每个单独 spawn，配任务 ID 防重防冲突。

**第四步，工具层对齐。** 插件 / MCP 工具如果持有状态（登录态、游标、缓存），确认它按 session key 隔离，而不是进程级全局单例，否则两个子 Agent 会互相踩。

## 踩坑点

- 简报里没写"不许反问用户"，子 Agent 卡在等待输入，任务挂死。简报永远加一句：缺信息就按假设继续，并在结果里标注假设；
- 子 Agent 返回体超限被截断，主 Agent 拿到半份数据还以为完整。对策：限长 + 强制"摘要 + 落盘路径"双交付；
- fire-and-forget spawn 之后主 Agent 继续往下跑，结果没人收。要么显式等待，要么明确声明这是异步任务并约定回传机制；
- 并行子 Agent 写同一个文件，后写覆盖先写。每个任务独立子目录是最省心的解法；
- 排查时用 session 列表看有没有孤儿 session，长时间 running 的大概率是卡死了。

## 可复用建议

把任务简报做成固定模板：**Goal / Constraints / Deliverable / Do-not / Assumption policy**，团队所有 spawn 都走这个模板，子 Agent 行为的方差会明显下降。再把"摘要 + 路径"定成默认交付协议，主会话上下文就能长期保持稳定，长对话不再"失忆"。

## 总结

Session 隔离的本质不是开关，而是契约：**进什么**（自包含简报）、**出什么**（限长摘要）、**留在哪**（独立产物目录）、**活多久**（用完即弃）。把这四件事写成模板固定下来，子 Agent 就是干净的外包工，而不是把泥带进客厅的室友。
