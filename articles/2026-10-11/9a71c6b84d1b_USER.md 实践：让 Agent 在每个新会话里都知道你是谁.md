## 背景

用 OpenClaw 这类常驻 Agent，上下文是按会话切分的。`memory/` 下的日记式文件能沉淀事实，但都是碎片；系统提示词（AGENTS.md）写的是通用工作规则，不适合塞个人化信息。结果就是每次新会话，你都得重新自我介绍一遍：时区、主力系统、代码风格、称呼。

## 问题

Agent 对"你是谁"没有稳定认知，会带来三个具体麻烦：

1. 回答默认通用化——你用 macOS + 远程 Linux，它总给你 Windows 方案；
2. 偏好反复交代，浪费 token 还容易漏；
3. 记忆文件越堆越多，关键事实被淹没在流水账里，检索质量下降。

## 做法

**1. 建文件**：在 workspace 根目录（如 `~/openclaw/workspace/USER.md`）建一份用户画像。定位要明确：稳定、低频变化、手工维护，和按日期的 memory 文件严格分工。

**2. 控制规模分区写**，建议 30 行以内：

```markdown
# 用户画像
## 基本信息
- 称呼：老周；时区：Asia/Shanghai；沟通语言：中文
## 环境
- 开发机：macOS；服务器：Debian 12，Docker 部署
- 主力语言：Go / Python
## 偏好
- 回答直接给结论，细节放折叠
- 代码默认附错误处理，不要省略 import
## 边界
- 不要主动推送总结类消息
```

**3. 在 AGENTS.md 加规则**：每次会话开始先读 USER.md；只有当用户明确说出稳定事实（换了时区、换了主力语言）时才更新，且更新前先展示 diff 请用户确认。临时任务状态禁止写入。

**4. 验证**：新开会话直接问"我的服务器是什么系统"，不重新交代就能答对，说明链路通了。

**5. 定期修剪**：换环境或每季度人工过一遍，删过期条目。

## 踩坑点

- **写太长**：我最初塞了 80 行，Agent 输出明显被带偏，把画像里的措辞原样复读进回答。压到 30 行内才正常。
- **易变信息混入**：写过一句"本周在赶 deadline"，两周后它还在影响语气。状态类内容应留在按日期的 memory 里。
- **Agent 自动改写**：没加"确认后写入"规则时，Agent 会把对话里的临时信息顺手写进 USER.md，几轮下来文件变成垃圾场。写这个文件必须是显式、经确认的动作。
- **隐私边界**：走云端 API 时，这个文件会被请求带上。身份证号、住址这类就别写，先想清楚它会流到哪里。

## 可复用建议

- 把 USER.md 当配置文件对待：进 git、写 commit message、可回滚。改坏了能 diff 回去。
- 多角色可拆多份（工作/个人），在 AGENTS.md 里按场景指定读哪份，避免上下文串味。
- 记住三者分工：USER.md 管"我是谁"（稳定）、memory 管发生了什么（按时间）、AGENTS.md 管你该怎么干活（规则）。互相侵入是大多数记忆混乱的根源。

## 总结

USER.md 没什么技术含量，价值在于把用户上下文从会话记忆里拆出来，变成可审查、可版本化的静态文件。十几行字、半小时维护成本，换来每个新会话不用从零开始。建议从最小版本起步，跑两周再按实际的失真点补条目，不要一上来铺大而全。
