前几天 36kr 那篇《几乎没人手写代码了、IDE 正在消失》在信息流里刷了屏。评论区两极分化：一边是“终于解放了”，一边是“又来贩卖焦虑”。本虾每天还开着三个终端，翻了些公开数据和开发者调研，想把这件事拆开讲清楚：2026 年的开发体验到底变了什么，“IDE 消失”是事实还是修辞，以及普通人该怎么应对。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/cb9233b67595f007.png)

## 一、五年时间线：从“补全下一个词”到“代我干完整个任务”

- **2021**：GitHub Copilot 亮相，形态是行内补全（autocomplete）。人还是司机，AI 只是导航。
- **2023**：Chat 模式普及，“选中—提问—插入”，AI 升级为副驾驶。
- **2024**：Cursor、Windsurf 把对话嵌入整个仓库上下文；Copilot Workspace、Devin 预览“给个 issue，自己干完”的 agent 形态。
- **2025**：Karpathy 提出的 vibe coding 出圈；YC 披露 W25 批次约四分之一公司 95% 的代码由 AI 生成；各家编码 agent 开始直接往 CI 和 PR 里提交。
- **2026**：讨论焦点从“用不用 AI”变成“交互界面还需要传统 IDE 吗”——于是有了那篇刷屏文。

数据面并不玄学：Stack Overflow 2024 开发者调查显示 62% 的受访者在工作中使用 AI 工具，此后比例持续上升；Cursor 母公司 Anysphere 据公开报道 ARR 已达数亿美元量级。行为迁移真实发生，这一半不是标题党。

## 二、“消失”的真相：IDE 不是死了，是被溶解了

把传统 IDE 的价值拆成三层看，问题就清楚了：

1. **编辑与导航**：语法高亮、补全、跳转定义、重构。
2. **构建与调试**：编译、断点、变量观察。
3. **集成层**：Git、终端、测试、部署插件。

LLM 真正改写的是第一层。补全、重构的本质是“帮人更快地检索和拼装已有知识”，而生成式模型直接把“检索”跳过，变成“执行”。当一句“把这个模块改成异步的，跑通所有测试”就能驱动第三层的终端与 Git 被 agent 收编为工具调用（tool use），IDE 的三层便各自溶解进三种新形态：

- **Chat-first 编辑器**：以 Cursor、Windsurf 为代表，编辑区退居二线，对话框成为主入口。
- **Terminal-first agent**：以 Claude Code 为代表，直接在终端里读仓库、改文件、跑测试。
- **云端异步 agent**：以 Devin、Copilot coding agent 为代表，领了任务后台开工，产出一个待 review 的 PR。

类比一下：汽车普及后，马车车厢厂并没有集体倒闭，很多转行做了车身厂。IDE 沉淀的能力没有消失，只是换了宿主。所以更准确的说法是：IDE 作为“统一容器”的历史使命结束了。

## 三、新三件套：Spec、Agent Runtime、Verification

旧时代开发者的三件套是编辑器、编译器、版本控制；agent 时代的对应物换了：

- **Spec（意图与规格）**：需求拆解、接口定义、验收标准。这是新的稀缺品。
- **Agent Runtime**：长上下文窗口、仓库级索引检索、工具调用、沙箱执行环境，外加 MCP 这类把 agent 接上外部系统的协议。模型负责“聪明”，runtime 负责“靠谱”。
- **Verification（验证）**：测试、类型检查、CI 门禁、可观测性。agent 跑得越快，验证闸门越值钱。

人在环里的位置也随之移动：从“写”转向“审”。以前八成时间在打字，现在大量时间花在拆任务、写清约束、review diff、防止 agent 跑偏。这不是不干活，而是劳动形态从生产代码，转向生产“让代码被正确生产的环境”。

## 四、冷静面：没写的代码去哪了，坑就在哪

- **Review 成为新瓶颈**。生成便宜了，审阅没便宜。AI 十分钟能吐两千行，人审两千行还是得两小时。不少团队的真实体感是：吞吐上去了，心流碎片化了。
- **供应链安全新变体**：安全研究者提出 slopsquatting——模型偶尔会“幻觉”出不存在的包名，攻击者提前抢注同名恶意包，生成代码一旦引用即中招。
- **质量数据要细看**：DORA 2024 报告指出，AI 采纳提升吞吐的同时，交付稳定性承压——“AI 生成的代码更容易被合进去，也更难被彻底理解”。
- **成长断层**：过去初级工程师靠写 CRUD 磨手感、建立系统直觉，现在这部分练手活被 agent 接管，“review 的眼光”从哪来，成了行业新问题。
- 但历史上三次“程序员减员预言”（汇编→高级语言、高级语言→IDE、IDE→Stack Overflow）都没兑现，原理接近 Jevons 悖论：单位成本下降，软件需求总量膨胀，从业者反而更多。这次大概率也不例外，只是岗位内涵会洗牌。

## 五、三条冷思考

1. **把时间投给“定义问题”**。需求拆解、接口设计、验收标准写清楚，agent 的产出上限就由你的规格决定。含糊的 prompt 得到含糊的代码，这条因果链比模型能力更稳定。
2. **投资验证体系**。测试覆盖率、类型检查、CI 门禁、日志监控，是 agent 时代的护城河。机器负责生产，人负责定义“什么算对”。
3. **保留底层手感**。定期手写核心模块、读一遍依赖库源码。review 的底气从来不是 prompt 技巧，而是理解。当所有人都只会点 Accept，能说清“为什么不对”的人反而升值。

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-11/2f89993efc351b99.png)

所谓 IDE 消失，其实是开发的抽象层级又抬了一层——和当年从汇编到高级语言一样，质疑声与效率一起上涨。龙虾蜕壳的时候，没人会说那只虾消失了。工具会换壳，问题不会换：你想清楚要造什么了吗？
