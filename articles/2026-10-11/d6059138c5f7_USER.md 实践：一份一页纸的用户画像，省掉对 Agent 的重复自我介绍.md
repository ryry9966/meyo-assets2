## 背景

Agent 的上下文是易失的。会话一关，昨天的默契就清零：你的时区、主力语言、技术栈、"生产目录不许碰"这类底线，每个新会话都得重新交代。系统提示是静态的，MEMORY.md 记录的是动态事件，而"我是谁"这种长期稳定的信息，缺一个专门的载体——这就是 USER.md 的定位。

## 问题

没有用户画像时，Agent 的输出有三个典型症状：

- **建议泛化**：方案不考虑你现有技术栈，推荐一堆你根本不用的东西；
- **默认值错误**：按英文语境回复、按别人的工作习惯组织输出；
- **重复 onboarding**：同样的背景被反复询问，连回答本身都在消耗 token。

这不是模型能力问题，是上下文供给问题。修法很便宜。

## 做法

1. **建文件**：在 Agent 工作区根目录新建 USER.md，与 MEMORY.md 并列。多数框架在加载持久记忆时会优先读取它。
2. **按固定结构写，只写事实**：推荐五个分区——环境（时区/语言/设备）、技术栈、沟通偏好、边界与红线、当前主线（每个项目一行）。
3. **控制预算**：全文 40–60 行、1–2KB 以内。写不进去的内容，说明它属于别处。
4. **定更新机制**：每两周人工审一遍；也可允许 Agent 通过文件工具提议修改，但必须经你确认后落盘。用 git 管起来，改动可回溯。

一个精简模板：

```markdown
# USER.md（最后更新：2025-06-30）
## 环境
- 时区 UTC+8，中文优先，英文文档可读
- macOS + Linux 服务器
## 技术栈
- 主力 Python / Go；结论先行，给可运行的最小示例
## 沟通
- 直接指出错误，不铺垫；不确定就说不确定
## 边界
- 生产环境只读；删除类操作必须先确认；不输出任何凭证
## 当前主线
- 订单服务迁移（预计 7 月底完成）
```

## 踩坑点

- **写太长**。画像一长，注意力被稀释，关键约束反而失效。凡是 Agent 能从会话和 MEMORY.md 推断出来的，都不要写进来。
- **放敏感信息**。密钥、住址、真实手机号一律不写。把它当作可能进日志、可能被同步的文件来对待。
- **叙事化写作**。"我是一名十年经验的工程师，平时喜欢……"这类段落信息密度极低。Agent 要的是可执行条目，不是人设小说。
- **过期冲突**。两个版本的事实并存时，Agent 行为会很怪。顶部加"最后更新"字段，季度做一次清理。
- **越界当配置用**。"先跑测试再提交"这类流程指令属于 AGENTS.md 或系统级配置。画像描述"你是谁"，不描述"该怎么做"。

## 可复用建议

- 超过 2KB 就拆：主线项目单独成文件，USER.md 里只留一行引用。
- 与 MEMORY.md 划清边界：**USER.md 是稳定的你，MEMORY.md 是流动的事**。
- 把审阅挂在已有习惯上，比如每周规划会前花两分钟过一遍，否则必然荒废。
- 团队场景可为每个成员维护独立画像文件，Agent 按当前操作者加载。

## 总结

USER.md 的价值不在"让 AI 更懂你"这种叙事，而在工程上：把高频、稳定、易复述的上下文，固化成一个有预算、有结构、有更新机制的文件。成本半小时，收益是每个新会话都从"认识你"的状态开始。这是目前性价比最高的一类 Agent 配置，值得今天就建。
