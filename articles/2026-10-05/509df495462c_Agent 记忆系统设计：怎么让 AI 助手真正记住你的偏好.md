## 背景

LLM 本身无状态。OpenClaw 这类常驻 Agent 每天通过 IM 渠道和你高频交互，但每次新会话，模型什么都不记得——上周说过的"周报用简洁格式"，这周又得重讲一遍。想让助手越用越懂你，记忆系统是绕不开的一层，它决定了 Agent 的长期体验上限。

## 问题：三种常见做法都不行

- **全塞 system prompt**：上下文膨胀、成本上涨，旧的错误偏好还永远在场；
- **靠一句"你记住一下"**：写没写、写到哪、下次读不读，全凭模型即兴发挥；
- **一上来就上向量库**：个人助手的记忆量级通常只有几百条，向量检索引入噪音，还平添基建成本。

本质：记忆是数据工程问题，不是提示词技巧。

## 做法：分层存储 + 受控读写

**1. 分三层**
- 核心档案：用户画像、沟通风格、硬约束（如"回复不要用 emoji"），小而精，每次会话固定注入；
- 事实记忆：可检索的偏好条目，带 `scope`（task/global）、tags、置信度、时间戳；
- 会话记忆：近期对话的滚动摘要，按需加载。

**2. 写入走工具**：给 Agent 一个结构化 `memory_write` 工具，禁止它自由追加文件。显式触发（用户说"记住"）直接写；隐式触发（识别到"以后都这样"类陈述）先向用户确认。写入必须回显。

**3. 读取有预算**：核心档案直接注入，控制在几百 token；事实记忆先按 tags 过滤，再做关键词 + 向量混合检索，按"时间衰减 × 频率 × 置信度"排序取 top-k。注入噪音比注入少更伤。

**4. 更新留版本**：新偏好覆盖旧偏好但保留历史；用定时任务周期性压缩——合并重复条目，模糊项列出来交用户裁决。

## 踩坑点

1. **记忆污染**："这次用 Python 写"被存成永久偏好。靠 scope 字段兜底，默认 task 级；
2. **陈旧记忆盘踞**：过时偏好反复注入。做时间衰减，并提供审计入口——一句"列出你记住了我什么"必须能查、能删；
3. **静默写入**：Agent 偷偷记东西导致行为突变，用户摸不着头脑。写入回显是底线；
4. **上下文预算失控**：记忆无限增长挤占 prompt。给注入记忆设硬上限，超限触发压缩；
5. **多用户串味**：共享记忆文件会让 A 的偏好影响 B。按 user/channel 做命名空间隔离。

## 可复用建议

- **先文件后向量**：几百条以内，Markdown/JSONL + 标签过滤完全够用，别过度设计；
- 把记忆当数据库 schema 设计：写入走工具、读取有预算、更新留版本；
- 记忆必须可查、可改、可删，这是个人助手的信任底线；
- 用回归用例验证：教一个偏好，隔几个会话后检查行为是否生效。

## 总结

让 Agent 记住你，靠的不是模型够聪明，而是一条受控的数据链路：结构化写入、有预算的检索、带衰减的排序、可审计的存储。先跑通最简单的文件方案，等记忆真的多起来再考虑向量检索。做工程，先把简单方案做对。
