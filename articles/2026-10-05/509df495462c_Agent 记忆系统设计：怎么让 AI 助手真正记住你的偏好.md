## 背景

常驻型 Agent（比如接在 IM 里的 OpenClaw 助手）最大的体验落差往往不是能力，而是“记性”：上周才说过部署用 pnpm、回复要短、别自动 commit，这周它又问一遍。根因大多不在模型，而在记忆系统没做设计。

## 问题

三种常见的错误做法：

1. **全量塞上下文**：把历史对话全部注入。token 成本线性上涨，噪声还会引起指令漂移；
2. **只靠向量库**：偏好类事实（“我用 pnpm”）文本太短，embedding 相似度区分度差，召回不稳定；
3. **静默记忆**：Agent 自己决定记什么，用户看不见、改不了，一旦记错就持续污染后续输出。

## 做法

把记忆拆成三层，重点对“偏好”这一层做工程化：

**1. 分层**

- 工作记忆：当前会话上下文，会话结束即弃；
- 情景记忆：事件流水（做过什么、时间），append-only，按天落盘；
- 语义记忆：用户偏好与长期事实，结构化、少量、可编辑。

**2. 偏好用文件，不用向量**

偏好是少量、可枚举、需要人审的事实，用一个 Markdown 文件维护即可：

```markdown
# preferences.md
- runtime: pnpm（来源: 2025-01 用户明示, 置信: 高）
- 回复风格: 简短, 少用列表（来源: 多次纠正）
- 禁止: 未经确认自动 commit
```

每条带来源和时间。检索方式就是“整个文件注入”，几百 token 以内，不需要向量。

**3. 写入判据（最关键）**

- 显式指令（“以后都用 X”）→ 立即写入；
- 重复模式（同一纠正出现 ≥3 次）→ 写入；
- 一次性任务上下文（“这次先别发通知”）→ 不写入。

原则是宁漏勿错：记错一条的成本远高于漏记。

**4. 注入点固定**

system prompt 末尾固定注入偏好文件全文；每次写入后回显给用户（“已记住：xxx，说‘忘了’即可删除”）。透明是信任的基础。

**5. 回归验证**

准备 5~10 个固定问题（“我平时用什么包管理器？”），每次改动记忆逻辑后跑一遍，防止退化。

## 踩坑点

- **偏好只增不删**：三个月后注入 2k token 噪声。规则：每次写入时顺带复审最旧的几条，长期无命中就降级或删除；
- **多端并发写同一文件导致覆盖**：改成读-改-写加时间戳，或约定只有一个实例持有写权限；
- **把情绪当偏好**：某天用户说“别问了直接做”，被存成永久偏好，下次酿祸。凡是禁止类偏好，首次写入必须用户确认；
- **情景记忆和语义记忆混库**：检索时流水淹没事实，宁可分两个目录。

## 可复用建议

- 偏好条目 schema 固定：key / value / source / confidence / last_hit；
- 写入走统一函数，禁止各插件绕过直接改文件；
- 每周 cron 跑一次记忆 review，输出 diff 让用户过目；
- 所有记忆操作留日志，出问题能回放。

## 总结

让 Agent 记住你，本质是数据治理问题：什么该记（判据）、记在哪（结构化文件）、怎么用（固定注入）、谁来管（用户可见可改）。先用“一个可编辑的偏好文件 + 严格写入判据 + 固定注入点”跑起来，等真实使用暴露召回瓶颈，再考虑引入向量检索。多数场景，第一步就够用了。
