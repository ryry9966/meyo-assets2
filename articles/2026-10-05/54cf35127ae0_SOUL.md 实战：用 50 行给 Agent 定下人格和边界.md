## 背景

OpenClaw 的工作区里有几个约定文件：`AGENTS.md` 管行为规则，`TOOLS.md` 管工具约定，而 `SOUL.md` 管的是这个 agent “是谁”。跑了一段时间的用户大多遇到过同一个现象：agent 用着用着，腔调变了，边界感也没了——你让它只做总结，它开始自作主张帮你重写文档；你希望它回复克制，它在群里越来越话痨。这些多半不是模型能力问题，而是人格和边界没有落到纸面上。

## 问题

SOUL.md 解决的是两个经常被混为一谈的问题：

1. **一致性**。Agent 长期运行、多会话切换后，语气、称呼、做事风格会漂移。尤其接了多个 MCP 工具和插件之后，每次会话的上下文组合不同，行为更不稳定。
2. **边界**。Agent 拿到 shell、文件系统、消息发送权限后，“它默认愿意做什么”就成了安全问题。人格文件是软约束的第一层，决定它在灰色地带倾向于问还是做。

## 做法

我的 SOUL.md 约 40 行，分四段：

**身份**：一两句说明它是谁、为谁服务、语气基准。写具体动作，别写形容词。“回复不超过三段，先给结论”是可执行的；“友善专业”是废话。

**偏好**：格式习惯（默认用列表、代码块标注语言）、禁掉的口头禅（“当然可以！”这类开场白直接砍掉）、对不确定问题的处理方式（没把握就说不确定，不要编）。

**边界**：这是重点。明确列出需要先确认的动作：删除文件、往群里发消息、执行超过 30 秒的命令、访问工作区之外的路径；以及绝对不做的事：不主动升级依赖、不改配置文件里没提到的字段。

**升级路径**：遇到边界外的情况怎么问、问谁。一句“拿不准就停下来问，宁可慢一步”比十条细则都管用。

写完放进工作区根目录，开新会话生效，进版本库，每次改人格都走 diff review。

## 踩坑点

- **写太长**。早期我写过 200 行的“人格宪法”，效果反而变差——每轮对话都注入，稀释了真正重要的规则。现在控制在 50 行以内，删掉所有“希望你……”式的空话。
- **把它当防火墙**。SOUL.md 是提示词层的软约束，模型在长上下文里完全可能“忘记”。危险操作必须靠硬约束兜底：工具白名单、MCP 权限配置、宿主机沙箱。人格管倾向，权限管底线，两层缺一不可。
- **改了不生效**。编辑后当前会话不会自动重载，必须开新会话。有段时间我以为改了没用，其实是旧会话还在跑。
- **和其他规则文件打架**。AGENTS.md 写“自动提交代码”，SOUL.md 写“敏感操作先确认”，模型行为就会随机。规则只在一处声明，SOUL.md 引用而不重复。

## 可复用建议

- 每条规则写成祈使句 + 可判定条件，能举一个具体例子验证它是否被遵守。
- 人格文件也做 code review：跑两周攒一批不满意的回复，反推是哪条规则缺失或失效，一次只改一条。
- 边界部分和工具权限配置放同一个 PR 里改，保证软硬两层同步演进。
- 每月重读一次，删掉从未触发过的规则——规则越少，遵守率越高。

## 总结

SOUL.md 不是给 agent 的“人设文案”，而是一份随系统一起演进的行为配置。它管不了所有事，但把“它倾向于怎么做”从随机变成了可声明的。写短、写具体、和权限层配套，是这套做法能长期跑下去的关键。
