最近，Rabbit 创始人吕骋在采访中抛出一个观点：人不该为 Agent 改变思考方式。翻译成工程语言就是：输入接口应该迁就人，而不是要求用户先学会一套“提示词语法”再来用产品。这话听着很提气，但放进六十多年的人机交互史里看，只对了一半——而且没说的那一半，可能更重要。这篇文章把两半都摊开来讲。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-05/13817bb045190b93.png)

## 这句表态从哪来：Rabbit 的产品哲学

- Rabbit R1 是 2024 年 CES 上发布的橙色小方盒，售价 199 美元，首发约一万台当天售罄——市场对“少学一点操作”的渴望是真实存在的。
- 它的官方叙事核心是 LAM（Large Action Model）：不让用户打开 App、点击菜单，而是让模型自己学会“怎么做”，后来还推出 teach mode，用户演示一遍，机器照着学。
- 到通用 Agent 阶段，Rabbit 的思路是 generative UI：界面不预先固定，按任务现场生成，任务结束即销毁。
- 吕骋的观点一以贯之：用户说人话、甚至说模糊的话，产品负责把它变成动作。但当初媒体对 R1 的批评也集中在响应慢、完成率低——理想与工程之间的缝隙，正是这个话题值得展开的原因。

## 六十年交互史：人类其实一直在“迁就机器”

- 从打孔卡到命令行，程序员要背命令、记参数；1970 年代 Xerox PARC 搞出 GUI，1984 年 Macintosh 把它带向大众，人类改学图标、窗口、菜单；2007 年 iPhone 普及多点触控，改学手势；2011 年 Siri 上线，改学“唤醒词＋指令句式”。
- 规律很清楚：每一次交互革命都降低了学习成本，但没有一次把它降为零。每代人都得学一种新“语法”。
- Prompt engineering 就是当下最新的语法：few-shot、CoT、角色扮演、JSON 输出，本质仍是人在适配模型的输入规范。
- Culkin 有句名言：“我们塑造工具，然后工具塑造我们。”再往前，Engelbart 1962 年写《Augmenting Human Intellect》时立场更直白——能增强思维的工具，必然反过来改变思维本身。
- 虾注：学习成本每降一档，用户规模就涨一个数量级。降低学习成本从来不是“偷懒”，是普及的前提。

## 吕骋的底牌：为什么“迁就人”在技术上有戏

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-05/926e7b4bd97e7157.png)

这不只是情怀，有三层技术趋势在给它撑腰：

1. 模型能力上，function calling / tool use 已成标配，Agent 能把一段模糊的自然语言解析成结构化参数去执行；浏览器操作类 Agent（computer use、Operator 这类）甚至直接看屏幕、点按钮，连 API 都不需要。
2. 标准化上，MCP（Model Context Protocol）这类协议正在把“工具怎么被调用”统一起来，机器适配新工具的成本在快速下降。
3. 意图建模上，teach mode 和 generative UI 的共同哲学是：人提供 what（我要什么），机器补全 how（怎么做到）。

商业逻辑同样成立：愿意钻研提示词的永远是少数极客，要做大众市场，“意图先行”是唯一能走量的路径。GUI 让电脑走出实验室，触屏让手机进裤兜，逻辑一脉相承——谁先让用户“不用学”，谁先拿到下一个数量级的用户。

## 反方视角：模糊的输入，注定换来不精确的结果

- Agent 的执行循环是 intent → plan → act → verify。前三步模型可以扛，最后一步 verify 目前基本离不开人——谁来签字、怎么验证，都还没解决。
- 模糊意图的代价是“错得理直气壮”：订错机票、删错文件，机器不会心虚。执行类 Agent 一旦涉及破坏性动作，验证成本极高。
- 更关键的一点：把需求写清楚，本身就是思考。程序员 Rubber duck 调试法的价值不在那只鸭子，而在于“把问题描述清楚”会逼你重构思路。一条好提示词，本质是把目标、约束、验收标准想清楚——这个能力不是服务模型的，是服务你自己的。
- 还要区分“脚手架”和“思考”：早年 "please think step by step" 这类咒语已经被模型进化淘汰了，但“我的目标到底是什么、红线在哪、什么算做完”永远不会过期。
- GPS 是现成的案例：我们不再背地图了（机械部分被替代），但去哪、值不值得去，依然由人决定。思考方式确实变了，但要看变的是哪一层。

## 判断框架：哪层思考该守，哪层可以放

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-05/dd62bc0e43066b85.png)

- 该守住的：目标定义、价值判断、最终决策、对结果的验收标准。这些是“人”的坐标系，交给任何 Agent 都等于弃权。
- 可以放手的：过程性操作、格式转换、检索整合、重复性执行。这些属于“体力思维”，机器做得又快又稳，人做纯属浪费算力。
- 中间地带要加验证点：让 Agent 先交计划或草稿，人确认后再执行；破坏性操作单独设确认环节。信任要有边界，而边界必须落在流程上，不能靠感觉。

## 三条冷思考

1. 把“写清楚要什么”当作核心能力投资：目标、约束、验收标准三件套，在任何工具时代都保值，比任何提示词技巧都耐用。
2. 用“可验证的中间产物”代替一步到位：计划、草稿、Diff，逐环节签字放行，别把信任一次性付清。
3. 定期做“脚手架审计”：每隔半年删一遍自己的提示词套路，模型升级后不再需要的技巧果断扔掉，把省下的精力放回问题本身。

吕骋说人不该为 Agent 改变思考方式——对的那一半是：你不必再学咒语。没说的另一半是：你得想得更清楚。Agent 越强，咒语越贬值，清晰思考越保值。这门生意，长期看稳赚不赔。
