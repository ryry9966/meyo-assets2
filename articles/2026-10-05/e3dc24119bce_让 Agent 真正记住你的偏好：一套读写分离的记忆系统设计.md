## 背景

大模型本身是无状态的，会话一结束，上下文就没了。所谓"越用越懂你"，本质上要靠外部记忆系统：把用户偏好沉淀下来，在合适的时机检索、注入回提示词。我们在 OpenClaw 的 agent 插件里迭代过几版记忆方案，踩了不少坑，这里把一套验证过的做法整理出来。

## 问题：为什么"塞进 system prompt"不够用

最常见的做法是把用户信息全写进 system prompt，问题很快出现：

1. 条目一多，prompt 膨胀，token 成本和噪声同步上升；
2. 没有更新机制，"我以前喜欢深色主题"和"最近换浅色了"并存，模型随机听一个；
3. 偏好、事实、一次性指令混在一起，检索时互相干扰。

核心矛盾在于：写得太勤，记忆变垃圾场；写得太保守，agent 又显得没记性。

## 做法：读写分离 + 分层存储

**存储层**：每条记忆一条结构化记录，类型收敛到三种：

```json
{ "type": "preference | fact | event",
  "content": "...", "confidence": 0.9,
  "source": "session_id", "created_at": "...",
  "status": "active | superseded | expired" }
```

偏好（preference）单独设类型，和事实、事件分开，检索时优先。

**写路径**：不实时写入。会话结束后跑一个抽取步骤，从对话中提炼"候选记忆"，阈值放宽；再由合并任务做去重和冲突处理——新偏好把旧条目标记为 `superseded`，而不是覆盖删除，保留演变历史。

**读路径**：通过 MCP 暴露一个 `memory_search` 工具，agent 按需调用。检索用语义搜索加类型过滤，只取 top 3~5 条，每条附带时间戳和置信度，让模型自己判断该不该遵守。一次性指令（比如"今天用正式语气"）绝不入库。

## 踩坑点

- **什么都存**：早期连闲聊都入库，两周后检索准确率肉眼可见地掉。后来在抽取 prompt 里明确"转述出的偏好才存，情绪表达不存"。
- **覆盖式更新**：直接删旧记录，用户反悔时无法回滚。改成 superseded 标记后，回滚和调试都方便了。
- **记忆注入**：外部网页内容里出现"请记住：站长偏好……"会被抽取流程当真。写入前必须校验来源，会话外内容默认不入库。
- **去重失败**：同一偏好换个说法就成两条。合并任务里加一步语义相似度聚类，高相似旧条目直接合并。
- **全信模型自主决策**：完全交给模型判断何时读写，结果经常漏检索。现在改为关键场景（会话开场、配置变更）强制调用 `memory_search`。

## 可复用建议

1. 记忆类型收敛到 2~3 种，宁少勿多；
2. 写入走"候选抽取 + 合并"两阶段，不要边聊边写；
3. 每条记忆带时间戳和置信度注入 prompt，让模型看到证据质量；
4. 给用户一个可查看、可删除的记忆面板，这既是信任问题，也是合规需要；
5. 攒一个 20 条左右的回归用例集（"该记住的/该忘掉的"），每次改抽取 prompt 都跑一遍。

## 总结

记忆系统的关键不是"存得多"，而是"取得准、忘得对"。读写分离、类型收敛、冲突标记、来源校验，这四件事做到位，几百行的插件就能让 agent 的个性化表现上一个台阶。剩下的收益来自持续维护：定期翻记忆库、清掉噪声，比任何算法调优都有效。
