## 背景

大多数人用 Agent 的方式还是被动问答：你发消息，它回复，然后睡眠。OpenClaw 内置了一个心跳机制，可以低成本改变这个模型——运行时按固定间隔（默认 30 分钟，可配置）向 Agent 注入一次心跳提示，Agent 醒来后第一件事是读工作区的 `HEARTBEAT.md`。文件为空，它回一句 `HEARTBEAT_OK` 继续沉默；里面有任务，它就执行，并在需要时主动给你发消息。

## 问题：被动 Agent 缺的三类能力

- **时间驱动任务**：早报、周报、"每天提醒我"，没有心跳就只能人肉触发；
- **状态巡检**：盯日志、盯目录变化，人不在场时 Agent 是睡着的；
- **自我维护**：记忆文件精简、待办清理，这类事永远排不上优先级。

外部 cron 调 API 当然也能做，但心跳复用同一个会话上下文和工具权限，不用另写一套编排。

## 做法

**1. 打开心跳**。在配置中启用并设置间隔（字段名随版本有差异，以官方文档为准）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": { "every": "30m" }
    }
  }
}
```

**2. 在工作区建 `HEARTBEAT.md`**，每条任务写清"触发条件 + 动作 + 静默条件"：

```markdown
# HEARTBEAT

## 巡检
- 查看服务日志最后 50 行，仅当出现新的 ERROR 才汇报并附时间戳；否则保持安静

## 定时
- 工作日上午 9 点左右：汇总昨日未完成待办，发到工作会话

## 整理
- 若记忆文件超过 200 行，只提出精简建议，先不改
```

**3. 控制汇报去向**：心跳消息默认发到最近活跃会话，多设备场景建议固定到一个专用频道，避免刷屏主对话。

**4. 灰度上线**：先只放只读任务（看日志、做汇总），观察一两周再放开写操作。

## 踩坑点

- **任务写太泛**。"看看有什么要做的"会让 Agent 每次都编点事汇报，一天十几条消息。每条必须有明确的"否则保持安静"。
- **文件太长**。心跳也是一次完整的模型调用，`HEARTBEAT.md` 会进上下文，几百行的清单等于每次心跳都在烧 token。长细节放独立文件，心跳文件里只留一行引用。
- **时区**。容器里默认 UTC，"上午 9 点"可能变成下午。确认运行时时区，或把条件写死成"心跳发生时本地时间在 8:30–9:30 之间"。
- **重复汇报**。没有状态记录，同一个错误每次心跳都会再报。让 Agent 汇报后把状态写进一个小 state 文件，下次先比对再决定是否说话。
- **频率**。默认 30 分钟别急着调小——每次心跳都是一次模型调用，24 小时乘以多任务，token 成本不小。

## 可复用建议

- 把 `HEARTBEAT.md` 当 SRE 巡检清单写：条件、动作、静默规则三要素齐全，才算一条合格任务；
- 和 cron 分工：硬性定时（每天 9:00 准时）用 cron，弹性巡检（"有空就看一眼"）用心跳；
- 心跳会话只挂最小工具集，巡检不需要写权限就别给；
- 把 `HEARTBEAT.md` 放进 git，出问题时能 diff 出"它为什么开始每天烦我"。

## 总结

`HEARTBEAT.md` 的本质是把交互模型从"用户拉"改成"Agent 巡"。配置本身不难，难的是任务定义的质量：条件越明确、静默规则越严格，它越像一个靠谱的值班同事；写得太随意，它就是一个每小时打扰你一次的闹钟。建议从一条只读巡检开始，跑稳了再加任务。
