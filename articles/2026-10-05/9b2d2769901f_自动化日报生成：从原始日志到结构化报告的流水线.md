## 背景

团队每天都在写日报：把昨晚的告警、服务异常、发布记录、关键指标从各个系统里翻出来，拼成一段话发到群里。这件事不难，但每天占用 20–30 分钟，质量完全取决于当天谁在写。目标是把“人找数据”改成“数据找人”——用 OpenClaw 的定时任务 + MCP 工具 + Agent 摘要，跑一条稳定的日报流水线。

## 问题

拆开看有三个难点：

1. **数据散**。日志在日志平台，发布记录在 CI，告警在监控群，格式各异。
2. **原始日志不能直接喂模型**。一天的日志量轻松上百万行，直接塞给 Agent 既爆 token，也极易幻觉。
3. **输出要稳定**。日报是给人看的，格式漂移、字段缺失比不生成更糟。

## 做法

流水线分四段，原则只有一条：**确定性的事交给代码，模糊的事交给模型**。

**1. 采集层（MCP tools）**
把三类数据源封装成 MCP 工具：`query_logs(start, end, service)`、`list_deploys(day)`、`list_alerts(day)`，统一返回 JSONL，每条带 `source / ts / level / service / message` 字段。由 OpenClaw 定时任务每天 08:30 触发。

**2. 清洗聚合（纯脚本插件）**
一个插件脚本做确定性处理：去重、过滤心跳类噪音、按 service 分桶、统计 error 次数、取 Top 5 错误指纹（对 message 做正则归一化生成指纹）。产出几百行以内的“摘要中间产物”，落盘为 JSONL。这一步没有模型参与，可单测、可回放。

**3. 摘要生成（Agent）**
把中间产物交给 Agent，prompt 固定输出 schema：`{summary, incidents[], metrics{}, followups[]}`，附两份历史日报做 few-shot。明确要求：只基于输入数据写，不推断原因。

**4. 校验与投递**
用 JSON Schema 校验模型输出，字段缺失重试一次；仍失败则降级——把中间产物直接渲染成模板 Markdown 发出。最后推送群 webhook，并按日期归档 Markdown 文件。

## 踩坑点

- **时间窗口用半开区间 `[08:30, 次日08:30)`**。最初用闭区间，补跑时交界处告警重复出现。配合“日期做幂等键，已存在即跳过”解决。
- **脱敏要在采集层做**。日志里有 token 和内网 IP，指望模型“注意脱敏”不可靠，正则在 `query_logs` 出口统一清洗。
- **错误指纹别用原文**。同一堆栈因时间戳不同会被算成一百种错误，先正则替换数字和 ID 再聚合。
- **给流水线本身加心跳**。第一版 cron 静默挂了两天没人发现。现在失败走独立告警通道——“没收到日报”本身就是告警。

## 可复用建议

- **中间产物必须落盘**。回溯问题、评测 prompt 改动效果、补跑历史日报，全靠它。
- **采集与摘要解耦**。换数据源只需加 MCP tool，换文风只改 prompt，互不影响。
- **保留人工兜底**：日报末尾固定一个“编辑入口”，人可以追加一句话说明再转发。
- **同一套骨架可换皮**：窗口改成 7 天就是周报，数据源换成仓库活动就是研发周报。

## 总结

流水线上线后，日报撰写从每天约 30 分钟降到只做最后人工确认，且覆盖面比手写稳定——脚本不会“忘了看某个服务”。核心经验一句话：**让代码负责事实，让模型负责表达，让 schema 负责稳定**。Agent 自动化的大部分收益，来自把模糊任务切出足够多的确定性段落。
