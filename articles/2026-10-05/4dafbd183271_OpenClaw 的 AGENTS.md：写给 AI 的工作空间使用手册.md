# OpenClaw 的 AGENTS.md：写给 AI 的工作空间使用手册

## 背景

OpenClaw 的 Agent 不是一次性对话：它常驻在你的机器上，有一个长期使用的工作空间（workspace），里面放着笔记、脚本、技能和记忆文件。每次会话启动时，`AGENTS.md` 会被注入系统提示词，相当于你写给这位“数字同事”的入职手册。MCP 工具、插件、定时任务配置得再好，Agent 的行为下限很大程度上取决于这本手册写得怎么样。

## 问题

没有认真维护 AGENTS.md 时，常见症状是：

- 每次会话风格不一致，目录约定、命名习惯全靠它现猜；
- 在聊天里纠正过的错误，下次照犯，指令没有沉淀；
- 工具调用随意，破坏性操作不做确认；
- 该问的不问，不该动的（`.env`、生产配置）动了。

本质上，这是把“团队规范”寄托在一次次的口头提醒上，而不是文档。

## 做法

我的 AGENTS.md 结构固定为六段，总量控制在 100 行以内：

1. **环境事实**：操作系统、常用路径、时区、语言偏好。只写事实，不写期望。
2. **项目地图**：每个目录一句话说明用途，让它不用 `ls` 三次才知道东西在哪。
3. **约定**：代码风格、提交信息格式、文件命名规则。
4. **工具策略**：哪类任务优先用哪个 MCP 工具，什么情况下先列计划再动手。
5. **安全边界**：明确列出禁止触碰的路径和操作；破坏性命令必须先确认。
6. **升级规则**：不确定就问，不要自行发挥；失败重试设上限。

写法上坚持“条件 + 动作”句式，例如“删除文件前，先向用户列出文件清单并等待确认”，而不是“请小心谨慎”。

## 踩坑点

- **写成许愿清单**。“要聪明、要仔细”这类形容词不约束任何行为，Agent 无从执行。
- **太长**。AGENTS.md 每次会话都进提示词，几百行既烧 token 又稀释注意力。细则应拆到 skills 或独立文档，正文只留索引。
- **混入易变状态**。TODO、进度、会话记录属于记忆文件，AGENTS.md 只放稳定策略。策略和状态混写，很快就会腐烂。
- **规则互相冲突**。两处矛盾的要求会让行为不可预测，改动前先全文搜一遍相关条目。
- **子 Agent 没继承**。多 Agent / 嵌套工作空间各有自己的 AGENTS.md，别只改主工作空间。
- **写了密钥**。它会进入提示词，任何 token、密码都不要出现在这里。

## 可复用建议

- 把每次“Agent 做错了”当作一次事故复盘：先在会话里纠正，再把结论蒸馏成一条规则写进 AGENTS.md，这就是它的迭代方式。
- 用 git 管理它，改动走 commit，能回溯也能 review。
- 每月修剪一次：删掉从未起作用的规则，合并重复项。
- 改完开一个全新会话实测，而不是在旧会话里验证——旧上下文会掩盖问题。
- 多台机器、多个工作空间时，抽一个公共模板，机器差异单独一小节。

## 总结

AGENTS.md 本质上是一份写给非人类同事的运维文档：短、稳定、可版本化、持续迭代。它不决定 Agent 有多聪明，但决定了它有多稳定。手册的质量，就是这位常驻 Agent 在你机器上的行为下限。
