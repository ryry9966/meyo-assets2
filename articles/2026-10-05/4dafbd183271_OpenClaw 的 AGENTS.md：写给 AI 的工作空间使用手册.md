## 背景

OpenClaw 的 agent 每次启动会话，都会从工作空间读取一组固定的 Markdown 文件：IDENTITY.md 定身份，SOUL.md 定性格，TOOLS.md 记工具用法。而 AGENTS.md 是真正的"操作手册"——它决定 agent 怎么干活、什么不能碰、记忆怎么写。它和 README 的区别在于读者：README 写给人看，AGENTS.md 写给模型看，而且每次会话全量加载。

## 问题

实际跑下来最常见的三个痛点：

1. **同一个错误反复纠正**。上周告诉它"没指令别 push"，这周它又来了。
2. **行为漂移**。换个会话、换台机器，流程和分寸就变了。
3. **记忆污染**。它把临时调试结论写进长期记忆，之后每次都带着跑偏。

根因不是模型不行，而是缺一份稳定、常驻、可版本控制的规则源。

## 做法

我的 AGENTS.md 现在稳定在 40 行左右，分四块，结构大致是：

```markdown
# 硬性规则
- 未收到明确指令前，不执行 git push
- 删除超过 10 个文件的操作，先列清单等确认
- 跑了多个 MCP 工具时，写操作必须先汇报再执行

# 环境事实
- 包管理用 pnpm，测试命令：pnpm test

# 记忆策略
- MEMORY.md 只记跨会话仍成立的事实
- 调试结论留在会话里，不落盘
```

写法上守三条：**一行一条；写具体行为，不写形容词；给例子**。"不要说'很快就好'，直接给预计时间"比"要诚实"有效得多。

## 踩坑点

- **写太长**。超过一两百行后，规则明显被稀释，模型开始选择性遵循。规则是删出来的，不是堆出来的。
- **和 SOUL.md / TOOLS.md 抢地盘**。重叠的指令会互相打架：人格归 SOUL，工具细节归 TOOLS，AGENTS.md 只管流程和边界。
- **写虚话**。"要小心""要聪明"没有可执行性，等于没写。
- **内容过期**。技术栈换了、机器换了，规则没跟着改，agent 会理直气壮地执行过时流程。建议每月 review 一遍。
- **忘了成本**。它每次会话都全量加载，篇幅直接换算成 token 和注意力开销。

## 可复用建议

- 把**"纠正两次"当触发器**：同一件事纠正到第二次，立刻固化成一行规则，别指望自己记得。
- 全局一份（默认工作空间），项目里可再放一份更具体的；冲突时项目级优先。
- 工作空间放进 git，AGENTS.md 的 diff 就是你对 agent 的运维日志，回溯非常方便。
- 规则尽量写成"条件 → 行为"格式，遵循率显著高于开放式描述。

## 总结

AGENTS.md 的价值不在写了多少，而在它是否随真实使用持续演化。它本质是一份 Living Document：你纠正 agent 的每一次，都是给它打的补丁。维护好这一个文件，比反复口头纠正、或指望记忆系统自动"学会"，成本低得多，也稳定得多。
