## 背景

OpenClaw 的 Agent 能跑 shell 命令、读写文件、调用 MCP 工具。很多人第一反应是“让模型碰文件系统太危险”。但 OpenClaw 的设计假设恰恰相反：**模型一定会犯错、会被注入、会拼错路径**。所以安全从来不靠模型“懂事”，而是靠沙箱把错误的半径压到最小。

## 问题：误删是怎么发生的

实际使用中，误删文件基本来自这几种场景：

- 路径拼接错误：`rm -rf "$WORK_DIR/tmp"` 在变量为空时退化成删别处
- 用户说“清理一下项目”，Agent 对清理范围的理解比你想的大得多
- prompt 注入诱发了意料之外的删除操作
- `git clean -fd`、`find -delete` 这类“间接删除”绕过了人的直觉审查

## 做法：四层防线

**1. 文件系统隔离。** Agent 进程跑在容器/受限工作区里，默认只挂载 workspace 一个目录，宿主其余路径不可见。额外挂载一律 read-only，除非显式声明可写。

**2. 执行层路径校验。** 所有文件类工具调用（包括 MCP 工具）先过 gateway：realpath 规范化 → 检查软链接真实指向 → 前缀必须在白名单目录内。`../../` 和 symlink 逃逸在这一层被直接拦截。

**3. 危险操作策略。** 删除类命令默认改写为移动到 `workspace/.trash`，或要求执行层人工确认。注意：确认必须发生在 CLI/审批消息层面，模型在对话里说“已确认”不算数。

**4. 兜底。** workspace 定时快照（rsync 或直接 git 提交），审计日志记录每次工具调用的完整参数。出问题可回滚、可追责。

落地步骤：开启 sandbox 并指定 workspace root → 显式列出必要挂载（全部 ro）→ 删除策略设为 trash + confirm → 打开 audit log → 配置快照 → 做一次演练：让 Agent 尝试删 workspace 外的文件，验证拒绝日志出现。

## 踩坑点

- **把整个 $HOME 挂进沙箱**：等于没隔离，Agent 能删的就变成你的家目录
- **以 root 跑容器**：越权风险被放大，务必降权用户运行
- **黑名单思维**：只拦 `rm` 拦不住 `mv` 到 /dev/null、`>` 截断重定向、python 一行脚本。正确姿势是默认拒绝、按需放行
- **确认放在 prompt 里**：执行层没人拦就是没拦，提示词不是安全边界
- **自写 MCP 工具直连宿主文件系统**：绕过整个沙箱，等于在墙上开了个门
- **工作目录漂移**：Agent `cd` 出 workspace 后用相对路径执行，校验必须基于绝对路径

## 可复用建议

1. 安全边界放执行层，prompt 只是体验优化
2. 删除永远是“移入回收站 + 可恢复”，真删留给人工
3. 每新增一个插件/MCP 工具，同步更新路径白名单和危险操作表
4. 定期做越界演练，用审计日志验证防线真的在生效

## 总结

OpenClaw 防误删不是赌模型不犯傻，而是四层纵深：文件系统隔离限定可见范围，执行层校验拦住路径逃逸，策略层把删除降级为可恢复操作，快照与审计最后兜底。模型可以错，但错的代价被压进一个可回滚的目录里——这才是 Agent 敢碰文件系统的前提。
