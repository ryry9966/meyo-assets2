## 背景

Agent 默认是无状态的。每次新会话，它对你一无所知：技术栈、命名习惯、写作偏好、正在推进什么项目——全都要重新讲一遍。OpenClaw 的记忆机制（MEMORY.md、会话摘要）解决了“记事”，但“你是谁”这件事一直缺少一个稳定落点。USER.md 就是这个落点：工作区里一份纯文本文件，声明式地描述用户，Agent 在会话开始时读取，作为长期上下文的一部分。

## 问题

不写 USER.md 的代价很具体：

- 每次重复交代背景，任务越复杂浪费越多；
- Agent 只能给出“通用正确”的回答，比如推你不用的语言、用你不喜欢的风格写文档；
- 靠记忆机制零散积累，事实散落、互相冲突，没有单一事实来源。

## 做法

核心思路：把用户画像当代码管理——声明式、版本化、定期修剪。

1. 在工作区根目录建 USER.md，建议分区：背景 / 技术栈与工具链 / 沟通偏好 / 当前目标 / 明确禁区。一行一个事实，不写叙述性段落。
2. 在 AGENT.md 里告知 Agent：会话开始先读 USER.md；确认学到持久性事实（而非临时任务上下文）时，提议增改。
3. 更新走“提议—确认”流程：Agent 给出 diff，你确认后写入，不要让它自由覆写。
4. 进 git。变更历史就是画像的演进史，回滚也方便。

一个可抄的骨架：

```markdown
# USER
## 背景
- 后端工程师，主力 Go/Python
## 偏好
- 回答先给结论，再给推理
- 代码注释用中文
## 当前目标
- （一句话，附日期）
## 禁区
- 不要主动重构无关代码
```

控制篇幅在 1–2KB。它的每一行都会进入每个会话的上下文，写多了是持续付税。

## 踩坑点

- **写成日记而非事实。**“最近在学 Rust”可以，“今天调试很不顺”不要。
- **塞敏感信息。**密钥、住址、证件号不放——它们会随上下文进入每次模型调用和工具参数。
- **事实过期不删。**不带日期的易变事实，半年后 Agent 会把新旧信息混着用。给易变条目标注日期，定期清理。
- **与系统提示冲突。**优先级要在 AGENT.md 里写死：USER.md 定义偏好，AGENT.md 定义行为边界，冲突时后者优先。
- **偏好太抽象。**“写得专业点”没有可执行性，“默认分点、不用 emoji”才有。

## 可复用建议

- USER.md 管“你是谁”，PROJECT.md 管“在做什么”，两者不要混。
- 设固定复查节奏（比如每月一次），像做依赖升级一样修剪画像。
- 团队场景可拆成共享版（工具链、规范）+ 个人版（偏好、禁区）。
- 拿不准一条该不该写，用这个判据：六个月后仍然为真、且会影响回答方式的，才写。

## 总结

USER.md 便宜、可读、可版本化，是把 Agent 从“每次重来的陌生人”变成“熟悉的同事”的最小改动。它不智能，甚至有点原始，但正因如此可靠：所见即所注入。先写一版 20 行的，用两周，再决定怎么扩。
