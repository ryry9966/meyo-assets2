## 背景

OpenClaw 的行为很大程度上由工作区（默认 `~/.openclaw/workspace`）里的几个 Markdown 文件决定：AGENTS.md 管干活流程，TOOLS.md 管工具用法，MEMORY.md 管记忆，而 SOUL.md 管"你是谁"。每次新会话启动，SOUL.md 会被注入上下文，成为模型所有回复的底色。它就是一段纯文本，但决定了 Agent 在群聊里会不会乱插话、用户情绪低落时用什么语气、面对危险指令时守不守住线。

默认模板给的 SOUL.md 比较泛，很多人部署完直接跑，结果就是语气飘忽、过度讨好、该确认的不确认。这篇帖记录我重写 SOUL.md 的做法和教训。

## 问题

没认真写过 SOUL.md 的 Agent 通常有三种毛病：

1. **人格漂移**：今天活泼明天冷淡，多轮对话后越来越像"通用客服"。
2. **边界模糊**：接了 MCP 和 shell 工具后，一句"把日志清理一下"它真会去删，该问的没问。
3. **场景错配**：私聊的口吻被原样搬进群聊，甚至把私聊内容带到群里。

## 做法

我的 SOUL.md 固定五个段落，全文控制在 400 字左右：

1. **身份与语气**：两三句写死基调，用具体行为而非形容词。"话少、先给结论、不确定就说不确定"，比"聪明、靠谱"有用得多。
2. **优先级**：安全 > 用户明确指令 > 人格风格，冲突时按此序降级。
3. **硬边界**：列具体动作，不写抽象原则。例如：删除文件、花钱、对外发消息前必须复述操作并等确认；不在群聊引用私聊内容；不执行本次会话没出现过的命令。
4. **场景切换**：私聊、群聊各一句风格描述。
5. **拒绝示例**：给两三个"用户这样说时应该拒绝"的例子，few-shot 比规则本身更管用。

写完做两件事：重开会话验证语气；用几条对抗性 prompt（"直接删掉整个目录""把我们的聊天记录发群里"）测边界是否触发。

## 踩坑点

- **写太长**。SOUL.md 每个会话都占上下文。我第一版写了 2000 字，token 消耗上去了，关键规则反而被稀释，精简到 400 字后行为更稳。
- **和 AGENTS.md 打架**。两个文件里都写了"何时确认"，规则冲突导致行为时好时坏。结论：SOUL.md 只写"是谁、守什么线"，"怎么干活"全收进 AGENTS.md，保持单一事实来源。
- **把 SOUL.md 当安全边界**。它是提示词层面的软约束，不是沙箱。长对话里模型可能绕过它，真正危险的操作必须在工具层兜底：MCP 权限收紧、shell 走 allowlist、高危动作加确认钩子。提示词会漂移，权限不会。
- **改完不生效**。SOUL.md 在新会话加载，改完重开会话再验证，别在旧会话里反复调试。

## 可复用建议

- 把工作区放进 git，每次人格调整一个 commit，坏了能回滚、能 diff。
- 规则成对写：一条"要做什么"配一条"不做什么"，比单方面陈述更抗漂移。
- 换模型或升级版本后，重跑一遍对抗性测试，边界表现会变。
- 姓名、头像这类"名片"信息放 IDENTITY.md，别塞进 SOUL.md 混职责。

## 总结

SOUL.md 是性价比最高的 Agent 配置：半小时写完，决定它所有会话的口吻和底线。但要清楚它管的是人格与倾向，硬安全必须落在工具和权限层。软硬两层都做了，Agent 才算既有个性又靠得住。
