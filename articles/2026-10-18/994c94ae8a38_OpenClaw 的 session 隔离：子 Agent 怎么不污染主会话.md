## 背景

用 OpenClaw 跑自动化久了，主会话最容易变成垃圾场：调研任务的中间输出、超长工具返回、试错日志全堆在上下文里，几轮之后指令遵循明显变差。子 Agent 本来是解法，但如果用得不对，污染只是换了个位置。

## 问题：先分清隔离边界

OpenClaw 的 session 隔离是**上下文级**的：spawn 出来的子 Agent 有自己的会话文件和独立上下文窗口，它的工具调用、长输出、中间推理都写在自己的 transcript 里，主会话默认只拿回一份摘要。这解决的是"上下文污染"。

但它不解决另外两个通道：

1. **文件系统是共享的**。子 Agent 写的文件、改的 git 状态，主 Agent 一样看得见；
2. **长期记忆是共享的**。子 Agent 若写了 memory 或 AGENTS.md，等于把临时结论固化进主会话。

所以污染有三条路：上下文、文件、记忆。只堵第一条是不够的。

## 做法

1. **派活前先定交付物。** spawn 时任务描述写成四段，固定模板：

```
目标：…
约束：不写 memory/AGENTS.md，不做 git commit（除非任务即提交）
交付：≤20 行结论 + 产物相对路径
禁止：粘贴原始工具输出
```

2. **给子 Agent 划独立工作目录**，如 `workspace/subtasks/<task-id>/`，所有中间产物落在这里，返回时只给路径。主会话需要细节自己去读，而不是把内容塞回上下文。
3. **并行任务各自用独立子目录**，避免互相覆盖。
4. **验证隔离生效**：跑完后翻主会话的 session 文件（`~/.openclaw/agents/<agent>/sessions/` 下最新 jsonl），确认里面只有你的 spawn 调用和一段短摘要；子 Agent 的会话文件单独存在且明显更长。30 秒能查完，建议养成习惯。

## 踩坑点

- **默认权限是继承的。** 子 Agent 拿着主 Agent 的全部工具和凭证，隔离的是上下文不是权限。敏感自动化单独建一个 agent、配最小工具集，比指望 prompt 约束可靠。
- **"返回摘要"不限长度就等于全文。** 不写行数上限，模型倾向整段复述工具输出，等于换了个文件污染。
- **上下文隔离 ≠ 状态隔离。** 常见翻车：子 Agent 在仓库根目录跑测试，留下构建产物或改了 lockfile，主 Agent 下一轮读到的环境状态已经变了。
- **子 Agent 自己也会爆上下文。** 多级拆解时，子 Agent 内部同样要遵守"落盘、返回路径"的纪律，否则只是把垃圾场搬到子会话，还多花一层 token。
- **cron 长期跑会堆积大量 session 文件**，定期清理，否则排查时找不到关键记录。

## 可复用建议

- 四段式任务模板存进 workspace，每次 spawn 复制改参，别每次现写。
- 固定产物目录规范，主/子 Agent 只认这个约定，省掉"东西在哪"的沟通。
- 发布、支付、删数据这类操作固定走独立 agent + 最小权限，主会话只做编排。
- 把"检查主会话 transcript 是否干净"加进自动化任务的验收清单。

## 总结

OpenClaw 把上下文边界画清楚了，但文件和记忆两条通道要自己管。一句话原则：**子 Agent 像外包**——给它独立工位（子会话）、明确交付物（摘要 + 路径）、收走钥匙（最小权限），主会话才能长期保持干净。
