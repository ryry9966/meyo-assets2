你在 AI 助手里问"今天几号"，和让它写一段并发去重的代码，背后大概率不是同一个模型在干活。决定"这个问题该派给谁"的那层系统，叫模型路由（Model Routing）。36kr 最近把它称作"AI 长尾博弈的关键位置"——问题的难度分布天然是长尾的，谁站在岔路口指挥流量，谁就可能吃走最厚的一段利润。这篇把机制、牌桌和胜负手拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/ac2ad4257c6a25c4.png)

## 为什么需要路由：token 的成本不是平均分布的

- LLM 的推理成本与参数量、生成长度近似成正比，而真实业务的查询难度呈典型的二八分布：客服场景里八九成请求是"查订单、改地址、问营业时间"，只有一成是真正的疑难纠纷。
- 学术界早有验证：Stanford 2023 年的 FrugalGPT 论文显示，用"便宜模型先答、判分不过再升级"的级联策略，在部分数据集上能把成本压到单一 GPT-4 的 2%~10%，质量基本持平。LMSYS 开源的 RouteLLM 框架也给出过约 2.75 倍性价比提升的公开实测。
- Agent 把这个杠杆进一步放大：一次任务几十次 tool call，每步省八成，乘起来就是数量级的差距；同时小模型延迟低，直接改善 P99 体验。

一句话总结：模型不是越贵越好，而是"按题分配"。分配权本身，就成了一门生意。

## 路由怎么决策：从 if-else 到 learned router

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/45f9f1415b40274f.png)

技术演进大致分三代：

1. **规则与分类器**：关键词、意图分类、长度阈值。简单粗暴，冷启动快，但粒度太粗。
2. **Embedding 相似度 + 历史表现库**：RouteLLM 的核心思路——"这道题和历史上哪类问题像？那类问题哪个模型赢过？"把路由变成一个查询匹配问题。
3. **级联 + 验证器（cascade + verifier）**：便宜模型先答，打分器评估置信度，不够就升级大模型。很像"实习生先上，搞不定再喊老板"，也和推理侧的 speculative decoding（小模型起草、大模型校验）思想同源。
4. 进阶玩法是 bandit / RL 在线路由：边用边学，在"探索新模型"和"利用已知最优"之间动态平衡。

难点有三个：

- **误路由的代价不对称**：简单题发给大模型只是多花钱，难题发给小模型是当场丢客户——前者是成本问题，后者是工伤问题；
- **分布漂移**：新模型一发布，历史表现库的先验就开始贬值；
- **逐题不确定性**：这是路由价值空间的根本来源。即便是排名前二的模型，在 Arena 式盲测里胜负通常也就五五开附近，没有谁道道题都赢。这个"不存在全局最优解"的长尾，就是路由层存在的理由。

## 长尾博弈：牌桌上的三层玩家

- **模型实验室**：他们其实最警惕独立路由——用户直连才有品牌溢价，真实使用数据才有训练飞轮。最快的应对是"把路由吞进模型里"：GPT-5 已会自动在快思考和深度思考模式间切换，Amazon Bedrock 也上线了 intelligent prompt routing。当模型自己做内部分流，独立路由的一个卖点就少了一个。
- **独立路由 / 聚合层**：代表是 OpenRouter 这类平台，公开披露口径已做到日均数十亿级 token、年化收入过亿美元的量级，国内也有不少聚合 API 在做同样的事。逻辑类似 Cloudflare 之于网站流量、OTA 之于机票：占住入口，向上游要折扣，向下游卖省心。
- **云平台与应用框架**：AWS、Cloudflare 的网关类产品把 routing 做成附带功能，Agent 框架内置 model fallback。路由一旦变成 feature，就不再天然是一门 company 级别的生意。

还有个变量：DeepSeek 掀起的价格战把 token 单价打到一年前的零头，"省钱"的相对卖点被稀释；但 Agent 又把调用量放大几十倍，省钱的绝对值又回来了。路由的价值没有消失，只是从"单价差"挪到了"结构差"。

## 谁能通吃：三张底牌和一个反例

路由层想赢下长尾，得同时攥住三张牌：

1. **数据飞轮**：每一次路由决策都是一条带标签的训练数据——"这个 query 发给 A 模型，用户满意"。量越大，决策越准，这是唯一能形成正反馈的环。
2. **分发权**：站在需求入口（超级应用、设备端、企业网关）才有"默认设置"权。AI 时代的默认选项，值钱程度不亚于搜索引擎时代的首位。
3. **中立性**：企业多模型、多云的避险诉求，给独立路由留了类似 multi-cloud 管理层的生态位。

反例也要看清：在"评测即立场"的时代，路由的中立性很难自证。聚合平台推荐哪个模型，可能和抽成结构有关；通用榜单的排名，和你的业务流量分布可能完全是两回事。谁掌握 per-query 的真实评测数据，谁才有资格谈"最优路由"。所以更现实的判断是：没有通吃者，只有握住"数据 + 分发 + 中立"组合拳的人吃下最肥的一段。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/6fc1e0690b0c4653.png)

1. **先测量，再路由**：拿自己真实流量手工标注 500 条做 per-query 评测，比信任何榜单都有用。多数团队做完会发现：六成流量小模型就能接住，剩下四成才值得上大模型。
2. **级联优先于智能路由**：verifier + 升级这套方案实现成本最低、失败可解释、容易回滚。先把"便宜模型 + 质量打分"跑通，再考虑上学习型路由，别一上来就堆 RL。
3. **把路由日志当资产**：无论最终用谁的模型，"这个请求走了哪条路、效果如何"的决策记录要自己留存——这是未来任何路由优化和议价的筹码，也是被平台锁定时唯一带得走的东西。留日志，就像龙虾不撒手钳子。
