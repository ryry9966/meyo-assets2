打开任意一家模型厂商的价目表，你会看到一个耐人寻味的数字：同一个生态里，旗舰模型与轻量模型的输入价格能差 16 倍以上，而用户请求里真正需要旗舰级算力的可能不到两成。这片由价差和算力浪费构成的灰色地带，正是近两年 AI 圈热议“路由（Routing）”的土壤。36kr 那篇《路由的威力》把问题挑明了：在 AI 的长尾博弈里，谁能通吃？下面把它拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/ef9a94e56cdcedc4.png)

## 一、两种路由，一套底层逻辑

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/befeeac43a7f2406.png)

**第一种在芯片层面：MoE（Mixture of Experts）。**
- 大模型不再对每个 token 动用全部参数，而是由一个门控网络（gating network）实时调度，把 token 分发给少数几个“专家”子网络。
- 典型参数：Mixtral 8x7B 是 8 选 2；DeepSeek-V3 总参数 671B，但每个 token 只激活约 37B，从 256 个专家里选 8 个。
- 好处是总容量变大、单次成本近似不变；代价是路由器必须做负载均衡，否则专家会“冷热不均”（expert collapse），DeepSeek-V3 甚至专门设计了无辅助损失的均衡策略来稳住训练。

**第二种在产品层面：模型路由 / 级联（cascade）。**
- 请求进来，先由一个轻量分类器判断难度：摘要、翻译、格式化这类轻活交给便宜的小模型，多步推理、专业领域问题才升级到旗舰。OpenRouter、LiteLLM 这类网关，以及 FrugalGPT、RouteLLM 等研究，做的都是这件事。
- 级联其实是老手艺：2001 年的 Viola-Jones 人脸检测就用“便宜特征先筛、昂贵特征精查”的级联结构；连 speculative decoding（小模型起草、大模型校对）本质上也是一种 token 级路由。

两种路由共享同一个逻辑：让算力与请求难度匹配。一个管 token 去哪，一个管 query 去哪。

## 二、长尾的经济学：九成请求其实很便宜

- 请求难度呈长尾分布：大多数是改写、总结、填表式“轻活”，真正咬硬骨头的长尾少数才需要重算力。
- 价差有多离谱：GPT-4o 输入约 $2.5/百万 token，GPT-4o-mini 只要 $0.15，相差约 17 倍；开源模型还能再低一个量级。
- 收益有多实在：斯坦福 FrugalGPT 论文（2023）显示，级联策略在部分基准上最高省 98% 成本而质量不掉队；LMSYS 的 RouteLLM 用 Chatbot Arena 数据训练路由器，号称在保住 95% GPT-4 质量的同时砍掉最高 85% 成本。
- 给每个请求都上旗舰，等于开 F1 送外卖——能跑，但账单很感人。这也是 Notion、Cursor 这类应用都在内部悄悄做路由的原因；Character.AI 用小模型加 INT8 量化扛住高并发，同样证明了“够用就好”在工程上完全成立。DeepSeek-V3 能把 671B 模型的训练成本压到百万美元量级，MoE 调度也功不可没。

## 三、谁能通吃：三方的围猎与反围猎

判断“通吃”，标准老三样：网络效应、切换成本、规模经济。候选人各有筹码：

1. **独立路由 / 网关层**：OpenRouter 们的筹码是跨厂商视野——它见过所有应用的请求难度分布，能持续优化并把比价能力货币化，站位很像当年的 CDN 与 OTA。软肋是层太薄：API key 一换就走，切换成本约等于零。
2. **模型厂商**：可以“自己路由自己”——把产品线拆成 mini / flash / pro / thinking 多档再加自动选择；更狠的武器是价格战，开源模型价格每跳水一轮，路由层的套利空间就被压扁一分。纵向整合是最容易发生的结局。
3. **应用层**：握着用户和工作流，能在 agent 流水线里按步骤路由，看到的不是单条 query 而是完整任务上下文。切换成本最高，但议价能力分散在无数应用手里。

CDN、支付路由、云成本管理的历史给了一个不浪漫的结论：中间层很少通吃，更多是“收税者”——抽成稳定，但天花板取决于上下游价差。真正难被替代的资产只有一样：难度信号的元数据飞轮。谁站在入口，谁就能持续积累“什么问题该花多少钱”的知识。

## 四、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/7e2a6bb06977aa30.png)

1. **先测量，再路由。** 上来就搭路由系统是本末倒置：先记录自己流量的难度分布与失败样本，多数团队会发现自己 70%~90% 的流量根本不需要旗舰模型；升级动作交给不确定性信号（自一致性投票、验证器、用户重试）触发。
2. **纯路由层是薄冰，要么上浮要么下潜。** 上浮做工作流与 agent 编排，下潜做评估与可观测性（eval / observability）；停在正中间的中间商，命运系于模型价格曲线——价格战每打一轮，毛利就薄一层。
3. **盯住两个先行指标。** 一是旗舰与开源模型的价差曲线，二是单次 agent 任务里多模型调用的占比。路由的价值 ≈ 价差 × 调用频次，两个变量同时收缩时，路由就从一门生意退化为工程最佳实践——像今天的负载均衡一样重要，但不再性感。

路由不生产智能，它只是算力的搬运工。但搬运工站在码头，看得见每一票货的去向——这可能是“通吃”叙事里最实在的部分。
