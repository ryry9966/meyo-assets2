## 背景：agent 每次都在搬进一间陌生的房间

用 OpenClaw 一段时间后，workspace 里会慢慢长出一堆东西：notes、memory、脚本、各种临时产物。问题是，agent 每次新会话面对的都是一个"陌生的房间"——它不知道你的目录约定，不知道哪些文件能动，更不知道你上周才教过它别踩某个坑。

AGENTS.md 就是为此存在的约定：一份放在 workspace 根目录、每次会话开始都会被 agent 读取的纯 Markdown 文件。它不是给人看的 README，而是写给 AI 的操作规程。在 OpenClaw 的文件体系里分工很清楚：SOUL.md 管人格和语气，AGENTS.md 管做事方式。

## 问题：没有手册的典型症状

- 临时文件随手扔在根目录，你每隔几天清理一次；
- 每次都要在对话里重复"用中文回复""别动那个配置"；
- 同一个错误隔几天再犯一遍，你越用越像在带一个记性不好的新同事。

这些不是模型能力问题，是上下文缺失问题。解法就是把约定固化成文件。

## 做法：四步搭起骨架

**第一步，定结构。** 三个部分就够：这个工作区是干什么的（一段话）、东西放在哪里（目录契约）、干活要遵守什么（行为规则）。

**第二步，写目录契约。** 明确 `notes/` 放长期笔记，`memory/` 交给记忆机制管理，`scripts/` 只放可复用脚本，临时产物进 `tmp/` 且随时可清理。路径写具体，不要写"放在合适的位置"。

**第三步，写行为规则。** 用祈使句加具体条件：回复语言、危险操作前必须确认、哪些目录只读、输出格式偏好。

**第四步，写负面清单。** "不要""禁止"比"建议"有效得多。AI 对边界的敏感度远高于对愿景的敏感度。

子目录还可以放各自的 AGENTS.md，处理更局部的规则，离代码越近越具体。

## 踩坑点

1. **写太长。** 超过一两百行，重点就被稀释。规则文件不是文档库，越长越没人遵守——包括 AI。
2. **和其他文件冲突。** SOUL.md 管人格，AGENTS.md 管做事方式，同一件事别在两处写两个版本，agent 会随机选一个。
3. **当日记用。** 流水账进 memory，AGENTS.md 只放"长期成立"的规则。
4. **写抽象口号。** "要严谨""要高效"没有信息量；"提交信息用中文、单行、不超过 50 字"才有用。判断标准：AI 读了这条之后，行为会有可观测的变化吗？
5. **不维护。** 过期的规则比没有规则更糟——它会让 agent 自信地做错事。

## 可复用建议

- **把 AGENTS.md 当事故复盘产物。** 每次踩坑，先别骂模型，把教训转化成一条规则写进去，同样的问题就只付一次学费。
- **用版本控制管理它。** 改规则和改代码一样留 diff，出问题能回滚。
- **每月清一次。** 删掉不再成立的条目，规则文件的生命力靠删减维持。
- **新项目直接复制模板。** 三段式骨架可以跨项目复用，具体条目按项目填。

## 总结

我的 AGENTS.md 最终只有四十多行，但几乎所有"重复说第三遍"的问题都消失了。它的价值不在文件本身，而在于把你和 agent 的磨合成果固化下来——写得越具体、越克制，agent 就越省心。本质上，这是你给一个长期协作者写的交接文档，值得花半小时认真写一次，然后用一个月慢慢修。
