## 背景

社区内容产出靠人肉撑着，总有断更的时候。我想借这个机会验证一件事：用 OpenClaw 的定时任务 + MCP 工具链，能不能跑通一条"选题 → 写稿 → 发布"的自动化闭环。目标不是炫技，而是让它在无人值守下**稳定、不重复、不出事故**。

## 问题定义

难点从来不是"能不能发出去"，而是：

1. 内容重复、自我抄袭；
2. 幻觉链接、编造引用；
3. 格式崩坏、触发社区风控；
4. 出错时没有刹车。

## 架构与做法

整体分五层：

- **调度层**：OpenClaw cron 每天固定时段触发，注入当前本地时间与运行编号；
- **素材层**：脚本抓取订阅源（RSS、GitHub trending、社区热帖），做摘要取 top-5，不进 agent；
- **写作层**：Agent 只做一件事——基于给定素材产出结构化 JSON（title / tags / body / sources），限定语气、长度和允许的 Markdown 子集；
- **工具层**：发帖能力封装成两个 MCP tool：`draft_topic` 和 `publish_topic`，后者发布前强制查重；
- **安全层**：默认先进草稿区，人工确认后才正式发布；连续 N 篇通过率达标再放开全自动。

一条核心设计原则：**Agent 不直接碰 HTTP**。它只输出数据，副作用全部收在一个薄脚本层里，可测试、可拦截、可重放。每次运行落一个 run 目录，素材、prompt、输出、API 响应全存档。

## 踩坑实录

**1. 重试导致双发。** 网络超时后重试，同一个帖子发了两条。解法：对 title + 首段做 hash 指纹，`publish_topic` 前先查库，同时把指纹透传给服务端做幂等键。

**2. 时区坑。** cron 按 UTC 跑，帖子凌晨四点发了出去。解法：调度层固定时区，并在每次运行的上下文里显式注入本地时间，不依赖 agent 自己推算。

**3. 幻觉链接。** Agent 编了一个"看起来很合理"的参考链接，实际 404。解法：规定 sources 里的 URL 必须逐字来自素材层抓取结果，发布前脚本逐个 HEAD 校验，校验不过就剔除。

**4. Token 爆炸。** 早期把整份 RSS 全文塞进 prompt，又慢又贵，输出质量反而下降。解法：素材层先做摘要，prompt 里只放 top-5 的标题、要点和原始链接。

**5. Markdown 兼容。** 社区编辑器吞嵌套列表和部分代码块。解法：固化一个受支持语法的子集模板，写作 prompt 里明确禁用其余写法。

**6. 没有刹车。** 某天素材源全挂了，agent 基于"记忆里的旧素材"硬写了一篇过时内容。这是最危险的一次。解法：加硬规则——素材为空直接跳过本次运行并告警，禁止凭记忆成文。

## 可复用建议

- **工具与智能分离**：agent 出结构化数据，写操作放脚本层，权限最小化；
- **一切写入操作都要幂等**：指纹 + 幂等键 + run 目录回放，三件套缺一不可；
- **灰度上线**：回复他人 → 草稿待审 → 定时自动发，逐级放开；
- **监控朴素指标**：成功/失败数、人工拦截数、被删被踩数，比任何 dashboard 都诚实。

## 总结

回头看，机器人本体代码只占三成工作量，七成花在防呆上：幂等、限流、校验、刹车。OpenClaw + MCP 这套组合真正的价值，是把"能力"做成可拔插的工具、把"判断"交给 agent、把"安全"留回人手里。想抄作业的同学，建议先从草稿模式跑两周再谈全自动。
