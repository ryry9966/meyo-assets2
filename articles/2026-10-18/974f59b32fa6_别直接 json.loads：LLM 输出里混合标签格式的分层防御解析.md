# 背景

在 OpenClaw 的插件和 MCP 工具链里，LLM 输出经常要被下一跳程序直接消费：工具调用参数、结构化中间结果、传给下游脚本的配置。我们在提示词里明确写了"只输出 JSON"，但实际跑起来，拿到的文本形态五花八门——尤其在换模型、长上下文、或者输出里嵌了代码片段的场景。

# 问题

常见的混入形态至少有这几类：

1. 裸 JSON（理想情况，但只占一部分）
2. ` ```json ` 围栏代码块包裹
3. 自定义标签包裹：`<json>...</json>`、`<answer>...</answer>`，有时模型自创标签名
4. 前后带解释性文字："好的，以下是结果： {...}"
5. 多个 JSON 对象拼接、重复输出两遍
6. 伪 JSON：尾逗号、单引号、中文引号、NaN、注释

只要一种没覆盖，一次解析失败就让整条 agent 链路中断，而且往往是长任务跑到第 N 步才炸，排查成本很高。

# 做法：分层提取 + 独立校验

核心思路是拆成两层：**提取层做多级降级，校验层用 schema 一票否决**。提取成功不等于数据合法。

提取函数骨架：

```python
import json, re

def _reject(c):
    raise ValueError(f"non-standard constant: {c}")

def extract_json(text: str):
    candidates = [text.strip().lstrip("﻿")]
    # 围栏代码块（非贪婪）
    candidates += re.findall(r"```(?:json)?\s*(.*?)```", text, re.S)
    # 自定义标签，容忍多种标签名
    candidates += re.findall(
        r"<(?:json|answer|result)>(.*?)</(?:json|answer|result)>", text, re.S)
    for raw in candidates:
        try:
            return json.loads(raw.strip(), parse_constant=_reject)
        except (json.JSONDecodeError, ValueError):
            continue
    # 兜底：感知字符串引号的括号配平扫描
    return balanced_scan(text)
```

提取之后走 pydantic / JSON Schema 校验，不过就按失败处理，进入重试或人工兜底。

# 踩坑点

- **正则贪婪匹配**会把两个代码块之间的文字一起吃进去，务必用非贪婪 + `re.S`，并优先取第一个完整块。
- **括号配平必须感知字符串字面量**。值里出现 `{` 或引号转义就错切，是这类兜底最常见的 bug。
- `json.loads` 默认接受 `NaN`/`Infinity`，这不是严格 JSON。下游如果用别的语言解析，会在这里翻车。
- **流式输出别边流边 parse**。拿到的是半截 JSON，要么等终止符，要么用增量解析器。
- **静默降级最危险**。修复了尾逗号却不记录，提示词退化了你根本发现不了。至少要记录每次命中的 `source_format` 分布。

# 可复用建议

- 提取函数写成纯函数，单元测试直接喂真实脏样本，攒一个"失败语料库"，每次线上解析失败都补进去。
- 提示词仍然要求单一哨兵标签（如 `<answer>`），但解析端永远不假设它存在——提示词是引导，不是契约。
- 有 API 级 JSON mode / structured output 就优先用，但降级管线保留。换模型、换供应商时不用改一行代码。
- 定期看 `source_format` 分布，某类形态占比突然上升，通常意味着换模型或 prompt 被改出回归了。

# 总结

防御性解析的本质，是承认"模型输出是不可信输入"。分层降级、独立校验、可观测，三件事做齐，链路鲁棒性会有数量级提升。这套代码与具体模型无关，建议直接沉淀为插件公共库，而不是每个工具各写一份。
