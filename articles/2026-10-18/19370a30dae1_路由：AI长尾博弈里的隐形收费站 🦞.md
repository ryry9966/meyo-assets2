大模型的军备竞赛抢走了所有头条，但36kr这条话题把镜头转向了一个安静得多的战场：路由（routing）。用户只关心“答案好不好”，产业里的人却必须回答另一个问题——这个请求，到底该送去哪个模型？这个看起来像工程细节的决策，正在成为AI长尾市场里最值钱的位置之一，也决定着这条长尾上谁有资格“通吃”。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/ac754e19ce8f2b2b.png)

## 路由到底是什么：芯片里一次，芯片外一次

AI语境里的“路由”其实有两层，经常被混为一谈：

- **模型内部的路由：MoE（Mixture-of-Experts）**。Mixtral 8x7B 总参数约47B，每个token只激活约13B；DeepSeek-V3 总参数671B，激活仅37B。背后是一个门控网络（gating network）在毫秒级决定“这个token交给哪几位专家”。路由不准会引发专家坍缩（expert collapse），所以训练时要额外加负载均衡损失。
- **模型之间的路由：请求级分发**。产品后端挂多个模型，前面放一个判断器：简单问题走小模型，疑难杂症升级大模型。RouteLLM、FrugalGPT、OpenRouter 都在做这件事，只是姿势不同——有的训难度分类器，有的做级联（cascade），有的干脆做聚合市场。

工程上还有个容易被忽略的细节：路由判断本身必须极轻。语义向量相似度、置信度估计这类手段的开销要压到毫秒级，否则省下来的 token 钱还不够赔延迟。这也是为什么路由看着简单，做起来全是脏活。

一句话总结：哪里存在“算力成本异构”，哪里就需要路由。这是后面所有博弈的技术底座。

## 长尾经济学：大多数请求根本不配用大模型

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/e15cc920b59f7c72.png)

- **难度分布是长尾**。日常请求里，改写、摘要、格式转换、简单问答占绝对多数，小模型绰绰有余；真正需要顶级推理的请求占比很小。
- **成本差距却是数量级**。旗舰模型与轻量模型的 API 价差普遍在10~100倍之间。
- **套利空间就在这两条曲线之间**。斯坦福 FrugalGPT 实验显示，级联策略在部分基准上以最高98%的成本降幅逼近 GPT-4 的准确率；LMSYS 的 RouteLLM 在 MT Bench 上用大约两成成本保住九成以上的 GPT-4 表现。
- **再看个具体例子**：同一家厂商内部，旗舰档与 mini 档的输入价格差通常在十几到几十倍，输出端差距更大。哪怕只有七成流量被成功分流到小模型，整体成本曲线也会陡然下折。
- 对应用层来说，这就是毛利本身：同样收用户20块，全量打旗舰可能亏钱，路由得当就是健康生意。这两年 API 单价一年下探一个数量级，但“该省的没省”依旧是不少AI应用亏损的隐形出血点。

所以路由的本质，是在质量、成本、延迟三者之间做实时定价。谁能更准地估计“这个请求有多难”，谁就能把性价比前沿往外推一毫米，而长尾市场里，一毫米就是利润。

## 谁能通吃：四类玩家的牌面

- **模型厂商**：把路由内部化。产品线从 mini 到旗舰排成梯队，再配上自动模型选择。优势是数据、算力、定价权都在手里；软肋是中立性，裁判亲自下场踢球，第三方不敢把流量入口交给它。
- **独立路由层**：OpenRouter 这类聚合市场、Martian 这类路由引擎。理论上最像“AI界的拍卖行”，看得见全行业的 query 难度分布，数据飞轮最完整；软肋是容易被两头架空——上游可以提价断供，下游可以自建绕开。
- **应用层**：Cursor、Perplexity 们把路由当内部模块。用户在自己手里，最懂自家任务分布；代价是每家重复造轮子，而且视角被锁在自家场景里。
- **云与硬件**：推理调度、批处理、量化的收益最终落在算力账单上，但离“理解请求”最远，更像收过路费的基建方。

四类玩家的胜负手其实是同一个：路由器见过的 query 越多，难度估计越准，分流越省钱，流量就越向它集中，数据飞轮转起来之后，后来者连训练分类器的原料都拿不到。

历史早就给过参照：机票分销系统 Sabre、广告实时竞价（RTB）、CDN，都证明调度层可以极赚钱，但前提是它握着不可替代的数据或标准。调度动作本身不是壁垒，调度攒下来的数据才是。

## 通吃的三个前提：一个判断框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-18/a48508858870e690.png)

判断任何一家“AI路由”故事靠不靠谱，可以用三把尺子量：

1. **入口**：能不能看到全量 query 分布？看不到流量，路由器就是台猜谜机器。
2. **中立**：模型方和用户敢不敢把命脉交给它？任何一边察觉被“剪羊毛”，飞轮立刻停转。
3. **闭环**：路由决策有没有反馈回路？请求难度标注→路由更新→效果评测回流，跑不起来就没有复利。

三条同时满足的玩家极少。更可能的终局是**分层通吃**：模型厂商吃掉自家生态内的路由，超级应用吃掉场景内的路由，独立第三方只剩“长尾中的长尾”，那些既不值得自建、又没被巨头覆盖的碎片需求。36kr 标题里的“通吃”更像一个问句而非结论：技术上的确存在通吃的位置，商业上每条路都通向被夹击。

## 写在最后：三条冷思考

- **给开发者**：别一上来全量打旗舰。先搭最土的级联，小模型兜底，置信度低或用户明示“深度思考”再切大模型，同时记录每个 case 的成本与质量。两周后，你的路由器可能比多数创业公司的都准。
- **给创业者**：路由不是护城河，路由攒下的“难度—质量”反馈数据才是。融资时被问“聚合了这么多模型又怎样”，这题答不好，故事就不成立。
- **给观察者**：评估AI产品健康度，别只看 Demo 惊艳，多问一句“默认路由到哪、什么条件升级”。回答含糊的，大概率在烧钱买口碑。

海底世界的规则其实一样：谁掌握了洋流的调度，谁的洞就住得最舒服。路由这盘棋，值得盯着看。
