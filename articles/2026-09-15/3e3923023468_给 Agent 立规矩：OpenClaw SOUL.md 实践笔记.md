## 背景

OpenClaw 的工作区里有一组 Markdown 文件决定 agent 的行为：`AGENTS.md` 管操作规程，`MEMORY.md` 管长期记忆，`USER.md` 管用户画像，而 `SOUL.md` 管的是这个 agent"是谁"。每次会话启动，这些文件会被注入 system prompt，其中 SOUL.md 是唯一适合写人格、语气和价值边界的地方。

很多人装完直接用默认模板，甚至清空了事。短期没问题，等接了多个聊天渠道、挂上 MCP 工具、开始自动执行任务，问题就浮出来了。

## 问题

没有明确人格和边界的 agent，实测常见三类翻车：

1. **语气漂移**：今天像客服，明天像论坛老哥，跨渠道不一致，用户无法建立稳定预期。
2. **边界缺失**：模型倾向讨好，用户说"帮我把这目录清了"它真的执行删除；说"帮我回他一句"它替你写了情绪浓烈的话发出去。
3. **过度承诺**：对不确定的事给确定性答复，幻觉风险被放大。

SOUL.md 不是银弹——它是提示词层的软约束——但没有它，你连约束的锚点都没有。

## 做法

我的 SOUL.md 控制在 60 行以内，分四段：

**1. 身份与语气（约 10 行）**
两三句话定调，配正反例。比如："简洁直接，先结论后理由；不用表情包，不喊'亲'。"再补一条坏例子："不要输出三段式小作文。"

**2. 边界清单（约 20 行，核心）**
分三层：
- 绝对不做：不动钱包、不删数据、不代发私人消息、不透露通讯录里他人的信息
- 需要确认：任何写操作、花钱、对外发送
- 可自主：读、查、总结、草拟

**3. 不确定时的行为（约 10 行）**
明确"不知道就说不知道""连续两次尝试失败就停下来问我，不要自创第三种方案"。这条在自动化场景能拦住大部分连锁翻车。

**4. 分工声明（约 5 行）**
写明"操作细节看 AGENTS.md，用户偏好看 USER.md"，防止模型把人格文件当操作手册用。

写完重启会话，构造几个边界用例（"给 X 转个账""把这个文件删了"）验证反应是否符合预期。

## 踩坑点

- **写成操作手册**：步骤类内容应放 AGENTS.md，两处重复会互相打架，表现反而变差。
- **边界不可执行**："要有分寸感"没用。要写成"对外发送任何消息前，必须先展示原文等待确认"。
- **当成硬安全边界**：SOUL.md 是提示词，会被长上下文稀释，也可能被注入绕过。真正的红线（支付、删除、外发）要落到工具层：MCP 工具白名单、命令确认钩子、目录权限。人格文件与权限系统是双保险，不是互相替代。
- **写入敏感信息**：SOUL.md 每次会话都注入上下文，密钥、住址、身份信息别放。
- **照抄模板不改**：模板只是起点，语气示例和边界清单必须按自己的场景重写。

## 可复用建议

1. SOUL.md 进 git。每次 agent 翻车就回写一条边界，把它当"事故复盘文档"持续养，而不是一次性配置。
2. "禁止 / 需确认 / 可自主"三层结构几乎可套任何 agent 项目，不止 OpenClaw。
3. 每月删一次：清掉重复、从未触发、互相矛盾的条目，保持一页以内。规则越多，单条权重越低。
4. 改完必测：准备 3~5 个固定边界测试用例，每次改版跑一遍做回归。

## 总结

SOUL.md 的价值不在"让 agent 更像人"，而在把你的预期显式化：它是什么语气、什么能自己做、什么必须问你。这份文件的质量直接决定自动化的信任成本。先花半小时写清边界，比事后排查十次翻车划算。
