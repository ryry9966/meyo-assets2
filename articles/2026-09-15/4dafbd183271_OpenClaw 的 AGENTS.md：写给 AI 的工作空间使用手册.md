# OpenClaw 的 AGENTS.md：写给 AI 的工作空间使用手册

## 背景

OpenClaw 的 agent 每次会话启动时，会读取工作区根目录下的 `AGENTS.md`，把内容作为持久指令注入上下文。这个约定本质上是一份"写给 AI 的 README"：人类看 README 了解项目，agent 看 AGENTS.md 了解你的工作区规则。不管触发入口是聊天、定时任务还是插件/webhook，agent 都先读同一份手册——这也是它比在对话里反复叮嘱更可靠的原因。

## 问题

没有这份手册时，典型状态是：

- 每次会话都要口头重复"笔记放 `notes/`，文件名用日期前缀"；
- agent 在不同会话、不同机器上行为不一致；
- 它顺手读了 `.env`，或把临时文件散落在仓库根目录；
- 你纠正过的错误，换个会话又犯一遍。

这些不是模型能力问题，而是上下文问题：约定只存在于对话历史里，而对话历史是易失的。

## 做法

1. **建文件**：在工作区根目录创建 `AGENTS.md`，控制在 100 行以内。它会整份进入每次会话的上下文，长度直接换算成 token 成本。
2. **推荐结构**（按序）：
   - 工作区一句话定位 + 目录地图（每个目录干什么，两三行）；
   - 工作流约定：笔记/任务/文档的存放路径与命名规则；
   - 工具偏好：优先用哪个 MCP 工具、什么情况该先问再执行；
   - 安全边界：绝不读取或修改的路径（`.env`、密钥目录），绝不自动执行的命令类型；
   - 输出格式偏好（可选）。
3. **分层**：子目录可放自己的 AGENTS.md，离文件越近的规则优先级越高。根目录管全局，子目录管局部。
4. **迭代准入标准**：同一条纠正说过两次，就写进 AGENTS.md。
5. **验证**：开一个全新会话，让 agent 复述手册里的关键规则，或观察它建第一个文件时的行为。

## 踩坑点

- **写成小说**：规则超过一屏，关键约束会被稀释。删掉一切礼貌性说明，只留可执行、可验证的条目。
- **模糊指令**："小心操作"没用，"禁止修改 `secrets/` 下任何文件"才有用。规则要具体到 agent 能判断对错。
- **把密钥写进去**：AGENTS.md 会完整进入模型上下文，敏感值一律不出现，只写"密钥在哪个文件、不要读它"。
- **不入版本控制**：把它当配置代码，进 git、改动走 commit。目录重构后记得同步更新，否则 agent 会按旧地图走路。
- **用散文做本该机制做的事**：约束若能用权限配置或插件白名单硬性拦住，优先用机制，散文只做补充。

## 可复用建议

- 维护一份个人模板，新工作区复制后只改目录地图和特有约定；
- 仓库级规则放仓库的 AGENTS.md，个人偏好放 OpenClaw 工作区那份，职责分开；
- 每月花五分钟通读一遍，删掉已不成立的条目——手册和代码一样会腐烂。

## 总结

AGENTS.md 解决的不是智能问题，而是约定传递问题。它把口口相传的工作习惯变成一份随会话加载的契约：成本是一次写几十行 markdown，收益是 agent 在所有入口、所有机器上的行为一致性。第一版不必追求完美，先放三条你最常重复的指令进去，剩下的交给日常迭代。
