## 背景

OpenClaw 的 Agent 默认是被动的：你在聊天里发一句话，它才跑一轮。HEARTBEAT.md 改变了这个模型——框架给每个 Agent 挂了一个定时心跳（默认约 30 分钟一次，可在配置里调整），心跳触发时，Agent 会读取工作区根目录下的 HEARTBEAT.md，把里面的内容当作"待巡检清单"，自行判断要不要干活、要不要打扰你。

## 问题

很多人的 Agent 用着用着就退化成"高级搜索引擎"：你不问，它不动。但真正有价值的自动化往往不是一问一答，而是持续性巡检——备份没跑、证书快过期、inbox 里堆了未处理文件。这些事不该由你记住再去提醒 Agent，应该反过来：Agent 记住，并按约定周期检查。

## 做法

1. **定位文件**：在 Agent 工作区根目录建 `HEARTBEAT.md`。如果文件不存在，首次心跳时 Agent 通常会自己生成一份模板。注意：文件为空、或只有 `#` 开头的注释行时，心跳会直接跳过，**不调用模型、零 token**——所以想临时停用，清空文件即可，不必动配置。
2. **写任务**：每条用一句祈使句，写清"检查什么 + 满足什么条件时做什么"。例如：
   - 检查 `~/backup` 最新文件时间，超过 24 小时未更新就提醒我
   - 若 `~/reports/weekly.md` 本周未更新，起草周报框架并征求我确认
   - 每天上午整理一次 inbox，产出三行摘要
3. **控制节奏**：在 `openclaw.json` 的 `agents.defaults.heartbeat` 里调 `every`（间隔）和 `activeHours`（活跃时段），夜间降频或静默。
4. **验证**：观察两三个心跳周期。无事发生时 Agent 内部应答 `HEARTBEAT_OK`、不会给你递消息；看到它该沉默时沉默、该报告时报告，才算跑通。

## 踩坑点

- **文件越长，成本越高**。HEARTBEAT.md 是每次心跳的常驻输入，控制在 10 行左右，长任务说明挪到别的文件让 Agent 按需读。
- **别写有副作用的动作**。"自动发消息给客户""直接删文件"这类任务不要进心跳——心跳是无人值守执行的，且带全量工具权限。动作保持"检查 → 报告 → 征求确认"三段式。
- **条件必须明确**。"帮我盯着项目"这种模糊条目会让 Agent 每轮都汇报一遍同样内容，几轮后你会主动关掉它。告警疲劳对 Agent 同样成立。
- **心跳跑在 Agent 的会话上下文里**，高频心跳会污染你们平时的对话。巡检细节让 Agent 写进文件存档，回复里只给结论。

## 可复用建议

把 HEARTBEAT.md 理解成 **cron 条目 + 值班手册** 的组合：频率由配置管，判断标准由清单管。三个可复用模式：

1. **状态巡检**：目录/服务/证书是否过期、备份是否新鲜
2. **周期产出**：日报、周报的框架草稿，先备好再等你拍板
3. **阈值告警**：超过 N 小时未更新、连续失败超限才报告

每条保持"条件 + 动作 + 频率预期"三要素，写成模板后团队内可以直接互相抄。

## 总结

HEARTBEAT.md 的价值不在花哨，而在把"你惦记着问"变成"它按约定巡检"。建议从一条低成本、只读的任务开始，跑稳一个周期再加第二条。Agent 的主动性是被清晰的清单和边界喂出来的，不是被提示词许诺出来的。
