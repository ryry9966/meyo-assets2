## 背景

大部分 Agent 的默认工作模式是被动的：你不发消息，它就不动。但真想把 Agent 嵌进日常，你会发现需求大多不是"我问你答"，而是"有事你主动喊我"——日历快到点了提一句、CI 挂了告诉我、磁盘快满敲一下。OpenClaw 的 HEARTBEAT.md 就是为此设计的：Agent 按固定间隔被唤醒一次，读取工作区里的 HEARTBEAT.md，有任务就执行并主动发消息，没事就保持沉默。

## 问题

我之前踩过两个极端：一是把提醒逻辑写在会话里，换个会话就丢，且完全依赖我记得去问；二是用 cron 写死定时任务，时间精确但逻辑僵硬，需要一点判断力的活儿根本写不动。HEARTBEAT.md 的定位介于两者之间：一份间隔驱动的"模糊任务清单"，由模型自己判断"这次醒来有没有值得说话的事"。

## 做法

1. **找到文件**：默认在 `~/.openclaw/workspace/HEARTBEAT.md`，每行一个任务，并写清沉默规则：

```markdown
- 检查日历，未来 2 小时内有会议就提醒我
- 关注 foo 仓库 CI，失败才报告，成功不用说
- 服务器磁盘使用率超过 85% 才提醒
- 没有事就完全沉默，不要发任何消息
```

2. **调间隔**：默认 30 分钟，配置里改 `agents.defaults.heartbeat.every`，比如 `"15m"` 或 `"1h"`。
3. **控成本和出口**：心跳支持 `modelOverride` 指定便宜模型来跑；`target`/`direct` 决定心跳消息发到哪个会话，避免打扰主对话。
4. **观察一周再收敛**：先用默认配置跑几天，看 token 消耗和误报率，再删减清单。

## 踩坑点

- **心跳不是定时器**。它是"每 30 分钟醒来看一眼"，不是"9:00 准时执行"。精确时间的任务请走 cron/调度任务，别塞进 HEARTBEAT.md。
- **空文件也在花钱**：即使清单没内容，心跳仍会构造一次完整 prompt 调用模型。真想停，把 `every` 设成 `0m` 或删掉文件，而不是只清空内容。
- **清单越长越贵**：每一项都会被模型读一遍。我控制在 5 条以内，超出的迁到 cron。
- **有副作用的操作要谨慎**："自动重启失败服务"这类写进心跳，可能在你正用着的时候被触发，建议改成"报告并等我确认"。
- **多 agent 场景**每个 agent 有自己的心跳，注意别叠加成消息轰炸。

## 可复用建议

- 把 HEARTBEAT.md 当"轻量值班手册"：只放**判断型触发**的任务（条件满足才说），**时钟型触发**全部交给 cron。
- 每条格式统一：检查什么 → 触发条件 → 报告到哪，模型执行得更稳。
- 把 HEARTBEAT.md 纳入 git：改动可追溯，多机也能同步。
- 主动消息的价值密度要高，废话多了用户就会开始忽略它——这和告警治理是同一个道理。

## 总结

HEARTBEAT.md 解决的不是"能不能定时"，而是"Agent 要不要有主动意识"。它的工程价值在于：用极低的配置成本，给"周期性观察 + 条件性汇报"这类模糊任务一个归宿。用好的关键是克制——清单短、沉默优先、精确调度交给 cron。跑稳之后，Agent 会慢慢从一个工具，变成一个真的在值班的同事。
