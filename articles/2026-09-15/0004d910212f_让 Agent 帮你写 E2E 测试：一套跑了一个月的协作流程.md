## 背景

E2E 测试是工程团队里最“该做但总被拖延”的事：写起来慢、选择器脆、改版就挂。我们在 OpenClaw 上做了一个多月的实践：让 Agent 通过 MCP 操控浏览器、生成 Playwright 用例、失败后自我修复，人只负责审断言和合并 PR。本文记录这套流程和踩过的坑。

## 问题

直接丢一句“给这个页面写 E2E 测试”给模型，结果通常不可用：选择器靠猜、断言只检查元素存在、测试“永远绿色”。核心原因是 Agent 缺三样东西：真实的 DOM 上下文、执行反馈、项目约定。

## 做法

1. **接工具**：给 Agent 挂上浏览器控制的 MCP server（导航、截图、读可访问性树、执行 JS），再加一个“运行测试”的自定义工具，封装测试命令并返回精简后的失败输出。
2. **先探索再写**：要求 Agent 先遍历目标页面，产出选择器清单（优先 `data-testid`，退而求其次 role + 文本），落成独立的 selectors 文件。这个产物比测试代码本身更值钱。
3. **骨架 + 人工断言**：让 Agent 按 Page Object 模式生成用例骨架，断言留 TODO。人补业务断言——金额、状态流转这类逻辑别交给模型。
4. **失败回环**：用例挂了，把截断的报错和失败截图喂回去，限定最多 3 轮自修复，仍失败就停下出报告。
5. **进 CI**：Agent 产出以 PR 形式提交，走同一套 lint 和 flaky 检测，人工 review 后合入。

## 踩坑点

- **脆弱选择器**：Agent 很爱写 `div > span:nth-child(3)`。在项目约定里写死“必须用 data-testid”，违规直接打回。
- **弱断言**：`toBeVisible()` 一把梭等于没测，审查时重点看断言有没有业务含义。
- **死等**：模型喜欢 `waitForTimeout(3000)`。统一封装等待谓词，禁止裸等待。
- **flaky 误导**：偶发失败会让 Agent 做“玄学修复”（加等待、换选择器）。先手动跑 5 次确认稳定复现，再喂给它。
- **上下文膨胀**：别把整个 repo 塞进去，只给 selectors 文件、相关组件和一条示例用例。工具返回的报错也要瘦身，否则上下文很快被日志吃光。
- **环境安全**：Agent 拿到的是可执行权限，务必指向测试环境账号，生产数据只读。

## 可复用建议

- 把选择器规范和禁止事项写成一份 AGENTS.md 放仓库根目录，Agent 每次自动读到，比对话里反复强调有效得多。
- 轮次上限 + 人工兜底是硬约束，别相信“多跑几轮总会好”。
- 评估看用例可读性，别只看覆盖率数字。Agent 能把覆盖率从 0 拉到 60%，从 60 到 90 的硬骨头仍是人的活。

## 总结

Agent 写 E2E 的价值不在“全自动”，而在把它最擅长的脏活——遍历页面、写 Page Object、修选择器——接过去，让人专注断言设计和测试策略。工具接入、项目约定、失败回环、人工闸门，四件事配齐，这套协作就能长期跑下去。
