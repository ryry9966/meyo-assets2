## 背景

大部分 Agent 交互是拉式的：你发消息，它回答，会话结束就沉寂。OpenClaw 提供了一个 heartbeat（心跳）机制：agent 会按固定间隔自主醒来，读取工作区里的 HEARTBEAT.md，执行里面的检查项，必要时主动给你发消息。这个文件本质上是一份"值班手册"，让 agent 从被动问答变成定时巡检。

## 问题

没有心跳时，很多"该主动做"的事都靠人记着：服务器磁盘快满了、某个 git 仓库三天没动静、RSS 里有值得读的文章、每天早上该汇总一下待办。你可以写 cron 脚本，但脚本不懂语义，也不具备"判断要不要打扰你"的能力。heartbeat 的价值在于：把巡检逻辑写在自然语言里，由 agent 结合工具（shell、HTTP、MCP）执行，并自己判断"这事值不值得发消息"。

## 做法

1. 在 agent 工作区（默认 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`。
2. 用祈使句写检查项，明确四件事：做什么、什么条件算异常、异常时怎么办、没事时保持沉默。例如：

```markdown
# Heartbeat

每轮心跳：
- 检查磁盘：df -h，任一分区使用率 > 85% 才报告，否则不要发消息。
- 看一眼 ~/notes/inbox.md，若有新增待办，汇总成一行提醒。

每天（本地时区上午 9 点后的第一轮心跳）：
- 检查 OpenClaw 仓库最近 release，有新版本才提。

规则：没有值得报告的内容就静默结束，不要寒暄。
```

3. 通过环境变量控制节奏和成本：`HEARTBEAT_INTERVAL_MS` 调整间隔（默认约 30 分钟），`HEARTBEAT_TOKENS` 限制单次心跳的 token 上限，防止某项检查跑飞。
4. 修改 HEARTBEAT.md 不需要重启，下一轮心跳自动生效。

## 踩坑点

- **噪音是第一杀手。** 我初版写了七八项，agent 每轮都汇报一堆"一切正常"，最后只能静音。后来把"无事保持沉默"写成硬规则才解决。
- **别写模糊动词。**"关注一下"这种描述会让 agent 每轮都纠结；阈值和条件必须写死。
- **长任务和短间隔不匹配。** 某项检查要跑两分钟、间隔设 5 分钟，心跳就会堆积。按最慢的一项定间隔。
- **token 是持续开销。** 心跳按次消耗，项数多、间隔短时账单可观。建议先用长间隔（如 60 分钟）验证逻辑，再收紧。
- **时区问题。** 用"本地时区上午 9 点后第一轮"这类相对描述，别写死具体时间戳。

## 可复用建议

- 把 HEARTBEAT.md 当 runbook 写：每一项 = 触发条件 + 判定标准 + 动作 + 汇报格式。
- 分层管理：每轮必跑的放"每轮心跳"，低频任务用"每天/每周"约束，让 agent 往一个 state 文件记录上次执行时间。
- 结合 MCP 工具扩展检查项：RSS、日历、监控面板 API 都能变成心跳任务。
- 保持文件短小。每轮心跳都会读全文，无关内容都是成本。

## 总结

HEARTBEAT.md 的核心不是"定时执行脚本"，而是把判断权交给 agent：什么时候该说话，什么时候闭嘴。写好它只有两条工程习惯——**明确阈值、默认静默**。把它当成一份持续维护的值班手册而不是一次性配置，agent 才会真正成为主动的协作者。
