## 背景

我们社区需要定期产出内容：每周技术速递、新版本发布提醒、精华帖回顾。人工做了一段时间后发现两个问题：一是占用运营同学大量时间，二是产出质量不稳定、全看当天状态。于是尝试用 OpenClaw 搭一个发帖机器人，目标是**低频、高质量、可回滚**，而不是全自动刷屏。

## 核心问题

动手前先拆解清楚三个问题：

1. **内容从哪来？** 不能让模型凭空写，幻觉会直接变成社区事故。
2. **发到哪里？** 社区 API 有频率限制，对格式和标签也有硬性要求。
3. **谁来把关？** 全自动发布，等于把社区口碑交给一个采样温度参数。

## 架构与实施步骤

整体分五层，所有外部动作都封装成 MCP 工具，由 OpenClaw agent 统一调度：

- **采集层**：RSS、GitHub Release、论坛精华帖，封装为 `fetch_sources` 工具，输出结构化 JSON。
- **生成层**：agent 按模板生成草稿，prompt 中强制要求"所有数据必须来自工具返回值，禁止自行补全"。
- **审核层**：草稿先进队列，规则过滤（长度、敏感词、链接域名白名单），再人工过一遍。前两个月全量人审。
- **发布层**：社区 API 客户端，带 token bucket 限流、指数退避重试、失败落库。
- **观测层**：每次运行写一条记录（输入源、prompt 版本、草稿全文、发布状态），出问题可以回放定位。

## 踩坑实录

1. **幻觉链接**。第一版让模型"补全"参考链接，结果编造了不存在的帖子 URL。改法：链接只能从工具返回值中提取，且发布前逐条校验 HTTP 状态码。
2. **重复发帖**。定时任务异常重启后重复执行，同一主题发了两遍。解决：双层去重——标题哈希 + 向量相似度阈值 0.85，超阈值直接拦截。
3. **Cron 时区**。服务器是 UTC，读者在国内，"晚八点定时帖"实际在凌晨四点发出。同时要加文件锁，防止长任务被下一个 cron 周期叠加执行。
4. **内容质量漂移**。改了一版 prompt 模板后文风明显变油（疯狂堆感叹号），但没有量化指标能及时发现。后来给 prompt 加版本号，每周抽样三人盲评打分，低于阈值自动回滚到上一版。
5. **上下文超限**。采集源增多后 token 爆掉。改为先分源摘要再拼接，为生成环节预留固定预算。

## 可复用建议

- 外部动作一律封装成 MCP 工具，换平台只改工具实现，agent 逻辑不动。
- 从每周一篇起步，稳定跑满一个月再提频，别一上来追求日更。
- 必须留 **kill switch**：一个配置项能让整条流水线立刻停住。
- 所有生成物（包括被拒的草稿）落库，这是后续调 prompt 最有价值的数据集。
- 人审不是过渡方案，是长期兜底。自动化提升效率，但不免除责任。

## 总结

目前这个机器人每周稳定产出 1–2 篇速递，人审通过率从初期的 60% 提升到 90% 以上。最大的体会是：发帖机器人的难点不在"生成"，而在"约束"——限流、去重、校验、回滚，这些枯燥的工程细节才决定它能不能长期跑下去。建议有兴趣的同学从**只读不发**开始：先让 agent 每天产出草稿但不发布，观察两周质量，再谈自动化发布。
