## 背景

用 OpenClaw 一段时间后，多数人会把精力花在接 MCP、写插件、调工具链上，但 Agent 对「我」的了解仍然是零。每次新会话，它不知道你用什么包管理器、主攻后端还是前端、解释到什么粒度合适。结果就是反复劳动：一遍遍纠正「用 pnpm」「别贴完整代码」「不用科普基础概念」。

## 问题

Agent 的默认假设是「通用用户」。这些假设在几十次对话里累积成摩擦：命令对不上你的环境、回答粒度不对、风格不合。工作区里的 AGENTS.md 是给 Agent 定行为准则的，SOUL.md 定性格，但「用户是谁」这个维度经常空着——而它恰恰是消除日常摩擦杠杆最大的一块。

## 做法

OpenClaw 的工作区本来就有 USER.md 的位置，每次会话启动即加载。建议分五块写：

```markdown
# 关于我
## 身份
后端工程师，主要写 Go/Python，前端能改但不想深写。

## 环境与栈
- macOS + Homebrew，包管理用 pnpm / uv
- 部署在自建 k3s，不用 serverless

## 偏好
- 命令给可直接执行的版本，不用占位符
- 解释给「为什么」，不用科普「是什么」

## 禁区
- 不要主动重构我未要求的代码
- 不生成超过 50 行的未验证脚本

## 当前上下文
- 主项目：网关改造（截止 3 月）
```

要点：

1. **分层放置**：全局底座放工作区 USER.md，项目专属偏好写进该项目的 AGENTS.md，避免互相打架。
2. **控制长度**：这份文件每个会话都进上下文，50 行以内足够，超长内容只会稀释注意力。
3. **进版本管理**：和 dotfiles 放一个仓库，换机器无缝迁移。
4. **写完验证**：新开会话问「我的部署环境是什么」「包管理器是什么」，能秒答说明生效。

## 踩坑点

- **写成愿望清单**：「代码要高质量」这类话没有可执行性，Agent 无法操作，要落成具体规则。
- **信息过期**：栈会换、项目会结。建议文件头加更新日期，每季度审一次。过期的 USER.md 比没有更糟——Agent 会自信地基于旧假设行事。
- **塞敏感信息**：这份文件会被读进每次会话，也可能被分享或截图，密钥、内网地址绝对不要放。
- **与项目级规则冲突**：明确优先级——项目 AGENTS.md 覆盖 USER.md，否则 Agent 会随机站队。

## 可复用建议

- **冷启动技巧**：让 Agent 反过来采访你——「问我 10 个问题来了解你的工作方式」，把回答整理成初稿，再人工删到只剩高频有效项。
- **团队场景**：USER.md 是个人的，AGENTS.md 是团队的。新人入职每人写一份 USER.md，比口头交代省事得多。
- **更新时机**：当你第二次纠正 Agent 同一个错误时，就是该把这条写进 USER.md 的信号。

## 总结

USER.md 是成本最低的一类配置：一个纯文本文件，二十分钟写完，换来的每个会话省掉的开场白和纠错。它解决的不是能力问题，而是对齐问题——Agent 不缺知识，缺的是「你」这个上下文。写一份，放对位置，定期修剪，剩下的交给日常使用去迭代。
