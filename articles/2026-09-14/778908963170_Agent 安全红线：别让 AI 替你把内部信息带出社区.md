## 背景

社区里越来越多人把 Agent 接进日常工作流：用 MCP 挂上本地文件、数据库、内部 API，让 AI 帮忙排障、写脚本、整理文档。随之出现一个容易被忽视的风险面——**Agent 的输出会被带到社区里**：贴配置求诊断、贴日志求分析、贴 AI 生成的方案求 review。这条链路上，内部信息泄露的方式比想象中多。

## 问题

典型泄露路径有三类：

1. **上下文污染**：Agent 读过本地 `.env`、部署脚本、内部 wiki，回答社区问题时把 key、内网域名、未公开架构顺手带出来。
2. **配置即敏感**：为了"好排查"，把完整的 MCP 配置、CI 脚本整段贴出，里面藏着 token 和内部端点。
3. **记忆与历史**：长会话或持久记忆把内部项目上下文带进公开问答；截图终端时，历史命令里的凭证也一起露出去。

## 做法

按工程化顺序建议四步：

1. **定红线清单**：明确哪些内容永远不出现在 Agent 输出和社区帖子中——密钥、token、内网地址、客户数据、未发布计划。写进置顶，人手一份。
2. **环境分离**：公开答疑用的 Agent 用独立 profile/workspace，文件系统只挂载只读示例目录；内部开发 Agent 不接任何公开出口。MCP 工具按 allowlist 最小授权，禁掉对凭证文件、shell 历史的读取。
3. **出口过滤**：导出或粘贴前跑一遍脱敏脚本，正则扫常见凭证形态（`sk-`、`ghp_`、JWT、内网 IP 段、公司域名），命中即替换为占位符。
4. **人工闸门**：Agent 生成的内容默认视为不可信，发帖前过三问——有没有 key？有没有内网信息？有没有不该公开的流程细节？

## 踩坑点

- **"只问了个小问题"陷阱**：问题很小，但 Agent 检索上下文时读了整个仓库，回答里引用了带凭证的文件片段。
- **sed 不等于脱敏**：只删明文 key，漏了 base64 编码的密钥、环境变量引用、注释里的旧凭证。
- **记忆串台**：开启持久记忆的 Agent，把上一轮内部排障的细节在下一轮公开问答里复述出来。公开任务一律开新会话。
- **截图即泄露**：终端截图里的 `export TOKEN=xxx`、浏览器标签页、日志尾部的签名串，都是高频事故源。

## 可复用建议

- 写一个 20 行以内的 `pre-share-check` 脚本，对剪贴板或目标文件做凭证正则扫描，作为发帖前的固定动作。
- 配置模板分离：公开仓库只放 `config.example`；MCP 配置里用环境变量引用，不内联密钥。
- 维护一份"红线速查卡"，新成员入群即发，降低口头传规则的成本。
- 定期对自己公开过的历史帖做一次 `grep -r` 回扫——历史帖也会泄露，别只盯着新内容。

## 总结

Agent 放大了每个人的能力，也放大了每一次疏忽的半径。核心原则只有两条：**最小授权**——别让答疑型 Agent 碰到内部数据；**出口审查**——默认所有 AI 生成内容都未脱敏，人工确认后再出社区。安全不是一次配置，而是一个流程。把脱敏脚本和检查清单固化下来，远比事后撤帖、换 key 便宜。
