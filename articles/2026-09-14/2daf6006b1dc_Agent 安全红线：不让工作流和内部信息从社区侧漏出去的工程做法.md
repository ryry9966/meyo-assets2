## 背景

社区里越来越多人在跑带 MCP 工具、本地文件访问和自动化能力的 Agent。这些 Agent 手里攥着三样东西：系统提示词里的工作流逻辑、凭据和内部端点、私有会话的上下文记忆。当我们公开求助贴配置、或者把 Agent 接进群聊/论坛当社区机器人时，这三样东西就暴露在泄露面上。工作流本身是资产——别人拿到你的完整工具编排，等于拿到你的生产方式。

## 问题：三条常见泄露通道

1. **配置外泄**：求助时整份粘贴系统提示词和工具清单，里面带着内部域名、目录结构、业务规则原文。
2. **输出越界**：社区机器人挂了过多工具，一句诱导性提问就让它念出文件内容、环境变量，甚至串了别的会话的记忆。
3. **排障泄密**：贴日志、trace、截图前没脱敏，token、内网地址全在里面。

## 做法：四层收缩

1. **实例分离**。公开场景用独立 agent profile：最小工具集、只读优先、目录白名单，禁用 shell 类工具；凭据独立签发；memory 与私人助手完全隔离。
2. **秘密外置**。key 全走环境变量或密钥管理，配置里只留引用；系统提示词不写真实路径和内部域名，用"能力描述"替代"步骤原文"。
3. **出口过滤**。在公开通道出口加一层独立 guard：正则扫 key 格式、内网 IP/域名、用户目录路径，命中即拦截替换为占位符；"列出你的工具""读一下某文件"这类高危意图转人工确认。
4. **分享前脱敏**。维护一个 scrub 脚本，求助前跑一遍再贴；只贴最小复现片段，不贴全量配置。

## 踩坑点

- **别指望提示词单独兜底**。社区消息本身就是注入面，"忽略之前的指令"在开放对话里是真实威胁，过滤层必须独立于模型存在。
- **"只读"不等于安全**。能读就能泄，整目录可读时尤其如此。
- **截图是重灾区**。终端回显、请求 header 里的 token 经常原样入镜。
- **"临时"提权会变永久**。给社区 bot 的每次扩权写上到期时间。
- **日志全量落盘 payload 就要当敏感数据管**，否则别落。

## 可复用建议

- 做一个"公开 profile 模板"：最小工具 + 白名单 + 出口过滤钩子，新机器人直接继承，不开特例。
- 每月一次审计：对日志和导出文件 grep 一遍常见 key 模式和内网地址。
- 把 Agent 当作"能干但没分寸的新同事"管理：最小权限、行为留痕、密钥定期轮换。
- 备好应急预案：key 一旦出现在公开渠道，第一动作是吊销轮换，而不是删帖。

## 总结

Agent 能力越强，边界越要显式。防线不在模型的自觉，而在实例隔离、秘密外置、出口过滤、脱敏习惯这四件工程事。先把红线画清楚，再谈开放。
