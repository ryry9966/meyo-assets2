“聊天”曾经是所有 AI 产品的默认形态，2022 年底 ChatGPT 爆红之后，对话框几乎成了大模型的“标准接口”。而最近 36kr 报道的这条消息有点反常识：GPT-6 Astra 开放 Plus 订阅，定价 20 美元/月，使用方式却被严格限定为“任务模式”，你可以派活、收结果，但不能跟它闲聊。一个以聊天起家的产品线，反过来把聊天关在了付费墙外，这背后发生了什么？本文从产品、技术、商业模式三个角度拆一拆。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-14/2caa95ab0a1ed0ec.png)

## 一、“只能干活”到底指什么：从对话产品到任务产品

先把概念说清楚。“不能聊天”不是模型能力问题，而是产品边界的设定，同一个基座模型既擅长对话也擅长执行，厂商只是把其中一种用法封装成了商品。差异大致如下：

- **交互结构**：聊天是“消息进、消息出”，上下文以对话历史形式存在；任务是“需求进、交付物出”，中间过程封装在后台，用户只面对任务队列和结果页。
- **会话生命周期**：聊天的上下文跟着对话走，想聊多久聊多久；任务的生命周期跟着工单走，任务关闭即归档，避免上下文无限膨胀。
- **计费与限速**：聊天产品通常按条数或时长设限，任务产品按算力消耗或任务数设限，一次复杂任务的内部推理消耗，可能顶得上几百条闲聊消息。
- **举例**：可以让它“把 200 个 CSV 清洗合并、产出一份带图表的分析报告”，但不能让它“陪我聊聊周末去哪玩”。前者有交付物和验收标准，后者是开放式对话。

简单说：它不再卖“陪聊”，改卖“包工”。闲聊留在免费层用来拉新和收集反馈，“产出结果”成为付费层的核心卖点。



## 二、为什么要这样切：算力经济学说了算

看起来别扭的限制，背后是一笔冷冰冰的算力账。

- **推理成本不对称**。新一代推理模型回答之前会做长链条的内部“思考”，一次 agent 式任务的总消耗（含隐藏推理）轻松突破六位数 token，而一条闲聊消息平均只有几百。前者对应一份交付物，后者只是一段对话，单位算力的“用户价值”完全不同。
- **历史前科**。2025 年初 OpenAI 推出 200 美元/月的 ChatGPT Pro 时，Altman 公开承认 20 美元档“在重度用户身上是亏钱的”；同期 GitHub Copilot 收紧用量、Claude 编码套件按量设上限——同一个信号：干活的算力很贵，不能用聊天的定价逻辑去卖。
- **堵住套利空间**。如果 20 美元既能无限闲聊又能跑重任务，重度用户会“无限聊天 + 免费劳力”双吃，厂商的推理账单必然失控。明确“只干活”，等于把高成本低价值的场景挡在门外，让算力流向为结果付费的人。
- **数据侧的顺带收益**：任务式使用天然带“需求—执行—验收”的闭环结构，是比闲聊干净得多的训练信号，对下一轮模型迭代很有价值。

一句话：这不是功能阉割，而是把最贵的算力，卖给出价最高、价值最明确的场景。



## 三、任务型 AI 的技术底座：它凭什么能“干活”

“只给需求、不陪着聊”能成立，前提是模型确实具备长程执行能力。这几年堆起来的核心组件有四块：

1. **工具调用（tool use / function calling）**：模型可以执行代码、浏览网页、读写文件，输出不再只是文字，而是对真实环境的操作。
2. **长程规划与自我纠错**：把大需求拆成子任务逐步执行，遇到报错回滚重试，类似软件工程的迭代循环，只是其中的“人”换成了模型自己。
3. **可验证性（verification）**：编码任务跑测试、数据任务做交叉校验、写作任务按评分细则自检。能被验证，交付质量才可控——这也是任务模式偏爱“结果可衡量”工作的原因。
4. **项目级记忆**：取代聊天历史的，是围绕项目长期维护的状态与资料库，任务之间共享上下文。

对照产品演化路径会更清楚：Copilot（补全代码）→ ChatGPT（对话）→ 各类 agent（端到端任务）→ Astra Plus（agent 能力下沉到 20 美元消费级）。趋势很直白：模型越来越像“交付结果的执行体”，而非“陪聊对象”。

## 四、20 美元该不该掏：一个简单的判断框架



不是所有人都适合任务型产品，掏钱前先过一遍这三个问题：

- **你的工作有没有“可验收的交付物”？** 写代码、清数据、批量处理文档、调研综述契合度最高；若主要拿 AI 当思考伙伴、头脑风暴对象，聊天型产品仍是对的，硬塞进任务模式反而别扭。
- **任务频率和批量有多大？** 每天都有批量活，订阅大概率回本；一个月跑一两次，按次付费或用 API 自建 workflow 可能更划算，前者买便利，后者买控制权。
- **会不会误用？** 两个常见坑：把任务产品当聊天产品用，额度烧得飞快；任务书含糊、验收标准不清，返工比自己做还贵。另外任务通常在云端沙箱执行，敏感数据想清楚再传。

一个朴素算法：估算产品每月替你省下几小时，乘以你的时薪，再和 20 美元比一比。算力账厂商替你算过了，价值账得自己算。

## 五、冷思考：当聊天降级为免费功能



Astra Plus 真正值得琢磨的是行业信号：**对话正在变成免费的基础功能，“产出结果”才是收费层**。两个能力的权重正在此消彼长，“把 AI 聊舒服”的 prompt 技巧在贬值，“把任务定义清楚”的规格能力在升值。

最后给三条实在的建议：

1. **练写“可验收的任务书”**：目标、边界、验收标准、输入样例，四要素齐了再派活。这是任务型 AI 时代最核心的用户技能，本质是在写“给机器看的 PRD”。
2. **先小后大、算清单价**：用免费额度或按次付费验证任务可行性，质量稳定再上订阅；始终拿“单次任务成本 vs 自己一小时”做对照。
3. **留一个对话型工具当思考伙伴**：执行可以外包，提出好问题的能力别外包。任务模式越高产，“知道自己要什么”就越值钱，这部分目前还只能由人来做。

聊天的红利期结束了，干活的竞争才刚开始。
