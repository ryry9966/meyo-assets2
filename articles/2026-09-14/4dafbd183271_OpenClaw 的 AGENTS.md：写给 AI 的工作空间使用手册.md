## 背景

OpenClaw 的工作区里有一组约定文件：SOUL.md 管人格，IDENTITY.md 管身份，TOOLS.md 管工具说明，而 AGENTS.md 管的是**操作规程**——agent 每次启动、每次心跳、每次写记忆时该怎么做。它本质上是写给模型的运行手册，不是写给人的 README。

模型本身是无状态的。你今天调好的行为，明天换一个会话就可能走样。AGENTS.md 的作用，就是把那些“你理所当然认为它知道”的上下文固化下来。

## 问题

没有 AGENTS.md，或写得很差时，常见的翻车方式：

- agent 把中间产物随手写到工作区根目录，几周后文件堆成灾
- 记忆文件无限膨胀，每次启动都要吞几千 token，响应变慢
- 心跳任务重复执行，或者干脆不执行
- 每个新会话你都得重复交代同一套规矩

## 做法

我的工作区 AGENTS.md 稳定在 60 行左右，分五块：

1. **启动清单**：开机先读哪些文件（MEMORY.md、USER.md），按什么顺序
2. **记忆纪律**：什么值得写入 memory（长期偏好、项目状态），什么不值得（一次性问答）；memory 按日期分文件，避免单文件无限追加
3. **文件系统约定**：临时产物一律进专门的 scratch 目录，工作区根目录只放长期资产
4. **心跳行为**：心跳时检查什么（新消息、定时任务、是否需要 checkpoint），无事可做就直接结束，不硬找活干
5. **沟通边界**：哪些事必须先确认（删文件、对外发消息），哪些可以自主决定

写法上有个关键原则：**每条指令都要“可判定”**。不要写“保持工作区整洁”，要写“临时文件一律写入 /workspace/scratch，超过 7 天可清理”。

## 踩坑点

- **写太长**。我第一版写了 200 多行，实测 agent 对中后段指令的遵守率明显下降。砍到 60 行、只留高频踩过的坑之后，情况立刻好转
- **职责重叠**。同一件事在 AGENTS.md 和 SOUL.md/TOOLS.md 里都写、措辞还不一致，模型会随机挑一个执行。原则：AGENTS.md 只管流程，不管性格和工具参数
- **写完不迭代**。这是份活文档。我的习惯是：agent 每犯一次让你不爽的错，先问“能不能固化成一行规则”，能就加进去，同时删掉已不再触发的老规则
- **只有正面要求、缺少反例**。模型对“不要做 X，应做 Y”这种结构的遵守率，明显好于单纯一句“请做 Y”

## 可复用建议

- 把 AGENTS.md 纳入 git，每次修改写清动机——它就是你 prompt 工程的 changelog
- 每月通读一遍，删掉从未触发过的规则。规则条数是稀缺资源，别浪费在低频场景
- 新起一个 agent 实例时，让它先复述 AGENTS.md 的关键约束，验证加载链路真的生效
- 团队场景下把“个人偏好”和“项目规程”拆开，后者做成模板，跨工作区复用

## 总结

AGENTS.md 的价值不在文采，而在于把你反复口头交代的经验，压缩成模型每次都会读到的一页纸。它是你和 agent 之间的接口契约——接口越明确，系统行为越可预期。建议从最小版本起步：启动清单、记忆纪律、文件约定三块先跑起来，再用真实的翻车记录慢慢喂它。一个月后回头看，你会发现自己口头交代的次数明显变少了。
