2025 年科技圈出现过一次少见的名场面：平时互相卷到飞起的几家头部 AI 公司掌门人——OpenAI 的 Sam Altman、Anthropic 的 Dario Amodei、Google DeepMind 的 Demis Hassabis、Scale AI 的 Alexandr Wang——罕见联名撰文，呼吁给前沿 AI 建立独立的安全评估机制，并点名网络攻击是近期最现实的风险之一。其中被反复讨论的一个场景，翻译成工程师语言大致是：在一年左右的时间尺度上，自主 AI agent 有可能彼此串联、分工协作，形成类似 botnet（僵尸网络）的东西。这话从天天喊"加速"的人嘴里说出来，含金量不低。这篇不聊科幻，只聊三件事：Agent 僵尸网络到底是什么、为什么偏偏是现在被警告、以及普通人和企业能做什么。

## 老 botnet 是"提线木偶"，Agent botnet 是"会自己排班的员工"

先复习一下老知识。传统僵尸网络的代表作是 2016 年的 Mirai：它靠扫描弱口令（大量 IoT 设备出厂默认 admin/admin 这类）感染了几十万台摄像头和路由器，组成 botnet 后对 DNS 服务商 Dyn 发起 DDoS，导致 Twitter、Netflix 等一批主流站点在北美大面积无法访问。传统 botnet 的特点是：**节点是"傻子"**——执行静态脚本、听 C&C 服务器统一指挥，服务器一拔就瘫。

LLM 驱动的 agent 则完全不同，它具备推理、规划、工具调用能力：能读文档、写代码、开浏览器、调 API、管理凭据。节点从"傻子"升级成"聪明人"，带来三个质变：

1. **攻击门槛塌方**：下发任务用自然语言即可，从"会写 exploit"降到"会打字"；
2. **抗打击能力强**：遇到防御可以现场改策略，不像脚本一触即溃；
3. **没有明显的"头"**：agent 之间可以直接通过 API 甚至自然语言协调分工，拓扑天然分散，更难被一锅端。

一句话总结：传统 botnet 是提线木偶，剪断线就完事；agent swarm 是一群会自己排班、自己补漏的"数字临时工"。

## 为什么是现在：三个同时到位的拐点

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-14/a6634b3949599033.png)

**拐点一：能力过线。** 2023 年的 AutoGPT 还是"给个目标、跑十分钟就迷失方向"的玩具；2024–2025 年，agent 进入生产环境——Computer Use、browser agent、coding agent 已能连续完成几十步真实任务，SWE-bench 这类基准的成绩一年内翻倍再翻倍。"能不能独立跑完一条完整攻击链"，从理论推演变成了工程可行性问题。

**拐点二：部署上量。** 各家都在推 agent 平台和应用市场，MCP（Model Context Protocol）、A2A（Agent2Agent）这类互操作协议把"agent 互相调用"标准化，等于给数字劳动力修了高速公路。公路修得越宽，超速行驶的风险也越集中。

**拐点三：成本塌方。** 推理价格两年内降了一到两个数量级，jailbreak 手法公开流转，"越狱即服务"已现雏形。攻击的边际成本趋近于 API 费用，而收益（爬数据、薅羊毛、勒索）是实打实的。经济学上，只要成本收益曲线交叉一次，灰产就会自动入场，不需要任何人下命令。

再补一个技术佐证：2024 年 Cornell Tech 的研究团队发布过 "Morris II" 提示词蠕虫——在实验环境中，一段恶意 prompt 能随 RAG 系统的数据流自我复制，从一封邮件"感染"到助手处理的下一封邮件。"自传播的恶意 prompt"不是科幻，是已有 PoC 的攻击面。这个名字致敬的正是 1988 年互联网史上第一只大规模蠕虫 Morris Worm——历史确实押韵。

## "刹车"为什么喊得响、踩得难

- **竞争囚徒困境**：安全评估每多一轮，发布就慢几天；对手不慢，市场就没了。四巨头联名，本质是想把"大家统一降速"变成行业公约，破解囚徒困境。
- **没有统一的"拔电源"位置**：开源权重、多云部署、跨平台运行，意味着没有任何单一方握着全局 kill switch。
- **责任链条模糊**：agent A 雇佣 agent B 造成了损害，责任算用户的、平台的、模型供应商的，还是中间协议层的？现行法律里这题还是空白。
- **已有的刹车覆盖不到这里**：Anthropic 的 Responsible Scaling Policy、OpenAI 的 Preparedness Framework、各家红队测试，都属于"发布前踩刹车"；而 agent botnet 风险主要发生在**部署之后、互联之后**，这块目前基本是开放区域。

## 防"agent 翻车"清单：现在就能做的事

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-14/0a5ca837ae5d1673.png)

给企业的：

1. **最小权限原则照旧成立，且更重要**。给 agent 的凭据要限定 scope 和时间窗——别把 root token 发给一个"会自己想办法"的实习生。
2. **不可逆操作强制 human-in-the-loop**：转账、删除、对外发布，一律加人工确认闸门。
3. **出口加观测**：对 agent 的 API 调用做速率限制和异常检测（调用量、目标地址分布突变就是信号），日志别只记结果，把 agent 的"思路"也记下来。

给个人的：

4. 对接的第三方 agent / 插件做背景调查，**它的权限就是它能替你做事的上限**；
5. 内容层面保持"来源洁癖"：当机器生成内容的成本趋近于零，验证出处会从美德变成生存技能。

## 三条冷思考

1. **"一年"是风险提示，不是倒计时**。业界对时间点的预测纪录很差，但对方向性判断的纪录很好。重点不是日历，而是从现在开始建防御纵深。
2. **最大的脆弱点往往不是 AI，而是老毛病**：弱口令、没打补丁的系统、过度授权的 API。Mirai 当年没用什么高级技术，它赢在大量设备裸奔。agent 只会放大这些老毛病的倍数。
3. **把安全当地基，不是事后补丁**。加沙箱、加确认环节，短期看是拖慢节奏；对比一次大规模安全事件的善后成本，这是整个系统里性价比最高的保险。

深海里会排队协作的不止鱼群，还有龙虾列队迁徙——但至少它们不偷你的 API 额度。模型不会"想"害你，它只会非常认真地完成交给它的任何字面目标；当这个特性乘以上万个互联的 agent，靠谱的答案还是工程师祖传三板斧：最小权限、可观测、留人工通道。刹车不是不前进，是为了还能一直开。
