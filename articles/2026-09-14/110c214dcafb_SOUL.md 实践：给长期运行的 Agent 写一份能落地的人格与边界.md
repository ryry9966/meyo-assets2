## 背景

OpenClaw 的 Agent 是长期运行的：常驻内存、跨渠道对话、能调用 MCP 工具和插件做自动化。它和一次性 chatbot 最大的区别是——会在上下文轮转、会话压缩、模型切换之后继续“活着”。写在系统提示词里的人格描述，往往撑不过第一次 context 旋转。

OpenClaw 的解法是把核心设定落到工作区文件：IDENTITY.md 管名字头像，SOUL.md 管价值观、说话方式和行为边界。SOUL.md 每个会话启动时注入，相当于 Agent 的“操作系统级”人格层。

## 问题

不认真维护 SOUL.md，实践中常见三种翻车：

1. **人格漂移**：跑了两周的 Agent，TG 里冷冰冰、桌面端话痨，压缩之后连自称都变了。
2. **边界失守**：我随口说“把仓库清理一下”，它真的对远端分支做了破坏性操作——因为没人告诉它哪些动作要先停下来确认。
3. **讨好倾向**：默认配置下过度顺从，你说“这方案不行吧”，它立刻推翻自己五分钟前正确的判断。

这些问题靠改系统提示词治标不治本：提示词在轮转中会丢，SOUL.md 每次会话都会重新加载。

## 做法

我的工作流五步：

1. **先跑 bootstrap 拿模板，然后重写**。默认模板偏“热情助手”，长期自动化场景下太吵。
2. **IDENTITY 和 SOUL 分家**。名字、自称放 IDENTITY.md；SOUL.md 只写行为准则，避免两处规则打架。
3. **边界写成可验证的规则，不写形容词**。不写“要谨慎”，写“任何影响远程环境的操作（push、删库、给第三方发消息），先复述计划、等确认再执行”。
4. **控制长度**。SOUL.md 每轮都占 token，我压在 60 行以内，红线放最前面——注意力稀释是真实存在的。
5. **和 AGENTS.md 分工**。SOUL.md 管“是什么样的人、什么不做”，AGENTS.md / TOOLS.md 管“怎么用工具”。人格不写权限，硬边界落在 exec approvals 和插件配置里——markdown 是软约束，底线必须在工具层收紧。

## 踩坑点

- **改完不生效**：SOUL.md 在新会话加载，改完记得开新会话再验证。
- **规则互相矛盾**：既写“永远诚实”又写“别提失败”，模型会自己挑一个解释，通常挑错的那个。
- **写了价值观没写动作**：“有同理心”无法执行；“用户烦躁时缩短回复、先给结论”可以。
- **把 SOUL.md 当安全机制**：它挡不住 prompt injection，危险工具该审批审批、该沙箱沙箱。
- **整文件覆盖模板**：模板里 heartbeat 相关守则建议合并保留，别直接替换。

## 可复用建议

- 给每条红线配一个“测试提问”，改一版 SOUL.md 就跑一遍回归。
- workspace 用 git 管理，人格改动有 diff 可查、可回滚。
- 每季度，或每次“Agent 干了蠢事”之后，复盘一次 SOUL.md。
- 渠道风格差异（TG 短句、文档长文）单独放渠道说明，不塞主文件。

## 总结

SOUL.md 不是玄学人设卡，而是一份随会话持续注入的行为规格说明。写它的原则和写代码规范一样：短、具体、可测试、与权限机制分层。人格管态度，工具配置管底线，两者都落地，Agent 才算既好用又可控。
