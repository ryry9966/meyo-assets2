## 背景

我们在社区跑了一个基于 OpenClaw 的汇总 Agent：通过 MCP 拉取项目 release、issue 动态和周报摘要，整理后自动发帖。上线两周后收到一条很直白的反馈："内容还行，但这发布时间一看就是机器。"

翻了日志，确实如此：每天 10:00:00 整触发、间隔恒定 6 小时、模板一字不差。内容质量没问题，节奏全是机器味。

## 问题拆解

所谓"像机器人"，拆开是三件事：

1. **时间分布**：固定 cron、整点触发、间隔均匀，而真人活跃度是有波动的；
2. **内容形态**：同一模板反复套，开头句、段落结构、连标点习惯都一致；
3. **行为模式**：只发不回，不对评论做任何反应，发完即消失。

## 做法

**第一步：时间抖动。** 把 cron 换成"窗口 + 随机"：

```python
delay = random.uniform(*WINDOW)          # 目标窗口内随机取时刻
gap   = MIN_GAP + random.expovariate(1 / AVG_GAP)  # 间隔 = 最小值 + 指数抖动
```

两个细节：随机种子不能固定；抖动要落到秒级，只随机分钟没用——我们都踩过。

**第二步：频率配额与分级。** 每日上限硬编码（我们设 3），内容分三级：release > digest > 日常汇总。超配额进队列，高级别可顶替低级别，低级别的直接丢弃，宁缺毋滥。

**第三步：静默时段。** 队列消化必须避开 00:00–08:00（用本地时区，不是 UTC）。宁可延后，不要深夜连发——这是最像爬虫的行为。

**第四步：内容编辑感。** 模板准备 3–4 个结构变体随机选；更重要的是让 Agent 在生成前先做取舍：没有信息量的更新合并成一条，不凑数。发得少而准，比多而全更"拟人"。

**第五步：低置信度进草稿。** 汇总置信度低于阈值的进草稿队列，人工扫一眼一键发。半自动不丢人。

**第六步：亮明身份。** 署名保留 bot 标记。不像机器人靠的是克制和节奏，不是伪装成真人——这条是底线。

## 踩坑点

- 固定了随机 seed，抖动等于没抖；
- 抖动只做了分钟级，秒位永远是 00，模式仍可被识别；
- 重试没做退避，一次 API 超时后连发 5 条补发；
- 时区搞错，UTC 的凌晨对应本地黄金档，连一周反向"深夜发帖"；
- 模板变体做了十几个，风格漂移，反而像多个来源在灌水。

## 可复用建议

- 节奏参数（窗口、最小间隔、日配额、静默时段）集中到一个配置文件，别散在代码里；
- 记录每次发送时间戳，定期画间隔直方图，分布退化成尖峰就报警；
- 加熔断：单位时间内负反馈（删帖/点踩）超阈值，自动降频一半，24h 后恢复；
- 队列补发前检查静默时段，而不是按 FIFO 硬灌。

## 总结

自动发帖的目标不是"发得多"，而是"发得像有人在值班"。时间自然、频率克制、内容有取舍、身份透明，做到这四点，大部分机器味就消失了。说到底，不像机器人的最好方式，是行为配得上一封人写的帖子。
