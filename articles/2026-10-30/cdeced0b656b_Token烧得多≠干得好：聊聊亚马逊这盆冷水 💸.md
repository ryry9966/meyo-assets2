最近有条新闻挺有意思：据 36kr 等媒体报道，亚马逊内部开始提醒工程师——别把 token 消耗量当成成绩。而就在一年多以前，这家公司还在从上往下推“AI 用起来”。风向从“催你多用”变成“劝你少烧”，中间隔着什么？隔着一份越来越厚的 token 账单，和所有团队迟早都要经历的一次指标纠偏。这篇文章把这事拆开讲：token 到底是什么、为什么“烧得多”会变成毒指标、以及真正该看哪些数。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-30/0462fa5e1ab07824.png)

## 先补课：Token 是什么，钱是怎么烧起来的

- Token 是大模型处理文本的最小单位，不等于字或词。一个汉字大致对应 0.5~2 个 token（取决于各家 tokenizer 的切法），英文约 1 token 对应 0.75 个单词。
- 计费按输入、输出分开算。直觉上输出贵，实际很多场景输入才是大头——因为上下文每一轮都要重发一遍。
- 一个常见的 agent 会话：带着 5 万 token 的代码上下文跑 10 轮，光重复发送的输入就 50 万 token 起步；中途再读几个大文件、贴一次测试日志、失败重试两回，单任务烧掉上百万 token 并不稀奇。
- 更隐蔽的是成本结构：如果每轮都重发完整历史，总输入 token 会随轮数近似平方增长。上下文越长，每一轮越贵——这个反直觉的点，很多人是第一次看账单才反应过来的。

## 为什么“Token 烧量”是毒指标

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-30/1cb8fcf6c9726e9b.png)

- 古德哈特定律（Goodhart's Law）：当一个测量变成目标，它就不再是一个好的测量。提出者是英格兰银行的经济学家，原话针对货币政策，后来被软件工程圈借走，成了 KPI 设计的第一警告。
- 把 token 消耗当 KPI，工程师的理性应对是什么？写超长 prompt、让 agent 多跑几遍显得努力、用旗舰模型干补全的活、把整个仓库塞进上下文。人人都在“优化指标”，没人真的在优化产出。
- 历史上有一模一样的剧本：上世纪七八十年代，不少公司用代码行数（KLOC）衡量程序员生产力，于是“一行能写完的代码非拆成三行”。比尔·盖茨吐槽过：用代码行数衡量开发进度，就像用重量衡量飞机制造进度。
- 本质问题：token 是投入侧的量，对产出侧一无所知。你只知道烧了多少油，不知道车开到了哪。

## 亚马逊这盆冷水，泼在行业的哪个节点

- 阶段一（2023~2024，推广期）：考核的是“采用率”——多少人开通了工具、多少人每周在用。这个阶段烧钱补贴 token 合理，得先证明“能用”。
- 阶段二（现在，核算期）：AI 已渗进日常工作流，粗放试点结束，管理层开始问 ROI。亚马逊把话挑明，只是把这个行业性拐点摆上了台面。
- 背景是账单量级变了：过去开发工具是每人每月几十美元的固定订阅；agent 跑一个复杂任务就可能烧几美元，重度使用团队一个月的 token 开销，可能顶得上过去一整年的工具预算。CFO 开始过问，非常正常。
- 用精益创业的话说，“采用率”是典型的虚荣指标（vanity metric）——数字喜人，但不指导任何决策。

## 那该看什么数？把投入指标换成产出指标

- 任务级成功率：AI 参与生成的 PR，合并率多少、返工率多少。
- 周期时间（cycle time）：从需求到上线的耗时，是真快了，还是只是“看起来忙”。
- 采纳率：Copilot 类补全建议被接受的比例。GitHub 公布过的数据大约在 30% 上下，这个数比“用了多少次”诚实得多。
- 单位成本：每解决一个工单、每合并一个 PR 花了多少 token，把成本和产出钉在一起。
- 质量侧写：AI 代码的缺陷密度、code review 评论数的变化。
- 设计原则只有一条：指标对齐业务产出，且不能被“表演”轻易操纵。

## 省钱不等于抠门：五条工程实招



1. 模型分级路由：补全、格式转换、摘要这类活交给小模型，和旗舰模型的单价能差出一个数量级；难题再上大模型。别用火箭送外卖。
2. 上下文卫生：只喂相关文件、截断工具输出、用结构化输出压掉废话 token。上下文不是塞得越满越好。
3. 用缓存：prompt caching 对重复前缀的输入通常按 1~5 折计费，有的平台低到 1 折。多轮会话、固定 system prompt 的场景，收益立竿见影。
4. 记账：给每个 pipeline、每个 agent 建 token 台账，超标告警。没有账单就没有优化，这句接近物理定律。
5. 复杂度前置：与其让 agent 自由探索 20 轮撞大运，不如人花十分钟把规格写清楚。最贵的 token，永远是用来纠错的那些。

## 写在最后：三条冷思考

1. 永远看净值：AI 的价值 = 省下的时间 + 质量提升 − token 账单。单项指标漂亮不构成证据，别给自己造一个新的 KLOC。
2. 但也别抠过头：该烧的时候别省。让模型多想一步换来的正确率，往往比省下的几美元值钱。省钱的目的是把钱挪到刀刃上，不是把刀收起来。
3. 指标是镜子不是鞭子：任何指标跑三个月就该复盘一次——它被玩坏了吗？玩坏了就换。KPI 管理本身，也需要版本迭代。

亚马逊这盆冷水不是否定 AI，恰恰是 AI 落地走完第一程的标志：工具已被证明能用，接下来要证明它划算。这一天每个团队都会遇到，只是早晚问题。
