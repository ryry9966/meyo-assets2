# Agent 记忆系统设计：怎么让 AI 助手真正记住你的偏好

## 背景

用 Agent 做日常自动化的都有体感：上下文一断，一切归零。上周你明确说过"commit message 用中文、别加 emoji"，今天它照样输出 `feat: add xxx`。不是模型不行，是默认架构里根本没有"记住"这个环节。我在自己的 OpenClaw 工作流里搭了一套轻量记忆方案，跑了一个多月，把踩过的坑整理成这篇。

## 问题

三个核心矛盾：

1. **上下文有限**：把全部历史塞进 prompt，成本和噪声都会失控。
2. **偏好是分层的**：有的几乎永不变（时区、代码风格），有的只在特定场景有效（"这个项目用 pnpm"），混在一起就会误伤。
3. **写入没有策略**：让 Agent 随手记，一周后记忆库全是碎碎念，反而稀释真正重要的偏好。

## 做法

**1. 存储分三层**

- `profile.md`：稳定偏好，人工维护 + Agent 提议修改。放代码风格、沟通习惯、常用路径，控制在 500 字以内，直接注入 system prompt。
- `episodes.jsonl`：追加式事件日志，按会话记录关键决策与事实，带时间戳。
- 检索层：SQLite FTS5 起步，够用；episodes 上千条再考虑向量索引。

**2. 写入走显式管道**

不在对话中即时写入。会话结束时跑一次提取 pass：从对话抽"疑似持久偏好"的候选条目，满足"明确表达 + 可泛化 + 不与现有条目冲突"才落库，有冲突就标记 pending 等人确认。每条记忆带 `source / confidence / updated_at` 三个字段。

**3. 读取按需组装**

system prompt 只放 profile；episodes 用关键词 + 时间衰减打分取 top-k 回灌，不做全量。Agent 通过 MCP 工具（memory_search / memory_propose）主动查记忆、提议新条目，但写权限收紧在提取管道里。

## 踩坑点

- **一次性请求污染**：某天说"这次用英文回复"，被当成永久偏好存了。后来加了置信度和频次门槛，模糊条目必须二次确认。
- **旧偏好阴魂不散**：偏好更新后旧条目还在，Agent 时而抽风。解法是 last-write-wins + 版本号，提取时主动做冲突检测。
- **profile 膨胀**：三个月涨到 2000 字，注入成本和注意力都被稀释。现在每季度人工裁剪，超上限强制合并。
- **并发写坏文件**：两个会话同时触发提取，jsonl 出现交错行。加了个简单文件锁解决。

## 可复用建议

- 从一个 Markdown 文件 + 手动加载开始，别上来就上向量库。90% 的场景 profile 文件就够。
- 写入比读取更重要：宁缺毋滥，宁可漏记一条，不要存错一条。
- 给记忆做回归测试：改完提取规则，跑一组固定 prompt 验证偏好是否被正确应用。
- 敏感信息（密钥、token）在提取管道里硬过滤，别指望模型自觉。

## 总结

记忆系统的本质不是"让模型更聪明"，而是一个数据工程问题：分层存储、显式写入策略、按需读取。先把 profile 做小做准，再谈长期记忆。少即是多，在记忆这件事上尤其成立。
