## 背景

用 OpenClaw 这类常驻型 Agent 跑了段时间后，常见的一个现象是：模型、插件、工具链都没问题，但输出总差点意思——时区算错、commit message 风格不对、回复啰嗦，每次新会话都得重新交代一遍背景。

问题不在模型能力，而在上下文分工：Agent 知道怎么干活（AGENTS.md 管），知道自己是谁（SOUL.md / IDENTITY.md 管），唯独不知道**它是在为谁干活**。这些信息散落在聊天记录里，会话一重置就归零。

USER.md 就是补这块的：工作区里一个普通 Markdown 文件，每次会话启动时随系统提示加载，用来稳定描述"用户是谁"。

## 怎么写

核心原则：**只写会改变 Agent 行为的事实，不写简历。**

建议分五块，整体控制在 1–2 KB：

```markdown
# 用户档案
## 基本信息
- 时区：Asia/Shanghai；工作语言中文，技术术语可用英文
## 环境
- 主力机：macOS + Homebrew；代码统一放 ~/dev/
## 偏好
- 回复默认不超过 5 行；commit message 用英文祈使句
- 讨论方案先给结论，再给 1-2 个备选
## 当前项目
- xxx：负责后端，合作者 A/B
## 禁区
- 不要自动 git push；22:00 后不发非紧急通知
```

两个要点：

1. **偏好要写成可执行规则**。"回复简洁点"是无效输入，"默认不超过 5 行"才是 Agent 能稳定遵守的。
2. **和 MEMORY.md 分工**。USER.md 放稳定事实（时区、技术栈、禁区），MEMORY.md 放滚动事件（这周在改什么、临时约定）。截止日期这类短期信息混进 USER.md，很快过期变成噪音。

## 维护节奏

把它当成配置文件里的 `.editorconfig`，而不是一次成型的文档：

- 同一件事纠正 Agent **两次以上** → 当场写进 USER.md
- 每月删一次过期条目；换机器、换栈当天更新
- 新会话里问一句"你现在了解我什么"，验证加载是否生效

## 踩坑点

- **写太长**。这个文件每个会话全量进上下文，2 KB 是比较稳的上限。塞三千字个人简介，关键条目反而被稀释。
- **混入敏感信息**。密码、API key、真实住址不要写。文件会随工作区同步、可能随诊断日志导出，秘密只放该放的地方。
- **越界写 Agent 的指令**。"必须用 pnpm"这类是 AGENTS.md 的事，两个文件混写，后面没法维护。
- **只增不删**。半年不清理，过期的路径和下线的项目会持续误导 Agent。

## 可复用建议

- 一句话判断标准：**凡是口头对 Agent 说过第二遍的事，就值得进 USER.md**。
- 多设备使用时，把工作区放进同步盘，USER.md 天然成为跨设备的"用户态配置"。
- 团队/家庭共用实例，按人拆分（user-alice.md 之类）并在入口文件里指明映射，别共用一份。

## 总结

USER.md 的价值不在单次对话，而在复利：Agent 犯的每个错，纠正一次就固化一次，三个月后它会比你预期的更"顺手"。本质上，这是给自己建一份最小可行的用户画像——成本约一小时，回报摊在之后每一次会话里。
