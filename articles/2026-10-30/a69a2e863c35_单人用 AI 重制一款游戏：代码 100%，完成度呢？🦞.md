最近 36kr 报道了一个很有代表性的案例：一位开发者独自一人，用 OpenAI 的 Codex 让 AI 写下 100% 的代码，完整重制了一款经典游戏，并把过程细节公开分享。评论区照例两极分化，有人说“AI 程序员正式上岗”，有人说“不就是高级套壳”。抛开情绪，这件事真正值得看的是方法论：一个人加一个 agent，到底怎么把一个游戏从想法推到可玩？它证明了什么，又没证明什么？这篇把它拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-30/98e9919ba793f19d.png)

## 为什么“重制老游戏”是 AI 编程的完美靶场

用 AI 做软件开发，最怕的不是代码写不出来，而是“需求说不清楚”。重制一款老游戏，恰好绕开了这个死穴：

- **规格现成**：玩法、关卡、数值、界面早就冻结在原作里，等于自带一份完整的验收标准。AI 不用猜你想要什么，照着原版“抄作业”就行。
- **输出可验证**：逻辑对不对，跑一把就知道；碰撞穿模、掉帧、存档丢失都是清晰可判的 bug。AI 最大的毛病是幻觉，而有明确参照系的任务，幻觉最容易被抓住。
- **体量可控**：一款 8-bit / 16-bit 时代的游戏，逻辑代码通常在几万行以内，正好落在当前 agent 的能力射程内。

把时间轴拉长看，这是一条清晰的能力阶梯：2021 年 GitHub Copilot 上线，AI 开始补全函数；2023 年 GPT-4 演示了现场写 Pong；2025 年 Karpathy 提出 vibe coding，Codex、Claude Code 这类 agent 开始接管“任务级”开发。重制老项目，正是这个阶梯上第一个能拿出完整成品的场景。

## Codex 到底在干什么：从“副驾”到“外包团队”

很多人对 AI 编程的印象还停留在自动补全，但 Codex 这类 agent 是另一种工作模式。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-30/2ae4c7661d9174d4.png)

1. **传统 Copilot 模式**：你打字，AI 补下一行。决策权在人，协作单位是“行”。
2. **Codex 模式**：你派一个任务，它在云端沙盒容器里 clone 仓库、读代码、改文件、跑测试，最后交回一份可供 review 的 diff。协作单位变成了“任务”。
3. **几个关键机制**：隔离环境（不污染主分支）、多个任务并行跑、AGENTS.md 之类的项目级说明书（告诉 agent 本仓库的规矩）、用测试结果自我验证、不合格就自己重试。

打个比方：以前 AI 是副驾，方向盘始终在你手里；现在它更像一支外包小团队——你变成了甲方、架构师和验收员三合一。这位重制游戏的开发者，本质上做的是“管理一个 AI 开发部门”。

## 一人团队的流水线：五步把活儿跑起来

从这类公开分享的案例里，可以把流程提炼成五步，每一步都有工程讲究：

1. **先写规格，再派活**。把玩法拆成可验收的小任务：“实现二段跳”“敌人 AI 巡逻加追击”“暂停菜单”。任务描述越像测试用例，AI 产出越稳定。
2. **小步快跑，每步可玩**。一次只派一个小任务，要求每次都交付可运行的版本。人定期试玩，把“手感不对”翻译成机器能执行的指令，比如“跳跃前摇短了 0.1 秒”“受击硬直太长”。
3. **两条反馈回路**。逻辑 bug 靠单元测试自动验证；画面 bug 靠截图、录屏喂回给模型，让 agent 看着自己的输出改输出。
4. **架构要 AI 友好**。模块边界清晰、命名统一、目录文档齐全——这些原本是团队协作的规范，如今成了写给 AI 看的说明书。代码越整洁，agent 表现越好。
5. **版本管理兜底**。AI 改崩了就回滚。人工 review diff 是整条流水线里唯一不能交给 AI 的环节，也是最容易被新手省掉的环节。

## 代码 100% 生成 ≠ 游戏 100% 完成

这是热搜标题最容易误导的地方。所谓 100%，指的是代码提交记录，不是游戏完成度。

- **代码只占游戏工作量的一部分**。美术资源、音效、关卡节奏、手感调优，要么靠素材库和生成工具拼装，要么靠人一帧一帧磨。
- **手感既是玄学也是科学**。Coyote time（离开平台后仍可起跳的宽限期）、输入缓冲、跳跃抛物线，这些 0.1 秒级的参数，AI 能改，但“这样改好不好玩”的判断权仍在人。AI 不用睡觉，但它也不知道游戏好不好玩——它连手柄都没有。
- **发行侧另有门槛**。Steam 从 2024 年初起要求披露 AI 生成内容，相关披露已数以千计；素材的版权归属、风格一致性，仍是 AI 工作流的灰色地带。

换句话说，这个案例证明的是“单人可以承担过去一个小程序团队的编码量”，而不是“一个人等于一个游戏公司”。

## 成本账与能力边界

- **账要算全**。Token 和订阅费用大约在几百到上千美元量级，对照一位工程师的月薪，单人项目确实划算。但省下的是“第一版代码”的钱，不是“打磨成好游戏”的钱——后者往往更贵。
- **边界很清楚**。agent 擅长规格明确、结果可自动验证的任务；不擅长开放性创意、跨模块的性能优化，以及“哪里都不对但说不清”的体验问题。
- **换个赛道就未必灵**。同样的流程拿去做原创玩法，成功率会明显下降，没有原版当参照系，需求模糊的代价会指数级放大。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-30/93434866f0838bf6.png)

1. **把 AI 当不知疲倦的初级同事来管理**：任务拆小、验收标准前置、review 不省略。在 agent 时代，管理能力比提示词技巧更值钱。
2. **稀缺能力正在转移**：从“会写代码”转向“会定义问题 + 会判断好坏”。重制能抄原版的作业，原创没人给你抄，问题定义能力才是护城河。
3. **先跑通回路再上真项目**：拿贪吃蛇、俄罗斯方块这类经典小游戏练手，完整走一遍“写规格 → 派活 → 试玩 → 验收”的循环，比读十篇教程都管用。

AI 重制游戏不是魔法，而是一套可以被学习、被复制的工程流程。工具会继续换代，但“拆任务、定标准、做验收”这套基本功，大概率长期有效——毕竟无论代码是谁写的，最后按下开始键的都是人。
