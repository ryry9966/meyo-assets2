## 背景

OpenClaw 的工作区里有一组约定文件：AGENTS.md 管行为规范，MEMORY.md 管记忆沉淀，SOUL.md 管人格。多数人在前两份文件上花了不少心思，但 USER.md 往往是空的——或者压根没建。

这个文件解决的是另一类问题：Agent 知道"该怎么做"，却不知道"服务的是谁"。

## 问题

没有 USER.md 的典型症状：

- 每次新会话都要重新自我介绍：机器是 Linux、包管理用 uv、回复要中文、别自动 commit。这些话一个月要说几十遍。
- Agent 靠猜。它默认你用 macOS，假设你喜欢长解释，在你明确表达过偏好的会话之外又故态复萌。
- 行为不一致。同一件事，上午和晚上的会话给出两种风格。

本质上，"你是谁"这类低频变化、高频使用的信息，一直没有稳定落点，只能靠重复输入或碰运气的记忆检索。

## 做法

在 workspace 根目录建 USER.md，遵循"一行一个事实"：

```markdown
# 关于用户
- 时区 Asia/Shanghai，活跃时间 9:00–19:00
- 主力机：Arch Linux + zsh，服务器为 Debian 12
- Python 项目统一用 uv，Node 用 pnpm
- 回复用中文，代码与注释用英文，解释要短
- 不要自动 git commit，不要写营销式文案
- 当前在做：家庭服务器监控（细节见项目内 AGENTS.md）
```

三个步骤：

1. 先写一个 30 行以内的最小版本，只放"确定且稳定"的事实。
2. 验证生效：新开会话，问它"你了解我什么"，能准确复述说明读取链路是通的。
3. 滚动维护：Agent 做出错误假设时，不要只在当次会话纠正，把结论追加进 USER.md，一次纠错，终身有效。

## 踩坑点

- **写太长**。USER.md 每个会话都会进上下文，两百行既烧 token 又稀释注意力，关键偏好反而被淹没。控制在 50 行以内。
- **写成愿望清单**。"希望代码质量高"这类话不产生行为差异；"PR 描述用英文、不超过 10 行"才会。
- **把敏感信息写进去**。这份文件会随上下文发给模型 API，token、内网地址、客户名单一律不放。
- **和 AGENTS.md 混职责**。关于你的事实放 USER.md，关于 Agent 行为的规则放 AGENTS.md，两边重复容易出现互相矛盾的指令。
- **信息漂移**。项目会结项、设备会换，过期条目比没有条目更糟。建议每月清一次，或让 Agent 在交互中主动确认"这条还成立吗"。

## 可复用建议

- 结构固定为四块：环境、偏好、红线、当前上下文。前三块低频改动，最后一块允许常变。
- 变动频繁的内容（比如手头任务）挪到 MEMORY.md 或项目级文件，USER.md 只留一行指针。
- 把维护交给 Agent 本身：直接说"把这条偏好写进 USER.md"，比自己想起来手动编辑可靠得多。
- 文件就在 workspace 里，顺手 git 管起来，偏好变更可追溯。

## 总结

USER.md 是投入产出比极高的一个文件：三十行文字，换来的是不必每次会话重复自我介绍，以及跨会话的一致行为。它并不神秘，本质就是 prompt 工程里最经典的"提供上下文"固化成一份受版本管理的静态文件。花十分钟写第一版，剩下的交给日常纠错慢慢长。
