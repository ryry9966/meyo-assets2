## 背景

团队每天要交一份日报，但数据散落在 Git 提交、CI 运行记录、服务日志和工单系统里。原来的做法是下班前人工翻一遍、复制粘贴进模板——耗时，且格式天天漂移。上个月我把这件事交给 OpenClaw 跑成了一条流水线，本文记录做法和踩过的坑。

## 问题拆解

日报的本质不是“写作”，是“聚合 + 渲染”：

- 数据分散在四个来源，格式各异（JSON 日志、纯文本、API 返回）；
- 人工聚合容易漏掉低频但重要的事件，比如一次失败重试后成功的部署；
- 让 LLM 直接读原始日志，会超上下文，且数字上容易幻觉。

## 做法

整体分三层，核心原则：**确定性的归代码，不确定的才归模型。**

**1. 采集层（代码，定时跑）**
三个小脚本分别拉 Git log、CI API、日志平台查询结果，统一归一化成 JSONL，schema 固定为 `{ts, source, type, actor, payload, hash}`。hash 用于去重，重跑不产生重复行。这一层也可以封装成 MCP tool，供 Agent 按需调用。

**2. 聚合层（代码）**
按天切分（注意时区），按 type 分组，统计出各类目的事件数、关键实体和异常项，产出一份几百行以内的“中间摘要”——而不是把几万行原始日志塞给模型。

**3. 渲染层（Agent）**
OpenClaw 定时任务每天 18:30 触发，读取中间摘要，按固定模板生成 Markdown：昨日产出 / 异常与风险 / 待办 / 关键指标，渲染完经 webhook 推送到群。

## 踩坑点

- **不要让模型做统计。** 最初我直接把原始日志丢给 Agent，让它“顺便算下失败率”，结果数字是编的。所有计数、求和必须在前两层用代码完成，模型只负责组织语言。
- **时区坑。** cron 按 UTC 跑，日报边界和本地日期对不上，出现过两天数据被合并。采集层统一打本地时间戳，聚合层按本地零点切天。
- **重试导致重复。** 任务失败重跑后，同一事件在日报里出现两次，靠 hash 去重解决；中间 JSONL 保持 append-only、幂等写入。
- **格式漂移。** 模型偶尔改标题层级，下游解析就挂。改成让模型输出限定字段的 JSON，再由代码渲染成 Markdown，格式就锁死了。
- **保留原始数据。** LLM 调用失败时可以直接重跑渲染层，不必重新采集。

## 可复用建议

- 中间 schema 才是这套东西的核心资产：同一份 JSONL，换一份渲染模板就是周报；加一条阈值规则就是告警。
- 先接一个数据源跑通全链路，再横向加源，不要一上来铺四个。
- 提示词模板和代码一起进版本库，改动可回溯。
- 报告末尾附上数据来源和条数，方便人对着原始记录抽查。

## 总结

流水线跑通后，日报从每天 20 分钟的人工活变成零操作，而且比人工更全。但真正的收益不是省时间：把“聚合”与“渲染”分离后，同一份数据能支撑日报、周报、告警多种视图。LLM 在这里只是最后一公里的排版员，确定性的管道才是地基。建议同样被日报困扰的团队从单个数据源开始试，成本很低。
