## 背景

E2E 测试的价值没人否认，但成本是真实的：选择器易碎、环境依赖多、写一套要几天，改版后维护更疼。多数团队的现状是"核心链路补几条，剩下的靠人肉回归"。有了 Agent 和 MCP 之后，"写-跑-修"这个机械循环终于可以部分外包出去——但直接把需求扔给 AI，效果通常很差。下面是我们实际跑通的一条路径。

## 问题

最常见的失败模式：把页面截图丢给 Agent，说"帮我生成登录和下单的 E2E 测试"。Agent 会基于猜测写出 30 条测试，选择器全是它想象出来的 class 名，一跑全红，人一看修不动，整批扔掉。

问题不在 AI 写代码的能力，而在两点：它不知道真实的选择器是什么，也没人告诉它哪些链路值得测。协作的核心就是把这两件事从它手里拿走。

## 做法

在 OpenClaw 里挂三个 MCP：文件系统、终端、浏览器（Playwright MCP），分五步走：

1. **先出测试清单，不出代码。** 让 Agent 读仓库里的路由和页面组件，输出一份"关键用户旅程清单"（比如：登录 → 加购 → 支付回调）。人只审这份清单，成本极低，这一步决定了 ROI。
2. **逐条生成，小批量。** 每次只生成一条旅程的测试，要求 Agent 通过终端 MCP 本地跑 `playwright test`，读失败输出自行修复，最多循环 3 轮，3 轮不绿就停下来问人。
3. **喂真实 DOM，不给截图。** 用浏览器 MCP 拿 accessibility tree 或 HTML 快照，选择器基于真实结构生成，命中率从"基本靠猜"提升到九成可用。
4. **稳定化收尾。** 让 Agent 把内联选择器收进 page object、把 `waitForTimeout` 全部换成事件等待；UI 缺稳定锚点的，人补一个小的 data-testid PR，Agent 接着用。
5. **接 CI。** 挂进流水线后，flaky 用例的失败日志定期丢回给 Agent 做分诊：是真 bug、环境抖动还是选择器漂移，让它先给结论，人复核。

## 踩坑点

- **禁止 sleep。** 不在规则里写死，Agent 碰到 flaky 的第一反应就是加 `waitForTimeout(3000)`，短期绿了，长期爆炸。
- **断言跑偏。** AI 爱断言实现细节（某个 class 是否存在），要明确要求断言用户可见结果：URL、可见文本、接口状态。
- **一次生成太多。** 批量超过 5 条，review 负担陡增，质量明显下滑，宁可多跑几轮小批量。
- **越界改动。** Agent 会"顺手"重构共享的 page object，需在规则里限制：动公共代码必须单独标出。
- **测试数据。** 它会编造魔法字符串，提前准备好 seed fixture，并要求只从 fixture 取数。

## 可复用建议

把约定沉淀成一份随仓库走的规则文件：禁止模式（sleep、nth-child）、断言风格、目录结构、分诊话术。每个项目冷启动只需做两件事——审一份旅程清单，补几个 data-testid。工具组合不必重，文件系统 + 终端 + 浏览器三个 MCP 就够；真正要固化的是"人审什么"：测试清单、选择器 PR，两个点足够。

## 总结

Agent 擅长的是写-跑-修这个反馈闭环，人该守住的是"测什么"和"什么算对"。小批量、真实 DOM、明确的规则文件，这三件事决定了这套协作是省时间还是添乱。跑通之后，我们新增一条 E2E 的成本从半天降到半小时左右，而维护负担的下降比编写提速更明显——这才是这套流程真正的收益。
