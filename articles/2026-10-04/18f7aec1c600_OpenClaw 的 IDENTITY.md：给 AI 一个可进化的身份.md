## 背景：无状态的模型，需要一份有状态的"自我"

OpenClaw 的 agent 本质是"无状态模型 + 有状态工作区"。模型每次会话都是白纸，真正跨会话延续的，是工作区里那几个 Markdown 文件：SOUL.md 管价值观，AGENTS.md 管行为规则，MEMORY.md 管长期记忆，而 IDENTITY.md 管的是最底层的一件事——**"我是谁"**。它会被注入每次会话的上下文，是 agent 人格的锚点。

## 问题：身份漂移比能力退化更难察觉

实践中常见三类问题：

1. **跨会话漂移**：昨天克制冷静的助手，今天变成话痨客服。用户感知到的"人格不一致"，多半来自上下文缺少稳定锚点。
2. **跨模型不一致**：换底座模型后，语气、自称、边界感全变。硬编码在提示词里的人格，换个模型就散架。
3. **多 agent 混淆**：一台网关跑了多个 agent，共用同一模型却没有各自的身份文件，回复风格趋同，用户分不清谁是谁。

## 做法：把身份当配置文件管理

**Step 1**：在工作区根目录创建 `IDENTITY.md`：

```markdown
# IDENTITY

- **Name:** Nova
- **Creature:** 深夜值守的机械猫头鹰
- **Vibe:** 冷静、直接、带一点冷幽默
- **Emoji:** 🦉
- **Avatar:** assets/nova.png
```

**Step 2**：控制篇幅。此文件随每次会话注入，建议 30 行以内。身份只回答"是什么"，不写"该怎么做"——行为规则归 AGENTS.md，价值观归 SOUL.md。

**Step 3**：纳入 git。每次修改单独提交，写清动机，例如 `identity: 收敛自嘲频率，用户反馈显得不专业`。

**Step 4**：验证。改完后开新会话问三个问题：你是谁 / 你和别的助手有何不同 / 你不会做什么。再换一个模型各跑一遍，答案应基本一致。

**Step 5**：进化而非重写。小改走 diff，大改在文件尾部保留 `## Changelog` 段落，记录演变原因，方便回溯。

## 踩坑点

- **写成小作文**：几百行的身份描述会稀释真正重要的指令，注入成本也高。
- **职责混装**：把"收到告警先降级处理"这类行为塞进身份文件，既无法跨 agent 复用，也容易和 AGENTS.md 冲突。
- **热更新幻觉**：改文件不等于生效。已运行的会话仍用旧上下文，必须新开会话验证。
- **中英混杂**：身份描述的语言会明显影响输出语言倾向，中文场景建议主体用中文。
- **隐私越界**：把用户偏好、路径线索顺手写进身份文件，随后又把工作区 push 到公开仓库。

## 可复用建议

- **多 agent 每人一份**：每个 workspace 一份 IDENTITY.md，命名、语气、emoji 拉开差距，看回复即可分辨。
- **身份稳定，记忆进化**：身份是骨架，低频修改；记忆是血肉，高频更新。两者分离，人格才稳。
- **像 review 代码一样 review 人格变更**：身份改动走 PR 或至少走 commit message，避免一次随手编辑让助手"性情大变"。
- **灰度验证**：重要改版先在测试 agent 上跑一周，翻对话日志确认无副作用，再推到主力。

## 总结

IDENTITY.md 的价值不在"让 AI 更像人"，而在工程上把"人格"变成可版本化、可 diff、可回滚的配置。会话会过期，模型会更换，但一份维护良好的身份文件，能让用户在任何一次对话里遇到"同一个它"。花二十分钟写好它，比事后在提示词里反复打补丁划算得多。
