## 背景

OpenClaw 的主会话是长期存在的：绑定频道或对话，记忆、上下文、工具调用历史持续累积。当我们让主 Agent 干重活——翻几千行日志、批量抓网页、跑一轮探索性调试——这些中间产物一旦进入主会话，上下文窗口就会被撑爆，后续对话质量明显下降。子 Agent 的价值就在这里：把脏活外包出去，主会话只留结论。

## 问题

常见的两种坏写法：一是直接在主会话里连续调用工具，工具输出把主会话灌满，模型开始"忘事"、指令漂移；二是 spawn 子 Agent 时把整段历史塞进去，子 Agent 和主会话共享上下文，隔离形同虚设，失败重试、错误堆栈照样回流到主会话。

## 做法

OpenClaw 的子 Agent 默认跑在独立 session 里，关键是把"独立"做实：

1. **用 `sessions_spawn` 显式派生**：给子 Agent 一个独立的 session key，它的上下文窗口和工具调用历史从零开始，主会话看不到它的中间过程。
2. **任务描述代替历史投喂**：spawn 时传"任务卡"而不是对话记录——目标、边界条件、交付格式、超时时间，四样写清楚。
3. **只回收结构化结果**：子 Agent 结束后，主会话只拿到最终产物（一段短 markdown 或 JSON），中间读过的文件、失败的重试全部留在子 session 里。
4. **隔离工作目录**：涉及文件读写时给子 Agent 单独的 workspace 路径，避免它改写主会话正在用的状态文件。
5. **必设超时**：子 Agent 卡死不能拖累主会话，超时后回收，主 Agent 拿到失败信号自行决定重试或换路。

## 踩坑点

- **记忆文件串味**：子 Agent 能读到主 workspace 的记忆文件，容易继承陈旧假设。要么限制读取范围，要么为它准备精简版的任务上下文。
- **共享工具实例**：多个子 Agent 抢同一个浏览器 profile 会互相踢登录态，并发场景要分配独立实例。
- **假隔离**：spawn 时把主会话全文粘进任务描述，等于没隔离。任务描述是摘要，不是备份。
- **结果不收敛**：不规定交付格式，子 Agent 回来一大段流水账，主会话照样被污染。

## 可复用建议

把子 Agent 当纯函数用：输入是任务卡，输出是结果，对主会话零副作用。任务卡模板固定四段——目标、约束、交付格式、禁止事项；结果强制"一段话 + 关键数据"。团队可以沉淀几个标准子 Agent（日志分析、网页抓取、代码检索），复用同一套隔离配置，减少每次现写 prompt 的偏差。

## 总结

session 隔离不是一个开关，而是一组纪律：独立 session key、摘要式任务卡、结构化回收、独立工作目录、强制超时。做到这五点，子 Agent 才真正是"可丢弃的外包工"，主会话才能保持干净、长期可用。
