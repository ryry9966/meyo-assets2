## 背景

跑自动化工作流时，我们经常在主会话里派生子 Agent 去做独立任务：抓资料、批量调 MCP 工具、做代码审查。OpenClaw 的主会话本质是一条持续累积的上下文——消息、工具结果、记忆文件都会沉淀在里面。如果子 Agent 和主会话共用一条上下文，问题很快就来了。

## 问题

最常见的三种污染：

1. **上下文膨胀**：子 Agent 的中间输出（尤其是 MCP 工具的长结果）全部写回主会话，几轮下来主循环的可用窗口被吃掉大半。
2. **记忆污染**：子 Agent 调用的工具顺手更新了共享 memory 文件，主会话下次唤醒时读到的是任务的中间态。
3. **状态串扰**：子 Agent 的失败重试、临时状态被主循环当成自己的历史。

实际表现很典型：主 Agent 突然"记得"一些没做过的事，或者回复风格被带偏。

## 做法

1. **派生时显式声明独立 session**。给子 Agent 分配独立 session id（或开启 isolated/sandbox 模式），确保它有自己的一份上下文文件，而不是复用主会话的。
2. **用"任务简报"代替共享历史**。不要把主会话历史塞给子 Agent 当背景，而是写一份自包含简报：目标、约束、相关文件路径、验收标准，控制在几百 token 内。
3. **收窄工具面**。子 Agent 只挂载它需要的 MCP server 和插件；写操作类工具（文件写入、memory 更新）默认不给，除非任务确实需要。
4. **约定结果契约**。要求子 Agent 只返回结构化结果：一段结论 + 产物文件路径。原始日志、完整工具输出落盘到 workspace，不回传。
5. **落盘验证**。跑一个冒烟用例：主会话问一句"我们刚才聊了什么"，确认子 Agent 的中间过程没有出现在主会话历史和 memory 文件里。

## 踩坑点

- 子 Agent 和主会话写同一个 memory/notes 文件，并发时后写覆盖先写。给子 Agent 单独的子目录或文件前缀。
- 图省事把主会话历史全量复制给子 Agent，隔离形同虚设，token 也白烧。
- 忘记设超时和 token 上限，子 Agent 卡在某个 MCP 工具上，留下僵尸 session。
- 结果契约太松，子 Agent 把大段原文粘回来，等于变相污染。契约里明确"超过 N 行就落盘，只回传路径"。

## 可复用建议

- 沉淀一份标准的任务简报模板和结果契约，所有子 Agent 复用，别每次手写。
- 产物一律进文件系统，会话只承载对话；**文件路径是主会话和子 Agent 之间唯一的窄接口**。
- 子 Agent 的 session 日志单独归档，排障时独立回放，不用翻主会话。
- 定期清理已完结的子 session，避免磁盘和索引膨胀。

## 总结

session 隔离的核心不是"少给上下文"，而是划清边界：主会话和子 Agent 之间只交换两样东西——一份自包含的任务简报，一份结构化的结果。中间过程留给子 Agent 自己的 session 和文件系统。做到这一点，主会话的上下文和记忆才是可预测的，长跑工作流才稳得住。
