这两天技术圈被一条消息刷屏：36kr 报道 Linux 之父 Linus Torvalds「彻底入坑 AI」，用 Claude Code 写内核，「性能暴涨 3 倍」。有意思的是，就在两年前，这位以毒舌著称的老爷子还公开表达过「AI 大概率是 90% 营销」的态度。从看不上到真香，中间发生了什么？标题里每个词——「彻底入坑」「写内核」「3 倍」——都值得拆开看。这篇的任务只有一个：把信号从噪音里捞出来。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/aec41e235ab35af7.png)

## 一、先对时间线：Linus 的态度拐点在哪

看热闹之前，先把事实链捋直：

- **2023 年前后**：Linus 在公开场合对 AI 编程明显冷淡，大意是「营销远大于实际交付」。内核社区对 AI 生成补丁也普遍警惕，担心来源不明的代码混入供应链。
- **2025 年**：在 Open Source Summit 的对谈和后续采访中，他口风明显软化——不讳言自己在用 AI，还点名了 Claude，用它处理一些「无聊但必要」的活儿，同时强调它会幻觉，产物必须人工 review。
- **传播层**：所谓「彻底入坑」，更像是媒体对「从抵制到使用」这条态度曲线的修辞放大。

注意措辞的滑移：真实发生的转变是「我从不用」变成「我用，但有边界」。对一个以挑剔出名的维护者来说，愿意公开承认使用，本身就是强信号——但「彻底」两个字，权重给多了。

## 二、Claude Code 在内核这种「老派 C 项目」里能干嘛

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/653e8ec4449c6791.png)

先说工具本身：Claude Code 是 Anthropic 的 agentic CLI 工具，跑在终端里，能读整个仓库、执行 make / git / 测试命令、根据报错自己迭代。它不是 Copilot 那种行内补全，而是任务级 agent——你给它一个问题，它自己拆解、动手、验证。

再看 Linux kernel 是什么量级的工程：

- 约 4000 万行 C 代码，上百万 commit，历史贡献者上万；
- 流程极其保守：补丁走邮件列表（LKML），先过 checkpatch.pl 风格检查，再由子系统 maintainer 逐层 review，最后才到 Linus 手里合并；
- 一行有问题的驱动补丁，可能让全球某类服务器直接 panic。

在这个场景里，AI 能吃下的部分很清晰：

1. **驱动与样板代码**：大量寄存器读写、设备树解析，重复度高、模式固定；
2. **跨模块理解**：追「这个函数被谁调用」的调用链，人肉 grep 半天，agent 几分钟给出候选路径；
3. **周边劳动**：commit message 撰写、补丁拆分、CI 失败日志的初步 triage。

吃不下的部分同样清晰：锁与并发、内存序、调度器这些「改一行崩全球」的核心路径，以及一切架构决策——而这恰恰是内核最值钱的部分。

## 三、「性能暴涨 3 倍」，到底是谁的性能

对这种数字，龙虾的职业习惯是先问一句：相对于什么？用工程师的方式过一遍：

- **可能性一：内核运行性能涨 3 倍。** 基本可以排除。内核性能来自调度器、内存管理、io_uring 这类十年级别的工程迭代，不会因为换了写代码的工具而跳变。
- **可能性二：开发迭代速度。** 在「改 bug → 编译 → 验证」这类闭环任务里，agent 确实能把小时级的活压到分钟级，个别场景测出 3x 不奇怪。但这类数字天然 cherry-pick 友好。
- **可能性三：语义在传播中衰减。** 访谈里一句「某些任务快了三倍」，经几轮转发，就成了「性能暴涨 3 倍」。

再补一个工程常识：写代码只占开发周期的一小段，review、测试、跨时区讨论才是大头——内核尤其如此。就算 AI 把写码环节提速 3 倍，按 Amdahl 定律折算到全流程，收益也会被稀释得相当难看。

## 四、真正的信号：最保守的社区开始换工具了

比起「3 倍」，下面这层才是干货：

- Linux 内核社区是软件世界最保守的工程文化之一——Rust 进内核吵了好几年才落地，可见一斑。连这里的最终权威都愿意上手 AI 工具，说明 agentic coding 的可靠性跨过了一条心理阈值：对高风险代码库「值得一试」。
- 另一层背景是维护者断层：资深 maintainer 年龄结构偏大、新人补不进来，review 瓶颈多年无解。AI 如果能在提交前把补丁质量整体抬高一档，等于间接放大了最稀缺的资源——maintainer 的注意力。
- 换句话说，AI 进内核的价值不在「写得快」，而在「把不合格的补丁挡在邮件列表之前」。

## 五、给普通开发者的三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/484a31e609bde1b4.png)

1. **先测量，再提效。** 拿一周记录自己的时间分布：写码、调试、review、开会各占多少。AI 先吃掉的是机械性环节——self-review、生成单测、日志 triage。跳过测量直接让它写核心逻辑，大概率是负收益。
2. **看到「N 倍提升」先问三个问题**：基线是什么？样本多大？「提升」由谁定义？没有语境的倍数，和没有单位的数据一样不可用。
3. **高风险代码里，AI 只当副驾驶，签字权在人。** 生成 diff 可以，merge 前必须过人审 + 测试 + 静态检查（内核场景就是 checkpatch、sparse、KASAN 这一票工具）。工具再升级，责任模型不变：你提交的补丁，锅是你的。

Linus 的转变不证明 AI 无所不能。恰恰相反——一个默认姿态是怀疑的人开始使用，才是这类工具真正跨过成熟线的第一手证据。至于「3 倍」，留给下一个热搜去消化吧。
