## 背景

跑过一个长期 Agent 的人多半遇到过这种情况：同一个助手，周一还严谨克制，周三突然自作主张删了你的定时任务。原因是身份信息散落在 system prompt、代码里的字符串、上一次会话的记忆里——谁都能改，没人负责。

OpenClaw 把这件事收敛成一个文件：`IDENTITY.md`。会话建立时 Agent 读取它，作为"我是谁、怎么做事"的唯一事实源。这不是什么新发明，本质上是把 prompt 工程里最玄学的部分，变成一个可以 diff、可以 review、可以回滚的 Markdown 文件。

## 问题

没有它的时候，常见的三种失控：

1. 人设写死在代码里，改一次要发版；
2. 多入口（CLI、Web、MCP 工具调用）行为不一致，因为每个入口注入的 prompt 不一样；
3. 调了三个月的手感，一次重构全部丢失，没有任何痕迹。

## 做法

我目前的文件结构，放在 workspace 根目录，随工作区走：

```markdown
# Identity
## 定位
一句话说清：负责什么，不负责什么。
## 行为边界
- 哪些操作必须先确认（删除、外发、花钱）
- 哪些默认直接做（格式化、lint、补测试）
## 语气
用可执行规则代替形容词，例如"先给结论，再给依据"，
而不是"简洁专业"。
## 记忆约定
什么写进 MEMORY.md，什么只留在会话里。
## 升级路径
拿不准时找谁，用什么格式上报。
```

迭代节奏按代码来：改动走 git，小步提交；每次只改一个行为点，用最近一周的会话日志做回放验证；commit message 里写清"为什么改"。一周一个版本足够，不必天天调。

## 踩坑点

- **写太长**。超过一页，模型对后半段的遵守率明显下降，控制在 40 行以内。
- **写形容词不写规则**。"专业、友好"没法执行，"先说结论"可以。
- **和 system prompt 打架**。别重复框架已有的指令，冲突时模型随机站队。
- **让 Agent 自己改自己**。允许模型提议修改，但合并必须由人确认。
- **写进敏感信息**。这个文件会进每次上下文，按"最坏情况会泄露"的标准来写。

## 可复用建议

- 把 `IDENTITY.md` 纳入 code review，与人写的代码同标准；
- 单独维护一份 changelog，只记结论，不记过程；
- 准备三个固定测试问题（一个日常、一个边界、一个恶意）做冒烟测试，改版必跑；
- 多 Agent 场景下，共享一份"底线"文件，各角色只叠加差异，不要每人抄全文。

## 总结

`IDENTITY.md` 的价值不在文件本身，而在于它把 Agent 的"性格"从一次性 prompt 变成了可版本化、可评审、可回滚的工程资产。身份漂移是常态，你要做的不是阻止漂移，而是让每次漂移都留下记录、能被纠正。先写十行跑起来，比设计一个完美模板更重要。
