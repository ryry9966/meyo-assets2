## 背景

多数人用 AI 助手还是"你问我答"：不开口，它就静止。OpenClaw 有个容易被忽略的机制叫 heartbeat（心跳）：agent 按固定间隔被唤醒一次，自行判断"现在有没有值得说的事"。配合 MCP 工具和 cron，可以搭出一套真正 proactive 的自动化——它不等你开口，但也不该变成骚扰源。

## 问题

把心跳打开很容易，难的是三件事：

1. 唤醒后 agent 不知道"沉默"也是合法输出，结果每隔几分钟发一条废话；
2. 检查逻辑全写进 prompt，每次心跳都全量执行，token 和延迟都不可控；
3. 没有去重，同一条告警一天推二十遍，最后你把它静音，proactive 就死了。

## 做法

1. **先定"该不该说话"。** 心跳 prompt 里明确写：没有值得报告的事就只回 `HEARTBEAT_OK`，这条消息会被吞掉、不推给用户。这是防刷屏的第一道闸门。
2. **把"检查"做成工具而不是 prompt。** 用 MCP 暴露几个轻量接口：读日历、查仓库 CI 状态、看磁盘与监控摘要。prompt 只负责决策，事实全部走工具，避免模型凭记忆编造。
3. **加一个状态文件做去重。** 让 agent 读写一个小 JSON，记录上次告警时间与内容 hash。条件没变化不重复推送，状态升级（如 warning→error）才允许再发。
4. **cron 管确定性任务，heartbeat 管模糊判断。** "每天 8 点发日报"用 cron；"感觉 CI 不对劲就提醒我"用心跳。别用定时任务模拟判断，也别让心跳去干调度。
5. **主动消息单独路由。** 把 proactive 输出发到专门的会话/频道，并设免打扰时段。主对话流保持干净，噪音才有地方去。

## 踩坑点

- 心跳间隔起步别低于 15–30 分钟，先跑一周看误报率，再逐步收紧；
- 工具超时设短（秒级），心跳里一次失败的工具调用会拖住整个循环；
- 模型偶尔会"表演勤奋"，比如每次心跳都去 git pull。在 prompt 里写死：只有满足明确条件才允许调用对应工具；
- 时区。cron 与心跳的时间判断都要显式指定时区，否则提醒会漂移；
- 所有主动行为留日志（时间、触发条件、动作），否则出问题时你无法复盘它为什么给你发消息。

## 可复用建议

- 心跳 prompt 三段式：检查清单 → 判定条件 → 沉默条款。沉默条款放最后、写具体；
- 去重状态文件与消息模板分离，换模型不用改逻辑；
- 给每类主动行为设每日预算，比如最多 3 条，超出的合并成一条摘要再发。

## 总结

Proactive 的关键不是让 AI 更聪明，而是给它一套"什么时候闭嘴"的约束：心跳负责唤醒，工具负责事实，状态负责去重，门控负责克制。把这四件事拆开做，你的 assistant 才能从问答机变成一个不打扰你的同事。
