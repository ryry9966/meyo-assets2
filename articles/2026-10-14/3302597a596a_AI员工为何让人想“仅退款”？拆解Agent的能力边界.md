最近 36kr 一篇文章《马斯克吹爆的AI员工，我用完只想仅退款》冲上热议：作者被“AI 即将包揽白领工作”的宣传打动，花真金白银订阅了某款“AI员工”服务，结果让它写周报像模像样，让它独立跟一个项目就原形毕露，最后只想走“仅退款”流程。这不是个例——社交平台上晒“AI员工翻车截图”的帖子越来越多。话题源头绕不开马斯克：他这两年反复为自家 Grok 站台，称模型已达“博士级”水平，并多次预测 AI 会接管大部分白领工作；厂商们顺势把订阅服务包装成“AI员工”，月费几百块，对比真人工资显得“太划算”。今天不聊段子，龙虾钳子敲着计算器算三笔账：这类产品到底在卖什么、为什么干不好“长活”、雇之前怎么判断值不值。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/4fea9b82f746b66c.png)

## 一、“AI员工”是个营销词，不是技术名词

先拆包装。所谓“AI员工”，技术上是这么一摞东西的组合：

- **LLM（大模型）**：负责理解和生成，相当于“大脑”；
- **RAG（检索增强）**：外挂一个企业知识库，让它能查资料；
- **工具调用（Tool Use）**：能点网页、调 API、写表格，相当于“手”；
- **流程编排**：把上面几样串成一条自动化工作流。

这套东西在学术界叫 Agent（智能体）。2023 年 AutoGPT 就以“自主 AI”的名义火过一波，结果因为长任务里反复跑偏、疯狂烧 API 费用，几个月就哑火了。厂商后来学聪明了，给它换了个带人力资源味的名字，“数字员工”。

为什么这么改名？因为定价锚点变了。同一套软件，叫“工作流工具”，你的心理价位是每月 99 元；叫“AI员工”，对比真人月薪几千上万，几百块瞬间显得白菜价。用工资做价格锚点，是近几年 SaaS 圈最聪明的定价发明——也是最经不起类比的：真人会计错了账要担责，会跨八个系统对数据，会揣摩老板没说出口的需求；Agent 只会执行训练数据里的模式，错了不担责，法律上也无人可追责到它头上。

## 二、为什么 Agent 干不好“长活”：误差会滚雪球

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/094638ae3aef3527.png)

宣传视频里最唬人的，是 Agent 一气呵成完成任务的样子。问题恰恰出在“一气呵成”——它的每一步都不是 100% 可靠，而误差是相乘的：

- 假设单步成功率 95%（已经很高了），连续跑 20 步，全程成功率只剩 0.95²⁰ ≈ 36%；
- 一次真实办公任务（读文档→查系统→写方案→调格式→发送）轻松超过 20 步。

这不是推测，是实测结论。AI 评测机构 METR 在 2025 年发布的“任务时长”研究给出量化曲线：当前最强模型能以约 50% 成功率完成的任务，换算成人类工时大约只有 1 小时；任务每变长一个量级，成功率就断崖式下跌。卡内基梅隆大学的 TheAgentCompany 基准更直白：在模拟一家软件公司的环境里做端到端任务，2024 年底最强模型的完成率约 24%，四分之三的活儿干不完或干错。

第二重瓶颈是“记性”。128K、200K token 的上下文窗口听着很大（约几百页文档），但一个真实项目几周的群聊记录、表格、历史邮件轻松超载；而且模型存在斯坦福 2023 年论文指出的 "lost in the middle" 现象——长上下文中间部分的信息最容易被忽略。更麻烦的是跨天状态：它今天给你的方案，明天它自己“不记得”，除非厂商专门建了记忆系统——而这恰好是整个技术栈里最贵、最难做好的部分。

## 三、三类最容易“仅退款”的场景

翻车不是随机的，集中在三类被宣传得最凶的场景：

1. **跨系统办公自动化**。让 Agent 操作浏览器和办公软件，本质是给机器人装了个“鼠标手”。界面一改版、按钮一挪位置，流程立刻崩。这一点老前辈 RPA（机器人流程自动化）十年前就用无数张工单替它踩过坑了。
2. **深度行业知识工作**。法律检索、财务分析、合同审核——上限往往不在模型，而在你喂给它的知识库质量。RAG 检索不到关键条款，模型就开始一本正经地“编”。Garbage in, garbage out，这条铁律在 Agent 时代只是换了口锅。
3. **多人协作与责任链**。它没法在会上察言观色，没法替你签字担责，在审批流里只能算“实习生的实习生”。

还有一笔隐性账：Agent 每个任务要调用模型几十上百次，每次还要重新读一遍上下文，token 消耗远超普通对话。个人试用水花不大，一旦全公司规模化部署，账单涨速经常超出采购时的预估。

## 四、雇之前，先跑一遍这个自查流程

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/199c32f7b40e32ba.png)

判断一个“AI员工”值不值，按这个顺序过一遍：

- **第一关：用你自己的脏数据测**。厂商 demo 里的数据都是精修过的，你公司那些命名混乱的表格、扫描件才是真实战场。
- **第二关：只盯两个硬指标**。任务完成率，以及你的返工时间。改它输出的时间超过它帮你省下的时间，就是负 ROI，功能列表再华丽也白搭。
- **第三关：看失败兜底**。它出错时是硬着头皮编，还是停下来举手求助？会求助的 Agent 才值得长期用。
- **第四关：按“高频 + 结构化 + 低风险”筛活儿**。数据整理、周报初稿、会议纪要很适合；跨部门协调、对外承诺、需要拍板的事，先别交出去。

心态也要切换：把它当“按月付费、随时可解约的工具”，而不是“入了编制的员工”。工具思维，才能算清账。

## 写在最后：三条冷思考

1. **“员工”是定价策略，不是技术描述**。把这个词从宣传页划掉，它就是一套 LLM 工作流自动化套件，值不值取决于你的任务结构，不取决于类比。
2. **能力边界在快速移动，但合同按今天签**。METR 的曲线每几个月上移一截，今天的差评不代表明年还差；可你今天付的是今天的钱，为明天的承诺买单就是亏。
3. **最稳的用法不是替代一个人，而是切走一个人的重复部分**。切得越细、越结构化，“仅退款”的概率就越低。

Agent 的进步是真的，营销的通胀也是真的。两边都记账，才不会被任何一边带跑。
