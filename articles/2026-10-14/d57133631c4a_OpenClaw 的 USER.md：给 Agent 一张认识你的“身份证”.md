## 背景

OpenClaw 的工作区里，AGENTS.md 管“怎么干活”，SOUL.md 管“什么性格”，但很多人忽略了一个文件：USER.md——告诉 Agent “我是谁”。它和 MEMORY.md 的分工值得先说清楚：MEMORY.md 记动态事实（聊过什么、做过什么），USER.md 放稳定画像（时区、技术栈、沟通偏好）。前者是日志，后者是档案。

## 问题：Agent 默认对你一无所知

现象很常见：

- 让它“明早提醒我开会”，它不知道你在 UTC+8；
- 让它写代码，它默认给你 Python，而你的主力是 Go；
- 每个新会话都要重新交代背景，或指望它从聊天记录里“悟”出来。

MEMORY.md 能部分缓解，但它是追加式的、易碎的。稳定偏好这种东西，写成静态档案更可靠，也更好审计。

## 做法

1. 找到工作区（默认 `~/.openclaw/workspace/`，以你的配置为准），新建或编辑 `USER.md`。
2. 按四个区块写，全部用短 bullet：

```markdown
## 基本信息
- 时区：Asia/Shanghai，工作日 09:00–19:00
- 语言：中文优先，技术名词保留英文

## 技术环境
- 主力：macOS + Go/TypeScript，编辑器 VS Code
- 部署：自建 K8s，不用 Serverless

## 沟通偏好
- 结论先行，不要铺垫和客套
- 给方案时列出取舍，不要只给一个选项

## 当前上下文（2025-06 更新）
- 在做网关重构项目
- 近期目标：把告警噪音降下来
```

3. 控制篇幅。USER.md 每个会话都会进上下文，建议压在 60 行以内。“当前上下文”过时就删，别恋战。
4. 重启会话（或 reset）让它生效，然后问一句“你现在对我的了解有哪些？”，做一次审计。

## 踩坑点

- **写成小作文**：200 行的 USER.md 每轮对话都在消耗 token，还会挤占真正的任务上下文。档案要像名片，不像简历。
- **塞进动态信息**：待办、任务进度应该进 MEMORY.md 或任务系统。USER.md 放易变内容，很快就会自相矛盾。
- **写入敏感信息**：明文密钥、精确住址不要放。上下文可能被日志或同步，档案里只留“工作需要的最低限度”。
- **和 AGENTS.md 抢活**：USER.md 写“我是谁”，AGENTS.md 写“你怎么做”。同一条规则出现在两个文件里，行为会漂移。
- **以为改了立即生效**：工作区文件在会话启动时读取。改完不重启，Agent 还在用旧档案。

## 可复用建议

- 给工作区上 git，USER.md 的变更历史就是你偏好的演进记录。
- 每月固定 review 一次，重点清理“当前上下文”区块。
- 多人共用的实例，USER.md 只写主用户；家人、同事的偏好放到各自场景的规则文件里。
- 新搭一个 Agent 环境时，先写 USER.md 再玩插件和 MCP——收益/成本比最高的往往是这张“身份证”。

## 总结

USER.md 是成本最低的 Agent 调优手段：花二十分钟写一份克制、结构化的个人档案，换来的是它从第一次对话起就知道你的时区、技术栈和沟通习惯。把它当档案维护，而不是当日志堆放，定期修剪，效果很稳定。
