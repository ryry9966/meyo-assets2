最近 36kr 一篇关于“AI员工”的体验稿上了热议：作者被马斯克式的造势吸引，付费试用某款 Agent 产品，结论是——用完只想“仅退款”。“仅退款”这个词从电商评论区借来，杀伤力在于连退货都嫌麻烦，等于宣告商品一文不值。笑归笑，这波情绪背后是个正经问题：大模型能力肉眼可见地变强，为什么落到“AI员工”这个产品形态上，体验落差这么大？这篇从技术和商业两个角度拆一拆。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/051aff965d5223bf.png)

## 一、“AI员工”到底是什么货

先把概念落地。市面上叫“数字员工”“AI员工”"Agent"的产品，技术栈大同小异，核心是三层：

1. **大模型大脑**：负责理解和规划。本质是概率生成模型，输出是“推理出的最合理答案”，不是数据库里查出来的标准答案；
2. **工具调用（Tool Use / Function Calling）**：让模型能操作浏览器、调 API、写文件、发邮件——这是它看起来“能干活”的关键；
3. **编排与记忆**：把“规划 → 执行 → 观察结果 → 修正”的循环串起来（业内叫 ReAct 范式），再配一层短期记忆。

它和上一代 RPA（流程自动化机器人）的区别在于：RPA 是人把规则写死，机器人照剧本演；Agent 是模型临场自己规划。自由度更高，但不确定性也更高——这个 trade-off 就是后面所有问题的源头。

## 二、演示惊艳、上手拉胯：四个技术根因

很多人第一反应是“模型不行”，更准确的描述是：**长链条任务会把小误差放大成灾难**。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/57bdf7c47c90f176.png)

1. **误差累积**。假设 Agent 单步操作准确率 95%——这在当前模型里已算优秀——一个 20 步任务的整体成功率约为 0.95²⁰ ≈ 36%。步骤越多，可靠性衰减越狠。你在 demo 里看到的十步以内小任务，和宣传里“全自动完成一整个项目”，根本不是一个难度量级。
2. **Benchmark ≠ 真实任务**。以代码 Agent 为例，SWE-bench Verified 上头部模型 2025 年已突破 70%，但评测集是经过清洗的 GitHub issue：上下文干净、验收标准明确。真实企业需求往往是一句模糊的人话，还夹着历史包袱。
3. **长尾暴露**。80% 的常见场景演示都能过，剩下 20% 的边缘情况——奇怪的文件格式、网页弹窗、验证码、接口返回异常——才是日常使用的主场。研究机构 METR 的纵向测量显示，AI 能可靠完成的任务时长目前仍以分钟计，虽然该指标大约每 7 个月翻一倍，但离“全职员工”还差几个数量级。
4. **环境脆弱**。Agent 依赖网页结构和接口稳定，目标网站改个按钮位置，整个流程就断。更糟的是它失败时常常不自知，还会一本正经汇报“任务已完成”——这比明着失败更伤信任。

## 三、“吹爆”的传播学，与“仅退款”的商业账

再看非技术侧。

- **叙事先行**。“AI 将取代所有工作”这类表述，本质是融资叙事的一部分。马斯克式发布擅长用 best case 定义预期，而用户付费后遇到的是平均 case。传播学上这叫可得性偏差：一两个惊艳 demo 的记忆强度，远超十次平平无奇的使用。
- **话术升级**。不少销售把 copilot（副驾驶）包装成 autopilot（自动驾驶）。一字之差，责任主体从“人”变成“系统”，但当前技术成熟度其实只到 copilot。
- **商业模型拧巴**。按席位收费是 SaaS 老逻辑，成本却按 token 线性增长——用户用得越狠，产品毛利越薄甚至为负。于是有些产品悄悄限速、限额，进一步坐实“名不副实”的体感。
- **价值锚点错位**。“仅退款”的深层原因在这：用户按“雇个人”的锚定价——一个月几百块该顶半个员工；产品实际交付的是“一个高速但需要盯着的实习生”。预期差一拉开，差评和退款就是必然。

## 四、谁该用、怎么用：三道门的判断框架

骂完说干货。AI 员工不是不能用，是要挑着用。拿到任何 Agent 产品，先过三道门：

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/6a831602f67f65f1.png)

1. **第一道门：容错率**。出错的代价能不能被低成本发现和回滚？写代码有测试和版本管理兜底，适合；群发客户邮件、自动下单，一步错步步错，不适合。
2. **第二道门：结构化程度**。输入输出有没有明确格式和验收标准？“把 200 份简历按模板提取字段”结构清晰，适合；“帮我想想战略”模糊开放，不适合。
3. **第三道门：频率与量**。高频重复才摊得薄学习和配置成本。一年用三次的任务，人自己做更快。

三道门都过了，再补一个工程习惯：**先影子运行（shadow mode）**。让 Agent 和人并行干同样的活，对比两周产出，拿数据说话，再决定放权到哪一步。记住一个定位：当前所有 Agent 产品的真实身份是“高速实习生”——产出快、便宜、但必须配 reviewer。把它当员工用会失望，把它当放大器用才有价值。

## 五、三条冷思考

1. **算清“任务单位成本”**。正确的 ROI 公式是：单次任务的 Agent 成本 + 人工检查修正成本，对比纯人工成本。只拿订阅费和人月薪比，是锚错了。
2. **对 benchmark 保持职业怀疑**。看评测先问一句：评测集的任务分布和我的业务像不像？要求供应商提供 PoC 和影子运行数据，比看发布会幻灯片靠谱一百倍。
3. **别追求一步到位的全自动**。把流程拆开：确定性强的环节交给规则和 RPA，模糊环节交给模型，人守住关键节点。“半自动先跑通，再逐步放权”，是过去一年真正跑通 Agent 落地的团队共同路径。

一句话收尾：AI 员工不会摸鱼，但它会一本正经地犯错。先当好它的产品经理，再谈让它当你的员工。
