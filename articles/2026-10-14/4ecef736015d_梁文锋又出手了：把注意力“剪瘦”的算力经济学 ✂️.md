热搜上那句“梁文锋，又出手了”，指的不是融资、不是公开发声，而是一篇论文：DeepSeek 发布了实验版模型 DeepSeek-V3.2-Exp 和配套技术报告，有人在作者列表里认出了创始人梁文锋的名字。一家头部 AI 实验室的创始人仍在一线推技术路线，这本身是新闻；但对工程师来说，更值得展开的是报告里的真正主角——DeepSeek Sparse Attention（DSA），一套把注意力计算“剪瘦”的方案。这篇文章把这笔账算清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/a4179d827ec56056.png)

## 先对齐事实：这次“出手”出的是三样东西

- **一个实验版模型**：V3.2-Exp 的官方定位就是“实验版”，基座延续 V3.1-Terminus，重点变化只有一个——引入 DSA 稀疏注意力；
- **一篇技术报告**：DSA 的设计、训练方法、评测细节都写在报告里，梁文锋名列作者。在 DeepSeek 内部，创始人署名并不常见，这个细节被广泛解读为“核心决策者仍在一线押技术路线”；
- **一次直接降价**：模型发布同时，官方把 API 输入输出价格下调超过一半。降价的逻辑很工程化——稀疏化之后，算同样的 token 成本确实低了，价格只是成本曲线的真实反映。

一句话概括：这不是发布会式的“出手”，而是把一篇论文直接兑现成了账单上的价格。

## 注意力为什么贵：一笔 O(n²) 的账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/6478381dd5cf5c7b.png)

Transformer 的自注意力有个绕不开的性质：序列里的每个 token，都要和所有 token 各算一遍相关性。

- **平方复杂度**：计算量随序列长度平方增长。上下文从 4K 拉长到 32K，长度 ×8，注意力计算量 ×64；
- **显存压力**：KV Cache 随序列长度线性膨胀，长对话、长文档场景里显存往往先一步爆掉；
- **大量无效计算**：32K 上下文的注意力矩阵约 32000×32000，超过 10 亿次相关性打分，但绝大多数 token 对之间根本没什么关系。就像你读一篇论文，不会真的逐字对照第一页和最后一页。

长文本“贵”的根源就在这里：钱大部分花在了“礼貌性地看一眼所有内容”上。业界的稀疏注意力研究线——从 Longformer、BigBird，到 DeepSeek 自己 2025 年初的 NSA 论文——都是冲着这笔账去的，DSA 可以看作它从论文走进生产 API 的工程落地版。

## DSA 做了什么：先“点名”，再“精读”

DSA 把注意力拆成两步，思路类似查资料：

1. **Lightning Indexer（闪电索引器）**：一个小网络快速扫过全部 token，为当前 query 需要的内容打重要性分——相当于先翻目录；
2. **Top-k 稀疏注意力**：只挑出得分最高的 k 个 token，对这一小撮做精细的注意力计算——只精读重点段落。

几个工程细节值得划线：

- **稀疏模式是学出来的**：哪些 token 该被选中，不是人工规则，而是模型在训练中自己学会的，且训练和推理共用同一套稀疏逻辑，避免“训练稠密、推理稀疏”带来的精度裂缝；
- **收益直接写进价格**：官方数据显示，预填充（prefill）和解码（decode）阶段的算力开销明显下降，于是才有底气把 API 价格砍掉一半以上；
- **对效果的影响可控**：报告中的评测显示，长文本、代码、工具调用等能力与上一版本本持平——省掉的是无效注意力，不是有效信息。

类比成一句话：从“每读一个字都要回头看全文”，改成“先查索引，再精读相关段落”。图书馆变大一万倍，你反而读得更快。

## 为什么这事值得行业多看一眼

- **效率路线再次得手**：过去一年的主流叙事是堆算力，DSA 代表另一条路——同样的能力，更少的计算。从 V2 的 MLA、V3 的 MoE 到 V3.2 的 DSA，DeepSeek 一贯把创新点押在“每 FLOP 的性价比”上，这次只是又落了一子；
- **成本决定应用渗透**：token 价格降一半，很多原本算不过账的场景——长文档 RAG、多轮 Agent、代码仓库级理解——突然就能算了。这里有个反直觉的 Jevons 悖论：资源使用效率提高，总消耗往往不降反升。对推理算力的需求，可能不因为省钱而减少，反而因为便宜而被放大；
- **开源与降价的飞轮**：权重开源、API 降价，吸引开发者把工作流建在它的技术栈上；社区反馈的工程问题，又加速下一轮迭代。用生态换时间，是这套打法的核心。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-14/58205192f1e35fa3.png)

1. **给开发者**：做长上下文应用（RAG、Agent、代码助手）的，值得把 V3.2-Exp 拉进自己的 benchmark 跑一遍，重点看长文档检索问答的稳定性。实验版毕竟是实验版，关键业务先小流量灰度，再决定是否切换；
2. **给选型团队**：别把“算力=能力”当成默认假设。评估模型时，把“每百万 token 成本”和“单位功耗性能”一起放进对比表——这一轮竞争里，算法效率红利正在和算力堆叠并驾齐驱；
3. **给围观者**：看 AI 新闻别停在标题。真正有信息量的是技术报告里的消融实验和成本拆解，那里写着“为什么成立”；标题只负责告诉你“谁又出手了”。

注意力机制的进化史，本质上是一部“如何更聪明地偷懒”的历史。这一手，把偷懒写成了论文，还顺手打了折。
