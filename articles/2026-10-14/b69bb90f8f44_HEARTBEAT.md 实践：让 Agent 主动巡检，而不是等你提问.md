## 背景

OpenClaw 里的 Agent 默认是被动应答：你发一条消息，它跑一次。问答型用法没问题，但有一类需求很别扭——"帮我盯着 XX，有事告诉我"。总不能每隔半小时手动戳它一句。

HEARTBEAT.md 就是给这类需求准备的：它是 Agent 工作区（默认 `~/.openclaw/workspace/`）下的一个特殊文件，Gateway 按固定间隔（默认 30 分钟）唤醒一次 Agent，把文件内容当作 prompt 交给它执行。本质上，这是给 Agent 加了一个"值班巡检"循环。

## 它解决什么问题

被动模式下的三个痛点：

1. 需要持续关注的轻量事项（仓库更新、磁盘水位、收件箱摘要）全靠人触发；
2. 用系统 cron 调 Agent 得自己拼 prompt、管会话和投递，胶水代码不少；
3. 想让 Agent 有"例行公事"的持续性，而不是每次从零开始。

注意边界：心跳是固定间隔巡检，不是精确定时调度。"每天 9 点发日报"这种需求请用 OpenClaw 自带的 cron 任务，别塞进心跳。

## 怎么配

1. 打开工作区里的 `HEARTBEAT.md`。默认内容为空（或只有一级标题），此时心跳触发会被直接跳过，几乎零开销——这是刻意的省 token 设计，没事就别乱写。
2. 按条目写任务，每条说清三件事：**检查什么、什么条件算"有事"、有事时怎么汇报**。例如："检查 `~/repos/foo` 是否有新的远端提交；仅当落后超过 5 个提交时在群里说一句，否则保持安静。"
3. 调整频率就改心跳间隔配置（`intervalMins` 或对应环境变量）。15–60 分钟覆盖大多数巡检场景。
4. 看 Gateway 日志确认心跳在跑：每次触发能看到执行还是 skip，skip 通常意味着文件被判为空。

## 踩坑点

- **把重活写进心跳**。心跳是一次完整的 Agent run，跑长任务会占用会话、放大 token 消耗。重任务拆给 cron 或手动触发。
- **Agent 太爱汇报**。模型天然倾向"报告点什么"，任务描述里必须显式写"无事不打扰"，否则每半小时收到一条废话。
- **文件写错位置**。多 Agent 场景下每个 Agent 有独立 workspace，写错目录就是不生效，且报错不明显。
- **会话污染**。心跳产出默认进主会话上下文，高频心跳会把主对话搅乱。可配置独立投递，让巡检结果不和日常对话混在一起。
- **成本低估**。每跳是一次 run，工具调用越多越贵。上线前先手动按低频率观察几天。

## 可复用建议

- 把心跳文件当 crontab 维护：定期删过时条目，保持短小。
- 任务尽量只读、幂等；确需写操作，先在任务里限定明确路径。
- 建立团队约定：心跳默认静默，只有阈值触发才发声——"安静"是特性不是故障。
- 分工记法：巡检用心跳，定点用 cron，临时用对话。

## 总结

HEARTBEAT.md 的价值不是炫技式自动化，而是把那些"你想起才做"的小事，变成 Agent 替你记着的事。写得克制、汇报边界清晰，它就是一个安静的值班员；写得太满，它就是一个每半小时打扰你一次的话痨。先从一两条低频检查开始，跑稳了再加。
