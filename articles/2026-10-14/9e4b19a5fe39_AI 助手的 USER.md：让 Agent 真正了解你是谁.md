## 背景

大多数 Agent 框架都有项目级记忆文件——AGENTS.md、CLAUDE.md 这类，用来描述"这个项目怎么干活"。但它们回答的是"项目是谁"，不是"我是谁"。于是每次开新会话，Agent 都要重新打听：你主用 TypeScript 还是 Python、测试怎么跑、部署在哪、时区在哪、喜欢先给方案还是直接动手。跨项目使用时，这种重复尤其明显。

## 问题

这些信息其实高度稳定，却散落在每一次对话里。后果有三个：

1. Agent 输出永远偏"通用教程味"，因为它只能按最大公约数猜你的偏好；
2. 你反复解释，浪费的 token 和耐心都是真金白银；
3. 换项目、换机器后上下文清零，Agent 对你的"了解"没有任何积累。

## 做法

思路很简单：在用户级目录放一份 USER.md，作为全局上下文注入每次会话。以 OpenClaw 为例（其他框架同理，只要有全局 memory / bootstrap 注入机制即可）：

1. 新建 `~/.openclaw/USER.md`（或你框架对应的全局记忆路径），确认它会被默认加载进上下文；
2. 按固定骨架写，硬性控制在 40 行以内。我的骨架分五段：
   - **身份与环境**：常用语言、OS、时区、工作时段；
   - **技术栈与默认约定**：包管理器、lint 规则、目录习惯；
   - **协作偏好**：先方案后动手、diff 要小、不确定就问；
   - **明确不要做的事**：负向约束，见下文；
   - **正在做的事**：当前 1-2 个项目的一句话描述。
3. 建立"过期即改"规则：会话结束时如果 Agent 发现 USER.md 与事实冲突，让它主动提出，由你决定是否更新；
4. 纳入 dotfiles 仓库，多机同步。

## 踩坑点

- **写成了简历。** 第一版我写了 90 多行，结果 Agent 回复明显变啰嗦，还开始引用已过期的旧项目细节。现在控制在 40 行内，宁缺毋滥。
- **塞敏感信息。** API key、内网地址、客户名单一律不进 USER.md。它是每次会话都会读取的明文文件，泄露面和 .env 不在一个量级。
- **与项目级文件打架。** 项目里 AGENTS.md 说用 pnpm，USER.md 写着默认 npm，Agent 会随机站队。原则：USER.md 只放跨项目稳定的事实，项目特有约定全部下沉到项目文件，并在 USER.md 里写明"项目文件优先"。
- **偏好写成形容词。** "代码要优雅"没有信息量，"函数不超过 50 行、默认写纯函数不用 class"才有。负向约束尤其值钱：我写了"不要主动加注释、不要用 try-catch 包一切"，这几条几乎每次会话都在阻止坏输出。

## 可复用建议

- 把 USER.md 当**配置**而不是**文档**：事实化、短行、可 diff；
- 每季度花十分钟审一次，删掉不再成立的条目——过期信息比没有信息更糟；
- 让 Agent 参与维护：可以在会话里让它输出"建议新增/删除条目"的 diff，你审核后合并；
- 团队场景可派生一份 TEAM.md 承载共享约定，与 USER.md 分层，互不污染。

## 总结

USER.md 解决的不是模型能力问题，而是信息供给问题：Agent 不是不够聪明，而是一直在盲猜你是谁。一份 40 行以内、事实化、定期维护的用户级记忆文件，维护成本极低，却能让 Agent 在每个新会话里直接从"了解你"的状态开始干活。建议先按五段骨架起步，用两周，再根据实际摩擦修条目。
