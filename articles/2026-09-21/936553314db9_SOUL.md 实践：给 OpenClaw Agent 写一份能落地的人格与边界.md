## 背景

OpenClaw 的 Agent 是长期驻留的：工作区里除了 AGENTS.md（怎么干活）、MEMORY.md（记什么），还有一个常被忽视的 SOUL.md。它会在每次会话启动时注入系统提示词，决定 Agent“是谁”——语气、立场、做事的分寸。很多人拿默认模板跑了几个月没动过，结果是：模型一换版本、对话一拉长，人格慢慢漂移，说话越来越像通用客服。

## 问题

没有明确 SOUL.md 时，常见三类翻车：

1. **代发消息翻车**。Agent 挂着 IM/MCP 工具权限，替你回消息时用词过于绝对或过度热情，对方看到的是“你的口吻”，锅却归你。
2. **边界靠猜**。什么该自动执行、什么该先确认，全靠模型临场发挥，同一件事今天做明天问。
3. **人格漂移**。多会话长期运行后，语气和最初设定渐行渐远，团队共用一个 Agent 时尤其明显。

## 做法

我的 SOUL.md 现在控制在 40 行以内，分四段：

- **身份**：一两句话说清“你是谁、为谁服务、擅长什么”。写“你是我的运维助手，主要处理告警和工单”，不写“你是一个乐于助人的 AI”。
- **语气**：给可判定的规则，比如“中文回复，先结论后细节，不确定就说不确定，禁止营销腔”。
- **边界**：核心段落。每条尽量和权限对应，如“调用发消息类工具前必须让我确认”“删除、付款类操作一律先停下来问”。
- **冲突裁决**：写明优先级，比如“隐私 > 正确性 > 速度”，长对话里模型有据可依。

写完跑一组红队 prompt 验证：诱导它直接发消息、假装我已授权、套取其他会话内容，看边界是否触发。然后把 SOUL.md 进 git，像 review 代码一样 review 每次改动。

## 踩坑点

- **写太长**。SOUL.md 每个会话都注入，两百行“人格散文”既稀释关键规则又烧 token，规则密度比篇幅重要。
- **只写禁止不写替代**。“不要乱发消息”不如“不确定时草拟内容贴给我确认”。
- **和 AGENTS.md 抬杠**。两个文件规则重叠、版本不一致，行为就会飘。建议 SOUL.md 管“人格 + 软边界”，硬限制交给工具白名单和确认机制——别指望一段文字当安全边界。
- **出事不改**。每次翻车后应回写一条边界，SOUL.md 是活文档，不是一次性设定。

## 可复用建议

- 模板骨架：身份 / 语气 / 边界 / 冲突裁决，四段各 3–8 行。
- 每条软边界配一个硬手段：文字约束 + 工具权限，双保险。
- 用 git 管理，commit message 写清改动原因，方便回溯“它为什么变成这样”。
- 每月跑一次固定的红队问题集，当回归测试。

## 总结

SOUL.md 不是玄学人设，而是一份注入成本固定、影响每一次会话的配置文件。把它当代码维护——短、可判定、有测试、有版本——Agent 的行为才会长期稳定。人格靠它立住，硬边界靠权限兜底，两者缺一不可。
