## 背景

对话式 Agent 的默认形态是"你问它答"，它永远在等你。但我们真正想要的往往是个值班员：定时巡检日志、到期前提醒、异常时上报。OpenClaw 给出的方案很轻——工作区里放一个 `HEARTBEAT.md`，Agent 按固定周期读一遍，自己判断"现在有没有活要干"。没有 cron 表达式，没有额外服务，逻辑就是几行 Markdown。

## 问题

用 cron + 脚本也能做定时任务，但决策逻辑是死的。"如果今天比昨天降温超过 8 度，提醒我带外套"，这种带语义的条件分支脚本很难写，heartbeat 文件里一句话就够。代价是引入了模型调用成本和不确定性——所以它适合低频、判断语义化、动作短小的场景，不适合当万能调度器。

## 做法

**1. 建文件。** workspace 根目录放 `HEARTBEAT.md`（默认在 `~/.openclaw/workspace/`，多 Agent 时每个 workspace 一份，天然隔离）。

**2. 配周期。** 在 `openclaw.json` 里：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": { "every": "30m" }
    }
  }
}
```

**3. 写条目。** 每条 = 触发条件 + 动作 + 无事时的行为：

```markdown
- 每天 09:00 前后，汇总昨天全部 commit，三条以内摘要发我。
- 若 ~/logs/error.log 上次检查后新增 ERROR，摘录并给定位建议；否则不回复。
- 周五 17:00 输出本周待办完成度。
```

**4. 理解 tick 语义。** 每个 tick，系统往主会话注入一条轻量提示让 Agent 读该文件；无事可做时 Agent 回 `NO_REPLY`，这条消息会被吞掉、不推送给你。文件为空或不存在，tick 直接跳过，零 token 成本。另外默认只在 Active Hours（本地白天时段，可配置）触发，深夜不会打扰。

## 踩坑点

1. **文件非空 = 每 tick 一次 LLM 调用**，哪怕最终 `NO_REPLY`。先跑 30 分钟粒度看日志和成本，多数任务根本不需要 5 分钟一次。
2. **条件必须写进文件**，别指望模型自己猜边界。"什么情况动作、什么情况不回复"要明说，否则它会周期性给你发废话。
3. **污染主会话上下文。** heartbeat 跑在主会话里，动作要短平快，别在里面安排"全库重构"级别的长任务。
4. **时间判断靠模型而非 cron**，"每天 9 点"实际可能 9:07 触发，条目里写"09:00 前后"更符合现实。
5. **权限收窄。** heartbeat 意味着无人值守调用工具（shell、发消息）。先在最小权限沙箱里验证，再逐步放开，别一上来给 root 加全通道发送。

## 可复用建议

- **模板化**：文件固定分三段——固定巡检、条件提醒、周期报告，加任务只加条目。
- **状态外置**：让任务把"上次检查时间/游标"写到 workspace 的小文件里，heartbeat 读它做增量判断，比依赖会话记忆可靠得多。
- **分级部署**：巡检类任务单独开一个 Agent、独立 workspace 和独立周期，与主助手隔离，互不挤占上下文。
- **固定交付渠道**：用 heartbeat 的 target 配置把输出路由到指定会话，避免"消息发到我不知道的地方"。

## 总结

HEARTBEAT.md 的本质，是把触发器从"人的提问"换成"时间 + 文件里的条件"，而判断仍由模型完成。它的甜点区是：低频、语义化条件、短动作。建议从一条任务、30 分钟周期起步，观察一周日志和账单，再决定要不要加第二个。
