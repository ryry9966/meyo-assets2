## 背景：会话是无状态的，身份不该也是

LLM 本身没有记忆，每次新会话人格归零。OpenClaw 的做法很朴素：把身份写进工作区里的一个 Markdown 文件——IDENTITY.md。会话启动时，引导流程会把它和 AGENTS.md、SOUL.md、USER.md 一起注入上下文，Agent 从第一条消息起就知道"我是谁"。

关键在于：它只是一个文件。你可以编辑，Agent 自己也能编辑（前提是它有工作区写权限）。这就给"身份可进化"提供了物质基础。

## 问题：身份散落在 prompt 里，改一次痛一次

没有这套机制时，常见做法是把人设塞进系统提示词或反复口头强调。实际用下来有三个问题：改人设要动配置、重开会话、逐个渠道验证；多 Agent 场景下人设容易互相覆盖；最麻烦的是完全无法追踪"Agent 是什么时候变成这样的"。

## 做法：五步跑起来

1. **定位文件。** 默认工作区在 `~/.openclaw/workspace/`，确认 IDENTITY.md 存在，没有就新建。最小模板：

```markdown
# IDENTITY.md

- **Name:** 小爪
- **Creature:** 机械章鱼
- **Emoji:** 🐙
- **Vibe:** 冷静、先给结论再给依据、不说客套话
- **Avatar:** assets/avatar.png
- **Notes:** 同一问题解释两次后，提醒我沉淀成文档
```

2. **验证注入。** 开新会话（`/new` 或重启网关），让 Agent 自我介绍一遍。注意身份文件是会话启动时读取的，中途改文件不会热生效。

3. **打通进化回路。** 在 AGENTS.md 里加一条约定："某类偏好重复出现三次以上时，可在回复末尾提议一条 IDENTITY.md 的 diff，由我确认后写入。"要点是提议制，不是 Agent 直接改。

4. **定时反思（可选）。** 用 heartbeat/cron 跑一个反思 prompt，让 Agent 审视当前身份与实际交互的偏差，输出变更建议。频率别高于每天一次。

5. **纳入 git。** 身份每次变化都是一个 commit，出问题回滚一个 diff 的事。

## 踩坑点

- **会话中途改文件不生效。** 身份在 bootstrap 阶段注入，改完务必开新会话验证，不要在旧会话里反复调试。
- **文件写太长。** IDENTITY.md 每个会话都吃上下文，十几行足够。人设背景展开成千字文会稀释行为，还烧 token。
- **职责混淆。** "我是谁"放 IDENTITY.md，"用户是谁"放 USER.md，"怎么干活"放 AGENTS.md，"记住了什么"放 memory。把任务知识塞进身份文件是最常见的坏味道。
- **沙箱只读。** 文件工具对工作区只读的话，进化回路直接断了，配完记得让 Agent 试写一次。
- **IDENTITY.md 与 SOUL.md 冲突。** 两个文件说反话时行为会很怪，动一个之前先 grep 另一个。

## 可复用建议

- 把身份当配置代码管理：小步提交、diff 审查、可回滚，别在聊天窗口里口头改人设。
- 变更走"提议—确认"两段式，保持人在环上，避免身份漂到不可控的方向。
- 多 Agent 各用各的工作区和文件，不要为省事共用一份 IDENTITY.md。
- 每隔一两个月重读一遍当前文件，问自己：这还是我想要的样子吗？不需要就让 Agent 提议精简。

## 总结

IDENTITY.md 的价值不在于"给 AI 起名字"这种仪式感，而在于把人格从不可追踪的提示词，变成可版本化、可审查、可协作编辑的工程对象。文件很小，但它把"身份由谁定义"这个问题的答案，从"谁最后说的算"变成了"git log 说的算"。建议每个跑 OpenClaw 的用户都花十分钟，把这份文件从默认模板改成一份有意识的配置。
