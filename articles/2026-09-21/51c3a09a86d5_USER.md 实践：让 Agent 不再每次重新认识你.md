# 背景

用 OpenClaw 一段时间后，你会发现一个尴尬的模式：Agent 记得住"上周做了什么"，却记不住"你是谁"。时区、工作语言、主力技术栈、命名习惯、"回复要短"、"不要自动 push"——这些几乎不变的偏好，每个新会话都要重新交代一遍。

工作区里其实早有分工：`SOUL.md` 管 Agent 是谁，`MEMORY.md` 管发生过什么。唯独"用户是谁"缺一个稳定载体。系统提示词太静态，自动记忆抽取又有损、容易捞进噪音。`USER.md` 就是补这个缺口的：一份由你自己维护、每次会话随工作区注入上下文的 Markdown 文件。

# 怎么写

在 workspace 根目录（默认 `~/.openclaw/workspace/`）创建 `USER.md`，固定分区：

```markdown
# 环境
- 时区 Asia/Shanghai；沟通用中文，代码和注释用英文
- 主力机 macOS + Linux 服务器，shell 用 zsh

# 技术栈
- Python 3.12 / TypeScript；包管理 uv、pnpm
- 正在维护 2 个 OpenClaw 插件

# 协作偏好
- 先给结论和代码，不要铺垫
- 禁止自动 git push，不要碰生产环境
- 方案先列两个选项，再给推荐

# 当前重点（2025-06）
- 值班告警自动化，目标是减少人工介入
```

要点三条：

1. **短**。整文件控制在 60 行内，它每个会话都要进上下文，写长了就是持续的 token 税。
2. **写可执行的参数，不写自我介绍**。Agent 不需要履历，需要的是能据此调整行为的条目。
3. **进 git**。偏好变更走 diff，Agent 行为为什么变了，你随时可查。

# 让 Agent 参与维护，但别让它说了算

可以养成一个动作：每月让 Agent 读一遍 `USER.md` 加近期会话，输出"建议新增/删除/修改"的 diff，你确认后合入。文件不会烂掉，也不会因无人审核的自动改写而漂移——见过有人把它放任 Agent 自己改，最后改成了一篇小作文，恢复比重写还费劲。

# 踩坑点

- **过期信息比没有更糟**。Python 从 3.10 升到 3.12 忘了更新，Agent 会一直按旧版本给兼容建议。变动的当天顺手改。
- **敏感信息别进文件**。API key、真实住址、证件号不写，这个文件可能被同步、备份、带进日志。
- **和 MEMORY.md 划清边界**。判断标准：每月都在变的进 MEMORY.md，季度级才变的才配进 USER.md。两边重复会出现互相矛盾的指令。
- **形容词无效**。"希望专业一点"没法执行；"先给结论""给两个备选"才行。

# 可复用建议

- 用固定模板起步，五个分区封顶：环境、技术栈、协作偏好、禁区、当前重点。
- 每季度做一次十分钟 "profile lint"：逐条问"这条还能约束 Agent 行为吗"，不能就删。
- 多角色用户可拆多份 USER.md（个人/工作），按 agent 实例分别挂载。

# 总结

USER.md 的价值不在文件本身，而在"保持它为真"的纪律。它便宜、可控、可版本化，是把通用助手变成"你的助手"这件事里，投入产出比最高的动作之一。先写 20 行，用一个星期，再决定加什么。
