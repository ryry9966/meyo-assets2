## 背景

我们在社区里跑了一个基于 OpenClaw 的自动发帖流程：定时任务拉取仓库 issue、RSS 和周报摘要，Agent 整理后通过 MCP 工具发到论坛和群。跑了两周，效率不错，但群友反馈很直接：“整点报时”“一看就是机器发的”。内容本身没问题，问题出在节奏上。

## 问题：机器人感来自统计规律

复盘下来，被识别成机器人不是因为单条内容差，而是时间序列太规整：

- 每天 09:00:00 整触发，秒级精确；
- 三帖间隔恒定四小时，像闹钟；
- 内容模板指纹重：同样的开头、同样的 emoji、同样的标签顺序；
- 账号只有“发”这个动作，从不回复、不引用，评论区永远沉默。

人不是 cron。人类发帖时间近似泊松过程——有集中、有空档、有偶尔的深夜爆发。节奏控制的本质，就是给这些可预测的统计量加上合理范围的噪声。

## 做法：三层控制 + 一个人工卡点

**1. 时间层：抖动窗口**

不要在 cron 里定死时刻，触发后做二次延迟采样。比如目标“早上九点”，就在 08:40–09:50 之间按正态分布取值（σ≈25 分钟），并刻意避开整点和半点。工作日和周末用不同窗口。

```python
import random, datetime

def jitter(target_hour, sigma_min=25):
    base = datetime.datetime.now().replace(
        hour=target_hour, minute=0, second=0)
    delay = random.gauss(0, sigma_min * 60)
    return base + datetime.timedelta(seconds=delay)
```

**2. 频率层：配额与空窗**

设每日配额上限（我们定为 3）和最短间隔（90 分钟），每周随机抽 1–2 个“空窗日”完全不发。注意空窗日必须每次随机生成，不能固定周几。有事件驱动的热点内容时，例行内容主动让路。

**3. 内容层：去模板指纹**

开头结尾句式池至少 5 套轮换；emoji、标签、分段方式在有限集合内随机组合；摘要长度允许自然波动，不追求固定字数。时间和内容只去一个指纹，另一个就会暴露你。

**4. 行为层：让账号呼吸**

发帖后 30–60 分钟内安排一次评论区巡检，有回复就回，且回复延迟别低于几分钟。用 OpenClaw 的事件监听加延迟队列很容易实现。

**5. 人工卡点**

周报、公告这类高风险内容先进草稿箱，人工一键放行。全自动只留给低风险、例行性的短内容。

## 踩坑点

- 抖动窗口太窄：只在整点后 0–10 分钟随机，等于没抖；
- 随机源固定了 seed，模式每隔一周精确重复；
- 时区错位：服务器是 UTC，“早九点”实际发在东八区下午五点；
- 回复太快：Agent 十秒回评论，比人快两个数量级，反而更假；
- 把平台限流当节奏控制——被踢了才降速是被动挨打，配额要主动设。

## 可复用建议

1. 把“何时发”做成独立配置层，与“发什么”解耦：窗口、方差、配额、空窗日全部可配。
2. 像写测试一样自检：定期导出自己的发帖时间序列，画间隔直方图、看整点占比，规律一眼就能看出来。
3. 一条原则：凡是统计上可预测的量——时间、间隔、长度、句式——都给它加一个合理范围的随机性。
4. 宁少勿滥。低密度高质量活得久，高密度低质量是最快的社死路径。

## 总结

机器人感不来自某一条帖子，而来自时间与内容上的双重规律。工程上就三件事：时间抖动、频率配额、内容去指纹，再加一层人工卡点和定期自检。调整之后，我们的帖子再没被点名“像机器”，一个重要的副产品是：发帖量降了四成，互动率反而上去了。
