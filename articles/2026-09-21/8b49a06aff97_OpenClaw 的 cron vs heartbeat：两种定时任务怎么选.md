## 背景

OpenClaw 给 agent 内置了两条"定时干活"的路径：**cron job**（基于 cron 表达式的精确调度）和 **heartbeat**（固定周期的自主巡检）。两者都能让 agent 在你没盯着的时候做事，但触发逻辑完全不同。最常见的错误是只抓着一个用：要么全交给 cron 把巡检拆成几十条任务，要么全靠 heartbeat 结果账单和时间精度双双失控。

## 问题

我最早把两类需求全塞给了 heartbeat：每日早报让它"顺带"发，异常盯梢也靠它。跑两周暴露两个毛病：

- **时间不精确**：heartbeat 只保证间隔、不保证时刻，早报经常 9:10、9:40 才到；
- **成本线性上涨**：默认 30 分钟一跳，一天 48 次带完整上下文的模型调用，其中绝大多数心跳其实无事发生。

反过来，把所有"时不时看一眼"的需求写成几十条 cron，改一个检查项要挨个编辑任务，维护不动。

本质区别一句话：**cron 是"你决定何时触发"，heartbeat 是"agent 每个周期醒来，自己判断要不要做"**。前者的判断逻辑写在你的 message 里；后者的判断权在模型。

| 维度 | cron | heartbeat |
|---|---|---|
| 触发依据 | cron 表达式 / 一次性时间点 | 固定周期 |
| 决策者 | 你（写在指令里） | agent（结合清单自行判断） |
| 时间精度 | 分钟级、确定 | 只保证间隔 |
| 成本模型 | 触发才产生调用 | 每周期一次调用 |
| 适合 | 定时报表、提醒、数据同步 | 异常巡检、待办兜底 |
| 不适合 | "有事才做"的条件任务 | 精确时刻触发 |

## 做法

### 1. 时间确定的活 → cron

```bash
# 工作日每天 9:00 出值班摘要，跑在隔离会话
openclaw cron add --name "morning-brief" \
  --cron "0 9 * * 1-5" \
  --message "汇总昨晚告警和未合并的变更，输出值班摘要" \
  --session isolated
```

一次性任务（"明早 8 点提醒我"）也走 cron 的单次调度，具体参数看 `openclaw cron add --help`。写完先 `openclaw cron run <id>` 手动触发一次，验证输出和投递链路，再等真实触发。

### 2. 有事才做的活 → heartbeat

在配置里开启（键名以你版本文档为准）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": { "every": "30m" }
    }
  }
}
```

然后把巡检清单写进工作区的 `HEARTBEAT.md`，agent 每次心跳会参照它逐项判断：

```markdown
# 巡检清单
- 有未处理的告警？→ 汇总并通知
- 今日备份已跑且成功？→ 否则提醒
- 其余情况：HEARTBEAT_OK
```

关键是最后一条：agent 判断无事时回复 `HEARTBEAT_OK`，消息不会被推送，这就是"沉默成本"的控制阀门。

### 3. 推荐混合部署

cron 负责"定时必做"（早报、日报、同步），heartbeat 负责"空闲巡检"（异常、待办兜底）。两者叠加，覆盖绝大多数自动化场景。

## 踩坑点

1. **心跳间隔过短**：5 分钟一跳就是一天 288 次调用。从 60m 起步往下调，观察成本和漏报率。
2. **HEARTBEAT.md 写成散文**：判断标准模糊，agent 每次行为漂移。必须写成可判定的"是/否"检查项，并写明默认动作是沉默。
3. **时区**：cron 按 gateway 所在机器的时区跑，容器里默认 UTC，`0 9 * * *` 实际是北京时间下午 5 点。上线前用测试任务验证一次。
4. **一个 cron 塞多个目标**：失败难定位。一个任务一个目标，出问题可以单独 `run` 复现。
5. **心跳"消失"**：刚结束人工对话会触发活跃会话抑制，心跳推送被静默，这是设计行为，不是坏了。
6. **cron 输出堆在主会话**：污染日常上下文，建议隔离会话 + 显式指定投递渠道。

## 可复用建议

- 一条判断标准：**能写成 cron 表达式的用 cron；只能描述成"隔一阵看一眼有没有事"的用 heartbeat**。
- 心跳清单控制在 5 项以内，每项必须是可判定的检查，不是模糊目标。
- 关键 cron 任务先手动 `run` 验证投递，再等真实触发。
- 任务命名带"频率 + 用途"（如 `daily-brief`、`hourly-sync`），每月 `openclaw cron list` 清理僵尸任务。

## 总结

cron 是日程表，heartbeat 是值班直觉。前者适合"我知道什么时候该干"，后者适合"我不确定有没有事、但希望它自己看一眼"。别用 heartbeat 追时间精度，也别用 cron 堆条件判断——各司其职，再加一个写清楚的 HEARTBEAT.md，OpenClaw 的自动化就稳了。
