## 背景

多数人用 Agent 的方式是问答式：你发消息，它响应。OpenClaw 有一个容易被忽略的机制——heartbeat（心跳）。Agent 每隔一段时间被自动唤醒一次，读取工作区里的 `HEARTBEAT.md`，按里面的约定决定"要不要做事、要不要汇报"。这是把 Agent 从被动应答器变成主动值守进程的最简单入口：不用写插件，不用接 MCP，一个 Markdown 文件就够。

## 问题

实际使用中，大量任务本质是"巡检"而非"应答"：每天早上汇总昨天的 git 提交、检查磁盘占用和证书有效期、盯一个 RSS 源、提醒某个待办。这些事用对话式交互很别扭——你得记得去问，Agent 永远不会主动说。`HEARTBEAT.md` 就是解决这个错位的：把"什么时候检查什么、怎么汇报"写成文件，Agent 在每次心跳时自己执行。

## 做法

1. 在 Agent 工作区（workspace 目录）下创建 `HEARTBEAT.md`。
2. 内容建议三段式：**检查项**（每条写清触发条件 + 动作）、**汇报格式**（发到哪个会话、什么粒度）、**安静规则**（无事可做时直接结束，不发消息）。
3. 在 `openclaw.json` 里配置心跳间隔（`agents.defaults.heartbeat.every`），默认 30 分钟，可按 agent 覆盖。
4. 先把间隔设成 5 分钟验证链路跑通，再调回 30–60 分钟的常规值。
5. 复杂动作交给 skill 或 MCP 工具完成，`HEARTBEAT.md` 只负责"何时 + 检查什么 + 怎么汇报"，别把具体步骤全塞进去。

示例片段：

```markdown
# 每次心跳
- 若最近一次 git fetch 有新提交：汇总 commit 标题，发到 #dev。
- 检查 ~/.certs 下证书有效期 < 14 天：发警告，写明域名和剩余天数。
- 都不满足：不做任何事。
```

## 踩坑点

- **空文件也会触发执行**：留一句"无事可做直接结束"，否则每个心跳周期白烧一次 token。
- **任务不幂等就会复读**：磁盘一直超阈值，你就每半小时收一条同样的警告。让 Agent 先查上次状态（比如写个 `.last-state` 文件），有变化才报。
- **文件别写长**：`HEARTBEAT.md` 每次心跳都会进上下文，写满几百行等于定时烧钱。
- **别用心跳做精确调度**：它不是 cron。到点必须执行的任务用 cron 触发，心跳适合"状态巡检"这类模糊周期任务。
- **汇报目标要先确认**：没指定会话目标时，消息可能发到默认频道，建议先小范围验证再放开。

## 可复用建议

- 把 `HEARTBEAT.md` 当配置代码管理：进 git，改动走 diff，出问题可回滚。
- 所有检查项统一成"条件 / 动作 / 静默规则"三要素，Agent 的遵循度会高很多。
- 如果你的版本支持，给心跳单独配低成本模型，主会话模型留给对话。
- "状态文件 + 去重"模式可以推广到任何巡检类自动化，不限于心跳场景。

## 总结

`HEARTBEAT.md` 的价值不在功能多强，而在它把"主动"这件事从工程问题降级成了写一个 Markdown 文件。先从一两条真实的巡检需求开始，控制间隔、控制篇幅、保证幂等，你会得到一个会自己干活的 Agent，而不是一个更贵的聊天机器人。
