# 背景

E2E 测试是工程里最“贵”的一类资产：写起来慢、selector 容易碎、页面一改版就大面积红。很多团队的应对方式是少写、只盖核心链路，回归全靠人肉。Agent + 浏览器 MCP（比如 Playwright MCP）改变了一点成本结构：agent 可以真实打开页面、点按钮、读 DOM，再据此生成测试代码——它不再是凭想象写 `page.click`，而是先操作一遍。

# 问题

直接丢给 agent“帮我生成登录的 E2E 测试”，产出通常有三类毛病：

1. **选择器幻觉**：写出 `.btn-primary > span:nth-child(2)` 这类看似合理但页面里根本不存在的路径；
2. **断言过弱**：只断言“没抛异常”，不断言业务结果（订单号、跳转 URL、列表条数）；
3. **脆弱等待**：`sleep(3000)` 一把梭，本地能过、CI 时灵时不灵。

本质原因是：agent 没看过你的真实页面，也没继承你的测试规范。

# 做法

我们在 OpenClaw 里把这件事拆成一条可复用的流程，核心思路是**先操作、后生成、再收敛**：

**1. 喂上下文。** 把测试目录约定、fixture/helper、data-testid 规范、常用登录姿势写进一个 skill 的说明里，agent 启动时自动携带。没有这一步，每次生成物风格都不一样。

**2. 让 agent 用浏览器 MCP 走一遍真实流程。** 明确要求“先探索、再写码”：打开目标页面，记录每一步实际可用的 selector、接口响应和页面状态，探索结果作为中间产物落盘。

**3. 带约束生成。** prompt 里写死硬规矩：优先 data-testid；禁止 nth-child 长链；禁止固定 sleep，统一用 auto-waiting 断言；每个用例头部注明对应的用户故事。一次只生成 3–5 个用例。

**4. 失败回喂。** 测试跑挂后，把报错、截图、trace 丢回给 agent 让它修，限制 2–3 轮，超过就转人工。多数失败是 selector 漂移和异步没等够，agent 自己能收敛。

**5. 沉淀。** 把“探索 → 生成 → 自修”封成一个 OpenClaw 插件命令，日常一句话触发；CI 里只跑生成的 smoke 子集，控制时长。

# 踩坑点

- **别一次生成几十个用例**。评审成本会反噬收益，小批量迭代才可持续。
- **测试数据要隔离**。agent 很自然地复用环境里的脏数据，建议每条用例自己造数据、自己清理。
- **flaky 别用重试掩盖**。retries 能让报告变绿，但会掩盖真实的不稳定，先修因再谈重试。
- **MCP 会话设超时**。agent 探索时偶尔卡在弹窗或意外跳转上，不设超时会一直挂着占资源。

# 可复用建议

- 把约束清单（selector 规范、断言要求、命名规则）固化成 prompt 模板放进 skill，比每次手写 prompt 靠谱得多。
- 生成的用例保留“用户故事注释”，PR 评审先看注释是否成立，再看代码。
- 先盖 golden path，再让 agent 补边界场景；边界用例人工确认后再入库。

# 总结

Agent 写 E2E 的价值不在“一键生成”，而在把写测试从手工编码变成**审核 + 收敛**：agent 负责探索和初稿，人负责判定哪些行为是业务真正要守护的。规范前置、小批量生成、失败回喂——这三件事做好，E2E 覆盖率就能以很低的边际成本慢慢涨上来。
