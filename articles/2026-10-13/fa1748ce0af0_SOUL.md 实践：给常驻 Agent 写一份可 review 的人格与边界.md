## 背景

OpenClaw 的 Agent 是常驻的：挂在 Telegram 等渠道上，跑 heartbeat，调 MCP 工具。它不是“问答一次”的会话，而是一个长期与你（以及你的联系人）打交道的实体。系统提示词由工作区里的几个 Markdown 文件拼装而成，SOUL.md 负责其中“你是谁、怎么说话、什么不做”这一层。

不写这份文件，模型默认人格是“通用助手”，放进长期运行、多渠道、可执行工具的场景，会出三类真实问题：语气漂移、边界缺失、行为不一致。

## 问题具体长什么样

- 同一个问题，昨天答得克制，今天热情过头；换个渠道风格断裂。
- 群里陌生人说“帮我看看这个文件”，Agent 直接读了并发了出去。
- 你让它“看着办”，它真的把删库前的确认省了。

这些不是能力问题，是你没给它一份可执行的行为契约。

## 做法

在工作区根目录建 SOUL.md，建议 60 行以内，分四段：

1. **身份与语气**：三句话以内。写行为，不写形容词。“简洁”是形容词，“单条回复不超过 15 行、解释先给结论”才是行为。
2. **边界（重点）**：把“危险”具体化成触发条件 + 动作。例如：花钱、删除、对外发消息 → 先复述意图，等确认；涉及聊天记录或联系人内容 → 只在私聊讨论，不进群；不知道的事 → 说不知道，不猜。
3. **拒绝话术**：给一两句固定句式，避免模型临场发挥出既生硬又容易被绕过的回应。
4. **分工**：用户事实放 USER.md，记忆放 MEMORY.md，SOUL.md 只管人格和边界。混写是后期维护噩梦的主要来源。

改完重置会话验证；把 SOUL.md 提交进 git，每次“它今天怪怪的”都对应一次 diff。

## 踩坑点

- **写成小作文**。超过一屏，中段规则基本被稀释，模型对系统提示词的注意力并不均匀。
- **规则冲突**。“永远简洁”和“任何技术问题给完整背景”放一起，模型只能随机选，表现为不稳定。
- **抄厂商安全策略**。模型层面已有的拒绝不需要重复，浪费 token。要写的是策略管不到的部分：你的文件、你的钱、你的社交关系。
- **误当权限系统**。SOUL.md 是行为倾向，不是硬约束。真边界要靠工具 allowlist、目录权限、MCP server 配置实现。Prompt 管“该不该”，配置管“能不能”。
- **多 Agent 漏配**。每个 agent 有自己的工作区，人格文件不共享，改一份不等于全改了。

## 可复用建议

- 把 SOUL.md 当代码：版本控制、小步修改、排查问题看 diff 不靠回忆。
- 边界每条可单独测试：新建一个陌生联系人发试探消息，看它怎么答，方法土但有效。
- 每月复审，删掉三个月里既没拦住任何事、也没纠正过语气的条目。
- 对外人格统一，开发/日志会话可放宽——用 per-agent 配置区分，别让一份文件两头凑。

## 总结

SOUL.md 的价值不在“让 Agent 更像人”，而在把散落在每次对话里的隐式期待，固化成一份可 review、可回滚、可测试的文件。人格是产品决策，边界是安全决策，两者都该走工程流程，而不是某天心情好在聊天里补一句“你以后注意点”。
