最近 36kr 一篇报道刷了屏：一个叫 REA 的开源项目，三天在 GitHub 拿下 12 万 star，卖点是"无需源码，Agent 就能复刻任意软件"。评论区迅速分成两派：一派喊"软件行业要完蛋了"，另一派说"又是 demo 驱动的狂欢"。先别急着站队，这篇文章把这台机器拆开看：它到底在做什么？能做到哪一步？真正被改变的又是什么？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/bfb1a3842e22fa41.png)

## 一、它到底在做什么：一次"行为级反编译"

传统复刻软件有两条老路：

- 拿到源码，读懂再改——门槛高，而且多数商业软件根本不给源码；
- 截几张图丢给 AI 生成前端——只能得到一层"看起来像"的皮。

REA 这类项目走的是第三条路：把"源码"换成"行为"。

1. Agent 像真人用户一样操作目标软件：点按钮、填表单、切页面、走完核心流程；
2. 多模态模型在每一步截图，识别界面元素、状态变化和业务逻辑，把"看到什么 → 做了什么 → 出现什么"整理成结构化规格；
3. 代码生成模型再把这份规格翻译成可运行的工程，产出前端、交互和基础后端。

打个比方：传统逆向工程是"拆开发动机看零件"，这套方案是"坐进副驾看司机开了三天车，然后自己学开车"。学术上接近 behavior cloning（行为克隆）的思路——不重建内部结构，只从外部观测重建输入输出关系。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/8eec1008e2271be5.png)

## 二、为什么偏偏是现在：三块拼图刚好凑齐

"AI 复刻软件"的想法 2023 年 AutoGPT 就火过一轮，当时翻车的原因很简单：模型"看得懂"但"点不准、写不全"。这两年三件事同时成熟：

1. GUI Agent 能力上线：多模态模型对屏幕元素的定位、点击、表单填写准确率大幅提升，各类系统级 benchmark 的任务通过率从个位数爬到了可用的水平；
2. 代码生成跨过"能跑"门槛：Cursor、Claude 类工具让"生成一个能启动的项目"成为日常，而不是抽奖；
3. 开源社区的放大器效应：star 数本身就是传播素材，热度自我强化，媒体跟进后进一步破圈。

所以"三天 12 万星"不是单一奇迹，而是能力临界点 × 传播机制的乘积。

## 三、它克隆了哪一层，克隆不了哪一层

把"软件"摊开，至少有五层：代码层、体验层、数据层、运营层、合规层。Agent 克隆的是前两层里最薄的部分，后面三层基本碰不到。

克隆得动的：

- 界面与交互：按钮布局、页面流转、操作路径；
- 功能清单：demo 级别的"你有的我也有"。

克隆不动的：

1. 数据与网络效应：复刻一个二手交易平台的全部页面，卖家和买家依然在原平台。用户、内容、关系链不跟着界面走；
2. 后端复杂度：支付对账、风控规则、库存一致性、高并发架构——这些不在 UI 里，黑盒观测根本看不到；
3. 集成与合规：银行、税务、企业内部系统的对接，认证资质、数据合规要求，这不是代码问题，是资质和信任问题；
4. 持续运营与 SLA：软件价值的一半是"明天还能用、出了事有人负责"，克隆出来的项目没有这句话。

类似戏码历史上演过很多轮：千团大战时团购网站的界面被抄了个遍，最后活下来靠的是地推和供应链；大量社交 App 换皮上线，死在冷启动。复刻 UI 从来不难，难的是界面背后那坨东西。

## 四、真正被改变的：软件的"边际成本"塌了

与其争论"软件完蛋了吗"，不如看成本曲线发生了什么。过去做一个可用产品要数月工程，现在 demo 以天计、MVP 以周计。几个确定性影响：

1. 小团队：验证想法的成本大幅下降，agent 相当于一台"超高速原型机"，试错循环从月级压缩到天级；
2. 大厂：功能层面的护城河贬值，竞争重心被迫从"做出来"转向数据、生态、分发、信任这些克隆不了的地方；
3. 从业者：纯 CRUD、纯切图的岗位价值承压；懂业务、懂数据、懂系统设计的人更值钱；
4. 行业副作用：同质化加速——凡是"agent 一晚上就能克隆的功能"，本身就不配做长期壁垒，这反而逼着所有团队往深处走。

当然要泼盆冷水：目前这类项目的演示普遍精彩、工程普遍粗糙。"看起来像"和"在异常路径、安全边界、百万并发下跑得稳"之间，隔着测试、可观测性、权限模型这些又脏又硬的活——而它们恰恰是黑盒克隆最难覆盖的部分。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/ea8fc319fdbf7fdc.png)

1. 判断产品被"克隆"的风险，别盯着代码，先问一个问题：它有没有源码以外的东西？私有数据、双边网络、深度集成、合规资质，占得越多越安全；一样都没有，那它本来就该被更快地迭代掉；
2. 把它当工具用，而不是当威胁看：竞品交互调研、内部工具批量生成、原型快速验证，这些场景现在就能吃到红利，先行者已经把 agent 写进了日常工作流；
3. 技能上向"克隆不了的层"迁移：数据管道、系统架构、安全、领域知识、跟人打交道的能力——站到 agent 的上游去，别挤在它的下游。

软件不会完蛋，会完蛋的是"只靠壳赚钱"的软件。做产品的道理跟做龙虾一样：壳是用来挡伤害的，肉才是重点。
