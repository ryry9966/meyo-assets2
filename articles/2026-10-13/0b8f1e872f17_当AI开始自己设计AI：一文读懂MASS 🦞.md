热搜上出现「UC Berkeley、Sakana AI 团队提出 MASS」，后面还跟着一个更唬人的词——RSI（Recursive Self-Improvement，递归自我改进），很容易被读成「AI 要自己进化起飞了」。剥掉修辞，这其实是一件工程上很具体、可量化评测的方法论工作：**让 AI 自动设计 AI 的 Agent 团队**。这篇讲清楚四件事：MASS 是什么、怎么跑、为什么会被挂到 RSI 上、以及热搜表述里哪些地方要打折扣。

## MASS 到底是什么：不是新大模型，而是新的「元层」方法

先钉死一个最容易混淆的点：MASS 并没有训练出一个参数更多的新 LLM，它做的是模型之上的那一层——**多 Agent 系统（Multi-Agent System）的自动化设计**。中文媒体有的译作「多 Agent 自监督」，有人理解成「多 Agent 系统搜索」，都差不离：前者描述它的反馈方式，后者描述它的方法论。

它自动化的，是过去由人类 Agent 工程师手工拍板的三类决策：

1. **模型选择**：每个 Agent 用哪个底层模型，用大的还是小的、贵的还是便宜的；
2. **Prompt 设计**：每个 Agent 的 system prompt 写什么、扮演什么角色；
3. **拓扑结构**：Agent 之间谁把输出传给谁、谁给谁挑错、谁负责汇总。

方法上大致是进化搜索 + 多目标优化：维护一个候选系统种群，经历「生成 → 在基准上打分（效果 + 推理成本）→ 留优汰劣」的循环。最终产出的不是单一设计，而是一整条 **Pareto 前沿**——一组在性能与成本之间做取舍的最优设计集合。

打个比方：以前工程师靠手感调 prompt 到凌晨三点，现在这份活外包给了进化算法。

## 它怎么跑：把「工程经验」变成一个搜索问题

理解 MASS 的关键是：它把「怎么搭一个好用的 Agent 团队」这个模糊问题，变成了一个目标函数可计算的优化问题。流程可以拆成四步：

1. **定义任务**：给定任务数据集和评测基准（研究型、Agent 型任务等）；
2. **生成候选**：由系统自身的「设计者 Agent」写出候选的多 Agent 配置，也就是上面三个旋钮的一种组合；
3. **评估**：每个候选在任务性能、调用成本两个目标上打分；
4. **迭代**：在「性能-成本」平面上保留非支配解（Pareto 前沿），在其基础上做变异和组合，进入下一轮。

所谓「自监督」，指的是评估信号几乎全部来自自动化 benchmark 与成本核算——中间不需要人类逐步打分，反馈闭环自动完成。

搜出来的配置常常是人类直觉想不到的组合，比如「搜索用便宜小模型、校验用昂贵大模型、中间结果落盘共享再汇总」这类分工。

## 为什么会被挂到 RSI 上：一个 60 年的老想法落进工程轨道

RSI 不是新概念，它的脉络值得捋一下：

- 1965 年，统计学家 I. J. Good 提出：一旦出现能设计更聪明机器的机器，就会引发「智能爆炸」；
- 2003 年，Schmidhuber 的 Gödel Machine 形式化描述了自改进程序的理想形态；
- 2024 年的 **ADAS**（Automated Design of Agentic Systems）：让 Agent 写代码生成新的 Agent，开启「Agent 设计 Agent」的先河；
- 2025 年的 **Darwin Gödel Machine**：一个会修改自身代码库的编码 Agent，在 SWE-bench 上把成绩从约 20% 自我迭代到了约 50%。

MASS 的位置，是把自动化的对象从「单个 Agent 的代码」上移到「多 Agent 系统的完整配置」，并引入成本这个工程上绕不开的目标。这条线的共同特征是：人类只负责定义任务和评估，中间的「设计」环节逐步交给 AI 自己。热搜里的「RSI 新突破」，指的就是这个闭环又收紧了一圈。

## 实验说明了什么：几条反直觉的结论

按论文与相关报道，实验结论大体指向一个方向：**多 Agent 的价值取决于你怎么组装**。

- **多 Agent 不是免费午餐**：不少单轮简单任务上，单个强模型配一个好 prompt 就能打平甚至胜过草台班子的多 Agent 团队；MAS 的红利主要体现在复杂、多轮、可分解的任务上；
- **小模型能打出超额性价比**：多个便宜小模型通过拓扑分工、互相校验，在部分任务上能逼近单个大模型，而综合成本低得多——这正是 Pareto 前沿的价值所在；
- **好设计是「尖」的**：在一个 benchmark 上称王的配置，换一类任务可能立刻拉胯。不存在万能框架，只存在与任务匹配的设计；
- **组合爆炸面前人类直觉容易失灵**：「模型 × prompt × 拓扑」的空间随规模指数膨胀，自动化搜索往往比手搓更稳。

## 收尾：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/fc9879a629a4d067.png)

1. **「RSI 突破」≠ AGI 近在眼前。** MASS 优化的是系统级配置（选模型、写 prompt、连拓扑），并不修改模型权重。底层模型的能力上限依然决定整个系统的上限——外环跑得快，内环没变。
2. **评估才是真正的瓶颈。** 优化器只优化你给它的指标。benchmark 污染、评测标准与真实需求错位、Goodhart 定律（「当一个指标变成目标，它就不再是好指标」）都会被自动化迭代放大。自监督循环里的「监督者」若本身不准，强化的可能是钻空子行为。
3. **对从业者，这是确定性最高的一波。** 无论 AGI 叙事成不成立，「自动化 Agent 系统设计」本质就是 Agent 领域的 AutoML，有立竿见影的工程价值——做 Agent 产品的团队，完全可以把日常「人肉 A/B 测 prompt、测路由」升级成带成本约束的自动化搜索问题。
