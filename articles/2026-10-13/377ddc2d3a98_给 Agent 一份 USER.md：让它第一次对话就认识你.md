## 背景

玩 Agent 这一年多，大多数人都在打磨「怎么让 Agent 干活」：AGENTS.md 写工作流，MCP 挂工具链，skill 拆步骤。但很少有人认真回答另一个问题——**Agent 知道你是谁吗？**

每次新会话，模型对「用户」的了解是零。它不知道你的主力语言是 Go 还是 Python，不知道你在东八区，不知道你要一句话结论还是完整推理。于是它只能按大众默认值来猜。

## 问题

这些猜测在日常聊天里无伤大雅，但在自动化场景里会被放大：

- 定时任务让 Agent 写脚本，它默认给了 Python，而你的服务器只装了 Node；
- 让它总结 issue，输出三屏长文，你只想要五条要点；
- 跨会话问同一个项目，它每次都要重新确认一遍背景；
- 多人共用一个 Agent 时，所有人的回答都长一个样。

这些不是模型能力问题，而是缺一份「用户上下文」。我的做法是在工作区加一个 `USER.md`，和 `MEMORY.md`、`AGENTS.md` 放同级。

## 做法

**1. 建文件，分区写。** 每区只放稳定、可执行的事实：

```markdown
# USER.md
## 身份
- 称呼：老周；直接叫，不用敬语
## 环境
- 时区：UTC+8；时间一律本地格式
- 主力：macOS + Linux 服务器（Ubuntu 22.04）
## 技术栈
- 服务端 Go，脚本优先 Bash，环境未装 Python
## 沟通偏好
- 先给结论，再给过程；默认中文；代码注释用中文
## 禁区
- 不动 nginx 配置；不执行发邮件类操作
```

**2. 控制长度。** 50～100 行封顶。这个文件每次会话都进 prompt，行数就是成本，冗余就是噪声。

**3. 建更新回路。** 在 AGENTS.md 加一条规则：「当确认到我身上稳定、长期成立的事实时，主动提议追加到 USER.md」。也可以挂个 hook，每周从记忆里提炼重复出现的用户偏好，生成候选条目，人工确认后合入。

**4. git 管理。** 机器间同步靠它，回滚也靠它。

## 踩坑点

- **写成简历。**「十年后端经验、热爱开源」对 Agent 没用。它要的是能改变行为的事实：用什么栈、要什么格式、不碰什么。
- **放进易变信息。** 本周任务、临时排期放进去两周就过期，而过期信息比没有信息更糟——Agent 会信以为真。易变内容留给记忆系统。
- **和 AGENTS.md 冲突。** 两边都定义回复格式，Agent 行为会抖动。用户事实归 USER.md，工作规范归 AGENTS.md，单一来源。
- **隐私越界。** 密钥、住址、证件信息别放。这份文件每次会话都会随 prompt 发到模型服务端，要当成公开配置来对待。
- **一味堆条目。** 超过百行后，尾部内容的实际遵守率明显下降，定期删比持续加更重要。

## 可复用建议

- **月度 profile lint**：让 Agent 对比近期会话和 USER.md，列出「已过期」「重复」条目，提案删除，人审后执行。
- **多人场景**：每人一份 `USER.<name>.md`，会话启动时按身份注入对应文件，避免互相污染。
- **写法**：全部用祈使句短条目，别写段落。Agent 对列表的遵守率远高于散文。

## 总结

USER.md 是我今年加的最便宜也最有效的配置之一：十几分钟写一份，换来的是 Agent 从「每次见面的陌生人」变成「记得你偏好的同事」。核心原则就三条——只放稳定事实、控制在百行以内、让更新成为回路而不是手工债。它不提升模型能力，但解决了一个更基本的问题：别让每个会话都从零认识你。
