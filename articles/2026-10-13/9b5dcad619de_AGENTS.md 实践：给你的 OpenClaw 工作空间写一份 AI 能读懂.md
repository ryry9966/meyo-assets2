## 背景

最近半年，我们在几个 OpenClaw 工作空间里陆续落地了 AGENTS.md，收益很稳定。所谓 AGENTS.md，就是放在仓库根目录的一个 Markdown 文件，Agent 每次进入工作空间时会自动读取，作为它的默认上下文。它和 README 的分工很明确：README 写给人看，讲项目是什么；AGENTS.md 写给 AI 看，讲在这个工作空间里怎么干活。配合 MCP 工具和插件使用时，这个入口尤其关键。

## 没有它会发生什么

实际踩过的场景：

- Agent 猜错包管理器，`npm install` 和 `pnpm` 混用，锁文件被反复改写；
- 每次会话都要在 prompt 里重复一遍“单测用 `pytest -q`，别跑全量”；
- 手写代码被塞进 `generated/` 目录；
- 换一个模型、或新同事接手，这些口头约定全部清零。

本质上这是一个上下文传递问题：工程约定散落在脑子、群聊和历史 commit 里，Agent 一个都看不到。

## 怎么写

我们的模板控制在 80 行以内，固定五段：

1. **项目概览**：两三句，说清这是什么、边界在哪。
2. **常用命令**：必须是可直接复制执行的完整命令。写 `pytest tests/unit -q`，不要写“跑一下单测”。
3. **代码约定**：命名、错误处理、目录职责，只列 Agent 容易违反的那几条。
4. **禁区**：不要动 `generated/`、不要升级依赖、不要新增顶层目录。经验上，禁区比指引更有用。
5. **工具偏好**：优先用哪个 MCP 工具，哪些操作必须先问人再执行。

维护节奏只有一条：每次你纠正 Agent 一次，就沉淀一条进 AGENTS.md。这个文件应该像代码一样走 review、进版本控制，而不是写完就不管。

## 踩坑点

- **写成第二份 README**。架构演进史、徽章这类内容对 Agent 是纯噪音，越短越好。
- **命令失效不更新**。Agent 会忠实地执行错误命令，然后反复失败。建议在 CI 里加一步冒烟校验，确认文档里的命令真实可跑。
- **monorepo 不分子目录**。根目录的 AGENTS.md 管全局约定，前端、后端子目录各放一份覆盖本地差异，子目录优先级高于根目录。
- **塞得太满**。超过一两百行，关键指令会被稀释，Agent 的遵从率明显下降。
- **写敏感信息**。这份文件会整体进入上下文，任何 token、内网地址都不要出现。

## 可复用的建议

- 把 AGENTS.md 当“给 AI 的 runbook”而不是文档：祈使句、可执行命令、明确的禁止项。
- 结构稳定比内容丰富更重要，五段式够用了。
- 命令改名、目录迁移后，立刻同步更新，养成随手 diff 的习惯。
- 如果你维护插件或 MCP server，也可以在自己仓库里放一份，写清工具的正确调用方式和非法输入长什么样，Agent 的接错率会下降很多。

## 总结

AGENTS.md 解决的不是能力问题，而是沟通问题：把散落在口头和聊天记录里的工程约定，固化成 Agent 每次都会读到的入口。我们最直接的体感是——纠正同一个错误的次数从每会话几次降到接近零。写它的成本不到一小时，回报是持续的。建议每个 OpenClaw 工作空间都配一份，从今天这份模板开始即可。
