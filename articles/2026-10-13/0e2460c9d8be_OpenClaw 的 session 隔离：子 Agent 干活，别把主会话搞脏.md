## 背景

OpenClaw 的主会话是长期存在的：系统提示、用户偏好、历史对话、每一轮工具调用都在同一个上下文里滚动。日常问答没问题，但一旦开始跑自动化任务——cron 定时任务、webhook 触发的链路、批量检索和处理——主会话很快就会被中间过程填满。

子 Agent 就是为这个场景准备的：通过 `sessions_spawn` 拉起一个拥有独立 session 的执行体，它自己跑、自己记录过程，结束后只把结果交回主会话。隔离不是附加功能，而是上下文管理的基本手段。

## 问题

不隔离会发生什么，我踩过实锤：

- 让主 Agent 直接读几个大文件做汇总，几轮之后它开始“忘掉”系统提示里的行为约束，回复风格漂移；
- 一次失败重试五六轮的调试过程全部留在主上下文里，触发 compaction 的频率明显变高，早期关键指令被压缩稀释；
- 工具调用日志（尤其大段读取结果）挤占窗口后，模型倾向于“抄近道”，质量肉眼可见地下降。

本质上是把上下文当成了无限资源，而它是预算。

## 做法

我的原则：**凡是“过程重、结果轻”的活，一律丢给子 Agent**。具体步骤：

1. **划边界**：批量检索、日志分析、大文件处理、探索性排查——这类任务只要结论，不要过程留痕。
2. **自包含的 task**：子 Agent 默认看不到主会话历史，所以 `task` 里必须写全——目标、输入数据、输出格式、超时时间。别指望它“记得你刚才说过什么”。
3. **约定返回契约**：只回一段结构化摘要（结论 + 关键数据 + 失败项清单），在 task 里明确禁止回传完整过程。
4. **命名与清理**：session key 用可读命名（比如带任务名和日期），方便事后在 sessions 列表里追溯；`~/.openclaw` 下的会话文件是逐条追加的 jsonl，定期清理，磁盘不会自己变小。

## 踩坑点

- **task 信息给少了**：子 Agent 拿不到上下文就开始自己猜，方向跑偏还返工。宁可 task 写长一点。
- **fire-and-forget**：派出去就不管，主会话没收到回执就继续往下编。务必等结果落地再推进。
- **并行写竞态**：同时 spawn 多个子 Agent 操作同一份工作区文件，互相覆盖。让它们各自写独立文件，最后由主会话合并。
- **隔离 ≠ 免审**：子 Agent 调工具同样走权限和审批流程，别以为换了个 session 就绕过了。
- **隔离不免费**：每个子 Agent 都要重新装载系统提示和工具定义，五秒钟的小任务用它反而更贵。

## 可复用建议

- 一句话判断标准：需要“过程”留在上下文里的，主会话自己做；只要“结论”的，spawn 出去。
- 把返回格式固化成一个 spawn 模板，之后每次复用，只改任务描述和输入。
- 主会话保持“调度员”角色：拆解、派发、汇总，不亲自下场干重活。

## 总结

session 隔离的本质是把上下文当预算管理：主会话的窗口留给长期有效的信息和决策，脏活累活的中间产物关在子 Agent 的独立 session 里，跑完只留一份摘要。做法不复杂，难的是养成习惯——每次想让主 Agent 亲手处理大块数据时，先问一句：这个过程的日志，我真的想让它陪我聊到明天吗？
