## 背景

团队每天要发一份进展日报，内容散落在 git 提交、CI 运行记录、错误日志和任务看板里。此前靠人肉拼凑：打开五六个面板，复制粘贴，再写两句总结。问题是耗时长、口径不一致，忙起来还会漏发。

## 问题

最初的偷懒做法是写一个定时 Agent 任务，让模型直接读原始日志然后"写一份日报"。跑了一周就暴露三个问题：

1. 日志量大，动辄几十万行，塞不进上下文，只能截断，截断后的数据不可信；
2. 模型会"编数字"——把截断样本里的错误率当成全天错误率；
3. 输出格式漂移，今天 Markdown 明天多一段 JSON，下游解析经常挂。

结论很明确：日报里的数字必须由代码算，模型只负责把算好的结果"说成人话"。

## 做法

现在这条流水线分四段，确定性与概率性严格分离：

**1. 采集（cron + MCP）**。用 OpenClaw 的定时任务每天固定时间触发，通过几个 MCP server 分别拉取 git 提交、CI 结果、错误日志、看板变更。每类数据单独落盘，一个源失败不影响其他源。

**2. 清洗（纯脚本）**。用 jq 和几段脚本把原始数据归一化成统一 JSON：字段固定、时间统一时区、错误按服务聚合，所有数字在这一步算完。全程无模型参与，可单测、可重放。

**3. 摘要（Agent + 约束输出）**。把结构化 JSON 喂给 Agent，Prompt 只要求三件事：按模块归并相似事件、一句话概括趋势、标注异常项。输出强制走 JSON Schema 校验，失败重试一次，再失败降级为模板拼接。

**4. 渲染与分发（插件）**。模板引擎把 JSON 渲染成 Markdown，输出插件推送到 IM webhook，同时按日期归档到仓库。中间的结构化 JSON 一并归档，方便事后重渲染或回溯。

## 踩坑点

- **时区错位**：cron 按 UTC 触发，日志时间戳带偏移，第一版统计窗口整整偏了 8 小时。现在所有时间统一归一，统计窗口在代码里显式声明。
- **静默失败**：某天数据源接口挂了，流水线没报错，日报只是"内容变少"。现在每段采集带结果计数，低于阈值直接告警——宁可发"生成失败"，不发残缺报告。
- **幂等性**：手动重跑导致重复推送。现在推送前按 `日期+版本号` 查重，重跑只覆盖归档、不重发消息。
- **Prompt 版本化**：摘要 Prompt 曾与代码分开管理，回溯旧报告时口径对不上。现在 Prompt 和 Schema 一起进仓库，改口径必须走提交。

## 可复用建议

- **先定 Schema 再写 Prompt**：报告结构稳定，Prompt 才有锚点；
- **代码能算的不交给模型**：数字、聚合、排序全部前置；
- **中间产物落盘**：日报只是视图，结构化 JSON 才是资产，随时可换模板重渲染；
- **给报告加 coverage 字段**：标明哪些数据源成功、哪些缺失，让读的人知道置信度。

## 总结

流水线上线后，日报生成稳定在一分钟内，人工介入只剩异常项复核。核心经验一句话：把流水线拆成确定性的数据段和概率性的表达段，模型只做它擅长的归纳，其余交给代码。搭建成本大概一个下午，换来的是每天省半小时，以及一份口径始终一致的报告。
