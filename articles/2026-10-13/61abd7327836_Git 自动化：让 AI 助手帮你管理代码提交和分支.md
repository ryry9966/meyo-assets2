## 背景

接入 OpenClaw 之后，编码速度明显上去了，但 commit 质量在往下掉。一个任务下来 agent 改了十几个文件，人懒得拆，最后 git log 里全是 "update"、"fix bug" 这种大杂烩。分支也一样，`feature/` 开了七八个，合并完没人删。既然 agent 能干活，干脆把提交和分支这两块事务性工作也交给它。

## 问题

先明确要解决的三件事：

1. **commit 拆分**：AI 改动跨度大，人肉 diff 拆提交成本高；
2. **分支生命周期**：建分支、合并、删分支这个循环没人愿意手动走完；
3. **安全边界**：agent 直接操作 git，怕误提交敏感文件，更怕它"顺手"改写历史。

## 做法

核心思路：**能力白名单 + 规范前置 + 分级放权**。

**第一步，收敛权限。** 我用 MCP 的 git server（受限 shell 也行），只放行 `status / diff / add / commit / branch / checkout / log / worktree`，明确禁掉 `push --force`、对远端分支的 `reset --hard`、一切改写历史的操作，`main` 分支设为只读。

**第二步，规范写进仓库级指令文件。** commit 用 conventional commits 格式（type + scope），分支命名 `task/<编号>-<短描述>`。这份文件随代码一起 review，相当于把团队规范变成 agent 的运行时约束。

**第三步，提交流程固定化。** agent 每次提交前必须：`git status` + `git diff --stat` 看全貌 → 按逻辑分组（功能、依赖升级、文档分开）→ 指定文件逐组 add → 按规范生成 message → 输出提交摘要。前两周我要求每次提交前停下等人确认；跑顺后改成纯格式化、注释类低风险改动自动过，逻辑改动仍需确认。

**第四步，分支自动化。** 任务开始时 agent 自动 `checkout -b`；合并后负责 `branch -d` 和清理本地引用。另外用 `git worktree` 给 agent 单独开工作区，避免和人抢同一个目录——后面证明这一步非常关键。

## 踩坑点

- **`git add -A` 惹祸**：第一次放手就差点把 `.env` 提交进去。现在指令强制 add 前先检查 status，pre-commit 再加 detect-secrets 兜底。
- **agent 想"整理历史"**：它看到 commit message 不整齐会主动提议 rebase + force push。这不是 bug，是过度热心，直接在权限层禁死。
- **pre-commit 失败后死循环**：lint 报错，agent 反复修了五轮。约定：同一 hook 失败两次就停下汇报，不许继续。
- **detached HEAD 静默丢提交**：agent 在游离 HEAD 上提交过一次，提交不在任何分支上。现在每次操作前校验当前分支存在且符合命名规则。

## 可复用建议

1. 规范别写在对话里，写进仓库级指令文件，和代码一起演进；
2. agent 的所有 git 命令落日志（命令 + 输出），出问题可回放；
3. 自动化程度跟着信任走：人确认 → 白名单内自动 → 全自动，逐级放开；
4. worktree 隔离 agent 工作区，成本一行命令，收益是主工作区永远干净。

## 总结

这套流程跑了一个多月，git log 可读性恢复了，僵尸分支清零。经验浓缩成一句：**让 agent 干拆提交、管分支这类事务性劳动，人守住两条底线——历史不被改写、敏感信息不出库。** 自动化不是一步到位，而是把信任逐步下放的过程。
