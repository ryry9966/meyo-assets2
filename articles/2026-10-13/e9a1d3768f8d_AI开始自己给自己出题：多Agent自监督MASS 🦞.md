最近技术圈热议：UC Berkeley 与 Sakana AI 的团队提出了名为 MASS 的新方法，主打“多 Agent 自监督”（multi-agent self-supervision），被不少人视为 RSI（Recursive Self-Improvement，递归自我改进）路线上的新进展。这几个词单拎出来都不新鲜，组合起来却指向当前大模型进化最现实的瓶颈：当高质量外部数据越来越稀缺，AI 能不能靠“自己给自己出题、互相批改作业”继续变强？这篇文章把这件事拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/83f9d7be2140e191.png)

## 一、RSI：一个从冯·诺依曼就开始做的老梦

RSI 的定义很朴素：系统修改自身，修改后的版本更强，且这个循环能持续滚动。它不是 2025 年才有的新词：

- 1940 年代，冯·诺依曼的自复制自动机理论证明：机器可以内含自身的完整描述，“自我改造”在数学上并不违反任何规律；
- 2003 年，Schmidhuber 提出 Gödel Machine：一个可以自我改写代码、且只在“能证明改进”时才动手的程序。想法很美，卡在“证明”两个字上——没人能给“这段代码更好”写出证明；
- 2017 年，AlphaZero 用纯自我博弈在围棋上超越人类，第一次证明“自己产生训练信号”在封闭规则下完全可行。

为什么此刻爆发？LLM 补上了通用底座，但 RSI 跑起来需要三样东西：稳定的任务流、可靠的验证器、可持续的算力。前两件目前都缺货，第三件缺钱。

## 二、真瓶颈：自我改进的“燃料荒”

现在的对齐与训练范式基本靠“外部燃料”：

- SFT 需要人工编写的高质量示范，RLHF 需要人类偏好标注，既贵又慢，还把模型上限锁死在人类水平附近；
- Epoch AI 的估计是，高质量公开文本数据的“有效供给”可能在 2026~2032 年间被训练消耗殆尽；
- 让模型给自己当老师也有坑：同一个模型既出题又判卷，会系统性地偏好自己擅长的任务，错误在闭环里自我强化。相当于学生自己批改自己的作业，还专挑会做的题做。

所以问题的关键不是“要不要自监督”，而是怎么避免单人闭环的自欺。MASS 给出的答案：把“一个人干三份工”改成“一个班组协作”。

## 三、MASS 的思路：把自我改进改成流水线

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/d33dd8e43e772b0f.png)

从公开介绍看，MASS 把自我改进的各个职能拆给角色、配置各异的多个 Agent，大致可以概括为四步循环：

1. **出题**：任务生成 Agent 从已有经验和语料中派生新任务，比如把一段代码改写成一道带可验证答案的编程题，并控制难度梯度（curriculum），不让模型永远在舒适区刷题；
2. **解题**：多个执行 Agent 并行作答，产出多样化的候选解；
3. **判卷**：验证 Agent 交叉检查——代码能不能跑通、多个判卷者结论是否一致、推理链是否自洽，只有通过可靠性筛选的样本才被保留；
4. **回流**：筛选后的轨迹进入经验库，经蒸馏（distillation）或上下文记忆反哺下一轮，闭环继续转动。

为什么“多”是关键而非炫技：

- **异质打破同源偏差**：不同提示、不同模型的出题人与判卷人互相纠错，缓解“自我确认”效应；
- **利用 verifier's gap**：验证通常比生成容易，多角色互查把“自评”升级为“同伴互评 + 抽查”；
- **天然并行**：出题、解题、判卷三段流水互不阻塞，算力利用率高。

它也不是孤例，而是一波明确的趋势：Sakana 自己的 Darwin Gödel Machine 让会自我改写代码的 Agent 在 SWE-bench 上从约 20% 提升到 50%；Absolute Zero、R-Zero、SPICE 都在做“零外部数据”的出题-解题-验证闭环。MASS 的特点在于把“自监督”明确架在多 Agent 协作的骨架上。

## 四、冷思考：RSI 头上的三道天花板

- **验证器瓶颈**：改进的上限约等于判卷的上限。判卷 Agent 若有系统性盲区，错误样本会被当作“高质量数据”蒸馏进模型——这是 reward hacking 的自监督版本，而且更隐蔽；
- **收益递减**：迄今所有 self-improvement 实验的曲线都在几十到几百轮内趋平，没有任何团队观察到失控式指数增长，算力与上下文成本是硬约束；
- **可控性**：RSI 恰好是 AI safety 社区长期研究的场景。自监督不等于放养，人工抽检、版本回滚、独立评测（evals）必须留在环内。

## 五、三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/d37edfda013afb9b.png)

1. **先问验证信号从哪来**：判断一类“自我改进”工作的可信度，第一眼看它有没有可执行的验证（代码测试、数学验算、工具调用结果）；纯开放生成领域的结论要自动打折；
2. **先落地轻量版**：不急着复现整条流水线，两个模型互出题、互评，加规则校验兜底，先在内部评测集上确认增益，再考虑放量；
3. **把人工监督改成抽样审计**：留 1%~5% 的黄金评测集做盲测，定期对照，防止自监督闭环悄悄漂移。

RSI 的故事从来不是“AI 觉醒”，而是一条工程流水线在一节一节接起来。MASS 接上的这一节，名字很朴素：让模型们互相当老师。
