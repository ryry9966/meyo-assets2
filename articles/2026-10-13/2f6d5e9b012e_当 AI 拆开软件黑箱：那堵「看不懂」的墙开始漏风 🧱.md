过去二十年，闭源软件有一条心照不宣的护城河：源码一旦编译成二进制，就变成一堆人类很难读的机器指令。想看懂它？请雇稀缺的逆向工程师，抱着 IDA Pro 或 Ghidra 啃上几周汇编。这道墙在密码学意义上并不算安全，但它用「分析成本极高」换来了事实上的壁垒。2024 年以来，大模型开始系统性地进入二进制分析与漏洞挖掘领域，这条成本曲线正在被快速压平——墙没塌，但确实漏风了。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/f008d14badb566c8.png)

## 墙是怎么砌起来的：编译即信息蒸发

要理解 AI 撬动了什么，得先看清这道墙的施工工艺：

1. **编译本身就是有损压缩。** 源码里的变量名、函数名、注释、类型层级，编译后基本全部蒸发，只剩寄存器操作和内存地址。人类读二进制，相当于在没有地图、没有路牌、连街名都被抹掉的城市里导航。
2. **厂商还会主动「加料」。** 控制流平坦化（把代码搅成一碗面）、字符串加密、加壳（VMP、Themida 这类虚拟机保护）、反调试陷阱——每一层都是给分析者上强度。OLLVM 这类混淆框架在游戏和金融客户端里几乎是标配。
3. **真正起作用的是经济学。** 逆向工程师本来就稀缺，人工分析一个中型商业软件动辄数周甚至数月，多数安全团队的预算根本覆盖不了。「看不懂」不是密码学保证，而是把「难」冒充成了「安全」——业界管这叫 security through obscurity，一个公开的秘密。

## AI 改变的不是技术，是成本

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/593af1fa380e175a.png)

有意思的是，反编译器并不是新东西。Hex-Rays、Ghidra 早就能把汇编转成伪 C 代码。问题在于，它们输出的代码「结构对了，灵魂没了」：函数名叫 `sub_40A2C0`，变量叫 `v1`、`v2`，语义全靠分析师脑补。真正的瓶颈从来不是「翻译成伪代码」，而是补齐语义这一步。

大模型恰好卡在了这个点上：

- **语义恢复**：LLM 读完伪代码能推断「这函数像是在做 license 校验」「这是 AES 的 key expansion」，并批量完成重命名；
- **汇编直译成高级语言**：LLM4Decompile 这类专门微调的模型，把汇编作为输入直接生成可读的 C 代码，学术基准上已经能产出可直接编译运行的版本，质量在快速逼近人工分析结果；
- **混淆还原**：面对控制流平坦化后的「面条代码」，LLM 能辅助重建控制流结构——这正是过去最耗人力的环节；
- **Agent 化迭代**：最新的玩法是让 AI agent 挂在 Ghidra 上，反复「反编译—提出假设—用调试器验证—修正」，把过去几周的工作压缩到几小时。

打个比方：过去逆向像在没有路牌的城市里自己画地图，现在你多了一个会说当地话、还能帮你辨认街区的导游。它仍会犯错、必须人工验证，但「从零开始」的冷启动成本坍缩了。

## 已经发生的信号，不只是论文

如果说 2023 年还停留在演示层面，2024–2025 年是真实案例落地：

1. **2024 年 11 月**，Google Project Zero 的 Big Sleep agent 在 SQLite 中发现了一个真实的栈溢出漏洞，被普遍视为 AI agent 首次在主流真实软件中挖出 0-day。注意：目标不是玩具，而是部署量以十亿计的基础软件，这类漏洞过去主要靠顶尖专家审计发现。
2. **OSS-Fuzz 接入 LLM 后**，Google 披露 AI 增强的模糊测试让代码覆盖率显著上升，并在几个月内新发现了二十个左右此前未知的开源漏洞。
3. **DARPA 主办的 AIxCC**（AI Cyber Challenge，总奖金约 2950 万美元）在 DEF CON 决赛上，让多支队伍的自主系统在真实开源项目里找漏洞并自动生成补丁，部分系统确实找到了此前未知的真实漏洞。

有人会说：这些靶子都是开源项目，跟闭源有什么关系？关系在于——能力是通用的。闭源二进制只是「多套了几层混淆」的同类问题；开源项目反而是因为语料充分、ground truth 明确，最先被 AI 打穿。同一把锤子，敲的只是不同的门。

## 漏风，不等于倒塌

也要泼一盆冷静的水：

- **「藏」的红利确实在消失。** 客户端里硬编码的 API key、自创的加密算法、license 校验逻辑，被批量理解的概率大增。厂商的对策会分层：法律层靠许可协议与反规避条款，技术层靠虚拟机保护、硬件 attestation 和服务端校验——但混淆的边际收益正在递减。
- **开源反而先受益。** 开源软件的痛点从来不是「看不懂」，而是「没人看」。AI 把审计成本拉低后，依赖供应链审计、补丁比对、patch diffing 这些领域会最先提速。
- **真正的分水岭在预算迁移。** 当「对手大概率已读懂你的代码」成为默认假设，安全投入就该从「藏起来」转向「扛得住」：内存安全语言、持续 fuzzing、纵深防御。这其实是 Kerckhoffs 原则的正确打开方式——系统安全不该依赖攻击者看不懂。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/633761719b8d7cc9.png)

1. **按「对手已读源码」来设计系统。** 秘密不进客户端，校验放服务端，加密用标准库。AI 时代还在发明「自创加密」或把密钥藏在二进制里，约等于明文。
2. **安全预算从混淆迁向工程。** 加壳和混淆仍有价值，但别再指望它们当唯一防线。同样的预算花在内存安全、模糊测试和上线后的持续监测上，「被读懂」才不会致命。
3. **个人的价值排序要换了。** 逆向的入门曲线被 AI 削平，纯「会用 IDA」的稀缺性在下降；会向工具提出好问题、能验证 AI 的判断、懂操作系统与体系结构底层原理的人，价值反而在上升。工具换代时，先换代的是人的技能结构。

墙漏风不可怕，可怕的是把全部身家押在「没人看得懂」上。现在，最好默认风会一直吹进来。
