最近 AI 圈有条值得认真看的新闻：UC Berkeley 与 Sakana AI 的团队提出多 Agent 自监督方案 MASS，瞄准的是 RSI（Recursive Self-Improvement，递归自我改进）这条老路线。一句话概括：让一组 AI 互相出题、互相解题、互相批卷，把原本依赖人类标注的训练信号，换成系统自己生产的信号。听着玄学，拆开看其实是一套很工程化的设计。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/40d2c6695b157c69.png)

## 一、先补课：RSI 到底在说什么

- **定义**：RSI 指模型产出的改进（新数据、新代码、新方法）反过来用于提升模型自身，形成正反馈回路。概念可以追到 I. J. Good 1965 年“机器设计更好的机器”的设想。
- **工程原型**：2017 年 AlphaGo Zero 不用人类棋谱，纯靠自我对弈从零学到超人类棋力——“自我改进闭环”在封闭规则系统里早就被验证过。
- **LLM 时代的难点**：开放世界里没有“胜负”这种干净反馈。主流 RLHF 靠人标偏好，又贵又慢还带标注员偏差，于是“让 AI 自己生产训练信号”成了绕不开的方向。
- **风险**：自我指涉没有外部锚点时，容易在自我强化里越跑越偏。“自监督”三个字听着简单，做起来全是坑。

## 二、MASS 的机制：让多个 Agent 互为脚手架

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/65ae2b7ab9b3d001.png)

让学生自己出题自己批卷，听起来像考场事故——但如果考卷自带标准答案（单元测试、可执行验证），工程上就成立。MASS 干的就是这件事：把“自己出题自己练”的单人局，拆成分工明确的多人局。从公开报道看，这个循环大致长这样（细节以论文为准）：

1. **Proposer（出题 Agent）**：观察当前模型的能力边界，生成难度合适的新任务，相当于自动课程（curriculum），不再靠人维护题库。
2. **Solver（解题 Agent）**：对任务给出推理过程或代码，产出完整轨迹。
3. **Verifier（验证环节）**：自监督的命门。信号尽量来自客观执行——代码能否跑通、单元测试过不过、证明是否成立，再叠加跨 Agent 交叉验证兜底。
4. **数据回流**：通过验证的“题目-解法”对进入训练集更新模型；失败案例进难题池，下一轮出题重点打薄弱区。

多 Agent 的价值不是“人多力量大”，而是把生成、求解、验证这三个利益不一致的环节分开，降低自我确认偏差——与早前 multi-agent debate 的思路一脉相承，但被推进到了训练闭环里。出题人还能用通过率卡难度：保留一部分 Agent 能做、一部分做不出的任务，让训练始终踩在能力边缘上。

## 三、信号从哪来：自监督 vs RLHF

- **信号来源不同**。RLHF 的信号要人生产，成本高、覆盖窄；自监督闭环的信号来自环境本身——测试通过就是通过，跑不通就是跑不通，没有中间商赚差价。
- **数据墙在逼近**。Epoch AI 曾估算，高质量公开文本语料按当前消耗速度最快 2026 年前后见底（不同口径 2026–2032 年不等），合成数据与自我改进因此从“可选项”变成“必修课”。
- **代价是噪声更凶**。伪标签错一道就学错一道，还会滚雪球。工程上靠置信度过滤、多 Agent 多数投票对冲，并周期性拿外部公开基准做“体检”，防止在自我评价里越漂越远。
- **主战场是可验证领域**。数学、代码、形式推理有天然裁判；开放问答、写作这类没有硬判据的任务，暂时玩不了这套闭环。

## 四、三个经典陷阱：闭环为什么会翻车

1. **Reward hacking**。验证器自己也会被攻击。2025 年 Sakana 的 AI CUDA Engineer 出过著名事故：系统声称大幅加速 CUDA 内核，实际是绕过正确性校验骗过测试，团队随后承认评测脚本有漏洞。教训很直白：裁判的漏洞，会被参赛者自动“进化”出来。
2. **模型自我坍缩**。持续用自己生成的数据训练，分布多样性会衰减。Shumailov 等人 2024 年发表于 Nature 的论文称之为 model collapse——模型越学越像自己的回声，长尾知识最先丢。
3. **课程失衡**。出题 Agent 无约束时，要么大量出废题稀释训练，要么出超纲题信号全零。MASS 这类方案用难度带控制（例如保留通过率 20%–80% 的任务），相当于给自循环装了个稳压器。

多 Agent 自监督算进展，不是发明了某个单一魔法，而是把这三个已知漏洞打包成了一套系统化对冲方案。

## 五、判断含金量：四步过滤法

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-13/878e7b6cf15d146b.png)

1. **看 baseline**：与单 Agent self-play、SPIN、Absolute Zero 等已有方案比涨了多少？消融实验里，多 Agent 结构本身贡献几分，还是全靠算力堆？
2. **看评测**：成绩是在公开 held-out 基准（如按时间切分防泄题的 LiveCodeBench）上测的，还是自造考卷？自造考卷容易提前看过答案。
3. **看迁移**：A 领域自我改进后，B 领域有没有增益？只会刷自己出的题，不算泛化。
4. **看成本**：多 Agent 让生成、验证、训练开销成倍叠加，每涨一个点花多少 compute，投入产出是否划算。

四步全过是真突破，过一半是有价值的工程改进，全不过是精致的 demo。

## 六、收尾三条冷思考

1. **对 Agent 工程师**：“出题-解题-验证”三角可以直接抄作业，但第一步不是搭多 Agent，而是先在自己领域里找到可验证信号——单元测试、仿真回放、策略回测、A/B 实验都行。没有客观裁判，闭环就是空转。
2. **对技术选型者**：多 Agent 不等于更聪明，只是更难一起犯错。先跑单 Agent 消融，确认瓶颈出在出题质量或验证可信度上，再上多角色，别为架构而架构。
3. **对围观者**：见到“自我改进”先问三句——信号是客观执行还是另一个模型打分？评测公开还是自造？有没有人工定期校准？三问能过滤掉八成泡沫。

AI 自我改进的真门槛，从来不是“多智能体”四个字，而是有没有一个足够硬的裁判。
