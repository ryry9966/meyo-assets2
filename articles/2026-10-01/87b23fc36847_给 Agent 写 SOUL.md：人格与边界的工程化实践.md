## 背景

OpenClaw 的工作区里，除了管"怎么干活"的 AGENTS.md，还有一个 SOUL.md——定义 Agent "是谁"的文件，每次会话都会注入上下文。很多人装完直接用默认模板，或者把网上抄来的几百行 system prompt 整个塞进去，两种做法通常都撑不过一周的真实使用。

## 问题

实际跑下来常见的三类麻烦：

1. **人格不稳定**：今天是冷冰冰的工具人，明天过度热情，跨渠道（Telegram / CLI / 微信）表现不一致。
2. **边界缺失**：Agent 替你答应事情、过度道歉，或在正式场合用表情包口吻。
3. **提示词膨胀**：人格、操作规则、用户偏好堆在一个文件里，模型在长上下文中开始选择性失忆。

## 做法

我的 SOUL.md 稳定在 40 行左右，分四段：

- **身份**：一两句说清"你是谁、为谁服务"。例："你是我的个人助理，跑在我自己的设备上，数据不出本机。"
- **语气**：不写形容词，写具体行为。"直接给结论，再给理由；不用'好的没问题'开头；中文回复，技术名词保留英文。"
- **取舍**：冲突时的优先级。"不确定先问，不猜；安全相关的问题不将就。"
- **边界**：每条负面规则配一个替代动作。"不替我做承诺，改为：列出选项等我确认。"

分工保持干净：SOUL.md 管"是谁"，AGENTS.md 管"怎么干活"（工具规范、目录约定），USER.md 管"我是谁"（称呼、时区、偏好）。名字、头像这类静态标识在新版里拆到了 IDENTITY.md，人格性的内容留在 SOUL.md——三者混写是最常见的结构错误。

然后是版本控制加迭代：workspace 用 git 管，观察到不想要的行为就加一行，两周后删掉没起作用的行。每次换模型或升级后，让 Agent 复述一遍自己的 SOUL.md，确认注入正常。

## 踩坑点

- **写成小作文**：超过百行，人格描述被稀释，模型对中间段落的遵守率明显下降。
- **形容词无用**："友好、专业、有温度"改不了任何行为，具体句式才能。
- **只有"不许"**：负面清单不配替代行为，模型只会换一种方式越界。
- **语言错位**：文件用英文写、日常用中文聊，语气会走样。主要用什么语言就用什么语言写。
- **过度拟人**：让它声称有情绪、有连续记忆，短期有趣，长期会诱发角色扮演漂移和奇怪的拒绝。
- **别放敏感信息**：这文件每次会话都注入，也是你哪天可能截图分享的东西。

## 可复用建议

- 模板骨架就四段：身份 / 语气 / 取舍 / 边界，每段 5–10 行。
- 文件头加一行版本注释，行为变更记一笔，方便回溯是哪次修改导致漂移。
- 每季度清理：删掉"没有它也没区别"的行。
- 硬约束（如禁止执行的命令、权限红线）同步写进 AGENTS.md 的执行规范：人格管"倾向"，规则管"硬约束"，两层兜底。

## 总结

SOUL.md 不是玄学人设，而是一份要持续维护的配置文件：短、具体、可执行、版本化。人格决定你每天愿不愿意用它，边界决定你敢不敢把权限交给它。花一个下午写清楚并迭代两周，比抄任何"万能 prompt"都值。
