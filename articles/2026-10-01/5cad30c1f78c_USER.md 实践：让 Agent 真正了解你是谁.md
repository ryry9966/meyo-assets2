## 背景

OpenClaw 的 workspace 里有几个约定文件：`AGENTS.md` 管行为规范，`MEMORY.md` 管滚动记忆，`USER.md` 管"你是谁"。大多数人会反复打磨 AGENTS.md 的措辞，USER.md 却常常空着，或只有一句"我喜欢简洁的回答"。结果就是 Agent 每次会话都在重新猜你的环境。

## 问题

没有 USER.md 的典型表现：

- 默认给你 macOS 的命令，而你跑的是 arm64 Linux；
- 回答里混着你根本不用的技术栈；
- 每次都要重复声明"我用 xx，别给我 xx"；
- 自动记忆虽然能积累事实，但碎片化、不可控，写错了你都不知道错在哪。

USER.md 的定位是：一份**你自己维护、每次注入、可 diff 可回滚**的静态上下文。它解决的不是"记住对话"，而是"预先声明事实"。

## 做法

文件默认在 `~/.openclaw/workspace/USER.md`（以你的 workspace 配置为准）。我分五段写，总量控制在一屏以内：

1. **环境**：操作系统、架构、时区、主力语言、网络环境特点；
2. **技术栈**：语言和具体版本、常用框架、部署方式，别写"最新版"；
3. **偏好**：回答详略、注释密度、是先给方案还是直接动手；
4. **边界**：明确不要做的事，比如"删除操作必须先确认""不要自动重启服务"；
5. **当前项目**：两三行在做什么，帮 Agent 对齐上下文。

两个原则：**写可验证的事实，不写愿望**——"我主力用 Go 1.22" 是事实，"请用最佳实践" 是废话；**能被证伪的才留下**，说不出对错的句子直接删。

冷启动偷懒法：让 Agent 采访你一轮，自己生成 USER.md 草稿，你删改一遍，五分钟出及格初版。建议把 workspace 放进 git，每次变更都有据可查。

## 踩坑点

- **写成 system prompt**。"你是一个严谨的助手"属于 AGENTS.md/SOUL.md，USER.md 只放关于你的事实，混写会导致两份文件打架；
- **太长**。它每个会话都注入，写两千字等于持续挤占真实任务的上下文，且靠后内容注意力更弱；
- **放敏感信息**。workspace 可能被备份、同步，或被你后来装的工具读到。密钥、住址一律不写，交给环境变量和密钥管理器；
- **过期事实**。换了机器、换了语言栈没改文件，Agent 会"自信地"引用旧信息。每季度或每次大环境变更后过一遍，commit message 写清改了什么；
- **优先级冲突**。USER.md 和 AGENTS.md 说反了怎么办？在 AGENTS.md 里显式写一条优先级规则，别指望模型自己猜。

## 可复用建议

- 把 USER.md 当配置文件，不是日记：小、稳、可版本化；
- 多人共用一个实例时用 workspace profile 隔离，各写各的，别塞一个文件；
- 定期跑一个"审计 prompt"：让 Agent 列出它从 USER.md 推断出的结论，你核对哪些是错的——这是发现过期内容最快的办法。

## 总结

USER.md 是性价比最高的 Agent 调优手段：十几分钟写一份，换来每次会话省掉的开场白和猜错的环境。它不智能，但正因为它不智能——纯静态、可 diff、可回滚——才可靠。先写环境和技术栈，偏好和边界慢慢补；用三个月你会发现，MEMORY.md 里"猜对的事"变多了，因为你的 Agent 终于知道你是谁了。
