## 背景

Agent 拥有 shell 和文件读写工具，执行结果是真实落盘的。而 LLM 输出本质上是概率性的：一次幻觉、一段藏在网页里的提示注入、一条 MCP 工具返回的恶意内容，都可能让模型拼出一条危险的删除命令。所以“为什么 Agent 不会误删文件”，答案不应该是“模型够聪明”，而应该是架构层的强制约束。

## 问题：最常见的误解

把 system prompt 里的“请不要删除文件”当成安全边界。提示词是行为引导，不是访问控制——任何注入内容都可能在语义层面覆盖它。真正的隔离必须落在执行环境和工具调用链上，这也是 OpenClaw sandbox 的设计出发点。

## OpenClaw 的分层做法

1. **网关收敛出口**：Agent 进程本身不直接碰宿主文件系统，所有工具调用经 gateway 分发，策略在网关层统一生效。
2. **工作区限定**：文件工具默认根锁定在 workspace，根外路径直接拒绝；对路径做规范化与 symlink 解析，防 `../` 和软链接绕过。
3. **容器沙箱执行**：shell 命令在容器内跑——只挂载 workspace、默认只读、非 root 用户、默认无网络（需要时走代理出网）。
4. **危险操作闸门**：命中破坏性模式库的命令（`rm -rf`、`dd`、`mkfs`、`git reset --hard` 等）自动升级为“需人工确认”，Agent 无法自行放行。
5. **审计与回滚**：每次调用记录输入、目标路径与结果；重要任务前自动做快照，最坏情况可恢复。

## 配置要点

1. 开启 sandbox 模式，确认 workspace 根指向任务目录；
2. 配置敏感路径拒绝列表：`~/.ssh`、`~/.config`、各类密钥文件；
3. 非 root + 只读挂载 + 关网络，按任务最小开放；
4. 打开危险命令确认闸门，并按操作类型分级；
5. 放置 canary 文件做演练：用“故意让它删”验证隔离是否真的生效，而不是相信配置文档。

## 踩坑点

- 图省事把整个 home 挂进沙箱，隔离等于零；
- 挂载 docker.sock，等于把 root 交给容器；
- 确认疲劳：见弹窗就点“允许”，闸门沦为形式，建议高危操作强制二次输入；
- 盲信第三方 MCP 工具：sandbox 管的是你的 shell，管不了工具自带的高权限文件接口，第三方工具要单独声明权限范围；
- 凭证泄漏：明文注入沙箱的环境变量可能被读出并外发，密钥应走 secret 注入机制。

## 可复用建议

- **最小权限**：只给当前任务需要的目录和命令，任务结束回收；
- **把 LLM 输出当不可信输入**：写插件和 MCP 工具时自己做校验，不假设上游干净；
- **身份隔离**：Agent 用独立系统用户和 API key，不与个人主账号混用；
- **定期演练 + 审计巡检**：关注日志中的异常路径访问模式。

## 总结

Agent 不误删文件，靠的不是模型自觉，而是出口收敛、路径限定、容器隔离、人工确认、审计回滚五层叠加。每一层单独看都可能被绕过，叠起来才把事故成本抬到可接受的范围。与其相信模型行为，不如先把边界建好。
