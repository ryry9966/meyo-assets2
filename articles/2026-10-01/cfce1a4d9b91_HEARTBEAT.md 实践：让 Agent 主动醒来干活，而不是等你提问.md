## 背景

多数人用 Agent 的方式还是一问一答：你不发消息，它就是死的。OpenClaw 里其实藏着一个常被忽略的机制——心跳（heartbeat）。每隔一段固定时间（默认 30 分钟），gateway 会向主会话注入一条心跳 prompt，让 agent "醒一下"；如果 workspace 根目录存在 `HEARTBEAT.md`，它就会读取这个文件，判断有没有该干的事。官方文档对这段着墨不多，但用好了，它相当于 agent 侧的 cron + 任务清单。

## 问题

我最初的痛点很典型：想让 bot 每天早上汇总一次昨夜的监控告警、每周清一次待办、有异常时主动提醒——这些事靠"我记得去问它"必然断档。写在系统 cron 里调脚本可行，但逻辑一变就要改代码；放在 agent 侧，任务描述本身就是配置，改一句话就行。

## 做法

1. **建文件**：在 workspace 根目录（默认 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`。注意是 workspace 根目录，不是某个项目目录。
2. **写成 checklist**：每条任务带三要素——触发条件/频率、要做什么、结果发到哪。例如："- 每天早上 8 点后的第一次心跳：通过 MCP 监控工具拉取昨夜告警，有内容就整理成不超过三条的摘要发到通知渠道，没有则跳过"。
3. **配置间隔**：`openclaw.json` 里 agents 段下的 `heartbeat.interval` 按需调整。做日级任务时，默认 30 分钟够用，靠任务描述里的"当天第一次"来去重。
4. **省钱关键**：文件为空或无任务时，让 agent 回复 `HEARTBEAT_OK`，gateway 会短路这次心跳，几乎不产生额外输出。把这个约定写进心跳 prompt 或文件开头。
5. **让它真能干活**：心跳里引用的 MCP 工具、插件命令要提前配好权限，否则 agent 只能在心跳里"许愿"。

## 踩坑点

- **interval 别贪快**。每次心跳都是一次真实的模型调用，5 分钟一跳、清单又长，月底 token 账单会让你清醒。
- **任务必须带跳过条件**。没写清"无事可做时怎么办"，agent 会每跳都发一轮"今日无异常"，通知很快沦为噪音。
- **注意会话隔离**。心跳默认跑在主会话上下文里，长对话会被周期性稀释。需要隔离时查一下 heartbeat 的 direct/target 相关配置，把心跳放进独立会话。
- **别把重活塞进心跳**。心跳适合轻量、可快速完成的检查类任务；跑几分钟以上的活拆出去用显式触发。
- **改了不生效**：先核对文件路径与当前 workspace 是否一致，再确认心跳没有被会话活动跳过。

## 可复用建议

把 `HEARTBEAT.md` 当代码来 review，每条任务问三个问题：什么条件下才该做？结果送到哪？能不能跳过？建议文件开头维护一段"全局约定"（时区、默认通知渠道、静默时段），下面再按频率分组列任务。新任务先手动触发验证一次，再交给心跳接管；每月清一次清单，删掉从没产生过价值的条目。

## 总结

`HEARTBEAT.md` 的本质，是把"定时任务 + 自然语言逻辑"合并进 agent 的工作区：成本是周期性的一次模型调用，收益是 agent 从应答机变成有自主节奏的协作者。克制地写清单、明确跳过条件、控制频率，它就安静可靠；反过来，它就是一台烧钱的消息轰炸机。建议从一条日报任务起步，跑稳了再逐步加码。
