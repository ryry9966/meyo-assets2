## 背景：身份文件不是一次性的

OpenClaw 的 workspace 里有一组 Markdown 文件共同决定 agent 的行为：AGENTS.md 管流程约定，SOUL.md 管性格底色，USER.md 记用户偏好，IDENTITY.md 管"我是谁"——名字、形象、语气基调。

多数人的做法是初始化时改个名字、选个 emoji，之后再也不碰。但 agent 一跑几个月，说话方式和决策倾向会被系统提示词、工具输出和日常对话慢慢带偏，身份文件和实际行为渐行渐远。

## 问题：三个典型症状

1. **身份漂移**：设定的"简洁直接"，几周后变成絮叨的客服腔
2. **文件之间抢地盘**：性格描述同时出现在 IDENTITY.md 和 SOUL.md，改了一边忘另一边
3. **改了无法追溯**：为什么改、什么时候改的，没有记录，回滚只能靠猜

根因只有一个：把身份当成一次性设置项，而不是持续校准的配置。

## 做法：把身份当代码维护

**第一步，写短。** IDENTITY.md 控制在 15 行以内：name、creature、emoji，加一句 persona 和两三条行为边界。越短越不容易被稀释。

**第二步，纳入 git。** workspace 本来就该是仓库，IDENTITY.md 的每次修改走 commit，message 写清动机——"语气太卑微，收窄边界"比"update"有用得多。

**第三步，分层。** 不变的内核（价值观、红线）放 SOUL.md；可进化的身份（语气、称呼习惯、决策风格）放 IDENTITY.md；用户相关的观察放 USER.md。三个文件各管一段，别交叉。

**第四步，定回顾节奏。** 我固定每周翻一次对话记录，对照身份描述找偏差：哪条描述已不符合实际行为？实际行为里有值得固化的新特点？发现偏差就改文件，而不是往 AGENTS.md 里临时打补丁。

## 踩坑点

- **让 agent 自由改写自己的身份**。可以，但必须走"提议 → 人审 → 合入"的流程，否则某次对话里的情绪化结论就能覆盖掉几周的校准成果
- **身份文件里混任务细节**。"优先用表格输出"是流程约定，该进 AGENTS.md；"用户习惯叫它小爪"才是身份
- **一次改太多**。身份改动的效果有滞后性，一次改三条，两周后你不知道是哪条起的作用，务必小步提交
- **只加不减**。描述越堆越多，重点被稀释，每月做一次瘦身，删掉已不生效的条目

## 可复用建议

- 维护一份"偏差清单"：左边是身份描述，右边是观察到的实际行为，差距就是下次修改的依据
- commit message 统一格式，比如 `[identity] 收窄幽默边界：群聊场景过度玩梗`，半年后回看就是一份演化史
- 多 agent 用户可以把跑得顺的那份 IDENTITY.md 作为模板 fork，不必每次从零写

## 总结

IDENTITY.md 的价值不在初始写得多完美，而在它是否跟着真实使用持续演化。文件短、版本化、分层清晰、定期回顾——把这四件事做成习惯，agent 的身份就会从"配置"变成"履历"。
