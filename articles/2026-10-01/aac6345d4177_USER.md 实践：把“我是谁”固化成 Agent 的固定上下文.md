## 背景

用 OpenClaw 做日常自动化一段时间后，最大的摩擦不是模型不够聪明，而是它每次醒来都“不认识我”。SOUL.md 定义的是助手的人格和通用行为，系统提示词面向所有人——但你的时区、机器环境、技术栈、哪些操作可以直接放行，Agent 一概不知。结果就是两类低效：要么每次会话手动交代一遍背景，要么 Agent 自己猜，猜错就返工。

## 做法

核心思路：把“重复交代自己”固化成一份版本化文件。在 workspace 里建 `USER.md`，会话启动时它会随记忆文件一起注入上下文，相当于一份专属于你的提示词补丁。

我的分层结构：

```markdown
# 用户档案
## 基本盘
- 昵称 / 时区 Asia/Shanghai / 中文交流，代码注释用英文
## 环境
- macOS 15 / zsh / node 22 / 主力编辑器 Neovim
## 协作偏好
- 回复先给结论，细节放后面
- git push、rm 类命令必须先确认；lint、test 可直接跑
## 禁区
- 未被要求时不主动重构；不推荐某个我不用的方案
```

维护上守三条规则：
1. 入 git 管理，改动走 diff，可审计、可回滚。
2. 约定口令：我说“记住这个”时，Agent 先复述要写入的条目，确认后追加到对应小节。
3. 每月 review 一次，过期即删。

## 踩坑点

- **写太多**。USER.md 每次注入都占注意力，超过 40 行后关键偏好反而被稀释。宁可精简，塞不下的内容拆到项目级文件。
- **放错层**。任务清单、项目进展属于 MEMORY.md 或仓库内的项目说明文件，放进 USER.md 一周就开始腐烂。
- **放敏感信息**。密钥、完整手机号不要写，会话日志可能被导出用于排障。
- **过期比缺失更糟**。换了技术栈没更新，Agent 会自信地按旧栈写代码。环境类条目建议标注更新日期。
- **写成散文**。结构化 bullet 的遵循度明显好于大段自然语言，LLM 对短句和列表的解析稳定得多。

## 可复用建议

- **冷启动用采访法**：直接让 Agent“问我 10 个问题，生成 USER.md 初稿”，比从零写快得多，还能挖出你自己没意识到的偏好。
- **环境信息自动生成**：写个脚本输出 OS、shell、工具链版本，定期粘贴进环境小节，避免手写漂移。
- **分层而非膨胀**：USER.md 只放跨项目稳定事实；单仓库的约定放该仓库自己的文件；两者冲突时明确写清“谁赢”。
- **给偏好标注强度**：区分“硬规则”和“默认倾向”，只有硬规则才允许出现“必须”。

## 总结

USER.md 不提升模型能力，它压缩的是固定成本：把每次协作前“你是谁、怎么跟你配合”的解释工作变成一次配置。做法上抓住三点——短、结构化、版本化。建议今天先起一个 10 行的最小版本跑两周，按实际摩擦迭代，比一次写满更有效。
