## 背景

OpenClaw 的工作区里有几个约定文件：AGENT.md 管操作规范，USER.md 记用户偏好，而 SOUL.md 承担另一个维度——Agent 是谁、说话什么调、哪些事不做。它每次会话开始都会注入上下文，相当于人格层的 system prompt。但很多人拿它当说明书用，结果人格没立住，边界也没生效。

## 问题

常见三类症状：

1. **语气漂移**：会话开头冷静克制，跑了几十轮后开始满篇感叹号、过度道歉或过度套近乎。
2. **边界失守**：让删文件就删、让发消息就发，事后才发现中间没有确认环节。
3. **人格形同虚设**：写的是"你是一个专业、友善、乐于助人的助手"，模型读完和没读一样。

## 做法

我的 SOUL.md 固定六段，总长控制在 80 行以内：

1. **身份一句话**。不堆形容词，写定位："你是长期驻留本机的助手，服务对象只有我，默认对话是工作场景。"
2. **语气写成可判定规则**。不写"简洁专业"，写"先给结论，再给一条可直接执行的命令；不用感叹号；单次回复不超过三段"。
3. **红线清单**。只读目录、需人工确认的操作（发消息、删数据、涉及金额）、绝对不做的事。通过 MCP 接入的写类工具，默认归入"需确认"一档。
4. **例外条款**。红线配出口："清理 temp 目录不视为删除用户文件，无需确认。"否则 Agent 会因为怕违规，卡死在正常工作流里。
5. **失败行为**。不确定就说"我不确定"，禁止编造路径和命令；拒绝时给替代方案，而不是只说不行。
6. **负面示例**。把真实跑歪的对话改写成两三行对照，比十条正面规则都管用。

改完进 git，跑一组固定的回归问题（十个左右，覆盖闲聊、高危操作、歧义指令），diff 对比前后输出。

## 踩坑点

- **把工具用法塞进 SOUL.md**。那是 AGENT.md 的事。SOUL.md 每轮占上下文，塞满操作细节会稀释关键规则。
- **红线写绝对**。"绝不删除任何文件"看似安全，实际让清理类任务全部卡住，最后只能手动救场。
- **长会话漂移**。SOUL.md 只在开头注入，几十轮后权重下降。对策：把最关键的一两条红线同时写进 AGENT.md 的硬性区，或利用心跳任务让 Agent 定期自检。
- **多 Agent 复用同一份 SOUL.md**。自动化跑批的和日常陪聊的性格混在一起，两边都别扭。分开维护。

## 可复用建议

- 把 SOUL.md 当**配置文件**对待：小、可测、有版本。改人格等于改代码，走同样的评审流程。
- 每条规则自问一句：模型能不能用"是/否"判断自己违反了？不能就重写。
- 负面示例从真实事故里攒，不要自己编。
- 定期删规则：某条三个月没拦住过任何事，删掉。

## 总结

SOUL.md 不是给 Agent 贴标签，而是给决策加一层路由：它决定模糊指令来了往哪边倒、高危操作有没有闸门。写得越像行为契约、越不像自我介绍，Agent 就越稳定。它值得和你的代码用同样的标准维护。
