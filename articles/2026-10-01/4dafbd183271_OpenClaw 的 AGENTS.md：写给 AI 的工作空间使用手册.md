## 背景

OpenClaw 的 agent 是常驻进程：跨渠道收消息、跑定时任务、调用插件和 MCP 工具。它的工作区里有几个各司其职的 markdown——SOUL.md 管人格语气，MEMORY.md 管长期记忆，而 **AGENTS.md 是每次会话都会加载的操作手册**，决定 agent 怎么干活。

问题在于，很多人要么留空，要么贴一段网上抄的模板。手册存在但不生效，等于没有。

## 问题

没有一份靠谱的 AGENTS.md，常驻 agent 的指令缺失会被时间放大：

- **反复摸索**：每次都重新试命令、猜目录、踩一遍已知的坑；
- **叮嘱不持久**：你在聊天里说"别动那个文件"，换个会话它就忘了；
- **行为漂移**：今天长篇大论，明天惜字如金；定时任务失败时刷屏轰炸；
- **越权操作**：直接 shell 连数据库，绕过你配好的 MCP 工具。

本质是：工作区的使用知识在你脑子里，agent 每次都从零开始。AGENTS.md 就是把这部分知识持久化的最便宜的方式。

## 做法

**1. 分层放置。** 工作区根目录的 AGENTS.md 写全局规则：安全约束、回复风格、工具优先级。子项目或技能目录可以放嵌套文件写局部规则，就近生效——注意两层别冲突。

**2. 写这六块内容：**

- **安全硬约束**（置顶）：删改文件先确认；密钥和隐私数据不进聊天记录；工作区外的写操作默认拒绝。
- **工具优先级**：查库用哪个 MCP 工具、发文件走哪个插件、什么情况才允许直接 shell。
- **渠道差异**：聊天渠道回复短句，任务完成后给结构化汇报。
- **定时任务行为**：失败先记日志，不要连续重试刷屏。
- **文件操作规范**：哪些目录是生成产物不许手改，哪些是记忆区可以写。
- **已知坑**：那些你解释过不止一次的事。

**3. 控制篇幅。** 几十行足够，短句加标题分节，命令写成可直接复制执行的形式。agent 吃结构，不吃散文。

**4. 当代码对待。** 进 git、走 review、改了部署方式同步改文档，回滚有据可查。

## 踩坑点

- **写成人向 README**：大段项目历史和口号，白占上下文，agent 每轮都要付费读一遍。
- **职责越界**：把"你是谁"写进 AGENTS.md，把"怎么干活"写进 SOUL.md，两份文件互相打架，行为不稳定。人格归 SOUL，操作归 AGENTS。
- **规则过期**：换了构建方式没更新文档，agent 按旧命令反复失败，你还以为它变笨了。
- **硬约束埋中段**：塞在长文中间的"禁止事项"会被稀释，单独成节、放在前面。
- **什么都往里塞**：五百行的手册不如六十行的卡片，上下文是稀缺资源，省着给真正的任务用。

## 可复用建议

- **错误台账法**：agent 同一件事错第二次，就把纠正写进 AGENTS.md。这是投入产出比最高的一条实践——第三次修复的成本趋近于零。
- **每条规则可验证**："回复默认不超过三句"优于"简洁一点"。
- **每月 review 一次**：删掉过期项，手册和代码一样会腐烂。
- **调试心态**：每当想问"它怎么又不知道"，先问自己"这事儿我写进手册了吗"。

## 总结

AGENTS.md 是 OpenClaw 工作区里成本最低、杠杆最高的一层。它不依赖更强的模型，只要求你把脑子里的操作知识写清楚、写短、保持更新。写好这份手册，agent 才能从"能跑"进化到"可靠"——尤其是在你不在场的时候。
