# 社区自动发帖的节奏控制：怎么不像机器人

## 背景

我在社区用 OpenClaw + MCP 搭了一条内容管线：博客更新、GitHub release、每周摘要，由 Agent 自动排期发布。跑了一个月后发现，自动化解决的是“懒得发”，却制造了新问题——发布痕迹太机械，评论区直接有人问“这号是脚本吧”。

## 问题

复盘下来，机械感来自四个特征的叠加：

1. **时间规律**：固定每天 09:00 整发布，翻历史记录一目了然；
2. **批量连发**：三条更新挤在同一批队列里，间隔不到两分钟；
3. **结构同构**：每篇都是同一个模板，连开头句式都一样；
4. **零互动**：发完即走，评论从不回复。

单独看每条都不致命，叠加起来就是典型的 spam 信号，对社区体验和账号权重都是损耗。

## 做法

**第一步，排程去规律化。** 放弃 cron 整点，改成“目标时间窗 + 随机偏移”：工作日 09:30–11:00 之间取随机时刻，节假日直接跳过。日上限设 1–2 篇，同版块两次发布间隔不小于 6 小时。

**第二步，先合并再发。** 管线里加一道聚合层：同主题的多条更新合并成一篇 digest，而不是拆成 N 篇碎片。发布频率天然降下来，信息密度反而上升。

**第三步，内容差异化。** 模板只保留骨架，首段由人工写或改，且每篇至少包含一个“只有人才能给出”的信息点——为什么值得看、踩过什么坑。再对最近 20 篇做相似度检查（n-gram 重合率就够用），超阈值直接退回队列。

**第四步，人在环路。** Agent 产出进入待审队列，人工过目后一键放行或修改后发。账号的评论、回复等社交行为保持人工，至少前期如此。

**第五步，观测与回退。** 记录每次发布的时间和互动数据，每周复盘。某类内容互动持续走低就降频或停掉，而不是继续灌。

## 踩坑点

- **伪随机**：第一版 jitter 只随机了小时，分钟恒为 0，看起来依然规律；
- **时区**：服务器是 UTC，定时任务在本地凌晨触发了好几天才被发现；
- **重试无幂等**：网络超时后重发，同一篇连发两次，比不发更伤信誉。发布动作必须带幂等键；
- **把“人味”理解为加表情和口语词**：结构化内容硬塞语气词反而更假，克制更重要；
- **补发积压**：频率调低后管线积压，某天一次性补发五篇，观感极差。宁可丢弃或顺延到下一期。

## 可复用建议

1. 节奏参数（时间窗、日上限、最小间隔、相似度阈值）全部做成配置，别硬编码在插件里；
2. 所有发布动作收敛到同一个 sender 模块，统一限流、幂等和重试策略；
3. digest 永远优于碎片，少发优于多发；
4. 如果账号本质上就是自动化发布，老老实实标注来源和规则，比伪装成真人可持续得多——“不像机器人”的目标是别刷屏、别千篇一律，不是骗过谁。

## 总结

节奏控制的本质，是频率、时段、内容密度、互动四个变量的联合调参。Agent 负责产出和排期，人负责判断和温度，管线负责限流和幂等。把机器的效率用在生产上，把机器的没分寸挡在发布前，社区里就不会有人觉得“这是脚本”。
