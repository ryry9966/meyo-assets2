## 背景

OpenClaw 这类常驻型 Agent 和普通聊天机器人最大的区别，是它长期"活"在你的机器上：跑定时任务、接 MCP 工具、在你的项目目录里干活。但每次会话启动时，模型上下文几乎是空的——它不记得你的时区、技术栈、代码风格偏好，甚至不知道你习惯用中文交流。

OpenClaw 工作区里已有一套约定文件：`AGENTS.md` 管行为规范，`SOUL.md` 管人格，`MEMORY.md` 管事件记忆。`USER.md` 是其中最容易被忽略的一个——它是"关于你这个人的档案"，会在会话开始时注入上下文。

## 问题

没有 USER.md 时，典型表现是：

- 每次都要重复交代"我用 Arch + Neovim，别给我推 VS Code 的方案"；
- 定时任务跑出来的结果不符合预期，因为 Agent 不知道在为谁工作；
- 回答风格漂移：一会儿极简，一会儿啰嗦。

本质上是 Agent 对你的认知全靠会话内临场推断，成本高且不稳定。

## 做法

1. 在工作区根目录（通常是 `~/.openclaw/workspace/`）建 `USER.md`，控制在一屏以内，30~50 行。
2. 分区块写，推荐结构：

```markdown
# User Profile
## 基本面
- 时区：Asia/Shanghai；主要用中文沟通
## 技术环境
- 日常机：Arch Linux，编辑器 Neovim，主力语言 Go / Python
## 偏好
- 回答先给结论，代码给最小可运行版本
- 不主动推荐新框架，除非问题本身涉及
## 当前上下文
- 最近在做一个 MCP server 的日志采集模块
## 红线
- 不动 ~/data 下的原始数据；git 操作前先确认分支
```

3. **让 Agent 自己维护它**，这是关键一步。直接对它说："把对话里确认的长期事实更新到 USER.md，只记稳定信息。"再约定每周让它自查一遍，删掉过时条目。
4. 和 `MEMORY.md` 分工：USER.md 放"稳定的人设"，MEMORY.md 放"流动的事件"。判断标准很简单——三个月后还有效的写前者，只有本周有意义的写后者。

## 踩坑点

- **写太长**。USER.md 每次会话都进上下文，200 行档案等于给每个请求加固定税，重要偏好反而被稀释。超过 60 行就该删。
- **放敏感信息**。时区、技术栈没问题，但 API key、住址、证件号别写——这些内容会随上下文发往模型服务端。需要引用敏感配置就用环境变量名占位。
- **把偏好写成死规则**。"永远不要用 Docker"这种绝对化表述，会让 Agent 在该用容器的场景硬绕弯。改成"默认不用，除非我明说"。
- **只写不改**。过期档案比没有更糟，Agent 会拿着你两年前的技术栈做推荐。定一个固定节奏（比如每月一号）让它自查。

## 可复用建议

- 建一份固定模板，多台机器、多个 Agent 实例之间直接复制，保持认知一致；
- 把工作区纳入 git 管理，档案变更可追溯，也能发现 Agent 有没有乱改；
- 团队场景下每人一份独立 profile，不要共用；
- 用心跳或定时任务做"档案巡检"：让 Agent 列出它认为可能过时的条目，你确认后删改。

## 总结

USER.md 是所有 Agent 配置里性价比最高的一件事：十几分钟写完，之后每一次会话都受益。它解决的不是模型能力问题，而是"默认上下文缺失"问题。Agent 干活不给力，有时不是提示词不行，而是它根本不知道在给谁干活。先花十分钟写第一版，再让它在日常协作里自己生长——这份档案会长成你和 Agent 之间最有效的接口契约。
