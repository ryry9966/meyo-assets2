## 背景

OpenClaw 的 Agent 行为不只由模型决定。工作区里有一组 Markdown 文件各司其职：AGENTS.md 管"怎么干活"，MEMORY.md 管"记住了什么"，而 SOUL.md 管"你是谁"——它在会话启动时注入 system prompt，并在会话压缩或重置后被重新注入。这意味着 SOUL.md 是少数能跨会话稳定生效的行为约束，值得当成配置文件认真维护，而不是随手写两行感想。

## 问题

不写 SOUL.md 也能跑，但跑久了会暴露几类问题：

- 默认人格偏"客服腔"，回复冗长、爱堆 emoji，在群聊里尤其吵；
- 长会话后期行为漂移，早期定的规矩悄悄失效；
- 该拦的事不拦：未经确认给联系人发消息、顺手装依赖、自作主张改配置；
- 工作频道和生活频道共用同一个 Agent，语气错位。

## 做法

1. **定位文件**：默认在 `~/.openclaw/workspace/SOUL.md`，没有就新建。
2. **控制篇幅**：200–500 字足够，核心规则放最前面，越靠后权重衰减越明显。
3. **写可验证的行为，不写形容词**。"回复先给结论，尽量三句内收束"是规则；"要聪明、有温度"不是。
4. **划硬边界**：未经确认不主动给联系人发消息；不静默执行安装和删除；涉及花钱、删数据的操作必须二次确认。每条一个动作，方便对照排查。
5. **声明优先级**：当"简洁"和"解释清楚"冲突时听谁的。规则之间不打架，Agent 才不会随机二选一。
6. **持续迭代**：观察到坏行为就补一条规则；也可以让 Agent 自己提议修订，人工把关后合入。把 workspace 纳入 git，改动可回溯。

注意分工：SOUL.md 写"是谁、什么能做什么不能做"；AGENTS.md 写"用什么工具、怎么干活"。别把操作手册塞进人格文件。

## 踩坑点

- **写成小作文**：三千字的 SOUL.md，中后段基本被稀释，等于没写。
- **边界只写在 prompt 层**：prompt 约束是软的，挡不住注入和模型抽风。发消息、执行命令这类高危动作，要在 gateway 或插件层再加一道确认或白名单，软硬双层都上。
- **改了没生效就以为写错了**：修订在新会话才稳定生效，改完重开会话再验证。
- **长会话漂移**：依赖系统对 SOUL.md 的周期性重注入，重要规则务必前置，别指望模型全程记得第四十条。
- **人设用力过猛**：设定"毒舌损友"风格，三天后自己都想关掉。人格服务于可用性。

## 可复用建议

- 模板五段：一句话身份 / 语气与语言 / 硬边界 / 优先级 / 自我修订方式。
- 上线前做一次红队测试：明确要求它做边界内禁止的事，看拦不拦得住。
- 每季度 review 一次，像对待 nginx 配置一样对待它。
- 多频道、多用户场景，考虑拆多个 workspace，各配各的 SOUL.md，别一份人格打天下。

## 总结

SOUL.md 不是玄学，而是一份低成本的、可版本化的行为配置。它决定不了模型能力的上限，但能守住下限：语气稳定、边界清楚、行为可预期。写短、写具体、软硬两层都设防，比任何精心设计的"灵魂"都实用。
