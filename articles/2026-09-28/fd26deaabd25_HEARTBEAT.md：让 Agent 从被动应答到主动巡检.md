## 背景

大多数 Agent 的使用模式是"拉"：你提问，它回答。但想把 Agent 当数字员工长期用，很快会遇到反向需求——"到点主动看一眼，有事再喊我"。比如磁盘水位、某个仓库有没有新提交、证书快过期、每晚汇总一次当天未读消息。OpenClaw 为此提供了一个很轻的机制：HEARTBEAT.md。Agent 按固定间隔被唤醒，读取工作区根目录下的这个文件，自行决定做不做、说不说。

## 问题

实践中常见两种失败形态：

1. **Agent 从不主动做事**——工作区里没有 HEARTBEAT.md，或者写了一大篇描述性散文，模型每次心跳都无从下手；
2. **Agent 变成垃圾信息源**——每隔 30 分钟发一条"一切正常"，三天后你把它静音，机制等于报废。

心跳的本质是"定时唤醒 + 读清单 + 自行判断"。判断规则不写清楚，行为就不稳定。

## 做法

1. 在工作区根目录（默认 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`，写成检查项清单，而不是文章。每项一行，包含三要素：**触发条件、要做的动作、发给谁**。例如：
   - `磁盘使用率 > 80% 时，执行 df 定位大目录，告警推送到 Telegram`
   - `每天 21:00 后的首次心跳，汇总当天未读消息要点`
2. 配置里确认 `agents.defaults.heartbeat.intervalMs`，默认 30 分钟，大多数巡检场景够用。
3. 明确写出静默规则：所有检查项都不命中时不要发消息。OpenClaw 的约定是 Agent 无事时返回 `HEARTBEAT_OK`，该回复会被吞掉，不会送达渠道。
4. 用 `activeHours` 限制活跃时段，避免凌晨三点收到"DNS 正常"。
5. 调试期把 intervalMs 临时调到 60000，观察两三轮会话日志，确认行为后改回去。

## 踩坑点

- **写成散文**：模型对长段描述的执行不稳定，务必短句 + 明确条件。
- **清单里放重活**：每次心跳都是一次真实的模型调用。长任务、批量分析应走独立的 cron 任务或 skill，别塞进每次心跳，又慢又烧 token。
- **把心跳当定时器**：心跳是固定间隔轮询，做不到"每天 9:00 准时"。精确调度请用 cron 任务，两者分工不同。
- **多 Agent 改错文件**：每个 Agent 有自己的工作区，确认编辑的是目标 Agent 的那份。
- **引用了不存在的工具**：清单里写了未安装的 skill，Agent 要么静默失败要么编造，保持清单与实际可用能力一致。

## 可复用建议

- 我目前的模板固定三段：**检查项**（条件→动作→渠道）、**静默规则**、**活跃时段**，全文控制在 15 行以内。
- 每月复盘一次：从不触发的项删掉，频繁误报的项收紧条件。Agent 也有"告警疲劳"，信噪比比覆盖面重要。
- 让 Agent 把每次心跳的结论追加到一个日志文件，方便回看它在心跳里到底做了什么，这也是调静默规则的依据。

## 总结

HEARTBEAT.md 是个小文件，但它把交互模型从"你问它答"变成"它巡你定"。价值不在于写多少条，而在于克制：少而准的检查项，加上严格的静默规则，才是一个你愿意长期开着的主动式 Agent。
