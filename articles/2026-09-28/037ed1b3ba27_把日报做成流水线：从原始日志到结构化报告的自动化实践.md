## 背景

团队每天要发日报，内容大多是：服务错误数、关键告警、发布记录、待办进展。以前的做法是各人翻自己的日志和群消息，手动拼一段文字，结果就是耗时不稳定、格式天天漂移、异常经常被漏掉。后来我在 OpenClaw 里用 cron + Agent + 一组 MCP 工具搭了一条流水线，每天早上自动产出结构化日报，人工只做最后确认。运行一个多月，简单说说做法和踩过的坑。

## 问题拆解

核心不是"让模型写日报"，而是把日报拆成两层：

- **数据层**：从多个来源抽取、清洗、聚合成固定的 JSON 结构，这一层必须确定性、可重跑；
- **叙述层**：让 LLM 基于聚合结果套模板生成文字，只负责表达，不负责算数。

想通这一点之后，整条流水线的设计就清晰了。

## 做法

1. **采集**：cron 每天 08:30 触发。通过 MCP 工具拉取三类数据：Nginx 访问日志摘要、应用错误日志、CI 与发布记录。每个来源一个独立工具，失败互不影响。
2. **归一化**：一个本地脚本把不同格式统一成 `{source, ts, level, metric, tags}`，按天聚合出：错误总数、Top5 错误、新增告警、昨日合并的 PR 列表。
3. **生成**：把聚合后的 JSON（不是原始日志）交给 Agent，prompt 里固定模板：概览 / 异常 / 变更 / 风险。明确要求模型只引用 JSON 里的数字，不补充未提供的信息。
4. **投递**：产出 markdown 存档到 `reports/2025-xx-xx.md`，同时推送到群。失败时推一条告警，而不是沉默。

## 踩坑点

- **原始日志直接进模型**：token 爆炸且数字不可信，模型会"编"出一个看起来合理的错误数。解法是先脚本聚合，数字一律来自脚本，模型只做叙述。
- **时区问题**：日志源是 UTC，人是 UTC+8，第一天日报的"昨日"跨错了半天。统一在归一化层转时区。
- **日志轮转**：08:30 拉取时昨天的文件已被切走。改成按日期 glob 兜底，拉不到就输出空值并标注"来源缺失"，而不是报错中断整条流水线。
- **格式漂移**：模型偶尔自作主张改标题、加感叹号。把模板逐字段写死在 prompt 里，格式就稳定了。
- **敏感信息**：日志里偶有 token 和手机号，进模型前先过一层脱敏正则。

## 可复用建议

- 数据层和叙述层彻底分离，聚合脚本可以单独测试；换模型不影响数字正确性。
- 报告按天存档为纯文件，方便 diff 和回溯，也为后续周报、月报提供了原料。
- 每个数据源做成独立 MCP 工具，新增来源就是加一个工具，主干不动。
- 上线前跑两周"影子模式"：流水线产出但人工核对，确认数字可信后再切自动推送。

## 总结

这条流水线的价值不在"省了写日报的十分钟"，而在把报告的口径固定下来：数据来自脚本、叙述交给模型、格式由模板锁死。日报只是第一个应用，同一套结构换掉数据源，就能直接复用到周报、值班交接和事故复盘。
