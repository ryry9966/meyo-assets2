## 背景

用 OpenClaw 挂定时任务、接 MCP 工具做社区自动发帖的人越来越多：日报汇总、版本更新播报、RSS 精选。跑起来不难，难的是跑久了不被当噪音。最常见的短板不是内容差，而是节奏太"整齐"——整点发、间隔恒定、格式一样，人眼扫三下就能断定是脚本。

## 问题：机械节奏的三个特征

1. **时间特征**：固定 cron，每天 09:00:00 准时出现，误差为 0；
2. **频率特征**：不管社区活跃不活跃，每小时一条，深夜照发；
3. **内容特征**：同一模板、同一句式、同一组 emoji，标题结构完全一致。

反垃圾系统和真人用户识别的其实都是这些统计特征。解法不是伪装，而是把行为真的调整得更接近一个有作息、有判断的参与者。

## 做法：四层节奏控制

**1. 时间层：抖动 + 活跃窗口**

cron 只负责"起跑"，实际发布时间加随机偏移。注意用近似正态而不是均匀分布——均匀随机依然很假。±20 分钟内比较自然，同时定义活跃窗口（比如 8:30–22:30），窗口外顺延：

```python
delay = random.gauss(0, 8)  # 分钟级正态抖动
if not in_active_window(now + delay):
    delay = seconds_until_next_window() + random.gauss(0, 8)
```

**2. 频率层：配额 + 退避**

令牌桶限速，日配额按社区规模定，小社区一天 2–3 条足够。触发密集时进队列排队而不是连发；失败重试用带抖动的指数退避，别用固定 60 秒。

**3. 内容层：结构轮换**

时间调好了，模板一成不变照样露馅。准备 3–5 套结构（列表体 / 段落体 / 问答体），标题句式轮换，署名和 emoji 规则也随机化。变量注入时别每次填满所有字段——真人经常偷懒。

**4. 反应层：阅读延迟**

回复类任务不要触发即回。加一个和内容长度相关的"阅读延迟"（每千字 20–40 秒 + 抖动），发之前拉一下社区最近流：刚有人发了相似内容，就降级或合并，而不是再顶一条。

## 踩坑点

- **均匀随机 ≠ 像人**。人的行为是突发 + 长尾的，正态 / 对数正态分布更接近；
- **过度随机更假**：凌晨 4:23 发一条比每天 9 点差多了，安静时段比抖动幅度更重要；
- **抖动加错层**：触发抖了，重试还是固定间隔，一样露馅；
- **时区错位**：服务器跑 UTC、社区在东八区，活跃窗口整体偏 8 小时，先对齐时钟；
- **忽略反馈信号**：连续几条无人互动还按原节奏推，本身就是异常，该降频。

## 可复用建议

- 把四层封装成一个调度模块（或做成 MCP tool），参数化：窗口、抖动幅度、配额、模板池，每个社区一份配置；
- 上线前先 dry-run 一周，只记录计划发布时间不发帖，人工看一眼时间分布图，不合理再调参；
- 保留 10% 人工抽检，重点看内容结构相似度——时间节奏可以量化，内容节奏只能靠看。

## 总结

节奏控制的本质不是"骗过谁"，而是做一个不那么吵的社区成员：有作息、有配额、有变化、会看反馈。这套东西做成配置化调度模块，一个下午就能接进现有 OpenClaw 定时任务，收益是长期的——你的自动化内容会真正被读，而不是被折叠。
