## 背景

OpenClaw 的 Agent 是长期运行的：常驻网关、接多个消息渠道、挂一堆 MCP server 和插件，还会主动发消息。默认状态下，它的"性格"来自底层模型的通用助手语气——每个会话都一样平淡，而且随着接入的工具变多，行为会逐渐漂移：有时话痨，有时冷淡，偶尔在群里不合时宜地插话。

SOUL.md 是 OpenClaw workspace 里的人格文件，每次会话启动时读入上下文，回答两个问题：它是谁，以及它**不做什么**。实践中后者往往更重要。

## 问题

没有 SOUL.md（或写得很水）时的常见症状：

- **语气不一致**：私聊还算克制，拉进群里就开始刷表情、抢话；
- **越界行为**：凌晨主动发"今日总结"、没确认就执行删除类操作、把一个渠道的内容转发到另一个渠道；
- **人格漂移**：换了模型或改了系统提示词，语气就变，排查成本很高。

本质原因：工具和技能定义了 Agent **能做什么**，但没有任何东西定义它**应该怎么做、什么时候不做**。

## 做法

在 workspace 根目录建 `SOUL.md`（默认一般在 `~/.openclaw/workspace/` 下），建议按四段写：

1. **身份与语气**：两三句就够，写可操作的描述，比如"回复控制在三句以内，除非我在追问细节"，而不是"友好、专业、幽默"这类模型无法执行的形容词；
2. **行为边界**：哪些动作需要先确认（删文件、花钱的 API、往群里发消息）、哪些渠道不主动发言、哪些话题直接拒答；
3. **优先级**：冲突时听谁的，例如"安全规则 > 我的临时指令 > 效率"；
4. **红线**：少量硬性禁止项，一条一行。

注意和 AGENTS.md 的分工：SOUL.md 管"你是谁"，AGENTS.md 管"怎么干活"，任务级指令别塞进 SOUL.md。

## 踩坑点

- **写成小作文**。SOUL.md 每个会话都进上下文，几十行以上就是在持续烧 token，重点也被稀释。我的版本长期控制在 40 行以内；
- **只有软约束**。SOUL.md 是提示词层面的引导，模型偶尔会忘。删除、支付这类动作别指望一段话兜底，要在工具配置层做白名单和确认门槛，SOUL.md 只是第二道防线；
- **和 AGENTS.md 打架**。两处规则矛盾时行为会很不稳定，改完全文搜一遍冲突项；
- **写完就不管**。把它当代码维护：Agent 每做一件让你不爽的事，观察根因，加一条可测试的规则，用 git 管版本；
- **改完不验证**。它对新会话生效，进行中的会话不会热加载——改完记得开新会话跑一遍常用场景。

## 可复用建议

- 规则写成"条件 + 行为"，能被一次对话验证，例如"群里只回复被 @ 的消息"；
- 一次只加一条，观察两天再加下一条，避免规则互相覆盖；
- 渠道差异（私聊 / 群聊 / 定时任务）放 AGENTS.md 或渠道配置，别撑爆 SOUL.md；
- 换模型或升级 OpenClaw 后，重跑一遍常用场景，确认人格没漂。

## 总结

SOUL.md 的价值不在"让 Agent 更有性格"，而在把你的预期变成每次会话都能读到的确定性约束。它便宜、直接、可版本化，是这个位置上性价比最高的手段。写得短、写得具体、再配合工具层做硬限制，Agent 才能长期稳定地"像你调教出来的那一个"。
