## 背景

跑 OpenClaw 的人大多不止一台机器：开发机、家里常驻的主机、可能还有一台 VPS。行为可以用 AGENTS.md 统一，环境没法统一——macOS 用 brew，Debian 用 apt；开发机有 uv，服务器只有系统 Python；同一个 ffmpeg 在两台机器上路径和版本都不同。

OpenClaw 的工作区约定里，AGENTS.md 管行为，tools.md 用来记录工具使用备注。它的定位正是补这个缺口：让 Agent 开工前就知道"这台机器上工具的真实情况"。

## 问题

不写它的典型症状：

- Agent 猜环境：幻觉出不存在的路径，调用了机器上没有的命令；
- 同一套提示词在 A 机好使，到 B 机报错，排查半天发现是包管理器不同；
- 环境信息堆进系统提示词，装了新工具忘改，提示词永久过期；
- MCP 能标准化暴露工具列表，但暴露不了"这台机器的 ffmpeg 别加 -threads 8"这类本地经验。

本质：环境差异是事实（fact），不是指令，但多数配置体系只给指令留了位置，没给事实留位置。

## 做法

我采用"共享基底 + 本机覆盖"：

1. `tools.md` 进仓库，只写与机器无关的约定：命名偏好、禁用项、通用流程；
2. `tools.local.md` 进 .gitignore，写本机事实：OS、shell、包管理器、关键二进制路径与版本；
3. tools.md 末尾注明"本机细节见 tools.local.md"，按顺序加载。

条目全部用祈使句，不写说明文。对比：

- ❌ "这台机器装了 uv，它是一个 Python 包管理器"
- ✅ "Python 一律 `uv run`，禁止裸调 `python`"

精简骨架，可直接抄：

```markdown
# 环境事实
- OS: Debian 12 / shell: zsh
- Python: uv（一律 uv run）
- ffmpeg: /usr/bin/ffmpeg 6.1

# 强制约定
- 无 docker，容器类任务直接报错，不要自行安装

# 已知坑
- 大文件写 /mnt/data，/tmp 会被定期清理
```

总行数控制在 50 行内——它每次会话都进上下文，写长了 Agent 会略读，等于没写。

## 踩坑点

- **写成文档而非指令**：描述性长句 Agent 基本不看，祈使句加禁止项才有效；
- **与 MCP 重复维护**：能被 MCP 动态暴露的信息不要手抄进 tools.md，两份事实必然漂移，这里只留探测不到的经验；
- **路径写死**：跨机器复制时 `/Users/xxx` 直接失效；能用 `~` 就用，但部分执行环境不展开波浪号，先实测；
- **放密钥**：整篇会进模型上下文，token、密码一律不出现；
- **过期比缺失更糟**：我给事实区加了验证日期，配一个探测 OS/路径/版本的脚本定期生成草稿，人工核对后覆盖。

## 可复用建议

- 一台机器一份 local 文件，别写"如果是 macOS 就……"的条件句——那是让 Agent 做本该构建期做的事；
- 改工具链的 PR 带上 tools.md 的 diff，当作 review 项；
- 验收方式很朴素：新会话直接问 Agent"列出你当前可用的工具和路径"，答不上来说明文件没加载或写得太绕。

## 总结

tools.md 不是配置系统的替代品，而是机器与 Agent 之间的契约层：把环境差异从"运行时意外"变成"声明过的事实"。成本是装工具时多写两行，收益是不用在三台机器上重复调试同一个幻觉路径。够便宜，值得做。
