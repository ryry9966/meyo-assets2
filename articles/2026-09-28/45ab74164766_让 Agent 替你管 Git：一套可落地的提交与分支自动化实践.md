## 背景

我本地常驻一个 OpenClaw 工作区，日常让它跑脚本、看日志、整理周报。用了一段时间后发现，它离"独立开发助理"最近的一步是接手 Git：提交信息随手写、分支开完不删、改动攒一大坨一把梭——这些琐事最适合丢给 agent。

## 问题

先明确要解决什么，避免"为了自动化而自动化"：

1. 提交信息质量不稳定，回看历史基本靠猜；
2. 合并后的分支残留，两三个月能攒下十几条；
3. 一次改动横跨多个模块，拆分提交全靠自觉；
4. 直接让 agent"帮我提交"风险高：它可能把 `.env`、日志一起 commit，甚至自作主张 push。

## 做法

我的方案分三层：工具层、流程层、护栏层。

**工具层**：不追求花哨，直接给 agent shell 权限 + 一个状态已知的仓库。MCP 的 git server 也可用，但我实测 shell + 明确 SOP 更可控，报错信息也更完整。

**流程层**：把提交 SOP 写进 skill 文件，核心四步：

1. 先跑 `git status` + `git diff`，禁止只看 status 就下结论；
2. 按改动内容归类，按团队的 conventional commits 规范生成 commit message；
3. 只 add 明确列出的文件，先输出 dry-run 结果等人确认；
4. 确认后执行 commit，默认不 push。

分支清理挂在定时任务上：每周让 agent 列出已合并分支和最后提交时间，输出报告；确认后它再删除。只删 `git branch --merged` 能看到的分支，这条是硬规则。

**护栏层**：

- `push --force`、`reset --hard`、改写历史一律禁止，写死在 skill 里；
- commit 前对暂存内容做敏感文件检查（`.env`、`*.pem` 等），命中就停下上报；
- 所有 git 操作追加到一份操作日志，方便复盘。

## 踩坑点

- **只给 status 不给 diff**：agent 会凭文件名猜改动内容，写出的 commit message 看似专业实则胡说。必须强制读 diff。
- **cwd 漂移**：多仓库环境下 agent 偶尔在错误目录执行命令。后来 SOP 里要求每次先 `pwd` 加 `git rev-parse --show-toplevel` 核对仓库根。
- **中间态没处理**：agent 曾在我一次失败的 rebase 中间态下强行提交，把冲突文件直接 commit 了。现在 SOP 第一步是检查是否处于 merge/rebase 状态，是就直接报错退出。
- **自动提交太勤**：试过每小时自动检查并提交，历史很快变成噪音。改成手动触发 + 每日一条"待提交清单"提醒，节奏刚好。

## 可复用建议

- SOP 沉淀为 skill 文件进版本库，和代码一起演进；
- 权限渐进式放开：先只读报告，再 dry-run，最后才给写权限；
- commit message 让 agent 生成、人来确认，不要全自动；
- 用操作日志代替信任。

## 总结

这套东西没有用任何高级特性，本质是"shell + 明确 SOP + 硬护栏"。agent 管理 Git 最有价值的不是替你打字，而是把"看 diff、分类、核对、确认"这套流程稳定执行。自动化程度建议保持克制：机器做归纳，人做决定。
