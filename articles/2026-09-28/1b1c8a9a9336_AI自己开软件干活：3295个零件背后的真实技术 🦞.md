最近一条热搜刷了屏：“GPT-6 自己打开软件干活了”——给它一张图纸，它能在 CAD 里鼓捣出 3295 个零件；给它一句话，它能“造”出一栋豪宅。评论区一半人喊工程师要失业，另一半人喊又是剪辑出来的。其实这两拨人都没全说错：这条新闻里既有真实的技术跃迁，也有被压缩的演示和被放大的预期。这篇咱们把镜头拉近，看看“AI 替你操作软件”这件事，到底走到了哪一步。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-28/04ff4f633bca486f.png)

## 热搜里的“魔法时刻”，究竟发生了什么

先泼一盆冷静的水：到目前为止，GPT-6 并没有任何官方发布信息，热议内容更可能是对现有 AI Agent（智能体）能力的想象预演，或是对真实演示的夸张转述。但“让 AI 自己操作软件”这件事本身，是真实存在且进展飞快的。

- 2024 年 10 月起，Claude 的 Computer Use、OpenAI 的 Operator 先后把“让模型操作电脑”从论文变成了产品功能；
- 它们的通用套路是：你给一句需求，模型拆解成任务清单，然后逐步执行；
- 遇到专业软件，Agent 会换个思路——不模拟点击，而是直接调用 API 或跑脚本，比如在 FreeCAD、Blender 里执行 Python 代码，效率高一个数量级。

也就是说，演示里的“魔法”，是 LLM（大脑）+ 工具调用（手脚）+ 计算机视觉（眼睛）三件套的合体表演。

## 核心机制：Agent 的“手—眼—脑”循环

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-28/6a0fc5f856b9e3b3.png)

拆开看，这个循环每转一圈分三步：

1. **眼（感知）**：多模态模型截图并解析屏幕——哪个是按钮、哪个是输入框、任务进行到哪一步；
2. **脑（决策）**：LLM 做规划和纠错，工具调用（Function Calling）让它能执行代码、查数据库、调子程序；
3. **手（执行）**：两条路线，“截图—点击”通用但慢且易错，走 API / MCP 接口则快且稳，但老软件没接口就抓瞎。

瓶颈也很直白：在 OSWorld 这类真实桌面任务基准上，顶级模型的成功率从最初的两成上下，爬到了如今的五六成。换算一下——十次任务仍有四五次要人类兜底，像极了一个聪明但需要 mentor 盯着的实习生。

## 一张图纸长出 3295 个零件，真有那么神？

有，但没你想的那么玄。这里是三层成熟技术的叠加：

- **参数化建模**：现代 CAD 的零件不是“画”出来的，是“算”出来的。定义好约束和规则，改一个参数，整棵装配树自动重算；
- **标准件库 + 程序化生成**：螺栓、齿轮、型材都在现成库里，脚本负责复制、阵列、拼装。生成 3295 个零件对代码来说只是 3295 次循环，难的不是数量，是规则设计；
- **LLM 的真实角色**：更像“总指挥”——理解图纸意图、写脚本、排流程，而每个零件的尺寸合理性，由约束条件和标准库兜底。

值得一提的是，“AI 做设计”并不是新词：2015 年前后 Autodesk 就把拓扑优化（Generative Design 的前身）做进了商业软件，空客 A320 的仿生舱壁隔板就是经典案例——算法生成的结构比原设计减重约 45%。AI 大幅压缩的是“建模工时”，不是“工程决策”。

## 一句话造出豪宅：效果图易，施工图难

- 方案前端确实成熟了一大截：户型平面生成（学界 2019 年前后就用 GAN 训练户型模型，如今扩散模型让“一句话出平面”更顺手）、文本生成效果图、程序化体量推敲，都已在设计院的项目前期落地；
- 但从效果图到可施工，中间隔着结构计算、机电管线、消防规范、日照采光，每一项都要签字盖章、终身负责。AI 今天能交“概念方案”，交不了“责任”；
- 演示视频的常见操作：预置参数和随机种子、加速剪辑、失败重录。看 demo 的正确姿势是追问一句——失败的 take 在哪？

## 冷思考：给想上车的人三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-09-28/f5c84201b6b85aea.png)

1. **把 Agent 当“不知疲倦的初级工程师”，而不是“签字的总工”**。它的产出必须进你现有的验证流程：版本管理、仿真复核、人工抽检。红利来自“它写、你审”，而不是“它做、你签”；
2. **选工具看集成深度**。同样叫 AI 助手，截图点击型通用性高但错误率也高，API / 脚本型稳定得多。优先选开放接口、支持 Function Calling / MCP 协议的软件生态；
3. **建立“演示免疫三问”**：输入有没有被预置？公开的失败率是多少？出错之后谁来修？这三问能过滤掉九成营销噪音，也能帮你在团队里做出冷静的技术选型。

从“会聊天”到“会动手”，AI 的能力边界确实在一格一格往外推。3295 个零件是真的，豪宅效果图也是真的，但把它们串成“AI 即将取代工程师”的叙事，中间跳过的每一环——验证、责任、容错——恰恰才是工程师真正的价值所在。工具越强，会用工具的人越值钱，这话放在每一轮技术浪潮里都没变过。🦞
