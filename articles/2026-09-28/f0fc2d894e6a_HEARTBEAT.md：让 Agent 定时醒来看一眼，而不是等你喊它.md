## 背景

大多数时候我们和 Agent 的交互是被动模式：你发消息，它响应。但很多任务本质上是周期性检查——盯磁盘水位、看 GitHub 通知、早上汇总日程。OpenClaw 提供了一个很轻的机制：**HEARTBEAT.md**。Agent 按固定间隔（默认 30 分钟）心跳一次，读取工作区里的这个文件；文件非空，就把内容连同心跳提示一起交给模型，由模型自主决定要不要干活、要不要打扰你。

## 问题

新工作区的 HEARTBEAT.md 默认内容是 `(none)`，等于空——模型调用直接跳过，不花钱也不出声。结果是两极分化：不知道这个开关的人，Agent 永远被动；往里塞一堆任务的人，每 30 分钟被通知轰炸一次，三天后关掉。核心矛盾就一个：**怎么让心跳"该响才响"**。

## 做法

1. 编辑 `~/.openclaw/workspace/HEARTBEAT.md`，写清楚两块内容：
   - **规则区**：什么情况必须出声，什么情况回复 `HEARTBEAT_OK` 保持沉默（模型回复这个约定词时不会转发给你）。
   - **任务区**：每条一行，写清检查方式、判定标准、输出格式。例如"检查 /data 分区，使用率超 85% 才报告，格式：一行文字 + 当前值"。
2. 配置心跳参数：

```json
"agents": { "defaults": { "heartbeat": {
  "intervalMs": 1800000,
  "activeHours": { "start": "09:00", "end": "22:00" },
  "session": "isolated"
}}}
```

3. `session: "isolated"` 很关键：心跳默认跑在主会话里，会污染你正在聊的上下文；隔离开之后例行任务不干扰日常对话。
4. 先用短间隔（比如 2 分钟）跑一轮验证：任务能执行、通知能送达、沉默逻辑生效，再调回正常间隔。

## 踩坑点

- **文件非空 = 每个间隔一次模型调用**。没用的任务行及时清掉，不需要时临时改回 `(none)`。
- "只在我需要知道时才说话"必须显式写进规则区，否则模型倾向于礼貌地汇报"一切正常"。
- 心跳里调用 MCP 工具/插件前，先确认权限已放行，否则它每轮都失败重试，烧 token 还刷屏。
- 任务要幂等且短小。心跳不是 cron，别安排 10 分钟的长任务；大批量活儿让心跳只做"发现 + 触发"，执行交给别的通道。
- `activeHours` 按服务器时区算，部署在 VPS 上先校准时区，否则凌晨三点被叫醒。

## 可复用建议

- 把 HEARTBEAT.md 当配置文件管理，进 git，改动有据可查，出问题能回滚。
- 分层设计：心跳管"低频汇总 + 异常报警"，高频轮询交给外部脚本写状态文件，心跳只读结果做判断，各干各的。
- 给每个任务定义明确的"出声条件"和输出目标（哪个渠道、什么格式）。约束越具体，Agent 长期跑得越稳。

## 总结

HEARTBEAT.md 的价值不在"自动化"这个词，而在于它把"何时打扰用户"的判断权，交给了一个可版本化、可审计的纯文本文件。写好规则区、控住任务粒度、用隔离会话兜底，Agent 就能从一个应答机，变成一个安静值班的同事。
