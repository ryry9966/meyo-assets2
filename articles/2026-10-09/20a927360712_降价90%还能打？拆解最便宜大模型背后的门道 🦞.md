热搜只有一句话：Anthropic 发布了自家史上最便宜的模型，价格暴降 90%，官方评测里多项测试还能压过 GPT-6 Luna 一头。评论区立刻分成两派，一派喊"价格屠夫来了"，一派嘀咕"便宜没好货"。作为常年盯着 API 账单过日子的博主，RY哥想说的是：这条新闻真正值得聊的不是"谁又降价了"，而是降价背后的三件事——成本是怎么降下来的、跑分该怎么读、以及这对你手头的项目意味着什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/0c277c845e071cfd.png)

## 一、先算账：降价 90% 到底意味着什么

大模型 API 按 token 计费，"1M tokens"（一百万 token）是行业报价单位。主流旗舰模型常见定价在输入 $3/1M、输出 $15/1M 这个量级；降 90% 相当于直接打一折，输入价格跌到 $0.3/1M 附近。

- 举个例子：一条每天处理 5000 份工单、每份平均消耗 3000 token 的客服流水线，按旧价格跑一个月，光输出端就可能是几千美元；打一折后直接缩到几百美元。很多原本"算不过账"的场景，一夜之间从立项会的否决项变成了可选项。
- 但要泼一盆冷水：**单价降 90% ≠ 账单降 90%**。经济学里有个 Jevons 悖论——资源越便宜，消耗量反而涨得越猛。单价下来之后，开发者会更放心地让模型多跑、多试、互相校对，总 token 消耗往往跟着膨胀。
- 真正值得盯的指标是"每一美元能买到的智能"。这个指标近几年基本是指数级改善的，降价只是它的又一次显形。

## 二、便宜 ≠ 缩水：降幅是怎么做出来的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/a75c376e0126be4a.png)

硬件降价省不出一个数量级，90% 的降幅主要靠"模型 + 工程"两手抓：

1. **蒸馏（Distillation）**：用旗舰大模型当老师，批量生成高质量合成数据、做答案校验，再把能力"压"进一个小的学生模型。这是各家便宜模型的通用配方——老师在后台加班，学生上一线干活。
2. **架构优化**：MoE（Mixture of Experts）结构让每个 token 只激活一小部分参数，推理成本远低于同体量的稠密模型；配合更高质量的数据，小模型就能在多数日常任务上逼近上一代旗舰。
3. **推理工程**：FP8/INT8 量化、投机解码（speculative decoding）、更大的 batch、更高的 GPU 利用率（MFU）、Prompt Caching（缓存命中的输入按一折计费已是行业惯例）。每项单看都是百分之几十的优化，叠起来就是数量级的差距。
4. **竞争与规模**：推理是典型的规模经济——量大、单位成本低、敢降价、量更大，飞轮转起来。头部厂商贴身价格战，则在后面猛踩油门。

一句话总结：技术进步决定了降价的下限，商业竞争决定了降价的时机。

## 三、"多项测试超 GPT-6 Luna"该怎么读

跑分新闻建议过三个过滤器再看：

1. **看是哪些测试**。MMLU、MATH 这类静态基准，小模型经过精调后冲高分相对容易；而 SWE-bench、长程 agent 任务这类"脏活累活"，才是旗舰拉开差距的主战场。厂商把哪几张卷子贴上海报，本身就是一种表达。
2. **看性价比曲线，别看绝对分**。把"分数/价格"画到一张图上，便宜模型通常站在 Pareto 前沿上——它不是最强的，但对大多数任务是最划算的。对标旗舰的真正意义是逼你重新审视：这个问题，真的需要最贵的模型吗？
3. **看方差，不只看均分**。跑分是平均分，生产环境看的是长尾：1% 的失败率放在日调百万次的服务里，就是每天一万次事故。便宜模型在高难任务上的失败模式会更"活泼"，必须实测。

再补一个工程师冷知识：基准测试存在数据污染（benchmark contamination）的可能——考题混进了训练数据，分数就会虚高。所以第三方榜单和你自己的 eval，永远比官方海报可信。

## 四、这波降价对行业意味着什么

- **应用层是最大赢家**。单次调用成本降一个数量级，意味着一堆场景从"做不起"变成"随便跑"：全仓库代码审查、长文档批量解析、7×24 客服 agent、多 agent 互查互纠。
- **Agent 经济学补上了关键一环**。agent 最大的痛点是 token 消耗量是普通调用的几十上百倍；单价降 90%，等于把 agent 的运行成本压进了可用区间，这是很多 agent 创业者等了一年的那只靴子。
- **全行业毛利承压，降本成为标配**。蒸馏、缓存、量化会被所有厂商卷成基础操作。参考云计算的历史：价格战不是终局，终局是蛋糕整体变大。

## 五、给开发者的行动框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/2621fe920fe1f592.png)

落到实操，三条可执行的动作：

1. **分层路由**：80% 的常规调用（分类、信息抽取、格式转换、简单问答）走便宜模型，20% 的硬骨头（复杂推理、关键代码）留给旗舰。一个几十行的 router，通常能把账单砍掉一半以上。
2. **自建 eval**：拿 100~300 条业务真实样本，横评质量、延迟、成本三个维度，灰度跑一周再切全量。榜单可以看，决策要靠自己的数据。
3. **保持可切换**：用统一的抽象层或网关封装模型调用，别把 prompt 和工具链焊死在某一家上。价格战时代，低迁移成本本身就是议价权。

最后三条冷思考，收工：

1. **单价降 90% 不是智能贬值，而是"智能的电价"又降了一档**。回头看历史上每一轮降价，省出来的预算最后都变成了更大的用量，而不是更小的账单。
2. **最贵的从来不是 token，是错误的 token**。高危任务上一次错误决策的返工成本，可能吞掉省下的全部 API 费——便宜模型要用在它配得上的地方。
3. **"便宜模型 + 强工程"正在取代"贵模型裸奔"**。路由、缓存、eval、抽象层……真正的护城河，已经从"用哪家模型"变成了"怎么用模型"。
