最近 36kr 一篇实测把「ChatGPT 教我打麻将」送上了热议：AI 不再只输出一段段文字，而是直接在对话里摆出牌桌、演示出牌逻辑，你甚至能点着一张牌追问"打这张行不行"。很多人第一反应是"花活"，我的判断恰恰相反——这可能是继命令行、GUI、触屏之后，人机交互的又一次范式切换。这篇文章把它拆开看：原理是什么、难在哪、普通人能拿走什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/64f86ee431fc7a29.png)

## 一、新在哪：从“答嘴”到“上手”

- 过去和 AI 协作的标准姿势是纯文本流：模型输出 token，前端渲染成文字和代码块。你让它讲麻将，得到的是"先出幺鸡再打三万"这种全靠脑补的说明书。
- 现在，模型可以判断"这个任务适合可视化"，然后在对话流里嵌入一块真实的交互区域：牌面摆出来、出牌高亮、点一张牌就能继续问。OpenAI 在 2025 年 DevDay 上推出的 Apps in ChatGPT 与 Apps SDK，本质上是把这套能力制度化——第三方应用可以直接"住进"对话框。
- 关键差别在于：界面不再是产品经理提前画死的固定控件，而是模型根据任务现场调度、按需生成的。业内给这套东西起了个名字——Generative UI（生成式界面）。
- 打个比方：以前的 AI 像只会报菜名的服务员，现在它直接把菜端上桌，还允许你动筷子。

## 二、机制拆解：一块牌桌是怎么被“生成”出来的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/75b26d6fa6240631.png)

这条链路可以分四层看：

1. **意图判断层**：模型先推理"这轮该不该出 UI"。教麻将涉及空间布局、多步骤、高频状态更新，纯文本效率低，界面效率高——注意，这个判断本身是一次模型推理，不是写死的 if-else。
2. **组件调用层**：模型通过 function calling / tool use 输出结构化参数（牌面数据、轮到谁、高亮哪张），前端框架把这些参数映射成真实控件。模型和渲染层之间靠 schema 这份"合同"对接，参数错了界面就崩，所以 schema 设计比花哨动画重要得多。
3. **状态维护层**：麻将真正的难点是状态——吃碰杠、副露、牌池余量。模型要在长上下文里维护一个规则状态机，每步更新后再决定渲染什么。demo 里它能指着某张牌说"这张打出去容易被点炮"，背后是一整套规则推理，不是台词。
4. **回传闭环**：你在界面上的点击、拖动会作为新输入回传给模型，形成"界面 ⇄ 模型"的双向循环。单向广播叫幻灯片，双向闭环才叫交互。

工程师视角一句话总结：LLM 负责"决定显示什么、怎么解释"，渲染框架负责"像素级呈现"，tool call 负责中间的合同。三者解耦，才能既灵活又稳定。

## 三、为什么“打麻将”是个聪明的考题

选麻将当 demo 不是营销偶然，它把交互难题一次性踩全了：

- **空间性**：一百多张牌的位置关系，文字描述是灾难，图形化是刚需。
- **规则复杂且动态**：胡牌判定、听牌分析、防点炮，考验的是模型的规则推理能力。
- **多轮一致性**：一局几十个回合，状态错一步满盘崩，直接暴露长上下文的短板。
- **教学属性**：好老师讲究"边做边指"，这正是交互界面的强项——文本教学像读说明书，界面教学像手把手。

拉长视角看，交互史的主线始终是降低"表达意图"的成本：命令行要求你背语法，GUI 让你点图标，触屏让你直接摸。Generative UI 的野心更进一步——界面按需长出来，用完即走。机器第一次开始迁就任务的形状，而不是让人迁就机器的形状。

## 四、冷静看：理想很饱满，坑也很具体

- **延迟与成本**：每多一轮 UI 调用，就多几次模型推理和一次渲染。对话式 UI 近乎免费，生成式 UI 的每一块"屏"都是真金白银的算力。
- **幻觉搬进了界面**：文字幻觉顶多胡说八道，界面幻觉会画出一张不存在的牌、算错一个状态——而且人天然更相信看得见的东西，误导性反而更强。
- **一致性难题**：界面按需生成，意味着同一个任务今天长这样、明天长那样。学习成本没有消失，只是从"记菜单"变成了"记规律"。
- **生态位重构**：第三方应用进驻对话后，流量入口和分发逻辑都会变化。对开发者是机会，也是新的一层平台依赖，押注前先想好退出成本。

## 五、能拿走什么：三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/e5894b10545855af.png)

1. **用户侧**：遇到"说不清楚"的任务，主动要求换交互形态——"画出来""摆个步骤面板""做个对比视图"。界面是工具，别只会打字。
2. **开发者侧**：把业务拆成"结构化数据 + 渲染模板"，用 schema 约束模型输出。宁可界面少而稳，不要花而崩；运气交给真随机，稳定性交给 schema。
3. **判断框架**：一个任务适不适合上生成式界面，看三个指标——空间复杂度高不高、状态更新频不频繁、用户需要"操作"还是"阅读"。三条中了两条，就值得做。

AI 能教你打对每一张牌，但摸不摸得到好牌，还得交给真随机管。交互的下一站未必全盘如此，但方向已经清晰——机器正在学着落子，落在我们不用翻译就能看懂的位置。
