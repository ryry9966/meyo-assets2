## 背景

OpenClaw-CN 里越来越多人的日常是：Agent 挂着 MCP 工具连内部系统，遇到问题就来社区贴日志、贴配置、贴对话记录求助。也有人的 Agent 本身接了社区发帖自动化，定时输出摘要或回复。两条路径叠加，社区实际成了内部信息最容易外泄的出口，而且泄得无声无息。

## 问题在哪

真实见过的三类事故：

1. **求助帖带出上下文**：贴了一整段 Agent 运行日志，里面有系统提示全文、内部 API 域名，还有一段忘了删的 `.env` 内容。
2. **MCP 权限过宽**：filesystem 工具图省事挂了根目录，Agent 上下文里长期躺着内部文档，之后任何一次“把刚才的内容总结一下”都是泄露。
3. **自动化发帖失守**：日报类 Agent 把内部频道讨论汇总后发到公开区，发帖人自己甚至不在被汇总的频道里。

共性很清楚：泄露不是被攻击，而是我们自己把敏感数据喂进了上下文，又没在出口设闸。

## 我们的做法

按三道防线做，缺一不可：

**第一道：收权限。** 每个 MCP server 只挂明确需要的工具和目录，白名单制；数据库工具只给只读账号。演示、教学用 Agent 单独建实例，用假数据，和生产配置物理隔离。

**第二道：出口过滤。** Agent 对外输出（发帖、回帖、生成日报）前加一层代码级校验，不依赖提示词：用正则扫 API key 格式、内网 IP、内部域名、敏感字段名，命中即拦截并替换为占位符。系统提示里同时声明信息分级（公开/内部/秘密），但只作为第二层保险。

**第三道：审计复盘。** Agent 对外输出落一份只增不改的日志，每月抽查看拦了什么、漏了什么。团队约定：社区求助只贴脱敏后的结构（工具名、参数形状、报错类型），不贴原始日志。

## 踩坑点

- **只在系统提示里写“不要泄露敏感信息”基本没用**。提示注入和诱导提问都能绕过，必须靠出口的代码过滤兜底。
- **截图比文本更容易漏**。日志截图角落里的 token、浏览器标签页标题，肉眼自查很难发现。
- **长期记忆是暗雷**。Memory 功能会把会话内容写进持久化记忆，几周后社区问答时被顺手带出来。敏感会话直接禁用记忆，并定期清理记忆库。
- **工具回显别原文透传**。MCP 工具返回结果先做摘要再进上下文，能少带很多不该带的东西。
- **密钥泄露后只删帖不够**。当作已泄露处理，立刻轮换。

## 可复用建议

- 建一份团队脱敏清单：内部域名、IP 段、key 格式、项目代号、客户名，直接喂给出口过滤器。
- 做一个求助帖模板，字段固定，从源头减少“贴整段日志”的冲动。
- 上线前做一次内部“套话测试”：让同事扮演外部用户，尝试套系统提示、工具列表和工作流链路，能套出来的部分就是整改清单。
- 把 CI 里现成的 secret 扫描规则复用到 Agent 输出管道，不必重复造轮子。

## 总结

Agent 泄露的本质是权限设计和出口管理问题，不是提示词写得够不够狠的问题。收权限、加出口过滤、留审计日志，三道防线成本都不高，但每一道都得在事故前建成。社区乐于分享是好事，前提是我们先确认：贴出去的内容，确实只包含打算公开的部分。
