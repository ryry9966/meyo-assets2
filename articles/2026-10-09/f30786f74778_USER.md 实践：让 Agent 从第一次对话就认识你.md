## 背景

OpenClaw 的工作区里有一套约定文件：`AGENTS.md` 约束行为，`SOUL.md` 定义性格，`USER.md` 描述"用户是谁"。前两个大家多少会写，`USER.md` 却经常是空的，或者只有一行名字。结果是 Agent 每次会话都在重新认识你一遍。

## 问题

`USER.md` 缺失或写得差，损失很具体：

- **重复问答**：时区、常用语言、技术栈，每隔几天被问一遍；
- **建议不对路**：你写 Python 它推 Node 的方案，你一个人开发它给团队协作流程；
- **记忆错位**：`MEMORY.md` 记的是"发生了什么"（事件流），`USER.md` 该记的是"我是什么样的人"（稳定画像）。两者混用，事件越积越多，画像永远建不起来。

## 做法

我的 `USER.md` 保持在 40 行左右，分五段：

1. **身份与环境**：角色（如"独立开发者"）、时区、常用语言、工作时段；
2. **技术栈**：主力语言、框架、部署方式。写"是"，也写"不是"（如"本地开发不用 Docker Compose"）；
3. **协作偏好**：回答风格（先结论后细节）、注释语言、是否要解释 trade-off；
4. **红线**：明确禁止项，如"未经确认不要 push""不要替我回复私人消息"。对否定指令的遵守，写进文件比口头交代一次可靠得多；
5. **当前上下文**：正在做的 1–2 个项目和近期目标。这是唯一频繁变动的段，其余四段尽量稳定。

维护走两条线：

- **手动**：改完就提交 git，把它当个人配置而非随手笔记；
- **半自动**：在 `AGENTS.md` 里加一条，当用户说"记住：xxx"且内容属于稳定偏好时，先提议更新 `USER.md`，确认后写入。事件类记忆仍走 `MEMORY.md`。

## 踩坑点

- **写成简历**。早期我写了两百字职业经历，实测回答质量没变好，每次会话反而多烧一段 token。画像要的是决策相关信息，不是生平；
- **把可变状态写进来**。"这周在修登录 bug"三天就过期，过期信息比没有信息更糟，Agent 会基于它做错误假设。这类内容放 `MEMORY.md` 或留在会话里；
- **三个文件职责打架**。有段时间 `SOUL.md` 写"简洁直接"，`USER.md` 写"需要详细解释"，输出风格来回摇摆。后来明确分工：`SOUL.md` 管人格语气，`USER.md` 管客观事实与偏好，冲突以 `USER.md` 为准，并把这条仲裁规则写进 `AGENTS.md`；
- **敏感信息裸奔**。住址、证件号、密钥不要放。这个文件大概率随 system prompt 发给模型服务端，按"会出网"的标准来写；
- **写完就不管**。换了技术栈、换了工作重心，文件不更新，Agent 就一直拿着旧地图导航。

## 可复用建议

- 每月跑一次"画像校准"：让 Agent 对比 `USER.md` 与近期对话，列出建议增删的条目，人工确认后落盘。五分钟能清掉大部分腐烂条目；
- 项目级差异别塞进全局画像。某个仓库的特殊约定写进它自己的 `AGENTS.md`，全局 `USER.md` 保持"最大公约数"；
- 拿不准某条该不该写，用一个标准过滤：**半年后仍然成立、且会影响 Agent 决策的，才进 `USER.md`**。

## 总结

`USER.md` 是成本最低的 Agent 个性化手段：一个纯文本文件，几十行，换来少重复自我介绍、建议更对路、红线更可靠。它不是记忆系统，而是记忆系统的地基，把"我是谁"从对话里固化下来，Agent 的上下文才有稳定锚点。建议今晚花十分钟写第一版，剩下的交给 git 和每月校准。
