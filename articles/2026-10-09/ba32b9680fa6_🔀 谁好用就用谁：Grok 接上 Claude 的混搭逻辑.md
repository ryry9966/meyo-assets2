最近 AI 圈有条新闻热度不低：据 36kr 等媒体披露，Grok 的部分机器人功能被发现实际调用了 Claude 模型来完成，马斯克一方的态度也很直白——谁好用，就用谁。自家就是大模型公司，转身去接竞争对手的 API，乍一听像“打脸”，但如果你翻过 Cursor、Perplexity 这些产品的技术栈，就会发现这是行业里早已公开的常规操作。这篇就拆一拆：“跨厂混用模型”背后，到底是一笔什么账。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/4e94684ea20a9a82.png)

## 一、先还原事实：不是“跪了”，是“接线”

最常见的误读，是把“产品”和“模型”划等号。拆开看：

- **你看到的对话框只是前端**。一个 AI 应用的后端通常是一条流水线：意图识别 → 任务分发 → 具体模型处理 → 结果加工。哪个环节用谁家的模型，纯属工程决策。
- **这次事件的本质是“路由”被看见了**。Grok 某些任务（长文写作、代码类需求是重灾区）被发现由 Claude 完成，等于平时藏在后端的接线图暴露在了用户面前。
- **早有先例，而且全是头部产品**：
  - Cursor 允许在 GPT、Claude、Gemini 之间自由切换，用户自己就能选；
  - Perplexity 的问答混合了多家模型与自研模型；
  - 各家手机助手，也普遍是多模型混搭。

类比一下：三星一边和苹果在高端机市场杀得难解难分，一边给苹果供应屏幕和芯片。API 时代的大模型行业，正在复制这种“竞合”（coopetition）结构——市场上是对手，供应链上是客户。

## 二、模型路由：一套成熟的工程打法

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/1ca6ed4e91708f6d.png)

“谁好用用谁”听起来像口号，落到工程上叫 **model routing（模型路由）**，标准架构三层：

1. **任务分类器**：先判断请求是写代码、改文案、做数学还是闲聊，通常用轻量小模型做意图识别，单次成本几乎可以忽略；
2. **能力映射表**：每类任务对应性价比最优的模型，依据包括公开基准（SWE-bench 看代码、GPQA 看科学推理、AIME 看数学）和自家业务评测集；
3. **调度与兜底**：限流、超时、宕机时自动切换备选模型；简单问题走便宜小模型，难题再升级到旗舰模型（cascade 级联模式），整体单价能砍一个数量级。

为什么要这么麻烦？看几组量级就懂了：

- 主流厂商的旗舰模型与轻量小模型，API 牌价常相差 5~10 倍，而真实业务里大部分请求其实是简单请求；
- 训练一个前沿模型的成本以数亿美元计，而一次 API 调用只要几美分——“造”与“买”的经济账，完全可以按任务粒度分开算；
- 社区里 LiteLLM、OpenRouter 这类网关与聚合器，早已把上百家模型的接口抹平成统一形状，说明这是被反复验证过的通用架构，不是谁的权宜之计。

工程圈的老话在这里依然成立：能用钱解决的，先别急着重造轮子。

## 三、竞合生意：把 API 卖给对手，为什么双方都乐意

**站在 Anthropic 视角：**

- API 收入是纯增量。借竞争对手产品的出货量给自己铺调用规模，连市场费用都省了；
- 主流厂商对 API 输入默认不用于训练模型（以各家条款为准），所以卖调用权不等于送核心资产——真正的核心是模型权重和训练管线，不是每一次调用的文本。

**站在 xAI 视角：**

- 资源聚焦。算力与顶尖人才优先押注底座模型，边缘任务能买则买，是教科书级的 build-vs-buy 决策；
- 评测文化兜底。用统一的评测集持续给各家模型打分，谁分高用谁，避免“自恋式采购”。

这种剧本历史上反复上演：Netflix 的基础设施跑在 AWS 上，而亚马逊自家的 Prime Video 是它最直接的对手之一；Google 每年向苹果支付巨额费用换取 Safari 的默认搜索位，两家在搜索业务上同样针锋相对。商业世界里，“台上对手、台下客户”从来不是新闻。

## 四、风险与边界：借来的能力终究是租的

当然，这套打法不是没有代价：

- **供应安全**：把关键功能架在对手的 API 上，等于把一部分咽喉递了过去。对方涨价、限流、调整服务条款，你的产品体验第二天就得跟着抖三抖；
- **差异化稀释**：当所有人都能调用同一批模型，产品体验的天花板就被压平了。护城河开始从“模型本身”向数据、分发渠道、交互设计和路由层转移；
- **动态收敛**：路由表是活的。今天接 Claude，明天自家新版本在评测里反超，就切回来——这类接入多半是过渡态，而不是终局。

一句话总结：**混搭是战术，自研是战略**，两条腿走路缺一不可。

## 五、给开发者的三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/4b9e53bf605f7fb3.png)

如果你也在做 AI 应用，这件事的启发可以浓缩成三条：

1. **第一天就搭抽象层**：别把某家模型的 SDK 写死在业务代码里。统一请求格式、做 provider 适配器，理想状态是切模型只改一行配置；
2. **用评测说话**：为自己的场景攒几十到几百条评测用例，每次换模型跑一遍。路由决策靠数据，不靠品牌信仰，也不靠热搜风向；
3. **算任务级总账**：成本不是“每百万 token 多少钱”，而是“完成一个任务多少钱”——把重试率、失败率、延迟损失全折进去。有时候一个旗舰模型一步到位，比“便宜模型加三次重试”更划算。

最后一条冷思考：**“接入了 Claude”不等于不行，“全自研”也不等于强**。AI 产品的本质是一摞能力栈，用户只关心最后吐出来的结果好不好。把评判标准锚定在自己业务的真实输出上，比追任何一家模型的传闻都有用——这大概也是马斯克那句“谁好用就用谁”最朴素的工程翻译。
