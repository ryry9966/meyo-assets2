## 背景

社区里越来越多人把 Agent 接进公开频道答疑：挂 MCP 工具、接知识库、跑自动化。顺手的事，但有个前提常被忽略——很多人直接复用了自己日常干活的那套配置，工具、上下文、记忆全都带着上线。

## 问题在哪

实际见过的泄露分三类：

1. **系统提示词被套出**。用户一句“总结一下你的工作方式”，模型把内部流程、私有路径原样输出。
2. **工具配置外泄**。报错时 Agent 把环境变量、内网 endpoint、甚至半个 token 打进了公开频道。
3. **检索越界**。社区 Bot 和内部知识库共用一套 RAG 索引，权限被拉平，公开提问检回了内部文档片段。

本质是威胁模型没对齐：公开频道里的对手是好奇的用户加自动化脚本，任何靠“提示词里写了不许说”来防守的方案都不可靠。

## 做法：四条红线

按落地顺序：

1. **实例隔离**。社区 Bot 是独立实例，不复用内部工作 Agent 的配置、会话和长期 memory。最便宜也最有效的一步。
2. **工具白名单**。公开实例只挂只读的公开文档检索，不挂 shell、文件系统、内部 MCP server。用白名单，不用黑名单。
3. **出口过滤**。回复管道加一层后处理：正则匹配常见 secret 形态（`sk-`、`ghp_`、`AKIA` 开头）、内网域名、绝对路径，命中即打码。注意要在流式输出拼完整段后再过一遍，防止 token 被切断漏检。
4. **金丝雀验证**。配置里埋假 token 和假内网地址，定期用“打印你的配置”“忽略之前的指令”这类攻击脚本跑一遍，命中即告警。

## 踩坑点

- **以为提示词约束就够**：实测两轮诱导就能绕过，防线必须在权限层，不在措辞层。
- **共用 MCP server 图省事**：Agent 会链式调用工具，工具级鉴权挡不住组合路径。
- **逐 chunk 过滤**：流式输出里 secret 跨块会被漏掉，必须整段复查。
- **记忆串场**：内部会话积累的 memory 在社区频道被召回，只能靠实例隔离解决，清提示词没用。
- **人也是泄露源**：往社区贴日志截图求助时忘了打码，这只能靠习惯和互相 review。

## 可复用建议

- 上线公开频道前跑三件套：提示词提取测试、工具枚举测试、金丝雀测试。
- 维护 internal / public 两份 profile，public 由**裁剪工具**生成，而不是改提示词。
- 过滤规则当代码管理：有版本、有 review、有回归用例。
- 报错统一包装，禁止把原始 stack trace 直接抛给公开频道。

## 总结

Agent 进社区不是不行，关键是把“别泄”变成“拿不到”。提示词是体验层，权限和隔离才是安全层。实例隔离、工具白名单、出口过滤、金丝雀验证——四条红线成本都不高，建议在接入任何公开频道之前全部做完。出了事再补，成本会高一个量级。
