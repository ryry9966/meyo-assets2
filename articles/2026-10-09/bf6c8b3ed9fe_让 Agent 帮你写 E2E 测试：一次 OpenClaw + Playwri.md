## 背景

E2E 测试有两个老问题：写起来慢，改起来烦。我们的 Web 项目用 Playwright，但用例长期只覆盖核心路径，UI 一改就红一片，没人愿意修。这次试着把 OpenClaw 的 agent 接进测试流程，目标很克制：让它承担「写初稿」和「修破损」这两块机械劳动，而不是替代人决定测什么。

## 问题

直接对模型说"帮我写个登录测试"，效果通常很差：选择器靠猜（`nth-child` 满天飞）、断言只查"元素可见"、热衷写死等待。根因是它既没见过真实 DOM，也不知道你们的测试规范。所以 Agent 协作的关键不是"会生成代码"，而是给它真实上下文和一条失败反馈回路。

## 做法

**1. 喂上下文。** 把路由表、页面结构、既有用例的风格约定写进仓库的 `AGENTS.md`：选择器优先级 `data-testid` > role > 文本；禁止 `waitForTimeout`；断言必须落到业务结果。这一步的性价比最高。

**2. 接浏览器。** 给 agent 挂上 Playwright MCP，让它真实打开页面、抓 DOM 和可达性树，选择器从真实页面里取，而不是凭想象写。

**3. 一次一个流。** 每个 prompt 只做一个用户流，并要求 agent 先输出流程大纲（步骤 + 每步断言点），人工确认大纲后再生成代码。多花一轮确认，省掉大量返工。

**4. 失败自修。** 跑挂了就把报错 + trace + 截图丢回去，让它改选择器、补断言，循环两三轮。在 OpenClaw 侧可以把它包成一个可复用 skill：输入流描述，输出能跑的 spec 文件。

## 踩坑点

- **选择器**：不强制规范的话，agent 默认给最脆弱的 CSS 路径，规范必须写死在文档里。
- **假断言**：只断"能看见"不算测试，要盯住它是否断到订单状态、跳转 URL、接口返回这类业务结果。
- **环境不一致**：MCP 连的本地数据和 CI 的种子数据不同，本地跑绿的用例进 CI 可能挂。测试数据要固定、可重放。
- **上下文爆炸**：别把整个仓库丢给它，按流裁剪相关页面组件和工具文件。
- **假绿**：同一用例连跑 5 遍再合入，flake 当场暴露，别等 CI 随机红。

## 可复用建议

- 测试规范沉淀成文档，而不是口口相传——这也是 agent 唯一能读到的"团队经验"。
- 维护一份「关键流清单」，agent 按清单逐条补覆盖，避免它自选题材。
- 把「跑—收集 trace—提补丁」固化成固定提示词，修破损就变成一键流程。
- 人工审查只看一件事：断言质量。代码风格让规范管。
- 度量只看两个数：关键流覆盖数、flake 率。别用"生成了多少行测试"自嗨。

## 总结

Agent 擅长的是机械部分：按规范出初稿、按报错修破损，这两件事吃掉了 E2E 维护成本的大头。但"验证什么"的判断不该让渡——那是测试设计的核心。把规范写清楚、把反馈回路搭起来，AI 是个不错的测试初级工；想让它自己定义质量标准，目前还不现实。
