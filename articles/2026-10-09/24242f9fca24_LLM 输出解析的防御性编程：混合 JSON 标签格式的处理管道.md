## 背景

在 OpenClaw 的 agent 循环里，让模型"按约定输出 JSON"是高频操作：工具分派、MCP 参数填充、插件间传数据。提示词里明明写了"只输出 JSON，不要任何解释"，但解析层实际拿到的东西五花八门：三反引号代码块、`<json>`/`<result>` 之类的自定义标签、裸对象、前后还带一句"以下是结果"——同一天里几种形态都会出现。

这不是模型"不听话"，而是分布性现实：换模型、改提示词、调温度，格式分布就漂移。解析层如果只按一种格式写，第一周稳定，之后必然碎。

## 问题

线上实际收到过的形态，大致五类：

1. 三反引号代码块（带或不带 json 语言标记）包裹；
2. 自定义标签包裹，且标签名不固定；
3. 裸 JSON，但前后有空行或一句说明文字；
4. 字符串值里嵌套反引号，导致栅栏剥不干净；
5. 中文提示词场景高发：全角引号""、全角括号｛｝、尾逗号、`//` 注释。

## 做法

把解析做成一条有序管道，每层只解决一类问题，命中即返回：

```python
def parse_llm_json(raw: str) -> tuple[dict, dict]:
    text = normalize(raw)               # 去 BOM、零宽字符，统一换行
    for cand in extract_candidates(text):
        # 顺序：直接 loads → 按行剥栅栏 → 已知标签解包 → 括号配平扫描
        obj, meta = try_load(cand)      # 失败时走宽松修复，meta 记 repaired
        if obj is not None and schema_ok(obj):
            return obj, meta
    raise ParseError(sample=raw[:2000])
```

关键在"括号配平"这层：状态机扫描，跟踪当前是否在字符串内、是否转义，抓出所有顶层 `{...}` 候选，逐个尝试解析，取能通过 schema 校验的那个。全部失败后，把结构化错误回传模型重试，上限 2 次；仍失败就落盘原始输出供人工排查。

## 踩坑点

- **贪婪正则** `r'\{.*\}'` 配 `re.DOTALL`：遇到两个对象或正文里带花括号，直接把不相干内容串进来。用配平扫描替代。
- **只剥三个反引号**：模型在代码示例里会输出四个反引号的栅栏。按行匹配，并放宽反引号数量。
- **非贪婪取标签** `(.*?)`：字符串值里出现 `</json>` 会截断结果。先配平再取，或对候选做校验兜底。
- **全角符号被修复层静默转换**：要单独计数。修复率异常升高通常说明是提示词问题，别让解析器把它吞掉。
- **重试无上限**：一次解析失败触发完整 agent 重跑，token 很快烧穿。上限 2 次，之后走降级路径。
- **超长输出直接上正则**：回溯可能拖垮事件循环，解析前先做长度上限检查。

## 可复用建议

- 单一入口 `parse_llm_json()`，返回值带元数据（提取方式、是否修复过），调用方不要各写各的。
- 把线上失败样本攒成测试语料，解析器任何改动跑全量回归——这类 bug 的典型特征是"修好一个，崩掉另一个"。
- 运行时原生支持结构化输出（工具 schema、MCP structured content）就优先用，手写解析器只做跨提供商兜底，两者不冲突。
- 按失败类型打点：栅栏、标签、配平、修复、schema 各自占比。数据会告诉你该修提示词还是修解析器。

## 总结

防御性编程在这里的核心不是"把脏输出洗白"，而是让失败**可见、可归因、可重试**。假设每一种格式都会出现，把每种假设变成一条管道分支和一条测试用例，解析层就从"碰运气"变成了普通组件。
