## 背景

OpenClaw 的 Agent 每次会话几乎是无状态的，真正决定它“认不认识你”的，是工作区里的上下文文件：SOUL.md 定义 Agent 的人格，USER.md 定义的是你。每次新会话拉起时，这些文件会被注入系统提示词，Agent 对你的全部认知就来源于此。

## 问题

大多数人会花一晚上调 SOUL.md 的语气人设，却让 USER.md 空着，或只写一行名字。后果很典型：

- 时区靠猜：让 Agent 约会议，它按 UTC 算，错了 8 小时
- 偏好靠重复：每次都要说一遍“直接给结论，别铺垫”
- 人际靠回忆：提到“老张”时，它不知道这是合作方还是同事

理论上 Agent 能从聊天记录里慢慢“学”出这些，但那是低效且有损的——记忆会漂移，猜测会出错。这些信息你 30 秒就能写清楚，为什么要让模型猜三个月？

## 做法

在 `~/.openclaw/workspace/USER.md`（以实际部署路径为准）建文件，按“是否影响行为”分类：

```markdown
# 用户画像
## 基本
- 中文交流，所在地 UTC+8
- 工作日 9:00-19:00 在线，深夜消息默认不紧急

## 沟通偏好
- 先结论后细节，代码优先于文字描述
- 不确定时直接问，不要自己编

## 环境
- 主力栈：Python / Linux
- 部署走 Docker，别给裸机命令

## 高频联系人
- 老张：硬件供应商，回复慢，重要事项电话确认

## 红线
- 不主动操作生产环境
- 敏感信息不写入任何文件
```

写完无需重启，下一次会话自动生效。

## 踩坑点

1. **写太长**。这个文件每个会话都占上下文，见过有人写 3KB 的“人生经历”，关键信息反而被淹没。控制在 1-2KB，判断标准：这条信息会改变 Agent 的下一个动作吗？“喜欢喝美式”不会，删掉。

2. **写成简历**。“五年后端经验”对模型没用，有用的写法是“解释技术方案时可默认我有后端背景，跳过基础概念”。

3. **明文敏感信息**。workspace 可能被插件、同步盘、MCP 工具读到。密钥、证件号一律不进 USER.md，用“见环境变量 X”做间接引用。

4. **让 Agent 自动维护这个文件**。它会往里写一次性状态（“今天在赶版本”），污染长期画像。约定：临时状态进 MEMORY.md，USER.md 只收“半年后仍然成立”的信息，且写入前先向你确认。

5. **和 SOUL.md 冲突**。一个说英文回复、一个说中文，行为就靠模型抽签。改完对照检查一遍。

## 可复用建议

- 把 workspace 纳入 git。USER.md 的提交历史就是你偏好的演进记录，回滚也方便
- 每月跑一次定时任务，让 Agent 对比近期对话，**提议** USER.md 的 diff，人工审核后合并——是提议，不是自动写入
- 多实例部署时共用同一份 USER.md，保证所有 Agent 对你的认知一致
- 三行模板兜底：语言与时区 / 沟通偏好 / 一条红线。先跑起来，再逐步加

## 总结

USER.md 是个性化里成本最低、收益最高的一件事。它不是让 Agent 更聪明，而是把“你是谁”从每轮对话里的反复猜测，变成一次性的显式声明。花十分钟写好它，省下的是之后每天重复解释自己的时间。
