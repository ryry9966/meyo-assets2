## 背景

我们社区的内容一直靠几个人手写加手动搬运，节奏不稳定，热点经常错过。于是花了两周做一个发帖机器人：定时收集素材 → Agent 起草 → 人工审核 → 自动发布。目标不是全自动，而是把人从重复劳动里解放出来，同时保留最后一道闸门。

## 要解决的问题

- 素材收集和格式整理占用了大量重复劳动
- 手动发帖容易漏时段、发重、漏署名
- 直接让 LLM 自由发挥会产生编造内容和浓重的 AI 文风

## 架构设计

三层结构，核心原则是**权限最小化**：

1. **调度层**：cron 触发，每天两次固定时段运行，不做高频轮询
2. **Agent 层**：OpenClaw agent 挂载 MCP 工具，负责起草与自检，设置最大迭代次数和总超时
3. **工具层**：三个独立 MCP server 严格分权
   - `fetcher`：只读，抓取素材并附原始链接
   - `publisher`：全系统唯一有写权限的工具
   - `state`：SQLite 存内容 hash、发布记录、重试计数

流程：抓取 → 起草 → checklist 自检 → 写入待审队列 → 人工放行 → 发布 → 回写状态。

## 实施步骤

1. 先手动跑通一次完整流程，把提示词和检查项固化下来
2. 抓取、发布拆成独立 MCP 工具，各用最小权限 token
3. 加状态库：hash 去重、发布历史、失败计数
4. 上 cron 小频率试运行一周
5. 根据日志逐步放权，比如链接类帖子免审

## 踩坑实录

**1. 重试导致重复发帖。** cron 任务超时后重跑，publisher 不知道上一条已发出。解决：发布前先查 state 里的 hash，发布动作携带幂等键，同键二次请求直接跳过。

**2. Agent 编造事实。** 让模型总结社区动态时，它"脑补"了不存在的讨论串。解决：素材必须带原始链接，发布前用 fetcher 校验链接可达；提示词明确"只允许转述素材内容，不得补充"。

**3. AI 文风一眼假。** 排比句、"总之"式收尾，社区成员一看就出戏。解决：挑五条社区真实帖子做 few-shot，句式加负面约束；自检 checklist 不通过的直接重写，而不是硬发。

**4. 工具权限过大。** 最初 publisher 的 token 带删帖权限，属于过度授权。解决：重新申请只含发帖权限的凭据，工具层再做一层操作白名单。

**5. Agent 循环失控。** 起草失败后 agent 反复自我重试，一小时烧掉大量 token。解决：设最大迭代次数和总超时，超限直接落入人工队列，宁可人写也不空烧。

## 可复用建议

- **唯一写入口**：全系统只有一个工具能对外发内容，审计和紧急止血都简单
- **幂等和去重从第一天就做**，不要等出了事故再补
- **人审闸门别急着拆**，跑出两周无事故记录再考虑部分自动放行
- **每次调用记录 prompt 和工具调用序列**，排障基本靠这份日志
- 提示词和 checklist 当代码维护，进 git，改动能追溯

## 总结

机器人本身不难，难的是把"失败是常态"设计进架构：去重、幂等、权限收窄、人工兜底，缺一个都会在生产环境翻车。上线一个月，产出节奏稳定、零事故，人工成本降到每天几分钟审队列。下一步计划让 agent 预筛审核项，但会保留抽检——自动化可以逐步放权，信任必须用记录换。
