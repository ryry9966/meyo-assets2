热搜上"OpenAI 发布可交互界面"，很多人第一反应是：聊天窗口又改版了？其实这次改的不是皮肤，而是产品形态——对话本身开始承载应用。在 2025 年 10 月的 DevDay 上，OpenAI 把 Apps SDK 摆上台面：第三方应用可以以可交互界面的形式直接跑在 ChatGPT 的对话流里，Canva、Spotify、Zillow、Booking.com 成了第一批示范。下面拆四件事：它是什么、怎么实现、为什么做、对谁有影响。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/75282190a82fdbdc.png)

## 从"打字聊天"到"界面操作"，差的不只是一个窗口

- 传统 LLM 交互是纯文本循环：你输入自然语言，模型吐自然语言，所有参数全靠嘴描述——"日期选下周三""地图往左一点"。
- 可交互界面把输入空间扩展了：模型调用的返回不再是文字，而是结构化数据，前端据此渲染出真正的 GUI 组件——日历、地图、滑块、画布，你可以直接点、拖、选。
- 举例：以前让 AI 做海报，它给你一段排版建议；现在它直接在对话里打开一个 Canva 编辑器，你拖元素、改文案，模型在旁边接着聊"背景要不要再暗一点"，你点一下就行。
- 本质区别一句话：从"描述参数"变成"直接操作"。人机交互的带宽，从一句话一回合，变成一次手势触发多个状态变更。

## 背后的技术链条：tool calling + MCP + 沙箱渲染

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/1e2ec36163d7500d.png)

整条链路可以拆成五步：

1. 用户说："帮我找下周去京都、预算千元的酒店。"
2. 模型做意图判断，决定调用某个应用暴露的工具——这套机制就是 2023 年 6 月就落地的 function calling，并不新鲜。
3. 应用的服务端按 MCP（Model Context Protocol）标准返回结构化数据。MCP 是 Anthropic 于 2024 年 11 月开源的协议，OpenAI 在 2025 年 3 月宣布兼容，如今成了 Apps SDK 的地基。
4. ChatGPT 前端在对话流里渲染出可交互组件，通常跑在类似 iframe 的沙箱中，与宿主环境隔离、通过消息通道通信——既保安全，也保稳定。
5. 用户在界面上操作，组件状态回传并写入对话上下文，模型"看得见"你选了什么，接着往下聊。

关键在第五步的双向同步：UI 状态与对话上下文打通，才配叫"可交互"；只展示结果、不回传状态，那只是一张会动的截图。

把时间线拉直看更清楚：2023.06 function calling → 2023.11 GPTs 与 actions → 2024.10 Canvas（协作编辑画布）→ 2025.01 Operator（操控浏览器的智能体）→ 2025.10 Apps in ChatGPT。方向从未变过：让模型不止能说，还能"上手"。

## OpenAI 的算盘：从聊天工具到分发平台

- 官方口径中 ChatGPT 的周活跃用户已达 8 亿量级。把这个入口开放给第三方，相当于把一个巨型流量池的水龙头接了出去。
- 商业想象是标准的应用商店逻辑：早期接入免费，后续大概率走向分成、推荐位乃至广告——订阅之外的第二增长曲线。
- 更深一层是替代想象：传统链路是"搜索 → 点链接 → 跳转 app"，现在需求在对话内直接闭环。浏览器式的入口地位，正是搜索巨头们最在意的东西。
- 冷静补一句：入口生意从来不是技术问题，而是分账问题。开发者愿不愿意搬进来，取决于规则是否长期稳定。

## 对开发者和普通用户，分别意味着什么

开发者视角：

- 好处：不用自己烧钱获客，直接触达 8 亿周活的流量池；迁移成本低，很多团队已有工具化接口，补一个 MCP server 加前端组件就能跑起来。
- 代价：交互入口交给了宿主。数据归属、审核规则、体验规范都握在平台手里——参考小程序生态的演进路径，先来的吃流量红利，后到的卷规则细节。

用户视角：

- 好处：任务在对话内闭环，少开几个 app，上下文不用在多个窗口间反复搬运。
- 要留意的：授权一个应用，等于让它进入你的对话上下文。它的权限范围、数据用途，接入前值得看一眼。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-09/d0b51c3822d51653.png)

1. 判断"可交互"是真需求还是 demo 效果：看它有没有减少你的输入次数。真正有价值的界面，是把"用嘴描述参数"变成"动手直接操作"；如果只是加了动效，那叫演示视频，不叫产品。
2. 开发者接入前先算三笔账：平台分成比例、数据归属与迁移成本、体验规则的长期稳定性。工程上的建议顺序是先做 MCP 工具化、后做 UI——工具是自己的资产，界面是租来的摊位。
3. 普通用户把它当快捷方式，别当万能入口。涉及支付、隐私、账户的操作，回到官方渠道二次确认；权限按最小够用原则给，方便和边界要分开管。

聊天框从"显示屏"进化成"操作台"，这一步的真实分量要到一两年后才看得清。但可以确定的是：在模型能力的竞赛之外，"谁来定义人与模型的交互界面"，会是下一个主战场。
