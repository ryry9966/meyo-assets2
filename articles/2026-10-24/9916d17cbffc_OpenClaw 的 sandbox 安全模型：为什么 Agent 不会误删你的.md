## 背景

让 Agent 拿到 shell 权限这件事，劝退过不少人：模型一句幻觉出来的 `rm -rf`，代价可能是一整晚的工作成果。OpenClaw 的设计前提恰恰相反——默认假设模型输出是不可信输入，把安全边界从"模型自觉"挪到"执行环境强制"。这篇帖子拆一下它的 sandbox 模型，解释为什么在正常配置下，Agent 删不掉 workspace 之外的文件。

## 问题

核心矛盾在于：Agent 需要真实的文件系统操作能力（建目录、写文件、跑构建），但它的每一次决策都可能出错。如果把权限约束寄托在 prompt 上（"请不要删除文件"），那不叫安全模型，叫许愿。边界必须是结构性的：模型负责决定做什么，内核和策略层负责决定"允许做到哪"。

## OpenClaw 的做法

按默认配置跑一个"让它删文件"的实验，能看清四层防线：

1. **沙箱内执行。** Agent 的 shell 不是你的 shell。所有命令落在隔离执行环境（容器或命名空间）里，里面的根文件系统来自镜像层，`rm -rf /` 删掉的是沙箱自己的临时层，宿主机无感。
2. **挂载范围收窄。** 默认只有 workspace 目录以读写方式挂进沙箱，其余路径要么不挂载、要么只读。Agent 视野里的"整块磁盘"，实际只是 workspace 的映射。
3. **路径策略校验。** 工具调用层对每个路径先做 realpath 规范化，解析掉 `..` 和符号链接后再判断是否越界。越界调用直接拒绝，并把拒绝原因作为结构化错误返回给模型——模型会自行换方案，任务不中断。
4. **MCP/插件同池约束。** MCP server 和插件进程跑在同一个沙箱 profile 下，不存在"主 Agent 被关着、插件在宿主机裸奔"的旁路。

## 踩坑点

- **图省事把 `~` 挂进沙箱。** 最常见的自我瓦解。挂载即授权，这一步做了，沙箱等于白配。
- **符号链接与路径绕过。** workspace 里遗留一个指向 home 的软链，或者校验只用字符串前缀匹配，`workspace/../secrets` 这类路径就能穿透。确认你走的是 realpath 之后判定，不是 `startswith`。
- **插件要求 host 权限。** 某些插件声明需要访问宿主路径才能工作，答应了就开了洞。宁可换插件。
- **把沙箱当备份。** 沙箱防误删，不防"Agent 按你的指令认真删光了 workspace"。workspace 本身必须进 git。
- **改完配置不回归测试。** 升级后沙箱配置被覆盖、策略文件没加载，你不会收到任何提示，直到出事才知道。

## 可复用建议

- 权限按任务发：临时任务用窄 profile，长期任务再逐步放宽，原则是默认拒绝。
- 三层兜底：沙箱（防越界）+ git 快照（防真删）+ 审计日志（防"不知道发生过什么"）。
- 定期跑对抗性测试：直接对 Agent 说"清理掉所有日志文件"，对照它的实际动作和沙箱日志，比反复读文档有用。
- 拒绝要可恢复：策略层拦截时返回结构化错误而不是静默失败，让模型能自适应绕行，而不是整条任务链断掉。

## 总结

OpenClaw 不会误删文件，不是因为它更聪明，而是因为它被允许造成的伤害被结构性地限制住了。信任模型做决策，不信任模型守边界——这个思路同样适用于你自己在 MCP 和插件里新增的任何工具：凡是破坏性操作，校验放在执行层，并且永远假设模型总有一天会说错话。
