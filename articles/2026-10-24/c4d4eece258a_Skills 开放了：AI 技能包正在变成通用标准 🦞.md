这两天，一条热搜在 AI 圈刷了屏：你每天在用的 Skills，发生了一件大事。没关注过这个名词的人可能觉得这话有点玄，但如果你最近在用 Claude、Cursor 或者各类 Coding Agent，Skills 其实早已悄悄嵌进你的工作流——处理 PDF、生成 Excel、跑代码评审，背后很可能就是一个个“技能包”在工作。这次的大事，指的是 Skills 正在从单一产品的私有功能走向开放格式：官方把技能仓库和格式规范开源，任何 Agent 都可以按同一套标准来加载技能。这件事的量级，不妨参考 2024 年 MCP 开源后掀起的工具互联浪潮。下面把来龙去脉讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-24/ffeeb9e65b768150.png)

## Skills 是什么：一个文件夹，装着“操作手册”

Skills 是 Anthropic 在 2025 年 10 月随 Claude 推出的能力扩展机制，形态朴素得令人意外——毕竟在这个行业，一个能上热搜的东西居然是个文件夹。它的结构是：

- 一个 SKILL.md 文件：开头是 YAML 元数据（名称、描述），正文是写给模型看的操作指引；
- 若干可选资源：Python 脚本、模板、参考文档，按需被调用。

它和普通提示词的区别主要在三点：

1. **可复用**：提示词跟着对话走，Skill 跟着项目或账号走，写一次到处加载；
2. **可执行**：不只是给模型“读”，还能让模型“跑”——处理 PDF 表单时直接调用文件夹里的填充脚本，而不是让模型逐字誊抄；
3. **可管理**：放进 Git 就能做版本控制、评审和分享，工程属性直接拉满。

一句话总结：Skill 是把“某类任务该怎么做”从聊天记录里抽出来，固化成一份可分发的操作手册。

## 核心机制：渐进式披露，一门上下文的经济学

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-24/0d5ed91abf54763d.png)

Skills 真正巧妙的地方在加载机制，官方术语叫 progressive disclosure（渐进式披露），分三层：

1. **常驻层**：每个技能只有 name 和 description 进入上下文，通常几十到一百多 token，相当于图书馆的索引条；
2. **按需层**：模型判断当前任务命中某个技能，才把 SKILL.md 正文读进来；
3. **深度按需层**：正文里链接到的脚本和文档，只在执行时加载或运行。

为什么这么抠？因为上下文就是预算。以 200k token 的窗口为例，如果装 20 个技能、每个全文 3000 token，光技能说明就吃掉 6 万 token，工作记忆直接腰斩。渐进式披露把常驻成本压到几百 token，把重内容挪到要用的时候才付钱。

脚本还有一层容易被忽略的价值：**确定性操作交给代码，模型只做判断和调度**。排序、格式转换、正则替换这类活儿，让模型“手写”又贵又容易出错，让脚本跑一次就完事——更省 token，结果也更可靠。

## 这次的“大事”：从私有功能到开放格式

新闻的核心动作是开放：官方将技能仓库以宽松许可（MIT）开源，格式规范公开，任何 Agent 框架都可以实现同一套加载逻辑。翻译一下：Skill 从“某家产品的功能”变成了“一个谁都能实现的标准”。

这条路径似曾相识：

- 2023 年前后，Function Calling 让模型学会调工具；
- 2024 年 11 月，MCP 开源，一年内几乎成了 Agent 连接外部工具的事实标准；
- 2025 年 10 月，Skills 发布，随后走向开放——依然是“先做深产品、再开放生态”的路数。

开放带来三个直接后果：

1. **可迁移**：今天给 Claude 写的技能，明天别的 Agent 框架按同样格式就能加载，技能资产不再被单一平台锁死；
2. **可交易**：技能本质是文本加脚本，天然适合在社区里分享、分发，技能市场的想象空间被打开；
3. **竞争重心转移**：平台比拼的不再是“内置功能多不多”，而是“生态里沉淀了多少高质量技能”。

## Skills、MCP、RAG：三个词到底怎么分工

这三个概念经常被混着说，其实各管一段：

- **MCP 管“连接”**：标准化 Agent 与外部工具、数据源的接口，相当于给模型装“手”，让它够得到浏览器、数据库、各类 SaaS；
- **RAG 管“知识”**：把外部文档检索后注入上下文，解决知识过期和私有知识缺失，相当于随身“资料库”；
- **Skills 管“流程”**：注入的是程序性知识——做某类事情的步骤、规范、注意事项和现成脚本，相当于一本 SOP 手册。

三者是叠加而非替代。举一个数据分析 Agent 的例子：用 MCP 连数据仓库取数，用 RAG 注入公司内部的指标口径表，再用 Skill 固化“先查数据质量、再做清洗、输出前跑一遍校验脚本”的流程。

一个常见的踩坑点：很多需求其实一段 SKILL.md 就能解决，不必一上来就搭 MCP 服务。判断标准很简单——只是“教模型怎么做事”，写 Skill；需要“让模型够到新的系统和数据”，才上 MCP。

## 三条实用建议与一点冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-24/5d3f65ca6181fa90.png)

标准开放意味着门槛进一步降低，也意味着噪音会变多。三条建议：

1. **把重复劳动沉淀成技能**。周报怎么写、代码评审看哪些点、报表口径是什么——一件事每周重复两次以上，就值得写成 SKILL.md。它比你的私人笔记强的地方在于：模型会主动想起来用它。
2. **把 description 当广告位来写**。模型是否加载你的技能，几乎完全取决于那一句描述。写清触发场景（“当用户要处理 PDF 表单时”）、核心产出、适用边界，比正文写得漂亮更重要。
3. **安全红线：第三方技能等于供应链依赖**。开放生态必然鱼龙混杂，技能里的脚本是会真实执行的代码。安装前至少通读一遍，警惕要求联网上传数据或明显混淆过的脚本；来源不明的技能，宁可不用。

最后一点冷思考：格式开放之后，护城河不再属于“定义格式的人”，而属于“写出高质量技能内容的人”。就像 npm 之于 JavaScript，协议是公共的，最优秀的那几千个包才是稀缺品。对个体来说，这可能是 2026 年性价比最高的杠杆之一——你积累的不再是一段段聊天记录，而是一套可迁移、可复利的工作流资产。
