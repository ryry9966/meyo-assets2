过去两年，大模型的报价单越来越像水电煤账单：主流旗舰模型输入大约 2~3 美元/百万 token，输出单价还要再翻三四倍。Token 这个原本只属于 NLP 工程师的术语，如今成了财务报表上的一行成本。当“调用大模型”从技术选型变成采购决策，企业要做的第一件事不是追新模型，而是把 Token 这笔账算清楚——它怎么计价、为什么越用越贵、以及怎么把它花在刀刃上。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-24/bcaa811f72d6810b.png)

## 一、Token 是什么：从分词器到计价器

很多老板以为 token 就是“字”，其实差得远。

- **技术定义**：token 是分词器（tokenizer，主流基于 BPE 算法）把文本切出来的最小单位。英文大约 1 token ≈ 0.75 个单词；中文一个汉字通常对应 0.6~1.5 个 token，取决于各家模型的词表。
- **计价规则**：输入和输出分开计费，输出单价普遍是输入的 3~5 倍。原因是推理时每生成一个 token 都要完整跑一遍前向计算，而输入可以批量并行处理。
- **算一笔小账**：一次客服对话，系统提示词加历史消息约 3000 token 输入、回复 500 token 输出，按输入 $3/百万、输出 $15/百万计，单次成本约 1.6 美分。看着不多？乘以日均十万次调用，一个月就是近 5 万美元。

Token 本质上把 AI 从“卖软件”变成了“卖水电”——按用量计费，用多少付多少。

## 二、账单越拉越长的技术根源：注意力是平方级税

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-24/522bef9b39f1ef79.png)

为什么多轮对话越聊越贵？根源在 Transformer 的注意力机制。

1. **O(n²) 复杂度**：注意力计算量与上下文长度的平方成正比。上下文翻倍，计算开销不止翻倍，显存占用也同步上涨。
2. **历史消息的滚雪球**：多轮对话中，每一轮都要把之前的全部历史重新喂给模型。到第 10 轮时，输入长度可能是第 1 轮的 5 倍以上——你在为“重复阅读”反复付费。
3. **缓存折扣**：业界的应对是 KV Cache / Prompt Caching，命中缓存的输入部分无需重算，各大厂商给出 50%~90% 的缓存价折扣。这是长上下文场景必须盯住的报价栏。

一句话总结：**上下文是 AI 时代的“内存租金”，越长越贵，且按轮复利。**

## 三、Agent：把 Token 消耗放大一个数量级

单轮问答是 1 次输入加 1 次输出；Agent 工作流完全是另一回事。

- 一次典型 Agent 任务要经历：任务规划 → 调用工具 → 阅读返回结果 → 反思修正 → 再次调用，模型可能被唤起几十次。
- 业界普遍观察到，Agent 任务的 token 消耗可达单轮对话的 10~100 倍，其中大量花在“中间思考”和反复携带的上下文上。
- 这解释了为什么 Agent 产品普遍按“任务数”或“积分”计费而非按 token——本质是把波动的用量成本打包成确定价格，风险从用户侧转移到厂商侧。

企业侧的启示：评估 AI 成本时，别用“一次问答多少钱”做预算，要用“完成一个业务单元需要多少 token”做测算。

## 四、企业怎么算账：一个可落地的四步框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-24/9dee4530ec9f16ad.png)

1. **盘点场景**：列出所有调用点，记录 QPS、平均输入/输出 token 数、对话轮次、失败重试率。
2. **套公式**：单次成本 = 输入 token × 输入单价 + 输出 token × 输出单价，再乘 1.1~1.3 的重试系数。
3. **对照人工基准**：如果 AI 替代的是人工坐席或文档处理，按人时成本折算 ROI。行业里常见的参考结论是：推理费用通常只占 AI 项目总 TCO 的 30%~50%，剩下的花在评测、微调、数据治理、安全防护和人工复核上。
4. **动态修正**：模型降价极快——过去两年同等能力模型的单价下降了约一个数量级。预算要做成可随报价更新的活文档，而不是年初拍死的数字。

## 五、省钱不省能力的四个工程抓手

1. **模型分级路由**：简单任务（分类、格式转换、意图识别）走小模型，成本可低 10~50 倍；只有复杂推理才路由到旗舰模型。
2. **Prompt 瘦身 + 缓存**：砍掉冗余系统提示词，把稳定不变的部分放进缓存命中区，长上下文场景能省一半以上。
3. **约束输出**：输出 token 是成本大头，让模型输出结构化 JSON、限制最大生成长度，往往能砍掉 30% 以上的账单。
4. **蒸馏与自建的临界点**：当月账单到了百万美元级，把旗舰模型蒸馏成专用小模型、或用开源模型自建推理，开始比直接调 API 更划算——这是“Token 生意”里规模效应的拐点。

## 写在最后：三条冷思考

1. **Token 是变动成本，不是固定成本**。预算模型要绑定业务量（每千次会话、每份文档），而不是按月拍一个总额。
2. **最贵的 token 是无效 token**。幻觉导致的返工、超长 prompt 里的废话、没有裁剪的历史消息，才是账单黑洞——先做治理，再谈降价。
3. **算账的目的不是少用 AI，而是把钱挪到单位 token 产出价值最高的场景**。谁能把“每百万 token 创造的业务价值”算清楚，谁就在 AI 时代拥有了财务上的护城河。
