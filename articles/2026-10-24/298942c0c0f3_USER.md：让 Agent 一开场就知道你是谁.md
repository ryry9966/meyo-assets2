## 背景

OpenClaw 这类常驻 Agent 的工作流里，会话本质上是冷启动的。MEMORY.md 记录"发生过什么"——决定、事件、待办；SOUL.md 定义 Agent 的人设。但中间始终缺一层：**你是谁**。每次新会话，Agent 都要重新试探你的语言、时区、技术栈和沟通偏好。

USER.md 就是补这一层的：workspace 里的一个纯 Markdown 文件，随会话注入上下文，充当对用户的长期画像。成本几乎为零，效果却很稳定。

## 问题

没有 USER.md 时的典型症状：

- 每天开场先自我介绍一遍："我环境是 Mac，用 pnpm"
- 回复风格漂移：有时要求直接给 diff，有时又被塞长篇解释
- Agent 混用 npm/yarn 命令，或默认你在 Windows 上
- 定时任务按错误时区执行
- 反复追问已经回答过的问题

本质原因是把"用户状态"存放在了对话流里，而对话流是最易失真的存储介质。

## 做法

在 workspace 根目录建 USER.md，建议分五个分区：

```markdown
# User
## Identity
- 称呼、语言偏好：中文优先
- 时区：Asia/Shanghai，工作时段 09:00–19:00

## Environment
- macOS + zsh，包管理 pnpm，编辑器 VS Code
- 主力语言：TypeScript / Python

## Preferences
- 回复默认简短，代码优先于解释
- 改动直接给 diff，不要重复贴整文件

## Boundaries
- 不主动执行 rm、git push --force
- 内部项目名不拼进外部搜索

## Current Focus
- 见 PROJECT.md（易变事实不写在这里）
```

关键原则：篇幅控制在 80 行以内，它是每次会话的固定开销；只写稳定属性，易变内容交给 MEMORY.md 或独立项目文件；放进 git 私仓，改动可审计。也可以授权 Agent 协助维护——约定"从对话中确认到新偏好时，先给出 diff 提案，确认后写入"，避免它自作主张。

## 踩坑

- **写太长**。300 行的 USER.md 每次会话都烧 token，还会稀释关键信息。见过把 API 文档摘抄塞进去的案例，删掉后 Agent 反而更听话。
- **写成流水账**。"周二我修了登录 bug"这种事件该进 MEMORY.md，USER.md 是画像不是日志。
- **放敏感信息**。这个文件会进模型上下文，密钥、密码、真实手机号一律不写，需要引用就用占位符指向独立的加密文件。
- **与 SOUL.md 职责混淆**。"回复要简洁"放两边似乎都成立。建议约定：SOUL 管 Agent 性格，USER 管用户事实与偏好，冲突时以 USER 为准。
- **放错路径**。确认你的版本是从 workspace 根读取（注意文件名大小写），改完重开会话验证是否真正注入。

## 可复用建议

- 五分区骨架可直接抄，先只填 Identity 和 Environment，跑一周再补偏好
- 每月 review 一次，删掉过期的"当前在做"
- 团队场景每人一份，公共约定拆到独立的 TEAM.md
- 排查"Agent 不听话"时，先 diff 一下 USER.md 是否被污染——这往往比改 prompt 快得多

## 总结

USER.md 的价值不在花哨，而在把用户侧的稳定状态从对话流搬进结构化文件。这是上下文工程里性价比最高的一类收益：不写一行代码，只花半小时编辑文件，就能消掉大部分重复试探和风格漂移。写完第一次，你会开始分辨 Agent 的哪些行为其实是"它不了解你"——那就继续往里补。
