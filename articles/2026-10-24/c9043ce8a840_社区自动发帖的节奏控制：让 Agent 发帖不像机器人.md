## 背景

我们在社区频道用 OpenClaw Agent + MCP 定时工具做自动化发帖：每日摘要、版本公告、issue 周报。跑通很容易，难的是跑得"体面"——第一版上线一周就被群友吐槽"这 bot 比闹钟还准"，另一次因为重试风暴连发了五条重复消息。后来专门把节奏控制抽出来重做，记录一下。

## 问题：机械感从哪来

"像机器人"不是玄学，是几个可观测的统计特征：

- **固定间隔**：cron 每 60 分钟整点触发，发送时间戳方差为零
- **全天候在线**：凌晨三点照发不误
- **内容同构**：每条都是同一模板，开头结尾一字不差
- **秒回**：被 @ 后 0.8 秒响应，比谁都快
- **突发连发**：一个事件触发 N 条，或失败重试没有上限

反垃圾系统和真人用户都会注意到这些。

## 做法：把节奏做成独立的调度层

核心思路是**"发什么"和"什么时候发"解耦**，节奏控制不写进业务逻辑，而是独立配置。

**1. 时间层：抖动 + 活跃窗口**
- 间隔按基准值 ±20% 加抖动，且抖动用带偏好的分布（多数靠近基准、偶尔拉长）。不要均匀随机——均匀随机本身也是一种特征。
- 定义活跃窗口（如 9:00–23:00，社区本地时间），窗口外任务只入队不发送。
- 注意时区：调度器通常跑 UTC，窗口判断必须显式换算。

**2. 频率层：配额与合并**
- 每频道每日上限 + token bucket 限速。
- 高频事件做 digest：攒 30–60 分钟合并成一条，而不是一事一贴。
- 幂等键：同一事件重试不产生第二条，从根上杜绝重试风暴。

**3. 内容层：模板池**
- 同类消息准备 3–5 套模板，字段顺序可变，长短交错。
- 避免固定签名、固定 emoji 序列。
- 让 LLM 改写时 temperature 别开太高，否则会产出不合语境的"过度活泼"。

**4. 行为层：拟人延迟**
- 被 @ 后加 30 秒–3 分钟随机延迟再响应。
- 失败退避用指数 + 抖动；连续失败达阈值就降级为"仅记录、不发送"，等人工介入。

配置示意：

```yaml
pacing:
  active_hours: "09:00-23:00"
  tz: "Asia/Shanghai"
  interval_base: 60m
  jitter: 0.2
  daily_cap_per_channel: 12
  digest_window: 45m
  reply_delay: "30s-3m"
```

## 踩坑点

- **抖动种子写死**：有次复用了固定随机种子，bot 每天的抖动模式一模一样，等于没抖。
- **digest 攒太久**：合并窗口开到 90 分钟，热点讨论已经翻篇，摘要发出来没人看；实测 45 分钟左右比较稳。
- **时区事故**：窗口写成本地时间但服务器在 UTC，导致 bot 凌晨活跃、白天沉默，完全反着来。
- **重试缺幂等键**：MCP 工具超时后重试，同一内容连发五条，比不抖动更伤信任。
- **过度随机**：把措辞也完全随机化，语气忽冷忽热，比模板更像假的。

## 可复用建议

- 新自动化先跑 **draft 模式两周**：所有消息只落日志不发送，人工抽查节奏曲线（每小时条数、间隔方差）再放开。
- 保留**发送台账**：时间戳 + 内容 hash + 触发源，出问题能完整回放。
- 频道分级：公告频道节奏收紧，闲聊区放宽。
- 在合规前提下保持透明：频道规则若要求标明 bot 身份就标。节奏控制的目标是"像个有礼貌的成员"，不是伪装成人类。

## 总结

自动发帖"不像机器人"，本质是让对方感受到的节奏接近一个克制的人类运营：有活跃时间、有波动、会合并、不抢话。实现上没有黑科技，就是抖动、窗口、配额、幂等、延迟这五件事，外加一份可回放的台账。把节奏做成独立配置层之后，接任何新频道都只是换一组参数的事。
