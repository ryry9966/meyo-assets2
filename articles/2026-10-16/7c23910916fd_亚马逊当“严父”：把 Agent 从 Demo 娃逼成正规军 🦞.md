最近 36氪一篇《亚马逊，Agent最严厉的父亲》在从业者朋友圈刷了屏。这个比喻说的不是谁家的育儿观，而是这家公司对待 AI Agent 的态度：别人在发布会上炫 Demo，亚马逊在给 Agent 立规矩——先写 spec、再配身份、装好监控、算清成本，过不了“生产级”这道门，就不许出门上班。当"Agent"这个词被用滥的时候，这家最懂大规模软件运维的公司，给出了一套值得拆解的工程方法论。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-16/4596c092bf6c67d1.png)

## “严父”人设从哪来：一家对 Demo 过敏的公司

亚马逊的“严”不是性格，是文化惯性：

- **Working Backwards**：立项前先写新闻稿和 FAQ（PR/FAQ），把“上线后用户得到什么”写清楚，评审通过才动工。这套流程天然对“看起来很酷但说不清价值”的东西过敏。
- **运维卓越（Operational Excellence）**：AWS Well-Architected 五大支柱之一。支撑 Lambda 和 Fargate 的 Firecracker microVM，本质就是为“跑在别人生产环境里的代码”设计的隔离方案。
- **高层的定调**：贾西在 2025 年 6 月的内部信里判断，Agent 将改变每个团队的工作方式，未来几年企业职能员工数量会因 AI 提效而调整。一边全速推进，一边抬高准入门槛——严不是保守，而是“放行前检查”。

一句话：这家公司见过的线上事故太多，天然知道“演示成功”和“生产可用”之间隔着一条马里亚纳海沟。

## 机制一：Kiro——先把“感觉对”写成“写得清”

Kiro（AWS 2025 年推出的 agentic IDE）最有辨识度的不是自动补全，而是 **spec-driven development（规格驱动开发）**：

1. **requirements.md**：用 EARS 句式把需求写成可验收条款。比如“订单超时”功能要写成：When 订单超时 30 分钟，the system shall 向值班群发送提醒——这句话既是需求，也是测试用例；
2. **design.md**：数据模型、接口、时序图先落文档，再动手；
3. **tasks.md**：拆成带依赖关系的任务清单，Agent 逐项认领、逐项打勾。

再配 **hooks**：保存代码自动跑测试、同步文档，形成强制闭环。

为什么有效？LLM 编码 Agent 最大的毛病是“漂移”——聊着聊着就忘了约束。Spec 把约束外置成契约：Agent 对着契约干活，人类对着契约验收，扯皮空间大幅缩小。这几乎是 Working Backwards 文化在 AI 时代的复刻。

## 机制二：AgentCore——上户口、发工牌、装行车记录仪

2025 年 7 月 AWS 发布 Bedrock AgentCore，把“企业敢不敢把 Agent 放进生产环境”拆成了一件件基础设施：

- **Runtime**：每个会话跑在独立 Firecracker microVM 里，会话级隔离，支持最长 8 小时长任务，按需伸缩、闲时不计费；
- **Identity**：Agent 有自己的身份，按最小权限访问内部系统，而不是共享一把万能 key；
- **Gateway**：工具调用走统一网关，兼容 MCP 协议，鉴权、限流、审计集中管理；
- **Observability**：每次会话全程可追踪，一步一看，出事能回放；
- **Memory、Code Interpreter、Browser** 等模块化能力，且不限模型、不限框架（Strands、LangGraph 都能接）。

翻译成人话：给 Agent **上户口**（身份）、**发工牌**（权限）、**装行车记录仪**（可观测）、**算油费**（成本归因）。企业落地 Agent 的四大拦路虎——安全、合规、审计、成本——严父逐个发了工具。

## 为什么必须严：Agent 的错误是复利的

- **一道算术题**：单步成功率 95% 的任务，串行 20 步，整体成功率只剩 0.95²⁰ ≈ 36%。Demo 里走得通，生产里跑十次可能挂六次。
- **失败模式不同**：传统软件错了是“答错”，多步 Agent 错了往往是“做错”——调错 API、删错表、发错邮件，动作经常不可逆。
- **Werner Vogels 的名言**反过来说也成立：经验没有压缩算法，可靠性同样没有——只能靠流程、隔离、评测这些“笨办法”一层层堆出来，就像龙虾换壳，一层都不能省。
- **自家数据佐证**：Amazon Q Developer 已把 3 万多个 Java 应用升级到新版本，官方口径省下约 4500 个开发者年、年化约 2.6 亿美元。大规模、低容错、真金白银的场景，正是“严父式方法论”的主场。

## 严父 ≠ 慢：门内跑得快，门口把得严

- **对内激进**：贾西要求各团队把 Agent 真用起来，编码助手已大规模铺开，是全公司级别的推进事项；
- **对外开放**：Strands Agents SDK 开源、拥抱 MCP 标准、AgentCore 支持第三方模型——严的是工程标准，不是技术路线封锁；
- **组合拳的含义**：创新在沙箱里放开跑，放行到生产时一道门一道门过。速度与可靠从来不是二选一，而是分阶段的问题。

## 给开发者的三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-16/267378013f061c35.png)

1. **先建评测集，再谈上线**：把 Agent 要完成的任务做成可重复的测试用例（输入、预期动作、验收标准），每次改 prompt、换模型、动工具都跑回归。没有 eval 的 Agent，等于没有测试就上线的生产代码。
2. **Spec 先行，Prompt 其次**：需求用 EARS 写成可验收条款，先画接口和数据流，再让 Agent 拆任务执行。人和 Agent 对着同一份契约干活，而不是对着一段感觉。
3. **把 Agent 当新员工管**：只给最小权限、放进沙箱、留全量审计日志、按会话核算成本；凡是不可逆动作（写库、发消息、扣款）一律设人工确认点。

最后一条冷思考：严父的悖论在于，规矩太密会把 Agent 养得不敢动，规矩太松会养出不可控的“熊孩子”。门内自由、门口严格，两边都得有真功夫——这大概就是“最严厉的父亲”这个比喻的真意：养 Agent 如养儿，严不严不看嗓门，看门禁。
