## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，你会发现一个反复出现的摩擦：每次新会话，Agent 对你的了解几乎归零。它不知道你的时区、主力语言、想要长回复还是短回复，于是要么每次自我介绍一遍，要么忍受它基于通用假设给出的"标准答案"。

OpenClaw 的工作区里其实预留了这个位置：`USER.md`。和记录 Agent 人格的 SOUL.md、记录操作规则的 AGENTS.md 不同，USER.md 的职责只有一个——存放关于"你是谁"的事实，并在每次会话启动时被读入上下文。

## 问题

没有这份文件时，典型症状有三类：

1. **重复解释成本高**：项目背景、部署环境、命名习惯，每周都要重讲一次；
2. **错误假设**：Agent 默认给你冗长解释、推荐你根本不用的工具、在错误的语境下自作主张；
3. **记忆碎片化**：这些信息散落在 MEMORY.md 的历次会话记录里，互相冲突，没人负责整理。

## 做法

**第一步**，确认工作区路径（默认 `~/.openclaw/workspace/`，以你的配置为准），没有 USER.md 就新建。

**第二步**，用"一行一条事实"的格式写，控制在 50 行以内。分享一个我目前在用的骨架：

```markdown
# USER.md

## 环境
- 时区：Asia/Shanghai
- 主力语言：Python 3.12 / TypeScript
- 机器：macOS + Ubuntu 服务器（deploy 走 SSH）

## 偏好
- 回复先给结论，解释放后面
- 代码改动直接给 diff，不要整文件贴回
- 中文交流，技术名词保留英文

## 当前
- 正在做：xxx 项目的 MCP 接入
- 暂停：yyy（2025-11 起）

## 禁止
- 不要自动 push 到 main
- 未确认前不要删除分支
```

**第三步**，把整个工作区放进 git。之后你可以直接对 Agent 说"把这条写进 USER.md"，它改完你 `git diff` 审一眼再合入。

## 踩坑点

- **写成小作文。** USER.md 每次会话都进上下文，500 行的长文既烧 token 又稀释注意力，50 行以内、事实密度优先。
- **指令混进事实。** "你应该先给结论"是指令，该去 AGENTS.md；USER.md 只放"回复偏好：先给结论"这类事实。两者混放会导致优先级不可预期。
- **信息过期。** 过期信息比没有更糟——Agent 会持续引用一个你早已弃用的仓库。易变条目标注日期，定期清理。
- **敏感信息入库。** 这份文件会作为上下文被发送，不要写 token、密码、真实住址，只写变量名或引用方式。
- **放任 Agent 自动改写。** 让它提议、你来合入，否则几周后这份文件会漂移得面目全非。

## 可复用建议

- **四段式骨架可迁移**：环境 / 偏好 / 当前 / 禁止，这套结构可以搬到任何支持 profile 文件的 Agent 上，模式是通用的。
- **每月做一次"上下文对账"**：让 Agent 对比 USER.md 与近期会话记录，主动提出该删、该改的条目，你负责拍板。
- **四个文件各司其职**：SOUL.md 管人格，AGENTS.md 管规则，USER.md 管用户事实，MEMORY.md 管会话沉淀。交叉写入是混乱的开始。

## 总结

USER.md 不是什么高级特性，就是一份几十行的配置文件。但它解决的问题非常具体：消除重复解释，压掉错误假设。Agent 不会真的"认识"你，一份持续维护、小而准的事实清单，能覆盖八成的日常场景。把它当配置对待——写短、进版本控制、定期审查，就够了。
