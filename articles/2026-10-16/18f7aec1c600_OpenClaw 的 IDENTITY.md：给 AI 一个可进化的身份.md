## 背景

OpenClaw 的 Agent 不是一次性的：它跨会话、跨设备运行，接 MCP 工具、定时任务，还可能被团队多人触发。系统提示词解决的是"能做什么"，但长期运行还会暴露另一个问题——**它是谁**。语气忽冷忽热、自称不统一、换了台机器就像换了个助理，这些都是身份缺失的症状。OpenClaw 的 workspace 里预留了 `IDENTITY.md`，就是给这个问题一个正式的落点。

## 问题

我自己的配置里，身份信息曾经散在三处：启动器里的 system prompt 片段、每个 skill 的开头说明、以及聊天中临时口头纠正。后果很典型：

- 换模型或换机器后人格漂移，昨天还简洁干脆，今天开始满篇客套；
- 两个人同时改提示词，改动互相覆盖，也没有记录；
- 想让同一个 Agent 在不同项目里有微差（对外正式、对内随意），只能整套复制配置，改一处漏一处。

## 做法

1. **在 workspace 根目录建 `IDENTITY.md`**，最小字段：name（名字）、creature（本体设定，比如"一只驻场工程猫"）、emoji、vibe（两三句性格描述）。
2. **只写可操作的陈述，不写散文**。每行一个事实："默认用中文回复""报告先给结论""不确定时直说"。
3. **划清职责边界**：`SOUL.md` 管价值观和底线，`IDENTITY.md` 管身份事实，`USER.md` 管用户侧信息。三者不要互相覆写，否则排查漂移时无从下手。
4. **纳入 git**。每当觉得"它最近不太对劲"，就 review 一次 diff，改完 commit，身份变化从此有据可查。
5. **多项目复用**：主体身份放共享层，项目差异放在各自 workspace 的局部段落，改差异不影响主干。

## 踩坑点

- **写成小说**。三百字的角色小传，模型抓不住重点，还会稀释任务指令的权重。十行以内效果最好。
- **只写"不要做什么"**。纯负面清单会让模型整体保守化，正面的风格陈述比禁令更有效。
- **当成一次性文案**。真正有价值的是"进化"：把聊天里反复出现的纠正，定期固化进文件，而不是每次手动重说。
- **期望过载**。`IDENTITY.md` 管的是语气与身份一致性，管不住幻觉和工具误用——那是 `AGENTS.md` 和工具配置该干的事。

## 可复用建议

- 把它当**配置文件而非文案**：短、稳定、可 diff、可回滚。
- 建一个进化闭环：日常纠正 → 每周 review → 合并入档 → 观察一个会话周期再定去留。
- 团队协作时，围绕 `IDENTITY.md` 提 PR，是讨论"我们想让 Agent 是什么样"的最低成本方式，比开会拉扯有效得多。
- 多 Agent 场景下，用 emoji + name + vibe 三件套做区分，比改模型参数更直观。

## 总结

`IDENTITY.md` 的成本几乎为零，收益却随运行时间累积。它解决的不是"AI 像不像人"，而是长期运行的 Agent 在**时间、成员、项目**三个维度上的一致性。别追求一步到位：先写十行，跑两周，把真实的别扭之处改成条目，再 commit。身份本来就是长出来的。
