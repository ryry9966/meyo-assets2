## 背景

社区里最常见的求助方式是贴配置、贴日志、贴 agent 对话截图。到了 Agent 时代，这事的危险程度悄悄变了：一段会话上下文里可能同时装着你的系统提示词、skill 编排逻辑、MCP 工具清单、内网端点，甚至还有效 token。我帮人排查问题时见过不止一次，"求助帖"里直接带着完整的 Authorization 头，楼主自己都没意识到。

## 问题出在哪

三类高频泄露源：

1. **上下文即资产**。system prompt、工具编排、MCP 配置本身就是工作成果，整段贴出去等于把没打算开源的东西开源了。
2. **工具副作用残留**。file read、shell 输出留在会话里，导出日志或截图时被一并带走。
3. **自动化出口**。让 agent 自动写 changelog、回帖、总结会话时，它没有"这条能不能公开"的概念。

## 做法：四步落地

**1. 给信息分级。** 把接触 agent 的信息分三层：公开（可进社区）、内部（可进 agent 上下文但不可出）、凭据（不可进上下文）。写进你自己的系统提示：凭据一律环境变量注入，不要出现在任何会被复述的文本里。

**2. 权限按场景切 profile。** 不要一个全权限 MCP 配置走天下。建议三个档位：`public`（只读文档类工具，社区复现用）、`debug`（加日志查看，路径白名单）、`full`（完整工具链，只在本地沙箱）。复现问题时用 public 档起一个一次性会话，用完即弃。

**3. 出口前过一道 redact。** 写个二十行的脚本做机械检查：密钥正则（`sk-`、`ghp_`、Bearer 后随串）、内网域名和 IP 段、个人目录绝对路径。别信肉眼。截图同样要过——低分辨率糊掉的字符串，OCR 照样读得出来。

**4. 自动化出口加闸门。** agent 往公开渠道发内容（commit message、社区回帖、周报）的任务，前面加一步人审：先产出草稿到本地文件，确认后再发。可以在提示里明确禁止输出 env、内部 URL、会话历史三类内容——但要清楚，**提示词不是安全边界，工具权限和出口闸门才是**。

## 踩坑记录

- `.env` 整段贴进对话让 agent"帮我找哪行错了"，之后它复述问题时把 key 带进了所有后续回复。
- Markdown 代码块里的 Authorization header，渲染后不显眼，但全文都在。
- "仅管理员可见"的频道不等于不被索引、不被成员转存。
- 让 agent 自动总结会话生成日志，它把内部端点当"备注"写了进去。
- 以为撤回消息就没事，公开频道的机器人存档不讲情面。

## 可复用建议

- redact 脚本做成 alias 或 pre-commit 钩子，贴任何东西前跑一次。
- 发布 skill / MCP 配置前，用同一个脚本当 lint 跑一遍。
- 三层分级写进团队文档，新人接入 agent 前先读。
- 定期 grep 一遍自己的历史会话导出，检查有没有惯性泄露。

## 总结

Agent 把"贴日志求助"变成了"贴上下文求助"，泄露面从代码扩展到了工作流本身。防线不靠提示词自觉，靠三件实打实的事：**信息分级、权限最小化、出口审查**。每件都是二十分钟能落地的活，建议今天就做。
