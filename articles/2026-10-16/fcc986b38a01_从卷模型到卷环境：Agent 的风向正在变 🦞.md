最近 36kr 有一篇文章挺出圈：作者折腾完一款 AI 游戏后感慨，Agent 的风向变了。这不是一句玄学感叹。过去两年，Agent 从 AutoGPT 式"全自动助理"的狂热，走过"跑不通就怪模型"的幻灭，如今重新升温——但这一轮的底层叙事确实换了一茬。结合我前阵子动手搭小项目的体感，把这场转向拆成三个风向、一组机制，最后给三条建议。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-16/24621b996200a716.png)

## 风向一：从"卷模型"到"卷环境"

先给一个结论式的观察：Agent 领域的竞争力，正在从"谁的模型更强"转移到"谁把环境搭得更好"。

- 2023 年的叙事是：给模型一个目标，让它自己拆解、自己循环执行。AutoGPT 一夜爆红，随后集体哑火——大量项目在死循环里烧光 token，产出约等于零。
- 复盘下来，锅多半不在模型，而在环境：Agent 看不见系统状态、记不住历史交互、工具返回的结果没经过整理。相当于给一个人装上顶级大脑，却把他关进没有窗户、没有笔记本、电话全是杂音的房间。
- 一个朴素公式：**Agent 表现 ≈ 模型能力 × 环境质量**。模型能力这两年在快速商品化，各家旗舰你追我赶，单点智力很难再构成护城河。
- 于是差异化的重心挪到了环境侧：上下文（context）、工具（tools）、记忆（memory）、反馈回路（feedback loop）。业界给这套手艺起了个新名字——context engineering（上下文工程）。
- 游戏是最直观的例子。让 LLM 扮演 NPC，它的"人味"上限不由模型决定，而由游戏引擎决定：它看得见地图吗？记得住上一次对话吗？有没有清晰的日程和目标？斯坦福 2023 年的 Generative Agents 研究（Smallville 小镇，25 个 AI 居民）早就验证过：NPC 之所以"像人"，大头来自 memory stream、reflection、plan 这套环境机制，而不是模型本身有多聪明。

## 机制拆解：为什么"地面摩擦"决定成败

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-16/bd35c251bec75290.png)

环境为什么这么重要？用三个工程视角就能解释清楚。

1. **误差是乘法累积的。** 假设 Agent 单步动作准确率 95%，一条 20 步的任务链，整体成功率大约只剩 0.95²⁰ ≈ 36%。步数越长，越不能指望"模型会想"来兜底，只能靠降低每一步的摩擦：结构化输出、工具入参校验、失败自动重试、关键节点人工确认。
2. **上下文是稀缺资源。** 再长的上下文窗口，也装不下"整个世界"。工程功夫全在取舍：什么信息此刻该进窗口、什么该压缩成摘要、什么该外置成可检索的记忆（RAG、memory system）。塞错信息，比缺信息更致命——这跟做菜乱加料是一个道理，龙虾对此深有体会。
3. **工具即能力边界。** 2024 年底 Anthropic 开源了 MCP（Model Context Protocol），随后被 OpenAI、Google 等主流玩家跟进，工具接口正在标准化。这意味着"接什么工具、怎么把工具描述清楚"成了新的竞争面——模型的手脚越来越多，但"什么时候该用哪只手"，依然取决于环境设计。
4. **反馈信号决定迭代质量。** 游戏之所以是 Agent 的天然试验场，是因为它有清晰的状态、规则和即时反馈。Voyager 在 Minecraft 里让 Agent 自己写代码、沉淀技能库、持续自我升级，靠的正是环境给出的即时奖励。做过 AI 游戏的人几乎都会撞见同一个结论：与其抱怨模型不够聪明，不如把游戏世界的"可观测性"做足。

## 风向二：从"全自动"到"可控的自适应"

- 2023 年的执念是"一次给目标，Agent 自己跑一夜"。今天的共识是：全自动跑不通的地方，恰恰是产品机会所在。
- 主流形态变成了 human-in-the-loop：计划与执行分离（先出 plan 再动手）、风险动作加审批门（approval gates）、敏感操作默认暂停确认。计算机操作类 Agent（各家 computer use、Operator 类产品）落地时走的都是这条路。
- 一句话总结这轮转向：**自主性是个旋钮，不是开关。** 好产品不会问你"要不要全自动"，而是让你逐级放权——从"每步都确认"，到"只确认危险动作"，再到"结果出来抽查"。

## 风向三：从"通用 Copilot"到"垂直 Agent + 工具生态"

- 水平方向的"通用助理"一直很难收费：场景泛、价值模糊、替换成本低。真正跑出商业模型的，是垂直场景里的 Agent——写代码的、处理客服工单的、跑数据分析的，每个都有清晰的 workflow 和可量化的 KPI。
- 游戏本身就是一个被低估的垂直场景：AI NPC、动态剧情、玩家与 Agent 共创内容，是少数用户愿意"为体验本身付费"的 Agent 落地点。
- 工具生态在加速：MCP server 数量爆发，Agent 可调用的"手脚"越来越丰富。但生态越繁荣，"编排与取舍"的价值就越高——这正是环境工程的用武之地。

## 三条实用建议与一点冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-16/e243cd92c64bd553.png)

1. **先做小闭环，别先做通用助理。** 挑一个规则清晰、反馈快的场景（一个游戏、一类表单、一个代码仓库），把最小可用的 Agent 跑通，验证价值之后再扩边界。
2. **把预算从 prompt 技巧挪到环境上。** 一份写清楚"何时调用、输入什么、输出什么"的工具描述，胜过十句 prompt 咒语。同时尽早搭 eval（评测集）：没有评测体系的 Agent 调优，本质是玄学。
3. **把自主性做成旋钮。** 默认保守、逐步放权，高危动作加确认。让用户先感知到"可控"，Agent 才敢被真正用起来。

冷思考两句：demo 和产品之间，隔着的从来不是模型智商，而是可靠性。另外要有心理预期——模型每升级一代，你在环境层做的一部分 hack 会贬值；但"把环境设计对"的方法论不会贬值。风向再怎么变，这条是常量。
