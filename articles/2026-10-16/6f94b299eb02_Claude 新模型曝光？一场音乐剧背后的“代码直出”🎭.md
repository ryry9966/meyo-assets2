2025 年 2 月，海外开发者社区流出一段演示：有人用疑似 Anthropic 尚未发布的 Claude 新模型，只给了一句简短 prompt，拿到一个单文件 HTML 页面——双击打开，浏览器里就“上演”了一出迷你版《汉密尔顿》：有舞台布景、有角色走位、有歌词字幕，还有程序合成的旋律、节拍和“演唱”。国内科技媒体跟进报道后，“代码直出画面音效”冲上热搜。它到底是怎么“演”出来的？为什么工程师圈子的讨论热度比大众舆论还高？这篇拆给你看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-16/5547d9cc648bd63b.png)

## 一、“代码直出”≠ 生成视频：它写的是“施工图”

很多人的第一反应是“AI 会生成视频和音乐了”。方向反了——模型从头到尾只输出了一种东西：文本形态的代码。

- **画面**：HTML/CSS/Canvas/SVG 负责舞台、角色和动画，元素位置和动效全部由代码实时计算；
- **旋律与音效**：Web Audio API 里的振荡器（OscillatorNode）可以直接合成波形，音符按时间轴调度，鼓点、贝斯、和弦都是“算”出来的；
- **“演唱”**：部分借助浏览器自带的语音合成（SpeechSynthesis API），歌词能发出人声；
- **时序对齐**：requestAnimationFrame 把动画帧和音符事件对齐，保证唱到哪、演到哪。

打个比方：它不是拍了一部电影，而是写了一套“剧本 + 舞台调度表 + 自动演奏乐谱”，浏览器则是那个分文不取、24 小时待命的剧组。老程序员看到这里会心一笑：这正是 demoscene 社区玩了三十年的手艺——在几十 KB 的可执行文件里塞进整场视听演出，只不过这次执笔的换成了 AI。

## 二、真正难的在哪：一次跑通，考的是三种底层能力

用现成模型写个“会动的网页”并不新鲜，Claude 早在 2024 年 6 月就上线了 Artifacts 功能，在对话旁实时渲染代码产物。这次演示让人惊讶的不是“能不能”，而是“一次成活”的质量——背后是三种能力的叠加：

1. **一次成活的工程能力**。几千行代码要零语法错误、变量不冲突、时序不打架。LLM 生成长代码的传统翻车点是“看着像对的，一跑就崩”，而这类演示要求首次运行即通过，容错率为零。
2. **长程规划能力**。一出剧要先拆幕、再拆场、再拆曲目，歌词要踩拍，动画要跟节拍走。模型相当于把编剧、作曲、编舞、导演的分工压缩进一次生成，中途不能“忘了第一幕的人设”，这对上下文长度和内部规划都是硬考验。
3. **指令遵从与自我一致性**。在风格、角色、篇幅的多重约束下保持前后统一，这是更长上下文窗口加更强对齐训练的直接体现。

一句话总结：把“想象力”编译成“可执行物”，中间没有人工修 bug 的环节，这才是这次演示真正的含金量。

## 三、两条技术路线的分岔：生成媒体，还是生成“会动的程序”

把事件放进行业坐标系里看会更有意思，目前头部玩家走的是两条不同的路：

- **原生多模态路线**：直接生成图像、视频、音频本体，靠 diffusion 与视频生成模型驱动。表现力强，但推理成本高、输出体积大，结果通常不可交互。
- **代码中介路线**（Anthropic 的选择）：模型只输出代码，渲染交给用户设备。一个 HTML 文件几十 KB，换来的却是可交互、可二次修改、跨平台免安装的成品。

从工程经济学角度看，第二条路有个精妙之处：把渲染算力“外包”给每个用户的浏览器，边际成本趋近于零。代价是表现力上限受浏览器 API 约束，做不出电影级画面，更适合轻量、交互式、可玩的内容。

商业上也符合一贯战略：代码场景一直是 Anthropic 的招牌和营收主力，把 coding 做成护城河，比追着别人卷视频生成更聚焦。

## 四、先别急着上头：三盆冷水

1. **“疑似”两个字还没摘掉**。模型未经官方确认，而社区泄露和匿名跑分历来噪音很大，此前多家实验室的“神秘模型”最后都被证明没那么神。等官方发布说明和 SWE-bench 这类权威评测再下结论，不迟。
2. **demo ≠ 产品**。《汉密尔顿》原版是数百人团队打磨多年的舞台作品，演示里的“迷你版”在叙事、唱腔、编排上都被大幅简化。而且能被广泛转发的 demo，永远是挑过的那条 take——别用最好的演示外推平均水平。
3. **版权是悬着的另一只靴子**。《汉密尔顿》的词曲与剧本均受版权保护，生成“迷你致敬版”处于风格模仿与衍生作品的灰色地带。技术上有能力做，和商业上有权利卖，是两个问题。

## 五、给开发者的三条实用建议

1. **把“一次成活率”纳入自己的模型评测**。固定一批 prompt（比如“单文件实现带音效的贪吃蛇”“写一个九宫格交互动画”），统计零报错率和可用率。自己攒的小评测集，比排行榜更贴近你的真实工作。
2. **在 prompt 里点名浏览器原生 API**。明确要求用 Web Audio API、Canvas、requestAnimationFrame，产出质量通常显著好于笼统一句“加个音效”。记住一个原则：让模型写程序，往往比让模型直接生成媒体更便宜、更可控。
3. **修炼验证能力，而不只是生成能力**。当生成越来越便宜，稀缺的是判断力：快速 review 长代码、写自动化验收测试、把“什么叫好”定义清楚——这些才是最不容易被折旧的部分。

“代码直出”的本质，是 AI 找到了一种把想象力编译成可执行物的通用语法。至于演员表里还有没有人类——至少目前，观众席上鼓掌的人和验收单上签字的人，还是我们自己。
