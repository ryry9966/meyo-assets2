## 背景：大多数 Agent 是“叫醒式”的

我们平时用 Agent 的模式基本是被动的：你提问，它回答；你不发消息，它就静静躺着。问答类任务这样没问题，但一旦想让它承担“值班”角色——盯日志、查日历、巡检仓库、定时提醒——被动模式就露馅了：它不知道时间在流逝。

OpenClaw 的心跳机制就是为此设计的。网关按固定间隔（默认约 30 分钟，可在配置中调整）唤醒一次 Agent，并把 workspace 里的 `HEARTBEAT.md` 注入上下文。Agent 醒来后照着这份文件逐条评估：有事就做，没事就沉默。

## 问题：想让它主动，又怕它话痨

直接让 Agent“主动点”是行不通的——它会隔一阵子就发一句“一切正常”，比不发还烦。我们需要一个声明式的中间层：把“什么情况下说话、什么情况下闭嘴”写进文件，而不是靠每次对话临时调教。`HEARTBEAT.md` 扮演的就是这个角色，本质上是一份自然语言版的 crontab。

## 做法：五步跑起来

1. **定位文件**。在 workspace 根目录（和 `AGENTS.md` 同级）建一个 `HEARTBEAT.md`。没有它心跳照样跑，只是无事可做。
2. **每行一条检查项**。格式建议：条件 + 动作 + 阈值。例如：
   - 检查 `~/repos/api` 是否有未推送的提交，超过 3 个就提醒我；
   - 每天 9:00（UTC+8）汇总今日日历发给我；
   - 若 `error.log` 自上次心跳以来新增 ERROR，摘要前三条发我。
3. **静默规则写在最上面**。第一行就声明：“默认保持安静，仅在满足条件时发言，否则不做任何汇报。”这句的优先级要高于所有任务。
4. **控制体量**。全文 10 行以内。心跳上下文每次唤醒都会注入，文件越长，token 开销越大，注意力也越散。
5. **结合工具用**。检查项里可以直接引用 skills 或 MCP 工具，比如“通过日历 MCP 查今日事件”。心跳只做轻量检查，重的活留给你显式发起。

改完保存即可，下一次心跳自动生效，不用重启网关。

## 踩坑点

- **没有阈值导致话痨或失联**。“帮我看看日志”这种写法，Agent 要么每次都报，要么永远不报。必须写清触发条件：“新增 ERROR 且超过 5 条”。
- **忘了心跳本身有成本**。即使静默，每次唤醒也是一次真实的模型调用。任务密度低就把间隔调大。
- **时区问题**。涉及时间的任务务必显式写时区，否则“早上 9 点”可能按 UTC 执行。
- **把重任务塞进心跳**。如果巡检触发全量测试，一次心跳可能跑十几分钟，还会打乱后续节奏。心跳只负责“发现并通知”。
- **输出脱敏**。心跳消息走你配置的通知通道，别让它原样转发含敏感内容的文件。

## 可复用建议

把它当 crontab 维护，放进 git 做版本管理：每周回顾一次，删掉从没触发过的项，把你最近手动问过 Agent 两次以上的事提升为心跳项。文件结构固定为三段：静默规则、定时任务、条件告警。这套结构可以直接复制给多个 Agent 实例复用。

## 总结

`HEARTBEAT.md` 的价值不在“让 AI 主动”，而在“让主动有边界”。一份小而克制的检查清单，加上明确的静默规则，Agent 才能从问答工具变成一个真正不烦人的值班同事。先从一条任务开始，跑两周再加第二条——这个机制最怕的是一开始就写满整页。
