DeepSeek 放出新模型，顺带把 API 价格又往下调了一截，热搜词条写得很朴素——“用户要给 AI 付的钱又少了”。这句话背后其实是一道挺硬核的算术题：你每次调用模型付出去的钱，究竟花在了哪里？工程师又是从哪儿一毛一毛把成本抠下来的？这篇就把这本账摊开来看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-19/5896fe42521702fa.png)

## 一、先把账拆开：一个 token 的钱花在哪

- 主流大模型 API 按 token 计费，输入、输出分开算，输出通常比输入贵好几倍——因为“读题”是批量计算，“逐字答题”才是真正烧资源的部分。
- 一笔推理订单的成本大致三块：**GPU 算力、显存占用、服务调度开销**。
- 两个阶段的性质完全不同：prefill（读入 prompt）是计算密集，吃算力；decode（逐字生成）是访存密集，瓶颈在显存带宽。上下文越长，这两头都越难受。
- 容易被忽略的省钱开关：**缓存命中价**。如果你的应用每轮对话都带着同一段长前缀（system prompt、知识库片段），服务商会把重复部分留在显存里，第二次起按缓存价计费，通常比正常价便宜一个数量级。
- 举例：给客服机器人挂一份两万字说明书，几十轮对话反复带着它跑，账单大头其实是这段重复输入。选模型时先看缓存价，很多时候比看“单价”更实在。

## 二、MoE：671B 参数，每个 token 只叫醒 37B

- 早期的稠密（Dense）模型，每个 token 都要穿过全部参数，像一个公司开全员大会讨论一件小事。
- MoE（Mixture of Experts，混合专家）换了个思路：把模型拆成很多“专家”，一个路由器判断当前 token 该找谁干活，只激活其中一小部分。
- DeepSeek-V3 的做法：总参数 671B，每个 token 只激活约 37B，计算量直接降到约十八分之一。
- 类比：不是全院专家围着你转，而是分诊台按症状指派两三个科室，费用自然下来了。
- 注意它的代价：省的是计算量（FLOPs），但显存里仍要装下全部参数。所以 MoE 的省钱效果建立在大集群、高并行的基础上，小玩家想抄作业门槛不低。顺带一提，这种“全员待命、按需上岗”的组织方式，人类公司学起来都费劲，模型先跑通了。

## 三、这次降价的主角：稀疏注意力，砍的是 O(n²)

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-19/6575eec4984d93a4.png)

- Attention 的老毛病：每个 token 都要和历史所有 token 算一遍相关度，序列长度翻倍，计算量约翻四倍；同时 KV cache 的显存占用随长度线性膨胀。长文本场景下，显存往往比算力先爆炸。
- DeepSeek 在这条线上是连续出手的：更早的 MLA（多头潜在注意力）先把 KV cache 压缩到传统方案的一小部分；这次 V3.2 系列实验版上的 DSA（DeepSeek Sparse Attention）更进一步。
- DSA 的思路：加一个轻量的索引器给历史 token 打分，每个查询只挑出最相关的少数片段参与注意力计算，复杂度从 O(n²) 降到 O(n·k)，k 是固定的稀疏度。
- 结果：官方口径 API 价格下调 50% 起，长文本场景降幅更明显；公开评测上主要指标与上一代基本持平。说白了，不是模型变笨了来换降价，而是把之前“陪跑”的计算剪掉了。
- 这也是行业共识路线：agent 时代长上下文是基本盘，谁先把长文本成本打下来，谁就能接住下一波用量。

## 四、降价也不全是技术活：三股商业力量

1. **工程挤水分**：FP8 量化、更高效的算子、大批量并发调度，把同一批 GPU 的利用率抬高，单位成本应声下降。
2. **竞争压价**：2024 年年中那波价格战记忆犹新——国产主力模型一度降到每百万 tokens 一块钱以内，甚至直接免费；开源模型持续冲击，闭源厂商的定价空间被反复压缩。
3. **趋势性通缩**：a16z 统计过一个数字，同等能力的推理价格大约以每年 10 倍的速度下降。2022 年底跑一次 GPT-3 水平对话的成本，到 2024 年已经跌了两个数量级以上。

换句话说，硬件、算法、工程、竞争四条曲线同时向下。“AI 变便宜”不是限时促销，而是这条产业的主旋律。

## 五、便宜了，然后呢：Jevons 悖论正在重演

- 单价降不等于总支出降。经济学里的 Jevons 悖论：资源利用效率提升后，总消耗量反而上涨。蒸汽车间如此，token 也一样。
- Agent 是典型场景：一个自动查资料、调用工具、写报告的任务，来回几十轮调用，token 消耗轻松是单轮对话的上百倍。
- 便宜 token 的意义不是让你省着用，而是让过去“算不过账”的场景变得可行：全天候监控型 agent、超长文档分析、高频小调用。
- 对开发者来说，单价腰斩约等于预算空间翻倍——你可以多试十个以前不敢上的功能点。省 token 从来不是目的，干活才是。

## 冷思考：三条建议带走

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-19/e05dc2ea51c12e4f.png)

1. **别只看单价，按自己的业务算总账**：agent 型应用，输出 token 和调用次数是大头；长文档型应用，输入和缓存命中是大头。拿真实流量回放一遍再决定换不换模型，比看发布会靠谱。
2. **工程上先省钱，再谈换模型**：稳定 system prompt 前缀吃缓存价、及时裁剪无关上下文、输出用结构化格式控制长度——这些动作不动模型也能省出一大块。
3. **把省下的钱投回评测和数据**。在单价每年降一个数量级的世界里，护城河不在“此刻用哪家模型”，而在“你有没有一套自己的评测集，能快速判断每一次降价是否值得迁移”。价格往下走，能做的事往上走——这才是降价的正确打开方式。
