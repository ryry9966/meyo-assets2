## 背景

玩 Agent 这段时间有个明显的感受：模型能力上来之后，瓶颈往往不在"它多聪明"，而在"它掌握多少关于你的上下文"。OpenClaw 的工作区里，AGENTS.md 管行为规范，SOUL.md 管人格基调，而 USER.md 是专门放"用户是谁"的文件。它会在会话启动时注入 Agent 的上下文，相当于一份随身携带的用户画像。

## 问题

没有 USER.md（或写得很潦草）时，常见的尴尬：

- 每个新会话都要重新交代一遍技术栈、目录结构、命名习惯；
- Agent 默认热情长文回复，而你只想要干脆的结论；
- 它不知道你在做什么项目，建议总是泛泛而谈；
- 时区、部署环境、常用端口这类信息，说了就忘。

本质上都是同一个问题：系统提示词是通用的，你的偏好是私有的，缺少一个稳定的承载位置。

## 做法

我的 USER.md 目前 40 行左右，分五段：

1. **基本盘**：身份一句话、所在时区、主要语言；
2. **技术栈**：主力语言、框架版本、部署环境（比如"生产在 Debian 12 + Docker，别推荐 yum"）；
3. **沟通偏好**：回复要短、先给结论、不确定就直说、中文回复但保留英文术语；
4. **当前项目**：正在做的两三个项目，各一句话状态；
5. **禁区**：不要自动执行的操作，如直接 push main、动生产数据库。

写法上两个原则：**只写可执行的事实，不写抒情**。"我喜欢简洁"没用，"回复控制在 10 行内，先结论后原因"才是 Agent 能执行的指令。其次，**每条信息都要能改变 Agent 的行为**，否则删掉。

维护上我让 Agent 自己参与：隔段时间说一句"根据最近对话，更新 USER.md 的当前项目部分，diff 给我确认"。人只做审核，不做记录员。文件进 git，改坏了随时回滚。

## 踩坑点

- **写太长**。USER.md 每个会话都会注入，见过有人写 300 行，上下文一半被个人简历占掉。控制在 50 行内，长背稿放 MEMORY.md 按需检索；
- **过期信息比没有更糟**。项目状态两个月没更新，Agent 还在围绕你已放弃的方案给建议。"当前项目"这节要么常更新，要么别写；
- **别放敏感信息**。API key、密码、内网地址不要写。这份文件可能被插件读取、被日志打印、被你随手贴给别人排查；
- **和 SOUL.md / AGENTS.md 打架**。SOUL.md 写"热情健谈"，USER.md 写"话越少越好"，行为就不稳定。私有的覆盖通用的，重复的只留一处；
- **一份文件应付所有场景**。工作和个人混用同一个 Agent 时，考虑分工作区，至少把工作内容隔离出去。

## 可复用建议

- 起步模板就五段：基本盘 / 技术栈 / 沟通偏好 / 当前项目 / 禁区；
- 每月固定回顾一次，删过时项比持续追加更重要；
- 用指令化语言写偏好：动词开头，带量化标准；
- 敏感信息走环境变量或密钥管理工具，文件里只留指针；
- 改动走 git，让 Agent 提 diff，不要直接写。

## 总结

USER.md 不是什么高深机制，就是一份被稳定注入的纯文本。它的价值在于把"你和 Agent 的磨合成本"从每次会话压缩到一次配置。花半小时写第一版，之后交给习惯去迭代，两周后你会发现，Agent 的回复开始像一个认识你很久的同事，而不是每次都要重新自我介绍的陌生人。
