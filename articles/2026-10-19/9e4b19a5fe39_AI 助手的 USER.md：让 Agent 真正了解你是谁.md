## 背景

玩 Agent 的人大多在 AGENTS.md 和系统提示词上花足心思，教它怎么用工具、怎么写代码。但对"我是谁"这件事，往往靠每次会话开头手动交代："Arch 系统，Python 3.12，回答用中文，别加 emoji……"

OpenClaw 的 workspace 里有一个常被忽略的约定文件：USER.md。Agent 启动时会把它读进上下文，作为对你长期身份的认知。一句话分工：AGENTS.md 教 Agent 怎么干活，USER.md 告诉它在为谁干活。

## 问题

没有 USER.md 时，常见三类摩擦：

1. **重复自我介绍**：换会话、换设备，同样的背景信息再打一遍。
2. **Agent 猜错偏好**：默认输出英文注释、生成你早弃用的构建配置、你要简短它偏写长文。
3. **记忆靠聊天记录**：上下文一压缩，你的约束就丢了，行为开始漂移。

## 做法

**第一步：最小可用版本。** 在 workspace 根目录建 USER.md，先写五个区块：

- 我是谁：角色 + 主要工作内容，两三行
- 环境：OS、shell、常用语言和版本、包管理器
- 偏好：回答语言、详略程度、代码风格（如"注释用中文"）
- 禁区：不许动的目录、不许执行的命令类别
- 当前焦点：在做的 1–2 个项目，各一句话

**第二步：控制篇幅。** 经验值是 100–150 行以内。它每次会话都占上下文，写成长篇自传等于给自己加税。

**第三步：让 Agent 参与维护。** 我每隔一段时间让它对照近期对话，输出"建议写入 USER.md 的条目"，人工确认后合并，比自己回忆可靠得多。

**第四步：进 git。** 偏好变更可 diff，还能顺带看出自己的技术栈半年换了多少东西。

## 踩坑点

- **写太多**：有人把项目文档整段塞进去，核心约束反被稀释。USER.md 是索引，不是档案。
- **信息过期**：系统升级后没更新，Agent 一直按旧版本给方案。过期信息比没有信息更糟。
- **放敏感信息**：token、内网地址写进去，等于每次会话都送进上下文和日志。只写"密钥从环境变量取"这类规则，不写值本身。
- **与 AGENTS.md 边界模糊**：两边都写代码风格、内容打架。原则：AGENTS.md 管协作规范，USER.md 只管"我"。
- **偏好太虚**："代码要优雅"没有信息量，"函数不超过 50 行、避免装饰器"才可执行。

## 可复用建议

- 当配置文件写，不当日记写：短、结构化、可验证。
- 定期（比如每季度）审一次，删掉失效条目比新增更重要。
- 多设备/多 workspace 场景：全局一份基础版，项目里只放差异项。
- 团队内沉淀一份脱敏模板，新人照结构填空即可上手。

## 总结

USER.md 的价值不是让 Agent 更聪明，而是把重复沟通变成一次声明。成本只是一个 markdown 文件，收益是偏好的定义权回到你自己手里。如果你已经在维护 AGENTS.md，USER.md 是顺手就能补齐的另一半。
