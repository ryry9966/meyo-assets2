## 背景

订阅源越加越多，焦虑也越多。RSS 本身是个好协议，但原始条目噪音大：标题党、转载重复、很多 feed 只给摘要不给全文。我的思路是把**抓取、清洗、摘要、汇总**四步串成一条管线，交给 OpenClaw 里的 Agent 定时执行，每天早上产出一份 5 分钟能读完的简报。

## 问题

手工刷 RSS 有三个痛点：

1. 条目多、重复多，同一条新闻常被十个源转载；
2. feed 里往往只有 summary，点开才有全文，节奏被打断；
3. 人肉筛选不可持续，但全交给 LLM 又怕幻觉和成本失控。

## 做法

管线分四层：

1. **抓取层**：自建 FreshRSS/Miniflux，或直接用 rss-parser 拉源，按主题分组（agent、infra、论文等），每 2 小时增量抓一次。
2. **清洗层**：URL 归一化去重（去掉 utm 参数后取 hash），标题相似度去重，再用 trafilatura/readability 抓正文。抓不到全文的标记为 `summary-only`，不许模型编。
3. **摘要层**：用 OpenClaw Agent + 自定义 MCP 工具。MCP 只暴露两个能力：`fetch_batch`（读取清洗后的条目）和 `publish_digest`（写出汇总）。Agent 只做归纳，不做自由浏览——权限收窄后，成本和幻觉都可控。
4. **输出层**：每天 8 点生成 Markdown 简报，按分类分组，每条 2–3 句摘要 + 原文链接，落到本地文件并推送。

Prompt 的关键约束：只允许基于给定正文总结，信息不足就写"正文不足"；输出固定 schema 的 JSON，方便下游渲染：

```json
{"title":"...","summary":"2-3句","link":"...","category":"agent","confidence":"high|low"}
```

## 踩坑点

1. **正文提取失败率比想象高**：约两成站点反爬或全 JS 渲染。必须兜底：抓不到就用 feed 自带 summary，并在简报里标注"仅摘要"。
2. **token 成本**：不要一条一请求。按分类攒批（8–15 条一次），让模型一次性返回 JSON 数组，成本能降一个量级。
3. **去重必须在摘要前**：重复条目各摘要一遍再合并，既烧钱又让简报啰嗦。
4. **别让 Agent 联网自由发挥**：一旦让它自己搜索补充材料，延迟、成本、幻觉全会上来。管线里它的输入输出都应是结构化数据。
5. **定时任务要有哨兵**：cron 挂了没人知道。即使无新条目也发一份"空简报"，连续空输出就触发告警。

## 可复用建议

- 摘要 prompt 当代码管理，带版本号，方便回溯某天简报质量差是源的问题还是 prompt 的问题。
- 中间结果（清洗后的条目、摘要 JSON）落 SQLite 或 JSONL，可离线重跑和评估。
- `confidence` 低的条目折叠展示，人只审有疑问的部分，保持人在环。
- 先接 10 个以内源跑稳一周再加量，别一上来订 200 个 feed。

## 总结

这条管线没有黑科技，价值在于把"读"变成"审"：抓取和清洗决定下限，prompt 约束和结构化输出决定上限，Agent 只做它擅长的归纳。跑了一个月，每天早上简报 5 分钟读完，漏掉重要内容的次数反而比手工刷少——去重和分类帮我把注意力集中了。工程上，越是平凡的环节，越值得先做扎实。
