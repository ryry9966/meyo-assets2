## 背景

我们社区每周需要若干条精选技术帖，人工整理耗时不稳定。目标很朴素：做一个每天产出草稿、审核后自动发布的机器人。技术栈选了 OpenClaw Agent 做编排，工具一律封装成 MCP server，发布走独立插件。本文记录架构取舍和前两个月真实踩过的坑。

## 问题定义

难点不是“能不能生成内容”，而是三个工程问题：

1. 如何保证不重发、不漏发（状态一致性）；
2. 如何守住内容质量下限（审核门禁）；
3. 挂了之后怎么知道、怎么恢复（可观测性）。

## 架构与实现

分四层：调度层（cron）→ Agent 层（OpenClaw 负责编排）→ 工具层（MCP servers：素材抓取、发布、日志）→ 状态层（SQLite）。

1. **素材抓取**：只读 MCP 工具，拉取近 48h 热帖与标签，输出结构化 JSON；
2. **草稿生成**：Agent 结合素材和历史已发列表，embedding 相似度超 0.85 的选题直接跳过；
3. **审核门禁**：规则层（长度、外链数、敏感词）+ LLM 复核“是否值得发”；
4. **发布插件**：只接收结构化 payload，成功才写终态；
5. **日志告警**：每次运行 append-only 记录，失败走 webhook 通知。

关键设计是**两阶段提交**：发布前先写 `pending` 记录并生成幂等键（日期 + 选题 hash），发布成功后更新为 `done`。重启后扫到 pending 超过 10 分钟的记录，用幂等键反查是否已发，再决定补发或标记失败。

## 踩坑实录

- **重复发帖**：第一版在“发布成功后”才写库，进程恰在两步之间被 kill，同一内容发了两遍。解法就是上面的先写 pending。
- **内容同质化**：跑两周后草稿越来越像。加入 embedding 去重和“话题冷却期”（同标签 5 天内不重复）。
- **MCP 工具超时**：抓取偶尔卡 60s+，Agent 默认超时太短导致整条链路中断。给工具设独立超时与重试，超时降级用缓存素材。
- **时区问题**：调度用了 UTC cron，发帖时间每天漂 8 小时。调度统一改本地时区并在配置显式声明。
- **静默失败**：最初失败只写日志没人看。加了 webhook 告警才发现抓取接口三天前就开始 403。

## 可复用建议

- “生成”与“发布”拆成可独立测试的单元，中间强制过审核门禁；前期人工确认，稳定后再逐步放开。
- 工具做成无状态 MCP server，状态统一收敛到一层，别散落在 prompt 和内存里。
- 幂等键 + 状态机是自动化发帖的地基，比换更强的模型重要得多。
- 日志 append-only 且带 trace id，排障基本全靠它。

## 总结

这个机器人代码量不大，LLM 只占很小一部分，大头在状态管理、去重和失败恢复上。OpenClaw 和 MCP 解决了“怎么把工具接起来”，而“怎么让它长期可靠地跑”仍是一类朴素但必须认真对待的工程问题。建议从人工审核模式起步，再逐步收窄人的介入范围。
