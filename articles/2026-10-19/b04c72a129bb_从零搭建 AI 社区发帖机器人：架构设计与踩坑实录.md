## 背景

我们社区每天产生几十上百条讨论，一直想做一档"每日精选"，把高价值帖子汇总成摘要帖。人肉整理一次要两小时，坚持两周就断了。于是我基于 OpenClaw 搭了一个定时发帖机器人，跑了一个多月，这里记录架构取舍和踩过的坑。

## 问题定义

动手前先明确三条硬约束，后来证明它们比"提示词写得好不好"重要得多：

1. **内容必须可溯源**：引用的帖子、链接、数据必须来自工具返回，不允许模型凭记忆编造；
2. **发布必须幂等**：任何重试、超时都不能导致重复发帖；
3. **必须有兜底**：上线初期所有帖子先出草稿，人工确认后才发布。

## 架构与实现

整体是一条五层流水线：

- **触发层**：cron 每日 09:10（显式时区）触发 OpenClaw agent 任务；
- **采集层**：通过 MCP 调 `forum.search` 和 `forum.fetch_thread`，拉取近 24 小时帖子；
- **预筛层**：本地按回复数、点赞数过滤，只保留 Top 20，避免塞爆上下文；
- **生成层**：agent 按固定模板产出摘要草稿，模型只负责提炼观点，不负责提供事实；
- **发布层**：`forum.create_post` 带 `idempotency_key`（当天日期字符串），服务端按 key 去重。

状态用 SQLite 存三张表：已处理 thread、草稿、发布记录。所有 tool call 落日志。

```yaml
schedule: "10 9 * * *"
timezone: Asia/Shanghai
tools: [forum.search, forum.fetch_thread, forum.save_draft, forum.create_post]
mode: dry_run   # 前 14 天
```

## 踩坑实录

**1. 幻觉链接。** 第一版让模型"附上原帖链接"，它给的三条里两条是编的。修法：prompt 明确禁止输出工具结果之外的 URL，链接一律从结构化数据取字段拼接，模板渲染时校验域名白名单。

**2. 重复发帖。** 某天任务超时被重试，同一摘要发了两遍。修法就是幂等键，publish 工具在服务端先查 key 再写入。这属于"必须做"，不是"可以加"。

**3. 时区。** 最初 cron 按 UTC 跑，帖子固定在下午五点发出，用户反馈像水文。显式指定时区后解决。

**4. 上下文爆炸。** 热门日 200+ 帖直接打满上下文，输出开始丢内容。把预筛从 agent 内挪到 agent 外，用脚本先裁剪，问题消失。

**5. 触发反垃圾。** 补发历史精选时连续发帖，被社区限流。加了发布间隔与指数退避，补发任务拆成单帖队列。

## 可复用建议

- **MCP 工具权限最小化**：`save_draft` 与 `create_post` 拆成两个工具，自动发布放开前，agent 只拿得到前者；
- **先 dry-run 一到两周**，把草稿和人工发布的 diff 过一遍再放开；
- **模板固定结构、模型只填空**，比"自由发挥+事后修"稳定一个量级；
- **幂等键、状态库、tool call 日志**，是所有自动化任务的底线三件套。

## 总结

这个机器人技术含量不高，难点全在工程约束上：可溯源、幂等、兜底、限流。OpenClaw + MCP 让工具接入和调度变得很快，但真正决定它能不能长期跑下去的，是这些朴素手段。建议任何想做自动化内容流水线的同学，先把发布侧的防线搭好，再回头优化生成质量。
