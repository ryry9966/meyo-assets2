最近微博上有个热议话题：**道士念咒语就是在调用AI**。评论区一半人在玩梗，另一半工程师在默默点头。这不是纯属巧合，在 AI 圈，prompt（提示词）早就有个民间译名，就叫“咒语”；写 prompt 叫“念咒”，效果不稳定叫“咒语失灵”。把玩笑拆开看，道士和 prompt engineer 的相似度比想象中高得多；而拆到最后一层，两者的差别恰好就是工程与玄学的分界线。这篇文章把梗里真有效的部分、不该迷信的部分，一次讲清。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/e0d4cd22ab017fef.png)

## 梗从哪来：为什么“咒语”成了 prompt 的民间译名

- 2020 年 GPT-3 的论文《Language Models are Few-Shot Learners》展示了一件怪事：不改模型参数，只在输入里附上几个示例，模型就能“领会”任务。社区随即长出新工种 prompt engineering，专门通过设计输入文本来稳定引导输出。
- "prompt"一词本意是“提词”：剧组里躲在台下给演员递台词的 prompter。它天生就是个“给看不见的执行者递指令”的角色。
- 中文技术社区顺势形成一套黑话：训练模型叫“炼丹”，效果飘忽叫“玄学”，写提示词叫“念咒”，因为时灵时不灵，玄学氛围拉满。
- 道士类比之所以好笑又贴切，是因为结构同构：
  - 符咒文本 ↔ prompt 字符串
  - 念错一个字都不行 ↔ 输入必须语法正确、措辞准确
  - 被召唤的神明 ↔ 黑盒模型
  - 师门口诀、祖传符本 ↔ 官方模板、few-shot 示例
  - 法事显灵 ↔ 模型返回结果

## 历史彩蛋：咒语本来就是一份“命令行指令”

- 道教咒语的标准三段式：开头“奉请某位真君”（指定调用对象），中间陈述诉求（请求体），结尾“急急如律令”（要求立即执行）。
- 关键知识点：“如律令”原是汉代公文套语，居延、敦煌出土的汉简中反复出现，意思是“按法令火速办理”。道教把它借进咒语，等于给鬼神下了一道行政命令。
- 换句话说，咒语从诞生起就是人类向“不可见系统”发起的结构化请求：指定收件人、写明诉求、附上优先级和时限。从这个角度看，“念咒就是调用”几乎是字面成立——古人只是把 API 调用写在竹简上。

## 技术上“意外地准”的三个对应

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/b33e2545e38c6a87.png)

1. **字字不可错 = 措辞敏感。** 大模型做的是 next-token prediction，输入分布直接决定输出分布，同一问题换个说法，质量可能差一截。经典案例：2022 年 Kojima 等人的 zero-shot CoT 研究，只在提问后加一句 "Let's think step by step"，GSM8K 数学题准确率就从约 10% 升到约 41%，MultiArith 上从 17.7% 升到 78.7%。一句话让准确率翻四倍，这是一句被实验反复验证过的“现代咒语”。
2. **摆坛 = 准备上下文。** LLM 是无状态的，每次调用都是全新一场法事：system prompt 是布置坛场，few-shot 示例是上香；关掉 context window，神明当场退场，下次得重新请。
3. **符纸 = 输出格式约束。** 要求模型“只输出 JSON”“分三段写”“不确定就直说”，相当于给回答画了张符纸，防止显灵显得太自由。

## 类比在这里断掉：道士没有对照组，你有

- **可复现性**：temperature 设 0，同一 prompt 跑多次输出大体稳定，可以做回归测试；咒语灵不灵，历史上从没人跑过 A/B 实验。
- **可调试性**：工程师能看 logits、token 概率、attention 可视化，错了能定位“哪句话误导了它”；法事失败只有一种归因——“心不诚”，不可证伪，也就不可改进。
- **无特权音节**：咒语讲究“古音才灵”，prompt 完全不在乎文言白话，只在乎语义清晰、结构明确。咒语的法力来自神秘权威，prompt 的法力来自训练数据的统计规律。
- 所以准确的结论是：念咒是**信仰式调用**，prompt 是**工程式调用**。前者靠诚，后者靠测。

## 从念咒到写需求：现代“画符”五步

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/d56e2f7dbfa96dc8.png)

1. **立意（对应符头）**：先声明角色，“你是一名资深数据分析师”，等于指定调用哪一尊“法身”。
2. **陈情（对应符胆）**：任务、背景、已知信息一次说全，别让神明猜。传统符箓本就分符头、符胆、符脚三层，网友把这套对应整理得有模有样，当比喻很好，当文献考据不行。
3. **封印（对应符脚）**：加约束与格式，“不超过 200 字”“以表格返回”“引用需给来源”。
4. **上香（示例）**：附一两个输入输出样例，格式命中率显著上升，比反复解释省事得多。
5. **复盘**：同一 prompt 跑五次看方差，两种写法各跑一轮 A/B，留下胜者再迭代下一版。

补一句法力上限：prompt 只是接口，模型能力才是法力本身。在弱模型上念天花乱坠的咒，不如在强模型上把人话说清楚。

## 三条冷思考

1. **给“灵验”建对照组。** 输出不稳定时，固定参数、固定 prompt、同一问题跑十次看方差，比“多念两遍”有用得多。一切结论都得有基线。
2. **把咒语翻译回需求文档。** 下笔前自问：如果雇一个真人外包，我会怎么交代这件事？需求写得清，咒就灵；写不清，再华丽的辞藻都是噪音。
3. **警惕咒语溢价。** 市面上“999 条万能咒语模板”多数是把公开常识打包收费。模板可以借结构，不必供字面——真正值钱的是你对任务的清晰定义，而不是那句话本身。

道士念咒，调用的是期望中的确定性；我们写 prompt，调用的是概率中的确定性。都是人类隔着黑盒与不可见系统谈判的方式，区别只在于，我们这一代，终于能看到 log 了。
