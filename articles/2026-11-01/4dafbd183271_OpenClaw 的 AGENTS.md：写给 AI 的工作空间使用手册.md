## 背景

用 OpenClaw 跑过真实项目的人都有体会：agent 的执行质量，很大程度取决于它对工作空间的“先验知识”。每次会话都在开头重新交代“这个项目用 pnpm、跑测试用 make test、别动 dist/”，既低效也不可靠。

AGENTS.md 就是解决这件事的社区约定：一个放在工作空间根目录的纯 Markdown 文件，OpenClaw 进入工作空间时会自动读取，作为本次任务的长期上下文。本质上，它是你写给 AI 的入职手册。

## 没有它会出什么问题

- **用错命令**：项目明明用 pytest，agent 却写了 npm test，然后坚持修到“通过”为止，绕一大圈。
- **重复踩坑**：目录约定、命名风格、提交信息格式，每次都要口头补丁。
- **误碰禁区**：改了 lockfile、生成产物、CI 配置。
- **规则失焦**：规范散落在 README、CONTRIBUTING、Wiki 里，agent 不知道哪些对自己生效，干脆都不遵守。

## 做法

1. **根目录建 AGENTS.md，先写五段**：项目一句话简介；可直接复制执行的构建/测试/lint 命令；代码风格要点；禁区清单（禁止修改的路径）；已知陷阱（例如“mock 环境必须先起 docker compose”）。依赖特定 MCP 服务或插件的，也写清楚前置条件。
2. **控制篇幅**。整个文件会进上下文，建议 100 行以内，全部用祈使句，不要写成给人看的散文。
3. **用层级拆分**。Monorepo 在各子目录放各自的 AGENTS.md，OpenClaw 编辑某文件时以最近的文件为准；根文件只留全局共识。
4. **当代码管理**：改动走 PR review，随代码一起版本化。
5. **持续迭代**：agent 犯两次同样的错，就固化为一条规则；某条规则从未拦住过任何错误，删掉。

## 踩坑点

- **复制模板忘了改命令**。错误但具体的命令危害最大，agent 会忠实执行。
- **写成 README 摘要**。大段架构介绍没有可执行信息，纯浪费上下文。
- **与其他文档冲突**。遇到冲突 agent 会自己选边，结果不可预测；要么删，要么显式声明优先级。
- **写无法判定的规则**。“注意代码质量”等于没写。能用 linter/hook 保证的约束交给工具，AGENTS.md 只写工具管不住的。
- **写本机绝对路径或密钥**。前者让协作与 CI 失效，后者是安全事故。

## 可复用建议

- 五段骨架够用：简介 / 命令 / 风格 / 禁区 / 陷阱，宁少勿多。
- 命令必须**亲自验证过**：写进去之前在干净环境跑一遍。
- 规则尽量可判定：“测试必须跑 `uv run pytest -x`” 优于 “跑一下测试”。
- 与自动化分工：hook 和 CI 负责强制，AGENTS.md 负责解释与补充，不重复。

## 总结

AGENTS.md 是投入产出比最高的一类 agent 配置：一个纯文本文件，没有协议成本，效果直接体现在 agent 的一次通过率上。把它当配置代码维护——短、准、常更新——比堆长文档有用得多。
