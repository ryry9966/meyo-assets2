最近 Anthropic 对 Claude 的订阅体系动了一次不小的手术。据 36 氪等媒体报道，顶配的 Max 20x 套餐升级为 Ultra 档，并取消了沿用一年多的“5 小时限额”。对偶尔聊聊天的人，这也许只是产品页上换了个名字；但如果你靠 Claude Code 写代码、跑自动化 Agent，这条消息几乎等于“套餐底层逻辑换了”。这篇文章把来龙去脉、背后的算力经济学，以及不同用户该不该跟，一次拆清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/d32a14d36f65e5d5.png)

## 先复盘：5 小时限额是个什么东西

- Claude 的付费档位长期是三级：Pro（$20/月）→ Max 5x（$100/月）→ Max 20x（$200/月），名字里的 5x、20x 大致代表相对 Pro 的用量倍数。
- 所谓“5 小时限额”，是一个滚动窗口：系统统计你每个 5 小时区间消耗的 token（模型处理文本的基本计量单位），超了就得等窗口滑动重置，相当于每 5 小时发一张新饭票。
- 为什么要设这道闸？三个原因：
  1. **削峰填谷**：推理算力是刚性资源，滚动窗口能防止少数重度用户把 GPU 集群 24 小时打满，把突发流量摊成可预测的负载曲线。
  2. **公平调度**：没有窗口，突发型重度用户会挤占普通用户的吞吐，最后大家一起变慢。
  3. **成本闸门**：订阅是包月制，重度用户的边际推理成本可能远超月费——OpenAI 2024 年底推 $200 的 ChatGPT Pro 时就承认部分重度用户“人均亏损”，窗口本质是一道止损阀。
- 用自助餐类比：窗口防的不是吃得多的人，而是从开餐吃到打烊的人。
- 2025 年下半年 Anthropic 又叠加了周限额，官方给过参考区间：Pro 约等于每周 40–80 小时的 Sonnet 用量，Max 20x 约 240–480 小时，并称绝大多数用户触不到周上限。也就是说，此前其实是“5 小时窗口 + 每周总量”的双层结构。

## 这次改了什么：限制的颗粒度变了

- 按报道，Max 20x 升级为 Ultra 档，核心变化是取消 5 小时滚动窗口，只保留更宽裕的周度配额。
- 注意，这不是“用量变多”这么简单，而是限制的颗粒度变了：以前必须少食多餐，现在可以一顿吃到底。
- 举例：你让 Claude Code 重构一个几万行的老项目，任务要连续跑四五个小时。旧规则下很可能在第 3 小时被窗口掐断，任务挂起、等重置；新规则下，只要周配额没见底，就能一口气跑完。
- 说清楚一点：取消的是“节奏限制”，不是“总量限制”。周配额仍在，公平使用条款也在。理解这一点，才不会被“无限畅用”的传闻带偏。

## 为什么取消：Agent 时代的算力经济学

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/86bbaa3162656041.png)

- **需求侧变了**。Claude 的增长引擎已从“人类聊天”切换到“Agent 干活”。一个 Claude Code 会话动辄消耗数百万 token，机器 7×24 待命，和按人类作息设计的 5 小时窗口天然错配；而 Agent 工作流里，任务中断的隐性成本（重载上下文、重新规划、人工接管）往往比 token 本身更贵。
- **供给侧有底气**。敢取消高频闸门，等于公开表态：prompt caching（重复前缀缓存计费）压低了长会话成本，批处理任务挪进低谷时段，多区域容量有冗余，负载可以被更平滑地调度。
- **对手逼的**。OpenAI 有 $200 的 Pro 档和 Codex，Google 把对标档位直接命名为 Ultra（约 $250/月）。Anthropic 采用同名档位，既是术语对齐，也是向重度开发者喊话：我们在同一个竞技场，而且规则对你们更友好。
- **商业结构决定的**。Anthropic 收入大头在 API 和企业客户，订阅更像漏斗顶端：用 Ultra 锁住最挑剔的重度开发者，他们迟早转化为 API 或团队版客户。

## 三种用户画像，算三笔账

- **画像 A：日常问答、偶尔写点东西**。你的 5 小时窗口大概率从没卡过，这次升级几乎无感——别为无感的升级多付钱。
- **画像 B：重度 Claude Code / Agent 用户**。Ultra 的真正价值不是总量变多，而是任务连续性，不再在关键任务中途被迫停车。对这类用户，中断成本大于 token 成本，升级理由充分。
- **画像 C：小团队共享**。理论上可以几个人合用一个顶配档位跑轻量任务，但周配额是共享池：一人爆肝，全队清零。真要走这条路，先立内部用量规矩。
- 还有一点容易被忽略：限额取消后，“配速”的责任从平台转移到你手上。一个失控的 Agent 循环，完全可能两天烧光一周配额。

## 冷思考与实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/91a1d2198012008d.png)

1. **先审计，再升级**。打开设置里的 usage 面板，导出过去一两个月的用量，回答一个问题：5 小时窗口有没有真正卡过我？没卡过，Ultra 对你就是溢价买安全感。
2. **学会配速和分流**。重任务排进周预算开头；轻任务降级到 Sonnet、Haiku 等低档模型；Agent 循环里最贵的是输出 token，控制迭代轮数比换套餐更省钱。
3. **别把单一供应商当基础设施**。OpenAI、Google 都有对标档位，交叉订阅或混合 API 调用，常常比单家顶配更稳更省。限额规则说变就变，工作流不该绑死在任何一家的套餐页上。

限额定价，本质上是在给“算力期货”定价：平台赌你的平均用量，你赌自己的峰值需求。这次 Anthropic 把赌注抬高了一格，但牌桌逻辑没变——看清自己的牌，再决定跟不跟。
