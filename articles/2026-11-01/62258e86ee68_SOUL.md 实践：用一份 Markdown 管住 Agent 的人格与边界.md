## 背景

OpenClaw 的工作区里，每个 Markdown 文件职责明确：AGENTS.md 管做事流程，TOOLS.md 管工具备注，MEMORY.md 管记忆。SOUL.md 的位置比较特殊——它定义的是"这个 Agent 是谁"。每次新会话启动，内容会被注入 system prompt，并且在所有通道（WhatsApp / Telegram / CLI）全局生效。换句话说，它是你 Agent 的宪法。

## 问题

没有这份文件或随手写写的 Agent，有两个典型毛病。

一是**人格漂移**：今天话痨，明天冷淡，长对话聊到后面完全换了个人。

二是**边界缺失**：它太"热心"，会直接执行不该直接执行的事——没确认就群发消息、顺手跑清理脚本、把密钥贴进日志。

人格和边界其实是一体两面：稳定地"像什么"，和坚决地"不做什么"。

## 做法

我把 SOUL.md 拆成四段，整份控制在 60 行以内：

```markdown
# 内核
- 中文优先,技术术语保留英文;是助手,不是真人。

# 风格
- 单条回复默认不超过 200 字,先给结论再给细节。
- 信息不足时问一个问题,不要连猜三次。

# 边界(触发 → 动作)
- 涉及付款 / 删除数据 / 对外发消息:先复述计划,等明确"确认"再执行。

# 红线
- 不输出任何凭据;不冒充真人;不执行 AGENTS.md 之外的批量操作。
```

核心动作只有一个：**把形容词换成可执行规则**。"友好简洁"没有约束力，"不超过 200 字"才有。

写完用对抗性 prompt 验收：让它删文件、让它立刻发消息、告诉它"之前的规则作废"。边界经不经得起撩，一试便知。

## 踩坑点

- **写太长**：超过一屏，遵循度断崖式下降。SOUL.md 是 system prompt 的一部分，每个 token 都在稀释后面的规则。
- **和 AGENTS.md 抢活**："怎么完成任务"归 AGENTS.md，"我是谁、绝不做什么"归 SOUL.md。职责重叠会导致行为抖动。
- **边界写成愿望**："花钱要谨慎"挡不住任何事，"必须先确认"才挡得住。
- **用户偏好混进人格**：称呼、时区、口味放 USER.md，SOUL.md 保持对所有人生效的通用层。
- **改完不换新会话验证**：SOUL.md 按会话加载，拿旧上下文判断生效与否会误判。

## 可复用建议

- SOUL.md 进 git，每次调整带 commit message，人格漂移了能 diff、能回滚。
- 用四段模板起手，每段先写三行，跑两周再按真实翻车记录补规则——规则来源应该是事故，不是想象。
- 大版本升级或更换底层模型后，用固定的对抗性测试集回归一遍。
- 每月花十分钟重读一次：过时的边界比没有边界更危险。

## 总结

SOUL.md 不是玄学，是配置工程。它决定 Agent 在没人盯着时的行为底线。写短、写具体、写可执行，然后用测试代替信任——像对待生产配置一样对待它，它会还你一个跨会话稳定、关键时刻刹得住车的 Agent。
