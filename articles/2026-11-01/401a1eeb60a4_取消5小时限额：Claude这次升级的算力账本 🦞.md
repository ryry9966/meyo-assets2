AI 订阅这几年，“涨价”“降智”“偷偷收紧限额”大家见得多了，“把限额直接取消”还是头一回。据 36kr 报道，Anthropic 把 Claude 订阅中的 Max 20x 档位升级为 Ultra，同时取消了 5 小时滚动限额。消息一出，开发者圈讨论度直接拉满：一家以“算力紧张”著称的公司，为什么敢拆掉自家最核心的闸门？这篇文章把机制、账本和门道一次讲清。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/87e6979b11ad2f6d.png)

## 先补课：5 小时限额到底在限什么

- Claude 的订阅不是按 token 计费的“水电表”模式，而是“包月 + 用量上限”。以 Pro 档为例，每 5 小时形成一个滚动窗口（rolling window），窗口内可发送的消息数和处理的 token 量有上限；用完进入冷却，等窗口滚动刷新。
- 为什么必须限？LLM 推理是典型的 GPU 密集型服务：一次长对话可能携带几十万 token 上下文，KV cache 一占就是几个 GB 显存，顶级加速卡单卡日均成本以十美元计。一个不设限的重度用户，一天就能“吃掉”一整机推理资源。
- 5 小时窗口本质上是漏桶算法（leaky bucket）式的公平机制：把突发请求摊平，防止单个账号持续打满 GPU，同时挡住脚本化滥用和额度转售。
- 用户体感最难受的一点：窗口刷新时间取决于你上次发起请求的时刻。重度用户一天实际只有两三个完整窗口，“下午三点额度见底，晚上八点才恢复”是常态。

## Max 20x → Ultra：改的不只是名字

- 原有产品线大致是 Pro（20 美元/月）→ Max 5x（100 美元/月）→ Max 20x（200 美元/月），数字代表相对 Pro 的用量倍数。20x 档主要面向用 Claude Code 写代码、跑 agent 工作流的开发者。
- 升级为 Ultra 后，5 小时滚动限额取消，变化直接体现在工作节奏上：agent 任务可以连跑一整天，不用掐表等刷新，也不用在“现在用还是留到晚上”之间做选择题。
- 从产品逻辑看，这是一次标准的市场分层：把用量大但价格敏感的用户留在中档，把“为生产力付费”意愿强的重度用户集中到 Ultra 档。
- 命名也在对齐行业心智：Pro / Max / Ultra 这套话语体系，用户跨家比价时认知成本更低，这显然是有意为之。

## 为什么敢取消：一笔算力经济学的账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/3dd6b8b8abf6fc97.png)

- **供给侧**：推理成本在肉眼可见地下降。模型蒸馏与量化、KV cache 复用、投机解码（speculative decoding）、专用推理芯片、批处理调度——每一项工程优化都在压低“每百万 token 的服务成本”。限额松绑的前提，是这条成本曲线确实在往下走。
- **需求侧**：agentic coding 把模型从“问答工具”变成“生产力引擎”。一个工程师一天可以让 Claude Code 发起数千次工具调用、改动几十个文件。这类场景里，限额是最大摩擦点，也是取消后最大的受益点。
- **竞争侧**：OpenAI、Google 都在拉高订阅档位，Cursor 这类中间商靠转售模型额度活得相当滋润。模型厂商若自己把重度用户限死，等于把最愿意付钱的客群让给中间层。
- 还有个隐性收益：不限额意味着重度用户会跑出更多真实工作流数据。对做强化学习、评估与产品迭代的团队而言，这是比订阅费更长期的资产。

## 取消 ≠ 无限：几个容易被忽略的细节

- “取消 5 小时限额”不等于无限量使用。此前 Pro/Max 档就引入过周限额（weekly limit）作为总量闸门；5 小时窗口取消后，总量管控大概率以别的形式存在——周限额、单日总量、高峰期动态限速，或对超长上下文、超高并发单独设卡。看公告别只看标题，要看限额从“时间维度”换成了什么维度。
- 公平使用（fair use）条款依然有效：脚本化滥用、多账号、转售额度，该限制还是限制。
- 高峰期所有 Ultra 用户共享同一资源池，“不限额”并不保证“不排队”，体验波动可能只是被转移到了时段维度。
- 对团队采购来说，成本模型得重算：以前按“人数 × 每日窗口数”估算，现在要按实际 token 消耗与任务时长估算，预算弹性变大了，财务同学的表格也该更新了。

## 三条实用建议与冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/3aafdb5668a9adce.png)

1. **先算真实用量，再决定是否升级。** 拿过去一个月的消息数、会话时长做基准：一天用不满一个 Pro 窗口的人，升级 Ultra 纯属浪费；它的价值只对“窗口真的不够用”的人成立。
2. **把不限额用在 agent 化工作流，而不是纯聊天。** 真正的增量收益来自让 Claude Code 这类 agent 长时间跑批——大规模重构、补测试、批量处理文档；聊天场景多聊几句，边际价值很低。
3. **冷思考：别把“无限”当成永久承诺。** 订阅制取消限额，本质是厂商把成本波动的风险从用户侧挪回自己侧。参考云计算行业的历史，“无限量”承诺很难永久成立，按量计费与订阅制会继续混合演进。更稳妥的姿态是：把工作流设计成“即使限额回来也能降级运行”，这才是真正的抗风险能力。

限额这层壳，蜕掉一次，长出来的是更大的用量空间；至于壳会不会再长回来，看成本曲线和竞争格局的脸色。用户该做的，是趁窗口期把工作流跑顺，而不是把“不限额”写进自己的长期依赖里。
