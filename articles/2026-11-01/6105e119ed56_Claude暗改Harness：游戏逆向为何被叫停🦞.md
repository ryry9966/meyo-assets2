最近 AI 圈刷屏的热搜有个很“工程”的关键词：Harness。据 36kr 等媒体报道和社区的多方验证，Anthropic 被发现悄悄修改了 Claude 的 harness，加入了禁止协助逆向工程游戏的限制——没有发布会、没有更新日志，用户是从突兀的拒答和 system prompt 的版本 diff 里倒推出来的。表面看，这是一条“AI 不帮你拆游戏”的产品新闻；往深一层看，它演示了大模型时代的一个核心机制：模型的行为，很大程度不写在权重里，而是写在外围那层“脚手架”上。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/d074ef778ba8571d.png)

## Harness：模型之外的“第二大脑”

先定义，再谈事件。harness（也常叫 scaffold，脚手架）指包在模型外面的整套工程结构，大致包含四层：

1. **system prompt**：设定角色、边界与拒答规则；
2. **工具定义与调用循环**：搜索、代码执行、文件读写等 agent 能力；
3. **上下文管理**：截断、压缩、记忆注入；
4. **安全过滤层**：输入输出两侧的关键词与分类器。

打个比方：模型是发动机，harness 是 ECU 和交规的合体——同样的马力，踩多深、往哪开、哪儿限速，是它说了算。Claude Code 就是一个典型的 agent harness，同一个模型接不同的 harness，行为差异可以大到像两个产品。这次事件的“改 Harness”，改的就是这一层，而不是模型本身。

## “暗改”是怎么被发现的

这次的发现过程，堪称一次社区级的行为取证：

- **症状先出现**：一批原本能正常完成的反编译、逆向辅助任务，开始收到措辞高度模板化的拒答；
- **证据随后跟上**：Claude Code 的 system prompt 对用户可见，也能在运行时打印出来，有开发者把新旧版本做 diff，定位到新增的限制条款，方向直指游戏逆向；
- **结论耐人寻味**：harness 并不是黑盒，“暗改”想做到完全隐蔽几乎不可能，社区 diff 的能力比很多公司预想的强。

但它也暴露了另一面：没有 changelog 的变更，用户只能靠“行为回归”来考古。这在传统软件里相当于没有版本说明的静默升级——功能上未必致命，工程口碑上属于扣分项。

## 为什么偏偏拿游戏逆向开刀

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/aa4c952ef5608ed7.png)

游戏逆向是个天然的灰色地带，用途大致分三类：

1. **学习与互操作**：做模拟器、拆引擎、读网络协议；
2. **社区增值**：mod、民间汉化、存档修复、老游戏保存——Super Mario 64 反编译、宝可梦系列的 decomp 项目，都是社区历时数年、上百人协作的成果；
3. **克隆与抄袭**：把别人的玩法和代码快速换个皮上线。

法律上，逆向并非天然违法。SEGA v. Accolade、Sony v. Connectix 等经典判例都确认过“为了互操作的中间态复制”可以构成合理使用；但 DMCA 反规避条款和几乎每份游戏 EULA，又都在把边界往回收。而 AI 真正改变的是成本结构：过去 matching 一个关键函数要高手磨几个月，LLM 辅助可以把周期压缩一个数量级。学习用途受益的同时，抄袭门槛也在同步下降。

对平台来说，这就是一道风险账：游戏产业是 IP 诉讼的高发区，“用 AI 加速侵权”的叙事一旦成立，法律与舆论成本都极高。所以这道禁令未必等于“逆向有罪”，更像是平台在计算期望损失后，选了对自己最不划算的那种用途先按下停止键。

## 为什么改 Harness，而不是改模型

算一笔账就明白了：

- **成本**：重新训练或微调动辄数百万美元、数月周期；改一行 harness 规则，成本约等于零；
- **生效速度**：prompt 改动分钟级上线，训练以月计；
- **波及面**：改能力（权重）会伤及所有任务，改用途（脚手架）只影响特定场景；
- **可逆性**：harness 随时回滚，模型回滚等于重做。

于是管控正在从权重层迁移到脚手架层——policy as prompt。代价也很清晰：

1. **透明度**：用户读使用条款时，看不到 prompt 里真正生效的边界；
2. **可复现性**：同一版本号的模型，行为随 harness 漂移，学术评测和自动化流水线都会被殃及；
3. **边界治理**：今天禁逆向，明天限什么，由谁决定、如何公示，目前没有标准答案。

体面的工程做法其实存在：变更日志、政策版本号、机器可读的 policy 声明。社区这次的不满，与其说指向“禁”本身，不如说指向“悄悄”二字。

## 给使用者的三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/09e306f0d576cdc8.png)

1. **把 usage policy 当依赖项读**。模型“能做”和“被允许做”是两件事；把关键限制写进自己的需求文档，别等流水线跑到一半才收到拒答。
2. **对 harness 变更做监控**。如果你的业务构建在某个 AI 产品的行为之上，准备一组固定的回归用例定期跑；重要版本做快照，并保留一个备选模型作为 fallback。在大模型行业，最便宜的"training"其实是改提示词——你的系统必须假设它会变。
3. **逆向本身是中性技术**。互操作、安全研究、游戏保存都依赖它，真正要管理的是用途与产出物。decomp 社区多年的自发规范（自备正版 dump、产物不商用）给出了一种答案：边界可以由社区伦理承载，而不必全靠平台一刀切。

发动机没变，变的是交规。看懂 harness 这一层，你才算真正看懂了 AI 产品的行为逻辑。
