过去两年，“AI 写代码”最出圈的演示项目，不是什么企业级系统，而是复刻游戏：一句提示词，几十秒后浏览器里跑出一个 Flappy Bird 或 2048。这个保留节目最近被按下了暂停键——据36氪等媒体报道，Claude Code 一次未做声张的更新，让 Opus 5.5 在被要求复刻知名游戏时选择拒绝或转向。写游戏的能力没有消失，被装上的是一道“政策刹车”。这道刹车怎么装的、为什么非装不可、对写代码的人意味着什么，值得拆开看看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/6dadd99375dee593.png)

## 一、“悄悄更新”到底更新了什么

- 先对齐背景：Claude Code 是 Anthropic 的命令行编程 Agent，模型负责读代码库、做计划、改文件、跑测试，人在旁边验收。它的线上“行为”由三层东西决定：底座模型权重、system prompt 与使用政策、外挂的安全过滤组件。
- 据报道，这次改动落在政策层：当用户要求复刻可识别的知名游戏（尤其是“原版美术 + 原版玩法”的组合）时，模型会拒绝 1:1 复刻，转而提议做一款“机制相近、表达原创”的替代方案。你让它“做一个会下落方块的游戏”，它大概率照做；你让它“1:1 还原某知名游戏，包括美术”，就会被拦下。
- 之所以叫“悄悄”，是因为这类改动通常不打发布会：改几行 system prompt、调一版分类器，线上行为就变了。社区往往是在对比前后行为差异后才发现的。LLM 产品的更新日志远比传统软件模糊，这也是“静默更新”每次都能引发讨论的根本原因。

## 二、AI 为什么擅长复刻游戏：不是创造力，是模板

先戳破一个幻觉：模型能 30 秒写出 Flappy Bird，不代表它“懂游戏设计”。

1. 训练语料里，Flappy Bird、2048、Pong、贪吃蛇是全互联网重复度最高的练手项目之一：海量 GitHub 仓库、教程、博客、面试题。模型做的是高概率的模式检索，近似“默写模板”——不是从第一性原理推演出一只鸟，而是默写了全互联网交过作业的那只鸟。
2. 游戏规则本身（玩法、机制、数值）在版权法里一般不受保护，这就是思想/表达二分法（idea–expression dichotomy）；受保护的是表达层：美术素材、角色形象、音效、代码文本、名称文案。所以“复刻”天然横在灰色地带——复刻机制大概率没事，复刻表达基本有事。
3. 历史早有先例：2048 本身就是 Threes 的机制变体；2014 年 Flappy Bird 爆红后，山寨品一度刷屏应用商店。AI 只是把这个“人类山寨产业链”的产能放大了几个数量级。

换句话说，复刻游戏的演示越好看，厂商暴露的版权敞口越大——这正是要踩刹车的原因。

## 三、“刹车”是怎么装上去的：三层结构

工程上，这类限制通常不是单一开关，而是三层叠加：

1. **政策层**：在 system prompt 与使用政策中写入规则——拒绝再现受版权保护的表达，主动引导转向“inspired-by”方案。最便宜、最快上线，也最容易被提示词绕过。
2. **过滤层**：在输入和输出两侧跑分类器，识别“clone XX 游戏”“用原版角色形象”这类请求特征，命中即拦截或改写。
3. **训练层**：用偏好数据训练模型，让它主动偏好“原创但玩法相近”的输出，让拒绝显得自然，而不是机械地吐一句模板话。

难点在边界判定：写一个“有下落方块的游戏”算不算复刻俄罗斯方块？给 Pong 换一层皮算不算？分类器必然有误伤——而临摹经典机制，恰恰是学游戏开发最正当的路径之一。另外别忘了关键一点：这层刹车装在“助手”上，不在“能力”上。同一句提示词丢给开源权重模型，照样能跑出一只像素鸟。所以它是产品策略，不是物理定律。

## 四、商业账本：demo 营销退潮，IP 风险上台面

从“炫技”到“刹车”，转折点的本质是生意变了。

- 2023–2024 年，“AI 复刻游戏”是免费的病毒营销：一条推文、一段 30 秒录屏，换千万级播放。那个阶段厂商缺的是注意力。
- 现在厂商缺的是企业客户的信任。头部厂商先后向商业客户承诺输出侵权赔偿（IP indemnity），而 Anthropic 自己也在训练数据版权相关诉讼的名单上。每一个“AI 一键复刻 Angry Birds”的爆款演示，都可能变成未来法务函里的截图证据。
- 一边是几百万播放的 demo，一边是按席位计费、客单价数万美元的企业合同，还可能附带赔偿责任条款——这道算术题不难算。

顺带一个有意思的对比：此前官方宣传里，让模型“玩”宝可梦曾是展示 Agent 能力的招牌项目；让模型“复刻”游戏却踩了线。边界不在“接不接触游戏”，而在“是否再现了受保护的表达”。

## 五、写给开发者：一个三问判断框架

政策还会继续变，但判断方法可以沉淀下来。遇到“我想让 AI 做个 XX 那样的游戏”这类需求，先过三问：

1. **问来源**：素材从哪来？要求模型凭空生成的代码与逻辑，风险远低于“把原版素材、角色、音乐搬过来”。
2. **问表达**：你复用的是机制还是表达？机制（重力跳跃、消除、Roguelike 循环）可以大胆借鉴；表达（美术、角色、音效、命名、剧情文本）必须原创或取得授权。
3. **问用途**：自己学习跑通，和上架商店商用，是完全不同的风险等级。前者被误伤了大不了换个说法重试，后者值得先做一遍清权。

实操层面，把“复刻”这个词替换成更精确的表达：“实现一个类 XX 机制的原创游戏，美术与命名自拟”——通过率和合规性都会好很多。

## 写在最后：三条冷思考

1. 把“复刻”升级为“机制拆解 + 原创表达”。学游戏开发，真正值钱的是拆解玩法循环的能力，不是还原一只像素鸟——后者模型早就替你会了，现在连模型自己都开始拒绝再做一遍。
2. 选模型时把“行为可预期性”列为评估项。能力跑分人人会看，但商用场景里，政策边界是否清晰、会不会某天静默变脸，同样是采购指标。
3. 对 Agent 依赖做“版本管理”。固定模型版本号、给关键输出留回归用例，把 LLM 当成一个会悄悄改行为的依赖库来治理——这不是玄学，是新的工程纪律。
