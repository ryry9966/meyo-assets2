最近微博上有个说法传播很广：“道士念咒语就是在调用AI”。乍听像个段子，细想却戳中了一个有意思的结构：当人类面对一个**无法看透内部机制、但威力巨大**的系统时，总会发展出一套格式固定、措辞精确、代代相传的“咒语”。道教科仪如此，今天的 Prompt 工程也如此。这篇文章不评价宗教，只从语言学、人类学和工程三个角度，拆解这个梗为什么“越想越像”，以及它在哪里又“确实不像”。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-11-01/2f6fa357d2d83ad6.png)

## 咒语的结构，像极了一次函数调用

- 传统科仪里的咒语有相当固定的骨架：开头“奉请/敕令”指明调用对象（相当于设定 system role），中间陈述所求事项（task），随后给出约束与警告条款（constraints），最后以“急急如律令”收尾——类似一个终止符加执行指令。
- 周边配件也一一对应：符箓像序列化的配置文件，法印像签名校验，沐浴焚香、设坛净坛像初始化运行环境；念诵前的示范动作和手诀，则有点像 few-shot——先把“标准姿势”演示给系统看。用今天的话说，这就是一次带鉴权和参数的 API 调用。
- 有个历史细节很妙：“急急如律令”原是汉代公文的标准结语，意为“按律令速办”。道士把官府文书的权威格式借进咒语，让“受理方”必须照章办事。这和今天不少人写 Prompt 时刻意模仿“官方文档腔”、开头就写“你是一位资深专家”，是同一种心理：**借格式，借权威**。
- 千年迭代下来，这些咒语格式高度稳定、可复用、参数可替换（姓名、生辰、所求之事就是变量槽位），正是工程上“模板 + 变量”的思想。

## 为什么面对黑箱，人类都会念口诀

- 人类学家马林诺夫斯基在特罗布里恩群岛有个经典观察：在风平浪静的潟湖捕鱼，岛民几乎不搞巫术；一到危险的远海，仪式与咒语就密集出现。结论很直白——**人对自己能掌控的技术不搞玄学，对失控风险高的环节才仪式化**。
- 大模型恰好是当代人的“远海”：输入一句话，吐出黑箱结果，没人能完全解释为什么某个写法灵、某个写法不灵。于是社区里出现了大量口口相传的“咒语”：“一步一步思考”“你是资深专家”“这对我非常重要”。它们像法本一样被抄录、转发，并靠“我用过，真灵”的个案互相印证。
- 语言学家奥斯汀提出过“施为句”（performative utterance）：“我宣布”“我愿意”这类话不是在描述世界，而是在**执行**。咒语是施为句的极端形态——相信措辞本身就是因果力量。Prompt 工程师其实也活在施为句的世界里：同一个模型，措辞差一点，行为差很多。
- 一个有趣的注脚：2023 年 DeepMind 的 OPRO 论文让模型自动搜索 Prompt，发现“深呼吸，一步一步来”这句颇具“玄学感”的话术，在 GSM8K 数学题集上确实提升了准确率。说明在黑箱面前，仪式性措辞有时真有效果——只是机制至今没完全说清。

## 相似归相似，三个本质差异

1. **执行器不同**：咒语预设的接收方有意志、全知、绝对服从；大模型是基于统计的下一词预测器，输出带随机性——temperature 一调，同一个 Prompt 每次结果都不一样。
2. **可审计性不同**：API 调用有日志、有版本号、能 A/B 测试、能复盘；“神明接口”没有 SLA，无法 benchmark。这也是为什么工程能力能持续累积，而咒语的“有效性”长期停留在个案见证层面。
3. **失败归因耐人寻味**：Prompt 失灵，工程师习惯先怪自己写得不好；仪式不灵，传统解释也常落在“心不诚”“德不够”上。两者都倾向于把锅甩给使用者而不是系统——这是黑箱系统的共同文化副产品，值得警惕。

需要说明：这里做的是**结构类比，不是对宗教仪式的评价**。人类学研究表明，仪式承担着同步群体、安放焦虑的社会功能，与 Prompt 的功能根本不在同一层面。类比只在“用自然语言操作一个黑箱”这一点上成立。

## 这个梗对写 Prompt 的三点的确有用

- **结构化优于堆砌**：咒语能传千年，靠的是格式稳定。写 Prompt 也一样，“角色—任务—约束—输出格式”四段式，比反复加“非常重要”“拜托了”有效得多。措辞上的仪式性加码，收益远低于结构化拆解。
- **模板要参数化**：像科仪里的姓名生辰一样，把可变部分抽成变量（领域、受众、字数、风格），一个模板服务一类任务。建议像维护代码一样维护 Prompt：有版本、有变更记录、有适用范围说明。
- **敬畏可以有，测试不能少**：对黑箱保持谨慎是对的，但验证一句话术“灵不灵”，要靠固定测试集、多轮对照和成功率统计，而不是“我用了一次特别顺”的幸存者叙事。

## 收尾：三条冷思考

1. **分清仪式感与有效性**：在焦虑高、不可控的场景里，人天然想加咒语。允许自己有点仪式感没问题，但工程决策请回到日志、复现和对照实验上。
2. **咒语思维当脚手架，别当终点**：固定格式帮你快速起步，真正的提升来自理解模型行为——多读官方文档和论文，比多抄十条“神级 Prompt”有用。
3. **对非技术领域的“咒语”保持理解**：婚礼誓言、开工仪式、运动员的固定动作，背后是同一套心理机制。能解释它，不必嘲笑它——这大概是一个工程师最大的体面。
