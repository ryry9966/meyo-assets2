## 背景

AGENTS.md 是近一年在 agent 生态里逐渐收敛的一个约定：在工作空间根目录放一个 Markdown 文件，内容是「AI 在这个仓库里干活时应遵守的说明」。README 写给人看，AGENTS.md 写给模型看。在 OpenClaw 里，agent 挂载工作空间、启动任务时会读取它，相当于每次会话自动注入一份项目上下文。

## 问题

没有这份文件时，我们的日常是这样的：

- 每个新会话都要重新回答「怎么构建、怎么跑测试、哪个目录别碰」；
- 团队成员各自往 system prompt 和自定义指令里贴规则，版本不一致，行为漂移；
- agent 上手就改 lockfile 和构建生成物；
- 多 agent 协作时，同一个任务在不同会话里走完全不同的路径。

这些不是模型能力问题，是上下文缺失问题。解法很朴素：把规则固化成文件。

## 做法

1. **根目录建 `AGENTS.md`，五段式结构**：项目一句话简介；命令速查（构建/测试/lint，精确到可直接复制执行）；目录约定（哪里放什么、哪里只读）；风格与提交规范要点；禁止清单（不要动 lockfile、不要跑全量测试、不要提交生成物）。
2. **子目录可覆盖根文件**：`packages/foo/AGENTS.md` 只写与根文件的差异，子目录优先。monorepo 场景特别需要。
3. **控制篇幅**。几百行以内，规则写成祈使句加可执行命令，少写散文——模型对命令的遵从率远高于描述性段落。
4. **防腐烂**。CI 里加一个冒烟 job，把 AGENTS.md 里的命令真的跑一遍；构建方式变更的 PR 必须同步改它，和改代码同等对待。
5. **与 MCP/插件协同**。工具选择偏好也写进去，比如「优先使用 MCP 提供的检索工具，不要用 shell 里的 curl 抓内网资源」。

## 踩坑点（实测）

- **写太长反而更糟。** 我们试过把整本编码规范塞进去，结果模型对关键规则（别动生成物）的遵从率明显下降。上下文是预算，重点要省着花。
- **命令过期是最贵的坑。** agent 会照着跑，一条失效命令能浪费一整轮会话。命令先进 CI 校验，再写进文档。
- **规则冲突要显式仲裁。** 根目录写 pnpm、子目录写 npm，模型会随机站队。明确写上「子目录优先于根目录」。
- **别写敏感信息。** 密钥、内网拓扑会随文件进入上下文和日志。
- **它是提示，不是权限。** AGENTS.md 本质是引导性注入，真正要硬拦的操作交给 OpenClaw 的权限和沙箱配置兜底。

## 可复用建议

- **冷启动测试**：新开一个干净会话，让 agent 只凭 AGENTS.md 完成一个小任务（比如补一个单测并跑通）。跑不通的地方，就是要改的行。
- **每条规则写成「场景 + 动作」**：「修改 public API 后，运行 `pnpm test:types`」，而不是「注意类型安全」这类空话。
- **像代码一样 review 它**：走 PR、留变更记录，谁改构建方式谁同步改文档。

## 总结

AGENTS.md 的价值不在文件本身，而在于把团队的隐性默契显式化、版本化。成本很低，一两个小时能写出第一版，之后随踩坑持续迭代。建议每个 OpenClaw 工作空间都从最小可用版起步——宁可短而准，不要长而全。
