最近 36kr 报道的一组数据在技术圈刷了屏：一份企业调研显示，约 79% 的受访企业 GPU 利用率不足一半。还记得两年前"一卡难求"、高端卡加价都抢不到的行情吗？如今一边是动辄百万级的整机，一边是大面积空转吃灰。这事听着拧巴，但只要你在一线待过，就会发现它几乎是必然结果——问题不在卡，在系统。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/3b4aec619569b624.png)

## 先搞清楚：报告里的"利用率"到底量了什么

聊浪费之前，得先把指标掰清楚，因为"利用率"至少有三层含义：

1. **nvidia-smi 的 GPU Util**：采样窗口内有 kernel 在执行的时间占比。哪怕 100ms 里只跑了 1ms 的 kernel，也可能显示高利用率——它只能说明"卡醒着"，不能说明"卡在干活"。
2. **SM Efficiency**：SM 上有 warp 驻留并执行的时间占比，更接近真实忙碌程度。
3. **MFU（Model FLOPs Utilization）**：实际有效算力 / 理论峰值。当前主流大模型训练里，MFU 做到 35%~50% 就算优秀水平。

所以 79% 这个数字要拆开看：一部分是"真闲"（压根没任务可跑），一部分是"假忙"（在跑但效率低）。两者都是浪费，但病根和解法完全不同。

## 卡为什么空转：四个最常见的病根

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/fe53feba6bb5f880.png)

1. **潮汐负载**：开发调试集中在白天，晚上和周末任务稀少；推理流量随业务昼夜波动，峰谷差常见数倍。按峰值采购，谷值就是成片闲置——这是买卡的"先天矛盾"。
2. **部门私有制**：卡按项目划走，A 组闲着、B 组排队，没有统一调度池。这是组织问题而非技术问题，却是企业里最普遍的一种浪费。
3. **推理天生"吃不满"**：大模型逐 token 生成是访存密集型操作，算力大量时间在等显存带宽。没有 continuous batching、PagedAttention 这类优化，一张卡跑两三个请求就"看起来忙、实际闲"。
4. **软件栈短板**：数据预处理跟不上导致 GPU 等 CPU/IO、batch size 偏小、没开混合精度、多卡并行的流水线气泡——每项扣一点，加起来就是腰斩。

举个直观的例子：8 卡机器训练 7B 模型，如果 dataloader 每步阻塞 200ms、计算只花 300ms，光等待就吃掉 40% 的时间，卡再贵也白搭。

## 一个历史注脚：GPU 正在重演 CPU 的老路

- 二十年前，企业服务器 CPU 平均利用率同样长期低于 20%；后来虚拟化加云计算把资源池化、按需分配，才把利用率真正抬了上来。
- GPU 正沿着同一条曲线走：裸机分卡 → 容器化调度 → 硬件切分（MIG、vGPU）→ 按需付费的 GPU 云和 serverless 推理。
- 今天的低利用率，某种程度上是基础设施"代际差"的正常现象——不是卡不行，是配套还没跟上。抢卡潮的余温还没散，用卡的方法论已经换了一代。

## 怎么把算力"挤"出来：四类主流做法

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/47f9e63304123155.png)

1. **池化与统一调度**：把散在各组的卡收进资源池，用 Kubernetes 加调度器做排队、抢占、配额；白天保开发、夜间跑训练批任务，让卡分时复用。
2. **切分复用**：小模型和小实验用 MIG、vGPU 切片，别让一个 notebook 独占一整张卡。
3. **推理侧优化**：vLLM 这类推理引擎靠 continuous batching + PagedAttention，同等硬件吞吐常有数倍提升；再叠加量化（INT8/FP8）、投机解码，单 token 成本还能继续压。
4. **计量与考核**：给每个团队出"算力账单"，考核看 MFU 而不是 nvidia-smi 的假利用率。看不见的成本无法管理，账单一亮，浪费自己会收敛。

采购上还有笔隐藏账：TCO 不只是卡价，还有电费、机房、运维和贬值。利用率只有四成的自建集群，折算到有效算力上的单价，很可能比按需租云还贵。

## 写在最后：三条冷思考

1. **先有负载，再谈囤卡**：算力是耗材，不是买回来挂着当摆设的固定资产。采购前先画出现有和可预期的工作负载曲线，"基线自建 + 峰值租云"通常是更稳的组合。
2. **用对指标再做决策**：先把 MFU、goodput 这些指标测准，再决定是买卡、调优还是改造调度——别拿一张 nvidia-smi 截图拍板百万级的板子。
3. **低利用率不全是坏事**：它标志着行业从"抢卡焦虑"进入"用卡精打细算"的阶段。接下来几年，算力调度、推理优化、GPU 虚拟化会是确定性很强的方向——对工程师来说，问题清单本身就是机会清单。
