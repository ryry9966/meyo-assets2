最近技术圈刷屏的一条消息：开源社区放出了新方案，一行官方驱动代码都不用改，就把两张 RTX 4090 跑大模型推理的吞吐拉到接近翻倍。听起来有点玄——GPU 的算力怎么会被“藏”起来？不开驱动又是怎么“开锁”的？这篇文章把来龙去脉、背后的原理，以及你该不该跟进，一次讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/cdb517ce26d78bb7.png)

## 一、算力不是没有，是被“软禁”了

- 英伟达的商业模式是典型的“一芯多吃”：同一代核心，切出 GeForce（消费级）、RTX Pro（专业卡）、数据中心卡（A100/H100）等多个档位。很多能力出厂时就做进了芯片，只是靠驱动层的软件开关划分档次。
- 历史上的“软禁”名单很长：
  1. **FP64 双精度**：数据中心卡全速运行，GeForce 被砍到 1/32 甚至 1/64；
  2. **NVENC 并发路数**：消费卡限制同时开几路编码，社区项目 nvidia-patch 靠改驱动解锁，火了多年；
  3. **vGPU 虚拟化**：Maxwell、Pascal 时代的消费卡硬件上支持 GPU 直通，同样被驱动关掉，后来也被社区打开过；
  4. **NVLink 卡间互联**：RTX 3090 还留了一条，到 4090 直接物理移除。
- 这次的主角叫 **P2P（Peer-to-Peer DMA）**：允许一张 GPU 直接读写另一张 GPU 的显存，不经过 CPU 和系统内存中转。数据中心卡默认开放，GeForce 从 Kepler 一代起就在驱动里被禁用——调用 `cudaDeviceEnablePeerAccess()`，消费卡直接返回错误，官方支持文档里也写得明明白白。
- 市场细分本身是正当的商业行为，档位差价也是研发投入的来源；但“硬件能力”与“许可开关”的边界，全靠驱动里一行 if 判断守着。这次被开源社区翻出来的，正是这样一道软闸门。

## 二、钥匙在哪：P2P 是大模型推理的咽喉

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/92a7572364ca66bb.png)

- 背景：24 GB 显存装不下 70B 模型（FP16 权重约 140 GB），想把大模型跑在多张消费卡上，标准做法是**张量并行**（Tensor Parallelism）：把每层矩阵切开分给多张卡同时算，每步计算后做 all-reduce 通信汇总。也就是说，每生成一个 token，卡与卡之间都要来回搬数据好几次。
- 没有 P2P 时，这些通信走回退路径：GPU A → 系统内存 → GPU B，CPU 内存当中转站，还伴随频繁同步等待。对程序员来说，世界上最远的距离，是你的显存到我的显存之间还隔着一条系统内存。
- 有了 P2P：数据走 PCIe 点对点直传。PCIe 4.0 x16 单向理论带宽约 32 GB/s，实测对等拷贝能跑到 20 GB/s 上下，比回退路径高出不止一个量级。
- 通信开销在多卡推理里占比很大，堵点一通，端到端吞吐自然翻倍。注意：芯片峰值算力一个 FLOPS 都没变，变的只是卡间“高速公路”从乡道换成了直通高架。

## 三、不改官方驱动，怎么开锁的？

- **老办法**：2023 年 tinygrad 团队（George Hotz）直接修改内核模块 nvidia.ko，把驱动里“检测到 GeForce 就拒绝 P2P”的分支改掉。能用，但代价明显：动了带数字签名的驱动文件，Secure Boot 环境会报警，驱动一升级补丁就作废，等于每次更新都重新动手术。
- **新思路**：完全不碰驱动二进制。CUDA 提供虚拟内存管理 API（cuMemCreate / cuMemMap / cuMemSetAccess），开源方案在用户态做加载时钩子（LD_PRELOAD 一类），大体思路是利用这套 API 把对端显存映射进本进程地址空间，绕过驱动里按产品品牌做白名单检查的逻辑。
- 一句话概括原理：**限制是软件白名单，不是硬件熔断**。DMA 通路在硬件层面本来就是通的，驱动只是在门口查证件；新方案没有伪造证件，而是换了一条合规的门进去。
- 附带的好处很实际：官方驱动文件完好、签名校验照常通过，驱动例行更新后大概率还能继续工作，可维护性比改内核模块高一档——这也是它能上热搜的根本原因。

## 四、条件、边界与风险：天上不掉馅饼

- **硬件拓扑是第一道门槛**：两张卡最好挂在同一个 CPU 的 PCIe Root Complex 或同一颗 PCIe switch 下（比如主板 x8/x8 分槽），IOMMU/ACS 设置得当。第二张卡插在芯片组出来的通道上，红利会大打折扣甚至吃不到。
- **单卡用户与此无关**：这不是给芯片提频，只是拆掉卡间通信的墙。你只有一张 4090，吞吐不会变。
- **带宽天花板仍是 PCIe**：几十 GB/s 的直传速度，远比不了数据中心卡上 NVLink/NVSwitch 的数百 GB/s。卡数一多、模型一大，通信照样是主要瓶颈，这套解锁替代不了真正的互联硬件。
- **稳定性与合规**：绕过厂商限制处于 EULA 灰色地带，官方不背书也不支持；驱动大版本更新可能一夜失效，社区要跟着玩猫鼠游戏；消费卡没有 ECC 显存，长跑训练的出错率得自己兜底。自己折腾很香，进生产环境要三思。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/c3cffa30a166bd78.png)

1. **买卡先问场景**：单卡跑 7B~14B 推理，一张 4090 级别的卡足够；真要双卡张量并行，别只看算力峰值，把“卡间带宽、PCIe 拓扑、有没有 NVLink”放在第一优先级——3090 双卡（自带 NVLink）有时反而比 4090 双卡省心；预算灵活的话，按小时租云上的卡常常更划算。
2. **灰色工具不上生产**：拿来跑 hobby 项目没问题，但请保留原版驱动配置和回退脚本，驱动升级前先在测试机过一遍，别让深夜的自动化流水线替你踩雷。
3. **学会读“软件定义的性能表”**：买高端硬件，本质上也是买一份许可。以后横向比价时，把“被限制的特性、社区解锁的可能性”算进性价比公式，你对很多产品线的真实价值会有新的判断。

硬件给什么，驱动说了算；而驱动说了什么，开源社区正在逐行翻译。这场猫鼠游戏大概率还会继续——理解规则的人，永远是先吃到红利的那批。
