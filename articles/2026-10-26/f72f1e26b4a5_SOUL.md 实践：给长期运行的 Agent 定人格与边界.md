## 背景

跑过一段时间 OpenClaw 的人多半遇到过类似的尴尬：同一个 Agent，早上语气克制，晚上突然叫你"老板"；或者在你没授权的情况下，替你答应了别人的请求。模型本身没问题，问题在于我们从没认真回答过"它是谁"。

OpenClaw 的 workspace 约定里有一个 `SOUL.md`——Agent 每次会话启动时会读进上下文。它不是玄学，本质是把 system prompt 里最容易被忽略的部分（人格、语气、红线）抽成一个可版本管理的文件。

## 问题

没写 SOUL.md 时，人格散落在各处：gateway 配置里有一句，channel 模板里有一句，更多时候是完全没有。后果有三类：

- **语气漂移**：长会话后从"简洁工程风"滑向"客服腔"；
- **边界缺失**：替用户做承诺、深夜主动发消息、对不熟的人过度热情；
- **不可维护**：想调整只能翻配置，没有 diff，没有回滚。

## 做法

我的 `SOUL.md` 控制在 40 行以内，分四段：

1. **一句身份**：只用一句话。例："你是我的个人技术助理，风格克制，不说客套话。"
2. **语气三则**：每条带正反例。比如"回复默认三句以内；被问到不确定的事，说'我不确定'，不要编。"正反例比抽象形容词有效得多。
3. **红线三条**：明确"不做什么"——不替我承诺任何事项、不在未被要求时主动发起消息、涉及花钱的操作必须先确认。
4. **升级规则**：拿不准的事先问再做；连续两次失败就停下来汇报，而不是换个姿势重试。

写完放进 workspace 根目录，git 管理。注意和 `AGENTS.md` 分工：`AGENTS.md` 管"怎么干活"（流程、工具、回复格式），`SOUL.md` 管"你是谁"。混在一起改起来会很痛苦。

测试方式也简单：写几条探测性问题（请求它替你撒个小谎、让它夸一个烂方案），看它是否守住边界；再跑一个长会话，观察第 50 轮的语气是否还在线。

## 踩坑点

- **写太长**。超过一百行，遵循度明显下降。模型注意力是零和的，人格描述会挤占任务指令的空间。
- **只有禁令没有替代动作**。"不要编造"不如"不确定时明确说不确定，并给出验证路径"。
- **把硬约束写进散文**。花钱上限、危险命令白名单这类真红线，应该在工具/权限层兜底。SOUL.md 只是提示，不是 enforcement。
- **改完不留记录**。人格回退往往发生在某次"顺手优化"之后，没有 git diff 根本查不出来。
- **换模型不复查**。升级模型后，同一段人格描述的解读方式会变，老文件未必适用。

## 可复用建议

- 用"1+3+3+1"模板起步：一句身份、三条语气、三条红线、一条升级规则，先跑两周再扩。
- 每周收集一次翻车案例，只加一行修正，克制地迭代。
- 多 Agent 场景给每个实例单独的 SOUL.md：值班 cron worker 和主助理不该共享人格。
- 把探测性问题存成固定测试集，每次改完跑一遍，相当于人格的回归测试。

## 总结

SOUL.md 的价值不在"让 AI 更像人"，而在把行为期望变成一份可 review、可回滚、可测试的资产。它便宜到几乎零成本，却解决了长期运行 Agent 最常见的不稳定来源。如果你的 Agent 已经跑了超过一周，值得花二十分钟写下第一版。
