## 背景

OpenClaw 的 workspace 里预留了几份"接口文件"：`AGENTS.md` 管操作规范，`SOUL.md` 管人格设定，`USER.md` 管"你是谁"。前两个大家多少会改，`USER.md` 却常常只留一个名字，甚至空着。

结果是 Agent 对项目了如指掌，对你这个使用者一无所知。

## 问题

没有用户画像时，这几个成本每天都在付：

1. **重复交代**。新会话第一件事永远是自我介绍：用 pnpm 不用 npm、回复说中文、commit 不加 emoji、先给结论再给推理。这些话散落在各个会话里，从未沉淀。
2. **行为漂移**。同一台机器，昨天 Agent 风格简洁，今天又啰嗦起来——因为它每次都在猜。
3. **上下文浪费**。为了让它理解背景，先铺垫十几轮对话，token 花在寒暄上。

## 做法

**第一步：把文件写满，但控制规模。** 建议 40 行以内，固定四个区块：

```markdown
# USER.md

## 环境
- macOS + zsh，编辑器 VS Code
- Node 项目统一 pnpm，Python 用 uv
- 默认中文交流，代码注释可英文

## 偏好
- 先结论、后推理，不要寒暄
- commit 遵循 Conventional Commits，不加 emoji
- 改代码前先报改动范围，不做没说好的大改

## 禁止
- 未经确认不执行 push / 删除类操作
- 不主动升级依赖大版本

## 当前上下文（2025-06）
- 主线：某个 MCP 工具的插件封装
- 在研究：MCP resource 订阅机制
```

**第二步：确认加载路径。** 放在 workspace 根目录，会话启动即生效。如果你的其他 Agent 客户端走 MCP，可以把它注册成一个 resource，多处共享同一份事实源。

**第三步：当配置文件维护。** 进 git，环境变了、项目换了就更新，每月扫一眼，删掉过期条目。

## 踩坑点

1. **写成小作文**。两百行的画像里，真正影响行为的指令会被稀释，还烧 token。把它当成有预算的配置：每加一行，问一句"值一份持久上下文占用吗"。
2. **信息过期**。上季度的项目描述会让 Agent 基于错误前提干活。"当前上下文"区块务必带日期、勤修剪。
3. **优先级打架**。USER.md 说用 npm，项目级 AGENTS.md 说用 pnpm。提前定规则：项目级覆盖用户级，并在 USER.md 里写明这一点。
4. **敏感信息**。这份文件会被送进模型 API，别放密钥、真实住址、公司内部项目代号。
5. **偏好太虚**。"代码质量要高"无法执行；"注释只解释 why，不复述 what"才可判定。

## 可复用建议

- 固定标题结构，人和脚本都好解析，也方便 diff
- 分层清晰：USER.md 写"你是谁"，AGENTS.md 写"项目要什么"，不要互相塞
- 每条偏好写成 Agent 能照做、你能验收的指令
- 可以加个小脚本：文件超过 N 行，会话开始时提醒精简

## 总结

USER.md 的投入是一个几十行的文件，回报是每个新会话都免掉重复的自我介绍，Agent 的风格和假设也稳定下来。把它和 dotfiles 一样当成开发环境的一部分来维护——这是我知道的成本最低、杠杆最高的 Agent 调优手段之一。
