## 背景

OpenClaw 这类本地 Agent 框架的核心能力是"能动手"：跑 shell、读写文件、挂插件和 MCP 工具。但每个刚接入的人几乎都会问同一句话：它会不会把我的 home 目录删了？这个担心合理——模型幻觉、路径理解偏差、群聊消息里的 prompt 注入，任何一条都可能让一条 `rm -rf` 落到不该落的地方。OpenClaw 的回答不是"模型很聪明"，而是**假设模型一定会犯错，用架构兜底**。

## 问题

裸奔式 Agent 的典型事故链是：模型输出命令 → 直接 exec → 相对路径或软链接把目标带偏 → 递归删除。叠加 OpenClaw 常驻消息通道的特性（群里一句话就能触发任务），出错窗口远大于人工操作。所以安全模型必须同时回答三件事：**删不到、批不了、能回滚**。

## 做法：三层防线

**1. 边界：workspace + 沙箱。** 每个 Agent 绑定独立 workspace，文件工具以它为根。开 Docker 沙箱后，Agent 进程跑在容器里，宿主数据默认不在视野内；即使退回宿主模式，路径也会先做规范化（realpath），越出 workspace 的绝对路径、`../` 逃逸、符号链接跳板都会被拒。

**2. 收敛：gateway + 审批。** exec 类工具不直接落 shell，而是经 gateway 按白名单下发；命中高危模式（递归删除、覆盖式写入）时走审批门，需人工确认。插件和 MCP 工具注册进网关后，同样受这套最小授权约束，默认不给高危权限。

**3. 可恢复：快照。** workspace 支持操作前快照，破坏性操作即使误判也能回到上一状态。前两层是概率防御，这一层是兜底。

示例配置（示意，字段以所用版本文档为准）：

```json5
agents: {
  defaults: {
    workspace: "~/openclaw-workspace",
    sandbox: { mode: "non-main" },
  },
}
```

核心原则一句话：**把 workspace 当成 Agent 的全部世界，有价值的数据放在这个世界之外。**

## 踩坑点

- **workspace 设成 `~` 或 `/`**：边界形同虚设，等于没沙箱。
- **Docker 挂载贪多**：图省事把整个 home 挂进容器，沙箱白开。只挂必要子目录，参考资料用只读挂载。
- **workspace 里放软链接**：指向外部的 symlink 是最顺手的逃逸通道，别把链接当"快捷方式"塞进工作区。
- **审批疲劳**：什么都点确认，人就会习惯性全通过。把高频安全操作放白名单，把真正危险的留在审批里，这扇门才有效。
- **调试期放行忘了收**：临时开过的权限要记录，定期回收。

## 可复用建议

1. 新 Agent 一律从空目录起步，先跑通再放数据。
2. 上线前做破坏性演练：在测试 workspace 里让 Agent 执行删除，验证边界拦截与快照回滚真的生效。
3. 保留 exec 审计日志，事后能复盘"它当时想干什么"。
4. 权限配置进版本管理，改动可追溯。

## 总结

Agent 不误删文件，靠的不是模型自觉，而是三层架构：沙箱让它**删不到**，网关审批让它**批不了**，快照让它**错了也能回**。三层各挡一类风险，缺一不可。与其祈祷模型不出错，不如假设它一定会出错，然后把爆炸半径钉死在一个空目录里。
