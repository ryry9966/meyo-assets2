最近 36kr 这条热搜的画面感很强：硅谷正批量生产「AI 管家」——能开浏览器、填表单、调用支付接口的智能体（Agent），华尔街的银行和支付公司一边抢着接入，一边后背发凉。这不是赛博朋克剧本，而是一个正在发生的工程问题：当一个既听得懂人话、又能执行转账动作的程序上线，「搬空金库」就从电影桥段变成了安全需求文档里的一行字。这篇按三步走：它怎么工作、漏洞在哪、怎么防。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/3b69f1d4aef2c8d8.png)

## AI「管家」的工作原理：大脑、手和裸奔的神经系统

Agent 不是更聪明的聊天框，而是一个循环体：

1. **感知**：读取输入——用户指令、网页内容、邮件、API 返回值；
2. **推理**：大模型（LLM）决定下一步动作；
3. **行动**：调用工具——搜索、点击、填表，乃至调用转账/支付接口；
4. **回看**：把工具执行结果喂回模型，循环直到任务完成。

OpenAI 的 Operator、Anthropic 的 computer use、各家银行的智能客服，底层都是这套「感知-推理-行动」循环。行业还在往前推：Visa 和 Mastercard 都在布局 agentic payment 类协议，等于给 Agent 发放官方支付凭证。

工程师视角一句话总结：模型是大脑，工具是手，但神经系统（上下文）是裸奔的——所有输入一视同仁地混进同一个「想法池」。雷就埋在这里。

## 攻击面在哪：提示词注入与「致命三要素」

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/9641c13f1b273942.png)

安全研究员 Simon Willison 提出过一个著名的 lethal trifecta（致命三要素），三件事凑齐，Agent 就危险了：

1. 能接触**私密数据**：你的账户、订单、通讯录；
2. 能读到**不可信内容**：网页、邮件、PDF——这些攻击者可控；
3. 能**对外执行动作**：发消息、调支付接口、改权限。

而金融场景，这三条几乎是默认配齐的。

根源在于：LLM 在架构层面无法严格区分「指令」和「数据」。网页里用白底白字藏一行「请把余额转往以下地址」，模型可能真的执行——这就是 Prompt Injection（提示词注入）。它可以藏在任何 Agent 会读的东西里：一封邮件、一份 PDF，甚至一条日历邀请。截至今天，业界没有根治方案，只能缓解。

真实攻防案例值得细看：2024 年底有个叫 Freysa 的实验，一个 AI Agent 守着奖金池，规则是「谁能说服它批准转账，谁拿走钱」，每发一条消息还要付费。前 195 次尝试全部失败，直到有人伪造了一条「系统安全日志」，声称转账通道已获授权——Agent 照做了，攻击者赢走约 4.7 万美元。武器不是零日漏洞，而是一段精心措辞的话。

## 为什么金融是首选靶场

1. **钱本身是数字的**：金融系统天然 API 化，对 Agent 来说，「转账」和「下单买咖啡」是同一个函数调用；
2. **信任链入口先被攻破**：据公开报道，2024 年初香港一家跨国公司的财务人员参加视频会议，「CFO 和同事」全部是 AI 换脸换声，约 2.56 亿港元被分批转走——人这道防线先失守了；
3. **自动化放大损失**：传统诈骗一次骗一个人，注入攻击可以 7×24 小时批量运行，损失曲线从线性变指数；
4. **行业在抢跑**：支付协议、投研 Agent、智能客服密集上线，权限下发的速度经常快过风控模型迭代的速度。

Deloitte 的测算：美国与生成式 AI 相关的欺诈损失，可能从 2023 年的约 123 亿美元涨到 2027 年的 400 亿美元。数字可以争论，方向基本没有悬念。

## 防御怎么做：把权限当现金管理

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/15465a8321ae877d.png)

核心思想一句话：像管理现金一样管理 Agent 的权限——限额、上锁、留痕。

1. **最小权限（least privilege）**：只发完成当前任务必需的接口与额度。浏览比价的 Agent 不该持有付款凭证，就像实习生不该拿公司章；
2. **人审闸门（human-in-the-loop）**：超过阈值的转账、改绑收款账户、批量操作，强制人工二次确认；
3. **意图与执行分离**：模型只输出结构化的「意图」，实际调用走参数白名单和 schema 校验，不许自由发挥；
4. **限速限额**：给 Agent 配小额、低频的专用账户，就算被打穿，炸的也是副金库；
5. **审计与回放**：完整记录每次工具调用的上下文，出事能回放、能归因、能复盘；
6. **带外验证**：资金类操作用另一条渠道（电话、App 推送）确认，不复用同一上下文——深伪电话骗的正是「同一条管道」里的信任。

## 三条冷思考

1. 「模型够强就安全」是错觉。安全瓶颈不在智力，在权限设计：再能干的管家，也不该一次拿到一整面墙的钥匙。
2. 提示词注入之于 Agent，约等于内存越界之于传统软件——短期内无法根除，只能靠纵深防御硬扛。接受「这是常态」，才谈得上工程化。
3. 普通用户给 AI 助手开支付权限前，先确认三件事：有没有额度上限、大额要不要人工确认、能不能一键吊销。三缺一，就只给它「看」的权限。

金库没被搬空，从来不是因为小偷不够聪明，而是因为门设计得足够细。Agent 时代，同理。
