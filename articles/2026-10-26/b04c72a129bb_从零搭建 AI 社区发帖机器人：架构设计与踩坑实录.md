## 背景

社区里有几类高度重复的劳动：精华问答周报、新版本发布通知、未解决问题整理。以前全靠人肉，实际问题就三个：容易忘、发布时间不稳定、格式越写越漂。于是花了两周做一个发帖机器人，核心思路是用 OpenClaw 的 Agent + MCP 工具链搭一条「采集 → 起草 → 校验 → 发布」的流水线，人只保留最后一道审核。本文记录架构和一些真实的坑。

## 目标与约束

动手前先划边界，避免做成全自动刷屏机：

- 内容必须可溯源，禁止模型凭空生成链接和数据
- 每日发帖数量有硬上限
- 支持 dry-run 和一键撤回
- 全链路落库，出问题能回放

## 架构

```
cron 调度（任务幂等）
   │
   ▼
采集层（MCP tools：仓库 release / 论坛 API / issue 统计）
   │  产出结构化事实，每条带 source
   ▼
Agent 起草（只读采集层喂入的事实，输出 JSON）
   │
   ▼
校验门（纯代码：链接可达 / hash 去重 / 字数 / 敏感词）
   │
   ▼
发布器（写状态库 → 调社区 API → 回写 post id）
```

状态存储一张 SQLite 表就够：内容 hash、状态、重试次数、来源引用、社区端 post id。

## 实施步骤

1. 先把发布 API 封装成 MCP tool，用 curl 验证权限和字段，再接 Agent
2. 定义输出 JSON schema，正文模板渲染放在代码里，不让模型碰格式
3. 校验门逐条实现：链接 HEAD 可达性、hash 去重、规则拦截
4. dry-run 模式跑一周，只落库不发布，人工抽查产出质量
5. 灰度发到测试版块，稳定一周后切正式版块

## 踩坑实录

**1. 幻觉链接。** 第一版让模型「引用 changelog」，它编出一个格式完美、内容合理的假 URL。修复：链接和数据只能来自采集层传入的白名单字段。Agent 的职责是组织语言，不是提供事实。

**2. 重试导致重复发帖。** 发布成功但回调超时，调度器重试，同帖发了两遍。修复：发布前按内容 hash 查库，请求携带幂等键，服务端收到重复键直接返回已有 post id。

**3. 语气漂移。** 跑三周后帖子越来越像营销号，感叹号翻倍。修复：把两篇定稿范文固化进系统提示词；每次改提示词都跑一个 20 条样本的回归评估，肉眼对比再上线。

**4. 上下文爆炸。** 一次把全量 issue 喂给 Agent，直接超时。修复：裁剪是采集层的事，只喂 top N 加统计摘要。模型上下文是贵重资源，不是垃圾场。

**5. 密钥进日志。** 早期调试把带 token 的请求头打进了日志。修复：secret 全部走环境变量注入 MCP tool，日志统一脱敏。这条建议今天就该做。

**6. 速率限制。** 补发积压任务时撞上 429。修复：指数退避 + 每日配额硬上限，宁可不发，不硬撞。

## 可复用建议

- 能用确定性代码解决的事，不要交给模型：模板、去重、限流、重试
- Agent 只负责「写」，「发」永远是普通代码
- 发布器必须幂等，状态库是整个系统唯一的真相来源
- 每篇帖子记录 source 字段，事后可追溯、可道歉
- 先 dry-run 一周，比事后删帖便宜得多

## 总结

这个项目代码量不大，真正的工作量在设计边界：哪些事模型做，哪些事代码做，哪些事人做。把事实来源和发布动作锁死在代码层，把表达能力留给 Agent，机器人才能稳定长期跑下去。配置模板整理后会放到社区仓库，欢迎参考和拍砖。
