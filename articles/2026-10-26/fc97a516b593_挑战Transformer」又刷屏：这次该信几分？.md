这两天 AI 圈又吵起来了：一篇新研究被冠上“堪比 Transformer 奠基论文”的形容，评论区迅速分裂成“封神派”和“打假派”。有意思的是，这两派吵的根本不是同一件事——一边在吵技术，一边在吵叙事。其实这种争论早就是 AI 社区的保留节目，隔几个月来一轮。这篇把它拆开看：新论文在机制上动了哪一刀，大家到底在争什么，以及普通人怎么判断一篇论文值不值得当真。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/b295e18417d6bb00.png)

## 一、“堪比 Transformer”是个多高的门槛

- 2017 年 Google 八人组的《Attention Is All You Need》发表时，只是一篇机器翻译论文。它真正成为“奠基”，靠三件事叠加：
  1. **Self-attention** 让序列里任意两个 token 直接交互，长距离依赖不再需要逐层传递；
  2. 训练**完全并行**，甩掉了 RNN 顺序执行的枷锁，GPU 算力第一次能“喂满”；
  3. 结构足够**通用**，同一套骨架后来长出 GPT、BERT、ViT，横扫文本、代码、图像。
- 再加上 2020 年 OpenAI 的 scaling law 给出“加算力就能可预测地变强”的曲线，产业界才敢把千亿级赌注押上去。
- 所以“堪比”隐含的要求是：改写底层交互方式 + 可规模化 + 跨模态通用。三重门槛，绝大多数论文过不了第一重。

## 二、新论文动了哪一刀：把“翻笔记”换成“记小抄”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/9141fb9d056a47ac.png)

- 从争论焦点看，这类刷屏论文大多属于同一条技术路线：**线性架构 / 状态空间模型（SSM）**，代表作是 2023 年底的 Mamba，之后还有把“边推理边记笔记”推到极致的 Titans。它们瞄准的是 Transformer 的老毛病——attention 计算量随序列长度**平方增长（O(n²)）**，上下文拉到几十万 token 时，训练和推理成本都很惨烈。
- 挑战者的思路：不再让每个 token 和全部历史两两配对，而是维护一个**固定大小的记忆状态**，新 token 只对这个状态做更新，复杂度降到近似线性 O(n)。
- 打个比方：Transformer 像开卷考试，所有原文摊在桌上随翻随查，准确但桌子越坐越挤；线性架构像边看边把重点压缩成一页小抄，翻得飞快，但细节可能在压缩时丢掉。
- 代价就在这：固定状态有容量上限，在需要精确回忆长上下文细节的任务上（“大海捞针”式检索、MQAR 关联回忆测试）容易露馅。
- 所以目前最务实的方案是**混合架构**：若干层线性记忆 + 少量 attention 层，两头互补。Mamba-2、Jamba 这类系统已经在这么做了。

## 三、吵的其实不是论文，是四件事

1. **Benchmark 立场**：新架构的论文多选长序列、效率类任务，数字漂亮；批评者拿检索、推理类基准反击。双方挑的题不一样，结论自然对不上。
2. **规模缺口**：多数新架构实验停在亿级到几十亿参数、千亿 token 量级；而 Transformer 的护城河是在千亿参数、数万亿 token 上被反复验证过的。小规模结论外推到大规模，历史上翻过车。
3. **生态成本**：FlashAttention、vLLM、各种并行训练框架——整个工具链围着 attention 打磨了七八年。新架构得自写高性能 kernel（Mamba 的 selective scan kernel 本身就是卖点），复现门槛高，“论文里的数字”和“你自己能跑出来的数字”之间常有距离。
4. **叙事放大**：“堪比 Transformer”是转述者的修辞，不是论文原话。作者一般只声称：在 X 任务上，以 Y 倍效率达到 Z 性能。热度每放大一层，claim 就被多镀一层金。

## 四、之前那些“挑战者”后来怎么样了

- **LSTM（1997）**：统治序列建模近二十年，2017 年被 attention 取代——但“循环压缩记忆”的思想被 SSM 原样继承。
- **Mamba（2023.12）**：发布即爆红，社区几周内涌现大量复现；如今更多以 hybrid 形式进入生产模型，而非独立取代。
- **RWKV**：把 attention 改写成 RNN 形式的开源常青树，在端侧小模型场景有真实用户。
- **KAN（2024）**：用可学习激活函数替换“线性层 + 固定激活”，可解释性惊艳，但训练计算效率被广泛质疑。
- 规律很清晰：没有谁真正“杀死”了 Transformer，但每个挑战者都变成了工具箱里的新零件。架构演进的主旋律是**融合**，不是改朝换代。

## 五、给论文“验货”的四个过滤器

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/1bfa885bdab48c60.png)

下次再看到“颠覆 XX”的论文，可以过一遍这四道闸门：

1. **痛点闸门**：它解决的问题（长上下文成本、推理延迟）是行业的真实瓶颈，还是只在作者自建的任务里有意义？
2. **证据闸门**：有没有横跨两三个数量级的 scaling 实验？有没有第三方独立复现？对比双方的数据配比是否公平？
3. **基线闸门**：被比较的 Transformer baseline 调到位了吗？补上最新 kernel、充分调参再比一次，不少结论会翻转。
4. **时间闸门**：Transformer 从发表到确立统治地位用了三到五年。一篇论文的真实影响，看六到十二个月后的引用与落地，比看本周热搜靠谱得多。

## 冷思考三条

- 把“堪比 X”当传播修辞处理，别当技术结论。论文原文的实验边界，永远比热搜标题诚实。
- 真正值得持续追踪的主线是“每 token 成本”：架构竞争的重心正在从谁更聪明，转向**谁更便宜地聪明**。
- 对想上车的团队和个人：不押注单一架构。混合架构已成趋势，跟随开源生态、保持技术栈可迁移，比预测哪个“终结者”登基划算得多。
