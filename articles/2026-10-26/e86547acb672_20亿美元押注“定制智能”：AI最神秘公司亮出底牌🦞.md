2025年初，前 OpenAI CTO Mira Murati 创办了 Thinking Machines Lab。这家公司一度“神秘”到离谱：没有产品、没有论文、官网只有一页宣言，却被曝拿下约 20 亿美元种子轮、投后估值约 120 亿美元。热搜里那句“AI 圈最神秘的公司，终于公开了它的豪赌”，说的就是它。半年之后，底牌陆续翻开：研究博客、第一款产品 Tinker 相继亮相，核心判断也摆上台面，AI 的下一程，未必是“更大的模型”，而是“定制的智能”。这场赌局到底赌的是什么？值得拆成三层看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/c3137f21f3e299e2.png)

## 一、先看清这家公司的“配置单”

- **人**：创始团队约 30 人起步，几乎全是顶级实验室的核心成员——CTO Barret Zoph（前 OpenAI 研究副总裁）、首席科学家 John Schulman（RLHF 路线的奠基者之一），还有 Lilian Weng 等一批前研究负责人。
- **钱**：据报道种子轮约 20 亿美元、由 a16z 领投，投后估值约 120 亿美元。这个量级，此前通常只出现在成熟公司的后期轮次。
- **姿态**：长期“隐身”，不开发布会、不隔空喊话，发布节奏更像研究院而不是创业公司。

一句话概括：这是把研究院的配置，装进了创业公司的 deadline。动作本身就在传递信号——他们自认知道要去哪，不急着证明。

## 二、豪赌的标的：从“一个通用大脑”到“千万个定制大脑”

- **主流叙事**：Scaling is all you need——堆数据、堆算力，把一个通用模型做到极致，所有人在同一个 API 上排队。
- **他们的判断**：通用能力会继续涨，但最大的价值缺口在“定制”。企业要的不是“宇宙最强”，而是“最懂我这条业务线”；通用模型的“标准答案”落到具体场景，常常差最后 10 分。
- **落地动作**：第一款产品 Tinker 是一个微调 API，开发者用几十行代码，就能对 Llama、Qwen 等开源权重模型做监督微调（SFT）和强化学习微调，覆盖语言与多模态任务，并向学术研究者开放了优惠额度。
- **逻辑链条**：开源模型快速逼近闭源前沿 → “能力底座”不再稀缺 → 稀缺的是把底座改造成自家业务的“最后一公里” → 谁把这一公里的成本打下来，谁吃到大头。

类比 PC 时代：早期大家比拼“谁的整机更强”，后来真正赚到大钱的，是帮每个行业把机器改装成生产工具的人。

## 三、技术底座：用 LoRA + RL 把“定制”打成白菜价

这一步是他们敢下注的底气，也最值得工程师细看。

- 预训练像“通识教育”，微调像“岗前培训”。但全参微调是个显存刺客：除了模型权重本身，还要为每个参数维护优化器状态，显存开销动辄翻好几倍，普通团队根本玩不起。
- LoRA 的思路：冻结原权重 W，只训练一个低秩增量 ΔW = B·A。两片“薄片”矩阵的参数量比原矩阵低两三个数量级，训练成本断崖式下降。
- 他们发布的《LoRA without regret》给出几条反直觉结论：
  1. 秩（rank）够高时，LoRA 能追平全参微调的效果，“廉价版”不等于“阉割版”；
  2. 任务越复杂、数据越多，所需最优秩越高，秩是要按任务调的超参数，不是拍脑袋写个 8；
  3. 在 RL 场景里，LoRA 反而更稳：天然带正则化效果，不容易把模型训到“遗忘”；
  4. 甚至可以给 embedding 层加 LoRA，对引入新领域词表的任务很实用。
- **工程含义**：底座权重全租户共享，每个客户只挂自己的小适配器（adapter），一套集群可以同时服务成千上万个“定制模型”。等于把定制成本从“每个客户一个机房”，打到“每个客户一个插件”。

## 四、既然逻辑顺，为什么还叫“赌”？

- **逆风局**：它和 Scaling 叙事正面相对。如果通用模型持续碾压、长上下文加提示工程能覆盖大部分需求，定制层的价值空间就会被压缩。
- **上有压、下有卷**：OpenAI、Google 都提供微调 API；开源生态里的托管平台和社区工具链也在做同类的事。基座厂商“顺手”吃掉中间层，是所有中间件公司的宿命焦虑。
- **卖铲子的前提，是真有人淘金**：企业级微调需求真实存在，但“愿意为微调基础设施持续付费”的客户密度，还没被充分验证。
- **豪华阵容 ≠ 产品成功**：研究能力和 toB 的工程、服务、定价能力是两套肌肉，得重新长。

别忘了，20 亿美元种子轮本身就是豪赌的一部分，这个估值给的是“判断正确后的终局”，容错空间极小。

## 五、不站队也能带走的判断框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/18d6b6637c41a302.png)

- **判断要不要定制，先看两个信号**：你有没有“别人拿不到的数据”，有没有“可自动验证的反馈信号”（比如代码能否跑通、答案是否唯一正确）。两者都没有，微调大概率不如把 RAG 和提示工程先榨干。
- **数据质量 > 微调技巧**：几千条干净、多样、贴近真实分布的样本，往往胜过几十万条脏数据。
- **选型留后路**：把微调流程跑在开源权重模型上，用标准格式管理适配器，避免把“业务能力”焊死在单一供应商的 API 里。

## 写在最后：三条冷思考

1. “定制智能”和“通用大模型”不是对立选项，更像接力赛：通用模型负责能力上限，定制负责落地下限，赢家多半是把两段跑顺的人。
2. 这场赌局最大的变量是 RL。如果能力增长的主引擎从“模仿人类数据”转向“从反馈中学习”，那么定制就不只是省钱，而是能力来源本身，赔率会整个改变。
3. 对个人和团队，与其猜谁赢，不如掌握“把通用能力改造成业务能力”这套手艺：数据清洗、微调、评估、回滚。模型会过时，这套方法论过时得慢得多。

豪赌的看点从来不是筹码大小，而是敢把判断说清楚。这家公司迟到大半年的“公开”，至少做到一件事：让整个行业认真讨论“定制智能”是不是下一站。至于答案，让模型和数据去吵吧。
