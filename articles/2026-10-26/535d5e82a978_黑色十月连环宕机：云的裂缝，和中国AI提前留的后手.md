2025年10月，全球很多用户盯着手机上同一个转圈的小图标：10月20日，AWS 弗吉尼亚北部区（us-east-1）大面积故障，从 Reddit、Snapchat、Alexa 音箱，到智能门铃、扫地机器人，一批互不相识的服务在同一时刻集体失联；不到十天后的10月29日，Azure 又因一处错误配置把 Microsoft 365、Xbox 拖下了水。一个月内两场全球级宕机，媒体把它称为互联网的“黑色十月”。36kr 的复盘文章把目光投向了一个细节：风暴中心之外，一些中国AI服务站得很稳，因为它们“提前留了后手”。后手不是玄学，是一套可以拆开看的工程。这篇就把它拆开。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/5a30c3153ed57bf8.png)

## 一、时间线先摆清楚：两周，两次全球跌倒

- **10月20日，us-east-1。** AWS 事后报告给出的根因相当“家常”：一个负责追踪网络子网的自动化流程出现竞态条件（race condition），误删了 DynamoDB 服务端点的 DNS 记录。电话簿被撕掉一页，所有按名字找服务的请求集体扑空。
- **连锁反应。** 依赖 DynamoDB 的登录、鉴权、日志、消息队列接连失守，EC2 新实例的启动也被积压任务卡住。Downdetector 收到的报障以百万计，受影响在线服务上千个；主故障数小时内缓解，部分服务完全恢复花了十几个小时。
- **10月29日，Azure。** 官方归因于 Azure Front Door（全球流量入口服务）的一处错误配置变更，Microsoft 365、Xbox、Minecraft 等大面积报错。
- **11月中旬的余震。** Cloudflare 也出现一次全球性 5xx 风暴：一次数据库权限调整产生了异常数据，边缘节点代码在“脏数据”上崩溃。
- 共同点值得划重点：**没有一场是黑客大场面，起点全是自家人的例行操作。**

## 二、为什么“一个区域”能带走半个互联网？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/be561d2fb6c725b6.png)

- **高度集中。** 全球互联网流量越来越压在少数几家超大规模云上，而 us-east-1 是 AWS 最老、最大、配套最全的区域。大量第三方公司哪怕数据放在别的区，“控制面”也习惯性住在东区。
- **控制面 vs 数据面。** 类比打车：你已经在车上往前开，这是数据面；但派单、改目的地、结算全靠控制面。控制面一挂，旧的还能凑合，新的正常进不来，于是全世界一起卡住。
- **DNS 是根依赖。** 域名解析相当于互联网电话簿，TTL 缓存能撑几分钟，撑不了一夜；缓存一过期，故障就被“续上”了。
- **重试风暴。** 服务恢复的瞬间，全球客户端在同一秒按下 F5，二次压垮半死的系统。这就是为什么恢复曲线总比故障曲线更长。
- 结论：这不是某一家云的锅，而是“集中化”这条路线的固有代价——行业黑话叫 shared fate，共担命运。

## 三、所谓“留了后手”，其实是三张具体的牌

- **牌一：自建 + 多活。** 以 DeepSeek 为代表的公司，长期把训练和推理放在自建集群上，不把命运押在单一公有云的单一区域。少一层转包，就少一层“同时倒下”的概率。
- **牌二：开源权重兜底。** DeepSeek 以 MIT 协议开源模型，Qwen、GLM、Kimi K2 等也陆续开放权重。API 再稳，可用性也是别人家的；权重躺在公开仓库里，哪怕云断了，企业也能在自己的机器上继续跑推理。开源不只是获客策略，本质上是一份“可用性保险”。
- **牌三：降级预案。** 工程上叫 graceful degradation：故障来时核心对话保住，联网搜索、长任务可以排队或暂关，短时靠缓存顶住。不是全亮，也不是全灭，而是“该暗的暗，该亮的亮”。
- 一句话总结：**可靠性不是买来的，是设计出来的。** 龙虾壳就是外骨骼，平时看着多余，出事时能保命——好架构同理。

## 四、风暴从不预约：三条“后手清单”

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-26/03e00f61eb0436e1.png)

1. **审计你的“根依赖”。** 把 DNS、鉴权、配置中心这类服务列出来，逐个问：它们挂了，我的 Plan B 是什么？DNS 可以双供应商托管，控制面尽量别住进同一个可用区。
2. **演练过的备份才叫备份。** failover 没跑过，等于没有；重试记得加指数退避和抖动（exponential backoff + jitter），否则你就是下一场重试风暴的群众演员。顺带算笔账：99.95% 的 SLA 意味着每月允许约 21 分钟不可用，你的业务扛得住吗？
3. **给自己留一份“离线权”。** 企业侧，可以把开源权重自托管当成 API 的 Plan B，让关键链路至少有一层不依赖外网的兜底；个人侧，重要数据遵守 3-2-1 原则，3 份副本、2 种介质、1 份异地，别把人生唯一副本托付给某个转圈的小图标。

黑色十月过去，流量恢复，热搜翻页。值得留下来的结论其实只有一句：云没有原罪，集中也不是错误，真正的分水岭在于，风暴来临之前，你有没有为自己留一手。好系统从不承诺永不出故障，它只承诺一件事：故障发生时，世界仍然按计划运转。
