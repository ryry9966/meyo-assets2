## 背景

用 OpenClaw 挂上 MCP 工具后，让 agent 定期在论坛或 GitHub Discussions 发内容，技术上半小时就能跑通。真正难的不是"能不能发"，而是"发了之后像不像人"。社区对机器痕迹非常敏感：一眼假的内容不仅没有互动，还容易被管理员直接盯上。

## 问题：定时任务一眼假

最常见的实现是一个 cron，比如每天 10:00 准时发一条。这有三个明显破绽：

1. **时间戳过于规律**——发帖间隔方差为零；
2. **活跃时段反人类**——服务器跑 UTC，"上午十点"对社区用户来说是凌晨三点；
3. **行为单一**——只发新帖从不回帖，每条都带同样的结尾模板。

真人翻两页历史记录就能确认这是脚本。

## 做法：三层节流

我把节奏控制拆成三层。

**第一层：时间分布。** 放弃固定间隔，改成加权抽样：统计自己历史发帖的时段分布（或目标社区的活跃分布），按小时建权重表，每次发布从权重表里抽样，再叠加 ±20~40 分钟的均匀抖动。核心是"像自己"，而不是"像随机数"——纯均匀随机同样可疑，深夜时段的权重要压到接近零。

**第二层：频率约束。** 在调度器里加几个硬性限制，全部进配置：

```yaml
schedule:
  mode: weighted_hours      # 权重来自真实历史数据
  jitter_minutes: [20, 40]
  daily_cap: 2              # 单日主贴上限
  min_gap_same_board: 6h    # 同板块最小间隔
  quiet_hours: "00:00-08:00"
  mix: { post: 0.3, reply: 0.7 }
```

失败重试必须带指数退避和幂等键，否则网络抖动一次，同一内容连发三条，比不发还糟。

**第三层：行为混排。** 真人不是只发帖。让 agent 按比例混排"新帖/回复"，回复优先挂在别人的讨论下面；标题长度、段落结构、是否带代码块做随机变化；去掉每条帖尾的固定签名。发布前先进草稿队列，攒 3~5 条人工过一眼再放行。

## 踩坑点

- **cron 写死整点**：时间戳序列一眼规律。解法是抽样 + 抖动，别用固定 step。
- **时区坑**：服务器 UTC，社区在东八区。所有时间先转社区本地时区，再进权重表。
- **重试风暴**：HTTP 超时后无脑重试造成重复帖，务必用幂等键去重。
- **抖动幅度太小**：±2 分钟的抖动照样规律，抖动量级要和间隔量级匹配。

## 可复用建议

1. 时段权重、配额、静默时段全部配置化，不同社区不同配置，别硬编码。
2. 每周跑一次审计脚本：拉最近 100 条帖子时间戳，算间隔分布的方差和时段直方图，方差过低就报警。
3. 保留人工审核队列——宁可慢一点，也别让 agent 直接对公网发布。
4. 权重表用真实历史数据初始化，而不是拍脑袋填。

## 总结

反机器人检测的本质，是在判断行为分布像不像人。工程上要做的就三件事：**用真实数据建模时间分布，用硬配额兜住下限，用人工队列兜住质量**。节奏控制做好了，自动化才是可持续的。
