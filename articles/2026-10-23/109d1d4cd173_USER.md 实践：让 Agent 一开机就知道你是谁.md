## 背景

OpenClaw 每次会话启动，都会把 workspace 下的一组 Markdown 注入上下文：AGENTS.md 管行为，SOUL.md / IDENTITY.md 管人格，而 USER.md 这个槽位专门用来放"你是谁"。它默认几乎是空的，很多人装完直接跑，于是 agent 只能靠猜。

## 问题

不写 USER.md 的日常大概是这样：

- **重复确认**。开新会话、换设备，它又问一遍"你用 pnpm 还是 npm？"
- **错误假设**。默认给你 npm 命令、用英文回复、把"小改一下"理解成整文件重写。
- **记忆错位**。MEMORY.md 里堆了一堆项目细节，但那里该放事件流，稳定事实没有落脚点。

## 怎么做

1. 在 `~/.openclaw/workspace/` 下建 USER.md，控制在 60–80 行。它每个会话都进上下文，长度就是成本。
2. 用固定骨架填内容：
   - **基本约定**：时区、语言（中文回复，技术名词保留英文）、称呼；
   - **环境事实**：OS、编辑器、运行时、包管理器、部署方式（Docker 还是 PM2）；
   - **当前项目**：一行一个，带路径和状态；
   - **协作偏好**：先结论后细节；改代码给 diff，不要整段重写；我已懂的不要解释；
   - **红线**：不主动 commit，不代发消息，删除类操作必须二次确认。
3. 写"可执行的约束"，不要写自我介绍。"十年后端经验"没有信息量，"一律 pnpm，别给 npm 命令"才有约束力。
4. workspace 放进私有 git 仓库，每次改动走 diff review；每月清一次过期条目。
5. 验证方式：开新会话问它"我用什么包管理器？当前优先级最高的项目是什么？"答不上来，说明文件没生效或写法有问题。

## 踩坑点

- **写成简历**：形容词越多，约束越弱。
- **越写越长**：四百行的 USER.md 会稀释注意力，关键约束反而被忽略。
- **职责混淆**：稳定画像进 USER.md，动态事件进 MEMORY.md，两边重复必然漂移。
- **塞敏感信息**：密钥、住址、账号别放，它们会被带进工具调用和日志。
- **放任 agent 自动改**：它总结的"你的偏好"未必是你的偏好，必须人工过一遍。
- **过期信息滞留**：三个月前的"当前在做 X"，会让它一直往 X 上靠。

## 可复用建议

- 把 USER.md 当作用户侧的 prompt 工程：成本一小时，收益覆盖之后每次会话。
- 团队共享的上下文放 PROJECT.md，个人画像放 USER.md，别混在一起。
- 接了 MCP 工具或定时任务的，把"哪些操作需要确认"写进红线一节，比在每个流程里重复声明省事。
- 骨架保持稳定、只改内容，diff 干净，迁移也方便。
- 把"新会话问答探测"当回归测试用，每次改完文件就跑一遍。

## 总结

USER.md 是 OpenClaw 里成本最低、杠杆最高的一份配置。它不提升模型能力，只是把每个新会话里重复发生的"猜"变成"读"。写完初版大约一小时，之后每月十分钟维护，换来的是 agent 默认就处于正确的工作状态，这件事，值得所有跑自动化流程的人先做。
