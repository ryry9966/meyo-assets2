最近 AI 圈热搜三连击：Gemini 4 Argon 上线后 token 消耗量暴涨 3 倍；谷歌 CEO 首次公开谈起砍掉 3.5 Pro 的决策内幕；聊到兴头上还剧透了 5.0 的方向。三条消息看着像三个瓜，其实是同一件事的三个侧面——**谷歌正在对算力、产品线和发布节奏做一次大的重新分配**。这篇拆开讲：token 到底被谁烧掉的？砍掉一个 Pro 意味着什么？5.0 的剧透又是说给谁听的？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/ed2becf733d20ea6.png)

## 一、Token 暴涨 3 倍：大头是"看不见的思考"

用户屏幕上看到的对话，和账单后端的消耗，差距正在越拉越大。三个机制在叠加：

1. **思考模型的隐藏开销。** 推理型模型（reasoning model）在给出答案前，会先生成大段"思考 token"——界面上通常折叠不显示，但每一次前向计算都是真金白银。复杂问题思考几千上万 token 很正常，这部分可以轻松占到单次请求成本的一半以上。
2. **Agent 把加法变成了乘法。** 传统聊天是一次请求、一次回答；Agent 工作流是"规划→调工具→读结果→再规划"的循环。举个典型例子：让 Agent 修一个 bug，读仓库、定位代码、改写、跑测试、总结，动辄二三十次模型调用。每次调用的上下文还带着前几轮的完整历史，token 按乘法累积——这就是"一个 Agent 干一小时的活，顶过去一百次搜索查询"的成本真相。
3. **长上下文与多模态。** 百万级 context 窗口让"把整个代码库丢进去"成了常规操作；一张图折算几百到上千 token，一段视频更多。用户喂的东西越大，消耗曲线越陡。

所以"消耗涨 3 倍"未必等于"用户涨 3 倍"，更可能是**模型行为变了、使用范式变了**。对谷歌来说这是双刃剑：好消息是使用深度和粘性上来了，坏消息是推理成本同步甚至超线性上涨。

## 二、砍掉 3.5 Pro 的"内幕"：算力是零和的

CEO 敢把"砍产品"拿出来正面讲，说明这个决策偏"工程"而非"商业"。拆几个关键点：

1. **旗舰模型的隐性成本极高。** 一条 Pro 产品线不是训练一次就完事：后续每轮强化训练要占大集群，评测基准要持续维护，安全对齐要重做，推理服务要单独调优，API 文档和弃用周期都得养着。两条旗舰线并行，等于把这套成本乘以二。
2. **SKU 膨胀到了临界点。** 回顾一下：Gemini 1.0 时代有 Ultra / Pro / Nano，1.5 加了 Flash，2.5 又分 Pro 和 Flash，中间还有各种尺寸和实验版。开发者要查表才知道该调哪个。砍掉中间某一代 Pro，本质是做减法——旗舰管质量上限，Flash 级管走量，中间态越少越好。
3. **算力预算是零和游戏。** 同一批 TPU 集群，给旧模型做强化训练的时间，就是新模型少训练的时间。在 5.0 已经在路上的前提下，继续给 3.5 Pro 投入，是机会成本最高的用法。
4. **对开发者反而是好事。** 明确说"这条路不通了"，比悄悄降智、慢慢弃用要体面得多。模型 deprecation 在 API 行业是常态，区别只在于厂商说不说清楚。

## 三、剧透 5.0：亮牌是说给三类人听的

剧透下一代产品，成本几乎为零，收益却覆盖三个受众：

1. **说给开发者：** 潜台词是"别在 3.5 Pro 上做深度绑定"。用路线图提前管理迁移预期，能把未来切换时社区的骂声降一个量级。
2. **说给对手：** 前沿模型 6~12 个月一代已是行业节奏，版本号直接跳到 5.0，既是叙事对齐，也是心理占位——把"下一代"这个词先攥在手里。
3. **说给资本市场：** 证明路线图可控、管线清晰。对一家把 AI 押上重注的公司，"下一代在做什么"比"这一代多赚多少"更能稳住估值。

## 四、Token 经济学：推理正在反超训练

补一个背景，这盘棋就通了：

- **成本结构倒转。** 大模型早期，训练是成本大头；随着用户量上来，推理（serving）开销逐年攀升。一次旗舰级训练的投入普遍被估计在数千万到上亿美元级别，而头部产品的年度推理开销已经进入同一量级，甚至更高。
- **Token 既是收入也是负债。** 每个消耗的 token 都对应芯片的前向计算，卖得越多烧得越多。毛利取决于"单位 token 成本"能不能压下去——工程上靠 TPU 利用率、KV cache、批处理调度这些硬功夫。
- **谷歌的护城河恰好在这里。** 自研 TPU + 自有数据中心 + 端到端编译栈，让它的单位推理成本处于行业最低一档。同样的 3 倍消耗，别家可能肉疼，谷歌更多算"甜蜜的负担"。

串起来看就明白了：**消耗暴涨 3 倍 + 砍旗舰 + 剧透 5.0，本质是把算力从旧产品线挪到下一代，同时用更简洁的产品结构去消化暴涨的推理需求。**

## 五、给开发者的三条冷思考

1. **用"路由"思维选模型。** 90% 的日常请求（分类、抽取、改写、格式化）用 Flash 级小模型足够，把旗舰留给真正难的推理任务，成本差通常在 10 倍以上。别用大炮打蚊子，也别用弹弓打坦克。
2. **把 token 效率当工程指标考核。** 善用 context caching（重复前缀缓存计费更低）、精简 system prompt、控制检索召回条数。prompt 写得糙，等于每次请求都在给云厂商捐款。
3. **为 deprecation 留后门。** 在业务代码和模型 API 之间加一层薄抽象，对回答质量、延迟、成本做双模型对比。版本号是厂商的，架构主动权得是自己的。

模型行业没有稳态，只有下一班船。用龙虾的话说：壳迟早要蜕，重点是别把房子盖在壳上。
