最近 AI 圈流传一条热闻：谷歌把 4 个 AI agent 扔进《我的世界》，前期活得相当狼狈，累计死亡 605 次；后来它们不再硬刚，而是开始给自己写代码——造工具、补装备、定战术，最后把大 Boss 撂倒。看到"死亡 605 次"这个数字，工程师的第一反应不是心疼，而是：这是一份相当完整的失败数据集。这篇文章就拆一下，这 605 次死亡背后到底发生了什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/6ee2c46b96f44704.png)

## 一、先还原现场：实验大致分四个阶段

- **瞎摸索期**：4 个 agent 出生在随机地形，靠大模型理解状态、输出动作。605 次死亡的大头都贡献在这里——掉岩浆、被夜怪围殴、活活饿死，各有各的死法。
- **复盘期**：每次死亡后，系统把"死因 + 当时状态"写进记忆库，模型对记录做反思，提炼出"夜晚别出门""先做床设重生点"这类规则。
- **写代码期**：当预设动作集不够用时，agent 转向生成程序来控制角色，把常用逻辑固化成可复用的函数。
- **Boss 战**：带着装备、战术和分工进入终局，靠代码级的精确走位打赢 Boss。

有个细节值得注意：所谓"自己写代码"，不是 AI 突然顿悟了编程，而是 agent 框架里预留的"代码即动作"通道被彻底激活了。区别在于——前 605 次死亡恰好证明了：光用预设通道，不够。

## 二、为什么偏偏是《我的世界》

Minecraft 在 AI 研究界有个外号：**AI 的果蝇**。果蝇之于遗传学，约等于 Minecraft 之于 agent 研究，理由很实际：

1. 有社区级编程接口（如 Mineflayer），agent 用几行 JS 就能读世界状态、下发动作，不必从像素里硬猜。
2. 任务空间足够大：采集、合成、建造、导航、战斗，一个沙盒全齐。
3. 死亡成本为零。现实机器人试错一次可能报废一台设备，游戏里死了原地重生。
4. 结果可验证：有没有造出工作台、有没有打败末影龙，判定标准客观。

这条路线家谱清晰：2019 年 MineRL 比赛让 AI 学挖钻石；2022 年 OpenAI 用 7 万小时人类视频训练出会玩 Minecraft 的 VPT；2023 年 MineDojo 拿下 NeurIPS 最佳论文；同年英伟达等机构的 Voyager 让 GPT-4 驱动的 agent 靠"自己写技能代码"解锁了 3.3 倍的独有物品、2.3 倍的探索距离，效率比基线快 15.3 倍。谷歌这次，可以看作这条路线的延续与加码。

## 三、605 次死亡不是败绩，是训练语料

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/8d0f0abcca108c2b.png)

当前 LLM agent 的标准循环是：**感知 → 规划 → 行动 → 观察 → 反思**，反思结果写回记忆。这套循环的关键假设是：失败必须留下结构化信息，否则 605 次就只是 605 次。

- **感知层**：读取血量、背包、周围方块与敌人位置，压缩成模型可读的文本。
- **规划层**：把"活过第一夜"拆成"砍树→做木板→做工作台→做木镐"的目标树。
- **行动层**：调用动作或生成代码执行。
- **反思层**：死亡后自动生成"事故报告"，归因到具体决策，把教训变成可检索的规则。

对比传统强化学习更有感觉：AlphaStar 和 OpenAI Five 打赢职业选手，靠百万量级对局和精心设计的奖励函数。LLM agent 的优势在于能用语言总结教训——一次死亡的经验可以直接迁移到相似场景，不必再死一次。605 次死亡的真正价值，是把"死亡"这个稀疏信号变成了带死因注解的案例库。同样的死法在人类玩家那里叫头铁，在 agent 系统里叫经验回放。

## 四、真正的分水岭："代码"成了 AI 的手

比打赢 Boss 更值得展开的，是 agent 为什么选择写代码。

1. **点击是低维动作，代码是高维动作**。按 20 次鼠标挖 20 块石头，不如生成一个循环函数一次搞定，还不会手抖。
2. **代码自带调试闭环**。生成的代码报错了，stack trace 直接回喂给模型，改一版再跑——这就是 self-debugging，比"点击点歪了"这种模糊反馈精确得多。
3. **可复用、可组合**。"砍树"函数验证通过后存进技能库，下次向量检索直接调出；"砍树→合成→挖矿→冶炼"可以逐层组装成"从零武装到满配"的复合技能。
4. **可解释**。出了问题看日志定位，而不是对着一串点击序列发呆。

Voyager 在 2023 年就把"技能库 + 自动课程 + 环境反馈"跑通了，谷歌这次的差异点更多在多智能体协作与规模化。所以"AI 学会写代码"要打个引号：写代码的通道一直在，这次是模型终于把这条通道用出了花。

## 五、4 个一起玩，比 1 个强在哪

多智能体不是人数堆砌，而是分工带来的搜索空间缩减：

- **角色分化**：侦察、后勤、建造、战斗各管一段，每个 agent 的决策空间变小，出错概率随之下降。
- **天然评审团**：一个 agent 的计划先让同伴过目，等于内置了 code review，一部分幻觉在执行前就被拦下。
- **共享记忆**：公共黑板记录资源、坐标、任务状态，避免四个 agent 重复砍同一棵树。

2024 年 Altera 的 Project Sid 曾把上千个 agent 放进 Minecraft，观察到了自发的分工与交易行为——协作能力确实会随规模涌现。至于为什么是 4 个而不是 40 个，多半是协调成本的工程折中：沟通带宽有限，人一多，开会时间比干活时间还长。这点上，AI 团队和人类团队没什么本质区别。

## 六、泼点冷水：通关 Minecraft ≠ 通用智能

- **考场太宽容**：死亡免费、物理简单、目标明确，现实任务的每一条都不满足。
- **信息层有优势**：agent 读的是接口数据，人类玩家看的是像素，输入信噪比不在一个量级。
- **延迟与成本**：agent 思考以秒计，人类玩家以毫秒计，背后是持续调用大模型的真金白银。
- **迁移仍是开放问题**：游戏里死 605 次很便宜，工厂里"死"605 次是事故报告，Sim2Real 的鸿沟没有因为一条热搜变窄。

更准确的读法是：这是一次漂亮的 agent 系统工程验证，而不是"AI 突然变聪明了"。

## 写在最后：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/d3181818a81ebaec.png)

1. **评估 agent，看"错误恢复能力"而不是一次成功率**：遇到失败几步之内能修正，比永不失败更能说明系统健壮。
2. **想自己做 agent 的开发者，实用三件套没变**：代码即动作、技能库、失败后的结构化反思。三者齐备，605 次死亡才不是白死。
3. **看这类新闻多问两句**：目标是谁定义的、成功是谁验证的、输入是像素还是接口——答案决定这条新闻离你的业务到底有几公里。
