最近 AI 圈有条消息把好几个话题拧在了一起：据 36kr 报道，Gemini 4 Argon 的 Token 消耗量较前代暴涨 3 倍；谷歌 CEO 首次公开谈起砍掉 3.5 Pro 的决策内幕；顺带还剧透了 5.0 的方向。三件事看似零散，其实是同一盘棋的三个动作：用量在做乘法，产品线在做减法，下一代在做加法。这篇把账本摊开，看看谷歌到底在下什么棋。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/29e55e3f0fea497b.png)

## Token 翻 3 倍：三台“抽水机”同时开机

先说结论：消耗暴涨不是谷歌在乱烧钱，而是三种新用法同时把水龙头开到了最大。

- **思考 token（reasoning tokens）**：新一代模型答题前会先生成大量隐藏的“思考链”，这部分 token 照常计量、照常计费。一个复杂的数学或代码推理请求，思考部分的 token 经常是正式答案的好几倍——你看到的回答很短，背后的草稿纸很长。
- **Agent 循环的乘法效应**：Agent 干活是“观察—思考—行动”的循环，跑完一个完整任务调用几十次模型很正常；关键是每一轮都要携带越来越长的上下文——工具返回、网页内容、代码文件全算输入。粗算一笔账：1 万 token 上下文 × 30 轮调用，仅输入就是 30 万 token。
- **多模态与超长上下文**：一张图几百个 token，一段视频动辄数千 token；上下文窗口到了百万级，用户是真敢往里塞整本书、整个代码仓库，塞完还要问一句“总结一下”。

再往底层看一层：Transformer 的注意力计算量随上下文长度近似平方增长，KV cache 的显存占用则线性膨胀——上下文越长，单位 token 的推理成本越高。对谷歌来说，"3 倍"直接顶在自家 TPU 集群和每年数百亿美元级的数据中心开支上，这就是 CEO 必须亲自出来说话的原因。

## 砍掉 3.5 Pro：不是砍产品，是“并线”

“内幕”听起来神秘，翻译成工程语言就是三本账：

1. **维护账**：每条产品线都不是免费的——训练、对齐、安全评测、红队测试、量化部署、文档生态，全都要人养。SKU 越铺越多，边际成本越来越贵。
2. **体验账**：Flash / Pro / Thinking / 各种实验版，开发者早就选型困难。OpenAI 发布 GPT-5 时干脆取消手动选型号，内置一个 router 在“快回答”和“深思考”之间自动切换——事实证明，用户并不想当模型选型师。
3. **算力账**：训练预算有限，与其三线开花，不如把算力、数据和顶尖人才集中到一条旗舰线上。砍掉中端 Pro 的本质，是把“中间层”的活交给路由器和蒸馏小模型去干，而不是让产品矩阵硬扛。

行业里有个可类比的先例：云计算早年也是实例类型爆炸，后来反而靠自动伸缩把选择简化掉。模型产品线正在走同一条路——形态收敛，能力下沉。

## 5.0 伏笔：从“会聊天”到“会干活”

把“消耗暴涨”和“产品线合并”两个信号连起来读，5.0 的方向其实已经写在墙上：

- **Agent 原生**：长任务规划、工具调用、computer use 类能力成为一等公民，而不是外挂插件。
- **记忆分层**：上下文窗口终究有限，靠外部记忆 + 检索 + 缓存拼出“近似无限”的工作记忆。
- **推理效率**：MoE 稀疏激活、投机解码（speculative decoding）、KV cache 压缩——每一项都是给“3 倍消耗”踩刹车的技术。
- **计费形态演化**：从纯按 token 计费，走向“token + 缓存 + 批量 + 按任务”的混合模式，Google 的 context caching 和 Batch API 已经开了头。

判断依据不玄学：模型公司砍中端产品，通常发生在下一代旗舰能"以一敌三"的前夕——先腾出赛道，再放新车。

## 杰文斯悖论：越便宜，用得越多，这条路才健康

19 世纪经济学家杰文斯观察到一个反直觉现象：蒸汽机效率翻倍之后，煤的消耗不降反升——因为划算到值得烧煤的场景暴增了。AI 正在上演同一幕：单位 token 价格三年降了一个数量级（2023 年 GPT-4 级旗舰约 30 美元/百万输入 token，如今同级能力只要几美元），于是视频理解、代码 agent、批量文档处理这些“以前用不起”的场景全涌了进来。

所以"消耗涨 3 倍”和“AI 越来越便宜”不但不矛盾，反而是同一枚硬币的两面：单价下降 → 场景变多 → 总量上涨。判断一条 AI 产品线健不健康，盯这两个指标就够了：**单位 token 价格是否持续下降，总消耗是否持续上升**。两个同时成立，才说明智能在真正变便宜——连一只对投喂量敏感的甲壳类都懂：饵料单价降了，进食总量必然上升。

## 三条冷思考：把 Token 当电费管

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/874ba2b4880352fa.png)

1. **当电费管，别当流量费**：给团队建用量看板，prompt 定期瘦身；前缀重复的内容用 context caching（缓存命中部分通常只要原价一到四折），批量任务走 Batch API；再按难度分级调用——分类、摘要交给小模型，关键推理留给旗舰。盯“单位任务成本”，别只盯单价。
2. **架构上留退路**：产品线合并期最容易出 API 弃用和参数变更。用网关层把模型调用抽象出来，少依赖某家独有的私有特性，将来迁移成本能低一个量级。
3. **别被“暴涨”吓到**：总消耗上升是智能普及的副作用，不是收割信号。真正该检查的是自己团队的用量结构——如果 80% 的 token 花在了 20% 高价值任务之外，那问题不在谷歌，在你自己的流水线。
