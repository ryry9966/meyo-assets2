## 背景

OpenClaw 的 workspace 里，除了 AGENTS.md、TOOLS.md 这些“做事”的配置，还有一个 SOUL.md，决定 agent“是什么样的人”。随着接入的 MCP 工具、插件、定时任务越来越多，我发现行为漂移比能力不足更常见：同样的问题，昨天简洁今天啰嗦；聊天里谨慎，跑批时却一路执行到底。

## 问题

人格散落在各处：一段写在开场 prompt，一段靠对话里临时纠正，还有一部分活在“上次它做错之后我骂了它一句”的记忆里。结果是无法审计、无法复现，模型一升级风格全变。更麻烦的是边界：哪些操作必须确认、哪些信息不能外发，如果只靠工具层权限，agent 的“态度”仍然是随机的。

## 做法

1. **一份短文件**：workspace 根目录的 SOUL.md，控制在 30 行左右，分四块——身份与语气、价值取向、硬边界、升级路径（何时求助人类）。
2. **写行为，不写形容词**。“友好”没有约束力，换成“先给结论，再给两条理由；不确定就说不确定，不编”。
3. **边界必须可测**。比如“删除、对外发消息、涉及费用的操作，必须先复述将执行的命令并等待确认”。
4. **当配置管理**：进 git，每次事故后补一条规则，一个 incident 对应一行 diff。
5. **分层存放**：通用人格放 SOUL.md，频道差异（如群聊更简短）放对应集成配置，同一段话不要复制到三处。

一个可以抄的骨架：

```markdown
# SOUL.md
## 身份与语气
- 先给结论，再给两条理由；不确定就说不确定
- 默认中文，代码与术语保留英文

## 硬边界
- 删除、对外发消息、涉及费用：先复述命令，等确认
- 不输出密钥、.env 内容及无关个人信息

## 升级路径
- 连续两次失败或不可逆操作：停下，说明卡点，等人类决定
```

## 踩坑点

- **写太长**。两百行的人格描述会稀释注意力，模型开始选择性忽略。超出部分挪到 AGENTS.md 或 TOOLS.md。
- **和其他文件打架**。AGENTS.md 要求简洁、SOUL.md 要求温暖详尽，行为就会抽风。人格只留一个真相源。
- **把 SOUL.md 当安全边界**。它是 prompt 级引导，不是沙箱。真正的强制靠工具白名单和执行审批——SOUL.md 管“态度”，权限管“能不能”。
- **过度约束**。什么都要确认，agent 会变成不断请示的实习生，琐碎任务也没法自动跑。边界应与风险成正比。
- **换模型不复测**。风格漂移多半发生在升级之后，跑一遍边界测试集再上线。

## 可复用建议

- 维护一个 10 条左右的对抗性测试集（诱导删库、套取密钥、要求越权发消息），每次改动后跑一遍。
- 定期修剪：三个月没触发过的规则，考虑删掉。
- 人格与记忆分离：SOUL.md 管“我是谁”，MEMORY.md / USER.md 管“我知道什么”，别混在一起。

## 总结

SOUL.md 本质上是“人格即配置”：短、可版本化、可测试。它不解决安全问题，但能让 agent 在跨会话、跨频道、跨模型版本时保持一致的态度和清晰的底线。把它当成基础设施配置来维护，而不是一次性的人设创作，长期收益最大。
