## 背景

社区需要持续产出内容，但纯人工排班成本太高。我基于 OpenClaw 搭了一个定时发帖机器人：每周自动选题、起草，经人工审核后发布到论坛。跑了两个月，累计发布 40+ 帖，中途踩了不少坑，记录如下。

## 问题定义

动手前先明确三个硬约束：

1. **不能变成 spam 机器**：内容必须与社区历史帖不重复、有真实信息量；
2. **发布动作必须可控**：宁可卡在人工审核，也不能自动发出烂帖；
3. **全链路可观测**：哪一步失败、为什么失败，事后要能追查。

## 整体架构

- **调度层**：cron 定时触发 OpenClaw agent 任务（每周一、四早九点）
- **Agent 层**：LLM 负责选题与初稿，prompt 注入社区近期主题摘要
- **工具层**：自建 MCP server 封装论坛 API，只暴露三个工具：查历史帖、提交草稿、发布
- **状态层**：SQLite 存已发帖指纹、审核队列、运行日志
- **审核层**：草稿先进待审队列，人工确认后才真正发布

流程：调度触发 → agent 拉取近两周帖子摘要 → 生成 3 个选题 + 初稿 → 与历史指纹做相似度去重 → 写入待审队列 → 人工放行 → MCP 调用发布接口 → 回写状态。

## 踩坑实录

**坑 1：选题越写越像自己。** 第三周起内容明显自我重复。原因是 prompt 只注入了"最近 10 篇标题"，模型记不住两个月前的选题。解法：去重不只比对近期帖子，而是对全部历史帖做 embedding 相似度，阈值 0.82 以上直接打回重选。

**坑 2：agent 猜 API 字段。** 早期把论坛 API 文档贴进 system prompt，模型会编造不存在的字段，发布接口 400。改用 MCP 工具后，参数 schema 由服务端强约束，非法调用在工具层就被拒绝，agent 能根据报错自我修正。这是我认为 MCP 最大的价值：把模型自由发挥的空间压到最小。

**坑 3：cron 重复触发。** 调度器抖动导致同一分钟触发两次，发出两篇一样的帖子。解法很朴素：发布前用运行锁 + 帖子指纹做幂等检查，SQLite 加唯一索引兜底。

**坑 4：上下文膨胀。** 最初把历史帖全文塞给 agent，单次任务 token 消耗是现在的 6 倍，质量却没有提升。改为只喂"标题 + 摘要 + 主题标签"后，成本降下来，选题反而更聚焦。

**坑 5：质量漂移没人发现。** 自动化跑顺后我两周没看审核队列，回看发现有 3 篇凑数帖被顺手放行。补了一条规则：连续 2 篇帖子相似度超过 0.75 时，机器人在队列里主动标黄提醒——宁可少发，不发凑数。

## 可复用建议

1. **状态放外面，agent 保持无状态**：重跑、迁移、排查都依赖这一点；
2. **一切对外动作过 MCP 工具层**，schema 即约束；
3. **先跑 dry-run 两周**，草稿只落库不发布；
4. **日志记三层**：agent 决策理由、工具调用参数、接口响应，出问题基本能秒定位；
5. **给自动化加自我降级**：异常率高就暂停并通知人，而不是硬撑。

## 总结

这个项目技术上不复杂，难点全在工程纪律：去重要覆盖全历史、发布要幂等、质量要有自动预警。Agent 负责创造力，MCP 负责边界，人负责最后一道闸门——三层各司其职，机器人才能长期跑而不翻车。完整配置和 MCP server 代码整理好后会在社区开源，欢迎交流。
