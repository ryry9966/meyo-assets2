过去一年，"个人智能体"从发布会 demo 变成了真产品：OpenAI 的 Operator、Anthropic 的 computer use、一度刷屏的 Manus，再加上手机厂商塞进系统里的各种"一句话订机票"。愿景高度一致：你下指令，AI 替你点外卖、比价、下单、填报销。可真跑起来，大家撞上同一个尴尬事实——智能体最想替你用的那些 App，恰恰最不愿意开门：风控拦截、接口不给、条款明令禁止自动化操作。这不是某一家平台的傲慢，而是整套商业模式与智能体逻辑的正面相撞。拆开来看，问题的结构比情绪有意思得多。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/67bdc7a7ed948467.png)

## 一、智能体到底想干什么

- **三种工作方式**：① 调官方 API——最稳，但绝大多数消费级 App 根本不提供；② 浏览器/GUI 操作——读屏、识别界面元素、模拟点击输入，Anthropic 的 computer use 和 Operator 走的都是这条路；③ 系统级意图接口——苹果的 App Intents、国产手机厂商的系统级智能体，让 App 主动向操作系统"申报"自己能做什么。
- **理想链路**："帮我订周五最便宜的那班机票，出票后同步进日程。"Agent 拆解任务、跨平台比价、填表、支付，人只做最后一步确认。
- **卡点也在这里**：整条链路要求它"以你的身份"进入 App——而平台对一切"非本人、非手动"的操作，默认全部按敌人处理。

## 二、App 不开门的五堵墙

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/067a88794ff49e33.png)

1. **广告模型被拆台**。平台收入的大头来自"把人留住再卖曝光"，这是数千亿元规模的生意。Agent 是任务导向的：干完活就走，不刷信息流、不看推荐位。用户还在，注意力没了，广告库存直接缩水。
2. **推荐与定价权旁落**。排序、竞价、优惠券是平台控制交易路径的抓手。Agent 天然追求"全局最优"，会绕过推荐位、跨平台比价，动态定价和会员体系甚至可能被反向套利。
3. **风控分不清好蟹坏蟹**。反爬体系（设备指纹、验证码、行为检测）的假想敌是黄牛脚本与撞库工具。Agent 读屏、模拟点击走的通道和外挂是同一条，逐个甄别的误伤成本太高，一刀切最省事。
4. **责任没法算**。Agent 下错单、买错票、误支付，算谁的？支付授权、通讯录、位置信息经第三方转手，合规边界至今没有共识。
5. **数据护城河被截流**。用户行为数据是平台估值的核心资产。Agent 化之后，调用关系和决策依据先经过模型方，平台有从"超级 App"降级成"被调用零件"的风险——没有平台会主动给自己降级。

用龙虾的话说：谁都不想让自己的钳子，变成别人壳上的配件。

## 三、这堵墙，历史上砌过很多次

- 2008 年，淘宝屏蔽百度爬虫，对外说法是保护交易安全，实际效果是防止交易入口外移；
- 微信与淘宝互相封禁外链多年，直到监管推动"互联互通"才逐步松绑；
- 大量服务不提供完整 Web 版、强制跳转 App，逻辑同源：**入口即命脉**。
- 历史经验是：封堵几乎从未真正拦住范式转移——从 Web 到 App 到小程序，入口一路迁移；通常先开门的，是存量焦虑、急需增量的一方。今天的 App 面对 Agent，处境和当年的平台一模一样，只是角色对调了。

## 四、门缝正从三个方向被撬开

1. **协议层**：Anthropic 在 2024 年底发布 MCP（Model Context Protocol），OpenAI 随后宣布支持；Google 推出 A2A 协议，又联合多家支付机构推动 AP2（Agent Payments Protocol）。思路很清晰：别翻墙，走正门——平台把能力封装成受控接口，保留计费、审计和抽成权。
2. **系统层**：手机厂商握有天然话语权。智能体做进 OS 之后，App 以标准意图接口对接系统，很难拒绝自己的操作系统。
3. **人机共驾的中间态**：Agent 把购物车备好、比价表列好，最后一步支付由人亲手点。平台半默许，因为每一单仍然是"人的订单"。这是当前最现实的落地姿势，也是最容易被低估的过渡方案。
4. 此外还有互操作性监管的外部推力（如欧盟 DMA 对"守门人"平台开放接口的要求），相当于给墙开法定消防门——慢，但方向明确。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/5cda28757f624167.png)

1. **别急着欢呼，也别急着宣判**。门开不开，本质是利益分配问题，不是纯技术问题。技术只决定敲门的方式，协议与分成才决定开不开门。历史上"颠覆入口"的故事，最后大多以"重新谈分成"收场。
2. **判断一款 Agent 产品靠不靠谱，先看它走哪条通道**。要官方 API、走意图接口的是正路；靠模拟点击硬闯的，随时可能被封——而且被封的不是 Agent，是你的账号。再流畅的演示，也抵不过平台一次风控升级。
3. **对开发者：尽早准备"被调用"**。把服务封装成干净的工具接口，MCP 是个低成本起点。下一轮流量分发，入口可能不再是应用商店，而是别人的工具列表。先出现在工具列表里，比先做出漂亮界面更值钱。

智能体与 App 的关系，大概率不是谁取代谁，而是重新谈一次分成。门总会开，但钥匙不会白给——这一点，把推荐算法玩到极致的平台们，比谁都清楚。
