36kr 一篇《AI把整个软件生态打成筛子》最近刷了屏。核心论点并不新鲜：从 Cursor、v0 到 Devin、Claude Code，AI 正在把「需求 → 代码 → 上线」这条流水线逐环压缩。但结论足够扎心——站在流水线中间、号称「前后端通吃」的全栈开发者，成了被筛得最狠的一批。这轮冲击到底是真危机，还是标题党的余温？值得拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/c748eae714987033.png)

## 一、筛子在筛什么：软件分工链被逐环压缩

传统软件工程是一条接力长链：

1. 产品经理定义需求
2. 设计师出交互稿
3. 前端还原 UI
4. 后端写业务逻辑与接口
5. 测试保证质量
6. 运维部署上线

AI 在每个环节的渗透现状：

- **设计**：v0、Figma AI 能从一段文字描述直接生成可交互界面
- **前端**：Cursor / Copilot 覆盖了大量样板代码，GitHub 的研究显示使用 Copilot 后特定任务完成速度提升约 55%
- **后端**：CRUD、ORM、鉴权中间件这类高模式化代码，LLM 的产出质量已经「能打」
- **测试**：单测生成、用例补全逐渐成为 IDE 标配
- **运维**：IaC 脚本、CI/CD 配置、日志分析，AI 都能插一脚

真正的变化不是「AI 取代某个岗位」，而是：**每个环节的体力活被抽走，环节之间的墙被打薄**。原来五个人接力三周的活，现在一个人带着 AI 一周跑通。被打薄的，恰恰是「全栈」这个岗位赖以存在的理由。

## 二、为什么全栈最先「漏下去」：三个机制

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/6dd16f0fd77e0cf3.png)

**机制一：全栈的本质是「广而浅」，正撞在 LLM 的强项上。**
全栈的核心价值是覆盖面广、单点深度可妥协、靠检索与学习快速补齐。而 LLM 恰恰是「广而浅」之王——训练语料就是 GitHub 上海量的全栈式项目，样板代码和常见框架用法的模式重复度极高。过去你花五年攒下的「会 React 也会 Spring」，如今和模型之间只隔一个 prompt。

**机制二：最小可行团队正在缩水。**
Y Combinator 的 Garry Tan 透露，W25 批次约四分之一的初创公司，95% 的代码由 AI 生成；微软 CEO 纳德拉称其仓库中约 20%~30% 的新代码由 AI 编写；谷歌 CEO 皮查伊也说过超过 25% 的新代码由 AI 生成。当一个 idea 只需要一两个「判断者 + AI」就能跑起来，「全栈工程师编制」自然缩编。

**机制三：需求翻译层被直接穿透。**
过去是老板说话 → PM 写 PRD → 工程师翻译成代码，两层翻译、层层损耗。现在是自然语言 → AI → 原型，第一层翻译正在消失。全栈开发者原本身处翻译层的核心位置，如今位置本身被动摇了。

## 三、留在筛面上的是什么：四种正在升值的能力

筛子滤掉的是「可被 prompt 化的重复劳动」，留在筛面上的东西反而变贵了：

1. **架构与权衡能力**：AI 能给你十个能跑的方案，但「选哪个、为什么、三年后谁付代价」需要人拍板。缓存上 Redis 还是本地内存、服务拆多细，答案依赖业务上下文，模型给不出承诺。
2. **验证能力**：AI 生成的代码越多，「判断对不对」越稀缺。单测、集成测试、混沌工程、线上观测构成了 AI 输出的质检关。圈内开始流行一句话：AI 让写代码变便宜，让 review 变贵。
3. **领域知识**：懂支付清算规则、懂医疗数据合规、懂供应链库存模型的工程师，AI 只能当副驾驶——业务里全是写不进文档的隐性知识，方向盘还在人手里。
4. **产品 taste**：原型可以一键生成十个，但「哪个值得押三个月」的判断力没有贬值。当 demo 的边际成本趋近于零，选择比生产值钱。

## 四、历史不会重演，但会押韵

把时间轴拉长，「生态被打成筛子」至少发生过三轮：

- **编译器普及（1950s）**：写汇编的人一度恐慌，结果软件需求暴涨，程序员数量指数级增长——抽象层上移，产能被释放。
- **云计算与 DevOps（2010s）**：传统运维岗位收缩，但 SRE、平台工程这些更贵的岗位诞生。死掉的从来不是岗位，而是岗位里的手工部分。
- **开源与 SaaS 兴起（2010s）**：「会写代码」本身不再稀缺，稀缺的是把代码组织成可维护产品的能力。

规律是一致的：**技术打碎的从来不是职业，而是职业中的「翻译层」和「体力层」**。每打碎一次，剩余部分就向「判断、设计、负责」三件事集中。

## 五、冷思考：三条务实建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-23/642d0bb1755614bb.png)

1. **把熟练度预算换成判断力预算**。过去刷框架 API、背八股的时间，挪到系统设计、故障复盘和 code review 的较真程度上。AI 时代，「能看出 AI 错在哪」比「能写对」更值钱——毕竟 AI 不会替你背线上事故的锅。
2. **做 π 型人，别做一横型人**。全栈视野保留（知道每个环节的坑在哪），但至少扎深一根「领域 + 技术」交叉的支柱。AI 负责补齐广度，人负责深度。
3. **搭建自己的验证闭环**。无论团队大小，把自动化测试、监控告警、灰度发布练成肌肉记忆。当 AI 一天生成的代码超过你过去一个月的量，验证体系就是护城河，也是你敢让 AI 放量干活的前提。

最后一句实话：筛子不可怕，可怕的是站在筛孔正上方还觉得风光。与其抱怨孔径，不如主动挪位置。
