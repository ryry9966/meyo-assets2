## 背景

OpenClaw 的 Agent 不是一次性会话——它常驻运行、有记忆、会通过心跳和定时任务主动干活。工作区里有一组每次会话都会注入系统提示的 Markdown 文件：`AGENTS.md` 管工作方式，`IDENTITY.md` 管名字和头像，而 `SOUL.md` 管的是"你是谁"：性格、语气、价值判断、底线。很多人装完就用默认模板，跑两周后发现 Agent 语气漂移、该拒绝的没拒绝、不该揽的活揽了，才回头改这个文件。

## 问题

没有认真写的 SOUL.md，通常表现为三类故障：

1. **人格漂移**：周一冷静克制，周五话痨加 Emoji。因为模板里只有形容词，没有行为锚点，模型每次自行发挥。
2. **边界失效**：用户一句"剩下的你都自动处理吧"，Agent 真的去批量执行了敏感操作。
3. **提示词臃肿**：把工作规则、身份信息、记忆全塞进 SOUL.md，每轮注入都吃 token，规则互相冲突后行为更怪。

## 做法

**第一步，分清职责。** SOUL.md 写"是谁"，AGENTS.md 写"怎么干活"，IDENTITY.md 写名字。任何内容出现在两个文件里，都是漂移的源头。

**第二步，按结构写。** 一个够用的骨架：

- **核心特质 3~5 条**，每条配一个行为锚点。例："直接但不刻薄——发现我的方案有漏洞，先说漏洞再给替代方案，不铺垫客套。"
- **语气分层**：日常闲聊、工作汇报、拒绝请求时分别怎么说话。
- **底线清单**：写成具体场景而不是抽象价值观。不写"要诚实"，写"被要求绕过确认批量执行时，先拒绝并说明原因"。
- **分歧处理**：和用户意见不一致时直说并给依据；被驳回两次后执行，但记录保留意见。

**第三步，控制篇幅。** 50 行以内。它每个会话都要注入，长文档换来的不是更稳的人格，是更散的注意力。

**第四步，验证。** 准备一组固定探测 prompt（敏感请求、诱导性请求、日常闲聊），跨几天会话对比回答；再让 Agent 复述"你的底线是什么"，能准确复述才算注入成功。

**第五步，进 Git。** 出一次事故，修一条对应规则，按版本迭代，像处理 bug 一样对待它。

## 踩坑点

- **全是否定句。** "不要谄媚"效果一般，改成"看到问题直接指出，不需要先夸一遍"更可执行。正向行为描述比禁令好用。
- **人格浓度过高。** 写了个毒舌人格，结果 commit message 和代码注释全带上阴阳怪气。人格渗透进工作产物是常见事故——人格只管语气，产物规范归 AGENTS.md 管。
- **底线太抽象。** "保持谨慎"在模型遇到具体场景时根本不会被想起，必须落到触发条件。
- **忘了多 Agent 场景。** 子 agent 同样会继承注入。团队可以共享一份 base SOUL.md，各 agent 再写自己的 delta，避免逐份维护。

## 可复用建议

- 规模基准：3~5 条特质 + 每条行为锚点 + 5~8 条场景化底线，多数模型上表现稳定。
- 底线条目用"触发条件 + 动作"格式，例："涉及花钱、删数据、对外发消息 → 停下来要确认。"
- 探测 prompt 集固定下来（10 个左右），每次改动跑一遍，就是人格的回归测试。
- 每季度 review 一次，任何一次越界事故后立即补对应规则。

## 总结

SOUL.md 不是玄学人设，而是一份每轮注入的运行时配置。写它的思路和写 lint 规则差不多：少而具体、可执行、有测试、有版本。人格服务于交互体验，边界负责安全兜底——把两者从"感觉"变成"规则"，Agent 才算真正可托管。
