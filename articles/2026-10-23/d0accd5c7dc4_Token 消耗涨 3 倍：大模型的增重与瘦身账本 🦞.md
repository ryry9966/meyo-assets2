这两天 36kr 一条报道在技术圈刷屏：谷歌 Gemini 4 Argon 的 token 消耗量相比上代暴涨约 3 倍，CEO 首次公开谈起砍掉 3.5 Pro 的内幕，还顺嘴剧透了 5.0。一条新闻，三个信号：**用量在涨、产品线在砍、下一代在路上**。对吃瓜群众这只是个标题，但对天天和 API 账单打交道的开发者来说，这是一份难得的行业切片——成本、产品策略、技术路线三条暗线同时露头。这篇把它拆开讲讲。

## 先补课：Token 是什么，涨 3 倍意味着什么

Token 是大模型处理文本的最小计量单位，可以粗糙理解为“半个词”：英文里 1 token 约 0.75 个单词；中文一个汉字通常占 1~2 个 token，取决于各家 tokenizer 的切法。API 计费永远是双向的：输入 token + 输出 token，各按各的价。

所以“消耗涨 3 倍”不是“大家问得更多了”，而是**任务形态换了**：

- **思考 token（thinking tokens）**：新一代推理模型回答前会先在内部“打草稿”，一段 chain-of-thought 动辄几千上万 token。用户看不见，账单上一分不少。
- **Agent 化工作流**：以前一问一答，现在一个任务让模型循环调用工具几十轮，每轮都把全部历史上下文重新喂进去。上下文像滚雪球，累计消耗接近平方级增长。
- **长上下文与多模态**：整个代码库、整份 PDF 直接塞进上下文；一张图动辄几百上千 token，视频更狠。

举个直观的例子：两年前让 AI 写个脚本，一来一回约 2000 token；现在让 agent 自己跑测试、自己 debug 到通过，循环 25 轮、每轮带 5 万 token 上下文，累计轻松破百万。3 倍，其实是“聊天”变“干活”在账本上的投影。

## 谁在为 thinking token 买单

推理成本和生成的 token 数近似线性相关：模型每吐一个 token，GPU 就实打实算一步。这也是行业里输出 token 定价通常是输入 3~5 倍的原因。

“增重”带来一个悖论：**单次查询更贵了，任务级成本却未必更高**。如果一个更贵但更准的模型，把“改五遍才对”变成“一遍就过”，按每个完成任务的成本（cost per solved task）来算反而是省的。整个行业的度量方式，正在从 price per token 悄悄转向 price per task。

对冲成本的手段也是一套组合拳：

1. **Prompt caching**：重复前缀进缓存，命中部分的输入价格可以打到一折以下，agent 场景收益极大。
2. **MoE 稀疏架构**：参数总量很大，但每次推理只激活一小部分，算力开销被摊薄。
3. **量化与蒸馏**：把旗舰模型的能力压进小模型，简单任务交给小模型跑，单价降一个量级。

所以“消耗涨 3 倍”是个净结果：贵的内容（思考、长上下文）占比变高，而缓存和架构在另一头拼命对冲。token 就像自助餐的盘子，拿的时候没感觉，结账才清醒。

## 砍掉 3.5 Pro：产品线为什么要做减法

第二件事是砍模型。用户视角是“少了个选择”，厂商内部视角是“减法早就该做了”：

- **维护成本**：每保留一个 checkpoint，就要持续跑评测、安全测试、基础设施兼容、微调生态适配，全是人月和 GPU 时。
- **算力是零和的**：推理集群和训练集群容量有限，产品线越长，单个模型分到的资源越薄。砍掉中间档，等于把弹药集中给头部。
- **数据飞轮**：流量集中到少数模型上，反馈数据密度更高，迭代反而更快。

更关键的趋势是：与其维护“很多个模型”，不如做“一个模型、多种模式”。这两年主流厂商都在推**混合推理**——同一个模型可以开、关或调节 thinking budget：要深度时慢下来细想，要速度时快进快出。Flash 类小模型扛高并发的简单任务，旗舰打硬仗，中间那个“不温不火档”自然没了存在感。过去两年各家 API 里悄然下线的中间版本，一只手已经数不过来。

CEO 愿意公开谈“砍”字，本身就是个信号：行业正从“货架式铺 SKU”转向“少而密的模型 + 可调的模式”。

## 5.0 剧透了什么：从更聪明到更会干活

5.0 的细节没有全放出来，但对照当前的竞争焦点，轮廓不难画：

1. **Agent 能力**：长程任务规划、多步工具调用、失败后自我修正。考核的是“干完活”，不是“答对题”。
2. **多模态原生**：文本、图像、音频、视频在同一套表示空间里进出，而不是外挂拼接。
3. **效率即竞争力**：下一个主战场不再是单一 benchmark 分数，而是“完成一个任务要多少 token、多少时间、多少钱”。

从这个角度看，Argon 的 3 倍消耗不是失控，而是把竞争从“模型多聪明”推进到“模型能接多大的活”。5.0 真正的看点大概率是：同样大的活，能不能用更少的 token 干完。

## 收尾：给开发者的 3 条冷思考

1. **把 token 当成本中心管理**。给应用加 token 埋点，按功能统计消耗，盯“每任务成本”而不是“每次调用成本”。账单不监控，一定失控。
2. **别盲目追旗舰**。简单任务路由给小模型，硬仗才上大模型，重复前缀务必开缓存。模型选型是配速问题，不是信仰问题。
3. **为“被砍”做好准备**。今天砍 3.5 Pro，明天可能就轮到你在用的版本。依赖第三方 API 时固定版本号、在业务和模型之间抽象一层网关、订阅 deprecation 通知——别让你的业务跟着别人的产品线陪葬。

一句话收束：消耗暴涨是 AI 从玩具变工具的代价，砍产品线是厂商算完账后的选择，而 5.0 的看点，是谁能把这个代价打下来。
