## 背景

社区的每周精选帖过去全靠人肉：翻 issue、看讨论区、汇总、排版，一轮约 40 分钟，还经常断更。于是决定把流程交给跑在 OpenClaw 上的 agent：定时抓取本周动态，生成草稿，人工确认后自动发帖。

## 问题定义

动手前明确了三条硬性要求：

1. **内容可溯源**——不能出现任何编造的链接或数据；
2. **发布可控**——写权限最小化，默认 dry-run；
3. **失败可重试**——重复执行不能产生重复帖。

这三条后来分别对应了三个踩得最疼的坑，见下文。

## 架构

整条链路拆成五段，agent 只负责中间的"成稿"：

> 定时触发（cron 插件）→ 采集（脚本拉 release / 新话题，落 JSON）→ 起草（agent 读采集结果 + 样式模板）→ 审核（草稿推到内部频道，人工确认）→ 发布（MCP 工具调论坛 API）

关键决策：**不让 agent 直接持有论坛写权限**。另写了一个百来行的 MCP server，只暴露 `list_topics` 和 `create_post` 两个工具；`create_post` 默认 dry-run，带上确认参数才真正写入。token 用独立小号，权限只够发帖。

## 实施步骤

1. 采集脚本独立于 agent，输出固定 schema 的 JSON，每条带来源 URL；
2. 起草 prompt 里写死约束：只允许引用采集 JSON 中出现的链接，禁止自行补充；
3. 用内容哈希做幂等键，发布前查重；
4. cron 任务加文件锁，防止上一轮没跑完又起一轮；
5. 全程结构化日志，token 打码。

## 踩坑实录

- **链接幻觉**：前两版 agent 会"补"出似是而非的 issue 链接。改成"链接白名单来自采集结果"后才稳定，prompt 语气怎么调都没用，必须靠结构约束。
- **代码块炸排版**：草稿里嵌套 code fence 导致论坛渲染错乱，发布前加了一道 fence 归一化。
- **重试 = 重复帖**：一次论坛接口超时后重跑，发了两条一样的帖子。幂等键是事后补的——建议第一天就做。
- **风格漂移**：agent 爱加 emoji 和口号式收尾。把社区既有精选帖当 few-shot 塞进模板，并明确"禁止营销腔"。
- **频率限制**：连发多条触发限流，补了指数退避和条间间隔。

## 可复用建议

- 读写权限分离、写 token 最小化，是这类机器人的第一条安全线；
- 公开发布前保留人工确认，跑稳一个月再考虑放权；
- 采集与生成解耦：采集挂了不影响重发，生成挂了不丢数据；
- prompt 和模板进版本库，改样式能 diff、能回滚。

## 总结

机器人现在每周稳定跑一次，人工环节只剩"看一眼、点确认"，单次成本不到 5 分钟。最大的收获不是省时间，而是把"内容可信"变成了可执行的结构约束：来源白名单 + 幂等键 + dry-run，比反复调 prompt 语气有效得多。有同类需求的话，建议从"只读采集 + 人工发布"起步，写权限最后再接。
