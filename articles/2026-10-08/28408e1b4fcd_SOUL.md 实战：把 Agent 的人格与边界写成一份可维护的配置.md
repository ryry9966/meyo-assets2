## 背景

OpenClaw 的 Agent 配置里有一组 Markdown 身份文件：`AGENTS.md` 管操作规程，`TOOLS.md` 管工具用法，而 `SOUL.md` 管"你是谁"——人格、语气、价值取向和行为边界。很多人跑通工作流后把它当装饰，写两行就丢在那。实际用下来，这份文件对长期会话体验的影响，比大多数 prompt 调优都大。

## 问题

没有认真维护 SOUL.md 的 Agent，通常有三类症状：

1. **人格漂移**。长会话或换通道后语气忽冷忽热，昨天还简洁克制，今天满屏 emoji。
2. **边界模糊**。该确认的没确认（比如不可逆操作前不多问一句），不该插手的乱插手。
3. **形容词失效**。写了"专业、友好、高效"，模型无从执行，只能输出通用客服腔。

本质原因：SOUL.md 会在会话中被反复注入，它不是简介，而是持续生效的行为约束。写得含糊，约束就等于没写。

## 做法

社区里几个跑得稳的实例，写法大致收敛成这个骨架：

```markdown
# 我是谁
一两句话，身份定位，不写故事。

# 语气与表达
用可验证的行为描述。例如："默认中文，句子短，
先给结论后给理由，不用排比句和感叹号。"

# 原则
3~5 条，每条一句话，宁缺毋滥。

# 边界（硬性）
明确"不做清单"：不可逆操作前需二次确认；
不输出密钥；不冒充真人；超出能力时直说。

# 与其他文件的关系
操作规程去 AGENTS.md 找，本文件只管人格与底线。
```

几条经验：

- **控制在 60~100 行以内**。这份文件每个会话都进上下文，写长了反而稀释关键约束。
- **行为化描述**。"说人话、结论前置"比"专业友好"可执行得多。
- **边界用否定式明确列出**。模型对"不要做 X"的遵循度，明显高于"要做个有分寸的助手"。
- **当代码管理**：进 git，改动写 changelog，配一组固定的回归 prompt（10 条典型提问）验证改动前后的行为差异。

## 踩坑点

- **写成了小作文**。有人写了 300 行"成长经历"，人格没立住，关键边界反而被淹没。人格靠一致性，不靠篇幅。
- **和 AGENTS.md 打架**。SOUL.md 写"永远不执行删除"，AGENTS.md 流程里又有清理步骤，模型在两者间随机站队。原则：SOUL.md 管人格与底线，操作细节一律外移。
- **过约束**。语气限得太死，Agent 会变机械，甚至频繁拒绝正常请求。边界只写真正不可妥协的条目。
- **写入敏感信息**。SOUL.md 是进上下文的，别放 API key、内部地址。
- **改完立刻期待变脸**。已有会话受历史上下文影响，验证人格调整要用全新会话跑回归集。

## 可复用建议

1. 新实例先用 10 行极简 SOUL.md 跑一周，把不满意的具体对话记下来，再针对性补条目——从真实偏差出发，别凭空设计人格。
2. 每个条目后附一句"为什么"，方便半年后自己或接手的人判断该不该改。
3. 多人共用的 Agent，SOUL.md 变更走 PR 评审，人格也算基础设施。
4. 定期用"诱导越界"的 prompt 主动测试边界，而不是等出事再补。

## 总结

SOUL.md 的价值不在"让 Agent 更像人"，而在把散落各处的语气要求和底线约束，收敛成一个可版本化、可回归测试的单一来源。把它当配置代码对待：短、具体、有变更记录。人格是长期一致性堆出来的，不是一次写成的大文案。
