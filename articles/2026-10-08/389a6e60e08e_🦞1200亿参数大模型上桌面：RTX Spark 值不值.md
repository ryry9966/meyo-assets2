36kr 报道了“首款 RTX Spark 电脑开卖”的消息：一台 Mac mini 体积的桌面主机，官方宣称可以本地运行 1200 亿参数的大模型。过去想跑这种规模的模型，基本只有两条路——租云端 GPU，或者堆上多张几万元的专业显卡。这台巴掌大的机器凭什么做到？本文把它的原理、瓶颈和适合谁，一次拆清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/49aeb52dec1815d0.png)

## 巴掌大的“AI 工作站”，到底是什么

- 这类主机的核心是 NVIDIA 的 GB10 Grace Blackwell 超级芯片：20 核 ARM CPU 与 Blackwell 架构 GPU 通过片内互联封在同一颗芯片系统里。它的前身是年初发布的 Project DIGITS 概念机，年中更名 DGX Spark，如今终于从 PPT 走到了货架，华硕、宏碁等合作厂商的同源主机陆续上市，海外定价大致在 3000~4000 美元档。
- 一组后面会用到的关键规格：
  - AI 算力：约 1 PFLOP（FP4 精度）
  - 统一内存：128GB LPDDR5x，CPU 与 GPU 共享
  - 内存带宽：约 273 GB/s（记住这个数，它是后面故事的主角）
  - 网络：ConnectX-7 接口，两台并联可跑更大模型（官方口径最高 4050 亿参数）
  - 整机功耗上限约 240W，与一台高性能游戏本相当
- 一句话定位：它不是游戏机，而是一台“数据不出域”的本地 AI 开发机。

## 普通显卡为什么跑不动 1200 亿参数

大模型推理的第一道门槛不是算力，是显存容量。粗算公式：

显存需求 ≈ 参数量 × 每参数字节数 + KV Cache + 运行开销

- 1200 亿参数用 FP4 量化（每参数 0.5 字节），光权重就约 60GB，加上上下文缓存和系统开销，实际要准备 90GB 以上；
- KV Cache 是注意力机制为上下文留的“工作草稿”，上下文越长占用越大，所以长文本推理远比看起来吃内存；
- 旗舰游戏卡 RTX 4090 显存 24GB、RTX 5090 也就 32GB，连零头都装不下；
- 云 GPU 或多卡集群当然可行，但成本、数据传输和运维复杂度都上来了。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/4d1057024d53ec30.png)

RTX Spark 的解法是统一内存（unified memory）：CPU 和 GPU 共享同一个 128GB 内存池，GPU 可直接寻址全部容量，“模型装不进显存”这个问题在硬件层面被消掉——只要模型总量不超 128GB。这个思路也解释了为什么过去一年显卡厂商疯狂堆显存，而 Mac 凭统一内存意外成了本地推理的香饽饽。另一个关键词是 FP4：Blackwell 架构原生支持 4bit 浮点，把每个参数压到半个字节，1 PFLOP 的账面算力由此而来。但代价同样藏在规格里：LPDDR5x 是低功耗内存，带宽只有 273 GB/s。

## 能跑 ≠ 跑得快：带宽才是隐形天花板

- LLM 逐 token 生成是典型的访存受限（memory-bandwidth bound）任务：每生成一个 token，几乎要把全部权重从内存过一遍。预填充（prefill）阶段吃算力，它 1 PFLOP 不虚；解码（decode）阶段吃带宽，这才是它被诟病的地方。在 GPU 世界里，带宽就是收银台——容量再大，排队结账也得慢慢来。
- 估算速度上限有个简单公式：token/s ≈ 内存带宽 ÷ 权重体积。273 ÷ 60 ≈ 每秒 4~5 个 token，能用，但谈不上流畅；
- 对比参考：Mac Studio 高配带宽 800GB/s 以上，RTX 5090 单卡约 1.8TB/s，差距立现；
- 反过来，跑 8B~14B 的量化小模型（做 Agent、RAG、代码助手）能到每秒几十 token，32B 也能保住十几 token/s；
- 所以合理用法是：拿 120B 模型做“效果行不行”的离线验证，日常工作负载交给小模型加检索增强。

## 适合谁买，谁别碰：一个判断框架

适合：

- 做本地部署、量化、LoRA 微调实验的工程师，128GB 内存足够把整条推理链路拆开折腾；
- 医疗、法务、金融等数据不能出内网的团队——这是它相对云 API 最硬的理由；
- 离线或弱网场景的边缘部署，比如工厂、船舶、野外科研站点；
- 想系统学习大模型底层运作的学习者，把它当一台可反复拆装的“AI 实验台”。

不适合：

- 只调 API 做应用层开发的团队，云服务按量付费通常便宜得多；
- 要撑高并发在线服务的公司，它的吞吐撑不起生产流量；
- 游戏玩家，它压根不是为帧率设计的。

横向对比一下替代方案：租 H100 灵活但数据要出门；Mac Studio 统一内存更大、带宽更高，但工具链偏 MLX，CUDA 生态的训练与部署方案不如它成熟；RTX Spark 真正的护城河是 NVIDIA 软件栈——CUDA、NIM 容器、DGX 系统加上开箱即用的推理框架，把部署门槛压得很低。

## 收尾：三条冷思考

1. 买前先算两个数：显存（统一内存）容量决定“能不能跑”，内存带宽决定“跑多快”。token/s ≈ 带宽 ÷ 权重 这条公式，能帮你过滤掉绝大多数营销话术。
2. 看重软件生态的复利。硬件参数会被下一代芯片刷新，但 CUDA 生态、模型仓库和部署工具链的积累，是短期攒机方案追不上的。
3. 想清楚你是“用 AI”还是“做 AI”。前者，API 几乎总是更划算；后者，你买的不是跑分，而是数据不出门、随时可折腾、电费只有几百瓦的私有实验台。
