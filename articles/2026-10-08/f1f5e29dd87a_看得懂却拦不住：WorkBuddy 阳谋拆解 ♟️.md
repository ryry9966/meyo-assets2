最近 36kr 一条关于 WorkBuddy 的讨论被顶上热搜，评论区出现频率最高的词是"阳谋无解"。所谓阳谋，就是打法完全公开：每一步棋、每一个目的都摆在明面上，对手看得懂、甚至抄得走，但就是拦不住。AI 工作助手这个品类，为什么特别容易打出阳谋？"无解"到底是事实判断，还是情绪判断？这篇把它拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/ef5f6a43684ea194.png)

## WorkBuddy 在做什么：把"卖工具"换成"卖结果"

从公开信息和社区讨论看，WorkBuddy 属于 AI 工作助手（Agent for work）一类产品：你用自然语言交代任务，它自己理解、拆解、调用工具、交付成品。技术上这条 pipeline 大致是——

- LLM 负责意图理解和任务拆解；
- function calling / tool use 去操作日历、文档、邮件、表格这些既有软件接口；
- RAG 挂接企业与个人知识库，保证产出有出处；
- 多步规划（planning）把长任务串成流水线。

真正值得注意的不是技术，而是商业含义：传统办公软件卖"工具"，按席位收订阅费，省的是你的操作时间；AI 工作助手卖"结果"，近似于出售一份数字劳动力。价值锚点一换，定价逻辑、增长逻辑、护城河逻辑全都要重写——阳谋就藏在这场重写里。

## 阳谋的三层结构：明牌、飞轮、锁定

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/48f4f002333f4537.png)

外界普遍把这套打法总结为三层，每一层都公开：

1. **第一层，明牌抢入口。** 产品先做到"体验好到不像这个价格"，用低价甚至免费，把用户每天最高频的工作任务迁进自己的界面。它没打算藏，也没法藏——入口之争本来就只能明着打。
2. **第二层，数据飞轮。** 任务越多样 → 模型与工作流被打磨得越充分 → 交付质量越高 → 用户越多、任务越多样。这是典型的 flywheel effect，亚马逊和特斯拉都讲过同款叙事。举个具体例子：同一份周报任务，第一周它生成得平庸，第三个月它已经记得你的汇报格式、老板偏好和项目进度——是使用本身在喂养它。
3. **第三层，生态位锁定。** 当它成为团队里"默认的那个助手"，任务历史、组织知识、流程习惯都沉淀在里面。这时迁移成本不再是"换个软件"，而是"搬一次家"，还要重新培训所有人。

阳谋的要害在于：三层结构每一层都写在脸上，但每一层的破解成本都随时间指数上升。第一层你今天就能模仿，第三层你可能永远追不上。

## 为什么"无解"：不是看不懂，而是算不过账

阳谋最气人的地方在于：它连攻略都公开了，你还是打不过——因为攻略里没附预算表。拆成三笔账：

- **算力账。** Agent 一次任务动辄几十次模型调用，推理成本是单轮对话的几十倍。明牌低价的本质，是用资本的钱补推理成本，比拼的是弹药库深度——这不是执行力问题，是资产负债表问题。
- **分发账。** 入口型产品吃渠道。同样的功能，背靠亿级流量池与独立获客，成本差一个数量级。
- **两难账。** 被挑战者跟进降价，立刻失血；不跟，用户流失。博弈论里这是典型的非对称成本困境：同一个动作，对一方是战术，对另一方是战略级放血。

历史上有现成对照：2010 年前后 360 用"免费杀毒"横扫收费杀毒厂商，打法人尽皆知，收费厂商依然全线溃败——不是不聪明，是成本结构根本不允许它们打同一场仗。

## 阳谋也有边界：三个可能的破绽

"无解"是营销感很强的词。工程上没有绝对的系统，只有还没找到的边界条件：

1. **现金流期限。** 飞轮转起来之前，烧钱速度必须扛得住。补贴是一场和时间的赛跑，窗口期是硬约束。
2. **模型层变数。** 飞轮的"质量"环节建立在底层模型能力上。一旦别的模型拉开代差，或者操作系统、浏览器、IM 这类真·超级入口亲自下场，整个结构都要重估。
3. **垂直纵深与合规。** 通用助手覆盖 80% 的通用任务，但法律、医疗、工业领域的 know-how 和私有数据它短期够不着；企业客户对"数据去了哪"极其敏感，私有化部署、审计留痕是重服务玩家的主场。

所以更准确的表述是：在"通用工作入口"这个主战场上接近无解；但战场换个维度，解法存在。

## 冷思考：三条给普通人和小团队的建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/e17906d02746e356.png)

1. **别在主航道对撞，去主航道够不着的浅滩。** 与其做一个"更便宜的通用助手"，不如选一个垂直场景，把交付质量做到不可替代——深度是通用玩家最慢长出来的能力。
2. **把数据和工作流当资产，别把订阅当依赖。** 无论用什么工具，让任务记录、流程模板、行业语料保持可导出、可迁移。护城河要挖在自己脚下，而不是租借在别人的产品里。
3. **学会骑在阳谋上。** 入口格局越清晰，入口之上的插件、集成、垂直 Agent 生态就越值钱。对抗明牌的最好方式，常常是加入它的生态，同时保留随时切换的能力——既吃红利，又不被锁死。

阳谋之所以叫阳谋，不是因为藏不住，而是因为摊开给你看，你也只能眼睁睁。看懂结构、认清边界、找对自己的生态位，是旁观者唯一能做的三件事。
