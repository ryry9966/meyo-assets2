## 背景

用 OpenClaw 挂一个 Agent 加 MCP 插件，把 GitHub release、论坛新帖、日报聚合后自动发到社区频道，这套流程很多小组都跑起来了。技术上跑通只是及格线，真正的分水岭在节奏：发得对不对、密不密、像不像有人在说话。见过不少自动化账号上线第一周就被群主请出去，问题不在内容，而在节奏。

## 问题：节奏出卖了你

暴露自动化的典型信号有四个：

1. **固定间隔**。cron 每 2 小时整点发一条，时间戳排得像一条直线。
2. **事件后秒回**。release 刚打 tag，帖子 3 秒后出现，正常人做不到。
3. **内容同构**。每条都以“📢 最新动态”开头，长度误差不超过 20 字。
4. **全天候在线**。凌晨三点照发，周末比工作日还勤快。

人不会有这些特征，所以一出现就被识别。

## 做法：四层节奏控制

我们给自己的发帖队列加了四层，效果比较稳：

**第一步，调度层加抖动。** 不用固定 cron，改成“目标时间 ± 30~90 分钟随机偏移”，且偏移量用非均匀分布（偏向整点后 10~40 分钟）。均匀随机同样不像人——人的行为是聚簇的。

**第二步，作息曲线。** 给队列配 posting window：工作日 9:00–22:30，周末 10:00–20:00。夜间事件只入队不发，窗口打开后按优先级补发或直接合并。

**第三步，合并降频。** 低价值事件（单次 commit、单个 issue 更新）不单独发帖，攒够阈值或到每日两个 digest 时间点合并成一条。只有 release、公告走即时通道，且触发后加 5–15 分钟随机延迟再发。

**第四步，内容去同构。** 准备 3~5 套措辞模板轮换，段落数、是否带表情、开头方式做随机化；同时把每条帖子的结构哈希（事件类型 + 关键字段）记入日志，24 小时内同哈希不重发。

## 踩坑点

- **时区**。服务器是 UTC，社区在 UTC+8，第一批“凌晨帖子”就是这么来的。所有时间配置必须显式声明时区。
- **幂等**。Agent 重启或 API 超时重试，同一内容发两遍。每条消息带幂等键，发帖前先查日志。
- **语义级重复**。改了措辞但内容相同的帖子绕过了 URL 去重，靠结构哈希补上。
- **抖动过头**。第一版随机间隔 1~6 小时，结果有时 40 分钟连发三条，有时一下午没动静，比固定间隔更显眼。改成“基础节奏 + 小幅抖动”才稳。
- **反馈回路缺失**。以为调完参数就稳了，直到有人连续 mute。现在每天统计负反馈数，超阈值自动降频。

## 可复用建议

- 把节奏参数（`max_per_day`、`quiet_hours`、`jitter_window`、`digest_times`）做成队列模块的一等配置，别散落在代码里。
- 新账号先跑一周 dry-run：所有帖子先发到审计频道人工过目，确认节奏曲线再放开。
- 想清楚一件事：控制节奏不是为了伪装成人类，而是为了不打扰。社区规则要求标注 bot 身份就老实标注。我们优化的是“发得少而准”，不是“骗过检测”。

## 总结

自动化发帖的价值是降噪，不是制造噪音。调好调度抖动、作息窗口、合并降频、内容变化这四层后，我们的发帖量降了约六成，负反馈基本归零。所谓“更像人”，秘诀其实很朴素：发得更少、更准、更合时宜。
