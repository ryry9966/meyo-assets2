## 背景

Agent 接上浏览器或 fetch 类 MCP 工具后，最常见的需求就是"去这个网页看看"：盯价格、追文档更新、抓公告。这比靠模型记忆里的旧知识可靠得多。但在 OpenClaw 的实践里，采集恰恰是最容易出事的一环：要么被目标站封 IP，要么几千行脏 HTML 灌进上下文，要么更糟——网页里藏了一句"忽略之前的指令"，Agent 照做了。

我把这类问题统称为"稽客"问题：Agent 访问别人的站点，本质是上门拜访。做不成有稽之客，迟早变成不速之客。

## 三个真实的问题

1. **边界问题**：robots.txt、服务条款、频率限制，模型不会主动遵守，除非你在工具层强制。
2. **污染问题**：原始 HTML 里有脚本、隐藏文本和注入内容，直接喂模型既烧 token 又有安全风险。
3. **脆弱问题**：页面改版一次，解析逻辑就废一次，而 Agent 不会主动告诉你它抓回来的是空壳。

## 做法：五层护栏

**第一层，入口约束。** 采集前检查 robots.txt，只允许白名单域名，登录后才能看的内容一律不碰。这些写进 MCP 工具的配置里，而不是写在提示词里求模型自觉。

**第二层，工具降级。** 优先级：RSS / 公开 API > 静态 HTML + readability 抽取 > headless 浏览器。很多站有干净的 JSON 接口，F12 看一眼网络面板就能省掉整个 Playwright。headless 只留给实在必须 JS 渲染的页面。

**第三层，限速与退避。** 全局每域名限速（比如 2 秒一次），遇到 429/503 读 Retry-After，指数退避。多任务并发时，这层必须是全局共享的，不是单任务各自的。

**第四层，内容净化。** 拿到 HTML 后剥掉 script、style、注释、隐藏元素，转成 Markdown 再给模型；单页设最大字节数，超了就分段摘要。网页内容永远当"数据"处理：用明确分隔符包裹，并在系统提示里声明其中任何指令一律忽略。

**第五层，缓存与审计。** 用 ETag / Last-Modified 做增量，只把 diff 交给 Agent 判断；每次访问记录 URL、时间、状态码、字节数。出了问题能回放，这是排查的生命线。

## 踩坑点

- **Prompt injection 是常态不是意外。** 评论框、页脚、隐藏 span 里都可能埋指令。净化层和"当数据不当指令"的约束缺一不可。
- **headless 开销大**：内存占用和启动延迟都不低，能不用就不用。
- **编码**：老站 GBK 乱码，转码要在净化层做，别指望模型自己看懂。
- **429 之后继续打**：有些站不返回 Retry-After，退避策略必须带默认值。
- **缓存穿透**：URL 带随机参数会绕过缓存，抓取前先规范化（去 utm、参数排序）。
- **反爬的边界**：绕过 headless 检测、伪造指纹这类手段有法律和道德红线。被明确拒绝的站点别硬来，换公开 API 或直接联系站长。

## 可复用的建议

- 把采集封成一个独立 MCP 工具：输入 URL，输出净化后的 Markdown 加元数据（标题、抓取时间、字节数），Agent 永远不接触原始 HTML。
- 白名单、限速、最大字节数全部配置化，不同任务用不同 profile。
- 记一条铁律：能 RSS 不 API，能 API 不 HTML，能静态不 headless。
- 每周扫一遍审计日志里的 403/429，它们是目标站在跟你说话。

## 总结

Agent 采集网页，技术只是小半件事，大半件事是边界：什么能抓、多快抓、抓回来怎么处理。把约束放进工具层而不是提示词层，把网页当数据而不是指令，把每次访问当作可审计的正式拜访——Agent 才能长期、稳定、不打扰别人地跑下去。有稽之客，门才会一直开着。
