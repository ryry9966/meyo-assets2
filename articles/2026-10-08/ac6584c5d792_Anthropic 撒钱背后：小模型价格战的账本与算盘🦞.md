Anthropic 发布新一代 Haiku 5.5，话题热度却不在跑分，而在价格与补贴：API 降价、免费额度、批量折扣一起上，36kr 直接用了「开始撒钱」这个说法。开发者社区一片「真香」，但也有人在问：卖 token 的生意，怎么就卷到倒贴了？这篇文章把「撒钱」背后的账本拆开看看——它撒的是什么、为什么撒得起、以及你我该怎么接住这波红利。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/be3e35e0a689a24b.png)

## 小模型，为什么突然成了主战场

- 大模型比的是能力上限，小模型比的是「单位成本下的够用」。写摘要、抽 JSON、路由请求、跑工具调用，这些高频动作不需要旗舰模型出场。
- Agent 改变了 token 消耗结构。一个人一天手工处理几百条任务，一个 agent 一天可以跑几万次调用，其中八成以上是「体力活」。行业主流做法是 model cascade（模型级联）：大模型负责规划与兜底，小模型负责执行。量的大头，落在小模型头上。
- 竞争格局早就摆好了：Google 的 Flash 系列、OpenAI 的 mini 系列、开源阵营的 DeepSeek 与 Qwen 小尺寸版本，都在抢「高吞吐、低成本」这一层。Haiku 是 Anthropic 产品线里最轻的一档，5.5 的方向也延续定位：更快、更便宜，重点补齐编码与工具调用这类 agent 高频场景。

一句话总结：旗舰模型决定品牌高度，小模型决定现金流和市场份额。战场转移到这里，不奇怪。

## 「撒钱」撒的到底是什么

把新闻里的各种动作拆开，其实是五种工具的组合拳：

1. **直接降价**：以公开定价为参照，Haiku 这一档历史上大致是「输入每百万 token 一美元上下、输出几美元」的量级，新一代继续下压，与 Flash、mini 贴身肉搏。
2. **免费额度与 credits**：给新用户、学生、初创团队送 token，把「第一次调用」的门槛降到零。
3. **Batch API 折扣**：非实时的离线批处理通常再打五折，适合数据清洗、批量评估这类任务。
4. **Prompt caching（提示词缓存）**：重复上下文（长 system prompt、固定知识库）命中缓存后，读取价格可以低一个数量级，官方口径约为原价的一折。
5. **各类计划与活动**：初创扶持、教育补贴、限免活动，本质都是把获客成本前置。

关键认知：你的真实成本不等于官价，而是「官价 × 你的流量结构」。同样接一个 Haiku，会用缓存和批处理的人，账单可能只有裸用者的几分之一。

## 推理生意的账本：为什么大厂敢亏钱卖 token

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/65faa0ffb806717b.png)

这笔账要从成本结构说起：

- **小模型的边际成本低**。参数少、KV cache 小、单卡吞吐高，摊到每个 token 上的算力成本远低于旗舰模型，降价空间天然更大。
- **利用率决定单位成本**。推理是典型的固定成本生意：GPU 折旧、电力、运维先花出去，机器跑得越满，单 token 成本越低。降价换量、量再摊薄成本，这是云计算行业玩了几十年的飞轮。
- **补贴的三个战略目的**：
  1. **抢开发者心智**。API 一旦写进生产代码，切换就有成本——prompt 要重调、eval 要重建、行为要做回归测试。现在便宜用我，以后你自然留在这。
  2. **卡位 agent 流量**。下一代最大的 token 消费者不是人，是 24 小时跑在服务器上的 agent。谁锁定这层流量，谁就拿到 AI 时代的「云用量」。
  3. **数据反馈飞轮**。真实生产流量会暴露长尾问题，反哺下一轮模型迭代。

历史上这不是新剧本：云计算早期的价格战、浏览器大战、移动支付补贴，都是「先烧钱换网络位置，再用生态变现」。云计算后来证明了一件事——降价不等于亏损，规模本身可以成为利润来源。当然，前提是有人替你扛住训练成本和研发投入，所以这一轮「撒钱」更像资本支撑下的圈地，而非零售促销。

## 对开发者：红利是真的，坑也是真的

**红利：**
- 原型验证成本趋近于零。以前跑一轮 eval 都要精打细算，现在可以放开跑，实验密度直接上一个台阶。
- Agent 项目的单位经济改善。原本「账算不平」的自动化任务，现在能算平了，一批场景会从「不值得做」变成「可以做」。

**陷阱：**
- **价格锚定效应**。补贴价不是终身价。把商业模式的盈亏线押在当前单价上，等于把地基建在别人随时会撤走的土地上。
- **隐性成本**。rate limit、并发上限、缓存未命中的长尾、失败重试，都会吃掉账面上的节省。
- **切换税随时间累积**。写在代码里的 prompt 风格、输出解析逻辑、评测基线，用得越久，迁移成本越高。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/5370d3a27e670638.png)

1. **用自己的工作负载做 benchmark，别只看厂商榜单。** 拿 100~500 条真实业务样本，把候选模型的质量、延迟、成本跑成一张对照表，比看十篇评测都有用。榜单是别人的业务，账单才是你的。
2. **架构上留好模型抽象层。** 统一接口、prompt 配置化、维护一套可随时复跑的 eval。做到这三点，红利期你可以随意换模型薅羊毛，风向变了也能在一天内完成切换。自由来自工程，不来自忠诚。
3. **算 TCO，不算单价。** 把 rate limit、缓存命中率、重试成本、甚至工程师调试时间都算进总拥有成本。把补贴期当作「建仓窗口」——用它把产品跑起来、把数据和流程沉淀下来，而不是把低价当成永久的商业前提。

撒钱的意义，不在于今天便宜了多少，而在于它标记了竞争重心的转移：行业从「谁的模型最聪明」，开始转向「谁的模型最划算地够用」。对开发者，这是难得的窗口期；对行业，这只是洗牌的开幕。窗口期的红利，从来只属于动手早的人。
