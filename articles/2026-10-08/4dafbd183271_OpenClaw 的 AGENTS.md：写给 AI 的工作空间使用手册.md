## 背景

OpenClaw 的 agent 每次会话启动时，都会把工作空间里的 `AGENTS.md` 读进上下文。它不是普通的 README，而是这个 AI 的"上岗手册"：我是谁、我在哪台机器上、哪些事能自己做、哪些事必须先问人。OpenClaw 的设计里，`SOUL.md` 管人格，`MEMORY.md` 管长期记忆，而 `AGENTS.md` 管操作规范——三者分工不同，混着写是很多问题的根源。

## 问题

没认真维护这份手册的人，通常会遇到几类症状：

- 同一件事每次会话做法都不一样，文件放哪、命名怎么取，全看模型心情；
- agent 越权：没确认就把消息发出去、把临时脚本写进不该写的目录；
- 每次犯错都要口头纠正一遍，下次会话照犯；
- 把所有上下文塞进系统提示词，太长之后关键规则被稀释。

本质原因是：agent 是一个"每次上班都失忆的新同事"，而你没给它留入职文档。

## 做法

我的工作流分四步：

1. **以模板起步，不手写全文。** 初始化工作空间时 OpenClaw 会生成默认 AGENTS.md，先跑几天，观察 agent 哪里不符合预期，再针对性补规则。
2. **按职责分区。** 我现在的结构大致是：

```markdown
# 硬性边界（不可做）
# 环境事实（路径、时区、可用工具）
# 常规流程（日报、消息分诊、定时任务）
# 文件约定（笔记目录、命名规则）
# 汇报规则（何时自己动手，何时先问）
```

3. **写可执行的动作，不写愿望。** "保持整洁"是愿望；"会话笔记一律写到 `/notes/YYYY-MM-DD.md`，不存在则创建"是动作。每条规则一行，祈使句加具体路径或命令。
4. **用 git 管起来。** AGENTS.md 的每次修改都应可回溯。agent 连犯两次同一个错，就把纠正写进去，commit 信息写清楚为什么。

## 踩坑点

- **别当垃圾桶。** 超过一屏的规则，后半段基本会被忽略。硬性边界必须放最上面；易变细节交给 MEMORY.md，AGENTS.md 只留稳定规范。
- **别和 SOUL.md 打架。** 一边写"谨慎少言"，一边写"主动汇报所有动态"，模型行为会摇摆。同一件事只允许一个文件负责。
- **别把密钥写进去。** AGENTS.md 会被完整读进上下文，还会随工作空间被 git 同步。密钥放环境变量，手册里只写"从 `~/.config/xxx` 读取"。
- **改完不重启等于没改。** 运行中的会话还挂着旧上下文，验证规则生效要开新会话，并让 agent 复述一遍自己的操作规范——复述不出来说明写得太长或太模糊。

## 可复用建议

- 一个判断标准：如果明天入职的人类实习生需要知道，就写进 AGENTS.md；如果只是本次任务的细节，丢进 memory 或笔记。
- 每月做一次裁剪：删掉三个月没触发过的规则，总量控制在 40 行左右。
- 让规则"可测试"：每条规则都应能构造一个场景去验证，验证不了的说明写虚了。

## 总结

AGENTS.md 是 OpenClaw 工作空间里性价比最高的一份配置：不用写代码，却直接决定 agent 的行为下限。把它当成 runbook 来维护——短、具体、可验证、有版本——一致性会有肉眼可见的改善。手册写得越好，你需要盯着的次数就越少，这大概就是给 AI 写文档的全部意义。
