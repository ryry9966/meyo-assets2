最近 36kr 一条报道把小模型价格战顶上热搜：Claude Haiku 5.5 把价格打到「骨折」，把单次调用成本卷进「一分钱时代」。如果你两年前按 GPT-4 的价目表跑过业务，看到今天的价格大概会怀疑自己看错了小数点。但「打骨折」不是慈善，也不只是烧钱内卷——它是蒸馏、MoE、推理工程和市场策略四件事叠加的结果。这篇把账本摊开，算给你看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/ed811390df9dfa06.png)

## 先算账：一次调用到底要多少钱？

- **参照系**：上一代 Haiku 级小模型定价约 $1 / 百万输入 token、$5 / 百万输出；同档 mini 级（GPT-4o mini、Gemini Flash-Lite 等）已压到 $0.1~0.3 / 百万输入；国产厂商部分档位更是进入 1 元人民币 / 百万 token 以内。
- **折扣杠杆**：prompt caching 能把缓存命中的输入部分打到一折上下，Batch API 普遍五折。两招叠上，长尾场景的成本直接击穿一分钱。
- **实际算例**：给一篇 3000 token 的客服工单做摘要，输出 300 token。Haiku 级模型约花 3 分钱；换 mini 级再吃缓存和批量的折扣，单次调用进入 1 分钱以内。
- **历史锚点**：2023 年 3 月 GPT-4 定价 $30/$60（每百万 token），同等智力水平的模型两年半降了约两个数量级。a16z 管这叫 "LLMflation"：能力恒定前提下，推理单价大约每年降 10 倍。

版本号迭代很快，具体价目以官方页面为准——看趋势比盯某个数字重要。

## 价格砍到脚踝，靠的不是让利，是工程

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/2da537b8c944097b.png)

降价能持续，是因为边际成本曲线真的在下移，主要靠这几件事：

1. **蒸馏（distillation）**：大模型当老师，把能力「压」进小模型。以 Haiku 上一代为例，官方口径是编码能力接近自家 Sonnet 4，成本约三分之一、速度快两倍以上。老师教得越好，学生越小越便宜。
2. **MoE 架构**：总参数做得很大，但每次推理只激活一小部分。DeepSeek V3 总参数 671B，激活只有 37B——算力账单只按「激活的」算，不按「装着的」算。
3. **推理侧优化**：continuous batching、PagedAttention、prefix caching、FP8 量化这套组合拳，把 GPU 有效利用率从早年的三成提到六成以上。同样的显卡吞吐翻倍，单价就有砍半的空间。
4. **顺手的物理外挂**：speculative decoding 让小模型先猜、大模型验证，一次前向出多个 token；自研推理芯片再把单位算力成本往下压一层。

一句话总结：这轮降价不是赔本赚吆喝，是成本降了顺势定价，所以才卷得这么稳。

## 巨头为什么愿意卷：agent 改变了算力的消费方式

- **消费模式变了**。Chat 时代，一次对话十几次模型调用就到头；Agent 时代，一个任务动辄发起几百次调用——读文件、查代码、自检结果，其中大部分是「简单活」，小模型完全够用。
- **越便宜，总量越大**。单价降 10 倍，调用量涨 100 倍，总账单反而是涨的。经济学上这叫杰文斯悖论：蒸汽机效率提高后，煤烧得更多了；token 变便宜后，消耗只会更凶。
- **价格是获客手段**。开发者把工作流搭在谁的模型上，下一轮升级、下一份订阅就都跟着走。短期卷的是单价，长期抢的是生态位。

## 「一分钱时代」解锁了什么

- **以前算不过账的场景现在能跑了**：全量客服工单摘要、逐条代码审查、实时字幕翻译、千人千面的营销文案——共同点是「单次便宜、量极大」，过去单价高，整个方案就不成立。
- **成本重心迁移**：token 接近白送之后，钱花在编排、上下文工程、评测和可观测性上。值钱的不再是 token 本身，而是「怎么把 token 用对地方」。
- **创业门槛重排**：问题从「用不用得起大模型」变成「能不能把便宜 token 用得比别人聪明」。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-08/9b6056ca96e6ad61.png)

1. **做分层调用**：默认小模型，疑难 case 再升级大模型，一个 router 就能砍掉大半成本。别让旗舰模型去干 Haiku 就能干的活。
2. **算「每成功任务成本」，别只看「每百万 token 单价」**：重试、超长上下文、缓存命中率、失败率都要摊进去。单价便宜和账单便宜，经常是两回事。
3. **别把壁垒建在「我能拿到低价」上**：价格是厂商随时可调的变量，可迁移的架构、自己的数据和工作流才是护城河。另外提醒一句，token 贱卖不等于账单变小——agent 的消耗是指数级的，预算模型要跟着换。

价格卷到底，受益的是真把东西做出来的人。这次被优化的不是程序员，是 token。🦞
