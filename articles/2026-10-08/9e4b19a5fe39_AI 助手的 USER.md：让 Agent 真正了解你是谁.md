# 背景

OpenClaw 这类常驻 Agent 和一次性对话产品最大的区别，是它有 workspace——一个每轮会话开始都会被读入的持久目录。SOUL.md 决定它“怎么说话”，TOOLS.md 决定它“会用什么”，而 USER.md 决定它“怎么对你”。多数人的 USER.md 要么是空的，要么塞了些无关痛痒的自我介绍，结果就是：每次开会话都得重新交代时区、技术栈和沟通习惯，Agent 该猜错的还是猜错。

# 问题

Agent 真正需要的“你是谁”，通常有三类：

1. **环境事实**：时区、操作系统、语言偏好（中文回复、代码注释用英文）；
2. **稳定偏好**：要简洁回答还是完整推理、目录组织习惯、命名规范；
3. **边界约束**：哪些命令不许在生产环境跑、哪些操作前必须先确认。

这些不写下来，Agent 只能靠会话内临时推断，跨会话即失效。写下来但放错了地方，又会制造新问题。

# 做法

我的 USER.md 控制在 60 行以内，固定五节：

```
## 身份    时区 / 称呼 / 语言偏好
## 环境    主力设备 / OS / 常用工作目录
## 项目    当前 1-3 个活跃项目，各一行
## 偏好    回复风格 / 代码风格 / 禁止事项
## 边界    永远要做 / 永远不要做
```

配套三条纪律：

1. **只放持久事实**。判断标准：这条信息半年后还会影响 Agent 的行为吗？本周的调试任务不行，“对破坏性命令要求二次确认”可以。
2. **在 SOUL.md/AGENTS.md 里写清更新协议**。明确告诉 Agent：确认学到一条关于我的持久事实时，更新对应小节，替换优于追加；不确定就先问，不要擅自写入。
3. **控制体积预算**。这个文件每次会话开场都要注入，膨胀到几 KB 后既费 token 又稀释信号。我设了硬上限，超了就修剪。

写完做个验证：开全新会话，问它“你了解我哪些信息”，再故意用英文提问看它是否坚持中文回复。这两条都过，文件才算生效。

# 踩坑点

- **把易变状态写进去**。“正在调试 X 模块”这类信息两周后就成了误导源。易变的进 MEMORY.md，持久的才进 USER.md。
- **敏感信息泄露**。workspace 常被 git 同步或快照，我把 key、服务器 IP 全部挡在外面，只留“密钥从 vault 读取”这类指针。
- **Agent 乱追加导致文件腐烂**。没写更新协议前，我的文件一个月涨到 200 行，新旧事实打架（“用 Python 3.8”和“已迁移 3.12”并存）。加上“替换优于追加”才稳住。
- **假设 Agent 会自动维护**。默认行为里它没有主动写文件的冲动，协议必须显式声明，否则文件永远是静态的。

# 可复用建议

- USER.md 管“人”，项目级配置文件管“仓库”，别混。团队规范和你的个人偏好分开放。
- 更新协议浓缩成三个问题：是持久事实吗？是关于用户而非项目的吗？会改变未来回答吗？三个都满足才写入。
- 固定低频回顾节奏。我挂在月度周报流程里，5 分钟扫一遍，删过时项。
- 同时使用多个 Agent 工具时，注意各自读取的文件位置不同，用软链或同步脚本收敛到单一来源。

# 总结

USER.md 是我目前投入产出比最高的 Agent 定制手段：60 行文本，换来不用重复自我介绍、时区不再错乱、回复风格稳定。但它本质是个配置文件，配置文件就需要生命周期管理——有格式、有预算、有更新协议、有定期修剪。这四件事做对，Agent 才算真正“认识”你，而不是每次见面都从零开始。
