## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，你会发现一个尴尬的现实：它记住了你的日程和任务，却不记得你是谁。每次新会话，它不知道你主力写 Go 还是 Python，不知道你的时区，不知道你讨厌冗长的开场白。于是你反复在对话里自我介绍，或者忍受千篇一律的通用回复。

OpenClaw 工作区里有一组约定俗成的记忆文件：SOUL.md 定义 Agent 的性格边界，AGENTS.md 定义行为规则，而 USER.md 就是留给"你"的位置——一份 Agent 每次启动都会读到的用户画像。

## 问题

没有 USER.md 时，个性化只能靠两种低效方式：一是在对话里口头说明，成本高且不一致；二是塞进系统提示词，和 Agent 配置耦合，改一次要动核心文件。

本质上这是个上下文工程问题：哪些信息值得常驻上下文？答案是稳定的、跨任务复用的"关于你"的事实，而不是易变的任务细节。它直接影响 Agent 的默认选择——比如生成 commit message 的语言、调用 MCP 工具时的参数习惯。

## 做法

在工作区根目录建 USER.md，建议四个区块：

```markdown
# About Me
## 身份与环境
- 时区 Asia/Shanghai，工作时段 9:00-19:00
- 主力：Go / Kubernetes，偶尔写 shell
## 沟通偏好
- 中文回复，术语保留英文
- 先结论后依据，不要寒暄
## 边界
- 不动 ~/.ssh 下任何内容
- 部署操作先给方案再执行
## 当前关注
- 正在把 CI 从 Jenkins 迁到 GitHub Actions
```

然后验证加载：开新会话问一句"你现在了解我什么"，看它能否复述关键信息。没生效的话，优先检查文件路径和文件名大小写。

## 踩坑点

1. **写太长。** 超过 50 行，关键偏好会被稀释。画像要像 header 文件，不像文档。
2. **写成简历。** "十年经验""擅长架构"对 Agent 没有行动价值。写影响它行为的事实：工具链、目录约定、禁令、风格。
3. **放敏感信息。** 密钥、内网地址不要进 USER.md——它会被注入每一次会话，还可能随工作区同步出去。
4. **混入易变内容。** 今天的 TODO、本周的 bug 清单应进任务系统。USER.md 只放"季度级稳定"的信息。
5. **和 SOUL.md 打架。** 语气类偏好两边都写，结果互相矛盾。约定清楚：SOUL.md 管"Agent 是谁"，USER.md 管"我是谁"。

## 可复用建议

- 按"事实 > 偏好 > 边界 > 当前关注"排序，越重要越靠前，防止长文截断。
- 文件顶部加一行"最后更新日期"，每月 review 一次，删掉过时项目。
- 用 git 管理工作区，USER.md 的 diff 就是你工作流的演化史，回滚也有据可查。
- 团队共享 Agent 的场景，拆成 USER.md（个人）+ TEAM.md（团队约定），各自独立演化。
- 让 Agent 参与维护：定期让它总结"你最近的行为里哪些值得写进 USER.md"，人工审核后合入，画像会越用越准。

## 总结

USER.md 不是什么新协议，只是把"你希望被怎么协作"从口头重复，变成一份受版本控制、随上下文自动注入的配置。投入二十分钟，换来每个新会话零成本对齐。它的质量决定协作质量——这和给新同事写 onboarding 文档是同一件事，只不过这次的读者是一台没有常识、但极其听话的机器。
