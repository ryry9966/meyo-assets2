## 背景

多数人用 OpenClaw 还是“人找 Agent”：发消息、等回复、再发消息。但 OpenClaw 本质是常驻网关，Agent 的会话一直活着，其实天然适合另一种用法——**值守**。

它内置了一个很朴素的心跳机制：网关按固定间隔（默认 30 分钟）给主 Agent 注入一条极简提示，大意是“读一下 workspace 里的 HEARTBEAT.md，有指令就执行”。这个文件，就是你给 Agent 写的《值班手册》。

## 问题

三类事最适合交给心跳，却恰恰最容易被被动模式拖死：

- **状态监控**：磁盘快满、某个进程消失、错误日志暴增——等你想起去看，已经晚了；
- **增量整理**：新到的消息、日志里的新 ERROR，攒多了再看很痛苦；
- **例行汇报**：每日一条摘要，靠人记是记不住的。

这些事让 Agent 主动做没问题，但直接开心跳很容易翻车：要么每半小时骚扰你一次，要么 token 烧得不明不白。

## 做法

**第一步**，在 workspace 根目录（默认 `~/clawd/workspace`）建 `HEARTBEAT.md`，关键是每条任务都带“条件 + 动作 + 沉默规则”：

```markdown
# HEARTBEAT

每轮依次检查，全部正常只回复 HEARTBEAT_OK：

- 磁盘占用 > 85% 时报告，附 top 3 目录
- error.log 出现新 ERROR 时摘录最近 3 条
- 每日首次心跳汇总昨天未读消息，一条以内

规则：
- 无异常一律 HEARTBEAT_OK，不要寒暄
- 涉及发消息、花钱的操作，先停下来问我
```

**第二步**，按需调间隔。默认 30 分钟够用；真要盯敏感状态可缩到 10–15 分钟，再低就不划算了——每轮心跳都是一次真实的模型调用。间隔通过配置里 heartbeat 相关项或 `HEARTBEAT_INTERVAL_MS` 环境变量调整。

**第三步**，验证。文件每轮心跳都会重新读取，改完不用重启；故意往 `error.log` 塞一条 ERROR，等下一轮看它是否主动找你。

**第四步**，确认沉默协议生效。以 `HEARTBEAT_OK` 开头的回复会被网关吞掉、不投递到聊天渠道，这是“不打扰”的关键，务必写进文件里。

## 踩坑点

- **把重活写进心跳**。心跳只适合“轻检查 + 触发报告”；备份、批量抓取这类长任务交给系统 cron，否则心跳经常超时，token 账单也难看。
- **写“每天早上 8 点做 X”**。Agent 对时间的感知很弱，定时类需求老实用 cron 建任务，心跳只做状态触发的检查。
- **无条件任务**。“报告一下今日天气”这种条目会让每个周期都给你发消息，三天你就想关掉它。所有条目必须有条件分支。
- **上下文膨胀**。每轮心跳都会留在会话历史里，HEARTBEAT.md 和它的输出越短越好，会话定期重置。
- **机器睡着了**。本机休眠或网关没跑，心跳就静默停摆——把它当尽力而为的巡检，关键告警仍要有外部兜底。
- **多 Agent 改错文件**。每个 workspace 的 HEARTBEAT.md 相互独立，心跳不生效时先确认改的是哪个 Agent 的文件。

## 可复用建议

- 把 HEARTBEAT.md 当 **runbook** 写：检查项、阈值、动作、“何时才许打扰人”一应俱全，别人接手也看得懂。
- 高价值条目就三类：**阈值告警、增量摘要、变更检测**（盯某个关键文件或目录）。
- 把“沉默协议 + 花钱先问”两行固化成模板开头，作为所有 Agent 的默认配置。
- 一句话分工：**时间触发用 cron，状态触发用心跳**。

## 总结

HEARTBEAT.md 的本质，是把“什么时候该叫 Agent”的决定权从人手里交给状态：有事说事，没事闭嘴。配置成本几乎为零，但要从“被动问答”真正走向“主动值守”，纪律比功能重要——每条任务有条件、输出克制、重活外移。做到这三点，心跳才是值班表，而不是骚扰源。
