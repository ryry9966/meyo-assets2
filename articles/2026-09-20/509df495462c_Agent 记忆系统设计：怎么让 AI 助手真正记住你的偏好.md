## 背景

LLM 本身无状态。你在 OpenClaw 里跑的 agent，每次会话结束上下文就归零。没有记忆层的助手，你得反复交代"我用 pnpm 不用 npm""commit message 写中文"——这不叫助手，叫复读机。下面这套分层方案我们在实际 agent 上跑了几个月，目标是让偏好记忆**写得准、取得回、不过期**。

## 问题：三种常见做法为什么都会失败

1. **全塞 system prompt**：偏好攒到几十条后常驻 token 爆炸，无关内容稀释关键指令，模型开始"选择性失忆"。
2. **只追加不更新**：三个月前记了"喜欢详细解释"，上周记了"以后简洁点"，两条并存，召回哪条看运气。
3. **纯向量检索**：偏好里大量精确词（工具名、路径、参数），embedding 经常漏召回，必须关键词兜底。

## 做法：三层存储 + 两条策略

**存储分三层：**

- **L0 静态画像**：workspace 里一份 PROFILE.md，随系统提示常驻，严格控制在 500 token 内，只放高频、稳定的硬偏好。
- **L1 会话滚动**：`memory/YYYY-MM-DD.md` 日常笔记，会话中随时追加原始事实，不追求结构。
- **L2 长期记忆库**：结构化记录（类型 / 内容 / scope / 时间戳 / 来源），通过 MCP 记忆工具按需检索。

**写入策略**：不是所有话都值得记。触发条件限定三类——明确指令（"记住""以后都"）、重复模式（同一纠错出现两次以上）、强负反馈。写入走统一的 `memory_write` 工具做校验和去重，禁止模型直接改文件。

**整理策略**：heartbeat / 定时任务每晚跑一次合并——同 scope 同主题只保留最新记录，旧的归档；L0 中被推翻的偏好降级回 L2。

## 踩坑点

- **scope 不确认就写入**："以后都简洁"是全局还是本项目？不追问一句，三个月后全是错记忆。
- **会话结束才落盘**：进程挂了全丢，高信号内容要当场写。
- **只建索引不清理**：检索噪声逐渐淹没相关记录，整理任务不是可选项。
- **把记忆当可信输入**：用户粘贴的内容会进 L1，记忆一样能被注入，召回后按不可信文本处理。
- **隐私**：记忆文件随 workspace 同步/备份，敏感信息要单独隔离或脱敏。

## 可复用建议

- 记录必带 schema：`type / content / scope / source / timestamp / confidence`。没有 schema 的记忆库，三个月后没人敢用。
- 读写分离：读可以宽松（关键词 + 向量混合检索），写必须走唯一入口。
- 建一个记忆评测集：20 条"你还记得我 XX 偏好吗"式问题，改任何环节跑一遍防回归。
- 常驻提示词越短越好，冷数据放文件，靠检索获取。

## 总结

记忆系统的核心不是"记更多"，而是**写入有门槛、更新有机制、召回有兜底**。先把 L0 画像和统一写入工具做扎实，再逐步加检索层，比一上来就堆向量库靠谱得多。
