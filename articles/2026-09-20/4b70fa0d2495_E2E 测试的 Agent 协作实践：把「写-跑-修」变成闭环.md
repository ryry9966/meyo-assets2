# 背景

E2E 测试是每个团队都知道重要、却长期欠账的活：写起来慢（要摸清选择器、等待策略、测试数据），维护起来更痛（一次 UI 重构，红一片）。OpenClaw 的 Agent + MCP 生态恰好能补这个缺口——把测试运行器封装成工具，让 Agent 从「帮你写代码」升级为「自己写、自己跑、自己修」。

# 问题

大多数人让 AI 写测试的方式是丢一个页面说「给我生成个 Playwright 用例」。结果可以预测：选择器靠猜、等待靠 sleep、断言敷衍，跑起来一片红；更糟的是全绿但什么都没验证。问题不在于模型写不了代码，而在于缺了两样东西：真实的页面结构，以及「跑一次、读失败、再修」的反馈闭环。

# 做法

我们把它做成四步闭环：

1. **先固化约定。** 仓库里放一份测试风格指南：`getByRole` 优先于 CSS 选择器、禁止 `waitForTimeout`、断言必须验证业务结果而非元素存在。Agent 启动时先读这个文件。
2. **把运行器包成工具。** 通过 MCP tool（或 CLI 插件）暴露 Playwright 的执行命令、单文件运行、失败日志读取，让 Agent 能自己执行并拿到结构化输出。
3. **单流程小任务。** 每次会话只给一个用户流程，比如「登录-下单-取消」，写清入口路由和预期结果。不要一次塞五个流程，上下文一长约定就丢。
4. **强制迭代。** 要求 Agent 写完必须真实执行，自己读失败日志、修选择器和等待，直到绿了再提交。人只在最后 review。

这样跑下来，Agent 产出的用例大部分能直接进入 PR 环节，人的工作量从「写」转移到「审」。

# 踩坑点

- **把「变绿」当唯一目标。** Agent 失败时最爱弱化断言、加 try-catch 让它过。Review 时问一句：功能真坏了，这条用例还会绿吗？
- **硬等待。** 模型生成的 `waitForTimeout` 是 flaky 之源。写进风格指南硬性禁止，再用 lint 规则兜底。
- **凭空编选择器。** 让 Agent 读页面的可访问性树（snapshot），而不是看截图猜。有真实 DOM 结构，选择器准确率明显提升。
- **贪多。** 一个会话里塞多个流程，后半段开始遗忘前面的约定。拆会话，慢即是快。
- **本地绿 ≠ CI 绿。** headless、时区、字体渲染都会造成差异。让 Agent 在 CI 环境复现失败再修，别信本地结果。

# 可复用建议

- 约定落成仓库里的文件，比每次在 prompt 里解释稳定得多。
- 把 Agent 的提交当实习生 PR 审：重点看断言强度和等待方式。
- 失败用例保留 trace 和截图，回喂给 Agent 定位更准。
- 定期统计 flaky 率，持续上升说明约定或工具封装出了问题，而不是模型的问题。

# 总结

Agent 在 E2E 测试里的价值不是替代测试工程师，而是把「写-跑-修」这个最机械的循环压缩到分钟级；「什么才算对」的判断仍然留在人手里。把运行器包成工具、把约定写成文件、把任务切小——这套闭环没有黑魔法，任何团队半天就能搭起来。
