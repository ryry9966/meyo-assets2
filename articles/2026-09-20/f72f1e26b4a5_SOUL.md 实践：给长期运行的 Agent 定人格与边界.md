## 背景

OpenClaw 跑起来之后你会发现，工具链好搭，人格难定。MCP 接上、插件配好、定时任务转起来，Agent 是能干活了——但它说话的腔调、做事的分寸，全靠各处散落的提示词拼凑。时间一长，你自己都说不清它"应该是什么样"。

OpenClaw 把这件事收敛成一个文件：workspace 里的 SOUL.md。它会被注入每轮对话的上下文，充当 Agent 的"人格层"——身份、语气、原则、行为边界，都写在这一处。

## 问题

没有 SOUL.md 或写得随意时，常见三类毛病：

1. **语气漂移**。今天像客服，明天像理工男，长期使用的个人助理体验很割裂。
2. **边界模糊**。Agent 拿着你的消息通道、shell、浏览器权限，什么该自动做、什么该先问你，只靠事后口头纠正，等于没有边界。
3. **规则散落**。人格指令一半在配置里、一半在 AGENTS.md 里、一半在记忆里，改一处漏两处。

## 做法

我的 SOUL.md 稳定在 40 行左右，分四段：

```markdown
# Identity
你是我的个人助理，不装熟、不过度道歉、不自称"我只是一个AI"。

# Tone
默认简短直接；技术问题先给结论再给理由；不堆 emoji。

# Principles
不确定的事实明确说不确定；隐私优先，聊天内容不主动外传。

# Boundaries
花钱、发消息、删文件、对外发言：必须先确认；
定时任务只做白名单内的事；越界时停下来问，不要猜。
```

用 git 管理，每次 Agent 表现不符预期，就回头补一条具体规则，而不是重写全文。

## 踩坑点

- **写太长**。超过一两百行，规则互相稀释，模型注意力顾此失彼。40–60 行足够。
- **形容词堆砌**。"友好、专业、有趣"没有操作价值，换成可判定的行为："回复不超过三段""不主动推荐付费方案"。
- **指望 SOUL.md 兜底安全**。它是软约束。支付、删除、对外发送这类高危权限，必须在插件/工具层配确认机制，SOUL.md 只是第二道防线。
- **Agent 自己改 SOUL.md**。OpenClaw 默认允许它编辑自己的工作区文件。建议在 AGENTS.md 里声明"改 SOUL.md 需主人确认"，或至少靠 git diff 事后审查。

## 可复用建议

- **分层写**：SOUL.md 管"我是谁、守什么底线"，AGENTS.md 管"怎么干活"，USER.md 管"主人是谁"，别混。
- **边界写成"触发条件 + 动作"**：如"涉及花钱 → 列出金额和用途，等我回复"。
- **定期回填**：每月翻一次 git log，把踩过的坑固化成新规则。
- **换模型后重测**：不同模型对同一份 SOUL.md 的服从度不一样，边界场景要重跑一遍。

## 总结

SOUL.md 的价值不在"让 AI 更像人"，而在把你对 Agent 的预期，从口头习惯变成可版本管理、可迭代的工程产物。写得短、写得具体、边界落到工具层，它就是长期自动化里最省心的一层保障。
