## 背景

过去一年，我把不少自动化流程从云端 API 搬到了本地，动机有三个：一是隐私——日志、代码片段、家庭数据不想出网；二是 Agent 循环烧 token 太快，云端账单随调用量线性上涨；三是断网调试时，本地模型能兜底。这篇帖子记录我在一台家用机上给 OpenClaw Agent 配本地模型的全过程，重点是可复现的决策依据，不是跑分。

## 问题

核心矛盾是三件事互相挤压：**显存/内存、上下文长度、工具调用可靠性**。云端模型这三项都很充裕，本地 7B～14B 就要精打细算——尤其 Agent 场景每轮循环都带着完整工具描述和历史消息，对上下文和结构化输出的要求远高于单轮问答。

## 部署步骤

1. **算显存账。** 模型体积 ≈ 参数量 × 量化位宽 ÷ 8。7B 的 Q4_K_M 约 4～5 GB，再加 KV cache——上下文开 32K 会额外吃 2～4 GB。经验值：显存预算留 20% 余量。
2. **选推理框架。** Ollama 上手最快，llama.cpp 可控性最强，vLLM 适合有独显服务器想压吞吐的场景。关键是都能暴露 OpenAI 兼容接口，Agent 侧只需改 base_url。
3. **选模型。** 中文工具调用场景我最终落在 Qwen 系列 7B/14B 的 instruct 版本，另配一个本地 embedding 模型给 RAG。别用 base 模型，工具调用基本不可用。
4. **定量化档位。** 默认 Q4_K_M；显存富余升 Q5/Q6；Q2 以下别碰，JSON 输出会碎。
5. **接入 Agent/MCP。** base_url 指向本地端点，temperature 压到 0.1～0.3，开 JSON schema 约束输出。先跑通一个最小工具循环，再上真实流程。
6. **建基线。** 记录 tokens/s、显存峰值、20 条真实任务的工具调用成功率，换模型前后各跑一遍。

## 踩坑点

- **KV cache 是隐形杀手**：只按权重算显存，开长上下文直接 OOM。
- **小模型工具调用衰减明显**：7B 以下开始漏参数、编造工具名，必须配 schema 约束，不要裸跑。
- **Agent 循环放大 prefill 成本**：每轮重发全量历史，长上下文下慢到没法用。裁剪历史 + 复用 system prompt，比换大模型更有效。
- **macOS 统一内存 ≠ CUDA**：同一模型在 Mac 上能跑更大档位，但吞吐换算不能照搬。
- **别用单轮聊天测速**：Agent 场景的瓶颈分布和聊天完全不同。

## 可复用建议

- 先用 7B Q4 验证整条链路，再决定要不要上 14B——链路问题换模型解决不了。
- 在接口层留一个云端 fallback：同样的 OpenAI 兼容协议，本地超时或连续失败就切走。
- 攒一套 20～50 条的真实任务评测集，这是换模型时唯一的可信依据。
- 把每次的显存占用、tokens/s、成功率记进表格，两周后它就是你的选型手册。

## 总结

本地部署不是"替代云端"，而是给 Agent 体系加一层可控、离线、边际成本为零的执行层。先算显存账，用 schema 约束兜住小模型的输出，用真实任务评测说话——这三件事做对，家用机跑 7B～14B 做自动化是完全现实的。有余力再把评测集和 fallback 配置固化下来，后续换模型就是改一行配置的事。
