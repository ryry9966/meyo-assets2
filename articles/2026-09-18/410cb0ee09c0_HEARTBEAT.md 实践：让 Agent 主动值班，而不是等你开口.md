## 背景

大多数 agent 的使用模式是拉式的：你想起来才问，它答完就沉下去。OpenClaw 在网关层提供了一个反向机制——心跳（heartbeat）：按固定间隔（默认 30 分钟）向 agent 注入一次内部提示，让它去读工作区根目录下的 `HEARTBEAT.md`，自己判断"现在有没有该干的事"。这是把 agent 从问答机变成值守进程的最小实现，成本上就是多一个 markdown 文件。

## 问题

真正的问题有两个。第一，重复性关注点——日志里冒 ERROR、TODO 没人收尾、某个依赖仓库出了新 release——要么靠人脑记，要么写 cron 加脚本，但脚本只会 diff 和 grep，做不了"这条报错值不值得报给你"的语义判断。第二，单纯提高主动性很容易变成骚扰：agent 每半小时汇报一次"我检查过了，一切正常"，第三天你就会把它静音。HEARTBEAT.md 机制恰好同时处理这两件事：声明式地写清楚"盯什么、做什么"，再用一个静默协议解决"什么时候闭嘴"。

## 做法

1. 在工作区根目录建 `HEARTBEAT.md`（默认 `~/openclaw/workspace/HEARTBEAT.md`），写成"条件 + 动作"的检查清单：

```markdown
# 心跳检查项
- 若 logs/error.log 最近 30 分钟有新增 ERROR：
  归纳最近 3 条的共性，一句话发我
- 若本地时间在 21:00–23:00 且 state.json 中今日日报未发：
  汇总今天的会话要点成日报，发完把标记置为 true
- 若 ~/repos/openclaw 出现新 tag：读 changelog，摘要发我
```

2. 什么都不需要做时，agent 回复 `HEARTBEAT_OK`，网关会拦截这条回复、不推送到你的聊天渠道。这是整套机制里最关键的细节：主动 ≠ 吵。
3. 心跳间隔在 `openclaw.json` 里调整（默认 30 分钟）。巡检类任务 30–60 分钟足够，别为了"更实时"调到几分钟。
4. 需要跨心跳记忆的状态（"今天发过日报了吗"）让它写回一个 `state.json`，这个文件就是它的值班日志。
5. 反过来，删掉这个文件，心跳就空转跳过，不产生模型调用——不想用时直接摘掉即可。

## 踩坑点

- 愿望清单 ≠ 检查清单。"帮我关注行业动态"没法执行，模型只能现编。每条必须是可判定条件加明确动作。
- 文件越长越贵。每次心跳都是一次真实的模型调用（读文件加判断），控制在几十行以内，过期条目及时删。
- "每天一次"靠模型数心跳不可靠，写成时间窗口加状态标记；真正的定点任务用 cron 触发 agent 更稳，心跳留给条件触发型任务。
- 心跳会话和你手动会话不在同一个上下文，别指望它记得你昨天聊过的细节，状态一律落盘。
- 心跳是无人值守执行，工具权限要收紧：删除、群发这类操作，让它先出草稿等你确认。

## 可复用建议

- 每条检查项固定四要素：条件、动作、频率上限、输出渠道。
- 任务分两类入队：条件触发型进 HEARTBEAT.md，定时触发型进 cron 或计划消息。
- 起步只放一两件你真的心疼的事，跑一周再增量加；一次塞十条的结果是 token 账单和噪音一起涨。
- 像 review cron 一样定期 review 这个文件——它就是你的 agent 值班表。

## 总结

HEARTBEAT.md 本质是三件事的组合：固定节拍的哨兵循环、声明式任务清单、`HEARTBEAT_OK` 静默协议。机制本身不花哨，效果几乎完全取决于清单质量——条件可判定、文件够短、状态落盘、权限克制。守住这四点，agent 就能安静地从"工具"变成"值守"，而你只会在它真正有话说的时候被打扰。
