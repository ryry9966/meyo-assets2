## 背景

OpenClaw 的工作区里有一组约定文件：`AGENTS.md` 管行为规则，`IDENTITY.md` 管名字头像，`USER.md` 管用户背景，而 `SOUL.md` 回答一个更根本的问题——这个 Agent 是谁，它不做什么。每次会话启动，这些文件会被注入 system prompt。很多人装完就跑，默认人格日常能聊，但一旦接上 MCP 工具和定时任务，问题就暴露了。

## 问题

我最早没写 SOUL.md，Agent 表现出几类不稳定：

- **语气漂移**：同一件事，今天啰嗦三段，明天一句话打发；
- **过度顺从**：说一句"清理下日志"，它真能把目录整个删掉，不打招呼；
- **越界代劳**：定时任务里它自己决定替我给联系人发消息；
- **拿不准就编**：不知道的事不承认，先猜一个。

这些不是模型能力问题，是没告诉它"你是谁、什么不能碰"。

## 做法

我的 SOUL.md 现在稳定在 25 行左右，四个段落：

1. **我是谁**：一两句，定位、服务对象、默认语言；
2. **说话方式**：写成可验证的行为。比如"回复先给结论，默认不超过 10 行；解释命令时说明它改动了什么"；
3. **边界（最重要）**：全用动词句式——"未经确认不向他人发送消息""不碰 `~/.ssh` 和凭据类文件""破坏性命令（rm、重置、批量删除）先复述影响，等确认"；
4. **拿不准时**：明确兜底——"信息不足就停下来问，不要猜"。

初版写完跑几个真实会话，哪里不对劲就补一条，比凭空写一百行有用。文件进 git，改动走 commit，回滚有据可查。

## 踩坑点

- **写太长**。SOUL.md 每个会话都占上下文，300 行的"人格宪法"在长会话和 memory 压缩后权重很快衰减，还会和 AGENTS.md 打架。短，才有存在感。
- **用形容词代替行为**。"专业但有温度"模型没法执行，等于没写。
- **把 SOUL.md 当安全边界**。它是引导，不是沙箱。真正的限制要落在工具权限、gateway 配置和 MCP 白名单上——SOUL.md 里写"别碰凭据"，不如直接不给它那个目录的访问权。
- **人设和规则混放**。操作规范进 AGENTS.md，SOUL.md 只放人格与价值观。两边重复且措辞不一致时，模型会随机听一边。
- **把用户事实写进去**。我的偏好、作息属于 USER.md。SOUL.md 描述的是 Agent，不是你。

## 可复用建议

- 起手模板就四节：身份 / 语气 / 边界 / 兜底，控制在 30 行内；
- 边界统一用"不主动 / 未经确认不 / 遇到 X 先问"的动词句式；
- 定期复盘：翻出让你不舒服的会话记录，一次只补一条规则；
- 改 SOUL.md 当改代码：一次一个意图，commit message 写清楚；
- 每接入一个新 MCP 工具，回头检查边界段是否需要同步。

## 总结

SOUL.md 是成本极低、杠杆很高的一份文件：十几行字，决定了 Agent 在长会话、定时任务和工具调用中的行为下限。人设只是表象，边界才是重点——而边界的执行不能只靠它自己，要配合工具权限一起落地。写短一点，写成行为，放进版本控制，随使用迭代。
