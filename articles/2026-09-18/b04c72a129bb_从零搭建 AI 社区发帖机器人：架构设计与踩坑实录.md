## 背景

社区运营里有很多重复劳动：每周精华帖汇总、活动预告、热门讨论摘要。人工整理费时还容易漏。我的目标是做一个发帖机器人：定时抓取社区内容源，由 Agent 生成草稿，经人工确认后发布。定位很明确——自动整理、半自动发布，不做无人审核的全自动发帖。

## 整体架构

拆成四层，彼此只通过数据接口交互：

1. **触发层**：cron 定时任务 + webhook 事件（新内容到达时触发）。
2. **生成层**：OpenClaw Agent 挂载 MCP 工具（抓取、检索、格式化），输入结构化数据，输出固定 schema 的草稿 JSON。
3. **审核层**：草稿进入 SQLite 队列，通过简单管理面板批准、编辑或拒绝。
4. **发布层**：插件适配目标平台 API，内置限速、重试与幂等控制。

状态全部落库：内容指纹、草稿状态、重试次数、trace id。

## 实施步骤

1. 写采集插件，把 RSS、仓库 release、论坛 API 统一转换成标准 schema（标题、链接、摘要、时间戳）。
2. 设计 Agent prompt：只允许组织和改写传入内容，禁止补充外部事实；输出严格 JSON。
3. 去重：对标题和正文做指纹，与近 14 天已发布内容比对。
4. 审核面板批准后进入发布队列。
5. 发布适配器：令牌桶限速 + 指数退避重试 + 幂等键校验。

## 踩坑实录

- **幻觉链接**：早期 prompt 太开放，Agent 会"脑补"不存在的帖子链接。解法：生成后校验所有 URL 是否存在于输入集合，不在就打回重生成。
- **重复发帖**：cron 重叠触发，叠加"发布成功但回调超时"的场景，同一内容发了两次。解法：幂等键 = 内容指纹 + 目标平台 + 发布窗口，发布前先查状态机。
- **平台限速**：连发多条触发风控。解法：发布间隔加随机抖动，单日上限写进配置。
- **时区混乱**：cron 跑在 UTC，摘要里写"今天发布"，实际差了八小时。解法：全链路统一时区，并在 prompt 中显式注入当前时间。
- **超长截断**：某平台有字数上限，硬截断导致句子断裂。解法：适配器预校验，超限退回审核层由人工删减，不做静默截断。
- **prompt 漂移**：改一次 prompt 语气就变，新旧帖风格不一致。解法：prompt 纳入版本控制，每篇草稿记录所用版本，可回溯对比。

## 可复用建议

1. 生成与发布必须分离，中间留审核门，这是安全底线。
2. LLM 只做组织和措辞，事实与链接全部来自结构化输入。
3. 先跑一周 shadow mode：只生成草稿不发布，质量达标再放开。
4. 全链路 trace id，出问题能从发布结果一路追回采集源。
5. 幂等和限速不要指望"应该不会撞上"，要靠机制兜底。

## 总结

这个机器人真正花时间的，不是让 Agent 写出像样的摘要——那部分一两天就调通了。大部分时间花在去重、幂等、限速、审核这些"不性感"的工程细节上。OpenClaw 的插件与 MCP 机制让采集和发布适配成本很低，但边界情况处理没有捷径。一句话总结：生成靠模型，可靠靠工程。
