## 背景

社区每天有大量讨论散落在不同板块，人工整理精华帖很费时间。我们想做一个机器人：每天定时汇总前 24 小时的热门讨论，自动起草一篇"每日精选"，经人工确认后发到社区。顺带练手——把 Agent 调度、MCP 工具接入和插件化发布流程完整跑一遍。

## 问题：第一版为什么是废的

最直觉的做法是"一个 prompt 搞定"：让 Agent 拉数据、写帖子、直接调用发帖接口。跑了一周就下线了——重复发帖、编造不存在的帖子链接、偶尔把旧闻当新闻。核心问题是把采集、写作、发布、审核全塞进一次对话，没有状态、没有校验、没有兜底。

## 最终架构：四段流水线

1. **采集层**：一个 MCP 工具拉取近 24h 的帖子元数据（ID、标题、回复数、时间），只拉结构化字段，不拉全文。
2. **汇总层**：Agent 对候选列表打分（互动量 + 关键词）选出 Top 5，逐条生成一句话摘要。摘要必须附带原帖 ID，供后续校验。
3. **审校层**：先跑规则校验（ID 是否存在于库、是否与近 7 天已发内容重复、字数上限），通过后进入人工审核队列，确认后才触发发布。
4. **发布层**：薄薄一层插件，只做一件事——带幂等键（日期 + 内容 hash）调用社区发帖 API，失败重试三次后告警。

## 踩坑实录

- **时区漂移**：定时任务写死了 UTC，导致精选帖早上八点发，拉取窗口却少了 8 小时。后来所有时间统一存 UTC，展示层再转本地。
- **重复发帖**：重试逻辑没有幂等键，一次网络抖动发了两篇。幂等键是后补的，代价是一句删帖道歉。
- **幻觉链接**：模型会"脑补"不存在的帖子 ID 让摘要看起来完整。解法很土但有效：发布前用 ID 反查数据库，查不到整条丢弃，并在 prompt 里明示"只允许引用列表内的 ID"。
- **上下文爆炸**：最初把帖子全文塞给 Agent，几百条直接打满上下文。改成只传元数据 + 高赞回复片段，token 用量降到原来的十分之一。
- **工具超时**：MCP 工具偶发 30s 超时，Agent 卡死重试。给所有工具调用加了显式 timeout 和降级路径：拉取失败就跳过当天，而不是硬写一篇空壳。
- **审核被砍**：中途为了"全自动"砍掉人工审核，第二天就发了一篇把两个吵架帖并列当"理性讨论"的精选。人工环节加回来了——每天点一次确认，成本完全可接受。

## 可复用建议

- 发布动作永远放最后一层，前面必须有至少一道机器校验 + 一道人工闸门。
- 所有外部写操作带幂等键。
- 让模型引用结构化 ID 而非自由生成链接，发布前反查校验。
- 定时、时区、重试、告警——这些"无聊的部分"占了项目一半工作量，但决定了它能不能活过第一周。
- 每个环节落日志，排障时按时间线回放，比翻聊天记录快得多。

## 总结

这个机器人现在每天稳定发一篇，人工介入约一分钟。技术上没有黑魔法：Agent 负责它擅长的归纳和措辞，规则和流程负责它不擅长的确定性。如果你也在做类似的自动化，建议先跑通"采集 → 校验 → 人工确认 → 发布"这条最小闭环，再考虑加智能。欢迎在评论区交流你们的流水线设计。
