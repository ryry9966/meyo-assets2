## 背景

OpenClaw 的工作流里，让模型输出 JSON 是最常见的约定：skill 路由、插件参数抽取、把 MCP tool 的结构化结果回填给下游，都依赖一段"看起来是 JSON"的文本。但只要换模型、改 prompt、动温度，格式就会漂移：有的包在 ```json 围栏里，有的裸给，有的前面加一句"好的，结果如下"，有的用全角引号。我们流水线里粗略看过，同一段 prompt 下裸 JSON 大概只占六成——数字不重要，重要的是分布足够散，单一解析路径必挂。

## 问题

最朴素的写法是 `json.loads(output)`，失败就重试。实际后果有三类：

- **间歇性失败**：白天正常、换模型就崩，日志里只有一条 `JSONDecodeError`；
- **静默污染**：`strip()` 一下碰运气，偶尔把带前后缀说明的文本解析成错误路由；
- **修复掩盖上游问题**：prompt 约束失效没人发现，修复本身成了隐藏债务。

## 做法：按成本分四层，命中即返回

**第一层，源头约束。** 优先用模型的结构化输出 / tool call 能力，让 JSON 走通道而不是走文本，这是唯一零成本的一层。prompt 里同时写明"只输出 JSON，不要代码块"——但别指望它始终生效。

**第二层，围栏提取。** 正则抓所有 ```` ```json…``` ````（含不带语言标注的），多个块时从后往前试——模型习惯把结果放最后一个块。

**第三层，括号配对。** 没有围栏时，定位第一个 `{` 或 `[`，用栈扫描到配对位置（处理字符串内引号转义），而不是简单取"第一个花括号到最后一个花括号"——后者会被 JSON 之后说明文字里的 `{` 干掉。

**第四层，容错修复。** 仍失败时先规范化（全角引号/逗号转半角、去尾逗号），再交给 `json_repair` 这类库，修复结果必须打日志。

```python
FENCE = re.compile(r"```(?:json)?\s*(.*?)```", re.S)

def extract_json(text: str):
    text = normalize(text)                     # 全角→半角
    blocks = [b.strip() for b in FENCE.findall(text)]
    i = min((p for p in (text.find("{"), text.find("[")) if p >= 0), default=-1)
    if i >= 0:
        blocks.append(balance_slice(text, i))  # 括号配对切片
    for b in reversed(blocks):                 # 后面的块优先
        try:
            return json.loads(b)
        except json.JSONDecodeError:
            continue
    raise ParseError(text)                     # 交给上层带错误信息重试
```

解析成功后再过一遍 pydantic 校验字段和类型——**解析合法不等于语义合法**。失败时带上具体错误重试一次（temperature 设 0），比盲目重试三次有效得多。

## 踩坑点

- **字符串里嵌套围栏**：某字段内容本身是 markdown，FENCE 正则会把 JSON 从中间截断。缓解：括号配对结果优先，围栏只作候选。
- **修复改变语义**：`json_repair` 会把残缺数据"补"成合法但不同的值，要记录修复前后 diff。
- **流式场景**：增量输出时 JSON 不完整，攒到结束再解析，别在单个 chunk 上直接 loads。
- **修复率是指标不是噪音**：某天从 5% 涨到 40%，多半是 prompt 被改坏或换了模型，早报警比让解析器背锅强。

## 可复用建议

1. 解析器收敛成一个工具模块，别在各 handler 里复制粘贴；模块内记录"命中了哪一层"，排查时省一半时间。
2. 从真实日志里捞畸形输出，沉淀成样本语料做单元测试，每次换模型跑一遍。
3. text-JSON 按 legacy 路径维护，能迁到结构化输出就迁。

## 总结

输出解析不是格式约定，而是契约的一部分。防线放在两侧：prompt 端做约束，代码端做分层兜底，中间用日志和修复率把格式漂移暴露出来。四层结构加起来不到一百行，对流水线可用性的提升是实打实的。
