## 背景

玩 Agent 的人大多熟悉 AGENTS.md / CLAUDE.md 这类"项目说明书"：放在仓库根目录，告诉 Agent 项目的技术栈、约定和禁忌。但用得久之后会发现一个更基础的问题——Agent 知道项目是什么，却不知道**你**是谁。

OpenClaw 的 workspace 里支持放一份 `USER.md`（个人上下文文件），每次会话启动时注入 Agent 的上下文。它的定位和 AGENTS.md 互补：AGENTS.md 描述"这个项目怎么干活"，USER.md 描述"给我干活的人是谁"。

## 问题

没有个人上下文时，日常使用会出现几个典型摩擦：

- 每次重复交代环境："我用 macOS + Homebrew，别给 apt 命令"
- Agent 默认输出英文长篇解释，而你只想看中文结论
- 代码风格偏好反复被忽略，同一件事纠正三遍
- 换个会话，一切归零

这些不是模型能力问题，是上下文缺失问题。解法很朴素：把"关于你的稳定事实"写成一份文件，让 Agent 每次自己读。

## 做法

**1. 放对位置。** 在 workspace 根目录建 `USER.md`。它是个人文件，跟着你走，不进业务仓库——我用 dotfiles 仓库同步多台机器。

**2. 只写稳定、可执行的事实。** 我的骨架大致是：

```markdown
# About Me
## Environment
- macOS + Apple Silicon；包管理用 Homebrew，不用 apt
## Preferences
- 中文交流，先结论后细节，不铺垫
- 注释用中文，标识符用英文
## Conventions
- Python 用 uv，测试用 pytest
## Don't
- 不要主动升级依赖大版本
- 不要输出客套话
```

**3. 控制篇幅。** 这份文件每次会话都占上下文，建议 30 行以内。它不是日记，是配置。

**4. 迭代维护。** 规则很简单：**同一个纠正说第二遍时，就写进 USER.md**。也可以直接让 Agent 自己追加，"把这条偏好记进 USER.md"在 OpenClaw 里是可行的工作流。注意和 MEMORY.md 分工：USER.md 管稳定画像，MEMORY.md 管事件流水，别混着写。

## 踩坑点

- **写太多。** 初版我写了 80 多行，Agent 输出明显变啰嗦，注意力被稀释。砍到 25 行后反而更听话。少而准 > 多而全。
- **写空话。** "写出高质量代码"这种无法执行的描述等于没写。每条都应能推出具体行为："用 pytest""先给结论"。
- **信息过期。** 换了机器、换了技术栈忘更新，Agent 会拿着旧地图指挥。建议每月扫一遍。
- **塞敏感信息。** 别放 API key、真实住址。USER.md 每次会话都被注入，泄露面等于所有会话。
- **和项目指令打架。** USER.md 说"中文注释"，某项目 AGENTS.md 说"英文注释"，此时项目级优先。个人偏好别写死到必然冲突的程度。

## 可复用建议

- 用 dotfiles 管理，多机共用一份
- 四段模板够用：Environment / Preferences / Conventions / Don't
- 每条偏好写成"遇到 X 就做 Y"，方便 Agent 执行也方便你审计
- 定期让 Agent 读一遍 USER.md 并指出过时条目——自检比人肉记忆靠谱

## 总结

USER.md 解决的不是模型问题，而是信息架构问题：把"每次重复交代"变成"一次声明、处处生效"。它的价值不在多，而在于每一条都真实、稳定、可执行。花二十分钟写好初版，之后让日常纠错驱动迭代，你和 Agent 的沟通成本会明显下降，它终于知道你是谁了。
