## 背景

让 Agent 拿到 shell 和文件工具之后，大家担心的从来不是“它不会干活”，而是“它干活的范围不受控”。模型对路径、命令副作用、软链接指向的判断本质上是概率性的，一次幻觉就足以让 `rm -rf` 落在错误的位置。OpenClaw 的思路很明确：不赌模型聪明，赌它会犯错，然后用沙箱边界兜底。

## 问题：误删到底是怎么发生的

复盘常见的失控场景，基本是三类：

1. **工作目录漂移**：Agent 在多步任务中 `cd` 到了意料之外的目录，后续相对路径操作全部偏移；
2. **破坏性命令穿透**：`rm`、`find -delete`、覆盖重定向直接作用在宿主文件系统；
3. **插件/MCP 工具越权**：某个第三方工具拿到了过大的挂载范围，间接写到了 workspace 之外。

## OpenClaw 的做法

### 1. 分层沙箱，宿主路径不进来

Agent 默认运行在容器沙箱中，文件工具只挂载一个独立的 workspace 卷。宿主的 home、系统目录、SSH 凭证根本不在容器内——这是最硬的一道边界，不是靠 prompt 约束，而是靠不存在。

### 2. 路径解析 + 越界拒绝

文件类工具在执行前会对目标做 realpath 解析，解析结果必须落在 workspace 根之内，否则直接拒绝。这一步防的是软链接逃逸：workspace 里出现一个指向外部的 symlink，写操作会被拦截。

### 3. 破坏性操作走确认门

`rm`、批量删除、覆盖写这类操作默认进 permission gate，需要显式确认；更实用的做法是把“删除”降级为“移入 workspace 内的 trash 目录”，误删可回滚，Agent 侧感知不到区别。

### 4. 默认只读，按会话授权

工具集默认只读，写能力按任务/会话显式授予，用完即收回。shell 工具与专用文件工具走同一套路径策略，避免 Agent 用 bash 绕过文件工具的限制。

## 踩坑点

- **把整个 home 挂进沙箱**：等于没有沙箱，最常见的配置错误；
- **privileged 容器或挂载 docker.sock**：Agent 一条命令就能逃逸到宿主；
- **确认门设成“总是允许”**：图省事，防线归零；
- **只约束文件工具、放开 shell 工具**：策略不一致等于没约束。

## 可复用建议

- 最小挂载：只给任务需要的子目录，宁可多授权几次；
- 删除一律软删除，回收站放在 workspace 内并定期清理；
- 保留工具调用审计日志，事后能回答“它到底碰了什么”；
- 定期演练：在测试沙箱里故意让 Agent 跑危险任务，验证拦截是否生效。

## 总结

“Agent 不会误删文件”不是因为模型可靠，而是因为最坏情况下它也只会在一个可丢弃的沙箱里犯错。边界、解析、确认门、软删除，四层叠起来，才谈得上放心地让它自动化。
