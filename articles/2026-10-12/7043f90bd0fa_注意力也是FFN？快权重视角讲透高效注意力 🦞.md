NeurIPS'26 上有一项讨论度很高的工作，核心论点听着有点冲：**注意力其实也是一种 FFN**。这不是抖机灵，它背后是一条从 1991 年 Fast Weight Programming 一路铺过来的老线——把注意力改写成“权重在运行时由输入生成的 FFN”之后，Mamba、RWKV、RetNet、DeltaNet 这些高效架构的分歧点，会突然收敛到三个很小的设计旋钮上。这篇文章就把这条线拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/5c0cb3e74ec81c7e.png)

## 一、先对齐概念：FFN 和 Attention 各自在算什么

- **FFN** 就是 `y = W2·σ(W1·x)`。W1、W2 训练完即冻结，推理时无论来什么输入，权重纹丝不动。它是模型的“长期记忆”：以标准的 4 倍扩展为例，每层 FFN 参数量约是注意力层的 2 倍，事实性知识大多存在这里。
- **Attention** 的标准形式是 `softmax(QKᵀ/√d)·V`：每个 token 拿自己的 query 和全部历史 key 算相似度，再对 V 加权求和。它更像“工作记忆”：按需检索，用完即走。
- 成本差异才是关键：FFN 是 `O(n·d²)`，注意力的相似度矩阵是 `O(n²·d)`。序列长度 n 一旦超过维度 d，注意力就成为主要开销；n 到 128k 这个量级，平方项足以让训练显存失控。
- 一个容易被忽略的观察：如果把注意力输出改写成 `y = S(x)·x`，其中 S 是由上下文**即时拼出来的矩阵**——它和 FFN 的 `y = W·x` 在形式上只差一件事：W 是不是冻结的。

## 二、快权重：三十五年前埋的伏笔

- 1991 年 Schmidhuber 提出 **Fast Weight Programmers**：用一个“慢网络”生成并更新另一个“快网络”的权重。快网络的权重随输入流动，像一块可以边跑边改写的工作内存；相对地，SGD 慢慢磨出来的参数叫 **slow weights**。
- 2021 年《Linear Transformers Are Secretly Fast Weight Programmers》把这条线接回注意力：线性注意力的状态更新为 `S_t = S_{t-1} + φ(k_t)v_tᵀ`，读出为 `y_t = S_t·φ(q_t)`。S 是一张 d×d 的矩阵，每来一个 token 就加一项外积——这正是“慢网络（当前输入）在改写快网络（状态矩阵）”。
- 换个说法：KV cache 的另一种打开方式，不是老老实实存 n 个 key-value 对，而是把它们**焊接进一张固定大小的权重矩阵**里。

## 三、“注意力也是 FFN”到底在说什么

- 数学上可以严格写：单步注意力输出 `y_t = Σᵢ(q_tᵀkᵢ)vᵢ = (Σᵢ vᵢkᵢᵀ)·q_t`。括号里正是矩阵 S。把 q_t 看成输入、S 看成权重，这就是一个“权重由上下文现场拼装”的线性层——FFN 的动态版。
- softmax 的角色是检索时的非线性函数，把“模糊的关联”变成“尖锐的查找”；用特征映射 φ(·) 近似它，就得到线性注意力，此时注意力退化成纯粹的动态权重 FFN。
- 论文的统一框架下，softmax 注意力、线性注意力、Mamba 类 SSM、RWKV、RetNet、DeltaNet 全是“动态权重 FFN”，差异收敛到三个旋钮：
  1. **状态形状**：d×d 矩阵，还是更大的张量甚至一个小网络（TTT、Titans）；
  2. **写入规则**：外积累加 / 带衰减的累加 / delta 规则先擦后写；
  3. **读出规则**：线性读出、门控读出、softmax 精确检索。
- 所谓“高效注意力”，本质是把 n² 次成对比较压缩进固定大小的状态：省下算力与显存，代价是记忆被压缩、精确回忆变难。天下没有免费的上下文。

## 四、拿三个旋钮去拆热门模型

- **线性注意力**（Katharopoulos et al., 2020）：`S ← S + φ(k)vᵀ`，纯累加。写得越多越糊，像一块从不擦的黑板。
- **RWKV / RetNet / Mamba-2**：`S ← γS + kvᵀ`，加衰减因子，旧记忆指数褪色，黑板会自己变淡。Mamba-2 的 SSD 理论更证明了一类 SSM 与线性注意力数学对偶——同一个状态两套算法：递归形式省显存，分块矩阵形式吃满 tensor core。
- **DeltaNet / gated DeltaNet**：`S ← S − βk(kᵀS) + βkvᵀ`，写新值之前先把同 key 的旧值减掉，等价于 key-value 字典的覆盖写。做关联召回、状态追踪明显更稳，是近期长上下文任务榜单上混合架构的常客。
- **TTT / Titans** 走得更远：把“更新规则”本身换成一个小网络加梯度下降，fast weights 在推理时做 test-time 训练——注意力不只是 FFN，还是一个现场学习的小模型。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/e48e74416c5aa459.png)

1. **别急着宣布“Transformer 已死”。** softmax 的精确检索在长程精确回忆（大海捞针类任务）上仍有硬优势；目前跑得通的实际路线大多是混合架构——少数几层 softmax 注意力负责精确检索，大量线性/SSM 层负责省成本，是“分工”而不是“替换”。
2. **选型先算账。** `O(n²d) → O(nd²)` 的收益，只在 n 明显大于 d 时才兑现（长文档、基因序列、长视频）；如果你的上下文只有 4k~8k，固定状态省下的那点 KV cache 未必是瓶颈，换架构反而可能损失召回质量。
3. **读新架构论文，先找三个旋钮：状态多大、怎么写、怎么读。** 用这个框架去拆模型，能把“全新架构”的营销滤镜一层层剥掉，直接看出它到底动了哪个旋钮、用什么代价换的。

快权重视角最大的贡献，是把“内存不够用”这句工程师的日常抱怨，变成了一个可以设计、可以优化的数学对象。下次再看到“XX 架构刷新长序列榜单”，不妨先问一句：它擦黑板的方式，变了吗？
