NeurIPS'26 的讨论区最近被一篇论文刷屏，核心观点很抓眼球：**注意力也是 FFN**。乍一听像营销口号，其实背后是一条从 1991 年“快权重”（Fast Weights）延续至今的技术暗线。把注意力、FFN、线性注意力、SSM 放到同一张“记忆读写”地图上，很多高效注意力的设计取舍会突然变得好懂。这篇帮大家把这条线捋清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/b380a8cbff624054.png)

## 一句话版本：它们都在“查记忆”

先看两个容易被忽略的等价关系：

- **FFN 是记忆库**：Geva et al. 2021 指出，Transformer 的 FFN 本质是一组 key-value 记忆，第一层权重矩阵像 keys，第二层像 values，非线性激活充当相似度匹配。模型知识主要“住”在 FFN 里。
- **注意力也是记忆库**：y = softmax(qK^T)V，同样是“拿 query 去取 values”，只是 K、V 由当前上下文动态生成，相当于现场搭一个记忆库。

两者真正的差别只有一个：**记忆是什么时候写进去的**。FFN 的权重在训练期由梯度写入、之后冻结，这是慢权重；注意力在推理期逐 token 把信息写进 KV cache，这是快权重。所以“注意力也是 FFN”可以翻译成：注意力是一个**权重由输入实时生成的 FFN**。

## 快权重：一个 34 年前的老思路

- **1991 年**，Schmidhuber 提出 Fast Weight Programmers：慢网络用梯度下降学“技能”，快网络在前向传播中被逐时刻改写，充当短期记忆。2016 年 Ba et al. 又把这个思路接回深度学习。
- **2021 年 ICML**《Linear Transformers Are Secretly Fast Weight Programmers》给出精确等价：线性注意力可以写成 S_t = S_{t-1} + v_t k_t^T，读出 y_t = S_t q_t。S 就是那份被逐时刻写入的权重矩阵：外积是“写”，query 是“读”。
- **写入会打架**：不断做加法，相似内容会互相覆盖、干扰，这是 associative memory 的经典问题。Delta rule 的解法是先擦后写：S_t = S_{t-1} − β(S_{t-1}k_t)k_t^T + β v_t k_t^T；RetNet、GLA、Gated DeltaNet 再加门控衰减，控制“忘多少”。
- 一句话总结这一支的全部工作：**设计更好的写、擦、忘、读规则**。

## “注意力也是 FFN”到底在说什么

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/fb96aa04f98409dc.png)

- **softmax attention = 不压缩的快权重网络**。KV cache 就是它的权重矩阵：每个 token 追加一个 rank-one 更新，读出时 softmax 在全部槽位上做加权平均。记忆容量几乎无上限，代价是显存随序列线性增长、训练计算 O(T²)。
- **线性注意力 / SSM = 压缩进固定大小的状态**。所有写入合并进一个 d×d 矩阵，推理显存 O(1)；代价是检索精度受矩阵秩约束，随机 key 近正交意味着不冲突的键值对大约只能存 d 个量级，联想召回（associative recall）能力下降。
- **FFN = 训练后冻结的退化情形**：权重对所有输入共享，只读不写。
- 在这个模板下，DeltaNet 是“覆盖式写”，Mamba 是“对角 + 门控写”，TTT 更激进——直接把状态本身当成一个小网络、用测试时梯度下降来写；Titans 用“惊讶度”门控写入并叠加动量。Mamba-2 的 SSD 也早已证明注意力与 SSM 存在结构对偶。这篇新论文的贡献，是把整个谱系统一成**同一份快权重状态 + 四个可选算子（write / erase / forget / read）**的设计空间。

## 为什么这波研究现在突然提速

- **长上下文的账很现实**。以 7B 级 GQA 模型 fp16 估算，32k 上下文的 KV cache 约 4GB；batch 一大，推理瓶颈是显存带宽而非算力。固定状态模型解码时每 token 显存 O(1)，对高并发部署天然友好。
- **训练侧补齐了短板**。chunkwise 并行让线性注意力家族重新变回大矩阵乘（flash-linear-attention 这类 kernel），硬件利用率追上 softmax attention，不再只是“理论优雅”。
- **但纯固定状态有硬伤**。MQAR 这类联想召回测试反复显示压缩会丢信息，所以工业界的答案普遍是混合架构：Jamba、Samba、MiniMax-01、Gemma 3，都是“绝大多数层用线性或滑窗，留少数几层全局 softmax 兜底”。
- 统一视角顺便解释了混合为什么有效：那几层全局注意力，就是给整张记忆表开了几个**无压缩写入的口子**，专治召回失败。

## 收尾三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/de15bfd488f8d19a.png)

1. **框架统一 ≠ 性能领先**。新规则要过三关：chunkwise 训练 kernel 的硬件利用率、低精度下衰减与归一化的数值稳定性、长程遗忘曲线是否伤任务。读论文先盯这三处，再看头条数字。
2. **评估要贴自己的负载**。MQAR、needle-in-a-haystack、长文档 QA 是三把不同的尺子，结论可能互相矛盾；混合架构里“哪几层留全局注意力”的配置差异，影响常常大于模型本身。
3. **押注前看工程生态**。kernel 是否开源、vLLM/SGLang 是否支持、状态矩阵能否像 KV cache 一样量化压缩、与投机解码是否兼容，这些决定它能不能真的上生产，而不是只活在 benchmark 里。

注意力与 FFN 的边界被抹平之后，“高效注意力”不再是黑魔法集锦，而变成一张可以系统性搜索的地图：想要大容量就付显存，想要常数显存就设计更好的写擦规则，想两全就开几个全局口子。softmax attention 暂时还不用进博物馆，它只是选择了用显存换精度。对工程师来说，这张地图可能比任何单篇 SOTA 都更值钱。
