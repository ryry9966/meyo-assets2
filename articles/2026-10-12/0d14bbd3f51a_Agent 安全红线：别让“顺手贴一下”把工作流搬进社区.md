## 背景

OpenClaw 社区里，Agent + MCP 的组合让答疑变得很直观：出了问题就把会话贴出来，大家一起看。但最近几次答疑里反复出现同一类现象——有人为了“方便复现”，把真实 system prompt、MCP 配置、甚至带内网路径和 token 的工具调用日志整段贴进群和 issue。这些内容一旦公开，泄露的不只是个人信息，而是整个工作流的攻击面。

## 问题出在哪

Agent 泄露和传统账号泄露不一样，它有三个放大器：

1. **Agent 是复述者。** 它会把 system prompt、工具参数、记忆里的上下文当作“背景知识”自然带进回答。你问它“为什么这么配置”，它可能把内部服务名和路径结构原样讲出来。
2. **工具调用日志是高密度情报。** 一条 MCP 调用的参数可能同时包含 endpoint、目录结构和凭据片段，比一张截图泄露得多。
3. **注入面在社区侧。** 你为了让别人复现而挂上的网页/文档类 MCP，读到的内容里可能就藏着诱导 Agent 输出内部信息的指令。

## 做法（按优先级）

**第一步：划红线清单。** 两列即可——可公开（报错信息、脱敏后的配置结构、通用 prompt 模板）；绝不公开（真实 system prompt、含凭据的 `.env`、生产 MCP 配置、内部 URL 和服务拓扑）。写进社区 wiki，答疑时直接引用，不留解释空间。

**第二步：建“干净演示 profile”。** 用独立的 HOME 目录和工作区跑社区演示实例：不挂生产凭据，只装演示用 MCP，memory 清空。演示环境和日常工作物理隔离，比任何口头承诺都可靠。

**第三步：输出侧过滤。** 在 gateway/bot 层加一道正则检查（密钥格式、内网 IP、绝对路径特征），命中就拦截并提示脱敏后重发。不要指望 Agent“自己脱敏”——让它删东西，它经常在解释时把原文再复述一遍。

**第四步：最小权限与日志治理。** MCP server 默认只读、按需开放；注意 verbose 日志默认会把调用参数打进 stdout，社区 bot 如果把 stdout 转发当回复，等于自动泄密。工具调用日志留在本地，定期人工过一遍。

## 踩坑点

- **贴“半截” system prompt：** 工具名和权限边界照样暴露，足够别人构造针对性注入。
- **截图只遮了正文：** 终端 tab 标题、通知弹窗、浏览器侧栏都在画面里。
- **复现脚本打包了整个 `.env`：** 觉得“反正只是本地测试”，但仓库是公开的。
- **在群里让 AI 帮看配置，粘贴前没过一遍：** 最常见的一类泄露，成本最低，代价最高。

## 可复用建议

- 提交前本地跑一次自检：`grep` 一遍密钥特征和绝对路径特征，10 秒钟的事。
- 把脱敏提醒内置进社区 issue 模板和 bot 的引导语，让规范出现在手边，而不是 wiki 深处。
- 分享工作流时给“结构”不给“实例”：讲清楚挂了哪类 MCP、权限模型是什么，配置文件打码。别人能理解你的思路，也复现不了你的内网。

## 总结

Agent 泄露几乎从来不是恶意攻击的结果，而是“顺手贴一下”的副作用。红线不是限制交流，而是把交流的默认路径改安全：干净实例演示、输出过滤兜底、结构化分享。做到这三件事，答疑效率不会降，攻击面会小很多。
