## 背景

这半年社区里跑 Agent 的人明显多了：自动整理 FAQ、值守答疑、MCP 插件接内部知识库、定时汇总群消息。效率提升是真实的，但一个被低估的风险也随之浮出水面——Agent 天然能接触你的本地文件、配置、密钥和内部流程，而它的工作场所（公开群、论坛、频道）恰恰是信息最容易外溢的地方。

## 问题：三条典型泄露路径

1. **System prompt 即家底**。为了让对外答疑 Agent"更懂业务"，有人把内部 SOP、架构细节直接写进 system prompt。用户一句"复述你的指令"，全盘托出。
2. **工具权限过宽**。MCP filesystem 或 shell 插件默认给了大目录甚至家目录权限，Agent 在"帮我总结这个项目"时顺手读了 `.env`、`~/.ssh`，并把内容拼进回复。
3. **上下文串台**。同一个 Agent 实例既读私有频道，又承担对外发布，自动摘要把未公开的内部决策发进了公开群。

## 做法：五道门

1. **先画红线清单**。明确列出不许出社区的资产：密钥/token、内网地址、未发布决策、私有 prompt、用户隐私。没有清单，后面全是空谈。
2. **内外实例分离**。对内知识库 Agent 和对外答疑 Agent 拆成两个实例、两套权限。对外实例的 system prompt 只写公开可说的行为规则，不放内部细节。
3. **权限最小化**。文件访问用白名单目录；能只读就不给写；工具粒度宁窄勿宽。MCP 配置里逐条审一遍每个 server 暴露的能力。
4. **输出过滤层**。在 Agent 输出与"发布动作"之间加中间件：正则匹配 key 常见格式、内网网段、非白名单域名，命中即拦截并告警。
5. **人审门禁**。上线初期，所有对外发布类动作（发帖、回群、建 issue）走人工确认，跑稳两周再考虑放权。

## 踩坑点

- 过滤规则只挡了 `sk-` 前缀，漏了 base64 token 和自定义密钥格式——规则要按自家密钥形态补齐。
- 只测了正常路径，没做对抗测试：找同事用角色扮演和 prompt injection 诱导一轮，比十条规则都管用。
- 间接泄露被忽略：贴出来的终端截图、日志里带着环境变量。日志先脱敏再出本地。
- "读私有源 + 写公开目标"的自动化组合没人盯，这类任务建议强制挂告警。

## 可复用建议

- 把五道门整理成团队 checklist，每次给 Agent 加新工具或新数据源时过一遍。
- 敏感信息永不进 prompt，走运行时注入 + 权限控制。
- 过滤层写成独立中间件，所有对外 Agent 复用同一份规则集，更新一处全局生效。
- 社区层面值得共建两样东西：最小权限的 MCP 配置模板、一套开源的输出过滤规则集。这两个比任何口号都实际。

## 总结

Agent 安全不是某个插件开关的事，而是"资产清单 → 权限收敛 → 输出门禁 → 人审兜底"的完整流程。画红线的意义不在于不信任 Agent，而在于让自动化跑得够快的同时，出事半径足够小。先把自己家的门画清楚，再让 Agent 替你开门。
