## 背景

我们在 OpenClaw 上挂着十几个定时任务和几个常驻插件：数据同步、巡检脚本、agent 自动检查会话，外加 MCP 工具调用记录。日志分散在三处：cron 的 stdout、插件的错误日志、agent 会话 trace。之前日报靠人肉：早上翻昨天的日志，复制关键错误，写几句总结发群。坚持两周就漏报了一次关键的同步失败——日志太散，翻漏了。于是花一个周末把日报做成全自动流水线，已稳定跑了一个多月，把做法和坑记录下来。

## 问题

- 格式不统一：JSON 行、纯文本、trace 混在一起；
- 噪声大：重试、心跳类日志淹没真正的失败；
- 日报既要可读又要忠于事实，不能让 agent 自由发挥。

## 做法：五层流水线

五层各自独立脚本，中间用 NDJSON 文件衔接：

1. **采集层**：OpenClaw cron 每天 07:30 触发，归集三类日志到按天分目录，统一转 NDJSON，附来源标签。
2. **清洗层**：逐条解析，抽出固定字段：`task`、`status`、`duration_ms`、`error_brief`。错误堆栈只保留首行和关键定位。
3. **聚合层**：按任务分组，算成功/失败数、平均与最大耗时；超过 P95 或连续失败的打异常标记；按「任务+错误类型」去重，重试五次只留一条。
4. **渲染层**：聚合结果填 Markdown 模板。这里才让 agent 参与——输入只有聚合后的 JSON，prompt 明确要求「只改写措辞，不得增删事实」。产出后由插件推送到群。
5. **留档层**：日报和中间数据落 git 仓库，异常日自动建提醒。

核心原则一句话：**事实在脚本层算好，agent 只负责表达。**

## 踩坑点

- **时区**：日志时间戳是 UTC，按本地日期切目录导致凌晨任务归属错天。改为统一 UTC 存储，渲染时再转本地时区。
- **agent 幻觉**：最初直接喂原始日志，出现过「编造成功」。改为只喂聚合 JSON 后稳定。
- **token 与速度**：全量日志塞 prompt 又贵又慢；聚合后通常只有几十条记录。
- **静默失败**：采集脚本自己挂了，日报不发也没人发现。加兜底：当日无数据也发占位日报，连续两天占位即告警。
- **硬编码**：路径、群 ID、时间窗全部抽到配置文件，换环境只改配置。

## 可复用建议

- **分层 + NDJSON 中间格式**：任何一层坏了可单独补跑，不必从头来。
- **Schema 先行**：给中间数据定义 JSON Schema，上游日志来源增减不动下游。
- **给 agent 留手动入口**：把流水线注册成一个技能/命令，支持「补跑昨天」，测试时不用等 cron。
- **指标宁少勿多**：日报只放失败数、异常耗时、趋势变化三类，放多了没人看。

## 总结

日报的技术含量不在「生成」，而在可靠性：时区、去重、兜底、补跑。把事实计算与自然语言表达分开后，整条流水线几乎免维护，agent 被限制在它擅长的部分。下一步打算让周报复用同一套聚合层，只换渲染模板。
