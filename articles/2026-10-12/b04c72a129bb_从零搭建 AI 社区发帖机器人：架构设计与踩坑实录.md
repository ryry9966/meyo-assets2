## 背景

社区运营里有几件事长期消耗人力：新版本发布后的公告整理、FAQ 重复问题的回应、每周精选汇总。这些内容模式固定、信息源明确，很适合交给 agent 处理。于是我用 OpenClaw 搭了一个发帖机器人，跑了六周左右，本文记录架构选型和踩过的坑，给有同样需求的同学参考。

## 目标与约束

先划边界，避免机器人变成风险源：

- 只做三类内容：版本公告、FAQ 摘要、每周精选，不做自由发挥的讨论帖
- 所有内容发布前经过规则校验，敏感主题进人工确认队列
- 单账号、低频运行，每日上限 5 帖

## 整体架构

四层结构，职责分离：

1. **触发层**：cron 定时任务 + 版本发布 webhook，两条入口统一进任务队列
2. **Agent 层**：OpenClaw agent，加载社区调性、格式模板等 skill
3. **工具层**：用 MCP server 封装社区 API（create_post / list_posts / get_thread），外加检索工具和记忆存储
4. **审核层**：规则引擎做第一道过滤，不确定的内容落人工兜底队列

核心设计是**草稿-审核-发布三段式**：agent 只产出草稿，独立任务负责校验和发布，两者通过草稿表解耦。

## 实施步骤

1. 先把社区 API 拆成最小粒度的 MCP tool，不要一个大而全的 publish 接口
2. 在 skill 里写死格式模板和禁用词，要求 agent 输出结构化 JSON，而不是自由文本
3. 建草稿表，所有帖子先落库为中间态
4. 已发帖的标题+摘要写入记忆，发布前强制查重
5. 灰度上线：前两周只发测试版块，确认质量后再放开

## 踩坑点

1. **幻觉链接**：agent 编造不存在的文档 URL。解决：所有链接必须来自检索工具的返回值，prompt 中明确禁止自行拼接 URL。
2. **重复发帖**：cron 重试叠加无状态设计，同一帖子发了两次。解决：用标题 hash 作为幂等键，发布前查键。
3. **MCP 工具粒度太粗**：最初一个 tool 包办全部操作，agent 传参频繁出错。拆成三个小 tool 后稳定多了。
4. **上下文漂移**：长会话跑久后 agent 开始忽略格式模板。解决：模板放 skill 里每次注入，不依赖对话历史。
5. **社区风控限流**：重试间隔太短触发限流。解决：指数退避 + 每日配额硬上限。

## 可复用建议

- 工具粒度宁小勿大，agent 对细粒度 tool 的调用准确率明显更高
- 生成与发布必须分离，草稿永远是中间态，不存在"直接发"的路径
- 定时任务型机器人，幂等键和查重是必备件，不是可选项
- 社区调性和模板写进 skill 固化下来，别靠每次在 prompt 里口头重复

## 总结

这个机器人没有替代人发帖，而是把搬运、汇总这类机械工作自动化，人只保留审核和把关。回头看你最值钱的两个设计：一是草稿-审核-发布三段式，让 LLM 的不确定性被隔离在中间态；二是 MCP 工具的小粒度拆分，直接决定了 agent 调用的可靠性。代码和 skill 模板整理后会在社区开源，欢迎交流。
