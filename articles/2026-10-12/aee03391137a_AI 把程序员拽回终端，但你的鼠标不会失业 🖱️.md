命令行界面（CLI）大概是软件史上被“唱衰”次数最多的形态——自图形界面诞生那天起，每隔几年就有人宣布它进了博物馆。结果这两年剧情反转：AI 编程工具集体把主场搬回终端，Claude Code、Codex CLI、Gemini CLI、Aider，一个个 agent 就住在黑底白字的窗口里写代码、跑测试、提交 commit。36kr 热议文章的判断是“AI 复兴了 CLI，但图形界面不会消亡”，方向没错，但可以说得更透：**界面演进史从来不是替代史，而是叠层史。**

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/966751047d08d795.png)

## CLI 为什么又香了：agent 的母语是文本

LLM 处理的原生格式就是 token 化的文本。对模型来说，读一段 `git diff` 的成本，远低于解析一张截图或一棵嵌套十几层的 DOM 树。终端因此成了 agent 的“母语环境”，拆开看有四个硬理由：

1. **输入输出都是纯文本**。stdout、stderr、exit code 的反馈结构化程度极高，agent 发一条命令立刻知道成败，能自主决定下一步——这正是 agent 最需要的执行闭环。
2. **可组合性**。Unix 哲学讲究小工具 + 管道，`grep | sort | uniq` 这样的流水线，agent 可以像搭积木一样自由拼装，比逐个点 GUI 按钮灵活得多。
3. **Token 效率高**。同样的信息量，命令行文本往往比网页 DOM 或视觉截图省一个数量级的上下文，模型“看”得更省、更准。
4. **无头可自动化**。SSH 上服务器、跑定时任务、进 CI 流水线，终端天然不需要“有人盯着屏幕”。

所以 Claude Code、Codex CLI 把终端当主战场，不是复古情怀，是工程最优解。

## 界面层的历史：每次“革命”都是“叠加”

翻一下时间线会更清楚：

- 1969 年 Unix shell 诞生，人机交互就是一问一答的对话；
- 1973 年施乐 PARC 做出 Alto，1984 年 Macintosh 把 GUI 带给大众，“桌面隐喻”统治了个人电脑；
- 1990 年代 Web 界面崛起，2007 年 iPhone 又把交互拍进触摸屏。

关键在于：**每一代新界面都没有杀死旧界面**，而是各自沉淀到最合适的场景。GUI 统治消费端，CLI 退守服务器机房、开发者机器和自动化脚本，几十年从未离场。“CLI 已死”真正死掉的，只是“普通人必须用 CLI”这个假设，而不是 CLI 本身。

## GUI 的护城河：恰好补上 CLI 的盲区

GUI 不退场的底气，来自人脑和模型工作方式的差异：

- **可发现性（affordance）**：按钮和菜单把“能做什么”直接画在脸上；CLI 则要求你先知道“动词”存在才会去问。对新用户，GUI 的学习曲线永远更平。
- **空间认知与直接操纵**：拖拽、缩放、所见即所得，调用的是人类视觉通道的高带宽。做设计、剪视频、看地图、打游戏，纯文本承载不了像素级反馈。
- **信任与确认**：人在高风险操作前想“看见”状态——一个滑块、一张预览图、一次二次确认，本质是给决策加缓冲区。
- **安全的默认值**：图形界面天然带护栏。你在 Figma 里很难手滑删库，而 `rm -rf` 只需要一个回车。

一句话：CLI 服务“明确知道自己要什么”的人（和 agent），GUI 服务“需要边看边想”的人。这两种需求都不会消失。

## 真正的趋势：一套“三层界面栈”正在成形

把视角拉高，新的分工其实很清晰：

1. **自然语言层——表达意图**：“把这个仓库的测试跑绿”，人对 AI 说人话。
2. **命令行层——agent 执行**：AI 把意图翻译成命令与管道，在终端里循环“执行 → 读输出 → 修正”。
3. **图形界面层，人类监督**：人通过 GUI 查看结果、审批 diff、按下最终确认键。

有意思的是，翻译也在反向流动：Computer Use、浏览器 agent 正在教 AI 操作 GUI，点击、填表、拖滑块。所以终局大概率不是谁吃掉谁，而是**双向翻译链**：人 ↔ 自然语言 ↔ agent ↔ CLI/GUI ↔ 系统。

商业侧的印证同样直接：Cursor、Windsurf 把终端 agent 嵌进 IDE，Warp 给终端加 AI，Figma、Notion 这类图形化产品则在补 API 和 MCP 接口，所有人都在给“第二个用户”（agent）开门。

## 收尾前，三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/8117dfca92b5048f.png)

1. **学概念，别死磕语法**。AI 抹平的是“记不住命令”的成本，抹不平“不懂原理”的成本。搞懂 `rebase` 和 `merge` 的差别，比背 flag 重要得多——你得有能力判断 agent 给的方案对不对。
2. **做产品时给两个用户留门**。未来的软件会同时服务两类用户：人类要 GUI，agent 要 CLI 和 API。无头模式、结构化输出、幂等接口，正在从加分项变成标配。
3. **别把执行权全交出去**。AI 生成的命令不等于正确的命令。保持 dry-run 习惯、用沙箱和最小权限、把人留在审批回路里，agent 搞砸了是不会替你背锅的。

界面的轮回还会继续，但方向从未变过：让机器适配更多场景，让人保留最终判断权。工具可以换代，判断力不会过时，钳子再硬，也得听脑子的。
