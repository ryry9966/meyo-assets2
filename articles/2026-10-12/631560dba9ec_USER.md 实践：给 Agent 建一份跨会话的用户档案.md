# USER.md：让 Agent 每次都认识你

## 背景

用 Agent 干活半年多，一个摩擦反复出现：每次新开会话，都得重新自我介绍一遍。用的是 Linux 还是 macOS、默认 shell 是 zsh、回复要中文、代码注释能省则省、commit 不加 emoji……这些信息写进 prompt 十几行，删了又可惜。

项目层面的上下文已有成熟方案——AGENTS.md / 项目级说明文件解决了"这个仓库怎么干活"。但"我是谁、我怎么工作"这一层，长期散落在聊天记录里，换个会话就丢。USER.md 就是补这一层的：一份跨项目、跨会话、每次启动都注入的用户档案。

## 问题

不建档案的代价很具体：

- **重复成本**：每个新会话都要重新交代偏好，忘了就返工；
- **输出不稳定**：同一个需求，今天中文明天英文，今天给 sudo 方案明天给非 root 方案；
- **上下文割裂**：同时用 OpenClaw 和自建 MCP 工具时，每个入口拿到的关于"我"的信息都不一致；
- **偏好不可迁移**：聊得越久的会话越顺手，但这部分"调教成果"换会话即失效。

## 做法

四步：

1. **建文件**。放固定路径，如 `~/.config/openclaw/USER.md`，用 dotfiles 仓库托管，方便同步和回滚。
2. **只写可执行的事实**。我用四个 section：
   - 环境：OS、shell、编辑器、时区、语言；
   - 技术偏好：默认用 ripgrep、Python 用 uv 不用 pip；
   - 协作风格：先结论后过程、直接指出我的错误、不复述我的问题；
   - 红线：不自动 commit、删文件前必确认、不动 SSH 配置。
3. **注入**。OpenClaw 侧把它加进 system prompt 的加载列表；走 MCP 的自建 Agent 就在拼装 instructions 时前置读取。关键是要"每次必加载"，不能指望模型自己想起来。
4. **验证**。注入后问一句"你目前对我的了解有哪些"，确认生效，顺便排查过期信息。

## 踩坑点

- **写太长**。第一版我写了 200 行，关键偏好被稀释，模型经常"看到但没用上"。压到 50 行内明显改善。
- **写形容词不写行为**。"我喜欢高效沟通"没有信息量；"回复控制在 10 行内，先结论后细节"模型才能执行。
- **用户级和项目级混淆**。某个仓库的构建命令写进 USER.md，换项目就变成误导。原则：跨项目仍然成立的才进 USER.md，其余归项目文件。
- **冲突没定优先级**。项目文件和 USER.md 打架谁赢？我明确写了"项目级覆盖用户级"，并在注入顺序上保证。
- **敏感信息**。别写 key、内网地址——这份文件会发给每一个模型。

## 可复用建议

- **让 Agent 自己维护**：加一条"当我重复表达某个稳定偏好时，主动建议写入 USER.md"，比人肉记得更新靠谱。
- **版本管理**：进 git，Agent 建议的变更走 diff review，相当于把个性化做成了 config-as-code。
- **定期体检**：每月删一遍过期条目，环境类信息最容易过期。
- **拆稳定与易变**：语言、时区这类身份信息少动；工具偏好常改，行尾标注更新日期。

## 总结

USER.md 没什么技术含量——一个 markdown 文件，一段注入逻辑。但它是少数投入半小时、之后每个会话都在省时间的改动。Agent 的能力上限由模型决定，日常体验的下限由上下文质量决定，这份文件管的就是下限。建议先从 20 行的"环境 + 红线"写起，跑一周再迭代。
