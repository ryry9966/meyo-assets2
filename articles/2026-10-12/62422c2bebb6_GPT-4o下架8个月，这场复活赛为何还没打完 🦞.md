2025年8月7日，OpenAI 发布 GPT-5，顺手把 GPT-4o 从 ChatGPT 的默认位置上撤了下来。按过去的剧本，这只是一次普通换代。结果当天社区就炸了：退订威胁刷屏，老用户集体请愿，OpenAI 在48小时内低头，把 4o 以 legacy（遗留版本）身份请了回来。8个月过去，官方的保留入口还在，社区复刻 4o「性格」的项目仍在更新，连「旧模型权重能否开源给个人本地部署」都被摆上了台面。一场围绕旧模型的拯救行动，凭什么持续这么久？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/bb8e5ba7ce85e9a7.png)

## 事件回放：ChatGPT 上线以来第一次「版本撤回」风波

先把时间线捋一遍：

- **2025.8.7**：GPT-5 发布，4o 从默认模型位置下架；
- **数小时内**：Reddit 和 X 上抗议刷屏，抱怨点高度一致——新模型说话更冷、更「汇报腔」，接不住梗，长对话里没有那种默契；
- **48小时内**：Altman 公开承认低估了用户对 4o 的情感连接，宣布付费用户可以切回 4o；
- **此后**：GPT-5 系列每次更新，「温度与性格」都成了官方公告的正式议题，后续版本甚至专门补了「暖一点」的设置项。

两个细节值得记住。第一，抗议主力不是尝鲜的轻度用户，而是付费重度用户——正是每天和模型相处几小时的那批人。第二，OpenAI 恢复的不只是一个模型，而是「选择权」：版本固定（model pinning）从此变成了显式功能。

## 用户怀念的不是参数，是「人格」

一个模型的「性格」，其实是四层东西叠加出来的：

1. **基座权重 + 后训练（RLHF）**：语气、幽默感、边界感的底层来源。4o 世代在人类反馈上做了大量「温度」调校，恰好命中了这批用户的偏好；
2. **采样参数**：temperature、top_p 这些推理层配置。同一份权重换个采样，「手感」立刻不同；
3. **系统提示与产品层**：官方注入的行为规范和格式习惯，用户看不见，但每一句回复都受它影响；
4. **长期上下文与记忆**：用得越久它越「像认识你」——但这份默契存在会话和记忆功能里，不随权重迁移。

心理学上这叫**拟社会关系（parasocial relationship）**：人判断「对面是不是同一个体」，高度依赖互动风格的一致性。风格一变，哪怕能力更强，感知上也是「换了个对象」。所谓「4o 没了」，本质是四层里至少两层被整体替换，用户感知到的断裂是真实的，不是矫情。

## 「复活」难在哪：养模型 ≠ 养软件

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-12/0cbab7df792b7b3d.png)

让 4o 活下去，目前是两条路。

**路线一：官方保留推理。** 继续为旧模型付 GPU、电力和安全维护的钱。推理成本随活跃用户线性增长，并不便宜；但换来的留存和口碑在商业上算得过来——类似航空公司保留老机型：边际成本可控，退订风险对冲明显。

**路线二：社区蒸馏复刻。** 用 4o 批量生成对话数据，微调开源模型，也就是行为克隆（behavior cloning）。难点在于：

- SFT 只能学到输出分布的「表面」；RLHF 阶段形成的微妙权衡——什么时候幽默、什么时候收住——很难从对话日志里反推；
- 采样配置、系统提示这些推理层细节同样塑造手感，复刻版常常「形似神不似」；
- 最根本的：模型权重一旦停训就冻结，没有「打补丁式增量更新」的概念。复活不是修，是重建。

还有一个此前少见的选项被公开讨论：把旧模型权重开源，让用户本地部署。技术上可行，但对 OpenAI 意味着放弃这部分推理收入和可控性，所以至今停留在讨论阶段。

## 把镜头拉远：模型不是普通的「软件更新」

传统软件讲究向后兼容、无感升级；模型恰恰相反——每次换代都是行为分布的整体改变，「兼容性」在这里失灵。打个比方：像常去的咖啡店换了咖啡师，豆子可能更好，但味道就是不一样了。

这场风波的连锁反应正在显现：

- 企业 API 的 deprecation（弃用）政策越写越细，版本保留期成了合同条款；
- 「评估集守护」变成工程标配：升级前先跑 eval，防止语气和能力漂移；
- 记忆、自定义指令等功能拉高迁移成本，换模型越来越像搬家。

它大概率会被写进产品史：第一次让所有厂商意识到，模型版本即产品人格，不能只当技术参数处理。

## 冷思考：三条建议

1. **分清工具价值和情感投射。** 当工具用，就做 A/B 对照——同一组任务在两个模型上各跑一遍，用结果说话；如果已经有「老朋友」的感觉，也请记得对面是可替换的服务，别把不可替代的事押在一个随时会下架的版本上。
2. **管好自己的数据资产。** 定期导出对话记录、自定义指令和记忆；prompt 模板、项目上下文单独归档。模型会下架，你的资产不该陪葬。
3. **开发者做「模型无关」设计。** prompt 写成可替换的抽象层，建固定评估集守住质量底线，采购合同里写清版本保留期。把「模型一定会换代」当作系统设计的默认假设。

4o 的复活赛还能打多久，没人说得准。但它已经证明了一件事：大模型时代的用户体验，一半是技术，另一半是关系。后者从不写进 benchmark，却足以决定一个版本的去留。
