## 背景

做 Agent、MCP 工具链或自动化插件时，几乎绕不开一件事：让模型返回结构化数据，通常是 JSON。理想情况下，模型输出一段能直接 `json.loads` 的纯文本。但实践中，同一模型在不同 prompt、不同温度、不同上下文长度下，输出格式会漂移：有时包一层 markdown 代码块，有时前后加解释文字，有时裹在自定义标签里，偶尔还有转义嵌套。如果解析器只按“理想路径”写，上线后必然间歇性失败，且失败点分散、难以复现。

## 问题

我们在一条日均几千次调用的自动化流水线里做过统计：解析失败率约 3%，但拉出失败日志一看，原因至少有六类：

1. 被 ` ```json ` 围栏包裹；
2. 裸 JSON 前后带说明文字；
3. 被 `<answer>...</answer>` 之类标签包裹；
4. 字符串值里出现未转义的换行或引号；
5. 输出被 max_tokens 截断，JSON 不完整；
6. 中文输入下偶发全角引号、尾逗号。

单条规则处理一种情况可行，但规则叠加后会互相干扰——典型如用正则提取 `{...}`，贪婪匹配会直接跨过两层对象。

## 做法：分层解析，逐层降级

核心思路：不写“万能正则”，而是写一条**尝试链**，每层只做一种归一化，失败就交给下一层，最后由 schema 校验兜底。

**第 1 层：粗清洗。** 去 BOM、首尾空白、零宽字符；剥离 `<think>` 类推理标签内容。

**第 2 层：候选段提取。** 按优先级依次尝试：直接 `json.loads` 原文 → 提取代码围栏内容（注意字符串里可能嵌套出现围栏，所以提取后仍要走后层）→ 从首个 `{` 开始做括号计数配对（跳过字符串字面量内部的花括号）→ 提取自定义标签内容。

**第 3 层：白名单修复。** 只做确定性变换：去尾逗号、去行注释、全角引号映射。不要做激进的“猜结构”。

**第 4 层：schema 校验。** 用 pydantic / JSON Schema 验证字段与类型，缺字段走默认值或显式标记失败，绝不让半结构化数据流入下游。

**第 5 层：重试。** 带上原始报错，用更严格的 few-shot prompt 重试一次，并降低温度。

```python
def parse_llm_json(raw: str, model_cls):
    text = strip_noise(raw)                # 层1
    for cand in candidates(text):          # 层2：裸文本/围栏/括号配对/标签
        try:
            obj = json.loads(cand)
        except json.JSONDecodeError:
            obj = try_repair(cand)         # 层3：白名单修复
            if obj is None:
                continue
        try:
            return model_cls(**obj)        # 层4
        except ValidationError:
            continue
    raise ParseError(raw)                  # 层5：交给重试
```

## 踩坑点

- **贪婪正则跨对象**：`\{.*\}` 会匹配到最外层之外，嵌套结构必挂。用括号计数扫描，并处理字符串内的 `{`。
- **截断输出**：解析失败先看 `finish_reason` 和输出长度。截断的 JSON 修不回来，重试时应调大 max_tokens 而不是反复换 prompt。
- **修复层失控**：一旦修复逻辑开始“猜测”模型意图，就可能把坏数据洗成看似合法的数据——这类 bug 最难查。修复只保留确定性规则。
- **日志只存解析结果**：原始输出必须落盘（哪怕采样），否则线上问题无法归因。
- **围栏嵌套**：模型可能在字符串值里输出 ` ``` `，非贪婪匹配到第一个围栏就断，提取结果残缺。

## 可复用建议

- 把整条解析链抽成独立模块加单测，用线上真实失败样本做回归用例——失败样本库本身就是资产。
- 模型支持 JSON mode / 结构化输出时优先用，但保留解析链作为降级路径，切换供应商时你会感谢它。
- prompt 里给一个带字段说明的输出示例，比反复强调“请只输出 JSON”更有效。
- 把解析失败率当指标上报，而不是只打日志。

## 总结

LLM 输出格式漂移不是 bug，是常态。防御性解析的本质不是写更聪明的正则，而是把解析从一次性字符串操作，变成一条可观测、可降级、可回归测试的流水线：清洗 → 提取 → 修复 → 校验 → 重试。每个环节职责单一，失败时能明确归因到层。这套结构在任何一个 Agent 或插件项目里都能直接复用。
