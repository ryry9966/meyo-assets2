# OpenClaw 的 AGENTS.md：写给 AI 的工作空间使用手册

## 背景

OpenClaw 的工作区里，AGENTS.md 是地位最特殊的文件。SOUL.md 决定"它是谁"，USER.md 记录"它在服务谁"，而 AGENTS.md 回答的是"它该怎么干活"。每次会话启动时，OpenClaw 会把这份手册注入上下文——相当于给一个每天都会失忆的新员工，递上同一本员工手册。

手册写得差，员工每天重犯同样的错；手册写得好，你只需要教它一次。

## 问题

没有 AGENTS.md 或写得太敷衍时，通常表现为三种症状：

1. **行为漂移**：今天把会议记录规规矩矩写进 `memory/`，明天直接丢在根目录。
2. **约定靠聊天修补**：每个新会话都要重新交代"回复简洁点""别动 config"。
3. **越权操作**：Agent 热情过头，把你的笔记"整理"得面目全非。

这些不是模型能力问题，是手册问题：规则不存在、太模糊，或者被淹没在废话里。

## 做法

一份可用的 AGENTS.md 建议控制在 100~150 行内，分四层写：

1. **边界与安全（5-10 行）**：哪些目录只读、哪些操作必须先确认、隐私文件不许外发。放在最前面，权重最高。
2. **工作区地图（10-20 行）**：`memory/` 存什么、`skills/` 怎么组织、临时文件去哪。给路径，不给形容词。
3. **常驻规则（每条一行为主）**：写"触发条件 + 动作"。例如："收到会议记录 → 存入 `memory/YYYY-MM-DD.md`，正文首行标注来源。"避免"要细心""保持专业"这类无法验证的表述。
4. **流程约定**：记忆检索的时机、任务完成的汇报格式、什么情况下主动问而不是猜。

写完做一次验收：开新会话，只说"把昨天的笔记归档"，看它是否按手册执行。没执行，说明规则不够具体，或者位置太靠后被稀释了。

## 踩坑点

- **写成许愿清单**：80 条规则等于没有规则。删到只剩你自己能背出来的部分，其余拆进 skills 或按需读取的文档。
- **规则互相矛盾**："总是先确认再执行"和"heartbeat 自动处理收件箱"放一起，Agent 只能随机选一个听。
- **把秘密写进手册**：API key、家庭住址都不要出现。AGENTS.md 会被注入每次会话上下文，秘密放环境变量或独立加密文件，手册里只写"去哪拿"。
- **和 SOUL.md 抢戏**：语气、人设归 SOUL.md；AGENTS.md 只谈操作。两份文件说同一件事，改动时必有一份被忘掉。
- **只写不维护**：踩了新坑不回写，三个月后手册就成了文物。

## 可复用建议

- 把每次"Agent 干蠢事"的复盘变成一条规则，这是手册最重要的增量来源。
- 工作区用 git 管理，AGENTS.md 的每次修改都有 commit 记录，等于给行为漂移留了审计日志。
- 每月让 Agent 对照手册自查一次执行情况，把它的自我检讨作为修订输入——但人工把关，别让它自己给自己改 KPI。
- 兜底条款值得单独一行："不确定时，先问再动。"不是所有情况都能穷举，这一条是最后的安全网。

## 总结

AGENTS.md 的本质，是把你脑子里的隐性约定显性化，并放到模型每次都会读到的位置。它不提升模型能力，只收敛行为方差；写它的成本是一次性的，收益在之后的每个会话里复利。

如果今晚只做一件事：打开工作区，把上次 Agent 惹你生气的那件事，写成一条规则。
