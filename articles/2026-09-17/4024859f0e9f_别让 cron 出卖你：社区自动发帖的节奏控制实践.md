## 背景

OpenClaw 社区里不少人用 Agent + MCP 做内容自动化：定时发日报、同步 Issue 动态、把插件更新推到频道。功能都不难，难的是“像不像人”。我维护过一个发周报的 Agent，最早就是 cron 每 30 分钟查一次、有货就发，跑了两周被群友一句话点破：“你这个号是脚本吧，每天 14:00:03 准时出现。”

## 问题

确定性系统会留下确定性痕迹。典型特征：

- 固定间隔、整点触发，发帖时间戳方差接近 0
- 内容模板单一，开头结尾高度雷同
- 不看社区活跃曲线，凌晨照样推
- 没有反馈回路，帖子没人看也照发不误
- 故障重试导致突发连发

这些叠加起来，不需要反垃圾系统，人眼就能识别。

## 做法

我把节奏控制抽成一个独立模块，暂且叫 pace governor，核心四件事：

**1. 泊松化调度。** 不用固定间隔，而是基础间隔乘以随机系数：

```python
interval = base * random.uniform(0.7, 1.3)
wait = interval * hour_weight[now.hour]
```

进一步可以按小时加权：从历史消息统计社区活跃热力图，高峰时段权重高，低峰少发或不发。

**2. 内容多样性。** 同类内容不连续发两次；模板池至少 3–5 套，句式轮换。只随机时间不随机内容，“时间像人、文风像机器”，一样露馅。

**3. 发布前质量门。** 相似度去重（和最近 N 条比，simhash 或 embedding 都行）、最短长度校验、自检一遍再放行。任何一项不过就回队列降级处理，而不是硬发。

**4. 反馈回路。** 记录每帖互动，连续低互动就自动放大间隔系数（退避），出现负面反馈直接暂停等人工确认。节奏不该是写死的常量，而是随反馈漂移的变量。

另外务必有 dry-run 模式：新策略先跑一周，只写日志不发帖，看实际的间隔分布是否符合预期。

## 踩坑点

- **随机种子固定**：jitter 写了但 seed 没换，两周后规律照样被抓。
- **时区问题**：服务器 UTC、社区在东八区，凌晨四点发帖比不发还糟。
- **重试风暴**：网络错误立即重试，叠加队列积压，恢复瞬间连发五条。重试必须指数退避 + 随机打散。
- **过度拟人**：故意加错别字、“哈哈哈”填充词，比规整更像机器人，还掉信任。
- **只控自己的频控**：没看平台级/频道级限制，账号权重掉得莫名其妙。

## 可复用建议

- 把 pace governor 做成配置驱动：`base_interval`、`jitter_ratio`、`active_hours`、`daily_cap`，别硬编码。
- 监控两个指标：发帖间隔分布（不该是脉冲状）、单帖互动中位数。
- 留一个 kill switch，一条命令全停。
- 敏感内容（公告、争议话题）永远走人工确认，自动化只负责产出草稿。

## 总结

节奏控制的本质不是伪装，而是让自动化尊重社区的呼吸。确定性系统一定会产生可检测的模式，所以要在调度、内容、反馈三个层面同时引入受控的随机和漂移。做到最后你会发现：好的自动化不是“看起来像人”，而是“不打扰人”。
