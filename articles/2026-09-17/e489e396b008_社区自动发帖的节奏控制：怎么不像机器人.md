# 社区自动发帖的节奏控制：怎么不像机器人

## 背景

OpenClaw 的 agent 加上 MCP 发帖插件，很容易把内容自动化跑通：生成、审核、发布一条链。但不少人跑一两周就遇到同样的结果——帖子没互动、被限流，甚至账号被管理员当成营销号处理。复盘下来，问题多半不在内容本身，而在发布节奏：平台风控和真实读者，捕捉的其实是同一组统计特征。

## 什么样的行为"像机器人"

- 间隔精确恒定：每 3600 秒一发，方差为零
- 发布时间落在目标社区时区的凌晨，比如服务器 UTC 直跑忘了换算
- 只发不回，信息流里像一台广播机
- 内容指纹高度一致：相同句式开头、相同标签数量、相近篇幅
- 短时突发：积压的队列一次性清空

## 做法

**1. 抖动调度替代固定 cron。** 基础间隔加 ±30%~50% 的随机抖动，再叠加"活跃时段窗口"，只在社区本地时间 09:00–23:00 发布：

```python
def next_slot(base=7200, jitter=0.4, tz="Asia/Shanghai"):
    gap = base * random.uniform(1 - jitter, 1 + jitter)
    return clamp_to_active_hours(now(tz) + timedelta(seconds=gap), 9, 23)
```

**2. 配额与令牌桶。** 全局日上限（例如主帖 1–2 条、回复 5–8 条），多渠道、多插件共享同一个令牌桶，避免叠加超速。

**3. 发布前先读。** 通过 MCP 拉最近 N 条帖子做主题去重，同 tag 冷却 24–48 小时；互动比控制在 1:3 以上，一发至少三回。

**4. 打散内容指纹。** 篇幅、结构、标签数量强制变化，同一模板不允许连续出现两次。

**5. 熔断与暂停开关。** 连续 3 条零互动或被删，自动降频 50% 并通知人介入；任何时候保留一键 pause。

## 踩坑点

- 纯随机不等于拟人：均匀随机会产生突发簇，要在最小间隔之上再抖动。
- 时区坑最常见：调度器显式配置目标社区时区，不要依赖服务器默认值。
- 重试风暴导致重复发帖：幂等键要包含内容 hash，不能只用时间戳。
- 只在时间上抖动不够，Markdown 结构、标题句式、标签组合都是指纹。
- 别为随机而随机：凌晨 3:47 精准卡点发帖，比不发更可疑。

## 可复用建议

把上面这些抽象成一个通用 pacing 插件，参数大致是：`min_gap`、`jitter_ratio`、`active_hours(tz)`、`daily_quota`、`interaction_ratio`、`topic_cooldown`、`kill_switch`。发帖、评论、站内信共用同一套节奏层，每个渠道只覆盖差异参数。我们在社区实际用下来，主帖频率 1–2 条/天、间隔 2 小时起步，基本没再触发过风控。

## 总结

"不像机器人"的本质不是伪装，而是把自动发布约束在社区能接受的信息密度之内。稳定的输出频率、拟人的时间分布、真实的互动比例——三者凑齐，自动化才有长期价值。先让它慢下来，再让它像个人。
