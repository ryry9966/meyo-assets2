## 背景

玩 Agent 的人都遇到过类似场景：换一个会话，助手又从零开始问"你用的什么包管理器""部署到哪台机器"。OpenClaw 这类常驻型 Agent 虽然有记忆能力，但记忆是碎片的、对话式的，而真正影响协作质量的信息——技术栈、偏好、硬约束——应该是一份稳定的、可版本管理的声明式配置。

项目侧我们已有成熟方案：AGENTS.md 描述仓库约定。用户侧却普遍缺位。USER.md 就是补上这一块：放在工作区根目录，Agent 每次启动加载，相当于给助手配一份"用户手册"。

## 问题

没有 USER.md 时，个性化信息散落在三处：历史对话、各项目的 AGENTS.md、你自己的脑子。后果：

1. 每个新会话重复交代环境，或者更糟——不说，然后收到一堆不适配本机的建议；
2. 多个 Agent / 多个工具各自猜，行为不一致；
3. 记忆系统记住了零散事实（"用户用 pnpm"），但无结构，召回靠运气；
4. 项目级配置无法承载跨项目的个人偏好，比如"回复用中文、给命令而不是给描述"。

## 做法

核心原则：**只写会改变 Agent 行为的事实**。

1. **建文件**。工作区根目录放 USER.md，建议五段式：身份与角色（一两行）；环境事实（OS、shell、包管理器、运行时版本、常用路径）；协作偏好（语言、详略、输出格式）；硬约束（如"不要自动执行 git push"）；明确不希望触碰的禁区。
2. **控制体积**。目标 40 行以内。它会被塞进每一次会话的上下文，长文等于持续付费且稀释注意力。
3. **接入**。OpenClaw 工作区会自动加载；其他框架可以拼进系统提示模板，或用 MCP 暴露成 resource 按需读取。
4. **版本管理**。放私有 dotfiles 仓库，多机同步，改动走 commit——它是配置，不是日记。
5. **维护循环**。会话里让 Agent 支持"记住这一点"先落记忆，每周 triage 一次：反复出现的稳定事实晋升进 USER.md，过期的删掉。

## 踩坑点

- **写成自传**。800 行人生经历没有信息增益。判断标准：删掉这条，Agent 行为会变差吗？不会就删。
- **放敏感信息**。API key、内网地址不要进 USER.md——它会进入每个上下文，一旦同步或导出就是事故。
- **信息过期**。换了机器、换了栈没更新，Agent 会带着旧假设自信输出。文件头部加"最后更新"日期，并约定 Agent 发现事实冲突时主动提示。
- **和 AGENTS.md 打架**。优先级定死：项目技术细节以项目配置为准，USER.md 只管跨项目的个人偏好。
- **写不可执行的形容词**。"喜欢优雅的代码"落不了地，"默认给 diff 而不是整文件重写"才能落地。

## 可复用建议

- 用"行为变化测试"校验每一条：这条信息能让 Agent 少问你一个问题吗？
- 像对待配置文件一样对待它：小步提交、定期 review，可以让 Agent 每月 diff 一次并提议删减。
- 验证方法很朴素：新开会话直接问"我默认用什么包管理器"，答对才算生效。

## 总结

USER.md 的价值不在"Agent 懂你"这种拟人化叙事，而在工程上把个性化从对话记忆的玄学，变成一份可 review、可同步、可回滚的声明式配置。成本半小时，收益是此后每次会话少交代一遍自己。值得现在就写第一版。
