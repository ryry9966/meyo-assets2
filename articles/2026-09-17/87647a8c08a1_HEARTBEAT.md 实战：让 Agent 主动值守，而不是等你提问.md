## 背景

大多数人对 Agent 的使用模型是"问答"：打开会话、下指令、收结果、关掉。OpenClaw 里有一个存在感很低、但会改变使用范式的机制——**heartbeat（心跳）**。Agent 会按固定间隔（默认约 30 分钟）自动醒来一次，读取 workspace 根目录下的 `HEARTBEAT.md`：里面有任务就执行，没任务就继续睡。

这篇帖子记录我把它从"知道有这个功能"到"用顺手"的过程。

## 问题：被动模式覆盖不了的场景

- **长周期的事没人盯**：盯某个分支的 CI、看磁盘水位、等一封回信。
- **你得起头**：哪怕是"每天早上汇总昨天日志"这种确定性需求，也得靠你自己记住去问。
- **跨会话失忆**：会话一关，上下文就断了。

这些任务的共性是：触发条件是**时间或状态**，不是你的提问。这正是心跳要解决的。

## 做法

1. 在 workspace 根目录建 `HEARTBEAT.md`，默认内容就写 `HEARTBEAT_OK`——这是"无事发生"的哨兵值，Agent 读到它（或文件为空）会直接跳过本轮。
2. 用"条件 + 动作 + 出口"的清单格式写任务：

```markdown
# Heartbeat Tasks

## 每轮巡检
- 检查 ~/logs/disk.log，若磁盘使用率超 90%，用 message 工具通知我，同一问题只提醒一次。
- git -C ~/projects/api status，若有超过 24h 未提交的改动，提醒我。

## 定时动作
- 若当前在 08:00–08:30 且今天尚未发日报：读 journal.md，汇总成三条以内推给我。
- 其他情况一律回复 HEARTBEAT_OK。
```

3. **间隔按任务性质调**。巡检类 30 分钟够用；别为了"即时感"压到 5 分钟，成本是线性涨的。配置键名以你安装版本的文档为准。
4. **让通知落地**。心跳产出如果只留在会话里，你不看就等于没做，任务里要显式调用消息工具把结果推出来。

## 踩坑点

- **任务写得太开放**。早期我写过"看看有什么值得关注的"，结果它每次醒来都发一段小作文。改成可判定的条件后，95% 的心跳以 `HEARTBEAT_OK` 收场。
- **没有"只提醒一次"约束**，重复告警会轰炸你。
- **忘了哨兵值**。文件里留着半成品任务，Agent 每轮都认真执行，token 悄悄烧掉。
- **依赖的工具没就绪**（比如某个 MCP server 没起），任务会静默失败。首次配置后务必盯两三个周期，确认真的在跑。
- **心跳也是一次模型调用**，不是免费 cron。另外注意时区和活跃时段，别让它在凌晨三点给你推日报。

## 可复用建议

- 把 `HEARTBEAT.md` 当**值守手册**而不是任务堆：条件可判定、动作可完成、出口明确（要么通知，要么 `HEARTBEAT_OK`）。
- **分层**：高频低成本的检查放心跳；重活、有副作用的操作留给显式指令。
- 加一条"把每次非 OK 心跳的结果追加到 journal.md"的任务，等于自带审计日志，排障时救命。
- 定期回顾：一个月后把从未触发过的任务删掉，它们只会稀释每轮心跳的注意力。

## 总结

`HEARTBEAT.md` 的本质，是把提示词从"一次对话"升级为"常驻循环"。它不适合放宏大目标，适合放那些"你懒得记、忘了会心疼"的小事。写得越克制，Agent 越像一个可靠的值守者，而不是一个定时说话的碎嘴。建议从一两个真实痛点任务开始，先跑一周，再谈扩展。
