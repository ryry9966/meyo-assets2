# 背景

OpenClaw 的 workspace 里有一组约定文件：`AGENTS.md` 约束 agent 怎么干活，`SOUL.md` 定义人格，而 `USER.md` 是唯一一个**以你为主语**的文件——身份、环境、偏好、硬约束。它随会话启动注入上下文。很多人装完框架直接开跑，这文件一直空着，结果就是每个新会话都要重新自我介绍。

# 问题

Agent 的短期记忆随会话结束清空。`MEMORY.md` 记的是事件流，适合“上周我们定了什么方案”，不适合“我是谁”。这类长期、结构化的事实如果散落在对话或 memory 里，会出现三个典型症状：

- 每次重复交代技术栈、时区、命名习惯；
- Agent 从零猜你的环境：生成的命令里 Python 版本、包管理器、路径全靠蒙；
- 输出风格漂移：你想要简洁结论，它今天给你八百字教程。

# 做法

在 `~/.openclaw/workspace/USER.md` 按分区写，控制在 60 行以内：

```markdown
# 用户档案
## 身份
- 称呼：老周
- 语言：中文优先；代码注释与 commit message 用英文
## 环境
- 主力机 macOS + Homebrew；服务器 Ubuntu 22.04
- Python 3.12，包管理用 uv
## 偏好
- 回答先给结论，细节放后
- 不用 emoji
## 硬约束
- 未经确认不重启生产服务
- 不要动 ~/deploy 目录
## 当前状态（更新于 2025-06）
- 正在重构内部 CI 流水线
```

两条原则：**事实句式、一行一条**；“当前状态”单独分区并标日期，和永久事实物理隔离。

# 踩坑点

1. **写太长**。有人把两百行简历塞进去，关键约束反而被稀释——上下文窗口和模型注意力都是有限资源，30~60 行足够。
2. **敏感信息入库**。密钥、密码、token 绝对不要写，这个文件可能被工具链读取、被 git 同步。
3. **易变信息不标日期**。三个月前的“当前在做 X”会让 agent 一本正经地错下去。
4. **和 SOUL.md 写反**。SOUL.md 是“agent 是谁”，USER.md 是“用户是谁”，混了人格会漂。
5. **写完不复核**。建议每月通读一次，删过期项。

# 可复用建议

- 把 USER.md 纳入私有 git，变更可追溯、可回滚；
- 团队内共享**模板结构**，不共享内容；
- 约束句式用“必须 / 不要”，比描述性语句服从率高得多；
- 授权 agent 自己维护：确认后把新事实追加到“当前状态”，人工做月度审计，形成半自动闭环。

# 总结

USER.md 本质上是一次上下文工程：把最稳定的那部分信息从对话流里抽出来，沉淀为静态资产。花二十分钟写清楚你是谁，比每次会话浪费的重复沟通便宜得多。它不炫技，但复利明显——agent 越了解你，交付质量的方差越小。
