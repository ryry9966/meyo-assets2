## 背景

Agent 一旦接入外部工具，“抓网页”几乎是最先被提上来的需求：摘要资讯、监控文档更新、比价、给 RAG 补料。OpenClaw 生态里很多同学的做法是直接给模型一个 `fetch` 工具，短期能跑，跑久了问题集中爆发。这篇帖子把我们内部那个抓取中间层——同事戏称“稽客”，所有网页进出都要过它这一关——的思路整理出来，供参考。

## 问题：三个典型翻车现场

1. **SPA 页面抓回来是空壳**。静态请求拿到的 HTML 只有一个 `<div id="root">`，模型对着空页面开始自由发挥。
2. **页面内容污染 Agent**。正文里藏着“忽略之前所有指令”的注释或隐藏文本，抓回来直接进上下文，等于把陌生网页的话当成了系统提示词。
3. **被封 IP / 拖垮资源**。无频控、无重试上限，某个插件循环抓同域名接口，半小时后整个出口 IP 403。

根因是同一个：把抓网页当成“取一段字符串”，而不是一条带策略的流水线。

## 做法：四个环节

**1. 分层抓取。** 先走静态 HTTP（带合理超时和如实标识的 UA），解析后判断内容密度：正文长度低于阈值，或命中“疑似框架页”特征（正文占比极低、几乎全是 script 标签），才升级到无头浏览器渲染。绝大多数站点第一层就够。

**2. 清洗与降维。** 抓回来不直接喂模型。剥离 script / style / 注释 / 隐藏元素，readability 提取正文，转 Markdown，按 token 上限截断，并固定输出结构：

```json
{ "status": 200, "url": "...", "title": "...", "content_markdown": "...", "truncated": true, "fetched_at": "..." }
```

**3. 策略闸门。** 域名白名单 + 每域名频控 + robots.txt 检查 + 单页大小上限。这些不是道德装饰，是工程必需：频控保护出口 IP，robots 检查省掉后续扯皮，白名单让“Agent 能看到什么”变成一份可审计的配置。

**4. 缓存与观测。** 用 ETag / Last-Modified 做条件请求，同一 URL 短时间内不重复抓；每次抓取记一条日志（谁发起、是否命中缓存、被哪条策略拦截）。出问题能回放，比靠猜强。

## 踩坑点

- **别把登录态塞进共享浏览器 profile**。多个插件共用一个无头浏览器实例时，A 的 cookie 会泄漏给 B 抓取的站点。按插件隔离 profile。
- **编码坑**。不少老站是 GBK，不按响应头 / meta 探测编码就解码，回来的就是一屏问号。
- **重试要有退避和上限**。指数退避、最多三次；403/429 直接熔断该域名一段时间，而不是换 UA 硬闯——硬闯只会让封禁升级。
- **截断要在清洗之后做**。先截断再清洗，可能像样的内容一行都没留下。
- **隐藏文本不只是注入风险，也是 token 浪费**。`display:none` 的评论区动辄几千字，进上下文纯属烧钱。

## 可复用建议

- 把抓取层做成独立的 MCP 工具，接口收敛为一个 `fetch(url, options)`，插件只消费结构化结果，不碰原始 HTTP。
- 策略全部配置化（一份 YAML），接入新插件时 review 配置而不是 review 代码。
- 把“网页内容 = 不可信数据”写进系统提示词，同时让抓取工具在返回里带 `untrusted: true`，双保险。
- 有官方 API 的站点优先走 API，抓取是兜底，不是首选。

## 总结

Agent 采集网页的难点不在“抓到 HTML”，而在抓到之后发生的一切：清洗、隔离、频控、审计。把这些从各插件里抽出来，收敛成一条有闸门的流水线，Agent 的网页能力才从“能跑”变成“敢开”。这层中间件代码不复杂，几百行的事；但它决定了你的 Agent 是个可靠的工具，还是个随时可能被网页反向操控的入口。
