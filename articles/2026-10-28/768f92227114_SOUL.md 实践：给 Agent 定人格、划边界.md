## 背景

OpenClaw 的 Agent 每次会话启动时会读取工作区里的一组 Markdown 文件，SOUL.md 是其中专门定义"这个助手是什么性格、守什么规矩"的一份。它不是 system prompt 的替代品，而是长期生效的人格层。实际情况是，很多人的 SOUL.md 要么留着脚手架模板没动过，要么被写成了几百行的"规则大全"，Agent 表现忽好忽坏，又说不清原因。

## 问题

用下来常见三类毛病：

1. **人格不稳定**：私聊里简洁直接，拉进群聊就变得啰嗦客套，换个渠道不像同一个助手。
2. **边界模糊**：接上 MCP 工具和自动化之后，Agent 敢直接发消息、敢调用付费接口，出了事才发现没设防。
3. **规则互相打架**：SOUL.md 写"回复要短"，AGENTS.md 又要求"输出完整报告"，模型只能随机站队。

## 做法

我的迭代流程四步：

**1. 用行为锚点写人格，不用形容词。**"直接"没有约束力，"先给结论再给理由，不写客套开场白"才有。挑 3~5 条核心特质，每条配一句可观察的行为描述。

**2. 边界写成可判定的条件。**比如：花销类操作先确认再执行；未经确认不主动给第三方发消息；MCP 工具按白名单放行；涉及家人隐私的记忆内容一律不外发。每条都要能回答"什么情况触发、触发后做什么"。

**3. 控制篇幅，分工明确。**SOUL.md 一屏以内，只回答"我是谁"；操作细则放 AGENTS.md，工具用法放 TOOLS.md。人格文件里塞满操作步骤，是它失效的开始。

**4. 进 git，按翻车记录迭代。**把工作区纳入版本管理。每次行为不合适，往 SOUL.md 加一行而不是一段，跑一两周观察副作用，再决定去留。

## 踩坑点

- **写成巨型规则列表**：超过两三屏，模型开始选择性失明，优先级反而丢了。删到只剩你愿意长期逐条维护的量。
- **文件间冲突**：改 SOUL.md 前先 grep 一遍 AGENTS.md 和自定义 prompt 模板，矛盾指令比缺失指令更糟。
- **边界太抽象**："注意安全"等于没写。要写成"删除类操作必须附带影响范围并等确认"。
- **把任务状态写进 SOUL.md**：待办、项目进展属于记忆层，混进去会让人格文件随会话漂移。
- **只测一个渠道**：心跳任务、群聊、私聊是三种语境，至少各跑一轮再判断人格是否一致。

## 可复用建议

一个骨架，直接抄：

```
# 性格（3~5 条，行为锚点式）
# 语气（分场景：私聊 / 群聊 / 心跳汇报）
# 硬边界（确认类、禁做类、工具白名单）
# 优先级（边界 > 用户偏好 > 性格表达）
```

再补两条经验：给 SOUL.md 单独留 commit 记录，回溯人格变化很方便；平时翻车先记一行到独立日志，月底集中提炼成规则，比当场情绪化加规则质量高得多。

## 总结

SOUL.md 的本质不是"调教话术"，而是给 Agent 一份长期稳定的行为契约：人格靠行为锚点，边界靠可判定条件，维护靠版本管理和克制的小步迭代。写好这几十行，比堆一百条规则更能决定你的助手像不像"你想要的那一个"。
