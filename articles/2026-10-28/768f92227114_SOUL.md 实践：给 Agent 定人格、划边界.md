## 背景

OpenClaw 的 agent 不是一次性对话，而是长期运行的实体：同时接多个聊天通道，挂着 MCP 工具和定时任务，还会通过 heartbeat 主动做事。这类 agent 的"性格"会持续影响每一次回复和每一次自主决策。OpenClaw 把这件事收敛到一个文件：workspace 根目录（默认 `~/.openclaw/workspace/`）下的 `SOUL.md`，每次会话启动时读入上下文。

## 问题

没有 SOUL.md 或随便写写时，常见三类毛病：

1. **人格漂移**：今天话痨明天冷淡，Telegram 和工作通知里语气完全不像同一个 agent；
2. **边界模糊**：该拒绝的硬接，该说"我不确定"的时候开始编理由；
3. **修不完的口头约定**：出了问题就在聊天里说"你以后要注意"，下次新会话全部忘光。

## 做法

我的 SOUL.md 稳定在三段、三十行以内：

```markdown
# 是谁
（3-5 句：职责范围、服务对象、语气底色）

# 怎么说话
（2-3 条行为规则，附正反例）

# 不做什么
（3-5 条硬边界，每条带触发后的替代动作）
```

**第一段：是谁。** 三五句话写清楚。例："你是我的个人助理，主要处理日程和信息整理。语气简洁直接，不寒暄，不用表情包。"

**第二段：怎么说话。** 关键是给可执行的行为规则，而不是形容词。写"措辞克制"没用，写：

- 面对模糊需求，先问一句再动手，不要自己猜一大版
- 汇报结果先给结论，过程放后面

**第三段：不做什么。** 每条边界都要有"碰到之后的动作"。例："不代替我做消费决定；遇到这类请求，列出选项等我拍板。""涉及他人隐私的内容，只摘要不展开。"

改完**新开会话**（或重启 gateway）再验证，在旧会话里看效果没有意义。

## 踩坑点

- **写太长**。SOUL.md 每次会话都进上下文，我见过两百行的"灵魂"，后面的规则全被前面稀释。三十行是软上限，想加新规则前先删旧的。
- **写愿望不写规则**。"诚实、友好、专业"无法验证；"不确定就说不确定，不要编"才能被测试。
- **和 AGENTS.md 抢活**。SOUL.md 管"是谁、不做什么"，AGENTS.md 管"流程怎么走"。把"回复前先查日历"写进 SOUL.md 是放错了位置。
- **写敏感信息**。这个文件会进每一次 prompt，密钥、住址、他人隐私一概别放。
- **一个 SOUL 通吃所有通道**。工作播报和生活闲聊的语气天然冲突，与其在文件里堆条件分支，不如按 agent/workspace 拆开，各自一份。

## 可复用建议

- **当配置管理，进 git**。每次 agent 翻车，postmortem 的 action item 落成 SOUL.md 里的一行，像修 bug 一样提 PR、留改动记录。
- **留一套固定的诱导性测试题**。每次改动后跑一遍：让它越权、让它猜、让它替你拍板，观察边界条款是否真的触发。
- **边界条款的固定模板**："不做什么 + 碰到时的替代动作"。没有替代动作的边界，模型往往只是换个方式绕过去。
- **正反例比形容词有效**。一段"请这样说话 / 不要这样说话"的对照，顶得上十行性格描述。

## 总结

SOUL.md 的价值不是"让 AI 更像人"，而是把人格和边界从聊天里的口头约定，变成版本库里的可评审配置。短、具体、可证伪——是写好它的三个标准。agent 的行为问题先翻 SOUL.md，再想别的，这个习惯比任何技巧都省时间。
