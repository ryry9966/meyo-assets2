## 背景

OpenClaw 的 agent 平时是“被动”的：你发消息，它回复。但很多事不适合等人来问——每天早上汇总一次收件箱、磁盘快满了要告警、把碎片笔记归档进 memory。这类任务的正确触发方式不是你记得它，而是它记得你。

HEARTBEAT.md 就是干这个的：它是 agent workspace 里的一个约定文件。Gateway 按固定间隔（默认 30 分钟）触发一次心跳，把“读一下 HEARTBEAT.md”作为系统提示喂给 agent；agent 判断有没有事可做，有就执行并主动发消息，没有就回复 HEARTBEAT_OK，这条回复会被吞掉，不会打扰你。

## 问题

没有心跳机制时的两个典型困境：一是周期性任务靠人肉触发，迟早漏；二是把“定时”逻辑硬塞进对话提示词，改一次需求就要重写一遍上下文。心跳把这些变成声明式文件——改检查项就是改 Markdown，不用动代码。

## 做法

1. 在 workspace 根目录建 HEARTBEAT.md，用“检查项”的写法而不是命令堆砌：

```markdown
# 心跳检查项（逐条判断，无事可做直接回复 HEARTBEAT_OK）

## 1. 收件箱摘要
- 读 MEMORY.md 中的 last_digest 时间戳
- 仅当距上次 ≥ 24h 且有未读条目时，生成不超过 5 行的摘要
- 发送后把时间戳写回 MEMORY.md

## 2. 磁盘告警
- 仅当 /data 使用率 > 90% 才通知
- 同一告警 24h 内不重复发送（状态记到 MEMORY.md）
```

2. 配置节奏。openclaw.json 里调间隔和活跃时段（字段名以你版本为准）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": {
        "every": 1800,
        "activeHours": { "start": "08:00", "end": "23:00" }
      }
    }
  }
}
```

3. 状态外置。每轮心跳接近独立调用，agent 默认记不住“上次跑没跑”。让任务把时间戳、已通知条目写进 MEMORY.md 或专门的状态文件，下一轮先读再判断。

4. 分级输出。观察类结果只写 memory，不打扰；只有满足明确条件（超阈值、超时限）才发消息。

## 踩坑点

- **心跳轰炸**：任务没有终态，agent 每 30 分钟通知一次同样的事。给每个检查项写静默条件，并真的让它落盘记录状态。
- **token 成本**：每次心跳都是一次模型调用，HEARTBEAT.md 每轮注入。文件保持一屏内，没事就让它秒回 HEARTBEAT_OK，别往心跳里塞长任务。
- **上下文污染**：心跳默认跑在主会话里，重活会把对话历史撑爆。长任务拆给 cron 调度或独立 session 的子 agent，心跳只负责“判断要不要启动”。
- **幻觉状态**：让 agent 读它没有工具权限的文件，它会编。每个检查项引用的数据源，确认对应工具已配置且权限足够。

## 可复用建议

把每个检查项固定成四段式：**触发条件 / 数据来源 / 动作 / 静默条件**。上线前先把间隔调长（比如 6 小时）观察几天日志，确认噪音和成本可控再收紧。多个检查项保持相互独立，避免一个失败卡住整轮心跳。

## 总结

HEARTBEAT.md 的本质是把“什么时候想起 agent”这件事从你的大脑挪进一个声明式文件。它不神秘，就是“定时器 + 检查清单 + 状态文件”的组合，但配好之后，agent 才真正从问答工具变成驻留的同事。建议从一个低风险任务开始——比如每日摘要——跑稳了再加监控类检查项。
