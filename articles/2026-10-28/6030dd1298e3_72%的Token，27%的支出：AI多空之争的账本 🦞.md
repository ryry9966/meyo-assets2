最近 AI 圈吵得最凶的，是一组看起来有点拧巴的数字：约 72% 的 token 消耗发生在低价甚至开源模型上，对应的支出却只占约 27%；反过来，少数旗舰模型用小头流量，拿走了大头收入。多方（看多 AI 的人）说这是需求真实爆发的证据，空方（看空的人）说这是"用的人多、付的钱少"的泡沫信号。同一组数字，两个剧本。这篇文章把它拆开：token 怎么计费、缺口怎么形成、双方各对在哪错在哪，以及普通团队和开发者能从中捞到什么可操作的东西。

## 一、Token 是 AI 世界的"度电"

- **什么是 token**：tokenizer 把文本切成最小计费单元。英文约 0.75 个词一个 token，中文一个汉字约 0.6~1.5 个 token，取决于分词器。
- **为什么按 token 计费**：Transformer 推理的计算与显存开销近似随 token 数增长。输入部分（prefill）可以并行处理，输出部分（decode）必须一个一个往外蹦、受显存带宽限制——所以输出 token 的单价通常是输入的 3~5 倍。
- **隐藏条款**：o1、DeepSeek-R1 这类推理模型会先生成大量"看不见的"思考 token（chain-of-thought），按输出价计费。你以为只问了三句话，账单上躺着三千字内心独白。
- 所以 token 之于 AI，就像度电之于电网：既是消耗计量单位，也决定了整张成本结构表。单价差几分钱，在亿级调用量下就是几千万美元。

## 二、量的世界和钱的世界，是两个世界

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-28/a58dc2f117962432.png)

这组镜像数字最早在海外开发者社区流传，常被追溯到 OpenRouter 这类 API 聚合平台的公开统计：token 消耗榜和收入榜，常年不是同一批模型。

- **高频低价区**：分类、信息抽取、RAG 改写、摘要、内容审核——单次价值低但 token 巨大，对质量容忍度高，几乎全被开源模型（DeepSeek、Qwen、Llama 系）和小模型吃下。
- **低频高价区**：复杂代码生成、Agent 编排、长链路推理——量不大，但对可靠性要求苛刻，客户愿意为旗舰闭源模型付溢价。

**空方的读法**：如果这些 token 真值钱，用户为什么不肯付费？说明大量消耗是被便宜价格催生的低价值任务，价格一涨就会蒸发。再叠加 2025 年头部云厂商合计普遍被预估在 3000 亿美元以上的资本开支，收入缺口（红杉 David Cahn 那篇《AI 的 6000 亿美元问题》）依然刺眼。

**多方的读法**：token 是领先指标，收入是滞后指标。谷歌披露的月度 token 处理量在 2025 年从数十万亿涨到千万亿（quadrillion）级，几个月就翻一番；27% 的支出对应的绝对值本身已是天文数字。这就是杰文斯悖论（Jevons paradox）：效率提升、单价下降，总消耗反而暴涨——1865 年是煤矿，2025 年纳德拉拿它回应 DeepSeek，逻辑同款。

## 三、价格雪崩：收入掉得比用量涨得快

72/27 这个缺口不是静态的，它正被三股力量持续撕大：

1. **技术降本**：斯坦福《AI Index 2025》估算，达到 GPT-3.5 水准的推理价格，两年内从约 $20/百万 token 降到 $0.07，降幅约 280 倍。背后是 FlashAttention、vLLM 的 PagedAttention、大批量调度、FP8 量化、投机解码这些工程红利。
2. **架构稀疏**：MoE 路由让"大脑"不必每次全开——DeepSeek-V3 总参数 671B，每次推理只激活约 37B，单 token 成本被结构性地压了下来。
3. **开源价格战**：DeepSeek-R1 上线时输出价约 $2.19/百万 token，约为 o1（$60）的 1/27——又见 27，纯属巧合但很好记。闭源厂商随后集体降价。

需求端价格弹性极高：单价跌，用量涨，但收入等于两者相乘，这场赛跑里降价常常跑赢增量。于是"量"的曲线陡峭上扬，"钱"的曲线相对疲软。

## 四、历史对照：铁路、光纤和"没白烧的钱"

- **1840 年代英国铁路狂热**：投机者血本无归，但路网留了下来，重塑了整个经济的空间结构。
- **2000 年互联网泡沫**：光纤被严重过量铺设，大量 dark fiber 在破产清算中贱卖，十年后被 YouTube、Netflix 用满。

多方喜欢讲这两个故事。但空方指出的两个关键差异，值得认真对待：

1. 铁路和光纤是一次性沉没成本，GPU 是折旧周期 3~5 年、耗电惊人的持续成本，"先建后赚"并不自动成立，成败取决于利用率（业界常用 MFU 衡量）和电价。
2. 软件的边际成本趋近于零，而 GPU 推理每个 token 都有真实的边际成本。如果量的狂欢集中在近零收入的开源模型上，资产负债表不会自己变好。

## 五、下结论之前，先避开三个统计陷阱

1. **Token ≠ 价值**：一百万 token 的向量检索，和一百万 token 的并购合同审阅，价值密度完全不同。按 token 统计天然抹平了这个差异。
2. **样本偏差**：公开聚合平台偏向价格敏感的独立开发者；大企业的私有化部署和巨头内部用量根本看不见。72/27 未必能代表全市场。
3. **口径混乱**：自建开源模型的 token 在 API 视角下"支出为零"，但 GPU 折旧和电费真实存在；推理模型的隐藏思考 token 又会人为推高用量。同一组数字，多方和空方各取所需。

## 收尾：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-28/3c9320c8a35ae5cd.png)

1. **量价分开看**：别只盯 token 增速，同时追踪每 token 收入（ARPT）的走势——电信行业看 ARPU 看了几十年，这是判断需求成色的老办法。
2. **算单位经济学，不算宏大叙事**：一个 Agent 任务端到端烧掉几万 token（含思考 token）成本几毛钱，如果它替代的人力值几十块，需求就是真的；比值不成立，再陡的曲线也是补贴出来的。
3. **使用者先做分层路由**：批量杂活交给便宜/开源模型，关键步骤才上旗舰；善用 caching（缓存命中的输入常常一折起）和 batch API（约五折）；上 Agent 之前先设 token 预算和硬上限。价格战打到什么时候没人知道，但省钱这个变量，永远握在你自己手里。
