## 背景

OpenClaw 的主会话承载着你和助手的全部日常记忆：完整对话历史、工具调用结果、长期偏好。一旦某个重活——全网调研、批量日志分析、代码库扫描——直接在主会话里跑，几十轮工具调用的原始输出就会把上下文撑满，表现就是模型开始"失忆"、响应变慢、token 账单变长。

子 Agent 的设计初衷就是解决这个问题：把脏活放进独立 session，主会话只拿回结论。但隔离并不是开了就自动成立的，配置不当照样污染。这篇帖记录我们社区实践里验证过的一套做法。

## 污染的三条路径

动手之前先搞清楚污染怎么发生的：

1. **上下文污染**：子 Agent 的工具日志、中间推理被整段写回主会话历史；
2. **状态污染**：子 Agent 和主会话共享同一个 workspace 或记忆文件，互相覆盖；
3. **复用污染**：session 被复用，子 Agent 带着上一个任务的旧上下文开工，行为诡异。

## 做法

### 1. 判断什么该下放

经验阈值：预计超过 10 轮工具调用，或产出是"一份结论"而非"一段对话"的任务，都值得丢给子 Agent。典型场景：深度检索、批量文件处理、试错型调试。

### 2. 独立 session + 独立 workspace

在配置里为子 Agent 分配独立的 session 键，并给它单独的工作目录。原则很简单：主会话的 workspace 只放"共识产物"，子 Agent 的草稿和临时文件留在自己目录，结束后只把最终文件合并过去。

### 3. 控制回传体积

要求子 Agent 返回结构化摘要：结论、关键路径、异常清单，并在提示词里明确"不要粘贴原始日志"。回传内容超过几百字就先落盘成文件，主会话里只保留文件路径加一句话摘要。

### 4. 记忆写入收敛

子 Agent 默认不应写全局记忆文件。需要沉淀的结论，由主会话确认后再写入——否则一次性的中间结论会被当成"长期事实"留下来，这是最隐蔽的一类污染。

### 5. 生命周期管理

一次性子 Agent 任务完成即结束 session；定时任务类子 Agent 用固定 session 键并设置重置周期，避免跨天累积无关历史。

## 踩坑点

- **递归 spawn**：子 Agent 又开子 Agent，没有深度限制，session 树失控。务必加层数上限。
- **并发写冲突**：多个子 Agent 同时写同一个文件。按任务分目录，或者排队。
- **回传夹带**：模型回传时"顺手"把工具日志带回来，主会话照样被撑爆。回传格式要做强制校验，而不是靠提示词祈祷。
- **审计断档**：想回看子 Agent 干了什么，发现 session 已经清掉了。保留最近 N 个子 session 供排查，审计日志另存。

## 可复用建议

- 一句话原则：**主会话是决策层，子 Agent 是执行层，执行层只交作业，不搬桌子。**
- 把"回传格式"写成一个可复用的提示词模板，所有子 Agent 共用；
- 定期清理子 session 目录，需要留痕的归档到独立目录，不留在活跃区；
- 每次主会话出现"失忆"症状，先查最近一次是否在主会话里跑了长任务——十有八九是它。

## 总结

Session 隔离的本质不是"多开几个会话"，而是控制信息回流的方向和体积：任务往下放，结论往回收。把 workspace 划分、记忆写入、回传格式这三件事管住，主会话就能长期保持干净、可预测。隔离做得好不好，不看配置多花哨，看一个月后主会话还记不记得你上周说过什么。
