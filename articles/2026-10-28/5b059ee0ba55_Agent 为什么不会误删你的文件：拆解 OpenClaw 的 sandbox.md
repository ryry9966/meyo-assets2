## 背景

给 Agent 接上文件写入和 shell 执行能力之后，社区里被问得最多的一句话是：它会不会哪天把我整个目录删了？这个担心很合理——模型输出本质上是概率性的，而 `rm` 是确定性的。OpenClaw 的 sandbox 模型回答这个问题的方式，不是"相信模型足够聪明"，而是**让运行时不给模型犯错的机会**。核心原则一句话：Prompt 只是请求，不是权限。

## 问题

复盘真实的误删事故，成因基本集中在四类：

1. **路径幻觉**：模型"猜"出一个看似合理的绝对路径，恰好撞上重要目录；
2. **通配符失控**：`rm -rf $DIR/ *` 里变量为空，展开范围远超预期；
3. **级联失败**：脚本前一步出错，错误状态传导到清理逻辑，删除范围扩大；
4. **上下文注入**：被读取的网页/文档内容诱导 Agent 执行破坏性命令。

这些问题靠 system prompt 写"请不要删除文件"是拦不住的。

## 做法：五层边界

OpenClaw 的 sandbox 是分层拦截，而不是单点防御：

1. **工作区监狱**：所有文件工具的路径在运行时做 canonicalize，必须落在 workspace root 内。`..` 穿越、绝对路径、指向外部的 symlink，一律拒绝。这在工具实现层强制，与模型是否"配合"无关。
2. **shell 命令网关**：Agent 拿到的 shell 不是裸的。命令先经解析器检查，命中危险模式（`rm -rf`、`find -delete`、`dd` 写盘等）时，或改写为沙箱内等价操作，或升级为人工确认。
3. **最小权限的 MCP/插件**：每个插件声明所需文件 scope，运行时按 scope 发放 capability，越界调用直接拒绝并记录审计日志。
4. **不可逆操作二次确认**：删除、覆盖、批量写入前，Agent 必须产出 diff 或操作清单，用户确认后才放行。确认点在运行时拦截，模型无法自行跳过。
5. **可回滚底座**：批量变更前自动打快照；删除一律先进沙箱内的 `.trash/`，保留若干天。

一次"误删"需要同时穿透这五层才会真的发生——这才是安全模型真正在买的东西。

## 踩坑点

- **symlink 逃逸**：模型在沙箱内 `ln -s /` 再穿过去操作。canonicalize 必须在**每次工具调用时**执行，不能只在会话开始校验一次。
- **解释器绕过网关**：`python -c "shutil.rmtree(...)"` 不命中 shell 规则。网关要么覆盖解释器内嵌代码，要么限制脚本类工具的导入面。
- **`.git` 目录被当成普通文件改动**，导致快照回滚失效，需要单独保护。
- **确认疲劳**：如果每次读写都弹确认，用户会练成无脑全过。确认额度只留给真正不可逆的操作。
- **沙箱过窄会把模型逼向绕路**。拒绝日志和放行日志同样重要——拒绝原因里藏着沙箱配置的问题。

## 可复用建议

1. default deny + 显式 allowlist，先收窄再按需放开；
2. 权限校验全部放运行时，**永远不要写进 system prompt**；
3. 不可逆操作用"移动到回收站"替代直接 unlink；
4. 每次文件变更记录结构化日志：工具名、原始参数、解析后真实路径、前后 hash，事后可完整回放；
5. 定期用自己的沙箱做红队演练：诱导它删 workspace 外的文件、建逃逸 symlink、用 base64 编码绕网关。

## 总结

Agent 不会误删文件，不是因为模型品行好，而是因为即使它"想"删，路径解析、命令网关、权限边界、二次确认、快照回滚中至少有一层会拦住它。好的 sandbox 设计不是消灭单点失误，而是把单点失误变成需要同时穿越五道防线的小概率事件。把这套分层思路套到你自己的 Agent 工程里，大部分"不敢放手让它跑"的顾虑是可以被工程手段消解的。
