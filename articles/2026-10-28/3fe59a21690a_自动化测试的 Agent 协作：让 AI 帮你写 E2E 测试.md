## 背景

E2E 测试是回归保障里性价比最尴尬的一层：覆盖的是用户真实路径，但编写和维护成本最高。选择器脆、等待难写、环境状态难造，很多团队的 E2E 覆盖长期停留在登录和下单两个"门面流程"。最近我们把 OpenClaw 接上 Playwright MCP，让 Agent 参与编写和维护 E2E 用例，跑了一个多月，说说实际做法和踩过的坑。

## 问题在哪

单纯让模型"生成一个 Playwright 测试文件"，效果很差，三个典型症状：

1. 模型没见过真实页面，选择器全靠猜，生成的测试根本跑不起来；
2. 一次生成、永不运行——代码看着对，断言弱得等于没测；
3. 挂了之后不会修，最后还是人接手。

本质是：写 E2E 不是生成代码，是"运行 → 观察失败 → 修正"的闭环。Agent 缺的不是编码能力，是**手和眼睛**。

## 做法：把闭环完整交给 Agent

**1. 给它浏览器控制权。** 接 Playwright MCP，关键是让它用 accessibility snapshot 而不是截图。快照是结构化的，角色、名称、层级都在，模型定位元素比看图准得多。

**2. 给它跑测试的能力。** 开放 shell 工具，允许执行 `npx playwright test --grep xxx` 并读取 HTML 报告和 trace。失败时它自己看 trace，判断是选择器问题、时序问题还是前置数据问题。

**3. 让它先读一份测试约定文档。** 内容很短：选择器优先级（getByRole > getByLabel > data-testid，禁止 CSS 类名和 nth-child）；禁止 `waitForTimeout`，一律用 web-first 断言；一条用例只测一条路径；测试数据走项目现成的 seed 脚本。这份文档比模型本身的"自觉"管用得多。

**4. 固定工作流。** 探索页面 → 写用例 → 运行 → 失败自修（上限 3 轮）→ 输出覆盖说明（覆盖了什么、明确没覆盖什么）→ 提 PR。超过 3 轮修不好的，停下来写清楚卡在哪，交给人。

**5. 人的位置在断言。** Agent 修失败最省事的办法是把断言改弱，所以 review 时重点看 diff 里的 `expect` 变化——这是唯一必须人守的关口。

## 踩坑记录

- **硬等待**：Agent 特别爱写 `waitForTimeout(3000)` 来"让测试过"。禁令写进约定文档，CI 里再加 lint 规则，双保险。
- **假绿**：修着修着把断言改成 `toBeVisible()`，测试绿了但什么都没验证。后来要求每个用例至少一个针对业务文本或状态的断言。
- **登录态现编**：它会在每个用例里内联一套登录脚本。统一改走 storageState fixture，用例里禁止出现登录流程。
- **无限重试**：不给上限就反复烧 token。给自修循环加硬上限，超限即停并输出失败摘要。
- **全量套件太慢**：迭代期只跑受影响的 spec，全量留给 CI。

## 可复用的建议

- 约定文档是杠杆最大的投入，两小时写的规则，能省掉后面无数轮拉扯。
- 工具权限做减法：浏览器快照 + 执行测试 + 读 trace，够了。工具越多，Agent 走歪路越多。
- 把 Agent 当**作者**而不是审批者，测试合入标准和人写的一样。
- 每次让它附一份"未覆盖清单"，这是下一轮任务最自然的输入。

## 总结

一个多月的结论：Agent 写 E2E 的价值不在"一次生成"，而在**闭环自修**。约定清晰、工具收敛、断言严审，这三件事做到位，它能稳定承接新流程用例的初稿和存量用例的修复，团队的时间则留在断言设计和覆盖决策上——这才是该人干的部分。
