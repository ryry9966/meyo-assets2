最近 AI 圈流传一组扎眼的数字：某一大类用量吃掉了 72% 的 token 消耗，却只贡献了 27% 的支出。多头拿它当“需求真实且在早期”的铁证，空头拿它当“收入撑不起盘子”的裂缝——同一组数字，两种剧本。这篇文章不站队，先把 token 的量价账本拆开：错位从哪来，意味着什么，普通人该盯什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-28/9f652647c639416b.png)

## 一、先对口径：Token 的“量”和“钱”不是一个坐标系

- **Token 是大模型世界的计价像素**：约等于 0.75 个英文单词、大半个汉字。模型输入输出都按 token 计费，且输入、输出单价不同——输出 token 通常贵 3~5 倍。
- **“72% 消耗”按数量算，“27% 支出”按美元算**。数量 × 单价 = 金额，两者严重错位，说明 token 和 token 之间的单价差极大。
- 直观例子：轻量级模型约 $0.1~0.3/百万 token，旗舰推理模型能到 $10~60/百万 token。同样烧 1 亿 token，账单能差出两三个数量级。
- 还有一类“隐形消耗”：reasoning 模型的思考过程也是 token，用户看不见，但照样计费。
- 口径提醒：不同统计来源（API 路由平台、云厂商、第三方机构）覆盖面不同，流传最广的一种解读指向开源/低价模型生态——免费或低价模型承接了海量推理流量，收入大头仍由闭源旗舰拿走。绝对数值有争议，但“量在大头、钱在小头”的方向，多家数据能互相印证。
- 为什么这事重要？因为 AI 商业模式的所有争论，最后都落在一个算式上：**收入 = 消耗的 token × 单位价格**。消耗和支出对不上，说明这条公式里的两个变量正在朝不同方向狂奔。

## 二、错位从哪来：三重结构性原因

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-28/07fc4eb718796ba7.png)

1. **长尾场景跑在便宜模型上**。翻译、摘要、分类、RAG 检索、日常闲聊，量大、单价极低；真正烧钱的是 code agent 的长循环和深度推理——量小、价高。就像自助餐厅：端走最多盘子的客人，点的往往是最便宜的菜。
2. **免费与补贴用量占比高**。C 端聊天产品的大量额度是免费的，token 被真实消耗却没有对应收入，厂商把它记作换数据、换用户习惯、换市场份额的获客成本。
3. **成本曲线崩得比价目表更快**。MoE 架构、KV cache、prompt caching、batch API、蒸馏小模型，把每 token 推理成本一年压低一个数量级（a16z 称之为 LLMflation：同等能力的价格年均下降约 10 倍）。成本降得快，厂商才有底气用价格换量。

一句话总结：**量在便宜处堆积，钱在贵处结算**。

## 三、多空之争：同一枚硬币的两面

- **多头读法：Jevons 悖论**。19 世纪蒸汽机效率提升后，煤的消耗不降反升——因为用得起煤的人多了。Token 同理：单价暴跌 → 调用量爆发 → 总支出盘子反而扩大。72% 的消耗证明需求是真的，而且大头还没开始付费，这是“增长前夜”而非“天花板”。
- **空头读法：capex 与收入的剪刀差**。超大规模厂商每年在数据中心、芯片、电力上砸下数千亿美元，推理端收入增长明显滞后；且相当比例的消耗来自 agent 的无效循环、爬虫和重复试验——烧的是电，不产出价值。这是“泡沫进行时”。
- 值得注意的是，双方共用同一组事实，分歧在于对未来现金流的理解不同——这更像一场估值之争，而非事实之争。
- 分歧核心其实只有一个问题：**token 的价值密度会不会上升**？量能不能变成钱，什么时候变。

## 四、量变成钱：历史上发生过三次

1. **电力（1880s–1920s）**：发电成本骤降、用电量暴涨，发电公司利润长期平淡，钱最终被用电的工厂和家电产业赚走。
2. **铁路与带宽（1840s / 1990s）**：修路铺线的卷到破产，用路的人——物流公司与互联网公司——享受了低成本基础设施的红利。
3. **云计算（2006–2015）**：早期同样有人喊“烧钱泡沫”，后来 SaaS 应用层把算力变成了稳定的订阅收入。

共同规律：**基础设施层的量价错位是常态，价值兑现靠应用层**。当然，历史类比只提供先验，不能替代当下验证——AI 的成本下降速度和应用迭代速度都比以往快得多。AI 卡没卡在“应用层时刻”，才是多空真正的战场。

## 五、三条建议与冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-28/8f3beb6acd2ee800.png)

1. **对开发者：别让一个模型打天下**。做模型路由——80% 的高频简单任务（分类、格式化、检索改写）交给轻量模型，20% 的硬任务升级到旗舰模型；再叠加 prompt caching 和 batch API，综合成本常能砍掉一个数量级。Agent 场景尤其要算细账：一次多步任务的 token 消耗可能是单轮对话的几十倍，路由省下的都是真金白银。
2. **对观察者：把量和价拆开看**。别只盯 token 增速，盯“每百万 token 的收入”和付费转化率。单一口径的数据最容易带节奏——量是先行指标，钱是确认指标，两个都看才不容易被单边叙事收割情绪。
3. **冷思考：错位本身不是判决书**。它既可能是泡沫的证据，也可能是普及的前奏——电力、铁路、云计算都经历过这一段。与其押注结论，不如持续追踪两个信号：agent 任务的完成率与留存，以及推理毛利率的走向。等量与钱重新对齐的那天，这场争论自然会有答案。
