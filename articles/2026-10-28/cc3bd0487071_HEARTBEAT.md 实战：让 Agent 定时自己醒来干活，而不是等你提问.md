## 背景

多数人的 OpenClaw 用法还停留在“你问一句、它答一句”。但 MCP 工具、插件、执行能力都接好了之后，瓶颈其实不在能力，而在触发——缺一个定时闹钟。OpenClaw 提供了 HEARTBEAT.md 机制：daemon 每隔固定间隔（默认约 30 分钟，以版本配置为准）触发一次心跳，Agent 醒来读一遍工作区里的 `HEARTBEAT.md`，判断有没有要处理的事：有就执行并推送结果，没有就保持沉默。

## 问题

没有心跳的 Agent 是纯被动的。日报、巡检、收件箱检查这类重复动作，最后都变成“我记得去问它”。用系统 crontab 也能定时，但那是脱离 Agent 上下文的孤立脚本，不共享会话、记忆和工具链。我们真正想要的是：Agent 在固定节奏里自己醒来，用已有的工具判断“现在有没有事”，而不是无脑跑脚本。

## 做法

1. 在 Agent 工作区（通常 `~/.openclaw/workspace/`）创建 `HEARTBEAT.md`，用清单格式写任务。这个文件既是指令也是状态，每次心跳都会重新读取，改完下一拍即生效。
2. 在配置里调整心跳间隔（找 gateway / agents 下的 heartbeat 配置项，不同版本字段名略有差异）。
3. 先用一条低成本只读任务验证链路，再逐步加量。

```markdown
# 心跳任务

## 每次心跳
- 检查 INBOX.md 有无未勾选条目；有则处理并勾选，无则 NO_REPLY

## 时间窗
- 09:00–09:30 且今天未发过日报：汇总昨日 git log，输出不超过 10 行，发完记录日期
- 其余时间一律 NO_REPLY
```

关键认知：每次心跳是一次真实的 Agent 推理轮次——读文件、调工具、给结论。把“没事就 NO_REPLY”明确写进文件，是它不发噪音的前提。

## 踩坑点

- **噪音轰炸**：初版写“检查邮件”，结果每 30 分钟收到一句“没有新邮件”。沉默条件必须显式定义，NO_REPLY 不写就是骚扰。
- **Token 成本**：心跳是完整推理轮次，HEARTBEAT.md 控制在十来行以内；重活交给它调用的工具，不要让它每次现场长推理。
- **长任务穿插**：心跳通常跑在与日常对话共享的会话里，重任务会和你的交互互相穿插。心跳只放轻量巡检，重活让它只做“标记”，由你确认后再执行。
- **时间不可靠**：模型未必准确知道现在几点，“早上发日报”可能凌晨触发。让心跳第一步先取系统时间，再做时间窗判断。
- **宿主机要活着**：心跳由 daemon 驱动，机器睡眠或 gateway 挂了就全停。放在常开设备上跑。
- **语义区分**：需要精确 cron 语义（每天 8:00 整）的任务，用 OpenClaw 的定时任务能力；心跳适合“固定频率巡检 + 自主判断”。

## 可复用建议

- 把 HEARTBEAT.md 当 runbook 写：每个任务四要素——触发条件、动作、输出格式、沉默规则。
- 用 checkbox 当状态位，让 Agent 处理完自己勾选，天然幂等，重启也不重跑。
- 先跑一两周只读任务（RSS 摘要、磁盘水位）建立信任，再接任何会写、会发的东西。
- 让 Agent 每次心跳往 `heartbeat.log` 追加一行，凌晨三点它干了什么，可审计。

## 总结

HEARTBEAT.md 的本质是把 Agent 从 pull 模式切到 push 模式：触发交给 daemon 的固定节拍，判断交给模型，执行交给 MCP 工具，而契约就是这份十行以内的小文件。文件短小、沉默规则明确、任务幂等——这三点守住，主动式 Agent 才不会退化成噪音生成器。
