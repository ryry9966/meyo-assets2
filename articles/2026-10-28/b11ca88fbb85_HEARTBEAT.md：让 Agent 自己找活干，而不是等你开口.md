## 背景

OpenClaw 的 agent 默认是纯被动模型：你不发消息，它就静止。但日常里最有价值的助手行为往往发生在你没开口的时候——早上自动汇总日历、发现磁盘快满了主动报一句、检查到有仓库没 push 才提醒你。OpenClaw 内建了 heartbeat 机制来解决这个问题：每隔一个固定间隔（默认约 30 分钟），系统给 agent 注入一次心跳，agent 读 workspace 根目录的 `HEARTBEAT.md`，按清单决定"这次心跳要不要干活"。

## 问题

被动模式有两个隐性代价：一是记忆负担在你身上，你得记得"该找 agent 要早报了"；二是时机错过就作废，凌晨的故障提醒放到早上已经没意义。用 cron + 脚本自己造？那调度、会话、MCP 工具调用、消息投递全要重写一遍。HEARTBEAT.md 的思路是：调度交给系统，"要不要做、怎么做"写成给 agent 的判定清单。

## 做法

1. **确认心跳启用**。新版默认开启，间隔可在配置的 `heartbeat.every` 里调（如 `15m`）。别压得太狠——每次心跳都是一次真实的模型调用，有固定 token 开销。
2. **在 `~/.openclaw/workspace/HEARTBEAT.md` 写任务**，每条遵循"条件 / 动作 / 沉默"三段式：

```markdown
# Heartbeat checklist

- 第一次落在 09:00–10:00 的心跳：汇总今日日历与未读邮件，
  超过 3 条才算值得报告
- 扫描 workspace/projects 下所有 git 仓库，存在未 push 的
  本地提交才提醒，附上 repo 名
- 磁盘占用 > 85% 或关键服务异常时立即报告
- 以上都不满足：一律回 HEARTBEAT_DONE，不要发任何消息
```

3. **限制打扰面**。配置 `activeHours`（如 08:00–22:00）控制窗口，`target: last` 指定投递渠道，别让心跳消息插进你正在聊的会话。

## 踩坑点

- **不写沉默规则是最常见翻车**：agent 每个心跳都热情汇报"一切正常"，一天几十条，你只会把通知关掉，机制就此报废。`HEARTBEAT_DONE` 是约定的内部标记，agent 回它就不投递。
- **任务写成人话愿望**（"帮我盯着点服务器"），agent 每次都在猜；写成可执行判定 + 具体工具，输出才稳定。
- **心跳是独立 session**：别指望它记得你主会话刚聊的内容，需要的信息让它在心跳时自己读文件或调插件。
- **无人值守上下文**：它会自己调 MCP 工具和 shell，权限该收就收；任务要幂等，崩溃重跑后可能再执行一次。
- **忘配 activeHours**，凌晨三点收日历汇总——这是我真实收到的。

## 可复用建议

- 把 HEARTBEAT.md 当"带判断力的 cron"：适合需要理解上下文、调工具、做取舍的巡检类任务；精确到分钟的批处理仍然交给系统 cron，别硬塞。
- **渐进上线**：先放一条低风险任务跑一周，确认输出质量和打扰频率，再逐条加。
- **条目控制在一屏内**，低频任务写成条件（"仅周一"），开销才可控。

## 总结

HEARTBEAT.md 的价值不是让 agent 更聪明，而是把触发权从你的记性转移到一份可版本管理的清单上。它好不好用，几乎完全取决于规则写得像不像可执行判定——写得像条件，它就稳；写得像愿望，它就开始猜。
