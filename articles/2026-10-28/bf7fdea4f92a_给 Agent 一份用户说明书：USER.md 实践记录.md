## 背景

OpenClaw 的每次会话几乎都从近乎空白的状态开始：系统提示词是通用的，workspace 里没有关于“你是谁”的任何信息。结果就是你每天都在重复自我介绍——“我用的 Arch”“别给我客套话”“服务器路径在 /srv/xxx”。这些信息散落在历史对话里，Agent 每次都得靠不稳定的记忆检索捞回来。

OpenClaw 的 workspace 约定里有一个 USER.md：会话启动时注入上下文。它不是聊天记忆，而是一份关于用户本人的静态配置。看起来很简单，但写好它值得花心思。

## 问题

- 同样的偏好反复纠正，跨会话、跨渠道（Telegram / Discord / CLI）表现不一致；
- MEMORY.md 塞满后，关键事实被日常琐事淹没；
- Agent 的默认行为（过度解释、答非所问的客气话）与个人习惯冲突。

## 做法

1. 在 workspace 根目录建 `USER.md`，控制在 60–100 行。它每次都进上下文，token 是硬成本。
2. 分五段写：
   - **基本盘**：称呼、时区、常用语言；
   - **环境**：OS、技术栈、常用路径；
   - **偏好**：写成可执行规则，“代码优先，解释不超过 3 句”，而不是“简洁一点”；
   - **红线**：明确不做什么（不自动执行删除命令、不主动给某人发消息）；
   - **进行中**：当前项目一句话概述。这段最容易过期，要定期换。
3. 和 AGENTS.md 划清边界：AGENTS.md 管“Agent 怎么干活”，USER.md 管“用户是谁”。重叠的规则迟早漂移，只留一处。
4. 更新机制：同一条纠正说过两次以上，就写进去。可以每周让 Agent 读近期对话起草 diff，人工审后合并。

## 踩坑点

- **写太长**。第一版我写了 200 多行，上下文被撑满，Agent 开始忽略后半部分，删到 80 行后才稳定。
- **塞敏感信息**。密钥、住址、密码都别放，这份文件会随每次请求发出去，也可能被备份同步。
- **形容词不可执行**。“专业一点”没有信息量，Agent 不知道怎么落地，全部改写成具体行为。
- **状态内容放错位置**。“这周在赶 X”放 USER.md，两周后就是错误指令，这类内容进 MEMORY.md。
- **忘了更新**。不更新的 USER.md 比没有更糟——过时信息是每次会话都被强化的。

## 可复用建议

- 把 USER.md 当代码：进 git、写 commit、每月 review 一次做减法；
- 多工作区场景：USER.md 放用户级目录跟随你，AGENTS.md 放仓库级跟随项目；
- 冷启动：把最近一个月的对话丢给 Agent，让它起草初版，人工删减，十分钟够用。

## 总结

USER.md 的价值不在“个性化”这个词，而在于把重复沟通成本固化成一份可版本化、可 review 的文件。它很土，一个 markdown 而已，但它是少数投入十分钟就能在之后每次会话持续生效的东西。先写 50 行，跑两周，再决定要不要扩。
