## 背景

OpenClaw 的 workspace 约定里，AGENTS.md 管任务规则，SOUL.md 管人格基调，USER.md 则负责“用户是谁”：时区、技术栈、沟通偏好、手头的项目。它每次会话随系统上下文注入（workspace 通常在 `~/.openclaw/workspace`）。很多人装完就忘，或者写成一段自我介绍，没发挥实际价值。

## 问题

没有像样的 USER.md，后果很具体：

- 每个会话都要重复交代“用中文、别客套、我在 Ubuntu 上”；
- Agent 给出通用答案，不知道你的 shell、编辑器和部署方式；
- 跨会话记忆混进大量一次性信息，真正稳定的偏好反而没位置。

本质是把个性化寄托在聊天记录上，而聊天记录是日志，不是配置。

## 做法

1. 在 workspace 下新建 USER.md，纯 Markdown。
2. 控制篇幅：目标 300–800 字，只写稳定事实，不写愿望，一个要点一行。
3. 参考结构：

```markdown
# 用户画像
- 角色：后端开发，主写 Go / Python
- 环境：Ubuntu 24.04，zsh，Neovim，Docker 部署
- 语言：中文交流，代码注释和 commit message 用英文
- 回复风格：先给结论和代码，不要免责声明
- 时区：Asia/Shanghai，10:00–19:00 在线
- 当前项目：内部网关重构（2025-Q3 起）

# 禁止
- 不主动推荐付费服务
- 示例不用真实域名
```

4. 进 git，和 workspace 其他文件一起版本化；换项目时顺手更新“当前项目”一栏。
5. 验证：新开会话问“列出你对我已知的全部信息”，检查注入是否生效、有无遗漏。

## 踩坑点

- **写成简历**：长段落会被稀释，行式要点优先，一句一个事实。
- **塞敏感信息**：文件是明文且会发到模型服务端，密钥、手机号、客户名一律不放。
- **职责重叠**：这里写“回复要短”，AGENTS.md 又写“输出完整分析”，行为就会漂移。一个关注点只写一处——USER.md 管“我是谁”，AGENTS.md 管“怎么干活”。
- **信息腐烂**：“当前项目”三个月不更新，Agent 会基于过期上下文给建议。条目加日期，定期删。
- **愿望当事实**：“我很忙”没有可操作性；“默认不超过 5 句，除非我要求展开”才是配置。

## 可复用建议

- 冷启动可以让 Agent 读你近期聊天记录起草初稿，再人工删减——它比你清楚你重复过什么。
- 用定时任务每月提醒自己 review 一次，类似依赖更新的节奏。
- 分层存放：稳定偏好放 USER.md，易变的工作状态放 MEMORY.md，别混。
- 定期看 token 占用，文件超过一千字，先怀疑哪些条目可以删。

## 总结

USER.md 的价值不在“让 AI 更懂你”这类玄学表述，而在确定性：偏好从聊天记录里抽出来，变成一份可 diff、可 review、可回滚的配置。写它花不了半小时，换来的是每次会话省掉的重复交代。建议今天就建一个，从五行开始。
