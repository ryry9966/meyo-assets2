## 背景

OpenClaw 的工作区里，除了管流程的 AGENTS.md 和记用户上下文的 USER.md，还有一个常被忽略的文件：SOUL.md。它定义这个 Agent 是谁——语气、价值观、做事风格和行为边界。很多人搭好环境就急着接 MCP、配插件，SOUL.md 一直留着模板默认值。结果就是助手能用，但语气不稳定、行为不可预期，定位始终模糊。

## 问题

没有明确人格边界的 Agent 有三个典型症状：

- **语气漂移**：今天像客服，明天像论文摘要，长对话后越说越机器。
- **无原则顺从**：用户随口一句"把这个目录删了"，它不加确认就动手。
- **边界模糊**：对超出能力范围的任务硬答，宁可编也不说不知道。

这些不是模型能力问题，是配置缺位。SOUL.md 就是补这块的地方。

## 做法

我的写法分四段，全文控制在 60 行以内：

1. **身份与语气**：两三句说清"你是谁、用什么口吻说话"。写具体行为而不是形容词——"用短句、先给结论再给理由"比"友好专业"可执行得多。
2. **原则**：列 3~5 条决策优先级，比如"准确优先于速度；不确定就明说不确定；删除、付款、对外发送类操作必须先确认"。
3. **边界**：明确不做的事——不冒充真人、不代做法律/医疗决定、不主动推送未要求的内容。
4. **与用户的关系**：说明这个助手服务谁、默认假设是什么，避免多会话场景下人格错位。

写完让 Agent 复述一遍它对 SOUL.md 的理解，偏差处就是表述含糊的地方，改到复述稳定为止。

## 踩坑点

- **写太长**。SOUL.md 会被加载进上下文，几百行的人格描述会挤占任务空间，还稀释重点。原则超过 10 条，模型基本只记得前几条。
- **形容词堆砌**。"聪明、严谨、有同理心"没有可执行性，模型只能自行解释，解释结果每次都不一样。
- **混入任务流程**。SOUL.md 管人格和边界，具体工作流归 AGENTS.md。混写会导致改流程时顺手把人格改坏。
- **一次定稿不再维护**。用一段时间发现语气不对，应回头改文件，而不是在对话里临时纠正——临时纠正对其他会话无效。

## 可复用建议

- **版本化**：SOUL.md 放进 git，每次调整留 commit 记录，方便回滚和对比。
- **一处定义**：多 Agent 场景下，公共人格规则放共享 SOUL.md，个性差异放各自的 IDENTITY.md，避免规则打架。
- **diff 式迭代**：每次只改一两处，观察几天再继续，别一次重写全文，否则无法归因。
- **红线单独成段**：把"必须确认才执行"的操作清单独立出来，后续接审批钩子时可以直接引用这一段。

## 总结

SOUL.md 的价值不在于"给 Agent 注入灵魂"这种玄学叙事，而在于把语气、原则、边界变成可版本化、可审计的配置资产，和 AGENTS.md、MCP 配置属于同一层级。建议还没写的人先花半小时写个 20 行的版本跑一周，再根据实际别扭的地方迭代——比一开始追求完美定义有效得多。
