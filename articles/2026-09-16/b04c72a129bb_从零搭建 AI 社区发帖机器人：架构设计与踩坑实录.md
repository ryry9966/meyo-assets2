## 背景

我们社区每周要发一期资源汇总帖：翻仓库 release、收集群里的好帖、写摘要、排版、定时发。流程不难，但每次 40 分钟，而且经常拖到周更变双周更。于是我基于 Agent + MCP 工具链做了一个半自动发帖机器人。

先明确目标：**不是全自动，而是"机器起草、人工审核、定时发布"**。社区账号代表官方形象，任何模型直连生产写操作的方案我都不接受。

## 整体架构

四个模块，单向流水线：

1. **采集层**：cron 每日触发，通过 MCP 的 `fetch_url` 抓 RSS、仓库 release、社区热帖列表；
2. **加工层**：Agent 读取素材，按固定模板生成草稿（摘要 + 分类 + 链接），单条素材控制摘要长度；
3. **审核层**：草稿落库进队列，我在管理页确认或修改，这一步不可跳过；
4. **发布层**：审核通过后调用社区 API 发帖，写回 `post_id`，便于追踪和删帖回滚。

关键决策就一条：草稿-审核-发布三段式，模型的输出永远停在草稿态。

## 实施步骤

1. 定义 MCP 工具集：`fetch_url`、`search`、`list_recent_posts`、`create_post`，输入输出全部走严格 schema，不收自由文本；
2. 写 system prompt：固定模板、字数上限、明确"只能引用工具返回的 URL 和数据"；
3. 先跑一周 dry-run，草稿只落库不发，人工核对质量；
4. 审核脚本加一道去重：草稿内链接与最近 30 天帖子比对，命中即拦截；
5. 发布后写回 post_id，异常时可以程序化删帖。

## 踩坑实录

**1. 模型编造链接。** 初期让它"补全来源 URL"，结果出现 404。修复：prompt 里禁止生成工具输出之外的任何 URL，链接只能原样透传。

**2. 重复发帖。** cron 任务偶发超时被重新调度，同一天发了两遍。修复：引入幂等键（日期 + 栏目），发布前查 `list_recent_posts`，命中就跳过本轮。

**3. 时区算错。** cron 跑在 UTC，周报标题的日期错了。修复：代码里统一转本地时区后把日期作为变量传给模型，绝不让模型自己算日期。

**4. Markdown 转义。** 标题里的下划线和星号被社区渲染器吞掉，排版糊了。修复：发布前对特殊字符转义，并加了渲染预览步骤。

**5. Token 失控。** 一次塞 30 条素材，输出被截断。修复：map-reduce，先分批摘要再汇总，单次输入锁定预算。

**6. 重试风暴。** 社区 API 限流后脚本无脑重试，差点被临时封 IP。修复：指数退避、上限 3 次，遇 429 直接放弃本轮等下个周期。

## 可复用建议

- 凡是让 Agent 碰生产写操作的场景，**必须加人工审核闸门**；
- 工具返回什么，模型只能引用什么，不要让它"回忆"URL 和数字；
- 幂等键 + dry-run 模式是自动化任务的基本配置，不是可选项；
- prompt 和模板进版本控制，出问题能 diff 回溯；
- 日志记录每次工具调用的名称、输入摘要、耗时，排障全靠它。

## 总结

上线两个月，周报准时率从"看心情"变成 100%，人工耗时从 40 分钟降到约 5 分钟审核。但真正的收益不是省时间，而是**流程被固化**：素材有来源、草稿可追溯、发布可回滚。AI 自动化的价值在于把"每次靠自觉"变成"每次靠流程"，模型只是流程中的一环——把它当能力有限的初级同事来设计系统，反而能跑得稳。
