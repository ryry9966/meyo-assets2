## 背景

OpenClaw 里的 Agent 默认是纯被动模型：你不发消息，它不醒来。问答场景没问题，但一旦把它当"常驻助手"，就会发现缺口——没人在场时它什么都不做。OpenClaw 提供了两条走向主动的路：cron 式定时任务，和更轻量的 **HEARTBEAT.md** 机制。后者是本文的主角。

## 问题

HEARTBEAT.md 解决的是"常设指令"问题：

- 有些事需要周期性检查（磁盘水位、收件箱、日历冲突），但不值得为每件清单独写一个 cron job；
- 有些偏好是长期有效的（"晚上十点后别打扰我"），塞进系统提示又容易在长对话中失焦；
- 你希望 Agent 自己判断"有没有事"，没事就闭嘴，而不是每次都来刷存在感。

## 做法

1. 在工作区根目录建文件 `~/.openclaw/workspace/HEARTBEAT.md`。
2. 写清三部分：规则、检查项、动作边界。示例：

```markdown
# 常驻任务清单

## 规则
- 仅 09:00–23:00 允许主动发消息，其余时间保持安静
- 无事可做时回复 HEARTBEAT_OK
- 检查类任务只报告，不执行任何写操作

## 检查
- [ ] 服务器磁盘使用率 > 85% 时提醒我
- [ ] ~/inbox/TODO.md 有新增条目时汇总给我

## 维护（需确认）
- [ ] 发现 ~/Downloads 超过 7 天的文件时，列出清单等我确认
```

3. 默认每 30 分钟心跳一次，可用环境变量 `HEARTBEAT_INTERVAL_MS` 或配置项 `agents.defaults.heartbeat` 调整（不同版本字段名略有差异，以你版本的文档为准）。
4. 多渠道用户建议显式指定心跳投递目标，否则消息会落到主会话当前活跃的渠道。
5. 改文件内容无需重启，下一跳自动读取；改间隔需重启 gateway。

关键机制：每次心跳触发一次模型调用，Agent 读到默认心跳提示词后检查清单，无事可做时回复 `HEARTBEAT_OK`，网关识别该标记后**不向你投递任何消息**——这是"安静机制"的核心，也是它比定时群发优雅的地方。

## 踩坑点

- **成本**：心跳等于固定频率的模型调用。30 分钟一跳、挂前沿模型，一个月下来不是小数目。建议拉长间隔，或给常驻 Agent 配便宜模型。
- **上下文污染**：心跳运行在主会话里。如果让它每跳都读大文件，主会话上下文迅速膨胀，拖累正常对话质量。检查类任务要求"读摘要，别读全文"。
- **权限失控**：心跳是无人值守的，别写"发现垃圾文件就删"。原则：检查类只报告，写操作必须先列清单等确认。
- **夜间轰炸**：不加时间门控，凌晨三点也会推消息。活跃时段务必写进规则区。
- **长任务重叠**：单次任务耗时超过间隔，下一跳会叠上来。心跳里只放 5 分钟内能完成的事。

## 可复用建议

把 HEARTBEAT.md 当作一份"值班手册"而非任务堆：

- 固定三段式：**规则区**（时段 / 安静机制 / 权限边界）+ **检查区**（只报告）+ **维护区**（需确认）；
- 条目控制在 10 行以内，每条写清触发条件和输出格式，Agent 的执行稳定性会明显提升；
- 文件纳入 git 管理，改版可回溯、可 diff；
- 一句话分工原则：**心跳负责"发现"，cron 和人工负责"执行"**。重活、长任务、精确调度都不要塞进心跳。

## 总结

HEARTBEAT.md 的价值不在花哨，而在于用一个 Markdown 文件把"常设指令 + 周期自检 + 安静机制"收敛到一处。它把 Agent 从"你问才答"推向"定时巡更"，同时通过 HEARTBEAT_OK 控制了噪音和成本。实践中的分寸感很重要：清单要短、权限要小、间隔要合理。配好之后，你会发现最舒服的用法往往是最克制的那种——Agent 大部分时间沉默，偶尔开口，且开口时说的都是你真正需要知道的事。
