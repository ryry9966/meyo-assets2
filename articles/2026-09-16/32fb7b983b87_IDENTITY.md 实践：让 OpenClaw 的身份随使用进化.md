## 背景

OpenClaw 的工作区里有几个约定的 Markdown 文件：SOUL.md 管价值观和行为边界，USER.md 存用户画像，IDENTITY.md 则回答"我是谁"。很多人把它当成初始化时的装饰品——起个名字、配个 emoji 就不再动。但它其实是系统提示词的一部分：每次会话启动时会被拼进上下文，直接影响模型的自我表述和语气稳定性。换句话说，它不是档案，是运行时配置。

## 问题

不维护 IDENTITY.md，会出现几类典型症状：

- 跨会话人格漂移：昨天自称"沉稳的工程伙伴"，今天开始用夸张语气卖萌；
- 调语气时把一堆"你要怎么说话"塞进 SOUL.md，文件越写越乱；
- 换设备或多人共用实例时，行为不一致；
- 改了文件却发现没生效——旧会话缓存的是旧的系统提示词。

## 做法

1. **定位文件**：`~/.openclaw/workspace/IDENTITY.md`，首次启动时由初始化流程生成。
2. **保持最小字段集**：name、creature、vibe、emoji、avatar。够用即可，不必自行扩展 schema。
3. **只写"我是谁"，不写"我该怎么做"**。身份描述（"说话直接、先给结论"）放这里；行为规则（工具边界、安全红线）放 SOUL.md / AGENTS.md。两者不重叠是稳定的前提。
4. **版本化**：把 workspace 纳入 git，每次身份调整一个 commit，message 写清动机——文件历史就是人格变更日志。
5. **建立进化循环**：定期（比如每两周）复盘 bad case，把问题归纳到身份层面的根因，而不是逐条打补丁。改完 `/new` 开新会话验证。
6. **多 agent 场景**给每个 agent 独立 workspace，避免身份串味。

## 踩坑点

- **写成小作文**。几百字的身份文件会稀释注意力还烧 token，目标控制在十行以内。
- **与 SOUL.md 冲突**。一边写"简洁克制"，另一边写"热情活泼"，模型会在两者间摇摆。
- **emoji 失效**。部分纯文本渠道渲染不了 emoji，别把它当唯一识别符。
- **补丁式膨胀**。某次回答冒犯了你，就加一行"永远不要 XX"，三个月后文件里全是这类一次性规则。
- **误以为热加载**。IDENTITY.md 在会话启动时注入，改动只对新会话生效。

## 可复用建议

- 用"具体形容词 + 一个例子"替代抽象褒义词。"不说教、先给结论再给理由"比"友好专业"可控得多。
- 定期修剪：删除已内化到模型行为或已被 SOUL.md 覆盖的行，身份文件应该是全工作区最短的那份。
- name / emoji / avatar 跨渠道保持一致，用户在 Telegram 和终端里看到的是同一个"人"。
- 把身份变更当小型 A/B：调整 vibe 后观察一两天再决定是否保留。

## 总结

IDENTITY.md 的价值不在初始设定写得多漂亮，而在是否形成了可维护的进化回路：观察 bad case → 归纳身份层面的根因 → 小步修改 → 新会话验证 → git 留痕。把它当配置代码而不是文案来管理，agent 的人格才会随着使用越来越贴合你的预期。
