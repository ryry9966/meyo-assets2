## 背景

E2E 测试是分层测试里最贵的一层：写起来慢、断言脆、UI 一改就挂，团队覆盖率常年欠账。最近我们把 OpenClaw 的 Agent 接入测试流程，让它承担 E2E 用例的生成、执行和初步修复，在两个真实项目里跑通了。这里记录可复用的做法。

## 问题

直接把需求文档丢给 Agent，让它"写一套 E2E"，产物基本不可用，问题集中在三类：

- **选择器是编的**：生成 `div > button:nth-child(2)` 这类定位，看似合理，真实 DOM 里根本不存在——因为它没看过页面。
- **断言是空的**：不少用例跑完全绿，细看只断言"元素存在"，没验证任何业务结果。
- **等待靠 sleep**：`sleep 3000` 满天飞，本地能过，CI 随机挂。

根因相同：Agent 只有想象力，没有反馈。而写 E2E 的本质是和真实页面对话——这恰好能靠工具补上。

## 做法

流程四步，全部用 MCP 工具串起来：

**1. 接入执行环境。** 给 Agent 配两个 MCP 工具：浏览器操作（打开页面、读 accessibility tree、点击、截图）和测试执行（跑 Playwright、返回失败日志）。没有这两样，后面都是空谈。

**2. 规则前置。** 仓库里放一份 `test-rules.md`，写死硬约束：只用 role / data-testid 定位；禁止 sleep；断言必须落到业务结果（状态流转、接口返回、落库数据）；禁止 try-catch 吞异常。生成前 Agent 先读这份文件。

**3. 定点补洞，不批量生成。** 先人工维护"页面 × 关键路径"的覆盖矩阵，把缺口喂给 Agent，一次只补 1–3 个用例。生成后立刻在 headless 环境执行，失败日志原样回传，让它自己修，循环到绿再进 PR。

**4. 人工只审两处**：选择器策略和断言语义。格式问题交给 lint。

## 踩坑点

- **给截图不如给 accessibility tree**：截图耗 token 且定位不准，结构化树又便宜又稳。
- **一次超过 5 个用例，质量明显滑坡**，后半部分全是 happy path 复读。
- **Agent 修失败时倾向"改断言迁就现状"**。规则里要写明：调定位可以，削弱断言必须报备。
- **测试数据是隐形雷**：先给 fixture 约定，否则它会写出依赖执行顺序的用例。
- **CI 重试设为 1 次**：重试机制会掩盖 flaky，别让绿码制造安全感。

## 可复用建议

- 在仓库放两三个 golden 用例当范例，Agent 的模仿能力远强于理解抽象规则。
- 工具反馈越真实，产出质量越高。宁可花半天接 MCP 工具，不要用纯 prompt 硬凑。
- Agent 适合补长尾覆盖（异常分支、边界输入），核心主链路仍然人写。
- 每次 diff 限制在单个测试文件内，方便 review。

## 总结

Agent 写 E2E 不是"一句话生成测试套件"，而是把 Agent 当作有工具、有规则、有反馈回路的新同事：它写、它跑、它修，人守住断言语义和覆盖规划。流程搭好后，我们仓库的 E2E 从十几条涨到五十多条，人工投入反而下降。真正值钱的不是生成速度，而是"跑失败 → 读日志 → 自修复"这条闭环。
