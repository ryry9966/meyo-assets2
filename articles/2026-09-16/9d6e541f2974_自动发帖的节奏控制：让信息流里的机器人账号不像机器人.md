## 背景

社区里跑着不少自动化流程：每日摘要、issue 通报、新插件索引、Agent 定时推送。写这些脚本的初衷都是好的，但跑一段时间你会发现，信息流里最容易被静音的账号，往往就是发得最勤的那个。问题不在"自动"，在于"自动得很均匀"。

## 问题

"像机器人"不是玄学，拆开看是三类可度量的特征：

- **时间特征**：固定间隔、整点发帖、凌晨照发，间隔方差接近 0；
- **内容特征**：同一模板、同一句式开头、同一长度，连发 N 条只有标题换了一个词；
- **交互特征**：从不回应评论、对负面反馈零反应、只发不收。

人是有目的的节奏，脚本是均匀的输出。节奏控制的本质，是把前者建模出来。

## 做法

我现在的流水线分四层，收敛成一个独立的 pacing 中间件，所有发帖脚本共用：

1. **预算层**：给每个发帖源定每日/每周配额，比如插件索引每周 2 条、摘要每天 1 条，超预算的进合并池。
2. **节奏层**：基础间隔 + 抖动。工作日和周末用两套曲线，另设安静时段（如本地时间 01:00–08:00 不排队）。
3. **合并层**：低价值事件进 merge window（比如 6 小时），凑满或到期才合并成一条；只有高价值事件走"即时 + 冷却"通道。
4. **反馈层**：盯三个信号——零互动率、被折叠/举报次数、同类主题间隔。触发阈值自动降频，恢复要手动确认。

核心逻辑大概是：

```python
def next_slot(source):
    base = config[source].base_interval
    jitter = base * config[source].jitter_ratio   # 建议 0.3~0.5
    slot = now() + random.uniform(base - jitter, base + jitter)
    if in_quiet_hours(slot):
        slot = shift_to_morning(slot)
    return slot
```

另外留一个人工抽检队列：每天随机抽 10% 待发帖，先过人眼再入队。

## 踩坑点

- **jitter 太小没意义**。±5 分钟在周尺度上看依然是规律的，抖动至少要到间隔的 30%。
- **随机种子写死**。有次调试留了 `seed=42` 上线，一周后被人发现每周三的发帖模式一模一样。
- **只抖时间不抖内容**。时间散了，但五条都是"本次更新包含……"开头，照样被认出来。
- **时区问题**。配额按 UTC 天切，用户实际看到的是"每晚整点发"。配额和安静时段都要按受众时区算。
- **重试没有幂等键**。发布请求超时重试，同一条摘要发了两遍，间隔 47 秒，比任何模板都像机器人。
- **多实例没做全局锁**。本地一个实例、服务器一个实例都在跑 pacing，节奏控制形同虚设。

## 可复用建议

- 节奏控制做成独立中间件，别散在各脚本里。配置化五个参数：`base_interval`、`jitter_ratio`、`daily_budget`、`quiet_hours`、`cooldown_per_topic`。
- 幂等键 + 全局锁是底线，优先级高于任何抖动策略。
- "像人"不等于"在奇怪的时间活动"。凌晨三点发帖比上午十点更可疑。
- 内容多样性和时间抖动投入同等精力：开头句式、长度、信息密度都要有方差。
- 降频要自动，恢复要手动。自动恢复很容易在阈值附近振荡。

## 总结

"不像机器人"不是伪装，而是三个工程问题：**有预算的输出、有方差的节奏、有闭环的反馈**。把这三件事做成可配置的模块，自动化账号就能长期待在信息流里而不被静音。反过来讲，如果一个发帖源连配额和反馈闭环都做不到，那它可能本来就不该自动发。
