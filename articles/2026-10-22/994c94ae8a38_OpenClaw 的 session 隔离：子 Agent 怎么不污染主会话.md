## 背景

用 OpenClaw 跑自动化任务久了，几乎都会遇到同一个问题：主会话越来越"脏"。让主 Agent 派一个子 Agent 去做代码排查、批量读文档、跑一串 MCP 工具调用，结果子 Agent 的中间推理、工具输出、失败重试全被写回主会话上下文。几轮下来，上下文窗口被塞满，主模型被无关细节带偏，token 消耗翻倍，回复质量肉眼可见地下降。

OpenClaw 在设计上是支持 session 隔离的：子 Agent 拿到的是一条独立会话，工具调用痕迹和中间状态都封在子会话里，主会话只接收一份结构化结果。但很多污染问题其实出在**使用姿势**上，不是机制本身。

## 问题：三种典型的污染

1. **上下文污染**：子 Agent 的过程性输出进入主会话历史，主模型每次推理都要"背着"这些噪音。
2. **状态污染**：session 隔离 ≠ 文件系统隔离。子 Agent 在 workspace 里改了文件、装了依赖，主会话后续任务照样受影响。
3. **结果污染**：子 Agent 返回的"总结"本身没有约束，一段几千字的 dump 回灌主会话，等于换了个方向继续污染。

## 做法：一套可复现的隔离流程

以派发一个排查类子任务为例，流程大致是：

1. **拆任务，不拆对话**。给子 Agent 的 spawn 指令里写清目标、边界、期望输出格式，不要让它"接着上文继续干"。子会话默认看不到主会话历史，任务描述必须自包含。
2. **约束返回体积**。在任务里明确要求：只返回结论、关键文件路径、失败原因列表，原始输出留在子会话。路径和 ID 优于内容全文。
3. **过程留在子会话**。子 Agent 的工具调用、重试、报错都发生在它自己的 session 里，主会话只看到最终结果——这是隔离的核心收益，别用"把过程也贴回来"的指令把它亲手关掉。
4. **文件副作用单独处理**。如果子任务会写文件，给子 Agent 配独立沙箱（OpenClaw 支持 per-agent 的 Docker 沙箱和 workspace），或者用 git worktree 给它一个独立工作副本，跑完再合并。
5. **MCP 服务注意共享态**。多个 Agent 连同一个 MCP server 时，连接是共享的，有状态的工具（登录态、游标、临时目录）要确认并发安全。

## 踩坑点

- **任务描述太省字**。子 Agent 缺上下文就会自己"脑补"，跑偏后重试，成本反而更高。任务 prompt 花两分钟写清楚，比事后收拾省半小时。
- **返回结果不限长**。没约束的总结照样能写一千字，建议在指令里直接给格式模板。
- **误以为沙箱默认开启**。本地裸跑时，子 Agent 的文件操作和主会话是同一块盘，改错目录就是事故。
- **并行派发同状态资源**。两个子 Agent 同时写一个文件或抢同一个 MCP 工具的会话态，属于经典翻车现场。

## 可复用建议

- 把常用的子任务模板（目标、边界、输出格式）存成固定片段，派发时填参即可。
- 主会话层面只维护"决策所需的最小信息"，过程性信息一律下沉到子会话或落盘文件。
- 定期回头看主会话上下文，如果发现大段子 Agent 过程残留，回去改 spawn 模板，而不是手动清理。

## 总结

session 隔离不是开关，而是一种协作纪律：**过程归子会话，结论归主会话，副作用归沙箱**。OpenClaw 把机制给了你，剩下的是把任务拆分、结果约束、文件隔离这三件事固化成习惯。做到这三点，主会话能长期保持干净，长任务的稳定性会有非常明显的改善。
