36kr 最近那篇《从来就没有什么 Personal Agent》，标题起得很毒辣。翻译成工程师语言就是：一个被反复画饼的抽象类，跑了三年，至今没有一个可运行的实例。从 2023 年 AutoGPT 刷屏那天起，"AI 帮你订机票、管邮箱、安排日程"的故事讲了三轮发布会，demo 一个比一个惊艳。但真把日常在用的 AI 盘一遍：聊天助手、编程助手、搜索助手——全都很好用，唯独没有一个是"懂你、替你、还主动"的私人管家。这篇不聊情怀，拆一下这层窗户纸背后卡着的三块硬骨头，顺便聊聊哪些 Agent 已经真刀真枪跑起来了。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/a83417016ff2c471.png)

## 一、先对齐定义：我们在等一个什么东西

所谓 Personal Agent，业界画饼时的核心承诺其实就三条：

1. **持久记忆**：认识你，知道你的偏好、日程、历史决策；
2. **跨应用执行**：能真操作你手机和电脑里的服务，而不只是输出文字；
3. **主动性**：不等指令，自己发现"该做的事"。

时间线上看，Siri 在 2011 年就打出了 intelligent assistant 的旗号；2023 年 AutoGPT 让"自主 Agent"出圈；2024-2025 年各家把 agent 写进战略关键词。叙事迭代了三轮，产品形态基本停留在"更聪明的对话框"。原因不是大家不努力，而是这三条承诺，各自横着一座山。

## 二、卡点一：记忆不是上下文，大模型天生"金鱼脑"

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/e3cbd3d0a4fcf9f5.png)

很多人以为 context window 越大，AI 就越"了解你"，这是最大的误会：

- **窗口是工作台，不是记忆**。哪怕 1M token 的上下文，也只是这一次调用的临时草稿纸，会话结束即清零。模型本身是无状态的，每次调用都从失忆开始。
- **工程补丁各有软肋**。RAG、向量库、记忆层（把历史压缩成可检索片段）是主流方案，但检索式记忆很脆：语义相似不等于事实相关，你要"上次订的那家餐厅"，它可能给你捞回三年前的一条影评；记忆还会冲突、会过期，"什么时候该忘"比"怎么记住"更难。
- **个人语境是长尾且隐式的**。你真正需要的是"我和谁、因为什么、在什么时间订了什么"这种跨年、跨应用的压缩状态，目前没有成熟方案。各家产品的 memory 功能，实际体验基本停留在几条偏好标签加对话摘要的量级，离"了解你"还差着量级。

## 三、卡点二：执行层的可靠性，乘法越乘越绝望

从"会说话"到"会做事"，中间隔着整个执行层：调 API、操作界面、处理异常。这里的数学很残酷：

- 假设单步操作成功率 95%（已经不低了），一个 20 步的任务全链路成功率就是 0.95²⁰ ≈ 36%。乘法不会骗人，但发布会会。
- 参照数据：学界计算机操作类基准（OSWorld、WebArena 这类）上，Agent 的端到端任务完成率长期在两位数百分比徘徊，简单任务尚可，长尾任务大面积塌方。
- 执行环境本身碎片化：没有统一 API，UI 自动化对页面布局变化极其敏感，验证码、二次确认、平台风控都是天然拦截。
- 更致命的是可逆性：聊天答错可以重问，机票订错只能认栽。现实世界大量操作不可逆，而 Agent 产品的生命线恰恰是"可回滚"。

## 四、卡点三：商业错位，"个人"是个赔钱的中间层

技术之外，还有一笔更冷的账：

1. **成本侧**：个性化记忆、多步执行意味着更多 token、更长会话，而个人订阅只有 20 美元/月的量级，算力账很难打平。
2. **生态侧**：Agent 要"替你操作"，就得横跨聊天、支付、航司、酒店。但这些入口和数据是各家的护城河，没人愿意把自己降级成"被别人调用的 API"。
3. **利益侧**：如果 Agent 靠广告或佣金赚钱，它推荐的到底是"对你最好"还是"出价最高"？中间人一旦站队，"个人"二字就名存实亡。

所以这个叙事在相当程度上是资本叙事：to VC 的故事好讲，to C 的产品难做。36kr 那篇的"从来就没有"，戳破的就是这层窗户纸。

## 五、但别误伤：窄 Agent 已经真刀真枪跑起来了

"没有 Personal Agent"不等于"没有 Agent"。真正落地的产品，无一例外满足同一个结构：**可验证 + 有边界 + 人在环**。

- **编程 Agent**（Cursor、Claude Code 这类）：结果可验证——编译过没过、测试绿没绿一眼便知；环境边界清晰；改错了能 revert。
- **Deep Research 类**：产出是报告，错了重写就行，不可逆成本为零。
- **客服与工单类**：场景封闭、流程可枚举，失败模式有限。

反观"个人通用管家"，三条全不占：结果难验证、边界无限大、错误不可逆。规律很清晰——Agent 的落地顺序，是从闭环窄场景向开放宽场景逐步外扩，而不是一步到位造出贾维斯。

## 六、收尾：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/ec516c104a5a52e6.png)

1. **评估任何 Agent 产品，先问两个问题**：做错了能不能撤销？结果对不对能不能自动验证？两个都是"否"的，大概率还活在 demo 阶段。
2. **对"懂你一切"的产品保持数据洁癖**：记忆即资产，也是攻击面。用之前先看有没有导出、删除、关闭记忆的开关，别把人生全量托付给一个没经过时间检验的黑盒。
3. **想入局的开发者，别做全能管家**：找一个足够窄的场景，把成功率从 60% 磨到 95%，把错误成本压到零——这比讲"下一代操作系统"的故事值钱得多。

Personal Agent 不会凭空降临，只会从一个个磨出来的窄闭环里长出来。没有天降的私人管家，只有一步一步把单点成功率做上去的工程。
