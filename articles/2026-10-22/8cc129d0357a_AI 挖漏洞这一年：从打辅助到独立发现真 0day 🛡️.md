2024 年 10 月，Google Project Zero 宣布了一个安全圈等了很多年的结果：由大模型驱动的 agent「Big Sleep」，在一款几乎装进每台手机和每个浏览器里的软件 SQLite 中，发现了一个此前无人知晓、且具备可利用条件的内存漏洞，也就是俗称的 0day（厂商自己都还不知道、更没修复的漏洞）。这是 AI 第一次独立找到真实世界软件中的未知漏洞。一年过去，这类新闻从偶发变成了批量，36kr 那句「AI 到处挖漏洞一整年，终于给人类爆了个大的」，说的就是这条曲线的陡然抬头：AI 挖洞不再是发布会上的演示，而是真的在持续产出。下文拆三件事：挖到了什么、怎么挖的、水位到底有多高。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/4396d67f99e0192e.png)

## 成绩单：这一年 AI 到底挖到了什么

- **2024 年 10 月，破冰**：Big Sleep（Project Zero 与 DeepMind 合作、基于 Gemini）在 SQLite 中发现栈缓冲区下溢（stack buffer underflow）。SQLite 号称全球部署量最大的软件之一，手机、浏览器、汽车里都有它，这个洞的分量不言而喻。
- **2025 年，从个案到量产**：Google 公布 Big Sleep 在 FFmpeg、ImageMagick、GLib 等主流开源库中连续发现多个未知漏洞；11 月又在 Chrome 的 JavaScript 引擎 V8 里找到 2 个新漏洞，其中 1 个可被实际利用——这是 AI agent 首次在 Chrome 引擎层面挖到可利用漏洞，所谓「爆了个大的」，指的就是它。
- **另一条战线是 fuzzing**：Google 把 LLM 接入 OSS-Fuzz（覆盖数千个开源项目的自动化测试平台），让 AI 自己编写测试入口，一年找到 26 个新漏洞，其中 1 个被评为 critical。
- **商业化玩家也在冲榜**：自动渗透测试 agent XBOW 曾登顶众测平台 HackerOne 的美国区榜单，团队称其约四分之三的报告被判定有效。
- 给个对照组：全球每年披露的 CVE 大约四万个，绝大多数仍由人类研究员和传统工具完成。AI 的绝对占比还小，但从 0 到 1 已经完成，斜率才是重点。

## 原理：AI 不是瞎蒙，它有三种打法

传统挖漏洞的三件套：fuzzing（海量随机与变异输入喂程序、看会不会崩）、静态与动态分析、人类专家审计。AI 做的事，本质是给每一件都换了引擎。

1. **AI 写 fuzz target（OSS-Fuzz 路线）**。Fuzzing 最大的瓶颈是入口：每个库都得有人写代码告诉 fuzzer 怎么调用它，而 LLM 恰好擅长写这类样板代码。于是流程变成：AI 读 API 与示例 → 生成测试代码 → fuzzer 跑出崩溃 → AI 协助复现、分类、去重 → 人类最终确认。最费人力的环节被自动化了。
2. **Agent 式代码审计（Big Sleep 路线）**。给 agent 配上研究员的同款工具：源码浏览、调试器、命令行，让它跑人类的工作循环，提出假设（「这里输入长度和缓冲区大小对不上」）→ 设计实验触发 → 观察结果 → 修正假设。它还特别擅长交叉比对 commit 历史、文档与测试用例，专找「代码改了、文档没改」的不一致处，而行业经验是：不一致的地方，往往埋着 bug。
3. **自主渗透测试（XBOW 路线）**。面向 Web 应用，把 SQL 注入、XSS、IDOR 这类检测模式成熟的漏洞做成自动化探测流程，由 LLM 理解目标、编排 payload、判断响应。

一句话总结分工：fuzzer 出暴力，LLM 出直觉，知道去哪看、看什么、怎么验证。这恰好补上了传统工具最弱的一环。

## 为什么是现在：三个条件刚好凑齐

- **代码能力过了阈值**：挖洞需要读懂几十万行陌生代码的控制流与数据流，长上下文窗口加强代码模型的组合，第一次让机器「读得动」真实项目。
- **Agent 基建成熟**：工具调用、多轮规划、沙箱执行在 2024–2025 年快速标准化，AI 才能真正操作调试器、跑命令，而不只是输出文本。
- **经济学变了**：漏洞挖掘是典型的样本极稀疏任务，专家一天审一个组件，一年未必命中一个 0day；而 agent 的边际成本趋近于零，可以 7×24 跑。当地毯式排查便宜到人人用得起，防御方第一次在产能上拿到先手。
- 历史彩蛋：机器挖洞的首次公开表演是 2016 年 DARPA 的 Cyber Grand Challenge，参赛系统 Mayhem 全自动找漏洞、打补丁。当年更像原型验证，十年后补齐的是「智能」这块拼图。

## 冷水时间：真实水位没那么科幻

- **人类确认省不掉**：AI 报的洞里误报不少，「可利用」的结论通常需要工程师花数天复现并构造利用链。现阶段它更像高产但需要 mentor 的初级研究员，产出惊人，final review 还在人手里。
- **覆盖面偏科明显**：强项集中在 C/C++ 内存安全类 bug 和 Web 常规漏洞；对业务逻辑漏洞、需要协议领域知识（密码学、工控等）的问题，仍差得远。
- **攻防是双刃剑**：同样的能力，红队用叫提效，黑产用叫降价。自动挖洞把 0day 的发现成本打下来，也意味着从披露到被利用的时间窗口在压缩——防御方的 patch 速度，从来没有这么重要过。

## 给开发者和企业的三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/8cb66b0e40860df3.png)

1. **把 patch 窗口当核心 KPI**。默认「披露即被利用」会常态化：用 Dependabot、Renovate 这类工具做依赖自动更新，建立高危漏洞 72 小时内可发版的流程，比堆更多扫描器值钱。
2. **从源头减少 AI 最爱咬的那类洞**。新项目优先考虑 Rust、Go 等内存安全语言；存量 C/C++ 代码把 ASan、UBSan 和 coverage-guided fuzzing 挂进 CI。AI 挖洞的第一战场就是老 C 代码，别让你的项目成为别人 agent 的练手靶场。
3. **AI 审计当增量防御用，同时更新威胁模型**。人机结合：AI 全量初筛、人工确认，以低成本覆盖大部分代码；另一边，做安全规划时要默认对手也在用同样的技术，预算和响应预案按「更短的时间窗」来编。

## 写在最后

安全行业的老话：防御方要修所有门，攻击方只需找到一扇。过去这句话的潜台词近乎宿命，人类看守不了那么多门。AI 这一年做的事，本质是第一次让守门方也能机械化地检查所有门。门仍会漏，但攻防的成本曲线，正在朝对普通人更有利的方向弯过去。前提只有一个：你把补丁打上了。
