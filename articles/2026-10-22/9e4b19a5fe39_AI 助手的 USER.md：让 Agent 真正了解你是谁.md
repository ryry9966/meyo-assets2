## 背景

用 Agent 干活几个月后，最明显的成本不是 token，而是重复自我介绍。每个新会话都要再说一遍：主力语言是什么、包管理用 pnpm 不用 npm、回复要短、别主动加注释。会话一断，全部归零。

项目层面我们有 CLAUDE.md / AGENTS.md，它告诉 Agent“这个仓库怎么回事”。但“我是谁、我怎么干活”这件事，一直散落在每次对话的开头。USER.md 补的就是这块：一份描述用户本身的持久上下文文件，随会话自动加载。

## 做法

**第一步：确定路径和加载方式。** 放在固定位置，比如 `~/.config/openclaw/USER.md`，或 OpenClaw workspace 的 memory 目录。如果 Agent 只认项目级文件，就在 CLAUDE.md 里引用它；也可以用 MCP 暴露一个 `get_user_profile` 的 resource，任何 client 都能读，不绑定具体工具。

**第二步：写内容，控制在 30–60 行。** 推荐五段结构：

```markdown
# 角色与环境
- 后端工程师，负责支付网关
- macOS + Neovim，部署走 K8s

# 默认偏好（可被覆盖）
- 技术内容用中文，代码和 commit message 用英文
- 先给结论，解释控制在三句以内

# 硬性规则
- 不动 migrations 目录
- 删除操作必须先列清单确认
- 不要建议我换语言/框架

# 常用命令
- test: make test-short
- lint: make lint
```

**第三步：验证生效。** 新开会话，问一个只有读过文件才答得出的问题（比如“我的测试命令是什么”），再观察回复风格是否变化。

## 踩坑点

1. **写太长。** 我早期写了 200 行，每次会话吃掉几千 token，重点还被稀释。现在压到 50 行内，长内容拆成按需加载的独立文件。
2. **写成简历。** “五年经验、精通 XX”对 Agent 没有决策价值。判断标准：这条信息会改变它的行为吗？不会就删。
3. **表述绝对化。** “永远用中文”在处理英文 issue 时就很别扭。大部分写成 defaults，只有极少数才是 hard rules。
4. **过期信息比没有更糟。** 我曾在文件里留着已废弃的部署方式，Agent 一本正经按旧流程写脚本。现在按季度 review 一次。
5. **同步泄露。** 放 dotfiles 仓库多机同步很方便，但容易混进公司内网域名和真实项目名。要么脱敏，要么把公共部分拆成单独文件。
6. **优先级冲突。** 项目级配置应覆盖用户级偏好，落地时确认加载顺序，避免“全局说不用 npm、项目说用 npm”时 Agent 行为摇摆。

## 可复用建议

- 模板固定五段：角色与环境 / 默认偏好 / 硬性规则 / 常用命令 / 禁止事项，照抄即可。
- 把维护交给 Agent 本身：每月让它 diff 一次近期对话历史，提议 USER.md 的增删，人工把关合并。
- 团队场景沉淀一份脱敏的“团队版”，新人 clone 之后，Agent 的上手成本立刻降下来。
- 配合 MCP 做成 resource 而不是写死在某个工具里，将来换 Agent 不用重写。

## 总结

USER.md 解决的不是能力问题，是记忆问题。它把“你是谁”从每次会话的一次性输入，变成一份版本化的静态资产。三条原则：控制在 50 行以内、只写影响决策的信息、定期清理。做到之后，Agent 的默认输出会明显贴近你的习惯——而且写这份文件的过程，本身就是一次很诚实的自我梳理。
