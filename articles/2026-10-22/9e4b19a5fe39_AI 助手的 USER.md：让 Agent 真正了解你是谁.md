## 背景

每个 Agent 会话开始时，上下文都是空的。项目侧的解法已经很成熟：`AGENTS.md` / `CLAUDE.md` 让 Agent 秒懂仓库结构、构建命令、代码规范。但"项目知识"和"人的知识"是两回事——Agent 知道这个仓库怎么跑，却不知道你是谁：你用什么语言沟通、偏好的技术栈、哪些事不希望它擅自做主。

USER.md 就是补上这一层的做法：一份稳定的、版本化的个人上下文文件，让 Agent 在每次会话启动时默认知道"对面坐的是谁"。

## 问题

没做这层的典型症状：

- 每个新会话都要重新自我介绍一遍："我用 pnpm 不用 npm""回复用中文""不要动 main 分支"；
- 同样的偏好在不同会话里被不一致地遵守，全看模型当天心情；
- 自动化场景（定时任务、webhook 触发）没有人在场自我介绍，Agent 只能靠猜，猜错就写进结果里。

## 做法

**1. 放哪里。** 全局配置放 `~/.openclaw/USER.md`（或你所用框架的全局/工作区根目录），项目相关约束放项目的 AGENTS.md，两者分层、互不抢占。

**2. 写什么。** 控制在 30~50 行，固定小节：

- **身份与角色**：一句话说明你是谁、主要工作内容；
- **技术栈与环境**：OS、包管理器、主力语言、部署方式；
- **沟通偏好**：语言、详略程度、是否要解释变更理由；
- **边界与禁区**：不自动 push、不改某些配置、敏感目录跳过；
- **高频上下文**：常用路径、测试命令这类每次都要用的信息。

**3. 怎么生效。** 确认你的 Agent 启动流程会读取该文件（OpenClaw 工作区会加载根目录下的上下文 md；其他框架可用 system prompt 注入或 MCP 资源加载）。用一个固定问题验证："你现在知道我的包管理器是什么吗？"答不对就是没加载到。

## 踩坑点

- **写成日志 dump。** 超过一屏，关键信息会被稀释——模型注意力有限，越短越有效。
- **塞敏感信息。** 这个文件会被原样送进模型上下文，API key、真实手机号、内网拓扑不要写。
- **与项目文件冲突。** 全局说"用 pnpm"，某项目 AGENTS.md 说"必须 npm"，要显式声明优先级（项目覆盖全局），否则 Agent 会随机选一边。
- **内容过期。** 换了机器、换了栈忘了更新，Agent 拿着旧地图导航。文件头加一行"最后更新日期"提醒自己。

## 可复用建议

- 用 git 管理，放 dotfiles 或私有仓库，多机同步，改动有据可查；
- 严格区分"稳定事实"（角色、栈、偏好）和"临时任务上下文"，后者别放这里；
- 每次发现 Agent 答错"关于你的问题"，把正确答案补进去——把它当成记忆的补丁流程，而不是一次性配置；
- 团队场景可以抽象出 ROLE.md 模板（角色 + 栈 + 偏好三段式），新人入职填一份，Agent 立即可用。

## 总结

USER.md 本质上不是新协议，而是把"每次口述自我介绍"固化成一份版本化配置。成本极低——今天从 10 行开始写，跑两周、迭代一次，之后所有会话里关于"你是谁"的回答会稳定一致。这可能是投入产出比最高的一次 Agent 配置。
