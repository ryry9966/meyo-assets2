大模型公司的成本，历来是行业最大的“薛定谔之谜”：API 定价挂在官网，unit economics 锁在抽屉里。2025 年 2 月底，DeepSeek 用五天开源了五个推理基础设施项目，随后又把 V3/R1 推理系统的硬件配置、成本与理论收入一并贴在 GitHub 上——理论日成本约 8.7 万美元，理论日收入约 56.2 万美元。有分析师顺着这套公开数据往下算，得出 AI 推理的毛利率约 82%，也就是这次热搜里那个数字。这是第一次，有人能拿着可验算的公开数据回答“卖 token 到底赚不赚钱”。这篇拆三件事：账怎么算的、毛利靠什么撑起来、以及这个数字该怎么用、别用错。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/f23e1628f5219978.png)

## 先复盘：DeepSeek 摊了哪些牌

- **开源五连发**（Open Source Week）：FlashMLA（MLA 注意力的解码 kernel）、DeepEP（MoE 专家并行通信库）、DeepGEMM（FP8 矩阵乘）、DualPipe 与 EPLB（流水线并行调度与专家负载均衡）、3FS（高性能文件系统）。覆盖的正是推理系统里最吃性能的几层。
- **推理系统“开箱详解”**：约 278 个 H800 节点组成 V3/R1 服务集群，按每小时每卡 2 美元的租赁价计成本，叠加跨节点通信、存储与带宽，得出理论日总成本 87,207 美元。
- **收入侧**：假设当天所有 API 调用都按官网定价计费，理论日收入 562,027 美元，对应“成本利润率 545%”。

关键在于：别人开源模型权重，DeepSeek 连算力账本一起开源，行业第一次有了可交叉验算的推理成本基准。

## 82% 是怎么算出来的：一笔可以验算的账

先把口径捋清楚，这是整件事最容易翻车的地方：

- **成本利润率 545%** =（收入 − 成本）÷ 成本。56.2 万减 8.7 万，再除以 8.7 万，约等于 545%。
- **毛利率** =（收入 − 成本）÷ 收入 = (562,027 − 87,207) ÷ 562,027 ≈ 84.5%。
- **热搜里的 82%**，是分析者把夜间折扣、prefill/decode 定价档位、token 结构等因素加权后的口径。数字有出入，量级一致：AI 推理是门毛利率 80% 上下的生意。

收入结构里还有两个“隐性加成”：

1. R1 是推理模型，思维链长，输出 token 占比高，而输出恰是最贵的部分——每百万 token 2.19 美元，输入缓存命中只要 0.14 美元。
2. 缓存命中把输入成本压到约 1/4，用户薅得越狠，系统吞吐反而越高，等于盘活了闲时算力。

对照一下：OpenAI 只给过“推理成本每年降 10 倍”的方向性判断，从没拿出可验算的账本。DeepSeek 等于把行业的定价锚点从“拍脑袋”推进到“有底稿”。

## 撑起高毛利的三个技术杠杆

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/e18c42c82e5a9e72.png)

毛利率高不是躺赚，本质是单位 token 的服务成本被技术压到了地板上：

1. **MLA 把 KV Cache 压掉九成**。推理最稀缺的资源是显存容量与带宽，传统 Multi-Head Attention 的 KV Cache 随上下文线性膨胀。MLA（Multi-head Latent Attention）把 KV 压缩成低秩潜向量，官方数据显示相比 MHA 减少 90% 以上。显存省下来，同样的卡就能塞更大的 batch，吞吐直接起飞。
2. **MoE 让每次只开部分灯**。V3 总参数 671B，但每个 token 只激活约 37B，单 token 的 FLOPs 远小于同规模稠密模型——算力花在刀刃上。
3. **PD 分离 + 通信优化榨干硬件**。Prefill 是计算密集，Decode 是访存密集，拆到不同集群分别调优；DeepEP 用 NVLink/RDMA 混合通信做跨节点 expert all-to-all，DualPipe 让计算与通信重叠、消掉流水线气泡；DeepGEMM 在 H800 上把 FP8 矩阵乘跑到 1350+ TFLOPS。

值得玩味的背景：H800 削减了互连带宽，通信本该是短板，但 MLA 减少了跨节点 KV 传输，DualPipe 藏住了通信延迟——这是约束倒逼出来的算法-系统协同设计。开源之后，这些手段变成了行业公共品。

## 别急着抄作业：四个必须打的补丁

82% 是“理想工况”下的账，直接套到任何一家公司都会失真：

- **理论 vs 实际**：账假设 GPU 满载 24 小时，真实流量有昼夜峰谷；深夜时段（16:30–00:30）还有五折到二五折的自动折扣（即降价 50%–75%），实际加权收入低于官网价。
- **只算了变动成本**：8.7 万美元里主要是 GPU 租赁，没算研发团队薪酬、训练成本摊销、数据与实验的沉没成本。把研发摊进来，利润率立刻缩水一个量级。
- **租赁价 vs 自购折旧**：按 2 美元/卡·小时租的；若自购 H800，每卡两万多美元的前置投入叠加折旧，毛利结构完全是另一回事。
- **模型结构**：R1 的长输出、高单价撑起了收入侧，普通对话模型或小模型 API 未必有这种结构，横向对比容易踩坑。

账是人算的，口径是人定的。

## 冷思考：拿这个数字做决策之前

1. **先问分母，再看分子**。听到任何毛利数字，第一反应问口径：全成本还是变动成本？满载理论值还是真实利用率？同一套系统，口径一换，毛利从 84% 掉到 50% 以下都正常。
2. **把缓存命中率当成成本杠杆**。DeepSeek 输入价格缓存命中只有未命中的约 1/4，系统提示词前置、上下文复用，账单立减六成起步——对 API 重度用户，这是最便宜的“降本增效”。
3. **给应用留可替换性**。82% 的毛利意味着定价仍有下探空间，价格战没打完。业务逻辑别焊死在某家 API 上，同时盯住 vLLM/SGLang 加开源 kernel 的自托管方案——自托管与云 API 的 TCO 边界，正在快速移动。

一句话收尾：82% 最大的价值不是答案本身，而是行业第一次知道该追问什么问题。
