## 背景

OpenClaw 这类常驻个人 Agent 有个绕不开的现实：会话上下文是易失的。重启、压缩历史、换设备之后，模型能依赖的只有工作区里的几个文件。`MEMORY.md` 记录"发生过什么"，`SOUL.md` 定义"Agent 是谁"，但"用户是谁"长期散落在聊天记录里。USER.md 就是补这一块——一份由你维护、Agent 每次启动都会读到的稳定档案。

## 没有它会发生什么

- 时区、主力语言、技术栈这些基本盘被反复询问
- 明明说过"回复要短"，三天后它恢复长篇大论
- 换设备或清理会话后，个性化全部归零
- 定时任务按错误的时间、错误的风格执行

本质就一条：稳定事实混在易失对话里，检索天然不可靠。

## 做法

**1. 建文件。** 在工作区根目录创建 `USER.md`，分区写，用原子化短句：

```markdown
# USER.md
## 基本信息
- 时区：Asia/Shanghai
- 语言：中文优先，技术名词保留英文

## 技术栈
- 主力 TypeScript / Node.js，包管理器用 pnpm

## 沟通偏好
- 先给结论，默认不超过 5 行，不用 emoji

## 当前项目
- 工作区插件开发（预计 6 月收尾）

## 禁令
- 未经确认不发送任何对外消息
- 22:00 后不触发非紧急通知
```

**2. 授权维护。** 在 `AGENTS.md` 或 `SOUL.md` 里加一条：当用户陈述稳定事实（"以后统一用 pnpm"）时，主动更新 USER.md，但落笔前先复述变更内容，得到确认再写。

**3. 纳入 git。** 档案变更像代码一样有 diff、可回滚，出问题能定位到哪次改动。

## 踩坑点

- **写太长。** 它每个会话都会被注入 prompt，几百行既费 token 又稀释重点，稳定事实建议控制在 40 行以内。
- **陈旧信息比没有更糟。** 旧项目不删，Agent 会一直围绕一个已经死掉的方向展开。宁缺毋滥。
- **描述太主观。** "喜欢简洁"没法执行，"回复默认不超过 5 行"可以。写可证伪的条目。
- **放敏感信息。** 密钥、token 写进去等于进每次上下文，绝对不要。
- **授权失衡。** 不授权则文件半年不变；全权放任则 Agent 会按自己的理解改写你的偏好。折中方案是"先确认再落笔"。

## 可复用建议

- **区分两本账：** 稳定身份进 USER.md，动态事件进 MEMORY.md，混写必然腐化。
- **季度清理：** 设个提醒，每三个月删一次失效条目，顺手 git commit 留档。
- **验证生效：** 直接问 Agent "我现在用什么包管理器、几点之后别打扰我"，答错说明文件没被读到，或写法有歧义。
- **多实例复用：** 几个 Agent 可以指向同一份 USER.md 作为唯一事实源，避免各自记忆漂移。

## 总结

Agent 的能力上限由模型决定，但它的"懂事程度"由你喂的上下文决定。在所有配置项里，USER.md 大概是投入产出比最高的那一类：十分钟写完，之后每次会话都在替你省去重复解释。建议先从时区、语言、沟通偏好这三条写起，剩下的让它在使用中自己长出来。
