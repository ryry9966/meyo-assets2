36kr 报道，谷歌 Gemini 4 Carbon 的首批实测信息流出，几位拿到内测资格的开发者给出的评价高度一致：“手感直逼 Opus 5.5。”官方没开发布会，第三方 benchmark 也还没出分，一句“手感”就够把社区点着了。追热点之前，更值得花十分钟搞清楚的是：大模型圈天天挂在嘴边的“手感”，到底是玄学，还是一套可以拆解的工程逻辑？这篇文章把它拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets2@main/images/2026-10-22/b7fc73260b598ec9.png)

## 一、“手感”不是玄学，是五个可测维度的主观加总

“手感”听起来像玄学，拆开看全是可量化的东西。老玩家所谓的手感差异，基本落在这五处：

1. **首因响应质量**：第一句话是否直给。有的模型习惯先铺三行背景再给答案，用户立刻觉得“不跟手”。
2. **指令遵循（instruction following）**：约束一多就见真章。“用表格输出，每行不超过 15 字，末尾附三条风险”，三个约束叠一起，各家差距立刻显形。
3. **长上下文一致性**：塞 20 万 token 的文档再提问，中段内容还记不记得。经典的 needle-in-a-haystack 只考检索，更狠的是多跳推理——A 信息在第 3 章，B 在第 17 章，问题偏要你把两者连起来。
4. **一次通过率**：代码场景看 pass@1 和 SWE-bench 这类指标；写作场景看你要返工几轮才能交付。
5. **信息密度**：同一个问题，A 模型 300 token 讲透，B 模型 800 token 还在绕。废话率直接决定“跟不跟手”。

所以“手感直逼”翻译成工程语言，大概率是：没有明显短板，而不是某项碾压。顺带一个冷知识：各家 API 的默认 temperature 和内置 system prompt 都不同，同一个模型换组默认参数，手感就能差一个档位。这也是为什么“我测的”和“你测的”经常对不上。

## 二、为什么“首批实测”要自动打折

首测信息的置信度，要先过三道折扣：

- **幸存者偏差**：愿意晒图的人晒的是惊艳 case，答砸的截图没人发社交媒体。你看到的样本，是被筛选过的。
- **Prompt 资产差异**：内测者往往带着自己打磨了几个月的 system prompt，换个人裸测，结论可能整个反转。这类测试测的一半是模型，一半是提问者的功力。
- **版本漂移**：内测 build 到正式发布之间，还有安全策略调整、后训练收尾、推理参数调优。业内不止一次出现过“内测惊艳、发布平庸”的剧本。

再加一条数学常识：三五个人一周的主观体验，样本量约等于 nothing。可靠的模型评测需要固定测试集、盲测和成百上千次试验。首测的正确打开方式，是当“赛前采访”听——有信息量，但不是成绩单。

## 三、两家的手感为什么天生不同：路线决定的

如果这次对比属实，差异大概率来自两家多年积累的技术路线，而不是某个单点突破：

- **基础设施与架构**：Google 自研 TPU，全栈闭环，在 MoE（Mixture of Experts）架构和超长上下文上是老玩家，Gemini 系列历代都把长文档处理当主打牌。
- **训练取向**：Anthropic 走 Constitutional AI 路线，写作风格克制，代码与 agentic 任务（多步骤工具调用）是社区公认的强项。
- **风格来自 post-training**：当 base model 能力相近时，RLHF/RLAIF 调出来的“性格”才是手感差异的主因。有人偏好直给，有人偏好严谨，这是取向之别，不是强弱之别。

由此推论，“手感直逼 Opus”即便属实，更可能说明 Google 在后训练风格上向“专业生产者友好”方向又拧了一格，而不一定是 raw capability 反超。这两件事在讨论里经常被混为一谈，值得分开看。

## 四、与其等跑分，不如建一套自己的“手感”评测法

等别人给结论，不如自己动手，成本一个下午：

1. **攒 20 条私人测试集**：3 条长文档提炼、3 条多重约束指令、3 条真实业务代码、3 条 20 轮以上的多轮对话，剩下的位置放你日常最烦的脏活。测试集固定，结论才可复现。
2. **盲测 A/B**：同一 prompt、同一 temperature，抹掉模型名再对比。盲测能干掉品牌光环和“新模型兴奋剂效应”。
3. **盯失败模式，不看成功案例**：成功截图人人会发，幻觉方式和“不听话的方式”才决定它能不能进你的生产流程。
4. **记两个数字**：首 token 延迟（TTFT）和每百万 token 成本。手感再好，贵三倍慢一倍，工程上就得重新算账。
5. **用 API 测，别用网页测**：聊天网页叠了检索、画布、路由等一层产品魔法，你测到的是产品，不是模型。

## 五、三条冷思考

1. **首测当风向标，别当判决书。** 合理姿势是三步走：等正式发布 → 等第三方固定 benchmark 跑分 → 拿自己的测试集复测。三步走完，再决定要不要换主力模型。
2. **“手感”会过时，工作流不会。** 这两年模型榜单一轮轮洗牌，真正保值的是你的 prompt 库、评估流程和数据管道。把对单一模型的依赖做薄，换血成本趋近于零，你才站在买方市场。
3. **警惕旗舰迷信。** 日常八成任务是简单活，中档模型加好的 prompt 和检索增强，效果与旗舰差距很小，账单却可能差 5 到 10 倍。为最后 5% 的提升付三倍价格之前，先盘点自己的任务列表里有多少是简单活。

热搜一周换三个主角，工具人的正确姿势始终不变：谁好用用谁，自己的测试集，才是唯一的裁判。
